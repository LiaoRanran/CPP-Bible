# B. 红队批判架构（只报新的；已登记的 W1/W2/W3/A3 不重复）

## B.1 L2 调度（自报 12%）：不是空壳，是"连壳都还没有"【已实现=0】

**实测**：`tools/` 下 `model_router.py / task_queue.py / diagnostics.py / mutation_fuzz.py / retry.py / doc_search.py` 全部不存在（Test-Path 逐个验证）。
存在的 `task_state.py`（233 行）是**手工 create/update 命令行工具**：状态文件放 `data/tasks/`，当前该目录为空；它没有队列、没有 claim 原子性、没有 worker、没有模型路由、没有自动续跑。517 给它算"任务队列 40%"（0.5/4 分），按真实代码应是 **0/4**——它是状态笔记本，不是调度器。
**判定**：524 层 3 的三件套（多模型路由/幂等状态机/Supervisor Loop）在代码中 **0 件**。"12%"是设计完成度不是工程完成度。

## B.2 L3 智能（自报 12%）：有真骨架，但骨架接错了位置【部分实现】

- **文件图（knowledge_graph.py，580 行）是真骨架**：SQLite、deps/impact/chain/orphans 可跑，工程影响面查询成立。
- **概念层（526/528 新增）有表无魂**，三条实证：
  1. **零连通**：`concepts --json` 实测 157 概念，连接 ≥2 原子的 **0 个**（脚本 `_concept_conn.py`）。连"内存屏障(fence)"都只挂在 FENCE-001 一张卡（2 条命题），LOCK-001/RACE-001 谈同类机制却没有复用该概念节点。原因在回填动作：object 被写成**句子**（如"数据竞争原子性/不建立happens-before"），不是规范概念名；alias 表（11 条）归一命中 0 处（`build` 输出自报）。
  2. **conflicts 100% 噪声**：19 组候选中极性命中 **0**，19 组全靠 CONTRADICTS 边，而 `knowledge_graph.py:104` 把 `contrasts`（对照）和 `contradicts`（矛盾）**合并成同一类边**（REL_MAP 第 104 行），工具自己在输出里都注明"多半是对照，需人工筛"。当前规模下这是纯负担。
  3. 528 任务 1 要求"回填一张 STAGING warn 少一条"，但 `claim_structured_staging.txt`（27 个 id、41 行）在 27/27 全回填后仍原样保留——**死台账**，不影响功能但说明"回填后自动消失"的设计注释与实际维护脱节。
- **判定**：525"产物依赖图≠概念语义图"的批判不仅仍成立，而且 528 的回填方式（自由文本 object）**系统性地阻断了概念层连通**。这不是继续回填能修好的，要改 schema 约束。

## B.3 claim_structured v0.3 的 observation/inference 二分能被绕过【实证·新阻断】

**规则事实**（gate_engine.py:1942 `check_observation_needs_artifact`）：observation 命题的唯一机器判据是"evidence 里至少一张卡带 artifact_assert 或 run_match_file"。**没有任何规则检查命题内容是否真的是可观测事实**。
**攻击构造**（`_adv_critique/_verify2.py`，沙箱实测）：
- 原子 status=`machine-verified`（无人签），claim_structured 写一条纯法理推断（例："X 法理上意味着一个需要标准推断才能成立的结论"），`claim_type: observation`，evidence 挂一张带 `run_match_file` 的合规卡；
- **实测：block=0**（仅 artifact_version 迁移 warn）。同内容若标 inference 且无人签会 block——分流阀的全部强度压在 Writer 的一个自报字段上。
**现实印证**：样板 FENCE-001 的 prop-1"阻止编译器消除该循环"标 observation，这其实是"机制归因"（编译器为什么消除、屏障为什么阻止），严格说是 inference——专家都在边界上摇摆，机器无判据。
**结论**：524 强度匹配铁律的第 1 档"observation 纯机验自动 verified"当前**不成立**；它等价于"Writer 想全自动就写 observation"。这不是要 LLM 判真伪（那违反 Oracle 铁律），而是 observation 的定义需要**可机器执行的活性判据**（见 529 P0-2）。
**同构族**：自标 observation / 把 inference 命题挂到别人带工件的卡 / external_basis token 宽松匹配（`_BASIS_TOKEN_RE` 允许任意 6 位英文标识符在独立来源 ref 里出现即登记，gate_engine.py:1981-2020）。

## B.8 增量 manifest 指纹不含 .out【实证·新中危】

`card_fingerprint`（replay.py:1486-1507）只 hash 卡内容+fixture+artifact，**不含 run_match_file 指向的 .out**。

## 总结判断（给建设者，不带情绪）

系统在"字节层不可骗"这条线上已经相当成熟，P0-A/名册/三分类/毒样例回归构成了真实护城河；**但 528 批次把资源投在了"字段填充率"（claim_structured 27/27、概念表 157），并以填充率宣告 L3 点火——实测填充率 100% 而语义能力 0%（概念不连通、观测可自标）**。下一步最高 ROI 不是再写层、再铺字段，而是 3 个"让已有结构兑现承诺"的小改动 + 1 个 L2 最小队列骨架；同时停止 warn 整体 accept。详见 529 提示词。
