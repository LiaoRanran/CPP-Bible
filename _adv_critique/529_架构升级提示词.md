### P1-3 L2 调度最小骨架：单文件 SQLite 队列（到子命令粒度，不要 Supervisor）
**为什么现在做**：524 层3 的三件套里，唯一在单人/单模型下就有真实收益的是"幂等任务+断点续跑"；多模型路由/Supervisor 没有第二模型与无人值守前提，现在做是空转。

**数据结构**（新文件 `tools/task_queue.py` + `data/tasks/queue.db`，gitignore 同 tasks/）：
```sql
CREATE TABLE tasks(
  id TEXT PRIMARY KEY,            -- 幂等键（dedup_key: 同 type+payload_hash 只入队一次）
  type TEXT NOT NULL,             -- atom_produce/redteam/replay_batch/...
  payload_ref TEXT NOT NULL,      -- 指向仓库内任务文件（不把长 prompt 塞库）
  status TEXT NOT NULL,           -- queued/claimed/done/failed/blocked
  priority INTEGER NOT NULL DEFAULT 100,
  deps TEXT NOT NULL DEFAULT '[]',-- 前置任务 id（JSON 数组），未 done 不可 claim
  claimed_by TEXT, claimed_at TEXT, heartbeat_at TEXT,
  attempts INTEGER NOT NULL DEFAULT 0, result_ref TEXT, error TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
```
**首版子命令**（全部纯本地、零新依赖、原子事务 `BEGIN IMMEDIATE` 保证并发 claim 不重领）：
- `enqueue --type --payload-ref [--priority] [--deps id,...] [--id]`（同 id/dedup_key 已存在→打印已存在并退出 0，幂等）
- `claim --worker <名> [--types t,...]` → 输出一个 deps 全 done 的最高优先级 queued 任务 JSON，原子改 claimed/attempts+1/heartbeat
- `heartbeat <id> --worker <名>` / `done <id> --result-ref` / `fail <id> --error` / `blocked <id> --reason`（worker 必须与 claim 者一致才能改，防串）
- `list [--status] [--json]` / `next`（=claim 的只读预览）
- **stale 接管**：claimed 且 heartbeat 超 600s → 下次 claim 可被重新接管回 queued，attempts 保留；attempts>3 自动 blocked（防无限重试）。
**与 task_state.py 关系**：task_state 保留为"长任务进度笔记本"，task_queue 只管"谁该干什么/干完没"；v1 由人执行 `task_queue next` 手动派给当前会话（不做自动 Supervisor Loop）。

**验收机器判据**：pytest ≥6 例：①enqueue 幂等（同键两次只一条）②claim 并发/串行不重领（两连接争抢同一行只一个成功）③deps 未完成不可 claim ④非 claim 者 done 被拒 ⑤heartbeat 超时可接管 ⑥attempts>3 进 blocked。N=1 行为与 task_state 不冲突；`data/tasks/` 不进 git。
