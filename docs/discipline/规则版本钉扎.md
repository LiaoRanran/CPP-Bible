# 规则版本钉扎（D1）

> 门禁：`G-RULES-PINNED`（L0）；工具 `tools/rules_manifest_671g.py`；
> manifest `data/rules_manifest_671g.json`；红路径 `tests/test_d1_rules_manifest_671g.py`。

## 问题

判决产物只写"67 条规则"，不写**哪一版**。规则增删后，旧判决无法判断"按当时规则该是什么结果"，
可复现性断裂。

## 机制

每个判决产物（JSON）必须带：

| 字段 | 含义 |
|---|---|
| `rules_version` | 语义化版本 MAJOR.MINOR.PATCH（当前 `1.0.0`） |
| `rules_sha256` | 规则元组（id/title/severity/kind/basis/quadrant/scope/automated/meta）按 id 排序后的规范化哈希（**排除 check 函数对象**） |

manifest 还钉：`engine_file_sha256`（tools/gate_engine.py 文件哈希）、count、severity 分布、rule_ids、
effective_date、supersedes。

## 流程

```bash
python tools/rules_manifest_671g.py --generate            # 生成/重生成 manifest
python tools/rules_manifest_671g.py --check             # 校验与现行规则一致
python tools/rules_manifest_671g.py --stamp data/671g/verdicts/v1.json
```

* 规则变更 → `--generate --version X.Y.Z --supersedes <旧版>`（语义化：判据语义变更 bump major/minor）；
* 旧判决在规则升级后：保留但必须能在 supersedes 链上追溯；stale sha 的判决门禁直接 block；
* 当前现行：67 条（block 44 / warn 16 / advice 7），manifest `1.0.0`。

## 边界

* 只钉判决规则（gate_engine.RULES），不钉检测器代码本身（检测器版本进产物 env 字段）；
* verdict 目录 `data/671g/verdicts/` 不存在时门禁视为"无判决"（不判红），出现即强制钉扎。
