# 评估过拟合防御（E3，回测教训）

> 门禁：`G-NO-OVERFITTING`（L0；三集合未映射时 warn，框架就位）；
> 工具 `tools/overfitting_defense_671g.py`；配置 `data/671g/eval_split.json`；测试 `tests/test_e_671g.py`。

## 金融回测教训

量化策略在历史数据上反复调参，回测漂亮、未来失效。规则工程同形：在测试集上反复改规则直到检出率好看，
数字就是"挑出来的"。

## 三道防线

1. **三分离**：train / validation / test 三个 id 集合**两两不相交**；测试集只用于最终一次评估；
2. **调参登记**：每条规则每次参数调整必须登记 tuning_set，**只能 train/validation，禁 test**；
3. **多重检验校正**：同一数据集 m 次假设检验必须报校正后的结论：
   * Holm（逐步降权）控制 FWER：`holm(pvals, alpha)`；
   * Benjamini–Hochberg 控制 FDR：`benjamini_hochberg(pvals, alpha)`；
   * 不许只挑显著的那一条报。

## 现状（诚实）

holdout/corpus 是 reveal **盲测集**（test 角色），规则孵化在 atoms/draft 与训练资产；
完整三集合 id 映射待论文批次细化（配置含 note，门禁 unarmed/warn）。新规则在盲测集上调参视为违规。

## 用法

```bash
python tools/overfitting_defense_671g.py --check
python tools/overfitting_defense_671g.py --holm 0.001,0.02,0.5,0.9
python tools/overfitting_defense_671g.py --bh 0.01,0.02,0.03,0.9
```
