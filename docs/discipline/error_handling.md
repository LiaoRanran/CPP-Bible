# C5 · 错误处理规范（666 批）

> **一句话**：这套系统里最贵的错误**不是崩溃，而是静默**——
> 把"不知道"渲染成"没问题"，比直接抛异常危险得多。

## 1. 两种失败模式，各有归口

| 类别 | 策略 | 理由 | 例 |
|---|---|---|---|
| 判决 / 供应链 / 账本 | **fail-closed** | 这些路径的"通过"是结论的基石，宁可拒判 | 缺依赖、缺证据文件、哈希不符、解析失败、schema 不认 |
| 报告 / 诊断 / 观测 | **fail-open（但必须显形）** | 报告缺失不该阻断合并，但**不许**悄悄少一项 | 观测日志写盘、advisory 报告、快照缺失 |

**判据**：问一句"如果这条错了，会不会让一个错结论看起来是对的？" 会 ⇒ fail-closed。

## 2. 三态必须分开（`unknown` 是一等公民）

```
pass       证据齐、判据满足
fail       证据齐、判据不满足
unknown    证据不齐 / 仪表不可用 / 环境不支持   ← 不得降级为 pass，也不得并入 fail
needs_review 需要人（例如机器卡无人签）
```

**反模式**：
- ❌ `except: return "pass"`（把异常当通过）；
- ❌ 把 `miss`（仪表报了但没命中）与 `unknown`（仪表根本没跑）合并统计 ——
  MSan 全缺、TSan 在 WSL 间歇 FATAL 都会制造这种混淆；
- ❌ `ok = not findings`（空结果不等于通过，可能只是没扫到）。

## 3. exit code 约定（CLI）

| code | 含义 | 谁用 |
|---|---|---|
| `0` | 判据满足（或只读自检通过） | 全部工具 |
| `1` | **判据不满足**（有 FAIL 项） | 门禁/审计类 |
| `2` | **环境不可用**（缺编译器/缺依赖/无法建立仪表） | 真跑类（如 645 无 g++） |

> `2` 的存在是为了**不让环境问题伪装成结论**：`645` 缺 `g++` 时返回 2，
> 而不是"编译失败 ⇒ 结论错"。

## 4. 错误消息的四要素

`[工具] ✗ <现象> —— <判据> ；<怎么修>`

例：`[F2] ✗ 投影差值 5 != 低成本可补 9 —— 投影只吃 low 档；检查 liveness_completion_613.load_low_cost()`。

**必须**包含修复线索；**禁止**只写 `assert False` 或裸 `OperationalError`。
（`prop_graph` 遇旧库时给"跑 build 自愈"的指引，是本条的正例。）

## 5. 日志与留痕

- 观测日志走 `CPPBIBLE_OBS`（默认关；测试里显式关掉以避免写盘）。
- 结构化报告落 `data/*.json` + `data/*.md` 成对出现：机器读 json，人读 md。
- 报告顶部必须写**生成命令与时间**（可复算入口）。

## 6. 数据损坏 vs 口径漂移（本批新增）

两者**不同**，处理也不同：

| 现象 | 判定 | 处置 |
|---|---|---|
| HMAC 不符 / 哈希链断裂 | **篡改** | fail-closed，红线 |
| 记录内容无法解析 | **损坏** | fail-closed + 报修复路径 |
| 记录有效但输入哈希对不上当前工作区 | **漂移**（历史记录的正常属性） | fail-open，**单列显形**（如 `vsa_inputs_current`），不得报"无效" |
| 计数/快照与当前测量不符 | **口径漂移** | 更新快照 **并**交代旧值的下场（历史快照 / 作废），见 C6 |

## 7. 红线

- 不允许"为了绿"把 fail-closed 改成 fail-open（必须走 ADR + 人审）。
- 不允许在没有对照的情况下把 `unknown` 写成 `miss`。
- 不允许在报告里省略"环境不可用"的样本（`2` 比"假 pass"好）。
