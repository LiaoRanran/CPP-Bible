# 误报率"胸腺"（阴性选择）（D3）

> 门禁：`G-FP-THYMUS`（L0；无带代码检查器的规则时 unarmed，只 warn 不阻断）；
> 工具 `tools/false_positive_thymus_671g.py`；配置 `data/671g/thymus/config.json`；
> 正确代码库 `data/671g/thymus/clean/`；红路径 `tests/test_d3_thymus_671g.py`。

## 隐喻

胸腺对 T 细胞做阴性选择：攻击自身正常组织的细胞不出胸腺。每条**会对 C++ 代码判错的规则**发布前，
必须先在"已知无缺陷代码库"上跑误报率：

* 误报率 **< 5%（10 条以上正确样本）** ⇒ pass，可发布；
* 误报率 **≥ 5%** ⇒ block，不许发布；
* 样本不足（< 10）⇒ inconclusive（warn），**不许带过**；
* 检查器在正确代码上**崩异常也算误报**（不可用检查器不许发布）。

## 边界（诚实登记）

* 现行 67 条判决规则是**卡内容/治理规则**（gate_engine.RULES），**不是可对 .cpp 运行的静态检查器**
  —— 因此当前胸腺对它们 **unarmed**（门禁显形为 warn，不是假装覆盖）；
* 今后新增**带 .cpp 检查器**的规则（LLM fuzz 孵化出的新检测器尤然），必须在 config 注册
  `"checker": "tools/<mod>.py::<fn>"`（fn(path)->bool，True=判缺陷），否则发布不受胸腺约束；
* 正确代码库准入：人工确认无 UB/内存/并发缺陷 + sanitizer 双档无告警 + 来源/确认人登记，达到 10 条。

## 用法

```bash
python tools/false_positive_thymus_671g.py --register-rule R-ID --checker tools/x.py::check
python tools/false_positive_thymus_671g.py --check
```

## 历史误报率登记

67 条现行规则无 C++ 检查器，**无法直接计算历史误报率**——本批不编造。相关历史教训：
变异 kill 是内部指标、holdout 对照误报盲测 1/9（累计 2/11，见 `data/671g_数字真实性核查.md`）
是检出器在 holdout 对照上的误报，不是规则在正确代码库上的误报，两者勿混。
