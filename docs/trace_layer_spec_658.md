# 658 H1 · 轨迹层规格设计（v41 结论落地，P1 仅设计不实现）

> v41 结论：agentic 时代，错误在**多步轨迹**上，不在单点断言上。本段只做规格设计。

## 1. 轨迹是什么
一条**验证轨迹** = 验证器为得出某卡判决而经历的有序步骤序列：
`[观察证据 E1] → [调用规则 R_a] → [中间结论 C1] → [引用引文 Cit_x] → [调用规则 R_b] → [最终判决 V]`。
每一步带：输入、所用工具、引用、输出、时间戳。

## 2. 轨迹错误分类
- **T1 单点断言错**：某步输出错（现有层已覆盖）。
- **T2 步骤遗漏**：该调 R_b 没调（652 T2 假开关同类）。
- **T3 引用断裂**：步骤引用了 Cit_x，但 Cit_x 与结论无逻辑支撑（H2 反事实算子要抓的）。
- **T4 顺序/依赖错**：R_a 必须在 R_b 前，顺序反了导致误判。
- **T5 循环/自引用**：轨迹成环（ch28 自引用同类）。

## 3. 轨迹验证 vs 断言验证的关系
- 断言验证（现有 four_state）是轨迹验证的**投影**：只看最终 V，不看路径。
- 轨迹验证在**路径层**补 T2–T5，是断言验证的超集。
- 不替代：能跑通轨迹验证前，断言验证仍是 L0 红线。

## 4. 数据形态（供 H3 小核查器复用）
每条训练样本 = `{card, trajectory: [step], final_verdict, error_type (none/T1..T5)}`。
本批只定 schema，不实现轨迹采集器（交人：需 instrument gate_engine 记录步骤）。
