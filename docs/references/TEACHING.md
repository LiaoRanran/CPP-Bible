# 教学标准（CPP-Bible 的「声音」与写法）

> 定位：本文件是全书**教学语言与文风**的硬性标准，与 `AGENT.md`（工程纪律）、`SOURCING.md`（引用可溯源性）、`Chapter Template`（`chXX_template.md` 结构）并列。
> 硬核（证据、标准、门禁）已经就位；本文负责让硬核**被读进去、被记住、被信任**——即「人味」。
> 适用范围：`Book/` 147 章 + `Part0_Prerequisites/` 全部；现有章节（C1–C4、A1–A6）按本文 retrofit。

## 一、总纲：硬核与人味不矛盾

人味的本质不是形容词，是**作者在场**。三种在场，缺一种就塌：

1. **亲手跑过**（证据）——本手册的签名：每条机制都配真机产物（`objdump`/实测输出/退出码），可复现。没有「理论上」。
2. **踩过坑**（事故现场）——真实 UB、真实崩溃、真实 CERT 案例。不是「注意：此处有风险」，而是「这是一段尸检报告」。
3. **读过来路**（历史注脚）——为什么它长成这样：标准化政治、被 UNIX 逼出来的妥协、谁反对过谁。

> 立场：文采最足的从来不是辞藻，是「**我亲手跑给你看**」。当一章同时有真机证据 + 一个事故现场 + 一处历史注脚，它天然有人味，无需额外修辞。

## 二、每章叙事骨架（固定，但允许微调）

沿用全书的成熟骨架，顺序即节奏：

1. **① 我们真正要回答的问题**——先抛真问题（不是「本章介绍 X」），把读者拽进悬念。
2. **判决先行**——能在开头给结论就给（C1「先给判断」、C2「先给结论」）。读者带着结论看证据，记忆更牢。
3. **证据压阵**——原理 → 真机汇编/实测 → 反例。每个「为什么」配一段可复现产物。
4. **边界与代价**——什么时候不对、什么被牺牲、什么未定义。绝不把结论说满。
5. **小结 + 移交下一章**——留钩子（「下一章讲 X，正是在这层上再走一遍」）。

> 防止枯燥的技巧：每 3–4 段放一个小钩子（反直觉事实 / 一个问题 / 一句可动手的指令）。禁止「教科书式平铺」：定义→性质→例子的流水账。

## 三、五条写作定律

1. **比喻守恒律**：比喻必须保留原概念的**拓扑关系**（结构对应），且删掉它正确性不受损（它是糖不是骨架）。
   - 好：`影子空间` = 调用者在门口摆好的四把椅子，名牌写好了谁坐哪、坐多久（调用者清栈）——对应、生命周期都对得上。
   - 坏：「栈像一摞盘子」——比喻本身没错但无信息增量，且掩盖了「栈向低地址生长」这一关键事实。
2. **数字与真机说话**：写 `4294967295`、`0x4886_8A60`、`80 bytes`、`0xC0000374`，不写「很大的数」「某个地址」「一些开销」。有人味的是具体。
3. **让读者动手**：每章至少一个「你现在就可以做」的小实验（Compiler Explorer 敲两行看 `-O2` 怎么撕；本机 gcc 跑 demo 看退出码）。参与感 = 记忆。
4. **声音分寸**：第一人称克制；**承认灰度**（「没有标准答案，我的选择是 X，因为 Y」——本手册用 `[经验]` 标注承载）；幽默只**自嘲**，绝不嘲读者（读者写错是自然的，帮他绕开，不笑他）。
5. **先具体后抽象**：先给一个能跑的反例/现象，再抽象出规则。认知负荷一次只放一个反直觉点。

## 四、盒子体例（可选，宁缺毋滥）

盒子是人文层的标准容器，**放段尾或边栏，不挤占正文事实密度**。

- **`> 历史注脚：`** —— 落真实文献（`ritchie:chist` / `hopl:*` / `qcon:*`）。只写可核实的事实（年份/人名/决策），不写感想。例：Hoare「十亿美元错误」（C5）。
- **`> 事故现场：`** —— 带可复现程序或已登记案例键（`cert:` / `ubsan:` / `so:`）。例：UAF 尸检（C5）。
- **`> 立场：[标准]/[经验]/[实现·x86-64]`** —— 已有标注体系，继续用；区分「标准规定」与「我的取舍」与「实现细节」。
- **`> 一语` / `> 类比` / `> 坑`** —— 来自 one_liner/analogy/pitfall 体系（147/147 已建），一句话收口。

## 五、红线（人味的防腐层）

1. **禁止编造轶事**：包括「某年某月有人在论坛问过……」这种句子。没有出处不写。人文素材与事实素材**同等可溯源**（挂键，见 `SOURCING.md` §3.9）。这是本手册与口胡自媒体的分界线。
2. **人文不稀释事实**：盒子之外，正文事实密度不许降。一章最多 1–2 个盒子。
3. **反公式化**：盒子是可选，不是每章强制。**宁可 30 章有，不可 147 章齐刷刷**——强制全覆盖 = 公式化，公式化是人味的天敌。
4. **术语一致**：与 glossary（385 条）对齐；首现给英文。不过度拟人、不油腻、不上价值、不翻译腔（少用「被」，用短句）。
5. **可证伪**：每条断言必须能被一段真机输出/标准条款/文献事实推翻或证实。写完后自检（见六）。

## 六、写后自检清单（可证伪）

- [ ] 本章有没有至少一处**真机证据**（汇编/输出/退出码）？没有 → 补 demo 或标 `[待补 demo]`。
- [ ] 有没有一处**承认取舍/边界**（`[经验]` 或边界段）？
- [ ] 每个**历史注脚**是否挂了真实键、且只写可核实事实？
- [ ] 有没有**编造的轶事/没出处的「传说」**？有 → 删。
- [ ] 比喻删掉后，正确性是否受损？受损 → 比喻承载了事实，改写。
- [ ] 数字是否具体（`4294967295` 而非「很大的数」）？
- [ ] 术语是否与 glossary 一致、首现给英文？
- [ ] 是否给了读者一个**可动手**的小实验？

> `check_citations.py` 查引用键不查文风；文风靠本清单 + 人审。两者都过，才算「硬核且有人味」。
