## 1. 核心贡献定稿（4 条，每条带证据）

> **建议**：把现有 C1–C3（纯形式化）扩为 **C1–C3 + C4（可证伪的实证协议）**，
> 因为本文在 E&D 赛道真正的差异化是**「把'我们更好'变成一个能被一次实验否证的问题」**。

### C1 · 失败驱动验证能力演化的形式化（monotonicity / minimality / auditability）

| 项 | 内容 |
|---|---|
| **我们做了什么** | 把验证器演化定义为 $\mathcal{C}_{t+1}=E(\mathcal{C}_t,F_t)$，$F_t$ = 已登记的 `miss ∪ unknown`；给出**三条可检验性质**：单调性（$\mathrm{cov}$ 不减）、最小性（每条新规则可追溯到登记失败）、可审计性（失败→规则→复测三元组成链） |
| **别人做过什么** | 变异引导测试生成（ACH/MUTGEN）用**变异反馈**驱动**测试生成**；benchmark 自演化（Benchmark Self-Evolving 等）用**模型反馈**驱动**题目改写**——**都不演化"证据获取能力"本身** |
| **差异化** | 演化的对象是**尺子（$\mathcal{C}$）**，不是题目也不是测试；且演化输入被**约束为已登记失败**（禁止无失败依据的规则膨胀） |
| **证据** | §4.0 定义 1–3；§4.6 闭环；§4.7 **EE = 1.9pp/规则**（现算，命令见附录 D）；§6.2/§7.6 **A0−A5 证伪条件** |
| **薄弱点** | EE 是**描述性速率**（跨批、双口径），不是同批配对效应量——论文已显式声明（§4.7 双口径警示）✅ |

### C2 · 四态判决的信息论分析（`unknown` 一等公民）

| 项 | 内容 |
|---|---|
| **我们做了什么** | 把 `pass/fail/unknown/contradict` 建模为隐变量对 $(y,d)$（断言真值 × 检测器可用性）的部分编码；证明「分母 = catch + miss」是唯一不污染估计的口径 |
| **别人做过什么** | ① **Belnap (1977) 四值逻辑 FOUR**：`Both`/`None` 与本文 `contradict`/`unknown` **同构**——这是**形式语义先例**，**必须引用**（见任务 C 的 M8）；② Rice 定理给出「sound + complete + 终止」三不可兼得，为 `unknown` 提供**定理级辩护** |
| **差异化** | Belnap 给的是**逻辑语义**；本文给的是**统计口径分析**（合并 `unknown`→`miss` 系统性低估、→`pass` 造假阴性）+ **实证**：口径消融显示 external 影响达 **10.8pp**（43.3%–54.2% 之间读者可自由发挥） |
| **证据** | §3.2；§4.0 定义 4；§6.3 口径消融表（A/B/C 三臂同批重算） |
| **建议强化** | §4.2 加一句：「四态不是工程便利，而是 Belnap 双格 FOUR 在'真值序 × 信息序'两个正交序上的投影」并 `\cite{belnap1977useful}` |

### C3 · 可审计性的三条件形式化（来源可溯 / 状态可复现 / 篡改可检）

| 项 | 内容 |
|---|---|
| **我们做了什么** | 给出三条件：$\forall v\,\exists(e,r): v=R_r(e)$（可分解为规则×证据）；第三方可从落盘产物重建判决时刻输入；受控目录任一修改改变 Merkle 根 + 账本 append-only |
| **别人做过什么** | ① **de Bruijn 判据**（独立小校验器传统，40 年）；② **SQL Server 2022 Ledger / Google Trillian**（工业级防篡改账本，API 禁 UPDATE/DELETE）；③ 溯源审计（Kao 2025 / Wang 2026） |
| **差异化** | 本文把三条件**绑成一条可被外部打断的链**，并把「完整性 ≠ 正确性」显式拆开（Merkle 证明账本未篡改，**不证明判决正确**）——这一条**主动写进威胁模型**（T1 残余） |
| **证据** | §4.4 provenance/scope 拆分（26 卡，provenance 26/26、scope 0/26）；§4.5 对账器；§9.1 #3（5 Merkle 根一致、452 账本零改） |
| **薄弱点** | 🔴 **Merkle 未声明 RFC 6962 域分隔**（0x00/0x01）；🔴 **账本哈希未声明 RFC 8785 JCS 规范化**；🔴 **452 账本事件不含 `rules_manifest_sha256`** ⇒ 第三方拿今天的规则无法复算历史判决。见 §3 |

### C4 · 同批配对的三臂对照 + 可证伪的 ablation 协议（E&D 差异化）

| 项 | 内容 |
|---|---|
| **我们做了什么** | ① 在**同一批样本**上做 FD / Static / Random（真 B3）三臂**配对**对照（精确 McNemar + Cohen's h + Δ CI）；② 把核心机制的可否证条件**预写**成六组 ablation，其中 **A0−A5 的 CI 跨 0 即否决核心机制** |
| **别人做过什么** | 大多数自演化/验证系统**报告自己定义的成功指标**，不提供「本机制可被一次实验推翻」的协议 |
| **差异化** | 本文的卖点不是「我们更好」，而是「**我们更好是可被否证的**」——且我们**主动承认当前样本量跑不出可判读的 Δ** |
| **证据** | §6.1 三臂表；§6.5 统计检验（FD vs Static：p 3.05e-5/3.81e-6，h 1.80/0.87；FD vs Random：p 6.10e-5/7.63e-6，h 1.61/0.81）；§6.2/§7.6 判读规则 |
| **薄弱点** | 🔴 合并陈述的统计量取错（应为 p≤**6.1e-5**、h≥**0.81**、Δ≥**23.8pp**，非 3.1e-5/0.87/25.7pp）——见任务 B 的 B7/B4 |

## 2. 贡献陈述模板（可直接落笔，中英对照）

> **中文**：本文的贡献不是「一个更强的验证器」，而是**把「验证器有多强」变成一个外部可度量、可被第三方打断、且可被自己否证的问题**：
> **(C1)** 失败驱动演化算子 $E(\mathcal{C}_t,F_t)$ 的形式化（单调/最小/可审计）；
> **(C2)** 四态判决的信息论口径分析（`unknown` 一等公民；分母 = catch + miss）；
> **(C3)** 可审计性三条件（来源可溯/状态可复现/篡改可检）；
> **(C4)** 同批配对三臂对照 + 预注册的 ablation 否证协议。
> 我们**不声称**首个实现、**不声称**优于真正的静态检测器、**不声称**绝对检出率。

> **English**：Our contribution is not "a stronger verifier" but making *"how strong is a verifier"* an **externally measurable, third-party interruptible, and self-falsifiable** question: (C1) a formalization of failure-driven evolution; (C2) an information-theoretic caliber analysis of the four-state verdict; (C3) three conditions for auditability; (C4) a same-sample paired three-arm contrast plus a pre-registered falsification protocol. We claim **neither** first-ever implementation, **nor** superiority over real static detectors, **nor** absolute detection rates.

## 4. 威胁模型增补（写入 §3.3 T13–T16 / §8）

> 现有 T1–T12 完整；以下 4 条来自 671c/671f，**均有真实 CVE/实证支撑**，建议补入。

### T13 · Peeking / 选择性停时（Statistical 层）

| 项 | 内容 |
|---|---|
| **威胁** | 账本逐条累加而检出率按快照报告，混用即 peeking；56% 心理学家承认看结果后决定是否补数据（John/Loewenstein/Prelec 2012），power posing 的「25→10→7→5」分块是教科书案例 |
| **缓解** | 统计计划冻结 + **e-process/置信序列**作为扩样协议的**预先承诺**（与 §3.1 联动） |
| **残余** | 无强制机制阻止事后选择 μ₀ ⇒ 必须**预注册** μ₀（如 baseline 实测率），**禁止事后挑最有利的 μ₀** |

### T14 · 评测污染的四层模型（External 层，**补强现有 T3**）

| 项 | 内容 |
|---|---|
| **威胁** | 污染分**字面 / 近重复 / 语义 / 流程**四层，可「**虚高但可复现**」——哈希链一致、对账器一致、复现逐行跑通，**共同复现的仍可能是泄露答案** |
| **缓解** | ① **配对反事实探针**：同一断言只改变量名/编译器/版本/证据顺序，原题高而变体骤降即疑似记忆；② 开封事件日志；③ 四层去重（sha256 → n-gram/MinHash → embedding） |
| **差异化** | 现有 T3 只讲「样本泄漏」，本模型更完整 |

### T15 · LLM 通道不可信（prompt injection / 对抗样本）（Internal 层）

| 项 | 内容 |
|---|---|
| **威胁（真实 CVE）** | ① **CVE-2025-59145 CamoLeak**：Markdown 隐藏注释经 Copilot 外泄密钥，**CVSS 9.6**；② HiddenLayer 对 Cursor 的 README `<!-- -->` 注释攻击；③ 间接注入：InjecAgent ReAct GPT-4 ASR **24%**、BIPIA Code QA **52.77%**；④ AI 文本检测通道被引导改写后最强检测器 **T@1%F 平均降 87.88%** |
| **缓解（三层）** | 提示级：spotlighting/datamarking（不可信文本每行加前缀）；结构级：StruQ 结构化查询；**架构级：LLM 输出永不直接成为判决**，必须过确定性 schema 校验（字段白名单），**ML 检测只 warn 不 block** |
| **结构性卖点（建议原句入文）** | 「**注入最多污染'证据加工'，污染不到'判决复算'**——因为判决全部程序化、由不依赖内核的对账器核对。这是本文 gate 架构的结构性优势。」 |
| **残余** | 触点登记表未做（每个 LLM 触点两问：是否消费不可信文本/输出是否可入账本） |

### T16 · 小样本投毒 / 供应链（External + Internal 层）

| 项 | 内容 |
|---|---|
| **威胁（决定性变量是绝对条数）** | **250 条**恶意文档（**0.00016% token**）即可稳定植入后门，100 条不够、250 条稳成——**决定变量是绝对条数而非占比**；本项目 holdout 22 / corpus 60 的规模**正落在该区间，无安全边际**。另有：干净标签投毒不掉准确率（Witches' Brew：1% 预算 90% 成功率而验证精度仍 92.2%）⇒「指标正常」不能放行；语义层污染（改写版进 prompt，n-gram 去重失效）；**流程层污染**（看测试集分数选规则）——虚高但可复现 |
| **缓解** | ① **canary 金丝雀卡**（少量只有作者知道答案的标记卡混入候选流）；② 配对反事实探针；③ 四层去重；④ 对账器使用**与内核不同的依赖集**（破解供应链投毒"自证清白"）；⑤ 候选按不可信代码处理，沙箱运行 |
| **残余** | 被动清洗不可靠（3% 投毒即可把错误率 3%→24%）⇒ 只能当第一道滤网 |

> **建议**：T13–T16 每条给「威胁 / 缓解 / 残余」三列，与现有 T1–T12 表同构。
> **克制提示**：若篇幅（9 页）不允许，**优先级 T15 > T16 > T13 > T14**
> （T15/T16 是审稿人最可能追问的「你们处理 LLM 不可信输入了吗」）。

## 6. 「我们做了什么」vs「别人做过什么」对照表（可直接进 §2）
