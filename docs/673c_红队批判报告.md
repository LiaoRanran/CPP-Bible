## 1. 新颖性批判 —— **5 / 10**

### 1.1 核心贡献究竟是什么

论文 §1.3 自述三贡献：C1 失败驱动验证能力演化的形式化（三条性质）；C2 四态判决的信息论分析；C3 可审计性的三条件形式化。系统落点是"67 条规则 + 452 账本 + Merkle"的可执行系统。

### 1.2 逐条攻击

**攻击点 1（最致命）：名为"形式化"，实为"术语化"——全篇零定理、零证明。**

C1 的三条性质（单调性 / 最小性 / 可审计性）在 §4.0 定义 3 中只是**对演化算子的约束条件**：

> "**最小性**：$E$ 的每次应用必须由 $F_t$ 中**已登记**的失败触发——每条新增规则可追溯到至少一个登记失败（禁止无失败依据的规则膨胀）"（L156）

这本身没问题，问题是**论文从未验证这三条性质在当前系统上成立**。67 条规则里有多少条能追溯到登记失败？论文**不给这个数字**。§4.7 的 Evolution Efficiency 用"63→67 规则 / 80.0%→87.5%"算了个 1.9pp/规则，但那两个率**来自不同样本集**（§4.7 自己标了"双口径警示"）⇒ EE 不能用来验证最小性。

后果：审稿人会写——*"The authors define three properties but never verify them, nor prove anything about them. The 'formalization' is a vocabulary, not a theory."*

**对比已有工作**：
- QuickCheck / Hypothesis（属性测试）：**演化的是属性集**，失败驱动（shrinking）是其核心回路。本文的"失败驱动"与 PBT 的 counter-example-driven refinement **在机制层面同构**，差别只在"被演化的是验证器而非属性集"。这个差别论文在 §2 表格里用一行"演化的对象：验证器能力 $\mathcal{C}$"带过——**一行表格不足以支撑一个贡献**。
- KLEE / SymCC（符号执行）：路径探索同样由"未覆盖分支"驱动，同样是失败/未覆盖驱动的证据获取。本文**完全没有引用任何符号执行工作**（§2 六条线里一条都没有）⇒ 审稿人若来自程序分析背景，第一句话就是"这和 KLEE 的 search heuristic 有什么区别"。**这是相关工作最大的空洞。**
- CELEUS（e-value / 序贯检验）：论文 §4.8 已诚实声明不声称首创，定位合理。但差异声明太弱（见 §3）。

**攻击点 2：C2 的"信息论分析"名不副实。**

§1.3 C2 原文：

> "**C2 · 四态判决的信息论分析（§4.2）**：把 `pass/fail/unknown/contradict` 视为对'断言真值 × 检测器可用性'两个隐变量的编码；分析每种合并方式（`unknown`→`pass`、`unknown`→`miss`）引入的信息损失及其偏差方向"（L61）

但 §4.2 与定义 4（L158）**全文没有一个比特、没有一个熵值、没有一次互信息计算**，只有四行表格 + 一段"合并会怎样"的定性讨论。**"信息损失"是隐喻，不是度量**。

更麻烦的是首创性：四值逻辑（Belnap 1977）、数据库中的 NULL 语义（Codd）、程序分析的 lattice（top/bottom/unknown）、定理证明器的 "unknown/don't know" 应答——`unknown` 作为一等公民是**至少四十年的常识**。论文在 §2 定位表里给六个相关工作全部打"四态判决：否"，却**不引任何四值逻辑 / 抽象解释文献**，这会被读成"故意不引以降低新颖性门槛"。

**首创性声明裁定**：
- ❌ "e-process 首次用于代码验证" —— 论文**没有这样声称**（§4.8 明确否认），✅ 站得住（因为没声称）。
- ⚠️ "规则版本钉扎" —— §4.4 自述"仿 Confluent Schema Registry"，且**当前实现是 manifest 级、452 条存量账本未回填**（L210）。⇒ 这是**已存在工程模式的移植 + 未完成的实现**，不能算贡献。
- ❌ "四态判决" —— 见上，站不住。
- ⚠️ "失败驱动验证器演化" —— 与 PBT/符号执行的 counter-example-driven refinement 同构，** novelty 在于"演化对象"的移位**，但论文未把这个移位做成可检验的命题。

**攻击点 3：会被判为"工程实现而非研究贡献"吗？—— 会，而且风险很高。**

证据：论文大量篇幅在系统与治理细节（67 规则的 severity 分布 44/16/7、L0 7 个 / L1 10 个门禁、射程自检 5/5、Merkle 5 目录、452 账本、semantic scope 0/26）。这些是**软件工程与项目治理**，不是研究。而研究部分（C1/C2/C3）**只有定义、没有定理、没有实验**。

审稿模板里那句 *"This is a well-engineered system paper, but I don't see a research contribution"* 是本稿**第二大概率**的拒稿理由。

## 2. 实验设计批判 —— **4 / 10**

### 2.1 致命结构问题：**核心机制的证伪实验没跑，而"显著"的数字全部来自无关对照**

论文自己在 §6.2 写明：

> "**A0 − A5（失败驱动 vs 同预算随机选资产）是唯一能证伪核心主张的对照**——若其 Δ 的 CI **跨 0**，则'失败驱动优于随机预算'**不成立**"（§6.2，L358–361）
>
> "**现状：设计已冻结、实验 0 组已跑**"（L301）

而摘要与 §9.1 的"显著"结论全部来自 §6.1 的三臂对照。论文自己在 §7.2 承认了这组对照与核心机制无关：

> "**FD 的优势来自两处**：① 运行时证据（sanitizer 在 WSL 里真编译真运行）；② 失败驱动演化（把漏检转成新增检测能力）。本实验只能分离出①（Static vs FD 的差就是'有/无运行时证据'），② 需要 ablation（§6.2，**已设计、未跑**）"（L527）

⇒ **推论**：Δ(static→FD) = +80.5pp 测的是"有 sanitizer vs 没有 sanitizer"，**与"失败驱动"无关**。论文花了整节篇幅报四个 p ≤ 3.0×10⁻⁸ 的数字，而这四个数字**没有一个能支撑论文标题里的"失败驱动"**。

审稿人只需要问一句：*"If I remove failure-driven selection and just enable sanitizers, do your numbers move at all?"* —— 论文的答案是"不知道，因为没跑"。

这是**本稿第一大概率的拒稿理由**。

### 2.2 基线选择：遗漏了更强的对照

| 缺失基线 | 为什么必须比 | 论文现状 |
|---|---|---|
| **clang-tidy / cppcheck / clang static analyzer** | 这是"真正的静态检测器"的现成代表。论文 §9.2 Claim 3 说"不能支撑优于真正的静态检测器"，理由是"真 detect_static 未暴露"——但**社区有现成的**，不需要自己实现 | 完全未比 |
| **LLM 直接判断（多模型）** | 论文 §6.7 做了，但只 GLM-4 单模型单 prompt、n=20、且 `answer_leak_risk=true` 未分离 | 跑了但不可用 |
| **sanitizer 全开（无失败驱动选择）** | 这正是 A5。也是"运行时证据 vs 失败驱动"的分离实验 | **未跑** |
| **人类专家基线** | C++ UB 判定的人间基线（例如让 3 位 C++ 工程师判同一批 41 条） | 0 人（论文承认 IRR 未做） |

尤其 **clang-tidy**：本稿最容易被一句话击穿的地方是"82.9% 听起来很高，但 clang-tidy 在同一批 planted UB 上能抓多少？"。论文**完全没有这个数**，而这是审稿人第一个会问的。

### 2.3 LLM 臂：结论下得比数据硬

§6.7 表：LLM 12/12 vs FD 6/12，对照假阳 4/8，配对 McNemar **b=0, c=6, p=0.031**，论文写：

> "**配对精确 McNemar** | b=0, c=6, **p=0.031** | — | **LLM 显著'更好'**"（L485）

问题三连：
1. **n=20、p=0.031 是边缘显著**，且样本是"id 升序、非随机"（论文自己写，L478）⇒ 不是随机样本，McNemar 的配对随机性假设不成立。
2. **"LLM 显著更好"这个读法与 §6.7 的结论自相矛盾**：结论段（L487）说"LLM 更灵敏但特异性低……不能直接当判决用"，而表格判读列写"LLM 显著更好"。**同一个实验，两处结论方向相反。**
3. **`answer_leak_risk=true` 未分离**（L490）⇒ 12/12 里有多少是"读题"未知。既然未知，就不该用这个 12/12 去做统计检验并得出"显著"。

最省事的处理：**把 §6.7 的统计检验整段删掉，只留描述性登记 + 两条警告**。这个臂的定位是"T15 的实证"，不是"另一个基线"。

### 2.4 外部锚定 H2：诚实，但假设本身设计有问题

§6.8：A 层 28.6%（35 条）、B 层 80.0%（15 条）、**合计 44.0%**，H2 阈值 45% ⇒ 差 0.8pp 未过，论文"如实登记为未通过"。

诚实度 ✅。但**设计上有硬伤**：

- **自相矛盾**：§6.8 正文写"**两部分子集必须分列**（目标类不同，不可合并成一个数读能力）"（L505），紧接着表格给出**合计行 44.0%**，而 **H2 的判定正是用这个合并数**（阈值 45%）⇒ **用一个自己声明"不可合并"的数去判假设**。若按"必须分列"，H2 根本没有定义（A 层 28.6% 和 B 层 80.0% 各自对什么阈值？）。
- **B 层 80.0% 是上界**：B 层片段是"由我方按准则重建的 UB"（`verified_source=false`）。⇒ H2 的实测值里有一半是**自造样本**，外部锚定的"外部性"只剩 A 层 35 条。
- **抽样方式未随机化**："按文档顺序扫 87 条规则，同一规则只取一条可编译片段" ⇒ 这是**便利抽样**，不是概率抽样。CI [14.6, 46.3] 是在"这 35 条是从某个超总体随机抽出"的假设下算的，该假设**不成立**。
- **prelude_v1 是方法补充**（L509）：原样可编译率仅 11/60 ⇒ 给 49 条片段注入了标准头 + `using namespace std`。这是**改了样本**，且 `using namespace std` 本身可能引入/掩盖问题。论文登记为"偏离预注册"✅，但未评估这个偏离对 28.6% 的方向性影响。

### 2.5 消融设计本身的漏洞

- **B3 与 A5 概念重复**：§5.2 B3 = "同等预算下随机扩充证据"；§6.2 A5 = "失败驱动 → 随机选资产"。**同一个对照，两个名字**。而论文在 §5.2 写"三臂**已跑**"（L284）、在 §6.2 写 A5"实验未跑"（L356）。读者必然困惑：到底跑了没跑？673a 声称修了 §5.2/§5.3 的矛盾，**这一处没修干净**。
- **A1 用 git 历史回退规则集** ⇒ 657 时点的规则集跑在 672h 的样本上，但 672h 的样本是在 671a/672h 阶段才种的，规则集与样本集**时间上不匹配** ⇒ A1 测的是"旧规则在新样本上"，而非"去掉失败驱动"。
- **A2 需新建划分** ⇒ 新建的 dev/blind 划分与论文主结果用的 holdout **不是同一批** ⇒ A2 的结果无法与主结果对话。
- **六组 ⇒ 15 对**（L383）：C(6,2)=15，但**主对比只有 5 对**（A1–A5 各 vs A0），其余 10 对是组间交叉，无假设支撑 ⇒ 用 15 对去做 BH/Holm 会**稀释主对比的校正力度**。

## 3. 统计严谨性批判 —— **4 / 10**

### 3.1 e-value / 序贯检验：用得可疑

§4.8（L772–780）：把账本事件视作二值序列，对零假设 $\mu_0$ 与备择网格做似然比混合，得 e-process；实测 FD vs Static 的 e-value **2.5×10⁸**（holdout）/ **1.8×10⁷**（corpus）。

**问题 1：关键参数全部未给。** 论文说"对零假设 $\mu_0$ 与备择网格做似然比混合"，但**通篇没有出现 $\mu_0$ 的数值、备择网格的定义、混合先验**。而 e-value 的大小**对这些选择高度敏感**——备择网格若含接近 1 的 $\mu$，在连续 catch 序列下 e-value 会指数爆炸。2.5×10⁸ 主要反映的是"观测率 82.9% 远离某个未声明的 $\mu_0$"，**不是可复算的证据强度**。审稿人会直接要求删掉这个数。

**问题 2：论文自己说 $\mu_0$ 必须预注册，但没做。** §3.3 T13（L133）：

> "**无机制强制 μ₀ 事前选定 ⇒ 必须预注册 μ₀**"

这是**已知的未决项**，而 §4.8 照样报了 e-value。⇒ 自己违反自己登记的纪律。

**问题 3：anytime-valid 与固定样本检验混用。** §4.8 说 e-value 定位是"扩样过程的安全带 + 跨批证据合并器，不是主结果检验"（L780）。但 §8 Statistical 行（L592）把"必报差值 + CI + 效应量 **+ e-value**"并列为主报项。⇒ **口径自相矛盾**：一处说不是主检验，一处列进主报项。

**问题 4：与 CELEUS 的差异声明太弱。** 论文说"CELEUS 把 e-process 用于 LLM 评测以省样本（54–62%），本文用于知识断言判决账本的任意时刻有效性 + 第三方离线复算"。但**数学是同一套**（都是似然比混合上鞅 + Ville 不等式）。差异只在**应用场景**（评测 vs 判决账本）。审稿人会问："既然数学相同、且你说是初步探索未进 CI，这一节对本文的贡献是什么？"

### 3.2 多重比较：主结果表未校正

§6.5 给了四组对比的 p 值（2.3×10⁻¹⁰ / 3.7×10⁻⁹ / 1.9×10⁻⁹ / 3.0×10⁻⁸），**没有做任何校正**。而论文 §6.2（L383）与附录 B（L723）都声明"多重比较：探索性 BH-FDR / 确认性 Holm"。

四组对比**不独立**（同一批 FD 结果，两个检测集 × 两个基线），检验族应该预定义。虽然 p 都在 10⁻⁸ 量级、Holm 校正后仍显著，**做与不做的结论相同，但纪律上必须做**——而且论文已经把 BH/Holm 工具化了（`ablation_stats_671b.py`），没理由不做。

### 3.3 Δ CI 用了自己在附录 B 禁用的方法

附录 B（L720）："**禁用小样本 Wald**"。

§6.5（L452）："差值 CI | 配对 **Wald-on-difference** / 独立 **Newcombe 混合**"。

⇒ 四个主 Δ CI（[68.4, 92.6] / [33.1, 57.5] / [59.6, 86.7] / [28.6, 52.7]）**全部是配对 Wald-on-difference 算的**。在 p₁=0.829 / p₂=0.024 这种极端比例下，**Wald 差值的覆盖率显著差于名义 95%**，且 CI 端点可能出现越界（这里没越界是因为 Δ 离 100 还远，但 corpus random 臂 [28.6, 52.7] 的 Wald 假设在 n=64 上已经偏弱）。

论文其实**有更好的工具**（Newcombe 混合），却只在独立样本上用。**应该用配对的 Newcombe / 或基于精确 McNemar 的 CI**。

### 3.4 Cohen's h 的阈值误用

§6.5 把 h = 1.98 / 0.97 / 1.65 / 0.85 全部标"（大）"，依据是 Cohen 的 0.2/0.5/0.8 阈值。

但：**Cohen's h 的 0.2/0.5/0.8 阈值是为"两个独立比例、比例处于中等范围"设计的**。当 p₂ = 2.4%（1/41）时，arcsine 变换在接近 0 处的导数趋于无穷，h 会被**系统性放大**。用一个"极端比例 + 配对设计"下算出的 h = 1.98，去套"大效应"的标签，是**跨设计套用阈值**。

论文 §7.1 第 6 点（L522）已经有"效应量标签必须按阈值读"的教训，但**没有意识到阈值本身的适用边界**。这是一个更细的漏洞，但对统计背景的审稿人是显眼的。

### 3.5 样本量数字：同一量两个值 + 列错位

- §6.5 表（L463）："| 检出 Δ=10pp（独立两臂） | **376/组** |"
- §7.3 表（L535–536）：列头是"| ±10pp CI 半宽所需 n | 检出 10pp 差异所需 n/组 |"，holdout 行填 **61 / 236（±5pp）**，corpus 行填 **97 / 378（±5pp）**
- 摘要（L34）与附录 E（L811）："±5pp 半宽需 holdout **236** / corpus **378**"

⇒ **378 是"±5pp CI 半宽所需 n"，却被填进"检出 10pp 差异所需 n/组"这一列**，并在单元格内自标"（±5pp）"来自救。**376 与 378 是两个不同量的值，出现在相邻两节，读者必然误读为同一个数。**

更根本的问题：**样本量计算公式从未给出**。236 用 Wald 正态近似 $n = z^2 p(1-p)/e^2$ 算 p=0.829, e=0.05 得 ≈ 218，用 Wilson/CP 半宽迭代会得到不同值。**不写公式 ⇒ 不可复算**。论文在附录 E 说"逐条可复算"，但样本量这一条**复算不出来**。

### 3.6 只报召回，不报精确率

全文报的都是检出率（recall）。唯一对照的假阳率是 **FPR 18.2%（2/11）**，n=11，CI [2.3, 51.8]。

⇒ 论文**从未给出 FD 在同一批样本上的精确率**（在 41+11 条上，FD 报警的样本里有多少是真错）。18.2% FPR 意味着约 1/5.5 的对照样本被误报，而**这个数没有进入任何主结论**。审稿人会问："a detector with 18% FPR and 82.9% recall — what's the precision on your actual sample mix?" 论文答不上来（因为对照样本只有 11 条，且**只在 corpus 侧或 holdout 侧中的一个**，论文没说清这 11 条来自哪个集合）。

### 3.7 统计严谨性 · 三个最可能被攻击的点

| # | 攻击点 | 证据 | 严重度 |
|---|---|---|---|
| S1 | e-value 的 $\mu_0$ / 备择网格 / 混合先验**全部未声明**，而论文自认 $\mu_0$ 必须预注册却未做 | §4.8 L776–778；§3.3 T13 L133 | 🔴 致命 |
| S2 | 四组主对比**未做多重比较校正**，而论文已声明 BH/Holm 口径并已工具化 | §6.5 L430–435 vs §6.2 L383 / 附录 B L723 | 🟠 高 |

## 5. 可复现性批判 —— **5 / 10**

### 5.1 WSL 硬依赖：可复现性的致命伤

§9.3（L631–633）：

> "| 1 | holdout / external 检出率 | **WSL + g++ + `setarch`**；缺 WSL 静默掉分（669d 历史：35.0%→10.0%） |"

⇒ 论文的**两个核心数字**（82.9% / 62.5%）在**没有 WSL 的 Windows 原生环境**下不仅复现不出，**而且会静默降级为 unknown 而不报错**（§7.1 第 2 点，L518）。

后果按平台拆：
- **Linux**：`setarch -R` 有 ⇒ 可复现（但未验证过）。
- **macOS**：**没有 `setarch`**（BSD 系无此命令）⇒ **不可复现**。
- **Windows 原生**：实测 `cannot find -lubsan`（MinGW-w64 未带 UBSan 运行库，652 G3）⇒ **不可复现**。

⇒ 在 NeurIPS 的评审池（Linux 居多，但 macOS 评审人比例不低）里，**相当比例的复现尝试会直接失败或静默出错**。"诚实登记"不能抵消这一点——审稿人的复现失败就是复现失败。

**更糟的是"静默"**：缺 WSL 时不是报错，而是把 15 条样本降级为 `unknown`，external 从 35.0% 掉到 10.0%，**护栏仍绿**（L518）。⇒ 一个复现者可能拿到 10% 并写进 review，而**没有任何东西警告他环境错了**。

### 5.2 匿名化 vs 可复现：自相矛盾

论文说"仓库路径匿名化为**通用描述**"（L7），但附录 D（L738–755）给的是：

```
python tools/holdout_reveal_5_672h.py
wc -l data/authority/decision_event_v2_ledger.jsonl  # 452
python -c "import json;d=json.load(open('data/current_numbers.json',...))"
```

⇒ 这些是**具体路径 + 具体文件名**。匿名化版本把这些改成"通用描述"后，**命令就不可执行了**。审稿人拿到的复现包若真的匿名化，就**无法复现**；若可执行，就**没匿名**。二选一。

（附带：`tools/holdout_reveal_5_672h.py`、`tools/baseline_670a.py` 这些文件名**本身就泄露作者与批次编号**，匿名化不彻底。）

### 5.3 预注册的漏洞

四个批次各有预注册（672f `prereg_672f.json`、672h `prereg_672h.json`、672i、672j），且**都先于实验单独 commit**（8da9c601 / 02f652ef / 04d8c344 / 65cfe0cd）——这点做得**很好**。

但漏洞有三：
1. **统计方法在预注册之后被"重做"**：672k 提交 `45e741a8` "统计检验重做（扩样后全量重算 + post-hoc power + e-value + 样本量）"。⇒ 预注册锁的是 McNemar + CP + Cohen's h，实际执行时**新增了 e-value 与 post-hoc power**。论文**没有提供"预注册 vs 实际执行"的差异对照表**。
2. **种子**：672f 统一 seed=20260930，但论文**正文从未写出种子值**（只在 data/ 产物与预注册文件里）。⇒ 正文层面的可复现性缺失——读者看论文无法知道该用哪个种子。
3. **§6.8 的 prelude_v1 是明确的方法补充**（偏离预注册），论文登记了✅，但未说明**这是本项目中第几次偏离**。若只有这一次，应明说"本项目共 1 次偏离"；若多次，应列表。

### 5.4 "双路径交叉复现"的说服力不足

§6.1/672h 的双路径：路径 B 是"**独立重实现**：不 import baseline_670a / stat_bounds / ablation_stats；CP 用二分法 + log-gamma 独立实现"（672h 报告 §3）。

这是**好的工程实践**，但**不是独立复现**：
- 两条路径**由同一作者**写（DCO 均为 LiaoRanran）；
- 两条路径**跑在同一台机器、同一个 WSL 环境**上；
- 两条路径**共享同一份输入产物**（`reveal_5_672h.json`）⇒ 只能验证**统计计算**正确，不能验证**判据与数据采集**正确。

### 7.2 最大的三个风险（按严重度排序）

> **风险 1（致命）· 核心机制的证伪实验没跑，而所有显著数字来自无关对照。**

> *动作*：投稿前跑 A5（接口已解阻）；跑不掉就在摘要明说；无论如何补 clang-tidy 基线。

> **风险 2（致命）· 标签效度 0 人复核，82.9% 悬空。**

> 两个核心数字在无 WSL 环境**不仅复现不出，还会静默降级**（15 条 → unknown，external 35.0%→10.0%）**而护栏仍绿**（§7.1 L518）。macOS 无 `setarch`、Windows 原生无 UBSan 运行库（652 G3）。匿名化与附录 D 的具体路径直接冲突。
> *动作*：复现脚本加 fail-loud 环境自检；附录 D 分匿名/完整两栏；正文补 seed；预注册差异对照表。

**这篇论文的诚实度足以让它被认真读完，但它的研究命题还没有被任何实验碰过。** 673c 二阶段（人味增强）能修掉写作与工程细节层面的大部分问题（W1–W8、被动语态、工程细节、失败案例），但**风险 1 与风险 2 只能靠补实验解决，写作层面无解** —— 这一点必须在 673c 的验收报告里如实写明，不得用"人味增强"掩盖。
