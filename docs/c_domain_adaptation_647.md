### 2.2 需要 C 专用规则的语义点（新增规则，**不改现有 67 条**）

规则层虽然大部分复用，但**"卡里该怎么写"**不同 ⇒ 需要一批**C 特有的卡级断言**（新规则，前缀建议 `C-*`）：

| 主题 | 为什么 C 与 C++ 不同 | 建议新规则（示例） |
|---|---|---|
| 指针与数组退化 | `sizeof(arr)` 在形参里退化是指针（C 无引用） | `C-ARRAY-PARAM-DECAY` |
| `malloc/free` 配对 | C 无 RAII ⇒ 生命周期靠人 | `C-ALLOC-FREE-PAIR` |
| 字符串函数边界 | `strcpy/strcat/sprintf` 无边界检查 | `C-STR-BOUNDED` |
| 函数指针与回调 | C 的主流抽象手段，C++ 有 lambda/虚函数 | `C-FNPTR-SIGNATURE` |
| `volatile` 语义 | C 的 `volatile` 用于 MMIO/信号，与 C++ 内存模型不同 | `C-VOLATILE-MMIO` |
| `setjmp/longjmp` | 跨栈跳转，C++ 里几乎不用 | `C-SETJMP-SCOPE` |
| 整数提升/符号 | `unsigned` 与 `int` 比较、隐式窄化 | `C-INT-PROMOTION` |
| 位域布局 | 实现定义（impl-defined）| `C-BITFIELD-IMPLDEF` |
| 宏卫生 | `#define` 无作用域 | `C-MACRO-HYGIENE` |
| 未定义行为面 | C 的 UB 列表与 C++ **不同**（如严格别名规则在 C 里更窄） | `C-UB-ENUM`（引用标准条款） |

**工作量估计**：**10 条规则 × 0.5 人日 = 5 人日**（含每条的反例与正例卡）。

### 2.3 编译与标准源

| 项 | 现状（C++） | C 需要 |
|---|---|---|
| 编译器探针 | `compiler_probe_645` 用 `g++/clang++` | 加 `gcc -std=c11/c17/c23` 与 `clang -std=c11/...`；**探针工具只需参数化 language**（约 0.5 人日） |
| 标准文本 | `standard_fetcher_645` 打 **eel.is/c++draft** | eel.is **没有 C** ⇒ 需新源：**open-std.org**（WG14 的 N 文档）或 ISO 公开草案；**授权/链接稳定性需人核**（约 1 人日 + 人裁决源） |
| 标准编号 | — | **C11 = ISO/IEC 9899:2011（N1570）· C17 = :2018（N2310）· C23 = :2024（N3096）** |

### 2.4 卡片语料（C 原子卡，第一批 10 张）

建议（每张都要"标准条款 + 真实编译器实测 + 反例"三件套）：

1. `C-PTR-DECAY-001` 数组退化与 `sizeof`
2. `C-MALLOC-PAIR-001` 动态内存配对与失败路径
3. `C-STR-BOUND-001` `strcpy/snprintf` 的边界语义
4. `C-FNPTR-001` 函数指针类型与回调
5. `C-VOLATILE-001` `volatile` 的真实语义（不是"多线程同步"）
6. `C-SETJMP-001` `setjmp/longjmp` 的作用域限制
7. `C-INT-PROMO-001` 整数提升与有符号/无符号比较
8. `C-BITFIELD-001` 位域布局是实现定义
9. `C-MACRO-001` 宏卫生（括号、求值次数、`do{}while(0)`）
10. `C-UB-001` C 的 UB 清单与 `-fsanitize=undefined` 实测
