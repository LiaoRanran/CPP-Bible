## A3-2 · 射程自检（改数必红）

### 方法

字节级备份 → 改一个数 → 跑校验 → **字节级还原** → `git status` 验证零差异。
脚本：`669d_audit/a3_tamper2.py`（改逐样本明细）、`a3_tamper3.py`（改汇总产物）。

> **踩坑记录（供后续复用）**：第一版用 `Path.read_text/write_text` 备份还原，
> 因 Python 文本模式默认做 `\n → \r\n` 转换，**内容逐字符相同但字节变了**，
> 导致 `git status` 仍显示 `M`。已改用 `read_bytes/write_bytes` + `shutil.copy2`，
> 还原后 git 零差异。后续所有改数实验必须用字节级方式。

### 结果 1：改**逐样本明细** `data/holdout/reveal_3_detail_668.json`（h1: catch→miss）

重算：87.5%（14/16）→ **81.2%（13/16）**

| 校验 | 基线 | 改数后 | 判定 |
|---|---:|---:|---|
| `test_drift_guard_668.py` | 0（绿） | **1（红）** | ✅ 有射程 |
| `test_caliber_check_669.py` | 0（绿） | 0（绿） | ❌ **无射程** |

### 结果 2：改**汇总产物** `data/holdout_reveal_3_665.json`（error_subset.catch 14→13）

| 校验 | 基线 | 改数后 | 判定 |
|---|---:|---:|---|
| `test_caliber_check_669.py` | 0（绿） | **1（红）** | ✅ 有射程 |
| `test_drift_guard_668.py` | 0（绿） | **1（红）** | ✅ 有射程 |

### 根因：`caliber_check_669` 读的是汇总，不是明细

`tools/caliber_check_669.py` 第 101 行：

```python
ho = _j("data/holdout_reveal_3_665.json")     # ← 汇总产物
es = ho["error_subset"]
add("holdout.valid", ..., es["catch"], es["catch"] + es["miss"], ...)
```

它**不读** `data/holdout/reveal_3_detail_668.json`（逐样本明细）。
所以它所谓的"现算"，实际是**在汇总产物内部自洽**（k/n 与 rate 对不对），
而非从最底层明细重算。

**风险**：若有人同时改汇总与文档并保持自洽，`caliber_check` 不会红。
缺口由 `test_drift_guard_668.py::test_holdout_detail_matches_summary`
（明细 ↔ 汇总比对）补上 —— 两层合起来才完整。

### 还原验证

```

git status: 空=零差异 ✅
```

| 字段 | `web/data/status.json` | 权威源 `counts_659` | 一致 |

| `rules.rules_total` | 67 | `len(gate_engine.RULES) = 67` | ✅ |

`37 / 47` 是 **659 批次之前的历史口径**（且把 atoms 当 cards，完全未计 71 张证据卡）。
当前权威口径应为 `atoms_real=42`、`cards_real=113`（含证据卡）。
前端展示的卡数比实际少 5 张实卡、少 66 张卡（含证据）。

> 这正是 B 段 `G-RATE-CONSISTENCY`（三处数字必须一致）要堵的口子 ——
> 本批已实现该门禁，可在下次运行时捕获此类脱节。

### 发现 3：`status_reconciler_658` 卡数口径把 README 算进去了

第 93–97 行：

```python
for _, _, files in os.walk(bd):
```

虽是小偏差，但性质是"同一事实源两套口径"，属于 B 段 `G-DENOMINATOR` 的治理范围。
