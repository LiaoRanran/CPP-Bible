# 常见问题 FAQ

**Q1：这跟普通的 C++ 教程/笔记有什么区别？**
普通教程说"这样是对的"，你得信作者。祈易每张卡都附带**真机编译/运行输出**作证据，加**复现清单**（编译器版本+命令+输入+期望输出），你 30 秒能自己重跑确认。信任链可被你亲自打断验证。

**Q2：为什么有些卡显示 unknown（未知）而不是 pass/fail？**
这是刻意的。**unknown = 检测器不可用或测量配置不对**，不是"没测出来就当失败"。把 unknown 偷偷降级成 pass 会污染结论，所以系统宁标 unknown。

**Q3：external 检出率为什么有两个值（35.0% 和 43.75%）？**
因为**分母口径不同**：35.0% 是 14/40（全部 40 个样本），43.75% 是 14/32（排除 5 个 unknown + 3 个"本就不是缺陷"的样本）。两个口径都给，结论随口径变——必须一起看，不能只挑好看的（详见 `_arch_v47/31`）。

**Q4：学习台会把我学的东西上传吗？**
不会。进度只存在你浏览器的 localStorage（键 `qy-learn-progress-v1`），可一键导出/导入 JSON，**不出本机**。导入时逐条校验，坏数据自动跳过并计数；默认"更靠前的进度优先"合并，不会被旧档案回退。换设备用导入功能迁移。

**Q5：为什么实验页的 baseline / ablation 显示"待生成"？**
因为那两部分实验（4 个对照系统 + 6 组消融）还没跑完（对应规划任务 A03/A04）。我们**不编造数字**占位，所以老实标注待生成（文案为"待670a生成"）。当前图表里的检出率/变异率/演化等都是已现算的真实值。字段契约（`queyi-baseline/v1`）已定好并写进 `docs/670c_前端完成度.md`，数据一落盘页面自动出现。

**Q6：需要联网 / 装依赖才能看吗？**
不需要。前端是零构建纯静态站，图表是自研 SVG / Canvas（没引 ECharts），数据在 `web/data/`。但必须用 http 打开（本地起 `python -m http.server 8000 --directory web`），因为 `file://` 会被浏览器的 CORS 拦住 fetch JSON。

**Q7：为什么 452 账本"零改"？**
那是人工审过的权威标注（LLM 判错→人纠正）。它是整个系统可信度的地基，所以划了红线：**任何批次都不得改动这 452 条**。改动会动摇可复算性。670c 的主门禁在 `--check` 模式下会对受控目录（`atoms/` `evidence/` `Examples/` `Book/` + 452 账本）做跑前跑后快照，实测 **1910 个文件、写入 0 处**。

**Q8：我可以贡献卡片吗？**
可以，走 DCO（提交加 `Signed-off-by`，见 README_v2）。新卡标准路径：写 atom → 配真机证据 → 写复现清单 → 过门禁 → 进卡库。

**Q9：星图 178 节点会不会卡？**
不会。670c 起星图改用 **Canvas** 渲染，并且**布局只在加载时算一次**（实测 60–130ms），之后按需重绘，没有每帧物理循环。1093 条边按"样式×权重档"分桶绘制，只有约 16 次 `beginPath/stroke`。另外做了防重叠：最近点对从 1.56px 提到 15.97px。`prefers-reduced-motion` 下动画全关。

**Q10：项目还没做完，现在看有意义吗？**
有意义。验证器、卡库、学习台、判决页、验哈希都是**已经能用的真功能**；论文和少数实验在补。你想看"一个知识验证系统长什么样"，现在就能看全貌。

## 关于"数字可信吗"

**Q11：你们说自己 87.5%、97.3%，我凭什么信？**
三条理由，都不需要你先信任我们：

1. **数字现算，不写死。** 前端只渲染，值来自台账文件（`data/holdout_reveal_3_665.json`、`data/656_mutation_report_core.json` 等），每个数的**来源文件、公式、分子分母**都随值一起给出。比如 holdout 87.5% 旁边写的是 `catch/(catch+miss) = 14/16`。
2. **有独立的复现审计。** 669d 做了一轮独立复现审计（见 `docs/669d_复现审计.md`、`docs/669d_门禁真实性.md`），并把它固化成 **6 条 P0 门禁**：G-RATE-CONSISTENCY（率与分子分母自洽）、G-DENOMINATOR（分母口径必须显式）、G-STATS-FROZEN（统计口径冻结，不许悄悄换）、G-BOUNDARY-REQUIRED（断言必须有边界三元组）、G-BASELINE-EXISTS、G-IRR。这些门禁可被你自己跑：`python tools/run_669d_gate.py`。
3. **一致性是被机器盯着的。** 670c 加了漂移监控 `tools/drift_watch_670c.py`：关键数字（卡数/规则数/账本数/holdout 检出率/corpus 检出率/变异率）**变化超 ±10% 且没有对应实验记录就标红**。

**而且我们把"自相矛盾"也公开登记**：670c 曾观测到 `web/data/status.json` 与 `web/data/verdicts_667.json` 对卡数给出不同值（37/47 vs 42/52）。查下来根因是 **status.json 是陈旧产物**——重跑一次构建管线后两者一致（42/52）。**陈旧产物会伪装成"数据矛盾"**，这正是加漂移监控的动因。我们没有把这条不一致藏起来。

**Q12：那你们还承认哪些"没做到"？**
都在明面上：
- baseline 对比与 ablation 六组**尚未落盘**（页面显示"待670a生成"，不编数字）。
- 仓库拆分的**内核层**已完成（CPP-Bible 侧是薄 wrapper，解析到 `queyi-verifier` 的 canonical）；但**判决/变异层**（`gate_engine.py` / `verifier_closure_*.py` / `mutation_*.py` 共 10 个文件）两侧各有一份**完整实现、当前逐字节相同**——这是 647 方案 §六 明确留交人裁决的债务。`python tools/check_split_670c.py` 会检查它们**有没有漂移**。
- 知识图谱里 **0/47 张卡带攻击边**（攻击边只存在于 misconception↔prop 之间），因此既有冒烟里"存在受攻击的卡节点"一条在改动前后**同样 FAIL**；我们没为了让它的变绿去改数据或改别人的脚本。
- 前端测试是 **Node 真求值 + jsdom 结构冒烟**，不等价于真实浏览器端到端测试。

## 关于"怎么复现"

**Q13：我想自己把这些数字跑出来，从哪开始？**
读 **[REPLICATION.md](REPLICATION.md)**。里面有精确环境要求（**WSL 是必须的**，因为外部 corpus 依赖 WSL 下的 g++ 交叉编译）、安装步骤、数据位置、逐条命令与**预期数字+CI**，以及常见问题（WSL 没装怎么办 / sanitizer 失败怎么办 / CRLF 问题怎么办）。

一键版：
```bash
python tools/reproduce_all_670c.py              # 门禁 → holdout → corpus → 变异 → 反事实 → fast 测试
python tools/reproduce_all_670c.py --skip-slow  # 跳过慢测试
```
每一步记录命令、退出码、输出摘要与"是否匹配预期"；**某步失败不中断**，继续跑后面的，最后输出 `data/reproduction_report_670c.json`。

**Q14：我怎么确认数据文件没被换过？**
用 `data/dataset_hashes_670c.json`：里面是所有数据文件的 SHA256、大小、生成时间与 commit SHA。逐文件核对即可。数据集的结构化元数据（含每个文件的字段定义）见 `data/croissant_670c.json`（Croissant 格式，NeurIPS E&D 赛道要求）。
