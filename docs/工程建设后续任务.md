## P1 · 测试效率优化（672f暴露的问题：全量pytest要60+分钟）

### 问题
672f验收时跑全量pytest（`-m "not slow"`），Windows上17分钟只到27%，预计全量60+分钟。
核心验证（40+新增断言+658/669d/guard门禁）已全绿，全量回归里的失败是预存的，和本批无关。

### 三层优化方案

#### 第一层：立即能用（不改代码）✅ 已完成（672h，2026-10-01）
- 每个批次只跑**相关测试文件**+门禁，不跑全量pytest
- 命令进化：`python tools/fast_gate.py --tests tests/test_xxx.py`（门禁+本批测试一把过，<5分钟）
- 全量回归交给CI，本地不跑

#### 第二层：建立两级测试体系 ✅ 已完成（672h，2026-10-01）
- 快速门禁（本地，<5分钟）：`python tools/fast_gate.py --all`
  = 658门禁 + 669d门禁 + 671a guard + 全部非slow测试（可选前端 node web/run_tests.mjs）
- 全量回归（CI，<30分钟）：全部pytest（含slow）+ 前端断言 + 构建验证
- 具体做法（已完成项）：
  1. ✅ `pyproject.toml` 加 `markers = ["slow: 耗时>10s的测试，默认跳过"]`
  2. ✅ 给单测 >10s 的测试打 `@pytest.mark.slow`（WSL编译、全量重跑类；明细见本文件 §672h）
  3. ✅ 新建 `tools/fast_gate.py`（含自测 `tools/test_fast_gate.py` 16条）
  4. ✅ 批次流程默认用 fast_gate（AGENT.md 工作纪律已写入）

#### 第三层：根治（长期）
| 优化点 | 效果 | 工作量 |
|---|---|---|
| pytest-xdist并行（`-n auto`） | ✅ 已完成（672h）：本机已装 xdist 3.8，`--all` 默认 `-n auto`；非slow全量 60min串行 → **≈5.7min** | 10分钟 |
