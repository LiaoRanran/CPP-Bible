# ADR-0001：原子稳定 ID 方案

- 状态：**已接受**（2026-09-10，G1）
- 决策人：人（DRQ-3 选 A），执行：架构师

## 背景

原子库需要一个长期稳定的标识，用于：交叉引用、学习路径 DAG、证据绑定、评审点名、迁移追溯。

## 候选

**A. 域前缀 + 序号**：`ATOM-{DOMAIN}-{SHORT_TOPIC}-{NNN}`，例 `ATOM-MEM-MOVE-001`。
- 优：人可读、可在会议里点名、域信息自带、排序稳定。
- 劣：拆分/合并需维护迁移表；序号分配需中心化（防冲突）。

**B. 内容寻址**：`sha1(规范断言文本)[:12]`。
- 优：天然去重、无需中心分配、同义改写自动识别（其实是劣：改写即变 ID）。
- 劣：不可读、不可念、评审无法点名；同义改写产生新 ID，反而制造"同一论断两个 ID"。

**C. 纯自增序号**：`ATOM-0001`。
- 优：最简单。
- 劣：无域信息，重排/分域后毫无语义；与"按域组织"的目录结构脱节。

## 取舍

选 **A**。决定性理由：**教材要被人讨论**。ID 会在评审、issue、会议里被点名，"MOVE-001 这条有问题"必须能说出口。hash 做不到这一点。

代价是必须维护 `atoms/id_migrations.json`，我们接受——迁移是低频事件，而点名是高频事件。

## 否决理由

- 否 B：不可读是硬伤，且"改写即变 ID"与规则 3（同义改写保留原 ID）直接冲突。
- 否 C：与按域目录结构脱节，且无法从 ID 判断归属，后续分域治理会失控。

## 后果

- 正面：ID 自带域信息，`ls atoms/mem/` 与 ID 中段一致，双向可查。
- 负面：新增原子需查域内最大序号防冲突 → 需一个 `atoms` 写入工具（G5 实现）或人工核对。
- 约束：三条强制规则（入库后不变 / 拆分合并不改原 ID 只登记迁移 / 同义改写保留原 ID）必须由 G3 门禁强制，否则规则会腐化。
