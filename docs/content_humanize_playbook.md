# CPP-Bible 内容人文升维 · 方法论（Playbook）

> 目的：在「硬核技术 + 真实编译取证」既有铁律之上，给每一章叠一层**人文/历史动机**叙事，
> 并把代码注释、习题、应用章节做到"能读、能抄、能落地"。本文件是后续 147 章铺开的统一标准。

## 0. 总原则（不可越界的红线）

1. **不伤干货**：历史动机是"前置叙事"，不是稀释技术核心。技术论述、D5 基准、ASM 证据、交叉引用一律不删不改。
2. **不增章数**（项目铁律）：所有扩写在**现有章内**插入新节/段，绝不新建 `ch*.md`。
3. **不增空洞 cpp 块**（项目铁律）：每个代码块要么可独立编译（CI 绿），要么是有价值的注释/示意块。
4. **实证可复现**：所有性能/行为论断仍走「本机真实编译器取证 + 上游源码 URL 行号」双轨。

## 1. 每章"历史动机"叙事模板（人文关怀层）

在章首 `## ① 概述` **之前**插入 `## ⓪ 历史动机：<X> 的来龙去脉`（应用章/历史章可放在概述之后）。
叙事要素（按章取舍，但至少覆盖 1–4）：

1. **痛点起点**：在该特性出现之前，工程师真实面对什么麻烦？（具体场景，不空泛）
2. **关键人物与时间线**：谁、在哪一年、因何创造？（真实姓名/公司/年份，可查证）
3. **转折点**：哪一版/哪一事件让它定型或被广泛采用？（如标准采纳、许可证变更、开源）
4. **为什么是它**：对比同时代替代方案的取舍（为什么 C++ 选择这条路）
5. **今日坐标**：它现在活在哪里、被谁用（真实产品/项目），给读者"学这个有用"的锚点

写法：用 `> 历史动机` blockquote 起头 + 2–4 段 prose，丝滑过渡，不堆砌年份。
**禁忌**：编造无法查证的人物/数据；用"约""据记载"等模糊词替代不确定事实。

## 2. 代码块"详细注释"规范

- 每个教学 `cpp` 块：块首用 `//` 说明"这段在演示什么"；关键行逐行注释**为什么**这样写（不是复述代码）。
- 易错点必须注释：UB 边界、生命周期、ABI、平台差异。
- 保留既有 `[标准]/[实现]/[平台]/[经验]` 标注体系，新注释不与之冲突。

## 3. 习题升级模板（从算法 → 应用 + 引用）

旧范式（淘汰）：纯算法题（如"写个 max 模板"）。
新范式（目标）：**真实场景题 + 可查证引用**。每题结构：

```
### 练习 N（难度 ★★/★★★）
<真实工程场景描述，点明"这会在哪里遇到">

<details><summary>答案与解析</summary>
<可编译 cpp 块（CI 安全）>
[标准] <ISO 条文/行为依据>
[引用] <真实文档/论文/开源项目 URL，可查证>   ← 新增：把习题接到真实世界
</details>
```

引用来源示例（真实可查）：
- Qt 官方文档：`https://doc.qt.io/qt-6/<topic>.html`
- Unreal 官方：`https://dev.epicgames.com/documentation/...`
- ISO 标准草案：WG21 论文 `https://www.open-std.org/jtc1/sc22/wg21/docs/papers/...`
- 真实开源项目（Chromium/Boost/LLVM 源码 URL）

## 4. 应用章节（Qt / Unreal / Chromium / Boost …）扩写规则

用户明确："像游戏引擎、Qt 这些具体应用章节可以无限细致扩写实际使用和历史。"
在本 Playbook 下，应用章扩写 = **历史动机（第 1 节）+ ⓪ + 真实工程使用场景（新增 ㉑ 节）**。

### 4.1 CI 安全代码规则（关键！）

编译门禁（`tools/chapter_compile_check.py`）对**每个** ```cpp 块：剥离 `#include`（仅保留
`<experimental/simd>`/winsock/windows），注入标准 prelude，独立编译。**真实第三方头**
（`#include <QObject>`、`#include <Unreal/...>`）会导致块失败，需走 `compile_exempt.json` 豁免。

为保持 CI 绿色、不膨胀豁免表，扩写代码遵循：

| 目标 | 手法 | 是否编译通过 |
|------|------|--------------|
| 演示框架**概念**（如信号槽分发、UObject 反射） | 用**标准 C++ 等价实现** + 空宏 shim（仿 ch134 的 `UCLASS()/GENERATED_BODY()` 空宏） | ✅ 通过 |
| 展示**真实 API 写法**（`QPushButton`、`AActor` 等） | 写成**仅注释的 cpp 块**（`// 真实 Qt 写法：...`），门禁按空块编译 | ✅ 通过 |
| 必须含真实第三方头且无法 shim | 显式加入 `tools/compile_exempt.json`（诚实豁免，不偷偷失败） | ⚠️ 豁免 |

> 经验：应用章扩写优先"标准 C++ 等价 + 注释呈现真实 API"双轨，既绿又教真东西。

### 4.2 真实使用场景（㉑）内容清单

- 该框架/库**今天被谁用**（3–5 个真实产品/项目，含汽车座舱、影视虚拟制片等行业外案例）
- 一个**端到端小例子**：从"包含头/宏"到"跑起来"的关键步骤，配详细注释
- 与标准 C++ 的边界：哪些必须靠框架、哪些能用标准库替代（呼应 ch41/ch39）

## 5. 铺开顺序建议（后续批次）

1. **应用章先行**（用户点名）：Qt(ch129)、Unreal(ch134)、Chromium/Abseil(ch130)、Boost(ch128)、LLVM(ch127)。
2. **核心语言/库章历史动机**：part03–part10 每章加 ⓪，重点 ch22(auto)/ch27(cast)/ch41(智能指针)/ch61(模板)/ch115(移动)。
3. **习题升级**：每章在现有 Exercises 段追加 1–2 道"应用+引用"题（不删旧题，旧题保留作基础）。
4. 每批编辑后跑 `python tools/chapter_compile_check.py <章>` 确认零新增失败。
