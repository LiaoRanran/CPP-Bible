#### （c）4 个工程细节（v1.1 §4.9）

1. **为什么用 WSL 而不是原生 g++**：本机 MinGW-w64 **未带 UBSan 运行库**，链接期实测 `cannot find -lubsan`（652 差啥清单 G3）⇒ 只能用 WSL 的 gcc。代价三重：Windows 原生复现不出；**macOS 连 `setarch` 都没有**；**缺 WSL 时静默降级 `unknown`（external 35.0%→10.0%）而护栏仍绿**。
2. **tectonic 下载两次被截断**：本机无任何 TeX 发行版，自备自包含引擎 **tectonic 0.15.0（19 MB）**；zip **两次截断**，第三次才成功。教训：**二进制依赖必须校验字节数后再解压**。（任务书记载的 6.7 MB 截断值**在仓库产物中核验不到，故本稿不引用该数值**——同一条纪律也适用于我们自己的笔记。）
3. **437 个 `Examples/*.cpp` 的 CRLF/LF 漂移**：证据哈希对**文件字节**取 sha256 ⇒ 一次换行符漂移让历史哈希全部失效（DEBT-002，"碰到即转" + `.gitattributes`）。直接关系 §4.4 的"状态可复现"。
4. **多 Agent 并行写区冲突**：672g 的 `c5baff7f`（新建 fast_gate + 7 处 slow 标记）与 672h 的 `88ff505d`（"补齐 c5baff7f **在途快照**之后的工作"，21 个文件 +35 处标记 + fast_gate 终版）**动同一套文件**，且两者**同时写** `docs/工程建设后续任务.md`。**侥幸没冲突**——靠声明而非设计。教训：并行批次必须先把"谁写哪个文件"写进任务书。

#### （d）个人判断 / 诚实声明（v1.1 §7.9）

- **相信但未验证（4）**：e-process 适用于判定账本（μ₀ 未预注册）；失败驱动在同预算下优于随机（**A5 未跑**）；VC/EE 的构念效度（无人验证 VC 高⇒判得准）；provenance/scope 拆分能防误用（**scope 0/26，零数据支持**）。
- **故意不做（5）**：全程序静态分析（复杂度；代价是对编译期不可见问题结构性盲视）；形式化证明（代价：给证据不给保证）；多语言（代价：C++ UB 是**最容易被检测器看见**的一类，换语言大概率不成立）；训练判决模型（会与被判对象共享失效域，T15）；把变异得分当检测率（代价：少一个好看的数 96.5%）。
- **做了但效果不好（4）**：**LLM 裁判臂**（结果与预期相反，假阳 50%，单模型单 prompt，`answer_leak_risk` 未分离 ⇒ **v1.1 已删去其统计检验**，因 n=20 非随机子集上的 p=0.031 不支持"显著"，且原表格判读列与结论段方向相反）；**semantic scope 回填 0/26**；**OTS 时间锚仍是占位**；**护栏的最后一个洞**（666 事故形态今天仍能重演——v1.0 诊断了病、承认药无效、却继续用这个药）。
