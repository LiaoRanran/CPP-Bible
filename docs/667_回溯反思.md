## 2. 关键失误与教训（逐条给证据）

### 2.1 656 变异测试："变异没进射程"的假象　[已查证]

- 现象：core 62.5%（30/48）/ all 28.8%（15/52），远低于 80% 目标。
- 真相：不是内核抗变异强，而是**变异体根本没被任何测试执行到**。
- 证据：`tools/mutation_test_656.py` 的 `--check` **射程自检**（放宽 `_HASH_RE` 必须被杀）——
  **首版存活** ⇒ 直接照出"变异体未进射程"。
- 教训：**任何"覆盖率/检出率"类指标，必须先自证"被测对象真的进入了判定路径"**，
  否则高分是空转。→ 规则 R4。

### 2.2 660 C2 holdout seed 标签过度声称　[已查证]

- 现象：对外说"holdout 20 个样本"，其中**真错只有 7 个**。
- 证据：`data/holdout_reveal_3_665.json::compare_reveal_2` —— `before_total: 7, before_rate_pct: 80.0`；
  665 报告 C1 明写"真错 7 → 17"。即 20 个样本里 13 个是"标签 unknown / 非真错"。
- 后果：**80%（4/5）这种小分母数字一度被当成能力证据**；分母构成一变，率就从 80 掉到 66.7。
- 教训：**样本集必须同时报"样本数 / 真错数 / 可测数"三个数**，只报一个是过度声称。→ 规则 R2。

### 2.3 665 corpus 43.8%：不是算术错，是**分母没声明**　[已查证（本批修正了 brief 的表述）]

- 实测：`catch 14 / miss 18 / unknown 5 / not_error 3`，`detect_rate_pct = 43.8`。
- 现算：`14 / (14+18) = 43.8%` ✔、`14 / (40−5−3) = 43.8%` ✔、`14 / 40 = 35.0%` ✘。
- ⇒ **算术自洽**。真正的缺陷是：产物与前端都写"**40 条** 43.8%"，读者按 40 一算得 35.0%，
  于是"43.8% 算术不自洽"的怀疑本身就是**分母未声明**造成的。
- 教训：**每一个比率都必须把分母写成字段（`denominator`），不能只在注释里说**。→ 规则 R1。

### 2.4 666 三个链路自污染缺陷　[已查证]

| 缺陷 | 机制 | 为什么危险 |
|---|---|---|
| 钩子自污染 | `pre-push` 跑 `compile_gate.py`，它会**写受控目录** `Examples/atoms/*.asm`，随后钩子又查"受控目录必须干净" ⇒ 自锁 | **守护者自己破坏前置条件**；且第一次处置（接受 gate 产物 + 重钉）是错的，正确处置是"照卡声明的命令重建" |
| 数据被抹 | 665 G1 手工往 `web/data/status.json` 追加字段，而 `web_status_655.py` 会重写该文件 ⇒ 下次 `--build` 必丢 | **凡生成器会重写的文件，字段必须由生成器产出** |
| OTS 循环 | `tool_integrity --update` 重写 `merkle_roots.json`，而 `.ots` 锚的正是它 ⇒ 重钉一次、锚过期一次 | 两个"信任动作"互相使对方失效 |

- 共性：**都不是功能 bug，是"动作之间互相污染"**。这类缺陷单测抓不到，只有"跑一遍完整链路"才现形。→ 规则 R7。

### 2.5 B3 去写死的盲替危险（`test_prop_graph` 的 79）　[推断（部分已查证）]

- 已查证：`counts_659.PROPOSITIONS = 89`（扫卡面 `claim_structured`）；而历史快照里命题数是 **79**（640c：节点 121 = 命题 79 + 误解 42）；卡数同样有 **27（历史）vs 37（现算）**。
- 危险：一个字面量 `79` 在不同上下文里**指的不是同一个量**（历史命题数 / 图节点分量 / 断言期望值）。
  若"去写死"时直接把 `79` 换成 `89` 或换成"当前现算值"，就把**口径错位固化进了断言**。
- 666 的正确做法（应固化）：换成三种**不变量**之一 —— ① 事实源对齐；② 可加性/划分性；③ 结构不变量。
- 教训：**断言可以写死"口径"，不可以写死"测量值"**；替换前必须回答"这个数在原文里指哪个量"。→ 规则 R3。

### 2.6 标签本身是最大误差源　[已查证]

- 反事实算子的真值按 `external_anchor` 规则标注（standard ⇒ independent / measurement ⇒ dependent）。
- 666 新增判据"断言自报机器实测"⇒ F1 从 0 → **1.0**，但**判据与标签同源** ⇒ 这是**上界**。
- 同样的病：外部 corpus 的 `source` 只到类别级，`verified_source` 里有 false 项。
- 教训：**标签的可信度上限 = 打标签那套规则的可信度**；用同源判据去评估同源标签，得到的永远接近 1。→ 规则 R5。

### 2.7 检出率的"提升"多为改测量方法　[已查证（本批再加一条硬证据）]

| 次 | 变化 | 真相 |
|---|---|---|
| 665 | 20→30 样本，率 80.0% → 66.7% | **分母构成变了**，不是退步 |
| 666 A5 | 66.7% → 81.2%（声称双档 -O0/-O2） | 声称"没改一行检测器代码，只改档位" —— **但本批现算：产物里仍是 66.7%，且产物自述 -O1 单档** ⇒ **这次连"改完的口径"都没落到产物上** |
| 667 §0 | `--check` 报"✅ 与现算一致"，实际 holdout 字段差 14.5pp | **检查器没查关键字段** |
| 667 §0 | 反事实：第三判据**已写进** `counterfactual_citation_658.py`，但 `counterfactual_cases_665.json` 仍是旧算子（10 条 / F1=0.0），论文写 20 条 / F1=1.0 | **改了代码没重跑落盘** |

- 教训（最重的一条）：**改口径必须同时做三件事** —— ① 重跑并落盘产物；② 作废旧数字；
  ③ **把新数字纳入 `--check` 比对**。少任何一件，"改进"就是无源之水。→ 规则 R1/R6。

## 6. 给 1b 的三条硬约束（规划的准入条件）

1. **任何进入论文的数字，必须能在新克隆里用一条命令复现**；复现不了的一律降级为"登记项"，
   并在 Claim 边界表标 ❌（当前 81.2% 就是第一个受害者）。
2. **先解决"测量可信"，再谈"扩样"**：在 R1/R2/R6 落地之前扩充样本，只会把误差放大。
3. **每个季度必须有"可提交终态"**：不许出现"理论上完善了但没有产物"的阶段
   （666 的双档 pipeline 就是这个失败模式）。
