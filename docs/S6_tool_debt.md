# S6 工具债台账（毒样例 P4–P7 的盲区与改进方向）

> 来源：G5 第四批·阶段二 PERF-003 独立红队（48 次工具调用，实读夹具与工件）。
> 处置原则：**本批只登记、不改规则**——四条规则均为 `warn` 级启发式，改动会波及既有 42 张卡，
> 需单独一批做（含回归基线重测）。

## 一、P4–P7 在 PERF-003 上 4/4 零命中（红队实证）

| 规则 | 期望它能抓什么 | 本卡实况 | 为什么没抓到 |
|---|---|---|---|
| `EV-SELF-SATISFIED-ASSERT` | 夹具自定义符号 + 断言只做存在性匹配 ⇒ 断言被自身定义满足 | 夹具**只是调用** `::operator new`、并未重定义；8 条断言全是 printf 格式串存在性检查 | 规则用 `operator\s+(new\|delete)` 正则判"夹具自定义"，**判错了前提**（调用≠重定义）；且只认 `_Zn`/`_Zd` 前缀。本次"放过"是巧合而非判对 |
| `EV-FALSIFICATION-QUANT` | falsification 无量化取值 | falsification 里数字成堆（含双平台表） | 判据退化为"出现过任意一个数字"（`re.search(r"\d", f)`）；而当时卡内"同一夹具可给出 0"**没有任何取 0 的实测记录**（可能性声明被当成对照） |
| `EV-TRIVIAL-OBSERVATION` | actual 只有纯存在性判断 | `sink_nonzero=1`、`heap_at_sso_capacity_plus8=1`、"三个锚实为 AND" | 只认三种 null 拼写（`!= nullptr` / `not null=1` / `is null=0`），同型读数换个名字即漏 |

## 二、改进方向（下一批工具债，按优先级）

1. **`EV-MATRIX-UNBACKED`：豁免条件收紧**（红队建议，本文件核心条目）
   - 现状：`any(k in raw for k in ("外部", "留痕", "待 CI", "CI 回填"))` ⇒ 关键词自证
   - 改为：**豁免必须伴随可核对内容**——卡内需出现"与 `matrix.compiler` 条目数相当的留痕证据"，
     例如每条额外编译器至少要有一个可核对锚（`.out` 文件路径 / CI run 号 / `::notice::` 注解 /
     现场复跑命令行）；仅有"外部留痕"四个字不算。
   - 副作用评估：现有多编译器卡需补齐锚，预计新增若干 warn（接受为真实债）。

2. **`EV-SELF-SATISFIED-ASSERT`：前提判定修正**
   - 现状把"调用 `::operator new`"误判为"夹具自定义" ⇒ 前提错误
   - 改为：只匹配**定义**形态（`void* operator new(` / `void operator delete(` 出现在函数定义位置），
     并扩展到"断言候选为**夹具自写格式串**"这一同构风险（printf 格式串存在性检查同样零判别力）。

3. **`EV-TRIVIAL-OBSERVATION`：从拼写白名单改为结构判据**
   - 现状认三种 null 拼写；改为识别"**恒真型结构**"：形如 `X_beats_Y`、`X_nonzero`、`X_plusN`
     这类由夹具自身定义直接推出的布尔读数，并要求每张卡至少一条"对关键变量有响应"的对照。

4. **`EV-FALSIFICATION-QUANT`：从"有无数字"升级为"是否有两个不同取值"**
   - 要求 falsification 里出现**成对取值**（如"应为 3 / 实测 0"）或明确的反向读数；单纯出现数字不算。
