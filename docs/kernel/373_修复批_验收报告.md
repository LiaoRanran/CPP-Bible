## 3. 🔴 实测对裁决的两处修正（以实测为准，如实记录）

### 3.1 裁决 §2.1 预计「误伤 0」，实测 **6**
`EV-OUT-UNDECLARED-KEY` 命中 6 张（CONC-002/003/004/005/006、LANG-002），且这 6 张的未声明键
**全部是"卡内全无提及"的键** ⇒ 与编造键 `fabricated_leak=64` **结构上不可区分**。
故本规则按 **warn** 落地（强制声明完整性，不阻断），升级 block 需先补 `run_match_keys`
（属证据卡内容改动，本批铁律禁止）。

### 3.2 裁决 §2.2 的判据无法拦住原始攻击卡
裁决称"通用符号 `main/call/ret` 不在夹具源码且无 symbol_map → block"。实测：`main` 通常
**既在工件里也在夹具源码里**（`int main()`），故该判据对 373 B2-R1 的载荷 `contains "main"`
**不会触发**。本批按裁决字面实现（通用符号不可映射 → block），并在毒样例中用"夹具/工件
均无 main"的卡验证其确实 block；**但"通用符号在工件里天然恒真"这一层，仍由红队/人审承担**，
工具无法判别（判别它需要实验语义）。

### 3.3 附带发现的真缺陷（非误伤）
`EV-MEM-017` 断言 `contains "_Znwm"`，而 MinGW 工件里 operator new 实为 **`_Znwy`**
（LLP64 下 `size_t` = unsigned long long）。该卡在 Windows 侧走 sha 比对、**断言从未被评估**，
因此"双平台 confirm"掩盖了它。已 warn 并登记 DEBT-003。
