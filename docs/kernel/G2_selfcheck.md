## 2. 验收门达成度

### 门 ① 机制类论断跑通完整闭环并产出真实证据 —— ✅ 达成

论断：**对含堆缓冲的类型，移动构造不分配堆内存（0 次），拷贝构造分配 1 次。**

独立复跑（本机 2026-09-10）：

```
15.3.0 -O0: 证伪对照(假移动)分配=1 / 构造分配=1 拷贝分配=1 移动分配=0
15.3.0 -O2: 同上
13.1.0 -O0: 同上
13.1.0 -O2: 同上
 8.1.0 -O2 (c++17): 同上
汇编（15.3.0 -O2）：main 中 call malloc 3 次（构造 1 + 拷贝 1 + 假移动对照 1），真实移动路径 0 次
证据可复现性：仓库 .asm sha256 = 460c3981…4002f，与证据卡记录**逐位一致**
```

闭环要素齐备：假设 → 受控变量（唯一变量 = 拷贝/移动构造）→ expected/actual 字段化 →
**证伪对照真失败**（假移动实现分配 1 次，证明实验能区分真假移动）→ 双层互证（运行时计数 +
汇编调用点）→ 跨优化级别（-O0/-O2）+ 跨版本（15.3/13.1/8.1）一致 → 一键复现（命令自包含）。

### 门 ② 灰色地带产出三编译器对照 —— ⚠️ **部分达成（如实标注）**

论断：`f(g(), h())` 中 `g`/`h` 求值顺序为 **unspecified（未指定，非 UB）**。

独立复跑（本机）：

```
矩阵：{GCC 8.1.0, GCC 13.1.0, GCC 15.3.0} × c++17 × {-O0, -O2}   （6 组）
结果：6 组全部输出 hg|f(1,2)（右→左求值），rc=0，无 UB 征兆
结论：confirm（unspecified）；多版本两档一致 ≠ 可依赖
```

**缺口（不得合并宣称）**：
- `Clang-19` 列：本机无 Clang，唯一路径是 CI 的 Clang-19 job——**尚未接线**（见 §5 DRQ-G2-1）；
- `MSVC` 列：无任何可用路径，故本门标注"部分达成"。

按 M2 §2 表述纪律：本机三版本 GCC 只能称**多版本对照**；"三编译器对照"特指 {GCC, Clang, MSVC}。
不把 6 组 GCC 组合伪装成"三编译器"，是本门诚实性的关键。

### 门 ③ 置信规则可手算复核 —— ✅ 达成（且复核出两处歧义）

手算复核 M3 示例：base = 0.50（ISO `[lib.types.movedfrom]`）+ 0.15（first_hand）
+ 0.10×1（另有 1 个独立源 cppreference）= **0.75（中）** —— 与 M3 一致，公式无黑箱。

复核同时发现两处设计歧义（草稿缺陷），已定死：
1. **`first_hand` 双算**：该词既是 §1 表里的 L1 基础分档（0.50），又是 §2 公式的布尔加分项（+0.15）。
   若把"本书实测"写进 `sources[]` 又置 `first_hand: true`，会重复计分 → 已定死：`sources[]` 只放
   外部来源，一手实测仅以 `first_hand: true` + `evidence[]` 表达。
2. **基础分性质未声明**：0.50/0.40/0.30/0.20 是约定的**相对权重**（非概率真值），分档线 0.80/0.60
   待 G3 用 golden 反推校准 → 已补声明 + S4 约束（改权重须过历史 golden 回归）。

## 5. 缺口、移交与 DRQ

**DRQ-G2-1｜Clang 列接线方式**（决定门 ② 能否从"部分达成"升为"达成"）：
- **A（我的倾向）**：在 CI 加一个"Gray-zone Matrix"步骤，用 runner 自带 `g++`/`clang++` 跑
  `_atom_eval_order.cpp`（c++17 × -O2）并打印两边输出，人工比对一致性；不设自动断言（因为
  "未指定"的两个合法顺序都可能出现，机器不能断言"必须是右→左"）——这一步的价值是**留痕对照**，
  不是判红绿。
- **B**：把对照并入 Clang-19 compile job（容器内跑），更贴近"三编译器"语义但接线复杂。
- **C**：本轮不接线，接受门 ②"部分达成"，Clang 列留到 G3 随门禁引擎一起做。
- 代价：A 约 10 行 YAML 但要验证 CI 环境；B 最严谨；C 零成本但门 ② 留缺。
- 补充：**MSVC 在任何方案下都无路径**（无许可证/无 runner），故"三编译器"永远只能是
  "GCC + Clang 双编译器 + MSVC 以标准条文代替"——这个边界建议写进 M2，避免以后反复承诺。

**DRQ-G2-2｜"一键复现"要不要工具化**：M2 §1 的 `reproduce` 字段目前是"手工命令"。可写
`tools/atom_evidence_replay.py`（读证据卡 frontmatter → 执行 command → 比对 actual → 报
confirm/refute），成为 G3 的 S2"干净环境重跑"底座。约半天工作量；不做则 G2 的"一键复现"仍是
文字承诺。

**未达门声明**：门 ② 在 DRQ-G2-1 落地前维持"部分达成"，**G2 未完全达门，不进入 G3**。
