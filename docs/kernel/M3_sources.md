# G2.2 来源与置信 M3（Sources & Confidence）

> 原则：**判定可以靠人，但格式与必填性必须机器卡死**（用户 G2 点名第 3 件事）。

## 1. 来源分级（权重从高到低）

| 级 | 来源类型 | `source.kind` | 基础分 |
|---|---|---|---|
| L1 | ISO/IEC 标准条文 | `iso` | 0.50 |
| L1 | 本书一手实测（自己编译/运行/反汇编） | `first_hand` | 0.50 |
| L2 | 被采纳提案 / 公认权威著作 | `proposal` / `authority` | 0.40 |
| L3 | 官方实现文档（cppreference/GCC/LLVM/MSVC 文档） | `official_doc` | 0.30 |
| L4 | 社区（博客/问答/论坛） | `community` | 0.20 |

**`independent` 字段（防伪多源）**：两条来源若后者只是转述前者，`independent=false`。
判定：是否给出可独立核验的原始出处（标准条款号 / 提案编号 / 可运行代码）？给不出 → 视为转引同源。
**转引同源不累加置信**（否则抄三篇博客就能刷到高置信）。

**基础分性质（2026-09-10 补）**：0.50 / 0.40 / 0.30 / 0.20 是**约定的相对权重**——用于排序与门槛，
不是概率真值（没有哪个来源"真的是 50% 可信"）。分档线 0.80 / 0.60 由 G3 用"先标 golden 再反推"
校准（M5 口径），改权重或分档线须过全部历史 golden 回归并写理由（S4）。

## 2. 置信度可计算（可手算复核，验收门要求）

```
conf = base_level                    # 取 sources[] 中最高基础分
     + 0.15  若 first_hand == true（有一手实测）
     + 0.10 × min(独立源数 - 1, 2)    # 每多 1 个独立源 +0.10，上限 +0.20
     - 0.20  若存在未仲裁冲突（contradicts 未消解）
     - 0.10  若所引标准版本已被 supersedes
     - 0.15  若 dependent_only（全部来源转引同源）
clamp 到 [0, 1]
```

分档：`≥0.80` 高 / `0.60~0.79` 中 / `<0.60` 低。
**低置信的断言不得在正文写成确定性表述**，必须带"据…/在…条件下/存在争议"限定语。

**防双算（2026-09-10 手算复核发现的设计歧义，已定死）**：`first_hand` 是**布尔加分项**，
不是 `sources[]` 条目。上一节表里 `first_hand` 虽列为 L1 基础分 0.50，但两者的记账位置不同：
- `sources[]` **只放外部来源**（`iso` / `proposal` / `authority` / `official_doc` / `community`）；
- 本书一手实测只表达为 `first_hand: true` + `evidence[]`（证据卡）。

若把"本书实测"同时写进 `sources[]`（kind: `first_hand`）又置 `first_hand: true`，会重复计分
（base 已含 0.50 一手分，再加 0.15）。**公式里的 `+0.15` 与表中的 0.50 二者只能出现一次。**

**手算示例**（移动语义原子，逐项可核）：
- sources：ISO `[lib.types.movedfrom]`（0.50）+ 一手实测（first_hand）→ base = 0.50
- +0.15（first_hand）
- +0.10（另有 1 个独立源 cppreference）
- 无冲突、未过时、非转引 → 0 扣减
- **conf = 0.75（中）**

> 要到 0.80+ 需再补一个独立源或补跨编译器实测——这条规则的意义是：**逼作者去补证据，而不是改数字**。

## 3. 争议档案（冲突显性化）

两个来源结论冲突（`contradicts`）时：
1. 不许静默选一边，必须开争议档案：`evidence/{domain}/EV-*-dispute.md`
2. 字段：`claim` / `side_a{source, evidence}` / `side_b{...}` / `arbiter`（人） / `resolution` / `date`
3. 未仲裁前：置信度按规则 -0.20，正文必须标注"存在争议"
4. 仲裁后：把结论回写进原子，争议档案保留（不删，留痕）

## 4. originality / superiority 强制规则（本节点名项）

**格式强制（机器可查，判定靠人）**：

1. `superiority` 是**必填非空字符串**。
2. 必须对 `sources[]` 中**每个 `independent: true` 的来源**各写一条，格式固定：
   ```
   {source_id}：本书多给了什么 —— <具体增量>
   ```
   若独立源 N 个而条目数 < N → **门禁报错**（这是可机械检查的部分）。
3. **禁词表**（出现即打回，因为这些是零信息增量）：
   "讲解更详细" / "更通俗易懂" / "更全面" / "更加深入" / "帮助读者理解" / "结合实际"
   判定：增量必须是**可验证的名词性内容**——多给了哪个实验、哪个汇编证据、哪个反例、哪组数字、哪条边界条件。
4. 允许的表述范例：
   - "cppreference 只给'有效但未指定'的措辞；本书补了可编译对照实验，把'有效'落成'可安全析构/可赋新值'两个可观测操作"
   - "标准未规定扩容倍数；本书补了 libstdc++ 15.3 下的实测增长序列（1→2→4→8）与汇编证据"
5. **答不出增量 = 二手拼盘** → `status` 不得置 `verified`，退回重做。

**版权红线（合理使用边界）**：
- 标准条文：只引**条款号与必要短句**，不整段复制 ISO 文本（ISO 标准受版权保护）。
- 提案/论文：引标题、编号、结论要点，图表不复制（需授权）。
- 他人代码：引思路并注明出处，代码必须**重写**且可编译；不改写成"本书原创"。
- 任何复制超过 3 行原文 → 必须加引用块 + 明确出处，否则视为侵权风险项，门禁报警。

## 5. 溯源图（来源 → 原子 → 证据）

```json
{
  "atom": "ATOM-MEM-MOVE-001",
  "sources": [
    {"id": "S1", "kind": "iso", "ref": "ISO/IEC 14882:2023 [lib.types.movedfrom]", "independent": true},
    {"id": "S2", "kind": "official_doc", "ref": "cppreference std::move", "independent": true},
    {"id": "S3", "kind": "community", "ref": "某博客（转述 S2）", "independent": false}
  ],
  "evidence": ["EV-MEM-001"],
  "superiority": {
    "S1": "本书多给了什么 —— 标准只说'有效但未指定'，本书把它落成两个可观测操作（可析构、可赋新值）并给出反例",
    "S2": "本书多给了什么 —— cppreference 无证据；本书补 -O2 汇编（malloc 2 次）与假移动对照（分配=1）"
  },
  "confidence": 0.75
}
```
（`S3` 为转引同源，不计入独立源加分。）

## 6. 反例自检

- 置信度公式若不能手算复核（有查表/黑箱） → **不合格**。
- `superiority` 只写一句泛泛而谈却放过 → **不合格**（禁词表是硬约束）。
- 转引同源被当成独立源累加 → 造假 → **不合格**（`independent` 字段即为此存在）。
- 冲突被静默选边 → 违背争议档案 → **不合格**。
- 复制 ISO 条文整段却标原创 → 触版权红线 → **不合格**。
