## 4. 🔴 实测否决：蓝图的"规则级快修"前提不成立

对存量 **56 张**合法证据卡，按蓝图 §三的**原文判据**实现三条规则，实测命中：

| 规则（蓝图原文） | 命中合法卡 | 判定 |
|---|---|---|
| `EV-OBSERVATION-VISIBLE`（expected/falsification 中每个数字 token 须在声明键值中出现） | **32 / 56** | ❌ 不可落地 |
| `EV-ASSERT-DISCRIMINATOR`（断言文本须逐字出现在夹具源码中） | **29 / 56** | ❌ 不可落地 |
| `EV-ARTIFACT-GEN-TRACE`（artifact 生成段 argv[0] 须为编译器） | **11 / 56** | ❌ 不可落地 |

根因（三条各不相同，不是同一类错误）：

1. **B3**：卡散文里的数字大量是**行号 / 条款号 / 编译档位 / 替代场景值**
   （如 `3 条命令`、`-O0`、`§2.2`、`[basic.lval]`、`1/1`），与"观测读数"不是同一语义层；
   "数字 ⊆ 声明值"把两层混为一谈。
2. **B2**：`artifact_assert` 锚的多是**工件内**特征（mangled 名 `_Z10spin_plainv`、
   反汇编文本 `movl $1, %eax`）——它们本来**不该**出现在夹具源码里；另有散文断言（"空壳工件"）。
   "逐字出现在 fixture 源码"是错误判据（正确的判据空间是"夹具 ∪ 工件 ∪ 符号表"）。
3. **N4**：11 张命中里有相当部分是**"产出段归属"算法**的误判（同一 `command` 多段含 `-o`），
   规则本身方向对，但"哪个段产出 artifact"未定义 ⇒ 先定义再判。

**结论**：三条都不能按蓝图原文提交。这恰恰证明 373 §3.5 两阶段协议的价值——
**独立方给的攻击与优先级可信，但"修复实现"不可直接照抄**（监工自己也写了"若与实测冲突以我实测为准"）。
