## 0. 选题与预期暴露的系统问题（写于实验前）

选题：**跨 TU 的 inline 函数 ODR 一致性**（`lang` 域 / `rule` 类）。
选它的理由不是"它好写"，而是它**同时压三处系统薄弱点**：

| # | 预期暴露 | 具体在赌什么 |
|---|---|---|
| S1 | replay 的 `command` 是否能表达**多文件构建 + 两种链接顺序** | 现有 50 个夹具全是单文件；`command` 是多行 shell，理论上可表达，但**未实证** |
| S2 | `artifact` / `artifact_sha256` 是**单产物**字段 | 多 TU 会产出多个 `.asm`，卡只能锚一个 → 暴露"一卡一产物"隐含假设 |
| S3 | "UB 必须有 sanitizer 证据"的隐含假设 | ODR 违反 ASan/UBSan **都不抓**；本实验若能用**链接顺序**观测到 UB，即证明该假设过强 |

## 1. 待解释的现象（实验前陈述，尚未观测）

把同一个 `inline` 函数在**两个 TU 中定义成不同语义**（不同返回值）、且两个 TU **都被 `#include` 到同一头文件**，
编译链接后程序的行为应当如何？

## 2. 假设（≥2 个，其中 ≥1 个反直觉）

- **H1（直觉假设）**：编译器/链接器会发现"同一个 inline 函数有两个不同定义"，**编译或链接报错**（或至少警告）。
- **H2（反直觉假设，本轮主打）**：**不报错**——ODR 违反是"**无须诊断**（no diagnostic required）"的未定义行为。
  链接器只把**同名符号**合成一个（取它先遇到的那个定义），两个 TU 各自看到的定义**被静默取其一**；
  因此**程序结果会随链接顺序改变**，且**随优化档改变内联/非内联形态**。
- **H3（备选，若 H2 的部分分支不成立）**：`-O2` 下两个 TU 各自的调用点被**完全内联**，
  于是"取其一"不发生，输出**不随链接顺序变化**，而是各 TU 用自己的定义。
  —— 若观测到 H3 而非 H2 的某一分支，**不视为 refute**，而是"UB 的又一种合法表现"，
  须在卡内并列记录（这正是本实验的判别价值）。

## 3. 预言矩阵（实验前写死；`a`/`b` 为两个 TU，`stable` 为两 TU 定义完全相同的合规对照）

| # | 实验 | 唯一变量 | 预言输出（写死） | 若违反则说明 |
|---|---|---|---|---|
| E1 | `-O0` 链接顺序 `a b` | 定义不同 + 顺序 | `tu_a=1 tu_b=1 stable_a=42 stable_b=42` | 若 `tu_a=1 tu_b=2` → H2 被否（未取其一） |
| E2 | `-O0` 链接顺序 `b a` | 定义不同 + 顺序 | `tu_a=2 tu_b=2 stable_a=42 stable_b=42` | 若与前一行相同 → **顺序无关**，H2 被否 |
| E3 | `-O2` 链接顺序 `a b` | 优化档 | **不确定**：`1/1`（未内联取其一）或 `1/2`（各自内联）；两者都合法 | — |
| E4 | `-O2` 链接顺序 `b a` | 优化档 + 顺序 | 与 E3 同构（`2/2` 或 `1/2`） | — |
| C1 | 合规对照（两 TU 同定义） | 无 | 无论 `-O0/-O2`、无论链接顺序，**恒为 42/42** | 若随顺序变化 → 夹具本身有别的变量未控住，实验作废 |

**活性对照**：`stable_*`（两 TU 定义逐字相同的 inline 函数）恒定 42 —— 证明"输出确实来自运行时执行"，
且证明"链接顺序本身"不是结果变化的原因（否定"顺序是混淆变量"）。

**判别力自检**：E1 vs E2 的差异只可能来自"链接顺序"，C1 证明顺序本身无害 ⇒
若 E1≠E2，则该差异**只能**归因于"两个 TU 的 inline 定义不同"（=ODR 违反）⇒ 支持 H2。

## 4. 边界与红线（实验前声明）

- **有界**：实验无循环、无网络、无外部依赖，单次运行 < 1s。
- **不可依赖的判据**：**不得**用 sanitizer 报错/不报错作为本实验的判据（ASan/UBSan 对 ODR 违反不敏感，
  这是本实验**主动声明**的检测边界，也对应 S3）。
- **不做的事**：不去论证"哪一个定义才是对的"——标准只规定"必须相同，否则 UB"，不存在"取其一"的**合法**结果。
- **跨编译器**：同一组实验须在 MinGW 15.3 与 WSL/Linux g++ 两侧都跑；若两侧的系统性行为不同，
  须并行列记（这正是 `rule` 类原子该有的边界声明）。
