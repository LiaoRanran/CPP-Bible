# 实验预注册模板（preregistration）

> 来源：`References/architecture_架构演进/491_人的因素与认知偏差防护方案_*.md`（预注册机制）；
> 498 任务 6（P1-8）。
> 用途：**性能类与对照类实验在动手前必须填本模板**。红队事后 diff「冻结 commit ↔ 最终卡」，
> 检查预测是否是**事前**写下的（而非事后诸葛亮）。

## 为什么（491 §一）

单人项目里最大的偏差风险是**后见之明**与**确认偏误**：
先跑实验、看到数据，再写"我早就预期如此"——卡看起来无懈可击，但预测能力为零。
预注册把「假设与预期值」**先冻结进 git 历史**（时间戳即见证），使"事后解释"在结构上不可能。

**先例**：371 的预言冻结（commit `1001649`，实验前独立提交）——MCC 六步留痕的雏形。

## 模板（复制本段填写）

```markdown
# 预注册 · <实验标题>

- **日期**：YYYY-MM-DD
- **执行者**：<writer / coolie / human / …>（模型族：<qwen-hy4p / ds-v4.1-flash / …>）
- **关联原子/卡**：<ATOM-… / EV-…>（实验前可只写选题方向）

## 1. 假设（一句可证伪的陈述）
<hypothesis>

## 2. 预测结果（**实验前写死**）
<predicted_result —— 具体的观测值或方向，例：`pool_n2_meta > pool_n1_meta`；
若预测的是数值区间，写明区间与依据。禁止写"应该有提升"这类不可证伪的表述。>

## 3. 零假设
<null_hypothesis —— 与假设互斥、且同样可观测的那个陈述（例：`pool_n2_meta == pool_n1_meta`）>

## 4. 实验方案
- **fixture 结构**：<自包含？变量怎么控？对照组是什么？>
- **编译器**：<GCC 15.3.0 (MinGW-w64) / GCC 13.3.0 (WSL) / …>
- **优化档**：<-O2 / -O0 / -O3>
- **平台**：<Windows / WSL>（跨平台结论须声明两平台各测）
- **std**：<c++17 / c++20 / c++23>（注意 GCC 8.1 不支持 c++23）

## 5. 判定指标（metrics）
| 指标 | 取值方式（grep 什么 / 断言什么） | 期望 |
|---|---|---|
| <指标名> | <例：`objdump -d x.exe \| grep -c 'lock'`；或 `run_match_keys` 的某键> | <值/方向> |

> 纪律：指标必须**机器可复算**（命令 + 读数），不接受"目测""感觉"。

## 6. 证伪标准（falsification_criteria）
<看到什么结果就承认假设错 —— 逐条写，且必须与 §2 的预测直接冲突>

## 7. 冻结见证（witness_commit）
- **实验前独立 commit**：`<hash>`（`git show --stat <hash>` 可验；提交时间即"预言先于观测"的见证）
- 提交内容：本预注册文件（不含任何实验数据）
```

---

## 使用纪律

1. **顺序**：填模板 → **独立 commit**（只含本文件）→ 才开始写夹具/跑实验。
2. **不改预测**：实验中途发现方案要变 ⇒ **新开一份预注册**（旧的那份保留，别改），
   否则冻结见证失效。
3. **红队职责**：事后 diff「冻结 commit 的预测」与「最终卡的 claim/actual」——
   若预测值与实测方向相反却仍声称"符合预期"，判**红队不通过**。
4. **适用范围**：性能类（倍率/时间）、对照类（A/B 两组）实验**强制**；
   纯观测卡（如"某符号是否出现"）可豁免，但豁免要在卡内写明"非预测型"。
5. **与产线接口**：本模板的落地位置与流程说明见
   `docs/kernel/writer_production_flow.md`（Writer 生产流程规范，479 建）§3 步骤 1。
