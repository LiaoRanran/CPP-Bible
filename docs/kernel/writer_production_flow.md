# Writer 生产流程规范（断言先行 / TDD 顺序反转）

> 版本：v1.0（2026-09-14，479 批次）
> 来源：454 §T1「断言先行」→ 471/477 提炼（最被低估的零成本成果）→ 478 §一 落地方案。
> 地位：**Writer 生产流程的规范件**（与 M2 实证规范、G1_layout 卡模板、S1–S6 制衡同级）。
> 铁律编号：**P-TDD**（Production-TDD）。

---

## 1. 为什么改：一个真实事故根因

三起方向性错误同一根因（全部为真跑事故，非假设）：

| 事故 | 现象 | 根因 |
|---|---|---|
| **ALLOC-002** | Arena/Pool 元数据口径反转（"不随规模变"实为"随规模变"） | 断言抄了夹具的编译期常量 |
| **LEAK-002** | LSan 零报告被推翻 | 断言基于夹具输出而非理论预期 |
| **EV-MEM-017** | `_Znwm` vs `_Znwy`（32/64 位算子错配） | 符号名按夹具实际输出写，未先定理论 |

**共同机制：先写夹具 → 看到输出 → 按输出写断言 ⇒ 断言被输出锚定成自证。**
夹具若有 bug（口径不统一 / 观测通路失效 / 计数器被优化折叠），断言把 bug 一起固化，
红队必须"读出夹具源码 + 反推理论"才能发现"断言与夹具同错"——成本极高。

### 1.1 旧流程（**禁止**）

1. 写夹具 → 编译运行 → 看到输出
2. 按输出写 `expected:` ⇒ 断言必然通过（**自证**，零判别力）
3. 写 `claim`：被输出锚定

### 1.2 新流程（P-TDD，强制）

1. **先写断言**（基于理论预期，不看夹具输出，此时夹具可尚未存在）
   - 例：「arena 元数据不随规模变」→ 断言 `arena_n1_meta == arena_n2_meta`
   - 例：「pool 元数据随块数增长」→ 断言 `pool_n2_meta > pool_n1_meta`
2. **再写夹具**让断言可被检验
   - 断言不通过 → **二选一必须解释**：理论预期错了，还是夹具有 bug
   - 断言通过 → 这是**独立验证**，不是自证
3. **最后写 claim**（基于断言结果，不是基于夹具输出）

与 TDD「红 → 绿 → 重构」同构：先写会失败的断言（红），再写夹具使其通过（绿），最后优化夹具（重构）。

## 2. 铁律 P-TDD（逐字，不得改写）

> **断言必须在看到夹具输出之前写好。断言基于理论预期，不基于夹具输出。写完断言后再写夹具，夹具运行结果如果和断言矛盾，必须解释是理论错了还是夹具有 bug，不能改断言去匹配输出。**

## 3. Writer 操作清单（逐步）

| # | 步骤 | 产出 | 违规信号 |
|---|---|---|---|
| 1 | 写 `hypothesis` + `falsification`（要证什么、怎么证伪） | 卡字段 | 先动夹具 |
| 2 | **写断言** `artifact_assert` / `run_match` / `expected`（基于理论） | 断言文本 | 断言里出现"从输出抄来的数" |
| 3 | 写夹具（自包含 · 确定性 · 可重入 · 内容寻址，见 M2 §夹具四要求） | `_atom_*.cpp` | 夹具里 `printf` 硬编码期望值 |
| 4 | 真跑夹具，**对比** `expected:` 与实测 | 差异分析 | 静默改 `expected:` 去匹配输出 |
| 5 | 一致 → 写 `actual:`；不一致 → **停在步骤 4 分析**（改理论 或 改夹具） | `actual` / 修正记录 | 直接改断言 |
| 6 | 写 `claim`（≤50 字，锚方向不锚倍数）+ 留痕 `matrix` | 卡完成 | claim 复述夹具输出 |

**步骤 4 的强制解释义务**：任何 `expected` 与实际不符，必须在卡内或工单留下"是理论错还是夹具错"的判断与依据；
**禁止**把 `expected` 改成实测值后不留痕（这正是 S3-EXPECTED-HARDCODED 与 373-B2「恒真载荷」的来源）。

### 3.1 性能/对照类实验：**实验前必须预注册**（498 P1-8 / 491）

P-TDD 管的是"断言先于夹具"，**预注册管的是"预测先于观测"**——性能类与对照类实验
（倍率、时间、A/B 两组）在**动手前**填 `docs/kernel/preregistration_template.md`，
写死 hypothesis / predicted_result / null_hypothesis / metrics / falsification_criteria，
并**独立 commit 冻结**（只含该文件；commit 时间戳即"预言先于观测"的见证，先例 371 `1001649`）。

- **红队职责**：事后 diff「冻结 commit 的预测」与「最终卡的 claim/actual」——
  方向相反却声称"符合预期"的，判不通过。
- **理由**（491 §一）：不预注册时，人会在看到数据后写"我早就预期如此"，
  卡看起来完整但预测能力为零（后见之明 + 确认偏误）。
- 纯观测卡（"某符号是否出现"）可豁免，但须在卡内写明"非预测型"。

## 4. 与既有制衡的接口（TDD 反转如何被机器看见）

| 机制 | 关系 |
|---|---|
| `S3-EXPECTED-HARDCODED`（证据卡期望值硬编码进夹具字面量 → block） | P-TDD 的**下游拦截器**：违反 P-TDD 的最常见产物 |
| `EV-FALSIFICATION`（缺证伪对照 → block） | 断言先行的前提：先写 falsification 才知道断言该长什么样 |
| `EV-SELF-SATISFIED-ASSERT` / `EV-TRIVIAL-OBSERVATION`（自证/恒真观测 → warn） | 自证的**机器判据**：断言对关键变量零响应即命中 |
| `EV-FALSIFICATION-QUANT`（伪证伪无量化对照 → warn） | 断言必须可复算：只写"若…则应…"不算 |
| M2 §夹具四要求 | 步骤 3 的质量门槛（本流程不替代它） |
| 红队两段式盲读（先读夹具源码，不读卡自述） | 独立验证 P-TDD 是否被遵守（ALLOC-002 正是这样被抓出） |

## 5. 反模式清单（出现即返工）

1. **抄输出**：`expected: pool_meta=32` 而 32 是从夹具 `printf` 输出里抄的 → 应改为关系式断言（如 `pool_n2_meta > pool_n1_meta`）。
2. **改断言不改结论**：实测与预期不符时，只把 `expected` 改成实测值，不解释理论/夹具谁错。
3. **空断言**：断言只做存在性判断（`x != nullptr`）、对 claim 关键变量零响应（P6 形态）。
4. **断言来自夹具的自定义定义**：断言文本在夹具中能找到**定义处**即通过，而无调用点（P4 形态）。
5. **先跑通再补断言**：先让夹具"跑出好看的数字"，再回头写断言去匹配（本规范的核心禁止项）。

## 6. 适用范围与例外

- **适用**：所有新原子/新证据卡的夹具生产（G5 起的批次一律适用）。
- **批量迁移**：存量卡的断言若属"抄输出"形态，**不在本规范强制返工范围内**（改卡受铁律限制）；
  但发现即登记（`_worklog` / 债务台账），由红队按既有流程处置。
- **例外**：纯观测卡（如环境探针）无理论预期可先行时，`expected` 须写明"观测型，理论预期不适用"
  并给出观测口径（避免把"没有预期"当成豁免）。

---

## 7. 验收与自证

- 本规范为**流程性**要求，不新增 gate 规则（机器判据已由 §4 的既有规则承担）。
- 违反 P-TDD 的**可观测产物**（硬编码期望、恒真观测、缺量化对照）由现有规则 block/warn，
  故本规范的落地**不需要**新的门禁数字变化——如果有一天这些规则命中数上升，说明 P-TDD 未被遵守。
