## §2 窄化三条的细化要求（建设者必须遵守）

### 2.1 EV-OUT-UNDECLARED-KEY（替换 B3 蓝图原文）
- 判据：`.out` 中出现的 `key=value` 行（正则 `^\w[\w-]*=`），其 key 必须在 `actual.run_match_keys` 中声明；未声明的结构化读数行 → warn→block。
- **不抓**：散文行（无 `=`）、注释行（`#`/`//` 开头）、expected/falsification 里的数字（那是红队/人审的活）。
- 误伤面：预计 0（只抓结构化编造行，不碰散文）。实现后实测 56 卡确认。

### 2.2 EV-ASSERT-SYMBOL-MAPPED（替换 B2 蓝图原文）
- 判据：`contains/absent/contains_in/absent_in` 的断言文本必须命中 ∈ {夹具源码标识符 ∪ 该卡 artifact 文本 ∪ 卡内显式声明的 `symbol_map`}。
- **关键**：不要让工具模糊匹配"夹具函数名→工件符号名"（`spin_plain` vs `_Z10spin_plainv` 的映射不可靠）。要求卡内显式声明 `symbol_map: {spin_plain: _Z10spin_plainv}` 字段，工具只做精确匹配。
- 纯散文断言（如"这段代码证明无泄漏"）不由本规则拦，由红队/人审承担。
- 通用符号 main/call/ret 不在夹具源码且无 symbol_map → block。

### 2.3 artifact_producer 显式字段（替换 N4 蓝图原文）
- 卡 frontmatter 新增 `artifact_producer: <command片段>`，显式声明哪一段 argv 产出 artifact 文件。
- 工具校验：该片段的 `argv[0]` ∈ 编译器白名单（g++/gcc/clang++/clang/c++/cc）；纯 cp/python 复制 → block。
- 存量 56 卡缺此字段 → 第一阶段 warn（advice），给迁移期；新卡必须填（block）。
