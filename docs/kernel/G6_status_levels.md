# G6 · 四级状态与失效后果分级（DAL）

> 来源：`References/300_四级状态自动化体系_从人审驱动到机器自治.md`（决策：**放权**）。
> 本文件是**规范**（可被门禁强制）；300 是论证稿。二者冲突以本文件为准，差异见 §6。
> 落地日期：2026-09-12。落地前状态：`draft | verified | rejected`（人审为唯一升级通道，人审即瓶颈）。

## 1. 目标

把"人审"从**默认通道**改为**分级通道**：低失效后果的原子走机器门禁 + 红队即可入库，
人只保留两件事——**方向判断**与**严重度裁定**。依据是 300 §1.2 对能力的划分：

| 只有人能做的 | 机器/Agent 能做的 |
|---|---|
| 这条洞见值不值得教（方向） | 断言是否可证伪、证据是否支撑（机械核查） |
| **失效后果的真实严重度**（DAL） | 与已有原子是否重复（全库比对） |
| 是否值得投入重写 | 格式/引用/工件一致性（纯工具） |

放权的**风险等价物**是"降标"：如果放权的同时让门槛静默变松，得到的是更快的错。
故本规范的一半篇幅是**反作弊约束**（§5）——它们不是可选项，去掉任一条，放权即退化为降标。

## 2. 四级状态

| 级 | `status` | 谁可置 | `verified_by` 前缀 | 含义 |
|---|---|---|---|---|
| 0 | `draft` | Writer（Agent） | — | 草稿；**不得被内容层引用** |
| 1 | `machine-verified` | 门禁/CI（自动） | `machine:` | 全部机器判据通过（gate 无 block、evidence replay confirm、poison 通过） |
| 2 | `red-team-verified` | 红队 Agent（独立上下文） | `redteam:` | 独立子 agent 盲读夹具+工件，再对照卡；阻断项已处置 |
| 3 | `human-verified` | **人**（`human:liaoranran`） | `human:` | 监工签署；`verified` 为四级前历史别名，**语义等价**（存量沿用，不强制改名） |
| — | `rejected` | 任一方 | — | 证伪/撤回；保留文件与历史，不删除 |

**唯一判断点**：代码里判断"是否已验证"必须走 `gate_engine.is_verified()` / `level_of()`。
禁止散落 `status == "verified"`——新枚举会让写死的等值比较**静默跳过**（不报错、不拦截），
等于把 S1/S2/证据边界三条硬约束一起关掉（这正是 300 §4.1 差点踩中的坑，见 §6-F1/F2）。

### 2.1 晋升与降级

- 晋升逐级或按需跳级均可，**但必须留痕**：`status_history: [{level, at, by}, …]`，
  链首 `draft`、链尾 = 当前 `status`、`at` 为 ISO 日期（`draft` 级可写 `legacy` 表示时间未记录）、
  `by` 前缀与该级执行者匹配。
- 降级不删记录：在链尾追加低级别步骤（例如发现断言边界写错 → 追加 `machine-verified` 前的 `draft`）。
- `at: legacy` **仅限 draft 级**：历史原子没留起草时间，逼填日期就是逼造数据。

### 2.2 为什么"逐级强制"没有写进规则

300 §2.2 要求"禁止跳级"（draft→machine→red-team→human 每步 +1）。四级体系启用**之前**的
20 颗已验证原子都没有 red-team 级记录，硬要求逐级只能靠**编造**红队记录来满足。
**规则若要求机器无法核实的历史，就是在生产假记录。** 故只拦风险实质：

> **人级必须链上含非人级前驱**（machine 或 red-team）——人只能签"已被机器验过"的东西。

这条抓住了跳级的危害（未经核查的内容被人签成已验证），且不制造虚假历史。

## 3. 失效后果分级（DAL）

单字母 A–E，描述**若本条断言是错的，读者会付出什么代价**：

| DAL | 失效后果 | 人审 |
|---|---|---|
| `A` | 读者写出 UB / 并发 / 资源安全缺陷（崩溃、数据错误、安全漏洞） | **强制** |
| `B` | 读者形成方向性错误的认知，且会在后续学习中持续付错（教学结论反向） | **强制** |
| `C` | 局部定量结论偏差（性能倍数、空间代价），不改变方向 | 红队通过即可 |
| `D` | 表述/术语瑕疵，不影响可执行结论 | 红队通过即可 |
| `E` | 纯组织性内容（索引、导航、元数据） | 自动通过 + 抽查 |

### 3.1 DAL 由谁定（**放权体系里最关键的一环**）

- `dal` 由 Writer 提出、红队复核；**但豁免人审这个决定本身必须人签**：
  `dal: C|D|E` 的原子须带 `dal_reviewed_by: human:*`（同一批可一次签分级表）。
- 原因：若不要求人签，Writer 只要写 `dal: C` 就能绕过人审——**放权变成权力反转**，
  且 300 §1.2 自己承认"失效后果的真实严重度"正是机器不擅长的项，把它交给 Writer 自评是自相矛盾。
- **上调（A/B→C/D/E 方向相反时为上调严重度）机器可做；下调（→C/D/E）必须人签**。
  即"越权放行"必须过人手，收紧自动生效。

> 与 `References/296`（claim 契约 v0.2）的关系：296 的 DAL 是**契约散文里的一段 checklist**，
> 本规范把它升级为**机器可查的 frontmatter 字段**，语义统一为"读者侧失效后果"。
> 同一字段只有一个定义，不再出现"同名三口径"。

## 4. 门禁落点（机器可判部分）

| 规则 | 级别 | 判据 |
|---|---|---|
| `ATOM-STATUS-VALUE` | block | `status` ∈ 枚举（枚举外取值会让等值比较静默漏过，故显式拦） |
| `ATOM-STATUS-TRANSITION` | block | 非 draft ⟹ `status_history` 合法：链首/链尾/单调/格式/前缀，**人级须含非人级前驱** |
| `ATOM-DAL-MATCH` | block | 已入库原子须有合法 `dal`；A/B ⟹ `human_review: required` 且状态为人级；C/D/E ⟹ 须 `dal_reviewed_by: human:*` |
| `S1-AUTHOR-SELF-VERIFY` | block | `verified_by` 前缀与状态级别匹配（人级唯人，Agent 不得自证；机器/红队级各自留痕） |

`golden_lock` 同步分列计数：`human_verified` / `red_team_verified` / `machine_verified`
+ `dal_gap`（DAL A/B 却非人级 = 越权放行，**上升即恶化**）。只盯总数会被
"人级掉 1 / 红队级涨 1"这类置换掩盖（总数不变、保证级别其实降了）。

**机器抓不到、必须靠红队兜的**（放权≠免检）：夹具活性（对照实验是否真的活着）、
工件与断言代际一致、平台表述宽度、与先例的重叠。第五批 LEAK-002 的 H1/H2 就是这一类——
DAL C 不豁免它们，只是不再需要人审签字。

### 4.1 基础设施故障必须与内容证伪分流（**放权前必修**）

机器自治把"全部判据"交给脚本，于是**脚本自身的不稳定性会被放大成内容结论**。
2026-09-12 实例：`Examples/` 夹具子目录化迁移窗口期，`atom_evidence_replay --check`
一次性输出 `confirm=0 refute=48`，全部原因是 `cc1plus: Examples/_atom_*.cpp: No such file or directory`
（夹具尚未就位），复跑即 `confirm=48 refute=0`。

**危害**：`refute` 是"卡被证伪"的语义，与"基础设施没就位"完全不同的处置路径。
在无人值守的门禁里，一次目录迁移会显示成"48 张证据卡集体失效"——足以误判整批作废，
或反过来让人对真证伪麻木（告警疲劳）。

**要求**：replay 的判定分三类而非两类——`confirm` / `refute`（内容层）/
`infra_error`（夹具缺失、工具链找不到、编译环境不可用、工作区正被其它进程修改）。
`infra_error` 必须**阻断晋升并提示重试**，且**不得污染 golden_lock 的 `replay_confirm` 计数**
（否则基线会被 infra 抖动拉低，掩盖真实退化）。当前实现尚未分流，登记为 G6 落地后的第一顺位技术债。

## 5. 反作弊约束（三条铁律）

1. **判断单点化**：新增状态只改 `is_verified()`/`STATUS_LEVEL`，不改调用点。
2. **人级须有非人级前驱**：堵住 draft 直签人级。
3. **免人审须人签**：堵住 Writer 自定 `dal` 绕过人审。

抽查机制（人工，非门禁）：每批随机抽 1 颗 DAL C/D/E 原子做全量人读，
错判计入该批质量问题；连续两批抽查不合格则**回收该批的自主晋升权**。

## 6. 与 `References/300` 的差异（修正记录）

| # | 300 的写法 | 事实/修正 |
|---|---|---|
| F1 | §4.1「当前 `ATOM-NO-UNVERIFIED` 只认 `status: verified`」 | **规则名错**。实测 `ATOM-NO-UNVERIFIED` 只拦 `unverified`/`needs` 子串；真正的人身签名约束是 `S1-AUTHOR-SELF-VERIFY`，另有 `ATOM-VERIFIED-BOUND`、`S2-EVIDENCE-VERDICT` 两处绑定。按 300 原文改会漏掉这三处 |
| F2 | §2.3 新增 `machine-verified` 等取值 | 未提**静默失效**：三处 `status == "verified"` 与 `golden_lock` 的 `verified_atoms` 会一起静默跳过。故本方案把判断先收敛到 `is_verified()`，再扩枚举 |
| F3 | §3.1 DAL 定义「继承自 296」 | **不成立**：296 的 DAL 语义是"claim 被证伪的知识后果"，300 是"读者侧失效后果"，同名异物。本规范统一为后者并登记（§3.1 末） |
| F4 | 未写 DAL 由谁定 | 300 §1.2 把"严重度"列为机器不擅长，却让分级决定"谁需要人审"——**循环**。补 §3.1：免人审须人签 |
| F5 | §2.2「禁止跳级」 | 终态无法证明路径（草稿在 `goldens/` 不进扫描），且强制逐级会逼造假记录。改为"人级须含非人级前驱"（§2.2） |

## 7. 存量兼容（2026-09-12 落地时）

- 20 颗已验证原子统一补 `dal` + `human_review` + `status_history`（三点 `draft(legacy) → machine-verified → human-verified`，
  日期取各自 `verified_at`）。**保守映射：除 `ATOM-UB-GRAY-001` = A（UB 致崩溃/数据错）外全标 B**。
- 为何不按内容细分：`PERF-001/002/003` 本质是 DAL C，但**下调需人签**（§3.1），
  故先按 B 记（不降标），待监工签 `dal_reviewed_by: human:liaoranran` 后下调为 C。
- `status: verified` 保留为 human-verified 别名，存量不强改（改名会牵动 95+ 处引用，
  收益只是字面统一）。新增原子一律用四级显式取值。

## 8. 反例自检

- 新增一个状态取值却不改 `is_verified()` → 相关硬约束静默失效，**不合格**。
- `status: human-verified` 而 `status_history` 只有 `draft → human-verified` → 未过机器验证即人签，**不合格**。
- `dal: C` 无 `dal_reviewed_by: human:*` → Writer 自评豁免人审，**不合格**。
- 用 `status: machine-verified` 就跳过 `evidence[]`/`first_hand`/`superiority` → **不合格**（绑定对三级同时生效）。
- 把 `dal` 当作"重要性/篇幅/难度"来标 → 语义漂移，**不合格**（它只描述"错了的后果"）。
