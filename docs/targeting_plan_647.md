# 647 E3 · 648+ **打靶计划**（基于 E1/E2 调研；本批不执行）

> 输入：`docs/c_domain_adaptation_647.md`（E1）· `docs/embedded_adaptation_647.md`（E2）。
> 原则：**每一批都有可验收的产出 + 明确的失败预案**；**不建卡就不许说"打靶成功"**。

---

## 一、总目标与顺序

```
648  第一批：C 语言基础卡 10 张（真编译器实测 + 标准条款 + 反例）
649  第二批：嵌入式特有卡 10 张（交叉编译器；L0 真机项**先定获取方式**）
650+ 视 648/649 结果决定：继续扩域 / 深化信任根 / 真实用户测试
```

**为什么 C 先于嵌入式**：C 的基础卡可以用**本机编译器**拿到 L1/L2 证据；
嵌入式的最高档（真机 L0）**本机拿不到**（E2 §二.3）⇒ 先把"能自证的"做完。

## 二、648 · 第一批：C 语言基础卡（10 张）

| # | 卡 id | 论断（要一句话说得清） | 证据来源 | 反例 |
|---|---|---|---|---|
| 1 | `C-PTR-DECAY-001` | 形参数组退化为指针 ⇒ 函数内 `sizeof` 拿不到数组长度 | gcc/clang `-Wall` + 标准 6.7.6.3 | 用 `sizeof` 判长度的"看起来对"的代码 |
| 2 | `C-MALLOC-PAIR-001` | `malloc` 的每条失败路径都必须有对应处置，且与 `free` 配对 | 静态审查 + `-fsanitize=leak` 实测 | 早退路径漏 `free` |
| 3 | `C-STR-BOUND-001` | `strcpy/strcat` 无边界；`snprintf` 返回值语义易错 | 标准 7.24.2 + ASan 实测 | `snprintf` 返回值当"写入长度"用 |
| 4 | `C-FNPTR-001` | 函数指针类型必须与目标函数**完全一致**（含 `const`/参数） | 标准 6.7.6.3 + 编译器告警 | 通过 `void*` 强转绕过 |
| 5 | `C-VOLATILE-001` | `volatile` 只保证"不被优化掉的访问"，**不**提供原子性/顺序 | 标准 6.7.3 + 反汇编实测（`-O2`） | 用 `volatile` 当多线程同步 |
| 6 | `C-SETJMP-001` | `longjmp` 跳过后，非 `volatile` 局部变量值不确定 | 标准 7.13.2.1 | `setjmp` 后读普通局部变量 |
| 7 | `C-INT-PROMO-001` | 整数提升 + 有符号/无符号混比 ⇒ 意外巨大值 | 标准 6.3.1 | `x < sizeof(y)` 类比较 |
| 8 | `C-BITFIELD-001` | 位域布局/顺序**实现定义** | 标准 6.7.2.1 + 双编译器对比 | 跨编译器假设位序 |
| 9 | `C-MACRO-001` | 宏要防求值多次/优先级：括号 + `do{}while(0)` | 标准 6.10.3 + 展开实测（`-E`） | `#define SQ(x) x*x` |
| 10 | `C-UB-001` | C 的 UB 清单（含严格别名）与后果 | 标准 Annex J.2 + `-fsanitize=undefined` | 有符号溢出"就回绕"的假设 |

**每张卡的验收标准（四条，缺一不算完成）**：
1. **标准条款**：给出编号（如 `6.7.6.3`）+ 一句原文摘录；
2. **真实编译器实测**：`gcc` 与 `clang` **各一次**（L1），记录命令与输出（**不是**"应该会告警"）；
3. **反例**：至少 1 个"看起来对但错"的代码片段，并说明它错在哪条规则上；
4. **可判性**：能被现有 67 规则中的形式规则（或 E1 §2.2 的 `C-*` 新规则）判 pass/fail。

**648 的验收口径**：10 张卡全部满足上表四条；**新规则 ≤3 条**（能复用形式规则就不新增）；
`run_648_gate` PASS。

**风险预案**：
- 若**标准源（WG14 N 文档）拿不到**（E1 §2.3 未决）⇒ 退化为"**用 C 编译器实测为准**，标准条款留空并标记 `needs_human`"，**不许编造条款号**；
- 若某张卡**给不出机器可判的形式**⇒ 降级为 `PED`（教学）卡并如实登记，**不硬塞进验证面**。

## 三、649 · 第二批：嵌入式特有卡（10 张）

**前置门槛（必须先满足，否则 649 不做）**：
1. **L0（真机实测）的获取方式已定**：QEMU（可脚本化）**或**真板 + CI 硬件 —— 二选一，**人裁决**；
2. 交叉工具链 `arm-none-eabi-gcc` 在构建环境可用（E2 未验证）；
3. E2 §2.3 的**证据分级扩 L0** 已落地（否则卡片的最高证据只能到 L1，价值有限）。

| # | 卡 id | 论断 | 证据档位 |
|---|---|---|---|
| 1 | `EMB-ISR-NO-BLOCK-001` | ISR 内不得调用阻塞 API | L1（编译告警/静态）+ L0（板上时序） |
| 2 | `EMB-VOLATILE-MMIO-001` | 寄存器访问必须 `volatile` | L1 + 标准条款 |
| 3 | `EMB-STACK-BUDGET-001` | 栈用量必须有证据（`-fstack-usage`/静态估算） | L1（工具输出） |
| 4 | `EMB-FPU-COST-001` | 无 FPU 时浮点是软件模拟（代价可测） | L1（反汇编/周期） |
| 5 | `EMB-REG-LAYOUT-001` | 寄存器结构体布局须 `static_assert` 校验 | L1（双编译器对比） |
| 6 | `EMB-SHARED-ATOMIC-001` | `volatile` ≠ 原子；共享数据要临界区 | L1 + L0 |
| 7 | `EMB-STARTUP-SECTIONS-001` | `.data/.bss` 初始化依赖启动代码 | L1（链接脚本/map 文件） |
| 8 | `EMB-ATTR-PORTABILITY-001` | `__attribute__` 用法在 GCC/Clang 间差异 | L1（双编译器） |
| 9 | `EMB-INTERRUPT-LATENCY-001` | 中断延迟可测量（含优先级配置） | **L0 必需** |
| 10 | `EMB-POWER-MODE-001` | 低功耗模式进出条件与唤醒源 | L1 + L0 |

**649 的验收口径**：同上四条；**其中标记 L0 的条目必须真跑过**（否则不得标 L0，只能标 L1 并如实登记）。

**风险预案**：
- **拿不到 L0 环境** ⇒ 649 **只做 1–8**（L1 可得的），9/10 明确**挂起**并登记（**不假装**）；
- 工具链装不上 ⇒ 649 整批**顺延**，改为在 648 的基础上扩 C 卡数量（保底产出）。

## 诚实登记

1. **本批（647）只做调研**：E1/E2/E3 **不建任何卡片、不写任何规则、不改任何代码**（§十二.5）；
2. **本计划的所有工作量都是估计值**，未做试点校准；
3. **两个最大未决点**：① 标准源（WG14/ARM 文档）可用性与授权；② 嵌入式 L0（真机）获取方式 ——
   两者都是**交人项**，不是技术能单方面解决的；
4. **不承诺"打靶一定成功"**：648 若发现"某类论断机器判不了"，正确做法是**把它降级为教学卡并登记**，
   而不是降低判据把卡片"做绿"。
