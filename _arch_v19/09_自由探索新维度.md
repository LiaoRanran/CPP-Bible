## 一、新维度陈述

前 8 个维度（含前 9 轮调研）都把阙疑当作**技术系统**来探；本维度把它当作**激励系统**来看。

> **D9（新）· 激励兼容性假设：在单用户系统中，验证者、被验证者、验收者是同一效用函数。拦截有确定成本（返工、延期、数字变差），而宽松没有即时外部成本（没有第二个用户/读者/监管者受损）。因此系统的均衡演化方向不是越来越严，而是越来越"看上去严、实际上宽松化"。机械判决层 9.2/逃逸率 0.34% 的高分与 0 block / 186 warn / 大量 legacy 豁免并存，不是两个独立事实，而是同一激励结构的两个必然输出。**

这解释了一个纯技术视角解释不了的现象：**为什么规则越建越多（63）、工具越建越强（196），而当前实际拦截数是 0，且 warn 被周期性地"采纳为基线"。**

## 二、理论基础

- Goodhart（1975）："Any observed statistical regularity will tend to collapse once pressure is placed upon it for control purposes."；Strathern（1997）凝练为"When a measure becomes a target, it ceases to be a good measure"【已查证，原始 1975 澳洲储备银行会议论文；Strathern, European Review 5(3):308, 1997】。
- Manheim & Garrabrant 把 Goodhart 失效分为四机制：**回归型**（选代理指标同时选中噪声）、**极值型**（优化到旧关系失效区）、**因果型**（监管动作本身导致关系崩塌，含指标操纵）、**对抗型**（目标不同的 agent 主动制造崩塌）【已查证，arXiv:1803.04585, 2018】。
- 组织行为学经典：Kerr（1975）"奖励 A 却指望 B 的愚蠢"——激励错位下个体理性地优化被奖励项【一方称，Academy of Management Journal 18(4):769–783，标题/卷期高置信，正文未重开】。
- 这些不是道德批评：它们预测的是，**没有任何坏人，系统也会向宽松漂移**，因为严格的成本由系统承担、收益在系统外部（未来的学习者），而外部受益者在单用户结构里没有席位。

## 三、本仓证据（p09 活跑 + git 历史 + 台账，全部可复算）

1. **活跑 gate（CPPBIBLE_OBS=0）：block=0 / warn=186 / advice=5。即当前没有任何一条规则真正拦住任何东西。** warn 分布：
   - ATOM-CLAIM-CONCEPT-NORMALIZED 77（概念不在规范集）
   - OBSERVATION-LIVENESS 50
   - INFERENCE-NOT-MACHINE-VERIFIED 28
   - EV-MATRIX-UNBACKED 16（p03 证明该规则真实有效，这 16 卡确实缺第二留痕）
   - EV-OUT-UNDECLARED-KEY 6 等。
   - 注册 severity 设计是 block 40 / warn 16 / advice 7——**40 条设计为 block 的规则在当前数据上 0 命中，而 warn 在持续挂账**。
2. **信号被定期"转正为基线"（因果型 Goodhart 的直接物证）**：近期提交（本调研期间并发会话刚提交，HEAD 6861a7f 附近）：
   - `d1508d6 fix: golden_lock 接受 OBSERVATION-LIVENESS 50 条 warn 为 legacy`
   - `3ac90d1 fix(A3): 适配 golden 锁已采纳 OBSERVATION-LIVENESS=legacy（基线 136→186）`
   即 50 条 warn 没有被修复，而是被**验收锁接受为 legacy 基线**，门禁基线随之从 136 抬到 186。这是教科书式的"度量→目标→改写度量阈值"。
3. **豁免台账规模**：poison_exemptions.yaml 27 条规则豁免，**27 条全部带 redteam_seen: legacy**；compile_exempt.json 225 行有效条目；artifact_producer_exempt.txt 57 行。毒样例规则覆盖率分母因此是 39/63（brief 数字）——24 条规则没有端到端毒样例（台账辩称由 pytest 兜底）。
4. **git 历史（1455 提交）**：含 legacy/豁免/降级/接受等宽松化语义 ≈ 49（3.4%），含拦截/封堵/收紧 ≈ 60；显式提及 legacy 的提交 21 条。宽松化不是一次性事件，是持续的小步动作流（49 条里大量是"适配/化债/归档/接受"措辞）。
5. **与维度5 同源的人审宽松化**：388 边 13 分钟批量授权（0 逐条），是人在自己的效用函数下对"返工成本"的理性反应。
6. **反向证据也记录**：40 block 规则的存在、124 毒样例、逃逸 1/1406 的诚实公布、warn 全部显式登记而非隐藏——说明系统有很强的"诚实文化"在**对抗**该漂移。本论点不是"系统在作弊"，而是"诚实文化在与激励结构拔河，且激励结构在 warn 层持续得分"。

## 四、该维度如何改变前 8 维的结论

- 它解释了为什么**元验证（维度3）和人审重做（维度5）应该排最前**：它们是仅有的两个"给严格性提供外部支点"的动作——双实现引入异质执行者，真逐条人审引入（哪怕只有一个人的）非机器成本信号。
- 它给维度1/7 的自进化判了死刑的另一条理由：让系统在"自己承担成本、自己无人受益"的结构里自动进化，进化方向必然朝宽松（Kerr/Goodhart 预测），除非外部受益者（真人掌握度）进入回路。
- 它给维度2 VDD 提了个醒：76% 文本规则即使前移到生成期，也会被后续以"legacy/豁免/适配"形式重新打开——**没有激励配套的规则会被规则化地规避**。
- 它重新解释 v11 的 A1（治理文档在信任根外）：那不仅是技术漏洞，是激励问题——政策文件没有保护，因为保护政策的收益在外部，改政策的便利在内部。

## 五、可操作的推论（只给方向，不做建设）

1. **把 warn 当作有保质期的负债，而非可接受状态**：为每条 warn 记 birthday + SLA（要么限期修复，要么显式降级并改变规则的设计声明，禁止"接受为基线"而不动规则）。golden_lock 应锁"warn 不增"而非"接受当前 warn 快照"。
2. **让宽松动作比修复更贵**：豁免/legacy 需要写一份"谁是该宽松的外部受害者、为什么现在可接受"的显式陈述（27 条 poison legacy 目前理由是"pytest 已覆盖"，应升级为可核验的具体测试名映射——这其实台账已部分要求，执行可抽查）。
3. **引入外部受益者视角的最小动作**：哪怕没有第二用户，也可以用"未来学习者"假设人格做红队——每条 block 规则配一句"如果这条失效，学习者会形成什么具体错误心智模型"。这把外部收益内部化，是单用户下唯一可做的激励校正（弱于真多主体，但成本≈0）。
4. **度量层防 Goodhart**：逃逸率/通过率任何一个被当目标时都要配对抗指标（如 warn 存量、豁免增长率、规则变更方向的净严格度：block→warn 的降级必须留痕计数）。

## 六、反例与风险（≥2）

1. **0 block 可能只是"系统已收敛到干净态"的正常结果**：规则跑在已被多轮清洗的 27/56 卡上，无 block 可以是成熟而非放水。反证检验：warn 规则里 EV-MATRIX-UNBACKED（16）是 p03 证明真实有效的缺口、CONCEPT-NORMALIZED 77 是概念本体欠债——这些是**已知未修**而非无问题，故"干净态"解释不成立于 warn 层。
2. **legacy/豁免可能是务实的工程节奏**：把不经济的端到端毒样例换成 pytest 正反例（台账明文）是合理测试分层，不等于放水。该机制本身不坏，坏的是**豁免总量没有反向指标和到期复查**；本论点针对的是"只增不减、接受为基线"，不是豁免制度本身。
3. **激励分析在单用户下可能过度拟人**：没有组织政治、没有 KPI 奖金，"激励"只是个人的时间偏好；把个人自律问题包装成机制问题可能开错药方。回应：正因为是单人，才更需要把外部性显性化（规则 3、4），个人自律需要外部化的脚手架（这正是整个阙疑项目存在的理由——它本来就是给自己造的外部记忆）。
4. **"外部受益者"在可预见未来可能一直缺席**：若用户主要是自学者本人，"未来的我"能否承担独立验证者角色存疑（self-binding 的经典弱点）；此时该维度给不出结构性解，只能给纪律性缓解——必须诚实承认这是上限。

## 七、模型上限态（自判）

**单用户无法消除激励不兼容的根因（受益者不在场），但可以做到三件事：让宽松动作留痕且不廉价、给严格性配异质支点（双实现）、把"未来学习者"制度化地放进每一次降级决策。** 这是本轮自由探索给出的、与技术维度正交的新边界：**阙疑的下一阶段不仅要防错误的结论，还要防正确的规则被自身的激励结构慢慢溶解。** 我把它列为与维度3/5 并列的三个优先方向之一。
