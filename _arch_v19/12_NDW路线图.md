# 12 · NDW 路线图（下一步落地路径，每项带开门数字 + 验收标准）

> _arch_v19（595）· 2026-09-21 · 只读（本文件是探明边界后的路线建议，不是建设实施）
> NDW = Now（现在做）/ Door-gated（等开门信号）/ Wait（冻结等待）。所有验收标准均可机器复算。

## 一、NOW（0–3 周，纯本地，总预算 ≈ 1.5–2.5 人周）

### N1 人审台账诚实化（G1/G9）
- **动作**：① 报告口径改写为"1 审阅者/2 次批量授权/388 边/独立逐条 0/抽样 20（C-P95≤13.9%）/镜像 194 单列"；② 主动学习挑 30 条（多命题卡桥边+34 条 medium+W2 判决实际依赖边）做真逐条复核，理由必须引用边两端具体命题短语；③ grounded 计算把 194 对称边标 `derived_from_reverse`，不计独立人类票。
- **开门数字（开工即满足）**：distinct_reasons=5、逐条=0、镜像=194（p05 已测得）。
- **验收标准**：30 条复核后逐条率 >0 且每条 reason 含边特定引用；复核边的 approve 错误率 C-P95 上界可算（n=30 时 0 失败≈9.5%）；W2 报告中 IN114 的置信度注释区分独立票/镜像票。
- **止损**：复核发现 >3 条原批量 approve 实为误标 → 暂停，回查整个 AI 预标注漏斗（此时 C-P 13.9% 的最坏情形被实证，需扩大复核到 60–90 条）。

### N2 尺子全集完整性根 + 活规则清单锁（G2/G6）
- **动作**：.tool_checksums / Merkle 根扩入 mutation_fuzz.py、tool_integrity.py、d5_compile_gate.py、d5_runtime_gate.py、d5_source_integrity.py、attack_edge_generator.py、bkt_solver.py、learner_mastery_update_613.py；固化 `RULES` 活 id 集合（63）为期望清单，增删规则须显式改清单。
- **验收**：受保护关键尺子 11/11（当前 3/11）；CI 中"静态枚举 vs 活注册表"差异必须为 0（当前 4，本轮探针 p03 复现）；篡改任一新增保护文件必导致校验失败（毒样例回归一条）。

### N3 规则双实现常态化种子（G3）
- **动作**：以 p03 为模板，对 EV-ZERO-DIAG-WERROR、S3-EXPECTED-HARDCODED、EV-ARTIFACT-VERSION-MATCH、M1 字段删除检测各做一个异质第二实现（不同解析路径），接入 CI 持续比对。
- **验收**：4 条规则双实现对全部存量卡判决一致率 100%（不一致即告警，不允许静默）；每季度至少一次真实分歧触发（若无分歧，怀疑第二实现退化为镜像，需换人/换法重写）。

### N4 宽松化反向指标（G4/G7）
- **动作**：golden_lock 从"接受当前 warn 快照"改为"warn 总数不增（186 封顶，新增须同时消旧）"；27 条 poison legacy 豁免补到期日 + 具体 pytest 测试 ID 映射；新增 metric：规则降级次数（block→warn/advice）与豁免净增长，随报告输出。
- **验收**：warn=186 只降不增（任何 PR 抬升即红）；豁免台账无缺失到期日/测试映射的条目；commit 中再出现"采纳…为 legacy"必须附带降级计数变化。

### N5 统计口径与台账更正（G13/G14）
- **动作**：逃逸率报告同时给双侧 CI 与单侧上界并标明语义（双侧 [0.0018%,0.396%]；单侧 95%=0.337%，契约语义引用单侧）；权威数字改为 atoms 27（23 verified+3 red-team-verified+1 draft）/evidence 56/MIS 79/tests 174。
- **验收**：p00 探针数字与权威台账逐项一致；报告不再出现无口径标注的"上界 0.3956%"。

## 二、DOOR-GATED（开门才启动；门不开不投人）

### D1 学习者传感器接通（G5）—— 门轴
- **开门数字**：`data/learner_behavior.jsonl` 真实（非 simulated）事件 ≥ **50 条**，覆盖 ≥ **10 个不同 KC**，时间跨度 ≥ **7 天**（防一次性表演）。
- **门后动作**：BKT 四参数网格 MLE 在该数据上可拟合（likelihood 显著优于 0.1 先验），recommender 第一次输出因人而变的推荐。
- **验收（v18 跃迁三条件的具体化）**：系统输出（推荐顺序/内容）因某用户掌握度跃迁而改变，且该变化可双向追溯（行为事件→BKT 更新→推荐 diff）；至少 1 个 KC 完成 未掌握→掌握 的可观测转移。
- **门不开时**：明确**不**启动任何练习生成器/自进化闭环。

### D2 VDD 窄子集（维度2）
- **开门数字**：D1 已验收 + 47 条 A 类规则的 schema 化设计评审通过。
- **动作**：A 类规则约束解码化（先服务"为薄弱 KC 生成练习"，不生成完整 verified 卡）；B 类 16 条保持 replay 独立执行，失败回灌。
- **验收**：生成练习对 A 类规则首过合规率 ≥95%；任何生成内容未经 replay+人审不得进入 evidence/atoms；生成内容 0 条触碰 block（否则生成器回炉，不放行内容）。

### D3 自进化 L2 实验（维度1，严格封顶在 L2）
- **开门数字**：D2 运行 ≥4 周且人审合并队列稳定运转。
- **动作**：机器提案（修复 warn/起草练习/补证据）→ verify 全家桶 → 人审 merge；L3 自动合并永久冻结。
- **验收**：机器提案被人接受率、接受提案的事后推翻率（保留 90 天）双指标公开；推翻率 C-P 上界超阈值即关停提案器。

### D4 证据卡 attestation 化（G12）
- **开门数字**：出现"向他人展示/分享证据"的真实需求（开源发布/求职/第二学习者）。
- **验收**：陌生人仅凭 attestation+源码在干净环境重跑，56 卡复现率（结构断言口径）可量化；attestation 含规则集哈希，与 N2 根联动。

### D5 Clang/交叉编译矩阵（G8，嵌入式顺势）
- **开门数字**：嵌入式内容批次启动或 CI 具备 Clang/arm-none-eabi 能力。
- **验收**：19 张多编译器卡的第二编译器列回填；GCC 79/Clang 1 的多样性比例改善；跨编译器分歧全部有解释（不静默）。

## 三、WAIT / FREEZE（不设开门，明确冻结）

- **W1 全自动自进化闭环（L3+）/ 自修复自动合并**：违第一原则，永久冻结，除非系统外存在与生成者利益独立的 reward 主体。
- **W2 朴素多 agent 辩论/LLM 自裁为终审**：v18 已用三项 2025–26 研究否掉，不重复投入。
- **W3 单用户 BFT/TEE/密钥身份/链上身份**：v10/v16 结构性结论，等真多主体。
- **W4 跨领域平台化（电子/金融多域）/ Coq-Lean 全量形式化 / 概率 AF / KG 嵌入**：v15 + 本轮维度6 结论，冻结。
- **W5 继续手工加码文本规则追求逃逸率更低**：边际≈0（单侧上界 0.337%，分母 1406，再降需数千次试验），资源转 N/D。

## 四、时间-资源约束下的现实排法（对应 brief §七）

- 第 1 周：N1+N2+N5（诚实化与保护，成本最低、止血最急）。
- 第 2–3 周：N3+N4。
- 之后：进入等待——**路线图的主要动作是"等 learner_behavior 出现 50 条真实事件"，在那之前，所有看起来更宏大的方向都应被本路线图显式拒绝。**
- 免费额度：全部 N 项纯标准库/已有 g++，无新依赖、无 LLM API 刚需；D2 才可能产生模型调用成本，且由真实学习需求触发。

## 五、本路线图与前 9 轮路线图的关系

v11 的 R1（v7 基线重冻结）/R3（治理文档）/R4（grounded 全局答案）大部分已在 609–613 批次兑现；v14 人审、v16 Merkle、v17 replay 可证、v18 D5 均已落地或半落地。**本轮路线图的特征是"不再新增机械能力，转去做前九轮埋下的账的诚实化，并把下一步的开关明确交到真实学习者手里"——这是从建设节奏到等待节奏的切换建议。**
