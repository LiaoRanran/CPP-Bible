## 一、一页结论

**元验证是本轮探针中"单位投入挖出最多实证"的方向，也是唯一在一个下午就产出可复算硬结果的方向：一把尺子（EV-MATRIX-UNBACKED）用独立第二实现重判，自然实现与官方实现一致率只有 68.4%（19 张适用卡 6 张分歧），分歧根因恰好是官方在 2026-09-12 被 P12 毒样例攻击打出来后才补的一行预处理。** 这不是纸面风险，是差分测试（differential testing）思想在本仓的一次微缩实证：**规则的"正确性知识"有一部分不在规则主逻辑里，而在被历史攻击逼出来的辅助函数里，读代码重写会自然丢失。**

同时，保护集审计发现：定义攻击面的关键尺子 `mutation_fuzz.py`、定义元校验的 `tool_integrity.py` 自身、以及 d5/attack_edge/bkt 等 8/11 关键尺子**不在 checksum 保护集内**（196 个工具仅 12 项被钉）。

**范式跃迁潜力评级：中-高（不扩规模但直接抬"令人信服"的天花板；是 DDC 思想在单用户下唯一可低成本兑现的形态）。**

## 二、理论基础

- Thompson《Reflections on Trusting Trust》（1984）：编译器可自举植入后门，源码审查无法发现二进制中的恶意【已查证，CACM 27(8):761–763，DOI 10.1145/358198.358210；Russ Cox 2023 用原始代码复现】。
- Wheeler 的 Diverse Double-Compiling（DDC）：用一个**独立的可信编译器**重新编译被测编译器源码，逐字节比对，可检测 trusting-trust，且给出形式化证明【已查证，arXiv:1004.5534，2009 GMU 博士论文】。
- Knight & Leveson（1986）：多版本编程的失效高度相关（common-mode failure），"N 个相似实现 ≠ N 倍可靠性"【一方称：v10 已检索 IEEE TSE SE-12(1)，DOI 10.1145/TSE.1986.6312924，本轮未重开正文】。这规定了"第二实现"必须真异质（不同语言/不同解析路径/不同人），否则只是同谋。

## 三、本仓探针证据（p03，全部可复算）

**实验1 · 读代码能否完整枚举规则：**
- 静态正则枚举出 59 条，活注册表（import `gate_engine.RULES`）63 条，**静态漏 4 条：S1-AUTHOR-SELF-VERIFY / S1-GIT-AUTHOR-BINDING / S2-EVIDENCE-VERDICT / S3-EXPECTED-HARDCODED**——漏掉的恰是"分权/反自证"系列（id 前缀含数字 S1/S2/S3，朴素枚举器假设前缀纯字母）。**含义：连"列出全部规则"这件元工作，读代码都做不对，必须活跑。**

**实验2 · 同一规则双实现差分（EV-MATRIX-UNBACKED）：**
- 2a 自然第二实现（一个读了规则主逻辑的工程师会写的版本：剥 actual 段→数留痕锚）：19 张多编译器卡中 **6 张被误判 BACKED（应 UNBACKED），一致率 68.4%**。
- 分歧根因：sha256 行的纯数字片段（如 `0724805925216`）被"CI run 号裸数字"锚正则误收。官方 `_raw_without_actual`（gate_engine.py:987-999）**除剥 actual 外还剥 artifact_sha256 行，注释明确写"2026-09-12 由 P12 毒样例首跑暴露：只剥 actual 时毒卡仍靠 sha 全零被放行"**。
- 2b 对齐该预处理后：**一致 19/19 = 100%**。
- 解读：规则主判据可被独立复现，但**抗攻击知识隐性地埋在预处理里**；差分测试一次就把它挖了出来。这正是 DDC/差分测试相对"自查"的价值——不依赖作者记得自己为什么写这行。

**实验3 · 尺子自身的保护面：**
- `.tool_checksums` 钉 12 项：5 CORE（gate_engine/poison_drill/atom_evidence_replay/cppbible/toolchain）+ pyproject + conftest + governance_docs_manifest + supply_chain×2 + poison_exemptions.yaml + poison_surface_map.json。
- 196 个 tools/*.py 中 191 个无校验。关键尺子裸露：**mutation_fuzz.py（变异发现器，改它可让逃逸样本消失）、tool_integrity.py（元校验器自身）、d5_compile_gate/d5_runtime_gate/d5_source_integrity.py、attack_edge_generator.py、bkt_solver.py、learner_mastery_update_613.py**（11 项中 8 项裸露）。
- 注：v16 曾报"规则/策略文件不在保护内"，本轮确认 poison_exemptions.yaml / poison_surface_map.json / governance manifest 已纳入（v16 后已修），但变异器与元校验器自身仍裸露——v16 的纠偏需要再更新。

## 四、实现路径（单用户可做的 DDC 最小子集）

1. **规则双实现常态化（1–2 人周/条，先做高价值 5 条）**：选 block 级、历史上被攻击打过的规则（EV-MATRIX-UNBACKED、S3-EXPECTED-HARDCODED、EV-ZERO-DIAG-WERROR、M1 字段删除检测、artifact_sha 校验），用**异质路径**重写（不同语言思路：主实现是逐行 Python 解析，第二实现用整体 YAML 解析或声明式规则表），CI 每次跑两实现，分歧即报警。本轮探针已提供第 1 条的完整模板。
2. **把 mutation_fuzz.py / tool_integrity.py 纳入校验和**（0.5 人日）：纯增量，扩大 `.tool_checksums` 覆盖；进一步用 Merkle 根钉住"全部尺子文件"（v16 阶段1 已探针验证可行）。
3. **规则注册表自身的活跑快照**：把"活跑 63 条 id 集合"固化为期望清单，任何增删规则必须显式改清单——防止规则被静默移除（静态枚举 59≠63 证明静默差异真实可能）。
4. **不做**：引入 Coq/Lean 形式化全部规则。C++ 语义和教学命题不可判定，重量级自举在本仓无落点（v15/v17 已论）。

## 五、成本-收益

- 成本：极低（第 1 条双实现含探针 < 半天；checksum 扩面 < 1 天）。
- 收益：把"规则正确"从"作者声称 + 毒样例侧覆盖"升级为"异质实现一致 + 攻击知识被差分逼出"。这是单用户结构下**唯一不依赖第二个人**就能获得的近似独立票（独立性来自实现路径差异，不来自主体差异；强度弱于真多主体，但 Knight-Leveson 警告的是"相似实现"，异质实现正是对该警告的对症）。
- 上限：双实现共享同一份自然语言规格，规格本身若错，两个实现会一起错（common-mode 仍在规格层）。元验证能消实现 bug，消不了规格 bug。

## 六、与现有系统的关系

- v17 已证 replay 内置轻量翻译验证（`_recompile_invariant`）——那是对**编译器/工件**的翻译验证；本维度是对**验证规则自身**的翻译验证，同构、互补。
- v16 Merkle 阶段1 已验证文件集完整性根；本维度补上"哪些文件必须进根"的具体清单。
- 与维度4分布式互补：多主体给独立票（结构性受阻），双实现给异质票（现在就能做）。

## 七、反例与风险（≥2）

1. **规格层 common-mode**：两个实现都忠实实现了一条错误规则时，差分 100% 一致但结论全错。差分测试不验证规则该不该存在。缓解：毒样例（攻击驱动）+ 人审规格，但无法根除。
2. **双实现的维护成本与腐化**：第二实现若无测试价值会随主实现一起失修，最终退化为复制件；且为了"让它过"可能反向把第二实现写成主实现的镜像（伪差分）。需要分歧报警持续有真实触发（本轮 6 条分歧证明触发真实存在，但这是一次性红利）。
3. **自举悖论**：tool_integrity.py 校验别人，谁校验它？扩大 checksum 集只是把信任根再挪一格（挪到 git/本地），v10 已证明单用户无密钥下信任根不可真正闭环——元验证提高攻击成本，不创造新信任主体。
4. **隐性知识的反身性风险**：把"sha 剥离"这类补丁知识显式化后，攻击者也能读到——安全靠的是"你不知道要构造什么攻击"的模糊性会下降；净收益仍为正（防御者收益更大），但这是攻防军备竞赛而非一劳永逸。

## 八、模型上限态（自判）

元验证在单用户下的上限 = **关键规则异质双实现 + 尺子全集完整性根 + 活规则清单锁**三件套；它把"验证器可信度"从自评抬到"可被任何人用第二实现复核"，是六维里信任分（当前 8.9）和度量分（8.6）少数还有明确工程空间的方向。但它本质是**加固现有范式**，不产生新能力——质变成色中等，可信度成色很高。
