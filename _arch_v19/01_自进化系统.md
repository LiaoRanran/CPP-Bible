## 一、一页结论

**阙疑当前自进化等级 = L0+（L1 半成品，L2 以上在现有数据下结构性不可达）。**
不是因为缺一个 `discover()` 函数，而是因为自进化闭环的两个必要输入——**独立发现源**与**外部 reward（学习者结果）**——在单用户、零真实学习事件的仓内都不存在。p01 实测：27 张原子卡的命题证据覆盖率已经是 **79/79 命题全有 evidence、29/29 inference 全有 external_basis、27/27 卡被证据覆盖，仅 1 条 prerequisite 悬空**——机器在"卡面结构完整性"这个 discover 空间里已经几乎无缺口可发现。自进化若启动，只会在一个被打磨到无缝的结构上做空转。

**范式跃迁潜力评级：中（线性增量为主，只有在外部条件变化后才质变）。**

## 二、理论基础（L0–L5 与第一原则的张力）

- L0 纯人工 → L1 机器发现（只读 gap 扫描）→ L2 机器提案 → L3 自动闭环（提案自动合并）→ L4 主动进化（自定搜索方向）→ L5 目标自校准。
- 理论原型 Gödel Machine：**只有当内嵌证明器能形式化证明某次自我重写"期望效用更优"时才允许重写**【已查证】。Schmidhuber 的原始工作（2003 技术报告，Springer 2007 成书版）自己就指出：在不附加限制性假设时，"证明一次修改净有益"在实践中不可能——这正是 L3/L4 的理论天花板。
- 2025 年的工程化版本 Darwin Gödel Machine（DGM）放弃了形式证明，改为**经验验证每次自改**：自改代码→在 SWE-bench/Polyglot 上跑分→保留涨分的变体，SWE-bench 20.0%→50.0%，但全程需要**沙箱 + 人监督**【已查证】。这等于承认：当代自进化 = "外部基准当 oracle + 人保留否决权"，不是自动闭环。

## 三、本仓探针证据（p01 原始输出）

| 五步 API | 仓内语义命中工具数 | 实质 |
|---|---|---|
| discover | 59 | 多为 coverage/triage/audit 只读扫描，无统一缺口模型 |
| propose | 63 | 多为 candidate/proposal/regen，但无"命题/证据内容"自主生成器 |
| verify | 171 | **极强**：gate/replay/poison/mutation 全家桶 |
| merge | 7 | accept/promote/transition 多为状态机辅助，无自动合并通道 |
| report | 108 | dashboard/html/summary 成熟 |

- 知识缺口（discover 原料）：命题无 evidence **0/79**；inference 无 external_basis **0/29**；prerequisite 断链 **1/25**（`ATOM-UB-GRAY-001 → ATOM-UB-DEF-001` 目标不存在）；无证据 serves 的原子 **0/27**。
- 闭环 reward：`data/learner_state_612.jsonl` 27 行全是 `kind=init, mastery=0.1`；`data/learner_behavior.jsonl` **0 事件**。真实掌握度更新 = 0。
- 含义：**verify 这一环独强，discover 的文本侧已无矿，reward 侧是空的**。自进化循环缺的是首尾（发现什么值得改、改了有没有用），不是中间（怎么验）。

## 四、实现路径（若要做，分三档）

1. **L1（0.5 人周，纯只读可先做原型）**：统一缺口模型——把 p01 的四类扫描扩成持续 discover：悬空 prerequisite、warn 规则长期挂账（186 条，见维度9）、`INFERENCE-NOT-MACHINE-VERIFIED` 28 条、证据 status 缺失 42/56（p04）。产出"缺口清单"而非补丁。
2. **L2（1–2 人月）**：机器起草补丁/新证据，**强制走现有 verify 管线 + 人审合并**（对应 DGM 的 sandbox+human oversight，也对应 SapFix"永不自部署"，见维度7）。第一原则零违反：生成者是 proposer，judge 仍是 gate+replay+人。
3. **L3+（结构性暂缓）**：自动合并需要独立 reward。唯一合法 reward 是**真实学习者的掌握度变化**（D5 钥匙），但当前样本量 0；在 reward 出现前，L3 等价于"让系统按自己的指标优化自己"=Goodhart（维度9 实锤）。

## 五、成本-收益

- 成本：L1 极低（探针已证明半天可出数字）；L2 中等（起草器 + 人审队列）；L3 不可仅用工程投入买到，需要真实用户活动。
- 收益：L1 把"缺口"从散落报告变成单一待办源（管理收益高，能力收益低）；L2 可把 186 warn 的消化提速（但注意 warn 里 77 条是概念归一化这种语义判断，机器提案质量存疑）；L3 才是质变，但门槛在仓外。

## 六、与现有系统的关系

完全顺承：v18 的 Learner Twin 是 L3 的 reward 传感器（已建但 0 事件）；v11 已判定"真实缺陷率分母原理上不可知"——那正是 discover 侧独立发现源缺失的另一种表述。自进化不是新系统，是把现有 171 个 verify 工具**首尾接上**，而首尾在仓外。

## 七、反例与风险（≥2）

1. **影子赛跑（p07 实证）**：系统自生成变异→自验→自修，覆盖的永远是自己 7 个算子的已知族；p07 十轮模拟显示对"真实缺陷率分母"增益恒为 0。自进化会制造"越来越强"的错觉，实际只是对自己影子过拟合（与 DGM 的外部基准、AlphaGo Zero 的真实胜负环境形成对照——它们有仓外 oracle，阙疑没有）。
2. **第一原则冲突点在 L3**：一旦系统能自动 merge 自己的提案，"生成者不能兼任判断者"被破——除非 reward（真人掌握度）与 proposer 严格分离。L3 自动合并若用系统自产指标做 reward，是结构性违规。
3. **Gödel 式证明在本域不适用**：C++ 教学结论的"净有益"不可形式化（涉及学习者认知），所以连"证明安全再自改"这条路都没有；只能经验验证，而经验验证需要外部样本。
4. **缺口已被打磨殆尽的另一面**：discover 在卡面 0 缺口，意味着 L1 的产出很快枯竭——自进化的燃料（结构缺陷）在前 51 批已被烧完。

## 八、本维度的"模型上限态"（seed evolving 自判，不抄旧调研）

在单用户 + 零真实学习者事件 + 无独立缺陷发现源的约束下，**自进化的可达上限是 L2（机器提案、人机共审合并），且主要价值是消化存量 warn/缺口这一次性债务，不构成持续进化能力**。L3 及以上不是工程问题，是"系统是否还连着真实学习者"的问题——这把球又踢回给 D5 钥匙：**自进化的质变不在进化器，在传感器**。
