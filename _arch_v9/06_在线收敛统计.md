**唱反调（本题最该说的话）**：
1. **"反复看同一个指标"在本仓是常态，但今天没有做任何 α 花费** ⇒ 现有所有 `C-P 95%` 区间的"95%"只对**单次**成立；把它们当作"连续监测的可信区间"是**统计误用**（会累积假阳性）。
2. **置信序列不是"更准的区间"，而是换了一个承诺**：它承诺"任意停止时刻覆盖"，代价是**同一 n 下区间更宽**。对本仓意味着：**用 CS 就无法再报出"看起来很窄"的区间**——这是要付的代价，不能只取其名。
3. **本仓当前的最大障碍不是统计方法，而是"尺子换了 5 次"**：v1（23.7%，含 M2 假逃逸）→ v2（6.3%）→ v3（3.8%）→ v5（≈0.9%）这条"历史"里，**每次"下降"的主要成分是口径修正，不是同一个量的变化**。⇒ **在没有冻结尺子之前，任何"逃逸率在降"的统计检验都是无意义的**（检验的是"不同尺子"，不是"同一把尺子的收敛"）。**这是本节最重要的一句。**

## 三、差距与风险

1. **缺口 1**：**没有序贯控制**。"每批看一眼逃逸率然后说'在降'"是典型的 peeking：看 N 次，单次 95% 的区间有 `1-(0.95)^N` 的概率至少一次误判（N=10 ⇒ ≈40%）。
2. **缺口 2**：**没有"批次可比性"的机器前置条件**。今天没有任何字段记录"这批用的是哪把尺子（口径版本）/哪套 oracle（gcc/gate/replay 版本）"⇒ 无法机器判定两批能不能比。（这与 Lens 3 的 D2 是**同一份数据**。）
3. **缺口 3**：**曲线数据不足以支持任何趋势结论**（1 个时点；且 v1–v5 是尺子变更史）。**算不出的就明说：今天无法给出任何带错误率上界的"在降"结论。**
4. **风险 A（最隐蔽）**：**把"抽样误差区间"当成"总误差区间"**。除了抽样，还有：运行间方差（579 已实证 ≥2/998）、口径变更、oracle 换代、非独立性（同一批内的变体共享基线与缓存 —— 严格说 k/n 的"独立同分布"假设不成立！）。⇒ 任何"上界"都必须**同时**声明它没盖住哪些误差。
5. **风险 B**：**用 α 花费掩盖"尺子变更"**。若允许在尺子变更后继续用同一张控制图，系统会显示"收敛"而实际是**换了评分标准**。⇒ 前置条件必须**机器可判**（见 N 的 `ruler_fingerprint`）。

## 四、N / D / W

**N（现在借，1 件）——给 `stat_bounds.py` 加"α 花费"版区间 + "在降"判据（纯新增函数）**

```
# 新增（不动任何既有函数）
def cp_interval_spent(k, n, looks, conf=0.95):
    """Bonferroni 式 α 花费：把总 α=1-conf 平均分给 looks 次看。
    语义：只要你**看的次数不超过 looks** 且每批 n 达标，则所有 looks 个区间
    **同时**成立的置信度 ≥ conf（保守；不需要任何分布假设之外的近似）。"""
    alpha = 1.0 - conf
    return cp_interval(k, n, 1.0 - alpha / max(1, int(looks)))
```
- **"在降"的合法宣称条件（全部满足才允许写进报告）**：
  1. **尺子一致**：两批的 `ruler_fingerprint` 相同 —— 定义为 `sha256(gate 规则集 id 排序 ‖ mutation 算子集合 ‖ 口径版本号 ‖ oracle 版本 3 元组)`（新字段，随批次落 `metrics.jsonl`）；
  2. **批次样本达标**：每批 `judged ≥ n_for_upper_bound_zero(0.05, 1-α/looks)`（α 已花费；今天该值 = `n_for_upper_bound_zero(0.05, 0.95)` = 59 的量级，**具体值须按花费后的 conf 重算，我不在此写死**）；
  3. **区间分离**：最新批的**上界** < 基线批的**下界**（同一 `conf_t = 1-α/looks` 下算）；
  4. **批次 ≥6**（避免用两点画趋势；这是**纪律**不是统计定理，写死为门槛）。
  - 三条不满足 ⇒ 报告只能写"**未判**（insufficient evidence for trend）"，**不许写"在降"**。
- 机器验收：① `cp_interval_spent(k,n,1,conf) == cp_interval(k,n,conf)`（looks=1 退化必须逐值相等）；② `looks` 增大 ⇒ 区间**单调不缩**（单测：对固定 (k,n)，`cp_interval_spent` 的宽度随 looks 单调不减）；③ **既有函数输出零变化**（`cp_interval/wilson/proportion/...` 的回归锁逐字保留）。
- 零误伤证据：**纯新增函数**；`metrics_collector` 只**新增** `ruler_fingerprint` 字段与 tag 文案，不改既有键与口径；不动 mutation 报告的任何数字。

**D（攒数据，3 件，全部是"让趋势可被机器判"的前置）**

- D1：**冻结尺子**：从现在起，`ruler_fingerprint` 变更必须**显式登记**（谁、为什么、影响哪条曲线）。**这是全批最便宜、收益最大的一件事**（没有它，后面所有统计都是空谈）。
- D2：批次元数据随 `metrics.jsonl` 落盘：`{ruler_fingerprint, oracle: {gcc, gate, replay}, judged, k, n_a, variance_note, looks_so_far}`。
- D3：**连续 ≥6 批**（每批 `judged` 达标）——这是唯一能让"在降"变成可判的方式。**今天距此差：5 批 + 每批元数据。**

**W（等条件，3 件）**

- W1：**真正的 anytime-valid 置信序列**（Howard et al. 那一族；有 `confseq` 参考实现）。解冻信号：① 已有 ≥6 批**同尺子**数据（否则 CS 也救不了）；② 能用纯标准库实现其**单调性/覆盖性**的自检（否则无法验证自己没写错）；③ 接受"区间变宽"的代价。**现在不做**：在没有 D 的前提下引入 CS = 用一个更保守的区间去测一个还在变的量。
- W2：**SPRT / CUSUM / EWMA 在线控制图**。解冻信号：① 指标进入**稳态期**（尺子冻结 + 连续 ≥10 批）；② 有明确的"过程基线"（否则控制图没有中心线可言）；③ 能把"报警"与"判决"物理隔离（报警只进报告层）。**现在不做**：本仓的指标是**移动靶**（规则/算子/卡都在变）。
- W3：**A/A 检验与 flaky 判定**。解冻信号：① 需要区分"指标变化"与"跑批抖动"时（579 已实证抖动存在：`989/9/185` ↔ `991/7`）；② 有足够的重复跑预算（每次全量 ~200–690s）。**部分条件已满足**（579/580 已经用"同输入两次跑逐条相等"做了确定性自检）——本 lens 只把它**登记为统计前件**，不重复建设。
