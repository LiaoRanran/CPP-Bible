**唱反调（关键）**：
1. **DDC 的条件比字面严得多**：它要求两套**语义等价**的编译器 + "假设独立性"论证；本仓唯一在用的编译器是 g++（`toolchain.resolve_gpp()`），**第二套编译器是否可用我未核实**（规则里出现过 clang 字样，但**编译可用性未验证**，且本仓明令：禁止在共享工作树实跑、我只读）。⇒ DDC **不是**现在能直接借的 N，最多是 W（见下）。
2. **SBOM/in-toto/SLSA 都是"对外交付"的格式**：本仓没有外部消费者（不 push、不出包），现在落地 = 为了格式而格式。**借它们的"字段习惯"（谁/何时/在什么条件下/产出什么）而不是格式**。
3. **Model cards 对我们最不适用**：它描述的是"模型的性能与局限"，而阙疑要的是"**判定者版本 × 判定对象 × 判据类型**"的绑定 —— 更接近 in-toto 的 attestation 谓词，而不是 model card。

## 三、差距与风险

1. **缺口 1（核心）**：**没有"命题/证据 → 哪个 oracle 在哪个版本下判过"的绑定**。今天只有"卡面可选字段 + 报告层 stale"，且 0 张卡填过 ⇒ **换 g++ 之后，机器说不出哪些结论需要重验**。
2. **缺口 2**：**没有"判据类型"分类**。"这条结论是否依赖编译器行为"（compile/sha/run）与"是否只依赖规则文本"（rule）在数据里无法区分 ⇒ 影响面只能取"全体"（保守但无用）。
3. **缺口 3**：**没有换代收口条件**。换代后"何时算跑完"没有定义 ⇒ 容易出现"一半新版本、一半旧版本却被当作已确认"的中间态。
4. **风险 A（假继承，最危险）**：若允许"版本号向前兼容 ⇒ 结论自动继承"，攻击者只需把 registry 里的版本号改成兼容形态即可让结论免于重验。**⇒ 继承必须默认 fail-closed，且任何"兼容性声明"必须绑定人签**（照 `log_overturned` 的 git 作者模式）。本仓 `oracle_registry.json` 目前**没有任何签名**（谁改的只能靠 git 历史）。
5. **风险 B（TCB 声明被当成已证明）**：`scope` 是散文。一旦把它当"能力声明"用于自动决策，就会出现"散文承诺被当机器保证"的经典谬误。（本仓已有 564/575 的同类教训。）

## 四、设计草案（只设计，不实现）

**4.1 最小数据结构（在现有两处上扩字段，不新建服务）**

```
# data/oracle_registry.json（现文件，只加字段；保持"判决不读"不变量）
oracles.<name> = {
  version, scope,                       # 现有
  judges: ["compile","sha256","run_match","assert","rule-set"],   # 新增：它到底判什么
  invalidates_on_change: ["compile","sha256"],                    # 新增：版本变即失效的判据类型
  tcb_note: "g++/binutils/OS 本机工具链"                            # 新增：一行诚实声明（散文，仅供人读）
}
```
```
# 卡面/命题（可选字段，机器只读不判）
verified_by_oracle: {oracle: gcc, version: 15.3.0, judges: [compile, sha256], judged_at: 2026-09-18}
```

**4.2 换代重验调度算法草案（fail-closed 优先）**

输入：① registry 新旧差异；② 对象的 oracle 归属；③ 依赖边（Lens 2 的 DAG，可缺）；④ 三份 `--check` 基线。

1. **种子集** `S0` = { 对象 | 其归属 oracle ∈ 变更集合 }。**无归属（今天 100%）⇒ 默认全部进入 S0**（保守，且这正是"缺口 1 补不上的代价"）。
2. **闭包扩展** `S = closure(S0)`：沿**依赖边反向**（被依赖者变了 ⇒ 依赖它的一律进 S）。边缺失时**不扩**，但必须在报告里写"闭包不完整：缺 N 条边"。
3. **分档**：`强制重验`（其 `judges` 与变更的 `invalidates_on_change` 相交）／`可继承（需人签）`（其余）。**没有任何对象可以凭版本号自动继承**。
4. **调度**：按拓扑序分批跑；**每批只写"新归属"**，跑完一批才把该批从 `stale` 摘出；**未跑完的批次一律 stale**（禁止中间态进入"已确认"计数）。
5. **收口判据（机器可判）**：`S` 内所有对象都有新归属 **且** 三份 `--check` 基线重跑结果被显式记录（gate 规则/命中、replay confirm、poison 通过数）**且** mutation 权威值重跑一致。任一不满足 ⇒ 换代视为**未完成**。

**4.3 为什么这套能"弱模型可执行 + 不需要模型裁判"**：全部步骤是集合运算 + 查表 + 计数；没有一步需要语义判断。

## 五、N / D / W

**N（现在借，1 件）——`tools/oracle_rotation.py`：换代影响面报告（只读）**

- 命令形态：`--to gcc=16.0.0`（或 `--diff-registry <old> <new>`）/ `--check-registry`。
- 输出：① 卡面 `verified_by_oracle` 与 registry 不一致的卡（**今天 = 全部 83 张，因 0 张填**，报告须把这条**说成人话**："无归属 ⇒ 保守全量"）；② 按 `judges`/`invalidates_on_change` 算出的强制重验集合；③ 需重跑的三份 `--check` 清单 + mutation 权威值。
- 机器验收：① 与 `metrics_collector.oracle_report()` 的 `stale` 计数**逐条相等**（双实现对账）；② 只读（无写调用）；③ 两次跑 stdout 一致；④ **不得** import/调用任何判决入口（静态断言：源码不含 `gate_engine.run`/`replay.replay_card` 调用）。
- 零误伤证据：新文件；`oracle_registry.json` **只读**（本批我一次都没写它）；判决路径零改动；`--check` 基线数字不变（因为不跑它们）。

**D（攒数据，2 件）**

- D1：**给 83 张卡补 `verified_by_oracle`**（机器只出清单，人/强模型填）。这是让影响面从"全体"缩到"实际批次"的**唯一**办法；也顺手让 `oracle_report()` 的 `stale` 有意义。
- D2：**每次跑批把当次 oracle 版本 + 三份 `--check` 数字落进 `metrics.jsonl`**（只加字段）。换代收口的"证据"就靠这条时间序列。

**W（等条件，3 件）**

- W1：**in-toto/SLSA/AIBOM 式谓词化 attestation**。解冻信号：① 需要对外交付/跨系统审计；② D1/D2 已完成且字段稳定 ≥6 批。**现在落地 = 为格式而格式。**
- W2：**DDC（跨编译器重编译）**。解冻信号：① 第二套独立编译器在本机**经核实可用**（本次未核实，且**禁止实跑**）；② 已有"同一夹具两编译器行为一致"的判据需求；③ 能把 DDC 的"假设独立性"用本仓语言写清。⚠️ 特别注意：DDC 的对象是**编译器自身**，不是夹具；把它用在"夹具双编译"上是**另一个更弱的主张**（只能叫"跨编译器行为一致性检查"），不许混称 DDC。
- W3：**密码学签名/身份**（对 registry 与 attestation 签名）。这是 562 的冻结项之一：只评估解冻信号 —— 需要"跨机器/跨组织信任"时才解冻；本仓单人单机，git 作者绑定已覆盖"人的动作归属"。**不设计实现。**
