# 560-D · 方案自攻击与风险红队（最重要的一章）

> 每条优化逐个过三问：①动没动"必须真跑外部 Oracle 才信"？②会不会引入新的非确定性/竞态让"全绿"不可信？③错了怎么被机器发现、怎么回退？
> 判定：**动了 Oracle 且给不出可证明等价护栏的，本轮直接否决。**

## D1. 对 B1（编译层/P0-A/cache）的攻击

- **攻：P0-A 只重编 artifact 行，helper 后置覆写会不会漏网（E01 复活）？**
  已落地的 `_artifact_compile_lines`（:1080）就是干这个的——它按 `-o` 目标准确挑行。风险在于：若某卡 asm 是由"先编译中间文件、第二步生成 asm"的多段管道产出，只挑直接产 artifact 的行可能漏掉被污染的中间件。
  **护栏**：①不改提取逻辑，B1 只减"非 sha 锚定"的 exe/run 重复，不碰 artifact 行选择；②E01 毒样例（poison 现有真编译载荷）必须在改动前后各跑且 trap 率不下降；③新增一条毒样例："两阶段编译，污染第一阶段中间产物"，若当前提取就漏，**本轮报告并禁止声称 B1 有收益**（实测门槛而非假设）。
- **攻：环境探测进程内缓存，换了 g++ 怎么办？** 缓存只在单进程内（lru_cache），新 worker/新 replay 进程重新探测；门禁都是短进程，窗口最大=一次全量 replay 时长，而工具链切换需要人装编译器（低频、可见）。残余风险：同一夜跑中换工具链——nightly 文档写明"运行中勿动工具链"，且 worker 启动时记录 g++ 路径+大小+mtime，完成时复核不一致整批复跑。
- **攻：ccache 服务异步探索任务，污染的缓存会不会回流门禁？** 物理隔离：ccache 只在 mutation/探针命令路径启用，任务行 verify_cmd 走门禁路径时环境不含 ccache 包装（`_wrap_ccache` 只在非 P0-A 生效，本就有分支）。验收：grep 确认 gate/replay 主路径 CCACHE_DISABLE 仍在。
- **判决：-O 分级在设计阶段就被实测击杀**（大 TU -O0/-O1/-O2 差 <5%），不落地、不进路线图，避免未来苦力浪费一轮。

## D2. 对 B2（并行 replay/golden）的攻击

- **攻：两个 worker 同写一个 .asm 怎么办（508 原攻击复现）？**
  三道：①调度层 shard 不重叠（同卡不会被领两次，534 原子 claim 保证）；②锁按 artifact_rel 哈希分文件，同路径操作互斥；③各自 `-o` 在 `build/workers/<wid>/`，正式 Examples/atoms 工件仍是快照-还原唯一写点，而快照-还原也在卡锁内。**这是确定性隔离（路径+锁），不是"大概率不撞"。**
- **攻：sanitizer/ASan 的临时文件、g++ 进程的 %TMP% 残留跨 worker 串台。**
  护栏：每 worker TMP/TEMP/ASAN_TMPDIR 全指向自己的工作根（B2.1）；探针实测前先造一个"读 TMP 路径写标记"的夹具跑 4 worker，确认标记文件各在各家。
- **攻：worker 跑的时候人/另一个会话改了夹具，并行结果半新半旧。**
  输入冻结校验（B2.3）：池启动前记录输入集哈希，每个 worker 完成时复核，任何不符整批 invalid。**宁可整批复跑，不出具混合血统的绿灯。**
- **攻：golden 复用 replay_resultset，清单被伪造/过期怎么办？**
  ①清单含工作树指纹（fixture+artifact+tools 关键文件哈希）+生成时间+worker 数，指纹不符 golden 拒绝消费直接回退串行（fail-closed）；②清单由 replay 进程写、golden 只读，不接受人手编辑；③抽验 3 卡真跑，抽验不符同样整清单作废；④slow 测试里保留"串行全量周更"一条，防止复用路径长期无对照漂移。
- **攻：并行加速后机器发热/杀毒扫描介入，编译时间波动让"读数断言"类卡 flaky。**
  本仓 run 类断言比的是 .out 内容与 asm 符号，不是墙钟；但 PERF 卡（benchmark）读数可能受并行负载影响——**PERF/计时型卡不进并行池，固定串行单跑**（与 533 的"计时读数不做 V-iso 通道"同口径）。
- **攻：jobs 数设错（超核）导致更慢且互相拖。** 默认 min(核-1,4)，`--jobs 1` 完全等价旧路径；加速比与核数一起写进 resultset，异常（加速比<1.2）自动 warning。
- **残余风险诚实声明**：Windows 上进程级隔离不如 Linux namespace 强（g++ 若读全局配置仍可能共享）；缓解是工具链已钉绝对路径（_pin_compiler），且编译器配置不随项目变。**若 4 worker 实测出现任何一次 verdict 与串行不一致，B2 整体回退，不做概率性放行。**

## D3. 对 B3（测试选择）的攻击

- **攻：这正是 548 踩过的"diff 按卡裁剪漏跨卡规则"。**
  设计已规避：选择集**永远包含全卡 gate 扫描**（gate 是 Python 侧全库分析，3.4s 不是瓶颈）；裁剪只裁"真编译 replay"，不裁规则分析；impact 闭包是多跳（558 已做），不是单跳 diff。
- **攻：改了 replay.py 还只跑选择集会怎样？** 规则 B3.2 明写：工具文件变更→全量，没有例外。这条是硬编码路径名单，不做智能推断。
- **攻：选择器自己有 bug，长期漏跑一类测试。**
  周 canary（选择集 vs 全量比对）+ 分歧率永久入 metrics；一次分歧即当周回退；选择规则变更也触发全量。
- **攻：白名单本身烂了（门里没放关键单测）。** 白名单随新工具文件强制更新（CODEOWNERS/评审清单挂"新增 tools/ 核心文件必须同时加白"）。

## D4. 对 B4（gate 缓存）的攻击

- **攻：sha 内容键比 mtime 键贵（每次读全文件）。** frontmatter 小（KB 级），56 卡+27 原子全读 <0.4s 实测；不存在性能问题，而 mtime 键在 git checkout 后会假命中——不用。
- **攻：缓存层让规则看到过期索引。** 规则注册时声明依赖（cards-only / atoms-only / relations），索引在一次 run() 内构建一次并冻结，规则不持有跨进程缓存，无陈旧问题。

## D5. 对 B5（并行调度）的攻击

- **攻：系统会不会偷偷变成 G-supervisor 自起 worker？**
  worker 进程只能由人显式 `worker-start`；task_queue 里**没有任何 spawn/Popen worker 的代码路径**（代码评审 grep 断言：调度库内禁止出现启动 worker 的调用）。池容量耗尽是排队，不是扩容拉起。
- **攻：worker 池容量/资源标签被误配，poison 与 replay 同池。**
  resource_pool 是 enqueue 必填（默认按 type 推导），claim 候选过滤；配置错误导致同池时，B2 的工作根隔离仍保底（poison 在 tempdir 本来就不碰正式工件），但调度层额外做池类型白名单校验，replay_build 池拒入 poison 任务。
- **攻：并行加速了任务周转，handoff/断点续跑的信任链被并发放大？**
  534 的三级信任（L1 物证继承/L2 判决必重跑/L3 不继承）逐卡独立，并行不改变任何信任判定；每个 shard 的 verified_facts 不跨 worker 继承。

## D6. 物理下限声明（不硬凑）

单进程 56 卡真编译下限 50–70s（重 TU 主导，A §4①），这是 Oracle 物理量。B 系列**不声称**能消灭它：日常靠增量 manifest（已实现，0.3s）绕开，nightly 靠并行摊薄到墙钟 ~40s，单卡真编译 1.6-1.8s 永远在。任何"缓存命中即通过"式提案都把系统退化回恒真比对——CCACHE_DISABLE 存在的全部理由就是记住这一点。已压项之外若还要更快，唯一答案是加核或减少证据卡数量（削弱覆盖，不做）。

## D7. 回退总表

| 优化 | 回退动作 | 回退触发（机器可判） |
|---|---|---|
| B1 缓存/降面 | 环境变量/单 commit revert，主路径默认旧行为 | E01 类毒样例 trap 率下降；56 confirm 漂移 |
| B2 并行 | `--jobs 1`（逐字节旧路径） | 任一卡 verdict 与串行不一致；输入冻结校验失败；PERF 卡 flaky |
| B2 golden 复用 | 清单指纹失效即自动回退串行 | 抽验不符/工作树指纹不符 |
| B3 测试选择 | 本周回全量 PR | canary 分歧≥1；工具文件改动规则漏触发 |
| B4 缓存键 | 删缓存回退每次重扫 | 141 命中数漂移 |
| B5 worker 池 | 人停所有 worker，队列回到手工单领 | 加速比<1.2；出现双领/跨池混跑 |
