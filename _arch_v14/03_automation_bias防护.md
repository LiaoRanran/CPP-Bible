# 03 · automation bias 防护

## 3.1 防护机制谱系

- **隐藏机器预测**：人审先独立判断，再看机器预测（避免锚定）。
- **强制理由**：无理由不可提交（本仓采用）。
- **反向提问**：问"这条攻击为何不成立"而非"是否成立"（激活批判思维）。
- **陷阱题**：插入已知错误机器预测，检测是否纠正（维度 2）。
- **决策延迟**：强制阅读证据 N 秒才可提交。
- **置信度校准**：人审自报置信度，与机器对比。

## 3.2 本探针模拟结果（实证）

在 194 边 + 10 陷阱题队列上：
- **rubber-stamp 评审者**：agree_rate=**1.0**，confirmed=204（含全部陷阱），caught_traps=**0**。
- **careful 评审者**：agree_rate=0.936，confirmed=191（正确拒绝陷阱+不确定），caught_traps=**10/10**。

→ 结论：**rubber-stamp 在数学上"完美"（100% 同意机器）却是错的**；其可被机器检测（agree_rate==1.0 且 reason 过短）。

## 3.3 机器可检测信号（落地为代码）

对每条人审记录存：`review_seconds`、`reason_len`、`agree_with_machine`。触发复核的条件：
```
agree_with_machine == True AND reason_len < 10  → 标记 rubber-stamp
agree_rate(整批) == 1.0                          → 整批重审
review_seconds < 5                               → 标记未读证据
```
本探针 `detect_signals` 已给出该逻辑骨架。

## 3.4 564 "卡绑定判别题"能否用于攻击边确认？

- 564 设计的卡绑定判别题（让人审就卡面具体断言做判断题，而非接受系统结论）**可直接迁移**到攻击边确认：把"这条 MIS 攻击该命题吗？"做成基于卡面断言的判别题，而非"系统说成立，你同意吗？"。
- 关键：人审界面**不预显 W2 预测**，或把预测放在判断框下方且标注"仅供参考"。

## 3.5 外部实证【一方称：待核验】

- NEJM AI 2026 RCT：automation bias 使受训医生遇错建议准确率 −14pp。
- automation bias 元分析（见 590 引用）：系统越"权威呈现"，rubber-stamp 率越高 → 界面对预测的呈现方式本身就是干预变量。

## 3.6 本仓落地评估

- 零成本可落地的三件套：**强制理由 + 陷阱题 + agree_rate 异常检测**。
- 界面层：W2 预测默认隐藏或弱呈现；决策延迟（读证据 ≥3s 才可提交）。
- 与"零误伤"对接：rubber-stamp 是正确命题被错误标 OUT 的主因，防护即守底线。
