# 04 · 论证图可视化

## 4.1 可视化方式谱系

- **节点-边图**：命题=节点，攻击=红边，支持=绿边，IN=绿/OUT=红/UNDEC=灰。
- **辩护链树**：从 IN 命题出发展示其辩护（谁击败了攻击它的节点）。
- **攻击矩阵**：命题×命题攻击强度热力图。
- **时间线 / 分层视图**：按类型/卡片/主题分组。

## 4.2 纯标准库能实现到什么程度？（本探针实证）

- **能**：生成自包含静态 HTML（无外部 JS 库、无 CDN），含 SVG 圆形布局图（内圈 MIS/OUT 红、外圈命题/IN 绿）、攻击边红线、支持边绿细线、悬停 tooltip、图例、统计摘要。
- **不能（纯标准库）**：力导向动态布局（需迭代计算，可写但交互差）、拖拽缩放（需浏览器 JS 事件）。这些需外部库（D3/vis.js/ECharts）或把布局计算前置到 Python（本探针即此思路）。
- 本探针产物：`visualization/index.html`（自包含）+ `visualization/graph.json`（供外部工具消费）。图规模：79 命题 + 42 MIS = 121 节点，194 攻击边 + 80 支持边。

## 4.3 交互设计（人审视角）

- 点击命题 → 展示辩护链 + 攻击它的边 + 它攻击的边 + W2 状态。
- 点击攻击边 → 展示证据（MIS refutations 文本片段）+ 可信度 + 人审状态。
- 筛选：按 IN/OUT/UNDEC、按命题类型、按人审状态（待审/已确认/已拒）。
- 布局切换：圆形（本探针）/ 分层（按卡片）/ 力导向（需 JS 库）。

## 4.4 与现有 CLI 的关系

- `prop_graph.py stats/query` 是**机器侧**（CLI 输出 IN/OUT 计数、pending 队列）。
- 可视化是**人审侧**（图形理解）。二者数据同源（同一 W2 结果），CLI 给数字、HTML 给直觉。
- 本探针的 `graph.json` 可直接被 `prop_graph` 未来的 `--viz` 子命令消费，无需重复计算。

## 4.5 外部实证【一方称：待核验】

- Gephi / Cytoscape：图布局成熟，但重、需 Java/Electron；本仓规模不需要。

## 4.6 本仓落地评估

- **N 段立即可做**：本探针已生成的静态 HTML 即是 MVP；后续若要交互，加内联 vanilla JS（仍纯标准库生成）即可，不引入依赖。
- **风险**：121 节点 + 274 边全画会信息过载（维度 13）。缓解：默认只画 IN/OUT 状态 + 点击下钻，不一次性全展开。
- 交付：596 建设批次可直接复用 `visualization/index.html` 作为人审界面雏形。
