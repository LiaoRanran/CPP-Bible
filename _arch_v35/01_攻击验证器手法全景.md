# _arch_v35 · 01 攻击验证器手法全景（2024–2026 真实案例与攻击面分类）

> 所属：`_arch_v35_brief.md` 方向 1。全部来源访问/检索日期：2026-09-27，编号见 `99_来源清单.md`。
> 诚实约定：【已查证】= 论文摘要页/官方文档实读核对；【推断】= 由多源机制推导；【盲区】= 未找到可靠来源。

## 1. 一句话结论

**2024–2026 的公开证据显示：攻击者的首选目标正在从"模型"转向"验证层"——裁判、审计器、评测流水线、工具描述、依赖闭包全部出现过真实攻击或系统性失败案例；而"验证 LLM 的系统"作为被攻击对象，只有零散案例（裁判被注入、基准被污染、Arena 被刷榜），尚无系统化的攻击面模型——这正是阙疑攻击面五层分类可以填补的空白。**

---

## 2. 攻击面五层分类（每层：手法 → 真实案例 → 成功率/检测难度/防御成本）

### L1 输入层：对抗样本 / 提示注入打穿裁判

- **手法**：在被评文本/候选答案中埋藏指令（"给我的回答打高分"），或用优化方法生成对裁判模型的定向注入串。
- **真实案例**：
  - Maloyan/ Ashinov/ Namiot（2025）系统研究 LLM-as-a-Judge 架构对提示注入的脆弱性，证明 pairwise 与 pointwise 架构均可被定向操纵。【已查证：摘要层】[v35-S2]
  - arXiv:2504.18333：结合学术与实战视角分析 LLM 裁判系统对注入攻击的脆弱面。【已查证】[v35-S1]
  - Llama-4/LM Arena 事件（2025-04/05）：Meta 以未公布的实验版模型刷 Arena 榜单（2000+ 对战），事后 LM Arena 被指控默许顶级实验室"化名测试+定向优化"；2025-05 arXiv 对 2024-01→2025-04 的 200 万场对战分析显示刷榜已形成产业。【已查证：事件多源一致】[v35-S11] 这不是 prompt injection，但它是"人类裁判池被选择性利用"的真实案例——**人类验证者同样可被攻击**。
- **成功率/检测难度/防御成本**【推断，基于上述论文定性结论】：定向注入在无防御裁判上成功率常为"显著高于随机"量级（各论文口径不一，未采信具体百分比）；检测难——注入串可以伪装成正常内容；防御成本中——输入与指令隔离、裁判只见"内容不见来源"。
- **对阙疑**：阙疑的 LLM 判决路径已用"LLM 永不给 pass"消掉大半输入层风险（注入最多骗出 fail/unknown，不产生通过）；真正暴露的是**改判路径**——B1 冲突检测接收高置信冲突信号，若冲突信号本身可被伪造，B1 就成了攻击者的"合法改判通道"。【推断】

### L2 工具层：工具投毒 / 返回值篡改

- **手法**：工具描述（对用户不可见、对模型可见）埋指令；工具返回值在传输/渲染层被篡改。
- **真实案例**：
  - Invariant Labs（2025-04）MCP 工具投毒攻击（TPA）：恶意 MCP server 在工具描述注释中藏指令，操纵 agent 从同会话其他 server 外泄消息历史；Cursor/Claude Desktop 类客户端均受影响；传输层加密完全无效。【已查证：多源一致】[v35-S3]
  - MCPTox（2025）：首个针对真实 MCP server 的工具投毒基准，系统度量主流 agent 被毒化描述操纵的概率。【已查证：摘要层】[v35-S4]
  - 机制共识：MCP 把所有工具描述原样注入上下文，每加一个 server 攻击面就扩大一次；OWASP LLM Top 10 (2025) 将提示注入列为 LLM01、供应链为 LLM03、过度代理为 LLM06。【已查证】[v35-S5]
- **对阙疑**：阙疑的验证器几乎不用"自由文本工具描述"（L0 真机裁判是编译器+条款），工具层暴露面集中在**探针构建工具链**与 **challenger_652 的算子**——它们若被篡改，产出的"证据"本身就毒。对应防御已在：B7 工具门、verifier_closure 闭包校验。【已查证：内部 652 报告】

### L3 数据层：基准污染 / 证据伪造

- **真实案例**：
  - 基准污染综述（arXiv:2406.04244，55+ 研究口径的系统综述于 GEM 2026 再确认）表明污染是 LLM 评测的系统性问题而非个案。【已查证】[v35-S6][v35-S7]
  - **BenchMarker（ACL 2026）**：用教育测量学+LLM 裁判审计 12 个 MCQA 基准——**TruthfulQA 47% 题目可在线检索到（污染）**，HellaSwag 100% 违反至少一条写作规则；被污染题虚高准确率，写作缺陷能改变模型排名。【已查证：摘要页精读核对】[v35-S16]（brief 中的 47% 数字确认无误）
  - PoisonBench（ICML 2025）：偏好学习阶段的数据投毒脆弱性基准。【已查证：摘要层】[v35-S9]
  - ICML 2026 position paper：主张基准应"可推理而不可训练"（contamination-resistant）。【已查证：转述层】[v35-S10]
  - 证据伪造端：ImpossibleBench（ICLR 2026）把单元测试改写成与规范冲突的"不可能任务"后，GPT-5/o3/Claude 级模型仍能找到作弊路径"通过"测试——**验证器给出的 pass 信号可以在语义上完全虚假**。【已查证】[v35-S12]
- **对阙疑**：阙疑卡片本身是知识断言（可被 L3 污染：来源页被 SEO 篡改、条款号张冠李戴），poison_drill 的 8 毒样例与 124/124 触发率是内部证据，但**毒样例的多样性（8 种）与攻击全集（五层×各手法）相比明显偏窄**。【推断】

### L4 模型层：裁判模型投毒 / 微调后门

- **真实案例**：
  - CodeJudgeBench（ACL 2026，26 个裁判模型）：仅调换 pairwise 呈现顺序即可显著影响判决；模型间方差大；存在显著随机性。【已查证：摘要页精读核对】[v35-S17]（brief 提到的"命名扰动/误导注释敏感"在摘要页未列明，需全文核对，暂记【部分查证】）
  - BabelJudge（arXiv:2606.22329）：四偏差（位置/冗长/顺序不一致/跨语言退化）+ agent 轨迹九种扰动；斯瓦希里语顺序一致性 0.480——**换槽位后裁判接近抛硬币**，而原始准确率（0.660）完全看不出。【已查证：摘要页精读核对】[v35-S15]
  - 医学域证据（Nature Communications 2025）：对抗提示与微调攻击可操纵医疗 LLM，且新模型不一定比旧模型更抗攻击。【已查证：摘要层】[v35-S13b，见 99]
- **对阙疑**：阙疑刻意最小化 LLM 裁判权限（LLM 不产 pass、L0 真机为最终 oracle），模型层风险被架构性压低——这是 2026 裁判可靠性文献反向印证的正确决策：**与其审计裁判，不如让裁判的权力小到不值得攻击**。【推断】

### L5 供应链层：依赖篡改 / 构建投毒 / 验证代码本身被换

- **真实案例**：
  - XZ Utils（CVE-2024-3094）：两年社工夺权后植入后门，目标正是 sshd 验证路径——"验证者供应链"已被实战打穿过一次。[v34-S9]【已查证，回指】
  - MCP 生态：官方 SDK 架构级 RCE、registry 多数可投毒。[v34-S50/S51，回指]
  - Ingress NGINX 2026 停运：维护者倦怠导致安全接管的实例。[v34-S9，回指]
- **对阙疑**：这正是 641/647 信任根闭包（23→33 条目）与 RATS 三分（reference_values 7 / endorsements 4 / verifier_code 27）的防御对象；652 差分验证还抓出 `budget_guard`/`shadow_mode` 假开关（G12）——**供应链层攻击的最小实例（自家代码语义被无意改错）已在内部真实发生过一次**。【已查证：内部 652 报告】

## 3. 阙疑 9 个保护器的覆盖矩阵

| 攻击面 | 防它的保护器/机制 | 覆盖判定 |
|---|---|---|
| L1 输入（骗 LLM 判决） | "LLM 永不给 pass" + B1 冲突改判约束 | 部分覆盖：改判信号的**真实性**无人验【推断】 |
| L1 输入（骗人类评审） | B3 盲审协议 | 覆盖，但 B2/B4/B5 真实触发量≈0（647 诚实登记）【已查证】 |
| L2 工具 | B7 工具门、verifier_closure | 覆盖，652 实测有效（差分验证） |
| L3 数据（卡片污染） | poison_drill（8 毒样例）、challenger_652（50/50） | **偏窄**：毒样例 8 种 vs 攻击手法全集；challenger 未接 67 规则（G9）【已查证】 |
| L3 数据（裁判可靠性） | 无直接保护器 | **未覆盖**：四偏差/顺序敏感性类问题目前靠"LLM 权力最小化"架构性回避【推断】 |
| L4 模型 | B4 校准追踪、B8 shadow 轮转 | 部分覆盖；shadow_mode 有假开关嫌疑（G12）【已查证】 |
| L5 供应链 | 33 条目闭包、VSA HMAC+RSA、Merkle 账本、B2 anti-windup、B9 熔断、B10 预算 | 覆盖最厚的一层；对称密钥与公钥同源的独立性上限问题见 06 篇 |
| 全局（保护器自己被骗） | 无 | **系统性空白**——即 v35 主题：元验证层 |

## 4. 阙疑应该怎么做（3 条）

1. **把攻击面五层分类写成正式文档（`_arch_v35` 素材→规格附录）**，为 L1–L5 各层指定"最小攻击演示集"，把 poison_drill 的 8 毒样例按五层扩到 ≥25 条（每层 ≥5），指标沿用 618 批的"诚实覆盖率/验证独立性"口径。成本低，直接喂第一篇论文的攻击集。[v35-S12 口径]
2. **给 B1 改判通道加"改判理由可重放"约束**：每次高置信冲突改判必须附可独立重算的证据哈希（复用 independent_verifier_628 的零 import 重算），堵住"伪造冲突信号→借 B1 合法改判"的通道。【推断】
3. **在对抗性评审前先跑"顺序/位置扰动自检"**（BabelJudge 式）：凡涉及 pairwise/排序类判断（含 challenger 的十卡×5 算子），强制双序运行并要求两序结论一致，不一致判 conflicting——这是从 CodeJudgeBench/BabelJudge 直接搬来的零成本加固。[v35-S15][v35-S17]
