# _arch_v35 · 06 信任根的递归信任问题——无限回归终止在哪一层

> 所属：`_arch_v35_brief.md` 方向 6。全部来源访问/检索日期：2026-09-27，编号见 `99_来源清单.md`。
> 诚实约定：【已查证】=官方/论文页实读；【推断】=机制推导；经济激励部分证据最弱，单独标注。

---

## 1. 一句话结论

**"谁验证验证者"的无限回归在实践中从不靠技术单方面终止，而是终止于四种信任的叠加：数学（最小 TCB，de Bruijn）、物理（硬件信任根，本身有攻击面且已被证明可沦陷）、社会（透明日志+多方+公众审计，把"信任某人"换成"没人能悄悄改历史"）、经济（赏金/声誉，让攻击与失职变贵）。阙疑的 33 条目闭包+Merkle 账本已实现"社会信任"的技术前提（不可静默篡改），但最后一层的信任承担者是"作者本人"——这是单人项目递归终止的真实位置，必须显式声明而不是假装它不存在。**

---

## 2. 回归怎么终止：四层信任及其攻击面

### 2.1 数学终止：TCB 最小化（承 04 篇）

- de Bruijn 准则：把信任收缩到小内核；Milawa 塔式逐级验证 [v35-S26][v35-S27]。
- 终止位置：**"这个内核小到可以被彻底审计"**——终止依据是穷尽性论证，不是又一层的验证器。
- 攻击面：内核的**语义**仍可能全人类都理解错（规格歧义）；构建链绕过（Thompson）。

### 2.2 物理终止：硬件信任根——它解决递归吗？【已查证：机制与攻击面文献】

- 机制：TPM/TEE/Secure Enclave 把信任根沉到不可篡改的硅片（度量启动、quote 远程证明；Intel DCAP 的 quote 验证链 [v35-S35]；TPM 内密钥不出芯片）。
- **它不解决递归，它转移递归**：你必须信任芯片厂商与固件。攻击面已被实锤——SCRUTINIZER（NDSS 2025）专门处理"已被攻陷的 TrustZone"上的取证，默认假设安全世界可沦陷 [v35-S34]；供应链侧固件篡改是持续议题 [v35-S36 第三方]。
- 结论：硬件根把"无限回归"换成"有限但昂贵的信任（厂商+制造链）"，适合高价值端点，**不适合单人开源项目的成本结构**。【推断】

### 2.3 社会终止：透明日志、多方与公众审计【已查证：官方文档】

- 模型核心：不要求任何人"可信"，只要求**篡改必留痕、留痕必可被任何人发现**——CT 日志（RFC 6962）/Rekor 的 inclusion+consistency 双证明、PyPI Trusted Publishing 与 npm provenance（Sigstore 签名隐式兼容）[v35-S37][v35-S38][v35-S39]。
- 多方签名：PyPI/ crates 类 registry 的发布审批、复现构建社区的多链交叉（DDC 的社会版）。
- 攻击面：**阈值以下的合谋**与"所有见证人同时失明"（XZ：一个人经营了两年社区信任后夺权 [v34-S9]）；可见性疲劳（没人真的看日志）。
- 结论：社会终止把问题从"信任"转换为"**篡改成本 ≥ 攻击收益**"的经济学，配合 2.4 使用。

### 2.4 经济终止：赏金/质押/声誉——证据最弱的一层【诚实标注：证据弱】

- 现状：bug bounty 在软件域是成熟制度（Immunefi 等 Web3 赏金平台为高风险协议提供规模化的攻击者换边激励 [v35-S40 第三方]）；v34 已验证"付费维护者安全实践 +55%" [v34-S9]。
- **质押（staking）/声誉系统在"验证器正确性"上的应用**：检索未找到非区块链语境的成熟实践【盲区】；Web3 方案本身引入新攻击面（经济操纵）。判定：**对阙疑当前阶段只有 bug bounty（verification-bounty，v34 P8 已排）是可用的经济机制**；质押/代币激励在论文里只能作为 future work 提一句，不可作为信任主张。

## 3. 阙疑的递归终止审计【已查证：内部，机制评估为推断】

现有信任栈（641/647/651/652 批）：

| 层 | 组件 | 终止于什么 |
|---|---|---|
| 判决层 | 813 行内核（纯函数、零领域依赖） | 数学+代码可穷尽审计（TCB 最小化的正确实践） |
| 完整性层 | 33 条目闭包（RATS 三分：reference 7 / endorsements 4 / verifier_code 27） | 哈希比对——**防静默篡改，不防闭包自身语义错误** |
| 凭证层 | VSA HMAC → RSA-2048 | 密钥持有者；公钥同源 → 独立性 L1/L2 而非 L4（629 诚实登记） |
| 账本层 | 452 事件 + RFC 6962 Merkle checkpoint + inclusion/consistency 证明 | RFC 6962 的社会信任模型（2.3）；OTS 外部锚 pending |
| 人审层 | 语义对齐、B3 盲审、规则治理 | **作者本人** |

**终止审计的三个诚实结论**【推断，基于上表】：

1. **递归已经在正确的层终止**：账本层的 Merkle/透明日志是标准的社会终止结构；内核层的 813 行是标准的最小 TCB。技术选型与 2.1/2.3 的最佳实践一致。
2. **但最底层的信任承担者=作者本人，且未被声明**：VSA 密钥、闭包基线、账本 checkpoint 的最终担保人都是同一个实体。单人期这是事实（Sigstore 出生时有 Red Hat/Google，阙疑没有），**风险不在"单点"本身，而在单点未声明**——论文与开源若宣称"不可信任何单点"就是虚假陈述。
3. **独立性分级暴露了精确的短板**：外部锚独立性 L2 未达 L3 [651 报告]。差的就是"另一个独立实体的眼睛"——即 v34 P8 的外部贡献者与 P16 的独立安全评估，不是任何新技术。

## 4. 阙疑应该怎么做（3 条）

1. **发表"信任终止声明"（Trust Termination Statement）**：一页纸，声明四件事——递归终止于哪一层（33 条目闭包+作者）、该层为什么暂时可信（可穷尽审计+透明账本）、单点是谁（作者本人）、消除单点的触发条件（≥1 外部 maintainer 或独立安全评估，接 v34 P16 门槛）。这页纸同时是论文的 Threat Model 小节和开源页的 Trust 页。
2. **VSA 去同源化**：RSA 公钥由"独立重实现（independent_verifier_628）+外部锚（OTS/第三方 checkpoint）"双通道分发，使凭证验证不依赖"签名者自报家门"——把凭证层独立性从 L1/L2 推向 L3 的最小改动。
3. **账本定期人肉+异构双验**：对 452 叶子账本，固定每批次由 (a) 内核自检、(b) 独立重实现重算、(c) 人工抽 5 条对原始证据——三通道全部一致的批次才在总览标记"账本核验通过"；把"社会信任"先以最小规模（作者+工具+偶发读者）跑起来，等外部贡献者出现即自然升格。
