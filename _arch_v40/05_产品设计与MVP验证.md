# _arch_v40 · 05 产品设计与 MVP 验证（方向 4）

> 核心问题：MVP 不自嗨、用户访谈、可用性测试(5 用户)、真/伪需求、免费vs付费；教学 MVP 怎么验证、第一批用户从哪来。
> 诚实标注：【成功案例】/【失败案例】/【数据支撑】/【个人观点】。

---

## 一、MVP 不自嗨

- **自嗨信号**：自己觉得酷但没人愿花 10 分钟用；解决"不存在的需求"。
- **反自嗨法**：先找 5 个真实目标用户做访谈 + 可用性测试，再写代码（v38 已规划"一张卡七日闭环"）。

## 二、用户访谈（第一批从哪找）

- 渠道：合肥高校嵌入式/CS 学生群、知乎 C++ 话题关注者、本地 meetup  attendees、Reddit r/embedded/r/learnprogramming。
- 问"过去一周你怎么学 X / 遇到什么坑"，不问卷臆想功能。记录原话。

## 三、可用性测试：5 用户发现 85%

- Nielsen 定律：5 个用户约暴露 85% 可用性问题【数据支撑/成功案例】。阙疑教学 MVP 上线前找 5 个嵌入式学生，让其独立完成"一张卡七日"流程，录屏+事后问。
- 失败案例：跳过测试直接推广→ 真实问题爆发在差评里【失败案例】。

## 四、真需求 vs 伪需求

- **真需求**：用户主动复诊/愿意付费/向他人推荐。
- **伪需求**：礼貌性"挺好的"、访谈说想要但行为不买账。
- 判据：看行为不看口头（v38-00 已预警教学可能反噬核心）。

## 五、免费 vs 付费

- 教学 MVP 早期**全免费**（获反馈优先）；付费在验证"留存+愿意付"后（方向 6 排最后）。

## 六、对阙疑的可执行建议

1. **先做 5 人访谈 + 可用性测试，再决定 MVP 范围**（不先写产品代码）。
2. **MVP = 一张卡七日闭环**：用户选一张 C++ 卡，跟练+验证+改判，跑通即验证。范围极小、可证伪。
3. **第一批用户**：合肥高校嵌入式学生（线下最容易触达）+ 知乎 C++ 关注者（线上）。
4. **判定指标**：7 日完成率 + 是否向同学推荐（行为指标），非 star 数。

## 七、能学/不能学（3 条）

- 能学：5 用户可用性测试、行为>口头、MVP 极小可证伪。
- 能学：访谈问"过去行为"而非"未来意愿"。
- 不能学（不依赖）：大规模 PMF 调研——单人时间只够 5-10 人深访【个人观点】。

## 八、来源

【数据支撑】Nielsen 5-user 85%; [v38-00] 教学 MVP; 【失败案例】跳过测试推广; 【个人观点】双非线下优先. 盲区: 教学 MVP 具体完成率无数据（待实测）。
