# _arch_v40 · 08 社区运营（方向 7）

> 核心问题：Discussions/Discord 选型、社区规则、负面反馈处理、核心贡献者培养、治理演进；阙疑现在要不要建、怎么建。
> 诚实标注：【成功案例】/【失败案例】/【个人观点】。

---

## 一、选型：GitHub Discussions vs Discord

- **GitHub Discussions**：与代码/issue 同处，适合"问题+提案"，单人维护成本低→ 阙疑首选。
- **Discord**：实时聊、氛围强，但需 moderator 值守，空群显冷→ 有贡献者后再开。
- 失败案例：项目 0 用户就开 Discord，三个月变鬼群，反而减分【失败案例】。

## 二、社区规则

- CoC 阙疑已有（v39-00）；加"如何提 good first issue / 如何报 bug"简明指南。
- moderator：早期只有作者一人，明确"响应时间不保证"，避免设高预期。

## 三、负面反馈处理

- issue 吵架：公开、就事论事、引用账本/证据（阙疑有"篡改必留痕"天然优势，争论可落到数据）。
- 恶意 PR：CI 门禁 + DCO 签名（v39-10）是两道闸；拒绝不解释清楚理由。
- 社区分裂：保持单一决策源（作者），避免早期委员会制扯皮。

## 四、核心贡献者培养路径

用户 → 提 issue/修 good first issue → 成为 contributor → 授权 review → 维护者。
- 关键动作：及时合并+致谢+在 README/博客点名（正向反馈循环）。

## 五、治理演进

独裁（现在）→ 委员会（有 3+ 贡献者）→ 基金会（有外部资金/法律需求）。**现在就规划"独裁→委员会"的触发条件**（如 contributor≥3 时引入轻量决策记录）。

## 六、对阙疑的可执行建议

1. **现在不开 Discord**，用 GitHub Discussions（已有 issue/PR 基础）。
2. **贡献者≥3 时**启动轻量治理（决策记 ADR，v39-10 工具链思想）。
3. **所有争议落到账本/证据**——阙疑的独特社区治理武器。

## 七、能学/不能学（3 条）

- 能学：Discussions 先行的低成本社区、贡献者培养闭环、账本化争议解决。
- 能学：治理触发条件前置规划（防早期委员会扯皮）。
- 不能学（不依赖）：多 moderator 轮值——单人期只能作者值守【个人观点】。
