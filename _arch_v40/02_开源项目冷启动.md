## 一、从 0 到第一个 star：怎么被发现

- **平台真相**：Show HN 标签在 138 次 AI 工具发布中统计上无优势、48h 内略负 [v40-S3，数据支撑]。Reddit/知乎/V2EX 同理——**发帖平台不是杠杆，项目本身的可分享性是**。
- **被发现机制**：GitHub 搜索（README 的 SEO 关键词）、被论文引用（第一篇论文是最强发现器）、被他人 fork（有 artifact 才有人 fork）。
- **成功案例**：Rust/TypeScript 等靠"解决真实痛点 + 教科书级文档"自然增长；失败案例：大量"Show HN 一日游"项目星标当日回落【失败案例/个人观点】。

## 二、第一个贡献者

- **good first issue**：把"低门槛+高价值"列出来——阙疑可开：补一张卡的证据双轴标注、写单测、翻译 README。避免开"重构内核"类吓退新人。
- **onboarding**：CONTRIBUTING.md + 一键环境（Nix，v39-10）+ 标注"新手友好"标签。阙疑已有 DCO/CoC 地基（v39-00），补齐 CONTRIBUTING 即可。

## 三、README 转化率

高转化 README：一句话价值主张 + 3 行能跑的 demo + 与其他项目的差异表 + 架构图。阙疑当前 README 未知（00 盲区），但**最大卖点应是"篡改必留痕的账本 + 单脚本重放"**（v39-11 独占空白格），须置顶。

## 四、对阙疑的可执行建议

1. **先清 655 交人 9 项再公开**（CRLF/pytest 预失败/136 脏文件）——第一印象即技术债会劝退。
2. **公开当天不发 HN**，而是：发论文预印本（arXiv，v37）+ 在论文 related work 引自己仓库 + 知乎写"我们怎么验证知识断言"长文（中文圈对"可验证性"话题有受众）。
3. **开 5-8 个 good first issue**（证据标注类），吸引第一批贡献者。
4. **README 首屏放账本重放 GIF + 差异对比**（G12 假开关被差分抓出是绝佳 demo 素材）。

## 五、能学/不能学（3 条）

- 能学：good first issue 设计、README 差异置顶、论文→仓库引流。
- 能学：单脚本重放 artifact 作为"star 理由"（多数 OSS 无此）。
- 不能学（不依赖）：刷 HN/Reddit 爆款——数据证明无效 [v40-S3]；靠内容质量。
