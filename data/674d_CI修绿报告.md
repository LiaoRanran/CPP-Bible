**实测遗漏 9 个**（`pytest tests/ --collect-only`，去重）：
`test_647_end_to_end_slow.py`、`test_protector_rollout_642.py`、`test_protector_rollout_647.py`、
`test_queyi_core_interface_v02_631.py`、`test_queyi_core_interface_v03_632.py`、`test_queyi_data_models_645.py`、

### 1.2 跨平台缺陷（**真实 bug，非环境噪声**）

| # | 位置 | 现象（Linux 实现，Windows 上恰好掩盖） | 修复 |
|---|---|---|---|
| a | `tools/sandbox_apply_622.py::_norm` | `card_rel.replace(os.sep, "/")` —— `os.sep` **只认当前平台** ⇒ Linux 上 Windows 风格输入 `atoms\x\A.md` 原样保留反斜杠，`git checkout -- \atoms\x\A.md` ≠ 期望 | 显式压平两种分隔符（`replace("\\","/")`）；`is_allowed()` 复用同一函数 ⇒ 判定同时收紧 |
| b | `tools/transparency_log_628.py` | 台账里的 `vsa_file` 是**写入机形态**（开发机 Windows ⇒ `data\vsa\x.json`）⇒ Linux 上 `os.path.join(ROOT, 它)` 得到 `.../data\vsa\x.json`（反斜杠是文件名字符）⇒ `FileNotFoundError`；且与 `relpath` 产出的相对路径逐字不等 ⇒ 已入册凭证被误报 `unlogged` | 新增 `_posix()` / `_abs_path()` / `_rel_key()`：读取侧与生成侧都归一到 POSIX；**绝对路径不 relative 化**（e2e 夹具用 `mkdtemp` 绝对路径） |
| c | `tests/test_task_queue.py::test_c6_...` | `verify_cmd="exit /b 3"` 是 **Windows cmd 专有**；Linux `sh` 视 `/b` 为非法参数 ⇒ 退出码 **2**（`assert 'rc=3' in '...rc=2'`） | 改用解释器退出码：`"{sys.executable}" -c "import sys; sys.exit(3)"` |
| d | `tools/merkle_integrity.py`、`tools/tau_d_635.py` | `stat().st_file_attributes` 是 **Windows 专有**字段；运行期有 `except AttributeError` 兜底，但 **mypy 在 Linux 静态报** `[attr-defined]` ⇒ CI 的 mypy 硬门禁红 | 改 `getattr(..., "st_file_attributes", 0)`（行为不变，静态类型干净） |

### 1.3 并发污染（xdist；**根治而非跳过**）

**现象**：`-n 16` 下 12 例红、`-n0` 全绿，全部形如
`AttributeError: module 'gate_engine' has no attribute '_cards' / '_git_author_for' / 'run'`、
`AttributeError: 'dict' object has no attribute 'id'`。

**根因**：本仓有一批"最小仓库"类测试在自己 `tmp_path` 下造 `tools/gate_engine.py` **并插进 `sys.path`** ⇒ 同 worker 内**后续**测试 `import gate_engine` 时，`sys.modules` 里已是那个**假模块**。
受害面：`kc_inventory_612`、`overturned_channel_592`、`overturned_curves`、`perf_646`、`rule_card_mapper_646`、`coverage_gap_631`。

**修复**：`tests/conftest.py` 新增 **autouse fixture** `_isolate_tool_module_cache` —— 每个测试结束后还原工具模块缓存与 `sys.path` 快照。
**根治而非跳过**：受害用例在并发下**照常真跑**（实测 `-n 16` 全绿），覆盖率不减。

### 1.4 测试逻辑错误：校验对象错（顺带修）

③ 无空白归一。
⇒ 改调**权威实现** `atom_evidence_replay.check_artifact_assert(meta, art_path)`（断言强度不降反升：参数完备性 fail-closed 是旧写法没有的）。
注：卡的 schema 是 `673q A`（`8f1092c4`）有意升级的，测试是**未同步的消费方**。

## 2 · replay 失败根因（**两类**，13 张 refute）

### 2.1 `compile_error` × **11 张**（假红：相对输出路径 + 缺失父目录）

**卡**：EV-LANG-003/004/005/006/007/008/009、EV-MEM-046/047、EV-UB-003

**现象**：`❌ compile_rc：2/3 条命令失败` → `rc=1 gcc … -o build/c648/_c_decay.…`、`rc=127 build/c648/_c_decay.exe :: 可执行文件不存在`。
**定位**：卡的 `command` 用**仓库相对**输出路径（`build/c648/…`），而 `atom_evidence_replay.run_commands(run_lines, run_root(), env)` 的 **cwd 是跑批根**；干净检出上 `build/` 被 .gitignore **不存在** ⇒ gcc 无法写 ⇒ rc=1 / 127。
**反证**：`mkdir -p build/c648` 后单卡跑 ⇒ **confirm**（纯目录缺失，非内容证伪）。

**修复（根治）**：`run_commands` 前为命令的**输出目标**（`-o X` 与 `> X`）预建父目录（幂等、只建目录、不改判据）。
**验证**：删除 `build/` 后逐卡 → EV-LANG-003/007、EV-MEM-046、EV-UB-003 **全部 confirm**。

### 2.2 `sanitizer_reported` × **3 张**（跨平台 sanitizer 行为差异）

**卡**：EV-UB-DIVZERO-669（`expected_sanitizer: [ub]`）、EV-UB-NULLDEREF-669 / EV-UB-OOB-669（`[address]`）
**现象**：`❌ sanitizer 命中 ub, address（未在 expected_sanitizer 声明：…）`
**根因**：**Linux（g++ 13.3）上 UBSan 与 ASan 同时报出**该 UB（同一处越界/空解引用既是 UB 又是 memory error），而卡归属的 **MinGW GCC 15.3 只报其中一种**。
**修复**：如实补全为 `[ub, address]`（两者都是该 UB 的**预期**表现，**不是放松**：原本期望的类别仍在）。

**哈希面重锚（顺序敏感）**：改卡 → 重建 Merkle 根 → **重新生成 `.ots`** → 更新占位登记摘要 → 重签 `.tool_checksums`。
（漏掉"重生成 .ots"会让 `ots_anchor_613 --check` 立刻红——本批踩过一次并已修正。）
