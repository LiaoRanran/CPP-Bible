## 四、为什么仍是 0 —— 如实解读

1. **判决是预测，不是实测**（621 §六.3 不跑门禁 + 无沙箱施加 API）。
   50 条的 verdict 全部由 v7 先验预测得出，**没有任何一条被真实 gate 跑过**。
   ⇒ "0 逃逸"应读作"**预测模型认为它们不会逃逸**"。
2. **预测模型天然保守**：v7 真逃逸仅 1 条，先验里几乎没有逃逸样本，
   多数投票必然给出 blocked/n_a。这是**方法的结构性保守**。
3. **新颖性不足**：A3 已测出 50 条的（卡,算子）组合 **100% 已存在于 v7**，
   只有变异点是新的 ⇒ 攻击面组合本身没有突破。
4. **36 条可判全是 blocked**：Top1 composite 从 0.15 递减到 0.0375，
   说明排序头部都是"预测被拦且盲区信号弱"的项，攻击价值低。

## 五、局限性声明

1. **本轮没有产生任何新的机器验证事实** —— verdict 全为预测。
2. **沙箱 API 仍未落地**：`mutation_fuzz.py` 依旧不提供 apply-to-copy，
   这是 VFDR 恒 0 的**根本瓶颈**（620 §九.8 已登记，621 未解除）。
3. **样本量小**：50 条（可判 36）相对 v7 的 1593 条只是 3%，统计意义有限。
4. **3 轮仅消化 30/36**：未覆盖全部可判候选。
5. **Top10 排序语义**：A3 已指出 Top 榜实际是"最不可判"而非"最可能逃逸"，
   本轮沿用该排序，故优先攻击的是 n_a 类项 —— 但 n_a 不入 ranked，
   实际进入窗口的是 blocked 项，存在**排序目标与实际候选错位**的问题。
