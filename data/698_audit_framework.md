## 1. 5 步审计协议的形式化

### 总览

| 步 | 名称 | 一句话 | 对应公理 |
|:--:|---|---|---|
| **1** | **Declare**（声明口径） | 把"这次评估到底测了什么"写成机器可校验的记录 | 697 A1（口径可枚举性） |
| **2** | **Enumerate**（枚举失效模式） | 列出**全部**可能的口径变化轴，而不是担心"可能有问题" | 697 A1 + 695 P2（枚举使不变性检验有限） |
| **3** | **Pair**（配对实验） | 同一样本在两个口径下各测一次 | 697 定理 A1（非配对不可识别） |
| **4** | **Quantify**（漂移检测与量化） | 转移矩阵 + McNemar 单向性 + 效应量 CI | 697 T1–T4、698 T5/T6 |
| **5** | **Report**（报告与可追溯） | 数字必须随附口径与三组件向量 | 692 `measurement_context_id` |

---

### Step 1 · Declare（声明口径）

**输入**：一次评估的原始配置。
**输出**：口径五元组 $Q = (D, A, E, \Theta, P)$ 的**机器可读记录**。

| 分量 | 含义 | 必填字段（最小集） | Queyi 对应 |
|---|---|---|---|
| $D$ | 数据集 / 样本总体 | 样本清单 + 每样本内容哈希 | 1147 条（676g） |
| $A$ | 组件 / 资产池 | 声明资产集 + **各资产是否实际支持** | 8 声明 / 6 支持 / 2 结构性恒 unknown |
| $E$ | 环境 | 692 的 15 字段 `EnvironmentProfile` | WSL vs native |
| $\Theta$ | 配置 | 档位、超时、检查集 | `-O0/-O2`、60s |
| $P$ | 协议 | 记账口径 / 聚合规则 / 标签词表 | unaware / OR / `defect_type` 34 类 |

**通过条件（4 条，全部必须满足）**：
1. **完整性**：五元组每个分量非空，且 $A$ 中每个资产标注 `supported ∈ {true,false,unknown}`；
2. **可哈希**：能算出一个 `measurement_context_id`（692 §2 的公式），同口径同 id；
3. **可枚举**：每个分量的**可取值集合**被列出（Step 2 的输入）；
4. **无隐含默认**：任何"我们一直都是这么做的"默认值必须显式写出。

> **失败模式**：字段缺失 ⇒ 该 claim **无判定**（不是 `unresolved`，是**非法**）—— 这是 697 公理 A1。

---

### Step 2 · Enumerate（枚举失效模式）

**输入**：Step 1 的口径五元组 + 每个分量的可取值集合。
**输出**：**失效模式清单**（本框架固定为 8 类，见下表）+ 每类的**可检测性**。

**8 类失败模式**（4 类结构性漂移 + 4 类非漂移失效）：

| # | 失败模式 | 类型 | 是否可**只读**检测 | Queyi 实测 |
|:--:|---|:--:|:--:|---|
| F1 | **分母 / 构成漂移** | 结构性 Type I | ✅ | $g_{\text{app}}$ 5.30 → 18.61pp |
| F2 | **环境漂移** | 结构性 Type II | ❌ 需配对 | −35.34pp（566 帧） |
| F3 | **标签漂移** | 结构性 Type III | ✅ | 13/34 vs 18/70 |
| F4 | **聚合漂移** | 结构性 Type IV | ✅ | 均值口径可被拉低 33.33% |
| F5 | **对抗性利用**（reward hacking） | 需优化者 | ❌ | 本场景不存在（697 SG-3） |
| F6 | **标签噪声** | 数据质量 | ✅ | κ=0.727 是 AI 重标，非人类 IRR |
| F7 | **克隆泄漏** | 统计 | ✅ | 批内克隆率 62.2%，随机折高估 +0.108 AUC |
| F8 | **测量记录不可追溯** | 治理 | ✅ | 452 事件缺 ruleset hash |

**通过条件（3 条）**：
1. **穷尽性检查**：8 类每类都给出"本系统是否存在"的判断（**不允许留空**）；
2. **可检测性标注**：每类标注"能否只读检测"；需新测量的必须**显式登记为待做实验**；
3. **反证条件**：每类给出"什么结果会推翻本判断"（可证伪性）。

> **为什么"枚举"是关键**：695-P2 已论证 —— **不变性检验只有在生成元集合有限时才可判定**。
> 泛泛担心"可能有漂移"是不可判定的；**枚举 8 类**把它变成 8 个有限检查。

---

### Step 3 · Pair（配对实验设计）

**输入**：Step 2 的清单中标注"需配对"的失效模式。
**输出**：配对表 $T^{(M\to M')}$（3×3 计数）+ 每个配对的 `measurement_context_id` 对。

**设计规则**：
1. **同一样本、两个口径**（不是两批样本）—— 697 定理 A1：非配对数据**不可识别**结构性 vs 真实；
2. **样本量**：本批模拟显示 $B \approx 30$ 即达 96% 检出（效应 35pp 时）；
   一般情形用 McNemar 功效公式反推（697-B §6 第 4 步给的是效应量口径，不是 p 值口径）；
3. **分层**：按 Step 2 的失效模式分层（Queyi 用 `defect_group`，11 层）；
4. **预算策略**：预期效应大 ⇒ **均匀采样**（698-B §2 实测自适应更差）。

**通过条件（3 条）**：
1. 每条配对记录携带**两个** `measurement_context_id`，且二者**不同**；
2. 配对表**质量守恒**（行和 = 列和 = $n$）；
3. 分层后**每层非空**（否则该层不可判定）。

---

### Step 4 · Quantify（漂移检测与量化）

**输入**：配对表 $T$。
**输出**：逐项 —— 漂移量 $D_\tau$ ± 95% CI、单向性判据 $c$、静默/响亮标记、可纠错性判定。

**四步算法**：

| 子步 | 动作 | 判据 | 依据 |
|:--:|---|---|---|
| 4.1 | **单向性检验** | $c = T_{\texttt{miss}\to\texttt{catch}}$；纯撤除 ⇒ $c = 0$ | 697 T4 |
| 4.2 | **静默 / 响亮** | 静默 ⟺ $T_{\texttt{catch}\to\texttt{unknown}} = T_{\texttt{miss}\to\texttt{unknown}} = 0$ | 697 T3（**注意：静默性由记账口径决定**） |
| 4.3 | **效应量 + CI** | 报 $D_\tau$ 与配对比例差 Wald CI，**不单报 $p$** | 697-B §6 |
| 4.4 | **可纠错判定** | 后处理层 ⇒ 可纠正（残留 0）；获取层 ⇒ 残留 = 1 − 可由保留列预测的比例 | 698 T6 |
| 4.5 | **链式传播** | 多步漂移**不可**用矩阵相乘推断 | 698 T5 |

**通过条件（3 条）**：
1. 每个数字都有**一行复算命令**；
2. $|D_\tau|$ 与**预先声明的实质阈值**比较（本项目用 5pp），而不只与 0 比较；
3. 若 $c > 0$，必须标注"**不是纯撤除型**"，禁止写成"口径变化"。

---

### Step 5 · Report（报告与可追溯）

**输入**：Step 4 的全部量化结果。
**输出**：可比较、可继承的测量记录。

**报告规范（5 条硬性要求）**：

| # | 要求 | 反面教材（Queyi 自身踩过） |
|:--:|---|---|
| R1 | 每个数字随附**口径五元组** | "70→34 类"不注明是两套不同划分 |
| R2 | 报**三组件向量** $(catch,\ unknown,\ conditional\_recall)$，不报单一 recall | E2 下 conditional_recall 分母归 0，唯一诚实答案是"不可计算" |
| R3 | 报**四态判定**（survives / weakened / collapses / unresolved） | 二态会把"没测"与"测了没中"混同 |
| R4 | 附 `measurement_context_id`；id 不同 ⇒ **结论不继承** | 666 事件（改代码没重跑、数字还被引用） |
| R5 | 附**反证条件**与**已知缺口** | `container_image = null`（指纹级而非镜像级） |

**通过条件**：R1–R5 全满足 ⇒ 该记录可进入"可继承"池；否则标记 `not-comparable`。

## 2. 跨领域适用性分析

**通用假设**：任何"用一组组件去测量一批对象"的系统，都可以套用五步协议。
下面是三个领域的逐步骤判定。

### 2.1 领域 1 · LLM 评估（judge 可靠性 / prompt 漂移）

| 步 | 直接适用？ | 需要什么改造 |
|:--:|:--:|---|
| 1 Declare | ⚠ 部分 | $A$ 从"检测器"变成"judge 模型 + prompt 模板 + 解码参数"；$E$ 要含**模型版本**（API 快照）；$P$ 要含**位置/长度偏置的缓解策略** |
| 2 Enumerate | ✅ 直接适用 | 8 类中 F5（对抗性利用）**存在**（prompt injection / reward hacking），F6（标签噪声）权重更大 |
| 3 Pair | ✅ 直接适用 | 同一批样本在两个 judge 配置下各评一次 —— **天然可行**（LLM 调用便宜） |
| 4 Quantify | ✅ 直接适用 | 三态改为 `{consistent, flipped, invalid}`；**单向性判据依然成立**（换 prompt 不应"凭空"提升） |
| 5 Report | ✅ 直接适用 | 需增加"**复现期**"字段（模型半年一换 ⇒ 记录必须含快照 id） |

**关键适配点**：LLM judge 的漂移**同时**含结构性（prompt/版本变化）与对抗性（被优化的 prompt）成分
⇒ **必须用 Step 4.1 的单向性判据区分**，否则会把"口径变化"误报成"能力提升"。

**现有外部证据**（698-E 方向 2/4）：`A Judge Should Know What Changed`（arXiv:2608.24419）
已形式化 judge 的 **invariance $S$ / sensitivity $R$** 二维剖面 ——
这与本框架的 Step 1（声明）+ Step 4（量化）**高度同构**，是本框架在 LLM 领域的**最近邻工作**。

### 2.2 领域 2 · ML 基准（数据集版本漂移 / 指标口径变化）

| 步 | 直接适用？ | 需要什么改造 |
|:--:|:--:|---|
| 1 Declare | ✅ 直接适用 | $D$ 要含**数据集版本 + 去重状态**；$A$ 是"指标集合"；$P$ 含聚合规则 |
| 2 Enumerate | ✅ 直接适用 | F1（分母/构成）**是主战场**：榜单组成变化、任务权重变化；F7（克隆泄漏）常见（训练集污染） |
| 3 Pair | ⚠ 需改造 | "同一样本两口径"需要**同一模型**在两个数据集版本上各评一次；若版本不兼容则不可配对 |
| 4 Quantify | ✅ 直接适用 | 三态 `{pass, fail, invalid}`；**可操纵性判据**（698-A §4）直接可用于榜单指标 |
| 5 Report | ✅ 直接适用 | 需增加"**榜单快照时间**"（榜单会变） |

**关键适配点**：ML 基准最容易被 **Type IV 聚合漂移**攻击（换平均口径、换任务权重即改变排名）
⇒ **建议把 698-A §4 的"可操纵性 = 掺入零能力组件后的相对变化"作为榜单健康度的常规指标**。

### 2.3 领域 3 · 科学实验（实验室环境漂移 / 试剂批次效应）

| 步 | 直接适用？ | 需要什么改造 |
|:--:|:--:|---|
| 1 Declare | ✅ 直接适用 | $E$ = 仪器型号 + 校准状态 + 温度湿度；$A$ = 试剂批次；$P$ = 统计方法 |
| 2 Enumerate | ✅ 直接适用 | **F2（环境漂移）是主战场**；F1（分母）对应"基线扣除/归一化口径" |
| 3 Pair | ✅ **最适用** | 配对设计（同一样本分装两批试剂）是实验科学的**标准做法**，比软件领域更成熟 |
| 4 Quantify | ✅ 直接适用 | 连续量而非三态 ⇒ McNemar 换成**配对 t / Wilcoxon**；单向性判据换成"系统性偏移 vs 随机" |
| 5 Report | ✅ 直接适用 | 需增加"**批次效应是否已作为随机效应建模**"字段 |

**关键适配点**：这是**四型中 F2 的天然主场**，而且实验科学有现成的**批次效应模型**
（mixed-effects / blocking）—— **Queyi 的方法可以借鉴它们的统计工具**，
反过来 Queyi 的**静默性**概念（丢失被记成 miss 而非 unknown）可以提示它们
**"负结果"里混进了多少"没测"**。

### 2.4 适用性总结

| 步 | LLM 评估 | ML 基准 | 科学实验 |
|:--:|:--:|:--:|:--:|
| 1 Declare | ⚠ 改造 $A/E/P$ | ✅ | ✅ |
| 2 Enumerate | ✅（F5 存在） | ✅（F1 主战场） | ✅（F2 主战场） |
| 3 Pair | ✅ | ⚠ 需版本兼容 | ✅（最成熟） |
| 4 Quantify | ✅ | ✅ | ✅（换检验） |
| 5 Report | ✅ + 快照 id | ✅ + 榜单时间 | ✅ + 批次建模 |

> **诚实边界**：以上是**理论分析**，**未在任何领域实测**（本批红线禁止新实验）。
> 每个"✅ 直接适用"都是**基于结构同构的推断**，不是验证结果。

## 3. 最小可行审计工具（MVP 设计）

> 按任务书要求：**不写代码，只写设计**。（本批已实现的 `detect_698_structural_goodhart.py`
> 是该设计的**第一个组件**——四型风险评分器。）

### 3.1 架构

```
┌────────────────────────────────────────────────────────────────────┐
│                      Audit-MVP（单进程 CLI）                        │
├────────────────────────────────────────────────────────────────────┤
│  [Ingest]  原始输出 + 元数据  ──▶  统一内部表示（IR）                │
│      │        · per_sample × per_component 裁决矩阵 R               │
│      │        · 口径五元组 Q                                        │
│      ▼                                                              │
│  [Declare]  口径完整性校验（Step 1 的 4 条通过条件）                 │
│      │        ✗ → 拒绝（非法 claim）                                │
│      ▼                                                              │
│  [Enumerate] 8 类失效模式逐类判定（Step 2）                          │
│      │        · 只读可判定的：F1/F3/F4/F6/F7/F8                     │
│      ▼                                                              │
│  [Score]    四型风险 0–100（已实现）                                 │
│      │        · Type I/II/III/IV → overall = max                    │
│      ▼                                                              │
│  [Pair]     若有配对数据 → 转移矩阵 + 单向性 + 效应量（Step 3/4）    │
│      │        · 无配对 → 输出"待做实验"清单，不猜                    │
│      ▼                                                              │
│  [Report]   可继承 / 不可比较 二分 + 反证条件（Step 5）              │
└────────────────────────────────────────────────────────────────────┘
```

### 3.2 输入格式（已实现，见 `detect_698_structural_goodhart.py`）

```json
{
  "system": "my-evaluator",
  "declared_assets": ["a1", "a2"],
  "samples": [
    {"uid": "s1", "per_asset": {"a1": "catch", "a2": "miss"},
     "defect_type": "t1", "source_batch": "b1"}
  ],
  "environment": {"reference_assets": ["a1","a2"], "current_assets": ["a2"]},
  "denominator_rules": ["catch_over_catch_plus_miss", "catch_over_total"],
  "aggregation_rules": ["or_any", "mean_per_asset"],
  "label_vocabularies": ["defect_type", "source_batch"]
}
```

**设计原则**：**只要求"原始裁决矩阵 + 口径声明"** —— 不要求用户改变评估流程，
不要求重跑任何东西（Queyi 的 demo 就是**只读**冻结矩阵）。

### 3.3 输出格式（已实现）

```json
{
  "risk_scores": {"type_I_composition": 46.02, "type_II_environment": 50.89,
                  "type_III_label": 41.88, "type_IV_aggregation": 33.33},
  "overall_max_risk": 50.89,
  "overall_verdict": "HIGH：报告值的一半以上可被口径操作改变，必须补齐口径声明与配对重测",
  "details": { "...": "每型的早期预警信号 + 量化明细" }
}
```

### 3.4 API 设计（三个端点，REST 风格）

| 端点 | 方法 | 输入 | 输出 |
|---|---|---|---|
| `/v1/declare` | POST | 口径五元组 | `measurement_context_id` + 完整性校验结果 |
| `/v1/score` | POST | 3.2 的完整 spec | 3.3 的四型风险 |
| `/v1/pair` | POST | 两组配对裁决 | 转移矩阵 + McNemar + 效应量 CI + 可纠错判定 |

**设计约束**：
1. **无状态**：每个请求自带全部输入（便于复现）；
2. **确定性**：同输入必同输出（无随机数；本批三个脚本都满足）；
3. **可离线**：纯标准库可跑（本批实现已满足 —— 本机无 numpy/sklearn）。

### 3.5 明确**不做**的事（scope 约束）

| 不做 | 为什么 |
|---|---|
| 不判断"报告值是否正确" | 需要参考口径的**实测**（697 定理 A1：不可识别） |
| 不自动"校正"漂移 | 获取层漂移**不可纠正**（698 定理 T6） |
| 不给统计显著性 | 四型风险是**启发式指标**，不是检验 |
| 不做跨系统比较 | 不同系统的口径不同，比较需先统一 Step 1 |

## 4. 与现有框架的对比

| 维度 | **Audit-MVP（本框架）** | HELM | DeepFact（audit-then-score） | SV-COMP |
|---|---|---|---|---|
| **审计对象** | **评估器本身**（口径 / 环境 / 标签 / 聚合） | 模型 | 模型输出的事实性 | 验证器（verifier） |
| **方法** | 口径枚举 + 配对 + 漂移代数 | 多场景统一评估 | 先审计再打分（fact-check pipeline） | 基准竞赛 + 见证校验 |
| **输出** | 四型风险 0–100 + 漂移量 ± CI + 可纠错判定 | 多维度分数矩阵 | 修正后的分数 | 排名 + 正确性见证 |
| **适用领域** | 通用（三领域已做适用性分析） | NLP / LLM | 事实性文本 | C 程序验证 |
| **是否需配对实验** | **是**（否则只给"待做"清单） | 否 | 否 | 部分（见证） |
