> ⚠️ **$F$ 检验在本设计里不可解读**：每格只有 1 次重复，误差项只能用 4 阶交互（$df=1$），

> `F_vs_4way` 字段**只用于暴露这一事实**，本报告不用它下任何结论。可信区间一律取 §4 的 bootstrap。

**读法**：

- **两个维度解释了 91.6% 的平方和**：$k$（61.7%）与 pool（29.9%）。也就是说，F1 的选择增益
  **主要由"预算档位"和"池里有没有零产资产"决定**，而不是由某个资产的检测能力决定。
- **linker 的效应量级只有 +0.19pp**（$SS$ 占比 0.01%），且在**选中集率上的效应严格为 0**
  （见 §3）。这与观测链里的 $-4.65\pp$ **相差 24 倍**，见 `715_观测vs实验_对比表.md`。
- **交互项不可忽略**：$A\times k$（+1.43）、$A\times B\times k$（−1.20）、$A\times B$（+1.17）、
  $B\times k$（+0.74）四个都显著，合计 $SS$ 占比 6.2%。**这就是"序贯分解有偏"的直接证据**：
  观测链按固定顺序一次动一个旋钮，等价于假设这些交互项为 0。

## 3. 次级响应：原始检出率（选中集）的效应

把同一套 Yates 分析用在**选中集率**（而非 $\Delta$）上：

| 项 | 效应 pp |
|---|---:|
| $k$ | −33.970 |
| accounting | +11.236 |
| accounting×k | −11.001 |
| pool | −10.877 |
| accounting×pool | −10.877 |
| pool×k | +10.877 |
| accounting×pool×k | +10.877 |
| **linker**（及含 linker 的所有项） | **+0.000** |

**为什么 linker 恰好是 0**：在 $k\in\{1,4\}$ 下，贪心选出的集合是
$\{$asan, ubsan, tsan, compiler-warn$\}$（$k{=}4$）与 $\{$asan$\}$（$k{=}1$），
**都不含 linker**；把 linker 换成全 miss 列因此**不改变选中集的覆盖**。
⇒ **在"控槽位"的操作下，linker 对所选集合的检出率没有影响**；
710-C 建议的"linker 自身覆盖 $-0.4711\pp$"是**池层面**的量（$4/566$ 独苗），
不是**选中集层面**的量。两者不矛盾，但**不能混用**。

## 5. 敏感性：只用 naive 记账的 $2^3$（排除退化格）

| 项 | 效应 pp |
|---|---:|
| pool | −6.275 |
| $k$ | +5.900 |
| pool×k | +1.939 |
| **linker** | **+0.258** |
| linker×k | −0.155 |
| pool×linker | +0.037 |
| pool×linker×k | −0.022 |

与 $2^4$ 的估计不同（pool −5.10 → −6.28，$k$ +7.33 → +5.90）：**差额正是被排除的退化格所携带的
$A\times B$ 与 $A\times B\times k$ 交互**。两种口径下结论**方向一致、排序一致**
（pool ≥ $k$ ≫ linker），但**效应量本身对退化格敏感**，报告时必须同时给出两组数。

## 6. 结论（三条）

1. **主效应排序稳定**：$k \gtrsim$ pool ≫ accounting > linker；前两者占 $SS$ 的 91.6%。
2. **交互项显著且不可并入单步**：4 个交互合计 6.2% 的 $SS$，直接证明 710-C 的**序贯分解有偏**
   （不是"错"，而是"把交互摊进了相邻步"）。
3. **linker 的因果效应在控槽位后接近零**（+0.19pp 于 $\Delta$、0.00pp 于选中集率）：
   观测链里的 $-4.65\pp$ **不能解释为 linker 的能力效应**。
