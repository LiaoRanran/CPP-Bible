## 1. 三层去重结果总览

| 层 | 判据 | 重复组 | 涉及样本 | 跨批组 | 结论 |
|----|------|-------:|--------:|-------:|------|
| **L1 精确** | 源文件字节 md5（多文件按文件名排序拼接；文本模式读取 ⇒ **对 CRLF/LF 不敏感**） | **91** | **321** | **0** | 无跨批字节级重复；321 条为**批内**同文件复用 |
| L1' 精确（标注） | 标注 `.json` 字节 md5 | 0 | 0 | 0 | 标注文件无重复 |

| **L2 归一化** | 去注释/去空白/标识符→`ID`/数字→`NUM` 后 sha256 | **163** | **674** | **7** | **62.2% 的样本（674/1083）落在某个结构完全相同的组里** |
| **L3 语义** | `defect_type` 组内 token TF-IDF 余弦 ≥ 0.9（**保留**数字字面量） | — | — | — | 相似对 **1029**，**全部批内，跨批 0 对** |
| **L3b 结构** | 同上但**常量归一**（数字→`NUM`），**只统计跨批** | — | — | — | 跨批近克隆 **103 对**，覆盖 4 个批对 |

**一句话结论**：
- 跨批**字节级**重复：**0**（干净）。
- 跨批**结构级**近克隆：**103 对 / 4 个批对**（真问题，且**标签不一致**，见 §4）。
- 批内**模板克隆**：**674/1083 = 62.2%**（最大的一类数据质量问题，见 §3）。

## 3. L2 归一化层：674/1083 样本结构完全同构（核心发现）

### 3.1 数字

- 归一化后共 **163 个重复组**，涉及 **674 条**样本；剩余 409 条各自唯一 ⇒
  **全库只有 572 种不同的代码结构，而样本数是 1083**。
- **模板克隆率 = 674 / 1083 = 62.2%**。
- 最大单组 **14 条**（`expA` 6 条 + `expC` 8 条，同一段"除零/UB"代码）。
- 各批参与重复的样本数：

  | 批次 | 可覆盖样本 | 落在重复组内 | 克隆率 |
  |------|-----------:|-------------:|-------:|
  | expA | 100 | 97 | 97.0% |
  | expB | 94 | 19 | 20.2% |
  | expC | 200 | 198 | 99.0% |
  | expD | 200 | 192 | 96.0% |
  | expE | 200 | 20 | 10.0% |
  | expF | 149 | 136 | 91.3% |
  | expG | 99 | 0 | 0.0% |
  | holdout | 41 | 12 | 29.3% |
  | corpus | 0（无源文件） | — | 不可测 |

  **expC / expA / expD / expF 是重灾区（91%–99%）**；**expG（真实 CVE 镜像）0% 克隆**，
  是唯一一批"每个样本结构都不同"的扩样 —— 这与 expG 走"真实世界缺陷"路线一致，可作论文里的正面论据。

### 3.2 典型例子（同一结构、仅常量或格式不同）

`expA/sample_001` ~ `sample_004`：唯一差别是数组下标 `p[0] / p[3] / p[5] / p[7]`。

```cpp
// sample_001.cpp            // sample_002.cpp（其余逐字相同）
int* p = new int[8];         int* p = new int[8];
p[0] = 42;                   p[3] = 42;
delete[] p;                  delete[] p;
int v = p[0]; // UAF         int v = p[3]; // UAF
```

`expC/sample_121`–`sample_132`：**12 条文件字节完全相同**（L1 已判重复，L2 自然同组）。

### 3.3 7 个跨批结构重复组（最需要处理的）

| # | 成员 | 批次 | 说明 |
|---|------|------|------|
| 1 | `expA:sample_080/081/082/083/097/098` + `expC:sample_133…140` | expA × expC | 14 条，同一"除零 UB"模板 |
| 2 | `expA:sample_088/089/090/099/100` + `expC:sample_141…148` | expA × expC | 13 条，同上模板的另一常量变体 |
| 3 | `holdout:h49` + `expA:sample_017/018/019/020/030/031/032/033/034` | holdout × expA | 10 条，堆缓冲区溢出写 |

| 5 | `expB:sample_B087` + `expD:D090/D091/D092` | expB × expD | 4 条 |

## 4. L3b 结构层：103 对跨批近克隆，且**标签互相冲突**

常量归一并限定"跨批"后，仍 ≥0.9 的对共 **103 对**，分布在 4 个批对：

| 批对 | 对数 | 相似度 | 代表 |
|------|-----:|-------:|------|
| expA × expC | 88 | 0.952–0.965 | `expA:sample_088` ~ `expC:sample_141…148` |
| expB × expF | 10 | 0.988 | `expB:sample_B092` ~ `expF:F106…F115` |
| expA × expB | 4 | 0.942 | `expA:sample_045…048` ~ `expB:sample_B093` |
| expC × holdout | 1 | 0.945 | `expC:sample_032` ~ `holdout:h50` |

**关键发现：103 对里，0 对的 `defect_type` 标签相同。**

```
expB:sample_B092 [other_ub]      ~ expF:F111 [bit_operation]        sim=0.9876
expA:sample_088 [undefined_behavior] ~ expC:sample_141 [optimization_dependent] sim=0.9650
expC:sample_032 [raii_violation] ~ holdout:h50 [MEM]                sim=0.9452
```

逐字核对源码（两例）：

```cpp
// expB/sample_B092.cpp  标签 other_ub        // expF/sample_F111.cpp  标签 bit_operation
int x = 0x1;                                  int x = 1;
int y = x << 32;  // UB: shift by width       int y = x << 32;  // UB: 有符号左移超位宽
```

```cpp
// expA/sample_088.cpp  标签 undefined_behavior   // expC/sample_141.cpp  标签 optimization_dependent
int a = 10;                                       int a = 10;
int r = a / 0;  // UB: integer div by zero        int r = a / 0;  // 整数除以零（UB）
```

**同一段代码在两个批次拿到不同 `defect_type`**。这不是"去重"问题，而是**跨批次标签体系未统一**
的问题（A 批用 `undefined_behavior`、C 批把同一现象归到 `optimization_dependent`），
会直接影响任务B 的 κ 系数（同一代码跨批标签不一致 ⇒ 一致性天然被拉低）。
建议在论文中要么统一 `defect_type` 词表，要么把 `defect_type` 明确定义为"批次内局部标签"。

## 7. 诚实边界

1. **L2 的"重复"是结构同构，不等于"同一个样本"**。判据是"去注释、去空白、标识符与数字全部占位化后
   完全一致"。仅常量或变量名不同的样本会被判为同组 —— 这**正是本审计想要暴露的**模板克隆，
   但严格说它们是"不同文件、不同缺陷实例"，不是字节重复。
2. **L1 用文本模式读取**（Python 默认 universal newlines）⇒ CRLF 与 LF 版本会被判为同一文件。
   这是刻意的（行尾差异不应算不同样本），但会让 L1 的 91 组略多于"纯字节 md5"的结果。
3. **L3 阈值 0.9 是经验值**，未做校准；TF-IDF 是词袋模型，对"换一种写法的同一缺陷"不敏感，
   可能漏报；同时短样本（10 行以内）容易虚高。本批对 top 组做了**人工源码核对**，
   但 1029 对无法逐对人工看。
4. **64 条 corpus 样本完全未进文本三层**（磁盘无源码），其重复情况只能用 676f 的登记结论。
   本报告所有"覆盖率 1083/1147"的比率都基于此，**不是 1147 全量**。
5. **本批不修改任何样本**。以上所有"建议"均为后续批次的输入，不在本批执行。
6. 去重脚本 `tools/audit_676k_dedup.py` 为纯标准库实现（无 numpy/sklearn 依赖），可离线复现。
