## 四、为什么是 0 —— 如实解读

1. **这 50 条并不是"跑过 gate"的结果**（见 §五），所以"0 逃逸"**不能**读作
   「新变异都被拦住了」，只能读作「**在 v7 同卡同算子的实测先验下，预测它们不会逃逸**」。
2. 预测依据全部是 v7 既有数据 ⇒ **先验里本来就没有逃逸样本**（v7 真逃逸仅 1 条），
   预测模型自然难以给出 escaped。这是**预测方法的结构性保守**，不是攻击面的证明。
3. 真正要回答"有没有新逃逸"，必须能**把 mutation 施加到沙箱副本并真跑 gate**——
   这正是 620 §九.8 登记的根本瓶颈，621 仍未解除（见 §六）。

## 五、⚠ 判决方式的重要声明（诚实登记）

**本轮的 verdict 是「预测」，不是真实 gate 判决。** 两个原因：

1. **621 §六.3 硬边界**：不跑监工门禁（`tool_integrity --check` / `gate --check` /
   `poison` / `replay --check`），仅 ci.yml 语法验证例外。
   （620 曾对 gate 开过口子，621 明确收回。）
2. **没有「施加到沙箱副本」的 API**：要跑真实 gate 就必须把变异写进卡，
   而硬边界 §六.5 禁止修改原始卡。`mutation_fuzz.py` 是**只读基线生成器**，
   不提供 apply-to-copy（620 §九.8 已登记为 VFDR 恒 0 的根本瓶颈）。

**预测模型**（确定性、可审计，全部依据 v7 实测）：
- 同 `card` + 同 `op` 在 v7 有记录 ⇒ 取多数判决（confidence=high）
- 否则同 `op` 在 v7 有记录 ⇒ 取多数判决（confidence=medium）
- 否则用策略先验 `blocked`（confidence=low）
- 全无依据 ⇒ `infra_error`

本轮 50 条**全部命中第一档（high）**：v7 对这 50 个「卡×算子」组合都有实测记录。

## 六、局限性声明

1. **生成策略有限**：只有 3 类（规则盲区 / 证据歧义 / 溯源不一致）、约 11 个模板，
   **远未穷尽**所有可能的变异形态。
2. **模板是"描述性"的，不是可执行补丁**：`content` 描述要改什么，
   并未生成可直接套用的 diff（受"不改原始卡"约束）。
3. **预测不是判决**（§五），本轮**没有产生任何新的机器验证事实**。
4. **未判定 equivalent**：等效性需要语义比对，本工具不做，如实记 0。
5. **50 条 vs 1593 条**：样本量仅为 v7 的 3%，统计意义有限。
6. **候选空间并未真正"打散"**：新 mutation 的「卡×算子」组合**全部已存在于 v7**，
   只是攻击点（`point`）与规则目标不同 ⇒ 新颖性有限（详见 A3 的新颖性评分）。
