## 2. 修复前发现的缺陷与处置（逐条，均可复现）

### 2.1 D1 · 三个论文门禁脚本的硬编码路径（包缺陷）

**症状**（`clone712` 实测）：

```
tools/paper_quality_gate_670c2.py  -> FileNotFoundError: .../research/latex/queyi_neurips2027_v1.1.tex
tools/paper_sync_check_670c2.py    -> FileNotFoundError: .../research/paper_shturl.md
tools/figure_data_check_670c2.py   -> FileNotFoundError: .../research/latex/queyi_neurips2027_v1.1.tex
```

**根因**：脚本里的 `ROOT/research/latex` 是**源写作仓库**的布局；709 拆包后论文改放
`paper/paper1/`，但脚本没跟着改。`REPRODUCTION.md` §4 明确要求用户运行这三条 ⇒ 用户必挂。

**修复**：三个脚本各加路径解析（候选顺序：原路径 → `paper/paper1/`），数据文件走
`data/<rel>` → `data/frozen_matrix/<rel>` → `data/frozen_matrix/<basename>`（与
`verify_paper_numbers.py::_p()` 同款）。`paper_sync_check` 在 Markdown 主稿不存在时
**打印 `NOT_APPLICABLE` 并退出 0**，而不是抛 `FileNotFoundError`——并在 `REPRODUCTION.md` §4
显式声明"这条检查在本包中不适用"。

### 2.2 D2 · 完整性清单从未随包发布（包缺陷）

**症状**（评审预告，实测复现）：

```
$ python tools/gen_693_manifest.py --check
[693-B2] 清单不存在：.../data/693_data_manifest.sha256     (exit 1)
```

即使清单存在，脚本里的 `TARGETS` 写 `data/<name>` 而包内文件在 `data/frozen_matrix/`，
14 项会全部判"缺失"。

**修复**：
1. `gen_693_manifest.py` 增加 `_resolve()`（三级回退），并把**实际相对路径**写进清单，
   这样 `sha256sum -c` 也能直接使用；
2. 生成并随包发布清单与 JSON 元数据；
3. 发现 709 拆包**漏掉 6 个冻结产物**（`676m_a5_matrix_corrected.json`、
   `683_real_world_project_matrix.json`、`683_real_world_type_matrix.json`、
   `684_complementarity_matrix.json`、`685_literature_matrix.json`、
   `689_annotation_key_mapping.json`），已补齐（与源仓库逐字节一致）；
4. 现在 `--check` 在干净克隆上 **15/15、失配 0、缺失 0**。

### 2.3 D3 · shell 脚本在 Windows 上因 CRLF 必挂（包缺陷）

**症状**：

```
Scripts/verify_environment.sh: line 18: set: pipefail : invalid option name
Scripts/verify_environment.sh: line 19: $'\r': command not found
```

**根因**：仓库没有行尾契约，`core.autocrlf=true` 的 Windows 用户 clone 出来就是 CRLF，
`set -euo pipefail\r` 直接语法错。Linux/CI 正常 ⇒ **同一份包在两平台行为不同**。

**修复**：新增 `.gitattributes`，`*.sh` / `*.bash` 钉死 `text eol=lf`。
修复后干净克隆实测四个脚本全部为 LF。

### 2.4 D4 · 冻结产物被行尾转换，sha256 锚定在克隆上必失配（包缺陷，最隐蔽）

**症状**（`clone712b` 实测）：

```
MISMATCH data/frozen_matrix/blindspot_676g_detection_matrix.json
MISMATCH data/frozen_matrix/676m_sample_manifest_corrected.json
MISMATCH data/frozen_matrix/681_type_stats_normalized.json
MISMATCH data/frozen_matrix/684_complementarity_matrix.json
MISMATCH data/frozen_matrix/685_literature_matrix.json
[693-B2] 校验完成：清单 15 项，失配 5 项            (exit 1)
```

`Scripts/reproduce_all.sh` 的 S1 阶段同样 FAIL（`missing=0 mismatch=5`）。

**根因（两层）**：
1. `data/frozen_matrix/` 里**混着 CRLF 与 LF 两种产物**（例如
   `blindspot_676g_detection_matrix.json` 是 CRLF，`a5_676f_detection_matrix.json` 是 LF）。
   没有显式属性时 git 套用本机 `core.autocrlf`，`git add` 时把 CRLF 收敛为 LF 入库，
   clone 出来的字节 ≠ 作者生成清单时的工作树字节。
2. 即使补上 `data/frozen_matrix/** -text`，**只跑 `git add -A` 也不会生效**：
   已被索引记录的旧 LF 版本因 stat cache 命中而不会重暂存（实测 `i/lf w/crlf` 残留）。
   必须 `git add --renormalize`。

**修复**：`.gitattributes` 增加 `data/frozen_matrix/** -text`（以及清单文件 `-text`）；
构建脚本在 `git add -A` 之后追加 `git add --renormalize -A`。
修复后干净克隆 `--check` 通过，`i/lf w/crlf` 残留数 **0**。

> 这一条是 712 最有价值的发现之一：**"按字节锚定 sha256"在跨机器复现时是假的**，
> 除非把行尾契约写进仓库。评审要的"陌生研究者能重算"，卡点正是这种看不见的字节漂移。

### 2.5 D5 · 公开包内含宿主绝对路径（匿名缺陷，跨批次同步）

`data/frozen_matrix/689_annotation_key_mapping.json` 145 行里有 **41 行** `src_path`
是 `<盘符>:\...\<源仓库根名>\Examples\...` 形态，直接暴露源仓库根名与宿主目录结构。

**修复**：新增 `tools/sanitize_annotation_key_paths_712.py`，**纯文本级**替换
（宿主前缀 → `upstream-root/`，尾部相对路径逐字保留），并在文件顶层写入
`src_path_sanitization` 记录规则与改动条数。写回前逐行校验
`anon_id / uid / defect_type / expected_verdict` **逐字未变**（实测通过）。
修复后扫描 `CodeLearnling` / 源仓库根名命中数均为 **0**。
详见 `data/712_匿名性审查报告.md` §3.3 的更新与 §6 登记。

### 2.6 D6 · 一键链的 S2/S3 依赖闭包不全（能力边界，登记而非掩盖）

`Scripts/reproduce_all.sh` 曾 exit 1，卡在 S2：`docker/paper/run_all.sh` 第 1 步
`import gate_engine` → `ModuleNotFoundError`。

**本批实测边界**：把 `path_config_625 / stats_672k / fix_676m_schema / audit_676k_integrity /
run_658_gate / run_669d_gate / guard_rerun_671a` 这 7 个缺失文件补进包后，
链条会继续向上要 `tools/atom_evidence_replay.py` —— 即 `docker/paper/run_all.sh`
**实质上依赖上游《圣经》工具链的门禁内核**，不是"补几个文件"能闭合的。

**处置（未采取"删文件刷绿"）**：撤销这 7 个文件的拷贝（半集成状态比缺失更误导），
由 `reproduce_all.sh` 做**能力探针 + 显式登记**（写入 `out/*/99_skipped.txt`，
报告中显示 `skipped (registered)`），真实失败仍然 fail-loud。
`REPRODUCTION.md` §5 明确写出"这里被跳过、为什么"，
并指出**等价的口内检查是 §2 的 `tools/verify_paper_numbers.py`（干净克隆 exit 0）**。

### 2.7 D7 · 另一处环境陷阱（登记）

`reproduce_all.sh` 优先使用 `python3`；在 Windows + WSL 下解析到 WSL 内的
`/usr/bin/python3`，而 Windows 侧装的 pytest 不在那里 ⇒ S3 打印
`No module named pytest` 并把门禁判为 FAIL。**不是包缺陷**，但会让复现者困惑，
已写入 `REPRODUCTION.md` §5 并给出处置命令。
