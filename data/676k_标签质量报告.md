## 3. 不一致案例分析

### 3.1 最高优先级：数据集**内部自相矛盾**（expE 挂起类样本）

`data/blindspot_676g_sample_manifest.json` 对同一批样本给出两个互相矛盾的登记：

| 样本 | `expected_verdict` | `hung_flag` | `hung_pool_reason` 的说法 |
|------|-------------------|------------|--------------------------|
| `expE:sample_E082` | **catch** | true | 「sanitizer 真实判据 = 挂起 → 120s 超时 → 无报告 → **miss**」 |
| `expE:sample_E089` | **catch** | true | 同上 |
| `expE:sample_E095` | **catch** | true | 同上 |
| `expE:sample_E099` | **catch** | true | 同上 |

`hung_pool` 共 35 条（expE 34 + expG 1），其中 **34 条登记为 `expected_verdict=catch`**
（expG 那条已登记为 miss，不在冲突范围内）。**重标注判定：这 34 条（以及全部挂起样本）
的 `expected_verdict` 应为 `miss`** —— 自死锁/优先级反转没有 sanitizer 报告可捕获，
唯一可观测量是超时。
**判断：原标注错，重标注对。** 建议后续批次把 `hung_flag=true` 的样本 `expected_verdict` 统一改为 `miss`，
或在论文中明确「catch 指批内自报判据，非独立检测器判据」。

### 3.2 行号口径不统一（系统性问题，非随机噪声）

行号差值的分布**高度结构化**，不是随机抖动：

| 批次 | 现象 | 证据 |
|------|------|------|
| **expB** | `defect_location.line` 以**去掉 8 行标注头之后的相对行号**计 | B014/B022/B025/B061/B069/B088/B090 共 7 条满足 `orig = rel − 8`；文件第 1–8 行正是 `// sample_Bxxx / defect_type: ... / planted: ...` 头块 |
| **expA/C/D/F** | 用**绝对文件行号**，与重标注口径基本一致 | expA 10/10 精确；expC 13/17；expD 12/22；expF 11/15 |
| **expE** | 无单一偏移，是「注释行 vs 代码行」与「指向哪个操作」的混合 | 差值 −2/−1 共 9 条（注释行）；−6…−8 共 4 条（指向更早的语句）；另 3 条差 −17/−11/−10 或 +5/+10 |
| **expG** | 绝对行号，但常把行号指向**独立成行的缺陷注释** | 11/25 精确；其余差值集中在 −1（5 条）/−2（3 条）/−3（5 条） |

把 expB 按 `+8` 基准校正后，精确命中从 57/119 升到 64/119。
**结论**：行号 47.9% 的低命中率里，绝大部分是**口径差异**（基准偏移 + 注释行/代码行之别 +
「指向失效操作还是指向使用点」），只有少数是真正的定位分歧。±3 行容差下命中率 81.5% 支持这一判断。

另有一类**真分歧**（不是口径）：`expD` 的 iterator 类样本，原标注指向**使用行**（`*it`），
重标注指向**失效操作行**（`erase`/`push_back`），如 D013/D017/D035/D053/D054。
这类分歧需要在数据卡里**明确规定行号语义**才能消除。

## 5. 整体标签质量评估与建议

### 结论

| 维度 | 评级 | 依据 |
|------|------|------|
| 缺陷类型（统一词表下） | **良好**（κ=0.77） | 具体类型几乎 100% 一致 |
| 缺陷类型（现状词表下） | **一般**（κ=0.59） | 70 个取值无统一，笼统标签拉低 |
| 期望判定 catch/miss | **良好**（κ=0.69） | 分歧集中在挂起类与内存序类 |
| 是否植入 | **良好**（κ=0.71） | 分歧仅 11 条，其中 10 条是 expG 语义差异 |
| 缺陷行号 | **差**（47.9% 精确 / 81.5% ±3） | 口径不统一为主因 |

### 建议

1. **不需要全量重标注。** 具体类型标签质量已经很好（100% 一致），全量重标是浪费。
2. **需要做的三件定向修复**：
   - **①统一 `defect_type` 词表**：把 `UB` / `undefined_behavior` / `other_ub` / `unspecified` / `MEM` /
     `memory_safety` / `memory` / `null_deref` / `null_pointer_deref` / `memory_order` / `memory-order`
     等**同义或包含关系的取值合并**；把 `conditional_trigger` / `optimization_dependent` 这类
     **元标签从 `defect_type` 里拆出去**，另设 `trigger_condition` 字段。预期可把 κ 从 0.77 推到 >0.85。
   - **②统一 `defect_location.line` 口径**：规定「指向缺陷所在操作行，使用绝对文件行号」；
     修正 expB 的 −8 基准偏移（7 条已确认）。预期精确命中率可到 ~0.7。
   - **③修正挂起类样本的 `expected_verdict`**：34 条登记为 `catch` 的挂起样本应为 `miss`
     （与 manifest 自己的 `hung_pool_reason` 一致），消除 §3.1 的内部矛盾。
3. **`planted` 字段语义必须写进数据卡**：expG 的 `planted=false` 表示「来自真实 CVE，非人工植入」，
   而 holdout 的 `planted=false` 表示「对照样本、无缺陷」——**同名不同义**。这是审稿人极易误读的点。

### 论文中如何引用（必须注明）

> 我们执行了 10% 分层抽样（n=144，种子 6761）的**双标注复核**。第二位标注者为
> **AI 标注代理**（非人类），在**抹除全部注释**的源码上独立判定。在统一到 15 类缺陷分类法后，
> `defect_type` 的 Cohen's κ = **0.77**，`expected_verdict` κ = **0.69**，`planted` κ = **0.71**。
> **该 κ 反映的是 AI 标注代理与原始标注之间的自洽性，不能解读为人类标注者间一致性（IAA）。**
> 缺陷行号在精确口径下一致率 47.9%，±3 行容差下 81.5%，差异主要来自各批次行号基准与
> 「指向失效操作 / 指向使用点」的口径不一致，而非定位分歧。

## 6. 诚实边界

1. **重标注者是 AI Agent，不是人类。** κ 是「AI 自洽性」，不是 IAA。论文中引用必须注明（见上）。
   这也意味着本报告**不能**替代真正的人类双标注；它只能回答「标签是否与代码本身自洽」。
2. **注释被抹除 ⇒ 保守下界。** 若保留 `// <<PLANTED-DEFECT>> ...` 这类行内标记，κ 会显著更高；
   但那种 κ 衡量的是「能否照抄注释」，没有信息量。
3. **批次身份是可见的**（`uid` 前缀含 batch）。因为批次与主题强相关（expE≈并发、expF≈嵌入式、
   expG≈真实 CVE），重标注者可能被批次身份提示。真实的人类标注者也会知道来源批次，
   但这确实会**抬高** κ；如需完全盲化，应打乱 batch 字段后再标。
4. **统一分类法是我自己定义的**（15 类）。κ=0.77 依赖这张映射表；换一张表结果会变。
   原始字符串口径的 κ=0.59 是**不依赖映射表**的硬数字，两个都应报告。
5. **多文件样本（4 条）与 corpus 无源码样本（13 条）未参与行号比较**，分母是 119 而非 131。
6. **有 3 条我判为「对照样本」（无缺陷）**：`expD:D126`、`expE:E031`、`expE:E200`。
   这是主观判断，不排除原标注另有依据。
7. 本批**不修改任何样本**；以上均为后续批次输入。
