## D2 开源社区建设

- **现状**：CONTRIBUTING 已有；Croissant+RAI 已生成；真实靶场浏览器/官网 8 页已建（683）。
- **优先级**（按"降低新人上手摩擦"排序）：
  1. **匿名一键可运行 quickstart**（Docker / `run_all.sh` 已 fail-loud）→ 审稿人与贡献者能 5 分钟跑通，直接回应可复现性审查。
  2. **真实靶场浏览器 + 文档**：把 688 A1-A5 的分层结果做成可交互页面，作为方法"能力边界"的活证据。
  3. **教程：如何新增资产 / 新判定**：让社区能扩展资产集（呼应 #3 组合优化）。
  4. **examples gallery**：每个资产一条最小可复现缺陷样例（从真实靶场 RW-* 抽）。
- **治理**：保持 append-only 审计链为贡献硬约束；PR 必须带 `integrity --update` 与 hash 钉定（防 686 #21 历史污染）。
- **注意**：开源前必须**匿名化**（移除 LiaoRanran/GitHub 直链）以匹配 NeurIPS 双盲（C4 P1）。

## D3 学术影响力建设

- **核心叙事**：不要主打"我们比 HELM 好"，主打"我们补了 HELM 缺的——四态判定 + 审计链 + 能力边界声明 + 失败驱动演化"（686 C2）。这是差异化的、谦逊的、可防守的。
- **渠道**：
  1. **Workshop**：NeurIPS/ICML 的 Evaluation & Benchmarking、Meta-Science 相关 workshop（与 E&D track 同生态，且欢迎负结果/失败模式）。
  2. **学术报告**：SE/PL 会议的 evaluation 主题；强调"评估治理"通用框架（AGEA，685）以跨出 C++ 圈。
  3. **社区联系**：与 HELM/Model Cards 作者、程序验证（sanitizer/符号执行）社区建立引用与对话，避免孤立。
  4. **社交媒体/博客**：只发"可复现的结果与能力边界图"，不发夸大 claim（严守 686 redlines）；用真实靶场分层图作为招牌证据。
- **可引用锚点**：TechRxiv/arXiv DOI（C3）+ TMLR DOI（C2）作为对外可见基础；rebuttal 弹药库（686 D）保证评审应对质量。
