### 3.3 **行尾契约**（本轮发现的隐藏杀手）

`core.autocrlf=true` 是全局默认。`.gitattributes` 原先只钉了 `*.sh`，**没有**保护数据区。
实测（干净克隆 vs 工作树，逐字节 `cmp`）：

| | before（`da1015a`） | after（`fb09345`） |
|---|---|---|
| `data/frozen_matrix/` 49 个产物的字节差异 | **31 个不同** | **0 个不同** |
| 例：`683_real_world_detection_matrix.json` | 247,619 B → **254,404 B** | 247,619 B（不变） |

⇒ 也就是说：**即使 713 把清单补上，`gen_693_manifest.py --check` 与 `reproduce_all.sh` 的 S1
sha256 阶段在任何 Windows 克隆上仍会全量失配**。修复：`.gitattributes` 增加

```
data/frozen_matrix/**          -text
data/693_data_manifest.sha256  -text
data/693_data_manifest.json    -text
```

（`-text` = 关闭一切行尾转换，而不是"不设 text=auto"——后者在无显式属性时仍套用 `core.autocrlf`。）
修复后克隆实测：`S1 数据完整性校验（sha256） missing=0 mismatch=0`。
