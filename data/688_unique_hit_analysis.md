# 688 · A5 真实靶场独苗命中分析

- **批次**：688 ｜ **数据**：`688_unique_hit_analysis.json`（来自 `683_real_world_detection_matrix.json` 110 样本）
- **定义**：OR 命中样本（65 个）中，若**只有一个资产**判定 catch，则称"独苗命中"。
- **意义**：独苗 = 该缺陷的检出完全依赖单一资产；该资产不可用则漏报。

## 1. 总体
- OR 命中 **65** 个；其中独苗 **27** 个 → **独苗占比 41.54%**。
- 即**超过四成的真实缺陷捕获，完全押在单一资产上**。

## 2. 谁是"独苗专业户"？
| 资产 | 作为唯一捕获者次数 | 移除该资产损失的 OR 捕获数 |
|---|---:|---:|
| **asan** | **18** | **18** |
| cross-compile | 3 | 3 |
| tsan | 3 | 3 |
| ubsan | 3 | 3 |

- **asan 是绝对主力**：18/27 独苗由 asan 单独捕获（如 RW-001 Heartbleed、RW-003、RW-008、RW-015 等 out_of_bounds）。
- 移除 asan → 损失 18 个 OR 捕获 → 覆盖率从 **59.09%（65/110）跌至 42.73%（47/110）**。

## 3. 独苗命中的缺陷特征（按类型）
| 类型 | 独苗数 |
|---|---:|
| out_of_bounds | 16 |
| integer_overflow | 3 |
| use_after_free | 2 |
| data_race | 2 |
| double_free | 2 |
| memory_leak | 1 |
| logic_error | 1 |

- 独苗集中在**内存安全类**（out_of_bounds 16/27）——这类缺陷 asan 一抓一个准，但往往只有 asan 能抓（ubsan/tsan/静态告警抓不到同一处）。
- logic_error 仅 1 个独苗，与其整体 3.23% 极低检出一致（几乎不被任何资产独抓或共抓）。

## 4. 解读与风险
- **正面**：asan 在真实靶场的单点突破能力极强，是 Queyi 真实召回的主要引擎（与 686 B2 资产集反事实"asan 是关键资产 −7.48pp"互相印证）。
- **风险（单点依赖）**：41.5% 的捕获依赖单一资产 → 一旦该资产不可用（如脱离 Linux/WSL，见 B2），召回会结构性塌方。这是能力边界的另一面：**广度不足，深度过度集中于 asan**。
- 与论文叙事契合：可用于强化"资产组合需冗余/多引擎"的 future work，以及"能力边界由类型决定"的结论。

## 5. 诚实边界
- 独苗定义基于 OR 并集内"恰好一个资产 catch"；若某资产判定 unknown（如 wunsequenced/compile-time 恒 unknown）则不会计入捕获者，不影响定义。
- 移除影响 = 该资产作为唯一捕获者的样本数（即独苗数），不等于"该资产贡献的边际覆盖"（共抓样本在移除后仍被其他资产覆盖）。

## 6. 对论文建议
- 真实靶场段增加"独苗分析"：用 41.5% 单点依赖 + asan 移除跌落 16pp 说明**能力边界的集中性风险**，并自然引出"多引擎/语义层冗余"的 future work。
