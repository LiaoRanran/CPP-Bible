# 616 D1 · 他验三件套架构设计（独立复核 + VSA 凭证 + 独立见证透明日志）

> 依据 `_arch_v20`（向外求索）：2026 年**数学界**（Lean Comparator / 四个独立内核 / Palomar）与
> **供应链界**（SLSA verified reproducible / Sigstore Rekor v2）独立收敛到**同一结构**：他验三件套。
> 本批**只做架构设计**（不接入生产流程）。

## 一、核心设计原则
1. **生成者 ≠ 判断者**（阙疑第一原则）——判断必须来自**独立于被验对象**的实现/主体；
2. **异质而非冗余**：多份"相似实现"= c≈1 的相关票（Knight-Leveson）；价值在**实现路径差异**；
3. **可验证凭证**：判断结果须是可被**第三方独立验证**的签名声明，而非"相信我"；
4. **不可篡改记录**：判断历史须 append-only + 完整性可证（透明日志），事后不可静默改写。

## 二、三件套设计
### 2.1 独立复核层（Independent Re-checker）
- **最小可行版本（已有）**：`tools/ev_matrix_unbacked_v2.py`——不 import/copy `gate_engine.py` 的第 1 条规则独立实现；
  616 B3 已建**双实现一致性回归锁**（`ev_matrix_dual_impl_lock.py`，当前一致率 **100%**）。
- **完整版本（路线）**：覆盖 gate_engine **全部 63 条规则**的独立实现（逐条异质重写）。
- **接口**：输入=证据卡目录；输出=逐卡 verdict（`BACKED/UNBACKED/…`）+ 与官方的一致/分歧。

### 2.2 VSA 验证凭证（Verifiable Statement Attestation）
- **格式（JSON）**：
  ```json
  {"vsa_version":"1.0","verifier_id":"<验证者>","verified_at":"<ISO8601>",
   "input": {"path":"<卡>","sha256":"<输入哈希>"},
   "result": {"rule":"EV-MATRIX-UNBACKED","verdict":"UNBACKED"},
   "signature": {"scheme":"hmac-sha256|ed25519","keyid":"<指纹>","sig":"<hex>"}}
  ```
- **签名**：单用户阶段用 **HMAC-SHA256**（对称，能证"未篡改 + 持有密钥"，**无公钥可验/非否认**）；
  完整阶段换 **ed25519**（非对称，任何人可验）。
- **验证流程**：`verify(vsa, key)` ⇒ 重算 `sig` 与 `input.sha256` ⇒ 一致则凭证有效。

### 2.3 独立见证透明日志（Transparency Log）
- **格式**：append-only 日志 `data/verification_log.jsonl`，每条 = 一个 VSA（或其哈希）。
- **完整性证明**：哈希链（每条含前一条哈希）或 **Merkle 树**（根可对外承诺，含包含证明）。
- **审计**：任何人可重放日志、校验链/根一致；发布 Merkle 根做外部时间锚（接 OTS）。
- **不可篡改**：append-only + 链式哈希 ⇒ 改中间条会断链。

## 五、风险与挑战
1. **单用户独立性有限**：所有验证者（含第二实现）仍是**同一主体**写的 ⇒ 独立性来自**实现路径差异**，弱于真多主体；
2. **签名密钥管理**：HMAC 对称密钥单点；非对称需托管与吊销机制（单人阶段难闭环）；
3. **透明日志存储**：本地文件可被删/改 ⇒ 需外部锚（OTS/公开仓）才真正不可篡改;
4. **共同模式失效**：两个实现共享同一**规格** ⇒ 规格错则一起错（差分测试消实现 bug，消不了规格 bug）；
5. **维护成本**：第二实现若无双实现锁会随主实现失修（B3 锁正是为此）。

## 六、边界
- 本批**只出架构设计**；未修改任何现有工具；VSA 用 HMAC 还是非对称**只在文档讨论，未实现**（D2 用 HMAC 原型）。
