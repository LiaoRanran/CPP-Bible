# 684 · B2 资产互补性量化

- **批次**：684 ｜ **机读**：`data/684_complementarity_matrix.json`
- **口径**：676f 判定矩阵（1137 样本）；$f(S)=\left|\bigcup_{a\in S}C_a\right|$；互补性定义为
  $M_{ij}=f(\{a_i,a_j\})-f(\{a_i\})-f(\{a_j\})+f(\varnothing)$。

---

## 1. 数学事实（必须先声明）

对**任何**覆盖函数（OR 并集），$f(\{a_i,a_j\})=|C_i\cup C_j| \le |C_i|+|C_j| = f(\{a_i\})+f(\{a_j\})$。
因此

$$
M_{ij} = |C_i\cup C_j| - |C_i| - |C_j| = -\,|C_i\cap C_j| \;\le\; 0.
$$

**互补性（按任务卡定义）恒 ≤ 0**：正值（严格互补）在覆盖函数下**不可能出现**。任务卡期待的「正/负/零分类」中，「正」类在本问题里为空。这不是数据巧合，而是覆盖函数的内禀性质。本批改把 $M_{ij}$ 如实解释为**冗余度（redundancy）**：负值越大 = 两资产重叠越多 = 同时选它们的新增覆盖越少；零值 = 一个的 catch 集被另一个包含（或其一为零信息）。

## 3. 与 FD 贪心选择的关系

冗余度直接决定贪心在第 $k$ 步的取舍：贪心选边际最大 = 选与已选集合重叠最小 = 选冗余度最小者。

- `asan` 与 `compiler-warn` 冗余仅 −44（最低之一）→ 贪心第二步后优先保留 `compiler-warn`；
- `asan` 与 `tsan`/`ubsan` 冗余 −169/−137（高）→ 但仍因各自独立 catch 量大而在前 3 步入选；
- 在 $k=4$ 时，贪心在 `cross-compile`（与 asan 冗余 −98）与 `compiler-warn`（−44）间选后者 → 与 A2/A3 实测 greedy 选 `{asan, ubsan, tsan, compiler-warn}` 一致。

**发现 B2.1**：FD 的 greedy 选择**隐式最小化冗余**；「互补性矩阵」若按任务卡定义，则本数据集无互补对，资产间是**替代（substitute）而非互补（complement）**关系。这解释了为何增加资产呈现边际递减（子模性），也意味着「组合更多资产」的边际收益受重叠限制——论文应如实陈述资产间为高度冗余/替代关系，而非互补。
