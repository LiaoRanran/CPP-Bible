### A · 焦点环令牌化（`web/css/a11y.css`）

问题根因：a11y.css 在 style.css **之后**加载、特异性同为 `(0,1,0)` ⇒ 后加载者赢，硬编码的旧暖橙把 `design-tokens.css` 的 `--focus-ring`（沉静蓝）整体覆盖，同一页出现两种焦点色（正文链接/按钮橙环、qy-nav shadow DOM 蓝环）。

|---|---|---|
| 2 → 2–5 | 注释 `统一 2px solid #d97757` | `统一 var(--focus-ring) + var(--focus-ring-offset)`（+ 覆写原理说明） |

### D · contrast_check 审计口径修正（`web/js/contrast_check.js`）

原状：27 对写死的清单（文件头自己承认"只审计 670c 组件用到的配对"）⇒ 新增组件、焦点环 vs 背景这类配对**永远进不了清单**，数字精确到小数点、语义却是松的。

改为两段式（旧函数签名与默认行为全部保留，回归不破坏）：

1. **基础清单 `PAIRS_670C`（27 对）**：一字不改，`auditCss()` 默认仍用它（contrast.test 依赖）。
2. **焦点环配对 `FOCUS_RING_PAIRS`（3 对）**：`--color-accent` × `--color-bg` / `--color-surface` / `--color-surface-2`（旧清单最大的盲区）。
3. **自动抽取 `extractPairs()`（35 对）**：扫 `web/style.css` + `web/css/*.css`（design-tokens 是令牌源，不扫），抓 `color:` / `background(-color):` / `border-color:` 里的 `var(--xxx)`，沿 var 链解析到 design-tokens 的**规范名 + 实色**，再按「同声明块 → 祖先选择器声明的底 → 页面底」兜底配成对。
   - 去重口径：**同一文件内**按 (fg,bg) 去重，跨文件各留一条（保留"这条出现在哪个样式表"的可定位性）。
   - 不做全交叉（fg 全集 × bg 全集）：那会把 accent 压 accent-strong 这种现实中不存在的组合算进来（实测 1.60:1，纯噪音）。
   - `:hover/:focus/:active/[hidden]/::before/::after` 等交互态与伪元素**不进**常规配对。
4. **解析不出的记 warn 不报错**：`--color-error` 缺失、契约上的非文字色被当文字用等，进 `warns` 并在 stdout 打印。
5. CLI 保留：`node web/js/contrast_check.js` 摘要；新增 `--json` 输出完整结果（含 `warns` / `stats`）。

**结果**：`pairs=65 failures=0 warns=2`，退出码 0（27 基础 + 3 焦点环 + 35 自动；×2 主题 = 130 项全 PASS）。

## 5. 诚实登记（已知未办 / 局限）

1. **未做真实浏览器验证**：本机无 playwright，全部结论为设计保证 + 单测覆盖。
2. **错误色 `#7f1d1d` 未令牌化**：`design-tokens.css` 里**没有** `--color-error`；`--color-fail` 的契约是"只用于小圆点/小标签/关键数字，**禁止大面积铺色**"，横幅是整条铺色 ⇒ 不能用它。令牌源本批只消费不修改 ⇒ 保留硬编码并加注释"错误色待令牌化"，归 672c 与令牌源一起决议。工具侧已发对应 warn。
3. **a11y 审计仍只覆盖静态 HTML**：JS 渲染 DOM 归后续批次（jsdom 可用但改造成本高）。
4. **`responsive.css:15`**：`button, .qy-btn, qy-button, .toolbar a, nav a, .skip-link { min-height: 44px; }` 对 `button` **全局**生效，小型内联按钮/图标按钮会被撑到 44px。本批不碰（任务书归 672c），仅登记。
5. **`robustness.css:21`**：`.qy-banner { z-index: 9999 }` 同样绕过 `--z-modal`。任务书只点名 a11y.css:21，本批未改，归 672c。
6. **`669c.css:25` `.st-num`**：用 `--color-text-faint` 作文字色，但令牌契约写明它是**非文字色**（占位/分隔/图标，3.45:1 不过 AA）。工具已 warn 报出（不进对比度网格，因为它不是"令牌用法问题"而是"用法纪律问题"），未改，归 672c。
7. **旧橙 `#d97757` 仍有 1 处命中**：`design-tokens.css:5` 的历史变更说明注释（"强调色从暖橙 #d97757 改为沉静蓝 #5b8def"）。令牌源属红线文件，本批不动；a11y/robustness/style/669c/responsive 五处**均为 0 命中**。
8. **组件 JS 的内嵌样式不在扫描范围**：`web/components/qy-button.js` 的 `:host([variant="primary"]) button` 设了 `color: #fff`，但背景仍是 `--color-surface-2`（浅色主题下是 `#f5f5f5`）⇒ 白字压浅底，实测约 1.07:1。这是**人工 grep 发现**的真缺陷；组件 JS 属红线（不改 JS），且任务书扫描范围是 CSS 文件，故只登记归 672c。（已确认：把它纳入扫描会立刻让审计变红，而本批无权修 JS。）
9. **抽取器的已知局限**：DOM 嵌套关系靠 CSS 选择器**推不出来**，本工具用"选择器前缀+组合器（强）/ BEM 前缀（弱）"启发式推断背景，推断出来的底在结果里标了 `inferred` 字段（`ancestor:<sel>` 或 `page`）供人工复核。已知一例归属不精确：`.deck-tab` 的真实底色是 `.deck-tabs`（surface-2），因命名是复数/单数差异未被识别 ⇒ 退到页面底（结论仍过 AA，但归属标注不精确）。
10. **2 处超出任务书行号表的改动**（`.ns-fallback a` / `.ns-note`，第 2 节已标注）：原因是任务书第 54 行把 `.ns-fallback` 的面色改成 `var(--panel)` 后，该块开始跟随主题 —— 浅色主题下面色变白，而这两行还是 666 时代的硬编码旧色，实测 **2.11:1 / 2.12:1 不过 AA**。不改就等于本批自己引入浅色主题回归，故一并令牌化（旧色保留为 fallback，noscript 场景下不依赖 CSS 时仍可读）。**如认为越界可单独回退这两行**，代价是审计回到 failures=2。
11. **过程中的一次红灯**：本批执行期间 `verdicts.test.mjs`（126 断言）与 `prune_672b.test.mjs` 曾报红，核查为并发批次正在改写 `web/data/metrics_666.json`（15:40）所致，与本批文件无引用关系；复核时 12 个前端测试 889 断言全绿。
