### 病根（环境性，不是代码债）

`numpy 2.5.3` 的 `site-packages/numpy/__init__.pyi` 使用了 **Python 3.12+ 的 `type` 语句**，
而本仓 `pyproject.toml` 的 `[tool.mypy]` 钉的是 `python_version = "3.11"` ⇒ mypy 解析该 stub 时
`syntax` 报错并 **Bail**，整个 `mypy tools/` 被阻断。
触发链：`tools/result_cache_655.py` 与 `tools/test_fast_gate.py` 顶层 `import pytest`
⇒ mypy 跟进 pytest ⇒ pytest 的断言重写模块连带 import numpy ⇒ 撞 stub 语法。

### 处置（与仓内 yaml.* / opentimestamps.* 同款：集中声明环境缺口）

`pyproject.toml` 增加两条 override：

```toml
[[tool.mypy.overrides]]
module = ["numpy", "numpy.*"]
follow_imports = "skip"

[[tool.mypy.overrides]]
module = ["pytest", "pytest.*", "_pytest", "_pytest.*"]
follow_imports = "skip"
```

* 本仓**无一行 numpy 代码**；跳过 numpy 子树不损失检查力。
* 不跟进 pytest 内部实现（本仓不需要对 pytest 自身做类型检查）；`pytest.mark`/fixture 的**用法**仍受检。
* ⚠️ 改 pyproject 会触发 `tool_integrity` 的 test_config 哈希面 ⇒ 已按规范 `--update --no-update-merkle` 重钉
  （**不重建 Merkle 根/不动 OTS 锚点**——那是 672f 踩过的坑）。

## E2 · drift_watch 空值运算隐患（已修）

`tools/drift_watch_671a.py` 的 `web_rate_changed` 判定：当基线值为 0 时 `rel_change` 返回 `inf`，
原代码把 `round(pct * 100, 4)` **直接写进 JSON 数值字段** ⇒ Python 序列化成 `Infinity`，
**严格 JSON 解析器（含浏览器 `JSON.parse`）会直接抛错**，下游静默拿不到 drift 报告。

修法：
* 新增 `finite_or_none` / `pct_display` / `sanitize_json` 三个纯函数；
* 数值字段只允许有限浮点（`inf/nan ⇒ None`），人话（"∞（基线为 0，相对变化不可定义）"）放 `pct_change_display`；
* **落盘前统一 `sanitize_json(report)`**（递归收敛，兜住其它路径）；
* selftest 增 4 条断言（inf/nan ⇒ None、显示文案、`json.dumps` 无 `Infinity/NaN`）。
* 复验：`python tools/drift_watch_671a.py` → **overall=PASS，drift 0**，2 项跨时间变化 justified。

⚠️ 同时登记：`drift_watch --selftest` 里"论文扫描至少匹配 4 条"这一项**当前为 FAIL**——
原因是论文正文（`research/`）尚未同步 672h 新数字（34/41、40/64），与 671a 守卫的 2 处 MISMATCH、
669d 的 3 条 BLOCK 同源，均等论文线更新后自动转绿（待同步清单见 `data/experiments/reveal_update_672h.json`）。
