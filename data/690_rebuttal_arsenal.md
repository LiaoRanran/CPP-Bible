## 0. 使用规则（先读这一节）

1. **语气分层**：我们与评审的分歧有三类，对应三种语气——
   - **事实纠正型**（我方数据可证伪评审说法）：**直接纠正 + 立刻给复算入口**。这类犹豫会显得心虚。
   - **维度错配型**（评审把两个维度压进一个词）：**感谢 + 拆解 + 给出两层处置**。这类不能对抗，只能拆解。
   - **范围建议型**（评审的建议对但过宽）：**接受较窄的部分 + 说明为什么不取更宽的部分**。这类要给理由，不能只说"我们保留"。
2. **每条回应都必须给复算入口**（脚本名 / JSON 字段 / tex 行号）。没有入口的回应等于没有回应。
3. **不要在 rebuttal 里引入新主张**。弹药库里的每一条都指向**已经测过、已经在稿子里、已经有机器可读产物**的数字或表述。
4. **字数预算**：E&D rebuttal 通常 500–1500 字。本库共 9 条主弹药，建议正文只放**前 5 条**（约 700 字），其余进 appendix-style 附件。

**回应要点**：

1. **该限定表述在 v1.1 中已三处存在，评审要求的并非"补充"而是"搬运"。**
   - `L154`：`*partial* historical pinning. **We give no theorems** for the three properties`
   - `L614–615`：`Historical-state pinning is separately *incomplete*: current-state verdicts are fully reproducible, historical ones only under an unchanged-ruleset`
   - `L1010–1012`：给出机制解释（受控目录移动会移动 Merkle root；历史重放假设规则集未变）
   另：`L1180` 已登记 `(4) The OTS time anchor is a zero-attestation placeholder`。
2. **评审指出的技术限制完全正确，我们不否认。** Merkle 根不含外部可信锚定时，同源整体重写确实可行。这是内禀性质，不是实现缺陷。
3. **我们实际主张的分解（三条，逐条可反驳）**：①**局部偏离可检测**（改任一叶子→根必变）；②**当前状态可第三方重算**（这是 `L614 "100% third-party re-review"` 的真实含义）；③**历史重放条件依赖**（规则集未变）。我们从未主张第④条——**抵抗同源重写**。
4. **我们主动把 OTS 的局限写进了稿子**：零证明占位 ⇒ 连"外部锚定"都不成立（`L899`/`L924`）。评审把我们没主张的东西当成了过度主张。

**语气建议**：**感谢 + 澄清（不对抗）**。核心动作是把三处限定句的**行号**直接摆出来——行号比任何辩解都有力。**不要写"评审误读了"**，只写"这一定位在稿中的 L154/L614/L1010，我们判断它可能被读摘要的读者错过，因此我们接受把它前移到摘要的建议"。**把"反驳"降格为"接受前移建议"，是我们能拿到的最优惠结果。**

### Q-B · 公式 E[J]=kd/n 错误（R1-07）

**评审意见摘要**：退化资产期望浪费槽位的公式 E[J]=kd/n 有误。

**我们的立场**：**质疑公式（评审的算术判断错误）+ 接受过度声明（"三池验证"确为过强）**

**回应要点**：

1. **E[J]=k·d/n 是超几何分布的精确均值，数学上正确。** 从 n 个候选中不放回抽取 k 个，其中 d 个退化资产，抽到退化资产数的期望为 k·d/n。推导见 `data/684_degenerate_assets_theory.md` §3（超几何分布 Pr[J=j] 与其均值），稿内表述在 `L2043`。
2. **但评审顺带指出的一个相邻问题我们接受**：稿内称该线性模型 "validated across three pools"，而三池实测中 `d=0` 池的模型预测 Δ=0、实测 Δ=+3.06pp（`684_degenerate_assets_theory.md` §4 表中该池 c 栏写"—（残差方差）"）。因此准确表述是**在 2/3 池上标定**，且 Δ≈c·kd/n 应理解为**下界**而非点估计（d=0 处的 +3.06pp 正是模型解释不了的部分）。我们会把 "validated across three pools" 改为 "calibrated on two pools with an unexplained non-degenerate residual"。
3. **可以补充一个对我们有利的事实**：本项目**已有一次成功的公式自查**——684 §4 记录，任务卡最初给出的曲率公式 κ=1−min f(A\{a})/(f(A)−f(A\{a})��在覆盖函数上口径不成立（实测各资产给出 −3.7~−69.6），我们改采标准 Conforti–Cornuéjols 定义并如实报告 κ=0.7588（`L2036`）。我们**主动**发现并修正过一个曲率公式错误，因此"有公式错误"不是对团队的描述，是对某一行的描述。
4. **数值一致性佐证**：三池单调一致（E[J]: 0 → 0.667 → 1.5；实测 Δ: 3.06 → 7.57 → 15.97pp），标定常数 c≈10.6–11.4 pp/槽位，跨池稳定。

**语气建议**：**感谢 + 不同意 + 给证据（对公式）+ 立刻接受相邻部分**。结构必须是"先纠正（带推导）、再承认（带改法）"，**顺序不能反**——若先承认，读起来像"我们错了"；若纠正后不承认，读起来像"我们不虚心"。**明确说出"评审的公式判断有误，但由此暴露的表述过度我们接受"，是这一条唯一能拿到的好结果。**

**预计字数**：180–230 字。

## 2. 拒绝类（1 条）· 必须辩且必须辩硬

### Q-D · 信息论 Goodhart 化是busywork，现在丢掉（R3-11）

**评审意见摘要**：信息论分析是 busywork，应从稿中移除。

**我们的立场**：**拒绝（对定性）+ 部分接受（对范围）**

**回应要点**：

1. **该分析做出了一个可被后续实验检验的预测，且预测被证实。** 684 测得：缺陷类型熵 H(G)=3.226 bits，单资产互信息最高 I(asan;G)=0.2986 bits，即**仅消除 9.3% 的类型不确定性**（H(G|asan)=2.927）。684 据此**预言**："先观测一个资产、再据类型预测后续资产"的自适应策略**先天信息不足**，因此自适应不优于全局贪心（`684_information_report.md` §4 原文）。
2. **该预言随后被独立证实**：自适应天花板仅 **+2.29pp**（OPT_s=59.33% → OPT_a=61.62%）；而真实自适应策略（先观察 asan，再用准确率 28.35% 的分组预测器选三个）达到 **57.75%，低于静态贪心**（`L2050` 附近，`data/685_direction1_experiment.json`）。**一个做出可检验预测并被证实的分析，不是 busywork。**
3. **它还解释了一个非显然的设计选择**：FD 实际选 `{asan, ubsan, tsan, cross-compile}`，而纯互信息最优 top-4 应为 `{asan, cross-compile, ubsan, compiler-warn}`——差异仅在末位（tsan 的 I=0.097 < compiler-warn 的 I=0.113）。FD 选 tsan 的原因是它的 **catch 频率（255）> compiler-warn（143）**，即**FD 的排序键是频率而非信息增益**。这个"选择键与信息目标错配"的诊断**只有信息论视角能给出**。
4. **我们接受评审的范围建议，并已按它调整定位**：稿内把信息论小节改述为"这是一个**证伪装置**，用于预测自适应天花板的大小并诊断 FD 的排序键；我们**不**把它作为 Goodhart 理论提出"。即 **保留测量、放弃理论**——这正是评审想要的"不要做理论"，我们已经做了。

**语气建议**：**感谢 + 不同意 + 用项目自己的数据反驳**。这一条**不能靠语气**，只能靠"预测—证实"这条硬链。**结构必须是：预言在前，证实在后**（这样读者先看到预测，再看到结果，无法回避）。**绝不能写成"评审没理解信息论的价值"**——那是姿态；必须写成"评审的判断可以被我们自己的两个实验直接检验，检验结果相反"。

**预计字数**：200–250 字。

**语气建议**：**感谢 + 确认 + 主动交出更坏的消息 + 给出补做计划**。第3 点（主动报告 κ=0.157）**是这一条的核心战术**：评审不知道这两个数，我们自己说出来，就把"被抓"变成了"我们比你更严谨"。**但代价是必须同时给出补做计划**，否则就是纯自伤。

### P-01 ★ "你们说演化有治理价值，具体体现在哪？没有演化循环会漏掉什么？"

**测什么**：这是整份 rebuttal 最关键的一问。它在测"治理 claim 是否为空"——如果答不出，第一贡献就悬空。

**回答框架（三层，每层都要有可数的证据）**：
1. **机制层**：演化循环的唯一合法输入是 verifier 自己的失败（`miss`/`unknown`），因此每一次规则变更都**必须**由一条已记录的具体失败驱动——这排除了"凭直觉调参"这一整类不可审计的修改。稿内 `L109`："how does a verifier evolve without grading its own homework"。
2. **反事实层**：没有演化循环会漏掉什么？——会漏掉**规格坍缩**。我们在演化中实测到两个规范以为存在、实际不存在的机制（`literal novel ≡ failure`、`fd_only ≡ greedy`，各 14/14 块），它们**只能**通过"失败 → 假设 → 检验"这条链被发现；而我们正是**因为有这条链**才把它们登记为已否证，而不是继续留在方法描述里。
3. **数量层（必须提前准备好——目前尚未聚合）**：452 事件账本中，按事件类型的构成：规则新增 / 规格坍缩被拒 / 冲突拒绝 / **零变更红线触发**。**其中"零变更红线触发"的计数是最强证据**——它直接度量"有多少次我们本可以改规则但被纪律拦住"。

> ⚠️ **诚实警告**：第 3 层我们目前**没有现成计数**。`690_tensions_and_blindspots.md` B-01 已把账本事件类型聚合登记为下批次必做项（只读聚合，不违反 690 红线）。**若 rebuttal 前仍未聚合，就只用前两层，不要编数字。**

**绝不能说**：❌"演化提高了检出率"（已被自己的消融否证）❌"我们让verifier 变强了"（claim 是可审计，不是变强）。

### P-03 ★ "TOST ±10pp 没过，为什么还说外部效度没问题？"

**测什么**：这是**陷阱式追问**——它的隐含前提是"外部效度没问题"，而我们从未这样claim 过。

**绝不能说**：❌"TOST没过只是样本量不够"（那正好是 margin 争议的导火索）❌任何形式的"合成与真实等价"。

### P-04 ★ "环境感知实验的因果识别策略是什么？怎么排除混淆变量？"

**测什么**：**这一问会击中我们当前的真实弱点**，必须诚实。

**回答框架**：
1. **先承认当前证据的等级**：现有证据是**口径推断**（architecture/caliber inference），**不是本机实测**（`689_environment_metrics_report.md` §2 自陈）。WSL→Windows native 的 59.09%→23.64%（−35.45pp）**不能支撑因果主张**，因为换环境时编译器版本、flag 可用性、ASLR、路径语义**同时改变**——这是被四重混杂包裹的单因子对比。
2. **给出我们承认的真实现象**（这一条无论因果如何都成立）：**静默退化**——unknown 率 Δ=**0.00pp**，即单看 recall 只会以为"只是低了"，看不到"39 个捕获的测量根本没有执行"。这是**记账问题**，不是因果问题，因果设计解决不了它，但协议能解决它。
3. **给出升级路径**（按 `690_experiment_designs.md` §2 的因子设计）：把"环境"拆成可独立操纵的正交因子——编译器身份 / sanitizer 可用性 / 优化级别 / OS 内核——做**≥2×2 因子设计**，并在因子内做**随机化分配**（预声明 seed），把"相关"变成"干预"。
4. **明确不 overclaim**：在因子设计完成前，我们**不使用"科学发现"字样**，只写"measured environmental loss"。

**绝不能说**：❌"我们证明了环境决定评估结果"（混杂未分离）❌"环境感知协议已验证"（未验证，是设计）。

### P-05 "LLM audit transfer study 与已有的 JudgeSense / BabelJudge / CodeJudgeBench 核心区别是什么？"

**测什么**：测我们是否知道这个位置有人占了。这是 novelty 的直接追问。

**回答框架**：

### P-07 "TOST 的 margin 为什么选 ±10pp？"

**回答框架**：
1. **不循环引用评审建议**：margin 必须由我们的理由决定。
2. **两个独立依据**：(i) ±10pp 约为**一次工具链替换实测漂移（≤2pp）的 5 倍**（`L2004`：asan +1.0pp、ubsan +2.0pp，κ=0.864/0.843）；(ii) ±10pp 约为**家族聚类 bootstrap 半宽（±8.1pp）的 1.2 倍**——即比抽样不确定性本身略宽。

### P-08 "你们的 p 值为什么这么小（如 2.3×10⁻⁴¹）？"

**回答框架**：
1. **给机制**：McNemar 四组对比**均为 c=0**（对手的 catch 是FD catch 的子集），差分结构为 0时 p 值随 n 急剧变小。
2. **给有效样本量**：家族聚类后 **n≈133–140**（不是1137）。
3. **始终并报效应量与CI**：**+24.0pp [+20.5,+27.5]（naive）/ [+16.6,+30.4]（cluster）**——p 小是 n 的结果，不代表大效应。
4. **给拆分**：+24.0pp ≈ **+12pp 退化资产放大 + +7~12pp 选择效应**。

**绝不能说**：❌"p 极小说明我们的方法很强"（学术禁语）❌只报 p 不报 CI。

### P-09 "110 条真实缺陷里，逻辑/并发类只有 3.23% 检出，这不是方法的失败吗？"

**回答框架**：
1. **承认这是检出上限，不是缺陷**：逻辑/挂起族 31 条 OR=3.23%，内存安全族 79 条 OR=**81.01%**（`683_real_world_analysis.md`）。
2. **给机制解释**：内存/UB 检测器的可观测量是"程序在真实执行路径上的内存动作"与"UB 事件"；逻辑绕过（验证次序错误、协议降级、状态机误判）在内存动作层面**没有可观测量**——程序不越界、不竞争、不溢出，只是"做了不该做的事"。
3. **给解决方案的正确归属**：覆盖这类缺陷需要**性质化测试（property-based）或状态机建模**，**超出了"检测器资产"的语义**——不是我们的工具不好，是测量对象换了。
4. **诚实登记**为 Limitations（我们已经在做）。

**绝不能说**：❌"我们的方法对逻辑缺陷也有效"❌"这是小众场景不必报告"。

### P-12 "为什么把 67 条规则和 452 个事件当核心贡献？看起来像工程日志。"

**回答框架**：
1. **它们是证据不是贡献**——我们会把"贡献"与"证据"分开陈述（这是 `690_tensions_and_blindspots.md` §2.3 提炼的维度原则）。
2. **贡献是那四个维度**（可审计治理框架 / 子模形式化 / 大规模实证 / 能力边界）；规则与事件是第①条的可数支撑。
3. **主动接受评审的删减方向**：附录的逐条规则清单（工程细节）我们会删；三个数留在摘要是因为**移出不省篇幅**。
4. **给出真正该被质疑的东西**：评审的实质问题应该落在"零变更红线触发了几次"——**这个问题我们有账本可答**，且答好它比列 452 更能说明治理纪律的价值。

**绝不能说**：❌"我们的规则数是创新点"❌把规则清单当技术贡献。

## 6. 追问库的使用规则

1. **P-01 / P-04 / P-06 是三条"诚实很贵"的追问**。它们要求我们交出不足（无账本构成计数、环境证据非实测、无人类标注）。**交出不足的收益是可信度，代价是分数。** 我的判断是**交出**——因为这三条都可以接着给"已知的升级路径"，而隐瞒的成本（被抓到）远高于承认。
2. **不得为追问而生成新数据**。所有回答框架里的数字都来自既有产物。若某条追问需要我们没有的数字，**正确答案是"目前没有，我们已登记为下批次工作"**，不是现场估算。
3. **若追问涉及 verdict 漂移**（R1 Weak Reject vs R2 Borderline vs R3 Solid Accept），**回答是"我们不知道三轮是否同一评审主体，因此不据此调整资源配置；我们只依据具体意见"**。绝不暗示"您比之前的评审宽松"。
