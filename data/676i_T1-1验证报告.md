## 1 · 机制核对（读源码 `compile_run_sanitize_pipeline.py`）

- 主入口 arg `changed`（line 490-507）：执行
  `git diff --name-only origin/master...HEAD` 与 `git diff --name-only HEAD~1..HEAD`，
  收集其中**文件名以 `ch` 开头、后缀 `.md`** 的变更章节（`_CHANGED_FNAME_RE`）。
- 零命中 → 打印 `[*] --changed: 无变更章节，跳过。`（`targets=[]`，不编译任何块）。
- 有命中 → 对命中的 `ch*.md` 抽取自包含块（`extract_blocks` 的 `self_contained`），
  逐块编译+链接+运行，`--chapter-context` 模式再补编译 `-O0` 对照。

**关键结论（重要）**：`--changed` 比对的是**提交区间**（`git diff A..B`），
**不包含工作树未提交改动**。即：仅在工作树改了章节而不提交，`--changed` 仍会跳过。

## 2 · 验证一：未提交改动 → 仍跳过（确认基线）

- 操作：向 `Book/part01_history/ch02_standardization.md` 末尾追加
  `<!-- T1-1 validation test -->`（HTML 注释，非 `cpp` 围栏，不改变块结构），**未提交**。
- 运行：`python tools/compile_run_sanitize_pipeline.py --changed --chapter-context`
- 结果：打印 `[*] --changed: 无变更章节，跳过。`，处理章节数 = **0**。
- 佐证：`git diff --name-only HEAD~1..HEAD` 不列出该文件（未提交改动对提交区间 diff 不可见）。

## 3 · 验证二：已提交改动 → 真跑（核心结论）

- 操作：将上述改动**临时提交**（`80abfc02`，见 §5 事故说明），使章节变更进入提交区间。
- 运行：同命令。
- 结果：**不再打印「跳过」**；pipeline 命中 `ch02_standardization.md`，
  抽取并编译+链接+运行其 **18 个自包含块，18/18 OK（exit 0）**。
- sanitizer 行：4 类 sanitizer（asan/ubsan/tsan/msan）全部 `skip(toolchain: Windows)`，
  与 676a 报告一致——这是 Windows/MinGW 工具链缺口（std::print 链接缺口 + winpthreads），
  **属误报/跳过，不是编译失败**。证明 Windows 本地 T1-1 的 toolchain-skip 是预期行为，
  真实编译/链接/运行链路本身工作正常。

⇒ **T1-1「有章节变更即真跑」机制有效**。下一次对 `Book/**/ch*.md` 的真实内容提交（push 后）
会触发 T1-1 真正编译该章节。

## 4 · 给 owner / CI 的两条提醒

1. **本地改章节后想本地触发 T1-1，必须先 commit**（哪怕临时）：`--changed` 只认提交区间 diff。
2. **Windows 本地 T1-1 永远 sanitizer=skip**：这是工具链缺口，不要据此判 pipeline 坏；
   真·sanitizer 覆盖需 Linux runner（CI 默认语境）。
