## 1. NeurIPS 2026 Evaluations & Datasets（E&D）Track 对数据集投稿的硬性要求

来源：NeurIPS 官方 E&D Call for Plapers — https://neurips.cc/Conferences/2026/CallForEvaluationsDatasets （NeurIPS 官网，2026，抓取日 2026-10-07）

| # | 要求 | 原文（节引） |
|---|------|--------------|
| 1 | **必须**用 Croissant 机器可读格式记录数据集，并随投稿上传 Croissant 文件 | *"Authors of datasets must use the Croissant machine-readable format to document their datasets and include the Croissant file with their paper submission in OpenReview."* |
| 2 | 2026 起**同时要求 core 与 RAI 两类字段** | *"This year, we request that authors provide both core and Responsible AI (RAI) fields of the Croissant format."* |
| 3 | 首选平台（Kaggle/OpenML/HF/Dataverse）只自动生成 core；**RAI 需作者自行补** | *"…a Croissant metadata file is automatically generated for you, including core Croissant fields. You will need to add the Croissant RAI fields."* |
| 4 | 自托管须**自行生成** Croissant 文件 | *"If you host your data elsewhere, you must generate the Croissant metadata file yourself."* |
| 5 | 可用官方在线工具验证有效性 | *"You can verify the validity of your Croissant file via this online tool."* |
| 6 | 数据须长期可用；>4GB 须附小样本 | *"New datasets should remain available long-term… for large datasets (larger than 4GB), authors are required to include a small sample…"* |
| 7 | 可访问性：审稿人无需向 PI 申请即可获得数据与代码；不合规可直接 desk-reject | *"Datasets and code should be available and accessible to all reviewers… Non-compliance justifies the desk rejection."* |
| 8 | 默认**双盲**评审 | *"the default review mode for the E&D Track is now double-blind"* |

时间线（同一页面）：摘要 2026-05-04 (AoE)、全文 2026-05-06 (AoE)、作者通知 2026-09-24。
→ 对 2027 投稿的含义：**Croissant（core+RAI）是入场券，必须在投稿时就有效**；等录用再补已晚（可能 desk-reject）。

### 1.1 NeurIPS 2026 最小 RAI 字段（8 项，精确字段名）

来源：NeurIPS 官方 Hosting Guidelines — https://neurips.cc/Conferences/2026/EvaluationsDatasetsHosting （NeurIPS 官网，2026）
与官方博客 — https://blog.neurips.cc/2026/05/04/responsible-ai-metadata-requirements-for-the-evaluations-and-datasets-track-neurips-2026/ （NeurIPS，2026-05-04）

| 字段 | 内容要求（官方表） |
|------|--------------------|
| `rai:dataLimitations` | 已知适用性约束：分布缺口、代表性不足、数据质量问题、领域限制；并列出**明确不推荐**的用途 |
| `rai:dataBiases` | 已知/疑似偏差：选择偏差、标签偏差、人口统计偏斜；哪些群体/场景被过度或不足代表 |
| `rai:personalSensitiveInformation` | 性别、社会经济、地理、语言、年龄、文化、健康、政治/宗教信仰等 |
| `rai:dataUseCases` | 构念效度（construct validity）：意图测量什么、有何证据；**已确立**与**未确立**的用例 |
| `rai:dataSocialImpact` | 潜在正/负面社会效应、滥用风险、公平性影响与缓解措施 |
| `rai:hasSyntheticData` | 布尔；含合成数据时鼓励在收集/标注字段描述合成过程 |
| `prov:wasDerivedFrom` | 派生来源数据集的 URI（可多个） |
| `prov:wasGeneratedBy` | ①预处理 ②数据收集 ③数据标注（**标注 schema、标注员指令、质控、标注者间一致性分数**） |

博客页逐字补充：*"we collaborated with the Croissant RAI team to establish a minimal set of RAI fields describing key aspects such as dataset limitations, potential biases, intended use, and other responsible AI considerations."*

> 官方明确：缺失 RAI 元数据的投稿 *"will be flagged during review"*；Hosting 页写 *"…may be desk-rejected"*。

## 2. Croissant core 规范（必填字段）

来源：Croissant Format Specification（MLCommons）— https://docs.mlcommons.org/croissant/docs/croissant-spec.html （MLCommons，Version 1.0，发布 2024-03-01；抓取日 2026-10-07）

### 2.1 Dataset 层必填（REQUIRED）

| 字段 | 期望类型 | 说明 |
|------|----------|------|
| `@context` | URL | JSON-LD context（官方附录 1 给出完整别名表，见 §5） |
| `@type` | Text | 必须 `schema.org/Dataset`（示例写 `sc:Dataset`） |
| `dct:conformsTo` | URL | 声明符合的规范版本（如 `http://mlcommons.org/croissant/1.0`） |
| `description` | Text | 数据集描述 |
| `license` | CreativeWork/URL | 建议 SPDX 许可 URL |
| `name` | Text | 数据集名称 |
| `url` | URL | 数据集网页 URL |
| `creator` | Organization/Person | 创建者（MANY） |
| `datePublished` | Date/DateTime | 发布日 |
| `distribution` | cr:FileObject / cr:FileSet | **Croissant 强制**：值必须是 FileObject/FileSet（不是 schema.org 的 DataDownload） |

推荐（非必填）：`keywords`、`publisher`、`version`、`dateCreated`、`dateModified`、`sameAs`、`inLanguage`；Croissant 另有 `isLiveDataset`、`citeAs`。

### 2.2 子结构

- **FileObject**：`sc:name`、`sc:contentUrl`、`sc:contentSize`（**Text 类型**——传数字会被官方校验器拒绝）、`sc:encodingFormat`、`sc:sha256`、`cr:containedIn`。
- **FileSet**：`containedIn`、`includes`（glob）、`excludes`；求值 = 先并 includes 再减 excludes。
- **RecordSet**：`field`（MANY）、`key`、`data`（内联记录，小枚举用）、`examples`。
- **Field**：`source`（DataSource；`fileObject`/`fileSet`/`recordSet` + `extract`）或 `value`（常量）、`dataType`、`repeated`、`references`、`subField`。
- **DataSource.extract**：`jsonPath` / `column` / `fileProperty`。

### 2.3 关键实现约束（682 实测，非规范原文）

1. **字段级 `source` 必须显式带 `fileObject` 引用**，只写 `extract` 会被 mlcroissant 判为 *"does not define `source` or `value`"*。
2. **内联 `data` 的记录键必须是字段全 id**（`"<recordSet-id>/<field-name>"`），否则报 *"Line #N doesn't have the expected columns"*。
3. `@context` 需包含官方全部别名（含 `equivalentProperty`、`samplingRate`），否则有 standard-context 警告。
4. `prov:wasDerivedFrom` / `prov:wasGeneratedBy` 等非 Croissant 词表属性，**值建议用纯文本**（结构化对象会触发解析器对匿名节点要求 `@type: schema.org/Text` 的报错）。
5. `contentSize` 必须为**字符串**（schema.org Text）。

## 3. Croissant RAI 规范（v1.0 全表）

来源：Croissant RAI Specification（MLCommons）— https://docs.mlcommons.org/croissant/docs/croissant-rai-spec.html （Version 1.0，发布 2024-03-06）
命名空间：`rai: http://mlcommons.org/croissant/RAI/`（**不带版本号**）；一致性声明：`dct:conformsTo: "http://mlcommons.org/croissant/RAI/1.0"`（**唯一 Required**）。

20 个属性（ONE/MANY 是**基数**不是必填性）：`dataCollection`、`dataCollectionType`(MANY)、`dataCollectionMissingData`、`dataCollectionRawData`、`dataCollectionTimeframe`(MANY)、`dataImputationProtocol`、`dataManipulationProtocol`、`dataPreprocessingProtocol`(MANY)、`dataAnnotationProtocol`、`dataAnnotationPlatform`(MANY)、`dataAnnotationAnalysis`(MANY)、`dataReleaseMaintenancePlan`(MANY)、`personalSensitiveInformation`(MANY)、`dataSocialImpact`、`dataBiases`(MANY)、`dataLimitations`(MANY)、`dataUseCases`(MANY)、`annotationsPerItem`、`annotatorDemographics`(MANY)、`machineAnnotationTools`(MANY)。

> 规范自注：属性名在文档内有拼写不一致（如 `dataUseCases` vs `useCases`、`dataAnnotationPlatform` vs `annotationPlatform`）——
> 682 采用 **RAI PROPERTY INFORMATION 表**的推荐拼写。

## 4. 682 采用的格式决策（供验收对照）

| 决策 | 取值 | 依据 |
|------|------|------|
| core 声明 | `dct:conformsTo` = 数组 `["…/croissant/1.0", "…/RAI/1.0"]` | core 1.0 有官方页面；RAI 1.0 有官方页面；两者同文件声明 |

## 6. 诚实登记（未核实 / 已知差距）

1. **Croissant 1.1 的存在性未逐字核实**：NeurIPS Hosting 指南的正文示例写 `"http://mlcommons.org/croissant/1.1"`，但 MLCommons 文档站抓取到的最新规范页为 **Version 1.0**（2024-03-01）。682 采用 **1.0**（有官方页面原文支持）；若验收方确认 1.1 已发布，只需改 `dct:conformsTo` 一个字符串。
2. **在线验证器未实测**：NeurIPS 推荐的网页验证工具需人工交互，682 用 `mlcroissant` 库（官方 Python 实现）加载通过；两者结果是否逐条一致未核。
3. **`rai:hasSyntheticData` 不在 RAI v1.0 的 20 属性表内**：该字段来自 NeurIPS 2026 Hosting 指南的最小字段表；RAI v1.0 页面（2024-03）早于该指南（2026）。682 按 NeurIPS 指南保留字段名，并在 `rai_metadata.json` 中显式登记该差异。
4. **平台托管未做**：682 只在仓库内生成并自校验；HF/Dataverse 上传、DOI、平台侧 Croissant 生成均未执行（投稿准备期任务）。
5. **`license` 与 `pyproject.toml` 的 MIT 不一致**（670c 已登记）：本批沿用 Apache-2.0（以 LICENSE 与 SPDX 头为准），未改动该历史不一致。
6. **`rai:dataCollectionTimeframe` 等时间字段未填**：语料构造跨 676c→681 多个批次，逐段起止日期未逐条采集（可从 git log 复原，未做）。
7. 本摘要的 NeurIPS 引文来自 2026-10-07 抓取的官方网站页面快照；2027 投稿前应再次核对（会议政策可能微调）。
