# MIS-MEM-030（misconception）

## 正面

【误解】MIS-MEM-030 arena/bump 分配器没有碎片（把一种使用模式下的性质当无条件结论）
触发说法：arena 分配器没有碎片，最省内存

## 背面

为什么错：**零内部碎片只在"批量申请 + 整体释放"下成立**：本批夹具的 `Arena` 只有 `release_all()`（重置 bump 偏移），**没有单块释放接口**；实测峰值 24000 B（= 24×1000）、元数据仅 8 B、内部碎片 0 —— 这组读数的前提正是\"只能整体重置\"。一旦中途释放单块，bump 指针无法回退，被跳过的空隙**不可复用**——这就是碎片
反例 1：**代价可量化、且与替代方案对称**：同一 workload 下 pool 峰值 32000 B（内部碎片 8000 B = 8 B × 1000）；arena 省下的这 8000 B 是**用丧失单块释放能力换来的**（元数据 8 B 对 32 B，因为它不需要 free-list）——\"谁更省\"取决于释放模式，而不是分配器名字
反例 2：**外部碎片维度未度量**：即便在整体释放模式下，若先后申请大小差异大且顺序交错，bump 的\"顺序推进\"会迫使峰值逼近所有同时存活对象之和（这正是 arena 在长生命周期场景下内存占用高的原因）
