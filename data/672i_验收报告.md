## 0. 一句话结论（与预注册预期**方向相反**，如实报告）

在 20 条 holdout 样本（12 真错 + 8 对照）上，**GLM-4 只看剥注释源码**：
检出 **12/12 = 100%**，而 FD 管线的同子集检出只有 **6/12 = 50%**（差别显著：精确 McNemar p=0.031，
6 条样本是"只有 LLM 抓到"）；
但 LLM 的**假阳性率 50%（4/8 对照被标为有缺陷）**。
⇒ 预注册 H1/H2/H3 全部**不成立**（H1 还出现了反向显著）。**不得**把它读成"LLM 比 FD 强"——
两者是不同判据：LLM 灵敏度高、特异性低；FD 反过来。

## 2. 协议（预注册 `prereg_672i.json`，commit 先于调用）

* 抽样（非随机、可复算）：6 条 FD-catch 真错 + 6 条 FD-miss 真错 + 8 条对照，id 升序 ⇒ 20 条。
* prompt v1：**剥离全部注释**（夹具头注释直接写"故意双重释放（ASan 取证）"⇒ 不剥就是喂答案）；
  不给 detector / planted 标签 / sanitizer 输出 / 文件名；要求只输出 JSON。
* 缓存：`data/experiments/llm_arm_672i_raw.jsonl`（逐条原始响应 + usage + 延迟，可审计）。
* 计费：总 **9166 tokens**（prompt 7425 / completion 1741），20 次调用。

## 3. 结果

| 指标 | LLM（glm-4） | FD（同子集） |
|---|---|---|
| 真错检出率 | **12/12 = 100%** | 6/12 = 50% |
| 对照假阳性 | **4/8 = 50%** | （FD 对赌集的定义为 0/8，见 672h 控制口径） |
| 与 FD 一致率 | 10/20 = **0.50** | — |
| 配对 McNemar | b（FD 独有）= 0，c（LLM 独有）= 6，**p=0.031** | — |

分层（H4）：runtime sanitizer 层 LLM 100%（n=9）｜static compiler 层 LLM 100%（n=3）⇒ 层间差 0pp（H4 不成立）。

**逐样本事实**（可核对 raw jsonl）：
LLM 正确抓到 FD 漏掉的 6 条：`h5/h33` 严格别名、`h29` 有符号左移、`h34` 竞态（fence vs atomic）、
`h46` vptr 破坏、`h59` 信号处理函数改非原子全局——这些正是"需要仪器才看得见"的运行时类缺陷，
说明**静态阅读能把 UB 模式读出来，但读不出"这一档编译到底报没报"**。
LLM 也正确地放过了 4 条对照（h12/h16/h17/h18，理由与代码一致）。

## 4. 4 条假阳性的定性分类（探索性，逐条附代码证据）

| 样本 | LLM 说法 | 代码事实 | 归类 |
|---|---|---|---|
| `h11` `_atom_weak_cycle.cpp` | "两个 shared_ptr 循环引用" | 回边用的是 `WP parent`（`using WP = std::weak_ptr<Node>`），**不是** shared_ptr | **误读**（真误报） |
| `h13` `_atom_move_no_gain.cpp` | "自定义 operator delete/delete[] 不正确" | 文件里 `operator new/new[]/delete/delete[]` 成对定义（第 25–36 行），未见其声称的不配对 | **无据**（低置信误报） |
| `h19` `_atom_alloc_arena.cpp` | "arena 的 allocate 不尊重对齐" | 文件确有 `alignas(16)` 缓冲 + bump 分配；`allocate()` 未显式对齐 | **可争议**（可能是潜伏真问题，不属本仓 planted 口径） |
| `h20` `_atom_named_rvalue.cpp` | "`CopyOnly&&` 上 `std::move` 出错" | 该文件本就是"拷贝代替移动"的**受控演示**（非 UB，项目判无缺陷） | **标准分歧**（LLM 按"最佳实践"判，项目按"UB/可检测缺陷"判） |

⇒ **FP 不能一律读成"幻觉"**：4 条里 1 误读 + 1 无据 + 2 标准/潜在问题。
这是"两个判据不同"的直接证据，也是 W6 讨论 FP 口径时必须带上的一句话。

## 6. 诚实边界（不许越界解读）

1. **模型与 prompt 都是单点**：1 个模型（glm-4）× 1 个 prompt 版本（v1）× 20 条样本；不得外推为"LLM 一般如何"。
2. **样本里有代码重复**：`h5` 与 `h33` 指向同一文件（`_atom_strict_alias.cpp`）——这是抽样规则的直接结果（未事后调整），
   它也顺带验证了模型对同一输入的稳定性（两条都判 true）。
3. **注释已剥离**，但代码里的标识符（如 `alias_kill`、`handler`）仍可能给模型提示 ⇒ LLM 的"高灵敏度"部分是它读源码的强项，不是它做了本仓的判定。
4. **不构成与真 B3 的比较**：本臂是 LLM 对照读法，不是 budget-matched 基线；论文里不得把三者并列成一个排行榜。
5. 对照的 FP 判定用的是本仓 planted 标签口径（UB/可检测缺陷）；换更宽的口径（含最佳实践），LLM 的 FP 会下降（见 §4）。
