# M6 算子改进方案（610 E4 · **只写方案，不落地**）

> 本文件是**方案文档**，不改一行算子代码：`tools/mutation_fuzz.py` 的 `mut_m6` 本批**未改**，
> v7 基线**未重冻结**，任何分母/拦截率/逃逸率**都没有变**。落地需单独授权（见 §6/§7）。
> 上游口径来源：`data/mutation/full_baseline_v7.json`（v7 冻结）+ `data/matrix_value_inventory.md`
> （587 任务0.1 机器生成的 matrix 取值台账）+ 609 E4 的 `tools/mutation_m6_optimizer.py`（4+4 分类）。

## 1. M6 算子现状（**实测，不引用任务书占位数字**）

| 指标 | 实测值 | 来源 |
|---|---|---|
| M6 可判分母 `judged` | **716** | `by_operator_rates.M6.judged` |
| blocked | **716**（`n_a=0`） | `by_operator.M6.blocked` |
| escaped | **0** | `by_operator.M6.escaped` |
| `equivalent_invalid` | **8**（全批 `equivalent=8` **全部**来自 M6） | `by_operator.M6.equivalent_invalid` |
| **严格拦截率** | **379/716 = 0.52933**，C-P95 [0.492014, 0.566403] | `by_operator_rates.M6.strict` |
| treated（表面）拦截率 | 716/716 = 1.0 | `by_operator_rates.M6.treated` |
| 逃逸率 | 0/716（C-P95 上界 0.005139） | `by_operator_rates.M6.escape` |

**口径纠正（登记）**：任务书写"M6 可判 332 ⇒ ~323"，v7 实测是 **716**（`n_a=0`）；
`332/323` 是占位数字，本方案一律用 716/708。
**读法提醒**：M6 的"表面 100%"是 `treated` 口径（解析失败一律算拦截）；真正有判别力的是
`strict` 口径的 **52.9%** —— 与其它算子相比明显偏低，这是"被等价变异稀释"的**最直接征兆**。

## 2. 问题分析：M6 打在 YAML 层，判决只读解析后的 frontmatter

M6 现行变形（`mut_m6`，逐字对照实现）：

| 形态 | 实现 | 解析后是否不同 |
|---|---|---|
| 重复 `id` 键（后写覆盖前写） | 追加一行 `id: <同值>` | **不同**（键层覆盖，可检测） |
| 缩进提升（某键多缩一格） | 改变嵌套归属 | **不同**（结构变了） |
| 全角键名（`ｉｄ`） | 键名换全角 | **不同**（键不存在 ⇒ 必填缺失） |
| 块式 → flow 写法 | `key: {a, b}` 改写 | **相同**（583 已证**等价**） |
| matrix 值层（586 删键 / 587 非法值） | `_mut_matrix_values` | **不同**（缺键 / 值非法） |

判决面只读**解析后**的 frontmatter ⇒ 凡"解析结果相同"的变异体，**无论多花哨都不改变任何判据**：

* 后果一：分母被稀释 ⇒ `strict` 拦截率被拉低（0.529 vs treated 1.0 的落差正是这部分）；
* 后果二：**看起来 100% 拦截**（treated 口径）会让人误以为 M6 检测力很强 —— 这是"数字好看"的陷阱；
* 后果三：另有一支**结构型误判**风险：语法层变异若被解析器"静默理解成别的意思"（例如全角键名被
  容错解析成合法键），攻击会变成**无效攻击**而不是被拦住 —— 这类必须靠"解析后不同"的正向证据。

**结论**：M6 只该保留"**解析后确实不同**"的形态，其余一律走 `equivalent_invalid` 通道
（已有的机制：583 起"块式→flow"就是这么被单列出来的，v7 里 M6 的 8 条等价即走此通道，**不进可判分母**）。

## 3. 改进方案（三选一或组合；只变异"解析后不同"的形态）

### 方案 A · 值层：只替换 matrix **非法值**（不新增形态，扩大覆盖面）
把 `matrix.compiler / std / opt` 的值替换成台账（§8）里**不存在**的形态：
`compiler: GCC 99.9.0 (假)`、`std: c++99`、`opt: -O9`、`compiler: ""`（空值）。
**关键**：值域真源是 `data/matrix_value_inventory.md`（587 任务0.1 生成），非法值必须来自台账的**反面**，
不许自己编造"看起来像"的值（否则会造出"其实合法"的假变异）。

### 方案 B · 结构层：必填键缺失 / 未知键 / 类型错位
删除必填键（`id` / `artifact` / `command`）、追加未知键（`x-evil: 1`）、把列表键写成标量
（`related_atoms: ATOM-MEM-001` 而非 `[ATOM-MEM-001]`）、把映射键写成 flow 标量。

### 方案 C · 语法层：让 YAML **解析必失败**（fail-closed 的正面证据）
缩进错位（把 `artifact` 缩进到 `matrix` 之下）、引号不匹配（`compiler: "GCC 13.3.0`）、
Tab/空格混用、重复顶层块键。判据不是"内容变了"，而是**解析器必须报错**（不许静默容错）。

## 4. 预期效果（分母变化 / 拦截率变化 / 逃逸率变化）

| 动作 | 可判分母 | strict 分子 | strict 点估计 | 说明 |
|---|---|---|---|---|
| 现状（v7 冻结） | 716 | 379 | 0.52933 | 基线 |
| **剔除已实测 8 条等价**（`EST_EQUIVALENT_IN_M6=8`） | **708**（算术下界） | 379（不变） | **0.5353** | **口径修正**带来的数字变化，**不是**检测力提升 |
| 方案 A/B/C 新形态**有效** | 708 + N | 379 + n_拦住 | 上升（真提升） | 必须逐个形态跑毒样例（§5）证明"拦住" |
| 方案 A/B/C 新形态**等价** | 不进分母 | — | — | 走 `equivalent_invalid` 通道，**不得计入分母** |
| 新形态**逃逸** | 708 + N | 379 | **下降** | M6 现为 0 逃逸；一旦出现即打破"零逃逸"，**必须先小样本验**再全量 |

> ⚠️ 两条**不许混淆**的话：①"分母 716⇒708"是**口径修正**（数字会动，检测力没动）；
> ②"strict 上升"若来自 ① 就是假进步。真实提升只能由"新增形态被拦住"（分子 +n）带来。
> 4 类等价划分还会覆盖多少**未知**等价，不重冻结就算不出来（下界 8、上限未知）。

## 5. 毒样例设计（**每种方案 ≥2 个**，共 6 个；每个都给出期望判决与漏检后果）

| 编号 | 方案 | 变异内容（对一张真卡） | 期望判决 | 应触发的检测器 | 漏检后果 |
|---|---|---|---|---|---|
| P-A1 | A | `matrix.compiler: GCC 99.9.0 (假)` | **refute/blocked** | 587/588 matrix 值校验（`EV-MATRIX`） | 假编译器值混入 ⇒ 值域漂移无人知 |
| P-A2 | A | `matrix.opt: -O9`（非法优化档） + `matrix.std: c++99` | **refute/blocked** | 同上 | 同上（且会让"编译依据"失真） |
| P-B1 | B | 删除必填键 `command`（其余不变） | **refute**（fail-closed） | 结构校验：必填字段齐全性 | 卡缺命令仍能入库 ⇒ replay 无从执行却判通过 |
| P-B2 | B | 追加未知键 `x-evil: 1`；并把 `related_atoms` 写成标量 | **refute/blocked** | 结构校验：未知键 + 类型校验 | 未知键成为绕过通道（"数据走私"） |

毒样例的**共同要求**：每条都要能在**一张真卡上单独注入**（不批量），并断言"注入后判决 = refute/blocked"；
**若某条毒样例在现状下被静默通过**，那条就是本节最重要的产出（要先修检测器，再谈扩分母）。

## 6. 风险评估（改算子 = 改口径）

1. **动已冻结数字**：v7 的 `by_operator.M6.*` 与全批 `judged/blocked/escaped/rate_flags` 都会变；
   必须**重冻结**（新版本号 v8）并重钉 `mutation_baselines` 的 Merkle 根与 supply chain 台账。
2. **等价判据自身会被质疑**：把"N 条等价"从分母里剔除 = 主张"N 条不算攻击"；必须能逐条复算
   （解析后 frontmatter 逐字段相同）⇒ 只在有正面证据时剔除。
3. **589 的 M1/M6/M7 重跑子集**会跟着变（该子集用于 034 幻影 finding 的观察面）。
4. **matrix 值校验（587/588）扩容**：方案 A 依赖值台账；若台账本身过期（新卡引入新值），
   非法值可能"其实合法" ⇒ 落地前必须先重跑台账生成。
5. **不许顺手改判决**：本方案只改"哪些变异形态进入分母"，**不动** confirm/refute 判定、不动卡面数据。

## 8. 与 587/588 的 matrix 取值校验的关系

* `data/matrix_value_inventory.md` 是 587 任务0.1 的**机器生成台账**（56 张卡，`compiler` 去重 8 个值等），
  它是"**什么是合法值**"的唯一真源，**不得手工编辑**；
* 588 的值校验是方案 A 的**检测器**：A 方案的非法值必须落在台账值的补集里，否则就是"自造假变异"；
* 反向约束：若 588 的值校验**放宽/收紧**了合法域，方案 A 的毒样例要同步重选
  ⇒ 本方案把"值域"与"变异形态"分开对待：**值域归 587/588，形态选择归 M6**。
