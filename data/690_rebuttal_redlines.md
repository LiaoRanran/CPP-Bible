# 690 · D3 · Rebuttal 红线清单

- 批次：690｜用途：**发出前的逐句检查表**

## 4. 逐句检查流程（rebuttal 发出前）

1. **逐句扫红线表**（§2 的 14 条 + §3 的 5 条）：把 rebuttal 全文的每个**肯定句**（含"我们"、"证明"、"显示"）在表里查一遍。
2. **三态检查**：每个 claim 必须落在三态之一——**已确认有 / 已确认无 / 未见证据未闭合**。禁止出现第四态（"大概 / 应该 / 可能是"）作为主张。
3. **数字可溯源检查**：每个数字必须能指向 `data/` 下的机读产物或 tex 行号。**指不动的数字一律删掉。**
4. **未核实数字清零**：本项目的历史教训（683 批次）——报告里预写的未核实数字（fncr=55.65%、linker 独苗案例）都被实测推翻。**任何 rebuttal 数字必须是本批实测或既有冻结产物的值。**
5. **语气终检**：把评审的每条意见标上我们的处置（接受 / 部分 / 质疑 / 拒绝），**确认没有一条被静默忽略**。沉默会被读作"没读懂自己的评审意见"。

## 5. 红线的例外（唯一三条允许的"软化"）

为免红线被教条化，明确三条允许的例外：

1. **可以承认"这行写得不好"** ——但必须紧跟"我们已改"和改法。红线禁的是**把改进伪装成从来没错**（如红线 3、4、5、8），不是禁自我批评。
2. **可以说"我们不知道"** ——且这是**最高性价比的一句话**（P-01 / P-04 / P-06）。我们有三处真实未知（账本事件构成计数、人类 IAA、环境因果识别），**诚实承认 + 给出已登记的补做路径** 远优于含糊带过。
3. **可以说"这超出本文范围"** ——但必须指出**它在本工作里的位置**（例如跨语言验证是 E2 的工作，不是本文的 claim）。**不能只说"不做"而不说"为什么不做"。**

## 6. 一页速查（发出前最后一眼）

| 问自己 | 若答案是"是"，则 |
|---|---|
| 这句话在稿里 / 机读产物里能查到吗？ | 查不到 → 删或标"待补" |
| 这句话是不是在讨好评审？ | 是 → 删（红线 8–14 方向） |
| 这句话是不是在逃避？ | 是 → 补（红线 15–19 方向） |
| 这个数字我本批核实过吗？ | 没 → **不要写**（683 教训） |
| 评审的这条意见我在 rebuttal 里回应了吗？ | 没 → 补（三态检查） |
| 我是否说了"等价 / 可靠 / 首创 / 更优 / 不可篡改"之一？ | 是 → 查红线表 |
| 这句话的主张落在三态的哪一态？ | 说不清 → 降级为"未见证据未闭合" |
