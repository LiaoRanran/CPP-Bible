## 二、数据层单点（E/F）设计要点

`web/js/data.js` 收口为统一入口：

- `fetchJSON(url, { retries=3, retryDelay=1000, timeout=8000 })`
  - **仅对网络/超时异常重试**；HTTP 状态码错误（404/5xx）**立即抛出、不重试**——404 是确定性失败，重试无意义，且前端 `boot()` 把 404 视为"源缺席"需快速降级。
  - 页内缓存挂在 `window.__dataCache`：缓存随单页生命周期自然重置，**不会跨"页面"泄漏**（纯 Node 测试无 window 时回退模块级 Map，仍去重）。
- `formatMetric(v)`：`null/undefined/''` → `'--'`，**真 0 → `'0'`**（旧实现把真 0 与缺失合并成 `'--'`，是在"撒谎"）。
- `pct(v)`：`v==null ? '--' : formatMetric(v)+'%'`；`esc(s)`：HTML 转义。
- `app.js` 改为 `export { fetchJSON } from './js/data.js';`，旧调用方（card.js / cards.js / starmap.js / verdicts.js / verify.js / experiments.html 等）**零改动**。

## 五、执行中暴露并修复的一个真 bug

`fetchJSON` 初版对所有失败（含 HTTP 404）重试 3×1s。这导致：
1. 前端 `boot()` 把 404 当作"源缺席"快速降级，却要等 3 秒重试——页面/冒烟假死；
2. 测试 `verdicts.test` 仅等待 80ms 就断言 `ready()`，`LOADED` 未填充即失败。

修复：HTTP 状态码错误不重试、仅网络/超时重试，并将页内缓存挂到 `window`（避免跨测试"页面"的缓存泄漏污染 no-data 用例）。修复后 889 原断言 + 两新套件全绿。
