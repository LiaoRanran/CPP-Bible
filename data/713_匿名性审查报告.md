## 2. 为什么"在原仓库上删名字"行不通

| 手段 | 是否可行 | 原因 |
|---|---|---|
| 改 README / 删文件里的名字 | ❌ 不足 | 提交元数据（author/committer/Signed-off-by）与 remote URL 仍在 |
| `git commit --amend` 改最后一次提交 | ❌ 不足 | 前 4 个提交与 remote 仍是 `github.com/LiaoRanran/...` |
| `git filter-repo` 重写全历史 + force push | ⚠️ 不安全 | ① 已 push 的对象会留在 fork / 镜像 / GitHub API 缓存 / Software Heritage，删除无法保证；② 需要 force push（违反本批红线 4） |
| GitHub 的"匿名提交"功能 | ❌ **不存在** | GitHub 无原生匿名提交能力；提交必然带 author/committer 邮箱 |
| **新建身份隔离副本**（本批采用） | ✅ 推荐 | 历史只有 1 次匿名提交、无 remote、内容已清洗；可发布到中立账号 / 组织 / 匿名托管 |

## 5. 发布路径建议（给用户的决策项）

**不要**在原账号 `LiaoRanran` 下新建仓库 —— 那等于换了名字接着挂身份。三条可执行路线：

| 路线 | 操作 | 优点 | 缺点 |
|---|---|---|---|
| **A. 中立账号 / 组织** | 用新邮箱注册与身份无关联的账号（不复用头像/用户名/bio），或建 organization 再 push | 保留 git 完整可追溯性（diff / blame / 版本） | 需新邮箱；账号若被关联仍可追 |
| **B. 匿名托管（推荐给双盲）** | 把 `queyi-audit-anon` 打成 tarball 上传 **Zenodo**（可先匿名后补作者）/ **OSF** / **Software Heritage** | 完全不暴露 GitHub 账号；有 DOI 可被审稿人引用 | 审稿人不能 `git clone`（但能下载解压，`REPRODUCTION.md` 的命令照跑） |
| **C. A + B 并行** | GitHub 中立账号托管 + Zenodo 归档一个 DOI | 兼顾"能 clone"与"能引用" | 工作量稍大 |

**双盲期间最低要求**：发布物**不得**包含指向 `github.com/LiaoRanran/*` 的任何链接。
当前 `queyi-audit-anon` 的 remote 为空、README 无外部身份链接，满足该要求。

**原仓库 `queyi-audit` 的处置建议**：投稿期内设为 **private**（不要直接删除 —— 删除会把 Owner 变成
`ghost`，但 fork/缓存仍可能保留；private 至少停止继续暴露）。投稿结束后再决定是否公开或删除。
