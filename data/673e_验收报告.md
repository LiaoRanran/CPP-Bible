### 1.3 任务 A · Merkle 域分隔（误报，复现成立）

**独立复现的三条证据**（全部自算，未引用 671e 的测试）：

1. **结构性**：`_LEAF_PREFIX == b"\x00"`、`_NODE_PREFIX == b"\x01"` ⇒ **sha256 输入的第 0 字节不相交** ⇒ 两个输入集合不相交。另穷举 6 叶树，验证**叶 hash 集合 ∩ 内节点 hash 集合 = ∅**。
2. **构造性 PoC**：取同树的一个内节点 hash，把它塞进证明的 `leaf.hash`、并把根换成该内节点 ⇒ `verify()` **拒绝**（"叶 hash 不匹配"）。反事实：把两个前缀都抹掉后，内节点输入以 `0x00` 开头（`u64(1)` 高位），而叶输入必须以路径开头、**路径不能含 NUL** ⇒ **路径绑定本身也挡住这一路**。
3. **长度扩展（671e 没做的一块）**：自带纯 Python SHA-256（与 `hashlib` 在 55/64/200 等填充边界逐例对齐），真的算一次 `H(m || glue || suffix)` ⇒ **得到的是不同 digest，不是同一 hash 的第二原像** ⇒ 用扩展后的文件去满足原 hash 的证明**被拒**。**结论：长度扩展在本构造下不可利用。**

### 2.3 三条必须同时读的发现

1. **预注册的主口径失效**：clang-tidy 四检查族在 holdout 上召回 100%、**假阳也 100%** ⇒ **零判别力**。根因：`cppcoreguidelines-*` 在几乎每个文件都报警（实测 `cppcoreguidelines-pro*` **200** 条 + `cppcoreguidelines-avoid*` **198** 条，而真正指向缺陷的 `clang-analyzer` 只有 **48** 条）。**级别（error/warning）不是判别器，检查族才是** —— 这是本实验的**预注册设计缺陷**，按纪律**原样报告、不回改预注册**；有效结论落在 StrictA/StrictB 上，并**显式标注为事后选择（post-hoc，p 值属探索性）**。
2. **FD 的优势有外部工具作证**：holdout 上 FD 82.9% vs clang-analyzer 48.8%，**c = 0**（工具的检出是 FD 检出的**子集**）⇒ FD 的检出集**严格包含**工具的检出集。
3. **FD 的短板同样被暴露**：corpus 上 FD 与 cppcheck **打平（p=0.383）**，且有 **8 条反向对**（工具抓到、FD 记 miss），全部集中在**未初始化变量**（`uninitvar` / `core.UndefinedBinaryOperatorResult`）、**路径未执行的重复释放**（`doubleFree` / `deallocuse` / `NewCircle`）、**编译期可见**（`missingReturn` / `wrongPrintfScanfArgNum`）三类。
