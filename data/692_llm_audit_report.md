## 0. 结论先行（四条）

1. **audit 链条在语言模态上可迁移**：provenance → caliber → 盲评 → 四态 → 逐样本落盘 → 口径敏感性，
   全部在 LLM 上执行成功（预注册三条件里的 ②③ 成立）。
2. **但"同一资产换句话判定不变"这条隐含假设，只在非推理型模型上成立**：
   prompt invariance = **96.25%**（`glm-4-flash`）vs **87.5%**（`glm-4.5`，未过预注册的 ≥90% 门槛）⇒
   迁移判定为**部分成功**。
3. **LLM 的 failure topology 与 sanitizer 正交**：sanitizer 的失败是**能力边界**（按缺陷族分化、与措辞无关）；
   LLM 的失败是**补全预算 + 过度自信 + 近似常量输出**（与预算和措辞强相关、与缺陷类型弱相关）。
   ⇒ 二者是**互补**证据资产，不是可替代品。
4. **新发现的可治理结论**：`unknown` 的**来源**决定治理动作——环境门控的 unknown 要换环境，
   预算门控的 unknown 要换预算。两者混在同一个 `unknown` 桶里，治理就无从下手（与 692-A 同源）。

## 3. 敏感性两则（同一份测量，口径一动数字就动）

### 3.1 补全预算敏感性（Model A，仅改预算）

| 轮次 | `max_tokens` | 截断（`finish_reason=length`） | 样本级 unknown | 样本级 unknown 率 | conditional recall | 能力分歧率 |
|---|---:|---:|---:|---:|---:|---:|
| A@700 | 700 | **76 / 160** | 46 | **69.70%** | 100% | 71.43% |
| **A@2000（主表）** | 2000 | **27 / 160** | 18 | **32.73%** | 100% | 72.00% |

⇒ 预算翻了 2.86 倍，**不可用率只减半**；仍有 27 次把 2000 token 全烧在推理上。
**"模型答不上来"里有很大一块其实是"预算不够"**——这是把 LLM 当证据资产时必须先量的东西。

### 3.2 聚合口径敏感性（探索性，事后登记）

| Model A 聚合口径 | conditional recall | 能力分歧率 | unknown | 可判定样本数 |
|---|---:|---:|---:|---:|
| 预注册：p1/p2 不一致取 p1 | 100% | 72.00% | 18 | 62 |
| 资产一致 OR：任一 prompt 报 catch 即 catch（与 8 资产 OR 同构） | 100% | 70.97% | **10** | **70** |

⇒ 同一批回答，仅换聚合规则就多捞回 **8 条**可判定样本。与 692-B 的 T1/T2、
692-A 的 aware/unaware 是**同一种现象**：**口径不是描述，是决定读数的零件。**

## 4. Failure topology：LLM 与 sanitizer 正交（核心发现）

| 维度 | sanitizer（asan/ubsan/tsan） | `glm-4.5` | `glm-4-flash` | cppcheck（对照） | clang-tidy C-main（对照） |
|---|---|---|---|---|---|
| `unknown` 的**来源** | **环境门控**（资产没跑） | **补全预算**（推理 token 吃满 → JSON 截断） | 无 | 源缺失 / 60s 超时 | 源缺失 / 60s 超时 |
| 本帧 unknown 率（样本级） | 0%（8 资产 OR 全部可判定） | **32.73%**（@2000）/ 69.70%（@700） | **0%** | 4.95%（28/566） | 5.12%（29/566） |
| 输出是否近似常量 | **否**（按缺陷族分化：asan 49.1% vs ubsan 18.2% vs tsan 22.7%） | 倾向 catch（115/160） | **是**（141/160 catch） | 否（按族分化） | **是**（513/537 出报告） |
| 自报置信度是否可用 | 不适用（不报置信度） | **否**（ECE 0.29，全部 ≥0.9 桶） | **否**（ECE 0.45） | 不适用 | 不适用 |
| 对措辞的敏感性 | 不适用（判定与 prompt 无关） | **12.5% 判定翻转** | 3.75% | 不适用 | 不适用 |
| 独有命中的族结构 | — | concurrency 6 / embedded 4 / memory_safety 4 / stl 3 | concurrency 13 / embedded 10 / language 4 | **concurrency 0** | — |
| 治理动作 | 换环境 / 补资产 | **换预算** | 换 prompt 工程 | 换规则集 | 收窄 checks |

**读法**：sanitizer 的失败**可预测、可按族归因、且与措辞无关**；LLM 的失败**主要由调用侧参数决定**
（预算、措辞），缺陷类型只占次要因素。⇒ 两者**测的不是同一片区域**：
本帧里 LLM 独有命中 sanitizer 抓不到的样本有 **21（A）/ 37（B）** 条，而 sanitizer 独有命中只有 **0 / 1** 条。
**这不是 superiority 结论**——LLM 独有命中里只有 13.5%–19.0% 被参考协议认定为"真错"，
其余是"参考声称不可达、LLM 读出来了"的**能力分歧**，要靠 §5 的人类参考标注才能定性。

## 5. 迁移判定（对照协议 §5 的预注册三条件）

| 预注册条件 | A `glm-4.5` | B `glm-4-flash` |
|---|---|---|
| ① Prompt invariance ≥ 0.90 | **87.50% ✗** | 96.25% ✓ |
| ② 四态完整落盘（含 unknown/contradiction 可逐条追） | ✓ | ✓ |
| ③ `V_LLM ≠ V_sanitizer` 成规模且方向可解释 | ✓（21 条，集中在 concurrency/embedded/memory_safety） | ✓（37 条，同上） |

⇒ **判定：audit protocol 可迁移（②③），但"资产稳定性"这一条只在非推理型模型上成立（①）。
本臂不声称 LLM 是 oracle，也不声称它更准。**

## 7. 给论文/后续批次的三条可执行建议（不改正文，仅建议）

1. **正文若要引用本臂，只能引用三点**：① audit 链条模态可迁移；② 预算/措辞是 LLM 资产的
   **一等治理参数**（与 692-A 的环境同构）；③ LLM 与 sanitizer 的能力区域**互补且不重合**。
   **不得**写成"LLM 也能检出 XX%"（暗示等效验证器），**不得**给出 LLM-vs-sanitizer 的准确率排名。
2. **若要把 LLM 纳入常规 4 资产池**，前置条件有三：配额定档登记、`unknown` 来源分离（预算 vs 内容 vs 拒答）、
   以及 prompt 不变性 ≥0.9 的**资产准入门槛**（本批 A 已被该门槛挡下）。
3. **人类 IAA 的紧迫性被本批再次放大**：§4 的 21/37 条"能力分歧"只有人能定性，
   而它们正是"LLM 到底看见了什么"的核心问题（本批无法回答，不猜）。
