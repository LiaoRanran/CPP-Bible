## 1. 收集流程（五步，全部可复现）

1. **候选起草**：按"来源矩阵 × 项目覆盖 × 类型覆盖"起草 130 条候选（CVE 为主，
   含 pwn/CTF 场景 5 条），每条记录项目 / 缺陷类型假设 / 机制一句话。
2. **在线验证（NVD API v2.0）**：逐条查询 `services.nvd.nist.gov/rest/json/cves/2.0?cveId=…`
   （无 key 限速 5 req/30s，脚本按 6.2s/条节流 + 断点续跑）；**应答原文**（英文描述 / CVSS /
   发布时间 / references）整体冻结进 `683_real_world_candidates_verified.json`。
   **结果：113 个唯一 CVE 全部 FOUND（零淘汰）**。
3. **PoC 重构**：以 NVD 描述驱动，写"缺陷机制最小重构"（单文件 <200 行，ASCII 源码，
   头部注释内嵌元数据）；同一 CVE 的重复候选去重后按项目写样本。
4. **编译门**：全部 110 个 PoC 过 `g++ -std=c++17 -fsyntax-only`（本地 MinGW 批量校验）。
5. **检测**：110 × 8 资产真实检测（WSL g++ 13.3 双档 + MinGW 本地资产），checkpoint 增量落盘。

## 3. 困难案例（逐条）

1. **RW-002（无限循环）**：任一 sanitizer 档位都只能以超时观测。处置：保留 + 在矩阵 note
   与本案中显式登记"超时→无报告→miss"；这条同时是"检测器对非终止性缺陷无观测面"的
   教科书级证据（分析报告 §2-(f)）。
2. **RW-027（regreSSHion 信号竞争）**：原机制为 SIGALRM；MinGW 无该信号 ⇒ cross-compile
   资产在本地编译失败（unknown）。改用 SIGINT 后两平台均可编译，且 WSL tsan **命中**
   （catch）——"平台适配不改变缺陷本质"的一个实例。
3. **逻辑/协议类（31 条 logic_error，OR 3.23%）**：内存/UB 检测器对其**结构上无观测面**
   （不越界、不竞争、不溢出）。处置：不删样本、不硬造 catch，如实保留为最大盲区族；
   这一族同时是"真实靶场总体检出率被拉低"的主因（分析报告 §2-(a)）。
4. **linker 资产 0 catch**：110 条全为单 TU 重构，linker 的触发面（多定义/缺符号）
   在该构成下不存在——登记为"资产适用面"事实，并给出后续方向（多 TU 样本集）。
5. **跨工具链一致性意外地好**：clang 18 与 g++ 13.3 在 asan/ubsan 上一致率 93.5%
   （κ 0.86/0.84）——"不同编译器会改变结论"的担忧在本口径下未获支持（已入论文附录）。
6. **MinGW clang 的 ASan 不可用**：`libclang_rt.asan_dynamic` 缺失（运行库未随 MSYS2 安装），
   尝试记录在案；跨工具链对比改由 WSL clang 18 承担（同平台双编译器，方法学更干净）。
