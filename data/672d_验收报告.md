## 2. perf 预算口径修正（任务 B）

**病**：`assets_gzip` 把所有 `src|href` 都算进"首屏 gzip"，包括 `<a href="data/metrics_666.json">`、`<a href="learn.html">` 这类**点一下才下载**的导航链接 ⇒ 台账/manifest 一变大、多加一个导航入口，首页"性能"就凭空变差，120KB 预算失去约束力。

**修**（`tools/perf_audit_670c5.py`）：

| 项 | before | after |
|---|---|---|
| gzip 口径 | 全部 `src|href` | **只算加载时资源**：`<link rel=stylesheet/icon/preload/manifest…>`、`<script src>`、`<img src>` |
| 导航链接 | 混在首屏里 | 单列 `nav_refs` 字段，只报告不计入预算 |
| 外部依赖检查 | 任何 `http(s)` 引用都算（672c 给首页加仓库链接后误报） | 只判**加载时**外部资源；`<a href="https://…">` 引用不算 |
| 产物字段 | — | 新增 `assets_gzip_kb_legacy`（旧口径对照）、`load_refs`、`nav_refs`、`gzip_scope` |
| 预算 | 120KB | **仍是 120KB（未放松）**；输出新增 `--out` |

**数字对比**（实测，修正后重跑）：

| 页 | 旧口径（含导航） | 新口径（仅加载时） |
|---|---|---|
| **index.html** | **57.2KB** | **24.0KB** |
| cards.html | 50.7KB | 35.9KB |
| learn.html | 52.0KB | 32.1KB |
| experiments.html | 61.9KB | 29.8KB |
| verdicts.html | 40.2KB | 36.5KB |
| starmap.html | 60.5KB | 47.8KB |
| verify.html | 29.1KB | 22.5KB |
| card.html | 33.6KB | 24.8KB |

> ⚠️ **数字变小 ≠ 性能提升**，只是口径从"整个网站的链接图"修正为"浏览器加载首页真的会下载的东西"。预算 120KB 保持不变（现状 24KB，仍有约 5 倍余量；是否收紧到 60KB 由 672e 决议）。

产物：`data/perf_672d.json`（`--write --out` 生成）。同步修改 `web/tests/perf_670c5.test.mjs`：外部依赖断言改为只判加载时资源 + 新增 7 条 gzip 口径断言（73→80）。

## 7. 诚实登记

1. **jsdom 审计发现的 2 处 `aria-busy` 残留本批未修**（只报告；修复 + 双工具合并归 672e）。
2. **未做真实浏览器验证**：playwright 不可用（Node 18/22 均报 ERR_MODULE_NOT_FOUND）；jsdom 审计 + 单测是全部保障。
3. **perf 数字变小只是口径变对**：57.2KB→24.0KB 不代表性能提升；报告与工具输出里都写了这句，防止误读。
4. **首页 DOM 测试绑定 672c 的首页结构**：672c 再改 `#ab-*` / `#metrics` 等结构需同步更新测试（测试会红，是故意的）。
5. **并发批次实况**：本批执行期间 672c 正在重制首页——`web/index.html`、`web/home.js` 多次变更，`robustness_670c3` 一度因 skeleton 被删而红（后 672c 恢复，现已绿）；我创建的 `web/run_tests.mjs` 被 672c 编辑过一次（加入了 home_672c/debt_672c，挤掉了 672d 的两行，**已加回**，17 个测试齐全）。
6. **jsdom 渲染的实现限制**（已写进工具 LIMITATIONS）：canvas `getContext` 被 shim 成 null（走站点自带的"无 canvas 降级"路径，与真实浏览器 WebGL 不可用同类）；`globalThis.performance` **不能**挂 window.performance（jsdom hr-time 会自引用栈溢出，实测踩过）；浏览器 `self` 全局需手工补；内联 module 以 data: URL 执行（相对 import 已重写为绝对 URL），与浏览器加载顺序不完全等价；fetch 是本地文件 mock。
7. **`data/perf_audit_670c5.json`（670c5 的旧产物）未重新生成**：仍是旧口径数字（57.5KB）。本批产物按任务书只落 `data/perf_672d.json`；672e 应以新口径重跑覆盖或删除旧文件，避免双口径并存误导。
8. **性能预算未收紧**：120KB 保持原值（现状 24KB，余量约 5 倍）。是否收紧（如 60KB）属口径决策，归 672e，本批不擅自改。
