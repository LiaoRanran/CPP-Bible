## 1. CI 拓扑（来自 `.github/workflows/ci.yml`）

```
push / PR / workflow_dispatch
│
├─ replay            (ubuntu, py3.11)   重编译 71 张证据卡 + sha/结构断言 + sanitizer
├─ pytest            (ubuntu, py3.11)   tests/，-n 16 分两阶段（not slow / slow）
│
├─ quality           needs: replay       27 项内容门禁的 CI 版（见 §2）
├─ gate              needs: replay       gate_engine --check + S1-S6（golden/debt/poison）
├─ concurrency-safety (ubuntu)           静态解析 ci.yml，检「写者先、读者后」不变量
├─ discipline-670c   needs: replay       670c 主门禁 + fast 测试 + 前端 + 复现冒烟（全 continue-on-error）
│
├─ compile           needs: quality+pytest+replay+gate
│                     matrix GCC-15（容器，钉 digest）/ Clang-19
├─ publish-check     needs: 同上          rewrite_links 自检
│
├─ site / pdf / epub needs: compile+publish-check
└─ deploy            needs: site+pdf+epub
```

并发安全约定（621 B3，写者先/读者后）：`replay` 会重写 `Examples/atoms/*.asm`，
故 `quality` / `gate` / `discipline-670c` 全部 `needs: [replay]`；
**不要反向**（replay needs gate）——那会让 gate 的结论在 replay 改完工件后立刻失效。
`ci_concurrency_check_621.py` 会静态校验这条不变量，防止被拆 job 时改坏。

### 2.2 必须 CI（本地环境不具备或口径不同）

| 检查 | 为何本地不能等价 |
|---|---|
| **pytest**（tools/ 单测） | 需 `pytest-xdist` 16 并行 + `slow` 标记那批（WSL 编译 / 全量变异 / 全量重跑），本地默认不跑 |
| **Cross-check Matrix** | 只留痕不断言：同一夹具在 GCC / Clang 下的求值顺序对照。CI 用 runner 预装的 g++ / clang++；本机 clang 22.1.8 是 MSYS2 build，语义近似但不是同一二进制 |
| **compile 矩阵** | GCC 侧要求**精确 15.3.0**（容器 digest 钉死，非 15.x 浮版本），本机是 15.3.0 MinGW-w64 但非官方镜像；Clang-19 由 apt.llvm.org 装 |
| **ASan / UBSan / TSan** | 本地 MinGW 缺完整 sanitizer 运行时，replay 会降级为 `⏭ sanitizer 工具链不支持`；Linux runner 才有 |
| **D5 Compile / Runtime Gate** | 115 个 D5 基准要在 Linux 下真编译 + 运行（30s 超时） |
| **Compile + Link + Run + Sanitizer**（T1-1） | 本地做 toolchain-skip 降级 |
| **Exempt Audit** | 用与 CI 相同的 `g++ -std=c++23 -O0 -fsyntax-only` 重编 65 条豁免；本地 mingw1310/1530 混用会产生平台差异误报 |
| **site / pdf / epub / deploy** | 需 pandoc + texlive-xetex + CJK 字体 + mermaid-filter + Chromium（`--no-sandbox` 靠 `.puppeteer.json`）+ mkdocs + pagefind，全部装在 `requirements.lock.txt` / apt |
| **DCO** | `.github/workflows/dco.yml`，硬门禁；本地只在 commit 时用 `-s` |

## 5. 首跑要盯的 5 件事（按优先级）

1. **replay job 的注解**：本仓 job 日志下载需 admin（实测 API 403），失败只体现在
   `::error::` 注解与 step summary。若 replay 红，先读注解而不是找日志。
2. **pytest 是否因工具改动而红**：本批改了 3 个被单测覆盖的工具。若红，
   先判断是「单测断言了旧行为」还是「真回归」——**不要直接改测试断言**。
3. **replay 的 sanitizer 段**：CI 上应从本地 的 `⏭ 工具链不支持` 变为真实跑
   ASan/UBSan/TSan。若 CI 上仍出现 `⏭`，说明 runner 工具链识别有问题（应报而非静默）。
4. **quality 的 Worktree Cleanliness**：`replay` 会重写 `Examples/atoms/`、`atoms/`、
   `evidence/`、`tools/golden_state.json`。本批改过 atoms/ 与 evidence/，**必须与
   重钉 Merkle 根在同一个 commit**（已做），否则这一步会红。
5. **compile 的 GCC 版本断言**：若报「GCC 为 X，期望精确 15.3.0」，是容器 digest 被
   动过或 runner 换了镜像，不是内容问题。

## 7. 遗留与建议（不主动做，等确认）

1. `golden_state` 缺 per-rule 基线 → 建议加一节 per-rule 计数，让下一次 warn 增长可逐规则归因。
2. `discipline-670c` 是「红但可见」而非硬门禁；若要让 670c 主门禁参与阻断，需要单独裁决。
3. 本批**没有**新增任何 CI 配置。若将来想要一条「只跑 fast_gate + quality 快校验」的
   轻量 CI，建议做成独立 workflow 且 `continue-on-error: true`（先观察），
   不与现有 `ci.yml` 的发布链路耦合——需你确认后再做。
