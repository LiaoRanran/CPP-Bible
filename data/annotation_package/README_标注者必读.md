# 标注者必读（README）

感谢你参与这次**独立盲目标注**。你的任务是：对 145 条 C++ 代码样本，判断它们在给定检测
条件下是否会触发诊断报告，并标注缺陷类型、严重度等信息。你的标注将被用于验证一套研究
标签的可信度（construct validity），是论文投稿前的关键证据。

预计总耗时：**2.5–4 小时**（可分段完成；建议每次 ≤1 小时，避免疲劳漂移）。

---

## 1. 你会拿到什么

| 文件 | 说明 |
|---|---|
| `sample_list.csv` | 145 条样本清单（匿名 ID、文件、配套依赖文件） |
| `sources/S001.cpp … S145.cpp` | 源码（已去标签、注释已净化、标识符已中性化；2 个配套 `.h`） |
| `annotation_template.csv` | **你要填写的表格**（8 列） |
| `annotation_guidelines.md` | 判定规则手册（**开始前必须通读一遍**） |
| `calibration/` | 校准练习集（10 条 + 参考答案），**先做校准再开始正式标注** |

## 2. 你**不会**拿到什么（盲性保障）

- 原始文件名、原始标注（expected_verdict / defect_type / planted / severity 的原值）；
- 样本的来源批次与分组信息；
- 其他任何标注者的结果。

材料包副本已做去标识化处理：注释中的提示性内容被遮盖（以 `[redacted]` 标记）、
疑似泄露的标识符被重命名、强提示字符串被中性词替换。**发现的任何残留提示请记录在 notes 中。**

## 3. 流程（四步）

1. **通读** `annotation_guidelines.md`（约 15 分钟）。
2. **做校准**：对 `calibration/sources/C01–C10` 独立判定并填写，然后打开
   `calibration/answers.csv` 对答案；与答案分歧较大时，回读手册对应条目（必要时与协调者讨论**规则**）。
3. **正式标注**：逐条填写 `annotation_template.csv`。建议顺序与 `sample_list.csv` 一致；
   每条：先读代码 → 写下判定 → 再填表；**对不确定的条目不要猜，用低置信度 + notes**。
4. **提交**：把填好的 `annotation_template.csv` 交回协调者（不要改文件名）。

## 4. 注意（对标注质量影响最大的三点）

- **判据是"检测器会不会报告"，不是"代码是不是坏"。** 逻辑错误、协议缺陷往往在
  asan/ubsan/tsan/编译器告警/交叉编译/链接器下**没有任何报告** ⇒ 应判 `miss`
  （这正是研究的核心发现之一，不是你的错误）。
- **不要为了"一致"而修改你的诚实判断**；预注册的 κ 阈值不要求你与任何人保持一致。
- **notes 很重要**：写清你的依据与不确定性（如"疑似越界但需 -O2 才触发"）。

## 5. 隐私与用途

- 材料包不含任何个人信息；结果以汇总统计形式用于研究论文（致谢中可匿名列出或按你要求署名/化名）。
- 你随时可以中途退出并交回已完成部分；退出的样本将标记为未标注，不进入一致性统计。

## 6. 联系与答疑

判定规则问题（可讨论）：协调者（项目作者）。
样本原始标签：**不可询问**（盲性红线，任何情况下不给）。
