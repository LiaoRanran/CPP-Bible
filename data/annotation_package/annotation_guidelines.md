# 判定规则手册（Annotation Guidelines）

版本：689-v1（2026-10-07）。本手册是标注的唯一口径来源；与手册冲突的直觉一律以手册为准。
每节末尾的【校准题】指向 `calibration/answers.csv` 中对应条目。

---

## 0. 总原则

1. 你判定的是**"这套检测设施会不会报告"**，不是"代码有没有问题"。
2. 每一条先按 §2 的字段顺序独立判定；不确定时降低 confidence 并写 notes，**不要跳过字段**。
3. 判定只依据样本自身 + 本手册的资产判据；**不依据**文件名、注释残留（若有 `[redacted]` 一律忽略其位置含义）。

---

## 1. 检测设施（8 资产）与判据

假设每个样本都会经过下述 8 个"资产"，每个资产跑两档优化（-O0 与 -O2；任一档报告即算报告）：

| 资产 | 什么情况下算"报告"（catch 依据） |
|---|---|
| **asan** | 程序输出含 `AddressSanitizer`、`LeakSanitizer`、`detected memory leaks` 或 `double-free` 任一字符串（堆/栈越界、UAF、双重释放、泄漏等） |
| **ubsan** | 程序输出含 `runtime error`（有符号溢出、移位、非法对齐、空指针解引用等 UB 运行时报告） |
| **tsan** | 程序输出含 `WARNING: ThreadSanitizer`（数据竞争、部分锁序问题） |
| **compiler-warn** | 编译期产生告警（如 `-Wall` 类告警：unused、mismatched-new-delete、dangling 提示等） |
| **cross-compile** | 同一代码在 g++ 与 clang 两个编译器下**输出不一致**（如行为不同、警告集不同导致的差异判定） |
| **linker** | 链接期报错（重复符号、未定义符号——仅限**跨编译单元**问题） |
| **wunsequenced** | 本设施在本工具链下**不可用**，一律不计（未知，不参与判定） |
| **compile-time** | 无本地检测器，一律不计（未知，不参与判定） |

判定公式（判定 `expected_verdict`）：

```
若 8 资产中至少 1 个（不含 wunsequenced / compile-time）产生上述"报告"
   ⇒ expected_verdict = catch
否则
   ⇒ expected_verdict = miss
```

> 注：`miss` **不等于**"代码没问题"。大量逻辑/协议/状态机缺陷在 6 个可用资产下
> 都不会有任何报告——这正是被研究的"能力边界"。

## 2. 逐字段判定

### 2.1 `expected_verdict`（catch / miss）
按 §1 公式。要点：
- **纯挂起**（死循环、自旋锁死锁、条件变量永久等待，程序超时被杀）：超时后**无报告** ⇒ `miss`；
  但若挂起**之前**已有报告输出（例如 TSan 已报 race 后又死锁）⇒ `catch`。
- **崩溃/abort/段错误**：通常有 stderr 报告 ⇒ 多为 `catch`；但"干净退出码为 0 的静默错误"
  （如逻辑错误、结果算错）⇒ `miss`。
- **只在特定优化档才触发**的缺陷（如仅 -O2 暴露）⇒ 仍 `catch`（任一档即可）。

### 2.2 `defect_type_family`（8 家族，必须选一）
| 家族 | 典型成员 | 判据线索 |
|---|---|---|
| `memory` | 释放后使用、双重释放、泄漏、未初始化读、智能指针/RAII 误用、移动语义错误 | 与对象**生命周期/所有权**相关 |
| `bounds` | 数组/容器越界、空指针解引用 | 访问**越出对象边界**或**非法地址** |
| `integer` | 有符号溢出、除零、移位 UB、位运算错误 | 整数运算本身越出定义域 |
| `alias_type` | 严格别名违规、type punning、对齐、端序 | 类型系统/内存表示层面的错误 |
| `concurrency` | 数据竞争、原子性/内存序错误、死锁、条件变量误用 | 多线程**交互**正确性 |
| `stl` | 迭代器失效、容器/字符串越界或误用、算法误用 | 标准库**容器/算法契约**违反 |
| `language_oop` | 虚函数/构造析构语义、lambda 捕获、逻辑/协议错误、跨 TU 问题、其他 UB | 语言语义、控制流逻辑、杂项 |
| `embedded_link` | 中断安全、寄存器/volatile 误用、链接/ODR | 嵌入式平台语义、**链接/编译单元**问题 |

选择规则：**取触发机制所属的家族**。一条样本可能触及多类，选"根因"家族；存疑时选更具体的家族，并写下候选。

### 2.3 `defect_type_free_text`
写具体机制（中英文均可），如 `stack-buffer-overflow (write)`、`missing unlock on exception path`、
`memory_order_relaxed missing acquire`。**不必与家族名重复**。

### 2.4 `planted`（true / false / unsure）
- `true`：能看出是**为演示缺陷而写的教学/注入式代码**（结构极度最小、为触发单点缺陷而构造）；
- `false`：像真实的项目代码片段/真实来源体裁（含无关的完整性、注释风格自然）或**无缺陷的正常代码**；
- `unsure`：无法判断。注意：**这不是"有没有缺陷"的判断**，是"是否人工构造"的判断。

### 2.5 `severity`（low / medium / high）
按**若在真实系统中触发**的后果量级判：
- `high`：内存破坏、任意代码执行、数据不可恢复损坏、安全边界突破；
- `medium`：崩溃/拒绝服务、数据竞争导致的不确定行为、资源泄漏累积；
- `low`：可观测但影响有限（小泄漏、仅告警级问题、端序/表示类的局部问题）。
**severity 与是否可检测无关**（一个 high 缺陷完全可能是 `miss`）。

### 2.6 `confidence`（1–5）
- 5：几乎确定；4：较确定；3：中等；2：较不确定；1：纯猜测（请在 notes 写清卡点）。

### 2.7 `notes`
写下：判定依据、不确定点、残余提示（如你发现了被遮盖的注释位置）、该样本是否依赖
特定编译条件/平台。

## 3. 边界案例（重点）

| 情形 | 判法 |
|---|---|
| 数组越界只读 1 字节（-O2 被优化掉） | asan 在 -O0 报 ⇒ `catch`（任一档即可） |
| 死锁：两个线程互等（永久） | 超时无报告 ⇒ `miss`（除非 TSan 已先报锁序） |
| 数据竞争但只在极端时序触发 | TSan 报 race ⇒ `catch`（tsan 判据） |
| 逻辑错误（协议状态机绕过） | 无资产报告 ⇒ `miss`；家族 `language_oop` |
| 未初始化读 | 若 asan 未报、编译器告警未出 ⇒ `miss`（该项目语料中该族多为此） |
| new[]/delete 不配对 | asan 报 alloc-dealloc-mismatch ⇒ `catch` |
| ODR 违规导致链接错误 | linker ⇒ `catch`；家族 `embedded_link` |
| 双重释放（第二次释放同一指针） | asan 报 double-free ⇒ `catch` |
| 对照样本（干净代码）被工具误报 | 只要资产有报告就判 `catch`（预期之外，notes 记"疑似误报"） |
| 不终止的无限循环 + 无输出 | `miss`（超时即无报告） |
| 仅"输出不同"（两编译器行为差异） | cross-compile 有差异判据 ⇒ `catch`（如输出差异构成该资产判据） |

## 5. 常见疑问（FAQ）

**Q：我可以编译运行样本吗？** 可以（依赖文件已随包提供）。但注意：你的判定应基于 §1 判据，
不是"我跑出来怎样"——设施配置（-O0/-O2 双档、8 资产、特定判据字符串）与你的本地环境可能不同。

**Q：注释被 `[redacted]` 了，影响我判断吗？** 不影响核心判定（代码结构自足）；若某处被遮盖
导致你无法判断，请写 notes 并将 confidence 降 1。

**Q：`miss` 太多是不是我判错了？** 不是。该语料约四成样本在 8 资产下无报告（38.4% 是
已发表口径的一部分）；你的任务就是如实判定。

**Q：时间不够怎么办？** 宁可少标、每条标得认真，也不要在疲劳状态下赶完——请在
提交时注明已完成的范围。
