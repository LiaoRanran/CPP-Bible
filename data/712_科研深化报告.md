## 2. 关键词扫描：结果与**方法局限**（这一节比结果重要）

扫描模式（中文 + 英文混排）：`首创 / 首次 / 第一个 / 证明了 / 已经证明 / 突破 / 彻底解决 /
完全解决 / we prove / first to / for the first time / state-of-the-art / 世界领先 / 填补空白 /
解决了…难题`，并用否定/登记语境（`不是 / 并非 / 不主张 / no claim / 未 / 不得 / claim no /
rather than`）做二次过滤。

**命中 310 处**，其中 65 处在否定或登记语境（即"主动声明我不是首创"——这些是**好信号**）。

对剩下 245 处抽读后的判断：

> **几乎全部是"过程性首次"，不是"学术优先权主张"。**

典型例子（均为**本批内的工程事件**，不是对文献的主张）：

| 文件 | 句子 | 性质 |
|---|---|---|
| `621_acceptance_report.md:92` | "621 第二轮**首次用上非 v7 的新 mutation**" | 本批第一次试用某手段 |
| `622_acceptance_report.md:233` | "622 **首次真正 push 并实跑**" | 流程事件 |
| `638_lifecycle_fsm.md:52` | "**本批首次上线**：`--check` 不创建 ledger" | 功能上线 |
| `646_performance_report.md:9` | "orchestrate（**首次** → 重复调用）" | 性能测量里的"第一次调用" |
| `647_calibration_enforce.md:7` | "**647 首次做到**" | 批次内首次 |

**方法教训（写给下一个做诚实性复查的人）**：

1. **关键词扫描不能判定"是否过度主张"**。"首次"这个词在本仓库的绝大多数用法是
   *"这个批次里第一次做某事"*，与 *"文献中第一次"* 是**完全不同的语义**，
   而两者在字面上不可区分。任何以此为依据的"发现 N 处过度主张"都是**假阳性**。
2. **真正有效的判据是"这句话主张的对象是谁"**：主张对象是"文献/领域"⇒ 需要优先权证据；
   主张对象是"本批次/本仓库"⇒ 只需本仓库内的记录。
3. 因此本报告**不给出"过度主张数量"**。给出这个数字等于用钝器量出精确值——那正是
   评审要防的"看起来更庞大"。

**唯一值得保留的可用结论**：全库 65 处主动否定语境（"不是第一""claim no priority"）
说明**默认写作姿态已经是防守型的**；过强措辞是例外而非常态。

## 4. 人可复核的薄弱点（移交，未改）

### W1 · 跨文档口径并列时会被读成矛盾

- 匿名包 `README.md` 写：**"Only two of seven axioms do work."**
- 论文 2 摘要写：**"only three of the eight are genuinely independent."**

两句话各自在其口径下都对（7 公理**核** vs 8 公理**系统**；"do work" 与 "genuinely independent"
也不是同一判据），但一个审稿人同时读到这两句，第一反应是"作者自己都说不清"。
**建议**：在论文 2 摘要或 README 之一补一个括号限定（具体替换文本见
`data/712_论文贡献收窄方案.md` §3 的剩余风险 1）。**本批不改**（红线 1）。

### W2 · A8 的"完备性判据"没有自动验证

与 714 批登记一致：A8 标签轴闭包是"有限域穷举（15 个标签映射）+ 人写规范"，
**没有**一条自动化检查会在它被破坏时报警。
**建议**：像 707 批那样把它落成 `tools/test_axiom_independence.py` 的一个断言
（A8 目前在该测试里是 `A8_missing_confirmed` 的占位）。**本批不启动新理论批次**，
只登记为下一批的候选。

### W3 · 关键词扫描的假阳性（§2）应写进复查协议

下一次有人做诚实性复查时，若不写明"关键词扫描不能判定过度主张"，
大概率会产出"发现 245 处过度主张"这种**看起来很有价值、实际是噪声**的结论。
本报告即为此留下书面依据。
