# 632 G1 · `vsa_secret.key` 安全审计

> 审计约束（§零）：**不删不改**密钥文件。本报告只观测**元数据**（存在性 / 字节数 /
> 是否被 git 忽略 / 是否已入库），**从未读取、打印、修改或删除密钥内容**。
> 下文所有涉及密钥内容处一律以 `<redacted>` 表示。

## 一、审计范围

- 目标：`VSA`（可验证凭证）体系的 HMAC-SHA256 签名密钥。
- 代码引用位置：`tools/vsa_attestation_628.py` 与 `tools/vsa_verify_628.py`
  均定义 `SECRET = os.path.join(ROOT, "data", "vsa_secret.key")`。
- 用途：对 VSA 凭证的全部字段做 HMAC-SHA256，产出 `attestation` 字段；
  验证时重算并比对（密钥缺失则 `vsa_attestation_628` 直接返回
  `secret key not found`，**不新建密钥**——避免把"密钥丢失"误报成"签名被篡改"）。

## 三、更正 632 baseline 的误报

`data/632_baseline.md` 任务0.2 记录 "`data/vsa/vsa_secret.key` 存在：`False`"。
实测证明**该路径不存在，但真正的密钥在 `data/vsa_secret.key`**——baseline 的探测脚本
（`tools/baseline_632.py` 的 `vsa_secret_key_exists` 默认查 `data/vsa/` 目录）**指错了路径**，
因此对真实密钥"视而不见"，给出错误的不存在结论。

⇒ 这是一个**监控探针偏差**而非安全事件，但必须登记：若有人依赖 baseline 的
"密钥不存在"做信任判断，会**误以为密钥未落盘**。建议把 baseline 的探测路径改正为
`data/vsa_secret.key`（或同时对两处都查）。

## 四、安全评估

### 正面（当前做得对）

1. **密钥不入库**：gitignored + 未 tracked ⇒ 不会进入版本历史、不会随 clone/PR 泄露。
2. **密钥缺失即失效而非伪造**：`vsa_attestation_628` 在密钥缺失时返回明确错误，
   不偷偷新建密钥——杜绝了"历史凭证假失败 / 假成功"的混淆。
3. **与零信任外部锚定一致**：VSA 链的信任根（HMAC 密钥）不在仓库内，
   审计方无法在仓库内伪造 VSA（B1 透明日志锚定 + B3 第三方独立验证的信任边界成立）。

### 风险（需改进）

1. **明文密钥落本地工作树**：`data/vsa_secret.key` 是明文 32 字节文件，
   若工作树被备份/同步/打包，密钥会随副本扩散。建议：
   - 文件权限收敛为 `600`（仅属主可读写）；
   - 理想做法：密钥移出仓库树，改由 **CI Secret / HSM / 系统密钥链** 注入，
     运行时只读入内存，用完即弃（参考 `e2e_attestation_629` 的"临时目录、用完即删"范式）。
2. **`.gitignore` 规则过窄**：仅精确匹配 `data/vsa_secret.key`。
   若有人重命名为 `vsa_secret.key.bak` / `secret.key` / `data/vsa/key`，即可能绕过忽略被提交。
   建议改为更宽的 `*.key` + `data/**/*secret*`，并加 **pre-commit 密钥扫描**（如 gitleaks）。
3. **信任根集中**：持有此密钥者即可签发任意 VSA ⇒ 单点信任。
   按 B1/B3 零信任，VSA 的**验证**应由独立第三方用**单独保管**的密钥完成，
   密钥不得与"审计方/出证方"同机同人。当前密钥在生产工作树内，存在共置风险。
4. **无轮换记录**：未发现密钥 version / 轮换时间戳。一旦泄露，无法判定哪些 VSA 是在
   旧密钥下签发的。建议给 VSA 增加 `key_id` 字段并在锚定里登记。

## 五、第三方零信任视角（关联 B1/B3）

- B1 已把整份透明日志 SHA256 锚定到 `data/vsa/anchor_<YYYYMMDD>.json`（默认 `LOCAL_ONLY`）；
- B3 已给出外人零信任复算步骤。
- 但 VSA 的 HMAC **可验证性**依赖此密钥：外部审计方只有在**独立持有密钥**时才能复算
  `attestation`。因此"外部锚定"目前锚的是**日志哈希**，而**不是 VSA 签名本身的可重现性**。
  ⇒ 诚实结论：透明日志的完整性可被零信任验证，但 VSA 的密码学可信度仍系于这把**未入库
  但本地共置**的密钥——这是当前信任模型仍待补的一环（建议后续将密钥 custody 外移到 HSM/CI）。
