## 0 · 三句话结论

1. **WGG 与 QueYi 共享同一个核心诊断**：*不能用下游任务得分来验证自演化评估器*。WGG 独立得出该结论（"坍缩的度量训练技能效果一样好"），是对 QueYi "报率必须带口径 + 必须外部盲测" 的**外部佐证**，应在 §2(7) 点明。
2. **两者的演化对象不同**：WGG 演化**打分函数**（typed drawback detectors 的组合表达式）在**固定任务集**上，由**锚点一致性**驱动；QueYi 演化**证据获取能力 C**（探测器×编译器×flag×平台），由**注册失败**驱动。这是真正的一句话边界。
3. **SEA 在统计层成熟度上领先于 QueYi**：SEA 的 anytime-valid gate 是"compose published guarantees"的工程化门控且已跑实验；QueYi 的 e-process 是**未冻结的 prototype**。此处**必须承认对方更强**，并把"冻结 alternative grid / mixing prior / μ₀"列为未来工作。

## 1 · WGG（arXiv:2607.12790）解析

| 维度 | 内容（来自摘要页） |
|---|---|
| 演化对象 | **带类型的小型"缺陷检测器"的组合表达式**（typed drawback detectors），有完整的创建/修订/淘汰生命周期；产出是**可检视表达式**，不是 LLM judge 黑箱 |
| 任务集 | **保持固定**（被演化的只是"给单个输出打分"的函数），显式避免"改考题"式作弊 |
| 驱动信号 | **与 10 条条目的 anchored reference set 的一致性**（作为适应度）+ **无标注输出的共识** 做正则（抑制只迎合小锚点集的过拟合） |
| 有效性证据 | 在**度量选择过程从未读取过的 locked set** 上，与隐藏 ground truth 一致性 **+0.21**，配对检验 **p = 0.014**，**优于其所包含的裸 LLM judge** |
| 反 Goodhart | 消融显示：**去掉 anchor guards ⇒ 度量坍缩为"永远通过"的空洞检测器**；移除检测器生命周期则不会 |
| 关键警告 | **下游任务得分不能验证自演化评估器**——坍缩后的度量"训练技能的效果一样好"；任务得分只回答"充分性" |
| 外部审计 | 当演化出的技能"钻了报告 rubric 的空子"时，**一个独立 judge 捕获该行为**并通过增加检测器修复 |
| 结果域 | MBPP+ / Spider 2.0-Snow / 报告生成，保留 ground truth 或人工 rubric 提升的 **88–110%** |

## 2 · WGG ↔ QueYi 对比

### 2.1 异同表

| 维度 | WGG | **QueYi** | 关系 |
|---|---|---|---|
| 演化对象 | 打分**度量**（检测器组合表达式） | 验证器的**证据获取能力 C**（探测器/编译器/flag/平台） | **不同**（一句话边界） |
| 任务集 | **固定** | 固定（同一 $X$ 重测），但**外部样本集在扩** | 同族纪律 |
| 驱动信号 | **锚点一致性**（agreement） | **注册失败**（miss/unknown → 新规则），且 minimality 要求可追溯到失败 | **不同**（本方案的核心对照问题） |
| 锚 | 10 条条目 anchored reference set | E8 外部锚（官方 C++ Core Guidelines，44.0%/50；verbatim 28.6%）+ meta-state reconciler 的 ground-truth baseline | **同构但对象不同**（它锚"分数一致性"，QueYi 锚"真值/元状态"） |
| 留出验证 | **locked set**（选择过程从未读取） | **blind holdout D2**（pre-reveal 不可见；强于 locked，因为含不可逆盲） | **QueYi 的盲性更硬** |
| 防过拟合 | anchor guards + 无标注共识正则 | 不可逆盲 + 预算匹配随机对照 + 口径三步骤 | 手段不同，目标同 |
| 反 Goodhart 证据 | 去 anchor guards ⇒ 坍缩为空洞检测器 | meta-Goodhart 事故（81.2% 从未落盘；改灯不重跑） | **独立佐证**（见 §2.2） |
| 可审计对象 | 度量表达式本身 | 判决→证据→复算链 + Merkle 根 + 452 事件账本 | **不同**（它审计"式"，QueYi 审计"链"） |
| 域 | LLM agent 技能 / 报告 rubric | 可执行 **C++ 断言**（运行时证据） | 不同 |
| 统计层 | locked set 配对检验（p=0.014） | CP 95% + 精确 McNemar；A5 已跑（**主端点不显著**，受 n=20/16 与退化资产限制） | WGG 有阳性结果，QueYi 的 A5 为中性 |

### 2.2 最强共鸣点（**应写进 §2(7)**）

WGG 的核心警告——"**下游任务得分不能验证自演化评估器**；坍缩后的度量训练技能的效果一样好，任务得分只回答充分性"——与 QueYi 的两条纪律**独立同源**：

1. QueYi：**主指标必须是外部样本上的判决准确率，而不是下游任务的任何分数**（§6 主实验：静态臂/随机臂/失败驱动臂都在同一批外部样本上重算）；
2. QueYi：**不能把"verifier 自己报的分"当证据**（meta-Goodhart，§3(b)）；口径必须随数字走。

⇒ 这是一个**外部作者独立得出的同一结论**，比自说自话强得多。建议在 §2(7) 用一句写实：*"WGG independently reports the same hazard we document: a collapsed metric can look adequate when judged by downstream task score, so evaluator validity must be checked on held-out data the selection process never read."*

**第二个共鸣**：WGG 的锚点守卫消融（去掉守卫 ⇒ 度量坍缩）与 QueYi 的 meta-Goodhart 事故（改口径不重跑 ⇒ 灯仍绿）**是同一失效模式**。可并列引用。

### 2.3 我们更弱 / 更强的点（诚实）

| 我们更弱 | 说明 |
|---|---|
| **演化对象的可检视性** | WGG 产出的是一个**可检视表达式**，审阅者能直接读；QueYi 的"能力 C"是一组规则+仪器配置，**其语义更分散**，需靠账本+Merkl 才可审 |
| **对照实验完成度** | WGG 有 locked set 实证（p=0.014）；QueYi 的 **A5 已跑但主端点不显著**（673r），A0–A4 未跑 |
| **工件可得性** | WGG 摘要页给出了 code 链接；QueYi 需匿名补充材料 |

| 我们更强 | 说明 |
|---|---|
| **盲性的硬度** | QueYi 是**不可逆盲**（revealed 后永久不可回盲，`iron_rule`），WGG 是 locked set（可被反复读取？摘要未明） |
| **审计粒度** | 逐样本 `id→verdict` 表 + 证据 sha256 + append-only 账本，可被第三方**逐条复算**；WGG 审计"式" |
| **执行语义** | QueYi 判的是**运行时证据**（编译/消毒器），不是文本蕴含或打分一致性 |

## 4 · SEA ↔ QueYi 对比

| 维度 | SEA | **QueYi** | 关系 |
|---|---|---|---|
| 门控对象 | 对 **adapter/harness 的修改** 做统计门控 | 对**判决/规则/口径**做 L0/L1 门禁 + 元状态对账 | **同族，对象不同** |
| 放行凭据 | 签发**可审计证书**（对照固定误差预算） | 要求**失败→规则→重测**三元组；账本 append-only | 同族（都要"有据才放行"） |
| 序贯统计 | **anytime-valid gate**（工程化、已跑） | **e-process prototype**（alternative grid/mixing prior/μ₀ **未冻结**，探索性） | **SEA 更强**（必须承认） |
| 版本化 | 版本化 harness（可追踪新版本） | `rules_manifest_sha256`（**manifest 存在，但 452 事件尚未携带该字段**） | **SEA 的钉定更完整** |
| 对照设计 | **deliberate no-op-composite control** | **budget-matched random A5**（673r 已跑真实逐资产对照；主端点不显著） | **同族精神**；两者都跑了对照，SEA 的为阳性、QueYi 的为中性 |
| 被改动的"能力" | 只在**冻结基座已能产生的行为中选择**（select），不创造新能力 | 演化的是**证据获取能力本身**（新增探测器/平台） | **不同** |
| 域 / 规模 | SWE-bench 代码修复 agent，4 基座 | C++ 断言验证，$n{=}41/64$ | 不同 |

### 4.1 必须承认的三点

1. **统计构造**：SEA 的门控是"组合已发表保证"的工程化实现且已在真实任务上运行；QueYi 的 e-process 是 **prototype**，其 μ₀ 从未预注册、alternative grid 与 mixing prior 未冻结 ⇒ **QueYi 的 e-values 不可复算，已移出 claim table**（`app:pinning`）。
2. **对照实验完成度**：SEA 跑了 no-op 对照；QueYi 的 B3 在扩样后**退回仪器级代理**。
3. **钉定完整度**：SEA 的 harness 天然版本化；QueYi 的 ledger 事件**尚未带 ruleset hash**。

⇒ rebuttal 中**不要**就"anytime-valid"与 SEA 争高下；正确姿态是：*"our e-process layer is a preliminary with unfrozen parameters; SEA's case shows what a production-grade anytime-valid gate looks like, and we cite it as the standard we have not yet reached."*

## 5 · 对比实验设计

### 5.1 情形 A：拿到代码/数据（需要先读全文 + 取工件）

**A-1（对 WGG）· 驱动信号的对照**
把 WGG 的"**锚点一致性 + 无标注共识**"移植为 QueYi 的一个**对照臂**：

- 输入统一：同一批 QueYi 样本（holdout 41 / corpus 64），固定任务集（它的纪律）；
- 臂 P（WGG 式）：用 **10 条锚定样本**的一致性作适应度选规则；
- 臂 F（QueYi 式）：用 **注册失败（miss/unknown）** 选规则；
- 主指标：在**同一 locked/blind 子集**上，达到同等 recall 所需的**规则数**与**样本数**（收敛效率），以及最终 recall 的配对差（精确 McNemar）；
- 预注册：H 假设"失败驱动以更少规则达到同等 recall"；**若 CI 跨 0 则报告为不成立**。

> 可行性：**高**——两者都产出"规则/检测器集合"，适应度函数可统一为"外部样本上的判决准确率"。
> 风险：语义需重定义（WGG 的度量打"LLM 输出质量分"，QueYi 判"断言真伪"），须在方法里写清这是**适应度重定义后的移植**，不是原系统复现。

**A-2（对 SEA）· 门控的对照**
把 SEA 的 anytime-valid gate 套在 **QueYi 的扩样流程**上：

- 流程：每批新增样本后跑门控，比较"**固定样本量检验**（CP/McNemar）"与"**anytime-valid 门控**"在**同等 error budget** 下的**停止时间与所需样本数**；
- 指标：达到同一结论所需的累计样本数、以及"违规停止"次数（应为 0）；
- 预期：anytime-valid 的代价是阈值更高（QueYi 已实测 ≈20 vs ≈3.14 单次检验），收益是**可随时停、可跨批合并**。
