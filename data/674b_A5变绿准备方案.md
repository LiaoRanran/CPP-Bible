# 674b A5 变绿准备方案（673r 执行前的设计）

- 日期：2026-10-03
- 目的：确认 673p 基础设施状态，给出 673r「让 detect 支持子集选择」的修改方案与影响分析
- 边界：本批**只做设计与准备**，未改任何 673p/673r 代码

## 1. 基础设施状态确认

### 1.1 资产池 `tools/verifier_pool_673p.py`（16 KB）

- 预注册记录：12 项资产 = **8 项已实测**（`measured_subset`）+ **4 项声明未接线**
  （`declared_unimplemented`），另 **2 项被排除**。
- 排除理由（预注册原文）：`measure` / `perf-counter` 是**性能测量仪器**，不产出缺陷判决；
  把它们当验证资产正是 670a Random† 的「仪器级退化」。
- 预注册纪律：声明未接线资产（`implemented=false`）**无实测判决归属 ⇒ 不进选择候选，
  也不进 replay**。

**对 673r 的约束**：资产池 12 项，但**只有 8 项可用于选择**。若想用满 12 项，
必须先接线那 4 项 —— 那是额外实现工作，不在 673r 的"改 detect"范围内。

### 1.2 选择层 `tools/selection_strategies_673p.py`（15 KB）

- 三策略：`FD`（failure-driven）/ `Random` / `Static`，入口 `select`。
- `fail_loud` 记录 4 条硬失败条件。673r 必须让这 4 条在真实调用路径上真的触发，
  否则等于没有护栏。

### 1.3 运行器 `tools/run_a5_experiment_673p.py`（27 KB）

- 依赖 `selection_strategies_673p as ss`、`verifier_pool_673p as vp`。
- 输出 schema `{id, detector, verdict, …}`，注释写明「该样本**被哪个资产判成什么**」
  ⇒ 需要**逐资产归属**，不是单一 verdict。
- 第 103 行实现说明：「**单归属重放**：用已落盘的 detector 归属复算『若只跑 S，这条样本
  会怎样』」。

**这是 673r 的核心着力点**：运行器已支持"给定子集 S ⇒ 重放该子集下的判定"，
所以 673r 要做的**不是**改运行器，而是**产出"每个资产各自单独判定"的落盘归属**。
现在 `PLAN` 是"每样本一个 detector"的一对一映射 ⇒ "某子集会怎样"无法重放。

### 1.4 预注册 `data/673p_a5_preregistration.json`（12 KB）

- `status = locked_before_experiment`；`immutability` 明确**事后不得回改**假设、主要指标、
  预算定义、纳入/排除标准与停止规则；结果与假设不符按 mismatch 如实报告，**不调参重跑**。
- H0：同等预算（同资产数）下，FD 与 Random 的 holdout 可测检出率**无差异**。
- H1：同等预算下，FD **高于** Random（单侧）。
- H_secondary_corpus（换 corpus 指标）；H_exploratory（**不参与通过/不通过判定**）。
- `budget_alignment`：Random 与 Static 必须在**与 FD 相同预算**下运行。
- 样本规模 holdout 41 / corpus 64，与 672h 一致，**不扩样**。

## 2. `tools/holdout_reveal_661.py::detect` 的现状

签名 `def detect(kind: str, files: list) -> tuple` → `(verdict ∈ catch/miss/unknown, note)`。

工作方式（读码确认）：
1. `srcs = [os.path.join(ATOMS, f) for f in files]` —— `files` 是**原子源文件名**；
2. 存在性体检，缺任一 ⇒ `unknown`；
3. 拷进临时目录（不污染 `atoms/`）；
4. `kind ∈ SAN`（tsan/asan/ubsan）⇒ 走 WSL，`-O0` 与 `-O2` **两档都跑**
   （666 A5 的设计：旧口径只跑 `-O1`，导致 5 个 miss 里 3 个是假 miss）；
   其它 kind 走本机 g++13.1 / clang22.1；
5. 命中判定按 kind 分别匹配；TSan 遇 `FATAL: ThreadSanitizer` 判该档**不可用**而非 catch；
6. 返回聚合 verdict + note。

调用点：`main()` 中
`for s in h["seeds"]: kind, files = PLAN.get(s["id"], ("unknown", [])); verdict, note = detect(kind, files)`。

**核心观察**：`PLAN` 是**样本 → 单个 detector** 的一对一映射
⇒ 「某资产子集 S 下这条样本会怎样」**在当前数据结构下无法表达**。
## 3. 673r 的修改方案

### 3.1 建议：**不要改 `detect` 本身**，新增一个薄封装

三条理由都很硬：

1. **已落盘的 reveal 记录依赖它**。`main()` 写出 `data/holdout/reveal_*.json`，
   那是一次性不可逆 reveal（`blind_before=true`、`irreversible=true`）。
   改 `detect` 的返回值/语义会让"旧记录是哪版 detect 生成的"不可判。
2. **盲区铁律**。`main()` 有守卫 `if rerun and not a.correct_harness: [REFUSED]`。
   673r 若改 `main()` 去重跑等于绕开它。**必须走独立入口。**
3. **两档 O0/O2 + TSan 不可用判定**是 666 A5 调出来的（修过 3 个假 miss）。
   复制一份 ⇒ 两处漂移；直接改 ⇒ 冒改已冻结测量器的风险。

### 3.2 建议形态（新增，不动 detect / main）

```
detect_for_assets(candidates, files, selected, *, attribute=True) -> dict
    # candidates: 该样本所有可用资产 id（来自 verifier_pool_673p.ASSET_POOL）
    # selected:   本次策略选中的资产 id（预算 k）
    # 返回 {"verdict": catch/miss/unknown,
    #       "by_asset": {asset_id: verdict},
    #       "caught_by": asset_id | None,
    #       "note": ...}
    # 实现: 对 selected 里每个资产各调一次既有 detect(kind_a, files)，再聚合
```

要点：
- **复用既有 `detect`**，不复制逻辑 ⇒ 666 A5 的两档/TSan 判定继续生效；
- `selected` 里有资产不在 `candidates` ⇒ **报 fail_loud**，不静默跳过；
- 聚合规则与 661 一致：任一资产 catch ⇒ catch；全 miss ⇒ miss；全 unknown ⇒ unknown。
  **绝不许把 unknown 当 miss** —— 那正是 666 修过的假 miss 教训。

### 3.3 落到逐资产归属（运行器已就绪的那一半）

新增落盘文件，如 `data/holdout/asset_attribution_673p-A5.json`：

```
{ "prereg_id": "673p-A5-random-budget",
  "asset_pool": [...12 项，含 implemented 标记...],
  "samples": [ {id, category, atom_ref, per_asset: {asset_id: verdict}, note} ],
  "generator": "holdout_reveal_661.detect_for_assets", "generated_at": ... }
```

有了它，`run_a5_experiment_673p` 的"单归属重放"才能真正回答
「若只跑 S（|S| = k），这条样本会怎样」，A5 才有同预算可比的 FD/Random/Static 三臂。

### 3.4 影响面

| 对象 | 影响 | 处置 |
|---|---|---|
| `holdout_reveal_661.py::main` | **不改** | 否则触发 `[REFUSED]` 铁律 |
| `holdout_reveal_661.py::detect` | **不改** | 已有 reveal 记录的可复现性依赖它 |
| `data/holdout/reveal_*.json` | **不改** | 不可逆记录 |
| `run_a5_experiment_673p.py` | 读新归属文件（新增路径），不改既有重放逻辑 | 673r 内 |
| `verifier_pool_673p.py` / `selection_strategies_673p.py` | 不改 | 673r 只消费 `ASSET_POOL` / `select` |
| 针对 `detect` 的既有测试 | 签名不变即无需改 | 红线 3：不得改断言 |

## 4. 673r 执行步骤建议

1. **先做归属，不做实验**：实现 `detect_for_assets` + 落 `asset_attribution_*.json`，
   **先不跑三臂**。这一步单独可验证（归属条数 = 样本数 × 可用资产数）。
2. **自检归属形状**：holdout 41 样本 × 8 可用资产 = 328 条判定；
   任何 unknown 都必须能在 note 里说出原因（不可用 vs 缺原子）。
3. **再接运行器**：让 `run_a5_experiment_673p` 读新归属做单归属重放。
4. **预算对齐检查**：三臂 |S| 必须相等（预注册硬规则），且 `fail_loud` 的 4 条
   要在真实路径上被触发过一次，否则护栏没被验证过。
5. **按预注册口径报结果**：H1 单侧检验；不符就报 mismatch，**不调参重跑**
   （`immutability` 是硬约束）。
6. **A5 的已知限制一起报**（预注册 `known_limitations` 的阻塞条件 3 限制 H0/H1 的
   可判定性）—— 不要只报"变绿了"。

## 5. 需要你确认的三点

1. 归属落盘文件的**路径与 schema** 是否照 3.2/3.3 定？还是有既定命名规范？
2. 4 项声明未接线资产：本轮**排除**（按预注册纪律），还是先接线以扩大可用池？
   排除则预算 k 上限是 8。
3. 归属生成是否算「测量修正」？若算，必须走 `--correct-harness` 式显式授权留痕
   （预注册的不可变条款禁止回改**假设与预算**，但允许登记 harness 修正 ——
   673t 的 pck 续签是同类先例）。
