## 1. 新增近邻（评审点名四篇）

### 1.1 DeepFact（ACL 2026 投稿轨；本批核验到 arXiv 版本）
- **元数据（已核验）**：arXiv:2603.05912 [cs.AI]，v1 2026-03-06、v2 2026-04-03；
  作者 Yukun Huang, Leonardo F. R. Ribeiro, Momchil Hardalov, Bhuwan Dhingra, Markus Dreyer, Venkatesh Saligrama。
  **会议状态未核验**（检索页出现 "ACL 2026" 关联但未见论文页确认；bib 按 arXiv 预印本记，注"ACL 2026 状态待核验"）。
- **机制**：Evolving Benchmarking via **Audit-then-Score (AtS)**——verifier 与基准标签不一致时必须**提交证据**；
  auditor 裁决；被接受的修订**先更新基准再评分**；基准随对抗/对话持续演化。
- **结果**：4 轮审计把专家 micro-gold 准确率 60.8% → 90.9%；产出 DeepFact-Bench（版本化、理由可审计）
  与 DeepFact-Eval（文档级验证 agent）。
- **它没做什么（具体）**：审计对象是**基准标签**（事实性断言的真值），不建模**环境 profile**、
  不报告**能力边界图**、没有 unknown/miss 四态分母纪律、不涉及 C++/执行级证据、资产池不演化。
- **与本文关系**：同为"审计使评估更可信"的证据，但 Queyi 的审计对象是**评估设备**
  （资产池/口径/环境/标签/分母五方面），且给出 8 类失败模式的可执行协议与阴性发现。

### 1.2 Who Grades the Grader?（2026-07，已核验）
- **元数据（已核验）**：arXiv:2607.12790 [cs.AI]，v1 2026-07-14、v2 2026-07-30；
  Xing Zhang, Guanghui Wang, Yanwei Cui, Ziyuan Li, Wei Qiu, Bing Zhu, Peiyang He。
- **机制**：把**评估指标本身**作为演化对象——搜索小型"类型化缺陷检测器"组合；
  选择信号 = 与 10 条锚定参考集的一致性 + 无标注输出的共识正则化；产出可检查表达式。
- **关键结论**：**锁定集审计**上 +0.21（p=0.014）；消融显示**移除锚定守卫 ⇒ 指标坍缩为
  always-pass 空洞检测器**；由此提出"任务分数只能验证**充分性**，不能验证**有效性**"。
- **它没做什么**：对象是 LLM agent 的**评分函数**（非执行级验证设备）；无环境 profile 建模；
  无四态/分母纪律；无真实漏洞语料；不研究"资产池构成 vs 算法改进"的定量归因。
- **与本文关系**：**最强近邻**（同为"演化评估器"）。差异：它演化的是"给单个输出打分的函数"，
  本文演化/审计的是"证据获取设备 + 其测量口径"，并给出构成效应的定量审计（Finding 1）与
  能力边界图（Finding 2）。其"always-pass 坍缩"与本项目"退化资产"是不同机制的同一类风险。

### 1.3 Self-Evolving Agents with Anytime-Valid Certificates（SEA，2026-07，已核验）
- **元数据（已核验）**：arXiv:2607.00871 [cs.AI]，2026-07-01；Biswa Sengupta。
- **机制**：把自我修改**限制在小 steering adapter + 版本化 harness**（围绕冻结基座模型）；
  用 anytime-valid 统计给出**可审计证书**与固定错误预算。
- **它没做什么**：是 agent 架构（统计保证针对策略改进），不研究**评估设备的测量有效性**；
  无 C++ 执行证据、无能力边界、无标签/环境/分母审计；"审计"对象是自身修改序列而非测量口径。
- **与本文关系**：都把"可审计性"做成架构级属性；它靠 anytime-valid 证书，本文靠
  claim→控制→重测的协议与四态结果。互补：证书回答"改进是否统计可信"，审计回答"测量结论是否幸存"。

### 1.4 SV-COMP 2026（TACAS 2026，已核验官方页面）
- **元数据（核验于官方页面，2026-10-07）**：第 15 届；TACAS 2026，2026-04-13，都灵；
  验证器登记 74 条（**C 相关 61**、纯 C 56；active 45）；validators 26 条（C 类 22；active 15）；
  witness format 2.0（YAML）；任务仓库 `sv-benchmarks` tag `svcomp26`。
  **任务总数 36402 未核验**（官方页面未列；报告 PDF 本批未能解析）⇒ 论文不得引用该数字。
- **机制**：固定任务集 + 统一资源限制 + 独立 witness validation（confirmed/unconfirmed 计分）。
- **它没做什么**：不把"评估结果在口径/环境/资产构成变化下是否幸存"作为研究对象；
  无四态 unknown 语义；无能力边界统计；不研究评估器自身的迭代改良（排名每年重跑而非演进）。
- **与本文关系**：详见 `data/689_svcomp_positioning.md`（一句话：SV-COMP 回答"哪个验证器在给定任务上好"，
  Queyi 回答"评估结果在评估器被审计后还成立吗"）。

## 4. 定位声明（写作红线）
