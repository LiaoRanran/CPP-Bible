# 655 C · 门禁三杠杆实测报告

> 任务书目标："fast pytest 从 15.4s 再砍 30-50%"。本报告**先定义口径再给数字**，
> 并把"没达成的部分"写在 §五。所有数字均为本机实测（2026-09-27，32 核，venv Python 3.13.13 /
> pytest 9.1.1 / xdist 3.8.0），产物见 `data/655_*`。

## 一、口径（先说清楚"15.4s"指什么）

| 口径 | 内容 | 实测基线（改动前同样命令） |
|---|---|---|
| **A** | 655 涉及测试子集：`test_655_tools.py + test_verdict_spec_v1_655.py + test_653_tools.py + test_652_tools.py + test_core_pbt_651.py`（56 例） | **42.94 s** 墙钟 |
| **B** | 653 门禁 fast 阶段同口径：`test_653_tools.py + test_652_tools.py + test_core_pbt_651.py`（22 例） | **18.02 s** 墙钟（与任务书所述 15.4 s 同一量级 ⇒ 该"15.4s"应是**子集口径**而非全量 fast） |
| **C** | 全量 fast 阶段（`-m "not slow" -n auto`） | **3210 例 / 634.3 s**（junit 自报）/ **636.7 s** 墙钟 |

> 全量 fast 远大于 15 s，故 §六 明确登记：**本批不宣称把全量 fast 砍掉 30-50%**，
> 宣称的是"**同一份工作**在三个杠杆下**重复劳动被消除**"。

## 二、杠杆 1：基于 git diff 的增量测试选择（`tools/test_selector_655.py`）

**做什么**：`git diff --name-only <since>...HEAD` + 工作区改动 → 映射到**受影响的测试文件**。

**映射规则**（全部可解释，`--json` 逐条给理由）：
- `tests/test_*.py` ⇒ 只选它自己；`tests/` 其他文件 ⇒ 全量；
- `tools/*.py` ⇒ 在 `tests/` 里**文本命中**该模块名的测试；**无命中 ⇒ 全量**（fail-safe）；
- `atoms/ evidence/ Book/ Examples/ web/ data/ docs/` ⇒ 命中该前缀的测试；
- 文档/表格类（`.md/.txt/.json/.yaml/.html/.css`）⇒ 登记但不回退全量；
- **高危面 ⇒ 直接全量**：`tools/gate_engine.py`、`tools/weighted_af_solver.py`、`tools/tool_integrity.py`、
  `tools/.tool_checksums`、`tests/conftest.py`、`conftest.py`、`pyproject.toml`。

**实测**：

| 场景 | 结果 |
|---|---|
| 5 个改动路径（4 个新工具 + 自身测试） | 选中 **1 / 545** 个测试文件（`tests/test_655_tools.py`） |
| 跑选中文件 | **15.65 s / 19 例 / 全绿**（对比口径 A 的 42.94 s ⇒ **−63.6%**） |
| 6 个 fail-safe 用例（自检） | 高危面 / 未归类 / 无测试提及的新工具 ⇒ **均回退全量**（`--check` PASS） |
| 本批真实工作区（1107 个加头文件 + 文档） | **回退全量**（含 `LICENSE` 未归类 + 大量无测试提及的 `tools/*.py`）——**设计使然**，见 §五.1 |

## 三、杠杆 2：pytest 结果缓存（`tools/result_cache_655.py`）

**做什么**：键 = `sha256(canonical_json({nodeids, inputs{path:sha256}, env{python,pytest,config}}))`；
命中前**逐文件重算哈希**，并要求条目自哈希 `entry_sha256` 一致。

**实测（同一组 5 个测试文件 / 56 例）**：

| 步骤 | 结果 |
|---|---|
| `--record`（从 junit 记录） | 条目写入：`tests 56 / failures 0 / duration 41.724 s` |
| `--lookup <key>` | **HIT**（摘要与依赖哈希一致） |
| 改依赖文件一个字节 | **MISS**，理由 `依赖文件漂移 1 个` + 漂移清单 |
| 手改缓存条目（`summary.tests=42`） | **拒绝采信**（条目自哈希不符），`--verify` 报 `tampered=1` |

**正确性边界**：缓存**不是信任根的一部分**（不在 `tools/.tool_checksums`），命中与否**不得**影响判决；
`data/655_result_cache.json` 可随时删除重建。

## 四、杠杆 3：按时长均衡分片（`tools/pytest_shard_655.py` + `tests/conftest.py`）

**做什么**：从 junit（或 `--durations` 文本）取时长 → **LPT** 按**整模块**分片（模块级切分是为了
不破坏本仓"同模块共享真实仓库状态"的隔离假设）→ conftest 新增 `--shard-id/--shard-count`
（**默认 0 = 关闭，默认口径一字不变**）在收集阶段 deselect 其它片。

**实测（全量 fast 用例集，4 片）**：

| 项 | 结果 |
|---|---|
| 划分正确性 | 未分片 3220 例 / 449 模块；四片 **780 / 809 / 818 / 813**，合计 **3220**（精确相等） |
| 互斥性 | 四片模块集合两两**零重叠**，并集 == 未分片集合 |
| 均衡度（junit 口径） | LPT 不均衡 **1.0006**（按模块名轮转 = 1.1234） |
| 均衡度（真实时长口径，见下） | 5 模块 40.81 s → 4 片预测 `[14.28, 10.05, 8.09, 8.39]`，不均衡 **1.3997**（轮转 1.778） |

**诚实登记（口径缺陷，本批实测发现）**：`pytest-xdist` 产出的 junit `testcase@time` 是**累计/失真口径** ——
3210 例求和 **9196 s**，而套件自报 **634 s**（比值 14.5）。因此基于 junit 的计划表**绝对秒数不可当墙钟**，
只可用于**相对均衡**；工具已内置该检测并打印 WARN、把 `caveat` 写进 `data/655_shard_plan.json`。
**正确口径**是 `pytest --durations=0 -n0` 的文本输出（`--durations-text` 已支持）。

## 五、没做到 / 没达到的部分（诚实登记）

1. **本批真实 diff 下选择器回退全量**：因为本批改了 1107 个 `.py`（许可证头），其中大量工具**没有被任何测试文本提及**
   ⇒ 按 fail-safe 规则必须全量。收益只在"小范围改动"场景体现（实测 −63.6%）；这不是缺陷，是**用保守换正确**，
   若要提高命中率，需要把"文本命中"升级为 **AST/import 级依赖图**（列 656+ 候选）。
2. **未达成"全量 fast 砍 30-50%"**：全量 fast 636.7 s ⇒ 3210 例，本批**没有**把它的墙钟砍半；
   三个杠杆消除的是**重复劳动**（未变更重跑、按需选例、按片摊薄），不是单次全量成本。
   全量成本的真下降需要"编译类测试下沉 + 并行假红清理"，属 656+ 议题。
3. **分片不减少总工作量**：单机串行跑四片比不分片更慢（多 4 次收集开销）；只在**多机 CI 矩阵**下才有墙钟收益。
4. **缓存的"跳过"未接入 CI**：本批只交付"可判定输入是否一模一样"的能力；是否真跳过由门禁/CI 决定
   （`run_655_gate.py` 里以 `--lookup` 结果作为**报告项**，不作为唯一判据）。
