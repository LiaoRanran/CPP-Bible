# A1 · 自动规则生成调研（对阙疑怎么用）

> 643 阶段 A。**工程调研**，不是学术综述：每条都问"阙疑能落哪一步、失败模式是什么"。
> 检索 8 次（聚焦"规则生成 + 人审介入点 + 失败教训"）。检索日期：2026-09-26。

## 一、现有做法盘点（≥5）

| # | 名称 | 机制 | 对阙疑的可借点 | 关键失败模式 |
|---|---|---|---|---|
| 1 | **Semgrep**（自定义规则） | YAML + 模式匹配写规则，**上手分钟级** | 若阙疑规则写成**声明式可读形态**（而非全内嵌 `check()` 闭包），自动草案才能"可读可审" | 模式语言越强（taint/dataflow）越难自动生成；用户写的规则**误报率**是主要抱怨源 |
| 2 | **CodeQL**（QL 查询） | 类 SQL 的对象化查询 + 数据流 | 规则=查询 ⇒ 可用"查询合成"的方式生成；**代价**：QL 学习曲线陡 | 自动生成的复杂查询**不可读** ⇒ 人审形同盖章 |
| 3 | **LLM 规则化 linter**（Metalint 系；LLM 生成/精化 lint 规则） | 让 LLM 从**代码库习惯（idiom）**里提炼规则候选 | **"从仓库自身习惯提炼"**正是阙疑 `MDL 准入` 的输入形态：规则 = 对已有 67 条的增量 | LLM 规则**泛化差**（过拟合到样例）；与既有规则**语义重叠**而不自知 |
| 4 | **静态分析降误报**（LLM 用于削减 SAST 误报） | 用 LLM 对既有告警做二次判定，而不是生成新规则 | 阙疑的 **B3 自身免疫热点**正是"降误报"问题：可先做"规则太严则收紧"，风险远低于"生成新规则" | 二次判定引入**新偏差**且难审计 ⇒ 只能作**建议**不能作判决 |
| 5 | **归纳式不变量合成**（Daikon 系 / 不变量挖掘） | 从运行轨迹**自动推断**候选不变量，再过滤 | 阙疑的"**逃逸案例 → 规则草案**"同构：从**反例**推进比从**正例**推进更省样本 | 推断出的不变量**大量平凡/冗余**（需 MDL/支持度过滤）——阙疑已有 642 MDL 准入器，可直接复用 |
| 6 | **合成代码评审意见**（Sourcery / CodeRabbit 式：LLM + 静态分析混合 + 校验环节） | LLM 出候选意见，**过一道校验**再发给人 | **"生成 + 校验"两段式**正是 643 D 阶段要做的形态（D2 生成 → D3 MDL → D4 反涟漪） | 无校验的 LLM 评审=噪声；校验不足则**假阳泛滥** |
| 7 | **差分/变异驱动的规则学习**（把"规则"当分类器，用带标签样本训练） | 规则=阈值/条件组合，用样本学 | 阙疑 `known_error_rate` 台账可作**标签源**（被推翻的判决=假阳样本） | **标签极稀**（阙疑仅 85/452 有归属、1/1406 逃逸）⇒ 学习器会过拟合 |

## 二、失败教训（归纳成 5 条）

1. **不可读的规则 = 不可审的规则**：QL 类强大但难读；自动生成若产出"人看不懂的查询"，人审只是盖章。
   ⇒ 阙疑草案必须**人可读**（名称 + 触发条件 + 判定逻辑 + 理由），且**长度受限**（MDL 编码长度天然约束）。
2. **过拟合是最常见病**：LLM/不变量挖掘都倾向"解释眼前样本"，泛化差。
   ⇒ 阙疑的防线应是 **反涟漪（D4）+ 豁免率（D3）**：草案必须在**别的卡**上也不炸。
3. **冗余规则比缺失规则更常见**：新规则常与既有规则**语义重叠**（同一问题被两条规则报两次 ⇒ 噪声翻倍）。
   ⇒ 必须在**入库前**做"与既有 67 条的覆盖对比"（阙疑 B1 覆盖矩阵可直接复用）。
4. **误报的代价不对称**：漏报=债，误报=**信任崩**（人开始忽略告警）。
   ⇒ 阙疑应按 **minimax 遗憾**取向：草案**宁窄勿宽**，且**默认 `advice`/`warn` 起步**（不直接 `block`）。
5. **自动生成的规则会"污染"基线**：一旦入库，它就参与后续一切判决与统计，**回溯极难**。
   ⇒ **只出草案、人审后入库**（643 §零.1）；草案放**侧车**，不写 `gate_engine.py`。

## 三、对阙疑的设计结论（落 D 阶段）

| 结论 | 落到哪 | 具体做法 |
|---|---|---|
| C1 **从反例（逃逸）推进，不从正例推进** | D1/D2 | `escape_root_cause_643` 先把逃逸归因到"规则缺失/太弱/冲突/能力天花板"，只为**前两类**出草案 |
| C2 **草案必须机读 + 人可读双形态** | D2 | 草案字段：`rule_id/title/trigger/decision/reason/provenance/expected_block_rate/MDL/phash`；`reason` 必须引用**具体逃逸案例 id** |
| C3 **入库前必须过三闸** | D3/D4 | MDL 准入（642 器）→ 反涟漪（沙箱）→ **人审**；三闸全过才可入库 |
| C4 **默认从宽** | D2 | 草案 `severity` 默认 `advice`；升 `warn/block` 需人签（避免自动生成把信任面收紧） |
| C5 **抗冗余** | D3 | 草案必须附"与既有 67 条的覆盖重叠估计"；重叠 > 阈值 ⇒ `REJECT_冗余`（本批新增结论，642 MDL 无此项） |

> **诚实登记**：Semgrep/CodeQL 的"上手难度"与"误报率"结论来自检索到的对比文章（厂商/博客口径，**非同行评审**）；
> Daikon 类不变量挖掘的"大量平凡不变量"是长期共识但本次未逐篇核对原文 ⇒ 上述 C1–C5 是**工程判断**，
> 不是文献定论。阙疑的规则是**内嵌闭包**（无声明式 precondition），因此"自动分析 precondition"
> 只能做**静态近似**（AST + 阈值常量扫描），这一点在 C1 工具里如实标注。
