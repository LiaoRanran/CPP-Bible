## 一、五条设计输入（可直接执行）

### D-1 **从反例推进，不从正例推进**（来源 A1-C1 / A2-K1）
- **做什么**：智能层的"发起端"统一改成 **逃逸/误报案例**（反例），而不是"仓库现状指标"（正例）。
- **落点**：B4（逃逸热点）→ D1（归因）→ D2（草案）；C1（precondition）以**规则**为目标端。
- **验收可检验**：`rule_drafter_643` 的每条草案必须带 `provenance.escape_case_id`；
  无 provenance 的草案 ⇒ `draft()` 直接抛错（而不是"允许但不建议"）。

### D-2 **生成与淘汰分工：生成可启发式，淘汰必须机械**（来源 A2-K4 / A2 教训 4）
- **做什么**：智能层只产生"**候选 + 预期**"（`expected_oracle`），**淘汰/拦截判定交给机械 gate**。
- **落点**：C2（生成计划）→ C3（沙箱跑 gate 实测）→ C4（等预算对比）。
- **验收可检验**：`targeted_mutator_643` 的 dry-run **不写生产**（断言 `atoms/` sha256 不变）；
  `attack_simulator_643` 的每次执行只读生产、只写 `data/` 与临时目录。

### D-3 **入库三闸 + 抗冗余（642 MDL 缺的第五闸）**（来源 A1-C3 / A1-C5）
- **做什么**：草案入库路径 = **MDL 准入（D3）→ 反涟漪（D4）→ 人审**；并在 MDL 前加一道
  **"与既有 67 条的覆盖重叠"检查**（642 的 MDL 器没有这一项，A1 教训 3 指出这是最常见病）。
- **落点**：`rule_draft_mdl_check_643` 复用 `mdl_gate_642.admit_new_rule`，并**额外**计算
  `overlap_with_existing`（草案目标卡集合 ∩ 既有规则命中卡集合）/|目标卡集合|。
- **验收可检验**：重叠 > 0.8 时结论降级为 `REJECT_冗余`（本批新增档，不改 642 器）。

### D-4 **所有"代理指标"成对出现，且不足样本不判**（来源 A3-G2/G3 / 教训 1–3）
- **做什么**：智能层的每个对外结论都必须**成对**（逃逸 ↕ 误报；覆盖率 ↕ 深度）
  并标 **n**；`n < 阈值` ⇒ 输出 `insufficient_data` 而**不是**给死结论。
- **落点**：B3（热点：warn 率 ↕ block 率 ↕ 豁免率）、B4（逃逸率 ↕ 有效攻击率）、
  E2（老化：趋势 ↕ n）、E3（校准度：`None` 而非 0，沿用 642 C2 口径）。
- **验收可检验**：任一工具的输出若只有单指标且无 `n` ⇒ 单测失败（本批在 B3/B4/E2 三处固化）。

### D-5 **隔离/白名单清单必须"逐条带取证 + 可复核"**（来源 A3-G5 / 阶段 0 实测）
- **做什么**：阶段 0 的并行安全登记（串行组 31→77 模块）与 C1 的白名单扩展都属"豁免清单"，
  必须**每条附取证**、并声明"经验累积、不声称完备"，否则等于把门禁悄悄关掉。
- **落点**：`tests/conftest.py` 的逐批取证注释（已做）、`docs/pytest_two_phase.md`、
  `auto_executor_whitelist_eval_642`（本批 C 阶段沿用其 score 口径）。
- **验收可检验**：C1 的 643 版（`whitelist_expand_decision_643`）输出里
  **每条留档项都带 `evidence` 字段**，空 evidence ⇒ 单测失败。
