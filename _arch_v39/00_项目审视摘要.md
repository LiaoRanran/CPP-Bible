## 一、现状总览

阙疑是一个"对可执行知识断言做验证"的单人工程系统，截至 655 批：47 张知识卡（37 verified + 10 draft650）、67 条规则、9 个保护器、813 行 Python 核心（`queyi_core_v10_641.py`，`kernel_digest=9e926c78`）、452 条改判账本（Merkle 锚定、sha256 未变）、逃逸率 0.0711%（1/1406，v7 冻结契约）、CS anytime 上界 0.9062%。验证信任根闭包覆盖 33 个文件，VSA HMAC 做证据链签名，UVK 纲领四条（永不自证/永不全信/永不 fail-open/持续进化）+ 待确认第五条（攻击面显式化，v37-01 推荐）。开源地基已落地（Apache-2.0 + DCO 1.1 + CoC/SECURITY/GOVERNANCE），但 CI 未强制 DCO、license header 普查与 136 脏文件清理仍在进行（655 批）。

## 二、10 维度审视

**D1 验证方法栈**【已查证】
- 已用：编译实测（C++ 真机编译/运行）、规则匹配（67 条）、变异测试（challenger 十卡 × 算子）、PBT（部分性质）、独立验证者（independent_verifier_628，纯标准库 RSA 重实现）、透明账本（452 事件 Merkle）、保护器（9 个）、人审（B1 冲突 + 闭环校准）。
- 成熟度：账本/内核/规则/独立重实现=高；challenger 变异集=中（G9 未修，仅 10 卡接入，50/50）；不可能卡/验证器变异集=未建（v35-M2/M3）。
- 阙疑能学：本调研方向 2/3 的覆盖率驱动与变异算子体系可直接扩充 challenger。

**D2 信任根**【已查证+推断】
- 链：知识断言 → 证据（双轴）→ 验证器（9 保护器 fail-closed）→ 内核（813 行）→ 信任根闭包（33 文件 + VSA HMAC + Merkle）→ **最底层=作者本人（git 提交 + 私钥）**，未声明（v35-06 洞察 4）。
- 缺口：无外部锚（比特币时间戳仅计划）；社会终止层（CT/Rekor 模型）未接入。阙疑能学：方向 11/13 的 OTS 真上链与透明日志接入。

**D3 已验证 vs 未验证**【已查证】
- 强证据：逃逸率（1/1406 冻结）、账本 452 事件不可篡改（Merkle）、假开关 G12 被差分验证抓出（653 实证）。
- 应验未验：R1–R6 规则的完备性、cs_upper_bound 的全域有效性、L0 真机裁判在嵌入式域的可得性（647 E2 自登记为盲区）。
- 已知盲区：自动免疫路径（0/23 硬开火但 23/23 软警报，口径仅 sanity check）。

**D4 测试覆盖**【已查证】
- tests/ 4015 例 / 541 文件，fast/slow 标记；变异测试检出率 50/50（G9 未修）；PBT 覆盖少数不变量。
- 盲区：并发安全、性能、可用性几乎无测试；未接 415 批全量 pytest 预存在失败（655 交人）。

**D5 保护器**【已查证】
- 9 保护器：B1 冲突改判裁决（真上岗）、B2–B9 覆盖编译/证据/合成/谱系/预算/校准/独立重实现/账本核验。
- 状态：B1 真上岗；challenger 类（G9）影子→半上岗；poison_drill（618）上岗覆盖率 95.2%（124/124）；B6（VSA 去同源）未落地【盲区：B6 是否实现以 647 为准，本文按 v35 推断为未落地】。

**D6 数据资产**【已查证】
- 452 账本：质量高（真实、Merkle），但缺人工标注（改判类型 + 事后对错）【v37-03 关键路径】。
- 37 卡：verified；10 draft：未冻结。104 条证据（evidence_index）：有等级但质量参差。67 规则：覆盖度未量化。

**D7 已知技术债**【已查证】
- 652 gaps 19 条；655 交人 9 项（CRLF 漂移、全量 pytest 预存在失败、license header 等）；136 脏文件（650–652 区间遗留）未清理——公开前硬阻塞。

**D8 验证盲区（可验证性视角）**【推断】
- 并发/线程安全：内核与账本并发访问无验证（方向 16）。
- 性能/WCET：无（方向 17，嵌入式卡尤其缺）。
- 安全性：自身攻击面只做了 fail 路径雏形，abstain/投毒/不可能卡对抗测试不全（方向 14，v35-M3/M4）。
- 可用性：门禁失败是否 fail-closed 到"阻塞发布"有实现但无度量。

**D9 与外部标准差距**【推断+已查证】
- 对照 ISO 26262/DO-178C：阙疑无安全生命周期文档、无独立评估。对照 Common Criteria：无 EAL 评估（方向 6/12）。对照 NIST AI RMF：有"测量/管理"雏形但无 GOVERN 文档化（GOVERNANCE.md 仅为占位）。阙疑处于"强工程实践、弱标准对齐"状态。

**D10 演进路线（628→655）**【已查证+推断】
- 628 独立重实现 → 641 内核 digest → 647 信任根审计 + 校准 → 652 假开关暴露 + challenger → 653 G12 修复 → 655 开源地基。
- 演进是人工驱动（每批人设计任务），非自动（方向 21 核心追问）。下一步验证能力应走：G9 修 → 变异集/不可能卡 → 形式规格 v1（v34-P2）→ 账本标注 → 外部锚。
