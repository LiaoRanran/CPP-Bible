## 一、验证方法谱系图（文字版）

横轴=验证强度（弱→强），纵轴=单位成本（廉→贵）。每格一方法：

```
强度\成本   廉                    中                    贵
强     ┌──────────┐      ┌──────────────┐     ┌──────────────────┐
       │ 声誉/同行 │      │ 独立重实现(DDC)│     │ 形式化证明       │
       │ 评审/日志 │      │ 变异测试      │     │ (seL4/CompCert)  │
       │ (CT/log) │      │ 透明账本      │     │ 硬件形式化验证   │
中     ├──────────┤      ├──────────────┤     ├──────────────────┤
       │ 单元测试  │      │ 覆盖率驱动验证│     │ 模型检查(CBMC)   │
       │ PBT      │      │ 审计抽样      │     │                  │
弱     └──────────┘      └──────────────┘     └──────────────────┘
```

## 二、阙疑当前位置

**坐标 ≈（强度中高，成本中）**：它比"单元测试/PBT"强（有 fail-closed + 账本 + 独立重实现），比"全形式化"弱（仅规格 v1，无证明）；成本远低于形式化（单机 + 免费层，v37-07），高于纯单元测试。同格邻居：独立重实现 + 变异测试 + 透明账本——这三者阙疑**同时拥有**，是它区别于绝大多数系统的地方。

## 三、独特性：知识断言的过程级验证是空白格

谱系里没有"可执行知识断言的验证"这一格——知识图谱社区做"三元组验证"（弱、文本引用），形式化社区做"代码/数学验证"（强、非知识），AI 社区做"模型验证"（对象错）。**阙疑独占"对 LLM 产出的具体知识断言做 fail-closed 过程验证 + 生产账本"这一格**。这是 v34 洞察"in-toto 时刻"的精确表述。

## 四、可迁移 / 不可迁移

- **直接可用**：变异测试算子（2/14）、独立重实现（1/11）、Merkle/透明日志（11/13）、GRADE 证据等级（19/20）、审计抽样（20/21）、覆盖率思想（5）、NIST AI RMF 映射（6/7）。
- **需改造**：形式化（只做安全核，1/15）、TLA+ 共识（13 多节点前）、覆盖率驱动（5 改"流程覆盖"）、CBMC（15 内核 C 层）。
- **不适用**：硬件 UVM 全套（5）、WCET/实时（17，非实时域）、模型鲁棒证书（3，不验证模型）、图谱嵌入（5，不可解释）。

## 五、路线图（Y1/Y2/Y3，对齐 01 总览）

- Y1：challenger 变异体系（→强度中上、成本微增）+ 账本标注 + 开源公开。
- Y2：内核关键不变量形式化（强度上移一档，成本中增）+ 账本接透明日志/OTS。
- Y3：半自动进化 + 外部评估，可选 CC EAL 叙事。

## 六、阙疑能学/不能学（3 条）

- 能学：把"验证强度/成本"二维当成每次架构决策的显式权衡（避免无意识过度/不足验证）。
- 能学：独占空白格本身就是论文 novelty 的精确表述（v37-04 novelty 三段式）。
- 不能学：把成本压到"纯声誉"级（会失去 fail-closed 担保）；强度永远到不了"全形式化"级（经济停止点，方向 8）。
