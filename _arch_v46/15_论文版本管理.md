# 方向 15：论文版本管理

## 核心结论

1. **必须区分三套"版本号"并让它们互相可查**：论文内部版本（v0.1→v0.3）、arXiv 版本（v1/v2/v3，**永久不可删**）、投稿轮次版本（submission / rebuttal / camera-ready）——三套混用是单人项目最常见的事故源。
2. **Overleaf 免费版不足以支撑这套流程**：免费版编译超时只有 **10 秒**（付费 240 秒），且 **Git 集成与 GitHub 同步都是付费功能**；因此必须"本地 Git 为主、Overleaf 为辅"，而不是反过来。
3. **每个会场的"改稿窗口"规则不同，写死规则比记住规则更可靠**：NeurIPS 在 rebuttal 期**完全禁止**上传修订版（"No revisions are allowed until the camera-ready stage"），而 ICLR 允许讨论期提交修订（页数上限从 9 页升到 10 页），ICSE 大修则**要求**提交带痕迹的版本（LaTeXdiff）。

## 精确数字与案例

### 一、三套版本号的正确定义

**（1）论文内部版本**：阙疑仓库 `research/` 下已有实测记录：`paper_v0.1.md`（64 行）→ `paper_v0.2.md`（81 行）→ `paper_v0.3.md`（117 行），另有 `CHANGELOG.md` 与 `PROTOCOL_v0.1.md`。这套编号只用于"内部可追溯"，**不应出现在投稿 PDF 里**。

**（2）arXiv 版本**：官方原文"Once made public, each version of a work is considered a permanent part of the scientific record and **may not be removed**"。每次 replace 或 withdraw **版本号 +1**，撤稿版本保留在版本历史里但不含全文链接。arXiv 明确列出"要求用版本号而非新建 ID"的情形：出版流程各阶段（submitted / revised / accepted / published）、相关工作不同内容（附录、勘误、扩展版、短版）、著名猜想的多次尝试、拆分与合并、翻译、living review、Comment 与 Reply to Comment。**引用必须带版本号**（`arXiv:YYMM.NNNNNvX`），官方并建议用 Comments 元数据描述各版本，示例：

> "For the longer conference version see: arXiv:YYMM.NNNNNvv1. For the shortened summary see arXiv:YYMM.NNNNNvv2, for the journal version that includes extended data in the appendix see arXiv:YYMM.NNNNNv3"

**（3）投稿轮次版本**：submission / author-response / camera-ready 三档。注意 arXiv 的"不可删"与投稿轮次的"可覆盖"是两个不同的域——**不要把 camera-ready 直接覆盖 arXiv v1，应新建 v2**。

### 二、Overleaf 的真实限制（免费版撑不住）

Overleaf 官方 plan limits 原文数字：

| 项目 | Free | Premium（Standard / Pro / Student） |
|---|---|---|
| 编译超时 | **10 秒** | **240 秒** |
| 每项目文件数上限 | 2000 | 2000 |
| 可编辑内容总量/项目 | 7 MB | 7 MB |
| 单个可编辑文本文件上限 | 2 MB | 2 MB |
| 单次上传上限 | 50 MB | 50 MB |
| 项目数 | 不限 | 不限 |
| AI 日配额 | Basic（无 assistant） | 依套餐 |
| **Git 集成 / GitHub 同步** | **不含** | 含 |
| 项目历史 / track changes | 不含 | 含 |
| 协作者上限 | — | Standard/Student **10**；Pro 不限 |

官方还建议：项目总大小最好 **≤500 MB**，若使用 GitHub 同步或 Git 集成则 **<100 MB**；超过 4 GB 时复制项目等操作会出问题。

**对阙疑的含义**：论文 + 附录 + 大量图表 + 复算日志很容易撞到 10 秒编译超时，而 Git 集成是付费功能。正确做法是**本地 Git 仓库为唯一真相源**，Overleaf 只作"临时协作/快速预览"，用 `git` 命令行而不是 Overleaf 的 Git 桥接。

### 三、本地 Git 工作流（可直接落地）

**仓库布局（论文侧）**：

```
research/
  paper/            # LaTeX 源
    main.tex
    sections/{intro,method,eval,threats,related}.tex
    figures/
    macros.tex
  CHANGELOG.md      # 已有（Keep a Changelog 风格）
  paper_v0.1.md ... # 已有（内部里程碑快照）
```

**分支策略（单人也要分支，因为要同时存在"已投版本"和"正在改的版本"）**：

- `main`：只放**已投稿的冻结版本**。每次投稿打 tag：`sub-neurips2027-ed`、`sub-icse2028`。
- `rebuttal/<venue>`：作者回复期间的修订分支，从对应 tag 拉出。
- `camera-ready/<venue>`：录用后的定稿分支。
- `arxiv`：与 arXiv 已发布版本一一对应的 tag：`arxiv-v1`、`arxiv-v2`。

**必须做的两件小事**：

1. **语义换行（semantic line breaks）**：每个句子一行，而不是每段一行。这样 `git diff` 才能显示"改了哪句"而不是"整段重写"。这是 LaTeX + Git 协作的通行规范。
2. **编译产物不入库**：`.gitignore` 加 `*.aux *.log *.out *.bbl *.blg *.synctex.gz *.pdf`（camera-ready PDF 例外，用 tag 标记来源 commit）。

**latexdiff / git-latexdiff（带痕迹版本的标准工具）**：

- `latexdiff`（ftilmann，Perl 脚本）：比较两个 `.tex` 文件并标记差异；配套 `latexrevise` 可接受/拒绝全部改动，手动编辑 diff 文件可只接受部分改动。依赖 `ulem`（下划线/删除线）与 `color` 宏包。
- `git-latexdiff`：把 Git commit 与 latexdiff 接起来，一条命令生成"两个 commit 之间的带痕迹 PDF"。典型用法：`git latexdiff --main main.tex <base-commit> HEAD -o diff.pdf`。Timothy Gebhard（2023-06-06）专门写过"Using git-latexdiff for paper rebuttals"的教程。
- **谁会要求你交这个**：ICSE 2027 大修论文必须提交"修订稿 + 标注修改的版本（如 LaTeXdiff）+ 作者回复文档"，由同一批审稿人复审，修订期约 **4 周**；ARR 重投则要求"point-by-point response + 章节行号引用"，并允许（不强制）对改动部分着色，着色版可与 explanation 放在同一 PDF。

### 四、各会场的"改稿窗口"规则（写死比记住可靠）

| 会场 | 审稿期能否改稿 | 页数变化 | 其他硬规则 |
|---|---|---|---|
| **NeurIPS 2025/2026** | **不能**。"No revisions are allowed until the camera-ready stage"；supplementary 也不能改 | 正文 9 页（references / checklist / 附录不计入） | rebuttal 每条评审上限 **10,000 字符**（已取消 global rebuttal）；rebuttal 中**禁止放链接**，唯一例外是审稿人索要代码时向 AC 发匿名链接；rebuttal 可含新结果但"original submission will serve as the basis"；checklist **不包含则 desk reject** |
| **ICLR 2026** | **能**。讨论期允许提交修订，页数上限 **9 → 10 页** | 投稿 ≤9 页，讨论/camera-ready 10 页；超页 desk reject；references 不限页；附录不限页（审稿人无义务读）；ethics statement ≤1 页不计；reproducibility statement 不计；LLM 说明放附录不计；致谢不计 | rebuttal 修订页数与投稿版相同（10 页） |
| **ICML 2025/2026** | 见 CFP | 投稿 8 页正文 + 不限页 references/impact statement/附录；**录用后正文可加 1 页** | impact statement 不计页；**2025 起录用的论文必须提交 lay summary**（camera-ready 时在 OpenReview 提交）；camera-ready 可改作者顺序但**不得增删作者**；ICML 2026 附录必须并入同一个 camera-ready PDF，**没有 camera-ready 补充材料** |
| **ACL / ARR** | 可随时改稿并提交 rebuttal | 长文 8 页、短文 4 页；**录用后各加 1 页**（长文至 9 页、短文至 5 页） | 重投**必须**提供上一版链接，未标注前版直接 desk reject；重投需 point-by-point 回复（含 meta-review），建议用章节行号；**得 1.5 分的不能在下个 cycle 重投，得 1 分的永不可重投**；撤稿发生在截稿 48 小时后须等第二个后续 cycle |
| **ICSE 2027** | 大修必须交"修订稿 + LaTeXdiff 标注版 + 作者回复" | 正文 ≤10 页 + references ≤2 页；camera-ready 加 1 页；大修再加 1 页 | 大修由同一批审稿人复审，修订期约 4 周，不达标即拒；**改用 IEEE 模板** |
| **ASE 2026** | 大修修订 2026-07-16，camera-ready 2026-08-03 | — | 另有 Tools and Datasets 赛道（截稿 2026-05-11） |
| **TMLR** | 作者**可**在讨论期更新论文并贴 rebuttal | — | 官方建议"waiting until all 3 reviews have been submitted before submitting any revised version"；被拒后重投**须作为新投稿**并提供前版链接与改动说明；录用后如需改稿，重大改动须放在 **"Post-Publication Changes"** 章节（致谢之后、参考文献之前）；**完整修订历史永久留在 OpenReview** |

**跨会场的通用陷阱**：camera-ready 阶段"可以改的"和"不可以改的"边界。NeurIPS 2025 FAQ 原文：title / keywords / abstract **可以**改，只要"do not substantially differ from the original submission"；作者列表**可以重排**，但**不允许增删**。ICML 同类规则一致（"no author additions or deletions are allowed"）。这意味着**任何作者变动都必须在投稿前定死**。

### 五、CHANGELOG 的写法与位置

- **格式**：采用 Keep a Changelog 风格。阙疑仓库已有一个可参考的实例：`ChineseResearchLaTeX/skills/paper-write-sci/CHANGELOG.md`，其首行写明"All notable changes to paper-write-sci will be documented in this file. The format is based on Keep a Changelog"。
- **论文版 CHANGELOG 应该记录什么**（区别于软件 CHANGELOG）：不是"加了什么功能"，而是**每条 claim 的改动轨迹**——新增/删除/收窄了哪条主张、数据口径变了吗（例如"holdout 真错 7 → 17"）、哪个数字从"内部变异率 97.3%"改成"不再作为缺陷检测率"。
- **与研究软件版本发布打通**：研究软件版本管理指南（LUMC DCC，2026-09-01）建议"从 tag 创建 GitHub Release，并把 changelog 条目粘进 release notes"。阙疑已有 `_auto/status.json`、`data/backups/` 这类工程习惯，可以直接把"论文里程碑"也纳入 release 体系（tag `paper-v0.3`）。
- **一定要记的"诚实登记"**：阙疑已有先例——`_auto/status.json` 的 `active_batch=660` 落后于实际 665（元状态漂移），以及"反事实算子 P=R=F1=0（待修）"。这类"已知缺陷"必须在 CHANGELOG 里留痕，否则 camera-ready 阶段会被审稿人或 AC 抓出来。

### 六、一条完整的 v0.1 → camera-ready 时间线（以 NeurIPS E&D 为目标）

1. **v0.1（已有，64 行）**：骨架。
2. **v0.2（已有，81 行）**：纳入新数据 + claim 边界。
3. **v0.3（已有，117 行，2026-09-29）**：holdout 30 / corpus 40 / 反事实 20。
4. **v0.4–v0.9（内部）**：按 §Threats to Validity 补齐统计（Clopper-Pearson 区间、Fisher 检验）、补齐 3 条 baseline、把"可复算"做成脚本。每个里程碑打 tag `paper-v0.4`…。
5. **submission（arXiv v1 同期）**：tag `sub-neurips2027-ed`；同时挂 arXiv v1（tag `arxiv-v1`）。**注意 NeurIPS 禁止在提交版本里引用自己的非匿名预印本**（ICML 原文同理），因此正文里不得出现 arXiv 链接。
6. **rebuttal**：NeurIPS 不允许改稿 → 只写 10,000 字符/条的 rebuttal，不放链接，新结果只作澄清。此阶段**不改 PDF**。
7. **camera-ready**：checklist 必含（否则 desk reject）；正文可微调但不得与投稿版"substantially differ"；作者不得增删；代码与数据集必须在 camera-ready 截止前公开可用（E&D 硬要求）。
8. **arXiv v2**：camera-ready 定稿后**新建 v2**，Comments 里写"v2: camera-ready version, accepted at NeurIPS 2027 E&D"。

### 七、ARR 的修订材料要求（最细的一份规范，可当模板）

ARR CFP 对重投的修订材料写得比其他会场细，可直接照搬：

1. **必须提供上一版链接**。原文："the authors must provide a link to the previous submission. Any paper previously submitted that does not acknowledge its earlier version will be desk rejected."（**即使上一版是被 desk reject 的也一样**。）
2. **必须提供变更摘要 + 逐条回复**：对上一轮**所有**审稿人（含 meta-review）的每条弱点与建议，要么说明如何修改，要么说明为何不同意；建议用章节与行号定位。
3. **允许着色但非强制**：可对改动部分着色，着色版可与 explanation 放同一 PDF；explanation 也可选地前置到主提交文件前，但**必须同时单独提交一个文件**到指定字段。
4. **作者变动**：新增作者须说明其贡献；移除作者须以删除其贡献的内容为依据；变动在 ARR 提交表单里单独填写，**不写在 explanation PDF 里**。
5. **审稿人复用规则**：原则上回到原审稿人与 AC；作者可带理由申请新审稿人/AC。**新审稿人被指示先独立形成判断**，只有在提交初始评审后才能看到上一轮评审与作者回复。
6. **冷却期**：得 1.5 分的不能在下个 cycle 重投；得 1 分的**永不可重投**；若上一版因匿名性违规被 desk reject，仍按标准重投流程，并在 resubmission notes 说明如何完成匿名化。

### 八、一份可直接复制的"改稿 SOP"

每个投稿轮次按这 6 步走，每步都留下可查证据：

1. **冻结基线**：`git tag sub-<venue><year>`，并把 commit hash 记入 `research/CHANGELOG.md`。
2. **建分支**：`git checkout -b rebuttal/<venue>`。
3. **按会场规则决定能否改 PDF**：NeurIPS **只写 rebuttal 不改 PDF**；ICLR **可改 PDF**（9→10 页）；ICSE 大修**必须**交标注版。判断依据写进 commit message。
4. **生成带痕迹版本**：`git latexdiff --main main.tex sub-<venue><year> HEAD -o diff.pdf`。
5. **逐条核对材料清单**：ARR 需要"前版链接 + explanation 单文件 + point-by-point"；ICSE 需要"修订稿 + LaTeXdiff 标注版 + 作者回复"；ICML 需要"lay summary（录用后）"；NeurIPS 需要"checklist（缺失即 desk reject）"。
6. **camera-ready 前三查**：①作者列表是否与原投稿完全一致（**不得增删，只可重排**）；②页数是否在允许范围（NeurIPS 9 页、ICLR 10 页、ICML 9 页、ICSE 正文 11 页含加页、ACL 长文 9 页）；③代码与数据集是否已公开可访问（E&D 硬要求，camera-ready 截止前必须完成）。

### 九、为什么"单人也要分支"：三个真实会同时存在的版本

单人项目的常见事故是"只有一个 main 分支 + 一个 main.tex"，于是在作者回复期改了正文，导致无法再生成"投稿版本 vs 当前版本"的对照。正确状态是**三个版本同时存在且都可达**：

- **投稿版本**（tag `sub-neurips2027-ed`）：对应 arXiv v1，对应 OpenReview 上的 submission。
- **回复期版本**（分支 `rebuttal/neurips2027-ed`）：ICLR 允许、NeurIPS 禁止改稿，这条分支在 NeurIPS 场景下只放"给 rebuttal 用的补充实验代码"，不放论文。
- **camera-ready 版本**（分支 `camera-ready/neurips2027-ed`）：从投稿 tag 拉出，改动**必须**满足"不与投稿版 substantially differ"（NeurIPS FAQ 对 title/keywords/abstract 的措辞）。

## 对阙疑的 3 条具体行动

1. **建 Git 论文仓库并把三套版本号打通。** 在 `research/paper/` 下初始化本地 Git 仓库（若 `research/` 已在仓库内则只加子目录），落地四类 tag 命名：`paper-v0.x`（内部）、`sub-<venue><year>`（投稿）、`rebuttal-<venue><year>`（回复）、`arxiv-vN`（预印本）。验收命令：`git tag -l | grep -E "^(paper-v|sub-|rebuttal-|arxiv-v)"` 输出非空；`git log --oneline -- research/CHANGELOG.md` 能看到每次改动的 commit。**时间点：2026-10-31 前建好，之后每次改稿必须提交。**
2. **加一份 `.gitignore` 并做一次 latexdiff 冒烟测试。** 内容：`*.aux *.log *.out *.bbl *.blg *.synctex.gz`。测试命令：`git latexdiff --main main.tex <前一commit> HEAD -o /tmp/diff.pdf`（需装 latexdiff + git-latexdiff）；若 `main.tex` 尚不存在，先用 `research/paper_v0.3.md` 转一个最小 LaTeX 骨架。**理由**：ICSE 2027 大修**强制**要求 LaTeXdiff 标注版，ARR 重投要求 point-by-point 回复，这两件事必须提前演练而不是临场学。**时间点：2026-11-30 前跑通。**
3. **在 `research/CHANGELOG.md` 里补一节"已放弃的口径"，与论文 §Threats to Validity 一一对应。** 至少写三条：①变异测试 97.3%（core）/ 81.5%（all）**不作为**缺陷检测率（论文已放弃该口径）；②反事实算子 P=R=F1=0 为待修项；③`_auto/status.json` 的 `active_batch=660` 与 git log 的 665 存在元状态漂移，作为"元状态不可信"的实证。每条须写明"何时发现、为何放弃、替代口径是什么"。**验收**：`grep -c "已放弃\|不作为" research/CHANGELOG.md` ≥3。**时间点：2026-11-15 前完成**，因为这是 camera-ready 阶段唯一会被反复追问的部分。

## 盲区（诚实标注）

- **Overleaf 具体价格**：本次只取到功能限制表，**未取到 Standard / Pro / Student 的具体金额**（不同地区与促销价不同），未核实。
- **Overleaf 免费版的协作者上限**：官方 plan limits 表里只写了付费档的 10 / 不限，**免费档数值未取到**，未核实。
- **ICML 2026 的确切页数**：ICML 2025 为 8 页正文 + 录用后加 1 页；ICML 2026 的 Author Instructions 页面未逐字核对页数条款，**按 2025 外推，未核实**。
- **NeurIPS 2027 的 rebuttal 字符上限**：按 2025 的 10,000 字符/条外推，**2027 未公布，未核实**。
- **ICSE 2027 大修的具体周数**：页面写"修订期约 4 周"，但精确日期（通知 2026-10-20 → 修订稿 2026-11-17）实际是 **28 天**，与"约 4 周"一致，但官方未用"4 周"字样表述，属本文件换算。
- **TMLR "Post-Publication Changes" 章节的强制程度**：原文是"Any significant changes **should** be documented in a section..."，用 should 而非 must，**是否强制未核实**。
- **`research/` 是否已是 git 仓库**：本次未运行 git 命令（遵守零污染约束），因此行动 1 的"是否需初始化"需执行时先确认。
- **LaTeX 骨架是否存在**：仓库 `research/` 现有 19 个文件均为 `.md`，**未见 `.tex`**；行动 2 需要先建立 LaTeX 骨架。
