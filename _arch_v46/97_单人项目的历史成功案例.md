# 方向 97：单人项目的历史（成功案例）

> 服务对象：双非本科（合肥、嵌入式、2026-09 起读大三、考研初试约 2027-12、毕业 2028-06）
> 项目锚点：**阙疑 / queyi** —— 「可被独立验收」的 C++ 知识验证器
> 精确锚点：**37 实卡**（verified 23 / red-team 3 / draft 11）+ 10 草稿；**67 规则**（block 44 / warn 16 / advice 7）；`tools/gate_engine.py` = **3826 行**；盲 holdout **30 seeds**（真错 17），检出 **66.7%**（10/15 可测）；外部 corpus **40 条**（43.8%）；缺陷夹具 **15 条**（重注入 6/6 = 100%）；反事实算子 **P=R=F1=0**。

## 核心结论

1. **单人项目的成功不是靠"一个人很牛"，而是靠三件事同时成立：一个被大厂忽略的窄缝、一个可被机器验证的产物、以及一个能把产物传播出去的免费渠道（GitHub / arXiv / 一条 HN 帖子）**。本方向列出的 12 个案例里，**有 9 个是"基础设施型工具"**（数据库、HTTP 库、打包器、linter、测试库、广告拦截器、笔记软件），**只有 3 个是"论文型成果"**（张益唐、Royen、Perelman）。→ **阙疑属于前者（工具型），这反而是好消息：工具型的成功路径比论文型更可复制、更少依赖运气。**

2. **C/C++ + 底层 + 单人的组合，在历史上出过至少 6 个万亿级/十亿级案例**：**SQLite**（D. Richard Hipp，2000 起，单人 → 3 人，全球**超一万亿**活跃部署）、**curl**（Daniel Stenberg，1998 起，单人长期维护，**安装量超 100 亿**）、**nginx**（Igor Sysoev，2002–2004 单人，2019 年被 F5 以 **6.7 亿美元**收购）、**Redis**（antirez，2009 单人）、**llama.cpp**（Georgi Gerganov，**2023-03-14** 单人起步，2026 年 **10 万+ stars**）、**uBlock Origin**（Raymond Hill，单人，**68.2k stars**）。→ **你的"嵌入式 + C++ + 单人"画像，在历史分布里不是劣势组合，是"最常出单人英雄"的组合之一。**

3. **但有一个你必须正视的统计事实：上述所有成功案例的"成功"都发生在 3–10 年的尺度上，且几乎都经历了"业余 → 全职 → 公司/基金会"的路径**。SQLite 从 2000 到"一万亿部署"用了 **24 年**；Zig 从 2016 到 2026 **十年未发 1.0**；Vue 从 2014 到能全职投入用了 **2 年**；llama.cpp 是唯一"爆发式"的（2023-03 发布，数月内成为标准），**但它是踩在 Meta 发布 LLaMA 权重这个一次性事件上的**。→ **对阙疑的含义：不要按"12 个月出结果"设计，要按"36 个月活下来"设计**（这也和你的考研/毕业时间线吻合）。

## 精确数字与案例

### 一、基础设施型工具（9 个案例）——与阙疑同构

#### 案例 1：SQLite（2000 起，单人 → 3 人）

- **作者**：D. Richard Hipp（美国，通用动力公司航空工程师出身）。
- **起点**：**2000 年**，Hipp 当时**处于失业/离职状态**，凭借此前做编译器的经验，用 **C 语言**写出第一版。
- **规模**：SQLite 官方与多方报道一致——**全球活跃使用量超过一万亿（1 trillion+）**，被"许多顶尖的网页浏览器、操作系统、移动电话"内置。**核心团队长期只有 3 个人**。
- **工程质量（最值得阙疑学的一点）**：源码约 **15 万行 C**，而**测试代码与测试脚本约 9,200 万行**（测试:源码 ≈ **600:1**）。此外 Hipp 为了自由开发 SQLite，**自己写了版本控制工具 Fossil**、自己写了 parser 生成器。
- **对阙疑的直接含义**：**"测试代码量远超源码"是这类验证型项目的标准形态**。阙疑目前 595 个 `.py` 工具 + 3826 行内核 + 67 规则，**测试资产相对源码的比例远低于 SQLite**——这是可以量化补强的方向。
- ⚠️ **"一万亿"是 SQLite 官方口径的活跃部署数（非用户数），本文未找到独立第三方复核**，列入盲区。

#### 案例 2：curl（1998 起，单人长期主导）

- **作者**：Daniel Stenberg（瑞典）。
- **起点**：**1996 年**他写了一个名为 httpget 的货币汇率查询工具，**1997 年**更名为 curl，**1998 年**首次以 curl 名义发布。**2000 年 1 月**改以 MIT/MPL 双许可发布 **curl 7.5.2**，解决了 GPL 项目无法使用 libcurl 的长期抱怨——**这是一次关键的"许可证决策"，直接打开了采用面**。
- **规模**：**安装量超 100 亿**（curl 25 周年时作者自述口径："远超 100 亿"）；代码行数 **超 15 万行**。
- **形态**：**一个人长期主导**（作者本人是核心维护者），但接受社区 patch。
- **对阙疑的直接含义**：**许可证选择是采用面的开关**。阙疑当前若用 MIT/Apache 是正确选择；如果核心规则库有"想商业化"的打算，**必须在 2027 投稿前决定许可证**（因为 E&D track 要求投稿时公开代码）。

#### 案例 3：nginx（2002–2004 起，单人 → 公司 → 6.7 亿美元）

- **作者**：Igor Sysoev（俄罗斯）。
- **起点**：**2002 年**开始开发，**2004 年**开源，目标是解决 **C10K 问题**（单机同时处理 1 万连接）。
- **结果**：成为全球最大 Web 服务器之一；**2019 年 F5 以 6.7 亿美元收购 Nginx Inc**；**2022 年 1 月** Sysoev 从 F5 离职（官方声明"将更多时间投入个人项目"）。
- **对阙疑的直接含义**：**"解决一个被明确命名、被公认困难的工程问题"（C10K）比"做一个通用的好东西"更容易被记住**。阙疑需要一句同等的"问题命名"——建议用 **"验证的独立性危机"（the independence crisis in verification）**，把"独立对账器"作为问题命名。

#### 案例 4：Redis（2009 起，单人）

- **作者**：Salvatore Sanfilippo（网名 antirez，意大利西西里）。
- **起点**：**2009 年**，为解决自己创业项目的实时统计需求而写。
- **形态**：**"以一己之力写出并长期维护"**（多方中文百科口径）；2020 年他宣布退居二线，**2025 年 11 月以"Redis 布道者"新身份回归**。
- **对阙疑的直接含义**：**单人项目的生命周期可以很长，且"退出—回归"是正常模式**。你考研期间"冻结"阙疑（见方向 67/99）在历史上完全成立，**不需要愧疚**。

#### 案例 5：llama.cpp（2023-03-14 起，单人起步）——最"爆发"的案例

- **作者**：Georgi Gerganov（保加利亚）。
- **起点**：**2023 年 3 月 14 日**，最初目的是"让 Meta 的 LLaMA 模型能在 MacBook 上跑起来"（纯 **C/C++** 实现）。
- **规模**：历经 **2023–2026 三年**，从个人项目成长为**开源 AI 基础设施核心**，**10 万+ GitHub stars**、数千贡献者；它定义的 **GGUF 格式**成为本地 LLM 的事实标准。
- **爆发的原因（关键）**：**踩在 Meta 开放 LLaMA 权重这个一次性事件上**，且**解决的是"在消费级硬件上跑"这个被所有人需要、但大厂不做的窄缝**。
- **对阙疑的直接含义**：**"大厂不做但所有人需要"的窄缝，是单人项目唯一的爆发入口**。阙疑的候选窄缝：**"跨编译器/跨优化档的可复算 C++ 判定证据"**——大厂做 sanitizer，但没人做"判定 + 哈希链 + 独立对账"。

#### 案例 6：uBlock Origin（单人）

- **作者**：Raymond Hill（网名 gorhill）。
- **规模**：GitHub **68.2k stars / 4.4k forks**（截至 2026-09 抓取），长期由作者一人主导。
- **对阙疑的直接含义**：**单人也能做出"被数千万人日用的关键基础设施"**。但要看到它的负面：**2026 年 1 月有恶意扩展冒充 Raymond Hill 的名义上架 Chrome Web Store** —— 单人项目的**品牌/信任风险**是真实成本。

#### 案例 7：esbuild（2020 起，单人）

- **作者**：Evan Wallace（**Figma 联合创始人兼前 CTO**）。
- **起点**：**2020 年**，作为**个人开源项目**用 Go 写了一个"比既有工具快 10–100 倍"的 JS 打包器。
- **结果**：被 Vite 等主流工具链采用，成为前端构建的基础设施。
- **对阙疑的直接含义**：⚠️ **注意"作者已财务自由"这个隐藏变量**——Evan Wallace 不需要靠 esbuild 谋生。**不要拿"名人副业"当"双非本科生主业"的模板**。这是本方向最重要的一条反例修正。

#### 案例 8：Ruff（2022 起，单人起步 → 公司）

- **作者**：Charlie Marsh。
- **起点**：**2022 年**，用 **Rust** 写了一个"极快的 Python linter"，目标是**替代十几个既有静态分析工具**。
- **规模**：**每周下载量达数百万次**（2024 年报道口径）；后续成立 **Astral**（同公司还做了 `uv`）。
- **对阙疑的直接含义**：**"把 N 个工具合并成 1 个，且快 10 倍"是被验证过的单人打法**。阙疑的对应版本：**"把 sanitizer + 静态分析 + 规则库的判定结果，统一成一条带 provenance 的四态判决"** —— 这正是你在做的事，**但你需要把它明确写成"合并 + 统一"的叙事**，而不是"又一个规则引擎"。

#### 案例 9：Obsidian（2020 起，2 人起步 → 7 人，零融资）

- **作者**：Erica Xu（现任 COO）与 Shida Li（现任 CTO），滑铁卢大学校友。
- **起点**：**2020 年初**（Y Combinator 校友背景），两人起步。
- **规模（2026 年报道口径）**：团队 **7 人（"7 人 1 猫"）**，**月活超 150 万**，**年经常性收入约 2,500 万美元**，**估值约 3.5 亿美元**，**零外部融资**。
- **对阙疑的直接含义**：**"极小团队 + 零融资 + 付费产品"是成立的商业路径**（对应方向 87/88）。⚠️ **但 Obsidian 是面向个人知识管理的 C 端产品，与阙疑的 B 端/学术定位不同，不能直接类比**。

### 二、论文型成果（3 个案例）——与阙疑的"研究"目标同构

#### 案例 10：Yitang Zhang（张益唐，2013）——"无影响力者"的终极案例

- **背景**：**2013 年 4 月**，**新罕布什尔大学**（University of New Hampshire）的**讲师/临时教职**张益唐，向 **《Annals of Mathematics》** 投稿。
- **结果**：证明了**素数间有界间隙**（bounded gaps between primes）——存在无穷多对素数，其间距不超过 **70,000,000**。**这是孪生素数猜想方向的第一次实质性突破**。
- **传播路径**：**投稿后数月内，Polymath8 协作项目把上界从 70,000,000 压到 246**；2014 年他获得 **MacArthur Fellowship（"天才奖"）**。
- **关键细节**：他**没有强力导师、没有顶级机构、长期默默无闻**，**唯一做对的事是把结果投给了最严的期刊**（Annals 是数学四大顶刊之一）。
- **对阙疑的直接含义**：**"把结果投给最严的 venue"是弱势者的最优策略**——因为严 venue 的审稿人**只看结果，不看你的头衔**。这直接支持"投 NeurIPS E&D 而非投一个水会"的判断（对应方向 16）。

#### 案例 11：Thomas Royen（2014）——"差点被埋没"的案例

- **背景**：**2014 年 7 月 17 日早晨**，德国**退休统计学家**（曾是企业统计工作者）Thomas Royen 在刷牙时想到证明思路。
- **结果**：证明了困扰学界多年的 **Gaussian Correlation Inequality（高斯相关不等式）**。
- **传播路径（最重要的教训）**：**他 2014 年就完成了证明，但因为"没人相信一个无名退休者"，论文被忽视近三年**；直到 **2015 年 12 月他把证明放到 arXiv（1512.08776）**，并被他人（Latała、Matlak 等）整理确认后，才在 **2017 年 3 月由 Quanta Magazine 报道**而广为人知。
- **对阙疑的直接含义**：**"结果正确"不等于"被承认"；传播通道是独立的一环**。阙疑必须提前准备：**arXiv 预印本（对应方向 13）+ 一条能被 HN/Reddit 讨论的"可复算的单一数字"**（例如"外部 corpus 43.8% 检出率，且附一键复算脚本"）。

#### 案例 12：Grigori Perelman（2002–2003）——极端的单人案例

- **背景**：**2002 年 11 月至 2003 年 7 月**，Perelman **把三篇论文直接张贴在 arXiv 上**（不是投期刊），宣称解决 **Poincaré 猜想**。
- **结果**：**2006 年他拒绝接受 Fields Medal**；**2010 年 Clay 研究所授予他 100 万美元千禧年大奖，他同样拒绝**。
- **对阙疑的直接含义**：⚠️ **这个案例的"拒绝荣誉"部分完全不可复制，不要模仿**。可复制的是：**"先把完整证明/完整工件公开，让世界自己验证"**——这正是阙疑"独立对账器"的哲学同源。

### 三、补充案例（作为边界条件）

#### 案例 13：Zig（2016 起，Andrew Kelley）——"十年不发 1.0"的对照

- **起点**：**2016 年**由 Andrew Kelley 发起。
- **2026 年状态**：**十年仍未发布 1.0**；**明确限制 AI 生成代码的贡献**；**2026 年基金会规模约 67 万美元**；**2026 年离开 GitHub 自建托管**。
- **对阙疑的直接含义**：**"不追求 1.0、不追求增长"也可以长期存活**——但代价是**必须接受"小众 + 低资金"**。这给阙疑提供了一个"最低维持模式"的模板（对应方向 91/99）。

#### 案例 14：Hypothesis（David R. MacIver，单人）——与阙疑最同构的案例

- **作者**：David R. MacIver（单人创建并长期主导）。
- **产物**：Python 的**属性测试（property-based testing）**库 Hypothesis。
- **结果（关键）**：**2019 年在《Journal of Open Source Software》(JOSS) 发表软件论文**，论文中写明 **"over 100,000 downloads per week"**。
- **对阙疑的直接含义（本方向最有价值的一条）**：**"一个测试/验证工具 + 一篇 JOSS 论文"是双非本科生完全可以走通的路径**。JOSS 是 **ISSN 2475-9066 的正式学术期刊，有正式同行评审流程**，**审稿标准是"软件本身"而非"新颖性"**（原文口径：**"Submissions that implement solutions already solved in other software packages are accepted into JOSS provided..."**——即**不要求新颖**）。→ **阙疑应该把 JOSS 作为 NeurIPS E&D 之外的"保底学术产出"**。

#### 案例 15：Andreas Madsen（2019/2020）——独立研究者进顶会

- **背景**：丹麦技术大学本科+硕士毕业后，**求职与申博屡屡失败**，决心做**独立研究员**（无导师、无经费、无机构）。
- **结果**：**2019 年底论文被 ICLR 2020 接收，并获得 spotlight**；另在 **Distill.pub** 发表。
- **对阙疑的直接含义**：**"无机构"不是投稿的硬障碍**（NeurIPS/ICLR 不要求机构隶属）。**真正的障碍是"没有合作者帮你扛审稿意见"**——所以阙疑需要提前准备"单人 rebuttal 策略"（对应方向 06）。

#### 案例 16：Bartosz Ciechanowski（个人博客）——"传播资产"的案例

- **形态**：波兰工程师**一人**维护的交互式科普博客（齿轮、机械表、GPS、月球等十余篇）。
- **结果**：被技术社区长期反复讨论与推荐（CSS-Tricks 等站点专文推荐），成为"个人品牌"的样板。
- **对阙疑的直接含义**：**一个高质量的可交互页面 = 一个永久有效的传播资产**。阙疑已有 `web/starmap.html` / `verify.html`（现场验哈希）——**这比论文更能带来"被看见"**。

### 四、把 16 个案例压成"成功条件表"

| 条件 | 出现次数（/16） | 阙疑当前是否具备 |
|---|---|---|
| 解决一个**被明确命名**的窄问题 | 12 | ⚠️ 未命名（建议："验证的独立性危机"） |
| 产物是**可被机器验证**的工件 | 13 | ✅ 对账器 + 哈希链 |
| 有**免费传播渠道**（GitHub/arXiv/博客） | 14 | ⚠️ 仓库未公开传播（0 影响力） |
| 作者能**全职或半全职**投入 ≥2 年 | 11 | ⚠️ 与考研冲突（方向 67） |
| 踩到**一次性外部事件** | 3 | ❌ 不可控 |
| 有**机构/公司/基金会**支撑 | 9 | ❌ 无 |
| 作者**已财务自由或另有收入** | 5 | ❌ 不适用（这正是风险点） |

→ **结论：阙疑在前 4 条上具备 2 条、部分具备 2 条。缺口集中在"命名"和"传播"，而不是"技术"。**

## 对阙疑的 3 条具体行动

1. **给问题命名，并把命名写进 README 第一行和论文标题（本周内）**：
   - 建议命名：**"验证的独立性危机"（the independence crisis in verification）**，一句话定义：**"当验证器与生成器同源时，验证结果无法被独立验收。"**
   - **落地文件**：`README.md` 第一段（**注意：本方向不修改仓库，仅给出建议文本**）+ 论文 v0.4 标题。
   - **验收标准**：找 3 个不了解项目的人读第一段，能各自复述出"它解决什么问题"。
   - **理由**：nginx 用 "C10K"、Ruff 用 "replace N tools, 10x faster"、llama.cpp 用 "run LLaMA on a MacBook"——**成功案例都有可复述的一句话**。

2. **把 JOSS 作为"保底学术产出"，2027-02 前完成投稿准备**：
   - **为什么**：JOSS 是 **ISSN 2475-9066** 的正式期刊，**审稿看软件质量而非新颖性**，**不要求机构隶属**，**Hypothesis（一个测试库）就发在 JOSS**。
   - **准备清单**：① `CONTRIBUTING.md` + 安装/使用文档；② 完整测试套件 + CI 徽章；③ 一篇 `paper.md`（JOSS 格式，约 250–1000 词）；④ 公开仓库 + 归档到 Zenodo 拿 DOI。
   - **时间点**：2026-12-31 前完成 ①②④；2027-02-28 前投 JOSS。**JOSS 通过后，再以"已被 JOSS 接收的软件"身份投 NeurIPS E&D**（软件论文可作为 E&D 的 artifact 支撑）。

3. **建一个"传播资产"并设定传播检验点**：
