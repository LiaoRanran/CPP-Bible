# 方向 87：单人开源项目收入来源

> 调研时间：2026-09-29（GMT+8）
> 锚点项目：**阙疑 / queyi** —— C++ 知识验证器（37 实卡 / 67 规则 / 盲 holdout 30 真错 17 / 外部 corpus 40）
> 作者画像：双非本科生，合肥，嵌入式，0 影响力，单人项目
> 联网检索：12 次 WebSearch + 4 次 WebFetch（含 curl 2025 财报、Caleb Porzio 一手长文、Tidelift 2024 调查原文）

---

## 核心结论

1. **开源收入的真实分布是「长尾极长、头部极窄」：Tidelift 2024 年对 400+ 维护者的调查显示，47% 的维护者拿不到一分钱、32% 能拿到「来自某个组织或个人的收入」、只有 25% 拿到捐赠平台的钱、只有 5% 拿到公司直接付款**；任何把「开源 = 能养活自己」当默认假设的计划都是错的。
2. **单人项目唯一被反复验证可行的高收入路径不是「接受捐赠」，而是「用开源做获客、把付费放在内容/托管/支持上」**——Caleb Porzio 的一手数据：纯赞助只到 ~$40k/yr，加上「赞助者专属录屏」后 **90 天内从 ~$40k 涨到 >$100k/yr**（终值 **$112,680/yr**，535 名赞助者、$14/月档）。
3. **对阙疑而言，2027 年之前现实的收入天花板是「三笔小额、互不依赖的钱」：一次 NLnet/OTF 类 grant（€5k–€15k）+ 一个 GitHub Sponsors 页面（大概率 < $1,000/年）+ 一到两份 C++ 验证方向的付费咨询/审计合同**；把「SaaS」或「双重许可」写进 2027 计划是不现实的，因为阙疑的实测规模（37 实卡、0 付费用户）距离能支撑 SaaS 的最小用户量差 3–4 个数量级。

## 精确数字与案例

### 一、先看基本盘：开源维护者到底能拿到多少钱

Tidelift 在 2024 年中期做的第三次维护者调查（**样本：400+ 名维护者**；其中 **70% 不是 Tidelift 的合作维护者**，即样本未被 Tidelift 自家用户污染）给出了目前最权威的分布。原文（`dev.to/tidelift`）关键数字：

| 收入来源 | 2021 | 2023 | 2024 |
|---|---|---|---|
| 完全拿不到钱（"I don't get paid to maintain projects"） | 46% | 46% | **47%** |
| 从「另一组织/个人」（Tidelift / GitHub Sponsors / 基金会等）拿到钱 | 32% | 31% | **32%** |
| 雇主薪资（维护是本职工作的一部分） | 27% | 28% | **24%** |
| 捐赠类项目（GitHub Sponsors 等） | 16% | 24% | **25%** |
| Tidelift | 15% | 16% | **19%** |
| 公司直接付款（非雇主） | — | — | **5%** |
| 个人直接付款 | 10% | 5% | **5%** |
| 开源基金会 | 3% | 3% | **3%** |
| 政府/公共机构直接付款 | — | — | **1%** |

同一份调查还有一个「问法差异」的实证：当被强制单选时，**60% 的维护者把自己归为「unpaid hobbyist」**；但当允许复选收入来源时，**只有 47% 说完全没拿到钱**——**13 个百分点的差额**说明「有一点点钱但不足以改变身份认同」是常态。原文对此的解释是："Some maintainers who consider themselves unpaid hobbyists probably only receive a nominal amount of income and not enough for them to begin to think of themselves as semi-professional or professional maintainers."

同一调查里另一条被反复引用的数字（Tidelift CEO Donald Fischer 语，见 Socket 报道）：**"Paid maintainers are 55% more likely to implement critical security and maintenance practices than unpaid maintainers."** 这条对阙疑的**论文叙事**比对付钱更有价值：它给了「给维护者付费 → 软件更安全」的因果链条一个可引用的一手数字。

### 二、案例 A：curl —— 单人主导项目的真实财务（最贴近阙疑的形态）

curl 是「一个人 + 几个核心维护者」的最成熟样本。2025 年度的收支（中文技术媒体转述 Daniel Stenberg 年度回顾，数据源为 curl 在 **OpenCollective** 上公开的账目）：

- **2025 年总收入：约 $58,193**。最大单笔赞助来自 **Elastic，$6,000**。期末可用余额 **$113,000**。
- **2025 年总支出：约 $67,002**（支出大于收入，靠历年结余补）。
- **支出中 85% 发放给核心维护者**；核心维护者 **Dan Fandrich 全年收入 $14,000**。
- 其中 **$2,619** 是通过 **GitHub Secure Open Source Fund** 的名义付给 Dan Fandrich 的。
- 其余支出：**$3,666** 买一台 Framework 笔记本、**$7,000** 差旅费、少量基础设施费用。
- 赞助形态四种：(a) 企业级月付（Elastic 为金牌赞助商）；(b) 小额月付（约 **$5/月**）；(c) 专项资金（2025 年为买 Framework 笔记本单独立项筹款）；(d) 基金赞助（GitHub Secure Open Source Fund）。
- **个人赞助者案例：Wei Ming（MiniTool COO）累计赞助 $11,250。**
- 另一个近期单笔：**CodeRabbit 以 $1,000/月 赞助 curl 项目**（Daniel Stenberg 本人 LinkedIn 公布）。

**阙疑可以从 curl 学到的最重要一条**：curl 的**总收入约 $58k/年**，但要养活「1 个主导者 + 若干核心维护者」——**人均远低于一份正常工程师薪水**。curl 之所以还能运转，靠的是 Daniel Stenberg 本人的知名度与 curl 的行业地位；阙疑两者都没有。

### 三、案例 B：Caleb Porzio —— 单人项目从 $0 到 $112,680/yr 的完整路径（唯一有一手拆解）

这是检索到的**唯一一篇由本人完整披露金额与方法的单人开源收入长文**（`calebporzio.com`，2020-06）。关键数字：

- **起点**：2018 年他在 Tighten 的薪水约 **$90k**；2019-01-11 离职做开源，**当年主动降薪约 $70k**，靠小规模代码咨询撑着。
- **GitHub Sponsors 开通日：2019-12-12**。GitHub 当时的政策原文（他本人引用）：**"They match the first $5k, and they take a ZERO percent cut."**
- **终值：$112,680/yr**，**535 名赞助者，最低档 $14/月**。
- **三段式增长**：
  - **Phase 1（纯善意赞助）**：只到 ~$40k/yr 之前的部分。他的原话："there aren't that many of them compared to the number of people actually using the software"。
  - **Phase 2「Sponsorware」**：把一个小 Laravel 包先只给赞助者，达到一定赞助人数后再开源。**效果：几天内年收入 +$11k**。
  - **Phase 3「赞助者专属录屏」**：先放免费基础录屏 → 文档里挂链接 → 几周后加一批「仅赞助者可见」的进阶录屏（用 Laravel + GitHub OAuth 校验赞助状态）。**效果：~90 天内年收入从 ~$40k 涨到 >$100k，即 +$80k**。他称这是"the single most impactful idea I have EVER had"。
- **他给的四条可操作建议**（原文）：(a) **定价要够高**——"The biggest mistake people make with GitHub sponsors is offering too small of a first tier. If people have the option of paying $1-5/mo. instead of >$14, they will pay the lesser amount."；(b) **档位名字按「用户类型」而非「金属等级」命名**（用 "The Agency" 而不是 "Platinum"），引导企业思考「我是哪类用户」而不是「我想花多少钱」；(c) **必须建受众**——"Twitter followers and email subscribers are your most valuable asset"；(d) **不要怕公开谈钱**——他本人因同事透露薪资而涨过 **$10,000**。

**阙疑可以从 Caleb 学到的最重要一条**：他的钱 **80% 来自「教学内容」，不是来自「软件本身」**。这直接指向阙疑的一个具体机会：**把 67 条规则（block 44 / warn 16 / advice 7）做成「C++ UB 与编译器行为」的付费教学内容**，而不是指望别人为验证器本身付钱。

### 四、案例 C：GitHub Sponsors 的平台级规模（用来校准期望）

- **累计发放 > $1 亿美元**，涉及 **> 28 万名赞助者**、**> 7 万个接受方**；时间点 **2026-07-20**（GitHub 官方博客，中文技术媒体转述）。
- 费率（GitHub 官方文档原文）：**"GitHub Sponsors does not charge any fees for sponsorships from personal accounts, so 100% of these sponsorships go to the [developer]"**；组织账户赞助最高抽 **6%**。
- 企业端案例：**Shopify** 等公司已开始大规模资助其依赖的开源项目。

**算一笔账**：$100M ÷ 70,000 接受方 = **人均累计约 $1,429**（注意这是 2019–2026 共 7 年的累计值，不是年值）。**这就是「单人开源项目靠 GitHub Sponsors」的现实量级：七年一千多美元。** 阙疑必须把这个数字刻在心里，才不会对赞助收入产生幻觉。

### 五、案例 D：双人/小团队项目的收入天花板（作为「做公司」的参照）

| 项目 | 收入数字 | 时间点 | 来源 |
|---|---|---|---|
| **Supabase** | ARR **$70M** | 2025-08（Sacra 估算） | Sacra |
| **Supabase** | ARR **~$101M**（2025 年底）→ **$170M**（2026-05，Sacra 估算）；融资 **$100M @ $5B 估值** | 2025-10-03 | PR Newswire / Sacra |
| **PostHog** | ARR **~$50M**；估值 **$1.4B**（2025-09 Series E） | 2025-10 | ARR Club / GrowthHunt |
| **Cal.com** | 营收 **$5.1M**（2024）→ ARR **$10M** | 2024 / 2026-08 | GetLatka / ARR Club |
| **Tailwind Labs** | 2024 年营收 **$3.6M**（2023 年 **$1.9M**）；同时**工程团队裁员 75%** | 2024 | GetLatka / OpenSourceForU |

⚠️ **Tailwind 的数字存在来源冲突**：OpenSourceForU（2026-01-14）称「营收骤降近 80%，跌至 2024 年 $3.6M」，而 GetLatka 记录 2023 年 $1.9M → 2024 年 $3.6M（即**上升**）。两个口径无法调和，**本文不采信任一方**，仅并列呈现。可采信的部分是：Tailwind Labs **裁员 75%**，创始人公开归因于 AI 改变了其商业模式（付费文档/课程需求被 AI 替代）。

**对阙疑的含义**：即使做到 Supabase / PostHog 这种量级，也是「双人起步 + YC + 数轮融资 + 数年」的结果；Cal.com 用了约 3–4 年做到 $10M ARR。**阙疑是单人、0 影响力、2026-09 起步——2027 年不可能到这个区间。**

### 六、案例 E：非捐赠类收入的六条真实路径与量级

**（1）双重许可（Dual Licensing）** —— 最经典但门槛最高的路径。三个真实案例：**MySQL**（GPL v2 + 商业许可，被 Sun 以约 **$1B** 收购，Sun 又被 Oracle 收购）；**Qt**（GPL/LGPL + 商业许可，Digia/The Qt Company 运营）；**Sleepycat / Berkeley DB**（Sleepycat License，被 Oracle 收购）。共同前提是：**有一个大量商业公司想闭源嵌入的核心库**。阙疑的 67 条规则与 `gate_engine.py`（3826 行）是内部工具链，**不存在「公司想闭源嵌入」的需求**，因此双重许可对阙疑在 2027 年前不成立。

**（2）合同/咨询** —— 最稳的一条。curl 的支出结构说明问题：企业愿意为「核心维护者」付钱，但走的是**赞助**而非咨询合同。对阙疑，更现实的是**C++ 内存安全 / UB 审计咨询**：用 67 条规则（44 条 block 级）作为审计清单，按项目收费。**未查到**「C++ UB 审计」的公开报价区间，列为盲区。

**（3）SaaS / 托管** —— Cal.com（自托管免费 + 云版付费）与 Supabase（开源 + 托管）都是这条。前提是**有一个需要托管的运行时**。阙疑是「跑一次 gate 出判决」的批处理工具，**天然不需要托管**，这是结构性的不利。

**（4）Bounty（漏洞赏金）** —— 平台级数字：**HackerOne 2025 年向白帽支付总额 $308M，同比 +35%**；Google 的 **OSS VRP** 有专门的开放源代码漏洞奖励规则页（`bughunters.google.com/about/rules/open-source/`），并在 **2026-03-19 更新过 OSS VRP 规则**（官方博客标题 "Streamlining Google's OSS VRP: Key Rule Updates"），目的是「filter out low-quality reports」。另有报道称 Google 的 VRP 在 15 周年时达到 **$17M 年度支出**（2026-04-07）。**对阙疑的适配性**：阙疑的 `data/defect_fixtures/defects.json`（15 条真实缺陷夹具，重注入检出 6/6=100%、历史覆盖 12/15=80%）在方法论上与「fuzzing 找 compiler bug」高度同源——**但 bounty 给的是「找到新漏洞的人」，不是「造了找漏洞工具的人」**，除非阙疑的规则真的抓到 GCC/Clang 的未公开缺陷。

**（5）课程 / 书籍 / 录屏** —— Caleb Porzio 的实证路径（见案例 B）。**这是对阙疑最现实的一条**：把「C++ UB 完整分类」「GCC/Clang/MSVC 行为差异」「编译优化级别对结果的影响」做成系列内容（对应本目录方向 26/27/28/30）。

**（6）平台型分配（Tidelift / thanks.dev / Open Source Pledge）** ——
- **Open Source Pledge**：成员公司承诺 **> $2,000/年/每名受雇工程师**，直接付给开源维护者与基金会（官网原文 "Our member companies pay >$2000/year/employed dev, directly to Open Source maintainers & foundations"）。**Sentry** 作为发起方之一，在 **2026-01-06** 的报告中披露当年向维护者支付 **$750,000**。
- **thanks.dev**：机制是「自动扫描下游厂商的依赖树 + 按比例分配」。**关键门槛（容易被忽略）**：thanks.dev 要求**维护者必须主动注册才能收到钱**——即「不注册 = 拿不到」。
- **Tidelift**：2024 年被 **Sonar 收购**（2024-12-18 宣布，金额未披露），收购后继续按订阅使用量与战略重要性向维护者付款。

### 七、把六条路径对阙疑打一次分

| 路径 | 阙疑可行性 | 现实年收入量级 | 依据 |
|---|---|---|---|
| GitHub Sponsors | 中 | $0 – $1,000 | 平台人均累计 $1,429（7 年） |

| 双重许可 | 极低（无嵌入需求） | — | 结构不匹配 |

## 对阙疑的 3 条具体行动

**行动 1（2026-10 月内，成本近零）：立刻开 GitHub Sponsors，但把档位设计成「内容付费」而不是「打赏」。**
具体做法：按 Caleb Porzio 的实证，**不要设 $1–$5 档**。设三档：**$7/月「Thanks」（无权益，纯善意档）**、**$14/月「Solo Dev」（解锁 C++ UB 逐条讲解录屏 + 67 条规则的设计理由）**、**$99/月「Team/Audit」（解锁用 67 条规则跑一次私有仓库的审计报告）**。第三档的名字刻意不用 "Platinum"，而用 "Team/Audit" 以引导企业自我归类（Caleb 的原文建议）。同时在 `README.md` 顶部放赞助按钮——**注意方向 86 的 GenAI 政策要求 README 公开声明 GenAI 使用方式，两件事可以写在同一节**。

**行动 2（2026-11 月至 2027-02，最高优先级）：把「67 条规则」变成可售卖的内容资产，先做免费部分拉受众。**
具体做法：以 `data/_gate_rules.json` 的 **44 条 block 规则**为骨架，做 **44 期免费短内容**（每期 3–5 分钟，讲一条 block 规则 + 一个真实 UB 例子 + 一段可在 godbolt/Compiler Explorer 上复现的代码），发布渠道优先选**英文平台**（Caleb 的实证是 Twitter + email list 最值钱；Reddit 的 r/cpp 与 r/cplusplus 是 C++ 受众集中地）。免费内容跑满 4 个月后再上 $14 档的进阶录屏——**顺序不能反**，Caleb 的原文是"if they like the free ones, they will sponsor me"。

**行动 3（2026-12 月前完成，与行动 1 同步）：注册 thanks.dev 与 Open Source Pledge 的被资助方名录，并给 curl 式的财务透明化做准备。**
具体做法：(a) 在 **thanks.dev** 完成维护者注册（**不注册就拿不到钱**，这是硬前提）；(b) 在仓库建 `FINANCE.md`，公开记录每一笔收入与支出——**curl 之所以能持续收到赞助，核心原因就是它在 OpenCollective 上公示每一笔款项**（"为了保持财务透明，curl 通过 OpenCollective 公示收到的每一笔款项"）；(c) 若未来有 501(c)(3) 或欧洲 fiscal host 需求，参考 Open Collective 的费率结构（**fiscal host 通常收 4–10% 的 host fee**，平台费可选）。

## 盲区（诚实标注）

1. **Tailwind 的收入数字存在来源冲突**：OpenSourceForU（2026-01）称「营收跌至 $3.6M，降幅近 80%」，GetLatka 记录 2023 年 $1.9M → 2024 年 $3.6M。**两方口径无法调和，本文不采信任何一方**。可采信的只有「裁员 75%」这一条。
2. **curl 的 $58,193 / $67,002 / $113,000 三个数字均为中文技术媒体转述**，本次未直接抓取 OpenCollective 上 curl 的原始账页（`opencollective.com/curl`）逐笔核对。列为待核实。
3. **C++ UB 审计 / C++ 验证咨询的公开报价未查到**：本文无法给出「一次 C++ UB 审计收多少钱」的数字，任何此类数字都将是编造。
4. **GitHub Sponsors 的 $100M / 28 万赞助者 / 7 万接受方是 2026-07-20 的累计快照**，不是年值；本文的「人均累计 $1,429」是**用总量除以接受方数量得到的算术均值**，不代表中位数（真实中位数必然远低于均值）。
5. **Sonar 收购 Tidelift 的金额未披露**：本文只能写「未披露」，不能推测。
6. **HackerOne 的 $308M 是全平台总额**，未拆分到「C/C++ 编译器/运行时相关漏洞」的子类；阙疑能从 bounty 拿到多少，本文无数据。
7. **「赞助者专属录屏」的转化率未核实**：Caleb 只公布了收入结果（+$80k/90 天），**未公布**免费录屏的观看量、转化率、$14 档的续订率。因此「同样的方法对阙疑有效」是**外推，不是实测**。
8. **所有金额均为名义值**：未做通胀调整，未扣除各国税负（MOSS 官方 FAQ 明确写 "Recipients are responsible for determining the tax implications of receiving an award"）。
