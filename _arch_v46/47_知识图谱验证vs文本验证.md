# 方向 47：知识图谱验证 vs 文本验证

> 调研时间：2026-09-29。联网检索 12 次（WebSearch 8 + WebFetch 4）。
> 锚点：阙疑已有 `knowledge_graph.db`（知识图谱）与 `propositions.db`（命题网络）。本方向回答一个非常具体的问题：**把判决建在图上，到底比建在文本上贵多少、准多少、什么时候会翻车。**

## 核心结论

1. **在"证据本身是结构化三元组"的任务上，图验证对文本验证是碾压性的**：`FactKG` 上，纯文本/无子图基线 BERT 68.99%、GEAR 基准 77.65%，而加了 **single-step 子图的 BERT 做到 93.49%**（arXiv:2408.07453）；但**一旦证据要从自然语言里现抽**（HotpotQA/NQ 这类），GraphRAG 相对朴素 RAG **普遍打平甚至更差**，且 token 成本是 **2.7–4.5 倍**（arXiv:2502.11371）。**分界线是"图是否已经存在"**。
2. **图验证的致命弱点是"图不完整"和"多跳"**：`Fact or Fiction?` 自承 **Direct 子图检索只有 49.0% 的图非空、Contextual 只有 62.5%**；RAG vs GraphRAG 评估显示 HotpotQA 上**只有 65.8% 的答案实体存在于所构建的 KG 中**，NQ 只有 65.5%。而多跳是图上最难的类型：最佳模型在 FactKG 的 Multi-hop 上只有 **80.32%**，远低于 one-hop 的 97.40%。
3. **对阙疑的正确姿势不是"二选一"，而是"图做断言、文本做溯源"**：混合策略（Selection/Integration）在 MultiHop-RAG 上把 65.77 提到 **77.62（+6.4 点）**，但 token 涨到 13,401。阙疑的 67 条规则本质是**显式图推理程序**——EMNLP 2025 的 PGR 用同一思路（把推理写成"预定义函数组成的图推理程序"）在 FactKG 上拿到 **86.82% SOTA**。**这是阙疑最该抄的一篇。**

## 精确数字与案例

### 一、基准起点：FactKG 是什么

- 论文：`FactKG: Fact Verification via Reasoning on Knowledge Graphs`，Kim 等，ACL 2023 long paper，arXiv:2305.06590；仓库 `github.com/jiho283/FactKG`。
- 规模：**108,000 条自然语言声明**（常引作 108,370 或 108k），基于 **DBpedia** 构建。
- 五种推理类型：**One-hop / Multi-hop / Conjunction / Existence / Negation**。
- 证据形式：**知识三元组构成的子图**（如 `Meyer Werft — location — Papenburg`）。
- 意义：这是"图验证"唯一一个**有标准测试集、有 SOTA 榜单、有可比数字**的赛道。阙疑若要论证"图验证"的价值，FactKG 是必须引的锚点。

### 二、图验证能有多准：`Fact or Fiction?` 的对照表

- 论文：`Fact or Fiction? Improving Fact Verification with Knowledge Graphs through Simplified Subgraph Retrievals`，arXiv:2408.07453（2024-08-15；FEVER workshop 2024，ACL Anthology `2024.fever-1.32`）。代码 `github.com/Tobias-Opsahl/Fact-or-Fiction`。
- 数据集划分：FactKG 训练:验证:测试 = **8:1:1**；DBpedia 完整版 **1.53 GB**（论文用精简版）。
- 准确率对照（同一测试集）：

| 模型 | 是否用 KG 子图 | 准确率 |
|---|---|---|
| FactKG BERT Baseline | 否 | **65.20%** |
| FactGenius RoBERTa Baseline | 否 | **68%** |
| BERT（本文，无子图） | 否 | **68.99%** |
| FactKG GEAR Benchmark | 是（基准） | **77.65%** |
| QA-GNN (single-step) | 是 | **78.08%** |
| FactGenius RoBERTa-two-stage | 是 | **85%** |
| **BERT + single-step 子图** | 是 | **93.49%** |

- **净增益：68.99% → 93.49%，+24.5 个点**（同一 backbone，唯一变量是有没有给图）。
- 分类型准确率（BERT single-step）：One-hop **97.40%**、Conjunction **97.51%**、Existence **97.31%**、Negation **92.54%**、**Multi-hop 仅 80.32%（最差）**。
- **子图覆盖率（关键盲点）**：Direct 方法只有 **49.0%** 的图为非空；Contextual 只有 **62.5%** 非空。**即"图检索失败"接近一半时间会发生。**
- 训练效率：GEAR 基准 **2–3 天**（RTX 3090）；QA-GNN **1.5 小时**；微调 BERT（无子图）约 **2 小时**；微调 BERT（one-hop 子图）**10 小时**；FactGenius **8 小时**（A100 80GB）。
- GPT-4o 纯 prompt 基线（100 条测试样本）：25 题/次 **73.67% ± 0.5**、50 题/次 **76.33% ± 3.3**、100 题/次 **73.00% ± 1.4**——**明显低于 93.49%**。
- 参数量：BERT **109,483,778** 参数；QA-GNN **109,746,945** 参数。
- 预处理耗时：检索全部子图约 **15 分钟**，嵌入全部词约 **1 小时**。

### 三、2025 年的两条进阶路线（都可被阙疑直接借鉴）

**（1）PGR：把推理写成"图推理程序"——阙疑最该抄的一篇**
- 论文：`Fact Verification on Knowledge Graph via Programmatic Graph Reasoning`，Hao & Wu，**Findings of EMNLP 2025**，pp. 5480–5495，DOI `10.18653/v1/2025.findings-emnlp.293`。
- 核心：**把推理过程显式编码为"由预定义函数组成的图推理程序"**，函数顺序执行完成图推理与最终预测。
- 数字：FactKG 上 **86.82% 准确率，SOTA，优于全部基线**；作者强调"显式推理步骤比隐式 NLI 方法更精确、更透明"。
- **为什么这对阙疑是"同一物种"**：阙疑的 67 条规则（44 block）+ 四态判决 = 一个**手写的、显式的图推理程序**。PGR 用学术语言把这个做法命名了、评测了、拿到 SOTA 了。**阙疑的 Related Work 应当把 PGR 作为最接近的工作之一，并说明差异（PGR 面向英文 KG 事实验证，阙疑面向 C++ 语义 + 可独立验收账本）。**

**（2）ClaimPKG：轻量专用 LLM 生成"伪子图"**
- 论文：`ClaimPKG: Enhancing Claim Verification via Pseudo-Subgraph Generation with Lightweight Specialized LLM`，Pham、Nguyen、Bui，arXiv:2505.22552，2025-05-28（**ACL 2025 Findings**）。
- 做法：**用轻量专用 LLM 把文本声明转成"伪子图"表示** → 指导子图检索模块 → 通用 LLM 出最终判决与理由。
- 数字：FactKG 上比强基线**高 9%–12% 准确率点（跨多个类别）**；且**零样本泛化到 HoVer 与 FEVEROUS**（非结构化数据集）。
- **对阙疑的含义**：如果阙疑想让 LLM 参与，**正确形态不是"LLM 直接判卡"，而是"LLM 只负责把自然语言断言翻译成图查询"**——判决仍由确定性规则出。这与阙疑"独立对账器不依赖内核"的哲学一致。

### 四、图 vs 文本在"开放语料"上的真实账：RAG vs GraphRAG 系统评估

- 论文：`RAG vs. GraphRAG: A Systematic Evaluation and Key Insights`，arXiv:2502.11371（v2 2025-10-17）。
- 生成模型：Llama-3.1-8B-Instruct 与 Llama-3.1-70B-Instruct；图构建用 **GPT-4o-mini**（附录补 GPT-4o）。
- 对比：RAG、KG-GraphRAG（Triplets / Triplets+Text）、Community-GraphRAG（Local / Global）、HippoRAG2。

**准确率 / F1（关键行）**

| 数据集 | 指标 | RAG | Community-GraphRAG(Local) | HippoRAG2 | KG-GraphRAG(仅三元组) |
|---|---|---|---|---|---|
| NQ (8B) | F1 | **64.78** | 63.01 | 61.03 | 34.28 |
| NQ (70B) | F1 | **68.18** | 65.44 | 64.03 | 28.50 |
| HotpotQA (8B) | F1 | 60.04 | **61.66** | 63.01 | 25.02 |
| HotpotQA (70B) | F1 | 63.88 | 64.60 | **64.93** | 30.73 |
| MultiHop-RAG (70B) | Overall Acc | 65.77 | **71.17** | 69.87 | 50.98 |
| NovelQA (8B) | avg Acc | **57.12** | 53.03 | 56.54 | — |

- **结论 1（单跳）：RAG 赢**。NQ 上 RAG 68.18 vs 最好 GraphRAG 65.44；NovelQA 细节题 RAG 57.12 领先。
- **结论 2（多跳）：图赢**。HotpotQA 与 MultiHop-RAG 上 Community-GraphRAG(Local) 与 HippoRAG2 反超。
- **结论 3（时序）：图大赢**。MultiHop-RAG Temporal 类：RAG **25.73** vs Community-GraphRAG(Global) **59.18**。
- **结论 4（"应该答无答案"时图严重幻觉）**：MultiHop-RAG Null 类：RAG **91.36** vs Community-GraphRAG(Global) **13.95**——**图的全局摘要在"信息不足"时几乎必错**。这对阙疑的 `unknown` 态是直接警告。
- **结论 5（KG 图不完整）**：HotpotQA 上**仅 65.8% 的答案实体存在于所构建的 KG 中**；NQ 仅 **65.5%**。KG-GraphRAG 因此最弱（HotpotQA 30.73）。
- **结论 6（互补性）**：MultiHop-RAG 上 **13.6% 的查询只有 GraphRAG 答对，11.6% 只有 RAG 答对**。

**成本账（同一篇论文的表 26–29）**

| 项目 | RAG | Community-GraphRAG | KG-GraphRAG |
|---|---|---|---|
| 检索 token（MultiHop-RAG） | **3,631** | 9,770 | — |
| 检索 token（ODSum-Story） | **2,279** | 10,244 | — |
| 构建时间（MultiHop-RAG, 秒） | **135** | 5,560 | 7,702 |
| 检索时间（MultiHop-RAG, ms） | 1,724 | **1,249** | 14,434 |
| 存储（MultiHop-RAG） | 127 MB | 165 MB | 117 MB |
| Overall 准确率（70B） | 65.77 | 71.17 | — |

- **token 倍数：MultiHop-RAG 上 9,770 / 3,631 = 2.69 倍；ODSum-Story 上 10,244 / 2,279 = 4.49 倍。**
- **构建时间：Community-GraphRAG 5,560 秒 / RAG 135 秒 = 41.2 倍**（离线一次性）。
- **意外发现：Community-GraphRAG 的检索延迟反而最低（1,249 ms vs RAG 1,724 ms）**，因为它做的是直接实体匹配而非 LLM 实体扩展。
- **混合策略**（70B, MultiHop-RAG）：Selection 65.77 → **72.30**；Integration 65.77 → **77.62（+6.4 点）**，但 Integration 的检索 token 涨到 **13,401**、检索时间 2,973 ms。

### 五、一个必须写进论文 Threats 的发现：位置偏差

- 同一篇 `RAG vs GraphRAG` 明确报告：**LLM-as-a-Judge 存在显著位置偏差——把 RAG / GraphRAG 的输出顺序对调，会导致 LLM 做出完全相反的判断**（尤其 RAG vs GraphRAG-Local）。
- **对阙疑的含义**：阙疑若用 LLM 做任何"哪个更好"的对比评估，**必须做顺序对调的双盲**。这一条与方向 48（LLM-as-judge）互相印证。

### 六、KG 的"结构化断言"到底断什么：五种推理类型与三种子图

这一段回答阙疑最实际的问题：**如果把断言写成图上的查询，能覆盖哪些类型的断言？**

**（1）FactKG 的五种推理类型（对应五类可断言的问题）**

| 推理类型 | 含义 | 最佳模型准确率（BERT single-step） |
|---|---|---|
| **One-hop** | 单跳：A 的某属性是否为 B | **97.40%** |
| **Conjunction** | 合取：A 同时满足条件 X 与 Y | **97.51%** |
| **Existence** | 存在性：是否存在满足条件的实体 | **97.31%** |
| **Negation** | 否定：A 不具有属性 B | **92.54%** |
| **Multi-hop** | 多跳：A→B→C 的链式推理 | **80.32%（最差）** |

- **对阙疑的映射**：C++ 规则里的"类型/属性断言"（如"该变量是 `volatile` 的"、"该对象生命周期已结束"）属于 **One-hop/Existence** 档（97%+）；"跨函数的时序断言"（如"该锁在返回前必须释放"）属于 **Multi-hop** 档（80%）。**这意味着阙疑若把规则图化，跨函数/跨翻译单元的规则会显著掉点，必须在论文里单独标注这一层的置信度。**

**（2）三种子图检索方法的覆盖率（决定"图能不能用"）**

| 方法 | 定义 | 非空子图比例 |
|---|---|---|
| **Direct** | 仅含两端节点都出现在实体列表中的三元组 | **49.0%** |
| **Contextualized** | Direct + 关系词出现在声明中的三元组 | **62.5%** |
| **Single-step** | 所有从实体列表节点一步可达的三元组 | 效果最佳（未给覆盖率） |

- **关键洞察（原文）**：**"子图越大性能越好"**，且**"简化方法优于复杂方法"**——模型能自行过滤掉 single-step 子图中的无关信息。
- **对阙疑的含义**：**如果阙疑的 `knowledge_graph.db` 覆盖率低于 50%，那么"Direct 式"的图断言在一半以上的卡上会直接失败。** 这正是行动 1 要做覆盖率体检的原因。

**（3）混合事实核查的第三条路**

- `Hybrid Fact-Checking that Integrates Knowledge Graphs, Large Language Models`（arXiv:2511.03217，2025-11-05）：**把 LLM + 知识图谱 + 实时搜索 agent 三者整合**，提出混合事实核查框架。**这条路线的意义是：它承认单一证据源不够，必须"图 + 文本 + 搜索"三层并用。** 对阙疑的映射是"**规则（图）+ 引用原文（文本）+ 编译器实测（执行）**"三源并用，而不是在"图 vs 文本"之间二选一。

### 七、工程侧的"图税"批评

- 多篇 2025–2026 工程博客（`bestaiweb.ai`、`mnemoverse.com`、LinkedIn `Santosh Majety`、`aicoolies.com`）集中批评 Microsoft GraphRAG 的索引成本，其中 `bestaiweb.ai` 直接给出 **"$33K cost cliff"（3.3 万美元成本悬崖）**的说法。
- **⚠️ 这些是博客/二手来源，非同行评审，本报告只登记不采信具体金额。** 但方向一致：**GraphRAG 的痛点不在查询，而在索引**——这与 `RAG vs GraphRAG` 的构建时间 41 倍是同一结论的两种表述。

### 九、把成本账算到阙疑的规模上（外推，需谨慎）

RAG-vs-GraphRAG 的成本数据是**大规模语料**（MultiHop-RAG 的构建时间 5,560 秒 / 检索 9,770 tokens），直接外推到阙疑的小规模语料会失真。但可以做一个**比例外推**作为决策参考：

- 阙疑当前规模：**37 实卡 + 30 holdout seed + 40 外部 corpus = 约 107 个验证单元**。
- 若每个单元平均涉及 3 条断言、每条断言需要 5 个三元组作证据，则 `knowledge_graph.db` 需要覆盖约 **107 × 3 × 5 ≈ 1,600 个三元组**。
- 按 RAG-vs-GraphRAG 的 token 倍数（**2.69–4.49 倍**），**图路线的检索成本约为文本路线的 3 倍**；但阙疑的语料是**离线、确定性、可缓存的**（不像 RAG 每次都要现检索），**所以这 3 倍只体现在"图构建"的一次性成本上，不体现在每次判决上**。
- **结论（外推，非论文数字）**：**在阙疑这个规模上，"图 vs 文本"的成本差异几乎可以忽略；真正的瓶颈是"图的覆盖率"（Fact or Fiction? 的 Direct 49.0% / RAG-vs-GraphRAG 的 65.8%），而不是"图贵不贵"。** 因此行动 1 的覆盖率体检优先级高于任何成本优化。

### 十、把两个方向的证据合起来看

| 场景 | 图验证 vs 文本验证 | 证据 |
|---|---|---|
| 证据已是三元组（FactKG 类） | 图 **+24.5 点** | 68.99% → 93.49% |
| 证据需现抽（NQ 单跳） | 文本 **+2.7 点** | 68.18 vs 65.44 |
| 证据需现抽（Hotpot 多跳） | 图 **+1.1 点** | 64.93 vs 63.88 |
| 时序推理 | 图 **+33.5 点** | 59.18 vs 25.73 |
| "应判无答案" | 文本 **+77.4 点** | 91.36 vs 13.95 |
| 检索 token | 文本省 **2.7–4.5 倍** | 3,631 vs 9,770 |
| 索引构建 | 文本省 **41 倍** | 135 s vs 5,560 s |

- **一句话：图的价值与"图是否已经存在"严格正相关，与"是否需要判 unknown"严格负相关。**

## 对阙疑的 3 条具体行动

1. **把 `knowledge_graph.db` 的断言能力做一次"覆盖率体检"（可立即做）**：写 `tools/kg_coverage_666.py`，对 `data/holdout/holdout.json` 的 30 条 seed 与 `data/external_corpus/external_corpus_665.json` 的 40 条样本，逐条计算「该断言涉及的所有实体/关系是否都在 `knowledge_graph.db` 里」的**非空子图比例**。参照 `Fact or Fiction?` 的 **Direct 49.0% / Contextual 62.5%** 与 RAG-vs-GraphRAG 的 **65.8% 实体覆盖率**——**若阙疑的非空率低于 65%，说明"图验证"在阙疑当前数据上不可用，必须先在论文里承认，再决定是补图还是改口径。**
2. **按 PGR 的形态重述阙疑的方法论（写作层，零代码成本）**：把「67 条规则 → 四态判决」在论文 Method 中**显式表述为"预定义函数组成的图推理程序"**，并引用 PGR（EMNLP 2025 Findings, 86.82% on FactKG）作为最近的同类工作。**具体动作**：在 `_arch_v46/` 内（不改仓库其它文件）先写一页对照说明，列出「PGR 的 function 序列」与「阙疑 block 规则」的一一映射，作为论文 Method 草稿素材。
3. **为 `unknown` 态单独做一次反幻觉审计（高优先级）**：依据 RAG-vs-GraphRAG 的 Null 类结果（RAG 91.36 vs GraphRAG-Global 13.95），**图/摘要式推理在"应判无答案"时几乎必错**。阙疑有四态判决（含 unknown），**必须单独统计 unknown 态的误报**（把 unknown 错判成 block 或 pass 的比例），并写成 `tools/unknown_audit_666.py` 的检查项。若 unknown 态误报率显著高于其它三态，则应在论文中把 unknown 的适用边界写死。

## 盲区（诚实标注）

- **`Fact or Fiction?` 是 2024 年的 arXiv 预印本 + FEVER workshop 论文**，其 93.49% 是**单篇论文自报**，未在 FactKG 官方榜单独立复现；且其 BERT 是**针对 FactKG 微调**的，不是零样本。
- **FactKG 数据集规模有两个口径**：ACL 2023 原文写 **108k**，二手页写 **108,370**；本报告采用"108k（≈108,370）"，**具体精确值未逐字核对原始 pickle**。
- **PGR 的 86.82% 与 ClaimPKG 的"9–12 点"来自各自论文摘要**，两者**不在同一评测协议下**（PGR 未说明是否与 ClaimPKG 同 backbone），**不可横向比较**。
- **`$33K cost cliff` 是博客来源**，**未核实**，已在正文标注为不采信。
- **RAG vs GraphRAG 论文的 token/时间表（表 26–29）来自二手抓取摘要**，未逐行核对 arXiv 原文 PDF；**构建时间 41 倍、token 2.7/4.5 倍等比值是基于抓取到的数字自行计算**，可能存在口径差（如是否含 embedding 阶段）。
