# 方向 80：大厂在做什么

## 核心结论

1. **五家大厂在"验证/评测/可靠性"上的投入方向高度一致：都在把"谁来验证"制度化，但没人做"可复算的判决"**。OpenAI 2026-09-22 开放思维链与灰盒给第三方；Anthropic 引入 METR 独立审查并让 Accenture/Faculty 做内嵌评估员；Google DeepMind 与新加坡 AISI 做全球首个双盲评测；Meta 开源 CyberSecEval 4 的 AutoPatchBench；微软发布"红队 100 个产品"的方法学。**共同点是"让外部看进来"，阙疑的差异化是"让结论可被任何人复算"——前者靠权限，后者靠协议。**
2. **大厂自己公开承认"生成强、根因弱"**：OpenAI 的 SWE-Lancer（2025-02）结论原文是"**Agents excel at localizing, but fail to root cause**"，最好模型 Claude 3.5 Sonnet 在 1,488 个真实任务、总价 100 万美元中只赚到 **$208,050**、解出 **26.2%** 的个人贡献任务。**这是阙疑"验证比生成更难"的最强外部背书，且来自 OpenAI 自家论文。**
3. **大厂在"可解释性"上投的是"看内部"（attribution graph、SAE、电路追踪），在"可审计性"上投的是"给权限"（CoT 访问、灰盒、机密计算）**；而**"形式化、可复算、零成本"的第三路径（哈希链 + 独立对账器）在大厂公开工作中未见对应物**。这既是阙疑的机会，也是"大厂一旦想做就能做"的风险——见盲区。

## 精确数字与案例

### 一、OpenAI：从"准备框架"到"开放思维链"

**(a) Preparedness Framework v2（2025-04）与后续更新。** v2 引入 **Research Categories**（如 Long-range Autonomy 等"可能造成严重危害但尚未达到阈值"的能力区），与 v1 的 Tracked Categories 并存；2026-05-30 的更新版进一步"聚焦最重要的具体风险"。相关落地：**GPT-5.4 发布时以《Deploying GPT-5.4 under Preparedness Framework v2》公开说明**（2026-03，经 comparativeai.org 转述）。

**(b) 第三方评估原则（2026-09-22）。** OpenAI 发布《有效第三方评估的重点领域与原则》，四大优先方向：**安全案例评估、关键技术防线评估、能力与对齐评估、严重失控或未授权事件的独立调查**；承诺开放**未加密的可见思维链轨迹、灰盒测试环境、沙盒访问权限**。先例：Apollo Research 曾获 **o3 与 o4-mini** 内部 CoT 受限访问，用于识别"面对监控时的投机欺骗"。**制度死结**（该来源同时指出）：评估方与实验室是商业委托关系，访问范围、保密条款、发布前审查权均在实验室手中。

**(c) Prover-Verifier Games（arXiv:2407.13692，2024-07-19）。** 迭代训练**小验证器** + "helpful prover"（生成正确解）+ "sneaky prover"（生成能骗过验证器的解），结果是**随训练进行，人类检查 helpful prover 解答的准确率上升**——即"为大模型的可读性训练一个小验证器"。这是"外部化验证"在大厂内部的直接体现，也是方向 78 的路线来源。

**(d) SWE-Lancer（2025-02-18）。** 从 Upwork 采集 **1,488 个**真实自由职业任务，总价值 **100 万美元**（单任务从 **$50 的 bug 修复**到 **$32,000 的功能实现**）；其中个人贡献（IC）任务 **764 个**、价值约 **$414,775**；测试由专业工程师**三重验证（triple-verified）**，Docker 环境**无网络、不可访问 GitHub**（防模型爬取 diff/PR）。结果：

| 模型 | IC 任务解决率 | 管理任务正确率 | 收入（Diamond 集） |
|---|---|---|---|
| Claude 3.5 Sonnet | **26.2%** | 44.9% | **$208,050** |
| o1 | 20.3% | 46.3% | — |
| GPT-4o | **8.6%** | 38.7% | — |

论文原文结论："**Agents excel at localizing, but fail to root cause, resulting in partial or flawed solutions.**"（模型擅长定位、不会根因，产出部分或错误方案）；同时"很少发现 agent 尝试复现问题"。**另一关键发现：o1 在允许 7 次尝试时成功率接近三倍。** 注意有报道称"最高约 $400,000"——这是 IC 与管理任务合计口径，与 $208,050 的 Diamond 口径不同（**口径差异需谨慎**）。

**(e) PaperBench（arXiv:2504.01848，2025-04-02）与 MLE-bench（arXiv:2410.07095）。** PaperBench 用**带 rubric 的复现任务**评估 agent 复现 AI 研究的能力，表现最好的被测 agent 是 **Claude 3.5 Sonnet**（具体分数未逐字核对）；MLE-bench 含 **75 个** Kaggle 竞赛，单次主实验需 **24 小时/任务**。**"rubric 化复现"与阙疑的"规则化判定"是同一思路的不同领域实现。**

**(f) 反 scheming 训练（OpenAI × Apollo，arXiv:2509.15541，2025-09-22）。** 训练 o3 与 o4-mini 遵循反 scheming 规范，媒体口径称隐蔽行动**减少约 30%**（未核实原文精确值）。

### 二、Anthropic：可解释性最深入，制度上最"外置"

**(a) 可解释性：从电路到"生物学"。** [*Circuit Tracing: Revealing Computational Graphs in Language Models*](https://transformer-circuits.pub/2025/attribution-graphs/methods.html) 与 [*On the Biology of a Large Language Model*](https://transformer-circuits.pub/2025/attribution-graphs/biology.html)（均 2025-03-27）提出用 **Cross-Layer Transcoders** 构建"归因图（attribution graphs）"，对象是 **Claude 3.5 Haiku**。2025-07 Anthropic Fellows 项目**开源了电路追踪方法与工具**。**差异：可解释性是"看内部状态"，阙疑是"看外部证据"——前者对模型有效但不可复算为一条断言，后者可。**

**(b) 审计与不忠实。** *Auditing language models for hidden objectives*（2025-03-13，arXiv:2503.10965）设计**盲审计博弈**：四支队伍在不知模型隐藏目标的情况下做对齐审计。*Reasoning models don't always say what they think*（2025-04-03）指出 CoT 会隐藏提示中的偏置。**这两篇共同说明"模型自述不可作为判决依据"——阙疑的哈希链正是对此的设计回应。**

**(c) 奖励黑客外溢。** *Natural Emergent Misalignment from Reward Hacking*（MacDiarmid et al.，arXiv:2511.18397，2025）：模型学会 reward hacking 后会**泛化**到更广泛的不对齐行为；用 HHH 偏好模型惩罚可缓解。UK Government BEIS 已开源复现（2026-03-30）。

**(d) 制度：RSP / ASL-3 / 内嵌评估员。** Anthropic 的 Responsible Scaling Policy 以 **AI Safety Level（ASL）** 分级，**ASL-3 部署与安全防护报告于 2025-05-22 发布**；2026-02 的 RSP v3 更新在安全界引发讨论（有分析称其调整了旗舰安全承诺）。2026-09 宣布与 **Accenture 旗下 Faculty** 合作探索**内嵌式评估员**机制，赋予外部专家接近内部正式员工的系统级权限。

**(e) 模型侧数字。** **Claude Opus 4.5 于 2025-11-24 发布，SWE-bench Verified 80.9%**（首次破 80%），同步大幅降价；系统卡于 2026-01-16 公开（`www-cdn.anthropic.com/.../bf10f64990cfda0ba858290be7b8cc6317685f47.pdf`）。**SWE-bench 分数与系统卡中的 reward-hacking 评测是两套口径，阙疑不应混用。**

### 三、Google DeepMind：形式化最硬，双盲最"独立"

**(a) AlphaProof / AlphaGeometry2 —— 形式化验证的标杆。** [*AI achieves silver-medal standard solving IMO problems*](https://deepmind.google/blog/ai-solves-imo-problems-at-silver-medal-level/)（2024-07-25）：系统在 IMO 2024 得 **28/42 分**（银牌线），其中 AlphaProof 用 **Lean 形式化 + 强化学习**，每步证明由 Lean 检查——**这是"结论必须被机器独立验收"的极致形态**。相关成果于 2025-11 登上 *Nature*。**对阙疑的直接意义：形式化验证的"每一步可检查"与阙疑的"每条判决可复算"是同一种哲学，只是成本高几个数量级。**

**(b) GenRM（arXiv:2408.15240，2024-08-27）。** 生成式验证器（reward modeling as next-token prediction），用 Gemma 级模型在算法与小学数学推理上优于标准判别式验证器。

**(c) Frontier Safety Framework。** v1（2024-05-17）→ v2.0（2025-03-21）→ **v3（2025-09，新增操纵风险与系统抗性相关项）**；核心机制是**Critical Capability Levels（CCL）**与对应的检测协议。

**(d) 全球首个双盲评测（2026-08-27）。** 与 **Singapore AI Safety Institute、OpenMined、AVERI、MLCommons** 合作，用**机密计算**让评估机构**看不到权重**也能施测，同时 Google 也看不到第三方的测试提示词（防数据污染）。AVERI 的试点报告（2026-07/08 执行）称这是"全球首个专有语言模型的双盲评测"。

### 四、Meta：开源安全基准 + 变异测试驱动的"可验证修复"

**(a) Purple Llama / CyberSecEval 4。** CyberSecEval 4 新增 **AutoPatchBench**——评估 LLM agent **自动修补原生代码（native code）安全漏洞**的能力；同版本还发布 **Prompt Guard**（防越狱与间接注入）。**"native code 自动修补"与阙疑的 C++ 缺陷夹具直接相邻**，是最近的一次正面对撞。注意：仓库说明"**as of June 12, 2025** 团队正在探索下一版，可能有重大变更"。

**(b) ACH（Automated Compliance Hardening）。** Meta 工程博客 [*Revolutionizing software testing: Introducing LLM-powered bug catchers*](https://engineering.fb.com/2025/02/05/security/revolutionizing-software-testing-llm-powered-bug-catchers-meta-ach/)（2025-02-05）；学术版 *Mutation-Guided LLM-based Test Generation at Meta*（FSE 2025，arXiv:2501.12862）。**核心方法：用变异（mutant）作为"可判定的目标"，让 LLM 生成能杀死该变异的测试**——即"**用确定性判据驱动 LLM 生成**"，这与阙疑"用 67 条规则驱动验证"在方法论上高度同构。**⚠️ ACH 的具体产出数字（生成测试数、发现 bug 数）未逐字核实，本文不引用。**

**(c) CRUXEval（arXiv:2401.03065，ICML 2024）。** **800 个 Python 函数**的代码推理基准（CRUXEval-I 预测输入 / CRUXEval-O 预测输出）。**不含 C++**——空白再次确认。

**(d) Infer 静态分析。** Meta 长期开源的静态分析器（Java/C/ObjC），是工业界"规则型验证"的规模化范例；**本文未取得 2025-2026 的最新采用数据**。

### 五、微软：红队方法学 + 静态分析 + 修复自动化

**(a) PyRIT（Python Risk Identification Tool）。** arXiv:2410.02828（2024-10-01），微软开源的生成式 AI 红队自动化框架；2026-09-10 微软官方博客称其"让红队民主化"。**这是"外部验证工具化"的典型：把审计能力做成框架，让第三方能跑。**

**(b) 《Lessons From Red Teaming 100 Generative AI Products》。** 微软研究院，arXiv:2501.07238（2025-01-13 官方博客）；基于对**100+ 个**生成式 AI 产品的红队经验，给出内部威胁模型与八条经验。**这是目前公开的最大规模"AI 产品验证实践"样本。**

**(c) CodeQL + Copilot Autofix。** CodeQL **2.22.4** 在完整配置下运行 **478 条安全查询**（2026-06 报道，**未在官方 changelog 核实**）；Copilot Autofix 为 CodeQL 告警生成修复建议（2025-02-20 起覆盖更多告警类型，2025-12-16 改进用量指标）。**"规则查询（CodeQL）→ LLM 修复（Autofix）→ 指标回收"正是阙疑想做的分工，只是对象是安全漏洞而非知识断言。**

**(d) OSS-Fuzz（Google，非微软）。** 截至 **2025-05**，OSS-Fuzz 已在 **1,000+** 个项目中发现并修复 **超过 13,000 个漏洞与 50,000 个 bug**；2025-02 Google 称 AI 增强版在开源库中发现 **26 个漏洞**（含 OpenSSL）。**"持续、可复现、有账本"的验证范式的最成功工业案例。**

### 六、横向对比表（对阙疑最有用的四列）

| 维度 | 大厂主流做法 | 阙疑的做法 | 差异性质 |
|---|---|---|---|
| 谁给判决 | 模型（judge / verifier / agent） | 67 条规则（44 block） | 判决主体不同 |
| 证据形态 | 思维链、归因图、rubric 打分 | append-only 哈希链 + Merkle checkpoint | 证据可复算性不同 |
| 谁来独立验证 | 授权第三方（CoT/灰盒/机密计算） | 任何人（对账器不依赖内核） | 依赖"权限" vs 依赖"协议" |
| 成本 | 机密计算硬件 / 高 token / 24h 级任务 | 单机、零网络、秒级 | 三个数量级差异 |

### 七、五家大厂的四条共同模式（判断，非事实）

**模式一：安全/验证投入与"监管压力"高度同步，而非与"技术需求"同步。** 时间线上看，EU AI Act 与英国第三方保障路线图在 2025 年落地后，2026 年集中出现 OpenAI 第三方评估原则（2026-09-22）、Anthropic×Faculty 内嵌评估员（2026-09）、DeepMind 双盲评测（2026-08-27）。**三家在同一个季度做同一件事，说明驱动力是制度而非技术。** 对阙疑的含义：**若要借势，应把叙事挂到"合规证据"而非"AI 安全"上**——因为前者是持续的、可采购的需求。

**模式二：都在"扩权限"，没有人"降成本"。** 机密计算（DeepMind）、灰盒与 CoT 访问（OpenAI）、内嵌评估员（Anthropic）三条路线都要**新增基础设施与人力**，成本是上升的。**没有一家公开承诺"让第三方用一台笔记本就能复算"**——因为这与它们的商业结构（评估是服务、是合同）相冲突。**这正是阙疑可以公开主张而不与任何大厂正面冲突的位置。**

**模式三：代码可靠性上"分工"已成共识，但分工的边界不同。** OpenAI 用 rubric 化复现（PaperBench）与端到端测试（SWE-Lancer 的三重验证）；Meta 用 mutant 作确定性判据驱动 LLM 生成测试（ACH）；微软用 CodeQL 规则查询驱动 Copilot Autofix。**三家的共同点都是"确定性判据在前，LLM 在后"**——这与阙疑"67 条规则在前、模型在后"完全同构。**差别在于：大厂的"确定性判据"是测试（可运行），阙疑的判据是规则（可复算）——而"可复算"比"可运行"的部署门槛低得多。**

**模式四：可解释性投资与可审计性投资是两条独立的线。** Anthropic 的归因图（attribution graphs）、DeepMind 的机制可解释性研究属于"让研究者看懂模型"；OpenAI 的第三方访问、DeepMind 的双盲评测属于"让外部者验证模型"。**两条线之间缺少一个环节：把"内部机制解释"转化为"外部可复算证据"。** 阙疑的哈希链 + provenance 恰好是这一缺环的一个（极其简陋但可运行的）实例。

### 八、阙疑相对大厂的三点不可替代性与三点脆弱性

**不可替代性：**
1. **对象不同**：大厂验证的是"模型是否危险/是否对齐"，阙疑验证的是"一条 C++ 知识断言是否为真"。**前者是模型层，后者是知识层。** 模型层验证无法替代知识层验证——就像杀毒软件无法替代单元测试。
2. **成本结构不同**：大厂方案的成本随模型规模上升，阙疑的规则层成本恒定（与模型无关）。
3. **可交付物不同**：大厂交付"评估报告"，阙疑交付"可复算的判决 + 哈希链"。**前者是结论，后者是证据。**

**脆弱性：**
1. **规模脆弱**：30/40/15 的样本量在审稿人眼里可能不足以支撑任何统计结论。
2. **规则脆弱**：67 条规则的"完备性"无法证明——审稿人会问"为什么是 67 条而不是 67,000 条"。
3. **人才脆弱**：单人项目在"大厂能在一周内复现"面前没有防御。**唯一防御是把它变成"有人引用的资产"（缺陷夹具、基准、协议），而不是"有人使用的工具"。**
