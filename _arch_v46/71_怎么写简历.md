# 方向 71：怎么写简历

> 服务对象：双非本科（合肥、嵌入式方向、2026-09 起读大三、考研初试约 2027-12）
> 项目锚点：**阙疑 / queyi** —— 「可被独立验收」的 C++ 知识验证器
> 精确锚点（以 `_arch_v46/00_仓库扫描.md` 实测为准）：**37 实卡**（verified 23 / red-team-verified 3 / draft 11）+ 10 张 draft650 草稿；**67 条规则**（block 44 / warn 16 / advice 7）；**9 个保护器**；**452 条判决账本**；`tools/gate_engine.py` = **3826 行**；盲 holdout **30 seeds**（真错 17 / 对照 9 / unknown 4），reveal_3 检出率 **66.7%**（10/15 可测）；外部 corpus **40 条**（A 54.2% / B 12.5% / C 0%，总 43.8%）；缺陷夹具 **15 条**（重注入 6/6 = 100%，历史覆盖 12/15 = 80%）；反事实算子 **P = R = F1 = 0**（待修）。
> ⚠️ 全文数字口径以 `00_仓库扫描.md` 为准，**不要写 83 卡、不要写 813 行**。

---

## 核心结论

1. **简历不是"经历清单"，而是"筛选器适配文档"**：招聘方在初筛阶段的平均停留时间被反复测出在 **6–7.4 秒**量级（TheLadders 2012 测得 6 秒、2018 测得 **7.4 秒**，30 名招聘官、10 周眼动追踪），因此简历的结构（信息落点）比内容长度更决定生死——把最强的一条量化成果放在第一屏左上，比多写 500 字更有效。
2. **对双非本科生，简历唯一能自己掌控的变量是"可验证证据"**：学校/学历不可改，但 **GitHub 可复算的仓库 + 一个可复现的数字 + 一个可被追问到底的技术细节** 是可以在 12 个月内从 0 造出来的。阙疑恰好天然提供这三样（3826 行引擎 / 67 规则 / 66.7% 检出率 / 15 条缺陷夹具），问题只在于**怎么写才不显得 overclaim**。
3. **"没发表论文"不等于"没科研经历"**：保研/复试场景下未发表论文在初审环节含金量确实有限，但"问题—方法—贡献—成果"（或 APR：Action–Problem–Result）结构能把"未发表"写成"可验证的在研工作"；关键是**主动标注状态**（如 `under review / preprint / 未投稿`），而不是让读者自己去猜。

## 精确数字与案例

### 一、先看筛选器的物理约束：你到底有多少秒

TheLadders 2018 年眼动研究（30 名职业招聘官、10 周、数百份简历）给出的核心数字：

- **平均初筛停留 7.4 秒**（2012 年同一机构测得 **6 秒**）；
- 招聘官的注视被 **6 个固定点** 吃掉约 **80%** 的注意力，优先级依次为：**姓名 → 当前职位 → 当前公司 → 在职时间 → 上一份职位与公司 → 教育背景**；
- 阅读路径呈 **F 型**：第一横（姓名/标题）、第二横（当前经历）、然后沿左侧竖向快速下滑；
- 明确被忽略的区域：**第一页下三分之一（Very Low）**、**第二页（Almost None）**、**右侧栏（Low）**、**长段落（Skipped）**、**页面底部的技能栏（Minimal）**、**Objective 自我评价（Skipped）**。

必须诚实标注的**方法论缺陷**（这一点很重要，因为它决定了你能不能拿"7.4 秒"当铁律）：样本仅 **30 人**、岗位类型未披露、方法学未在同行评议期刊发表、发布方 TheLadders 是求职商业公司存在利益动机。**可辩护的部分**是 F 型扫描（Nielsen Norman Group 在网络内容上独立复现）与"左上象限占优"。

**给阙疑的直接推论**：你的简历第一屏左上必须出现"姓名 / 目标岗位 / 一句话定位（含数字）"。把"阙疑：可被独立验收的 C++ 知识验证器（67 规则、检出率 66.7%）"放在这个位置，而不是放在第三页的"项目经历 2"。

### 二、真实正反例（技术岗，来自公开拆解文章）

**反面例（"负责/参与"式，来自多个简历指南的汇总）**：

> "2018–2020 年，在 XX 公司担任 Java 开发，负责后端开发，参与多个项目。"
> "负责 XX 模块开发，使用 SpringBoot + MySQL 完成功能。"

问题诊断：**弱动词 + 无量化 + 无技术细节**。有指南直接指出：一份简历里出现 **8 次"负责"、5 次"参与"**，HR 会把你归类为"执行层"。

**正面例（STAR / 场景-方案-量化-延伸 四段式）**：

> **S**：电商大促期间订单处理延迟达 **3s**，数据库 CPU 负载 **95%**；
> **T**：负责缓存架构改造与 SQL 慢查询优化；
> **A**：引入 Redis 缓存热点商品数据、重构 5 条联表 SQL、新增复合索引 `(user_id, order_time)`；
> **R**：QPS 从 **1200 → 8500**，接口响应 **1200ms → 120ms**，大促期间 0 超时。

同源材料给出的其他真实数字：某游戏公司技术总监展示对比案例——同一候选人两版简历，增加"通过 JVM 参数调优使 GC 停顿时间从 **1200ms 降至 180ms**"后，**面试邀约率提升 4 倍**；有统计称"包含量化成果的简历面试邀约率提升 **47%**"、"包含 3 个以上量化指标的简历，HR 平均阅读时长增加 **23 秒**"。

⚠️ 后两组数字（47%、23 秒、4 倍）**来自二手商业内容平台（锤子简历 / Boss 直聘年报转述）**，我没有找到原始研究报告，**列为未核实**。但方向是对的：量化 = 可验证 = 降低读者的判断成本。

**必须警惕的造假红线**（来自同一批拆解）：把"使用过 Docker"写成"精通容器化技术"（面试两个底层问题就露馅）；把 6 个月项目写成 1 年（被问季度里程碑时回答矛盾）；声称"提升 3 个 9"却无法解释 SLA 计算方式。**面试官会追问到底，简历上每一个数字都是面试题。**

### 三、双非学历这一关：能查到什么、不能查到什么

**能查到的硬事实**：

- 华为 2024 校招目标院校共 **55 所** = **985 共 35 所**（39 所 985 中落榜 4 所：中国农业大学、西北农林科技大学、中国海洋大学、中央民族大学）+ **211 共 14 所** + **非 985/211 的双一流 3 所**（中国科学院大学、南方科技大学、南京邮电大学）+ **双非 3 所**（深圳大学、杭州电子科技大学、重庆邮电大学）。→ **"华为第一学历必须 985"是谣言，但双非只有 3 所入列，合肥本地院校未在名单内（我查到的 2024 名单中不含合肥高校）**。
- 有内容称杭州电子科技大学"近年有 **325 人**进入华为，其华为致远班实习转正率超 **60%**，本科入职定级 **13 级**，月薪 **19–21K**"。→ ⚠️ **这是单一自媒体来源（超级简历 WonderCV 转述），我未找到华为官方或杭电官方数据，列为未核实**。
- 华为校招流程（官方口径转述）：官网注册投递 → 简历通过筛选 → 上机考试 + 综合测评 → **2 轮专业面试 + 业务主管面试** → 次日官网查进展。

**一个真实双非案例（来源可查）**：广州某双非一本市场营销专业学生，无奖学金无项目，秋招海投美团/阿里/腾讯基本卡在简历筛选；调整策略后拿到 **基恩士、唯品会、字节跳动、京东等 6 家**的面试机会。**注意：这是非技术岗案例**，不能直接外推到嵌入式。

**我明确查不到的**：合肥本地双非院校（如合肥工业大学以外的安徽省属高校）在长鑫存储/京东方/蔚来的简历通过率数据、各公司 ATS 是否做学历硬筛的规则。→ **列入盲区**。

### 四、页数与格式：可执行的经验线

多家简历指南的共识线（2026 年内容）：

- **应届生 / 工作 3 年以内：一页为主**（"98% 的使用场景简历应当保持在一页"——知乎高赞回答口径，属经验值非实证）；
- **5 年以上 / 带过多个完整项目：两页常见**；
- 研发岗例外：有指南明确写"**研发、产品类岗位对页数更宽容**"。
- 格式细节（多源一致）：**PDF 投递**（避免 Word 版本乱码）；中文用微软雅黑/宋体、英文用 Arial/Calibri，**字号 10.5–12pt**；简历**文件命名规范**（"姓名-学校-岗位-电话"）被多个来源列为高频减分项。
- **ATS 关键词匹配**：技能栏是"唯一同时面向人类和机器"的模块，需要包含 JD 里的原词（如"Linux 驱动""RTOS""C++11/14/17"）。

**7 大高频减分项**（多源交叉，知乎《今年秋招被刷掉的简历长这样》等）：模板不符合阅读习惯 / 内容没体现能力 / 多余的自我评价 / 单纯罗列技能不看匹配 / 简历命名不规范 / 格式出错 / 照片该不该放。

### 五、技能栏：从"精通/熟悉/了解"升级为"技能 + 等级 + 证据"

有指南直接点破：**技能栏是简历里被"注水"最严重的板块，也是面试官最爱下手验证的板块**——"写'精通 Java'的应届生，面试官两个底层问题就能验出来"。

推荐的三层写法（"技能 + 等级 + 证据"），四档定义（了解 / 熟悉 / 熟练 / 精通）：

- ❌ `熟悉 C++`（无法验证）
- ❌ `精通 C++`（对应届生是负分，面试官会直接问 UB、vtable、`std::move` 语义）
- ✅ `C++（C++17）：实现 3826 行静态规则引擎，覆盖 67 条规则（44 block / 16 warn / 7 advice），可复现命令见仓库 README`
- ✅ `测试与验证：设计 15 条真实缺陷夹具，重注入检出 6/6（100%）、历史覆盖 12/15（80%）`
- ✅ `统计评估：构造 30 条盲 holdout（真错 17 / 对照 9 / unknown 4），报告检出率 66.7%（10/15 可测）并附 Clopper-Pearson 区间`

### 六、科研简历（CV）与工业简历（Resume）不是同一份东西

- **学术 CV**：侧重学术成就、教育背景、论文/预印本、学术会议、导师、技能与语言；结构上"**倒序列出所有学历，注明院校、专业、时间**"，风格沉稳，适合投高校/科研机构。
- **工业 Resume**：侧重项目产出、工具链、量化结果，**一页**。
- **科研经历的写法**：即使 0 发表，也可以用"问题—方法—贡献—成果"或 **APR（Action–Problem–Result）** 结构写。多个保研问答指出：**未发表论文在初审环节含金量有限**，招生老师主要看"目前成果"；但把"在研工作 + 可复现代码 + 明确的 claim 边界"写清楚，远好过编造"已发表"。
- **arXiv 预印本**：可写，但**必须标注 `preprint` / `arXiv:XXXX.XXXXX` / `under review`**，不得写成"已发表"。

### 七、把阙疑写进简历的三个版本（本方向的可复用产物）

**版本 A — 工业简历（嵌入式/软件岗，4 行）**

> **阙疑 queyi：C++ 知识验证器（个人独立项目，2025.xx–2026.xx）**
> - 独立实现 **3826 行**静态规则引擎（Python），内嵌 **67 条规则**（**44 block** / 16 warn / 7 advice），对 C++ 代码产出**四态判决**（含 evidence + provenance）。
> - 设计 **哈希链 + Merkle checkpoint** 的判决账本（**452 条**），并实现**不依赖内核的独立对账器**，使第三方可复算结论。
> - 构造 **30 条盲 holdout**（真错 17 / 对照 9 / unknown 4）与 **40 条外部 corpus**（A/B/C 三层），报告检出率 **66.7%**（10/15 可测）与 **43.8%**（A 54.2% / B 12.5% / C 0%），并**主动披露 C 层 0%**。
> - 注入 **15 条真实缺陷夹具**，重注入检出 **6/6 = 100%**、历史覆盖 **12/15 = 80%**；代码与复现脚本开源（GitHub: `<URL>`）。

**版本 B — 学术 CV（申研/复试，按"问题—方法—贡献—成果"）**

> **研究项目：可被独立验收的知识验证器（独立完成，2025–2027）**
> - **问题**：LLM 生成的 C++ 知识无法被低成本独立验收；现有评测依赖模型自评，标签效度不可控。
> - **方法**：以"外部效度优先"为设计原则，构建 67 条规则的内嵌引擎 + 四态判决 + 证据 provenance；引入盲 holdout 与分层外部 corpus。
> - **贡献**：给出可复算的评估协议，并把三类测量陷阱量化为可复现数字——**标签效度 / 检测器可用性 / 编译档**（`-O1 → -O0` 使 **3/5** miss 被同一 sanitizer 抓住）。
> - **成果（当前状态）**：盲 holdout 检出 **66.7%**（10/15 可测）；外部 corpus **43.8%**；论文 v0.3（117 行）；**状态：未投稿 / 目标 NeurIPS 2027 E&D**。
> - **诚实边界**：反事实算子当前 **P = R = F1 = 0**（未修）；内部变异率 **97.3%** 已**主动放弃**作为缺陷检测率口径。

**版本 C — 30 秒电梯陈述（面试开场/邮件正文）**

> "我做了一个 C++ 知识验证器，核心不是它多准，而是**它的结论可以被别人独立复算**——我把它拆成了 3826 行引擎、67 条规则、一个不依赖内核的对账器，还有 30 条盲 holdout；我现在能给出的诚实数字是 66.7%，而且我公开写了哪些地方是 0%。"

## 对阙疑的 3 条具体行动

1. **今天就把 `README.md` 顶部改成"简历可直接引用区"（≤15 行）**：固定五行数字块——`3826 行引擎 / 67 规则（44 block）/ 30 盲 holdout（检出 66.7%）/ 40 外部 corpus（43.8%）/ 15 缺陷夹具（6/6）`，每行后跟一条**一行可复现命令**（如 `python tools/gate_engine.py --check`）。理由：面试官点开 GitHub 只看 1–2 分钟，README 首屏必须等价于简历首屏。产物：`README.md`（不改其它文件）。
2. **建立 `docs/resume_queyi.md` 三版本草稿（A 工业 / B 学术 / C 电梯）**，并强制每条数字后加"口径注释"（例如 `66.7% = 10/15 可测，非 17 条全量`）。理由：你已经踩过"83 卡 vs 37 实卡""813 行 vs 3826 行"两次口径漂移，简历上任何口径漂移都会在面试现场被击穿。产物：单文件，不改仓库其它文件。
3. **在 2026-12 前补齐"三个可被追问的深度锚点"**：① 任选 1 条 block 规则，写清它为什么是 block 而不是 warn（附一个真实反例）；② 解释哈希链 + Merkle checkpoint 如何防篡改，并给出"篡改 1 条账本 → 对账器报错"的可运行 demo；③ 说明为什么把 `-O1` 改成 `-O0` 会让 **3/5** 的 miss 被抓住。理由：TheLadders 的 6 个注视点里没有"项目详情"，**项目详情只活在面试追问里**；简历的作用是把追问引到你准备好的地方。

## 盲区（诚实标注）

- **"7.4 秒"不是定论**：样本仅 30 名招聘官、方法学未同行评议、发布方有商业动机。仅可作为"结构设计"依据，不可作为"内容深度不重要"的依据。
- **"面试邀约率提升 47%"、"阅读时长增加 23 秒"、"邀约率提升 4 倍"**：来自二手商业内容平台（锤子简历、百度智能云文章、Boss 直聘年报转述），**未找到原始研究，未核实**。
- **华为目标院校名单**：查到的版本为 2024 年（55 所，双非 3 所）；**2026/2027 年名单可能变化，需在使用前刷新**。且"名单"不等于"硬筛"，非目标院校投递是否被 ATS 直接过滤，**未查到官方规则**。
- **杭电"325 人进华为 / 转正率 60% / 13 级 19–21K"**：单一自媒体来源，**未核实**。
- **合肥本地双非院校（安徽大学、安徽建筑大学、合肥学院等）在长鑫/京东方/蔚来/科大讯飞的简历通过率**：**未查到任何公开数据**。
- **中国 ATS 使用率与具体 ATS 关键词规则**：未查到权威数据；"ATS 关键词匹配"是从英文招聘语境的通用建议外推的。
- **"一页 vs 两页"的 98% 说法**：属经验值/个人主张，**非实证**。
- 本文件中的"正反例"多数来自中文简历指南的公开拆解文章，**非一手 HR 访谈**；引用时已注明来源层级。
