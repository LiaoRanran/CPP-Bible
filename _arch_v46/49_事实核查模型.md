# 方向 49：事实核查模型（MiniCheck / FactScore / AlignScore / RAGAS / SelfCheckGPT）

> 调研时间：2026-09-29。联网检索 16 次（WebSearch 10 + WebFetch 6）。
> 锚点：阙疑的每张卡都带"证据 + provenance"。事实核查模型正是"声明 vs 证据"这条链路上**最便宜、最成熟**的一类现成工具。本方向回答：它们各自在验什么、多少钱、什么时候不能用。

## 核心结论

1. **这一类模型的共同任务边界是"grounded factuality（声明是否被给定文档支持）"，不是"声明是否客观正确"**：MiniCheck 的 LLM-AggreFact 明确定义为"给定上下文段落与声明，判断声明是否被上下文逻辑支持"。**对阙疑的含义极其关键——它们能验"卡里的断言是否与引用的标准原文一致"，但完全无法验"这段 C++ 是不是 UB"**。前者阙疑可以直接用，后者只能靠规则与编译器。
2. **成本优势是数量级的，且已被反复独立复现**：MiniCheck-FT5（**770M**）在 LLM-AggreFact 上 BAcc **74.7** 逼近 GPT-4 的 **75.3**，但 13K 测试集成本 **$0.24 vs $107（约 400–446 倍）**；Luna（DeBERTa-large **440M**）比 GPT-3.5 **降本 97%、降延迟 91%**。**对 0 预算的阙疑，这是唯一"能跑全量"的事实核查方案。**
3. **它们最容易被误用的地方是"以为它能判对错"**：SelfCheckGPT 是**零资源、只靠采样自一致性**（不查任何外部知识），Prompt 变体 AUC-PR 93.42 但**每条要采样 20 次**（GPT-3 API 下约 $200 / 1908 句）；FActScore 的原子事实拆分把**人工评估成本推到 $4/次生成、76 小时/$2,000 只做了 505 次生成**。**阙疑必须按"证据是否在手"来选择模型，而不是按分数高低。**

## 精确数字与案例

### 一、MiniCheck：把"事实核查"做成 770M 的专用小模型

- 论文：`MiniCheck: Efficient Fact-Checking of LLMs on Grounding Documents`，Tang、Laban、Durrett（UT Austin），arXiv:2404.10774，2024-04（EMNLP 2024）；仓库 `github.com/Liyan06/MiniCheck`。
- **三个变体（注意：没有 400M、没有 7B）**：
  - MiniCheck-Rbta：骨干 AlignScore（RoBERTa-Large），**355M**；
  - MiniCheck-Dbta：DeBERTa-Large，**355M**；
  - MiniCheck-FT5：Flan-T5-Large，**770M**。
- **LLM-AggreFact 基准**：论文版聚合 **10 个数据集**（AggreFact-CNN/XSum、TofuEval-MediaS/MeetB、WiCE、REVEAL、ClaimVerify、FactCheck-GPT、ExpertQA、LFQA），测试集约 **13K**；后加 RAGTruth 成为 **11 个**（官方 leaderboard）。
- **平衡准确率 BAcc**：

| 模型 | 平均 BAcc |
|---|---|
| **GPT-4** | **75.3** |
| **MiniCheck-FT5（770M）** | **74.7** |
| Claude-3 Opus | 74.1 |
| MiniCheck-Rbta | 72.7 |
| MiniCheck-Dbta | 72.6 |
| AlignScore（此前专用 SOTA） | 70.4 |

- **成本（13K 测试集，$0.8/GPU-hr）**：

| 模型 | 规模 | 训练数据 | 成本 |
|---|---|---|---|
| GPT-4 | — | — | **$107** |
| MiniCheck-FT5 | 770M | 35K | **$0.24** |
| MiniCheck-Rbta | 355M | 14K | $0.20 |
| MiniCheck-Dbta | 355M | 35K | $0.20 |

- **107 / 0.24 ≈ 446 倍**（论文摘要表述为 "400x lower cost"）。
- **训练数据**：合成数据 **约 14K**（C2D **7,076** 条 + D2C **7,319** 条，由 GPT-4 构造）+ 从 ANLI 取 **21K** 子集 = **35K**。
- **关键方法论发现**：**不需要先做 claim decomposition（声明原子化）**——该步骤通常使推理时间与成本增加 **2–4 倍**。
- **Leaderboard 更新（2024-2025）**：**Bespoke-MiniCheck-7B** 以 **77.4%** 登顶 LLM-AggreFact，**超过许多大得多的模型**；它用 **Llama-3.1-405B 合成数据**训练。官方 leaderboard 还给出一个极有说服力的成本对照：**"用 GPT-4 核查整个基准可花到 $100，而用小模型本地部署只需 $1"**。
- **官方明确警告**（leaderboard 原文）："若用 GPT-4 做事实核查器，**核查成本轻易超过生成成本 10 倍以上**。"

### 二、FActScore：把生成拆成"原子事实"再逐条验

- 论文：`FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation`，Min 等，arXiv:2305.14251，2023-05（**EMNLP 2023 main** `2023.emnlp-main.741`）；仓库 `github.com/shmsw25/FActScore`。
- 方法：把生成拆成"原子事实"（每句只传达一条信息）→ 对每条给二值标签（是否被知识源支持）→ FActScore = 被支持原子事实的百分比。
- **动机数字**：ChatGPT 生成的句子中 **40% 同时混合了"被支持"和"不被支持"的信息**——所以句级二值判断不够细。
- 拆分示例：`Thierry Henry (born 17 August 1977) is a French professional football coach, pundit, and former player.` → **5 条原子事实**。
- **人工评估成本**：**76 小时工作、总计 $2,000、评估 505 个生成**，即 **$4 / generation**。若要做 6,500 条生成，预估 **$26,000**；论文结论部分提到原本预估 12 个新模型需约 **$65K**。
- **与人标注一致率**：InstructGPT **96%**、ChatGPT **90%**、PerplexityAI **88%**、**平均 91%**；不一致案例中 **70% 源于"该事实是否被知识源支持"本身有争议**。
- **FActScore 结果**：

| 模型 | FActScore | 用搜索？ |
|---|---|---|
| InstructGPT | **42.5%** | 否 |
| ChatGPT | **58.3%** | 否 |
| PerplexityAI | **71.5%** | 是 |

- **每条生成的原子事实数**：InstructGPT **26.3**、ChatGPT **34.7**、PerplexityAI **40.8**；GPT-4 **60.8**；人类 **29.0**。
- **自动估计器**：误差率 **< 2%**；两个估计器排名相关性 **Pearson r = 0.99**；检索参数 k=**5** passage；NP 阈值 **0.3**；最佳配置误差率 InstructGPT **1.4%**、ChatGPT **0.4%**、PerplexityAI **0.1%**。
- **对阙疑的含义**：FActScore 的"原子化"思路**正是阙疑卡片应该有的粒度**——把一张卡的一句话拆成可独立判定的原子断言，**每条断言独立可验收**。但它的**人工评估成本（$4/次）对阙疑是不可承受的**，只能用其自动估计器路线。

### 三、AlignScore：把 7 类任务统一成一个"对齐函数"

- 论文：`AlignScore: Evaluating Factual Consistency with A Unified Alignment Function`，Zha 等，**ACL 2023** long paper（`2023.acl-long.634`），arXiv:2305.16739；仓库 `github.com/yuh-zha/AlignScore`。
- 训练：**4.7M 样本 / 15 个数据集 / 7 类任务**（NLI、QA、复述、事实核查、IR、STS、摘要），每数据集最多 50 万样本，3 epochs，batch 32。
- 模型：AlignScore-base（RoBERTa-base **125M**）、AlignScore-large（RoBERTa-large **355M**）。
- 评估：**22 个数据集**，其中 **19 个训练中从未见过（零样本）**；SummaC（6 个摘要数据集）+ TRUE（11 个数据集）。
- **SummaC（AUC-ROC 平均）**：AlignScore-large **88.6**（最优）、AlignScore-base 87.4、UniEval 84.6、QAFactEval 83.8、SummaC-CONV 81.0、ROUGE-2 78.1、ROUGE-1 77.4。**相对 ROUGE-1 平均 +11.2 分。**
- **TRUE（AUC-ROC）**：AlignScore-large **87.4**（零样本 **83.8**）最优；SummaC-CONV 82.5、QAFactEval 80.1、ROUGE-2 69.4。
- **人类一致性（Pearson）**：AlignScore-large **54.1**、QAFactEval 48.6、UniEval 43.2、ROUGE-2 **29.3**。
- **与 LLM 指标对比（Spearman）**：

| 指标 | SummEval | QAGS-XSum | QAGS-CNNDM |
|---|---|---|---|
| **AlignScore-large（355M）** | 46.6 | **57.2** | **73.9** |
| G-EVAL-4（GPT-4） | **50.7** | 53.7 | 68.5 |
| ChatGPT | 43.3 | — | — |

- **即 355M 的小模型在 QAGS 两个数据集上反超 GPT-4 的 G-EVAL**，但在 SummEval 上仍落后。
- 工程细节：上下文切分块约 **350 tokens**；RoBERTa 输入上限 512 tokens。

### 四、RAGAS：无参考答案的 RAG 三指标

- 论文：`Ragas: Automated Evaluation of Retrieval Augmented Generation`，Es 等，arXiv:2309.15217（**EACL 2024 demo**）；开源 `github.com/explodinggradients/ragas`。
- **三个指标**：
  - **Faithfulness（忠实度）**：`F = |V| / |S|`（被支持的陈述数 / 陈述总数）；
  - **Answer Relevance（答案相关性）**：`AR = (1/n) Σ sim(q, q_i)`，对生成的 n 个候选问题与原问题求余弦相似度平均（嵌入用 **text-embedding-ada-002**）；
  - **Context Relevance（上下文相关性）**：`CR = 提取的句子数 / 上下文中句子总数`。
- **WikiEval 数据集**：**50 个 Wikipedia 页面**（2022 年初以来发生的事件，超出模型训练截止时间），每页 1 个 ChatGPT 生成的问题，**2 名标注者**。
- 标注者间一致性：Faithfulness **95%**、Context Relevance **95%**、Answer Relevance **90%**。
- **与人类一致性（accuracy，Table 1）**：

| 指标 | Ragas | GPT Score | GPT Ranking |
|---|---|---|---|
| **Faithfulness** | **0.95** | 0.72 | 0.54 |
| Answer Relevance | **0.78** | 0.52 | 0.40 |
| Context Relevance | **0.70** | 0.63 | 0.52 |

- 论文**未报告 F1**，也**未报告任何货币成本**（只用 gpt-3.5-turbo-16k + text-embedding-ada-002）。
- 被评估为**最难**的维度是 Context Relevance（0.70）——ChatGPT 在长上下文中挑关键句常出错。
- **对阙疑的含义**：RAGAS 的**"忠实度 = 被支持陈述 / 总陈述"**与阙疑的"判决 + 证据带 provenance"是同一个数学形式。**Faithfulness 的 0.95 一致性是这一类指标里最高的**，可作为阙疑"卡内断言 vs 引用原文"的默认指标。**但注意它完全不判客观对错。**

### 五、SelfCheckGPT：不查任何外部知识的"自一致性"检测

- 论文：`SelfCheckGPT: Zero-Resource Black-Box Hallucination Detection for Generative Large Language Models`，Manakul、Liusie、Gales，arXiv:2303.08896（**EMNLP 2023 main** `2023.emnlp-main.557`）。
- 核心假设：**如果 LLM 对同一问题多次采样的答案相互矛盾，则该内容很可能是幻觉**——**零资源、黑盒**，不需要外部知识库。
- **五个变体**：BERTScore、QA（MQAG 多选题）、n-gram、**NLI**、**Prompt**。
- **WikiBio 数据**：**238 篇 GPT-3 生成文章、1,908 个句子**（Major-Inaccurate 39.9%、Minor-Inaccurate 33.1%、Accurate 27.0%）。
- **句级 AUC-PR**：

| 方法 | NonFact | Factual |
|---|---|---|
| Random（基线） | 72.96 | 27.04 |
| GPT-3 Avg(−log p)（灰盒） | 83.21 | 53.97 |
| SelfCheckGPT w/ BERTScore | 81.96 | 44.23 |
| SelfCheckGPT w/ Unigram (max) | 85.63 | 58.47 |
| **SelfCheckGPT w/ NLI** | **92.50** | 66.08 |
| **SelfCheckGPT w/ Prompt** | **93.42** | **67.09** |

- **Passage 级事实性排序（Pearson / Spearman）**：Prompt **78.32 / 78.30**、NLI 74.14 / 73.78、Unigram 64.71 / 64.91、BERTScore 58.18 / 55.90。
- **成本**：默认 **N = 20 个采样**（温度 1.0；主响应用温度 0 + beam search）。
  - GPT-3 API（$0.020/1k tokens）：全量实验（1,908 句 × 20 样本）约 **$200**；
  - ChatGPT API（$0.002/1k tokens）：约 **$20**；
  - **NLI 变体是性能/成本最佳折中**（AUC-PR 92.50，接近 Prompt 的 93.42，但算力低得多）。
- **样本数影响**：N=4 时 Prompt 变体 Pearson 仍有 **76.47**（N=20 为 78.32），收益递减。
- **外部知识消融**：若能拿到外部知识库，`WikiBio+Prompt` 达 NonFact **93.59**、Factual **73.11**、Pearson **85.90**——**但这就不是"零资源"了**。
- **对阙疑的含义**：阙疑**已有外部知识（标准原文 + 编译器）**，所以**不该用 SelfCheckGPT 的零资源模式**（它是"没有证据时的兜底"）；但如果阙疑的 LLM 生成了"解释性文字"，SelfCheckGPT-NLI 是**最便宜的幻觉过滤器**。

### 六、两个更贴近生产的补充：Luna 与 Lynx

**（1）Luna（工业界最看重的"低延迟"）**
- 论文：`Luna: An Evaluation Foundation Model to Catch Language Model Hallucinations with High Accuracy and Low Cost`，Belyi 等，arXiv:2406.00975，2024-06（**COLING 2025 Industry Track** `2025.coling-industry.34`）。
- 模型：**DeBERTa-v3-Large，440M**；**token 级**（而非样例级二值）幻觉检测。
- 数字：**成本降 97%、延迟降 91%**（对比 GPT-3.5 与商用评估框架）；RAG QA 测试集 **AUROC 0.80**；**在超过 16k token 的输入上仍保持 68% 的效率**；Triton + TensorRT 部署下 **16k token 处理 < 1 秒**。
- 训练数据：来自客服、金融、生物医学、法律等领域；标注用 **GPT-4-turbo**。
- 局限（原文自承）：**只对 RAG 场景的闭域幻觉有效**；开放域仍未解决；依赖 LLM 标注可能引入噪声。

**（2）Lynx / HaluBench（Patronus）**
- 论文：`Lynx: An Open Source Hallucination Evaluation Model`，arXiv:2407.08488，2024-07-11。
- **HaluBench：15k 条**幻觉评估基准（从二手来源读到"Lynx-8B 在 HaluBench 上比 GPT-3.5 高 **24.5%**"，**该数字未从原文核实，见盲区**）。
- **（3）RAGTruth**（arXiv:2401.00396，**ACL 2024 long** `2024.acl-long.585`）：**近 18,000 条自然生成的 RAG 响应**，**词级**幻觉标注——这是目前最细粒度的公开标注语料。

### 七、这五个模型的"元评估"问题：它们自己也可能不可信

- 论文：`Can We Trust the Judges? Validation of Factuality Evaluation Methods via Answer Perturbation`（arXiv:2609.15561，2026-09）。该文专门**验证事实性评估方法本身**，给出三条对阙疑有用的判断：
  - **ROUGE-1 与 ROUGE-L 频繁被证明不是有效的事实性度量**——"有时会给被破坏更严重的摘要打更高分"（引 GO FIGURE，Gabriel 等 2021 的五个条件协议）；
  - **JudgeBench（Tan 等 2025）把知识/推理/数学/编程数据集转成"标签跟随客观正确性"的响应对，发现包括 GPT-4o 在内的许多强模型"仅略高于随机"**——这与方向 48 的 50.86% 互相印证；
  - 该文自己走的是**"用现成 LLM 做声明分解 + 预训练 NLI 模型做分类"**的路线，**不需要训练数据**，且**任一组件可随新模型发布而替换**。**这条"LLM 分解 + NLI 分类"的组合，是阙疑在 0 预算下最可维护的形态。**
- 综述：`Hallucination to Truth: A Review of Fact-Checking and Factuality Evaluation in Large Language Models`（arXiv:2508.03860，2025）。其中有两条可直接引用的判断：
  - **"即便 GPT-4 与 LLaMA-2 这类先进模型，对通用知识查询的回答中也有约 5–10% 的事实错误"**；
  - **"仅给出真伪标签是不够的——预测必须被证据支持，才能保证系统透明并增强公众信任"**（引 Singhal 等）。**这句话几乎就是阙疑"证据带 provenance"主张的学术背书。**

### 八、把五个模型的适用边界列成表

| 模型 | 验什么 | 需要外部证据？ | 需要参考答案？ | 规模 | 成本量级 | 阙疑可用在哪 |
|---|---|---|---|---|---|---|
| **MiniCheck** | 声明是否被文档支持 | **是** | 否 | 355M–7B | **400 倍低于 GPT-4** | 卡内断言 vs 引用的标准原文 |
| **FActScore** | 原子事实精度 | 是 | 否 | 需 LLM 拆分 | **$4/生成（人工）/ 自动 <2% 误差** | 卡片的原子化改造 + 自动估计器 |
| **AlignScore** | 事实一致性（7 类任务统一） | 是 | 否 | 125M / 355M | 极低（355M 本地） | 证据段落 vs 断言的打分 |
| **RAGAS** | 忠实度 / 相关性 | 是 | **否**（reference-free） | 需 LLM | API 成本（未公布） | 卡内陈述忠实度（0.95 一致性） |
| **SelfCheckGPT** | 自一致性（无证据） | **否** | 否 | 需 LLM + 20 采样 | **$20–$200 / 1908 句** | LLM 解释文字的幻觉兜底 |
| **Luna** | RAG 幻觉（token 级） | 是 | 否 | **440M** | **−97% 成本 / −91% 延迟** | 全量卡的批量幻觉扫描 |

- **一句话边界**：**这五个模型全部只能回答"这段话有没有脱离它自己引用的证据"，没有一个是回答"这段 C++ 是否正确"的。**

## 对阙疑的 3 条具体行动

1. **把 MiniCheck-FT5（770M）接成阙疑的"证据一致性检查器"（性价比最高的一步）**：对每张卡的每条断言，输入「断言 + 该卡引用的标准原文段落」，输出二分类（supported / not supported）。依据：**BAcc 74.7 vs GPT-4 75.3，成本 $0.24 vs $107（≈446 倍）**，且**不需要 claim decomposition**（省 2–4 倍）。**落地**：写 `tools/evidence_consistency_666.py`，模型走本地（`MiniCheck-FT5` 或 `Bespoke-MiniCheck-7B`，后者 leaderboard **77.4%**）。**注意：本方向只写 `_arch_v46/`，具体落地由后续批次执行。**
2. **按 FActScore 的"原子事实"粒度重构卡片断言（结构改造，收益长期）**：把每张卡的一句话拆成**可独立判定的原子断言**，每条断言配 `evidence_ref` 字段。依据：FActScore 证明 **40% 的生成句混合了支持/不支持信息**，句级判断不够细；其自动估计器**误差 < 2%**、两估计器 **Pearson r = 0.99**。**这同时能直接提升阙疑 67 条规则的命中精度**——规则面对原子断言比面对整句更容易判。
3. **为 LLM 生成的"解释文字"单独加 SelfCheckGPT-NLI 过滤（补漏，成本可控）**：阙疑若在卡片或报告里输出任何 LLM 生成的解释性文字，用 **SelfCheckGPT-NLI 变体**（AUC-PR **92.50**，是性能/成本最佳折中）做兜底。**必须明确**：这是"无外部证据时"的兜底，**不能替代 MiniCheck**（阙疑有证据，就应该用有证据的核查器）。**成本**：按论文口径，NLI 变体远低于 Prompt 变体的 $200/1908 句。

## 盲区（诚实标注）

- **MiniCheck 的模型规模易被误传**：常见说法"400M / 7B"**在原文中不存在**——原文只有 **355M（Rbta/Dbta）与 770M（FT5）**；**7B 指的是后续 Bespoke-MiniCheck-7B（非原论文）**。本报告已按原文更正。
- **MiniCheck 合成数据量**：原文为 **约 14K（C2D 7,076 + D2C 7,319）**，**不是 20K**；20K/35K 是加 ANLI 后的总量口径，易混淆。
- **Bespoke-MiniCheck-7B 的 77.4%** 来自 **Bespoke Labs 官方文档页**（厂商自报），**未在 LLM-AggreFact leaderboard 页面逐行核对**；且该模型用 Llama-3.1-405B 合成数据训练，**复现难度高**。
- **LLM-AggreFact 的 11 个数据集**：论文原版写 **10 个**，官方 leaderboard 写 **11 个**（加了 RAGTruth）。**两个口径都对，但必须注明版本**。
- **FActScore 的"$65K"是结论部分的预估表述**，非实际支出；**$26,000 也是 6,500 条生成的预估**。本报告已分别标注。
- **RAGAS 论文完全没有成本数字**，本报告写"API 成本（未公布）"是诚实的。
- **RAGAS 的"与人类一致性 0.95/0.78/0.70"是 accuracy（成对比较一致比例）**，**不是 F1，也不是相关系数**；论文未报告 F1。
- **Lynx 的"比 GPT-3.5 高 24.5%"来自 2026 年的二手工程博客（zylos.ai）**，**未从 arXiv:2407.08488 原文核实**。
- **Luna 的 AUROC 0.80 是"RAG QA 测试集"单点**，论文未在本轮抓取中给出完整分域数字；"68% 效率保留"的具体定义未逐字核对。
- **AlignScore 的"4.7M 训练样本 / 15 数据集 / 22 评估数据集"来自二手抓取摘要**，未逐表核对 ACL 原文。
- **SelfCheckGPT 的成本 $200/$20 是论文附录 C 的估算**（按 API 单价推算），**不是实测账单**。
- **未查到**：针对 C++ / 编译器语义的事实核查模型或基准。**阙疑若做，属于空白区**，但空白区意味着**没有可对标 baseline**，必须写进 Threats to Validity。
- **最关键的一条盲区**：**以上所有模型都只验"grounded factuality"**。**没有任何一个能验证"C++ 代码是否 UB / 是否违反标准"**——这仍然是阙疑规则 + 编译器的活。**不要指望用事实核查模型替代 `gate_engine.py`。**
- 所有数字需在 **2027 投稿时点刷新**。
