# 方向 56：怎么写论文（每个 section 的模板 + 可填空骨架）

## 核心结论

1. **论文不是"研究做完后的报告"，而是"把想法想清楚的过程本身"**——Simon Peyton Jones 的原话是 "Write a paper, and give a talk, about any idea, no matter how insignificant it may seem to you"，写论文的第一价值是逼你把 claim 收敛到能自证的程度。
2. **NeurIPS 2025 的硬约束是"9 个内容页（含全部图表）+ 强制 Paper Checklist"**，页数/样式违规会被 desk reject；因此每个 section 的写作顺序应当是"先定 claim → 再定实验表 → 最后写文字"，而不是从头写到尾。
3. **对阙疑（queyi）这种"评估设计类"论文，最大的写作风险不是英语，而是 claim 与证据不匹配**（如把 97.3% 变异率写成"缺陷检测率"）——Paper Checklist 第 1 条（Claims）和第 2 条（Limitations）就是专治这个的。

## 精确数字与案例

### 一、先看目标会议的真实硬指标（不是"大约"）

NeurIPS 2025 官方 Call for Papers 的精确条款（来源：neurips.cc/Conferences/2025/CallForPapers）：

| 项目 | 精确数值 |
|---|---|
| 投稿系统开放 | 2025-04-03 |
| 摘要截止（强制） | 2025-05-11 AoE |
| 全文截止 | 2025-05-15 AoE |
| 技术附录/补充材料截止 | 2025-05-22 AoE |
| 作者通知 | 2025-09-18 |
| Camera-ready 截止 | 2025-10-23 |
| **正文内容页上限** | **9 页（含所有图表）** |
| Camera-ready 可加页 | **+1 页 = 最多 10 页** |

| 附录+补充材料 | ≤ 100 MB，附录**无页数限制** |
| 摘要早于全文的天数 | **4 天** |

**审稿体量（决定你要不要"抢眼"）**：NeurIPS 2025 共收到 **21,575 篇有效投稿**，接收 **5,290 篇**，录取率约 **24.5%**（来源：NeurIPS 2025 通知邮件，经 CSDN amusi1994 转述、LinkedIn Kelvin Le 报告）。作为对比，NeurIPS 2024 收到 **17,491 篇**，合计接收 **4,497 篇**（主赛道 4,037 + D&B 赛道 460），来源：NeurIPS 2024 Fact Sheet（media.neurips.cc/Conferences/NeurIPS2024/NeurIPS2024-Fact_Sheet.pdf）。

**给阙疑的启示**：NeurIPS 2027 E&D 与主赛道共享同一套格式政策。9 页正文意味着：**Introduction 最多 1.25 页，Related Work 最多 1 页，Method 2 页，Experiments 3 页，Discussion/Threats 1 页，Conclusion 0.5 页**——这是必须提前分配好的预算，否则写到一半就会发现放不下实验表。

### 二、Simon Peyton Jones 的"七条建议"（论文写作的元规则）

来源：simon.peytonjones.org/great-research-paper/（PPT 与视频同页）。七条建议的核心是：

1. **不要等"做完"才写**——写论文本身就是做研究的方法（"the way that you develop the ideas in the first place"）。
2. **明确你的"一句话贡献"（the one idea）**——如果你不能用一句话说清论文的贡献，说明你还没想清楚。
3. **讲故事（tell a story）**——Introduction 要在 1 页内讲完"问题→现有做法的缺陷→你的想法→为什么有效→证据"。
4. **把 Introduction 写成"给忙人看的版本"**——审稿人只读 Introduction 就会决定给几分。
5. **先写 Introduction 的骨架，再填充**——用"bullet 列表"起稿，再扩写成段落。
6. **反复修改（iterate）**——"your paper will be rejected if you don't revise it many times"。
7. **给非专业读者讲一遍**——找同实验室的人读，凡是他们卡住的地方就是你要改的地方。

### 三、Introduction 的可填空骨架（8 句法）

参照 UT Austin CS 391L 的 paper template（cs.utexas.edu/~mooney/cs391L/paper-template.html）与 PEEL 段落结构（Scribbr），Introduction 建议写成 5 段、每段一个"动作"：

```
[第 1 段 · 背景与问题]
C++ 知识库（如 <你的语料来源，例：CPP-Bible 的 37 张实卡>）在 <场景，例：嵌入式代码审查> 中
被广泛使用，但其正确性目前主要依赖 <现状，例：人工复核>，这带来了 <具体代价，例：不可复算、不可
独立验收> 的问题。

[第 2 段 · 现有做法的缺陷]
现有方法主要分三类：<A 类，引用 [1][2]>、<B 类，引用 [3]>、<C 类，引用 [4]>。
它们的共同局限是 <一句话缺陷，例：把"内部变异率"当成"缺陷检测率">，
导致 <后果，例：论文中的检出率不可比、不可复现>。

[第 3 段 · 我们的想法（一句话贡献）]
我们提出 queyi，一个 <定位，例：可被独立验收的 C++ 知识验证器>。
它的核心是 <一句话机制，例：67 条规则（44 条 block）+ 四态判决 + 哈希链 + Merkle checkpoint>，
使 <关键性质，例：任意一条判决都能被第三方用不依赖内核的对账器复算>。

[第 4 段 · 为什么有效 + 证据]
我们在 <数据集，例：30 条盲 holdout / 40 条外部 corpus / 15 条真实缺陷夹具> 上验证，
得到 <数字，例：盲 holdout 检出率 66.7%（10/15 可测）>。消融显示 <关键组件，例：四态判决> 贡献最大。

[第 5 段 · 贡献清单（编号 3 条）]
本文贡献如下：(1) <机制贡献>；(2) <数据/基准贡献>；(3) <可复现性贡献，例：公开独立对账器>。
```

**关键约束**：贡献清单里每一条都必须能在正文里找到对应 section（Checklist 第 1 条要求"claims 准确反映贡献与范围"）。阙疑的 3 条贡献建议写成：① 规则引擎 + 四态判决机制；② 三层外部 corpus（A/B/C）+ 盲 holdout 协议；③ 不依赖内核的独立对账器（可独立验收）。

### 四、Related Work 的四种组织策略

来源：lennartnacke.com/how-to-structure-your-related-work-like-a-pro/（2025-06-18）与 SPUR Lab 指南。四种结构：

1. **按时间线**（适合快速演进的领域）；
2. **按方法族**（最常用，推荐阙疑用）；
3. **按"我们 vs 他们"的差异轴**（每个小节结尾必须回到"我们的差异是什么"）；
4. **按问题维度**（适合跨领域论文）。

**铁律**：Related Work 不是文献综述，每一段最后必须有一句 "In contrast, our approach ..."（对比句）。否则审稿人会给 "the related work reads like a list"。

**阙疑的 Related Work 骨架**：
```
2.1 C++ 静态/动态缺陷检测（clang-tidy、cppcheck、ASan/UBSan [引用]）
    —— 差异：它们给"是/否"判决，我们给四态判决 + 证据带 provenance。
2.2 LLM-as-judge 与事实核查（FactScore、MiniCheck [引用]）
    —— 差异：它们依赖模型，我们要求判决可被非模型工具独立复算。
2.3 可复现性基准（如数据集/基准类工作 [引用]）
    —— 差异：我们额外提供"不依赖内核的独立对账器"。
```

### 五、Method section 的写法（MIT Comm Lab 标准）

来源：mitcommlab.mit.edu/eecs/commkit/journal-article-methods-cs/。CS 类论文的 Method 必须"完整呈现技术贡献"，评审关注点是：**是否给了足够细节让人复现？是否给了直觉？**

**推荐结构（阙疑版）**：
```
3. Method
3.1 Overview（1 张系统总图 + 3 句话说明数据流：语料 → 规则引擎 → 四态判决 → 哈希链 → Merkle checkpoint）
3.2 规则语言与 67 条规则（44 block / 16 warn / 7 advice）——给 1 条规则的完整 JSON 定义作为例子
3.3 四态判决的语义（pass / fail / unknown / not-applicable 各自的判据，用一张真值表）
3.4 证据与 provenance（每条判决附 evidence 的字段定义）
3.5 哈希链与 Merkle checkpoint（给链式结构的伪代码，5–10 行）
3.6 独立对账器（说明它为什么"不依赖内核"，这是本文最独特的卖点）
```

**可填空句子库**：
- "We define the rule language as a tuple (P, C, E, D), where P denotes ... C denotes ..."
- "Algorithm 1 shows the core procedure. In lines 3–7 we ..."
- "A key design decision is <X>, because <Y>. An alternative would be <Z>, but it fails when <W>."

### 六、Experiments section 的写法（含消融）

来源：ACL 系列论文写作指南（blog.csdn.net/qq_35082030/article/details/147579767）、Paper Lab 实验设计指南。评审的三个必问问题：**有没有 baseline？有没有消融？误差棒定义清楚了吗？**

**推荐结构**：
```
4. Experiments
4.1 Experimental Setup（数据集表 + 指标定义 + 编译档声明，例：-O0 / -O1）
4.2 Main Results（主表：holdout 66.7% / corpus 43.8% / 缺陷夹具 100%）
4.3 Ablation（去掉四态判决 / 去掉哈希链 / 换编译档）
4.4 Analysis of Failures（诚实列出 miss 的样本及原因）
4.5 Statistical Significance（若样本小，用 Clopper-Pearson 给置信区间，不要只给点估计）
```

**必须写清的数字细节**：NeurIPS Paper Checklist 第 6 条要求"所有训练细节"，第 7 条要求"误差棒的定义（标准差还是标准误）、计算方法、所捕捉的变异因素"。阙疑没有训练，但要写清：**编译器版本、优化档（-O0/-O1）、平台、样本量（30/40/15）**。

**消融的写法模板**：
> "Removing the four-state verdict (i.e., collapsing to binary) reduces the detectable rate from 66.7% to X%, confirming that the four-state design is critical for <性质>."

### 七、Threats to Validity 的五层写法（这是阙疑的加分项）

来源：ACM TOSEM/FSE 2024 论文 "Threats to Validity in Software Engineering – hypocritical paper section?"（dl.acm.org/doi/fullHtml/10.1145/3674805.3686691），该文从"六个方面"分析威胁：**显式文档化、分类、对应缓解措施**等。软件工程界公认的五类威胁：

1. **Construct validity（构念效度）**：你测的是不是你想测的？（阙疑的坑：变异率 ≠ 缺陷检测率，**这一点必须在这里明说**）
2. **Internal validity（内部效度）**：是否存在混淆变量？（阙疑的坑：编译档 -O1→-O0 使 3/5 miss 被同一 sanitizer 抓住）
3. **External validity（外部效度）**：结论能推广到多少？（阙疑的坑：40 条外部 corpus 分层 A 54.2% / B 12.5% / C 0%，C 层完全失效）
4. **Reliability（可靠性）**：换个人/换台机器结果一样吗？（阙疑的护城河：独立对账器 + 哈希链）
5. **Conclusion validity（结论效度）**：统计推断是否成立？（阙疑的坑：30 样本，需给置信区间）

**阙疑现成可用的素材**：`_auto/status.json` 的 `active_batch=660` 落后于实际提交 665——这是"**元状态漂移（metadata drift）**"的完美实证，可直接写进 Threats to Validity 的 Internal validity 小节。

### 八、Conclusion 的"三不写"

来源：Harvard Writing Center（writingcenter.fas.harvard.edu/conclusions）与 Scribbr 结论指南。

- **不写"新论点"**——结论里不能出现正文没讨论过的东西；
- **不写"exhaustive summary"**——短论文不需要把每段再复述一遍，Harvard 明确说 "you don't need to provide an exhaustive summary"；
- **不写"over-claim"**——不能说 "our system solves the C++ verification problem"，只能说 "our results suggest ... on the evaluated corpora"。

**结论骨架（4 句）**：
```
我们提出 <系统名>，一个 <定位>。在 <数据集> 上，它达到 <数字>，并且 <独特性质，
例：每条判决可被独立复算>。我们承认 <最大局限，例：外部 corpus 的 C 层检出率为 0>，
未来工作将 <方向>。我们公开 <产物，例：对账器与全部数据>，以便 <目标，例：第三方独立验收>。
```

### 九、Abstract 的 150 词骨架与标题写法

**Abstract 的四句结构（150 词内）**：
```
[句 1 · 问题] 一句话说清问题域（≤ 25 词）。
[句 2 · 缺口] 一句话说清现有做法的失效点（≤ 30 词）。
[句 3 · 方法 + 结果] 我们提出 <系统名>，<一句话机制>；在 <数据集> 上达到 <数字>（含样本量）。
[句 4 · 意义] 这些结果表明 <可推广的判断>（注意：不是"我们解决了 X"）。
```

**阙疑的 Abstract 填空版（替换尖括号即可）**：
> Verifying C++ knowledge without a trusted oracle remains an open problem. <现有方法> cannot support independent verification, because <失效原因>. We present queyi, a verifier with 67 rules (44 blocking) that assigns four-state verdicts with provenance-carrying evidence and a Merkle checkpoint. On a blind holdout of 30 samples (17 planted defects), it detects 66.7% of testable defects (10/15); on a 40-sample external corpus it reaches 43.8%. These results suggest that auditability can be achieved without a trusted oracle.

**标题写法的三条硬规则**：
1. **不用冒号堆叠**（"A: B: C" 三截式标题在 ML 顶会已显陈旧）；
2. **不要用 "Towards"、"On the" 开头**（除非你确实只做了早期工作）；
3. **把系统名放进去**——因为系统名是未来被引用的锚点。阙疑建议标题：**"Queyi: Independently Auditable Verification of C++ Knowledge Cards"**（英文用 `queyi`，中文用"阙疑"，与 `ROADMAP.md` 的命名统一要求一致）。

**摘要词数的硬约束**：NeurIPS 官方风格指南通常要求摘要**不超过 200 词**（第三方模板站 autosci.net 记为"通常不超过 200 词"，**官方页未逐字核实**）；但实践中 **120–150 词最稳**，因为超长摘要会在 OpenReview 列表页被截断。

### 十一、投稿前的 10 项自检（逐项打勾再提交）

| # | 自检项 | 不合格的典型症状 |
|---|---|---|
| 1 | 标题里有系统名，且不用 "Towards/On the" 开头 | 标题三截式冒号堆叠 |
| 2 | Abstract ≤ 200 词，含**样本量** | 只写百分比不写 n |
| 3 | Introduction 第 1 页就出现"一句话贡献" | 论点埋在第 3 页 |
| 4 | 贡献清单每条都能在正文找到对应 section | 贡献 4 条但正文只有 2 节 |
| 5 | Related Work 每段末有 "In contrast, our approach ..." | 读起来像文献列表 |
| 6 | Method 有 1 张总图 + 1 段伪代码 | 只有文字描述 |
| 7 | Experiments 每个数字都标了 n 与置信区间（或说明未给） | 只有点估计 |
| 8 | 有 Ablation，且能说明"哪个组件最关键" | 只报主结果 |
| 9 | Threats to Validity 五层齐全，含元状态漂移实证 | 只写 "our approach has limitations" |
| 10 | Paper Checklist 16 条逐条回答，无空缺 | 漏答第 2 条（Limitations） |

**最容易被忽略的两条**：第 2 条（样本量）与第 9 条（局限）。审稿人在 OpenReview 上给低分时最常用的措辞就是 "the claims are not supported by the evidence" 与 "limitations are not discussed"——这两条恰好是**纯写作层面**就能修掉的。

### 十二、Paper Checklist 16 条（必须逐条回答，缺失即 desk reject）

来源：neurips.cc/public/guides/PaperChecklist。16 条为：1. Claims；2. Limitations；3. Theory/Assumptions/Proofs；4. Experimental Result Reproducibility；5. Open Access to Data and Code；6. Experimental Setting/Details；7. Experiment Statistical Significance；8. Experiments Compute Resource；9. Code of Ethics；10. Broader Impacts；11. Safeguards；12. Licenses；13. Assets；14. Crowdsourcing and Research with Human Subjects；15. IRB Approvals；16. Declaration of LLM usage。

**对阙疑最相关的 3 条**：
- **第 1 条（Claims）**：摘要/引言的 claim 必须与实验范围匹配——**不能把 66.7% 说成"高准确率"**；
- **第 2 条（Limitations）**：回答 NA 等于"声称没有局限"，回答 No 等于"有局限但没讨论"——**阙疑必须回答 Yes 并写清 C 层为 0 的事实**；
- **第 16 条（LLM usage）**：若 LLM 只是润色文字则无需声明；若参与了核心方法（如生成规则）则必须声明。

## 盲区（诚实标注）

- **未逐字核对 Simon Peyton Jones 的 PPT 原文**：七条建议的措辞来自其官方页面摘要与多个转载版本，PPT 内文（含具体例子）**未逐页核实**，引用时以"其演讲提出七条建议"为准。
- **NeurIPS 2025 的 5,290 篇接收数与 24.5% 录取率**：来自通知邮件转述与第三方（CSDN/LinkedIn/OpenAccept），**未从 neurips.cc 官方统计页直接核实**；NeurIPS 2024 的 17,491 / 4,497 来自官方 Fact Sheet PDF，可信度较高。
- **NeurIPS 2027 E&D 的具体政策未知**：本文引用的 2025 政策**可能变化**，2027 投稿前必须重新核对 CFP。
- **"9 页"为 NeurIPS 主赛道通用值**：E&D / D&B 赛道是否完全一致**未逐条核实**（2025 CFP 称 D&B 与主赛道截止日相同、共享格式政策，但 2027 需重查）。
- **Threats to Validity 的"五层"分类**：不同社区（SE vs ML）分类不一，本文采用 SE 常用五类，**未声称是唯一标准**。
- **页数预算表的具体分配（1.25/1.0/2.0/3.0/1.0/0.5）为经验建议**，非任何官方规定。
