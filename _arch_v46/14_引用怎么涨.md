# 方向 14：引用怎么涨

## 核心结论

1. **有实测因果证据的只有两件事：挂预印本（+20.2%）和建 GitHub 仓库（月引用率约 +20%）**；"发推涨引用"被一个 550 篇论文的三年随机对照实验证伪（p>0.15），推文只涨下载量与 Altmetric 分数，不涨引用。
2. **推文与引用之间的相关性是"好论文本身就火"造成的假相关**（原文结论 "good papers are good"）；因此把精力放在"让论文可被检索、可被复现、可被引用"上，回报远高于做社媒运营。
3. **引用基础设施正在退化，必须自建可观测链路**：Meta 的 Papers with Code 已于 2025-07-25 下线；Semantic Scholar 等索引对新论文的参考文献存在"lag state"盲区；因此阙疑必须自己维护一份"引用/下载/复现"追踪脚本，而不是等平台给数字。

## 精确数字与案例

### 一、唯一有因果证据的两条：预印本 +20.2%，GitHub 仓库 +20%/月

**（1）预印本：+20.2%**

Colavizza 等（2024）用 PLOS × DataSeer 的 Open Science Indicators 数据集，覆盖 **PLOS 2018–2023 全部出版物** + 从 PMC Open Access Subset 抽样的对照组，**合计约 122,000 篇**，用宽泛控制变量隔离效应。结论（原文）：

- "the early release of a publication as a preprint correlates with a significant positive citation advantage of **about 20.2% on average**"；
- "sharing data in an online repository correlates with a smaller yet still positive citation advantage of **4.3%** on average"；
- "we do **not** find a significant citation advantage for sharing code"。

**（2）GitHub 仓库：月度引用率约 +20%**

Kang、Kang、Jang（2023），"Papers with code or without code? Impact of GitHub repository usability on the diffusion of machine learning research"，*Information Processing & Management* Vol. 60, Issue 6（2023-11）。方法：把 Papers with Code（PwC）索引的 ML 论文接到 Microsoft Academic Graph（MAG），再用 GitHub API 抓仓库级元数据；用**最近邻匹配 + 论文级固定效应 + 条件固定效应泊松模型**。样本 **19,109 篇**带代码论文。原文结论：

> "we estimate that papers enjoy approximately **20% advantages in monthly citation rates** after the creation of the first GitHub repositories, accounting for paper-level fixed effects and ages."

同文还发现"首次关联仓库所用框架（如 PyTorch、TensorFlow）的流行度趋势"也会影响月引用率——即**把代码挂在热门框架生态里，本身就有引用红利**。

**两条数字合起来给阙疑的直接含义**：arXiv（+20.2%）+ 一个真实可跑的 GitHub 仓库（+20%/月）是可叠加的，而且都不需要任何社媒运营。

### 二、被证伪的那条：推文不涨引用（550 篇，三年随机对照）

**反方证据（支持推文有效）**：Weissburg、Arora、Wang、Pan、Wang（2024），"Position: AI/ML Influencers Have a Place in the Academic Process"，arXiv:2401.13782，**ICML 2024**。数据集：**8,000 篇以上论文**，推文跨 **2018-12 至 2023-10**，对照组按 **9 个关键协变量**精确匹配。结论（摘要原文）：

> "Our statistical and causal inference analysis reveals a significant increase in citations for papers endorsed by these influencers, with **median citation counts 2-3 times higher** than those of the control group."

**正方证据（否定推文有效）**：Branch 等（2024），"Controlled experiment finds no detectable citation bump from Twitter promotion"，**PLOS ONE**，DOI 10.1371/journal.pone.0292201（2024-03-20 发表；2023-09-25 收稿，2023-12-13 接受）。这是**随机对照实验**，设计细节完整可复现：

- 样本：**110 篇**被推文论文 + 每篇 **4 篇**对照 = **550 篇**追踪论文；**11 个期刊**、**11 位推文者**（本文共同作者）。
- 推文者粉丝规模：实验开始时平均 **15,257**（范围 3,962–39,429）；最后一次实验推文时平均 **20,310**（范围 4,647–47,842）——**远高于普通研究者**，即效应上限已被放大。
- 实验期：2018-12-05 至 2020-04-16；最终数据采集 2023-04-16；统计用随机化检验，重复抽样 100,000 次。
- **三年后引用**：Web of Science 每篇 +0.6（+7%），**p = 0.258**；Google Scholar 每篇 +1.4（+12%），**p = 0.157**。原文："the overall increase in citation counts after three years (+7% for Web of Science and +12% for Google Scholar) was **not statistically significant (p > 0.15)**"。
- **其他指标（全部显著或接近显著）**：推文当天下载量高 **3.9 倍**（范围 2.4–6.9）；次日高 **2.6 倍**（1.3–5.1）；30 天后 Altmetric 分数高 **68%**（p=0.065）；30 天后推文数高 **64%**（p=0.004）；3 年后 Altmetric 分数高 **81%**（p=0.004）；3 年后推文数高 **105%**（p=0.004）。
- **功效分析**：要检出 WoS 的 7% 真实效应需要 **≥770 篇**推文论文（本实验的 7 倍）；要检出 GS 的 12% 需要 **≥330 篇**（3 倍）。本实验实际 n=110，**功效不足**。
- 作者结论："while discussing science on social media has many professional and societal benefits..., increasing the citation rate of a scientist's papers is likely not among them"；并用"**good papers are good**"解释相关性——不是推文导致引用，而是优质论文同时被更多转发和更多引用。

**Nature 新闻**在 2024-03-27 以"Tweeting your research paper boosts engagement but not citations"报道了该实验。**另一条相反方向的二手报道**：ScienceDirect（2024-02-01）"The impact of Twitter/X promotion on visibility of research articles"（Maastricht University）称"Twitter/X promotion has been shown to increase citation rates in well-established journals. We aimed to test the..."——**该文的具体数字未取到，未核实。**

**对阙疑的判断**：在"8,000 篇 + 9 协变量匹配"与"550 篇随机对照实验"之间，**后者是因果证据，前者是观察性相关**；因此策略应假定"推文不涨引用"。

### 三、GitHub stars 到底说明什么

Koch、Klein、Johns（2024），"The Fault in Our Stars: An Analysis of GitHub Stars as an Importance Metric for Web Source Code"，**MADWeb 2024**（NDSS Workshop），DOI 10.14722/madweb.2024.23004。该文分析的语义摘要（TLDR）为：

> "The results indicate that both downloads and stars pose a **moderately strong indicator** of the importance of client-side deployed JavaScript libraries, as well as their correlation with detected deployments across websites."

**未取到具体相关系数与样本量**（Semantic Scholar 页面只有 TLDR；PDF 在本环境不可读）。但该文的参考文献里出现一项重要质疑：**"Six Million (Suspected) Fake Stars on GitHub"（He 等，2026）**，构建了 StarScout 工具检测 2019–2024 年间的异常 star 行为，发现**虚假 star 活动在 2024 年激增**。**该项仅见于检索摘要，未核实原文。**

**对阙疑的判断**：stars 可以作为"仓库被看见"的代理指标，但**不能当作引用或影响力的证据**，因为刷 star 已形成规模。

### 四、可用的分发渠道与它们的真实体量

- **Hugging Face Daily Papers**：官方博客（2024-09-23）原文"In the past year, **3,700+ papers** have been featured, and the page has gained **over 12,000 subscribers**"。机制：AK（@akhaliq）与社区挑选、作者可**一键认领论文**（认领后自动与账号关联）、支持 upvote、每篇论文下方有讨论区可 @ 作者、`@librarian-bot` 推荐相似论文、支持多语言评论与翻译、可订阅每日邮件（不含周末）。**与 arXiv 有互操作**：在 arXiv 页面上看到 🤗 表情可跳转到 Daily Papers 页（需安装 "arXiv to HF" 浏览器扩展）。
- **Papers with Code 已于 2025-07-25 下线**：Meta AI 将其长期维护的 PwC 平台下线，Hugging Face 联合创始人兼 CTO Julien Chaumond 通过社媒宣布与 Meta、PwC 合作构建继任平台。中文报道称 2025 年 7 月研究者打开网站看到"502 Bad Gateway"。**对阙疑的含义**：不要依赖 PwC 的 leaderboard 曝光；其数据集/榜单生态正在迁移。
- **alphaXiv**：arXiv 论文讨论平台，斯坦福 AI 实验室 2025-08-06 推文称其"一年前作为 arXiv 论文评论平台推出"，2025-04 上线 "Deep Research for arXiv"（生成文献综述与最新论文链接）。**体量数据未取到。**
- **Awesome list**：`josephmisiti/awesome-machine-learning` 等长期维护的清单是经典入口，但**未查到任何"被 Awesome list 收录导致引用增长"的量化研究**。诚实标注为盲区。
- **Reddit**：**未查到任何关于 r/MachineLearning 帖子对论文引用影响的学术研究**。检索到的 Reddit 相关研究（Semrush 2025-11-10 分析 248,000 条 Reddit 帖、Profound 称 Reddit 占 Google AI Overview 引用 2.2%、Discovered Labs 分析 144,284 条 AI 引用）全部是关于**AI 搜索可见性**，与学术引用无关。**故本方向不主张任何 Reddit 引用效应。**

### 五、引用数据的可观测性正在变差

1. **"lag state" 盲区**：一项分析（The Neural Feed 转述，2026-03-28，标题"Researchers identify 'lag state' citation gap that biases automated literature reviews"）指出，新发表且正在被引用的论文，其**自身参考文献**尚未被 Semantic Scholar / AI2 等索引摄入并连接，导致这些论文在引用图里表现为"孤立或低连通节点"；偏差**恰集中在最新、被引最快、最前沿的研究**上，会扭曲图嵌入、基于图邻近度的检索与 RAG 系统。原文称该研究记录在一份含 **16 条以上条目**的 live research journal 中。**二手转述，未找到原始论文。**
2. **索引时延**：第三方博客（citepal，2025-12-21）称 Google Scholar 收录引用需 **24–48 小时**，Scopus 最长约 **1 个月**。**二手，未核实。**
3. **学术社交平台 vs 引用的另一条独立研究**：ScienceDirect（2024-02-01）那篇 Maastricht 的研究**具体数字未取到**，因此本方向只把它列为"存在相反结论的研究"，不作为依据。

### 六、可执行的"自建追踪"工具链

- **Semantic Scholar Academic Graph API**：无需 key 即可调用（约 **1 req/秒**；带免费 key 更高），关键字段 `title, authors, year, citationCount, influentialCitationCount, referenceCount, externalIds, publicationVenue, openAccessPdf`。可直接用 arXiv ID 查询：
  `curl -s "https://api.semanticscholar.org/graph/v1/paper/arXiv:<ID>?fields=citationCount,influentialCitationCount"`
  查引用者列表：`curl -s "https://api.semanticscholar.org/graph/v1/paper/arXiv:<ID>/citations?fields=title,year,authors&limit=100"`
- **arXiv API**：约 **1 req / 3 秒**，返回 Atom XML；摘要页 `https://arxiv.org/abs/{id}` 永远解析到**最新版本**，`https://arxiv.org/abs/{id}v1` 指向**不可变的特定版本**。**引用时必须保留你实际读的版本后缀**，否则"引用漂移"（citation drift）——因为后续版本可能大改内容。
- **arXiv 版本号不可删**：官方原文"Once made public, each version of a work is considered a permanent part of the scientific record and may not be removed"，替换或撤稿都会**版本号 +1**，撤稿版本仍保留在版本历史里。
- **Google Scholar 作者主页 + 引用提醒**：可管理自己主页上的条目，引用数由 Google 自动计算更新（官方说明："citations to them are computed and updated automatically"）。
- **Hugging Face 认领**：认领论文后自动与账号关联，可统计 upvote 与评论数。

### 八、两项 Twitter 研究为什么结论相反，该信哪个

| 维度 | Weissburg 等 2024（支持有效） | Branch 等 2024（否定有效） |
|---|---|---|
| 设计 | 观察性 + 因果推断（9 协变量精确匹配） | **随机对照实验（RCT）** |
| 样本 | 8,000+ 篇论文，推文跨 2018-12 至 2023-10 | 110 篇推文 + 440 对照 = 550 篇 |
| 结果 | 中位引用数为对照组的 **2–3 倍** | WoS +7%（p=0.258）、GS +12%（p=0.157） |
| 论文类型 | ICML 2024 **Position** 论文 | PLOS ONE 研究论文 |

关键差异有三点：（1）**RCT 是因果证据，匹配是相关证据**——"9 个协变量"永远无法排除"论文本身质量"这个混杂因子；（2）Weissburg 等测的是 AI/ML 影响力账号，而 Branch 等的推文者粉丝均值也有 15,257–20,310，**说明"粉丝量"不是差异的解释**；（3）Weissburg 等自己把论文定位为 "Position"（立场论文），而非实证主张。

因此本方向的判断是：**因果层面，推文不涨引用；相关层面，被大账号转发的论文引用更高——但两者的共同原因是"论文本身好"**。Branch 等用 "good papers are good" 概括了这一解释。对阙疑的实践含义：**把资源投到"让论文变好、变可复算"，而不是投到转发量。**

### 九、把"可复算"当传播策略：一个可量化的替代方案

既然推文不涨引用、而 GitHub 仓库涨 20%/月（Kang 等 2023），那么"传播"的正确形态是**让别人能跑你的代码**。四项可量化验收指标：

- **仓库可跑性**：`python tools/gate_engine.py --check` 在干净机器上一次通过，耗时写入 README。
- **数据可复算性**：holdout 30 样本（真错 17 / 对照 9 / unknown 4）与检出率 66.7%（10/15 可测）可由第三方脚本复现；外部 corpus 40 条分层（A 54.2% / B 12.5% / C 0%）与 43.8% 总检出率可复现；缺陷夹具 15 条与重注入 6/6=100% 可复现。
- **可引用性**：`CITATION.cff` 含 arXiv ID 与版本号；README 顶部一行"若你复现了本文结果请引用 arXiv:XXXX.XXXXXv1"。
- **可被索引性**：认领 Hugging Face Paper Page（认领后自动与账号关联，可统计 upvote 与评论）；**不再依赖 Papers with Code**（已于 2025-07-25 下线）。
- **可被第三方复现性**：外部研究者按 README 从零走一遍流程能否得到同一组数字——这是 ICSE Artifact Evaluation "Results Reproduced" 徽章的前置条件，也是唯一能被独立核验的"影响力"。

这四项都不需要社媒账号，且全部可验证——比"发 10 条推文"更符合 Branch 等的结论。

## 对阙疑的 3 条具体行动

1. **建一个引用/下载追踪脚本并每周跑一次，替代"等平台给数字"。** 新建 `tools/cite_track_667.py`（编号按仓库批次惯例），功能：用 arXiv ID 调 Semantic Scholar API 取 `citationCount / influentialCitationCount / referenceCount`，写入 `data/cite_track.json`（append-only，与既有账本风格一致）；同时抓 `arxiv.org/abs/{id}` 的版本号与 Comments 元数据。核心命令：`curl -s "https://api.semanticscholar.org/graph/v1/paper/arXiv:<ID>?fields=citationCount,influentialCitationCount,referenceCount"`。**时间点：arXiv v1 发布后 7 天内上线，之后每周一跑一次。**
2. **把"仓库可被引"做成硬指标，而不是把 stars 当指标。** 依据 Kang 等（2023）的 +20% 月引用率与 Koch 等（2024）的"stars 只是中等强度指标"结论，在 `README.md` 与论文里都加：`CITATION.cff`（含论文 arXiv ID 与版本号）、`docs/` 下放置 holdout 30 / 外部 corpus 40 / 缺陷夹具 15 三个数据集的复算脚本入口、以及一行"若你复现了本文结果请引用 arXiv:XXXX.XXXXXv1"。验收：`ls CITATION.cff && grep -c "arxiv.org/abs" README.md` 均非空。**时间点：与 arXiv v1 同批提交。**
3. **明确放弃"靠发推涨引用"，把省下的时间投到"可复算"上。** 依据 Branch 等（2024）的 550 篇 RCT（p>0.15，且作者粉丝均值 15,257–20,310 都测不出效应），在 `_arch_v46/` 新建 `cite_strategy.md` 写死三条：①不做持续社媒运营，只在 arXiv v1 发布当天发一条不带会场名称的说明；②所有宣传素材必须能落到"可复算命令"，例如 `python tools/gate_engine.py --check` 的通过率；③每季度核对一次 Semantic Scholar 与 Google Scholar 的引用数差异，并把差异记入 `data/cite_track.json`（对应"lag state"盲区）。**时间点：2026-11-30 前写完并冻结。**
