# 方向 78：小模型验证器的未来

## 核心结论

1. **1B–7B 级专用验证器在 2026 年已经"够用且便宜"**：RewardBench 2（2025-06）榜首是 **Skywork-Reward-V2-Llama-3.1-8B（84.1 分）**，击败了 70B/72B 模型与闭源 Gemini-2.5-pro（79.5）；在数学子域，**Qwen2.5-7B 底座的奖励模型（71.6）反超 Llama-3.1-70B 底座的（69.9）**。7B 单卡可训、可本地部署（综述称 8-bit Adam 可在单张 RTX 4090 24GB 上训练 7B），使"本地验证器"在成本上完全可行。
2. **但"把验证器换大"解决不了根本问题**：*Variation in Verification*（arXiv:2509.17995，2025-09）用实验证明 **"从 7B 扩展到 GPT-4o 无法克服根本性的验证挑战"**，并给出机制性数字——**TNR（识别错误的能力）从弱生成器（Llama-3.1-8B）上的 0.68 掉到强生成器（Qwen3-32B）上的 0.17**，且**"难问题"上 39.1% 的假阴性来自验证器自己生成错了参考解**。这意味着小模型验证器的未来**不是靠变大**，而是靠**外置结构化证据**（规则、可复算、可审计）——正是阙疑的路线。
3. **最优分工是"弱生成 + 强验证"，而非"什么都交给最大的模型"**：同一论文显示，Gemma2-9B 与 Gemma2-27B 的性能差距在验证后从 **10.3% 缩到 2.5%（收窄 75.7%）**，且"弱生成器 + 强验证器"能在匹配强生成器性能的同时**减少 token 消耗**；NeurIPS 2025 的 *Rethinking Optimal Verification Granularity*（arXiv:2505.11730）进一步研究了"用强验证器稀疏查 vs 弱验证器密集查"的最优粒度。对阙疑的含义：**67 条规则负责便宜的全量筛查，小模型负责语义复核，大模型只在冲突时升级**。

## 精确数字与案例

### 一、专用验证器的起点：过程奖励模型（PRM）

OpenAI, Lightman et al., *Let's Verify Step by Step*（arXiv:2305.20050，2023-06-01）：**过程监督（对每一步打分）训练出的模型解出 MATH 测试集代表性子集的 78%**，且过程监督**显著优于结果监督（outcome supervision）**。这篇论文奠定了"验证是一个独立、可单独训练的模块"这一范式，也是后续所有 PRM 工作的基准线。

Qwen 团队（2025-01）发布 **Qwen2.5-Math-PRM-7B**（过程奖励模型）与 **Qwen2.5-Math-RM-72B**（结果奖励模型），配套论文 *The Lessons of Developing Process Reward Models in Mathematical Reasoning*（arXiv:2501.07301）指出**常用的蒙特卡洛（MC）估计**在构建 PRM 训练数据时存在系统性问题。**注意：7B 做过程验证、72B 做结果验证**——同一团队在"验证粒度"上就选择了不同规模，说明"验证器大小"没有单一最优解。

### 二、小模型验证器"够用"的硬证据

**(a) RewardBench 2（AI2，arXiv:2506.01937，2025-06）。** 数据集 **1,865** 个 prompt（从约 3,000 个筛出），约 **70%** 为人类来源；四选一分类任务，**随机基线 25%**（对比旧版 RewardBench 的 50%），因此难度更高——**领先模型平均分比 RewardBench 低约 20 分**。榜单：

| 排名 | 模型 | 平均分 | 底座规模 |
|---|---|---|---|
| 1 | **Skywork-Reward-V2-Llama-3.1-8B** | **84.1** | 8B |
| 2 | ContextualAI/LMUnit-qwen2.5-72b（LM-as-judge） | 82.1 | 72B |
| 3 | ContextualAI/LMUnit-llama3.1-70b | 80.5 | 70B |
| 5 | google/gemini-2.5-pro（闭源） | 79.5 | — |

8B 冠军的子域分数极度不均衡：Factuality 84.6、**IF（精确指令遵循）仅 66.3**、Math 77.6、Safety 96.7、Focus 98.4、Ties 81.2——**"精确指令遵循"是所有奖励模型的共同短板（领先模型 <40%）**。下游相关性：Best-of-N 采样下 113 个 RM 与人类判断的 **Pearson r = 0.87**；但 PPO/RLHF 训练中，RM 分数在 **49.8–68.5** 区间后**饱和**，且**on-policy 模型（RB2 49.8–68.7 → PPO 59.5–60.7）与 off-policy 模型（RB2 65.6–72.9 但 PPO 仅 54.5–58.5）差异显著**——即"**取分最高的 RM 不等于 RLHF 效果最好**"。这是"验证器指标 ≠ 验证器效用"的关键反例。

**(b) 小模型在垂直域反超大模型。** SLM 综述（arXiv:2501.05465v2，覆盖约 **160 篇**论文，范围 **1–9B**，例外到 13B）汇总：**Qwen3-4B 媲美 Qwen2.5-72B-Instruct**；**Phi-4 的 MMLU 84.8 / GPQA 56.1 / MATH 80.4**；**DeepSeek-R1-Distill-Qwen-1.5B 的 AIME 28.9 / MATH 83.9**（数学上超过 GPT-4o 与 Claude-3.5-Sonnet）；**TinyGSM 上 1.3B 的"生成+验证"模型达 81.5，超过其教师 GPT-3.5 的 77.4**。还有一条 2026 年的 arXiv 热点（经知乎转述，未核实原文）称 **3B–7B 小模型在医疗事实核查中反超 GPT-4o**（QLoRA 微调 Phi-3 / Qwen2.5 / Mistral，仅用 1,008 条样本）。

**(c) 成本侧。** 综述给出的量化：**8-bit Adam 可在单张 RTX 4090（24GB）训练 7B**；**HIL 剪枝 + 量化使模型体积减少 87.94%、精度仅降 1.48%、GPU 实时性能提升 2.28×**；**推测解码把 11B T5 推理加速到基线的 3.4×**。叠加方向 76 中 Epoch AI 的"推理价格年降 9x–900x"，到 2028 年"本地跑一个 7B 验证器复核每条判定"的边际成本趋近于电费。

### 三、小模型验证器的天花板：三条机制性证据

**(a) 验证器扩展无效。** *Variation in Verification: Understanding Verification Dynamics in LLMs*（arXiv:2509.17995，2025-09）系统研究三维度（问题难度 / 生成器能力 / 验证器能力），核心结论原文即："**scaling verifiers from 7B models to GPT-4o fails to overcome fundamental verification challenges**"。精确数字：

- **TNR（识别错误）随生成器变强而崩塌**：Qwen2.5-72B 验证器在 Llama-3.1-8B 生成的解上 TNR = **0.68**，在 Qwen3-32B 生成的解上降到 **0.17**。
- **强生成器产生"内部自洽的错误"**：早期错误（如漏掉一个 case）会连贯传播，形成结构良好但错误的解，验证器倾向判对；弱生成器产生"表层矛盾"，反而好抓。
- **难问题上 39.1% 的假阴性包含"参考解本身错误"**——验证器自己生成参考解去比对，越难越错。
- **验证器能力的收益是阈值型/非线性的**：难问题区间（难度 [0.1,0.3)）数学域在约 **0.65 准确率**处平台化，NL Reasoning 甚至低于随机；中等问题区间（[0.4,0.5)）呈**线性关系（r > 0.9）**；易问题区间（[0.8,0.9)）在约 **0.9 处出现阈值**。
- **弱-强验证器差距收窄的地方，恰是两者都没用的地方**：论文明确"收敛发生在两者验证增益都降至 **0.1 或以下**的区域"。

**(b) 小模型自纠错必须有强验证器。** *Small Language Models Need Strong Verifiers to Self-Correct*（arXiv:2404.17140，ACL 2024 Findings）：研究 **≤13B** 模型能否自纠错，结论是**强验证器（GPT-4）比弱自验证器产生更少假阳性**，从而"解锁"小模型的自我改进；作者提出 **SCORE** 流程（用强验证器生成的引导性批评做监督微调），使小模型**不依赖知识蒸馏**也能成为更好的精修者。**这与方向 77 的结论一致：小模型不能自证，必须外置验证。**

**(c) 验证粒度存在最优解。** NeurIPS 2025, *Rethinking Optimal Verification Granularity for Compute-Efficient Test-Time Scaling*（arXiv:2505.11730）：研究"**强验证器稀疏使用（更大粒度 g、更大验证模型）** vs **弱验证器密集使用**"哪个更划算。**⚠️ 本文仅从检索结果确认标题、作者与会议，具体数字未取到原文（PDF 抓取失败）**，列为盲区。

### 四、落地证据：LLM 辅助静态分析正是"小模型 + 规则"的分工

- **LLM4PFA**（arXiv:2506.10322，2025-06-13）：用 LLM 做**路径可行性分析**来降低静态分析（SAT）的误报——即"规则工具给候选，模型判可行性"。这是"规则 + 小模型"分工的直接工业验证。
- **腾讯企业定制 SAT**（arXiv:2601.18844，2026-01-28）：在腾讯广告营销服务的大规模代码库上，用 LLM 降低静态缺陷检测误报。
- **LLM-Augmented Program Analysis**（ACM，2026-09-09）与 **Enhancing Static Analysis for Practical Bug Detection: An LLM 方法**（ACM TOSEM，2024）：都把 LLM 定位为静态分析的"增强层"而非替代层。

### 六、为什么"验证任务"对小模型格外友好（四条结构性理由）

**第一，验证的输入分布比生成窄。** 生成需要覆盖"所有可能的好答案"，验证只需要判断"这一个候选是否满足一组约束"。任务分布窄意味着所需的参数容量小——这正是 Phi 系列（1.3B 的 Phi-1 在 HumanEval 上超过 Codex-12B）与 1.5B 的 R1-Distill 能在数学上超过 GPT-4o 的机制解释。

**第二，验证有"可判定的中间锚点"。** 数学推理有最终数值可对照，代码有测试可运行，C++ 有规则可复算。**Anchor 的存在让验证器的错误可以被归因**——*Variation in Verification* 正是靠"验证器自生成参考解"这一可观测锚点，才定位出"39.1% 的假阴性来自参考解错误"。

**第三，验证的失败是"可测量的"，生成的失败是"开放的"。** 验证器可以用 TPR/TNR/假阴性率精确刻画（Graph Coloring 假阴性率 95.8%），而"这个代码写得好不好"没有单一标量。**可测量意味着可迭代**——这是小模型能在垂直域快速追上大模型的关键。

**第四，验证的上下文可以被人为压缩。** 生成需要完整上下文（整个仓库、全部依赖），验证只需要"断言 + 证据片段"。上下文压缩直接降低显存需求，使 7B 级模型在 24GB 单卡上可用（综述给出的量化：8-bit Adam 可单卡训 7B；HIL 剪枝+量化减体积 87.94%、精度仅降 1.48%）。

### 七、C++ 场景的特殊性（阙疑的原创空白）

现有全部证据都来自数学推理与通用奖励建模，**没有任何公开工作把"小模型验证器"用于 C++ 未定义行为/编译器差异判定**。这一空白的成因有三个：

1. **C++ 的"正确答案"高度依赖语义作用域**（cpp_standard / compiler / platform / input_domain 四维），同一个断言在不同档位下可真可假——这使"标签"本身成为难题（阙疑已把 semantic scope 写入 26 张 verified 卡，是先行动作）。
2. **C++ 缺陷的"可复现成本"高**：需要特定编译器版本、特定优化级别（阙疑已实测 `-O1`→`-O0` 使 3/5 miss 被同一 sanitizer 抓住）。
3. **缺乏大规模真实缺陷基准**（方向 79：Defects4J 有 835 个 Java bug、BugsInPy 有 493 个 Python bug，C++ 无对等物）。

**结论：C++ 验证是小模型验证器唯一尚未被"跑分经济"污染的方向**——因为连基准都还没建起来。这既是阙疑的机会，也是它必须自己承担基准建设成本的原因。

### 九、三条候选路线的取舍（结论先给）

| 路线 | 代表证据 | 成本 | 阙疑应否采用 |
|---|---|---|---|
| A. 纯规则（无模型） | 阙疑当前 67 规则；CodeQL 478 查询 | 近零 | **必须保留为 L1** |
| B. 专用小验证器（1B–7B） | RewardBench 2 的 8B 冠军 84.1；7B 数学反超 70B | 电费级 | **应做 L2，但只用于灰区** |
| C. 大模型验证器 | *Variation in Verification* 证明 7B→GPT-4o 增益有限 | token 级 | **仅作 L3 冲突仲裁，且结果不写入哈希链** |

**关键判断**：路线 B 的价值不在"比 A 更准"，而在"**把 A 的未知区变成已知区**"——即把四态判决中的 `unknown` 降下来。而路线 C 的价值不在准确性，而在"**当 A 与 B 冲突时提供一个第三方意见**"，且该意见**必须被标记为"非确定性证据"**，不得与规则判决同等对待。这条"证据分级"设计是阙疑相对所有 LLM-as-judge 系统的结构性差异。

### 十、对阙疑的三层分工（可直接落地）

| 层 | 承担者 | 成本 | 覆盖 |
|---|---|---|---|
| L1 全量筛查 | **67 条规则（44 block）** | ≈0（确定性代码） | 全部原子 |
| L2 语义复核 | **本地 1B–7B 验证器** | 电费级 | L1 命中 + 灰区 |
| L3 冲突仲裁 | **前沿大模型（外部，可选）** | 按 token | 仅 L1/L2 冲突样本 |

理由：L1 用确定性规则抓住"表层矛盾"（正是 *Variation in Verification* 说的"弱生成器错误"），L2 用 7B 处理语义，L3 只在少数冲突上升级——这与"弱生成 + 强验证"的成本最优结论一致，且**L1/L2 完全本地、可复算、不依赖任何厂商**。

## 对阙疑的 3 条具体行动

1. **在 2027-Q1 前把"L2 小模型复核层"做成一个可复算的对照实验**：选 **Qwen3-4B** 与 **Skywork-Reward-V2-Llama-3.1-8B**（均为开源权重，可本地跑）作为 L2，在 30 seeds 盲 holdout 上跑"L1 规则 → L2 复核"两段式，与"L1 单跑（检出率 66.7%）"对比。新增 `tools/l2_verifier_<批次>.py`，输出写入 `data/l2_verifier_eval.json`（字段：模型名、量化档、每条 seed 的 L1/L2/L1+L2 判决、token 数、耗时）。**无论结果好坏都登记**——这直接产出一张论文可用的"规则 + 小模型 vs 纯规则"表。
2. **把"验证器扩展无效"写进论文的 §Threats to Validity，作为设计选择的辩护**：引用 arXiv:2509.17995 的 **TNR 0.68→0.17** 与 **39.1% 假阴性来自参考解错误**两个数字，明确声明**阙疑不承诺"模型变强后验证自然变好"，而是把可靠性建立在可复算的规则与哈希链上**。同时把该论文的"弱生成 + 强验证"成本结论（Gemma2-9B vs 27B 差距从 10.3% 缩到 2.5%）写进 `research/09_ablations.md` 的消融计划。
3. **在 2026-Q4 做一次本地成本基准，量化"每检出 1 个真错"的成本**：用 `tools/cost_bench_<批次>.py` 记录三种配置（纯规则 / 规则+7B / 规则+7B+前沿）跑 30 seeds 的**墙钟时间与显存**，换算成人民币；同时把 RewardBench 2 的 **PPO 饱和区间 49.8–68.5** 与 **on-policy/off-policy 差异**写入选型备忘，避免"挑分最高的验证器"这一常见陷阱（对应阙疑只选"能本地复算"的验证器这一硬约束）。

## 盲区（诚实标注）

- **NeurIPS 2025《Rethinking Optimal Verification Granularity》**（arXiv:2505.11730）的**具体数字与结论未取到原文**（PDF 抓取失败），本方向仅确认其存在与主题，**不可引用其结论**。
- **医疗事实核查"3B–7B 反超 GPT-4o"** 来自知乎转述的 arXiv 热点，**未核实论文标题/编号与原始数据**，仅作趋势信号。
- **SLM 综述中大量基准分数**（Phi-4 84.8、Qwen3-4B 媲美 72B 等）**来自各原始论文的不同评测条件**，综述作者本人也提示"未独立复现、评估条件可能不同"，**跨模型横比不可靠**。
- **RewardBench 2 的 on-policy / off-policy 数字**取自论文图表转述，**未逐格核对原表**；"PPO 饱和区间 49.8–68.5"的具体含义（是 RB2 分数还是 PPO 分数）**需回原文确认**。
- **LLM API 具体单价（2026）**来自多个聚合站（spheron / morphllm / xalen），**互相口径不一，本文未引用任何具体价格数字**。
- **腾讯 SAT / LLM4PFA 的误报率改善幅度**未提取到精确百分比，**只做了定性引用**。
- **"1B 级模型能否胜任 C++ 语义验证"没有直接证据**——现有证据都在数学推理与通用奖励建模上，**迁移到 C++ UB 判定属于阙疑的原创空白**，需自测。
