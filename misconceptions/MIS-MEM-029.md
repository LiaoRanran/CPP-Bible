# MIS-MEM-029 · 性能结论不标条件，基准不控制变量

**层级**：deep —— 它不是记错一个数字，而是**把一个带条件的观察当成无条件结论**。危害发生在迁移时：
把别人机器上的结论套到自己的场景、把一次单跑当排序依据、把"三件事同时变了"的实验当因果证据。
这三件事在评审里都会伪装成"我们已经测过了"。

## 触发模式（学习者常这么说 / 这么写）
- "XX 比 YY 快 3 倍"——不说是哪台机器、哪个编译器、哪个标准库版本
- "用池分配器/内存池就能提升性能"
- "基准里各策略各跑一遍就有排序了"（不控制变量、不重复整轮、不标版本）

## 为什么它不成立
1. **平台翻转是实测的**（不是理论担忧）：同一夹具、同一工作量，MinGW/libstdc++ 上 `monotonic < pool < global`（两资源快 4.4× / 2.0×），Linux/glibc 上 `global < pool < monotonic`（两资源反而慢 1.9× / 1.37×）⇒ 同一句"池更快"在两平台上一直一假
2. **变量不唯一会被拆掉**：本卡初版声称"唯一变量 = 标准库"，实际 libstdc++ 列取自 MinGW、libc++ 列取自 WSL + `g++-14` —— 标准库/驱动/平台三者同变，因果无法归因；补"同一条驱动分别跑两标准库"的对照后，唯一变量才真正只剩标准库
3. **顺序效应会伪装成策略优势**：策略顺序固定时，冷启动与频率爬坡被算进第一个策略——实测 global 首轮 771200 ns、后续落到 47–49 万，只取首轮就会把"谁先跑"读成"谁更慢"

## 正确理解
- **判据（发结论前的四问）**：① 这数字在**哪台机器/哪个编译器/哪个标准库版本**上测的？
  ② 对照组**只变了一个变量**吗？③ 结论是**绝对数**（不可复现）还是**对比关系**（可能复现）？
  ④ 顺序/采样会不会污染它（是否重复整轮、是否交错）？
- 工程做法：性能结论**连条件一起写**；证据卡把**断言锚**（跨环境稳定的量）与**留痕**（时序数据）分开，
  前者才写进可自动比对的字段。
- 一条可复用自检：**"换个平台跑，我这句结论还成立吗？"**——本卡实测的答案是：连"谁更快"都翻转。

## 与 MIS-MEM-028 的分工
- **028**（内容类）：`sizeof(std::string)` **不都是 32** —— 布局是实现参数；
- **029**（方法论类，本条）：**性能结论必须带条件、基准必须控制变量** —— 结论的有效性取决于它的成立条件。
