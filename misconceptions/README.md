# misconceptions/ — 全局误解库

**为什么需要**：原子各自手写 `misconception` 文本，1300 个原子全手写不现实，且同一误解
（如"std::move 会移动对象"）会被反复写、表述不一致、反例强度不齐。故抽成**全局条目**，
原子只引用 ID。

**不是什么**：不是知识点清单，不是 FAQ。一条 = 一个**学习者会真实持有的错误信念** + 打掉它的反例。

---

## 文件结构

命名 `MIS-{域}-{序号}.md`，字段：

```yaml
---
id: MIS-MEM-001
name: std::move 会移动对象          # 一句话，学习者视角的断言（不是"正确说法"）
level: deep                        # surface | deep
domain: MEM
trigger_patterns:                  # 触发模式：学习者常这么说 / 这么写（≥1 条）
  - "std::move(x) 之后 x 就被搬空了"
refutations:                       # 反例（deep 必须 ≥2 条，surface ≥1 条）
  - "std::move 只是 static_cast<T&&>(x)，不生成任何指令 [expr.static.cast]"
  - "源对象有效但未指定 [lib.types.movedfrom]"
source: ch115_move.md ⑯ 易错点      # 出处（Book 章节 / 三样板），可追溯
related_atoms: [ATOM-MEM-MOVE-002] # 引用了本条误解的原子（可为空）
---
```

## 字段纪律（硬）

1. **`name` 必须是错误说法本身**，不能写成正确结论或"关于 X 的误解"这种元描述——
   错的是信念，引用它的原子要能直接拿它当"学生会这么想"来用。
2. **`level` 分两层，不是三层**（调研结论，见 `References/01`）：
   - `surface`：一次纠正即可（记错、混淆术语、记反了）。
   - `deep`：结构性误解，源于错误的**心智模型**——**必须配 ≥2 条独立反例**，
     且两条应从**不同角度**打（如"标准怎么说"+"实测后果是什么"），不要同一条换个说法写两遍。
   > 「概念混淆 / 边界误判 / 工具误用」只作**内容组织参考**，不列为字段。
3. **反例要给依据**：标准条款（如 `[lib.types.movedfrom]`）、实测后果、或 Book 章节。
   **不写"这是错的"这种无依据断言**——那只是把误解换个方向再说一遍。
4. **出处必填**：`source` 指向 Book 章节或三样板，保证每条都能回溯到真实素材，不是凭空编的。

## 原子如何引用

原子 frontmatter 用 ID 列表，不再内联文本：

```yaml
misconceptions: [MIS-MEM-001, MIS-MEM-002]
```

门禁规则 `ATOM-MISCONCEPTION-REF` 会校验：引用的 ID 必须存在于本目录（不存在 = block）。
