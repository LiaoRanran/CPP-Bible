# 05 · 等价变异体判据边界（Q5）

> 任务疑问：N5 判据——变体与原文经 safe_load 与硬化解析器两路规范化后都相等、且算子∉{M1,M7}，则标 equivalent（判决不可见面未变）。**是否存在"两路 frontmatter canon 相等、但第三条读取路径（replay 直接读工件/命令、某条规则用正则扫原文而非解析结果、run_match 读外部文件）产生不同 finding"的形态？** 我们的 canon 等价是 sound 还是 complete、偏向哪一侧？

---

## 1. 判据本体（代码实测，`mutation_fuzz.py`）

`equivalent_variant(op, orig_text, variant_text)`（L676–700）：

```
equivalent ⟺ op ∉ REPLAY_OPS(M1,M7)
            ∧ variant_text != orig_text
            ∧ _body_text(orig) == _body_text(variant)        # 正文逐字不变
            ∧ 两解析器视图相等：P1=replay.parse_frontmatter / P2=硬化 _StrictLoader
            ∧ _indent_smuggle_lines(fm_o) == _indent_smuggle_lines(fm_v)  # 缩进走私信号
```

- `_canon`（L626–637）：键字典序、列表**保留顺序**、**不做跨类型归一**、类型名进串。
- 声明 scope（L594–595）："`equivalent=True` ⇒ 该变体在**任何只读 frontmatter 的规则**下，都不可能产生与原文不同的 finding"——**明确限定为"只读 frontmatter 的规则"**。
- `REPLAY_OPS={M1,M7}`（L53）被硬排除，因为 M1/M7 的判决走 replay 读**工件与命令**（L602），frontmatter 相等不足判等价。
- 自证网 `selfcheck_equivalent`（L703–）：凡标 `equivalent` 的变体，若 `classify` 给出 `new_block/new_warn` 或 `verdict != escaped` → 判据假阳性 → fail-loud 列清单。→ "宁可漏标，不许错标"。

**先肯定**：设计已经比 naive 单解析器强很多（双解析器、正文闸、M1/M7 排除、自证网），方向是保守的。

---

## 2. sound / complete 偏向（诚实判定）

- **对"只读 frontmatter 规则集合 S 下不产生 finding 变化"**：判据是 **sound**（若 `equivalent=True`，则对 S 内规则确实无 finding 变化）——前提是 S 内所有规则都从 P1/P2 规范化后的表示派生，且 body 未被改（已 guard）。
- **但绝对不是 complete**：存在 canon 相等但真逃逸的形态——只要存在一条规则**不消费规范化表示**，而消费 raw text / 外部文件 / 工件。这正是任务说的"第三读取路径"。设计已承认 M1/M7（工件/命令）排除、body 改排除，但残留见下。
- **误判代价不对称**：把真逃逸洗成等价（漏）= 严重（污染"错误率上界"）；把无效变异当真洞（误报）= 可接受（只是多审一遍）。**安全方向应偏向"宁可误报、不可漏标"**。当前 `equivalent` 全满足才 True（任一视角存疑即 False），方向正确；但下面 §3 的缺口可能反转这个安全方向。

---

## 3. 第三读取路径反例构造（纯文本推演，未跑编译）

### 反例 A（设计层面成立，本仓现有规则集下暂被间接挡住 —— D 档待验）
设一条规则 `R` 用**正则扫 frontmatter 原始文本**某值子串（仓内确有此类手法：`gate_engine._fm_hardening_uncached` 对 `negative_controls` 用 `_NC_KEY_LINE.match(ln)` 扫**原始 fm 行**，L1374）。
- 若某 M 算子把 `key: value` 改写为 `key: "value"`（加引号）或改空白：
  - `parse_frontmatter` 与 P2 解析后都得到 python str `"value"` → `_canon` 相等（引号已剥离）→ P1/P2 视图相等；
  - `_body_text` 不变（只动 frontmatter 内值，正文未动）；
  - → `equivalent=True`。
  - 但 `R` 的 raw-text 正则若对引号/空白敏感 → 命中不同 → finding 不同。
- **本仓当前为何被间接挡住**：`negative_controls` 的 nc-form 检查比对的是**整行**（`_NC_KEY_LINE.match(ln)` 匹配整行值），值被改则 `_frontmatter_text` 不同 → P1/P2 取自同一 fm → 不相等 → not equivalent。所以**现有规则下暂未找到可击中的具体实例**。
- **诚实标注**：这是**设计层面的真反例**——一旦引入"基于 frontmatter 原始文本子串（而非解析结果）"的规则，canon 相等就会漏真逃逸。**D 档：在引入此类规则前，等价判据必须加入"raw frontmatter 文本逐字相等"这一道闸，而非仅 canon 相等。**

### 反例 B（M1/M7 已排除，但暴露"冻结项"风险）
replay 读 `artifact_sha256` / `run_match_file` / 命令（L18、L602）。这些走工件层，与 frontmatter 完全无关 → 设计用"排除 M1/M7"处理。但若未来新增算子 `Mx` 改的是"能被某 frontmatter 规则间接反映、但又能被 replay 直接读"的字段，且 `Mx ∉ REPLAY_OPS`，则 canon 相等但 replay 判决不同 → 漏。→ **D 档：REPLAY_OPS 必须与"replay 实际读取的字段"严格同步维护**，否则新算子自动落入"假等价"。

## 4. 学术等价性武器（外部对标）

- **[ES8] Le et al., EMI (PLDI 2014)**：Equivalence Modulo Inputs——用"等价模输入"验证编译器。但程序等价性**不可判定**；本仓 canon 是**语法级**等价（解析视图相等），弱于语义等价，**不能 certify"无真逃逸"，只能 certify"无 frontmatter-规则 finding 变化"**。诚实标注 scope。
- **[ES9] McKeeman 1998 Differential Testing** / **[ES12] metamorphic testing (Chen et al.)**：都说明"单实现/单解析器不可信"→ 支持用**双解析器**（正是 N5 已做的），但双解析器仍共享底层 YAML 假设 → 非真异质（呼应 Q2 的 common-mode）。
- **test-equivalence 不可判定**：无法保证等价判据完整 → **必须偏向保守（fail toward not-equivalent）**，当前已实现；真正护栏在 `selfcheck_equivalent`，但其可靠性取决于 `classify` 是否把变体跑过**全规则集**。

---

## 5. 真正该查的洞（D 档，不是假设）

> `selfcheck_equivalent`（L703）只查 `verdict != escaped` 或 `new_block/new_warn`——它依赖 `classify` 把变体跑过**全规则集（含非 frontmatter 规则、replay 路径）**。若 `classify` 只跑 frontmatter 规则，则非 frontmatter 规则对"标 equivalent"变体产生的 finding **不被 selfcheck 覆盖** → 安全网出现缺口，§2 的"偏向保守"被反转。
> **这是本次红队找到的最该验证的洞**：我没有读 `classify` 的完整规则遍历范围，无法断言它覆盖全规则集。→ **D 档：开工前必须读 `mutation_fuzz.classify` 确认其遍历范围 = 全 RULES + replay 路径；否则 `equivalent` 标志的"漏标保护"是空的。**

---

## 6. 结论与最小加固（N 档）

1. **`equivalent` 标志必须处处带 scope 限定词**（"仅对只读 frontmatter 规则"），禁止在报告/看板中被误读为"无害变体"。
2. **等价判据补一道"raw frontmatter 文本逐字相等"闸**（防反例 A），并将 `REPLAY_OPS` 与 replay 实际读取字段严格同步（防反例 B）。
3. **D 档先验 `classify` 覆盖全规则集**，再谈 `selfcheck` 的可靠性。
4. 误判代价不对称 → 保持"偏向 not-equivalent"，并把 `equivalent` 的标红从"静默标签"升级为"可见 warn"，让人能复查。

> 否掉方向也算交付：不要宣称 N5 给出了"等价变异体的完备判据"。它给出的是**限定 scope 内的 sound 且保守的语法级判据**，语义等价（EMI 意义）不可判定，完备性不成立。
