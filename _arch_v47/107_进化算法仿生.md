# 方向107：进化算法仿生

## 一、从 Darwinian evolution 到可计算的进化算法：仿生对象不是“自然很聪明”，而是一个受约束的群体过程

进化算法的仿生起点应当写成 Darwinian evolution，而不是一句“模拟自然选择所以能自动变聪明”。达尔文在《物种起源》中讨论的是种群内部的变异、有限资源下的生存竞争、差异化繁殖以及可遗传性共同造成的长期适应；它不是一个有目标函数、有工程师指定终点的优化器。自然选择也不等于“强者永远胜出”：环境会改变，性状可能存在代价，偶然漂变、迁移、生态位和历史路径都会影响结果。计算机中的 genetic algorithm（GA）把其中一部分抽象成有限种群、编码、适应度、选择、交叉、变异、替换和终止条件；这是一种有用的工程类比，但不是生物学等价物。达尔文没有提出二进制染色体、轮盘赌选择或交叉算子，Holland 的遗传算法则把“群体中可遗传结构在选择压力下扩散”变成了可执行的搜索程序。遗传编程（genetic programming，GP）进一步把个体从固定长度字符串换成树、图或程序片段，让选择、交叉和变异直接作用于表达式、AST 或代码。Koza 1992 年的书名“通过自然选择编程计算机”概括了这一方向，但“程序能被进化”仍然依赖表示语言、语法约束、执行环境和外部评价器。

对阙疑 C++ 知识验证系统，真正值得移植的不是“自然选择”四个字，而是四个结构性原则。第一，候选应有谱系：每条候选断言、反事实测试或变异算子都要记录 `parent_id`、变异类型、交叉来源、随机种子、编译器矩阵和生成时间，才能知道它是新结构、旧结构重组，还是同一反例的换名。第二，选择必须作用于群体而不是单个冠军：保留多个互不支配的候选，才能避免早期偶然高分把探索空间锁死。第三，变异必须是受约束的可解释变换，而不是任意改字符串；例如改变 `const`、引用类别、模板约束、重载候选、整数边界、`noexcept`、临时对象生命周期、标准版本、编译器或 `-O0/-O2`，每一种变异都要声明预期保持的关系或预期产生的差异。第四，适应度不是事实本身，环境中的评价器才决定搜索会朝哪里走。若评价器只奖励已有规则触发数，系统会进化出越来越会讨好 67 条规则的代码，而不是发现规则盲区；若评价器只奖励“新颖”，系统会偏好不能编译、超时、未定义行为或随机诊断。

共享 brief 给出的现状是 37 张实卡、67 条规则、9 个保护器、452 条账本、3826 行内核；盲 holdout 为 30 条，其中真错 17 条，检出率 66.7%；外部 corpus 为 40 条，当前报告的 43.8% 算术口径仍不自洽；变异测试为 core 97.3%、all 81.5%；反事实指标为 `P=R=F1=0`。这些数字不能被包装成“系统已经具备进化能力”。它们首先是测量边界：core/all 的高变异分数说明既有变异集合可能被测试得较充分，不等于发现了未知 C++ 语义；`P=R=F1=0` 可能表示反事实 oracle、标签或分母未定义，也可能是实际没有可计数命中，必须先拆出 TP、FP、FN、TN、compile_fail、inconclusive 和 nondeterministic。Darwinian analogy 在这里最有价值的地方，是迫使我们把“候选产生”“候选竞争”“环境反馈”“谱系保留”和“外部证据”分开，而不是把一个高分个体直接叫作新知识。

本方向因此采用一个保守定义：进化算法仿生是借鉴遗传、选择、重组、变异和群体多样性来搜索候选验证对象；它不会自动提供真值，不保证比随机搜索好，也不能替代 C++ 标准语义、编译器差分、人工复核和盲态协议。对 NeurIPS 2027 E&D 目标，最可证伪的研究命题不是“GA 能发现知识”，而是“在固定候选预算、冻结评估器和独立 oracle 下，带 C++ 语义先验的群体搜索是否比等预算受限随机搜索产生更多可复核的新反例或新断言”。这一定义把仿生从宣传口号改成可检验的实验对象。

## 二、选择、交叉、变异、适应度与遗传编程：把 C++ 候选表示成可审计的语义个体

一个可落地的 C++ 进化测试个体，不应是没有类型约束的源码字符串，而应是一个带语义元数据的结构体：`program_ast` 或最小源程序、标准版本、编译器/版本、编译参数、预期关系、实际观察、触发的规则位图、变异谱系、语义描述子、证据状态和重放哈希。种群初始化可以从 37 张实卡、已确认的 15 条真实缺陷夹具、标准条款对应的最小例子、编译器官方测试和失败归档中抽取 seed，但初始化 seed 只能进入隔离的开发档案，不能读取或改变盲 holdout。候选的基因可以是 AST 子树、类型关系、约束谓词、语句顺序、值类别、资源生命周期事件和编译配置；交叉可以交换两个合法 AST 子树、组合两个相容的前提集合，或把一个变异算子嫁接到另一个语义场景；变异则必须经过语法、类型、资源和沙盒检查。对于 C++，最危险的错误是把“能生成文本”当作“生成了合法个体”：大量候选会编译失败、触发 UB、依赖实现未定义行为或受到版本差异影响。编译失败不应默认为低适应度，更不能在适应度中被错误地记成一个“新奇反例”。它应有单独状态，并与真正的诊断分歧、静默误编译、错误接受、错误拒绝、运行时崩溃和标准歧义区分。

选择机制要避免单一冠军策略。轮盘赌会把尺度和离群值直接转成选择压力，锦标赛选择容易在小种群中快速复制偶然高分，精英保留则可能把早期投机个体永久化。阙疑更适合先用硬门槛过滤 `invalid`、`unstable`、holdout 污染、保护器违规、评估器修改和账本重放失败，再对合法候选使用偏序或 Pareto 排序。一个候选的结果可以写成向量：`(new_semantic_cell, independent_evidence, metamorphic_consistency, stable_replay, regression_safety, novelty, cost)`。其中 `independent_evidence`、`stable_replay` 和 `regression_safety` 不是可以被 novelty 抵消的软分；若独立证据为零，候选最多是 `draft` 或 `unknown`，不能因为命中了更多旧规则而晋升 `verified`。现有 holdout 只有 30 条，真错数为 17，因此单一“命中数”只有有限的 0 到 17 离散取值，大量候选必然并列；此时硬做精细的标量适应度会制造虚假分辨率。方向79提出的 Pareto/NSGA-II 思路可以作为候选选择层，但必须先实测同一非支配层中的完全并列比例；如果并列严重，报告“oracle 信息量不足”比强行宣称多目标算法有效更诚实。

交叉和变异也不能只按生物术语命名。交叉的价值是重组可复用的语义片段，但 C++ 的语法树存在类型、作用域、生命周期和模板实例化约束；简单随机交换两个子树可能得到大量无意义程序。应给每个算子登记前置条件、保持关系、失败状态、最小化规则和外部证据需求。例如，`T&&` 到 `T&` 的变异可以用于探索值类别和引用绑定边界；加入或删除 `const` 可以探索重载和可修改性；调整 concept 或 `requires` 可以探索候选集合；交换 `-O0` 与 `-O2` 可以探索实现差异，但不能把优化差异直接解释为标准错误。交叉应优先发生在相同语义接口的 AST 区域，变异后再由 clang tooling、编译器和 sanitizer 矩阵验证。每个候选还应保存最小反例，因为一个长程序中同时改变十个因素，无法说明哪一个遗传片段造成了结果。

遗传编程的正面证据必须与其失败证据一起看。GenProg 论文报告在 16 个程序、合计 1.25 million 行 C 代码和 120,000 行模块代码、覆盖 8 类缺陷的实验中，平均耗时 357 秒；这证明 GP 可以把程序修改搜索组织成可执行流程，却没有证明遗传操作本身就是主要增益。RSRepair 随后在 7 个程序的 24 个真实缺陷版本上用随机搜索比较，23/24 个案例在补丁试验次数和测试执行次数方面优于 GenProg，并明确建议任何优化算法都应与随机搜索比较。这个结果对阙疑是硬约束：若 GA/GP 只在名称上复杂，实验上却没有超过受限随机、爬山、贪心或 LLM 直接生成，结论应是负结果。方向79已经提出随机搜索对照、Pareto 选择和“新规则=可证伪预测”登记；本方向的仿生实现只能在这些护栏内工作。

## 三、进化测试与方向79/84/85的合流：从“优化一个分数”转向发现可证伪的 C++ 边界

方向79回答的是“GA/GP 是否真的比随机搜索强，以及怎样把适应度改成偏序向量”；方向84回答的是“如何保持持续生成新挑战的 open-ended evolution，并用 QD、MAP-Elites、POET 式环境—策略配对避免只追逐一个冠军”；方向85回答的是“当目标函数可能欺骗搜索时，能否用 novelty search 和行为档案进入尚未覆盖的语义区域”。方向107的增量不是再重复三个算法名称，而是把 Darwinian 的群体过程、进化测试的执行反馈和阙疑的证据协议接成一条受限流水线：选择负责保留多条谱系，变异负责提出最小语义变化，交叉负责组合已验证的可复用片段，novelty/QD 负责防止空间塌缩，外部 oracle 负责决定候选是否值得进入知识审计。

方向79的第一条底线是 No Free Lunch：Wolpert 与 Macready 1997 年的定理不是说算法都无用，而是说算法在一类问题上的优势必须由问题结构解释，不能普遍外推。阙疑的结构先验包括 C++ 类型系统、AST、值类别、生命周期、模板约束、编译器矩阵、37 张实卡和 67 条规则；这些先验应显式进入表示和变异器，而不是偷偷藏在 prompt 或脚本里。第二条底线是随机搜索对照：GenProg/RSRepair 的 23/24 反转说明，复杂的选择—交叉—变异流程可能只是增加了控制开销。第三条底线是 MUTGEN 的代理指标警告：在一个 motivating example 中，测试套件可以达到 100% line/branch coverage，却只有 4% mutation score；其主评估在 204 个 subjects 上报告 HumanEval-Java 89.5%、Leetcode-Java 89.1% mutation score。这里最重要的不是照搬 Java 数字，而是说明“覆盖率、规则触发数、编译成功率和变异分数”都只能是任务相关的观测，不是知识真值。阙疑的 core 97.3%/all 81.5% 更不能被直接升级成“未知缺陷发现率”。

方向84的 open-ended 观点提示：只运行更多代数不等于持续创新。可以把 C++ 的标准版本、编译器、优化级别、模板深度、生命周期事件、诊断类型、异常路径和 sanitizer 组合看成 challenge environment，把变异器、测试生成器和最小化器看成 solving strategy；但环境生成器只能产生隔离挑战，不能写生产规则、保护器、holdout、标签和账本。POET 的原始实验维护 20 个活跃环境，使用 24 维输入、4 维输出的二维 Bipedal Walker Hardcore 任务，三次运行每次最多 25,200 次迭代；这些数字说明环境—策略配对可以形成 stepping stone，却不能外推为 C++ 验证必然成功。对阙疑应保留 `novelty_archive`、`challenge_archive`、`verified_archive` 三个不同档案：新颖但不稳定的样本只能留在探索档案；有新诊断分歧但没有标准证据的样本进入审计队列；只有经过独立复核的断言或反例才进入 verified。MAP-Elites 的 cell 可以按“类型复杂度×生命周期事件”“模板约束×诊断分歧”“优化等级差异×重放稳定性”划分，但 cell 设计必须版本化，否则修改描述子后档案增长会成为度量变化的假象。

方向85的 novelty search 进一步说明，纯目标导向搜索可能被欺骗，行为新颖性能够把候选带到不同区域；但纯 novelty 也会被投机。对阙疑，行为描述子不能是任意源码 embedding，而应是冻结工具链可重算的语义特征：AST 结构、值类别、引用绑定、模板/概念复杂度、生命周期事件、诊断类别、标准版本、编译器差异、规则触发位图、反事实关系状态和重复运行稳定性。候选必须先通过“可编译、非 UB 或明确标记 UB、可重复、保护器无违规”的硬门槛，再计算 novelty。方向85提出把 metamorphic relation 作为 oracle 约束，这正适合反事实：例如预先登记“只改变值类别，其他前提不变时应保持某项性质”，然后观察实际差异；如果差异稳定、最小、跨配置复现并有标准或专家证据，才可能成为候选新规则。否则它只是一个行为陌生样本。

进化测试的输出也应从“最高 fitness 的程序”改成实验对象集合。每个候选需要有自然语言断言、形式化谓词、最小源程序、父代和变异序列、预期关系、实际结果、编译命令、标准版本、工具链哈希、随机种子、重放状态、证据来源和失败判据。一个可证伪断言应在看到盲 holdout 结果之前登记；如果外部新时间切分、真实缺陷夹具或独立编译器矩阵不支持它，就记录 negative result，不删除历史、不修改规则以营造进步。这样，“进化发现新知识”被严格拆成“产生候选—通过隔离执行—获得独立证据—由人工或标准来源晋升”。这比把一条漂亮的规则称为自动发现更慢，却更符合阙疑的四态判决和 E&D 对评估本身的要求。

## 四、适应度投机、规则退化与进化安全：为什么“越进化越高分”可能意味着系统越不可信

适应度投机的本质是候选优化了评分器的可见表面，而没有实现研究者的真实目的。阙疑至少有八个投机面。第一，候选反复命中已有 67 条规则，把规则触发量伪装成新发现；第二，通过增加代码长度、模板深度或无意义语法噪声制造 novelty；第三，利用编译器崩溃、超时或 UB 产生看似罕见的行为差异；第四，改变日志字段、顺序或 hash 让 452 条账本“新增”而语义重复；第五，读取 holdout、标签或评估器状态，专门针对 30 条盲样本过拟合；第六，生成一组相互依赖的候选，让同一个错误证据在群体中互相投票；第七，修改测试脚本、规则快照、保护器或评分程序；第八，用极低成本的大量失败样本挤占人工复核预算，使真正重要的候选无法被审计。

因此，适应度必须分成不可补偿的硬失败和可比较的软目标。硬失败包括 `holdout_contamination`、`evaluator_modified`、`protector_violation`、`ledger_replay_mismatch`、`non_deterministic_replay`、未声明 UB、环境缺件和不支持的事实断言；任何一个硬失败都使候选不能进入正式选择池，无论 novelty 或 coverage 多高。软目标可以是新增语义 cell、独立证据数量、反事实关系一致性、跨编译器重放率、既有真实缺陷夹具保持率、最小化程度、人工复核成本和行为新颖性。不要把这些目标未经论证地加权成一个标量；用词典序硬门槛、Pareto 非支配、分层档案或质量—多样性 cell 更稳妥。若必须给出总排序，也应把权重、单位、敏感性分析和随机搜索基线预注册，并报告不同权重下是否改变结论。

规则退化比普通早熟收敛更危险。普通 GA 的早熟收敛是种群个体趋同；阙疑的规则退化则可能表现为规则越来越多、命中越来越高、但知识边界越来越窄：新规则只是已有规则的同义改写，保护器被绕开，反事实指标仍为零，外部 corpus 的算术问题被掩盖，或者所有候选都围绕最容易触发的编译错误而忽略静默误编译、错误接受和标准歧义。应监测规则的语义去重率、触发分布熵、规则之间的覆盖重叠、独立证据比例、跨编译器稳定性、真实缺陷夹具回归率、候选谱系深度、有效 cell 占用率和失败类别比例。新增规则必须经过等价性检查和最小反例检查；若新规则只能在已有规则触发后成立，不能把它报告成独立发现。规则生产线必须是 append-only 提议，而不是在线自修改：搜索器可以生成 `R-NEW-xxx`，不能直接覆盖 67 条生产规则；人工晋升后生成新版本快照，旧快照、负结果和被拒绝候选都保留。

“适应度投机”还要求主动对抗评估器，而不是只在结果出来后解释。每轮进化都应加入已知的 mutation kill、已知真错、已知真不应触发、编译失败、UB、非确定性和规则冲突夹具；这些夹具不能成为可读取的标签源，而是由外部 runner 只读执行。应对评估器做红队式自测：故意改变日志顺序、删掉诊断、制造重复语义、改变临时路径、延长编译时间、加入不影响语义的 AST 噪声，检查评分器是否错误地把这些现象当成新知识。候选进程采用只读源树、无网络、资源限额和临时工作区；评分器在另一个进程或容器中运行，标签、holdout、规则快照和账本写接口对候选不可见。若候选尝试写入评估器或保护器，应记录为安全失败，而不是将其行为解释成创新。

反事实 `P=R=F1=0` 是本方向的关键压力测试。进化算法不应被用来“刷出一个非零 F1”来掩盖指标定义错误。先对反事实关系建立小型黄金集：已知应保持的关系、已知应改变的关系、不可判定关系和编译失败关系各自单列；为每个关系明确 TP、FP、FN、TN 的定义，并在分母为零时输出 `undefined` 而不是 0。只有当基础 oracle 能在黄金集上稳定恢复非零、可解释、可重算的指标，才允许把 GA/GP 的 fitness 接到反事实检测率。反之，若进化系统在 oracle 仍不稳时取得漂亮分数，最可能的解释是它进化出了评分器漏洞。core 97.3%/all 81.5% 也要保留为变异测试背景指标，并同时报告变异集合构成、等价变异、未执行变异、编译失败和真实缺陷重注入结果；不能把变异 score 直接当作“新规则有效性”。

## 五、结论、诚实盲区、来源与对阙疑的三条具体行动

结论是：Darwinian evolution 给阙疑的启发是“群体、谱系、变异、选择和环境反馈必须分层”，GA/GP 给出可执行的候选搜索框架，进化测试给出通过编译器、差分执行、变异关系和外部 oracle 发现反例的工程路径；但三者都不能替代真值。方向79证明必须有随机搜索对照、显式领域先验和偏序适应度；方向84证明开放式进化需要档案、挑战环境、质量—多样性和停止条件；方向85证明新颖性可以绕开欺骗目标，却也依赖正确的行为描述子和外部关系约束。它们合并后的阙疑方案应是：只读 seed 和语义变异器生成候选，冻结评估器进行编译/运行/差分，Pareto 或 QD 档案保留多样谱系，反事实关系负责提供可审计约束，盲态和 append-only 账本负责防止回盲，人工或独立来源负责最终晋升。系统能否优于随机搜索，必须由等预算、同工具链、同随机种子协议下的可复现实验回答。

诚实盲区有六项。第一，现有直接证据主要证明 GA/GP 可用于自动修复、测试生成或变异算子搜索，没有找到“自动发现 C++ 静态验证规则”的成熟对照基线，因此阙疑若完成该任务，创新性和评价难度同时存在。第二，GenProg 的 16 个程序、1.25 million 行 C、120,000 行模块代码和 357 秒，以及 RSRepair 的 7 个程序、24 个缺陷、23/24 优于 GenProg，来源可核实，但不能外推到 37 张实卡。第三，MUTGEN 的 100% coverage/4% mutation score 是 motivating example，不是所有数据集总体结果；204 subjects、89.5%/89.1% 是其特定 Java 基准结果，只能作为代理指标警告，不能直接当作阙疑提升。第四，MetaMut 摘要报告约 118 个语义感知 mutator、每个约 0.5 美元、在 GCC/Clang 发现 131 个 bug、其中 129 个确认或修复，但这是编译器变异算子的成功，不等于静态知识规则被自动发明。第五，`P=R=F1=0` 和 corpus 43.8% 仍需项目内部重新审计，本文没有重新运行阙疑代码，不能声称已经修复。第六，生物进化中的漂变、生态互作和遗传机制与计算 GA 有层级差异；“仿生”只说明设计启发，不赋予算法科学正确性。
