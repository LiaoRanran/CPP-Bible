# 方向 19：匿名化仓库怎么搞（E&D 默认双盲，代码也要匿名）

## 核心结论

1. **E&D 默认双盲，代码/数据必须用匿名账户托管，且"匿名"不仅是换用户名，而是要系统性擦除作者身份痕迹（姓名、单位、邮箱、个人域名、致谢、git 历史里的作者行）。** NeurIPS 2026 E&D FAQ（2026-04-07）逐字：*"Outside of these cases, submissions should be double blind, using anonymous accounts on data hosting platforms …"*。官方推荐工具：FAQ 明确 *"an anonymization service (https://anonymous.4open.science/) or another method"*。Anonymous GitHub（anonymous.4open.science）的核心机制是：*"Anonymous Github makes a read-only mirror of your repository … with every trace of the author's identity removed"*——即只剥 GitHub 用户名与提交者显示名，但**不会**自动清理 README/源码注释里硬编码的真名或 `git log` 的 author email（需配合方向 28 的 git filter-repo）。

2. **双盲匿名要擦的"身份面"至少有 7 类，漏掉任一类都可能被判匿名性违规：** ① GitHub 用户名/组织名（靠匿名镜像解决）；② 作者真名与拼音（README、论文 PDF 元数据、源码 header 注释）；③ 机构/实验室/学校名（致谢、README 介绍）；④ 个人邮箱与域名（`@ahtu.edu.cn` 之类，git log + README）；⑤ 个人主页/博客链接；⑥ 致谢（"感谢我的导师/课题组"）；⑦ 数据集里的 PII（corpus 40 若含论坛用户名，见方向 18）。ACM/OpenReview 双盲指南反复强调：*"Do not include anything … that would compromise reviewer anonymity"*（方向 26 引 POPL）以及 OpenReview 的 *"anonymized for double-blind review"* 要求。

3. **匿名化有"镜像式"（轻量、推荐）与"重写式"（彻底、适合录用后或自建匿名组织）两档，阙疑在投稿期用镜像式、camera-ready 前可转自建匿名组织。** Anonymous GitHub（tdurieux/anonymous_github，2026-09 仍活跃）是开源实现，原理是克隆仓库→剥离身份→发布为 `anonymous.4open.science/r/<slug>` 只读链接；Zenodo 则提供 *anonymous DOI*（投稿期隐藏作者，录用后解匿名）。两档对比：镜像式零摩擦但不改 git 历史（历史仍可能暴露 email），重写式（git filter-repo，方向 28）能彻底清历史但操作重。

## 精确数字与案例

### 一、NeurIPS 2026 E&D 双盲条款逐字

来自 E&D FAQ 与 CFP：

| 条款 | 逐字原文 | 对阙疑含义 |
|---|---|---|
| 默认双盲 | FAQ：*"Outside of these cases, submissions should be double blind, using anonymous accounts on data hosting platforms …"* | 代码/数据必须匿名账户 |
| 推荐工具 | FAQ：*"an anonymization service (https://anonymous.4open.science/) or another method"* | 官方点名 anonymous.4open.science |
| 代码可执行 | CFP：*"Code should be documented and executable."*（方向 20 详述） | 匿名后仍须可跑 |
| 数据最终形态 | FAQ：*"datasets and code … must be submitted in their final form by May 6, 2026 (AOE)"* | 匿名镜像须在截止前就绪 |

**关键张力**：E&D 同时要求"代码可执行 + 双盲匿名"。匿名镜像必须是**可运行的只读副本**（不能因为匿名就把运行入口删了），所以匿名化操作要"擦身份、保功能"。

### 二、anonymous.4open.science / Anonymous GitHub 机制

- **官方定位**（anonymous.4open.science 首页）：*"Share the code, not the author. Anonymous GitHub makes a read-only mirror of your repository, pull request, or gist with every trace …"* —— 重点：read-only、mirror、剥离身份。
- **开源实现**（tdurieux/anonymous_github，GitHub，2026-09-03 仍更新）：*"Double-anonymous review asks you to anonymize the artifact behind your paper — the code and data — exactly like …"*（与论文双盲对齐）。
- **能力边界（重要）**：镜像自动处理 GitHub 用户名/组织名与提交者显示名，但**不**清理：① README 正文里的真名/邮箱；② 源码文件头注释里的作者；③ git 历史 `author.email`（除非源仓库历史已清，见方向 28）；④ 论文 PDF 元数据（author 字段）。**所以匿名化是"镜像工具 + 人工清理 + git 历史清洗"三件套，缺一不可。**

### 三、须擦除的 7 类身份面（自查清单）

综合 NeurIPS FAQ、OpenReview 双盲政策、POPL 2026 AE 指南整理：

| # | 身份面 | 常见藏身点 | 处理方式 |
|---|---|---|---|
| 1 | GitHub 用户名/组织 | 仓库 URL、fork 网络 | 匿名镜像自动剥 |
| 2 | 作者真名/拼音 | README 标题、源码 header、`@author` | 人工替换 |
| 3 | 机构/学校名 | 致谢、README 介绍 | 人工删 |
| 4 | 个人邮箱 | README、`git log` author、`.mailmap` | git filter-repo（方向 28） |
| 5 | 个人域名/主页 | README 链接、论文页 | 人工改匿名 |
| 6 | 致谢句 | README/论文 | 人工删（camera-ready 再加） |
| 7 | 数据内 PII | corpus 40 来源标注 | 方向 18 RAI 字段 + 扫描 |

**特别提示（双非/0 影响力作者的反向优势）**：匿名化对阙疑是**利好**——双盲本就削弱作者声望的权重，正合"0 影响力本科生"的中立诉求；但反过来说，一旦匿名不到位（漏了 `@ahtu.edu.cn`），审稿人一眼认出学校，**双盲的保护反而失效且可能被视为违规**。

### 四、Zenodo 匿名 DOI 与录用后解匿名

- **Zenodo**（CERN 运营，默认给每个上传物一个 DOI）支持 *anonymous DOI*：投稿期隐藏作者与机构，链接给审稿人；录用后作者可"解匿名"让元数据公开。这对"数据集要永久可引"的场景（方向 17/20 的 SWHID 之外）是另一种持久标识。
- **与 Croissant 的关系**（方向 18）：Zenodo/HF/OpenML 都支持 Croissant，匿名 DOI 数据集 + Croissant 元数据 = "双盲 + 机器可读 + 永久可引"三件套。
- **解匿名时机**：NeurIPS 规定录用后 camera-ready 阶段才允许回填作者信息；此前任何公开作者身份（如在 Twitter 自曝、或个人主页挂预印）都可能违反双盲并触发调查。

### 五、OpenReview 与"主动泄露"风险

NeurIPS 用 OpenReview 投稿，平台本身有 *"anonymized for double-blind review"* 的提交约束。但风险常在**作者主动泄露**：① 把预印挂 arXiv 且未设匿名（arXiv 允许作者匿名投稿但需主动申请）；② 在社交媒体/个人站宣传；③ 代码仓库未被匿名镜像、直接给 `github.com/queyi/...`（会被审稿人搜到）。**对单人项目尤其危险**——作者名与项目名高度绑定，"queyi" 一旦和真实姓名关联，双盲形同虚设。建议：投稿期项目以匿名 slug 出现，真实身份仅在 camera-ready 揭晓。

## 对阙疑的 3 条具体行动

1. **2026-12 前用 anonymous.4open.science 生成只读镜像，并在提交前做"7 类身份面"人工自查表（覆盖 README、源码 header、论文 PDF 元数据）。** 步骤：① `git push` 干净仓库到私有 GitHub；② 在 anonymous.4open.science 输入仓库生成 `anonymous.4open.science/r/queyi-XXXX`；③ 人工搜 README 与 `.py` 文件头的真名/邮箱/学校/`@ahtu` 并删除；④ 确认论文 PDF 的 author 字段为匿名占位（OpenReview 提交时填匿名）。理由：FAQ 逐字要求"anonymous accounts"，且镜像只剥 GitHub 用户名不剥正文，人工清理是硬缺口。

2. **2026-12 同步用 git filter-repo 清洗 `git log` 的 author email 与 name（见方向 28），保证镜像背后的历史也不泄露身份。** 关键命令：准备 `mailmap` 把真实邮箱映射到匿名占位（如 `anon@anonymous.4open.science`），用 `git filter-repo --mailmap mailmap.txt` 重写全部历史；提交信息里若含 `@ahtu.edu.cn` 用 `--replace-text` 替换。理由：匿名镜像虽剥显示名，但 `git log` 的 author email 字段若未清，下载仓库的审稿人仍能看到真实邮箱——这是最常见的"匿名失败"盲区。

3. **2027-03 前规划"解匿名时间线"：录用后（约 2027-09）在 camera-ready 阶段回填作者/单位/致谢与 GitHub 真名，并把匿名镜像转为正式仓库（或保留镜像 + 加正式链接）。** 同时把匿名期链接写进论文 artifact 段，正式链接写进 camera-ready 脚注。理由：NeurIPS 要求 camera-ready 前才揭身份；提前泄露（如个人站挂预印）会被视为双盲违规。建议在 `research/19_anonymity.md` 记录该时间线与自查清单，作为投稿前 checklist。

## 盲区（诚实标注）

- **NeurIPS 2026 E&D FAQ 的"double blind … using anonymous accounts"逐字引文来自检索摘要**，未逐字打开正文核对完整段落；建议提交前 WebFetch 复核其是否对"代码仓库匿名"有更细规定（如是否接受自建匿名组织而非仅 anonymous.4open.science）。
- **Anonymous GitHub（tdurieux）的"剥离身份"具体算法未逐字读源码**——本组依据其首页/README 描述推断它剥用户名与显示名，不排除它已支持清洗 README 正文（需实操确认）。
- **Zenodo 匿名 DOI 的实际申请流程与时延未逐字核实**（本组仅确认其存在与"录用后解匿名"机制），提交前需实操一次确认。
- **OpenReview 对 NeurIPS 2026/2027 的具体双盲约束（是否自动检测作者泄露）未逐字核实**；本组引用其一般性 "anonymized for double-blind review" 表述。
- **"corpus 40 是否含 PII"未做扫描**（仅作为待办列入身份面第 7 类），若含论坛用户名则匿名化需额外处理数据而非仅元数据。
- **未核实**：E&D 是否接受"作者自建匿名 GitHub 组织"作为 anonymous.4open.science 的替代（FAQ 写"or another method"，但评审实操接受度未知）。
- **双非/0 影响力作者在双盲下的"反向优势"是本组推断**，无统计数据支撑；且匿名失败的风险对单人项目更高，这一权衡需谨慎。
