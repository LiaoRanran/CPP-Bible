# 方向 86：模型窃取/提取攻击（Model Stealing / Extraction）

## 核心结论

1. **模型提取攻击已被实证可低成本复刻生产级模型**：Carlini 等 14 位作者（Google DeepMind / ETH Zürich 等）在 ICML 2024 论文《Stealing Part of a Production Language Model》中，用 **不到 20 美元** 的 API 查询费完整提取了 OpenAI Ada 与 Babbage 的嵌入投影矩阵，并首次确认两模型隐藏维度分别为 **1024 与 2048**；对 gpt-3.5-turbo 估计 **2000 美元以内** 即可提取完整投影矩阵（arXiv:2403.06634）。起点则是 Tramèr 等 USENIX Security 2016 的开创论文：黑盒查询即可"以近完美保真度"提取逻辑回归、神经网络与决策树，并在 BigML 与 Amazon Machine Learning 上实测成功（arXiv:1609.02943）。
2. **攻击的杠杆点几乎都是 API 输出侧的多余信息**：Carlini 攻击之所以成立，是因为 OpenAI API 同时暴露 `logit_bias` 与 `logprobs`——论文给出 "This attack reveals the value of K-1 logits with each query"（每次查询可廉价获得多路 logit），最优变体 **每 logit 仅需 0.25 次查询、23.0 bit 精度**。负责任披露后 OpenAI 与 Google "have implemented defenses to prevent our attack or make it more expensive"（已实施防御或抬高成本）。这印证一条规律：**防御的本质是削减输出信道的信息量（节流、互斥、加噪、检测），而非"隐藏模型"本身**。
3. **对阙疑的直接含义**：阙疑的卖点"判决可复算 + 独立对账器"意味着其判定内核天然适合以 API 形式暴露——而判据规则集（67 规则）与判决逻辑（内核 `gate_engine.py` 3826 行）就是需要保护的知识资产。文献表明：（a）确定性输出 + 置信度暴露 = 最易被提取；（b）水印类防御（S&P 2024 的 MEA-Defender、ICML 2024 的 Bayesian Active Watermarking）已从"被动检测"走向"主动干扰提取"；（c）检测类防御（PRADA, EuroS&P 2019）在分布差异检测上有效但可被对抗规避。阙疑应把"判决 API 的提取威胁模型"写进论文的 threats-to-validity，并设计最小暴露接口。此外必须认识到：NeurIPS E&D 审稿人关注"评测基础设施本身的科学性"，若评测资产（盲集、夹具、判据）可被一条条查询窃走，则评测结论的排他性与可审计性都会被质疑——知识产权防护因此不只是工程问题，而是评测方法学的组成部分。

## 精确数字与案例

### 一、奠基案例：Tramèr et al., USENIX Security 2016

**论文**：*Stealing Machine Learning Models via Prediction APIs*，作者 Florian Tramèr, Fan Zhang, Ari Juels, Michael K. Reiter, Thomas Ristenpart（Cornell Tech / ETH / UNC / UW 等）。arXiv:1609.02943，2016-09 提交。

摘要逐字引文（arXiv v2）：

> "We show simple, efficient attacks that extract target ML models with near-perfect fidelity for popular model classes including logistic regression, neural networks, and decision trees. We demonstrate these attacks against the online services of BigML and Amazon Machine Learning."

> "We further show that the natural countermeasure of omitting confidence values from model outputs still admits potentially harmful model extraction attacks."

两条对阙疑重要的教训：（1）**即使去掉置信度输出**，仅靠标签输出仍可提取——说明"只返回四态判决、不返回分数"并不能免除提取风险，只能抬升成本；（2）该文同时提出方程求解式（equation-solving）提取，对线性模型与决策树查询次数在数万次量级即可重建（具体每模型查询数未在本次检索中逐字核实，见盲区）。

### 二、里程碑案例：Carlini et al., ICML 2024——生产级 LLM 的参数级窃取

**论文**：*Stealing Part of a Production Language Model*，作者 Nicholas Carlini, Daniel Paleka, Krishnamurthy Dj Dvijotham, Thomas Steinke, Jonathan Hayase, A. Feder Cooper, Katherine Lee, Matthew Jagielski, Milad Nasr, Arthur Conmy, Itay Yona, Eric Wallace, David Rolnick, Florian Tramèr。arXiv:2403.06634（2024-03-11 v1，2024-07-09 v2），发表于 ICML 2024（PMLR v235, carlini24a）。

摘要逐字引文：

> "For under $20 USD, our attack extracts the entire projection matrix of OpenAI's Ada and Babbage language models. We thereby confirm, for the first time, that these black-box models have a hidden dimension of 1024 and 2048, respectively. We also recover the exact hidden dimension size of the gpt-3.5-turbo model, and estimate it would cost under $2,000 in queries to recover the entire projection matrix."

攻击经济性（论文 Table 3 摘录，WebFetch 自 arXiv HTML v2）：

| 模型 | 维度提取查询数 | 维度提取成本 | 权重矩阵提取查询数 | 权重矩阵提取成本 |
|---|---|---|---|---|
| OpenAI ada | <2·10^6 | $1 | <2·10^7 | $4 |
| OpenAI babbage | <4·10^6 | $2 | <4·10^7 | $12 |
| gpt-3.5-turbo-instruct | <4·10^7 | $200 | <4·10^8 | $2,000（估计值†） |
| gpt-3.5-turbo-1106 | <4·10^7 | $800 | <4·10^8 | $8,000（估计值†） |

† 脚注注明 "Estimated cost of attack given the size of the model and estimated scaling ratio"，即 gpt-3.5 全矩阵提取**未实际实施**（"Attack not implemented to preserve security of the weights"）。

各攻击变体效率（Table 4 摘录）：

| 变体 | 依赖输出 | 每次查询精度 | 每 logit 查询数 |
|---|---|---|---|
| logprob-4 | top-5 logprobs | 23.0 bit | **0.25** |
| logprob-1 | top-1 logprob | 6.1 bit | 1.0 |
| binary search（无 logprobs） | 仅输出文本 | 7.2 bit | 10.0 |

**防御与厂商响应**（原文 Section 8 及正文逐字引文）：

> "Logit bias XOR logprobs. Our attack is 10× cheaper when an adversary can supply both a logit bias and also view output logprobs. This suggests a natural mitigation: prohibit queries to the API that make use of both logit bias and logprobs at the same time."

> "after responsible disclosure, both APIs have implemented defenses to prevent our attack or make it more expensive."

其他建议的防御：直接移除 logit_bias；以 block-list 替代；架构上把最后一层拆为 h→t→l 并插入非线性（因为 "Our attack only works because the hidden dimension h is less than the output dimension l"）；对输出 logits 加噪——原文坦承 "logit-noise has the potential to make models less useful"；对 logit_bias 查询做速率限制（每个 prompt 最多 T=h̃/5 次）；以及基于反滥用工具检测恶意查询。另确认 OpenAI API 限制 logit_bias 至多 **300 个 token**、范围 **[-100,100]**，且 **2023 年已移除 echo+logprobs 组合**。中文媒体报道（36 氪，2024-03-12）将攻击成本折算为"成本低至 150 元，调用次数少"。

### 三、防御谱系：检测、节流、水印——三类的实证效果

| 防御类别 | 代表工作 | 关键事实（已核实） |
|---|---|---|
| 异常查询检测 | PRADA: *Protecting Against DNN Model Stealing Attacks*（EuroS&P 2019, arXiv:1805.02628） | 自称 "the first step towards generic and effective detection of DNN model extraction attacks"，通过检测查询输入在 victim 模型内部中间分布上的统计差异识别提取式查询；该文同时给出了新的合成查询提取攻击（证明检测的必要性） |
| 被动水印 | MEA-Defender（IEEE S&P 2024, DOI 10.1109/SP54263.2024.00099） | 指出 "most of such watermarks fail upon model extraction attack"；提出把两个源类样本组合成水印样本、使水印的输入域与输出域都落在主任务样本域内，从而**在提取时被一并带入克隆模型**；在 4 种提取攻击 × 5 数据集 × 6 模型上验证鲁棒性 |
| 主动水印 | *Defense against Model Extraction Attack by Bayesian Active Watermarking*（ICML 2024, PMLR 235:51913-51935，Wang/Wu/Huang） | 归纳现有防御三大缺陷：(1) 部署时计算/内存低效；(2) 依赖昂贵的防御性重训练；(3) "watermarking-based methods only passively detect model theft without actively preventing model extraction"。方案：微调 victim 学水印后验，推理时随机采样水印加到查询输入上 |
| 领域特定水印 | Bounding-box Watermarking（Koda & Morikawa，arXiv:2411.13047，ECML-PKDD 2025） | 针对目标检测 API，通过隐蔽修改检测框注入后门水印；论文报告 "succeeded in identifying the extracted models with 100% accuracy in a wide variety of experimental scenarios" |
| 反例：防御为何难 | *On the Difficulty of Defending Self-Supervised Learning against Model Extraction*（ICML 2022, PMLR v162, Dziedzic 等） | 实证表明自监督编码器因输出维度大、特征丰富，**比监督模型更难防御提取** |

**LLM 专项综述**：《A Systematic Survey of Model Extraction Attacks and Defenses》（arXiv:2508.15031，2025-08）按攻击机制（基于查询、侧信道等）、防御策略（检测、水印、预防）与计算环境建立分类法；《面向大型语言模型的模型提取攻击与防御综述》（arXiv:2506.22521，2025-06）覆盖 LLM 特有的提取面。水印/指纹综述另见 Springer *Artificial Intelligence Review*（2026-02，DOI 10.1007/s10462-025-11474-6）与 ACM *Securing Large Language Models: A Survey of Watermarking and Fingerprinting*（DOI 10.1145/3773028）。

### 四、现实约束：查询节流在商用 API 中的形态

WebFetch OpenAI 速率限制文档（platform.openai.com/docs/guides/rate-limits，2026-09 现状）核实的结构：

| 层级 | 资格条件 | 月度用量上限 |
|---|---|---|
| Free | 位于允许地区 | $100/月 |
| Tier 1 | 已付费 $5 | $100/月 |
| Tier 2 | 已付费 $50 | $500/月 |
| Tier 5 | 已付费 $1,000 | $200,000/月 |

文档明确速率指标为 RPM（请求/分）、RPD（请求/天）、TPM（token/分）、TPD（token/天）、IPM（图像/分），"任何一项先达到即触发限制"；限制作用于**组织与项目级别**而非用户级别。注意：文档中 `x-ratelimit-limit-requests: 60`、`x-ratelimit-limit-tokens: 150000` 等只是**示例响应头**，非真实 Tier 1 数字（见盲区）。两个已核实的具体数字：向量存储接口 `/vector_stores/{id}/files` 限 **300 请求/分**；Carlini 攻击能得逞的深层原因正是 API 允许单次请求携带高信息量参数（logit_bias 300 token × [-100,100] 区间）。这组事实说明：**商用节流按"资源消耗"计（token/请求），而提取防御需要按"信息泄漏量"计**——两者错位，是论文可指出的结构性缺口。

### 五、中文文献补充与"判定型系统"的提取面

中文文献方面，本次检索核实了两篇系统综述：其一为《深度神经网络模型水印研究进展》（上海理工大学期刊社，2024 年第 3 期），按提取方式梳理各类水印方案，指出"以神经网络水印为代表的深度模型知识产权保护技术在近年来受到了广泛关注"；其二为《深度神经网络模型数字水印技术研究进展综述》（信息技术与工程期刊，2023-03），覆盖多类水印版权保护技术。两者共同确认：国内研究以水印/溯源为主线，对**判决型 API**（输出为离散裁决而非概率分布）的提取攻击与防御基本没有覆盖。

这一空白对阙疑意味着什么？传统模型提取攻击的目标是重建决策函数——输入连续、输出有梯度信息可爬；而阙疑的判定内核（`gate_engine.py`）输入是 C++ 知识断言与知识卡，输出是四态离散判决加规则编号。这类接口的"可提取性"呈现新的形态：其一，判决是**确定性**的，同输入必同输出，攻击者无需估计概率面，只需充分采样规则触发边界即可复刻；其二，67 条规则中每条规则独立触发，攻击者可以按规则逐一构造探针查询（类似变异测试的算子枚举），**规则集结构本身成为攻击的脚手架**；其三，阙疑引以为傲的"判决可复算"恰恰降低了攻击者的验证成本——被窃取的克隆体可以通过独立对账器做一致性自检。因此"可复算"是把双刃剑：它既是科研卖点，也是窃取方的质检工具。论文写作时应把这一对矛盾显式讨论，而不是只当作优势陈述。

## 对阙疑的 3 条具体行动

1. **建立判决 API 的提取威胁模型（时间点：2027-05 前，论文投稿准备期）**：在 `research/12_threats_to_validity.md`（若无则新建）增加小节 **T9 "Verdict-API Extraction Threat"**，内容至少包括：(a) 威胁定义——攻击者以黑盒查询复算逻辑（`gate_engine.py` 3826 行）与 67 条规则（block 44 / warn 16 / advice 7）的功能等价物；(b) 引用 Tramèr 2016 "omitting confidence values still admits extraction" 说明**只返回四态判决**不足以免疫；(c) 给出阙疑自身的查询经济性估算——复算一条 C++ 知识卡判决需要多少输入 token、暴露多少信息位（对照 Carlini 0.25 queries/logit 的度量方式），写入论文 Experiment 节的 defense 段落。
2. **接口最小暴露设计（时间点：2026-12 前，与 452 条判决账本重构同步）**：在判决 API 规范中落实三层防御：(a) **信息节流**——响应只含四态判决 + 规则编号（如 `{"verdict": "BLOCK", "rules": ["R001","R017"]}`），不返回分数/中间量，并在响应中加入与 Carlini "logit bias XOR logprobs" 同构的**互斥限制**：任何单一调用不得同时返回"判据文本"与"账本哈希"；同 key 每 prompt 的维度探测类查询限速（对照论文 T=h̃/5 思路，阙疑可定为同源查询 5 次/分）；(b) **审计留痕**——把每次 API 查询作为一条记录写入 append-only 哈希链账本（复用现有 Merkle checkpoint 机制），供事后取证与 PRADA 式分布检测。
3. **把"验证基础设施的 IP 保护"写成 E&D Track 卖点（时间点：2027-06 前）**：在论文中新增小节（建议标题 *Protecting the Evaluation Infrastructure Itself*），论证：阙疑的 30 条盲 holdout、40 条外部 corpus 与 15 条真实缺陷夹具是可复用资产，若经 API 暴露会被"夹具窃取"（bench-set stealing）。具体做法：借鉴 S&P 2024 MEA-Defender"水印落在样本域内"的思想，在 draft 卡（现有 11 张）中植入 2–3 条**金丝雀卡**（内容仅存在于 corpus、发布时替换为同构占位符），一旦第三方评测系统复现出金丝雀卡上的四态判决组合，即构成使用证据；同时在仓库 `README` 中记录金丝雀卡哈希（不上传卡内容）。这直接呼应 E&D Track "evaluation itself becomes an object of scientific study" 的定位。

## 盲区（诚实标注）

- **Knockoff Nets（Orekondy et al., CVPR 2019, arXiv:1812.02766）的具体提取精度/F1 数字未核实**：本次仅核实了摘要级表述（"We formulate model functionality stealing as a two-step approach…" 与在图像分析 API 上的验证），未打开原文表格抄录数字，本文未引用其具体百分比。
- **"Thieving LMs"（疑为 ICLR 2023 的蒸馏式语言模型窃取工作）未检索到**：两轮英文检索（"Thieving LMs" + distillation / side channels）均未命中该论文，无法确认标题、作者与数字，故不引用。若该文存在，属本方向重要一环，待后续核实。
- **OpenAI 当前真实的 RPM/TPM 数字未核实**：官方文档只给出 tier 资格门槛与月度上限，具体每模型速率需登录 developer console 查看；文档中的 `60 requests / 150000 tokens` 是示例值，切勿当作真实限制引用。
- **gpt-3.5-turbo 的 $2,000 / $8,000 是论文的缩放估计值，非实测**：作者明确脚注 "Attack not implemented to preserve security of the weights"；36 氪"150 元"仅对应 <$20 的 ada/babbage 实测项。
- **PRADA 的检出率/误报率具体数字未核实**：仅核实其"第一个通用检测步骤"的定位与机制描述，未抄录实验表。
- **样本偏差**：本方向的经典案例（Tramèr 2016、Carlini 2024）全部来自巨头 API 的分类/生成模型；对"判定型系统"（输出为离散裁决而非分布）的提取攻击实证研究几乎空白——这既是阙疑的写作机会，也意味着**没有可直接移植的数字**，行动 1 中的查询经济性估算必须自行实验得出。
- **商业防御实效未核实**：多账号（Sybil）绕过查询节流、盗刷免费额度、租用高层级账号等真实世界滥用路径的公开统计数据本次未检索到；水印防御在法庭与平台申诉中的实际采信情况（是否有已判例或平台处置案例）也未核实，论文引用时需注明"防御有效性多数止步于实验室数据集评估"这一局限。
