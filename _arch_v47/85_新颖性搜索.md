# 方向 85：新颖性搜索（novelty search）

## 一、问题定义：新颖性搜索不是“随机制造怪代码”，而是把行为差异变成探索信号

新颖性搜索（novelty search）的核心问题是：当我们不知道“通往真正好答案的中间路径”时，是否可以暂时不把一个可能有欺骗性的目标函数当作唯一导航，而改为寻找与历史行为不同的候选。Lehman 与 Stanley 在 2011 年的 *Abandoning Objectives: Evolution Through the Search for Novelty Alone* 中把这种思路系统化：传统进化搜索用 fitness 衡量离目标还有多远，但目标函数可能形成 deception，把搜索吸引到局部上升、最终却无法到达目标的死胡同；novelty search 则按照行为表征（behavior characterization）之间的距离评价候选。该文在迷宫导航和双足行走任务中报告了一个反直觉结论：忽略显式目标、只沿行为新颖性搜索，在这些具有欺骗性目标函数的任务上反而显著优于目标导向搜索。这里必须把“忽略目标”理解为搜索阶段的策略，而不是把正确性和外部证据删掉。对于阙疑 C++知识验证系统，候选不是“越不像历史代码越好”，而是“在可编译、可重复、可审计的条件下，进入一个既有 67 条规则没有充分解释的行为区域”。设候选程序或反事实测试为 `x`，行为表征为 `b(x)`，档案为 `A`，则一个基础的新颖性分数可以写成 `N(x)=mean_k distance(b(x), b(a_k))`，其中 `a_k` 是档案中与 `x` 最近的 k 个样本；若 `N(x)` 超过预先登记的阈值，或它进入一个尚未占用的行为区域，就允许将其放入 archive。档案不是普通缓存，而是探索历史的压缩地图：它保存曾经到达过哪些行为区域、每个区域最有代表性的候选、候选的质量和证据状态。这样做与单纯按检出数排序的区别在于，连续生成十个只改变变量名的样本不会挤占十个新颖性名额，而一个首次同时表现出“模板约束变化、临时对象生命周期变化、`-O0/-O2` 诊断分叉”的样本，可能得到更高的复核优先级。新颖性搜索的盲点也要先说清：行为距离依赖人为设计的 `b(x)`；距离度量错误时，算法会寻找度量漏洞；纯 novelty 还可能偏爱不能编译、永远超时或由未定义行为造成的噪声。因此在阙疑里，新颖性只能是候选生成和预算分配信号，不能直接产生 `verified`，更不能替代独立真值、人工复核和盲态协议。

## 二、行为表征、archive 与 quality-diversity：从“找到一个冠军”改成“照亮 C++ 缺陷空间”

行为表征不是源码文本的 embedding，也不是一个模型的自评向量，而应是能够由冻结工具链重算的、与 C++语义和验证目标相关的特征。第一层可以记录结构特征：AST 节点类别计数、表达式深度、模板参数数量、约束或 concept 的存在、重载决议候选数、值类别（lvalue/xvalue/prvalue）、引用绑定类型、`const`/volatile、整数提升和有符号性。第二层记录生命周期和资源行为：临时对象创建与销毁顺序、析构触发路径、移动构造/移动赋值次数、所有权转移、异常边界、协程暂停点、线程或原子操作类别。第三层记录编译与运行观测：标准版本、编译器身份和版本、`-O0/-O2` 或其他优化配置、warning 类别、sanitizer 事件、退出码、stdout/stderr 的规范化摘要、差分编译结果和重复运行一致性。第四层才是系统层特征：67 条规则的触发位图、四态判决前后的差异、证据类型、反事实关系是否成立、已有 452 条账本中是否出现过相同的语义签名。对这些特征要做规范化：删除地址、时间戳、随机临时目录和不可复现的日志噪声；对计数设上限；把“未执行”“编译失败”“不确定”与数值零分开。否则一个地址随机化的变化可能被误认为行为创新。Lehman 与 Stanley 的 novelty search 更接近一个按稀疏区域扩展的档案；Mouret 与 Clune 在 2015 年提出的 MAP-Elites 则把问题推进到 quality-diversity（QD）：先由研究者选择行为描述子的维度，把描述子空间划成网格或其他 cell，再在每个 cell 中保留质量最高的 elite。MAP-Elites 的论文强调，它不只返回单个最高分解，还能展示“高性能方案如何分布在不同变化维度上”，并在模块神经网络、模拟软体机器人和真实软体机器人等三个领域演示。迁移到阙疑，可以把 cell 设计为例如“类型系统复杂度 × 生命周期事件数”“模板/约束复杂度 × 编译诊断分歧”“优化级别差异 × sanitizer 事件类型”，每个 cell 保存一个质量最好的候选以及若干原始档案记录。质量不能只用“命中多少规则”，而应至少包含独立缺陷证据、反事实关系通过、回归夹具不退化、重复运行稳定、编译成本和误报风险；硬失败项不允许被其他高分抵消。若一个 cell 内出现多个互不支配的质量向量，可以参考 MOME 的思想：Pierrot 等人在 2022 年的 Multi-Objective Quality Diversity Optimization 中提出 Multi-Objective MAP-Elites，在每个描述子 cell 内保存 Pareto front，从而同时保留不同目标折中。对阙疑而言，QD 的价值正好对应“不要只找一个最好规则”：可以同时保留高新颖性、低成本、强复现、能暴露规则冲突的候选。archive 的实际字段应包括 `candidate_hash`、`behavior_descriptor`、`descriptor_version`、`cell_id`、`novelty_score`、`quality_vector`、`compiler_snapshot`、`rule_snapshot_hash`、`ledger_checkpoint`、`decision_state` 和 `replay_status`。其中 `descriptor_version` 很关键：一旦修改行为表征，旧分数不能悄悄与新分数混排，必须标记重算版本，否则“档案越来越丰富”只是度量改变造成的假象。

## 三、对 C++ 边界案例和反事实测试的作用：探索“规则没有覆盖的语义区域”，而不是追逐语法奇观

阙疑当前有 37 张实卡、67 条规则、9 个保护器和 452 条账本记录；共享 brief 还给出盲 holdout 30 条中真错 17 条、检出率 66.7%，外部 corpus 40 条、检出率 43.8%，变异测试 core 97.3%、all 81.5%，以及反事实 P=R=F1=0。这组数字共同说明：系统对既定变异集的表现不能推出它已经探索了 C++ 的边界空间；尤其 P=R=F1=0 不能直接证明反事实方法“没有发现任何东西”，因为还可能存在 TP、FP、FN、TN 分母未定义、标签错位、编译失败、关系未实现或结果不稳定等问题。新颖性搜索最适合介入的地方，是把 C++边界案例定义为“行为上的陌生且可核验”，而不是“文本上的陌生”。例如，候选可由单因素反事实算子产生：将 `T&&` 改为 `T&`，改变临时对象的生命周期，交换模板约束与重载候选，替换有符号/无符号比较，改变 `const`、引用折叠、整数提升、异常规格、协程暂停点、原子内存序或 `-O0/-O2`；每个算子都要预先声明保持关系和预期变化。若原程序与反事实程序在同一关系下应该保持输出、类型或诊断性质，而实际出现稳定差异，就不是单纯“新颖”，而是一个可进一步核验的候选。若两者应当发生变化，变化必须落在事先登记的维度上，不能用任意差异冒充缺陷。DeVries 与 Trefftz 在 2021 年 SBST 论文中把 novelty search 与 metamorphic testing 结合，用新颖性寻找广泛的独特测试，再用蜕变关系提供可验证的判据；论文明确针对传统 novelty testing 的 oracle problem，并报告该组合在一个测地线中点识别的 proof-of-concept 中，比直接搜索在更少进化代数内发现能使预期命题失效的测试。这个案例对阙疑的意义不是“照搬算法”，而是给出结构：`novelty` 负责扩大行为覆盖，`metamorphic relation` 负责提供可复核的关系约束，最终仍需外部确认。C++ 编译器测试也提供了相邻证据。现代 compiler fuzzing survey 将编译器模糊测试概括为程序生成、测试预言机、差分测试、减少和缺陷确认等问题；Csmith/CsmithEdge 相关研究则提醒，生成 C/C++ 类程序时，未定义行为既可能让测试无效，也可能被过度保守地排除，如何处理 UB 是测试效率和有效性的关键。阙疑可以把这些经验转成行为档案：不只记录“是否触发 sanitizer”，还记录“是否触发新的类型—生命周期组合”“是否在两个编译器或两个优化等级之间产生可重放分歧”“是否是既有规则的组合交互”“是否属于已经占用的 cell”。对反事实算子，第一轮不要追求大规模生成，而要先建立已知正例、已知负例和 inconclusive 三组 sanity check，分开计算 TP、FP、FN、TN、compile_fail、nondeterministic 和 label_missing；当分母为零时输出 `undefined`，禁止静默改成 0。只有当算子在已知夹具上恢复非零且可重算的指标后，才允许把 novelty score 接到候选排序器。这样，新颖性搜索的真正作用是把“尚未解释的边界行为”送进验证流水线，帮助 67 条规则发现盲区和交互，而不是把任何没有见过的 UB、编译器崩溃或随机输出都提升成知识。

## 四、对抗目标函数：新颖性本身也会被利用，必须把 archive 当作攻击面来审计

“对抗目标函数”在这里不是要求攻击外部系统，而是把候选生成器当作一个会主动利用评分漏洞的对手，反向检查阙疑的探索目标是否与研究意图一致。若奖励是 `novelty_score`，候选器可能生成大量语法无效程序、超长模板、永远超时的编译任务、带地址随机化的日志，借此制造高距离；若奖励是“新 cell 数”，它可能专门攻击描述子边界，例如让节点计数刚好跨过网格阈值，却没有产生新的语义；若奖励是“452 账本新增条数”，它可能通过重复语义、改变字段顺序或制造新 hash 让账本膨胀；若奖励是“67 条规则触发差异”，它可能反复命中已有规则组合，把旧知识伪装成新发现。Google DeepMind 对 specification gaming 的总结把这类现象描述为：智能体满足奖励规范的字面要求，却没有实现设计者想要的结果；2025 年一项 reward hacking 实证研究页面还给出了 15,247 个训练 episodes、15 个环境、5 种 RL 算法以及 2,156 个专家标注 episodes 的研究规模，并将 reward hacking 分为 specification gaming、reward tampering、proxy optimization、objective misalignment、exploitation patterns 和 wireheading 等类型。无论这些通用 RL 数字是否能迁移到 C++，其方法学警告都适用：代理指标不是目标本身。阙疑应把探索目标写成带硬约束的多目标偏序，而不是一个可以通过加权补偿的总分。建议把候选状态分为 `invalid`、`unstable`、`known_behavior`、`novel_candidate`、`independently_reproduced`、`human_reviewed` 和 `verified`；其中 `invalid`、`unstable`、保护器违规、账本重放不一致、holdout 污染和不支持的断言都是不可补偿的否决门。可排序的向量包括 `(semantic_novelty, new_behavior_cell, independent_evidence, relation_consistency, regression_safety, replay_stability, cost)`，并以 Pareto 或词典序加硬约束处理，禁止把“多覆盖了几个已有规则”兑换成“可以忽略一次账本不一致”。档案还要防止两种相反错误：一是 archive collapse，所有候选都挤在描述子空间的少数区域，表面上有很多样本、实际上没有多样性；二是 archive pollution，噪声和不可复现样本把有效区域淹没。前者可通过 cell 占用率、descriptor entropy、重复率和最近邻距离监测；后者要求每个候选保留原始源码、规范化源码、编译命令、环境快照、stdout/stderr、运行次数、差异摘要和失败原因，并把“新颖但不稳定”单独放进失败档案，不删除历史也不进入正式知识库。更重要的是，描述子和评估器必须版本化、只读化：候选程序不能访问评分脚本、标签、holdout、保护器配置或账本写接口；评分过程与候选生成过程隔离；每轮使用固定的已知回归夹具检验是否出现 reward hacking。只有当一个高 novelty 候选在新环境、重复运行、独立编译器或人工复核中仍保持同一结论，才有资格从探索档案转入证据档案。因而“对抗目标函数”不是把系统变得敌对，而是主动构造会钻空子的搜索器，检验新颖性指标是否真正指向 C++语义边界。

## 五、与 67 规则和 452 账本的结合、三条行动与来源

把 novelty search 接入阙疑，最稳妥的架构是“只读提议器—冻结评估器—append-only 账本—人工晋升”四层分离。67 条规则仍是当前生产判决规范，不能由搜索器在线改写；452 条账本仍是可追溯证据和实验历史，不能被候选器覆盖、重排或回盲。每个候选先从现有知识卡、C++标准语义变换或白名单反事实算子产生，计算 `behavior_descriptor` 和 `novelty_score`，进入独立 archive；随后在冻结的规则快照、保护器快照、编译器矩阵和 holdout 协议上只读评估；评估结果写入新的账本事件，引用前一 checkpoint 的哈希，而不是修改旧记录；最后由固定 gate 和人工复核决定能否晋升。建议三条具体行动如下。第一，建立“新颖性基线实验”：在相同候选预算、相同编译器和相同随机种子约束下比较随机受限变异、单纯 novelty search、novelty 加规则分歧、以及 MAP-Elites/QD 四个臂；每臂至少报告新行为 cell 数、稳定编译率、独立复核后的新增盲点、回归夹具检出率、重复率、CPU 时间和 Clopper–Pearson 区间，不能只报告 novelty 分数。第二，冻结并登记行为表征版本：先选少量能解释 C++边界的描述子，例如类型/生命周期复杂度、模板约束复杂度、诊断分歧、优化级别差异和反事实关系状态；把 `descriptor_version`、cell 定义、距离度量、archive 插入阈值与规则快照一起写入实验元数据，任何修改都产生新版本，旧档案不能被无声重算。第三，修复反事实 oracle 并建立“候选到知识”的晋升门：先在 15 条真实缺陷夹具、已确认 holdout 和人工构造的关系正负例上恢复可重算的 TP/FP/FN/TN；再要求每个 `novel_candidate` 至少通过一次独立编译或差分证据、一次重复运行、一次保护器检查、一次账本重放和一次人工语义复核，才可进入 `independently_reproduced`；没有外部证据的候选只能留在 archive。诚实盲区也必须写进论文：第一，现有文献充分支持“新颖性可绕开部分欺骗性目标”，但没有直接证明它能自动发现阙疑的新 C++知识规则；第二，MAP-Elites 的 cell 和 descriptor 依赖研究者选择，阙疑目前没有实测证明哪组描述子最能预测真实缺陷；第三，反事实 P=R=F1=0 的根因尚未由本文件重新审计，任何改进数字都必须在 oracle 修复后重新计算；第四，编译器版本、未定义行为、并发调度和浮点环境可能制造 aleatoric novelty，不能把每个差异都解释成规则盲点。本次调研实际执行了不少于 10 次 WebSearch，并对下列公开页面进行交叉核实，来源 URL 如下：1.
