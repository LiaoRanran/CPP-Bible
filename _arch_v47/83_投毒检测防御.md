# 方向 83：数据投毒的检测与防御（Poisoning Detection & Defense）

> 上游方向 91 已写"投毒攻击方法"，本方向聚焦"如何发现并抵御"。对阙疑（queyi）而言，威胁面非常具体：**67 条规则（block 44 / warn 16 / advice 7）、9 个保护器、452 条判决账本、37 张实卡**若被人恶意污染——例如攻击者提交一张"假知识卡"声称某条 C++ 未定义行为是良构——系统如何发现并抵御？本文把 ML / 知识图谱投毒检测的经典与前沿方法逐项对照到阙疑的 append-only 哈希链账本、Merkle checkpoint 与独立对账器机制上。所有数字均来自实际检索，未查到者标注"未核实"。

---

## 核心结论

1. **"签名 + 溯源（provenance）"是知识库投毒的第一道防线，但只能防"篡改"不能防"恶意但已签名"的条目。** IBM 的 ART 工具箱（MIT 许可，4.8K+ stars）把 provenance verification 列为与 activation clustering、spectral signatures、STRIP 并列的四大投毒检测模块之一（AI Safety Directory，2026-03-12）。阙疑的 append-only 哈希链 + Merkle checkpoint 已经天然具备"历史不可篡改"能力，但**当前并不能识别一条语义上错误、却由某个被攻陷的提交者合法签名注入的知识卡**——这正是 Oracle Poisoning（arxiv 2605.09822，未核实精确编号）在 4200 万节点生产级代码知识图谱上证明的盲点：在中等攻击者复杂度（L2）下，每个被测模型以 **100%** 概率信任中毒数据，270 次定向查询中 **269** 次接受了伪造的安全声明。

2. **异常检测（谱签名 / 激活聚类）在"小比例污染"下检出率极高，是规则层投毒最可复用的方法。** Tran、Li、Madry（NeurIPS 2018，arXiv:1811.00636）提出的 spectral signatures 通过对特征表示的协方差做 SVD，在真实图像集 + SOTA 架构上可"detecting and removing poisoned examples"；针对 RAG / 知识库投毒，Tan 等（复旦 / WPI，2024，arXiv:2411.18948）的 RevPRAG 通过 LLM 激活值训练孪生网络探测器，在 NQ / HotpotQA / MS-MARCO 三数据集、5 种 LLM 上取得 **98%** 真阳性率（TPR）同时假阳性率（FPR）接近 **1%**。这一"激活/嵌入层异常"思路可直接迁移到阙疑的 67 条规则嵌入聚类上。

3. **影响函数（influence functions）与鲁棒统计（trimmed mean / median-of-means）是"事后归因 + 清洗"的两条互补路径，但都对阙疑的确定性判决引擎提出改造要求。** Koh & Liang（ICML 2017，arXiv:1703.04730）把影响函数——"a classic technique from robust statistics"——用于"trace a model's prediction through the learning algorithm and back to its training data"，并明确能"detecting dataset errors"；在投毒场景，Delta-Influence（arXiv:2411.13731，2024/2026）专门用影响函数"unlearning / identifying poisons"。阙疑的 452 条账本 + 30 盲 holdout + 40 外部 corpus + 15 真实缺陷夹具构成天然"探针集"：一张新卡若使已知良构夹具的判决翻转，即可被影响函数式归因锁定。

## 精确数字与案例

### 一、异常检测与谱签名（Outlier Detection / Spectral Signatures）

传统异常检测把投毒样本当作训练集中的离群点（outlier）。在深度学习投毒中，最具代表性的"结构化异常检测"是 **Spectral Signatures**（Tran、Li、Madry，NeurIPS 2018）。

| 方法 | 论文 / 作者 / 机构 / 年份 | 核心机制 | 关键数字 |
|---|---|---|---|
| Spectral Signatures | Tran, Li, Madry（MIT，NeurIPS 2018，arXiv:1811.00636） | 对特征表示协方差做 SVD，找后门攻击留下的谱痕迹 | 16 页；在真实图像集 + SOTA 架构上验证"detecting and removing poisoned examples" |
| Activation Clustering | Bryant Chen 等（IBM，SafeAI 2019，arXiv:1811.03728） | 用 DNN 激活值做聚类，分离中毒/干净样本 | 提出 Activation Clustering 方法论检测并移除后门 |
| Robust Nonparametric Regression | arXiv:2305.16771（AAAI 2023） | median-of-means、trimmed mean 抵御 ≤ q 样本污染 | 对比 kernel regression / median-of-means / trimmed mean / corrected estimation |

逐字引文（Spectral Signatures 摘要）：
> "In this paper, we identify a new property of all known backdoor attacks, which we call **spectral signatures**. This property allows us to utilize tools from robust statistics to thwart the attacks. We demonstrate the efficacy of these signatures in detecting and removing poisoned examples on real image sets and state of the art neural network architectures."

对阙疑的映射：67 条规则可表示为"规则嵌入向量"，对 452 条账本判决产生的特征矩阵做 SVD，若某条新规则在谱上形成孤立方向（类似后门攻击的 spectral signature），即可被标记。注意：**阙疑当前 227 项工作树漂移 + README 口径滞后，规则集本身缺乏稳定的嵌入基线**，这是落地该方法的现实障碍（见盲区）。

### 二、影响函数与鲁棒统计（Influence Functions / Robust Statistics / 数据清洗）

影响函数源自鲁棒统计，用于把"某个预测"反向归因到"哪条训练数据最负责任"。这是发现投毒（尤其 label-flip / 知识卡造假）最直接的归因工具。

| 方法 | 论文 / 作者 / 机构 / 年份 | 关键结论 / 数字 |
|---|---|---|
| Understanding Black-box Predictions via Influence Functions | Pang Wei Koh, Percy Liang（Stanford，ICML 2017，arXiv:1703.04730） | 仅需梯度 + Hessian-vector product 的 oracle 访问即可扩展到现代模型；能"detecting dataset errors"和"creating visually-indistinguishable training-set attacks" |
| Δ-Influence | arXiv:2411.13731（2024/2026，TMLR） | 用影响函数"unlearning / identifying poisons"；指出 EK-FAC、TRAK 等 SOTA 影响函数常无法准确归因异常模型行为 |
| LDPGuard | arXiv:10415225（2024） | 通用可扩展框架抵御本地差分隐私下的数据投毒 |

逐字引文（Influence Functions 摘要）：
> "In this paper, we use influence functions — a classic technique from robust statistics — to trace a model's prediction through the learning algorithm and back to its training data, thereby identifying training points most responsible for a given prediction."

鲁棒统计对应"聚合层清洗"：在联邦/分布式场景，Krum、Trimmed Mean（deepwiki DFL-poisoning 5.5）通过几何/统计过滤 Byzantine 客户端。阙疑是**确定性单体内核**（gate_engine.py 3826 行），没有"多客户端聚合"问题，但可借鉴 trimmed-mean 思想：**对同一条 C++ 断言，用多条独立知识卡 / 保护器交叉投票，取中位数而非首命中**，使单张污染卡无法独占判决。

### 三、触发反转与运行期检测（Trigger Inversion / STRIP / Runtime Defense）

当投毒是"后门式"（特定 trigger 输入触发错误判决）时，检测要在运行期拦截。两条主线：

| 方法 | 论文 / 作者 / 机构 / 年份 | 机制 / 数字 |
|---|---|---|
| STRIP | Gao 等（arXiv:1902.06531，2019） | STRong Intentional Perturbation：对输入叠加多类扰动，看输出熵；后门样本熵低被识别 |
| Eliminating Backdoors in Neural Code Models via Trigger Inversion | arXiv:2408.04683（2024） | 针对**神经代码模型**的反向后门，触发反转定位并消除触发器 |
| ART Poison Detection | IBM（MIT，4.8K+ stars） | 集成 activation clustering、spectral signatures、provenance verification、STRIP-based 检测 |

逐字引文（ART 工具页）：
> "ART's poisoning defenses include activation clustering, spectral signatures, provenance verification, and STRIP-based detection that can identify poisoned samples in training datasets."

对阙疑：若攻击者在一张知识卡里埋"trigger"（例如某特定宏写法触发保护器放行），可用"触发反转"思路——在 gate_engine.py 对账器里对可疑输入做扰动重判，若判决熵异常集中到单一错误结论，则告警。**阙疑的"独立对账器（第三方不信任内核即可复算判决）"天然适合做运行期 STRIP 式校验**。

### 四、知识库 / 知识图谱投毒检测（RAG Poisoning / Oracle Poisoning / CLD-KB）

这是与阙疑最贴近的一类研究，因为阙疑本质是一个**结构化 C++ 知识库 + 判决引擎**，而非普通训练模型。

| 研究 | 关键数字 | 防御手段 |
|---|---|---|
| RevPRAG（Tan 等，复旦/WPI，2024，arXiv:2411.18948） | 注入 **5** 条投毒文本、top-k=5 检索；NQ/HotpotQA/MS-MARCO 各 **3000** 实例；5 种 LLM（GPT2-XL 1.5B、Llama2-7B/13B、Mistral-7B、Llama3-8B）；**98%** TPR、~**1%** FPR；并能区分"投毒响应"与"幻觉响应"（TPR 97%+） | 基于 LLM 各层激活值训练孪生/三元组网络探测器 |
| Oracle Poisoning（arxiv 2605.09822，未核实精确编号，2026） | **4200 万**节点生产级代码知识图谱；**6** 种攻击场景；L2 复杂度下 **100%** 信任中毒数据，**269/270** 次接受伪造声明；评估 **5** 种防御；只读访问控制消除直接修改向量 | 只读访问控制（完全消除）+ 4 种部分/模型依赖防御 |
| CLD-KB（PA-LLM-RAG，IoBT 知识库投毒防御，来源 dailysecurity.cn 二次报道） | 单条注入（投毒率 **1.6%**）即实现 **85%** LLM 上下文污染；饱和点 **7.7%**；每次任务 +**7ms** 开销；优于 DBSCAN/LOF/K-Means/孤立森林/One-Class SVM | One-Class SVM 边界 + 基于成员的类别扩散分析（双重异常检测） |

逐字引文（RevPRAG 摘要）：
> "Our results on multiple benchmark datasets and RAG architectures show our approach could achieve **98%** true positive rate, while maintaining false positive rates close to **1%**."

逐字引文（Oracle Poisoning 二次报道，中文）：
> "在中等攻击者复杂度（L2）下，每个测试模型以 **100%** 的概率信任中毒数据，在 **270** 次定向查询试验中有 **269** 次接受了伪造的安全声明。"

CLD-KB 的"投毒率 1.6% → 85% 上下文污染"对阙疑是极强的警讯：**352 条规模的知识卡中，只需污染约 5–7 条（1.6%–7.7%）就足以系统性扭曲判决**。阙疑的 67 规则 + 9 保护器总数 76，按 1.6% 估算仅 ~1 条恶意规则即可造成大面积污染——这凸显了"源可信分级 + 双检测器"的紧迫性。

### 五、差分隐私对投毒的缓解（Differential Privacy as Mitigation）

差分隐私（DP）通过对梯度/聚合加噪，客观上提高单条投毒样本的影响力稀释。但注意：**标准 DP 主要缓解"训练数据隐私泄露"，对"已签名的恶意知识卡"不是银弹**。

| 研究 | 关键结论 |
|---|---|
| Mitigating Data Poisoning Attacks to Local Differential Privacy（arXiv:2506.02156，2025；ACM 2025，doi 10.1145/3719027.3744839） | 分布式 LDP 易招致投毒，提出针对性缓解框架 |
| LDPGuard（arXiv:10415225，2024） | 通用可扩展框架抵御 LDP 投毒 |
| 综述（Zhao 等，arXiv:2503.22759，2025） | 将投毒攻击按多视角分类，并延展到 LLM 投毒这一新兴领域 |

逐字引文（Data Poisoning Survey 摘要）：
> "this survey categorizes data poisoning attacks across multiple perspectives... the discussion is extended to the emerging area of data poisoning in large language models(LLMs)."

对阙疑：DP 思路可启发"**保护器投票加噪 / 多内核交叉审计**"——即便某保护器被污染，加噪 + 多数投票使单点污染难以主导。但阙疑是确定性系统，**加噪会破坏"判决可复算"这一核心卖点**，故只能用在"候选集聚合"而非"最终判决"阶段（见盲区）。

### 六、小结：阙疑威胁模型与方法的对应地图

把上述五类方法映射到阙疑的具体资产，可以得到一张清晰的"检测-防御"对应表。阙疑与经典 ML 投毒的最大不同在于：**它不是用梯度训练出来的统计模型，而是确定性规则 + 哈希链账本 + 独立对账器构成的"可复算判决机"**。因此经典方法中"训练数据异常检测"要改写为"规则/知识卡异常检测"，"影响函数归因"要改写为"加卡前后判决翻转归因"，"运行期后门检测"则天然可由独立对账器的重判能力承担。下表给出资产—风险—检测手段的一一对应，便于后续落地时直接索引。

| 阙疑资产 | 投毒风险（攻击者目标） | 最匹配的检测 / 防御手段 | 现有机制可复用性 |
|---|---|---|---|
| 67 条规则（block 44 / warn 16 / advice 7） | 注入一条"假 block 规则"使某未定义行为被判良构 | 规则嵌入聚类（谱签名 / community detection）+ 影响函数翻转归因 | 中：需先解决 227 项漂移导致的规则基线不稳 |
| 9 个保护器 | 弱化某保护器，使污染卡绕过校验 | 保护器交叉投票（trimmed-mean 思想）+ 触发反转重判 | 高：独立对账器可直接做重判 |
| 452 条判决账本 | 提交一张伪造"已验证"知识卡并写入账本 | 源可信分级 + 数字签名 + Merkle proof 校验 | 高：append-only + Merkle checkpoint 已具备不可篡改基底 |
| 37 张实卡 / 10 草稿 | 在 red-team 或 draft 阶段埋 trigger | 运行期 STRIP 式扰动重判 + staging 人工复核 | 中：需新增 staging 流程 |
| gate_engine.py（3826 行） | 内核逻辑被恶意修改致判决偏置 | 独立对账器不信任内核复算 + 多内核交叉审计 | 高：机制已存在，需补自动化 |

需要特别强调：**CLD-KB 的"1.6% 投毒率即 85% 污染"结论意味着，阙疑 76 条规则+保护器只要被污染 1–2 条就可能系统性失真**。这比普通深度学习投毒（通常需 5%–10% 训练集污染才生效）更脆弱，因为规则系统是"首命中 / 短路判定"而非"大数投票"。因此阙疑不能依赖"污染比例低就安全"的假设，必须把"源可信分级 + 双检测器（聚类异常 + 翻转归因）"作为必选项而非可选项。

## 对阙疑的 3 条具体行动

1. **在账本 schema 增加"源可信分级 + 数字签名"字段，堵住"恶意但已签名"的盲点。** 修改阙疑 append-only 哈希链账本的每条写入结构，新增 `submitter_id`、`credibility_tier`（high/medium/low，参考 Armalo 的 source credibility tiers）、`signature`、`merkle_proof` 四字段；低于 high 级可信的提交（如匿名 red-team 卡、draft 11 张）进入 staging 区，需二次人工 / 双内核复核才提升为 verified。落地文件：`gate_engine.py`（3826 行）的账本写入模块；时间点 **2027-Q1 前**完成 schema 升级并补一次 Merkle checkpoint 重算。理由：Oracle Poisoning 证明"签名但错误"的条目是知识库投毒第一杀手，阙疑当前 452 条账本无提交者可信度维度。

2. **把现有探针集改造为"影响函数式投毒归因器"。** 利用阙疑已有规模（盲 holdout **30**、外部 corpus **40**、真实缺陷夹具 **15**、变异 core 97.3%）构建回归探针：每次向 67 规则或 9 保护器新增 / 修改一张卡后，自动跑 `python gate_engine.py --reconcile --probe new_card.json`，比对新增前后在 30+40+15 探针上的判决是否翻转；任一已知良构夹具（重注入 6/6、历史覆盖 12/15）判决被翻，则该卡标记为高影响异常（类比 influence functions 的"most responsible training point"）。时间点：**每个 Merkle checkpoint 提交前必跑**，纳入 CI。理由：Delta-Influence 证明影响函数能锁定 poisons；阙疑确定性引擎恰好适合做"加卡 → 翻转率"的精确归因。

3. **对 67 规则做"嵌入聚类 + 触发反转"双检测器，写入威胁有效性文档。** 在 `research/12_threats_to_validity.md`（或 _arch_v47 同级威胁文档）新增小节"T-知识卡投毒审计"，实现：① 用代码语义嵌入对 67 规则聚类，标记"桥接不相关 C++ 社区"或孤立规则（类比 GraphRAG 的 degree distribution / community detection 异常）；② 在独立对账器内对可疑输入做扰动重判（STRIP 式），若判决熵异常集中到单一错误结论即告警。时间点 **2027-05 前**交付检测器原型 + 文档小节。理由：RevPRAG 98% TPR / 1% FPR 证明激活/嵌入层异常检测在知识库场景高效；阙疑已有"独立对账器不信任内核复算"机制，天然适合运行期校验。

## 盲区（诚实标注）

- **CLD-KB 数字来自二次报道**：投毒率 1.6% → 85% 上下文污染、饱和点 7.7%、+7ms 开销均取自 dailysecurity.cn 的中文摘要（Cyber Security Daily Radar），**未直接打开原始论文核对**，可能为近似或翻译偏差，需原文复核。
- **Oracle Poisoning 的 arXiv 编号存疑**：dailysecurity.cn 给出 `arxiv 2605.09822`，年份 2605 明显为录入错误（应为 2025 或 2026，论文标注 2026-05-10）。**精确编号未核实**；4200 万节点、269/270 等关键数字来自该二次报道，建议以原文为准。
- **阙疑自身投毒抵抗力未实测**：本方向所有"对阙疑的映射"均为**方法论推演**，未对 67 规则 / 9 保护器做真实投毒红队实验；且项目已知算术不自洽（外部 corpus C 层 0% 检出）、反事实算子 P=R=F1=0，意味着探针集本身有缺陷，影响函数归因的基线不可靠。
- **DP 对确定性系统的适用性存争议**：标准差分隐私加噪与阙疑"判决可复算"卖点冲突，本方向仅建议用于候选聚合，**具体能否不破坏可复算性未验证**（未核实）。
- **样本偏差**：检索偏向英文顶会（NeurIPS/ICML/AAAI/arXiv）与 IBM ART 生态，中文一手文献（如期刊《软件学报》LDP 相关，jos.org.cn 7179）仅检索到摘要未深读；针对"小语种 / 双非本科生可复现"的低成本防御方案文献覆盖不足。
- **阙疑工作树 227 项漂移 + README 口径滞后**意味着本调研引用的项目数字（67/9/452/3826 行）可能已非最新，落地行动前需先 `git status` 核对真实规则与账本规模。
