# 方向131：编译器设计——三段式架构、SSA与机器核验的可信核

## 一、为什么编译器架构值得一个知识验证项目反复参照

编译器是把"人写的文本"变成"机器执行的动作"的翻译器。Aho、Sethi与Ullman在1986年初版的《Compilers: Principles, Techniques, and Tools》（龙书）中把这一翻译过程定型为前端、优化中段、后端三段[1]：前端负责词法分析、语法分析、语义分析，产出抽象语法树与中间表示；中段在中间表示上做与源语言和目标机器都尽量无关的优化；后端负责指令选择、寄存器分配、指令调度与代码发射，绑定到具体体系结构。2007年第二版由Aho、Lam、Sethi、Ullman修订，三段式仍是全书骨架[1]。Raccordon在《From ASTs to Machine Code with LLVM》中用一张三模块图重述同一分解，并称现代编译器是"由小型、松耦合组件构成的工具链"[2]。

三段式的根本动机是解耦两个高维变化轴：源语言轴与目标机器轴。N种语言、M种机器若两两直接翻译，需要N×M个翻译器；引入统一中间表示后只需N个前端加M个后端，工程量降为N+M。这是编译器设计给一切多源、多目标系统的第一条教益：中间表示不是内部实现细节，而是架构枢纽——它决定哪些信息在翻译中被保留、哪些被丢弃，从而决定后续所有分析与变换的能力上限。本节末尾先点一句：阙疑把知识卡文本"翻译"成对错判决，同样受制于这条规律。

## 二、LLVM：从一个博士课题到工业标准

LLVM是这条教益最成功的现代实例。Chris Lattner与Vikram Adve在2004年3月的CGO会议上发表《LLVM: A Compilation Framework for Lifelong Program Analysis & Transformation》，提出一个在编译时、链接时、运行时乃至两次运行之间"闲置时间"都能进行分析与变换的框架[3]。论文摘要明确：LLVM定义了一种静态单赋值形式的通用低级代码表示，配有语言无关的简单类型系统、类型化地址算术指令，以及统一实现高级语言异常机制的低层原语[3]。需要分辨的是三个文本：Lattner的硕士论文《LLVM: An Infrastructure for Multi-Stage Optimization》2002年12月完成于伊利诺伊大学厄巴纳-香槟分校，系统阐述多阶段优化设计[4]；2004年的CGO论文是其公开亮相；他2005年的博士论文则转向《Macroscopic Data Structure Analysis and Optimization》，研究指针密集程序的优化。LLVM最初并不是一个完整编译器，而是一套研究用基础设施；Clang前端的崛起、FreeBSD与Apple macOS从GCC迁移到Clang，才把它推上系统编译器位置。Clang在2010年2月4日完成首次完整自举：用Clang构建全部LLVM与Clang约55万行C++代码，二阶段构建出的Clang能再次构建自身，bootstrap闭环。

作为对照，GCC的历史早了近二十年。Richard Stallman于1987年3月22日发布GCC 1.0，最初只处理C语言，同年12月扩展到C++[9][10]。Stallman在1983年9月27日给Usenet新闻组的消息中，就把C编译器列为GNU工程首批组件[10]。据2019年前后的统计，GCC代码量约1500万行，是最大的自由程序之一[9]。GCC在2004年5月把基于SSA的Tree SSA分支并入主线，其GIMPLE中间表示与LLVM IR形成长期对峙。两者差异不止技术：GCC采用GPLv3许可证，部分BSD系系统因许可证与维护原因停留在GCC 4.2分支并最终转投Clang。许可证选择如何塑造基础设施生态，是编译器史给所有"想被别人用"的研究系统的第二条教益。

## 三、SSA与优化pass：中间表示如何决定优化能力

静态单赋值形式由Cytron、Ferrante、Rosen、Wegman与Zadeck在1991年10月的ACM TOPLAS论文《Efficiently Computing Static Single Assignment Form and the Control Dependence Graph》中系统化，卷13第4期，第451至490页[5]。SSA的核心约束是每个变量只被静态赋值一次：在控制流汇合点插入φ函数，以区分从不同前驱边传入的值。论文基于支配边界给出对任意图高效构造SSA与控制依赖图的算法，并给出其通常对程序规模线性的分析与实验证据[5]。SSA之所以关键，是因为它把"这个引用由哪个定值到达"梳理清楚，使常量传播、死代码消除、全局值编号等优化获得简洁统一的表达；def-use链可能随定值与引用数量乘积膨胀，而SSA把信息压缩到控制流图边数的量级。

在LLVM中，优化以pass为组织单位：LLVM到LLVM的pass读取IR、产出IR，如指令合并、全局优化、循环变换；代码生成阶段再做目标相关处理[3]。pass管道本质上是一串被仔细排序的源码变换，排序本身是经验与折中的产物——不同pass之间存在相互启用与相互干扰。一个研究系统若想让自己的"规则"可组合、可复用、可独立验证，pass管道是现成的架构范本：每个变换单一职责、输入输出同构、可单独测试、可在管道中重排并观察差异。

## 四、TableGen、MLIR与自举：编译器的元层

LLVM的另一件核心基础设施是TableGen。它是一种声明式领域特定语言，源文件（.td）由类与定义（两者统称记录）组成，llvm-tblgen解析并实例化记录后交给特定后端，产物通常是供C++包含的.inc文件[6]。TableGen不替字段赋予语义，意义完全由后端决定：代码生成器用它描述寄存器、指令、调度模型与指令选择模式，Clang用它生成诊断消息与属性，MLIR用它定义算子、方言与traits[7]。TableGen回答了一个实际问题：当目标描述包含成千上万条高度同构的结构化信息时，手写C++枚举与数组极易出错且难维护；用一种更小、更声明式的语言把信息"编译"成C++，把人从机械重复中解放出来。这是"为高价值窄领域设计小语言"的教科书操作。

MLIR把这一思路推向多层。Lattner、Amini、Bondhugula、Cohen、Davis、Pienaar、Riddle、Shpeisman、Vasilache与Zinenko在CGO 2021发表《MLIR: Scaling Compiler Infrastructure for Domain Specific Computation》[8]。MLIR允许同一系统内共存多层抽象与多种方言，使高层领域结构不必过早被抹平成低层指令；它最初为解决机器学习框架各自造编译器、重复实现SSA处理的痼疾而生，后扩展到量子编译、硬件综合、科学计算等领域[8]。

自举是编译器文化最深的一层：用语言自身编写该语言的编译器，再用自己编译自己。自举既是表达力证明，也是信任问题的起点。Ken Thompson在1983年图灵奖演讲《Reflections on Trusting Trust》中展示了一个能自我复制的编译器后门：即便源码干净，被感染的编译器仍能产出被感染的编译器与登录程序[11]。这意味着"源码可信"不等于"二进制可信"，信任链必须在某一层显式锚定。

## 五、CompCert与对阙疑的全面映射

Xavier Leroy在POPL 2006发表《Formal certification of a compiler back-end, or: programming a compiler with a proof assistant》，第42至54页，报告用Coq证明助手同时编写并证明一个从Cminor到PowerPC汇编的编译器后端：编译器代码与正确性证明同在Coq中完成，证明核心是语义保持——源程序上证明的安全性质对编译后的可执行文件同样成立[12]。Leroy后来在CACM 2009第52卷第7期以《Formal verification of a realistic compiler》向更广泛读者报告CompCert。CompCert的意义不在于产出最快的机器码，而在于把"翻译可信"从测试信任提升为证明信任：多数编译器靠海量测试建立信心，而测试在原理上不能穷尽；CompCert对编译管道给出机器检验的语义保持证明，形成可审计的信任链。也要诚实：证明覆盖的是编译器自身经形式化的部分，输入程序落入C标准未定义行为时，证明不提供超出语义规范的承诺。

现在回到阙疑。一个只有3826行内核、37张实卡、67条规则、9个保护器与452条账本的C++知识验证系统，与上述编译器史有四层结构性对应，这四层都应写进NeurIPS 2027 E&D Track的方法论叙事。

第一层，67条规则应拥有自己的DSL与编译器，而非散落在Python分支判断里。参照TableGen的定位：规则数量已达67条且高度同构（前提、证据模式、判决动作三段式），手写if-else会重蹈早期系统"没有统一表示"的覆辙——每条规则的语义只能靠阅读实现代码猜测。阙疑应设计声明式规则语言，字段至少含规则名、适用前提、所需证据通道、判决动作与保护器绑定，并编写编译器把规则源文件lowering到3826行内核的执行原语。收益是规则可枚举、可diff、可做规则级消融，67这个数字也成为论文可报告的设计资产，而非藏在代码里的实现偶然。一个合肥的双非本科、嵌入式背景、零学术影响力的作者，无法靠资源与人脉竞争，唯一可行路径是把小系统的每一处结构都做到可审、可证、可复算——编译器史恰好提供全套范本。

第二层，变异体生成就是编译器式的源码变换。阙疑的变异测试取得core 97.3%、all 81.5%的kill率：变异算子把正确C++片段变换为注入单一缺陷的片段，再检验系统能否判错。这与优化pass在IR上的位置完全同构——输入输出同构、单一职责、可组合、可独立验证。把变异生成器重构成显式pass管道，每个变异算子有名字、有前提、有预期缺陷类别，就能像LLVM对待优化pass那样做算子级消融与排序实验，回答"97.3%中每个算子贡献多少"。同时必须正视：97.3%是对自家变异体的kill率，与fuzzing社区反复警告的"自造靶子自造枪"风险同源（详见方向135）；变异算子越规则化、越可审计，过拟合指控越容易回应。

第三层，CompCert式可信核叙事。阙疑的判决产物——holdout 30条中17真错、检出率66.7%，corpus 40条检出率43.8%且存在算术不自洽——本质是"翻译"结果：知识卡经规则匹配、证据抽取、判决合成被翻译成对错标签。翻译质量要么靠测试、要么靠证明。阙疑无力对3826行内核做CompCert级全证明，但可做"轻量CompCert"：为每条规则的前提与判决给出形式化规格，对判决合成函数机器检验若干性质（如证据缺席时不得判错、判决对证据单调），把信任锚定在尽可能小的核上。反事实算子目前P=R=F1=0，恰说明这个翻译器有一条完全失效的通道——按CompCert的术语，这不是优化问题而是语义保持破裂，应作为最高优先级修复而非数字美容。43.8%背后的算术不自洽同理：连内部统计都不自洽的判决器，无法声称可信。

第四层，语言边界即能力边界。SSA与MLIR讲的是同一件事：中间表示能表达什么，系统才能分析什么。3826行内核的语言边界必须显式文档化——支持哪些C++构造、哪些断言形式、哪些证据类型；边界之外的知识卡应fail-closed拒绝而非硬判。9个保护器在架构中正是运行时边界守卫。Thompson的警告则提醒：阙疑若用大模型辅助生成规则或变异体，必须保留从规则源文件到执行产物的完整可重建链，防止"生成器里的偏差"像被感染的编译器一样自我复制而不可见。

最后补一条时间维度的判断：编译器从1987年GCC首发到2004年LLVM论文、再到2021年MLIR论文，每一次架构跃迁都间隔约十七至十八年，且都由"旧表示无法承载新问题"诱发。阙疑距离NeurIPS 2027投稿窗口不足一年，没有时间等架构自然演化，正确做法是把上述四层对应在投稿前一次性落到代码与论文中；对零影响力的独立作者而言，结构上的严谨与自洽，是唯一能与资源丰厚团队正面对抗的资产。

## 对阙疑的三条具体行动

1. **2026-12-31前**：完成67条规则的规则DSL最小规格（规则名、前提、证据通道需求、判决动作、保护器绑定五字段），实现首个编译器将规则源文件lowering到内核可执行对象；以现有67条规则全量迁移、452条账本回放判决逐卡一致为验收标准。
2. **2027-03-31前**：把变异体生成器重写为显式pass管道，每个变异算子独立可命名、可消融；产出core 97.3%的逐算子贡献分解表，并引入至少一类非自家设计的变异来源（借鉴fuzzing语法变换）做过拟合压力测试。
3. **2027-06-30前**：为判决合成核写出形式化性质清单（至少含证据缺席不判错、通道标注完备、判决对证据单调三条），用属性测试或证明助手原型做机器验证；论文中形成"CompCert-inspired trusted core"小节，并先修复反事实P=R=F1=0与corpus算术不自洽，再投稿NeurIPS 2027 E&D。

## 盲区

- CompCert证明覆盖范围随版本演进，本文未逐版本核实各遍（寄存器分配、指令调度等）证明完备度的最新状态；"可信核"叙事在论文中须精确限定到经证明的具体pass。
- 规则DSL的设计成本未估算：67条规则中若存在大量不规则特例，声明式迁移可能反而增加复杂度，N+M解耦收益成立的前提是规则确实同构。
- "博士项目长成LLVM"的说法需在引文中严格区分硕士论文（2002）、CGO论文（2004）与博士论文（2005）三个文本，避免张冠李戴。
- Clang 2010年自举"55万行C++"为当时数据，现代LLVM规模已数量级增长，引用须标注年代。
- 本文未实际打开Leroy 2006的Coq证明源码，证明与代码共同演化的真实维护代价只能从文献间接判断。
- Thompson后门在阙疑这类纯判决系统中的对应物（生成器偏差）尚无实证，目前只是架构警告而非已观测威胁。
