# 方向 38：测量偏差（measurement bias / systematic error in evaluation metrics）

> 本方向服务于「阙疑 / queyi」的 NeurIPS 2027 E&D Track 投稿。核心命题：当我们用**检出率 / 精确率 / 召回率**去评价一个 C++ 知识验证系统时，这些数字本身并不是"客观真理"，而是被**测量工具、标注者、样本、阈值、运行环境**共同塑造出来的。系统误差（systematic error / bias）不会因重复测量而消失，它会把一个"很精密但很错误"的结论伪装成可靠证据。本方向把阙疑的实测数字（盲 holdout 66.7%、外部 corpus 43.8%、变异 core 97.3%/all 81.5%、反事实 P=R=F1=0）逐一放回偏差透镜下重新审视。

测量学给我们一把统一的尺子。Bohrium 实验科学百科给出的测量模型是：

> `Observation = True Value + Bias + Random Fluctuation`

即任何一次"测量读数" = 真值 + 偏倚 + 随机波动。随机项可以通过"多跑几次取平均"用 `σ/√N` 压下去（这也是阙疑 452 条账本能做的），但偏倚项（Bias）是**方向性的、可重复的系统性偏移**，重复测量只会让它更"精密地错误"。E&D Track 的官方定位——"evaluation becomes an object of scientific study in its own right"——恰恰要求我们不再把 P/R/F1 当成天然正确的尺子，而是把"尺子本身是否歪了"当作研究对象。本方向就是一次对阙疑这把尺子的校准审计。

---

## 核心结论

1. **金标准本身就是被测量的"仪器"，标注者偏差会让 66.7% 的检出率同时高估和低估真值。** 阙疑盲 holdout 的"真错 17"由系统构建者本人判定，单一标注者即同时是"被测系统作者"与"金标准制定者"，这是最典型也最难消除的标注者偏差（self-confirmation bias）。Bohrium 测量学教材给出的测量模型 `Observation = True Value + Bias + Random Fluctuation` 在这里直接适用：重复跑 452 条账本只能减小随机项，**对偏差项无能为力**。Northcutt et al.（2019/2021, JAIR）用 confident learning 在所谓"无错"的 MNIST 和 ImageNet（如约 645 张 "missile" 被误标为其父类 "projectile"）中找出了大量标签错误，说明"权威金标准"本身常含系统性错误。

2. **基类频率偏差（base rate bias）是反事实算子 P=R=F1=0 与外层 corpus 43.8% 的隐藏解释器。** 当真实缺陷的基类频率（prevalence）趋近 0 时，精确率/召回率在数学上失去定义或塌缩为 0——这正是反事实算子 `P = R = F1 = 0` 的成因，而非"系统完全失效"。Wikipedia 的 base-rate fallacy 条目给出定量案例：在 40% 患病率人群中，阳性预测值 >93%；同款测试放到 2% 患病率人群，69 个阳性中仅 20 个为真（阳性预测值约 29%）。阙疑外部 corpus 40 只报"检出 43.8%"却未报该 corpus 中真实缺陷的基类频率，**用 P/R/F1 评价必须同时报告 prevalence，否则数字无意义**。

3. **仪器/环境偏差（instrumentation bias）与阈值选择偏差直接动摇阙疑的"确定性卖点"。** 阙疑的判定依赖 `gate_engine.py`（3826 行）读取 67 条规则；若规则存于 Python set/dict，其迭代顺序受 `PYTHONHASHSEED` 哈希随机化影响，则 append-only 哈希链 / Merkle checkpoint 的判定序列可能**每跑一次都不同**——这是把"非确定性"伪装成"可复算"的致命矛盾。同时变异分数 core 97.3%/all 81.5% 是在本机 sanitizer 运行时**全部缺失**（GCC `cannot find -lubsan`、Clang 缺 `libclang_rt.asan_dynamic_runtime_thunk.a`）的环境下算出的，而 Chandrasekar & Kramberger（2026, arXiv:2605.24217）刚证明：benchmark 客户端架构（如 GIL、asyncio 单进程排队）会系统性抬高/扭曲指标——**测量工具本身的偏差会原样污染被测系统的分数**。

## 精确数字与案例

下面用五个小节，把四类偏差（标注者、基类频率、阈值、仪器/环境/回归/幸存者）逐一落到阙疑的实测数字上。每一节都配一张表与至少一处逐字引文，并尽量给出可核验的论文名 + 作者 + 机构 + 年份。需要强调的是：这些偏差不是互相独立的——标注者偏差会放大基类频率误读，仪器偏差会污染阈值比较——它们常常叠加，因此阙疑的分数应当被当作"带系统性误差的区间估计"而非"点估计"。

### 一、标注者偏差：金标准不是天降真理，而是一个需要"校准"的仪器

标注者偏差（annotator / labeler bias）指：用来给系统打分的"正确答案"本身由人（或构建系统的同一批人）产生，带有方向性错误。经典缓解手段是报告标注者间一致性（IAA，如 Cohen's / Fleiss' Kappa），但阙疑当前**没有任何 IAA 数据**。

测量学把这种偏差纳入统一模型。Bohrium 实验科学百科逐字写道：

> "系统误差 (Systematic Error), 也称为偏差 (Bias), 是可预测的、方向性的错误。它不是随机的'抖动'，而是持续地将你的结果推向某个特定方向的'力量'。......与随机误差不同，简单地重复测量对系统误差无能为力。你只会得到一个非常精密但却错误的答案。"

把软件本身视为仪器时，"仪器偏差"被正式定义。Tustison et al.（2013, *Frontiers in Neuroscience*）引述 Sackett (1979) 写道：

> "defects in the calibration or maintenance of measurement instruments may lead to systematic deviations from true values"

该文第七条作者中包括 Luis Ibáñez（Kitware）、Brian Avants（UPenn）等，结论直白：**科学软件若不校准、不维护，其评估结果就会产生系统性偏差**。

更硬的证据来自标签噪声研究。Northcutt, Jiang & Chuang（2019 初稿 / 2021 JAIR, arXiv:1911.00068）用 confident learning 在数据集里找标签错误，逐字引述：

> "we use CL to find several label errors in the presumed error-free MNIST dataset" 以及 "estimating 645 'missile' images are mislabeled as their parent class 'projectile'"（ImageNet）。

**对阙疑的含义**：盲 holdout 的"真错 17"若由作者自标，则 66.7% 检出率的可信上界受限于作者自身的判定偏差；一个方向是引入第二位独立标注者（最好是另一名 C++ 工程师）重标同一 30 张卡，报告 Kappa，这正是 Tustison 指南 2.2.3「at least one co-author independently verify a subset of the results by running the data processing ... on their own computational platform」的精神。

标注一致性不是"差不多就行"。业界通用的判读经验是：Cohen's / Fleiss' Kappa < 0.20 几乎无一致、0.21–0.40 较弱、0.41–0.60 中等、0.61–0.80 较强、>0.80 几乎完全一致。若两位标注者在 30 张卡上只达到 Kappa ≈ 0.3，那么"真错 17"本身就带有可观的不确定性，66.7% 检出率的置信区间会被标注噪声显著拉宽——这正是 `33_小样本检出率置信区间.md` 与 `32_Clopper-Pearson精确计算.md` 已经铺好的统计基础，本方向负责把"标注噪声"这一项显式加回误差预算。

一个具体的工作示例：假设作者标了 17 个真错，独立标注者只认同其中 12 个、并把另外 3 个作者未标的卡判为真错。那么"真错数"在 [12, 20] 区间内摇摆，召回率分母随之变化——66.7% 这个数字可能在 60%–78% 之间浮动，**而这个浮动与系统能力毫无关系，纯粹来自测量工具**。

| 偏差来源 | 阙疑实例 | 量化/缓解 |
|---|---|---|
| 单一标注者 / 自确认 | 盲 holdout "真错 17" 由系统作者判定 | 引入独立第二标注者，报 Kappa（目标 >0.6） |
| 金标准本身含错 | MNIST/ImageNet 标签错误（Northcutt 2021） | confident learning 审计金标准 |
| 仪器未校准 | 变异分数在 sanitizer 缺失下算出 | 修复 sanitizer 后重测（见行动 3） |

### 二、基类频率偏差与假阳性悖论：43.8% 与 0% 都是 prevalence 的副产品

基类频率偏差指：P/R/F1/准确率这些指标会随"真实缺陷在总体中的占比"剧烈变化，而非只随系统能力变化。最直观的呈现是"假阳性悖论 / accuracy paradox"。

Wikipedia「Base rate fallacy」条目给了一组可逐字引用的数字（同一测试，假阳率 5%、假阴率 0）：

- 高患病率人群（1000 人，40% 感染）：真阳 400、假阳 30 → 阳性者"超过 93% 确信"真的感染。
- 低患病率人群（1000 人，2% 感染）：真阳 20、假阳 49 → "only 20 of the 69 total people with a positive test result are actually infected"（阳性预测值仅约 29%）。

条目原文写道：

> "the program's list of criminals will likely have far more innocents (false positives) than criminals (true positives) because there are far more innocents than criminals overall."

meanmethods 博客的贝叶斯清单更直白："A confusion matrix showing 98% accuracy on a class-imbalanced dataset is a hallucination."

**对阙疑的含义**：
- 外部 corpus 40 报"检出 43.8%"，但**没有报告该 corpus 中真实 C++ 知识缺陷的基类频率**。若真实缺陷极少，43.8% 的"检出"可能是大量假阳性。
- 反事实算子 `P = R = F1 = 0`：当反事实算子不注入任何错误时，基类频率 = 0，精确率分母为 0、无定义，而召回率与 F1 结构性塌缩为 0。这**不是系统失效的证据，而是基类频率为 0 时的测量 artifact**（与 ctx 标注的"待修"一致，但根因是度量定义而非能力）。
- 修正方式：在每一个 P/R/F1 旁**强制报告 prevalence**（真错数 / 总卡数），并让反事实算子注入已知数量的人工错误，使基类频率非零、指标可解释。

| 场景 | 阙疑数字 | 隐藏的 base rate 问题 |
|---|---|---|
| 盲 holdout 30 | 真错 17，检出 66.7% | 基类频率 17/30=56.7%，需显式报告 |
| 外部 corpus 40 | 检出 43.8%（A 54.2%/B 12.5%/C 0%） | 各层真实缺陷频率未报告 → 43.8% 不可解释为能力 |
| 反事实算子 | P=R=F1=0 | 基类频率=0，指标结构性塌缩（artifact） |
| 变异 core/all | 97.3% / 81.5% | 已放弃当作缺陷检测率（ctx），避免 base-rate 误读 |

**一个把偏差算出来的贝叶斯示例。** 设某 corpus 共 40 张卡，系统以灵敏度 `Se`（召回率）与特异度 `Sp` 工作，阳性预测值由贝叶斯公式决定：`PPV = Se·p / (Se·p + (1−Sp)·(1−p))`，其中 `p` 为真实缺陷基类频率。取一组并不过分的假设 `Se=0.67, Sp=0.85`：

- 若 `p = 0.567`（盲 holdout 的真实缺陷率），则 `PPV ≈ 0.85`：大部分"检出"是真的；
- 若 `p = 0.10`（外部 corpus 可能更接近的真实缺陷密度），则 `PPV ≈ 0.33`：每 3 个"检出"里只有 1 个真错；
- 若 `p = 0.0`（反事实算子零注入），`PPV` 分母为 0、无定义，`R=F1=0`：并非系统失败，而是度量本身塌缩。

也就是说，**同一套系统、同一组 Se/Sp，只要真实缺陷率从 56.7% 跌到 10%，"检出"的可信度就从 85% 跌到 33%**。这解释了为什么外部 corpus 43.8% 的"检出率"不能直接和盲 holdout 66.7% 比高下——两者背后的 `p` 很可能完全不同。阙疑论文里每一个 P/R/F1 都必须像上面这样把 `p` 摆到台面上，否则就是在做 Barth-Hillel 与 Kahneman 早在 1970–1980 年代就提醒过的"base-rate neglect"。

### 三、阈值选择偏差：四态判决把"何处算检出"变成可调旋钮

阈值选择偏差指：P/R/F1 强烈依赖"阳性"如何定义、决策阈值（operating point）放在哪里。Sameni（2025 初稿 / 2026 v3, arXiv:2504.02169, *On the Geometry of ROC and PR Curves*）的核心结论逐字为：

> "many of the most commonly used binary classification metrics are merely functions of the composition function G:=Fp∘F−1n, where Fp(·) and Fn(·) are the class-conditional cumulative distribution functions of the classifier scores in the positive and negative classes"

换言之，**指标是阈值（operating point）的函数**——换一个阈值，P/R/F1 全盘重写。

**对阙疑的含义**：阙疑是"四态判决"（verified / red-team / draft）与 67 条规则（block 44 / warn 16 / advice 7）。"检出率"到底把谁算作阳性？
- 若只把 `block` 规则命中算"检出错误" → 一个分母/分子；
- 若把 `block + warn` 都算 → 另一个；
- 若把 red-team 卡整体算"已知错误" → 又一个。

同一套系统，仅因"检出"的阈值定义不同，数字可在几十个百分点间漂移。这正是 E&D Track 欢迎的"compare evaluation designs and demonstrate how different assumptions lead to different results"议题。阙疑必须在论文里**显式固定"阳性 = 某条规则族命中"的定义，并做敏感性分析**（换定义后数字如何变）。

| 阳性定义 | 可能计入的规则 | 对检出率的影响 |
|---|---|---|
| 仅 block（44 条） | 阻断级错误 | 最保守，分母大、分子小 |
| block + warn（60 条） | 阻断+警告 | 中等 |
| 含 red-team 卡整体 | 3 张红队卡 | 取决于红队卡如何计数 |

**阙疑必须做的敏感性分析。** 由于 `G:=Fp∘F−1n` 把指标变成阈值的函数，最诚实的做法不是选一个"好看"的定义，而是把三种定义下的 P/R/F1 全部报告，并画出三者的差距带。若三种定义下数字相差不足 ±5 个百分点，说明结论对阈值不敏感、较稳健；若相差超过 20 个百分点（在规则族跨度大时很可能发生），则"检出率"这个数字本身的信息量极低，论文应转而报告"在 X 定义下为 a%，在 Y 定义下为 b%"。这恰好呼应 E&D Track 欢迎的议题："Compare evaluation designs and demonstrate how different assumptions lead to different results or conclusions"。此外，阙疑的"四态判决"里 `draft`（11 张）尚未 verified，把 draft 计入分母会显著拉低分母端的"已验证比例"，这也是一种阈值/口径选择偏差，必须在 metrics_report 里固定口径。

### 四、仪器/环境偏差、回归到均值、幸存者偏差：66.7% → 43.8% 的三种可能解释

**（a）仪器 / 环境偏差。** Tustison et al.（2013）引用 Gronenschild et al.（2012）：

> "significant differences in FreeSurfer output that varied with release version and with operating system"

即**同一算法、换软件版本或操作系统，输出指标就显著不同**。阙疑这边有两处同类风险：
1. 哈希随机化：若 `gate_engine.py` 用 set/dict 承载 67 条规则，`PYTHONHASHSEED` 未锁定时，规则迭代顺序逐次变化，append-only 哈希链与 Merkle checkpoint 的判定序列随之变化 → "可复算"卖点被非确定性击穿。
2. sanitizer 缺失：变异分数 core 97.3%/all 81.5% 在 GCC/Clang sanitizer 运行时**完全缺失**时算出，等同于用未校准仪器读数。

Chandrasekar & Kramberger（2026, arXiv:2605.24217）以 LLM 推理 benchmark 为例，证明客户端单进程 + GIL + asyncio 排队会系统性扭曲延迟指标：

> "widely used benchmarking utilities rely on single-process, asyncio-driven architectures that introduce fundamental client-side queuing bottlenecks" 且 "the Python Global Interpreter Lock (GIL) artificially inflates Time to First Token (TTFT) and Time Per Output Token (TPOT)"

——**测量管道的架构偏差会原样写进被测系统的分数**。

**（b）回归到均值（regression to the mean）。** 盲 holdout 66.7% 与外部 corpus 43.8% 的落差，未必都是能力退化。若盲 holdout 是相对容易/更"像训练分布"的自选样本，首次测量偏高后，换一批更难样本（外部 corpus）自然会向均值回落。Schmidt（2023/2025, arXiv:2305.05792, *Testing for Overfitting*）论证：标准渐近与集中不等式**在训练数据上做评估时不成立**，并提出用假设检验定量检测过拟合。另有一篇 NeurIPS 2019《A Meta-Analysis of Overfitting in Machine Learning》（基于 100+ Kaggle 竞赛）研究测试集复用导致的过拟合——其 PDF 本次未能抓取到逐字数字，**具体通胀幅度列为盲区待核实**。

**（c）幸存者偏差（survivorship bias）。** 我们测到的只有"活下来进入数据集"的卡：37 实卡（verified 23 / red-team 3 / draft 11）+ 10 草稿、452 条账本、9 个保护器。那些在 drafting 阶段被丢弃、未进入账本的卡**永远不会出现在任何 P/R/F1 里**。fastercapital 对 ML 幸存者偏差的总结指出它"can significantly impact the accuracy"——我们看到的"检出率"只覆盖了幸存子集，系统性高估了系统在全部候选知识断言上的表现。更微妙的一层：9 个"保护器"（guard / protector）本身就是作者为了"防止系统出错"而设置的，它们保护下来的卡天然偏向"系统能处理"的部分，等于在抽样阶段就过滤掉了对系统不利的样本——这是幸存者偏差与样本选择偏差的叠加。

**一个可以立刻执行的验证实验（针对 (a) 的哈希随机化风险）。** 在 `gate_engine.py` 入口显式设置 `os.environ["PYTHONHASHSEED"]="0"` 前与后，用**同一份输入（同一组卡 + 同一 67 条规则）各跑 5 次**，比较 5 次产出的 Merkle checkpoint / 最终判定哈希是否一致。若不一致，则"可复算"卖点被非确定性击穿，必须修复（显式排序规则后再入链）；若一致，则该风险排除并写入论文 Limitations。这个实验成本极低、证据极硬，是 E&D Track 最欢迎的"reproduction / stress-testing"型贡献。

| 偏差类型 | 阙疑对应现象 | 证据/来源 |
|---|---|---|
| 仪器/环境 | 哈希随机化、sanitizer 缺失 | Tustison 2013；Chandrasekar 2026 |
| 回归到均值 | 66.7% → 43.8% 落差 | Schmidt 2023/2025 |
| 幸存者 | 仅测"存活"卡，丢弃草稿 + 9 保护器过滤不可见 | fastercapital 2026 综述 |

### 五、把偏差画成一张总表：阙疑每一组数字该被哪把尺子校准

把上述四类偏差落到阙疑的四组实测数字上，可以看到一个清晰的"偏差地图"。E&D Track 欢迎的正是这种"compare evaluation designs and demonstrate how different assumptions lead to different results"式的批判性映射。

| 阙疑实测数字 | 主导偏差 | 该数字当前能否直接读作"能力" | 校准动作 |
|---|---|---|---|
| 盲 holdout 检出 66.7% | 标注者偏差 + base-rate | 半可：分母含自标金标准，且未报 Kappa | 独立第二标注者 + 报 prevalence |
| 外部 corpus 43.8%（A/B/C） | base-rate + 样本选择 + 幸存者 | 否：各层 `p` 未报，A/B/C 选择即偏差 | 分层报 prevalence，修算术不自洽 |
| 变异 core 97.3% / all 81.5% | 仪器/环境（sanitizer 缺失） | 否：已放弃作缺陷检测率（ctx） | 修 sanitizer 后重测，报前后差 |
| 反事实 P=R=F1=0 | base-rate（p=0 塌缩） | 否：度量 artifact，非能力 | 注入已知错使 `p>0` |
| 工作树 227 项漂移 / README 滞后 | 仪器/维护偏差 | 间接：削弱可复算可信度 | 清漂移 + README 对齐（见 `16_227项工作树漂移怎么清.md`） |

这张表的要点是：**阙疑目前没有任何一组 P/R/F1 能在"未做偏差校准"的前提下被诚实读作系统能力**。这不是否定阙疑，而是指出它恰好命中 E&D Track 的痛点——一个把"尺子本身歪了"讲清楚的批判/负结果型投稿，比一个报漂亮数字却经不起审计的投稿更符合 2027 E&D 的定位（"Submissions need not introduce a new model or outperform prior work"）。

**本方向与阙疑论文主线的咬合点。** 阙疑的三大卖点是"判决可复算 + 证据可追 + 盲态协议不可回盲"。本方向指出：可复算的前提是**测量本身无系统偏差**，而哈希随机化与 sanitizer 缺失恰恰威胁"可复算"；证据可追的前提是**金标准可信**，而标注者偏差威胁"证据"；盲态协议保证系统没见过测试卡，却**保证不了标注者没偏见、也保证不了基类频率合理**。因此本方向不是附属的"讨论"，而是对核心卖点的压力测试：只有在偏差审计下仍然成立的可复算，才是 E&D 意义上的可复算。建议把本方向浓缩成论文的 "Threats to Validity / Measurement Bias" 一节，与 `31_43.8%算术不自洽怎么修.md`、`33_小样本检出率置信区间.md`、`32_Clopper-Pearson精确计算.md` 形成统计+偏差的双保险。

## 盲区（诚实标注）

- **NeurIPS 2019《A Meta-Analysis of Overfitting in Machine Learning》的具体数字未核实**：该文 PDF（proceedings.neurips.cc）本次 WebFetch 无法解析，仅从搜索摘要得知"基于 100+ Kaggle 竞赛的测试集复用过拟合元分析"，其精确通胀幅度（如 leaderboard 在新测试集上的平均下降百分点）**未核实**，不写入正文数字。
- **反事实算子 P=R=F1=0 的精确根因未核实**：ctx 标注为"待修"。本方向推断为"基类频率=0 导致的指标塌缩"，但阙疑代码里反事实算子的具体实现是否真的零注入、还是另有 bug，**未核实**，需读 `gate_engine.py` 反事实模块确认。
- **外部 corpus 40 的 A/B/C 分层标准未公开/未核实**：ctx 标注"算术不自洽待修"。A 54.2% / B 12.5% / C 0% 是否各自基于不同基数、是否加权得到 43.8%，**未核实**；各层真实缺陷频率（prevalence）亦未报告。
- **阙疑未做任何标注者间一致性（IAA）测量**：全文的"标注者偏差"推论建立在"作者自标"的合理假设上，但缺乏 Kappa/一致性数据支撑，属推断而非实测。
- **变异分数 97.3%/81.5% 在 sanitizer 缺失下是否可信未核实**：ctx 已"放弃当作缺陷检测率"，但"缺失 sanitizer 是否系统性抬高/压低该分数"尚无前后对比实验，属待补实验。
- **哈希随机化是否真的改变了阙疑判定序列未核实**：本方向指出的 `PYTHONHASHSEED` 风险是**理论风险**；需实测"同输入跑两次、Merkle checkpoint 是否变化"才能确认偏差确实存在（可能规则本身已显式排序，则无此问题）。
