# 方向 20：代码"可执行地开放"的最小要求

## 核心结论

1. **NeurIPS 2026 E&D 把"可执行"写成了 desk-reject 条款，逐字原文是**：*"Code should be documented and executable. Non-compliance justifies the desk rejection of the paper."*（来源：NeurIPS 2026 E&D Track Call for Papers，"Dataset and Code Submission → Accessibility" 段）。同一页还写着 *"Datasets and code must be properly hosted, accessible, and clearly documented **upon submission**; these are essential submission requirements."* 注意时限：**不是 camera-ready 才要，是投稿时就要求可用**（全文截止 2026-05-06 AoE）。

2. **"代码是否强制"在 E&D 里是 contribution-dependent，而阙疑恰好落在"强制"那一类**。CFP 原文：*"code release is ***required*** at submission when the primary contribution is a reusable executable artifact, such as a benchmark suite, evaluation environment, data generator, or software tool, whose functionality must be inspected in order to evaluate the scientific claims."* 阙疑的核心卖点是"判决可复算 + 第三方可不信任内核地复算"——这正是"功能必须被检查"的可执行 artifact。因此不能走 Main Track 的 "no is an acceptable answer" 豁免（Paper Checklist Q5 原文：*"Papers cannot be rejected simply for not including code, unless this is central to the contribution (e.g., for a new open-source benchmark)."*）。

3. **最小集不是"有仓库就行"，而是五件套 + 一条可跑命令**：paperswithcode 的 ML Code Completeness Checklist（NeurIPS 2021 官方采纳）只有 5 项——依赖声明、训练/主流程代码、评测代码、预训练/预置产物、README 中含结果表 + **精确复现命令**。实证：NeurIPS 2019 仓库中**同时满足这 5 项的仓库中位 star 数 196、均值 2664**，显著高于缺项仓库。对阙疑而言，"精确命令"就是一条能产出账本哈希的 `python gate_engine.py --replay <ledger>` 之类。

## 精确数字与案例

### 一、NeurIPS 2026 E&D 官方 code policy 逐字原文

来自 https://neurips.cc/Conferences/2026/CallForEvaluationsDatasets （2026-04 更新，本组实测可访问）：

| 条款 | 逐字原文（英文） | 对阙疑的含义 |
|---|---|---|
| 触发条件 | "our code policy is **contribution-dependent.**" / "code release is ***required*** at submission when the primary contribution is a reusable executable artifact, such as a benchmark suite, evaluation environment, data generator, or software tool, whose functionality must be inspected in order to evaluate the scientific claims." | 强制发布 |
| 豁免条件 | "For submissions whose contributions are analytical, empirical, conceptual, or methodological and do not introduce such artifacts, code release is *not mandatory*, provided that the paper includes sufficient detail to enable meaningful review of the claims." | 阙疑不适用 |
| 托管 | "Code should be made accessible in an executable format via a hosting platform of your choice (e.g., GitHub, Bitbucket)." | GitHub 可 |
| **可执行性（desk reject 条款）** | "Datasets and code should be *available and accessible to all reviewers, ACs, and SACs at the time of submission*, and without a personal request to the PI. Code should be *documented and executable*. **Non-compliance justifies the desk rejection of the paper.**" | 最高优先级风险 |
| 匿名 | "Please make sure to properly anonymize your code based on the requirements of the above 'Review Policy'." | E&D 默认双盲 |
| camera-ready | "All accepted papers must have their code and datasets documented and publicly available by the camera-ready deadline." | 二段式义务 |

E&D FAQ（https://neurips.cc/Conferences/2026/EvaluationsDatasetsFAQ ）补充三条硬信息：① *"For the ED track, datasets and code are not considered supplementary materials. If your submission includes data and/or code, they must be submitted in their final form by May 6, 2026 (AOE), together with the full paper."*——**代码不算补充材料，不能"审稿期后再补"**；② 匿名可用 *"an anonymization service (https://anonymous.4open.science/) or another method"*；③ 若基于公开数据集，"you should make any code used to modify or otherwise use the public datasets … accessible and executable (meaning you will need to provide publicly accessible links to the data sources used)"。

NeurIPS 官方 CodeSubmissionPolicy（https://neurips.cc/public/guides/CodeSubmissionPolicy ）给出"不可执行时怎么办"的**唯一合法辩解口径**：*"Your code submission ideally should be self-contained and executable. If this is not the case, you must explain why. Possible reasons might include: 1. Specialized hardware is required to run the experiment…; 2. The code depends on non-open-sourced or non-free libraries, which do not include the algorithm that is claimed as the scientific contribution…"*。阙疑本机 sanitizer 全部缺失（GCC `cannot find -lubsan`、Clang 缺 `libclang_rt.asan_dynamic_runtime_thunk.a`）**不构成上述两条豁免**——sanitizer 是免费开源工具，属于"必须自己修好"的范围。

### 二、License 要求：代码与数据是两套口径

NeurIPS 主 CfP 的 Checklist Q12（Licenses）逐字要求：*"Cite the original paper that produced the code package or dataset… Remember to state which version of the asset you're using… State the name of the license (e.g., CC-BY 4.0) for each asset."* 即：**必须写出许可证名称与版本**，并在发布资产时 *"include a license, copyright information, and terms of use in the package"*。

E&D 特有的数据侧要求在 Hosting Guidelines（https://neurips.cc/Conferences/2026/EvaluationsDatasetsHosting ）里，逐字：*"**Dataset license** — Datasets should have a clear license that enables the intended use of the data… We recommend using open data licenses that allow reuse and reproducibility… **The license should be included in the Croissant file of your dataset.**"* 而 Croissant 的 `license` 字段定义原文是 *"Croissant recommends using the URL of a known license, e.g., one of the licenses listed at https://spdx.org/licenses/."*——**所以许可证要写成 SPDX 标识符或 SPDX 许可证 URL**（如 `https://spdx.org/licenses/Apache-2.0.html`），不能写"for research use only"。

对代码本身，NeurIPS 未指定具体许可证，只要求"明确"。业界事实标准是宽松型许可证：SPDX License List（https://spdx.org/licenses/ ）中 MIT 与 Apache-2.0 是最常用的两个宽松型标识符；Apache-2.0 额外含专利授权条款，MIT 更短更简单。阙疑若含论文可引用的工具链，选 Apache-2.0 更稳（专利明示授权）；若只求最小摩擦选 MIT。

### 三、README / LICENSE / 依赖锁定的最小集

paperswithcode 的 *releasing-research-code*（https://github.com/paperswithcode/releasing-research-code ，标注 "now official guidelines at NeurIPS 2021"，基于 200+ ML 仓库分析）给出**只有 5 项**的 ML Code Completeness Checklist：

1. **Specification of dependencies** — 原文给了具体形态：*"providing a `requirements.txt` file (if using `pip` and `virtualenv`), providing `environment.yml` file (if using anaconda), or a `setup.py` if your code is a library."* 并加了一句关键提醒：*"Assume minimal background knowledge and be clear and comprehensive - if users cannot set up your dependencies they are likely to give up on the rest of your code as well."*
2. **Training code** — 必须是"能产出论文主结果的脚本"，含超参与 trick；建议提供 `train.py` 作为文档化入口。
3. **Evaluation code** — *"Model evaluation and experiments often depend on subtle details that are not always possible to explain in the paper."* 建议 `eval.py`。
4. **Pre-trained models / 预置产物** — 目的是让社区"不必重新训练就能看到结果可信"。
5. **README 含结果表 + 精确命令** — 原文：*"Adding a table of results into README.md lets your users quickly understand what to expect from the repository… Instructions on how to reproduce those results (with links to any relevant scripts, pretrained models etc) can provide another entry point for the user and directly facilitate reproducibility."*

NeurIPS Checklist Q5 的指导文本进一步把"精确命令"定义死了：*"The instructions should contain the exact command and environment needed to run to reproduce the results."*——**"exact command and environment"** 这七个词就是"可执行地开放"的操作性定义。

对**长期归档**，MLRC 2026（已成为 NeurIPS 2026 官方 track，https://reproml.org/call_for_papers/ ）给出了可直接抄的做法，逐字：*"Sharing the code used to produce your results is **strongly recommended**. Authors should archive their implementation using the [Software Heritage Archive](https://archive.softwareheritage.org/), which provides a permanent, citable identifier for source code."* 即：GitHub 之外再打一个 Software Heritage 永久标识符（SWHID），写进论文脚注。

### 四、Artifact Evaluation 门槛：四档徽章与 EuroSys 五年真实获得率

ACM 官方 *Artifact Review and Badging*（v1.1，2020-08-24，https://www.acm.org/publications/policies/artifact-review-and-badging-current ）逐字定义：

| 徽章 | 逐字标准 |
|---|---|
| **Artifacts Available** | "Author-created artifacts relevant to this paper have been placed on a publically accessible archival repository. A DOI or link to this repository along with a unique identifier for the object is provided." 补充：*"Personal web pages are not acceptable for this purpose."*（个人主页不算） |
| **Artifacts Evaluated – Functional** | "The artifacts associated with the research are found to be **documented, consistent, complete, exercisable**, and include appropriate evidence of verification and validation." 四词各自的定义：Documented = 至少含清单 + 足够说明；Consistent = 与论文相关且实质贡献主结果；Complete = 相关组件尽量齐全（专有件可豁免但须说明获取方式）；**Exercisable = 脚本能成功执行、数据能访问并正确处理**。 |
| **Artifacts Evaluated – Reusable** | 高于 Functional 一级（本次未逐字抓取，见盲区）。 |
| **Results Reproduced** | "The main results of the paper have been obtained in a subsequent study by a person or team other than the authors, using, in part, artifacts provided by the author." |
| **Results Replicated** | "The main results of the paper have been independently obtained in a subsequent study by a person or team other than the authors, without the use of author-supplied artifacts." |

且原文强调：*"In each cases, exact replication or reproduction of results is not required, or even expected. Instead, the results must be in agreement to within a tolerance deemed acceptable for experiments of the given type."*——**允许容差，但"差异不得改变论文的主要结论"**。这对阙疑的四态判决/账本哈希场景尤其重要：判决复算应做到**逐位一致**（哈希链天然是精确量），而不是"容差一致"。

EuroSys 2021–2025 五年 AE 的官方统计（SIGOPS 博客 2025-08-05，https://www.sigops.org/2025/lessons-from-five-years-of-artifact-evaluation-at-eurosys/ ；完整论文 ACM REP '25，DOI 10.1145/3736731.3746152）：

- **Artifacts Available：161 件**
- **Functional：136 件**
- **Results Reproduced：75 件**
- **每年稳定约 58% 的录用论文参加 AE**
- AE 委员会规模 2025 年达 **98 人**
- 六类持续挑战中包含 *"Tight Deadlines"*、*"Specialized Hardware or infrastructure"*、*"Imprecise badge definitions"*（ACM 定义是 descriptive 而非 prescriptive，导致跨届解释不一致）
- 长期建议之一是 **"Explicit Artifact Commitment in Papers"**：*"Require authors to declare which results are reproducible and how at paper submission time."*

换算：161 → 136 → 75，即 **拿到 Available 的 artifact 中约 84.5%（136/161）能拿到 Functional，约 46.6%（75/161）能拿到 Results Reproduced**。这是一个可写进论文的"AE 通过率漏斗"参考基线。

### 五、"可执行"到底有多难：两个实测数字

**(a) NeurIPS 代码发布率的历史基线。** *What is the Impact of Releasing Code with Publications?*（arXiv:2308.10008，2023-08，后发表于 IEEE，DOI 10.1109/MCS.2024.3402543 待核）统计 2016–2021：NeurIPS 含开源代码论文比例从 **2016 年的 27.6%** 升至 **2019 年起稳定 >60%**（2018→2019 单年跳升 20.6%）；同期 ICRA 仅约 **5%**、CDC 约 **2.6%**。原文结论：*"publications at NeurIPS are ten and twenty times more likely to include OSC compared to publications at ICRA and CDC, respectively."* 另有：**2016–2020 年 NeurIPS 被引前 1% 的论文全部包含开源代码**；有代码论文发表四年后引用第三四分位数仍增长 **79.13%**，无代码论文降至 20% 以下。

**(b) "写出来"≠"跑得起来"。** *AI-Generated Code Is Not Reproducible (Yet): An Empirical Study of Dependency Gaps in LLM-Based Coding Agents*（arXiv:2512.22387v3，2026-03-23）：300 个项目（3 个 LLM 代理 × 100 个"请保证 100% 可复现"的提示词 × Python/JavaScript/Java），在干净 EC2 环境（Ubuntu 22.04、91 个基线包）中**仅 68.3% 开箱即用**，**31.7% 失败**。分层：Python 89.2% / JavaScript 61.9% / **Java 仅 44.0%**。依赖侧：**从声明依赖到实际运行时依赖平均膨胀 13.5 倍**（*"projects claiming 3 dependencies actually require an average of 37 packages"*）；失败原因中 **52.6% 是代码缺陷**、仅 **10.5% 是依赖缺失**。原文提醒：每个失败项目平均需 **15 分钟**人工调试，**每 100 个生成项目约 8 小时调试成本**。

这组数字对阙疑的直接含义：C++ 项目介于 Java 与 JavaScript 之间（编译 + 链接 + 运行时库，比 Python 脆弱得多）。若只发 `requirements.txt` 而不锁版本、不提供容器，**"可执行"大概率在审稿人机器上失败**，而按 E&D 条款这正好落在 desk-reject 措辞上。

## 对阙疑的 3 条具体行动

1. **在仓库根目录补三件套，并把"exact command and environment"写进 README 顶部（2026-12 前完成）**：`LICENSE`（建议 Apache-2.0，SPDX 标识符写 `Apache-2.0`）、`requirements.lock`（`pip-compile --generate-hashes` 或 `uv lock` 产出，见方向 23）、`REPRODUCE.md`（见方向 26）。README 必须包含一张"论文表 N 的结果 ↔ 一条可复制命令"的对照表，命令形态例如 `docker run --rm --network=none queyi/repro:v1 python gate_engine.py --replay fixtures/ledger_452.jsonl --expect-digest sha256:...`，并**实机跑一遍确认退出码为 0**。理由：E&D FAQ 明确代码须在 2026-05-06 前以最终形态提交，且 Checklist Q5 要求 *"the exact command and environment"*。

2. **写 `Dockerfile` 并在 CI 里跑"可执行性冒烟测试"，把结果做成状态徽章（2026-12 前）**：CI 步骤固定为 `docker build --network=none -t queyi:test .` → `docker run --network=none queyi:test pytest -q` → 与仓库内提交的 `expected_digest.txt` 比对账本 Merkle root。**必须先修 sanitizer**（`-lubsan` 缺失、Clang 缺 `libclang_rt.asan_dynamic_runtime_thunk.a`），否则"本机跑不起来"会被审稿人读成"artifact 不 executable"。若确有无法在本机复现的部分，**按官方唯一豁免口径**在 README 用一节 `## Known non-executable components` 逐条写明原因（参照 CodeSubmissionPolicy 的两条合法理由），不要沉默。

3. **在 `research/` 下新增 `20_code_availability.md`，用 Checklist Q5/Q12/Q13 的原文做自查表，并在 2027-03 前冻结匿名镜像**：内容包含 (i) Q5 答案与"精确命令"清单；(ii) Q12 的许可证表（每个第三方依赖的名称 + SPDX ID + 版本，C++ 侧尤其要列全 header-only 库的许可证）；(iii) 匿名化方案——用 `anonymous.4open.science` 或新建匿名 GitHub 组织，**务必清理 git 历史中的作者邮箱与远程 URL**（见方向 24、28）。同时按 MLRC 2026 做法，把最终版推到 **Software Heritage Archive** 取一个永久 SWHID 写进论文。

## 盲区（诚实标注）

- **ACM "Artifacts Evaluated – Reusable" 的逐字定义未抓取**。本次只逐字取到 Functional 一级，Reusable 一级的原文措辞属未核实。
- **E&D Track 未公布"因代码不可执行被 desk reject"的实际案例数与比例**。官方只有规则文本，没有执行统计；CFP 里 *"Non-compliance justifies the desk rejection"* 用的是 "justifies"（正当化）而非 "will result in"，**实际执行尺度未知**。
- **"Paper Checklist Q5 与 E&D CFP 的强制口径是否冲突"存在解释空间**。Checklist 说 *"Papers cannot be rejected simply for not including code, unless this is central to the contribution"*，CFP 说可执行 artifact 强制发布——两者在阙疑这类"工具即贡献"的论文上应理解为 CFP 更严，但**这是本组的推断，非官方明示**。
- **arXiv:2308.10008 的期刊版本 DOI 未逐字核实**（仅从检索结果看到 IEEE 页面 10621946）。引用时建议只用 arXiv 编号 + 年份。
- **arXiv:2512.22387 的编号与日期异常**（编号形如 2512 = 2025-12，但页面显示 2026-03-23 更新为 v3）。该文为 LLM 生成代码的可执行性研究，**样本是 Python/JS/Java，无 C++**，向 C++ 外推属推断。
- **EuroSys 的 161/136/75 是"artifact 件数"而非"论文数"**（一篇论文可提交多件），且 EuroSys 是系统会议、非 ML 会议，向 NeurIPS E&D 外推需谨慎。
- 未核实：NeurIPS 是否对**代码仓库本身**做自动化可执行性检查（如自动 clone + build）。官方文本只描述人工审稿路径。
