# 方向110：人工免疫系统

## 一、问题定位：人工免疫系统不是把生物学名词贴到检测器上

人工免疫系统（Artificial Immune System，AIS）是一组受生物免疫现象启发的计算方法，常见路线包括 negative selection（负选择）、clonal selection（克隆选择）、immune network（免疫网络），以及后来与 danger theory（危险理论）相关的上下文信号机制。它们共同关心的问题，是在一个会变化、会出现未知模式、且正常样本不可能穷尽的空间里，如何维持对“正常”的描述，如何发现偏离，如何让有用的识别经验保留，同时避免每次变化都把系统全部推倒重来。

这个问题与阙疑的 C++ 知识验证系统有表面相似性：系统目前有 37 张实卡、67 条规则、9 个保护器、452 条 append-only 账本记录，另有 30 条盲 holdout，其中真错 17 条而当前检出率为 66.7%。知识卡不是静态百科条目，而是带有来源、断言、适用条件、反例、验证结果和版本关系的结构化证据。规则也不是永远可靠的自然定律：C++ 标准会演进，编译器实现会变化，语言版本和编译选项会改变，某条规则可能从适用于 C++11 的安全建议变成 C++20 下的过时限制。因而系统同时面临两种不同事件：第一种是单条卡或单次提交异常，可能是误写、格式错误、来源缺失或投毒；第二种是规则库随时间发生真实变化，表现为整体分布漂移、规则命中率变化或新标准语义进入。若把两者都叫“异常”，就会把正常演进误杀；若把所有变化都当成正常，又会让投毒伪装成版本更新。

人工免疫系统最有价值的地方，不是提供一个神奇的“免疫式安全保证”，而是提供一个分层思考框架。负选择提醒我们从稳定的 self 基线出发，寻找不能被正常模式解释的 non-self；克隆选择提醒我们可以让高证据、高复现度的候选检测器获得更多资源，并通过小幅变异适应新情况；免疫网络提醒我们维护多个互补、不过度同质化的检测单元，关注它们之间的相似、抑制和冲突；危险理论则提醒我们，孤立的“陌生”不等于恶意，真正需要提高警报等级的往往是陌生性与完整性破坏、来源异常、判决翻转、重复失败等上下文信号的组合。

因此，本方向的工程结论必须先写清楚：AIS 只能作为基线检测之上的补充机制，不能替代哈希、来源、签名、schema、逻辑一致性、编译器实测和盲态回放。对一个可审计的 C++ 知识验证系统，最先要做的不是训练一群“抗体”，而是让每一张卡的输入、版本、来源和执行结果都可重放，让每一次规则变化都可解释，让误报和漏报都能被统计。人工免疫类比只有在这个基础上才有意义。

## 二、三条核心机制：negative selection、clonal selection 与 immune network

**1. Negative selection：从 self 基线生成 non-self 检测器。** 生物学类比通常从胸腺中的负选择讲起：与自体成分反应过强的细胞被淘汰，剩下的细胞可以响应潜在的外来模式。在计算实现中，先把一组被认为正常的样本定义为 self，再生成候选 detector；若候选 detector 与 self 的相似度超过匹配阈值，就删除它；若它不匹配 self，则保留并用于扫描新样本。输入可以是二进制串、实数向量、符号序列、图结构或特征组合，匹配可以用 Hamming 距离、欧氏距离、半径规则、k-NN 或其他相似度。Ayara 等人在 2002 年的 *Negative Selection: How to Generate Detectors* 中专门比较了检测器生成程序的时间复杂度、空间复杂度和检测率，结论不是某个算法普遍最优，而是三者之间需要权衡。2023 年的负选择异常检测综述也把 detector generation、representation、shape、matching 和 coverage 视为关键分类维度。

把它映射到知识卡，可以把一个版本中经过人工复核、来源完整、编译器实验可重放、没有判决冲突的卡集合定义为 self。新卡进入时，检测器不应直接问“它是否陌生”，而应计算多类距离：字段 schema 距离、来源可信度距离、断言与已有卡的语义冲突距离、适用标准版本距离、测试结果距离、对账结果距离，以及加入后导致的判决翻转距离。只有当多个维度共同偏离基线时，才把卡标为 suspect，进入人工复核或隔离队列。这样做比单独对文本 embedding 做离群检测更贴近 C++ 知识验证任务，因为一张文字风格不同但事实正确的卡不应仅凭陌生而被删除，而一张与主流措辞相似、却把 `std::move`、对象生命周期或未定义行为说错的卡，可能恰恰是最危险的“近邻投毒”。

负选择的限制同样必须正面承认。self 只能覆盖已观察到的正常空间；如果 37 张卡不足以覆盖 C++ 的版本、平台、编译器和上下文，检测器会把未见过的正常知识当作 non-self。检测器的生成在高维离散空间可能非常昂贵，随机生成还会产生覆盖空洞；阈值过低会漏报，阈值过高会误报。更严重的是，攻击者如果知道 detector 的表示和阈值，可以构造彼此接近、刚好落在正常边界内的投毒卡。因此，negative selection 更适合做“候选异常的发现”和“复核预算的排序”，不适合单独做 block 判决。

**2. Clonal selection：根据亲和度分配复核资源，而不是给高分样本自动盖章。** 克隆选择的计算抽象通常包括：计算候选抗体对抗原的 affinity，选择高亲和度候选，按亲和度扩增其克隆，对克隆进行变异，再保留记忆细胞。de Castro 与 Von Zuben 的 *Learning and Optimization Using the Clonal Selection Principle* 将这一原则用于学习和优化；该路线的计算含义是把搜索资源集中在表现较好的候选上，同时用变异保留局部探索能力。对知识验证系统，可把“抗体”理解为一个检测假设或复核策略，而不是事实本身。例如一个候选检测器可以是“检测 C++ 对象生命周期断言与 `-fsanitize=address` 结果是否矛盾”，另一个可以是“检测规则命中率突然改变且只由同一来源提交的卡造成”。候选策略在盲 holdout、真实缺陷夹具、编译器矩阵和反事实测试上的表现，才是它的 affinity。

这里必须防止一个常见误读：高亲和度只表示某个检测器在现有评测集上有用，不表示它发现的卡就是正确的。若把检测器输出反过来当作训练标签，系统就会产生自我强化回路：早期误判被克隆，克隆后的相似规则继续给出相同误判，最后形成一个看似“记忆稳定”但实际错误的规则簇。因此，克隆选择在阙疑中只能用于复核顺序、预算分配和候选策略进化；卡片的 verified 状态仍要依赖独立来源、可执行例子、版本条件、人工审阅或外部 oracle。新策略的收益还必须与随机搜索和固定基线比较，不能因为“变异后发现更多”就声称免疫算法优于普通检测。

**3. Immune network：用多样性、抑制和记忆管理规则群。** de Castro 与 Timmis 的人工免疫网络工作把网络模型用于信息压缩、数据聚类和多峰优化，并强调保持稳定的多个局部最优解。其可迁移的抽象不是“细胞真的互相交流”，而是维护一组相似度可计算的原型，并通过资源分配、相似原型抑制和新样本加入来平衡覆盖与多样性。对 67 条规则，可以构造一个规则—卡—测试夹具三部图：规则节点表示验证条件，卡节点表示证据，夹具节点表示可重放的程序行为；边表示命中、支持、冲突或覆盖关系。多个检测器如果只覆盖同一类 `const` 用法，而对生命周期、并发、异常安全、模板实例化和标准版本没有覆盖，它们数量很多却没有免疫网络意义上的多样性。

在工程上，网络机制可以做三件事。第一，按断言主题、来源、标准版本和测试行为聚类，发现某一簇突然膨胀或某一簇完全消失。第二，利用抑制思想避免大量几乎相同的规则重复占据复核预算，同时保留互相独立的验证路径。第三，对强冲突边设置高优先级：两张卡都标记 verified，但在相同编译器、相同标准和相同前置条件下得出相反结论，应进入冲突审计，而不是由多数票简单掩盖。网络并不自动解决 ground truth 问题；它只能把结构显式化，使“谁支持谁、谁与谁冲突、哪条卡改变了哪批判决”可查询、可回放。

## 三、面向 C++ 知识卡异常与投毒的落地架构

第一层应是**确定性基线检测**，而不是 AIS。每张卡入库前先检查 schema、必填字段、唯一 ID、来源 URL、抓取时间、内容哈希、提交者、审核轨迹、标准版本和编译器版本；账本继续采用 append-only，纠错通过追加反转条目实现，不能原地覆盖。用 SHA-256 或同类完整性校验能发现内容被改写，但不能证明内容本来就正确，所以还要把 provenance 与独立复核分开记录。NIST 的软件供应链安全指导把软件安全评价、开发者和供应商实践评价、以及证明安全实践符合性的工具和方法都列为治理内容，这对知识卡的来源治理有直接启示：卡片不是“文本文件”，而是供应链中的可审计制品。

第二层是**基线分布与影响检测**。对 452 条账本记录建立按规则、主题、来源、版本和时间的基线，至少保存：规则命中率、verified/warn/block/advice 比例、每张卡支持与冲突的边数、编译器通过率、sanitizer 结果、复核耗时、判决翻转数和外部来源分布。用中位数与 MAD、分位数区间、留一法影响值和变更点检测标记异常；不要只看平均准确率。比如一张卡加入后整体 F1 不变，但让某条 block 规则在一个特定标准版本下变成 warn，仍然是高影响异常。若规则命中率缓慢随 C++ 标准迁移而变化，这更可能是 concept drift；若命中率在一次提交后突然跳变，且变化集中到一个来源或一组相似卡，则应优先按投毒或错误变更调查。有关 concept drift 的异常与 change-point 研究说明，异常与分布变化需要联合识别，不能把每个变化点都解释为恶意。

第三层才是**negative selection 检测器池**。可以把规则命中向量、卡片元数据向量、冲突图局部结构和编译器测试结果编码成组合特征。用历史稳定区间训练 self，生成不匹配的 detector，并按以下信号加权排序：结构异常、来源异常、语义冲突、执行反例、判决翻转、时间突发和同簇重复。输出建议保留四态或多态：clean、suspect、conflict、reverted，而不是直接二元删除。关键是为 detector 做独立评估：在 30 条盲 holdout 上报告检出数、误报数、Clopper–Pearson 区间；在真实缺陷夹具上报告重放检出；在自适应投毒副本上报告检出与误删。负选择文献强调生成成本、空间和检测率的权衡，这意味着 detector 数量、覆盖率和计算延迟都应进实验表。

第四层是**clonal selection 式复核调度**。每个候选检测器有一个不等同于“真理”的亲和度向量，例如 `(holdout_detected, false_positive, replay_success, cost_ms, diversity)`。不能未经论证把它们压成一个总分；至少应保留偏序或 Pareto 前沿。高分且多样的检测器获得更多复核预算，失败检测器降权，但不从历史中抹除。检测器的变异可以是改变相似度阈值、替换特征组合、增加标准版本条件、生成反事实 C++ 例子或切换编译器矩阵。每次变异都在盲态登记，先写预测，再看 holdout，避免“看完答案再调整抗体”。

第五层是**immune network 式规则库监控**。把 67 条规则按主题、来源、版本、测试夹具和判决关系构成网络，每次更新计算网络差分。重点警报包括：一个新来源在极短时间内支持大量互相相似的卡；一条新规则突然覆盖大量旧规则；某个检测器簇互相复制、却没有新增独立证据；两条 verified 卡在同一条件下矛盾；一条卡的移除使大量判决同时翻转；规则库变化后 holdout 检出率下降但总体通过率保持不变。这些信号组合起来，才接近“危险上下文”。若知识卡被 LLM 检索后再生成解释，可以参考 RevPRAG 的输出侧检测思想：其论文在特定 RAG 数据集、模型和攻击设置下报告过接近 98% TPR 和较低 FPR，但该信号依赖可访问的 LLM hidden states，不能直接迁移到纯规则引擎。对纯 C++ 规则系统，显式逻辑冲突、来源完整性和执行轨迹通常比激活异常更可靠。

## 四、类比边界、失败模式与基线优先原则

第一条边界是，生物免疫系统不是一个只接受静态标签的二分类器。“self”和“non-self”在免疫学中并非永远固定；免疫耐受、组织环境、先天与适应性免疫、损伤信号共同影响反应。近年来对 self/non-self 二分法的讨论以及 danger theory 的研究都说明，危险上下文不能被简化为“陌生即坏”。对应到 C++ 知识，新的标准特性、新编译器警告或新的库惯例可能天然是陌生的，却不应被阻断。反过来，已进入规则库的内容也可能已经被污染，不能因为它属于 self 基线就永久可信。基线必须有来源和证据等级，并能定期重建。

第二条边界是，免疫记忆不等于不可变知识。生物记忆细胞是在复杂选择压力和反馈中形成的；工程中的“memory cell”只是版本化的检测器、规则或历史样本。若没有独立证据、回滚、时间戳和重新评估机制，所谓记忆只是把旧错误保存得更久。append-only 账本可以保证变更可追溯，却不会自动阻止毒卡合法进入；哈希能证明“现在与记录一致”，不能证明“记录内容正确”。因此，人工免疫系统不能成为跳过 provenance、签名和人工审核的理由。

第三条边界是，异常检测与投毒检测不是同一目标。异常检测发现偏离基线的对象，投毒检测则要判断偏离是否有意、是否会改变验证结果、是否绕过既有防线。一个新标准版本的规则可能是强异常但不是攻击；一组刻意模仿正常风格的投毒卡可能并不离群，却会改变局部判决。单一 detector 的高分不能证明攻击存在，单一模型的正常准确率也不能证明规则库没有后门。必须把内容异常、来源异常、执行异常和影响异常分开测量，并设置人工复核和可逆隔离。

第四条边界是，AIS 算法的性能不能脱离表示、阈值和数据集谈论。负选择在高维空间可能有覆盖空洞；克隆选择可能放大早期偏差；免疫网络可能把多数相似错误误当作共识；网络规模、距离函数和抑制规则也会改变结果。对于阙疑这样只有 30 条盲 holdout、37 张实卡的小样本系统，任何“98% 检出率”都可能有很宽的精确区间，不能照搬图像、网络入侵或 RAG 论文的数字。已有投毒研究还表明，少量干净标签投毒可能不降低整体验证准确率，却定向改变特定行为；所以必须报告目标判决翻转，而不能只报告总通过率。

基线优先可写成一条强制顺序：**先完整性，再来源，再结构，再逻辑，再执行，再统计基线，最后才是 AIS 异常评分。** 完整性层检查哈希、签名、append-only 和版本关系；来源层检查 URL、快照、抓取时间、作者和审核轨迹；结构层检查 schema、重复、字段边界和标准版本；逻辑层检查规则冲突、前置条件、覆盖关系和四态格一致性；执行层用最小 C++ 例子、编译器矩阵、sanitizer 和反事实测试重放；统计层监控规则命中率、判决分布、影响值和变更点；AIS 层只负责发现剩余的未知组合和安排复核优先级。若前六层都没有建立，AIS 越复杂，越可能把不可解释的误报包装成“仿生智能”。

## 五、对阙疑的三条行动、盲区与来源

**行动一：建立可重放的 self 基线与规则库健康快照。** 在 67 条规则和 452 条账本记录上生成固定版本快照，给 37 张实卡补齐 `source_url`、`fetch_timestamp_utc`、`content_sha256`、`rule_author`、`review_trace_id`、标准版本、编译器版本和测试夹具引用。每个 checkpoint 输出规则命中率、四态分布、来源分布、冲突边、判决翻转和留一法影响值。先用 schema、哈希、来源和逻辑冲突做确定性阻断，再以 MAD、分位数和 change-point 做基线报警。目标不是立即实现完整 AIS，而是把 self 定义成可审计、可重建、可比较的证据集合。

**行动二：做一轮“基线检测 vs AIS 检测”的盲态对照实验。** 在 30 条 holdout 和真实缺陷夹具上预先登记检测器，设置至少四个臂：固定规则基线、MAD/影响值基线、negative selection detector、加入 clonal/network 调度的组合臂。每个臂使用同一批输入、同一预算和同一复核规则，报告 TP、FP、FN、TN、检出率、误报率、精确区间、检测延迟、规则覆盖率和误删卡数。再构造不改变总体通过率但会改变目标判决的干净标签投毒，以及彼此相似、试图穿过简单阈值的自适应投毒。若 AIS 没有显著优于基线，必须保留这一 negative result；在小样本条件下，简单、可解释、可回放的基线优先于复杂仿生模型。

**行动三：把规则变化监控做成“网络差分 + 人工复核”的发布门。** 将规则、卡、来源、测试夹具和判决关系存成可查询图，更新时计算新增、删除、冲突、覆盖、来源集中和批量翻转。只有当变更通过 provenance 校验、独立对账器复算、C++ 编译/运行测试、盲 holdout 不恶化且冲突被解释后，才从 suspect 或 conflict 晋升为 verified。AIS 的 detector 可以为复核排序、寻找异常簇和生成反事实测试，但不得直接把新卡晋升为可信规则，也不得直接删除历史。所有撤回采用追加反转条目，保证攻击调查能够回答“哪一次变更、由哪条卡、通过什么规则、改变了哪些判决”。

本方向的盲区必须明确写出。第一，现有 AIS 文献大量来自网络入侵、分类、聚类和函数优化，尚未提供“C++ 知识卡投毒检测”的直接实测基线；本文的映射是架构启发，不是已被论文证明的效果。第二，negative selection 的检测器生成、覆盖率和阈值选择在不同表示空间下差异很大，不能从一个二进制串实验外推到 C++ 规则图。第三，RevPRAG 等 LLM 激活检测方法需要特定模型、数据和攻击样本，纯规则引擎没有相同的激活信号；即便 C++ 卡被检索进 LLM，也不能把公开论文的 TPR/FPR 当作本项目保证。第四，37 张实卡和 30 条 holdout 极小，任何百分比都应配精确区间，且要警惕把一次规则漂移误判为攻击。第五，人工免疫的生物类比可能诱导过度拟人化：它不能提供意图识别、绝对正确性或自动免疫投毒的保证。
