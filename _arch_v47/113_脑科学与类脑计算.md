# 方向113：脑科学与类脑计算——神经形态、脉冲事件与可审计验证系统

## 一、问题边界：类脑计算可以借鉴什么，不能把什么直接搬进阙疑

脑科学与类脑计算对阙疑最有价值的，不是再造一个“像大脑一样思考”的宣传口号，而是提供一组可拆分、可测量、可失败的工程假设：信息可以用稀疏事件表示，状态可以在事件到来时局部更新，预测可以先于完整输入形成，异常可以表现为预测误差或状态转移的突变，记忆可以被组织成带时间和上下文的局部状态，硬件可以通过减少无效搬运而降低延迟和能耗。这些假设能够启发 C++ 知识验证系统的输入编码、事件账本、异常检测和边缘部署；但它们不是“人脑机制已经被证明”的结论，也不意味着把神经元、突触、海马体等词替换进软件架构就产生科学贡献。真正需要验证的是：某一种事件表示是否减少了实际 I/O；某一种脉冲更新是否在相同检出率下减少 CPU 时间；某一种预测误差是否比完整重跑更早发现账本异常；某一种稀疏索引是否在目标嵌入式设备上减少了总能耗，而不是只减少了乘加次数。

“neuromorphic computing”通常指围绕神经元动力学、突触连接、事件通信和非冯·诺依曼数据流设计的计算系统；“spiking neural network，SNN”则是常见的抽象，神经元不持续输出浮点激活，而是在膜电位积累到阈值时产生 spike。真正的生物神经元远比常见的 leaky integrate-and-fire 模型复杂，类脑芯片也不等于生物脑的数字复制品。IBM TrueNorth 的公开论文给出了一个很适合说明工程取舍的数字：芯片包含 4096 个 neurosynaptic cores、约 100 万个数字神经元和 2.56 亿个突触，并以事件驱动路由连接；论文标题和摘要报告其处理器功耗为 65 mW，但这个数字属于特定芯片、特定工作负载和特定测量边界，不能转写成“类脑计算普遍比 CPU 低若干数量级”[1]。BrainScaleS-2 也不是纯粹的生物模拟器，而是模拟神经动力学核心、数字处理器和数字事件路由网络的混合信号系统；其约 1000 倍生物时间加速针对芯片内动力学，外部传感器、主机通信和执行器并不会自动获得相同加速[2][3]。Intel 对 Loihi 2 的官方技术 brief 宣称相较前代“up to 10x”，这是厂商给出的能力上限表述，必须和具体模型、芯片配置及测量方法一起引用[4]。

对阙疑而言，最重要的类比边界是：脑科学中的“记忆”“预测”“误差修正”是神经系统层面的理论构念；阙疑中的 452 条 DecisionEvent、37 张实卡、67 条规则、9 个保护器和 3826 行内核则是可序列化、可哈希、可回放的软件对象。生物脑可能通过多种并行回路、可塑性和神经调质共同完成任务，软件系统却必须说明每个字段、每个版本和每个判决的因果链。因而本文把类脑计算作为低功耗事件处理和不确定性管理的设计启发，而不把它当作对人脑真实工作机制的断言。尤其不能因为某个 SNN 在图像或语音数据集上有效，就声称它理解了 C++ 的对象生命周期、ODR、模板约束或未定义行为；也不能因为一个预测编码模型能解释若干神经影像现象，就声称“预测误差就是大脑唯一的纠错机制”。

## 二、机制谱系：脉冲、事件驱动、记忆与预测误差的工程含义

SNN 的基本工程优势来自“只在事件发生时更新一部分状态”的可能性，而不是“脉冲天然更智能”。连续时间神经元可以写成简化的状态更新：膜电位或内部状态在时间上衰减，输入 spike 到来时累加权重，超过阈值则发出新事件。若输入本身是事件相机、传感器边沿、日志追加、编译器诊断或文件变化，事件驱动流水线可以避免每个时间片对全部节点做全量扫描。TrueNorth 的论文明确把事件驱动路由作为降低通信和实现大规模并行的基础[1]；事件相机综述也指出，这类传感器以异步方式报告亮度变化，而不是按固定帧率输出整幅图像[13]。但若输入本来是每次都变化的密集文本、完整 AST 或高频全量构建结果，事件化之后仍可能产生接近全量的数据量，甚至新增时间戳、地址、队列和索引开销。因此阙疑首先应测量事件率、批量率和重放成本，而不能只在架构图上写“event-driven”。

“spiking neurons”对阙疑的直接启示是把状态更新从“每次查询重新计算”改成“增量事件触发”。例如，对每个知识卡维护一个轻量状态：最近一次证据时间、当前规则版本、编译矩阵覆盖、未解决冲突数、unknown 原因和异常分数。收到 `EvidenceAdded`、`CompilerObserved`、`RuleSuperseded`、`ReplayCompleted` 等事件时，只更新受影响的卡和依赖闭包；没有事件的卡不重复跑全套检查。这个设计并不要求真的训练 SNN，可以先用 C++ 的结构化事件和优先队列实现。若以后使用脉冲模型，spike 更像“状态变化通知”而不是“事实真值”：一个 spike 只能表示某个阈值事件发生，不能代替原始命题、证据 URL、编译器版本和哈希。每个事件必须带 `event_id`、`seq`、`prev_hash`、`self_hash`、`source`、`std_version`、`compiler_version`、`policy_digest` 和 `supersedes[]` 等审计字段；神经形态的稀疏性不能成为删除审计元数据的理由。

记忆机制可以分成两层理解。第一层是可靠的软件记忆：append-only 账本保存事实，当前投影保存可查询状态，规则快照和证据哈希让历史判决可重放。它对应的是数据库和事件溯源意义上的持久记忆，不需要声称与海马体等价。第二层才是类脑启发：相似但不相同的 C++ 样例既不能全部合并，也不能只靠文本相似度召回。海马研究常用 pattern separation 与 pattern completion 描述“把相似经历分开”和“由部分线索恢复整体”的功能，相关文献把这两者视为记忆研究中的重要计算概念[11][12]。转成阙疑的工程问题，就是为每个知识区域保留最小判别特征：AST 结构、值类别、类型关系、标准版本、编译器矩阵、触发规则和异常上下文；当新样例只有部分证据时，可以检索候选历史卡，但输出必须标为“候选关联”或 `unknown`，不能把相似样例直接补全为已证实事实。这样既借鉴了“分离/补全”的功能观点，也避免把神经机制类比成语义真理。

预测编码提供另一条有用但必须谨慎的路线。其常见表述是高层产生对下层的预测，下层比较实际输入与预测并向上传递 prediction error；预测误差通常还会受 precision 或置信权重调节[5]。该理论综述使用的是“potentially unifying account”，即潜在的统一解释，而不是已确证的大脑唯一机制；重复抑制、适应和其他神经机制也可能解释部分相同现象[5]。对阙疑，可以把它转为一个普通的软件残差：基于历史事件和规则版本，系统预测下一条事件的类型、来源、字段变化或依赖影响；真实事件到达后计算预测与观测的差异。若预测的是 `CompilerObserved`，则残差可以包括“未登记的编译器版本”“标准模式突变”“诊断类别突然改变”；若预测的是账本状态转移，则残差可以包括“没有前置证据却出现 block”“一次事件影响了未在依赖闭包中的卡”“哈希链断裂”。预测器只负责提出高优先级检查，不负责改写事实；误差大意味着需要复验或转 `unknown`，不意味着输入必然错误。

“error correction”在这里也应拆成两种。哈希链校验、字段 schema 校验、依赖图环检测、编译命令复跑属于确定性纠错或故障发现，可以给出精确结果；预测残差、SNN 分类、STDP 或 anomaly score 则是启发式检测，只能给出排序和风险提示。STDP 的经典定义涉及突触改变与前后神经元 spike 时间关系，相关综述把它与学习和记忆联系起来[10]，但“STDP 适合生物学习”不等于“STDP 会学习 C++ 标准语义”。阙疑如要实验，应该先将它限制在事件优先级或缓存采样策略，而不是让其直接改写 67 条生产规则。任何模型提出的规则都必须回到最小反例、权威来源、正负夹具、跨编译器复验和人审闸门。

## 三、稀疏性与能效：从理论折中到 C++ 边缘实现

稀疏性至少有三个不同含义，不能混成一个百分比：一是神经元或节点在某一时间窗内的 active ratio；二是连接矩阵中的非零比例；三是事件流相对满采样流的压缩比例。某个系统在激活上稀疏，并不保证内存访问稀疏；某个矩阵含有大量零，也不保证 CPU 或 MCU 会跳过这些零；非结构化稀疏如果需要额外索引，可能因为 cache miss 和分支而更慢。关于生物能耗的模型研究明确提醒，减少活动神经元会降低信号成本，但若为了保持相近的表示能力而增加总神经元数，固定成本可能抵消收益；在该文给定的信号成本/固定成本比和组合表示假设下，最优 active ratio 约为 30%–40%，不是“越稀疏越好”或所有硬件通用的最佳比例[6]。这条限定对阙疑非常重要：任何“事件越少，能耗就越低”的句子，都应改成“在测量边界、索引开销、固定成本和准确率约束同时固定时，较低事件率可能降低能耗”。

对阙疑的第一条具体启示是把“稀疏事件账本”设计成分层索引，而不是把完整账本变成黑箱神经网络。原始 `DecisionEvent` 仍然 append-only、可验证、可重放；另外维护按 `card_id`、`rule_id`、`std_version`、`compiler_family`、`event_type` 和时间桶建立的稀疏倒排索引。新事件只触发受影响的索引更新，查询某张卡时只读取其依赖闭包和相关事件，避免扫描全部 452 条历史记录。对于嵌入式 C++，可以使用定长结构、整数时间戳、紧凑枚举和预分配环形队列，避免在事件热路径中频繁 `new/delete`；但哈希、签名、证据 URL 等完整字段仍可保存在慢速存储，热路径只保存摘要和偏移。这样得到的是“冷热分层的事件驱动存储”，不是把审计信息牺牲掉换来的虚假低功耗。

对异常检测，预测误差最适合作为独立的早期预警器。系统可以为每个事件类型维护条件频率和时间间隔的基线，例如某个编译器版本下 `CompilerObserved` 与 `RuleDecision` 的正常先后关系、某类 C++ 语义卡的 unknown 比例、某个规则在不同标准模式下的命中分布。新事件到达后，先做确定性检查，再计算轻量残差：字段不在 schema、顺序不符合依赖、事件间隔异常、规则命中位图突变、跨编译器结果不一致。异常分数只用于选择“立即复跑”“追加证据”“进入人审队列”中的一种，不直接产生 fail。对于未知分布、冷启动、样本不足和模型没有校准的情况，输出 `unknown`，而不是把低分误认为正常。EvAn 论文把事件数据用于异常检测，说明“事件流+异常判别”是已有研究问题；但阙疑不能把该论文的存在当成自己的效果证明，必须在自己的 C++ 事件流上报告误报、漏报、检测延迟和能耗[9]。

对边缘嵌入式场景，真正值得做的是端到端测量：传感器或文件输入、事件编码、队列、规则筛选、候选预测、哈希计算、存储写入、输出与休眠都纳入功耗边界。不能只测一个 SNN 核心的突触操作。BrainScaleS-2 的混合模拟/数字结构说明“加速动力学”和“系统端到端吞吐”不是同一个数字[2][3]；Lava 的官方文档也显示，同一个 Process 可以用不同 ProcessModel 在 CPU、GPU 或神经形态后端执行，而且 Loihi 专用低层组件并非全部开源[8]。阙疑若没有 Loihi 或事件相机，不应为了“类脑”强行购买或模拟昂贵硬件；可以先在 C++ 中实现三种基线：全量扫描、按事件增量更新、按事件增量更新加预测残差，使用相同输入和判定逻辑比较 wall-clock、峰值内存、写放大、事件数、每条事件能耗和检出指标。

NeuroBench 这类基准框架的价值正在于把算法正确性与系统指标放在一起，而不是只报一个准确率或一个 TOPS/W[14]。阙疑应采用同样的纪律，至少固定：数据集版本、事件切分、编译器版本、优化级别、CPU 频率或 MCU 时钟、存储介质、是否计入预处理、是否计入模型加载、热启动/冷启动、重复次数和统计区间。若用 SNN 或脉冲预测器，还要报告时间步、编码方式、spike count、神经元更新次数、路由/内存流量和训练成本。低能耗如果以漏掉真实错误为代价，没有工程价值；高召回如果让嵌入式设备被大量误报唤醒，也不能称为能效提升。对当前阙疑的 30 条 holdout、17 条真错和外部 corpus 40 条的口径问题，更不能在小样本上用一次“类脑模型”结果宣称泛化改善。

## 四、面向阙疑的架构方案：事件账本、异常检测和验证闸门如何落地

建议把实现分成四个互相隔离的层。第一层是事实层：接收编译器输出、标准来源、代码夹具、人工判决和工具运行结果，形成 append-only `DecisionEvent v2`，不接受预测器直接写入生产结论。第二层是事件层：把新建卡、证据补充、规则发布、编译器矩阵更新、回放结束、哈希校验失败等变化编码为有限事件类型，维护依赖闭包和稀疏索引。第三层是预测/异常层：根据历史窗口产生下一事件类型、字段变化和状态转移预测，计算残差并生成 `AnomalySignal`，其中包含 `model_version`、`features_digest`、`expected`、`observed`、`score`、`threshold` 和 `reason`。第四层是决策层：确定性保护器、规则引擎和人审决定 `pass`、`fail`、`pass_with_exception` 或 `unknown`；预测器只能改变检查顺序和资源分配，不能绕过证据闸门。

具体的事件流水线可以是：输入边界先做 schema 和哈希检查；通过后写入原始事件；根据 `card_id` 和依赖图找到受影响节点；只重算这些节点的规则与编译矩阵；把新结果作为 superseding event 追加，不修改旧事件；同时更新预测状态和异常分数；若分数超过阈值，触发全量复核、跨编译器复跑或人工队列。对 C++ 代码，事件的最小语义摘要可以包括 token/AST 指纹、类型关系、值类别、生命周期标签、标准模式、编译器/标准库版本、命令行摘要和 sanitizer 状态。摘要用于检索和预测，原始源码与完整命令仍需按权限保留。这里的“记忆”是可回放的版本化状态，“预测”是候选检查顺序，“误差”是可解释的观测差异，三者都不能取代证据。

异常检测应该至少有三条并行路径。其一是结构异常：`prev_hash` 不匹配、`seq` 跳跃、重复 `event_id`、`supersedes` 指向不存在事件、依赖图出现非平凡 SCC，这些直接是确定性 fail 或 quarantine。其二是统计异常：某规则在某编译器/标准版本分层中的命中率、unknown 率或运行时间突然偏移，这些只进入 drift event；不能把分布漂移直接当语义错误。其三是语义异常：预测器发现新事件与历史模式不一致，要求增加证据、生成最小复现或交叉编译；如果无法排除环境缺件、未定义行为、编译器 bug 或夹具错误，保持 `unknown`。这种三路结构能避免把神经形态模型的一个分数混成所有错误类型，也能让审计者知道“异常发现”与“事实判决”之间隔了哪些闸门。

如果未来确实要试验 SNN，应先选窄任务：例如对按时间窗口聚合的事件序列预测“下一类账本事件”或“是否需要重新编译”，而不是直接预测 C++ 命题真伪。模型输出应与规则引擎并行运行，实验组和基线组使用同一事件流、同一规则快照和同一 holdout 隔离。指标包括：异常检测 AUROC/PR-AUC 只是辅助，核心必须是真实错误检出率、误报率、检测提前量、unknown 率、规则保持率、每条事件 CPU 周期、内存占用和端到端能耗。对新模型的任何收益，都要做删除模型、打乱时间、稀疏阈值变化和跨编译器的消融，检查收益是不是来自数据泄漏、样本顺序或更宽松的判定阈值。

对阙疑最现实的三条行动是：第一，先实现 `event_audit_harness`，把 452 条历史事件、37 张实卡、规则快照、证据哈希和编译矩阵生成只读回放清单，比较全量扫描与增量事件更新，验收标准是旧事件不变、哈希链可复算、回放结果逐项一致。第二，实现独立的 `drift_detector`，只读取事件摘要，按标准版本、编译器家族、规则和时间窗输出 unknown/命中/延迟漂移，并把每个异常映射到可解释原因；不允许模型直接写 67 条规则。第三，在一个真实嵌入式目标上做端到端基准，至少比较 C++ 全量扫描、稀疏事件索引、事件索引加轻量预测三种方案，报告准确性、误报、漏报、延迟、峰值内存、写放大、CPU 周期和功耗，而不是只报告 spike 数或理论 TOPS/W。若这三步没有测出稳定收益，就应诚实得出“类脑启发暂不值得增加复杂度”的结论。

## 五、三条具体行动、诚实盲区与来源

第一条具体行动是把“事件驱动”变成可审计的 C++ 基准：新增事件类型与 schema，保留原始 `DecisionEvent` 的 append-only 语义，建立按卡片、规则、标准版本和编译器版本的稀疏索引；用固定回放清单测量全量扫描和增量更新在同一判决集上的 CPU 周期、内存、延迟与能耗。第二条具体行动是实现预测误差型异常检测，但把它严格放在证据闸门之前：预测下一事件或下一状态转移，异常只触发复验、人审或 `unknown`，不直接把 `pass` 改成 `fail`，更不自动发布规则。第三条具体行动是建立边缘设备的端到端能效报告：包含输入、编码、队列、哈希、规则、存储、输出和休眠，分开报告事件率、spike/事件数量、固定开销和数据搬运；使用 NeuroBench 式的算法正确性与系统指标并列报告，避免把单芯片宣传数字误当成通用结论。

诚实盲区如下。第一，TrueNorth、Loihi 2 和 BrainScaleS-2 的数字来自厂商页面或论文的特定条件，不能直接比较；“65 mW”“约1000倍”“up to 10x”都不是阙疑实测。第二，predictive coding 是潜在的统一框架，不是已经证实的大脑唯一机制；本文把预测误差映射到软件残差，是工程类比，不是神经生理学结论。第三，30%–40% active ratio 来自特定能耗与组合表示模型，不能当作所有 SNN、CPU、MCU 或稀疏矩阵的最佳比例。第四，事件驱动只有在事件率低、索引与队列开销可控、硬件支持稀疏访问时才可能节能；密集输入、频繁写盘和不规则内存访问可能让它更慢更耗电。第五，EvAn、STDP、事件相机和 SNN 预测编码文献能够证明研究脉络存在，不能证明阙疑在 C++ 知识验证上有效。第六，当前 holdout 样本只有 30 条且真错 17 条，外部 corpus 的既有算术口径还不自洽；在修复数据协议、冻结 holdout、定义功耗边界之前，不应声称类脑方案提高了泛化。最重要的边界是：脑科学启发可以帮助阙疑减少无效重算、优先检查意外变化、保留上下文状态，但最终可信度仍来自版本化证据、确定性校验、可回放账本和明确的 `unknown`，而不是“更像大脑”本身。
