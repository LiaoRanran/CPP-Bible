# 方向 46：形式逻辑在验证中的应用——命题/一阶逻辑、Horn 子句、SAT/SMT 的真实边界

## 核心结论

1. **命题 SAT 在工业规模上"可解"，但可解的范围有硬边界，且这个边界是公开可量化的。** SAT Competition 2024 主赛道规则逐字：*"We will use 300-600 benchmark problems, the time limit will be 5000 seconds. Solvers in all tracks will be ranked based on the PAR-2 score, which is the sum of the runtime plus twice the timeout for unsolved instances. The solvers will be allowed to use up to 128GB of RAM."* 并且 **所有主赛道求解器必须同时为 SAT 和 UNSAT 两种情形提供证书**（certificate），UNSAT 证书需要独立的 proof checker 校验。**对阙疑的含义**：一个单人项目不可能自己写 SAT 求解器，也不可能保证在 5000 秒 / 128GB 内解完任意编码后的公式——所以"把 67 条规则全编码成 SAT 然后求解"这个方案在工程上是不成立的。

2. **一阶逻辑不可判定，工程上真正被用的是它的可判定片段 + 固定点求解，即 CHC（Constrained Horn Clauses）。** 2024 年 CONCUR 的主旨报告逐字：*"we focus on a fragment of FOL called Constrained Horn Clauses (CHC) and the CHC solver SPACER"*（Dagstuhl / LIPIcs CONCUR 2024, DOI 10.4230/LIPIcs.CONCUR.2024.1）。CHC 的表达力正好对应"程序不变量的存在性"：每个 Horn 子句形如 $\vec x.\ \varphi(\vec x) \wedge \psi_1 \wedge \dots \Rightarrow \psi$，求解即求最小不动点（与方向 48 的不动点迭代是同一件事）。**这是"把知识校验写成逻辑"时唯一有工业工具支撑的路线**：Z3 的 Spacer 引擎、cvc5 的 CHC 支持都直接吃 `.smt2` 格式的 CHC 文件。

3. **SMT 不是"一个求解器"，而是按理论分工的一组求解器，选错理论等于选错工具。** SMT-COMP 2024 Single Query Track 的逐 logic 冠军（我逐条读取了官方结果页）：**cvc5** 拿下 Arith / Bitvec（顺序性能）/ Equality / Equality_LinearArith / Equality_MachineArith / Equality_NonLinearArith 的顺序与并行性能第一；**Bitwuzla** 拿下 FPArith 全部五项与 QF_Bitvec / QF_FPArith / QF_Equality_Bitvec；**Z3-Noodler** 拿下 QF_Strings 全部五项；**Z3-alpha** 拿下 QF_NonLinearIntArith 与 QF_NonLinearRealArith 的顺序/并行/SAT 第一（UNSAT 第一是 cvc5）；**Yices2** 拿下 QF_Equality 全部五项。**没有全能冠军**——这对阙疑很关键：如果知识断言涉及字符串/正则（例如 C++ 标识符、模板名），要换 Z3-Noodler 或 cvc5，而不是继续用默认的 Z3。

### 三、CHC：程序验证与逻辑之间的桥

- **定义**：CHC 是 FOL 的一个片段，子句形式为 $\forall \vec x.\ (B_1 \wedge \dots \wedge B_n \Rightarrow H)$，其中各 $B_i$ 与 $H$ 是理论原子公式；**恰好有一个正文字**（Horn 性质）。求解 CHC 的语义就是求最小模型（不动点）。
- **对应关系**：命令式程序的验证问题（部分正确性、不变量存在性）可以**机械地**翻译成 CHC。参考文献：*Program Verification with Constrained Horn Clauses (Invited Paper)*，Springer LNCS（2022-08，DOI 10.1007/978-3-031-13185-1_2）——摘要逐字：*"we give a brief overview of how CHCs capture verification problems for sequential imperative programs"*。
- **工具**：**SPACER** 是 Z3 里的 CHC 引擎；2026-07 的一份 CEUR 摘要逐字：*"Today, many program analysis techniques formulate their verification tasks as logical constraints and rely on SAT or [SMT]"*（CEUR-WS Vol-4228）。
- **对阙疑的用途**：67 条规则中的**结构性不变量**（哈希链的前驱一致性、账本单调性、判决状态转移的合法性）天然是 Horn 形式，可以直接用 Z3 的 Spacer 检查"是否存在违反不变量的可达状态"。这是**可行且低成本**的一小块，不是全部。

### 四、C/C++ 上的真实工具与规模：CBMC 与 SV-COMP

**CBMC（C Bounded Model Checker）**，官网 `cprover.org/cbmc/`，GitHub `github.com/diffblue/cbmc`，当前发布版 **6.8.0**（Windows 安装包 `cbmc-6.8.0-win64.msi`；Ubuntu 26.04 / Debian trixie 上 `apt-get install cbmc` 给 **6.6.0**，Ubuntu 25.04 给 **6.4.1**，Fedora 44 给 **6.8.0**；Ubuntu 20/22.04 仓库里的版本是 **5.12**，官网称其 *"more than a decade old"*）。逐字能力声明：

> *"CBMC verifies memory safety (which includes array bounds checks and checks for the safe use of pointers), checks for various further variants of undefined behavior, and user-specified assertions… The verification is performed by unwinding the loops in the program and passing the resulting equation to a decision procedure."*
> *"CBMC comes with a built-in solver for bit-vector formulas that is based on MiniSat. As an alternative, CBMC has featured support for external SMT solvers since version 3.3. The solvers we recommend are (in no particular order) Boolector, CVC5 and Z3."*

**版本 6 的四个破坏性默认变更（必须知道，否则复现实验会失败）**：

1. 未定义行为检查**默认开启**（用 `--no-standard-checks` 恢复旧默认）；
2. `malloc` 默认**可能返回 NULL**（用 `--no-malloc-may-fail` 恢复）；
3. **调用无函数体的函数现在触发验证错误**；
4. 默认 verbosity 变为 **6**（`--verbosity 8` 恢复）。

**"unwinding the loops" 是关键限制**：CBMC 是**有界**模型检查，循环必须展开到某个深度（`--unwind`），因此它证明的是"在 k 步内无缺陷"，不是全称性质。**这一点必须写进阙疑论文的任何"我们用形式化方法"的句子旁边**，否则就是过度声明。

**SV-COMP（软件验证竞赛）规模**：SV-COMP 2024（第 13 届，TACAS 2024，卢森堡）的 TACAS 报告逐字：*"The number of verification tasks in SV-COMP 2024 was significantly increased to 30 300 in the C category."* 官方类别结构（`sv-comp.sosy-lab.org/2024/benchmarks.php`）显示 9 个大类：ReachSafety（含 14–15 个子类）、MemSafety（6 个子类）、ConcurrencySafety（4）、NoOverflows（2）、Termination（4）、SoftwareSystems（11–12）、C-Overall、C-Falsification、Java-Overall（1 个子类 `java/ReachSafety-Java`）。SV-COMP 2025 是第 14 届（TACAS 2025，加拿大 Hamilton，报告 DOI 10.1007/978-3-031-90660-2_9），赞助方新增 **Huawei – Dresden Research Center**。

⚠️ **我未能确认 SV-COMP 2024 有独立的"C++"类别**：类别前缀只有 `c/` 与 `java/`，`c/` 类别实际覆盖 C（以及部分 C++ 任务，具体口径未核实）。**不要**在论文里写"SV-COMP 有 C++ 赛道"。

### 五、把阙疑的 67 条规则变成逻辑公式：可行性与代价（核心分析）

**先说结论**：**"67 条规则全部形式化"是不可行目标；但其中一小部分（估计 10–20 条）是可形式化且值得形式化的。**

| 规则类型 | 形式化的可行性 | 需要的理论 | 代价估计 |
|---|---|---|---|
| 账本结构不变量（前驱哈希一致、序号单调、checkpoint 覆盖） | **可行** | 位向量 + 未解释函数（UF）；哈希函数视为 UF 即可，**不必**展开 SHA-256 | 低。CHC 编码数十行 `.smt2` |
| 四态判决的合法转移（不能从 verified 直接跳 draft 等） | **可行** | 有限状态 / 命题逻辑 | 低。可枚举状态转移表并检查不可达状态 |
| 依赖闭包与环检测（"哪些卡依赖哪些卡"） | **可行** | 图论算法，不需要 SMT（见方向 49） | 低。用 Tarjan SCC，O(V+E) |
| C++ 语法/语义规则（模板实例化、ODR、未定义行为） | **不可行（完整版）** | 需要 C++ 形式语义，而标准无形式语义 | **极高**（见方向 54） |
| 67 条规则的"全量互不矛盾" | **理论可判定但规模爆炸** | 命题逻辑，2^67 不可枚举；需 SAT，但编码本身要先建立 | 高。且**收益不明**：规则集合的矛盾通常靠人工审查发现 |
| 规则对真实 C++ 代码的"是否正确触发" | **不可行** | 等价于 C++ 语义 + 规则语义的联合判定 | **不可行**（见方向 55 的 Rice 定理） |

**成本的真实参照**：SAT Competition 的单实例时限是 5000 秒；CBMC 是**有界**验证；SV-COMP 的 30,300 个任务每个都有精确的规范文件（`.yml` + spec）。**一个单人项目要把 67 条规则写成 30,300 个任务那样的规格化基准，工作量量级是"另一个人年"**，而收益只是"证明我们的规则集不矛盾"——这在 E&D track 里不是加分项。**正确的做法是"选 10 条左右的不变量做形式化，作为可审计性的证据"，而不是"全量形式化"。**

## 对阙疑的 3 条具体行动

1. **新建 `formal/ledger_invariants.smt2`（SMT-LIB 2 格式），用 Z3 的 CHC 引擎验证 4 条账本不变量，时间点 2027-04 前。** 具体 4 条：(a) `entry[i].prev_hash = H(entry[i-1])`；(b) `seq` 严格递增且无洞；(c) Merkle checkpoint 的根等于叶子的 Merkle 折叠；(d) 判决状态转移只允许在预定义转移表内。**关键实现细节**：把哈希函数声明为未解释函数 `(declare-fun H (...) ...)`，**不要**尝试编码 SHA-256——这是让问题保持可判定的唯一方法。产出：一份 `.smt2` 文件 + 一份 `formal/README.md` 记录 Z3 版本号与命令（`z3 -smt2 ledger_invariants.smt2`），并把验证脚本挂到 CI 的一个可选 job 上。

2. **在论文 Evaluation 一节增加"我们能形式化什么 / 不能形式化什么"的小表，时间点 2027-06 前。** 表格三列：性质 / 形式化工具与版本 / 明确不能覆盖的部分。必须包含这三行明示的**边界**：(a) CBMC 6.8.0 是有界模型检查，循环展开深度 k 之外的性质**未被证明**；(b) 67 条规则中涉及 C++ 语义的规则**不形式化**，理由是 C++ 标准无形式语义（引方向 54 的 Cerberus/KCC 证据）；(c) 全量规则集的一致性**不作形式化声明**。**这一节是本文与"又一个 LLM 评测"的关键区别之一**——E&D track 的 CFP 明确欢迎 *"negative results"* 与 *"critical analysis"*。

3. **如果确实要引入 SMT，先按断言的理论选工具，并在论文中写清选型依据，时间点 2027-05 前。** 依据直接用 SMT-COMP 2024 的逐 logic 冠军表：若断言含**字符串/正则**（C++ 标识符、模板名匹配）→ **Z3-Noodler** 或 cvc5，不要用默认 Z3；若断言是**位向量/浮点**（数值溢出、位模式）→ **Bitwuzla**；若断言是**线性整数算术** → OpenSMT / cvc5；若断言是**非线性算术** → Z3-alpha / cvc5。**禁止**在论文里写"我们使用 SMT 求解器 Z3"这种无差别表述——那是没读过 SMT-COMP 结果的人才会写的。
