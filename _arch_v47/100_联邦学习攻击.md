# 方向 100：联邦学习攻击（Federated Learning Attacks）

## 核心结论

联邦学习（federated learning，FL）不是“把数据留在本地，所以天然安全”，而是把原来集中式训练中的单一数据入口，改造成“客户端、协调服务器、更新传输、聚合器、身份系统、模型发布和审计链”共同组成的分布式攻击面。McMahan 等最初把 FL 定义为：多个参与者保留本地训练数据，只上传本地计算出的模型更新，由中心服务器聚合；FedAvg 在五种模型架构、四个数据集上评估，并报告相对于同步 SGD 可减少 10–100 倍通信轮数。它解决的是数据不必集中搬运以及通信效率问题，不是正确性、机密性、身份真实性或抗投毒问题。Kairouz 等综述也把 FL 明确描述为“中心服务器编排、客户端数据分散”的设置，因此“没有原始数据离开客户端”不能被翻译成“没有信息离开客户端”。

对未来“多方贡献 C++ 知识卡/规则”的设想，第一条判断必须是：**知识卡和规则本身不是梯度，也不是天然可平均的神经网络参数。** 如果参与方提交的是 `ATOM-*.md`、标准条款、编译器实测证据、规则 JSON、判决枚举或带来源哈希的账本事件，最自然的协议是签名提交、证据分级、人工评审、append-only 账本、Merkle checkpoint 和独立 replay，而不是 FL。把这些离散且可审计的事实强行编码成 embedding、分类器权重或规则权重，才会产生真正的联邦训练问题；同时也会把“哪个参与方贡献了哪条事实、为什么该事实被接受”的可追责性，换成“某个数值更新改变了全局模型”。这不是免费升级，而是从内容治理问题转成分布式机器学习安全问题。

因此，**阙疑当前单人、中心化、37 张实卡 / 67 条规则 / 9 个保护器 / 452 条账本 / 3826 行内核的项目，不应为了热门而引入 FL。** 当前没有多家独立数据拥有者，也没有需要“数据不能互相分享”的真实组织边界；知识卡数量很小，单人可以直接审阅、签名和复算；中心化版本反而能保留来源、版本、审查轨迹和失败后的回滚路径。引入 FL 后，阙疑必须额外维护客户端身份、轮次调度、更新格式、密钥生命周期、掉线恢复、secure aggregation、DP 预算、鲁棒聚合、Sybil 防护、后门评测和跨参与方争议处理。若没有相应的隐私需求和独立参与方，这些成本不会产生科学增益，只会扩大信任边界，并让“可复算的 C++ 知识验证器”变成一个没有必要的黑盒训练服务。

本方向的核心判断可压缩成三句：第一，FL 降低了原始数据集中化风险，但更新本身可能泄露数据；第二，secure aggregation 隐藏单个更新，不保证聚合结果正确，甚至可能削弱服务器发现投毒的能力；第三，DP 限制单个用户对输出的影响，不保证 C++ 事实为真，也不自动解决 Sybil、后门、错误规则或恶意服务器。因此，只有当未来出现“至少多个彼此独立、不能直接交换原始 C++ 语料的真实参与方”，且中心化方案在隐私/合规上不可接受时，FL 才值得作为待验证的研究选项，而不是默认架构。

## 精确数字与案例

1. **gradient leakage：更新不是无害摘要。** Zhu、Liu、Han 的 *Deep Leakage from Gradients* 在计算机视觉和自然语言任务上报告，攻击可以从公开梯度恢复训练数据；摘要给出的结果是图像达到 pixel-wise accurate、文本达到 token-wise matching，并把梯度裁剪列为讨论过的有效防护之一。Geiping 等的 *Inverting Gradients* 进一步说明，在已训练的深度网络上也可以从参数梯度高保真重构图像；论文还证明，全连接层输入可以在解析意义上从某个参数梯度恢复，并明确指出，仅仅对多次迭代或多张图像做平均，并不能自动提供隐私保护。NIST 在 2024 年的官方文章据此提醒：即使 FL 使用了模型更新而不是原始训练数据，更新仍可能携带出乎意料的大量训练信息。

   对 C++ 知识卡而言，泄露对象不一定是图片。若客户端本地训练的是 C++ 代码片段分类器、UB/非 UB 判别器、标准版本识别器或规则权重模型，更新可能泄露：某家公司是否拥有某段专有代码、某个编译器版本的缺陷样例是否存在、某一硬件平台的内部测试分布、某条稀有规则是否命中过本地数据。对于只有一张卡或很小本地 batch 的客户端，单次更新的信号更集中；对于多轮重复训练，还可能通过差分比较推断某条卡何时加入或被删除。这里不能把图像重构成功率直接外推成“C++ 文本一定能被还原”，但应把“更新会泄露成员关系、属性和部分内容”列为可测试风险，而不是把 FL 当作隐私结论。

2. **model poisoning 比只改本地训练数据更直接。** Bagdasaryan 等的 *How To Backdoor Federated Learning* 指出，聚合器为了保护参与者本地模型的机密性，按设计看不到更新是如何生成的；攻击者可以用 model replacement 直接把恶意模型替换进联合模型，并植入干净样本上表现正常、触发条件下输出攻击者指定结果的后门。论文还指出，secure aggregation 会让聚合器不能检查单个参与者更新的异常；即使开放异常检测，攻击者也可以在训练损失中加入规避检测的约束与缩放目标。

   翻译到阙疑，后门触发器不必是图片里的像素图案，可以是“只在 C++17 + `-O2` + 某标准库实现时触发”“只涉及并发、协程、ABI 或未定义行为时触发”“只在某个规则组合和特定编译器输出上触发”。恶意客户端可能让普通题目仍然判为 `verified`，但对一个稀有的架构、生命周期、内存序或异常安全问题输出错误判决；也可能让一个 `block` 规则在触发词组合下退化为 `warn`。这比粗暴提交一张明显错误的卡更危险，因为全局平均准确率、普通 holdout 和常规规则计数可能都不变。

3. **Sybil 把“参与方数量”变成可伪造的权重。** Fung、Yoon、Beschastnikh 的 *Mitigating Sybils in Federated Learning Poisoning* 先评估了 Sybil 对 FL 投毒的放大作用，再提出 FoolsGold，通过跨轮客户端更新的相似性和多样性识别协同 Sybil。论文摘要明确说，Sybil 会显著加重 model poisoning；FoolsGold 不预设攻击者数量上限，也不需要学习过程之外的辅助信息，但其结论仍是针对特定攻击、数据分布和实验设置的防御结果，不是身份真实性的证明。

   在未来 C++ 卡片网络中，Sybil 可以表现为一个人注册十个“专家”、十个客户端、十个组织名，分别提交互相复制或方向一致的规则更新；如果服务器按客户端数平均，就能把一方意见伪装成多数。如果服务器又使用 secure aggregation，服务器可能只看到一团总和，无法把相似更新追溯到同一操作者。FoolsGold 一类相似度防御也会遇到真实非 IID 问题：不同参与方可能天然专注于嵌入式、并发、模板、标准库或编译器实现，合法的主题聚类并不等于 Sybil。因此，强身份、组织级额度、签名凭证、贡献历史和人工争议处理不能由相似度算法替代。

4. **secure aggregation 解决可见性，不解决正确性。** Bonawitz 等的 *Practical Secure Aggregation* 给出的是让服务器安全计算高维用户向量之和而不学习单个贡献的协议，并证明在诚实但好奇和恶意设置下，即使任意选定子集的用户随时掉线，也能维持协议安全；论文给出 16-bit 输入的通信膨胀示例：2^10 个用户、2^20 维向量约为 1.73 倍，2^14 个用户、2^24 维向量约为 1.98 倍。这个结果很重要，但它的安全目标是聚合隐私和掉线鲁棒性，不是证明每个更新来自正确训练数据，也不是证明聚合语义符合 C++ 规则。

   secure aggregation 与阙疑的冲突在于：阙疑最看重 provenance、review trace、evidence grade、规则 ID、判决理由和可回放性；而纯粹隐藏单个更新，会让服务器难以回答“哪一方改变了哪条规则”“哪一张卡造成了 verdict flip”“某个贡献是否由同一主体重复提交”。如果为了查毒而保留逐客户端可见性，则隐私收益下降；如果完全隐藏，就必须把检测、证明和争议处理前移到客户端，要求客户端生成可验证承诺、零知识证明或可审计的局部证据，这已经是新的密码协议工程。

5. **DP 有明确的保护对象，但不是事实正确性机制。** McMahan 等的 *Learning Differentially Private Recurrent Language Models* 把 user-level DP 加到 federated averaging 中，并报告在用户数足够大的数据集上，私有 LSTM 与未加噪模型在定性和定量上相近；其摘要也明确把“足够大的用户规模”列为条件，并指出代价更多体现为计算而不是效用。这个结论不能直接移植到阙疑：当前只有一个维护者，未来若只有少量组织，用户级噪声的统计与匿名性基础都不成立；而将离散的 `block/warn/advice` 规则或 37 张卡映射成连续参数后加噪，可能让确定性判决、边界条件和复算结果漂移。

   DP 的保证是限制单个用户或样本对输出分布的影响，目标是降低成员推理等隐私风险；它不判断一条 C++ 标准解释是否正确，不阻止恶意客户端故意提交一个在裁剪范围内的错误更新，也不阻止攻击者创建大量身份。更糟的是，噪声会掩盖小规模但真实的异常，导致审计者无法区分“正常 DP 噪声”“非 IID 差异”和“规则投毒”。所以若将来采用 DP，必须预先公布保护单位、采样机制、裁剪界、噪声机制、总隐私预算和输出版本，且把最终模型的语义回归、反事实测试和独立 replay 作为另外的完整性防线。

6. **鲁棒聚合不是万能的 C++ 事实审查器。** Blanchard 等的 Krum 论文指出，线性组合型更新规则甚至不能容忍单个 Byzantine 故障，并提出 Krum；其摘要给出的 d 维问题时间复杂度为 `O(n²·(d+log n))`。Pillutla、Kakade、Harchaoui 的几何中位数聚合工作则研究一部分客户端发送损坏更新的情形，给出对最小二乘加性模型的收敛结果，并在视觉和 NLP 任务上实验。它们保护的是数值优化在特定假设下的鲁棒性，不能证明“数值上接近多数”的 C++ 规则就是语义上正确的规则。非 IID 数据又会让合法的少数专业知识看起来像离群点，过度鲁棒化可能删除真正有价值的 ABI、嵌入式或编译器边界案例。

## 对阙疑的3条具体行动与否定条件

1. **先冻结 FL 引入门槛，只做威胁模型和离线仿真，不做生产协议。** 在 `data/` 或源码中不新增联邦服务；本文件只写入 `_arch_v47/`，与 v47 的“零污染”要求一致。建立一个离线模拟器：参与方 A/B/C 各自持有互不共享的 C++ 卡片子集，服务器只接收抽象的数值更新或规则 delta；分别模拟 honest-but-curious 服务器、恶意客户端、Sybil 客户端、串通服务器+客户端、掉线客户端和普通网络窃听者。资产固定为五类：卡片语义正确性、规则严重级别、452 条账本与 Merkle 根、参与者隐私、服务可用性。攻击成功条件预注册为：在固定 holdout 上至少造成一次目标 verdict flip；把一个 `block` 规则降为 `warn/advice`；让未授权主体推断某条卡是否在某参与方本地集；或让一个客户端更新无法被追责、回滚和重放。当前 holdout 只有 30 条、真错 17 条、检出率 66.7%，所以每次试验必须报告精确计数和置信区间，不能把一次翻转写成普适成功率。

2. **如果未来真的出现多方贡献，优先设计“可验证贡献协议”，而不是直接 FedAvg。** 每个卡片/规则贡献必须携带 `contributor_key_id`、组织级签名、内容 `sha256`、来源 URL、抓取时间、证据等级、review trace、适用的 C++ 标准/编译器/平台、测试命令和父版本哈希；客户端先在本地运行编译、反例、交叉引用和四态判决检查，再提交承诺。服务器只接受 schema 合法、签名有效、来源可追溯、能被独立 replay 的贡献。若实际对象仍是离散卡片，就使用签名事件合并和人工裁决；只有当各方确实训练同一个连续参数模型时，才评估 secure aggregation + 每客户端裁剪 + user-level DP + 鲁棒聚合的组合。任何 secure aggregation 方案都必须同时提供聚合结果承诺、参与者集合承诺、掉线清单、版本号、可回滚 checkpoint 和争议期，否则“保密的错误总和”不能进入阙疑账本。

3. **把攻击测试变成发布门禁，并明确否定条件。** 每一轮候选模型必须跑三组数据：干净 C++ holdout、针对标准版本/编译器/平台的触发器集、只包含稀有规则组合的反事实集；报告 clean accuracy、目标后门成功率、规则级 verdict flip、客户端影响分布、Sybil 权重、重构/成员推断指标、DP 预算和 secure aggregation 的最小参与数。采用 20% 权重的 Sybil 注入、单客户端 model replacement、跨轮差分推断、恶意掉线和相似度规避作为预注册压力档位；这些是测试条件，不是现实攻击概率。出现下列任一条件就否定 FL，不以“以后再补防御”为理由继续：①仍只有单人或一个中心化维护组织；②没有至少三个彼此独立且确有原始数据不能共享需求的参与方；③每轮有效参与数小于预先规定的匿名阈值，或身份系统不能阻止一人注册多个客户端；④无法同时保留来源证明、版本绑定、独立 replay、回滚和争议处理；⑤没有固定 DP 保护单位/预算，或不能测量噪声对四态判决的影响；⑥协议只能隐藏更新却不能证明聚合结果和客户端资格；⑦中心化签名卡片协议已经能以更低成本满足隐私、合规和协作需求；⑧新增 FL 的主要理由只是“论文热门”“方向看起来前沿”而不是一个可量化、无法由中心化方案解决的约束。以上是阙疑的工程否定条件，不宣称它们是所有 FL 系统的普适数学定理。

## 盲区（诚实标注）

第一，现有 gradient leakage、model replacement、Sybil 和 DP 文献大多面向图像、语言模型或连续参数优化；我没有找到经过一手实验证明的“C++ 知识卡/规则联邦学习攻击”数据集。因此，本文把图像/NLP 论文映射到 C++ 场景时，明确标为威胁推演而不是实测结论。未来必须用真实 C++ 标准文本、代码片段、编译器诊断和规则账本建立专门基线。

第二，DLG 与 Inverting Gradients 的强结果不能无条件外推到文本卡片、离散规则、稀疏更新或非神经模型；重构成功率受模型结构、批大小、局部步数、梯度裁剪、量化、初始化和攻击者可见信息影响。相反，不能因为 C++ 卡片不是图像，就声称泄露不存在；成员推断、属性推断、差分比较和来源元数据泄露仍可能成立。

第三，secure aggregation 的具体通信数字来自 Bonawitz 论文的协议、向量维度、参与规模和 16-bit 输入条件，不能直接当成阙疑未来实现的性能预算；它也不覆盖客户端端点被攻破、恶意客户端提交错误更新或全局模型输出泄露。Krum、几何中位数和 FoolsGold 的实验防御效果同样依赖攻击比例、数据分布和参数设置，不能写成“用了就安全”。

第四，DP 的“几乎不损失效用”来自足够大的用户级语言模型训练条件，不适用于当前 1 个维护者、37 张实卡、67 条规则的小样本离散验证器。本文没有给出适合 C++ 规则系统的 epsilon、delta、裁剪界或噪声强度，也不应伪造一个数字；未来只有在模型对象、保护单位和发布次数明确后，才能做隐私会计。

第五，本文的攻击者模型没有覆盖密码算法被破坏、所有参与方同时沦陷、硬件可信执行环境遭到物理入侵或国家级网络攻击；也没有把普通网络 DoS 当作 FL 特有结论。当前阙疑的中心化账本、独立对账器、证据 provenance 和 append-only 设计已经提供了比“只上传一个不可解释更新”更强的可追责基础；是否未来需要联邦协议，必须由真实数据主权约束和可复现实验决定，而不能由术语热度决定。
