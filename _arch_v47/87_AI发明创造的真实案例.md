# 方向 87：AI 发明创造的真实案例

## 一、先把“发明”拆成发现、优化、证明与归属
“AI 发明了某物”不是一个可以直接接受的科学结论，至少要拆成四个彼此独立的问题。第一是**发现**：系统是否提出了人类此前没有记录、且后来能够被独立复算的结构、算法、材料或蛋白设计；第二是**优化**：系统是否只是在既定目标、既定表示和既定测试集内找到更快、更小、更稳定或更高亲和力的方案；第三是**证明**：候选是否具有形式证明、可执行检查、物理计算、湿实验或独立复现，而不是只有模型分数和宣传口号；第四是**归属**：应该把功劳归给模型、搜索框架、数据集、验证器、提出问题的人、把结果转成可部署实现的人，还是共同归属。四者不能互相替代：一个算法可能是机器搜索出来的，但其正确性由张量恒等式或测试程序证明；一个蛋白可能是模型生成的，但是否真正具有结合能力要靠实验；一个材料候选可能是模型预测的，但“预测稳定”不等于已经合成；一个 C++ 优化可能确实更快，但“更快”不等于标准语义更正确。本文在 2026-09-29 以公开论文、机构原文、代码仓库和会议页面交叉核验，实际执行 **24 次 WebSearch、14 次 WebFetch**；对无法由一手页面确认的数字不把它写成事实。也因此，本文不接受“AI 像人一样拥有发明意图”或“模型自己理解了科学”的泛化说法，只讨论候选产物是否新、是否可运行、是否可证明或实验确认、是否有完整 provenance。与阙疑的关系也必须先摆正：阙疑目前是有 37 张实卡、67 条规则、9 个保护器和 452 条判决账本的 C++ 知识验证系统，盲 holdout 30 条中真错 17 条、现有检出率 66.7%，外部 corpus 40 条的 43.8% 还被既有上下文标为算术口径不自洽。因此，即使未来 LLM 提出了一个此前没有的边界断言，也只能先称为“候选新断言”，不能把候选生成、指标上升和知识归属混成“AI 发明了 C++ 真理”。

## 二、最硬的算法案例：AlphaTensor、FunSearch 与 AlphaDev
AlphaTensor 是“发现”和“证明”区分得相对清楚的案例。DeepMind 的 Nature 论文和官方说明把矩阵乘法编码成单人游戏：状态是待消去的三维张量，动作是对算法分解的选择；当张量被精确归零时，得到的是对任意输入矩阵成立的乘法恒等式，步骤数对应标量乘法数量。官方博客报告，系统在许多矩阵尺寸上找到超过当时已知复杂度的算法，并给出一个 4×5 乘 5×5 的例子：人类已有方案需要 80 次乘法，AlphaTensor 找到 76 次；在指定 NVIDIA V100 和 Google TPU v2 硬件上，面向实际运行时间的算法可比常用方案快 10%–20%。这可以称为算法空间中的新候选和优化，但“算法正确”来自张量分解的可验证恒等式，不来自 AlphaTensor 的自信分数；“硬件更快”又必须由固定设备、编译器、实现和基准输入实测，不能由理论乘法次数直接推出。搜索摘要和 Nature 新闻页面还明确报道了 4×4 矩阵仅用 47 次标量乘法的结果，但正文引用时应同时保留论文 DOI 与公开实现，避免只引用媒体标题。FunSearch 更接近“LLM 提议器 + 精确评估器”的可迁移范式：用户先写种子程序和评估程序，LLM 只生成函数代码，候选被自动执行，得分高者进入程序池，再经过迭代和多样性控制。DeepMind 官方页面明确说，评估器用于防止幻觉和错误思想；在 cap set 问题上，官方 Colab 明确展示了八维中大小为 **512** 的构造，超过此前已知构造，并称这是过去 20 年最大幅度的提升；但“496 到 512”这一对照数字在本文调研中没有由 Nature 正文页面直接取到，所以不把它作为已核实的一手数字。FunSearch 还在在线 bin packing 中生成了针对数据分布的启发式，官方只确认使用更少箱子装入相同物品，没有给出可泛化的统一百分比。更重要的是，官方承认研究者阅读高分程序后发现对称性，再据此修改问题定义并获得更好结果，这说明最终科学洞见是人机协作，不是无人介入的自主发明。AlphaDev 则是对 C++ 最有直接意义的真实案例：它从汇编指令空间开始，以排序正确性和延迟为奖励，逐条构造短排序程序；正确性通过对所有三元素序列等穷举输入的结果与期望排序结果比较，再以延迟进行优化。DeepMind 官方报告，生成的排序算法被反向工程并翻译成 C++，进入 LLVM libc++，短序列最高快 **70%**，超过 250,000 个元素的序列约快 **1.7%**；对 9–16 字节哈希范围的算法约快 **30%**，并进入 Abseil。这里的“发现”是出现了人类此前没有采用的指令序列，例如官方称为 swap/copy moves；“优化”是特定输入规模、处理器和库实现下的基准提升；“证明”则只覆盖测试和语义约束，不能自动推出所有 C++ 程序、所有架构、所有别名和未定义行为条件下都正确；“归属”也不能只写 AlphaDev，因为问题表示、奖励设计、测试 oracle、反向工程、C++ 落地和 LLVM 审核都贡献了可部署结果。

## 三、几何、材料与蛋白：成功并不等于“发现了自然规律”
AlphaGeometry 是一个必须谨慎命名的案例。官方 Nature 论文页面和 DeepMind 说明报告，在从 2000–2022 年 IMO 几何题整理的 30 道基准上，系统在竞赛时限内解出 **25 道**，此前最强方法解出 **10 道**，平均人类金牌得主在同一集合上为 **25.9 道**；训练流程从 10 亿个随机几何图形中推导关系，去重后形成 **1 亿个独特合成样本**，其中约 **900 万**含有新增几何构造。每个输出证明都由计算机检查，神经模型负责提出可能有用的点、线或圆，符号引擎负责规则推导。因此，它最稳妥的表述是“在已知竞赛问题上自动找到并验证了证明”，不是“AI 发现了新的几何公理”或“AI 独立创造了全新数学理论”。它展示的是证明搜索、构造选择和形式规则检查的组合能力；题目、几何公理、表示方式和最终问题集合仍由人类提供。AlphaGeometry 2 在官方 2024 年 IMO 说明中被报告为能解过去 25 年几何题的 **83%**，但这仍然是已知题目上的能力测量，而不是开放世界的新定理发现。材料方向的 GNoME 更容易被宣传语误读。Nature 论文和 DeepMind 官方页面报告，GNoME 预测了 **220 万**个新晶体，其中 **38 万**个落在最终凸包、被预测为最稳定且适合优先实验合成；模型通过图网络、主动学习和密度泛函理论计算反复筛选，材料稳定性预测在 MatBench Discovery 外部基准上的发现率从约 **50% 提高到 80%**，计算效率的发现率从低于 **10% 提高到超过 80%**。官方还报告，外部研究团队在并行工作中独立实验实现了其中 **736** 个结构；Berkeley Lab 的 A-Lab 使用 Materials Project 数据和 GNoME 相关稳定性信息，成功合成了超过 **41** 种材料。严谨表述应是：GNoME 产生了大规模计算候选，部分候选与外部实验结果重合，自动实验室验证了若干新材料配方；不能把 220 万都称为已发现材料，更不能把 736 个外部独立实现全部归因为 GNoME 发明。AlphaProteo 说明生物设计需要把“模型生成”与“湿实验成功”分开。官方技术报告对 8 个目标蛋白测试了 47–172 个候选设计：前 7 个目标均得到可测结合物，第 8 个 TNF-α 的成功率为 **0%**；BHRF1 的候选结合成功率为 **88%**，最佳设计达到 **8.5 nM**，IL-7RA 的最佳亲和力为 **82 pM**，官方总括为相对于既有方法在 7 个目标上约 **3–300 倍**的亲和力提升。对 SARS-CoV-2 和 VEGF-A 的部分 binder，Francis Crick Institute 外部团队进一步确认了结合模式和功能，包括细胞感染阻断或 VEGF 信号抑制。可是，作者自己也说明实验验证目标仍少、系统依赖目标晶体结构，PD-L1、TrkA、SC2RBD 等目标参与过开发，成功率可能高估对全新目标的表现，且尚未做全蛋白组特异性验证。由此可见，材料和蛋白案例中的“发现”最多是候选结构或候选分子被机器提出，“证明”是 DFT、结构学、结合实验和功能实验分别提供的局部证据，“归属”必须包括训练数据、实验平台、筛选流程和外部实验室；宣传中的“改变药物研发”或“未来超级电导体”只能作为潜在应用，不是已经实现的科学事实。

## 四、这些案例能否迁移到阙疑：AI 可以提出 C++ 边界断言，但不能自己宣布为真
把以上案例映射到阙疑，最有价值的不是照搬 AlphaZero、LLM 或材料模型，而是照搬它们的**提议器—评估器—外部确认**分工。首先，AlphaDev 证明了在低层程序空间中，机器可以提出人类没有主动写出的指令序列；FunSearch 证明了让模型输出“可执行程序”比输出不可复算的自然语言结论更有价值；AlphaGeometry 证明了生成器与规则引擎分离后，可以把“猜构造”和“检查证明”分开；TyMut 的 C++ 编译器测试则是相邻而非常关键的先例：它不是 LLM 发明，而是类型驱动变异、must analysis 与差分测试组成的自动化搜索。OOPSLA 2025 页面报告，TyMut 在约 **32 小时**内生成和测试 **250,584** 个程序，对接近 **80%** 的程序提供确定性 must oracle，发现 GCC 和 Clang 的 **102** 个 bug，其中 **56** 个被编译器开发者确认是此前新 bug，**26** 个导致编译器崩溃，超过一半导致误编译；另有一个长期 bug 后来被确认是 TensorFlow 现实问题的根因。这个数字不能被写成“AI 已发现 56 条新的 C++ 语言规则”，但它说明：只要候选空间、oracle、差分条件和确认流程设计得足够明确，自动搜索可以暴露此前未被记录的编译器行为和规范歧义。阙疑可以让 LLM 或搜索器提出这样的候选：在固定 C++ 标准版本、编译器版本和编译选项下，某个 `const`、引用折叠、临时对象生命周期、模板约束、重载决议、整数边界、`noexcept`、值类别或 `-O0/-O2` 改变，是否导致一个原本应保持的性质发生稳定分叉；或者提出一个反例，声称现有第 N 条规则在前提集合 P 下会误判。候选必须是结构化对象，而不是一句“我发现 C++ 有 bug”：`claim_id`、标准版本、编译器和版本、最小源程序、单因素变换、预期关系、实际诊断、运行输出、重复次数、规则触发位图、证据哈希、父候选、生成模型、prompt 哈希和时间戳都要落盘。然后由冻结的编译器矩阵、独立解析器、sanitizer 或 trap 模式、差分运行、C++ 标准条文核对、真实缺陷夹具和人工专家分别提供证据。必须明确四种结果：一是**发现候选**，即搜索器第一次提出了历史未见的程序或关系；二是**优化候选**，即在已知规则和测试下改善了运行时间、最小化程度或覆盖分布；三是**证明候选**，即有形式化推导、标准语义推导或能由独立 checker 重算的性质；四是**归属结论**，即谁提出问题、谁设计搜索空间、谁实现验证器、谁确认了语义、谁将其合并进规则库。阙疑最不能做的，是让候选规则修改 `gate_engine.py`、holdout、oracle、保护器或 452 条账本，再由修改后的系统给自己打高分；这相当于让 AlphaDev 自己改正确性测试，或让 GNoME 自己定义稳定性阈值。尤其当前 holdout 只有 30 条且有 17 条真错，任何在其上反复搜索的收益都可能是小样本过拟合；外部 corpus 43.8% 算术不自洽、反事实 P=R=F1=0 也都说明不能先拿坏 oracle 做奖励信号。阙疑可以声称“AI-assisted candidate generation for C++ boundary assertions”，但在独立确认之前只能使用 `candidate`、`unknown` 或 `needs_review`，不能写成“AI 发明了新 C++ 规则”。

## 五、结论、provenance 协议与对阙疑的三条行动
真正可辩护的结论是：AI 已经在算法搜索、程序优化、已知数学问题的证明搜索、材料候选生成和蛋白结合设计中产生了可核查的新候选，其中 AlphaTensor 的张量恒等式、FunSearch 的自动评估程序、AlphaDev 的 LLVM libc++ 优化、AlphaGeometry 的计算机检查证明、GNoME 的外部实验重合、AlphaProteo 的湿实验和外部实验室复核，分别展示了发现、优化、证明的不同组合；但没有任何一个案例证明“模型独自拥有发明意图”或“模型自己就是最终验证者”。因此，阙疑若要让 AI 发现新 C++ 边界断言，第一条行动是**冻结评估器并修复 oracle**：把 67 条规则、9 个保护器、盲 holdout、真实缺陷夹具、反事实计数器和独立对账器做成只读快照，先修复 P/R/F1 的 TP、FP、FN、TN、compile_fail、nondeterministic、inconclusive 分母问题，并重新核对 43.8% 的算术；在此之前，禁止用 gate 通过率或反事实分数训练搜索器。第二条行动是**实施提议器—评估器—晋升器三层隔离**：LLM 只能生成候选规则、最小 C++ 程序、变异算子和解释，候选写入临时目录；评估器运行在无网络、无密钥、生产文件只读的沙箱中；独立验证器重新解析源程序、执行固定编译矩阵、重跑夹具、复算账本哈希并检查评估器没有被修改；任何候选规则不得写生产 `gate_engine.py`、规则注册表、保护器、holdout、标签或正式账本。第三条行动是**建立机器可读 provenance 和人工归属记录**：每个候选保存 `candidate_hash`、`parent_hash`、`prompt_hash`、模型和版本、工具调用、源代码哈希、规则快照哈希、编译器镜像、标准版本、随机种子、输入卡哈希、stdout/stderr 哈希、独立 oracle 结果、人工复核人、复核时间、接受/拒绝理由、回滚关系和最终 commit；只有经过至少一次独立重放、一次回归夹具验证、一次外部语义证据或专家核验，并由人工签名批准，才能从 `candidate` 晋升为 `independently_reproduced`，再考虑进入正式知识库。归属记录不能把 LLM
