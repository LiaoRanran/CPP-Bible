# 方向 91：数据投毒攻击方法

## 核心结论

1. **投毒的决定性变量是"绝对条数"而不是"占比"，且门槛低到三位数。** Anthropic 对齐科学团队 + UK AI Security Institute + Alan Turing Institute（2025-10-08/09，arXiv:2510.07192）训练了 **600M / 2B / 7B / 13B 四种规模、共 72 个模型**，结论是"**as few as 250 malicious documents**"即可稳定植入 DoS 后门；原文明确："**just 250 malicious documents (roughly 420k tokens, representing 0.00016% of total training tokens) were sufficient to successfully backdoor models**"，且"**100 poisoned documents were not enough to robustly backdoor any model, but a total of 250 samples or more reliably succeeds across model scales**"。这条对本项目的直接含义是：**样本量小（37 卡 / 40 外部 corpus / 30 盲 holdout）的系统，恰好落在"几百条就能改写行为"的区间内**——规模小不构成安全边际。

2. **干净标签 + 梯度匹配攻击可以"打成功而不掉准确率"，因此任何以准确率为唯一健康指标的监控都会漏报。** Geiping、Fowl、Huang、Czaja、Taylor、Moeller、Goldstein《Witches' Brew: Industrial Scale Data Poisoning via Gradient Matching》（ICLR 2021，arXiv:2009.02276）在 CIFAR-10、**1% 预算、ε=16、ResNet-18** 下取得 **90.00%（±3.87）** 与基线设置 **91.25%（±6.14）** 的投毒成功率，而同一行的 **Validation Acc. 仍为 92.20%**；ImageNet 上"**Even at a budget of 0.05% and ε-bound of 8, the attack poisons a randomly initialized ResNet-18 80% of the time**"。原文自陈："**This attack is difficult to detect, because it does not noticeably degrade either training or validation accuracy**"。

3. **数据投毒的现成防御都是"用精度换安全"，且存在数据集依赖性，没有通用解。** Witches' Brew 原文："**to push the Poison Success below 15%, one has to sacrifice over 20% validation accuracy, even on CIFAR-10**"；异常检测在 10% 过滤下移除 **248** 张毒图（随机猜测 **200**）、20% 过滤下 **467**（随机 **400**），被原文判定为"**reducing filtering based methods to almost-random guessing**"。Steinhardt、Koh、Liang《Certified Defenses for Data Poisoning Attacks》（NIPS 2017，arXiv:1706.03691）给出更强的对比："**the MNIST-1-7 and Dogfish datasets are resilient to attack, while in contrast the IMDB sentiment dataset can be driven from 12% to 23% test error by adding only 3% poisoned data**"——**同一套防御，换数据集就从"抗得住"变成"加 3% 毒就损失 11 个百分点"**。

### 二、投毒比例 ↔ 效果的量化（用户最关心的"1% 能造成多少下降"）

| 场景 | 投毒比例 / 条数 | 观测效果 | 出处可信度 |
|---|---|---|---|
| IMDB 情感分类（NIPS 2017 认证防御实验） | **3% 毒化数据** | 测试错误率 **12% → 23%**（+11 个百分点） | 一手，逐字 |
| MNIST-1-7 / Dogfish（同篇） | 同等攻击 | **resilient to attack**（抗住） | 一手，逐字 |
| CIFAR-10 / ResNet-18（梯度匹配，定向） | **1%**（≈500 张） | 投毒成功率 **91.25%**，验证精度 **92.20%**（几乎无损） | 一手，逐字 |
| ImageNet / ResNet-18（梯度匹配） | **0.1%**（≈1000+ 张，ε=8） | 成功定向改写分类 | 一手，逐字 |
| ImageNet / ResNet-18（最低预算） | **0.05%**（≈500+ 张，ε=8） | **80%** 概率成功 | 一手，逐字 |
| Google Cloud AutoML 黑盒 | **0.1%**（ε=32，训练集 < 950,000 张） | **5/5 次**进入 top-5、**1/5 次**进入 top-1；干净 top-1 精度 69% | 一手，逐字 |
| LAION-400M / COYO-700M | **0.01%** | 攻击可实施，成本 **$60** | 一手，逐字 |
| LLM 预训练 | **250 篇**（0.00016%） | 稳定后门；**100 篇不够** | 一手，逐字 |
| LLM 微调（二手源） | **100–1000 条**（指令微调 100–500 条，数据集规模几千到几万条） | 不破坏正常能力即可植入条件触发的有害行为 | **二手（中文解析博客），未在原文核实** |
| CIFAR-10 标签翻转（二手源） | **2% 标签** | "接近完美的后门成功率" | **二手，未核实** |
| MNIST 标签翻转（博客自做实验） | 5%→~93%、15%→~85%、25%→~68%、40%→~45%、90%→~10%（第 5 轮准确率） | 存在非线性临界点（15%→25% 的下降远超 5%→15%） | **二手自做实验，低可信度** |

> 直接回答"1% 投毒能造成多少准确率下降"：**没有统一答案，取决于攻击目标**。定向（integrity）攻击下 1% 可以做到"准确率几乎不变、但目标样本被稳定改写"（91.25% 成功率 / 92.20% 验证精度）；可用性攻击下 3% 可以把 IMDB 错误率推高 11 个百分点，而同防御下 MNIST-1-7 毫发无损。**把"1% 投毒 → X% 掉点"当作通用法则是错误的**，这正是 E&D 论文值得批判性呈现的一点。

### 三、防御与其代价（逐字数字）

1. **异常检测 / 数据 sanitization**：Witches' Brew Table 6（CIFAR-10，4% 预算，ε=16，6 次随机种子平均）——
   - 10% 过滤：异常检测移除毒图 **248**，随机猜测 **200**；误删干净图 **252**（随机 **300**）
   - 20% 过滤：异常检测移除毒图 **467**，随机 **400**；误删干净图 **533**（随机 **600**）
   - 结论原文："**outlier detection is only marginally more successful than random guessing**"。
2. **差分隐私**：要把 Poison Success 压到 **< 15%**，必须牺牲 **> 20%** 的验证准确率（即便在 CIFAR-10 上）；原文将其与对抗训练类比："**Both methods can mitigate the effectiveness of an adversarial attack, but only by significantly impeding natural accuracy**"。
3. **认证防御（上界 + 配对抗击）**：Steinhardt/Koh/Liang NIPS 2017 对"先异常移除再做 ERM"这一类防御给出近似最坏损失上界，并配一个几乎匹配上界的候选攻击，从而可快速评估防御。
4. **鲁棒聚合**：Pillutla、Kakade、Harchaoui《Robust Aggregation for Federated Learning》（arXiv:1912.13445；IEEE Trans. Signal Process. 2022，DOI 见 IEEE Xplore document/9721118）用**几何中位数**做聚合 oracle 抵抗部分参与者被攻陷（本方向与 100 号联邦学习方向交叉）。
5. **标签噪声清洗（工程可用）**：Northcutt、Jiang、Chuang《Confident Learning: Estimating Uncertainty in Dataset Labels》（JAIR 2021，arXiv:1911.00068）——给出 CL 精确找到标签错误的充分条件，性能超过七种竞争方法（具体百分点**未核实**）。这是本项目"holdout 30 标签是否可信"最可直接落地的工具。
6. **Carlini 等给数据集维护方的低成本防御建议**：原文称"**we notify the maintainers of each affected dataset and recommended several low-overhead defenses**"，其中隐含的关键防线是**抓取时间快照与内容哈希**（直接针对 split-view 攻击）。

### 四、本项目（阙疑）的攻击面映射

把"验证系统"翻译成投毒术语：

| 阙疑组件 | 对应投毒概念 | 具体攻击手法 |
|---|---|---|
| 37 张知识卡（verified 23 / red-team 3 / draft 11） | **训练/构建集** | 干净标签投毒：提交一张"看起来合法、标注为 verified"的卡，卡内含一条只在特定上下文（如某标准条款、某编译器）触发的错误断言 → 类比 Poison Frogs 的"**one single poison image**" |
| 外部 corpus 40（三层 A 54.2% / B 12.5% / C 0%） | **外部爬取语料** | **split-view 攻击**：网页/标准文档在抓取时与人工复核时内容不一致；**frontrunning**：抢在快照窗口注入。C 层检出 0% 意味着**该层实际上是一个未被任何防线覆盖的注入通道** |
| 盲 holdout 30（真错 17，检出 66.7%） | **测试集标签** | 标签翻转：改一个"真错"标签为"正确"，检出率分母即被污染。30 条的规模下，**改 1 条标签 = 3.3% 投毒率**，已超过 IMDB 实验中造成 11 个百分点损失的 3% 阈值 |
| 67 规则（block 44 / warn 16 / advice 7） | **模型权重** | 规则投毒：让某条 block 规则在特定条件下降级为 warn → 等价于后门（见方向 92） |
| 反事实算子 **P = R = F1 = 0** | **检测器** | 一个恒不触发的检测器 = 对"后门检测器"的 **DoS 后门**（与 Anthropic 论文的 DoS 后门同构） |
| append-only 哈希链账本（452 条）+ Merkle checkpoint | **append-only 只防"篡改"，不防"毒从入口进"** | 投毒样本一旦合法入库，链会**忠实地永久保存它**；哈希链保证不可删除，反而使"清洗"必须靠追加反转条目 |
| 独立对账器（第三方可不信任内核复算） | **复算 = 只保证一致，不保证正确** | 若对账器与内核共享同一份被投毒的语料/规则，复算会**一致地复算出一个错误判决**——一致性 ≠ 正确性 |
| 变异 core 97.3% / all 81.5%（已放弃当作缺陷检测率） | **已被证伪的健康指标** | 与 Witches' Brew 的"验证精度不受影响"同构：指标健康但系统已被控 |

## 对阙疑的 3 条具体行动

1. **给每一条账本条目与每一张卡加 provenance 字段，并在入库路径强制校验（时间点：2027-03 前完成，2027-05 前出数据）。**
   - 在内核 `gate_engine.py`（当前 **3826 行**）的卡入库函数上增加 `card_provenance` 结构：`{source_url, fetch_timestamp_utc, content_sha256, rule_author, review_trace_id}`；`content_sha256` 与 `fetch_timestamp_utc` 直接对应 Carlini 等对 split-view 的低成本防御建议。
   - 账本条目（当前 **452 条**）从 v2 起增加 `provenance_ref` 与 `poison_flag` 两个字段；`poison_flag` 只能取 `clean | suspect | reverted`，且 `reverted` 必须以**追加反转条目**方式实现（不得原地改写，保持 append-only 语义）。
   - 对外部 corpus **40** 张卡补录抓取快照：为每张卡存一份 `corpus_snapshot/<sha256>.txt` 与抓取时间，任何一次评测复跑都必须绑定固定快照目录（消除 split-view 面）。

2. **做一次真实的"投毒—检出率"曲线实验，把 37/30/40 三个小样本的易感性量化成论文里的一张图（时间点：2027-06 前出数，2027-09 前定稿）。**
   - 协议：向盲 holdout **30** 中按 `k = 0, 1, 3, 5, 10` 注入定向毒卡（即 0% / 3.3% / 10% / 16.7% / 33.3%），每个 k 重复 ≥5 次随机种子，记录四态判决的 F1 与"真错 17 的检出率"从 **66.7%** 衰减到多少。
   - 与 PoisonBench（ICML 2025）的"**log-linear relationship between the effects of the attack and the data poison ratio**"对照检验：在 n=30 的极样本量下这条 log-linear 是否还成立（若不成立，本身就是一个 E&D 可发表的 negative result）。
   - 同步做"干净标签"版：毒卡的内容本身合法（不违反 67 条规则中任何一条），只在与另一张卡组合时才产生错误结论——用来复现 Witches' Brew 的"验证指标不掉、行为被改"现象。

3. **把"小规模 = 高易感"从风险翻转为论文论点，并在 threat-to-validity 里显式写出来（时间点：2027-04 前起草，随 `research/12_threats_to_validity.md` 更新）。**
   - 在 `research/12_threats_to_validity.md` 新增小节 **T-Poison**，第一条就引用 Anthropic/UK AISI/图灵 2025 的"**250 documents，0.00016%**"结论，明确写出：本项目的 37 + 40 + 30 规模**低于该常数门槛两个数量级**，因此"数据集规模小"不能作为免于投毒的理由，反而是**最高风险区**。
   - 论文正文中把"独立对账器"的定位改成一句可辩护的话：*"the reconciler guarantees recomputability, not correctness under a poisoned evidence base"*，并给出可证伪的检验（用第 2 条行动的曲线）。
   - 对 C 层（外部 corpus 第三层，检出 **0%**）单独写一句：该层当前**无任何有效防线**，在论文表格中以 0% 而非省略号呈现，避免审稿人质疑选择性报告。

## 盲区（诚实标注）

- **Anthropic/UK AISI 论文的适用范围极窄**：其实验只做 DoS 型后门（输出乱码），原文自陈"**Our study focuses on a narrow backdoor (producing gibberish text) that is unlikely to pose significant risks in frontier models**"，且"**It remains unclear how far this trend will hold as we keep scaling up models**"、"**unclear if the same dynamics ... will hold for more complex behaviors, such as backdooring code**"。把 250 条推广到"改写 C++ 知识判决"是我的类比，**无实验支持**。
- **label flipping 的一手百分点未取到**：Biggio 等 ICML 2012 摘要只说用梯度上升最大化测试误差，未给数字；Bhargava & Stamp 2025 摘要也只给定性结论（MLP 最鲁棒）。表中"2% 标签 → 接近完美后门成功率""MNIST 5%/15%/25%/40%/90% 系列数字"**全部来自中文二手解析博客（cn-sec.com 转载，2026-06-25），未在原文核实**，引用时必须降级或删除。
- **Bullseye Polytope 的具体成功率未取到**（只拿到仓库与摘要页），表中标"未核实"。
- **Confident Learning 的具体性能数字未取到**（摘要只说"exceeding seven recent competitive approaches"），未核实。
- **PoisonBench 的 log-linear 关系我未取到斜率系数**，只取到定性表述；若论文要用，必须打开 arXiv:2410.08811 正文取表。
- **样本偏差**：本方向几乎所有一手数字都来自图像分类（CIFAR-10 / ImageNet）与英文语料 LLM，**没有任何 C++ 静态/动态验证领域的投毒实测**。本项目类比的"知识卡投毒"目前是概念映射，不是实测结论。
- **防御侧不对称**：我只查了"防御的代价"，未查"攻击方在真实系统中被抓到的案例"，因此"投毒在现实中到底有多常被实施"无法回答。
