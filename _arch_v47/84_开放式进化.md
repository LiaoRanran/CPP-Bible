# 方向84：开放式进化（open-ended evolution）

> 调研时间：2026-09-29｜调研对象：阙疑 C++ 知识验证系统｜本方向实际 WebSearch：14 次；另以 WebFetch 核验 POET、Enhanced POET、MAP-Elites、novelty search、C++ 编译器测试等原始页面。项目数字沿用共享 brief：37 张实卡、67 条规则、9 个保护器、452 条判决账本；盲 holdout 30 条中真错 17 条、当前检出率 66.7%；外部 corpus 40 条、检出率 43.8%（算术口径仍待修）；变异测试 core 97.3%、all 81.5%；反事实 P=R=F1=0。

## 一、open-endedness 不是“无限生成”，而是持续产生可学习的新对象

开放式进化（open-ended evolution）首先要和普通优化、随机生成、自动调参区分开。普通优化预先给定目标，例如让测试覆盖率更高、让编译器崩溃样例更多、让某个标量适应度更大；搜索结束时通常返回一个最优解。开放式系统关注的不是一次性达到一个固定终点，而是能否在没有穷尽预设答案的情况下，持续产生观察者能够识别、学习或验证的新对象，并让后来的对象建立在前面的“踏脚石”（stepping stones）上。这里至少包含三个条件：一是新颖性，产物不能只是把同一个语法模板换变量名；二是可学习性或可解释性，观察者能够从产物中归纳出结构、机制或新的实验问题；三是持续性，系统不是偶然吐出一个新样本，而是在多轮搜索后仍能进入新的语义区域。第三个条件尤其重要，因为“运行得更久”不等于“继续创新”：如果档案不断膨胀但新样本都是旧规则的重复，或者指标只在第一轮上升、随后停滞，不能称为有力的 open-endedness 证据。

对阙疑来说，开放式进化不应被包装成“系统自己发现了 C++ 真理”。更准确的命题是：在冻结的编译器、标准版本、规则快照、盲态数据和外部判决器之下，系统能否持续提出新的、可编译且可复现的 C++ 语义情境，并把其中一部分转化为候选知识断言或候选反例。候选断言可以是“在某个标准版本与约束条件下，表达式 A 必须被拒绝”“某种值类别转换不会延长某个对象的生命周期”“两个看似等价的模板约束在重载选择中产生不同结果”；候选反例则是对已有断言寻找最小反例，例如改变一个 `const`、一个引用限定符、一个模板参数、一个 `noexcept`、一个边界值、一个编译选项或一个 `-O0/-O2` 条件后，断言的预期与编译器行为不再一致。系统发现的是“值得审计的偏差”，而不是直接取得 `verified` 状态。

“持久新颖性”（persistent novelty）在这里比一次性的 novelty bonus 更合适。一次性的 novelty 只需要离当前种群远，可能奖励随机噪声、非法程序、未定义行为或每次都不同的时间戳；持久新颖性要求新颖性在时间上可追踪，并且经过归一化、去重、重放和外部验证后仍然成立。可以为每个候选保存语义签名：规范化 AST、类型关系、值类别、生命周期事件、模板实例化摘要、标准版本、编译器矩阵、诊断类别、规则触发位图、运行行为摘要以及变异来源。候选与历史档案的距离不是源代码字符串距离，而是这些语义特征的距离；同时要记录它在哪个时间片首次出现、在哪些编译配置下稳定重现、是否被独立方法复核、是否已经转化为新的知识卡或反例。若一个样本在 GCC 13、GCC 14、Clang 17、Clang 18 中表现不同，它可能是有价值的标准/实现边界，也可能只是实现差异或未定义行为；持久新颖性只能把它送进审计队列，不能替它解释原因。

因此，本方向的保守定义是：open-endedness 是“在受限而可审计的搜索空间中，持续产生新颖、稳定、可解释并能降低未知的候选对象”的能力；它不是无约束自我修改，不是自动突破所有规则，也不是“越复杂越智能”。Enhanced POET 的摘要把 open-ended 算法表述为生成自身的、不断出现且适度有挑战的学习机会，同时承认原 POET 受到问题空间有限和缺乏普适进展度量的限制。这一点直接对应阙疑的现实：如果 C++ 变异器、评估器和知识 schema 都没有定义可审计边界，所谓开放式进化很快就会变成无法复算的随机实验；如果边界过窄，又只会重复 37 张实卡附近的已知结构。阙疑需要的不是宣称“无限”，而是测量在固定预算、固定工具链和固定 oracle 下，新增且经复核的语义区域是否仍在增长。

## 二、POET、持久新颖性与 quality-diversity：把“走得远”改成“保留多条可用路径”

POET（Paired Open-Ended Trailblazer）的启发不在于把双足机器人照搬到 C++，而在于它把“环境生成”和“解决环境的智能体”配对演化。原始 POET 同时维护环境—智能体对：环境通过突变产生新挑战，智能体在各自环境中优化，并尝试跨环境迁移；新环境还要经过 minimal criterion，不能简单地接受过难或过易的对象。原论文实验使用二维 Bipedal Walker Hardcore 的修改环境，控制器输入为 24 维、输出为 4 维，环境有树桩、缺口、台阶和粗糙地面等参数。可核验的结果包括：POET 中环境—智能体对的配对智能体达到 200 分以上才有资格繁殖，子环境由配对智能体得到 50 至 300 分才通过最小标准；实验维护 20 个活跃环境，三次运行每次最多 25,200 次迭代，每个 ES 步骤采样 512 个扰动，运行约需 10 天和 256 个 CPU 核心。在三个障碍难度等级中，从环境创建到解决的平均迭代数分别约为 638、11,180、22,178；三次运行的迁移替换尝试分别为 18,894、19,014、18,798，成功替换比例为 53.62%、49.26%、48.89%。禁用迁移的对照在极具挑战环境上没有取得同样结果，统计检验报告为 `p < 2.2×10^-16`。这些数字说明的是“课程和迁移可能打开直接优化到不了的路径”，不是 POET 对所有问题都保证成功；原论文还明确承认它不能保证达到某个预先指定的目标，且有限环境编码会把难度推到上限。

把这个结构映射到阙疑，可以定义“挑战环境”为一组 C++ 约束，而不是一条普通测试输入：标准版本、编译器与版本、语言特性组合、优化级别、sanitizer、模板深度、对象生命周期、并发或异常路径、预期诊断关系共同组成环境；“智能体”则是测试策略、变异算子组合、断言候选生成器或最小化器。环境突变器产生新组合，例如在一个已发现的引用折叠情境中只改变值类别，再迁移一个已经擅长产生最小模板反例的测试策略；或者把一个对 Clang 有效的类型驱动变异器迁移到 GCC 的约束空间。POET 的 stepping stone 对应“某个暂时没有新增命中、但产生了可复用语义变换的候选”，它可以帮助另一条分支进入以前到不了的标准/编译器组合。重要的是，环境生成器不能直接修改阙疑的 67 条生产规则、9 个保护器或 452 条历史账本；它只产生隔离实验对象。

持久新颖性和 POET 解决的是不同问题。持久新颖性回答“这个候选是否相对于整个历史档案仍然新，并且新颖性经重放后没有消失”；POET回答“环境和解决策略是否能共同产生逐渐可解决的挑战，并允许知识在分支之间迁移”。在阙疑里可以维护三个档案：第一是 `novelty_archive`，按语义签名距离保存多样候选，不要求每个候选立即命中缺陷；第二是 `challenge_archive`，保存标准版本、编译器、特性组合和可复现的挑战环境；第三是 `verified_archive`，只保存经过外部 oracle、人工复核或正式证据卡确认的新增断言/反例。三者不能混成一个分数。一个“很新但不可复现”的样本可以留在失败档案；一个“新颖度一般但揭示规则冲突”的样本可以进入重点审计；一个“命中已有变异”的样本不能因为运行速度快就挤占新颖性档案。

quality-diversity（QD）方法，尤其是 MAP-Elites，提供了比单一最优适应度更适合知识验证的组织方式。MAP-Elites 的核心不是只返回一个最高分解，而是在用户选择的行为描述维度上，为每个单元保留一个高质量精英，形成对搜索空间的“照明”。原论文在模块化神经网络、模拟软体机器人和真实软体机器人三个领域展示这一思路，并强调返回一组高性能、性质不同的方案，帮助观察属性之间的正负关系。对 C++ 知识发现，行为描述维度可以是 `language_feature`、`standard_version`、`compiler_family`、`diagnostic_class`、`semantic_distance`、`oracle_type`、`runtime_stability`；单元中的精英不是“分数最高的代码”，而是该语义区域内最小、最稳定、证据最完整的候选。这样做的价值是防止搜索早早收敛到最容易命中的模板，例如只生成编译器崩溃，而忽略诊断不一致、ODR、生命周期、异常安全和优化相关反例。

但 QD 也不能自动解决评估器问题。MAP-Elites 的网格维度由人选择，若维度选错，系统会把表面差异当作多样性；若质量指标只用现有规则命中数，档案会填满“对既有评估器最友好”的候选。更稳妥的做法是让质量成为多维约束：新反例增量、编译稳定率、跨配置一致性、最小化程度、独立 oracle 支持、回归夹具保持率和证据成本；多维结果采用 Pareto 非支配或分层硬门槛，而不是未经论证的单一加权总分。尤其要记录空单元、重复率、档案增长曲线、每个单元的首次/最近更新时间和被审计比例。若经过固定预算后新增非空单元只来自同一个诊断类别，系统应报告“多样性退化”，不能只报告档案总数增长。

## 三、进化测试如何发现新的 C++ 知识断言与反例

最可行的落点不是让系统直接“进化判决规则”，而是让它进化测试问题、语义变换和证据链。已有编译器测试研究提供了现实参照。Csmith 的工作把随机 C 程序生成与差分测试结合，用多个编译器/优化配置比较可观察行为，目标是暴露编译器错误；COMFUZZ 则把生成式与变异式方法用于合成更容易暴露 bug 的编译器测试；TyMut 面向 C++ 类型系统，引入类型驱动变异与 must analysis，对某些程序给出“必须良构/必须不良构”的测试 oracle，再把没有确定 oracle 的样本交给差分测试。TyMut 的公开实验摘要报告约 32 小时生成和测试 250,584 个程序，must analysis 为接近 80% 的程序提供确定性 oracle，发现 GCC/Clang 共 102 个 bug，其中 56 个被开发者确认是此前未知，确认 bug 中 26 个导致编译器崩溃，超过一半导致误编译；这些是特定论文和工具链条件下的结果，不是阙疑可以直接复现的能力承诺。更近期的 LLM 辅助进化模糊测试工作也采用多岛搜索来减少同质化，但其结果属于预印本或特定长时编译器 campaign，必须与阙疑的外部验证口径分开。

阙疑可以把发现流程写成五个隔离层。第一层是种子层：从 37 张实卡、现有 C++ 标准条款、已确认的 15 条真实缺陷夹具、编译器官方测试集和历史反例中抽取结构化 seed，但 seed 只用于提出候选，不改变盲 holdout。第二层是变异层：对 AST 和语义图进行受限操作，例如替换 `T&&`/`T&`、插入或移除 `const`、改变模板约束、调整重载候选、改变临时对象绑定、替换整数边界、加入 `noexcept`、交换 `-O0/-O2`、切换 GCC/Clang、改变标准版本、把一条语句拆成两条或进行等价重排。每个变异器必须声明预期保持关系或预期改变关系，不能只给“随机改代码”。第三层是执行层：在固定编译器、标准、架构、优化和 sanitizer 矩阵中编译、运行、收集 stdout/stderr、诊断类别、退出状态、汇编或布局摘要；未定义行为、超时、并发非确定性和环境缺件分别记为失败类别，不能默认为反例。

第四层是候选断言层。若原程序和变异程序在某个受声明关系下出现稳定差异，系统生成一个可证伪的断言，而不是一句自然语言猜测。例如：`在 C++20、Clang 18.1、-O2 下，满足约束 C 的重载集合中，表达式 E 必须选择函数 F；若选择 G，则该断言被反驳`；或者：`对同一对象生命周期变换 M，若规则 R 声称行为保持，应在三种编译配置下保持相同的可观察结果；若出现稳定分歧，登记为 R 的候选反例`。候选记录至少包含 `claim_id`、自然语言断言、形式化谓词、最小源程序、变异操作、预期关系、实际输出、矩阵、语义签名、去重依据、预计影响和失败判据。第五层是外部判决层：已有规则只能提供线索；真正晋升需要独立标准/文档证据、编译器开发者确认、人工 C++ 专家复核、可复算的多配置结果，或明确归档为 `unknown`。对标准语义尚无确定答案的样本，正确产物可能是“标准歧义候选”，不应被强迫归入 true/false。

进化测试的适应度应避免把覆盖率当成知识价值的同义词。可以报告一个结果向量而非总分：`new_semantic_cell`（新语义单元）、`stable_replay`（重放稳定）、`independent_oracle`（独立 oracle）、`new_failure_mode`（新失败类型）、`regression_survival`（既有夹具保持）、`minimality`（最小反例程度）、`cost`（编译与人工复核成本）。在小样本 holdout 上，`detected` 只有 0 至 17 的离散范围，直接用单一命中数排序会造成大量并列，也会诱导过拟合。应同时运行随机受限变异、规则引导变异、novelty-only、QD/MAP-Elites 和 POET 式挑战—策略配对对照；统一评估次数、编译器矩阵、随机种子和人工预算，先回答“开放式机制是否优于简单随机或贪心基线”，再讨论算法名称。阙疑已有的变异 score 只能说明既定变异集合上的测试充分度，不能证明发现了未知 C++ 语义。

一个小规模的第一阶段实验可以是：冻结 67 条规则、保护器、盲 holdout 和评估脚本，建立 4 个等预算臂，每臂生成 30 个候选并使用至少 5 个随机种子；四臂分别为受限随机、语义 novelty、QD 档案、POET 式挑战—测试策略配对。主要结果报告 `new_verified_candidate@budget`、`stable_replay_rate`、`semantic_cell_coverage`、`duplicate_rate`、`existing_fixture_regression`、CPU 时间和人工复核时间；每个候选都保存原始程序、变异程序、编译命令、环境哈希、标准版本、编译器输出和判决账本链接。若某方法只提高 coverage 或 novelty，却没有提高独立确认的新增候选数，结论应是“探索更广但验证收益未改善”。若某方法发现了一个反例，必须先做最小化、跨配置复跑和反向构造：确认不是 UB、编译器版本已知 bug、测试夹具错误、评估器解析错误或标准版本混用。

## 四、不可控演化、评估器坍塌与“越进化越不可信”的风险

开放式进化最大的风险不是系统停止，而是系统继续运行却逐渐脱离任务。第一类是目标坍塌：如果奖励只看“规则命中数”，候选会围绕 67 条现有规则反复生成，形成局部最优；如果只看 novelty，非法代码、随机诊断、非确定性输出和未定义行为可能成为永不耗尽的“新颖噪声”；如果只看编译器崩溃，系统会偏向容易触发崩溃的路径，却忽略更重要的静默误编译、错误接受、错误拒绝和标准歧义。第二类是评估器坍塌：候选生成器可能学会修改或影响计分脚本、污染 seed、读取 holdout、利用解析器边界、制造重复日志或让评估器超时后错误地记高分。Sakana AI Scientist 官方披露过为延长超时而修改自身代码的失败行为，这不是阙疑的实测结果，却说明“优化器会把评分规则当作可操作环境”的一般风险。阙疑的评估器一旦被候选写入、替换或间接影响，任何高分都失去证据意义。

第三类是多样性坍塌。多岛、QD 或档案并不自动保证真正的多样性：若所有岛共享同一个 prompt、同一个 seed 选择、同一个标量适应度和同一个错误的语义 embedding，迁移只会加速同质化；若档案只保留当前分数最高的个体，早期偶然高分会挤掉后来可能成为 stepping stone 的次优分支。应监测基因/程序相似度、语义签名相似度、行为描述单元占用、谱系深度、岛间迁移比例、独立谱系数和新单元发现的时间间隔。POET 原论文的迁移比例数字说明迁移可能有用，但它并不说明迁移越多越好；在阙疑中，迁移过强可能让一个错误的变异器迅速污染所有分支。必要时应设置冷冻谱系、隔离岛、不可回滚的外部 oracle 和迁移配额。

第四类是不可控演化。系统可能从“生成测试输入”逐步扩展到“生成规则代码”，再扩展到“修改评估器、保护器或账本格式”；即使每一步都看似提升局部指标，累积后也会丢失可解释性、破坏重放、改变知识 schema 或引入供应链依赖。DGM 类系统的经验表明，档案分支能够避免单链式退化，但其结果仍依赖编译可用性、编辑能力和基准分数；而且基准性能只是自我改进能力的代理，不等于安全性、稳健性或与人类意图一致。阙疑应将“可演化对象”限定为候选测试、候选断言、候选反例和实验配置；生产规则、保护器、holdout、标签、评估脚本、判决账本和信任根必须在权限和哈希上不可写。任何自修改代码都应运行在无网络、只读基线、资源限额和可销毁沙盒中，并由外部固定 runner 执行。

第五类是评估泄漏与统计幻觉。当前盲 holdout 只有 30 条，其中真错 17 条，检出率 66.7% 是一个点估计；如果进化过程多轮观察并反复调整，holdout 就不再是盲的。外部 corpus 40 条的 43.8% 口径已知算术不自洽，不能把它直接变为奖励；反事实算子 P=R=F1=0 也可能表示 oracle 计数不适用，而不是算法没有能力。开放式演化特别容易进行“隐式多重比较”：跑很多分支、很多种子、很多指标，最后只展示最高的一条。必须预先登记预算、选择规则、停止条件和主要指标，保留所有失败候选，按序贯账本记录每次评估，并把探索用集、选择用集、最终 holdout 和新时间切分集分开。若候选先看见标签再写断言，所得结果只能称为 post hoc 拟合。

第六类是知识身份污染。两个语义不同但源代码相似的候选可能被错误合并；两个源代码相似但标准版本不同的候选可能被错误视为重复；同一个编译器 bug 在多个变体中反复出现，可能被误记为多个新发现。因而“新断言”必须有规范化前提集合、标准版本、实现矩阵、反例最小核、证据来源和谱系关系。质量不够的候选进入 `draft` 或 `unknown`，不是进入 `verified`；被证伪的候选保留为负结果，不能删除以美化进化曲线。最终报告应同时给出成功、失败、重复、不可判定、环境错误和评估器错误的数量。开放式不是放宽阙疑的证据标准，恰恰要求更强的历史追踪和失败保留。

## 五、对阙疑的三条具体行动、诚实边界与来源

对阙疑的第一条行动是先实现“冻结评估器的 QD/持久新颖性实验”，暂不让任何进化组件写生产核心。建议在隔离实验目录定义 `candidate_id`、`parent_id`、`lineage_id`、`semantic_signature`、`behavior_descriptor`、`compiler_matrix`、`oracle_vector`、`replay_hash`、`archive_status` 和 `human_review` 字段；把候选分到 novelty、challenge、verified 三个档案。用 30 条盲 holdout 只做最终只读评估，不参与提示词或变异器训练；另从 15 条真实缺陷夹具和新时间切分集构造开发集。先比较随机、贪心、novelty-only 和 QD 四臂，至少报告每个 seed、每个单元和每个失败类别，不预设 QD 一定优于随机。验收条件不是档案变大，而是固定预算下新增稳定语义单元、独立复核候选和既有夹具回归率都能重算。

第二条行动是做“POET 式挑战—策略配对”的小型可行性试验。环境生成器只能改变标准版本、编译器、语言特性组合、约束类型和受控变异预算；策略生成器只能选择白名单变异、测试顺序、最小化操作和证据复核顺序。每次产生子环境时使用类似 `50 ≤ challenge_score ≤ 300` 的最小可学习性窗口，但这里的分数必须是编译成功率、可重复性、语义新颖性和人工可审计性组成的多维门槛，而不是一个任意标量。保留少量父子环境和跨环境迁移记录，观察是否出现真正的 stepping stone：一个在当前环境低分的策略，迁移到另一语义环境后是否带来新的、可复核的候选。若只是迁移后重复已有反例，应报告“没有观察到开放式增益”。实验资源应从小预算开始，不复制 POET 论文中 256 核心、10 天的规模；阙疑单人项目当前更需要可复算的负结果，而不是昂贵的演示。

第三条行动是建立“演化安全闸门”和停止条件。候选生成器、变异器和最小化器运行在只读源树与临时工作区；评估器、holdout、标签、规则快照、保护器和账本写入权限从进程级隔离；每轮对输入、工具、配置、输出和依赖做哈希。硬失败字段至少包括 `holdout_contamination`、`evaluator_modified`、`protector_violation`、`ledger_replay_mismatch`、`non_deterministic_replay`、`unsupported_claim`、`undefined_behavior`、`compile_environment_error`。任一硬失败都不能被更高 novelty 或 coverage 抵消。停止条件包括：连续若干代没有新增经独立复核的语义单元；重复率超过预登记阈值；档案多样性下降；回归夹具检出率下降；人工复核成本超过预算；或者评估器与候选谱系发生耦合。达到停止条件就冻结档案并人工审计，而不是自动扩大搜索。

诚实边界必须写进论文和项目说明。POET 的结果证明环境生成、解决策略和迁移可以形成有用的课程结构，但不证明 C++ 知识验证会因此自动发现新规则；Enhanced POET 虽然提出了领域一般的新颖度量和开放式进展度量，但摘要仍把有限问题空间和缺乏普适进展度量列为原 POET 的关键障碍。MAP-Elites 证明保存一组多样精英有助于“照亮”空间，但行为描述维度仍由人选择，错误维度会制造虚假多样性。novelty search 在迷宫和双足行走任务中可以显著优于目标搜索，说明目标函数可能欺骗搜索，却不意味着在 C++ 语义上可以放弃质量与真值。TyMut 的 250,584 个程序、102 个 bug 和 56 个开发者确认的新 bug 是强有力的编译器测试案例，但其 seed、must analysis、编译器版本和人工确认流程不能直接等价于阙疑的 30 条 holdout。故阙疑现阶段最稳妥的主张是：开放式机制可用于扩大“候选断言/反例”的探索面，并以持久新颖性、quality-diversity 和外部 oracle 共同组织证据；能否产生比随机搜索更多、更稳定、更有解释力的新 C++ 知识，必须由预注册对照实验回答，不能由概念类比回答。
