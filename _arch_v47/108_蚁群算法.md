# 方向 108：蚁群算法（Ant Colony Optimization，ACO）

## 一、核心结论：ACO 是带群体记忆的随机组合优化器，不是事实判决器

蚁群算法（Ant Colony Optimization，ACO）应被准确地理解为一类面向离散组合优化问题的元启发式，而不是“蚂蚁越多，答案越正确”的自然比喻。它把问题表示成一张图：节点代表状态、知识卡、测试动作或规则组件，边代表从一个选择到另一个选择的可行转移；每只人工蚂蚁从起点出发，按照启发式信息和信息素浓度逐步构造候选路径；一轮完成后，较优路径对所经过的边增加信息素，所有边同时经历蒸发。群体协作不依赖一只中心代理的全局推理，而依赖个体留下的分布式数值痕迹，这种“间接通信”通常称为 stigmergy。Dorigo、Maniezzo、Colorni 在 1996 年的 Ant System 论文中把它概括为正反馈、分布式计算、构造式贪心启发式和概率转移；论文发表于 *IEEE Transactions on Systems, Man, and Cybernetics Part B*，26(1)，29–41 页，并用经典 TSP 说明了方法。

对一条从当前节点 `i` 走向候选节点 `j` 的转移，常见的 Ant System 形式可以写成：

`p_ij^k(t) = [τ_ij(t)]^α [η_ij]^β / Σ_{l∈N_i^k} [τ_il(t)]^α [η_il]^β`。

这里 `τ_ij` 是边 `(i,j)` 的信息素，`η_ij` 是问题特定的启发式值，`α` 控制历史经验的重要程度，`β` 控制局部启发式的重要程度，`N_i^k` 是第 `k` 只蚂蚁在当前状态允许的候选集合。对 TSP，`η_ij` 常取 `1/d_ij`；对阙疑，可以把它替换为“预计能带来新证据的概率”“尚未覆盖的语义类别”“预计执行成本的倒数”或“到达一个可复核终点的启发式分数”，但这些替换都必须是显式的实验设计，而不是把一个主观分数伪装成知识真值。信息素更新通常写成 `τ_ij(t+1) = (1−ρ)τ_ij(t)+Δτ_ij(t)`，其中 `ρ` 是蒸发率。蒸发让旧经验逐步失效，沉积让高质量路径获得更多被再次选择的机会。

因此，ACO 的基本动力学同时包含探索与利用。低信息素差异、较小的 `α` 或保留较高随机转移概率时，蚂蚁会访问较多不同路径，属于探索；较大的 `α`、更强的精英更新、较小的候选集合或 ACS 的伪随机比例规则会让群体集中到已知好路径，属于利用。两者没有永远正确的比例：探索过强，预算被大量低质量路径消耗；利用过强，某条早期偶然的好路径迅速垄断信息素，其他路线几乎失去被访问的机会，形成停滞、早熟收敛或“错误共识”。这正是 ACO 与“群体智能”的关键关系：群体不是独立随机试验的简单并集，而是通过共享记忆改变后续个体的分布，所以它可能比独立随机搜索有效，也可能把同一个早期偏差放大到全群体。

对阙疑而言，最重要的边界是：ACO 可以作为候选顺序、规则组合和反例生成的搜索器，但不能成为 verified / red-team / draft / 未成立的最终裁判。尤其是，**452 条账本是审计事实的 append-only 记录，确定性复算是系统的可验证边界；随机蚁群不能直接修改、覆盖、删除、重排或重写这 452 条记录，也不能通过一次随机运行生成“新的正确账本”。** ACO 若被允许写入生产规则或账本，就会把概率性优化状态与历史事实混在一起，既难以重放，也无法区分“候选方案更会找到测试”与“知识主张本身成立”。合理的架构只能是：ACO 在隔离沙盒中读取固定版本的卡片、规则、保护器和账本检查点，提出一个候选动作序列；固定的验证内核执行该序列；独立对账器重新计算证据哈希、判决和账本 Merkle 根；人工或预先声明的批准流程决定候选是否进入研究数据，而非让蚁群直接改写系统状态。

## 二、精确机制与经典实验：信息素、TSP、参数和收敛不能混为一谈

### 1. 从真实蚂蚁到 Ant System、ACS 与 MMAS

1997 年 Dorigo 与 Gambardella 的 *Ant colonies for the travelling salesman problem* 发表在 *Biosystems* 43(2)，73–81 页。论文摘要明确说，人工蚂蚁利用沉积在 TSP 图边上的信息素，逐步生成更短的可行回路；计算机模拟覆盖对称和非对称 TSP。论文把 TSP 定义为：访问给定城市集合中的每个城市一次并返回起点的最短闭合巡回。在构造过程中，人工蚂蚁依据边上的信息素和与边长相关的启发式值作概率选择。这个实验的科学价值不在于“证明自然界蚂蚁能解决所有优化”，而在于展示了局部概率行为如何通过正反馈形成全局路径偏好：短路径被更早走完，单位时间内得到更多沉积，因而吸引更多后续蚂蚁。

Ant System 的优点是机制简单、分布式、能够用统一的信息素矩阵表达群体经验；缺点是所有蚂蚁都更新时，较弱路径也会留下痕迹，信息素差异形成较慢。1996 年论文明确讨论参数选择、模型早期设置，并把 TSP 结果与 tabu search、simulated annealing 比较；同时还说明了向非对称 TSP、二次分配问题和 job-shop scheduling 扩展的方向。这些是经典实验的可核实事实，但不能把“报告了模拟结果”改写为“在所有 TSP 基准上达到最优”。经典论文页面没有给出一个可以脱离实验设置直接复用的统一参数答案，因而阙疑也不应把某组默认参数包装为理论最优。

ACS（Ant Colony System）强化了利用。常见 ACS 版本包含全局更新、局部更新和伪随机比例规则：在每步选择时，以概率 `q0` 直接利用当前最有希望的边，以剩余概率按转移分布探索；蚂蚁经过边后进行局部蒸发，使刚被走过的边暂时降低吸引力，帮助同一轮的其他蚂蚁分散；完成一轮后，通常只让全局最好路径或迄今最好路径沉积较强信息素。这样的机制解释了为什么 ACS 在 TSP 上可以快速集中，但也解释了它对 `q0`、蒸发率和初始化非常敏感。1997 年论文的结论强调，应用 ACS 到新问题的关键不是把城市名称替换为别的对象，而是找到合适的图表示和适当的启发式距离。

MAX–MIN Ant System（MMAS）由 Stützle 与 Hoos 于 2000 年发表于 *Future Generation Computer Systems* 16(8)，889–914 页。其摘要明确指出，原始 Ant System 在大型传统 TSP 基准上相较精调算法表现较弱；MMAS 通过只允许最好解更新、限制信息素上下界、加强对搜索历史的利用，并可结合局部搜索来改善表现。论文报告了 TSP 与 QAP 的计算实验，并在 TSP 实验中使用 TSPLIB 较大实例和 3-opt 局部搜索。这里有两个对阙疑很重要的读数：第一，ACO 的效果通常来自算法变体、局部搜索和表示/启发式共同作用，不是“信息素”三个字单独带来的；第二，MMAS 通过上下界避免信息素完全失去多样性，恰好说明探索与利用要靠工程机制维持，而不能依赖群体自然平衡。

### 2. 参数、预算与可重复性

`α`、`β`、`ρ`、蚂蚁数量 `m`、迭代次数 `T`、候选列表大小、精英更新比例、`q0`、信息素上下界和局部搜索策略构成了 ACO 的主要实验自由度。参数的方向性含义可以这样理解：`α=0` 时不使用信息素，算法退化为依赖启发式的随机构造；`β=0` 时不使用局部启发式，早期探索可能更广但也更盲；`ρ` 太小，旧信息长期保留，错误历史不易清除；`ρ` 太大，刚积累的信息快速消失，群体记忆变弱。`m` 增大可以提升一轮候选覆盖，但会线性增加评估成本；`T` 增大只能增加搜索机会，不能保证命中正确反例；`q0` 越高，ACS 越贪心，越需要局部更新、信息素上下界或重启机制来防止停滞。

针对阙疑，不能先观察 holdout 结果再挑一组“看起来最好”的参数。至少应在盲态固定：算法变体、`α`、`β`、`ρ`、`m`、`T`、候选列表大小、信息素初始化、随机种子集合、停止规则、是否使用局部搜索、评估预算和输出字段。推荐把预算定义为“固定验证执行次数”而不是“运行若干秒”，因为机器负载、编译器缓存和并行调度会改变时间预算。每个 run 要保存参数 JSON、种子、输入快照哈希、规则快照哈希、保护器快照哈希、账本 checkpoint、候选路径、原始 stdout/stderr、证据哈希和重放结果。随机种子只让随机过程可重复，不会把一个错误的目标函数变正确；同一个 seed 也不能弥补编译器版本、线程调度、浮点实现或外部资源漂移。

### 3. 收敛是什么意思，不能怎么说

ACO 文献中的“收敛”至少有三种不同含义：找到最优解至少一次的概率趋近于 1；信息素逐步集中到某些边；当前蚂蚁越来越频繁地产生同一条路径。它们不是同一个命题。Stützle 与 Dorigo 2002 年的 *A short convergence proof for a class of ant colony optimization algorithms* 发表在 *IEEE Transactions on Evolutionary Computation* 6(4)，358–365 页。摘要给出的结果是：对任意小常数 `ε>0`，当迭代次数足够大时，找到最优解至少一次的概率 `P*(t) ≥ 1−ε`，并在 `t→∞` 时趋近于 1；在最优解被找到后，与该解对应的信息素最终高于其他信息素，且结果依赖 `τ_min`、`τ_max` 等上下界。这个结论针对特定类别、特定假设的算法，不能直接转译为“阙疑的随机蚁群一定找到真实 C++ 反例”，更不能转译为“蚁群运行久了就能证明规则正确”。

在工程上，最常见的早熟现象是信息素矩阵趋于近似单一：某条边的选择概率接近 1，其他边的概率接近 0。此时表面上“收敛曲线很平滑”，实际上可能只是搜索已经失去探索能力。可观测指标应包括：每轮唯一候选路径数、边熵或路径熵、最优值首次出现的迭代、最优值保持时间、信息素最大/最小比值、不同种子之间的结果方差、重启次数、反例类型覆盖率和独立复算通过率。对阙疑，“检出一个反例”不能用单一 reward 取代质量判断：一个重复触发已知 67 条规则的路径，可能得到很高覆盖，却没有带来新语义证据；一个更短的测试序列，可能遗漏真正困难的编译器标准版本交互。

### 4. 群体协作的边界：协作不等于共识真值

ACO 的群体协作有三层：个体蚂蚁在局部约束下构造候选；信息素把个体经验压缩为共享偏好；下一代个体使用共享偏好继续搜索。它适合“许多可行路径中找成本较低或收益较高的一条”，不适合“从有限证据推断一个不可替代的事实”。如果把“是否验证成功”直接定义成信息素奖励，蚂蚁会倾向于重复那些最容易让当前 gate 产生高分的路径；如果把“新增账本记录数量”定义为奖励，它可能大量产生重复事件；如果把“规则触发次数”定义为奖励，它可能学习到规则重叠，而不是新反例。必须把 novelty、独立证据、真实缺陷重注入检出、执行成本、回归风险、盲态合规和复算一致性分开记录，并将保护器违规、holdout 污染、账本重放不一致设为硬否决，不能让更多覆盖率抵消这些失败。

## 三、对阙疑的适用性判断：顺序可用，规则选择有限可用，反例路径搜索最值得试验

### 1. 验证顺序：适用，但只能优化“先做什么”

验证顺序天然可以编码成路径：节点是待验证的卡片、语义类别、编译器/标准版本组合或证据复核动作；边表示从当前动作转移到下一动作的成本与先决条件；路径长度是总执行时间、编译次数或人工复核成本；路径收益可以是预期新证据、预计高风险缺陷覆盖和发现早期失败的概率。ACO 在这里的合理问题是：“在有限预算下，怎样安排测试顺序，使高价值失败尽早暴露？”它不能回答：“哪张卡在语义上为真？”

可行的状态例子是 `card_id + claim_hash + standard_version + compiler_id + fixture_family + rule_snapshot_hash + ledger_checkpoint`。动作可以是选择下一张卡、选择标准版本、选择编译器、选择变异夹具或停止并升级人工复核。第一阶段只让 ACO 在固定的候选动作集合中排序，不改变动作语义；第二阶段比较 ACO 与固定规则排序、均匀随机排序、覆盖率贪心排序，指标包括首个真错出现位置、单位成本发现的新失败模式、30 条盲 holdout 的独立检出、执行时间和重放一致性。若 ACO 只减少了平均时间，却降低了跨种子覆盖或增加了盲态污染，就不能宣称整体改进。

### 2. 规则选择：可做候选组合或调度，不可直接改写规则语义

规则选择可以被表示为从候选规则集合中选择一个序列或子集。例如 67 条规则按 block、warn、advice 分组，蚂蚁选择一条规则组合，目标是减少重复触发、提高语义类别覆盖、控制运行成本和发现规则交互。信息素可以放在“规则—规则转移”上，也可以放在“规则—输入类型”的二部图边上。这样做的适用场景是离线实验：探索在相同预算下，哪些规则先运行、哪些规则组合能暴露保护器冲突、哪些候选规则值得人工复核。

局限也很明确。规则的四态结果是结构化的偏序信息，不是天然的单一标量；将 verified、red-team、draft、未成立粗暴编码为 `3,2,1,0`，就隐含了未经论证的距离和权重。即使改成多目标向量，例如 `(new_evidence, false_positive, cost_ms, regression)`，ACO 也只是优化候选方案，仍需要固定 oracle、盲态注册和独立验证。任何新规则都必须先登记自然语言断言、形式化谓词、预期增量、反例条件和证据来源；在看到 holdout 结果之前冻结提案；通过真实缺陷夹具或外部 corpus 的增量检出后，才可进入人工审查。**ACO 不得直接修改 452 条账本、67 条生产规则、9 个保护器或任何确定性复算代码。** 它的输出最多写入一个隔离的 `proposals/` 或实验 artifact，由审批流程决定是否生成下一版规则快照。

### 3. 反例路径搜索：最有研究价值，但要防止奖励投机

反例搜索比验证顺序更适合 ACO，因为反例往往是由多个离散选择组成的路径：选择 C++ 标准版本、编译器、优化级别、模板参数、生命周期动作、并发调度、输入边界、异常路径和观察器，最后到达“编译成功但语义异常”“不同编译器行为分歧”或“规则应该阻断却未阻断”的终点。每个部分路径可以留下信息素，提示后续蚂蚁优先尝试能够延伸出已知异常的动作组合。对 C++ 知识验证，尤其值得搜索的不是任意长路径，而是有明确约束的最小反例：在保持编译命令和环境快照不变的前提下，寻找最短输入、最少动作或最小标准差异，使两次独立求值出现可复核分歧。

但“反例”必须经过外部判据确认。一个随机路径导致崩溃，不等于知识卡错误；可能是夹具非法、未定义行为、环境缺依赖或测试工具自身故障。候选终点至少要有：原始输入哈希、完整编译命令、编译器与标准库版本、返回码、stdout/stderr、sanitizer 结果、规则触发前后状态、独立复跑、不同种子复跑和人工分类。对反事实检验，还要避免把同一个生成器和同一个 gate 当作唯一证据。ACO 可以发现“值得核查的路径”，不能把路径长度最短、信息素最高或 reward 最大解释成“反例已被证明”。

### 4. 最小安全实验方案

建议先做一个只读、离线、固定预算的三臂实验：A 臂为均匀随机路径，B 臂为确定性启发式排序，C 臂为 ACO。三臂使用相同候选动作、相同执行次数、相同夹具池、相同编译器矩阵、相同 holdout 隔离和相同停止规则；每臂至少使用多个预先登记的随机种子，报告均值、中位数、离散度、首个新失败模式出现的成本和重复运行一致率。ACO 参数可以先选一个小网格，例如 `α∈{0.5,1,2}`、`β∈{1,2,4}`、`ρ∈{0.1,0.3,0.5}`，但这些只是待验证配置，不是理论推荐；参数选择只能在训练/开发夹具上完成，最终 30 条盲 holdout 只运行冻结配置。

验收门槛应优先是安全和可审计，而不是单纯命中数：任何 `ledger_replay_mismatch`、`protector_violation`、`blind_holdout_contamination`、`unsupported_claim` 或 `non_deterministic_replay` 都直接判该 run 失败；仅当安全门通过后，才比较新反例数量、单位成本和统计区间。报告中必须把 ACO 与随机基线并列，因为蚁群的“智能”很可能只是额外预算、局部启发式或更密集的候选评估带来的。若 ACO 与随机搜索在区间上重叠，应诚实写成“未观察到超出随机基线的增量”，而不能写成“群体协作自动发现了新规则”。

## 四、对阙疑的 3 条具体行动

1. **先实现只读的验证顺序实验，不接入生产判决。** 固定当前知识卡、规则、保护器和 452 条账本的快照哈希，定义状态、动作和成本字段；实现 ACO、均匀随机、确定性启发式三个候选排序器。每轮只允许生成动作序列，最终执行仍由现有确定性内核完成。记录 `seed`、`alpha`、`beta`、`rho`、`ant_count`、`iterations`、`candidate_path`、`evidence_hash`、`replay_match` 和 `ledger_checkpoint`。验收条件是：同一快照、同一 seed、同一依赖环境可重建同一候选路径；不同 seed 的差异被明确报告；任何蚁群输出都不能写入 452 条既有账本。

2. **把规则选择限制为候选提议与多目标排序，并加入随机搜索对照。** 不允许 ACO 在线更改 67 条规则的语义、阈值、block/warn/advice 分类或 9 个保护器。对每条候选规则登记 `rule_id`、自然语言断言、可执行谓词、预期增量、falsify condition 和生成时的规则快照哈希；holdout 结果出来后不得回写提案。评价向量至少包括新失败模式数、独立证据数、误报数、执行成本、回归数和重放一致性；硬失败字段不能被加权目标抵消。以同等评估次数运行 ACO 与随机搜索，若 ACO 的优势不能在多个 seed 和冻结 holdout 上稳定复现，就把结果记录为 negative result，而不是保留“自动发现”叙事。

3. **把反例路径搜索做成外部证据实验，并把确定性复算设为不可越过的边界。** 先在已知真实缺陷夹具和独立开发夹具上测试 ACO 是否能更快找到最小反例，再使用完全未参与调参的盲集合。每个候选反例必须保存编译器、标准版本、优化选项、输入、生成路径、stdout/stderr、sanitizer、规则输出、证据哈希和人工标签；至少两次独立复跑并通过独立对账器。对于 452 条账本，允许的动作只有读取固定 checkpoint、验证哈希链和生成新的实验日志；**不得由随机蚁群直接改写、删除、排序、补写或覆盖账本，也不得用随机概率替代确定性复算。** 论文中的结论应写成“ACO 提议了需要核验的路径”，而不是“ACO 证明了规则或知识主张”。

## 五、盲区与来源

### 盲区（诚实标注）

1. 本次核实了 Ant System、ACS、MMAS、收敛证明和测试用例优先级相关论文的标题、作者、年份、摘要或出版信息，但没有对所有原始 PDF 的每张 TSP 实验表逐格复核。因此本文没有编造某个具体 TSPLIB 实例的最优长度、运行时间或胜率；“经典实验”只使用页面明确的对称/非对称 TSP、TSPLIB、3-opt、QAP 和基线比较事实。
2. ACO 参数对阙疑的推荐网格是实验设计建议，不是从文献推导出的最优配置。`α`、`β`、`ρ`、`q0`、蚂蚁数量和停止规则之间存在问题依赖性；即使某组配置在 TSP 上有效，也不能直接外推到 C++ 知识卡、规则交互和反例路径。
3. 收敛证明只适用于论文声明的算法类别和条件。它支持“在特定条件下，找到最优解至少一次的概率趋近于 1”等理论表述，不支持“随机蚁群必然找到真实 C++ 语义反例”或“运行时间足够长就能证明知识主张”。
4. 测试用例优先级方向确有 ACO 研究，但本次检索没有核实其所有数据集、seed 数、统计显著性和与现代基线的完整对照，所以这里只把它作为“顺序优化存在先例”，不把它写成阙疑效果的证据。
5. 本文关于 452 条账本、67 条规则、9 个保护器、37 张实卡和当前项目指标的表述依赖 v47 brief 上下文，未重新审计项目内核。它们在本文中是不可越过的工程约束，尤其是“账本 append-only、确定性复算不可被随机搜索改写”；若仓库实际接口不同，实施行动前必须以真实 CLI、schema 和哈希输出为准。
6. 信息素熵、重复路径比例、早熟收敛和 ACO 与随机基线的差异尚未在阙疑数据上实测。这里的局限是机制推论，不是已完成的实验结论；未来必须以固定预算、多 seed、盲态和独立对账结果更新。
7. 未找到“ACO 自动发现新的 C++ 静态验证规则并被外部证据确认”的直接实证基线。现有来源主要覆盖 TSP、一般组合优化、收敛理论、测试用例优先级和并行形式化表示。因此，阙疑若继续做，研究新颖性可能存在，但评价风险同样较高，必须依靠真实缺陷夹具、随机搜索对照和可证伪登记来降低自嗨风险。
