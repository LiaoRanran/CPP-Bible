**移动语义**

移动语义是 C++11 引入的特性，它允许把资源（比如堆内存）从一个对象转移到另一个对象，
而不是复制。这样可以避免不必要的深拷贝，提高程序性能。

```cpp
std::string a = "hello world, this is a long string";
std::string b = std::move(a);   // 移动而不是拷贝，很快
std::cout << a;                 // a 已经被移动，不要再用它
```

`std::move` 把 `a` 转换成右值引用，从而调用移动构造函数。移动构造函数把 `a` 内部的
指针直接拿过来，所以 `b` 得到了资源，`a` 变成空字符串。

**结论**：需要转移所有权时用 `std::move`，比拷贝快。

#### 用 `std::move` 申报所有权转移，别指望它自己搬东西

**问题（是什么）**

`std::move` 这个名字是 C++ 里最容易被误读的命名之一：它被调用之后并没有任何东西被"搬走"。
真正让人困惑的是这句话的矛盾感——**标准明文规定 `std::move(x)` 与一次类型转换完全等价**
（[xvalue.cast]）：

```cpp
// 标准 [xvalue.cast] 的等价关系（可编译互证）
std::move(x)  ≡  static_cast<std::remove_reference_t<decltype(x)>&&>(x)
```

既然它只是类型转换，为什么需要这个名字？因为在**重载解析**里，"是不是右值"决定了调用哪个
构造函数——`std::move` 的职责不是搬运，而是**申报意图**，把选择权交给重载解析。

**机制（为什么需要）**

一次 `T b = std::move(a);` 实际发生三件事，只有最后一件与"搬"有关：

1. `std::move(a)` 把左值 `a` 变成 **xvalue**（不产生任何机器码，纯编译期动作）；
2. 重载解析选中 `T(T&&)`（移动构造）而不是 `T(const T&)`（拷贝构造）；
3. **移动构造自己决定做什么**——对持有堆指针的类型，它是"偷指针并把源置空"；
   对没有间接资源的类型，它只能逐元素搬字节，与拷贝构造生成的代码相同。

所以"移动有多快"不取决于 `std::move`，取决于**被移动类型有没有可以掏空的间接资源**。

**证据（怎么知道）**

两个独立证据层，缺一不可：

| 层 | 证据 | 观测 |
|---|---|---|
| 运行层 | `EV-MEM-001`（6 组矩阵 + 证伪对照） | 构造 1 次分配 / 拷贝 1 次 / **移动 0 次**；假移动对照 1 次 |
| 汇编层 | `Examples/_atom_move_alloc.asm` | `main` 内 `call malloc` 恰 3 次（`@L109` `@L117` `@L144`），移动路径 0 次 |
| 汇编层 | `Examples/_atom_move_no_gain.asm` | `call malloc` 仅 1 次（`@L117`，HeapBuf 拷贝）；纯值组走 `pshufd` + `movaps XMMWORD PTR`（`@L136` `@L143`）= **32 字节搬运** |

两层的意义不同：运行层证明"移动确实没分配"，汇编层证明"移动**做了什么**"——这正是把
"移动更快"这种模糊说法换成可检验机制的抓手。

**反例与边界（什么时候不该用）**

**反例一：纯值类型没有收益。** `EV-MEM-002` 实测：

```text
HeapBuf  拷贝分配=1 移动分配=0 移动后源被掏空=是     ← 有间接资源：移动 = 偷指针
FixedBuf 拷贝分配=0 移动分配=0 移动后源完好=是       ← 纯值成员：移动 = 搬字节，源不动
array    拷贝分配=0 移动分配=0 移动后源完好=是       ← 标准库纯值类型：同上
```

`std::array<int, 8>` 的移动在汇编里是 32 字节 SIMD 搬运（`movaps`），而源数组一个字节都没变——
**移动的全部收益来自"掏空源对象"，没有可掏空的东西时，移动就是拷贝**。

**边界：移动之后源对象处于"有效但未指定"状态**（[lib.types.movedfrom]）。这不是修辞，
要按三分法使用：

- ✅ 可以：析构它、给它赋新值、重新 `clear()` 后再用；
- ❌ 不可以：读它的值、依赖它"是空的"、把它当空容器用。

**坑（连标准都替你兜不住）：**
- 写 `std::move(const T& src)` —— 得到 `const T&&`，移动构造需要 `T&&`，**静默退化为拷贝**；
- 写 `return std::move(local);` —— 移动构造虽被选中，但**阻止了 NRVO**（具名返回值优化），
  结果比不写更慢（[class.copy.elision]）；
- 对 `int`、`std::pair<int,int>` 这类 trivially copyable 类型用 `std::move` —— 没有收益，
  只是让代码更难读。

**什么时候该用**：当你**要把一个对象的资源交给另一个对象**，且这个对象确实持有间接资源
（堆内存、文件句柄、`unique_ptr` 持有的所有权），并且你**确定源对象之后不会再被读**时。
