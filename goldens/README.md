# `goldens/`：样板锻造缓冲区（人审前）

本目录存放 G4 三样板的**四步锻造留痕**。样板在这里改到人审通过后，才原子化进 `atoms/{domain}/`。
目的：保证 `atoms/` 里**只放已验收内容**（0.1 阶段门）。

## 为什么需要人工 checklist（而不是机器门禁）

`gate_engine` 的规则**只扫 `atoms/**`**——这是刻意的口径隔离：未验收内容不该污染原子库指标。
代价是本目录内容在原子化之前**没有机器门禁覆盖**。2026-09-10 监工裁决：用**轻量人工
checklist** 补位，**不**给引擎加 `--root`（避免把未验收内容的问题混进原子库口径、增加噪音）。

## 人审前检查清单（每份样板逐条打勾）

- [ ] **四步留痕齐全**：平庸版 / 红队报告（S1–S6 逐条）/ 5 分候选 / 人审结论——四段独立可见，
      不得合并成一段"我改了"
- [ ] **五件套**：祈使句标题 · 四段式叙事（问题→机制→证据→反例与边界）· 误解 surface/deep
      分层且 **deep 类 ≥2 反例** · 三问题主线（是什么/为什么需要/什么时候不该用）· ASM 行号注释
- [ ] **frontmatter 可被引擎解析**：把样板临时放进 `atoms/{domain}/` 试跑
      `python tools/gate_engine.py --run`，block 级必须为 0（advice/warn 允许并注明理由）
- [ ] **证据卡四校验 confirm**：`python tools/atom_evidence_replay.py --check`；
      `artifact_sha256` 与工件**同代**（改了 `.cpp` 或卡里计数就必须重生成并换哈希）
- [ ] **汇编行号逐行核对**：正文引用的 `@L109` 之类必须与 `.asm` 工件实际行号对应
      （**最容易出硬伤的地方**，人审必查）
- [ ] **注释里的机制断言必须有代码实证**：写了"X 会怎样"的注释，就得有一行代码把 X
      **演出来**——要么输出可见、要么反例注释附上**实测**的编译错误原文。
      🔴 教训（ch21 示例 34，监工 2026-09-11 抓到）：`mutable int debug` 只声明 + 注释断言，
      `debug` 全程是死代码，-Wall 拦不住未用成员 → 断言跑在了证据前面。
- [ ] **`claim_boundary` 如实**：覆盖证据实际跑过的编译器/优化档；未覆盖项明标"待补"而非含糊
- [ ] **`superiority` 非空**、逐来源写"本书多给了什么"、无 M3 禁词
- [ ] **红队报告是真攻击**：至少记录 1 处已修复缺陷；若确实挑不出，须说明"试了哪些角度"
- [ ] **rubric 自评**写明"从几分升到几分、具体补了什么"（只写分数不算）

## 通过之后

```bash
# 1. 原子化（把 5 分候选正文搬进原子卡，补 relations/evidence 引用）
# 2. 门禁复核
python tools/atom_evidence_replay.py --check
python tools/gate_engine.py --run
python tools/golden_lock.py sync
# 3. 提交
```

**注意**：原子化会让 `EV-SERVES-EXIST` 的对应债**自动清零**（规则自注行为）；同时该原子的
`relations` 若指向尚未锻造的原子，会新增 `ATOM-REL-TARGET` 债（规则提示"尚未锻造的先记债"）——
这两类变动都是**预期中间态**，用 `golden_lock.py check --accept "<理由>"` 显式留痕，不要静默 sync。
