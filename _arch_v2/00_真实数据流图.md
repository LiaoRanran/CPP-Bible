## 2. 信任边界一句话

**机器（B/C + poison/pytest）保证的是"文件/字段/字节/退出码自洽"；人（D/E）保证的是"主张与现实相关且正确"。两层之间唯一的接口是 frontmatter 里的几个自报字段（verdict / claim_type / signed_by / external_basis）——全部可被 Writer 书写，机器只验形式。当前系统的全部安全余量都押在"红队会看 + 人会签"这两个非机器环节上。**

## 3. EV-CONC-001 实跑日志（2026-09-15，【实测】，原始存 `_fence_replay_log.txt`）

```
[replay] evidence/conc/EV-CONC-001.md
  ✅ compile_rc    3 条命令全部退出码 0
  ✅ run_match    3 个 key 与 .out 逐字一致（run_match_file 模式）
  ✅ artifact_sha  8dd19bc6bf2facc2… == 卡值（归属 GCC 15.3.0 (MinGW-w64)）
  ✅ recompile  8dd19bc6bf2facc2… == 卡值（独立重编译复现）
  ⏭ sanitizer    已按 --no-sanitizer 跳过
  → confirm
```
verdict 产生机制：C2 退出码→C3 stdout 与 .out 逐字→C4 重生成 sha 对卡值→C4b 独立 tempdir 再编译一次 sha 复现。四盏灯全绿即 confirm；任一盏非绿即 refute/infra，**全程无一步读取 claim 文本**——这是 G2/G6/G7 三个语义缺口的总根源。
