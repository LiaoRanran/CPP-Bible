> 排序原则：①先闭合已实证的语义缝（不补黑名单补性质）②零模型依赖的先做③所有"放权"必须先有测量数据④每批独立可验收、可回滚、不 push/不 accept。
> 前置：530 批次 H（T1 已落地；T2-T7）是本路线图的第 0 批，照其施工版执行；本文件对 T2 做一处修正（帧符号枚举降级为 V-iso 辅助，见批 I 说明）。

## 档位定义
- **现在做**：零模型依赖、苦力可施工、当批即有机器验收物。
- **攒数据再做**：机制已知，缺触发数据；本档只允许建设测量设施，不允许启用能力。
- **等模型再做**：能力探针/准确率门未满足前禁止动工（写了也不给验收）。

## 批次 I · V-iso 阴阳同构验证层（最高 ROI，质变项）
**为什么第一个做**：六轮对抗唯一的整类收口、不依赖模型、不增加人审、不改信任结论；04 自我对抗已界定残余与成本上限。
**任务**：
1. EV frontmatter 增 `negative_controls:` schema + replay 执行（阴夹具编译运行，断言关键 key 翻转或 rc≠0，不满足→refute:negative_control_passed）；阴夹具独立 tempdir、不进卡 sha、不写 Examples/atoms。
2. gate 规则 `OBSERVATION-NEEDS-CONTROL`（warn 观察期，与 530 T4 合并；存量 0 block）。
3. rc≠0 阴面 half-credit 逻辑 + 阴/阳夹具 diff 行数采集（先记录）。
4. FENCE-001 样板补阴面（"删 fence→循环被消除"对照，利用现有多 TU 夹具，成本最小）。
5. pytest ≥6：阳 confirm/阴同值 refute/阴缺失字段报错/rc≠0 half-credit/存量 0 block/阴夹具不污染正式目录；毒样例注册（who 字面量）。
**依赖**：无（530 T1 已在）。
**验收机器判据**：样板卡 replay 四灯+阴面全绿；人造"阴面造假"卡 refute；56 卡全量 56 confirm 不变；fast 全绿；poison 无 uncovered。
**检查点（赌注复核）**：连续 5 颗带阴面原子后，若阴面平均生产成本 >阳面 50% 或阴面误判率 >10%，V-iso 收缩为仅 DAL A/B 强制，其余维持人审（04 已承诺）。

## 批次 VI · nightly 并行 replay（性能，实验性）
1. `--jobs N`：每卡独立临时 worktree+build_<pid>，产物 sha 回主进程比对；默认 N=1 行为逐字不变。
2. 实测 N=2/4/8 墙钟与加速比；加速 <2× 或出现任何 verdict 分歧 → 只保留分析不默认开（528 既定纪律）。
3. 慢测试随并行受益；日常 PR 通道已 <30s（增量），nightly 目标 <60s。
**依赖**：批次 I-III 稳定（并行只跑已闭合的验证器）。
**验收**：N=1 与串行逐卡一致；并行结果与串行 verdict 集合相等（pytest 顺序无关已在 508 覆盖）。

## 三句话收束
1. 现在的质变点只有一个：**阴阳同构验证（批次 I）**，其余都是还债或埋开关。
2. 系统变强不靠加层，靠把每个"人/LLM 在做什么"换成可计算的门，门没开之前诚实保持人审。
3. 下一次架构评审的及格线不再是"文档写了多少"，而是：G-iso 是否 ON、双率是否 100%、概念跨卡连通是否 >0、盲测集攒了多少条——四个数，别的不算。
