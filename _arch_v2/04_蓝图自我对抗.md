# 04 · 蓝图自我对抗（每个核心设计先过攻击者这关）

> 方法：切换成攻击者，对 03 的每个核心设计写"它怎么失败"，再给回应（加固/限定/承认赌注）。不辩护到底。

---

## C1. V-iso 阴阳同构层

**攻击 1a：阴面造假。** Writer 写一个"声称删了机制、实际没删"的阴夹具（注释写 `// fence removed` 但 `atomic_thread_fence` 还在）→ 阴面读数与阳面相同→但它会被判 `negative_control_passed`（没翻转）而 refute，所以这种偷懒直接红。✓ 被自己的规则拦。

**攻击 1b：阴面翻转了，但翻转原因不是机制。** 删 fence 的同时顺手改了别的（循环次数/打印格式），读数变化由无关改动引起——阴面通过，但没证明"是 fence 造成的差异"。
→ **成立的残余**。回应（限定）：阴面 diff 必须最小化——阴夹具与阳夹具的 diff 行数作为机器信号采集（建议 ≤N 行，先记录不阻断）；红队盲读时阴面 diff 是必看项（它比看阳夹具便宜得多，只看 diff）。彻底机器判定"单变量"不可行，承认这是留给红队的语义点，但工作量从"通读全卡"降为"看一个 diff"。
**攻击 1c：阴面让程序崩溃而不是读数变化。** 删机制导致 UB/崩溃，rc≠0——v1 规则已接受"rc≠0 也算翻转"（03 §3.1.1 写了 key 变化或 rc≠0），但 Writer 可以写个必崩的阴夹具（除零）冒充"机制破坏"。
→ 回应：阴面 rc≠0 时必须通过一个额外形式检查——崩溃点必须在夹具的机制相关行（v1 做不到机器判），故 v1 规定 **rc≠0 的阴面只算 half-credit**：需要红队确认或配一个"删机制但不崩溃"的第二阴面。先 warn 不 block，收集形态后再收紧。

**攻击 1d：成本攻击。** 每命题加阴面让弱模型生产时间翻倍，白嫖预算破裂。
→ 承认是真实代价。回应：阴面只要求"关键观测命题"（每张卡 1-2 条，不是每条）；且多 TU/已有多夹具的卡（如 EV-LANG 系列）天然就是阴阳面，零新增成本（FENCE 样板即用现有夹具）。若实测中位成本上升 >50%，V-iso 降级为只对 DAL A/B 强制。

## C2. V-honeypot 埋雷回归

**攻击 2a：雷库被针对性学习。** Writer（或模型）见过雷的形态后专门规避雷、用第 N+1 种形态。
→ 这正是军备竞赛残余。回应：雷库每季度注入红队新案例（血换的），且 trap_block_rate 只是信号不是唯一防线（V-iso 是性质层，不依赖雷）。承认它抓"回归"不抓"零日"。
**攻击 2b：埋雷脚本本身改坏仓库。** 活雷在沙箱跑，沙箱隔离有 bug 就污染正式工件（E09 竞态前科）。
→ 回应：honeypot 强制走独立 tempdir（P0-A 同款），禁止在 Examples/atoms 下跑活雷；CI 沙箱化是前置条件，不满足不上线。

## C3. synthesis 第三类

**攻击 3a：引用闭包造假。** synthesizes 列一堆真实 confirm 的卡，但综合结论与那些卡无关（引用灌水）。
→ 形式层拦不住（与 observation 自标同类）。回应：synthesis 永远人签 + 红队核验引用相关性是必查项；闭包验证只保证"积木是真的"，不保证"搭法对"——文档里诚实写明 synthesis 的机器保证边界。
**攻击 3b：反例清单选择性遗漏。** considered_counterevidence 只列容易反驳的。
→ 回应：红队职责显式包含"找未列入的反例"；kg suspect/极性算子可机械提示候选反例（概念同 subject 的对立命题）。承认无法机器穷尽。
**攻击 3c：三类边界争议导致 Writer 全标 synthesis 逃避阴面。**
→ synthesis 需要人签（比 observation 贵），逃避方向不经济；若实测发现滥用，把 synthesis 也加最小对照要求。

## C4. 概念受控词表

**攻击 4a：规范集本身写错/过早固化，逼真实新概念就范。**
→ 回应：受控化先 warn 后 block；规范集变更走和规则同级的毒样例+pytest 评审；保留 `proposed_concept:` 逃生槽（新概念进待确认队列，kg 单列不计连通），不堵知识增长。
**攻击 4b：人工聚类 157 短语的一次性成本被低估。**
→ 回应：若实测 >1 人天，砍范围——第一版只归一 subject（79 条命题的主语，量小），object 槽后置。承认这是范围可调的赌注。

## C5. LLM 判官 llm-screened

**攻击 5a：盲测集污染/过拟合（RHB 实测模型会对可见检查 special-case）。**
→ 回应：盲测集版本化、分域、对被评模型不可见（只在评估时由 CI 注入）、每批混入红队新真错误；EIR 用置信上界不用点估计。
**攻击 5b：判官与生产模型同族（自我批准）。**
→ 回应（硬约束）：判官必须是异族模型（02-B1：异质性才是安全判断有效的条件）；同族判官的筛查结果一律不认。单人单模型当前根本不满足 → G-llm-screen 物理上无法提前打开，这是个诚实的结论。
**攻击 5c：llm-screened 被下游当成 verified 用。**
→ 回应：教学导出只认 verified（§3.6）；llm-screened 在 kg/闪卡/book 三个出口都过滤；状态名带显眼前缀，且 gate 规则保证它不能作为 inference 的签署。

## C6. 信任开关状态机

**攻击 6a：指标博弈——为了开 G-router 伪造成本数据。**
→ cost_tracker 是 Agent 自报，能被注水。回应：路由决策数据只取 observability 的自动采集段（墙钟/退出码/卡数），不取自报 token；自报只用于趋势不用于开门。
**攻击 6b：开关抖动（指标在阈值附近来回，权限频繁收放）。**
→ 回应：enter 要连续 2-3 批满足、exit 立即触发（非对称迟滞，与 SOLiD 的 defer 思路一致：放权谨慎、收权果断）。

## C7. task_queue

**攻击 7a：worker 冒名 done 别人的任务。** 530 T7 已设计 claim 者一致性校验（pytest 钉）。✓
**攻击 7b：deps JSON 注入/环依赖。** → 回应：deps 只接受已存在 task id（外键校验）；建任务时做环检测（复用 kg DAG 思路），环拒绝入队。530 提示词未明确，补入施工。
**攻击 7c：队列变成新的永久负债（建好没人用）。** → 回应：8 周无真实任务自动标记封存并复盘（开关表里写了）；task_state.py 保留为退路，不是非此即彼。

## C8. 蓝图自身的"铺层罪"自查（针对我上轮批评建设者的同一把刀）
- V-iso/honeypot/task_queue/三分类/概念规范化：每一件都有当前 27 原子上的具体验收物或可复用夹具，不是"先建着"。
- LLM 判官/Supervisor/路由器/算子生成器/自动抽取：**全部只埋字段或攒数据，明确不建**（第 2 节开关 OFF + 05 路线图"等模型"档）。
- 唯一可能被质疑"过早"的是 synthesis 类——它的理由是当前 FENCE prop-1 归类已经尴尬（01 假设2 实证），且规则只 warn，不形成施工压力；若验收时认为不需要，删除该规则不影响其他模块（它是独立的）。

## 自我对抗总结
蓝图最大的赌注不是某个机制，而是**"V-iso 阴面的最小 diff 在实践中能被低成本维持"**——如果弱模型写阴面的成本/错误率太高，整套 observation 自动放权会停在人审，v8 退化为"多了几个 warn 的 v7"，但不会变坏（所有新规则 warn 起步、开关默认 OFF、可回滚）。这个下行风险有界，是我愿意下的注；它必须在第一批 5 颗带阴面原子生产后用真实成本数字复核（05 路线图设了检查点）。
