**关键设计矛盾（必须正面处理）**：194 与 17 不是"哪个对"，是两套口径（keep-low 投影 vs 严格大于）。炫酷做法不是藏，而是把**口径演化做成时间轴/切换器**——观众拖动滑块，519 节点坍缩成 121、194 击败边筛成 17，diff=0 的逐节点对齐过程本身就是最好的"严谨性表演"。

## 1. 引擎选型：三档，按"炫酷/通用/性能"选

| 方案 | 渲染/布局 | 规模与性能 | 许可 | 适配判断 | 来源 |
|---|---|---|---|---|---|
| **cosmos.gl v3**（`@cosmos.gl/graph`） | 力导向布局与渲染**全在 GPU**（vertex/fragment shader，TypedArray 零 GC） | 数十万节点边实时；v3 切 luma.gl/WebGL2、模拟与渲染分离（可冻结物理只渲染）、矩形/多边形框选、链采样 | **MIT** | **主推荐**：100 节点是"杀鸡用牛刀"，但牛刀保证永远不掉帧且有空间感 | S1 |
| **AntV G6 v5** | WebGPU/WASM 加速布局；内置 10+ 布局；**原生 3D 元素与 3D 布局** | 大厂维护（蚂蚁），中文生态，文档全 | MIT | 需要 DAG/层次/3D 场景复合时的备选；国内用户多 | S5 |
| **3d-force-graph + R3F**（vasturiano / Three.js） | Three.js 3D 力导向，InstancedMesh 一 draw call 上万实例 | 1 万独立 mesh 掉到个位数 FPS → InstancedMesh 稳 60；dpr 封顶 2、按需渲染 | MIT | 要真 3D 太空感、镜头穿越时选；工程复杂度最高 | S6 S7 S8 |
| Cosmograph 应用层 | cosmos.gl 的商业封装（2D/3D、时间轴、DuckDB 交叉过滤） | 百万级、SQL 过滤 | **CC-BY-NC-4.0，禁商用** | ⚠️ 不可用于 MIT 项目发行，只可本地玩；**只能用底层 cosmos.gl 引擎** | S2 S3 |
| Sigma.js v3 / Cytoscape | WebGL/Canvas + CPU 布局 | 实测 **7000 节点/16.6 万边就拖垮**（Stanford 演讲实测 sigma） | MIT | 规模或炫酷度都已不够 | S4 |

**结论【推断】：cosmos.gl（MIT 全 GPU）为主引擎，2D 星图主视图；节点点击聚焦时用 Three.js/R3F 做"潜入单卡证据链"的 3D 转场**。两层共享同一份归一化 JSON（见 §6），3D 只在详情层出现，不做全站 3D——纯 3D 力导向对可读性是损害（节点互相遮挡、边交叉不可读），业界共识是 3D 负责"震撼开场与沉浸"，2D 负责"读图干活"。

参考先例（论证/知识网络可视化已有学术与开源先例，不必从零发明）：

- **AgonProject**（2026-09，SAFA 2026）：浏览器内抽象论证框架编辑器，图上直接跑多语义求值并比较 IN/OUT/UNDEC——**和阙疑的 W2 标签几乎同构**，可直接参考交互。S9
- **PyArg 2.0**：AF/ASPIC+/ABA 的评估+可视化+解释算法（解释某论证为何不被接受），开源 Python+Web。S10
- **Argdown**（2025-12 v2.0）：纯文本 pros/cons 语法 → 论证图，Markdown 内嵌、可导 PDF/web component。S11
- **VIANA**（Konstanz）：五层视图（精读→关系抽取→论证重建→图探索），层间 morphing 无缝过渡、文本与图视觉锚定——**"卡详情 ↔ 星图"过渡的设计母版**。S12

## 2. 视觉编码：四态（五态）一眼可分，且色盲安全

状态色不能只用红绿（8% 男性红绿色盲）。推荐**色+形+光三通道冗余**：

| 状态 | 颜色（暗色底，建议） | 形状/描边 | 动效 | 对应数据 |
|---|---|---|---|---|
| machine-verified | 青绿 `#34d399` | 实心六边形（稳固） | 极慢呼吸辉光（2.4s） | gate pass |
| human-verified | 金紫 `#a78bfa`+金边 | 实心+外环勾签 | 外环静态微光 | human_authority |
| red-team-verified | 蓝青 `#38bdf8` | 实心+盾刻 | 静态 | 红队过 |
| draft / unknown | 灰 `#64748b` | 虚线描边空心 | 静止（不吸引注意） | UNDEC/draft |
| rejected/OUT/带例外 | 琥珀红 `#f87171` | 菱形或碎裂六边形 | **低频双闪**警示但不刺眼 | OUT/rejected/exception |
| abstain/挂起 | 琥珀黄 `#fbbf24` | 半填充（扇形 270° 缺口） | 缺口对应覆盖度 | 保形上界可视化 |

边的编码：

- **普通支持边**（命题→证据 observation）：细、低不透明度、无箭头
- **推论边**（inference）：同色但中分段虚线
- **击败边**（attack/defeat）：红橙、带箭头、贝塞尔微曲；严格击败（17）粗，投影击败（194）细——**粗细即口径**
- hover/选中：cosmos.gl v3 的 `highlightedPointIndices/outlinedPointIndices` 配置式高亮，邻居边自动加粗，非邻居压暗到 8% 不透明度（聚焦阅读）S1
- 节点大小：度数（degree）映射；外圈半径映射 cs_upper_bound 或闭包大小——**置信度变成空间占位**，而不只是数字

## 3. 分层叙事：不是一屏堆完，是"宇宙→星系→行星"三级缩放

参考 VIANA 的分层 morphing S12 与 Cosmos 产品的 2D/3D 切换 S3：

**L0 开场（Hero，首屏 8 秒）**：
- 全 GPU 星图从一个点爆发式生长到 100 节点/304 边（按域着色：MEM 蓝/CONC 橙/LANG 绿/HIST 紫…），36 个连通分量自然聚成 16 个"星系"（16 域），边像星座连线渐亮；
- 物理 2 秒后冻结（cosmos.gl v3 模拟/渲染分离，可 `stop()` 物理留镜头漫游 S1），用户滚动时不耗 GPU——满足"60fps + 不卡"；
- 一句大字："**37 张卡，每一条断言都有可复算的证据。**"（数字全部从构建产物注入，不手写）

**L1 星系（域视图）**：点击/悬停某域 → 镜头平滑推近（d3-zoom 式 transform 过渡），只留该域分量；右侧滑出卡列表面板。

**L2 行星（单卡详情）**：
- 卡变为中心恒星，命题为轨道行星（obs 实心/inference 空心），证据卡为被连线锚定的卫星；
- 点击任一证据 → 进入**证书视图**（见 `03_验证链展厅_证书可视化.md`）；
- 击败关系在此层用红色弧线从攻击命题打入，并标注 cred 值与轮次（3 轮收敛做成可播放的三轮动画：每轮 OUT 节点逐个熄灭——这是 W2 grounded 语义最直观的解释）。

**L3 时间轴（口径演化）**：底部时间尺 609→611→627，拖动播放 519→121 归一、194→17 严格化，右上角 `IN 114 / OUT 7 / UNDEC 0 · diff=0` 实时计数——**把审计结论变成 20 秒动画**。

- 点击节点：高亮+信息卡（claim 一句话、boundary 四档徽章、cs 上界、证书角标、"去书章"/"去证据"/"去视频"三链接）；

## 5. 性能预算（"秒开+60fps"的硬指标与兑现手段）

| 指标 | 目标（中端笔记本/手机） | 手段 |
|---|---|---|
| 首屏 LCP | <1.5s | 图谱数据构建期预计算成 Float32Array 二进制（cosmos.gl 原生格式 S1），gzip+br；首屏只载 100 节点（<50KB），3D/详情代码按需分包 |
| 帧率 | 交互期稳定 60fps | 全 GPU 布局渲染；物理冻结后纯镜头变换；`linkBlending:false` 关 alpha 混合提密图性能 S1 |
| draw call | 静态场景 <10 | 全图一个 InstancedMesh/一次绘制 S6 S8 |
| dpr | 封顶 2 | Retina 4–9 倍像素是隐形杀手 S6 |
| 空闲 GPU | ≈0 | 静态即停渲染循环（R3F `frameloop="demand"` / cosmos `pause()`）S6 |
| 降级 | 集显/老旧机自动降 | 检测 WebGL2 失败 → 退 2D Canvas 静态力导向（d3-force 预算 300 tick 预跑后只渲染）→ 再退静态 SVG；三级降级保证"打开就能看" |
| 大图谱未来 | 万节点 | cosmos.gl 数十万级已验证 S1 S4；布局结果缓存（与 golden 复用纪律同源），不重复模拟 |

## 6. 通用化：数据契约先行，引擎只是渲染器

**通用化是本方向最重要的架构决定**（brief 明确要求"不只是阙疑专用"）。定义一份中立 schema（构建期从阙疑数据导出，运行时渲染器零业务知识）：

```jsonc
// graph-bundle v1（gzip 后的 Float32Array + 轻量元数据）
{
  "nodes": [{"id","label","kind":"atom|evidence|proposition|chapter",
             "state","severity","domain","weight","confidence_bound",
             "url","cert_ref"}],
  "links": [{"source","target","type":"support|inference|defeat|prereq",
             "strength","caliber":"strict|projected"}],
  "epochs": [{"id":"609","node_count":519,"defeating":194,"labeling":{...}},
             {"id":"627","node_count":121,"defeating":17,"diff":0}],
  "clusters": [{"id","name","color","member_ids":[]}]
}
```

- 渲染器（建议名 **Verdict Atlas** / 中文"判词星图"）只认这份契约：任何"节点带状态、边带类型、可选时间轮次"的知识验证项目（形式化证明库、供应链 SBOM 依赖图、审计 finding 网络、Argdown/PyArg 产出）都能喂同一渲染器；
- 适配器模式：阙疑写一个 Python 导出器（`prop_network_inventory + pck + 609/627 台账 → graph-bundle`），与 400 工具同语言、可进 CI、产出锁哈希——**图数据本身也成为可验证工件**，呼应项目宪法；
- 渲染器独立 MIT 仓库发布（npm package + 无框架核心 + Preact/React 薄封装），这与方向二 queyi-core 的分发、方向三证书查看器组成同一套"可复用验证 UI 三件套"。
