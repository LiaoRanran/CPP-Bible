# 方向四 · 多感官：声音、触觉、物理动效与"展开节奏"

> 来源 [Sxx] 见 `99_来源清单.md`。
> 核心原则一句话：**多感官不是多放料，是让每个状态变化获得一个"对得上"的确认通道**——而且默认克制、可关、可降级。

---

## 1. 声音：零音频素材的实时合成是正解

### 1.1 技术事实

- Web Audio API 可直接用振荡器+噪声+包络合成 UI 音，无需任何 mp3/wav：零下载、零延迟（<1ms）、无离线失败、bundle 增量 0。已有 2.9KB gzip 的微库（TapTones，含 22 个预设：click/pop/toggleOn/error/sparkle…，**同库还内置 Vibration API 触觉配对**）；另有 Tiks 提供 10 种 UI 音、双主题（soft/crisp）、React/Vue hook、自动静音选项。S31 S32
- Tone.js（MIT，v15.4）是更重的完整框架（合成器/调度/效果），UI 微音效用不上；仅在未来做数据声音化（sonification）或互动音乐时引入。S30
- AudioContext 必须由用户手势启动（浏览器硬性要求）；音效默认音量建议 0.3，且每次重播前重置 currentTime。S30 S33

### 1.2 阙疑的声音设计表（少即是多）

| 场景 | 声音 | 规则依据 |
|---|---|---|
| 哈希重算通过/证书 sealed | 双音上行（C5→E5，约 120ms），"确认而非庆功" | 确认性动作才发声 S33 |
| 篡改被 verifier 拦截 | 柔和低音短警（saw 低频、≤180ms），**不惩罚不刺耳** | 错误音应告知不惩罚 S33 |
| 击败边三轮播放中 OUT 节点熄灭 | 每轮一声极轻单音，音高随轮次微降 | 声音编码进度 |
| 内存剧场 alloc/free | 轻"啵"/低"咔"，hover/指针光弧**无声** | 高频交互不发声 S33 |
| 步阶播放执行行 | 默认**无声**（教学节奏音会迅速变烦），可在设置开"节拍器"档 | 打字/键盘类不配音 S33 |
| 知识星图入场生长 | 一声 1–2s 的环境 pad（可选，首次访问） | 品牌时刻 |

强制工程项（来自 UI 音频审计规则集 S33）：

1. 每个声音必有视觉等价（声音从不单独承载信息）；
2. 全局声音开关 + 独立音量，持久化到本地偏好；
3. `prefers-reduced-motion: reduce` 时默认静音（作为声音敏感代理）；
4. 绝不给 hover、逐次按键配音；
5. 首次访问不自动响——等第一次点击后 AudioContext 才解锁。

## 2. 触觉：能做，但边界要诚实

- `navigator.vibrate(pattern)`：毫秒数组模式（振-停交替），**Android Chrome/Edge/三星/WebView 全支持，需用户手势**；**iOS Safari 全版本忽略**（API 存在但不接马达，Apple 限制）；桌面无硬件静默失败；不能控制强度（只有时长）。S34 S38
- iOS 17.4–26.4 曾可用"隐藏 checkbox switch 副作用"骗出 Taptic Engine（单击/确认双击/错误三击库 ios-haptics），**Apple 在 iOS 26.5 已修补**——不要把产品建在 hack 上，真实 switch 交互的原生反馈可保留，程序化三击模式不要依赖。S39

阙疑用法（渐进增强，不支持就无感降级）：

- Android 上"验证通过"= `[15]` 轻一击；"篡改拦截"= `[30,40,30]` 双击；拖拽框选节点到位 = `[10]`；
- 与 TapTones 同一调用点音+震一起触发（库已内建配对 S31）；
- 桌面/iOS 用户只看到视觉动画——三通道（视/听/触）任一缺失不损失信息（呼应 S33 视觉等价规则）。

## 3. 动效引擎选型：按层级分，不引全家桶

| 需求 | 选型 | 依据 |
|---|---|---|
| 通用微交互/布局过渡/滚动入场 | **CSS + Web Animations API + View Transitions API** | View Transitions 已全主流可用（Chrome111/Edge/Firefox144/Safari18），SPA 同文档+MPA 跨文档都行，浏览器接管快照插值，代码量极小 S40 S41 |
| 复杂时序编排（剧场多对象、证书链点亮） | **GSAP**（免费部分够用；ScrollTrigger 做滚动叙事） | 1000+ 并发动画稳 60fps，行业十年标杆；声明式库在 200–300 元素以上受 React 协调拖累 S34 |
| React 组件内弹簧/手势 | Motion（framer-motion 新版）或 react-spring | ~30KB、弹簧物理、与组件状态绑定顺手 S34 |
| 品牌角标状态机（证书盖章） | **Rive**（Canvas/WebGL WASM 运行时，状态机在编辑器里可视化配置） | 文件比等价 Lottie **小 10–15 倍**（240KB→16KB 实例），GPU 渲染、内存低 2–3 倍、60fps 到低端机；状态机驱动 idle→checking→sealed 正合其长项 S35 S36 S37 |
| 装饰插画/循环小动画 | 不引（Lottie 500KB 可吃 30% CPU 的教训 S37），需要时优先 Rive | — |
| 图谱与内存剧场 | cosmos.gl / 自研 Canvas 时间轴（见 01/02） | — |

**统一物理参数**（建立项目级动效 token，避免每个组件手感不同）：

- 标准弹簧：`stiffness 260, damping 26`（干脆无过冲感）；内容物用 `180/22`（轻柔）；
- 时长档：微反馈 120–200ms、面板过渡 240–320ms、场景转换 ≤500ms；
- 缓动：出场 `cubic-bezier(0.2,0,0,1)`（标准减速），入场可带回弹 0.02；
- 只动 `transform` 与 `opacity`（GPU 合成层），不动 top/left/width——实测把 margin-left 平移动画换成 translate3d 可把中端 Android CPU 从 45% 降到 12% S37b；
- `will-change` 同时不超过 5–7 个，防止 GPU 显存爆掉 S37b。

## 4. 节奏：分层展开（brief 说的"不是一下子全堆出来"）

- **首屏**：星图生长 2s（01 号 L0）；标题与 CTA 用 80–120ms 阶梯 stagger 依次浮现（View Transitions/WAAPI），总时长压在 1.2s 内，超过就成加载动画不是仪式；
- **滚动叙事**：GSAP ScrollTrigger 控制"信任三段式"段落（签→判→见证），每段进入视口时其图形成立（线条绘出、印章落定）；
- **详情层**：卡详情/证书页元素自顶向下四级 stagger（链时间线逐级点亮，各级 120ms），让眼睛有阅读顺序；
- **关闭即快**：退出/关闭动画时长 ≤ 入场的一半，不阻挡用户；
- IntersectionObserver 保证仅在屏内播放，滚过即停（省 GPU、不烦人）。

## 5. 无障碍与健康（炫酷的底线，缺了就是小作坊）

1. `@media (prefers-reduced-motion: reduce)`：关闭一切非必要位移/视差/生长动画，保留即时状态切换与不透明度淡入；View Transitions 提供 `prefers-reduced-motion` 跳过路径；声音默认关。S33 S40
2. 颜色不单独传意（方向一四态的形/光冗余同样适用全站）；
3. 动画不抢焦点、不造成布局位移（CLS=0）、尊重焦点环与 reduced-data；
4. 闪烁频率严格低于光敏阈值（警示用单次/低频双闪，不用高频频闪——红色边缘常亮替代）；
5. Lighthouse 性能/可访问性 >90 当组件级 CI 门槛（2026 一线开发者站的通行做法 S42）。
