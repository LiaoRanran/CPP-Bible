## 0. 目标：把"严谨"变成可以看见、可以亲手戳穿的东西

证书页的竞品不是其他教学站，而是两类成熟范式：

1. **区块链浏览器**（Etherscan 式）：任何人输哈希可查、时间线不可改、每笔"交易"可展开原始数据；
2. **供应链安全信任中心**（Sigstore/Rekor、SLSA、in-toto、OpenSSF Scorecard）：签名→证书→透明日志→包含证明的密码学叙事。

阙疑的 PCK（内容寻址 sha256 + M1–M7 负测试 + cs_upper_bound + provenance commit）在语义上已经是一套小型透明日志体系，**缺的只是把密码学仪式感翻译成视觉**。好消息：范式全部经过工业级验证，照其结构做即可。

## 1. 业界可抄的结构（一手事实）

## 2. 证书页（单卡）布局：一张"区块链票据"+ 四段验证链

```
┌─ 证书头：ATOM-MEM-MOVE-002 · machine-verified ● ─────────────┐
│ claim 一句话（中英）            状态徽章（四态+DAL色）         │
│ boundary: [std=C++17,20,23] [GCC15/Clang22] [-O0,-O2] [x86-64]│
├─ 指纹区（仪式感核心）───────────────────────────────────────┤
│ sha256:d8d6…f256  [现场重算 ✓]  ← 打开页即静默用 Web Crypto  │
│ 工件: evidence/mem/EV-MEM-001.md → .out/.asm（可下载）        │
│ 哈希比对动画：记录值与现场值两串十六进制逐位对勾（~600ms）     │
├─ 验证链时间线（in-toto 式 materials→products，竖向流动）──────┤
│ ① 标准层  ISO/cppreference/N1570（来源链接、抓取 sha）        │
│ ② 执行层  GCC 15.3 -O2 · 命令行可复制 · 真机构件（materials） │
│ ③ 判决层  gate_engine pass · 67 规则命中清单（可展开）        │
│ ④ 保护层  B1冲突? B2 windup? B3盲审? B4校准? B5 MDL → 全绿/挂起│
│ ⑤ 人审层  reviewer · method · 时间戳（unsigned 卡显式标"无人审")│
│ 每段右侧状态点，连线从上到下"点亮"动画（800ms 流式，方向四 §3）│
├─ 负测试区（最有差异化、最该炫的部分）─────────────────────────┤
│ M1 删sha → blocked ✓   M2 路径大小写 → blocked ✓ … M7 改读数 │
│ 交互：[喂入一个篡改] 按钮——读者改一个数字，verifier(wasm/      │
│ Pyodide)当场拒绝，红色 X 动画 + 声音（可选）。这是"亲手戳穿"  │
├─ 置信区 ────────────────────────────────────────────────────┤
│ cs_upper_bound=0.0091 仪表盘（半圆 gague，挂"分布无关/口径"）  │
│ 挂起率/覆盖度小图（与 v31 保形弃权路线衔接）                  │
├─ provenance：commit(可点 GitHub) · 工具版本 · prompt/rubric  │
└────────────────────────────────────────────────────────────┘
```

设计要点：

- **默认折叠原始 YAML，默认展开"人话结论+可点证据"**；Etherscan 也是摘要在上、raw data 在 tabs；
- 每个"✓"都是可点击的——点哈希看工件、点规则看规则定义、点人审看 ledger 事件，**没有不可追溯的图标**（这本身是信任语言）；
- 离线/无 JS 降级：`<noscript>` 与静态构建时直接给出"构建期已校验"结论（Cosign v3 离线哲学 S25）。

## 3. 全局视图：判决检索台 + 信任总览

三个页面构成展厅：

1. **证书页**（§2，单卡深读）；
2. **判决检索台（Rekor Search UI 静态版）**：
   - 全量 ledger 事件表（序号/时间/对象 id/动作/结果/签署者），客户端搜索过滤、按对象聚合；
   - 每条展开 raw json + 前后哈希（Merkle 链微缩图：本事件哈希由 prev_hash+payload 决定，篡改任意一处，链从该点之后全部变红——可做"拖动篡改滑块"小互动）；
   - 这就是"区块链浏览器感"，但**诚实标注：这是仅追加账本，不是工作量证明区块链**（命名克制，不蹭概念）。
3. **信任总览（首页 Trust 区）**：
   - 顶部数字带（构建期注入）：**37 卡 · 120 组真机编译 · 57 ASM 锚定 · 21 变异全 blocked 量级 · 0 真实危险逃逸**；
   - 证书状态甜甜圈（verified/unsigned/draft/rejected）+ 36 连通分量迷你星图（复用方向一组件，点入即星图 L1）；
   - "如何验证我们"三行命令 + `uvx quyi verify`（v31 已定的分发）；
   - OpenSSF 风格徽章（自有 SVG，构建期生成，不引外部第三方徽章服务——避免外链即信任的反讽）。

## 4. 视觉与动效语言（与星图、剧场统一）

- 深色底 + 单色强调；加密学元素用"刻蚀/金属细线"质感（细 1px 描边、等宽字体、微光），不要金融科技式金币/锁链俗套；
- 验证过程动效：状态点自上而下点亮、哈希逐位打勾、链连接用极细光线；失败用红但不闪烁、不恐吓；
- 成功的微仪式：现场重算通过后，证书角标轻微"盖章"动效（Rive 状态机最合适：idle→checking→sealed，单文件 10–20KB，比 Lottie 小一个数量级 S35 S36；此处值得用 Rive，其余页面不引入）；
- 节奏：证书页首屏 <1s 出摘要，哈希重算在 idle 时静默完成，动画仅在用户视线内播放（IntersectionObserver）；全程遵守 `prefers-reduced-motion`（方向四 §5）。

## 5. 通用化

- 证书渲染器同样 schema 驱动：`verifiable-claim v1` = `{claim, boundary, fingerprint:{algo,value,target_ref}, chain:[{stage,actor,evidence_ref,status}], mutation_tests:[{id,result}], bound, provenance}`；
- 任何"断言+工件哈希+多步验证记录"的项目（SBOM attestation、测试覆盖声明、实验复现证书）都能渲染；
- 现场验证用 Web Crypto（sha256 已是所有现代浏览器标配）+ Pyodide 跑复杂规则；纯静态、可嵌入任何文档站/博客（web component 形态，与 Argdown 的嵌入路线一致 S11）。
