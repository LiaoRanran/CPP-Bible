# 02 · 靶位 B：自身免疫率 / 误报度量框架

> _arch_v23 深度调研 · 2026-09-23 · 外部信息访问日期 2026-09-23。
> 术语对齐：阙疑"自身免疫率"= 验证系统把**正确/合规知识**误判为错误（false positive / false alarm / Type I error）的比率；"逃逸率"= 错误知识通过验证（false negative / miss / Type II error）。
> 标注约定同 01。本文给外部阈值与推导，不给工程实现；B5 的阈值是**带置信度的建议，最终由人裁决**。

## B1. 免疫系统怎么量化"自身攻击"

- **正常系统并不清零自反应细胞，而是容忍+压制**：健康人外周成熟 B 细胞中有 **5-20%** 编码多反应/自反应抗体——中枢删除（阴性选择）**故意保留**相当比例的潜在自反应淋巴细胞，靠外周 anergy（功能性失能）与 Treg 压制【已查证】https://www.frontiersin.org/journals/oncology/articles/10.3389/fonc.2022.894015/full ；综述同样指出"即使在中枢与外周容忍的严格监视下，仍有少量自反应淋巴细胞漏入正常人外周"【已查证】https://doi.org/10.1111/joim.12395
- **关键设计哲学**：免疫系统**不追求零自身免疫**。零自反应意味着零免疫库宽度（无法识别新病原体）；它接受"5-20% 细胞具有潜在自反应性但处于失能态"作为常态，把防线放在**激活控制**（需要共刺激信号才开火）而非删除干净。
- **临床自身免疫病的群体发病率很低**：80-100 余种自身免疫病；多发性硬化在西方国家约 **1/1000**（全球患者约 230 万）【已查证】https://pmc.ncbi.nlm.nih.gov/articles/PMC7925481/ 。即"潜在自反应细胞 5-20%"与"临床发病约 0.1% 量级"之间隔着多层激活门槛——**潜在误报能力高，实际误报开火率被多层压到极低**。
- **trade-off 的直接医学证据**：免疫检查点抑制剂（抗癌药，解除免疫刹车）通过降低对肿瘤的容忍来杀癌，但同时**必然**降低对自身的容忍——irAE（免疫相关不良反应）与疗效正相关；治疗本质上是人为把"逃逸率/肿瘤漏检"下调、以"自身免疫率"上升为代价【已查证，同 Frontiers 链接】。
- **可迁移的量化原则（推断）**：
  1. 度量对象不是"系统有没有误报能力"，而是"误报**开火率**"（失能态库存不算发病）；
  2. 双层指标：**库存自反应率**（规则库里有多少条可能误伤的宽规则）与**激活自免疫率**（真正被这些规则拦下来的正确卡片比例）——前者可以高，后者必须低；
  3. trade-off 是单调的物理事实，不是管理失误：加强检测必然升高误报，医学上没有免费午餐（与 B4 的 α-β 单调性同构）。

## B2. 回归测试/flaky test 的误报度量（与阙疑最同构的工程域）

- **术语区分（重要）**：软件工程把"测试在代码无变更时间歇失败"叫 flaky（噪声型误报），把"测试稳定地拒绝正确代码"叫 false failure/over-strict test（规则型误报）。两者都是验证系统对好代码开火。
- **工业实测数据**【已查证-汇编自各公司工程博客/论文，URL 内逐条引源】https://www.getpanto.ai/blog/flaky-test-statistics https://wopee.io/blog/flaky-tests-complete-guide/ ：
  - Google：约 **16% 的测试**存在 flaky 行为；单次执行 flaky 率约 **1.5%**；**84% 的"绿→红"转换由 flaky 引起而非真回归**（Google Testing Blog 2016/2017，420 万测试规模）；
  - Microsoft：约 **26% 的不同构建**受 flaky 影响（Lam & Godefroid, ISSTA 2019）；另有口径称测试失败中 13-25% 由 flaky 导致；
  - Meta（Machalica 等 2020）：单元测试 flakiness **远低于 1%**，E2E 约 **10%**——**测试层级越低，工业界容忍阈值越严**；
  - GitHub：9% 的提交触发至少一次 flaky 红构建（2020）；
  - Atlassian：后端 15%、前端 21% 的构建失败来自 flaky；治理前年耗约 15 万开发者小时；
  - 学术工业案例（Kowalczyk 等，TUM）：flaky 调查与修复吃掉约 **2.5% 的总开发者时间**。
- **信任侵蚀的临界点（最重要的定性结论）**：当团队形成"红 CI 大概率是 flaky"的预期后，**真回归也不再被调查**——Martin Fowler 2011 名言"非确定性测试有两个问题：无用，且是能感染整个测试套件的病毒"【已查证】https://martinfowler.com/articles/nonDeterminism.html ；Meta 的口径是"每个真实测试多少都 flaky，问题不是有没有，而是有多 flaky"，即把它当**连续度量**而非二元分类【已查证，wopee 引 Meta Engineering 2020】。
- **复合效应数学**：300 个单测各 0.5% flaky 率时，整轮全绿概率 0.995³⁰⁰≈22%，即 78% 的运行至少含一次假失败——**套件级误报率随规则数指数累积**，单条规则"看着很低"的误报率不能代表系统级体验【已查证，wopee】。
- **可迁移原则**：
  1. 工业界把"误报导致的失败占全部失败比例"作为核心健康指标（Google 84% 是反面基准），阙疑应对标定义：**全部"拦截/判错"事件中，事后被确认为误判的比例**（自身免疫事件占全部警报的比例）；
  2. 分层阈值：快速层（类单元测试=机械规则）应 <1%，慢层（类 E2E=模型判官/人审）可容忍约 10%——与 SOC 经验一致；
  3. 工业界没有公开的"统一法定阈值"：1% flakiness 预算是行业惯例非推导值，Google/Microsoft 的内部具体阈值未公开【已查证】https://dev.to/qapilot/flaky-tests-persist-because-everyone-is-ignoring-them-rationally-4m4h ——任何外部阈值都只能作参照系。

## B3. 安全检测（SOC/IDS/反欺诈）的误报阈值

- **SOC 告警现状**：Microsoft/Omdia《State of the SOC 2026》：平均 **46%** 告警为误报；不同研究区间 46-83%；平均每分析师每天约 2992 条告警，63% 完全未被处理；73% 安全团队把误报列为头号检测挑战【已查证-二手汇编引原始报告】https://www.vectra.ai/topics/alert-fatigue https://www.secure.com/blog/soc/soc-alerts
- **成熟度阈值（行业梯度，非标准）**【已查证】https://nflo.tech/knowledge-base/soc-metrics-mttd-mttr-kpi-security/ https://www.zerodaycyberacademy.com/ressources/soc-blue-team/detection-intrusion-les-bases ：
  - 世界一流/成熟团队：误报率 **<10-15%**（被普遍视为"强结果"）；
  - 良好可接受噪声：20-40%；
  - 40-60%：告警疲劳开始出现；
  - **单条成熟检测规则的调优目标：FP rate < 5%**；
  - 健康检查：64% 分析师时间花在误报上即人员流失/漏报拐点（Ponemon 2024，【一方称】）。
- **反欺诈域（成本最显式的领域）**：
  - 规则系统：检出 60-75%、误报 5-10%；ML 系统：检出 92-98%、误报 1-3%【一方称-行业文汇编，未回 Juniper/Riskified 原始报告】https://ecosire.com/es/blog/ai-fraud-detection-ecommerce-guide ；
  - 支付系统设计面试的公开口径目标：抓住 >99% 欺诈同时只挡 <0.1% 合法交易（内联硬拦截 <100ms，可疑走异步/step-up 而非硬拦）【一方称】https://systemdr.systemdrd.com/p/design-a-payment-fraud-detection ；
  - **成本矩阵决策法**：阈值不由"准确率"定，而由四类成本定——p\* = (C_FP−C_TN)/[(C_FP−C_TN)+(C_FN−C_TP)]；示例（£）TP=5/FP=40/FN=120/TN=0 得最优阈值 0.258，用默认 0.5 多花 14.6% 总成本【已查证-方法论文章】https://dev.to/multigrid/choosing-a-decision-threshold-with-real-costs-45d7 ；
  - 行业经验比：每 $1 欺诈直接损失对应约 $30 合法销售因摩擦损失（"false declines 比欺诈本身更贵"），所以支付域**硬拦截误报权重远高于漏报**，可疑交易走"加验证"而非"拒绝"。
- **可迁移原则**：
  1. 阈值必须从**两类错误的成本比**推导，不存在脱离成本的"可接受误报率"；
  2. 成熟工业系统普遍用**三级分流**（硬拦/加验证/放行）而非二元判决——阙疑对应 block/warn/abstain 三态，误报代价高的地带应默认走"加验证"（人审/他验）而非"硬拦"；
  3. 单规则 <5%、系统级警报中误报占比 <15% 是两个可参照的数量级（分别对应 Meta 单测与成熟 SOC 口径）。

## B4. 假设检验 α/β：最严格的误报-漏报理论

- **定义**：α = Type I error = 假警报（H₀ 为真却拒绝，即"正确知识被误判"）；β = Type II error = 漏报（H₁ 为真却未拒绝，即"错误知识逃逸"）；power=1−β【已查证-教材】https://nbisweden.github.io/workshop-mlbiostatistics/docs/SM4LS-book/SM4LS-inference/infe_04multiple.html
- **核心性质**：
  1. **样本量固定时 α 与 β 单调反向**——压低误报必然抬高漏报，唯一的免费午餐是增大样本量/信息量（Neyman-Pearson）；
  2. α=0.05 是惯例不是定理，源于 Fisher，且只对**单次检验**成立；
  3. 多重检验膨胀：m 次独立检验至少一次假阳概率 1−(1−α)^m——α=0.05 时 20 次检验即 64.2%【已查证】https://api.rpubs.com/hung/1364583 。
- **两类校正**：FWER（Bonferroni α/m，控制"至少一次假阳"，极保守、牺牲功效；适合 m<20、不能容忍任何假阳）；FDR（Benjamini-Hochberg，控制"所有发现中假阳比例"的期望，探索性大批量筛选用，常取 q=0.05）【已查证，教材同上】。
- **基率谬误（对阙疑最关键）**：在低基率域，即使 α=0.05、power=0.8，**通过的判决里假阳比例仍可极高**——例：100 个药只有 10 个有效，最终 13 个"显著"结果中 5 个（38%）是假的【已查证】https://api.rpubs.com/hung/1364583 。**判决可信度取决于基率，不只取决于 α。**
- **阙疑逃逸率 1/1406 的框架归属**【推断】：它是**观测到的失败事件/总试验**的经验比例，外面套的 CS anytime 上界（0.9062%）和 C-P 95% 上界属于"对二项比例的置信上界"，控制的是"漏报率未知但以 1−δ 概率不超过上界"——即阙疑至今严格控制的是 **β 侧（逃逸/Type II）**；自身免疫率对应 **α 侧**，但阙疑目前从未报告 α 的点估计或上界。
- **自身免疫率应该对应什么 α（推断）**：不应直接抄 0.05。理由：
  1. 阙疑的判决是**反复、批量、持续累积**的（卡片数千、规则数十、跨批次重判），实际处于"多重检验"情境，名义 α 必须按检验族校正才有系统意义；
  2. 阙疑域基率极低（真实错误知识是稀有事件，1406 中 1），在低基率域假阳会主导警报池——B3 的 SOC 46% 与 B4 的 38% 都是同一机制；
  3. 但阙疑误报的**成本结构低于支付域**：误判卡片为可疑的代价是复审工时（warn），不是拒绝客户；只有**硬拦截/拒绝入库**级别的误报才接近支付硬拦成本。因此 α 应按判决动作分级，而非全系统一个数。

## B5. 阙疑自身免疫率的可接受区间建议（建议，需人裁决）

> 置信度声明：以下区间为跨域外推【推断】，非任何外部标准对"知识验证系统"的规定；外部阈值来自测试/SOC/支付/统计四类异构系统，迁移时已按成本结构折算。629 A 线首次实测后应以实测分布回填校准，本节只给先验参照系。

**建议 1：定义两个分子，不要一个比率。**
- **自身免疫开火率（硬）** = 被硬判 reject/block 后经复核确认正确的卡片数 / 全部硬判事件数。这是"发病指标"，参照成熟 SOC（警报中误报 <10-15%）与支付硬拦（<0.1% 目标）之间，按阙疑硬拦成本（知识项目，可逆性中等）建议**先验目标 ≤5%，上限 10%**（置信度：中；依据：单条成熟检测规则 5% 与 Google 级测试纪律之间）。
- **自身免疫警报率（软）** = warn/送审事件中事后确认无问题的比例。参照 SOC 良好区间 20-40% 与规则型欺诈 5-10%，建议**先验目标 ≤20%，疲劳警戒线 40%**（置信度：中；40% 是 SOC 文献中疲劳"开始出现"的分级点）。

**建议 2：定义一个分母——库存误伤面。**
- 用一个**已知正确语料库**定期跑全量规则，报"在好知识上触发任意规则的比例"（类比免疫库的自反应细胞库存 5-20%、Google 测试库 16% flaky 存量）。这个数**允许较高**（它衡量规则库的潜在宽度，不衡量发病），但必须：①单调监控，突然上升即回归警报；②区分 warn 触发（可宽）与 block 触发（应近零）。
- 套件级用复合公式估算：P(至少一次误报)=1−(1−p)^n，n=卡片数；若单卡 p=0.5%、n=300 已 78% 的运行至少一次假警报——**规则/卡片规模上量后必须从单规则阈值转向 FDR 口径**。

**建议 3：触发动作（分级响应，类比多重检验校正与 SOC 调优）。**

| 观测 | 建议动作（只建议） | 外部对应 |
|---|---|---|
| 硬开火率 ≤5% | 维持 | 成熟检测规则 <5% |
| 硬开火率 5-10% | 该规则降级为 warn（先加验证不硬拦），登记 | SOC 10-15% 强结果上限 |
| 硬开火率 >10% 或单规则在正确语料上误伤显著 | **规则停用/重审（规则退役）**，等同测试界 quarantine flaky test | 内核社区"回归是最高罪"+测试隔离 |
| 软警报率 >40% | 告警疲劳警戒：该层规则批量调参/合并，防止人审橡皮图章化 | SOC 疲劳出现线 |
| 同批重判导致历史正确卡片大面积改判 | 按"回归"处理，最高优先级，可回退 | Linux 回归政策 |

**建议 4：逃逸率-自身免疫率 tradeoff 的处理。**
- 不要追求两条曲线的交点，要用**成本矩阵**（B3）：C_FP（误伤好卡片：复审工时+知识流失+作者信任损耗）与 C_FN（错误逃逸：品牌损害+教学污染）赋值后人裁；
- 外部经验一致指向：**在低基率域，先压低误报、用多一层"加验证"补漏报**，优于二元放宽阈值（支付业 step-up、SOC 分级、免疫的共刺激激活门控同构）；
- 信息量（毒样例/正确语料样本量）是唯一免费午餐——扩大双侧样本（更多毒样例+更大正确语料）才能同时改善两边，这与 629 共建两类语料一致【推断】。

**建议 5：与逃逸率并列的报告口径。**
- 每次对外给逃逸率上界时，同屏给自身免疫开火率点估计与样本量（对称原则：只报 β 不报 α 在统计学上是不完整的判决报告）；
- 卡片级判决标注 α/β 身份（"硬判/软判/弃权"），为未来 FDR 口径留结构——当规则数与判决数继续增长，单点 α=0.05 式表述会失去系统意义，需改用 FDR（BH 式"全部警报中误报占比"），软警报率其实就是 FDR 的经验对应物【推断】。

**B5 置信度总评**：方向（双侧度量、分级阈值、成本矩阵、FDR 口径）置信度高（四个独立领域同构）；具体数字（5%/10%/20%/40%）置信度中（跨域外推+部分数字来自二手汇编）；任何阈值在 629 实测前都只是先验，**最终阈值必须由人裁决并随实测校准**。
