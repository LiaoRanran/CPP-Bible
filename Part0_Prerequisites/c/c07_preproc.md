# C7 预处理：你写的 ≠ 编译器看到的

> 参考：《C 语言极致详解手册》。编译器 GCC 15.3.0（`gcc -std=c11`），所有输出为本机真实运行产物。
> 示例源：`c/_demo/c07_preproc.c`

## ① 我们真正要回答的问题 <span class="badge badge-std">标准</span>

1. `#include <stdio.h>` 到底把什么塞进了我的文件？为什么一个 30 行的源能编出几百行？
2. 宏 `MAX(a,b)` 和函数 `max(a,b)` 哪里不一样——为什么我传 `MAX(i++, j--)` 会出鬼？
3. `#` 和 `##` 是什么鬼；`__VA_ARGS__` 怎么让一个宏接任意参数？

> 判决先行：**预处理发生在词法/语法分析之前，做的是「纯文本记号替换」——它不求值、不检查类型、不算优先级、不懂 C 语义。** 你眼里的 `MAX(a,b)` 和编译器后面拿到的 `a>b?a:b` 根本不是同一段东西。本章所有事故，都源于「文本替换 ≠ 语义调用」这一个事实。

> 历史注脚：`ritchie:chist` 提到早期 C 没有真正的预处理器，分文件靠 BCPL 式的 `GET`/`INCLUDE` 文本并入；现代的 `#include` / `#define` / `#if` 是随后引入，最终独立成一个 `cpp` 程序。**至今预处理仍是编译流水线的「阶段 4」（N1570 5.1.1.2），在词法分析之前**——这正是「它不懂 C」的根本原因。

## ② 证据一：`#include` 是文本搬运工

把 `c07_preproc.c` 交给预处理器、丢弃行号标记：

```text
$ gcc -E -P c07_preproc.c | 行数统计  →  676 行
```

一个 30 行的源，预处理后变成 **676 行**——多出来的全是被 `#include <stdio.h>` 文本搬进来的声明。`#include` 不是「导入模块」，是**把另一个文件的内容原样贴到你这行所在的位置**。这就是为什么头文件要加 include guard（`#ifndef X_H`）：同一个头被贴两次，就会重定义。

## ③ 证据二：宏是替换，不是调用（两处真机事故）

### 事故 A：参数被求值多次 → 未定义行为

```c
#define SQUARE(x) ((x)*(x))
int r = SQUARE(i++);   /* 展开为 ((i++)*(i++)) */
```

真机（GCC 15.3，`-Wall -Wextra`）——编译器当场警告，运行给出反直觉结果：

```text
c07_preproc.c:21:21: warning: operation on 'i' may be undefined [-Wsequence-point]
SQUARE(i++) 初值 i=3 -> r=12, i=5  (期望 r=9,i=4；实为 UB)
```

`i` 在一个表达式里被**两次自增、且无序列点**，标准判定为**未定义行为**。本机恰好算出 `r=12`（两次读取拿到 3 和 4），`i` 变成 5——但换编译器/优化级别结果会变。**永远别给宏传带副作用的实参。**

### 事故 B：缺括号的优先级坑

```c
#define MAX_BAD(a,b) a>b?a:b
#define MAX_OK(a,b)  ((a)>(b)?(a):(b))
```

真机：`2 * MAX_BAD(3,4)` 展开成 `2 * 3 > 4 ? 3 : 4`，先算 `2*3=6`，因 `6>4` 为真才取 3：

```text
2*MAX_BAD(3,4) = 3   (人期望 2*4=8)
2*MAX_OK (3,4) = 8
```

宏的每个参数、整个表达式都**必须加括号**，否则嵌进别的表达式就按 C 运算符优先级重新结合——这是宏比函数危险的第二根刺。

## ④ 证据三：`#`、`##`、可变宏

```c
#define CONCAT(a,b)  a##b          /* 记号粘贴 */
#define STR(x)       #x            /* 字符串化 */
#define LOG(fmt,...) printf("[LOG] " fmt "\n", __VA_ARGS__)
```

真机：

```text
CONCAT(num,7)=42 ; STR(Hello)=Hello
[LOG] x=10 y=20
```

`##` 把左右两个记号拼成新记号（`num`+`7` → 标识符 `num7`，编译期就存在）；`#` 把参数变成字符串字面量；`__VA_ARGS__` 收集「格式串之后的所有参数」。这三者是「代码生成」的基石，也是宏地狱的源头（展开层层嵌套，报错信息晦涩到无从下手）。

## ⑤ 立场：什么时候用宏，什么时候别用

> 立场：[标准] 预处理指令（6.10）只做记号级替换，不做类型检查、不求值——这是它与函数的本质区别。`_Generic`（C11）能在编译期做类型分派，比宏泛型安全。
> 立场：[实现·GCC15.3] `-Wall -Wextra` 已能抓 `-Wsequence-point`（多次求值）、`-Wformat` 等一大批宏相关隐患；把警告当错误（`-Werror`）能挡住多数宏坑。
> 立场：[经验] 守则：**①能写 `static inline` 函数就别写无副作用宏；②宏参数与整体都加括号；③绝不给宏传 `i++`/`x++`/`f()` 这类带副作用实参；④类型泛型优先 `_Generic` 而非宏文本替换；⑤头文件永远加 include guard（或 `#pragma once`）。**

## ⑥ 小结与路线图

预处理 = 编译前的纯文本替换：`#include` 搬运、`#define` 记号替换、`#if` 条件裁剪；宏的两次求值与缺括号是两大经典事故；`#`/`##`/`__VA_ARGS__` 是代码生成工具也是调试噩梦。

下一章（C8）讲标准库：`string.h`/`stdlib.h` 里的函数「不替你管边界」，事故从文本层换到内存层——`strcpy`/`strncpy`/`memcpy` 的坑，和第 ⑥ 条守则一脉相承。
