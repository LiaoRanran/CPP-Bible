# C1 C 语言概述与核心哲学（对照 C++）

> 参考：《C 语言极致详解手册》。编译器：GCC 15.3.0（`gcc -std=c11`），与本书 C++ 部分同工具链。

## ① 我们真正要回答的问题 <span class="badge badge-std">标准</span>

1. 已经有了现代 C++，为什么还要学 C？C 到底「是什么」？
2. C 的设计哲学是什么？为什么 50 多年过去它还在操作系统、嵌入式、数据库内核里不可替代？
3. C 和 C++ 到底差在哪？为什么说「C++ 是 C 的超集」又不全对？

先给判断：**C 是「离金属最近的高级语言」。** 它几乎不给抽象税，程序员对每一字节、每一次内存访问都负有直接责任——这正是 C++ 的「零成本抽象」思想的根源。不懂 C，你理解的 C++ 永远差一层「为什么」。

## ② C 是什么：贴近硬件的高级语言

C 诞生于 1972 年，Dennis Ritchie 为写 UNIX 而设计。它的本质是**「中级语言」**：

> 历史注脚：`ritchie:chist` 里 C 不是凭空设计，而是被硬件**逼**出来的。前身的 B 语言（源自 Martin Richards 的 BCPL，Ken Thompson 为早期 UNIX 写在 PDP-7 上）只有「字」、没有类型。等到机器换到 **PDP-11——字节可寻址**——「字模型」撑不住了：同一地址既要当指令也要当 `char`/`int`。Ritchie 于是给 C 加了类型与结构体，却**保留了 BCPL 的指针算术**（地址直接加整数）。这就是为什么今天 `p+1` 跳过「一个元素」而非「一个字节」——C 的指针从根上带着 BCPL「地址即整数」的基因，不是后来打的补丁。

- 高层侧：结构化控制流（`if`/`for`/`while`）、函数抽象、类型系统、模块化编译（分别编译 + 链接）。
- 低层侧：直接内存访问（指针）、位运算、近乎一对一映射到机器指令、对硬件寄存器和内存布局的精细控制。

```text
        高级语言特性                低级语言特性
     ┌──────────────┐          ┌──────────────┐
     │ 结构化控制流  │          │ 直接内存操作  │
     │ 函数抽象      │          │ 位运算       │
     │ 类型系统      │    C     │ 裸指针       │
     │ 模块化编译    │          │ 内联汇编     │
     └──────────────┘          │ 硬件寄存器   │
            \                    /             │
             \                  /              │
           ┌────────────────────────┐          │
           │   C：「中级语言」        │──────────┘
           │   高效 + 可控           │
           └────────────────────────┘
```

> 立场：[经验] C 的「信任程序员」哲学意味着：编译器默认不替你做边界检查、不初始化内存、不阻止你解引用野指针。这些「不做」换来的是可预测的性能与极小的运行时依赖——代价是全由程序员承担正确性的重量。C++ 继承了这份重量，又用类型系统、RAII、`std::` 容器试图减轻它（见主书 part04/part05）。

> 历史注脚：所谓「信任程序员」（trust the programmer）是**后世对 C 哲学的概括，并非 K&R 原词**——K&R 在 *The C Programming Language* 序言的原文是 "C is not a big language, and it is not well served by a big book"；引言更点明「把语言保持在小尺寸有真实收益：程序员可以合理期望通晓并使用整个语言」。`[book:krc:preface]` 这一「小」的自觉，正是 C 与后来愈发庞大的 C++ 在哲学上的分水岭。

## ③ C 在计算机体系中的位置

- **操作系统**：UNIX、Linux 内核、Windows 内核大量用 C 写；C 是「系统编程」事实语言。
- **嵌入式/固件**：裸机环境没有 C++ 运行时，C 是首选。
- **数据库与运行时**：SQLite、PostgreSQL、Redis、Lua 运行时、Python 解释器核心都是 C。
- **现代 C++ 的底座**：C++ 标准库的实现（libstdc++/MSVC STL）、ABI、与 C 的互操作全建立在 C 模型上。

## ④ C 与 C++ 的关键差异

C++ 在 C 之上加了类、模板、引用、异常、命名空间、RTTI、`constexpr` 等。下表列出**作为 C++ 程序员最该知道的「C 没有什么」**：

| 特性 | C | C++ | 影响 |
|------|---|-----|------|
| 类 / 面向对象 | ❌（用结构体+函数指针模拟） | ✅ `class` | C++ 的对象模型（主书 part05） |
| 模板 / 泛型 | ❌（`_Generic` 仅 C11 有限支持） | ✅ | 主书 part06 |
| 引用 `&` | ❌（只有指针） | ✅ | 主书 ch20 |
| 函数重载 / 运算符重载 | ❌ | ✅ | 名字改编（C9） |
| 命名空间 | ❌（靠前缀约定） | ✅ `namespace` | 主书 ch23 |
| 异常 | ❌（靠返回码/`setjmp`） | ✅ `try/catch` | 主书 ch40 |
| `constexpr` / 模板元编程 | ❌ | ✅ | 编译期计算 |
| `bool` 真类型 | C99 起有 `_Bool`/`bool` | ✅ | 类型系统 |
| `struct` 内可放函数 | ❌ | ✅（成员函数） | OO |
| 内存管理 | `malloc`/`free` | 同上 + `new`/`delete` + RAII | 主书 part04 |

> 立场：[标准] 「C++ 是 C 的超集」**大体成立但不严格**：多数 C 代码能当 C++ 编译，但二者有真实不兼容处——最典型是 `struct` 在 C 里 `struct S x;` 必须带 `struct` 关键字（C++ 不用），以及 C++ 更严格的类型转换、更激进的 `const` 规则。混用边界见 C9。

## ⑤ 最小可编译 C 程序（本机 gcc 真机验证）

源 `c/_demo/c1_hello.c`：

```c
/* 编译: gcc -std=c11 -O2 -Wall -Wextra -o c1_hello.exe c1_hello.c */
#include <stdio.h>

int main(void) {
    int nums[5] = {1, 2, 3, 4, 5};
    int sum = 0;
    for (int i = 0; i < 5; ++i) {
        sum += nums[i];
    }
    printf("sum = %d\n", sum);
    return 0;
}
```

GCC 15.3.0 `-std=c11 -O2 -Wall -Wextra` 编译运行（真实输出）：

```text
sum = 15
```

注意几点对 C++ 读者的陌生处：
- `int main(void)` 的 `void`——C 里 `int main()` 表示「参数未声明」（老式），`int main(void)` 才是「明确无参」；C++ 中二者等价。
- C99 起才允许 `for (int i = 0; ...)` 在循环内声明 `i`；老 C89 必须提到块外。
- 没有 `std::`、`using namespace`、类——纯粹的「函数 + 数据」。

## ⑥ 小结与路线图

C 教会你「内存就是字节数组、函数就是跳过去执行、结构体就是带偏移的字节串」。下几章依次展开：工具链（C2）、类型系统（C3）、函数与栈帧（C4）、指针与内存（C5）、结构体/对齐（C6）、预处理（C7）、标准库（C8）、C 与 C++ 互操作（C9）。

> 立场：[经验] 学 C 不是为了「回退」到 C，而是为了**向前看穿 C++**：当你知道 `std::vector` 的 `push_back` 底层大概率是 `realloc`、知道虚函数表就是一张函数指针数组、知道 `extern "C"` 在修 name mangling——你就从「会用 C++」走到了「懂 C++」。
