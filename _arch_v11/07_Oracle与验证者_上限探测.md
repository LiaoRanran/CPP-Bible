## 二、模型上限态（真实判断）

1. **83 卡填 verified_by_oracle——"机器代填"在原理上不成立，"机器起草+核验"
   可行**：
   - 机器可以从 replay/gate 的实际运行记录**起草**归属（哪张卡被哪个 gcc 版本
     编译、被哪个 gate 版本判过——运行时工具链指纹已采集，
     atom_evidence_replay.py:577 _current_toolchain_id）。
   - 但让机器把起草结果**自行写入卡面** = 模型给自己发验证证书：注册表
     note 字段已明确"与版本不一致 ⇒ 仅报告层标 stale，判决层不读"
     （oracle_registry.json:2-3）。自填的 Oracle 身份没有任何防伪意义。
   - 可信闭环（模型可设计）：机器起草 → 人确认写入（卡面）→ tool_integrity
     不覆盖数据文件，故仍靠 git 留痕。⇒ **自动化上限是"零手写成本"，不是
     "零人审"**；身份真实性的根永远在人/带外。
2. **三个放权闸的可判定解冻信号（我给具体度量）**：
   - **llm_as_judge**：解冻需要① 盲测集（模型/同族未见过的样本）上累计
     n≥460 条、误判 0（1%@95% 的 C-P 逆解可由 stat_bounds 精确给数：
     n≥ln0.05/ln0.99≈298 条对 1% 单侧——【已查证公式】stat_bounds.py:198-207，
     n_for_upper_bound_zero(0.01,0.95)=299；460 是【一方称】更保守口径）；
     ② 盲测集构造本身需异族/人，模型不能自产自销。
   - **oracle_auto_accept**：同上且额外要求换代有真实验证实验（新旧版本
     对同一卡集判决逐条比对的历史数据，当前 0）。
   - **G-iso（异族独立验证）**：解冻信号不是零误判，而是**错误相关性可测**：
     异族与本族在盲测集上的错误相关系数有数字且低于阈值。2026 前沿给出了
     直接可借的度量（BEI/有效独立票数，arXiv:2604.07650 与 2605.29800，
     【检索 2026-09-19】）。当前 0 数据。
3. **换验证者交接契约——模型能设计协议，协议的"可信"靠人签**：
   形态：① 冻结旧版本全部判决快照；② 新版本对全卡集重跑（当前默认行为
   即全体强制）；③ 逐条 diff 旧/新 verdict，差异集进人审；④ 只有差异集
   全部人审签字后才更新 registry 版本号。卡点不在设计（我能给完整规格），
   在"兼容继承"必须人签——oracle_rotation.py:42-47 的 fail-closed 立场
   本轮读到并同意：版本号自动继承 = 攻击者改版本号即免验。
4. **只写不读为什么安全（核验代码后我的判断）**：当前 verified_by_oracle
   只影响报告层（prop_asof.py:176-182 的 stale 比对）。判决路径（gate
   规则）不读它 ⇒ 卡上填什么都不改变 block/warn，自填无利可图。**一旦
   判决逻辑开始读它（如"oracle 匹配即放行"），攻击面立刻打开**：攻击者
   自填 Oracle ⇒ 自我放行。故"只写不读"不是临时债，是放权前必须维持的
   硬不变量；573 D 实现写入侧安全，但读侧应永久默认关闭。
5. **G-iso 独立性的真实上限**：585 引"Cisco/govllm：同族一致不算独立"
   【一方称】。本轮检索到一手更新证据【已查证 arXiv 正文】：9 个来自 7 个
   族的模型在 NLI 上只有约 **2 个有效独立票**，名义独立性损失约 3/4，
   面板实际准确率比名义低 8-22pp（arXiv:2605.29800，2026-05-28）。
   ⇒ 即使异族，独立性也只能按"有效票"计：我作为 seed evolving 当 G-iso
     验证者，单模型独立票≈1 且与请求方族错误相关性未知，**不能自称独立
     佐证**，只能自称"带可复现锚的第二意见"。误判率上界只能靠盲测样本，
     同族/异族在小样本上都给不出紧界。

## 五、本维度自由探索

1. **"验证者集合"本身需要多样性档案**：当前 3 个验证者（gcc/gate/replay）
   中 gate 与 replay 同进程同语言（Python），共享代码缺陷（585 Q2 common-mode
   【一方称】，本轮读代码同意：同读 propositions.db/同 git）。真正的异类
   Oracle 只有 gcc。结构上**系统只有 1 个非 Python 验证者**——这是比开关
   放权更底层的单点。
2. **可验证计算（VC）作为"Oracle 输出"的补强**：把判决计算做成可验证（见
   13 自由探索），当前完全没碰；其在单用户下的意义是防进程内结果篡改，
   但工具链不成熟。
