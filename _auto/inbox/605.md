# 605 建设包：replay 状态机不变量显性化

## 背景与动机

602 异族调研（TLA+/翻译验证）发现：replay 早已内置隐式翻译验证（`_recompile_invariant` 行1409，独立重编译+CCACHE_DISABLE=1+比sha），但这些不变量是**隐式的**——散落在代码各处，没有独立的、可机器验证的不变量检查工具。

TLA+ 的核心思想是：**状态机的正确性 = 不变量在每一步都成立**。replay 的状态机（删工件→重编译→还原→比对）有几个关键不变量：
1. **工件还原不变量**：replay 跑完后，真实仓库的 Examples/ 工件必须与跑前逐字节一致
2. **编译可复现不变量**：同一张卡的同一条命令，两次编译的产物 sha 必须一致（短窗口内）
3. **锁一致性不变量**：并发跑 replay 时，锁文件必须正确互斥，不能出现两个进程同时写同一工件
4. **沙箱隔离不变量**：跑批根（batch_root）内的操作不能泄漏到真实仓库

当前这些不变量是"代码里隐含的"，不是"独立可验证的"。本批把它们显性化，新建独立的不变量检查工具，不修改 replay 本身。

## 任务清单

### 任务 0：先量——replay 隐式不变量盘点（只读，不写代码）

输出 `data/replay_invariants_inventory.md`：
- 列出 replay 状态机的所有隐式不变量（从代码中提取，附文件路径+行号）
- 每个不变量标注：当前是否有检查、检查在哪里、检查是否独立
- 区分"已显性化"（有独立检查）和"隐式"（散落在代码中）
- 预计：4-6 个不变量，其中大部分是隐式的

### 任务 1：新建 tools/replay_invariants.py——独立不变量检查工具

纯标准库，不修改 atom_evidence_replay.py。提供：
- `check_artifact_restore()`：跑前拍 Examples/ 指纹，跑一组 replay 后再拍，比对是否一致
- `check_build_reproducibility()`：对 N 张卡（默认 3 张）跑两次编译，比对产物 sha
- `check_lock_consistency()`：验证锁文件在 replay 运行期间存在、结束后清理
- `check_sandbox_isolation()`：验证 batch_root 内的操作不影响真实仓库（真实仓库指纹不变）
- CLI：`python tools/replay_invariants.py --check`（跑全部不变量，失败 exit 2）
- CLI：`python tools/replay_invariants.py --check --invariant artifact_restore`（只跑指定不变量）

硬约束：
- 只读真实仓库，不修改任何文件（检查用的临时文件放 %TEMP%）
- 不调用 replay 的写操作（用 monkeypatch 或直接调用内部函数）
- 每个不变量检查有明确的 pass/fail 判据，不输出"可能有问题"

### 任务 2：不变量审计报告

运行 `replay_invariants.py --check`，输出 `data/replay_invariants_report.md`：
- 每个不变量的检查结果（pass/fail/skipped）
- 失败的不变量附详细诊断（哪个卡、哪个命令、什么差异）
- 运行时间和资源消耗
- 已知限制（如编译可复现只在短窗口内验证，不保证跨天）

### 任务 3：测试 + 收工

新建 `tests/test_replay_invariants_605.py`：
- 测试每个不变量检查函数的正例（正常情况下 pass）
- 测试反例（故意破坏不变量后 fail）——用临时目录模拟
- 测试 CLI --check 的 exit code
- 测试幂等性（连跑两次结果一致）
