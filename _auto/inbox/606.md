# 606 建设包：replay 不变量深化（I3 锁一致性 + metrics 接入）

## 背景与动机

605 新建了 `tools/replay_invariants.py`，实现了 I1（工件还原）、I2（编译可复现）、I4（沙箱隔离）三个不变量的独立检查。但还有两个缺口：
1. **I3 锁一致性**未实现——replay 的 `_replay_lock_path()`（580 实现，跟随跑批根分片）是并发安全的关键，但没有独立的不变量检查
2. **metrics_collector 未接入**——不变量检查结果没有被 metrics 采集，无法在收敛曲线中追踪

本批补齐这两个缺口，让不变量从"可手动检查"变成"可自动追踪"。

## 任务清单

### 任务 0：先量——锁一致性现状盘点（只读，不写代码）

输出 `data/replay_lock_inventory.md`：
- 列出 `_replay_lock_path()` 的实现（文件路径+行号）
- 列出锁的获取（acquire）和释放（release）位置
- 列出 580 的锁分片设计（跟随 run_root/batch_root）
- 列出已有的锁测试（test_replay_lock_serial.py 等）
- 标注：锁一致性的不变量是什么（锁在运行期间存在、结束后清理、不泄漏到真实仓库）

### 任务 1：I3 锁一致性不变量检查（加入 replay_invariants.py）

在 `tools/replay_invariants.py` 中新增 `check_lock_consistency()`：
- 验证 `_replay_lock_path()` 返回的路径在 run_root()/build/ 下
- 验证默认情况下（无 batch_root）锁路径 = 真实 ROOT/build/.replay_lock
- 验证在 batch_root 上下文内，锁路径跟随 batch_root（不指向真实仓库）
- 验证锁文件在 replay 未运行时不存在（真实仓库无残留锁）
- CLI `--check` 自动包含 I3
- 更新 INVARIANTS 元组为 4 个

硬约束：
- 不实际运行 replay（只检查路径逻辑和文件存在性）
- 不创建真实锁文件（用临时目录模拟）

### 任务 2：metrics_collector 接入 replay_invariants

在 `tools/metrics_collector.py` 中新增不变量采集：
- 调用 `replay_invariants.run_checks()` 采集 4 个不变量的 pass/fail 状态
- 在 metrics 输出中新增 `invariants` 字段：`{"artifact_restore": true, "build_reproducibility": true, "sandbox_isolation": true, "lock_consistency": true}`
- 新增 `invariants_all_pass` 布尔字段
- 不修改既有 metrics 字段（向后兼容）
- 如果 replay_invariants 导入失败，invariants 字段设为 null 并记录警告（不 crash）

注意：metrics_collector.py 是 CORE_TOOLS 之一，修改后必须同 commit 运行 `tool_integrity.py --update` 重钉 .tool_checksums。

### 任务 3：测试 + 收工

- metrics 接入：invariants 字段存在 / 4 个不变量全 true / all_pass=true / 导入失败时 null
