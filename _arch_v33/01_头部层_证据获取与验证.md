## 0. 阙疑头部层现状（本仓库实读，非记忆）

- **获取**：648 批次以手工定点下载为主（N1570/N2310/N3096 已落盘，C17/C23 PDF 只留 sha256 [仓库实证]）；探针程序人手写（`_adv_v80/probes/` + `compiler_probe_645`）。
- **分级**：`evidence_grading_644/645` 五级——L1 多编译器实测 / L2 标准或单编译器实测（`compiler_run, compilers=1→L2, =2→L1`）/ L3 共识（cppreference 等二手）/ L4 单点 / L5 未验证；AI 生成默认 L5 [仓库实证]。
- **充分性**：每卡 ≥1 条 L1/L2 + ≥3 条独立证据；有独立来源（`independent`）字段防伪多源。
- **反例**：`counterexample_searcher_645/646`，只搜不判。
- **缺口**：无自动检索 agent；无证据把握度第二轴；网页证据无 query/时间戳留痕；标准引用钉到文件不钉条款锚点；无标准变更订阅。

**总判断**【推断】：头部层 2024–2026 的前沿主线是"**deep research 流水线产品化 + claim 核查小型化/模块化 + 标准源 git 化 + 编译器测试 LLM 离线化**"。阙疑头部层的下一步不是接更强的模型，而是把取证流程**拆成固定阶段、每阶段留痕、LLM 只做候选**——与 v31 的 L0–L3 判决宪法同一原则在头部层的投影。

## 1. 自动证据获取：deep research 已工程化，但边界清晰

### 1.1 流水线四阶段（两篇 2025 综述的收敛结构）

自主调研 agent 的事实标准管线：**规划 → 问题展开（question developing）→ 网络探索（检索/浏览器/API）→ 带引用报告生成**；2025 年的增量主要在"问题展开"（把一个模糊主问题改写成数十个带时间/实体上下文的子查询）与"事实完整性"（逐句可核引用）两处 [S1][S2]。

- 自主度分级（L1 代码补全 → L5 完全自主研究议程）：95+ 系统盘点结论是当前前沿系统在 **L4**（有界域内多步自主执行），L5 仍是愿望；六大开放问题里与阙疑相关的三条：持久知识积累、可靠自评、可复现性 [S3]。
- API 检索 vs 浏览器 agent：API 类系统（确定性检索端点）在可引用、可复现、成本上全面占优；浏览器仅在目标站点无 API 时使用；静态工作流（固定阶段图）在单人可控场景比动态多 agent 更稳 [S4]。
- **可验证环境中的自进化**：DeepSearch-World 把搜索/读页工具做成**确定性、可复现**的环境（缓存式检索结果），agent 在其中自蒸馏；强调"取证动作本身可复算"而非只有结论 [S5]。
- 实证行为：端到端 RL 训练出的 deep researcher 涌现"多源交叉验证、自我反思改道、找不到时诚实挂起"三类行为【论文】[S5 邻近文献 DeepResearcher]。

### 1.2 对阙疑的硬映射【推断】

1. **证据获取 agent 的输出永远进 L4/L5，不自动升级**——它能完成"找到并摘录"，不能完成"实测/标准原文比对"。升级只能由 L0 动作（真机编译、条款逐字比对）完成。这与 v31"LLM 永不给 pass"同构。
2. 头部取证应按四阶段拆成**可审计的固定流水线**，每阶段产物落盘：
   - 规划：`evidence_plan.json`（子问题树，每个子问题绑定卡 id + 断言文本）；
   - 问题展开：原子断言 + **时间/版本增广**（见 §3.1 PASS-FC 的 claim period 手法——"C17 下…"必须显式成查询的一部分，否则会取回 C23 的答案）；
   - 取证：每条来源留 `{query, url, fetch_time, content_sha256, site_restricted, rank}`；
   - 草稿：断言-证据对照表，三态（supported/contradicted/inconclusive），**不产生判决**。
3. 检索工具白名单优先（open-std.org / eel.is / github raw / godbolt / 编译器状态页），浏览器抓取为兜底且必须留"为何 API 不可用"的记录——对齐 S4 的 API-first 结论与 S5 的可复现原则。

> **H1（落地动作）**：实现 `evidence_seeker_v2`（只读、产物入 `data/evidence_store/` 与 sources 快照）：LLM 仅承担"生成检索式 + 起草探针程序 + 摘要"；所有检索经白名单工具；产物默认 grade=L5，附完整检索留痕；不触碰 gate_engine。先跑 10 张历史卡做回放评测（人评召回率/误引率），不达标不入主线。

## 2. 证据等级：L1–L5 之外，业界的两条正交轴

阙疑的 L1–L5 评的是**来源类型**；2024–2026 成熟方法论评的是另两件事，应当作独立轴引入，而不是替换。

### 2.1 GRADE：把握度按"断言-结局"评，五个降级域 + 三个升级域

GRADE（WHO/Cochrane 事实标准）把证据把握度分 **high/moderate/low/very low**，初始级别由研究设计决定，再按域调整【官方】[S10]：

- 降级五域：偏倚风险、不一致性、间接性、不精确、发表偏倚；
- 升级三域：效应量大、剂量-反应、残余混杂（主要用于观察性研究）；
- 把握度是**逐结局（per outcome）**的，且与推荐强度分离——"证据很弱"也可以给强建议（后果极端时）。

**对阙疑的硬映射**【推断】：L1–L5 保留为"获取轴"；新增第二轴**断言把握度（高/中/低/极低）**，每卡逐断言评：

| GRADE 域 | 阙疑头部层对应 |
|---|---|
| 偏倚风险 | 来源是否被篡改/二手转述（cppreference 编辑偏差） |
| 不一致性 | gcc/clang/msvc 结果是否冲突；标准措辞与实测是否冲突 |
| 间接性 | 实测程序与卡 claim 的贴合度（探针是否真的测了断言所述行为） |
| 不精确 | 编译器数量/优化档位/运行次数样本量（n=1 的 L1 应降档标注） |
| 发表偏倚 | 博客/营销文证据；标准草案 vs 已发布 IS |

### 2.2 AIS：可归因于已识别来源（Attributable to Identified Sources）

Google 提出、Computational Linguistics 2023 发表的框架：一个断言的可信度不取决于语气，而取决于是否**逐句可归因到一个已识别、可核验的来源**；FActScore 的原子化 + 来源支持率是其操作化（InstructGPT 传记仅 42% 原子断言有来源支持，RAG 后 71%）【实测】[S12]。

### 2.3 W3C PROV：来源不是字符串，是实体-活动-代理图

成熟的溯源数据模型是 W3C PROV 的 Entity–Activity–Agent 三元组（谁/用什么流程/产出了什么）【官方】[S11]。阙疑证书已有链状 provenance，PROV 给的是**可被第三方工具消费的图模型词汇表**。

> **H2（落地动作）**：证据记录从一条 `source` 字符串升级为双轴记录 `{acquisition_grade: L1..L5, certainty: high..very_low, downgrade_reasons[]}`；`independent` 的机器判据收紧为"**异工具链 + 异载体**"（gcc 与 clang 算独立；gcc 与 g++ 同驱动版本不算；标准原文与同段实测算独立）。证书链按 PROV 词汇导出（evidence=Entity，probe_run=Activity，compiler/human=Agent），为将来第三方核验留接口。

## 3. 自动化 claim 验证：MiniCheck/FACT 之后的 2025–2026 形态

v31 已覆盖 MiniCheck（770M 合成数据打平 GPT-4）与 FACT 谱系。本次补的新进展呈现同一个模式：**模块化小模型 + 迭代检索 + 三/四态判定**。

| 系统 | 时间 | 要点 | 数字 |
|---|---|---|---|
| PASS-FC [S6] | 2025-04 | claim 增广（**时间周期 + 实体简介**）、站点限定/多语检索、反思轮、三态聚合 | 六个数据集超基线【实测】 |
| EMULATE [S7] | 2025-05 | 多 agent **模拟真人取证分工**：查询生成/结果可信度排序/网页阅读/证据集评估/最终分类 | 多基准提升，代码开源 |
| CAAFC [S8] | 2026-05 | 时间序、可行动的自动核查；**证据自动更新机制**（取证不足自动补新证据）；三态判决含算法化聚合 | 多基准 SOTA【实测】 |
| ClaimCheck [S9] | 2025-09 | 透明五阶段模块（查询规划/取证/摘要/综合-补证/判决），**Qwen3-4B 小模型**在 AVeriTeC 达 76.4%，超 LLaMA3.1-70B 与 GPT-4o | 【实测】 |
| SemanticCite [S13] | 2025-11 | 引文核查四类：**supported / partially supported / unsupported / uncertain**；微调小模型可比大模型 | 1000+ 引文数据集 |

- 共同结构：**原子断言分解 → 检索 → 三/四态判定 → 反思触发再检索（预算有限轮次）→ 聚合**；判词永远是 supported/refuted/**unverifiable**（NEI 不是失败，是挂起）。
- ClaimCheck 的关键工程结论：小模型不够强的是"综合与判决"模块，模块化分解 + 中央事实核查报告（各模块留痕）即可弥补 [S9]。
- 老坑仍在：基准标签歧义会改变排名（ClearFacts/ClearCheck），多跳断言上小模型明显落后——小模型只打原子断言 [v31-S10 区，仓库已有结论]。

> **H3（落地动作）**：`evidence_sufficiency` 增加"反思式补证"：L1/L2 缺失时不直接判不足，先按断言类型生成 ≤3 条定向检索式（标准条款 / 编译器实测 / 反例），走完预算仍无证才落 `insufficient`；所有补证轮次与各轮 cs_upper_bound 入证书（机器强制"取证后重校准"，与 v31 A6/BCEA 警告合流）。claim 增广固定带**标准版本与时间上下文**（见 §7）。

## 4. 标准引用自动化：官方 API 不存在，但 git 化的机器可读源已足够好

### 4.1 C++ 侧事实清单【官方】

- 已发布 IS（ISO/IEC 14882:2024，即 C++23）只在 ISO Store 售卖；**ISO OBP 提供免费在线 HTML**，但仅限浏览、无 API、无批量授权，且被撤版标准（如 14882:2020）标注 withdrawn [S16][S14]。
- 进行中草案的 **LaTeX 源在 GitHub（cplusplus/draft）**，逐次会议有 tag；但 ISO 持有已发布版本版权，GitHub 内容不对应任何正式标准 [S14]。
- `eel.is`（cxxdraft-htmlgen 从 LaTeX 自动生成）提供**稳定条款锚点**（如 `[basic.pre]`），页面标注生成日期与源 commit [S16]。
- 每次会议的 **Editors' Report 是结构化变更日志**：如 N5047（2026-05）逐条列出 CWG/LWG poll 及对应 DR 编号（P 号），是机器追踪标准变化的最好入口 [S15]。

### 4.2 C 侧事实清单【官方】

- WG14 官网维护：项目状态页（C23=ISO/IEC 9899:2024，对应 N3220；C2y 草案 N3886）、逐版 CR/DR 记录、以及**按版本滚动的 issue log**——2026-09-20 更新到 N3966《C23 issue log r6》、N3967《C2Y issue log r1》[S17]。
- 编译器侧：GCC 2025-06 合入官方 **C23 特性状态表**（与 Annex M 一一对应，引用 N 编号）；clang 有 `c_status.html`；cppreference 维护 `compiler_support.html` [S18]。

### 4.3 对阙疑的硬映射

- "有没有官方 API"的答案：**没有，也不需要等**。LaTeX 源 + HTML 锚点 + Editors' Report/issue log 三个机器可读源已经能覆盖引用、diff、订阅；648 批次"C17/C23 只留 sha256"的负债可以用这些源还掉（N1570/N2310 为免费 HTML，可逐条款抽取并锁哈希）。
- 引用单位从"文件级"收紧到"**版本 + 条款锚点 + 抽取物 sha256 + 抓取日期**"四元组。

> **H4（落地动作）**：建 `standards_registry`（一个 yaml/目录，纯只读数据）：登记 C/C++ 各版 {正式版 ISO 号, 免费 HTML URL, 草案 N 号, git commit/tag, 抓取 sha256, 抓取日期}；卡 frontmatter 的 `sources[]` 必须引用条款锚点（`[basic.pre]`/C 条款号）与 registry 版本号；新增一个 CI 只读检查（引用的 N 号/commit 不是 registry 中登记值即 block），**先警告后阻断**给存量卡留迁移期。

## 5. 编译器实测自动化：2025–2026 的关键转向是"LLM 离线、组合在线"

| 工作 | 时间 | 打法 | 实测产出 |
|---|---|---|---|
| Fuzz4All [v31-S20] | 2024 | LLM 直接生成通用语言程序 | 覆盖率强，前端崩溃为主 |
| LegoFuzz [S20] | 2025-08/OOPSLA'25 | **离线**：LLM 从 146 个真实项目造 50 万小而特性密集的函数库（语法+语义过滤）；**在线零 LLM**：类型/语义约束下插调用、共享全局变量组合复杂程序 | GCC/LLVM **66 bug，其中 30 miscompilation**（部分隐藏近 20 年），覆盖率 +12.5%；现有 LLM 工具测不出深优化 bug【实测】 |
| Kitten [S21] | ISSTA'25 | 不用 LLM 的变异基线：种子语料 + 语法变异，9 个月 7 编译器 **328 bug、310 已确认/修复**；24h 内 bug 数显著超 Fuzz4All | 证明"朴素变异 + 好种子"仍是强基线【实测】 |
| Mut4All [S19] | 2026-02 TOSEM | 从**历史 bug 报告学习变异器**：LLM 发明→实现→精炼变异算子，再微调；自适应种子增强 | Rust 编译器 62 reported/41 新；C++ 34 reported/17 新【实测】 |
| Fuzpiler [S22] | 2026-04 | LLM 跨语言翻译 + 语义对齐，跨前端差分 | clang/clang++/rustc 分支覆盖 +5.19/+36.57/+23.91%【实测】 |

对阙疑 648 探针模式（人手写 10 卡 × 120 组）的直接含义：

1. **LLM 起草探针必须过"编译+运行有效率闭环"才入库**（v31 A11 已立此原则，ReFuzzer 96.6–97.3% 有效率是闭环后的数字 [v31-S20]）。
2. **离线造积木、在线拼探针**：把 LLM 成本限制在离线一次性阶段（造特性密集的最小合法片段），在线用确定性组合扩规模——这是单人项目唯一可持续的探针扩量方式。
3. 差分矩阵常态化：同一源 × gcc/clang × {-O0,-O1,-O2} × {gcc,g++}，比 stdout + sanitizer + 退出码；跨编译器分歧本身就是 L1→L3 降级/升级的机器证据。
4. 敬畏基线：不引 LLM 也应有 Kitten 式纯变异通道，作为 LLM 产线的对照臂（防止"看起来有效"其实不如语法变异）。

> **H5（落地动作）**：`compiler_probe_645` 升级为"积木库 + 组合器"：积木来源 = Examples 真实代码与 LLM 离线片段（过编译率/sanitizer 双闭环入库）；在线组合零 LLM 调用；每次差分自动产出 `{compiler, std, opt} → verdict 三元组`，分歧即反例候选。先复现 LegoFuzz 离线流程跑 500 条积木做成本标定，不追求直接对标 bug 数（阙疑的目标是知识卡证据，不是给 GCC 报 bug）。

## 6. 反例搜索：SMT/有界模型检验在 C 上不仅能用，而且是现成 Windows 可跑的成熟工具

### 6.1 工具现状（2025–2026）

- **ESBMC 7.x**：SMT-based 有界模型检验，Clang 前端支持 **C23/C++20**，多求解器后端（Bitwuzla 默认/Z3/CVC5/Yices）；增量 BMC、k-归纳、区间分析剪枝、unwinding assertion（**K 界没展开完会显式报错，不静默当安全**）；falsification 模式专找反例（递增 K 到 50）；有 Windows 下载包、VSCode 插件、Web 界面；SV-COMP 2025/Test-COMP 2025 参赛；**ESBMC-AI** 做 LLM 修复与 LLM 循环不变量 [S23]。
- CBMC（2025 ETAPS Test-of-Time 奖）：精确位级 C 语义、GOTO IR、多路径编码进单一公式；作者访谈的核心判断——关键软件的定义指标是**最小化误报率**，LLM 是强"猜测器"但判决仍靠 check【实测访谈】[S24]。
- 训练侧新证据：基于 SV-COMP 2025 的 500 个 C 验证任务评 14 个模型：属性成立确认普遍 >90%，但**违例检测参差且随程序变长急剧下滑**（100–200 行即有模型跌破 10%）；用约 3000 条符号执行 trace 续训 Qwen3-8B，违例检测 +17pp，8B 超未思考的 32B【实测】[S25]。

### 6.2 对阙疑的硬映射【推断】

1. `counterexample_searcher` 的升级目标不是"全网找反例"，而是对**可界算的探针程序**跑 ESBMC `--falsification`：sat→给具体输入 witness（比人读 UB 描述强得多），unsat→在 K 界内"成功"，unwinding 失败→`unknown(bound)`。
2. **判决语义纪律（直接照搬）**：有界成功 ≠ pass。BMC 的 SUCCESSFUL 只能写成证书上的"`unknown`，bounded K 内未反例"；它是否决"存在反例"的证据，不是"断言成立"的证明。这恰好是尾部四态里 unknown 的一个高价值来源类型。
3. 813 行核心不用 BMC（Python、无 IO 语义工具链，见 03 篇 §6）；BMC 只服务卡片探针（C 小函数、循环可界、无 libc 深依赖），覆盖面诚实登记，不包装成通用反例引擎。
4. LLM 违例检测弱（<50% 档）的实测再次支持：反例搜索器内部 LLM 只能做"猜测可疑边界"前置，SMT 判决不可让渡 [S25]。

> **H6（落地动作）**：选 3–5 张已有可界算探针的卡（如整型溢出/位域/setjmp 卡）做 ESBMC 试点：`--falsification` 出 witness 自动转成一条新 `.out` 对照与证书附件；判决书新增证据 kind `bmc_witness`（grade=L1 的反例侧，把握度由 K 界标注）；Windows 发行包可用性先实测再登记。

## 7. 证据时效性：标准会变，而且变更源全部是机器可读订阅源

### 7.1 标准侧的时效信号（全部免费、无需爬内容站）

- WG14 issue log 按修订滚动：C23 r6 / C2Y r1（2026-09-20）；C2Y 工作草案 N3861 列出 UB 清单——**截至 2026-03 已投票移除 36 项 UB**，并给编译器检测/内存安全模式路线图 [S17]。
- WG21 Editors' Report 每会一次，逐条 poll + DR；草案 N5054（2026-07）可直接与上版 diff [S15]。
- 编译器状态表随发布更新（GCC C23 表 2025-06 入库；clang/MSVC 逐版 conformance notes）[S18]。

### 7.2 "知识过期"的机制认知

RAG 工程界 2025–2026 的共识（来源质量参差，但结构结论稳定且与阙疑问题同构）：**语义相似度没有时间维**——新旧版本嵌入距离极近（余弦相似度 >0.9 的实测被反复引用），旧版本若表述更具体反而排位更靠前；纯靠检索排序无法区分"被替代"与"新表述"【二手实测汇编】。可操作的治理机制是四件事：**TTL 时效标签、双时态账本（valid time / system time、`supersededBy` 链接）、变更信号触发、只标记不自动改写**。

对阙疑，卡 frontmatter 已有 `claim_boundary.{standard, compilers, opt}`——它天然是时效元数据的挂载点，缺的是：**字段没有"上次核验时间/被谁替代/复核到期日"，也没有变更信号源**。

> **H7（落地动作）**：证据时效最小闭环——①`claim_boundary` 增 `verified_at / superseded_by / recheck_after`；②订阅三个信号源（WG14/WG21 issue log 的 RSS/git log、GCC/clang 发布页），信号触发后**只做标记**：关联卡入 `stale_candidate` 队列（不自动改判），头部层补证后走正常判决流；③C2Y 的 UB 移除清单单列（36 项中任何一项命中卡 claim → 强制复核），这是最高优先级时效债。与 643 `rule_aging` 同构为"证据老化"姊妹机制，复用其队列与看板。

### 三条不做清单

- **不做"自动找标准文本并自动改判"**：deep research 只在 L4 自主度 [S3]，标准版本迁移影响判决必须过人审（标准解释权不在 agent）。
- **不做浏览器开放域抓取入证**：浏览器抓取只用于白名单失败时的兜底且要登记理由；开放域网页证据默认 L4，把握度极低。
- **不给 BMC unsat 发 pass**：有界成功是 bounded-unknown（ESBMC unwinding assertion 的纪律 [S23]），这条破了等于自造 escape_rate=0。
