## 0. 阙疑中间层现状（本仓库实读）

- 67 条确定性规则（calibration_tracker_636），`smart_issue_finder_645`（命中/盲区/老化/错误率四源问题），643–646 已有规则起草→试跑→MDL 准入的批次实践与 rule_aging。
- 攻击侧：`targeted_mutator` 与固定 M1–M7 七类证书变异、`poison_drill`。
- 保护器即中间层与尾部层的铰链：B1 冲突（唯一改判）/B2 anti-windup/B3 盲审/B4 校准/B5 MDL；647 自登记**真实触发≈0、B4 逐规则错误率饱和**。
- 校准：abstain_classifier + four-state + cs_upper_bound，但保形标定与人审复核集的挂钩是约定而非机器强制（v31 已给升级路径）。

**总判断**【推断】：2025–2026 中间层最重要的工业化事实是——**"从历史事故自动合成检查器"在 2025 年下半年集中跨过了真实 CVE 门槛**（SOSP'25 等），而自进化闭环的共同结构是"挑战者–求解器–**外部验证器**–批评器"四环。阙疑 637–646 的循环已经是该四环的土法版本，差距集中在两点：挑战者太弱（只有盲区扫描）、规则来源太窄（只靠人手与 LLM 一次性起草）。

## 1. 自动规则发现：2025–2026 是"补丁→检查器"合成的兑现年

| 工作 | 场合 | 输入→输出 | 实测数字 |
|---|---|---|---|
| **KNighter** [S30] | SOSP'25（2025-10） | 历史 bug 模式 → LLM 合成专用静态检查器；对原补丁验证正确性 + 自动精炼压假阳 | Linux 内核 **92 个新 bug（平均潜伏 4.3 年），77 确认、57 修复、30 CVE**【实测】 |
| **Autogrep** [S26] | 2025-02 | 39,931 个漏洞补丁 → 645 条可复用 Semgrep 规则（20 语言）；多阶段过滤（去掉 71.15% 过具体、10.75% 重复） | 规则库规模与精度平衡【实测】 |
| **RULEDROID** [S27] | TSE 2026 | 官方安全文档 → RAG  grounding → 模块化 Semgrep 规则合成，再静态分析执行 | 真实应用发现 **57 个 CVE**【实测】 |
| **QLPro** [S28] | 2025-06 | 静态抽取污点规约 → LLM 分类配对 → 三票投票 → 规则生成 | 62 个真实漏洞：CodeQL 检出 24，QLPro 41，含 2 个 0-day【实测】 |
| **QLCoder** [S29] | 2026-08 | 给 CVE 元数据，经 MCP/LSP 反馈循环合成 CodeQL 查询；执行反馈在环 | 176 CVE/111 项目：**53.4% 合成查询正确**（纯 Claude Code 10%），F1 0.7【实测】 |

### 1.1 五篇工作收敛出的合成纪律

1. **LLM 出候选，静态引擎做执行**——没有一篇让 LLM 直接给结论；规则文本可解释、可在 CI 复跑 [S26-S30]。
2. **必须有负样本精炼环**：以原补丁（修复后代码）作阳性、以父提交作阴性过滤假阳；KNighter 明确把"对补丁验证"作为压 FP 的主回路 [S30]。
3. **规则带溯源**：每条规则回链具体 commit/doc/CVE（Autogrep/RULEDROID 皆然）——这同时是 MDL 准入材料与日后退役依据。
4. **投票/多角色只用于降噪不定罪**：QLPro 三票投在分类配对阶段，最终判决仍由静态引擎 + 人 [S28]。
5. **强基线仍然朴素**：2025 年的教训是纯 LLM 直接扫全仓不可行（上下文窗口、误报、不可解释），语言无关的简单变异/查询基线在多数评测里没被拉开差距（参见头部层 Kitten 对 Fuzz4All）。

### 1.2 对阙疑的硬映射【推断】

- 阙疑的等价物不是 CVE 补丁，而是三类已有台账：**①人审改判事件（decision ledger 452 事件）②毒化演练新攻击面 ③M1–M7 变异结果**。这就是 KNighter 的"历史 bug 模式"在知识验证域的对应物——原料已经存在，643 rule_drafts 是半成品管线。
- 67 条手写规则定位应明确：它们是**官方注册表**（高精确、零成本），自动合成规则的定位是**覆盖注册表外的长尾与新攻击面**，两者不是替代关系（Autogrep 39,931 补丁才得 645 条，提纯率约 1.6% [S26]——要对候选规则数量级有心理准备）。

> **M1（落地动作）**：上"候选规则挖掘器"（不动 67 条）：输入=改判账本+poison_drill 新攻击面+反例搜索器的 miss 台账；输出=候选规则草案，每条强制带 `{触发模式描述, 来源事件 id, 预测 FP 率, 阴性回测集}`；阴性回测直接复用 PCK 证书的 M1–M7 与已通过卡（通过卡变异后**必须**被拦=规则的最低验收）。过 MDL 才能上线，这是 647 B5 已立的纪律，KNighter 的 92 CVE 全部是同一纪律的工业证明。

## 2. 自动攻击/变异：变异器也要"离线学习、在线免模型"

- 编译器域证据已在 01 篇 §5（Mut4All 从 bug 报告学变异器 [S19]；LegoFuzz 离线积木在线组合 [S20]；Kitten 朴素基线 [S21]）。中间层取其**方法论**而非工具本身：
  - **变异器可学习**（Mut4All 把"发明变异算子"自动化，且学到的算子可跨语言迁移）；
  - **学习只在离线发生**（LegoFuzz 成本结构：在线大规模 fuzz 不调 LLM）；
  - **有效率闭环**（编译错误 + sanitizer 回灌修复，ReFuzzer 96.6–97.3% [v31-S20]）。
- 测试套件侧：SWE-Mutation 显示 LLM 自写测试抓语义变异复现率仅 10.2% [v31-S19]——攻击器必须由确定性一方持有，LLM 只能增强生成。

**对阙疑的硬映射**【推断】：M1–M7 是固定七类证书级变异；升级方向三条（与头部 H5 共源，此处给中间层视角）：

1. **claim 语义变异**：改数字/边界/标准版本号（C17→C23 替换是天然变异，直接测时效盲区）；
2. **反馈变异**：变异后让探针的编译/运行/sanitizer 输出回灌，自动修复无效变异；
3. **事故学习变异**：把"骗过一次判决的样本"（毒化演练沉淀）反提为新变异算子——Mut4All 范式在知识域的投影。

> **M2（落地动作）**：`targeted_mutator` 接变异器注册表（与规则注册表对称）：每条变异器带 `{来源: claim|ledger|drill, 有效率闭环阈值, 语言相关?}`；新变异器先 shadow（只记账不投毒）一个批次再启用；变异流持续再生但**变异域显式声明**（escape_rate=0 只能在声明域内声称，承接 v31/v25 纪律）。

## 3. 校准与可信度：保形预测 2026 已推进到"成对判决 + 级联 + 双阈值"

v31 已立 UniCR/CAP/BCEA 三件（split conformal、逐实例弃权、取证后必须重校准）。2026 新文献把阙疑 B6/级联的剩余数学补齐：

- **SCOPE（2026-02）**：成对 LLM 判决的保形弃权框架；核心构造是**双向偏好熵（BPE）**——正序/逆序各问一次聚合成顺序无关的不确定信号，再标定受理阈值，保证**受理样本错误率 ≤ α**（分布无关）【论文】[S31]。这正好把 v31 已定的 B6（Sage swap 双跑）从"公理体检"升级为**带错误率上界的机器量**。
- **Conformal Cascade（2026-07）**：多层级推理（便宜模型→贵模型→人）的保形框架，按校准后预测集大小决定受理：集塌缩成单答案即受理，否则升级；逐层 union bound，给分布无关精度保证 [S34]。
- **Conformal Thinking（2026-02）**：双阈值——上阈值（自信则停止推理，防错放）+ 下阈值（无望则提前终止，防烧钱），风险控制下的算力最优 [S33]。
- **级联决策实证**：校准过的置信 + 人反馈在线改进策略，跨 ARC/MMLU/医学 QA 累计遗憾最小【实测】[S35]；CAP 把逐实例弃权策略用 RL 学（点预测/集预测/全弃权三档按下游效用动态选），维持 90% 覆盖同时幻觉检测 AUROC +22.2%、校准误差降 70%+（v31 引 CAP，本篇补 S32 编号互证）。

**对阙疑的硬映射**【推断】：

- B6 落地口径建议直接采用 SCOPE：swap 双跑不只算一致率，BPE 作为非一致性分数进保形标定，最终输出"受理判决的错误上界 α"——与 cs_upper_bound 同口径替换，但数学凭据从土统计升级到分布无关。
- 三级级联（67 规则 → 小模型 → 前沿模型/人）的升级阈值不要拍脑袋：Conformal Cascade 给的是逐层 α 预算方法；阙疑单人项目可只做**两层**（规则+人），把 LLM 层整体当"可升级可跳过"的缓冲带。

> **M3（落地动作）**：校准模块统一三件套：①B6 用 SCOPE/BPE 口径（顺序脱敏后双跑，进保形标定）；②级联升级阈值按 Conformal Cascade 逐层分配 α（人审层 α=最严）；③取证/补证后重校准从约定升级为**机器强制**（v31 A6 已定，BCEA 警告），新证据轮次不重算则判决状态机禁止进入 pass。

## 4. 闭环进化：2025–2026 的共识结构 = 挑战者 / 规划者 / 求解器 / 批评器 + 外部验证器

- 自进化 agent 三分范式综述：经验驱动 / 对抗自弈 / 元学习-无奖励探索；2025–2026 标志性结果包括 SWE-RL 式自弈（无外部数据 +10.4pp）[S36 区]。
- **SAGE** 给出最小完整闭环：Challenger 持续生成更难任务 → Planner 结构化 → Solver 执行 → **外部验证器判对错** → Critic 双角色过滤（既滤问题也滤方案）防课程漂移；小种子集即可自训练，Qwen-2.5-7B 在 LiveCodeBench +8.9%、OlympiadBench +10.7%【论文】[S36]。
- Q-Evolve 式工作的共同教训：过程奖励/批评器质量决定闭环是否退化为"自我正确"；**分布内（in-distribution）迭代**是防漂移关键。
- AlphaEvolve 式"产物级迭代优化"（agent 改 artifact、外部标准验收）在知识域的同构物 = **改卡 → 真机/规则验证 → 保留或回滚**，阙疑 637–646 已手工跑通过该环。

**自进化闭环的三个已知死法**【综合 S36 区 + v31】：

1. **无外部验证器**：LLM 自评闭环必然漂移（v31 多智能体辩论放大偏差是同一结论）；
2. **无批评器/过滤器**：任务难度退化或自造简单题，训练信号坍塌（SAGE 的 curriculum drift）；
3. **持久化错层**：经验只进会话记忆不进注册表——下轮会话重造轮子（项目记忆：648 探针重复编译是同类病）。

> **M4（落地动作）**：中间层引入显式"挑战者"角色（接 smart_issue_finder）：从已通过卡反向生成**更强攻击变体**（不是生成新卡），求解器=规则起草/变异器，**验证器固定为真机编译+67 规则+M1–M7，禁止换 LLM 当验证器**，critic=B5 MDL + B4 校准双过滤。产出只进候选池，不触生产卡。防坍塌前提：挑战者产物每周限量、全量留痕、人可一键关停。

## 5. 领域适配：C++→C→嵌入式的最小成本路径——核心不动，适配层变薄

- EmbedAgent/EmbedBench（2025，126 例 × 3 平台 × 9 元件）：前沿模型在嵌入式开发任务上显著弱于通用任务——**给了原理图 DeepSeek-R1 也仅 55.6% pass@1，自行生成原理图更差（50.0%）**；跨平台迁移任务表现相对好【实测】[S37]。
- 跨语言效率评测（NeurIPS 2025，Python/C++/Java/JS/Ruby/Go）：功能正确普遍，效率仅约人类 62%，且**语言间系统性差异**（Python/Ruby/JS 明显强于 Java/C++/Go）【实测】[S39]。
- 正面迁移证据：符号执行 trace 续训可跨五类属性迁移（头部层 S25）；编译器 fuzzing 跨语言（Fuzpiler 头部队列）成立——**"验证工件"比"语言"更可迁移**。

对阙疑（648 已完成 C 十卡、未来嵌入式）【推断】：

- 三层里**语言无关资产**占绝大多数：判决状态机、账本、保护器、证书 schema、变异/规则注册表、证据分级、保形标定——全语言无关；
- 语言相关的只有四件薄适配：探针程序、claim 文本、编译命令矩阵、标准 registry（C 与 C++ 分别登记，已在 H4 建）；
- 嵌入式域的正确姿态是**明确承认自动化能力减半**（55.6% 是实测锚点），把 LLM 限制在起草、把人审比例调高、claim_boundary 收窄到该工具链实测可得范围；不承诺 host 工具链证据（与 v31 wasm 边界同纪律）。

> **M5（落地动作）**：架构上把"语言无关核心 / 语言适配包"边界写进文档（仓库拆分 C 线时即为验收条件）：适配包 = `{standards_registry 片段, probe_templates, compiler_matrix, claim_glossary}` 四件；新语言入场验收 = 648 模式重放（N 张标准 + 10 卡 120 组 + 门 0 block），不另造中间层。

## 6. 误报/漏报权衡：从"六行业代价表"升级到可逆性 × 后果矩阵 + 非对称保形预算

- v26 已有六行业错误代价比；2025–2026 决策框架的增量在两处：
  1. **可逆性 × 后果四象限**（agent 治理领域 2026 事实标准）：易逆+低后果自动；难逆+高后果前置人审；高后果但易逆=先执行后审计；新加坡国家 AI 治理框架把"动作的范围与可逆性"列为强制评估项【二手汇编，含 NIST 取向】[S41]。
  2. **非对称代价下的非对称阈值**：CBMC 作者的工业口径——关键软件定义指标是最小化误报率（高误报摧毁工具信任），而阙疑尾部层天然相反（漏放摧毁证书信任）；保形预测支持按代价函数逐实例设 α（CAP 已证），两侧阈值不需要、也不应该相同 [S24 区访谈]。
- 级联系统里纯置信阈值被证劣于"校准置信 + 在线人工反馈"策略 [S35]。

> **M6（落地动作）**：判决/升级策略矩阵化：横轴 DAL A–E（已有），纵轴可逆性（易逆/难逆），两轴共同决定 {自动 pass, 先执行后审计, 前置人审, 禁止自动}；pass 通道 α 比 block 通道严格一个量级（fail-closed 已在 B1）；每象限记录 FP/FN 实测率回灌 B4。

## 7. 人的角色：从"全量人审"到"判决时定点升级"，2026 人机协作有硬设计

- NIST AI RMF（Govern/Map/Measure/Manage）与 GenAI Profile 把"定义何时人必须介入、记录为何介入、监控介入是否按设计发生"列为治理要求；2026 行业共识是**判决时（decision-time）保障**而非训练时标注 [S41 区/NIST 官方表述]。
- 触发条件应是可测信号而非直觉：①校准不确定度（保形/选择性预测口径，不是裸 softmax）；②规则冲突/策略歧义；③OOD/漂移；④高后果/难逆动作；⑤重复申诉/高影响来源 [S41 区]。
- 效率设计：把升级当打分排序问题（priority_score），升级 Top-X%；UI 必须给推理、置信、备选；人的决定带**强制 reason code**回灌为标签；告警疲劳要调阈值并保证真恶化信号必达 [S41 区]。
- 人审自身不一致率 34–37%（MT-Bench/AlpacaFarm，v31 Sage 已引）——人审是权威源不是真相源，二审/盲审是必需品不是摆设。
- 反模式证据：TheCompany 多步办公任务 ~70% 失败率、最强模型仅完成 24%【二手实测引述】，说明"全自动"在长尾上不可行，升级通道是架构不是兜底。

**对阙疑的硬映射**【推断】：647 A2 已修半个高危洞（`DecisionEvent.from_dict({})` 默认 APPROVE+BATCH_AUTH），另一半是**人审队列的调度与接口**：

> **M7（落地动作）**：人审队列从 FIFO 改 priority 排序（DAL 权重 + 置信不足 + 冲突 + 连续被翻案）；override 接口白名单枚举裁决 + reason code 必填 + 缺字段 fail-closed（直接封死 647 A2 默认值洞）；看板并列三指标：升级率、人审翻盘率、误放事后追溯率（人审有效性可度量，防队列变黑洞）；anti-windup 冻结的是**超预算且超期**队列，冻结本身要通知而不是静默丢请求。

- **不让自进化环自产自销**：验证器角色 LLM 不得担任（SAGE 外部验证器纪律 [S36]）；critic 也必须含确定性组件（MDL/校准）。
