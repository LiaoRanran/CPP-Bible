## 1. 一句话结论

**资源版图上阙疑的自给率异常高：数据（452 账本+攻击集）自有、算力需求极低（全部实验单机/免费层可跑）、开源地基已落地——真正的短板只有"人"：导师（对冲机构信号+补安全领域背书）与外部眼睛（P16 单点消除）。因此资源篇的 80% 篇幅是"怎么冷邮件"与"怎么让人看到"，不是"怎么找资源"。**

## 2. 找导师：冷邮件工程【已查证：方法层多源一致 [S8]】

- **对象筛选（6–10 位，v34 口径）**：近三年发过以下主题之一者——LLM judge 审计（JudgeBench/CodeJudgeBench 作者系）、AI 安全红队（ATLAS 引用者）、软件供应链安全（Sigstore/in-toto 系）、formal methods for ML。每人的近作为邮件个性化素材。
- **邮件结构（五段 ≤150 词，多源共识 [S8]）**：
  1. 主题行带具体性："Meta-verification of LLM verifiers: a fail-closed system + production ledger（undergrad seeking collaboration）"——绝不写 "Research" 或 "Hi" [S8]。
  2. 第一句：你是谁+一个可验证的钩子（"I built and operate a verification system with a 452-event production adjudication ledger"）。
  3. 第二段：他们的哪篇工作与你相关、引用具体结论（证明读过）。
  4. 第三段：你要什么（一次 30 分钟通话 / 对论文初稿的意见），并给低门槛出口。
  5. 附：arXiv 链接+GitHub 链接+一页系统图（Figure 1）。附件≤2。
- **节奏**：一批 6–10 位、间隔一周、无回复不追发第二封（换对象不换人）；命中后的第一句问题永远关于他们的观点而非自己的系统。
- **身份表述纪律**：写"undergraduate researcher, first author, project lead"，不写"独立研究员"之类的虚衔——诚实反而加分。

## 4. 找算力：需求极低【推断，基于实验结构】

- 全部实验（E1–E7+A1–A4）的算力大头是：跑 2 个家族的 LLM judge 对 47+毒卡/不可能卡的判定（≈几百次 API 调用）+ 全量 pytest + 变异测试——单机 CPU 可跑 API 无关部分；judge 判定预算 ≈ 数十美元 API 费。
- 免费资源备选：Google Colab/Kaggle GPU（免费层）、Google Cloud Research Credits（学术申请）[S9]、GitHub Actions（门禁 CI 免费额度）。
- **结论：不申请任何算力合作**——算力申请的时间成本高于省下的钱；唯一例外是若导师要求使用其实验室集群。

## 5. 开源策略【已查证：地基已就位】

- **投稿前开源（推荐）**：arXiv 占位同周把仓库转公开（Apache-2.0/DCO 已就位）——理由：(a) artifact claim 需要可点开验证；(b) 抢发窗口内 GitHub 时间戳也是占位；(c) 冷邮件附件需要活的链接。
- **开源内容三包**：代码（全仓）、数据（Zenodo：452 账本快照+攻击集+schema）、重放（单脚本 artifact）。**不开源**：VSA 密钥（本就不入库）、`data/vsa_secret.key` 类凭据、未冻结的工作区脏文件（655_baseline 登记的 136 脏文件必须先清理——这是公开前真正的工程门槛）。
- **公开前 checklist（新增最关键三项）**：DCO CI 校验补上（目前未强制 [内部]）；license header 普查收尾（655 进行中）；SECURITY.md 里的漏洞报告通道指向有效邮箱。

## 6. 社区曝光（低成本序列）

1. arXiv 当天：X/Threads 一条推文串（带 Figure 1+一个真实改判案例动图）；HN 提交（标题用论文副标题的口语版）；r/MachineLearning 每周讨论帖。
2. 学术博客一篇中文+一篇英文（个人站/CSDN+个人 GitHub Pages），讲"为什么验证器不能自证"的故事版——对冲审稿人误解，也喂给搜索引擎。
3. 会议社交（若中）：只做两件事——demo 摊位放"现场重放一次改判"，与 §2 名单里的作者一对一约咖啡。

## 7. 阙疑应该怎么做（3 条）

1. **冷邮件批次绑定 arXiv 占位**：占位上线一周内发 6–10 封（邮件里有链接才有转化）；名单按 §2 筛选标准先列 10 人放进 08 篇时间线。
2. **公开前完成三项 checklist**（DCO CI/header 普查/脏文件清理）——排在 655 批次收尾后、arXiv 占位前，是开源动线上的硬阻塞项。
3. **曝光内容从"系统介绍"改为"案例故事"**：所有渠道统一用 G12（假开关被差分验证抓出）作故事核——真实案例的传播力是架构图的十倍。
