## 1. 一句话结论

**实验章的骨架是"三对比+四消融+一案例"，全部材料已在库里：对比（LLM 直接裁判 / 规则验证 / 阙疑全栈）不需要外部竞品——因为元验证没有直接竞品，对比对象就是"阙疑拆掉关键件后的自己"；基准构建的本质是把 452 事件从"生产日志"洗成"带标注、带 schema、可单脚本重放的 artifact"——这是 v34 已定的 ACM 三徽章路线，本篇把它拆成最小字段表；统计上，所有比率走 Clopper-Pearson 区间 [01 篇]，小样本不装大样本。**

## 3. 基准构建：452 事件 → 公开基准

- **最小字段表**（每事件）：event_id / 时间戳 / 卡 ID / 判决前值后值 / 触发保护器 ID / 冲突证据哈希 / 改判理由类别 / Merkle 叶证明。452 条中 MODIFY 口径 R5=0.9851 已知【已查证】。
- **标注需求**：每条事件加两类人工标注——(a) 改判类型分类（冲突/校准/预算），(b) 事后对错复核（当时判对了吗）。标注量 ≈ 452×2 人审小时级，是全项目最大人审投入，但也是"真实账本"novelty 的成本所在。
- **公开方式**：Zenodo 数据包（v34-P3 已排）+ 单脚本重放；负样本（毒卡/不可能卡）分开打包并附生成器，防污染复用。
- **口径纪律**（子代理两条提醒直接写进论文）：① 卡数口径在 37/47 间演进，论文固定用"47 张（37 verified+10 draft）"并给 breakdown；② 650–652 区间 136 脏文件的遗留现场不影响冻结数字（v7/账本 sha 未变），论文只引冻结契约数字。

## 4. 对比实验：没有直接竞品怎么比【推断】

三层对比梯度（每层都是"自己 vs 自己拆件"，加一个外部参照）：

1. **LLM 直接裁判**（GPT/Claude 级 judge 对同一批卡/毒卡判 pass-fail）——预期在注入串与不可能卡上大量被骗（ImpossibleBench/2504.18333 的结论背书）；
2. **简单规则验证**（去掉保护器与 fail-closed，只留规则匹配）——预期假阴/假阳双高（Rice 定理的工程体现）；
3. **阙疑全栈**。
4. 外部参照不比输赢、比**性质**：表中列出 BabelJudge 等工具"有/无对抗者/有/无账本/有/无 fail-closed"——用 02 篇的四维表代替不可比的数字。

**统计显著性**：逃逸率 0.0711%（1/1406）vs 对比层，用 Fisher 精确检验（小样本唯一正解）+ 报告效应量（风险差及其 CI）；绝不用 t 检验/正态近似【推断，统计学标准】。

**Threats to validity 必写三条**：内部（变異算子集有限、challenger 作者即系统作者的自评偏差）；外部（单域 C++、47 卡样本小、嵌入式域 L0 证据不可得 [647 E2 自登记]）；构念（"逃逸率"只对算子集定义——版本号铁律 [v35-02]）。

## 5. 阙疑应该怎么做（3 条）

1. **把实验章冻结为 E1–E7+A1–A4+案例 1 的清单**，每项标注"材料已备/需 656+ 批次补建"：需补建的只有 E4（不可能卡）、E5（变异集）、E1（性能）、A4（注入测试）四项——全部已在 v35-M1/M2/M3 的排期里，无新增方向。
2. **452 事件标注先行**：标注是论文的关键路径（人审瓶颈），在 challenger 扩容（G9）完成前的空档期先做——它不依赖任何未修复项。
3. **对比实验的 judge 用两个不同家族的模型**（如 GPT 系+Claude 系各一），报告双序一致口径（v35-01 建议 3）——一处细节挡掉"你只测了一个 judge"的审稿意见。
