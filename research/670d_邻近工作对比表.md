# 670d · 邻近工作精确对比表

> **性质**：对 `paper_v0.6.md` §2.8 五维表的**扩展**（6 维 × 6 工作），供论文改写时替换/补充。
> **纪律**：本表是**定位性/定性**对比，**不是**对各自系统的实测结论（§2.8 诚实标注）；文献信息以 arXiv 核验为准。

## 1. 六维对比表

| 工作 | 演化对象 | 验证对象 | 防过拟合机制 | provenance | 应用域 | **与我们的区别** |
|---|---|---|---|---|---|---|
| **Benchmark Self-Evolving**（arXiv:2402.11443, COLING 2025） | **题目**难度与分布 | 模型输出 | 换新题（多智能体改写/扩充） | 无 | 通用 LLM 评测 | 它演化**被测物**；我们演化**尺子**（判决与证据能力），且要求尺子变化**可被外部度量** |
| **ArenaBencher**（arXiv:2510.08569） | **测试用例** | 模型输出 | 多模型竞争式自动更新测试项（对抗泄漏） | 无 | 通用 LLM 评测 | 同上；且它的裁判仍是**固定测试**，无法表达"不知道" |
| **Meta ACH / MUTGEN**（arXiv:2501.12862 / 2506.02954） | **测试与变异体** | 代码缺陷 | 变异反馈驱动生成（合规加固） | 弱（无三元组） | 工业代码测试 | 我们**复用**"变异反馈驱动生成"，但**拒绝**把变异得分当检测率（§7.4 第 4 点） |
| **SWE-bench Verified / Pro**（OpenAI 等） | **样本**（人工核验/加难） | 模型补丁 | 人工核验 + 更难子集（对抗记忆） | 无 | 代码修复评测 | 它是**评测基准**；我们是**验证系统**——它测"模型会不会修"，我们测"断言真不真" |
| **MiniCheck**（arXiv:2404.10774） | 无（静态模型） | 文本 grounding（事实核查） | 无 | 无 | 事实核查 | 它判"文本是否被证据支持"（**相似度/蕴含**）；我们判"**可执行断言**跑一遍发生什么"（编译/运行） |
| **LiveBench**（arXiv:2406.19314, ICLR 2025） | **题目新鲜度**（月度更新） | 模型输出 | 客观 ground truth + 自动评分（规避 LLM 评审偏差） | 无 | 通用 LLM 评测 | 它防"记住题目"；我们防"**尺子被偷偷改短**"（口径纪律 + 元状态对账） |

## 2. 六维定义（表头口径）

| 维度 | 含义 |
|---|---|
| **演化对象** | 系统随迭代变化的是什么（题目/样本/测试/尺子） |
| **验证对象** | 最终被判定"对错"的是什么（模型输出/代码缺陷/文本蕴含） |
| **防过拟合机制** | 对抗"刷分/记忆/泄漏"的手段 |
| **provenance** | 是否携带"谁生成/谁验/证据在哪/在何条件成立" |
| **应用域** | 面向的领域（通用 LLM / 代码 / 事实核查） |
| **与我们的区别** | 一句话区分点 |

---

## 3. 一句话总结

> 上表 6 个工作，**5 个在换"被测物"**（题目/样本/测试/模型），**1 个（MiniCheck）在换"判据类型"**（但仍不执行代码）。
> **没有一个在换"尺子本身"并证明换尺子可被外部度量**——这正是祈易的位置：**判决能力与证据获取能力**的演化，且**可被第三方复算、可被证明不是刷分**（§2.8、§6.3）。
