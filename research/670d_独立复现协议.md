# 670d · 独立复现协议（独立复现者操作手册）

> **性质**：操作手册（**不改 `REPLICATION.md`**——红线；本文件是对它的**细化与勘误建议**）。
> **基线**：`REPLICATION.md`（661 D2）+ `docs/669_独立审计.md`（第三方只读审计）。
> **目标读者**：**没有上下文**的第三方复现者（M6 硬节点）。

---

## 0. `REPLICATION.md` 需先勘误的三处（复现前必读）

| 项 | `REPLICATION.md` 现状 | 实际 | 影响 |
|---|---|---|---|
| holdout 样本数 | "20 样本" | **30 样本**（可测真错 16） | 复现者会以为分母错 |
| WSL 依赖 | 标"可选" | **holdout/external 两个数字硬依赖 WSL** | 缺 WSL ⇒ **静默掉分**（35.0%→10.0%） |
| `env` 字段 | 未提 | external 产物**缺 `env`** | 复现者无法判断"低分是能力差还是环境缺" |

> **建议**：投稿前把这三条补进 `REPLICATION.md`（本文件给建议，不直接改）。

## 1. 环境要求（含版本）

| 依赖 | 最低版本 | 用途 | **缺了会怎样** |
|---|---|---|---|
| Python | ≥3.11（本仓 `.venv`） | 全部工具/测试 | 直接失败 |
| uv（可选） | ≥0.11 | `uv run` 一键环境 | 可用 `.venv/Scripts/python.exe` 替代 |
| Node.js | ≥20 | `web_logic_check_655.mjs` | 前端台账无法校验 |
| g++ | ≥13 | 编译检测 | 编译类检测全失效 |
| clang++ | ≥15 | 跨编译器差分 | B 层检测失效 |
| **WSL（Ubuntu 22.04+）** | — | **ASan/UBSan/TSan 真机检测** | **holdout/external 静默掉分**（关键！） |
| `setarch`（WSL 内） | util-linux | 关 ASLR（TSan 需要） | TSan 间歇性失败 |

## 3. 复现成功的判定标准

| 数字 | 判定 | 容差 |
|---|---|---|
| holdout 87.5% | **逐样本 `id→verdict` 一致** | 0（离散） |
| external 35.0% | 逐样本一致 | 0 |
| 变异 97.3% | `k/n` 一致 | 0 |
| 反事实 F1 | `tp/fp/tn/fn` 四元组一致 | 0 |
| 规则数/账本 | 精确相等 | 0 |

- **若环境不满足（如缺 WSL）**：**不得**判"复现失败"，应判 **`UNVERIFIED`**（这是 669 审计 P0-1 的核心要求）——**"跑不动"与"跑出低分"必须可区分**。
- **CI 重叠**：对含 CI 的数字，允许**点估计落在原 CI 内**即算通过（用于不同机器的小扰动）。

## 4. 常见失败模式（对照排查）

| 现象 | 根因 | 处置 |
|---|---|---|
| external 从 35.0% 掉到 10.0% | **缺 WSL** ⇒ 15 条 sanitizer 降级 unknown | 装 WSL，或判 `UNVERIFIED`（**不要**当能力差） |
| TSan 间歇性无输出 | WSL 高熵 ASLR | WSL 内 `setarch -R` 关 ASLR |
| 哈希漂移 / Merkle 不匹配 | **CRLF 转换** | `git config core.autocrlf false` 后重算 |
| `holdout_reveal_661.py` 报 `REFUSED` | **已 reveal（铁律）** | 这是**正确行为**，不是 bug |
| 前端台账 4/4 变红 | 前端数据漂移 | 重跑 `tools/web_data_653.py --build` |
| `ModuleNotFoundError: gate_engine` | 未加 `sys.path.insert(0,'tools')` | 见 §2 命令 |
| API key / 环境变量缺失 | 某些工具需 token | 检查 `.env`（**不得提交**） |

## 6. 一句话

> 复现协议的**关键不是"跑出同样的数"，是"跑不出来时能说清为什么"**——缺 WSL 必须判 `UNVERIFIED` 而非 FAIL，否则"环境缺失"会被误读成"能力不足"（这正是 669 审计 P0-1 的教训）。
