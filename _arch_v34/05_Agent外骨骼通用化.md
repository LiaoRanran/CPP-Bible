## 0. 阙疑外骨骼现状（v31–v33 口径）

- 已成型的原语：L0–L3 证据分级、四态判决（pass/fail/unknown/abstain）、保护器（B1–B5，v33 扩 B7–B10）、账本与权威日志（452 事件）、M1–M7 阴性测试、MDL 准入、人审队列、PCK 证书、reproduce manifest。
- 模型可替换性已在实践：25 个批次中换过多个 LLM；判决宪法要求 LLM 永不担任唯一改判者（v33 M3）。
- 当前无插件市场、无外部工具注册、无多域适配；外部接口只有仓库文件与命令行。

**总判断**【推断】：2026 年的 agent 框架格局给了阙疑一个极其清晰的空档——**LangGraph/CrewAI/AutoGen/Dify 全部解决"怎么让模型做事"，没有一个解决"做的事是否可被独立承认"**。阙疑的外骨骼价值不在编排（那是已商品化的一层），而在编排之下的**证据-判决-保护器-账本-信任根**五件套；而 2026 年 MCP 生态的安全事故潮证明，插件接口若不带阙疑式的准入与证据纪律，会比 npm 地狱更快更糟。同时，临床医学界在 2026 年独立重新发现了阙疑的架构（确定性核心作信任锚），这是跨域通用性最强的外部佐证。

## 1. 2026 框架格局：编排层已商品化，治理层是公开空白（问题 3）

### 1.1 四大框架的定位与缺口（2026-09 快照）

| 框架 | 形态/许可 | 心智模型 | 公开短板（多源一致） |
|---|---|---|---|
| LangChain/LangGraph | 库/MIT，100K+ stars | 图状态机、分支/检查点/HITL | 抽象税重、版本破坏性变更、memory 只是对话缓冲 [S47][S49] |
| CrewAI | 库/MIT，50K+ | 角色 crew+Flows 事件驱动 | 工具调用 trace 可能与实际执行不符（issue #3095 类）；恢复/检查点弱；多模型但偏 OpenAI 优化 [S47][S49] |
| AutoGen | 库/CC-BY；**已分裂** | 对话式多代理 | 裂为维护版、社区 AG2 fork、Microsoft Agent Framework（AutoGen+Semantic Kernel 合并，1.0 GA）三条线 [S47] |
| Dify | 可视化平台/Apache-2.0，149K stars | 线性工作流+RAG | 多代理委托/分支弱、团队治理浅（版本/回滚/多人编辑不深）、复杂逻辑有天花板 [S47] |

- **治理层是系统性空白**：生产团队视角的 2026-09 综述直接点名——AutoGen"止于对话协调，不管辖代理用决定做什么：无实时异常检测、无合规映射、无 prompt 攻击护栏、无行为测试套件"，生产部署者必须自建整个治理层；LangGraph/CrewAI 同样缺安全/合规/可观测性，需外挂商业治理平台 [S48]。
- **记忆层是第二空白**：四大框架的 memory 基本是会话缓冲/摘要，无跨会话持久认知记忆 [S49]。
- 市场正在分层：编排（开源框架）→ 观测评估（LangSmith 等）→ 治理（Openlayer/Credo AI/watsonx.governance 等）三层分立 [S48]——**没有任何一层把"判决的独立可重算性"当一等公民**。

### 1.2 阙疑的位置【推断】

> 阙疑不应再写一个编排器（LangGraph 的图、CrewAI 的角色都已够用且免费），而应作为**可嵌入任何编排器的治理/验证内核**存在：
> - 对 LangGraph：以"验证节点/策略节点"身份接入图（每个产生断言的节点过四态判决）；
> - 对 Dify：以外部验证 API + 证书存储接入其 RAG 管线；
> - 对 OpenAI Agents SDK：作为其 guardrails 钩子的外部确定性裁判（其 guardrails 是框架内机制，阙疑提供的是独立第三方可重算层）。
>
> 一句话定位（与 01 篇 §3 一致）：**"模型是可替换燃料，编排是可替换车架，阙疑是刹车、仪表盘与年检系统。"**

## 2. 领域无关的核心原语：哪些真的与 C++ 无关（问题 2）

### 2.1 五件原语的抽象检验

逐个过"去掉 C++ 语义后还剩什么"【推断，结合 RATS 标准词汇 [v33-S43]】：

| 阙疑原语 | C++ 实例 | 剥离语言后 | 领域无关性 |
|---|---|---|---|
| **证据 Evidence** | 编译器输出/asm/sanitizer 报告/标准条款 | 带类型、等级、来源、时间戳、环境绑定的材料包 | **完全领域无关**（RATS Evidence 同构） |
| **判决 Verdict** | 四态+条件+置信度 | 对一组证据按显式策略合成的结构化结论，含反例与理由 | **完全领域无关**（RATS Attestation Results） |
| **保护器 Guard** | B1 冲突/B5 准入/B8 shadow | 确定性策略点：准入/熔断/预算/工具门/人审中断 | **领域无关，策略库域相关** |
| **账本 Ledger** | 452 事件 Merkle 链 | 只追加、可加密验证、带时序锚的决策流水 | **完全领域无关**（CT/t-log/in-toto 同构） |
| **信任根 Root of trust** | 真机编译器+ISO/IEC 标准 | 域内不可再退让的事实来源 + reference values + endorsement | **接口领域无关，实例每域重建（§5）** |

派生原语同样可剥离：知识卡（带证据的结构化断言）、阴性测试（对验证器的攻击回归）、MDL（候选知识的准入门槛）、人审（HITL 升级点）、证书（证据+签名+展示层，C2PA/W3C VC 词表 [v33-S55]）。

### 2.2 分层架构建议（外骨骼化的工程形态）

【推断】参照 YASA 的 UAST 经验（语言无关核心+语言特定语义包 [v34-S33]）与 RATS 角色分离，建议四层：

```
┌─ 域适配层（可替换）：C++包 / 临床包 / 法律包 ……
│   · 信任根绑定（编译器+标准 / 指南+循证库 / 法规+判例库）
│   · L0 验证器（真机运行 / 确定性核查规则 / 引文核验）
│   · 证据类型与策略模板
├─ 验证内核层（queyi-core，稳定）：
│   证据模型 · 四态合成 · 保护器框架 · 账本 · 重放引擎
├─ 编排无关接口层：
│   验证节点 SDK（Python/TS）· MCP tool（受 §3 纪律约束）· 证书 API
└─ 编排层（可替换）：LangGraph/CrewAI/自研 CLI 均在更外层
```

v33 的 RATS 三分（reference values / endorsements / verifier code）正好落在"域适配层 vs 内核层"的分界上 [v33-S43]：政策外置（Appraisal Policy 在 RP 侧）的纪律保证内核不被任何单一域污染。

### 2.3 抽象的边界——什么不能强行通用

【推断】两个不可通用化的东西要诚实标注：
1. **"什么算证据"的本体论**：C++ 中"编译器实际行为"可以高于文档；医学中个案不能推翻指南；法律中判例有管辖等级。证据合并规则随域变化，内核只提供机制，不提供默认跨域政策。
2. **L0 的形态**：编译器是可重复执行的机器；临床指南是需要解释的文本——医学没有"真机"，只有"确定性核查+授权专家"（§5）。外骨骼可以要求每个域**显式声明自己的 L0 是什么**，但不能假装各域的 L0 等价。

## 3. 插件接口：规则/保护器/证据源插件如何不变成又一个 npm 地狱（问题 4）

### 3.1 MCP 生态 2025–2026 的事故潮——最及时的反面教材

- **架构级 RCE（OX Security，2026-04-15 披露；CSA 研究笔记 2026-04）**【第三方安全研究/行业联盟分析】[S50]：MCP STDIO transport 把配置中的命令串直接交 shell 执行，且**目标进程启动失败命令照样执行**；存在于 Anthropic 官方 Python/TypeScript/Java/Rust 四个 SDK；约 1.5 亿累计下载、7,000 公开服务器、约 20 万受影响实例、14+ CVE；Anthropic 定性"预期行为"，责任在下游。Cursor/Windsurf/Claude Code/Gemini-CLI 均在影响名单；Windsurf 存在零点击配置篡改链（CVE-2026-30615）。
- **市场投毒**：研究人员测试 11 个主要 MCP registry，**9 个可被试验性恶意包投毒**；一次攻击向一个 AI 技能市场灌入 800+ 恶意包；MaliciousCorgi 两个 VS Code 扩展（合计 150 万安装）长期窃取开发者打开的全部文件 [S50][S51]。
- **漏洞谱系**（vulnerablemcp 数据库，50 个/13 critical，2025-09～2026-02）[S51]：Figma MCP RCE、Cursor 大小写保护绕过、多个 DNS rebinding（Neo4j/Vet/Coder）、Google Docs 零点击 RCE、Git MCP RCE 链、fetch/filesystem SSRF/路径遍历——类型覆盖 RCE/SSRF/越权/数据外泄。
- OWASP MCP Top 10（MCP07 鉴权缺失）；NSA 发布首个 MCP 安全指南；CSA 指出基础规范无强制鉴权 [S50][S51]。
- 严重性放大器是 OWASP LLM06"过度授权"：插件直接进入 agent 执行上下文，恶意插件不只偷数据，还能**以你的身份指挥 agent 行动** [S50]。

### 3.2 比 npm 更危险的三个结构性原因【推断】

1. 插件运行时即凭据环境：npm 包多在构建期，MCP/agent 插件在会话期持有工具权限与上下文；
2. 评价信号缺失：registry 无成熟评分/签名/审计传统（npm 生态用二十年建立的防线这里从零开始）；
3. 配置即代码执行：STDIO 设计让"安装插件"≈"往 shell 写命令"[S50]。

### 3.3 阙疑插件接口的准入纪律（把自家 MDL/B5 用在自己身上）

【推断】阙疑未来开放三类插件（规则包、保护器、证据源/工具适配器），接口设计第一天就应内置：

> **P1 能力最小化+显式声明**：插件清单式声明所需权限（读哪些证据类型、能否出 pass、能否调网络），默认零权限；适配 OWASP"权限恰好够用"与 Rule of Two [S50][v33-S41]。**任何插件不得直接产出 pass/fail，只能产出证据**——判决权永远在内核（防止插件绕过四态）。
>
> **P2 准入即 MDL + 阴性测试**：插件必须随附自己的测试集与"攻击样本"（类比 M1–M7：给出应被拒绝的恶意输入集），过 B5 才进 registry；证据源插件额外要求来源白名单与引文可回溯（医学域同款要求 [S52]）。
>
> **P3 分发安全**：registry 只接受签名包（Sigstore/cosign 签名，[v32-Sigstore]）、内容寻址存储（03 篇 CAS）、依赖树 SBOM 与来源固定（commit/哈希，不用浮动 tag）；核心包拒绝 postinstall 类安装期执行。
>
> **P4 运行时隔离**：插件在沙箱（容器/WASM/受限子进程）中执行，文件系统与网络默认拒绝；STDIO 类命令拼接一律禁用，进程参数化启动（MCP RCE 的直接教训 [S50]）。
>
> **P5 shadow 先行+可杀开关**：新插件先 shadow 模式只记账（v33 B8）；每个插件独立熔断（v33 B9）；用户侧一个总开关可禁全部第三方插件。
>
> **P6 插件行为上链**：插件产生的每条证据/每次拦截写入账本（哪个版本的哪个插件、何输入、何输出）——插件作恶可事后审计，是投毒后的追偿前提。
>
> **一句话**：阙疑的插件市场哲学是"**少而慢**"——100 个经过准入与签名的插件胜过 10000 个自由注册的 MCP 服务器；把 MCP 事故当作提前免费拿到的压测报告。

## 4. 与 MCP/A2A 等标准的关系：借道而不押注

【推断】2026 的标准化正在 agent 层快速发生（MCP 工具、A2A 代理间通信、GAIE 推理扩展 [v34-S14]），阙疑策略：
- **消费标准而非自建传输**：工具接入用 MCP 客户端（带 §3 纪律），不自创插件传输协议；
- **产出标准化制品**：证书/断言用 in-toto/C2PA/W3C VC 词表（v33 T7），判决事件可导出为标准 attestation；
- **不押注单一编排标准**：AutoGen 在 2026 年一分为三 [S47] 证明编排层 API 不稳定，内核价值恰在于"车架换了刹车还在"——这正是"模型可替换、能力沉淀在框架"口号的技术兑现。

## 5. 信任根的跨域迁移：医学、法律的信任根是什么（问题 5）

### 5.1 临床医学：2026 年独立长出与阙疑同构的架构

- **可审计源验证框架**（Frontiers in Artificial Intelligence, 2026-02）【概念论文】[S52]：curated 医学知识库+显式 provenance 元数据、把建议链接到**可识别的临床指南与同行评审来源**的 RAG、记录输入/检索证据/推理步骤的**防篡改审计日志**；明确列出可行性挑战：知识库治理与更新、RAG 引文保真、证据偏见传播、延迟/可用性、隐私、FDA SaMD 与 EU AI Act 合规。
- **无 LLM 的确定性事实核查模块**（2026-06 v4）【论文】[S53]：把生成摘要与病历都分解为**原子命题**，用离散逻辑核查六类关系——否定、蕴含、时序一致、互斥、数值一致、存在性（遗漏检测）——独立于任何 LLM 给判定。这与阙疑"原子断言+L0 固定验证器+L1–L3"几乎逐元素同构。
- **确定性核心作信任锚**（arXiv:2604.26671，2026-04）【论文/观点】[S54]：明确提出 **deterministic clinical core as a trust anchor**，AI 作上下文验证器、分级模型升级、人监作为架构层；信任是**分级授权**：L1 监控告警 → L2 验证过的建议支持 → L3 有限直接操作；信任指标按计量学原则（测量不确定度、校准、溯源）设计。信任不是单个模型的属性，而是**嵌入了证据轨迹、人监、分级行动权的系统的架构产出物**。
- 临床医生偏好明确引用指南/高质量研究的建议；EBM（Sackett 1996）要求个人能力与最可靠外部证据结合 [S52]。

### 5.2 法律：信任根是法规/判例+可核验引文+职业责任

- ABA Formal Opinion 512（2024-07-29）：律师在法律文件中使用 AI 输出前负有**验证义务**（Model Rules 1.1 胜任、1.6 保密、5.3 非律师人员/工具监督）；至 2026 年初 35+ 州律协发布补充指南 [S55]。
- 信任根结构【推断】：成文法+生效判例（带管辖等级与时效性）→ 可核验引文（每条断言到条款/判例 pin cite）→ 律师职业责任兜底（人监不可移除）。

### 5.3 跨域迁移表与迁移方法

| 域 | 信任根（L0） | reference values | 人监角色 | 证书消费方 |
|---|---|---|---|---|
| C++（阙疑现域） | 真机编译器行为+ISO/IEC 标准 | 编译器版本、标准版本、规则库 | 作者/审校，可缺席于重放 | 读者/下游 agent |
| 医学 | 循证库（指南/RCT/系统评价，GRADE 分级 [v33-S10]） | 指南版本、证据等级、适用人群 | 临床医生（不可缺席，L1–L3 授权）[S54] | 医生/监管（FDA/EU AI Act） |
| 法律 | 生效法规+判例库 | 管辖区、时效、判例层级 | 执业律师（伦理义务 [S55]） | 律师/法院 |
| 工程运维（近邻） | 监控/日志+变更记录 | SLO、基线配置 | on-call | SRE/审计 |

【推断】迁移方法（不是搬规则，是搬方法）：
1. **找域内的"编译器"**：那个域里结果可被重复、权威、不可被模型意见推翻的东西——医学是指南+确定性质检规则，法律是法条文本；
2. **与域内专家共写 reference values 清单**：什么版本、什么等级、什么适用条件；
3. **保留同一套机制（证据/判决/保护器/账本），替换策略库与信任根**；
4. **人监等级随域重设**：C++ 允许"无人工、凭重放即 pass"，医学/法律永远要人签——这恰好是 RATS RP 政策外置的本意 [v33-S43]；
5. **不碰没有 L0 的域**（如开放式历史叙事、审美评价）：没有可退让事实源的域，外骨骼只能提供 provenance 不能提供 verdict。

### 5.4 对"通用 agent 外骨骼"叙事的最终修正

【推断】通用化的正确口号不是"一个框架验证一切知识"，而是：

> **"同一套可验证决策机制，绑定各域自己的信任根；内核领域无关，信任根永远域内。"**

这个定位在 2026 年有了罕见的双向佐证：安全工程侧有 RATS/SLSA/in-toto/C2PA 标准群 [v33]，临床侧独立长出确定性核心+证据轨迹+分级授权 [S52-S54]——两边在不知道彼此的情况下收敛到同一架构，说明这组抽象不是阙疑的发明，而是被多个高保障域重复发现的结构。这是方向 5 全部问题里最有分量的一个事实。

## 6. 给阙疑的 3 条具体建议

> **建议 A1：明确"不做编排器"，做可嵌入的验证内核；queyi-core 拆分按 §2.2 四层执行。**
> 内核稳定面写接口契约（证据提交/判决查询/账本读/保护器注册），LangGraph/Dify 适配作为外围示例；2026 年内不做自研多代理编排。模型可替换性从实践纪律升级为公开的架构承诺（燃料/车架/刹车叙事）。

> **建议 A2：插件接口按 P1–P6 一次设计到位，宁晚开放不乱开放。**
> 核心红线：插件只产证据不产判决；签名+CAS 分发；沙箱执行；shadow 准入；行为上链；用户总开关。MCP 只作为工具客户端协议引入且带同等约束。把"插件少而慢"写进项目价值观。

> **建议 A3：跨域只做"方法迁移文档+一个第二域试点"，不做通用产品。**
> 产出《域适配手册》（如何找域内编译器/reference values/人监等级）；第二域试点优选证据结构最接近的（工程运维：日志/配置即 L0，无伦理负担），医学/法律仅保持学术对话（§5 论文价值）不做产品——没有合资质伙伴与 L0 数据授权前，高监管域不碰（S52 所列 FDA/EU AI Act 义务单人无法承担）。

## 7. 盲区与诚实记录

1. **框架能力快照会快速过期**：AutoGen 已一分为三 [S47]，Microsoft Agent Framework/Google ADK/OpenAI Agents SDK 均在快速迭代；§1 的功能对比只在 2026-09 成立，架构判断（编排商品化、治理真空）比功能表更耐久。
2. **MCP RCE 数字来自安全厂商披露与 CSA AI 辅助研究笔记**：CSA 文档自述"未经官方审查批准"；20 万实例/1.5 亿下载为厂商估计量级，精确数以 CVE 数据库与厂商后续修复公告为准；本文将其作为设计教训而非司法结论使用。
3. **临床架构论文多为概念/观点而非落地系统**：Frontiers 文明确"不报告原型实现"[S52]；arXiv:2604.26671 为 perspective；它们证明的是**架构趋同**，不是该架构在临床已被验证有效——跨域有效性完全未证。
4. **法律域未检索中国法语境**：ABA 意见是美国普通法体系；中国法律 AI 的信任根（裁判文书网/法规库/司法解释层级）未调研，不适用 §5.2 结论。
5. **内核泛化的工程成本未估**：把 813 行 C++ 核心真正抽象成域无关内核，规格改写工作量可能接近重写；§2.2 是目标架构，不是近期任务，近期仍以 C++ 单域做深。
