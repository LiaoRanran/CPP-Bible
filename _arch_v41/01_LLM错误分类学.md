# _arch_v41 · 01 LLM 错误分类学（方向 1）

> 核心问题：LLM 生成代码/知识时的错误如何被学界分类、各类占比、C++ 特有失败模式，以及阙疑 67 规则/9 保护器对错误类别的硬覆盖。
> 诚实标注：【论文·实证】= 有实验数据；【综述】；【经典】= 学界共识；【推断】= 对阙疑的判断；【盲区】= 无法核实。

---

## 一、学界的错误分类谱系（三套独立 taxonomy 收敛）

1. **Dou et al. 2024（3 大类 /12 子类）**【论文·实证】：22 名专家双标注 7 个主流 LLM 在 3 个基准 + 自建 140 任务真实场景上的失败。三大类为**需求理解错、代码实现错、输入输出错**。关键发现：真实场景与学术基准的 bug 分布显著不同；LLM 倾向生成"更短但更复杂"的代码；复杂任务通过率断崖。[v41-S1]
2. **Wang et al. 2024（双维度 taxonomy）**【论文·实证】：6 个模型在 HumanEval 上 557 个错误解，开放编码。语义维度（missing condition / wrong direction / incorrect condition…）+ 语法维度（错误位置）。**最重要发现：大多数错误解可编译、可运行、无编译告警**——编译器完全不报错；且错误多为多行、需重构而非单行修补。[v41-S3]
3. **Lee et al. 2025（4 类幻觉）**【综述】：按可观测特征分为**语法幻觉、运行时幻觉、功能正确性幻觉、代码质量幻觉**，与模型架构解耦。[v41-S2]
4. **Song et al. MAPS 2023**：语义错（对自然语言意图的逻辑误解）占主导；三个模型成功率不同但错误类型分布一致——**错误模式是"生成范式级"的，不是某模型特有的**。[v41-S4]
5. **CodeMirage（JPMorgan，1137 个幻觉片段）**【论文+基准】：语法错 / 逻辑错 / 鲁棒性问题 / 安全漏洞（内存泄漏等）四类，GPT-3.5 产出。[v41-S5]

## 二、C++ 特有的失败模式（实证）

- **内存安全类是 C/C++ 主场**：微软年度 CWE 中约 70% 为内存相关【论文·实证，S6】；MITRE Top25 最危险弱点 #1/#5 均为内存类。
- **Copilot 约 40% 输出含可利用漏洞**：89 场景 /1689 程序（IEEE S&P 2022）【论文·实证，S7】。
- **2026 年最新多层验证（VulBench-CPP，8918 程序/851 题）**【论文+基准】：仅靠静态分析会产生大量"安全幻觉"，功能测试→静态→动态 sanitizer→ESBMC 形式化四层各有独占发现；AI 代码在动态分析层的问题密度系统性高于人类代码。[v41-S9]
- **安全关键合规：0/5 主流模型能生成 MISRA C++ 合规代码**（IEEE Access 2025）；DeepSeek 违规最少（60 行 13 违规），Meta AI 最多；逐条指令能改，整段代码无法自持。[v41-S10]
- **工业界 C/C++ 场景最差**：Cisco 对真实大代码库的实证——Copilot 在 C/C++ 上"经常生成不出有用代码，连空指针检查都没有"，解释也最肤浅。[v41-S8]
- **LLM 找 C++ bug 的能力**：beginner 错误检出尚可，真实代码库高级 bug 检出随难度显著下降【论文·实证，S11】。

## 三、"看似对实则错"的系统性偏差

- 三套 taxonomy 独立确认：**错误解大多编译通过、运行不崩**[S3/S4]——这正是 plausible-sounding error 的机制：next-token 预测保证"形似"，不保证"义对"。
- LLM 修复 UB 时倾向"复制修复的形状"（加 cast、调语句顺序）而不真正移除 UB；sanitizer -O1 才能揭穿【S9 同源现象；DEV 实测】。
- 【推断】这类错正是人审最易漏、自动化最值钱的格。

## 四、硬映射（对 67 规则 / 9 保护器）

**口径说明**：本工作树 `data/_gate_rules.json` 枚举 **63** 条（brief 锚定 67；差异登记为【盲区】，不编造补全）。逐条审视后：

1. **67 规则不是"C++ 错误分类规则"，是"验证治理规则"**：绝大多数（ATOM-FM/STATUS/EV-FALSIFICATION/EV-MATRIX/S1-*/S2-* 等）约束的是卡结构、证据可证伪性、状态迁移、谱系、作者绑定——**管的是"验证流程不许作弊"，不是直接识别 C++ 错误类别**。【已查证】
2. **C++ 错误类别的实际覆盖来自 L0 真机层**：编译实测（杀语法/类型/链接错）→ 运行+断言（杀功能错）→ Werror/矩阵（杀版本/平台偏差）→ 变异基线（杀边界错）。【推断，基于规则语义与 656/657 报告】
3. **覆盖矩阵**【推断】：

| LLM 错误类 | 阙疑现有手段 | 覆盖 |
|---|---|---|
| 语法/编译错 | L0 真机编译 | 强 |
| 功能/逻辑错（可运行） | 运行断言 + 变异基线 | 中-强（23 卡 pass，仅 10-11 变异/卡） |
| 边界错 | 边界三元组（657 起 26 卡） | 中（47 卡中 21 卡照实留空） |
| 内存安全/UB | 编译/运行（UBSan/ASan 非系统内置） | 中：VulBench 证明四层各有独占发现，阙疑无系统化 sanitizer 层 |
| 事实错（非可执行断言） | 规则 + 人审 | 弱：无外部证据核验自动化 |
| 需求理解错 | claim 结构规则 + 人审 | 弱-中 |
| 鲁棒性/异常路径 | 无 | 弱【盲区：未见专项】 |

4. **逃逸 1/1406 属于哪类**：v7 为冻结契约口径；可读文件中**未定位到该逃逸案例的具体类型标注**【盲区】，不编造。642 校准器将逃逸单列为"不可复算的冻结契约"。
5. **机器可验 vs 只能人审**：编译/运行/哈希/Merkle=机器可验（阙疑已做）；概念解释的贴切性、需求意图、跨域类比=只能人审。【推断】

## 五、直说：站不住或需补的点

- **阙疑宣称"验证 LLM 知识断言"，但 63/67 规则是过程治理规则，对"非可执行的事实型断言"没有机器判定手段**——这类断言目前实际靠人审，营销时不能暗示已被机器验证覆盖。【推断】
- VulBench-CPP 2026 证据表明静态/动态/形式化三层各有独占漏洞类，阙疑 9 保护器中无系统化 sanitizer/有界模型检查层，**C++ UB 长尾覆盖低于该基准的方法栈**。【推断】
- 有利证据：阙疑"机器判执行、规则管过程、人审判语义"的三层切分，恰好踩在 taxonomy 收敛出的"可编译但错误"的最大痛点上。【推断】
