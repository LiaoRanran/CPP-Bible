# _arch_v41 · 06 RAG / 检索增强能不能减少错误（方向 6）

> 核心问题：RAG 减幻觉的实证、引文忠实度、检索引入的新问题，以及阙疑 evidence_store（SHA256 内容寻址）与 RAG 生态的关系。
> 诚实标注：【论文·实证】；【综述】；【第三方】；【推断】；【盲区】。

---

## 一、RAG 确实减错，但减的是"参数知识错"，且减不干净

- **Finetune-RAG**【论文·实证】：按真实检索缺陷构造训练，事实准确率 +21.2%；但前提是模型被专门训练过抵抗误导上下文——朴素 RAG 不自动获得该鲁棒性。[v41-S50]
- **教育域对照实验（ICMET 2025）**：RAG 在课程知识库上显著降低幻觉，学生感知可信度与有用性双升【论文·实证，S52】。
- **公共卫生 MEGA-RAG**：多源检索+重排+差异感知精修，幻觉率降 >40%，F1 0.79【论文·实证，S53】。
- **即使检索完全正确，模型仍可能无视它**：ReDeEP（ICLR 2025，机制可解释性）——幻觉发生时知识 FFN 在残差流中压过外部上下文、复制头未整合检索内容；参数先验与证据冲突时模型会站错边。[v41-S51]

## 二、RAG 的新失败类：引文是"真支持"还是"事后贴金"

1. **引文正确性 ≠ 引文忠实性**【论文·实证】：Wallat et al.（ICTIR 2025）提出 citation faithfulness——高达 **57% 的引文是 post-rationalization**（模型先有答案再补引用）；用"移除被引文档看答案是否变化"的反事实测试可揭穿。[v41-S55]
2. **测量率随验证者口径漂移**【论文·实证】：同一 agent 输出，unsupported-citation 率 3%–18% 仅取决于验证者宽严；验证者对"支持谁"一致、对"该 flag 谁"负向一致性仅 0.27–0.30——跨论文数字不可直接比较，必须点名验证者与协议；conformal guard 可给分布内保证。[v41-S54]
3. **幻影引文（链接腐坏/源不可达）2.1%–15.5%**，Google 系两款 >14%；扩大模型规模不改善，提供商身份解释大部分方差【论文·实证，S56】。
4. **CiteGuard**：检索增强归因在 CiteME 上 68.1% 接近人类 69.2%；旁证——某些条件下 LLM 编造引文率 78%–90%，ICLR 2026 300 篇投稿中发现 50+ 幻觉引文【论文·实证，S57】。

## 三、检索侧：不完美检索是常态而非例外

- Google Cloud ASTUTE RAG 实测：真实 Web 检索中**约 70% 检索段落并不直接包含答案**；内部知识与外部证据的知识冲突是后检索阶段的核心瓶颈【论文·实证，S59】。
- 多源冲突需分型处理：查询歧义（应给多答案）vs 错误信息（应压制）vs 噪声；MADAM-RAG 联合处理也仅 EM 32.6，差距显著【论文·实证，S58】。
- 行业媒体口径（可信度弱、标【第三方】）：ERAA-2026 称 38% 引文不充分支持、多跳题仅 8% 全对——数字未经学术发表，仅作方向参考。[v41-S60]

## 四、硬映射

### 1. evidence_store（SHA256 内容寻址）与 RAG 是什么关系？【推断】

- 不是一类东西：RAG 向量库服务"召回"，按相似度排序、内容可变；阙疑内容寻址库服务"审计"，哈希即身份、不可变。**一个是证据的入口，一个是证据的锚点，天然互补**。
- 定位建议：**做 RAG 的下游验证器**——RAG 负责把证据送到模型面前，阙疑负责判决"主张↔证据"关系是否真实（含引文忠实性），判决结果入账本。这是比"自己做 RAG"窄得多、护城河深得多的位置。

### 2. RAG 减少还是增加待验证断言？——对象迁移【推断】

- 净效应：参数知识型断言 ↓，但新增"引文是否忠实/检索是否相关/来源是否可达/多源如何取舍"四类断言。验证需求不消失，**从验事实转向验 grounding**。阙疑 47 卡目前只覆盖前者，引文忠实性层为空白。

### 3. provenance 在 RAG 领域叫什么、谁在做？【已查证】

- 对应概念：attribution / citation faithfulness。在做的：Wallat/Anand（反事实忠实性）[S55]、CiteGuard（归因对齐）[S57]、ALCE（引文评测，Gao et al. 2023，行业事实标准，跨指 v35）。
- 阙疑的差异化：上述工作验证者口径不点名则数字不可比[S54]，而阙疑的账本+哈希把"用什么验证的"变成可核查记录——**把"点名验证者"从论文约定做成系统基础设施**，这是直接可占的叙事。

### 4. 可直接吸收的低成本算子【推断】

- 反事实引文测试（移源→看答案漂移）[S55]：与阙疑变异管线同构，一个工具位即可；
- 验证者作为可替换测量仪器 + 协议哈希[S54]：纳入信任根闭包即可，几乎零工程量。

## 五、直说：短板与风险

- 阙疑目前**无引文忠实性验证能力**，若以"验证 RAG 输出"为叙事，当前方法栈不成立——先立项反事实引文算子再讲故事。【推断】
- 行业媒体的 RAG 失败率数字（8%/38%）质量低，不应进入学术或营销材料，仅作线索。
- 有利：内容寻址 + 账本架构在 RAG 生态里是稀缺的审计层，位置被学界证据反向验证。
