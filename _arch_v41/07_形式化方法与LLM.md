# _arch_v41 · 07 形式化方法 + LLM 的结合现状（方向 7）

> 核心问题：LLM 与 Verus/Lean/Dafny 的结合进展与边界，阙疑 Rust+Verus 路径的位置，以及形式化能否验证"知识断言"。
> 诚实标注：【论文·实证】；【综述】；【推断】；【盲区】。

---

## 一、Verus：LLM 把"标注成本"打下来了

- **VeriStruct（2026）**【论文·实证】：规划器编排生成抽象/不变量/规格/证明 + 修复阶段；11 个 Rust 数据结构模块验证成功 10 个，共 128/129 函数（99.2%），人工标注大幅减少。[v41-S61]
- **ExVerus（ICML 2026）**【论文·实证】：反例引导修复——证明失败时生成并验证 SMT 反例、泛化为归纳不变量；成功率比 AutoVerus 高 38%、成本省 4.25×、代码混淆下 90% 仍可证（基线 33–50%）。[v41-S62]
- **但 LLM 并不理解验证逻辑本身**：VCoT-Bench（1988 任务）打开黑箱后，十个前沿模型在"验证思维链"上严重脆弱，远不及求解器推理【论文·实证，S63】。
- 早期 Yao et al. 2023：GPT-4+静态分析仅降低"入门级证明"人力，上下文无法保持、错误信息过载两大未解【论文·实证，S64】。

## 二、Lean：研究级形式化的最大敌人是"语义幻觉"

- **Lean Atlas（2026）**【论文·实证】：类型检查器只保证证明项的逻辑正确，**不保证命题/定义表达了 intended mathematics**——AI 形式化可通过类型检查却语义错误（semantic hallucination）；方案是人做语义核验、工具自动缩减审查锥（证明密集项目节点缩减 94–99%），并提出 aligned Lean code 质量标准。[v41-S67]
- **自动形式化不鲁棒**：对输入做同义改写（全局扰动），七个模型均敏感；局部改动数值/步骤时模型大多不能忠实反映，会自行"修正"回原样【论文·实证，S65】。
- **LeanMarathon**：多智能体 + 演进蓝图支持小时级长程形式化，但仍需两阶段编排与人工观察【论文·实证，S66】。
- Chojecki 综述：AlphaProof 等竞赛级成果显著，但开放猜想上脆弱、需大量人工监督；最有前途的是 LLM 与符号验证器紧耦合的闭环。[v41-S68]

## 三、Dafny：局部成功无法复合（compositionality 是当前断点）

- **DafnyComp（ICLR 2026）**【论文·实证】：单函数验证 >58%，跨 2–5 函数的复合规格端到端验证近零（最强 Pass@8 仅 2%）；三失败模式：规格脆弱、实现-证明错位、推理不稳定；92% 失败率警示安全关键场景。[v41-S69]
- **Prometheus**：瞬态拆解→分别验证→复合，86% vs 68%，规格越复杂增益越大【论文·实证，S70】。
- **Re:Form（TMLR 2026）**：0.5B 小模型即可在语法有效/可验证 Dafny 代码上超过专有模型，但 OOD 泛化仅约 14%【论文·实证，S71】。

## 四、硬映射

### 1. Rust+Verus 路径在 LLM+形式化浪潮中的位置——方向正确，顺序关键【推断】

- 阙疑计划的是"**用 Verus 验证验证器**"，不是用 LLM 验证业务代码。2026 证据给出两个直接含义：
  1. LLM 已把形式化标注成本大幅压低（VeriStruct 99.2%、ExVerus 省 4.25×）——**阙疑做形式化的外部成本窗口正在打开**；
  2. 但 LLM 生成的规格本身复合脆弱（DafnyComp 近零）、语义可幻觉（Lean Atlas）——**形式化浪潮本身比以往任何时候都更需要外部审计**，这正是阙疑的市场，且是被反向验证的需求。
- 顺序硬约束：Verus 验证 Rust 代码，必须**先完成 Rust 内核移植**（656 已冻结边界文档），不能跳步。

### 2. 形式化能验证"知识断言"吗？——只能验证一半【推断】

- 可形式化的一半：能转成可执行/可判定对象的断言（编译行为、运行结果、哈希关系）——与方向 1"机器可验"集合重合。
- 不可形式化的一半：语义意图（解释是否贴切、类比是否恰当）。Lean Atlas 给出了形式化的"不可能性证据"：**即使证明全对，类型检查器也不回答"你证明的是不是你想证明的东西"**——这一半永远落在人审，阙疑四态中的 unknown 正是对此的制度化承认。

### 3. 5–10 条高杠杆不变量值不值得用 Verus 写？——值得，但严格筛选【推断】

- 候选（656 PBT 已机械验证）：追加不可变、哈希链防篡改、Merkle 包含、worst-wins 半格、保护器置换不变。
- 判据：每条须 (a) 位于 Rust 内核、(b) 可自动 SMT 证明（不需交互式证明）、(c) 一次写定低频变更。达不到的不写——VCoT 证据表明 LLM 在深证明上不可靠[S63]，不要把人力押在长证明上。

## 五、直说：站不住或需补的点

- 若把"形式化"当作营销标签（无证明、仅规格草案），在 2026 Verus/Lean 的高实证标准下会被一眼识破——当前规格 v1 草案不宜对外宣称形式化。【推断】
- 时间风险：Verus 生态 2026 快速演化，阙疑 Rust 内核若 6–12 个月不落地，"Rust+Verus"叙事的新鲜度与先发优势会衰减。
- 有利：阙疑的账本（append-only）是形式化最友好的数据结构，迁移即验证的成本很低。
