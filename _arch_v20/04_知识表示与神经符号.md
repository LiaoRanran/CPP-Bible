# 04 · 知识表示与语义网（本体 / KGE / 神经符号 AI）

> _arch_v20 · 检索日期 2026-09-21 · 只读调研

## 一、外部最新进展（2024-2026）

### 进展 1：神经符号 AI 有了统一形式定义与第三代框架对比
- De Smet & De Raedt（KU Leuven，arXiv 2507.11127，2025-07）：把神经符号推理形式化为"逻辑函数与信念函数乘积上的积分/边缘化"，统一解释概率逻辑（DeepProbLog）、模糊逻辑、软逻辑三大类系统。【已查证】https://arxiv.org/pdf/2507.11127 （检索 2026-09-21）
- 框架实证对比（MSU，arXiv 2509.07122，2025-09）：DeepProbLog / Scallop / DomiKnowS 三个通用框架在表示语言、神经集成、学习算法上的表达力差异；指出多数 NeSy 研究是定制算法而非通用框架。【已查证】https://arxiv.org/pdf/2509.07122 （检索 2026-09-21）
- LLM 推理的 NeSy 综述（南大 LAMDA，arXiv 2508.13678，2025）：三路径 Symbolic→LLM、LLM→Symbolic、LLM+Symbolic。【已查证】https://arxiv.org/pdf/2508.13678 （检索 2026-09-21）

### 进展 2："LLM 翻译 + 符号执行器判决"被反复证明是抗幻觉结构
- Belle & Marcus（IJCAI 教程论文）：Logic-LM 把自然语言翻成逻辑公式再交符号执行器，"serves as an effective countermeasure against LLM confabulations"；Wolfram Alpha 同构管线；该结构甚至能处理部分模态推理。【已查证】https://gwr3n.github.io/presentations/IFORS_2026.pdf （检索 2026-09-21；为教程综述，具体系统数据以原论文为准）

### 进展 3：工业本体/SHACL 仍是"约束即验证"的成熟载体
- W3C PROV（2013 推荐标准，持续有效）：entity/activity/agent 三元模型 + bundle（"provenance of provenance"，溯源的溯源）+ PROV-CONSTRAINTS 约束校验。【已查证】https://www.w3.org/TR/prov-overview/ 与 https://www.w3.org/TR/2013/REC-prov-dm-20130430/ （检索 2026-09-21）
- KGE（知识图谱嵌入）方向本次未检索到 2025-2026 突破性新范式；v15 已判定其对阙疑不适用【一方称：前序结论，本次未重验】，本轮未见推翻证据。

## 二、对阙疑的范式级影响（5 维评估）

1. **适用性**：中-高（认知层面），低（工具引入层面）。
   - 阙疑的现有结构（原子卡/证据卡/命题/MIS + gate 规则）**本身就是一个手写神经符号系统**：LLM 当神经感知/生成层，编译器+gate 当符号判决层，论证图（W2 加权 AF）当推理层。外部 2025 文献为这个"野蛮生长"的架构提供了正式语言：gate 规则≈逻辑硬约束，W2 可信度权重≈belief function。
2. **颠覆性**：低-中。不会改变架构，但有两个现实升级点：
   - **声明式规则**：63 条 gate 规则目前是命令式 Python，静态枚举 59≠活 63（v19 G6）。SHACL/PROV-CONSTRAINTS 式"数据 + 声明式约束 + 独立校验器"恰好解决"规则可被朴素工具漏读"和"规则双实现"两个问题。
   - **概念本体**：77 条 CONCEPT-NORMALIZED warn + 28 条 INFERENCE warn（v19 G10）是本体欠债；但 NeSy 经验表明本体工程成本高，不应手工追全量。
3. **成本-收益**：
   - 规则声明式化：把规则的*声明部分*（id/selector/severity/判据）固化成机器可读清单（YAML/JSON schema），命令式实现保留——成本低（0.5-1 人周），直接修 G6/G2。
   - Logic-LM 式生成管线：让 LLM 产出的命题先行映射到受控词汇（原子卡 id/证据卡 kind 枚举），未映射项不入库——与方向 2"证据钩子"是同一件事。
   - 上 DeepProbLog/Scallop/OWL 推理机：无收益（关系规模 117 节点 388 边，探针 p01 实测，任何一阶规则引擎都过剩）。
4. **反例**：
   - NeSy 综述自陈"alphabet soup of systems"、无统一框架、通用表达力有限——追工具是追风口。
   - 形式化定义（逻辑×信念积分）对阙疑这种小规模、强机械判决系统是过度抽象。
   - 共享本体的风险：先验本体可能把未见过的误解类型挡在门外（MIS 库的价值在于记录真实错误，过早归一化会吃掉长尾）。
5. **与现有框架关系**：**同构补充**。不是新方向，是给现有方向发"理论身份证"，并指出声明式约束这一处具体欠债。

## 三、可落地建议

- **高**：gate 规则"声明清单 + 活规则锁"（G6），以 SHACL 式约束文件为目标格式；selector 与判据分离后，第二实现只需解释同一清单（呼应方向 1 Comparator）。
- **中**：命题/MIS 受控词汇映射作为 LLM 生成入库的前置校验（无 id 映射 → 退回，不 block 作者但不进论证图），逐步消化 G10，不搞运动式归一化。
- **低/冻结**：引入 OWL 推理机、KGE、概率 AF（v15 已判不适用，本轮维持）、DeepProbLog 类概率编程。

## 四、诚实声明

- NeSy 三篇论文均为本次打开的 arXiv 原文【已查证】；"阙疑=手写神经符号系统"是**调研者的同构推断**，非外部作者对阙疑的评价。
- W3C PROV 为 2013 老标准，之所以引用，是因为其 bundle/约束模型在 2025-2026 的 attestation 浪潮中仍是底座（方向 10 证实 SLSA/in-toto 与 PROV 角色同源）。
- KGE"无新范式"基于检索缺口（未发现≠不存在），标【待验证】并维持 v15 判断。
