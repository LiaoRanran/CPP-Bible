## 1. 一句话结论

**执行可视化领域二十年的元研究结论是"学生如何使用可视化，比可视化展示了什么更重要"——被动看动画不保证学习，主动操作/构造才有效。阙疑不自研可视化器：步阶执行直接借 Python Tutor 范式（2,500 万用户/5 亿次可视化，C/C++ 用 Valgrind 后端精确呈现栈堆），编译对照借 Godbolt，模板展开借 C++ Insights；差异化王牌是真机"跨编译器×优化级别"对比矩阵——让 UB 作为"程序属性而非某次运行属性"被看见。**

## 3. Notional Machines：把"那台机器"显式教给学生

- Sorva 2013（TOCE 综述）：应把执行程序的理想化机器作为**显式教学内容**，而非让学生自行猜构 [D8-S8]；SimpliPy（2025）是该思想新实例：源码行溯源 + 精确操作语义 + CFG 动画 [D8-S9]。
- 对阙疑：C++ 内存模型（对象生命周期、指针语义、序列点/求值序）就是要显式讲授的 notional machine，而不是寄望学生"写多了自然懂"。

## 4. 内存与 UB 可视化：空白即机会

- 2024–26 新工具：abhik.ai 交互式 vtable/继承布局教程（配测验）[D8-S10]、mubin.page vtable 调度可视化 [D8-S11]。**未检索到被广泛采用且经实证验证的专门 C++ 内存教学工具——空白本身是发现** [D8-S3]。
- **UB 教学最有说服力的素材 = 跨编译器×优化级别矩阵**：Lattner 2011 展示优化遍如何让含 UB 代码产生惊人结果 [D8-S12]；GCC/Clang/MSVC 三方分歧对照 [D8-S13]；核心命题"**UB 是程序的属性，不是某次运行的属性**"[D8-S14]——调试器里一次正确输出，只是含 UB 程序被允许做的事之一。目前多为社区整理，缺正式效果研究【盲区】。

## 5. 效果证据：主动使用是调节变量【中】

- Hundhausen et al. 2002（24 项 AV 研究元研究）："如何使用 > 展示什么" [D8-S15]；Naps et al. 2003 参与度分类法：viewing < responding < changing < constructing < presenting [D8-S16]。
- Shaffer et al. 2010：500+ AV 质量参差、主题偏斜、缺资源库 [D8-S17]；Muldner 2022：7 项 PV 对照实验 5 正 2 零 [D8-S18]。

## 6. 阙疑落地方案

| 教学主题 | 方案 | 参与层级 |
|---|---|---|
| 执行步阶（指针/栈堆） | trace 事件流（v32 已定 schema）渲染，真机 GDB/Valgrind 采集，不调试器自研 | changing |
| 编译与优化 | 内嵌 Godbolt 链接 + 自建"同代码三编译器×O0/O2 结果对照"真机矩阵 | responding/changing |
| 模板/隐式机制 | 链 C++ Insights + 关键例本地预生成（锁哈希） | viewing/responding |
| UB | 矩阵 + "程序属性"叙事 + 变体试错（改一行看结果漂移） | constructing |

## 7. 阙疑应该怎么做（3 条）

1. **不造可视化器，造数据与编排**：步阶渲染复用 v32 trace schema，执行后端用真机 GDB/Valgrind 采集（CTutor 解耦架构）；Godbolt/C++ Insights 以链接+预置例结合，避免把大工具塞进首屏。
2. **把"跨编译器×优化级别真机矩阵"做成 UB 主题王牌**：每张 UB 卡附可重跑矩阵与"程序属性"讲解；这是 Python Tutor 类工具（只演一次执行）给不了的体验，也是阙疑真机资产的独占价值。
3. **所有可视化设计按参与度层级验收**：默认要求学生操作（改参数/预测结果/构造变体）而非纯观看；每上线一个可视化，配一道"无辅助复测"题验证迁移，防止"看完就会"的幻觉。
