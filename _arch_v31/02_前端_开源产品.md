# 方向二 · 前端管线：开源之后怎么给人用

> 调研窗口：2024-10 ～ 2026-09，访问日期 2026-09-27。来源 [Sxx] 见 `99_来源清单.md`。
> 【实测】=有公开实测数字；【官方】=项目官方文档；【推断】=结合阙疑现状的设计建议。

---

## 0. 现状盘点（先弄清"前端"现在是什么）

实读仓库后的事实：

- **读者侧**：147 章 MkDocs 站点（mkdocs --strict 零告警，150 页，mermaid2 插件），CI 八 job 含 site/pdf/epub/deploy；PDF/EPUB 走 pandoc+xelatex。
- **验证侧 UI**：全部是 Python 标准库生成的**自包含单文件 HTML**（人审 v2 深色仪表盘、learner twin 仪表盘、argument_net/defense_chain 静态图），另有一个 `http.server` 的 grounded_web 只读查看器。**无 JS 框架、无后端、无数据库、无账号体系**。
- **学习侧**：BKT solver、learner mastery、行为事件 jsonl、recommender；导出物有 `data/flashcards/anki.csv`。
- **分发侧**：GitHub 开源（MIT），queyi-core 已拆到仓库外独立 git（无远端、未 push），68 个纯 Python 工具、零三方依赖（门禁/模型全是 stdlib + pytest）。
- **执行侧**：真编译器是 MinGW GCC 15.3 + Clang 22.1.8（Windows 本机），证据靠真编译真运行 + sanitizer + objdump。

**核心约束（决定一切选型）**【推断】：

1. 阙疑的公信力建立在"同一工件任何人可复算"。前端可以炫，但**网页上跑出来的任何结果都不是证据**，证据只能来自版本化编译器 + 锁哈希工件。
2. 维护者是 Python 单人团队。引入 Node/Rust 工具链的边际成本必须由边际收益证明。
3. 37 卡、7000+ 书代码块的规模，静态站点完全够用，长期不需要数据库。

## 1. 浏览器里跑 C++：可行，但只能当"读者玩具"，不能当证据源

### 1.1 2024–2026 浏览器内编译的真实水位

| 方案 | 形态与体积 | 能力边界 | 来源 |
|---|---|---|---|
| **browsercc**（BertalanD，npm 0.1.1） | 浏览器内 Clang/LLVM：clang.wasm 43MB + lld 23MB + sysroot 29MB + PCH 19MB（共约 114MB）；输出 WASI wasm，browser_wasi_shim 运行；支持 `-std=c++20`；MIT | WASI 无 C++ 异常、无线程；本质是编译到 wasm，**不是 x86 机器码** | 【官方】[S37] |
| **Wasmer SDK 4.4**（2024-10） | 浏览器内跑完整 clang 包约 100MB（压缩后约 30MB 目标），Chrome/Safari/Firefox 通吃 | 同上，WASIX 增强 POSIX 面 | 【官方】[S36] |
| **WASI Clang Playground** | 现成的浏览器内 C/C++ 编译运行演示，样例里已用 `std::print`（C++23 级特性） | 单文件教学 demo 级别 | [S38] |
| **Emscripten pthreads** | 稳定支持 `-pthread`（SharedArrayBuffer + Web Worker） | 要求 COOP/COEP 跨域隔离响应头，且必须与单线程版**出两个包** | 【官方】[S51][S53] |
| **Wasm 3.0**（W3C 标准，2025-09） | 异常处理、WasmGC、尾调用、多内存、64 位、SIMD 全部标准化 | 浏览器 wasm 已成熟；但 **WASI 服务端线程模型仍未定型** | 【实测综述】[S52] |

### 1.2 这条边界对阙疑意味着什么

浏览器 wasm 路线**永远做不到**的事【推断，依据 S37/S51/S52】：

- 产出 x86-64 / ARM 真实汇编并做 objdump 符号锚定（输出目标是 wasm 字节码，指令集完全不同）——书中 203 个锚定 asm 块、ch107/108 的 lock 前缀/xchg 实证无法在浏览器复现；
- 跑 ASan/UBSan/TSan（sanitizer 依赖具体平台插桩与 OS 接口）；
- 复现编译器差异矩阵（浏览器里只有一个 wasm 后端 clang，没有 GCC 15、没有 MSVC、没有多版本）；
- 无偏差地跑时序/性能数字（浏览器 JIT、调度、Spectre 降级计时器全是噪声源）。

**结论（产品铁律）**【推断】：

> 站点交互分两个信任档，视觉上必须让读者一眼分清：
> - **"试一下"档**（浏览器 wasm 或服务端沙箱）：可改代码、可运行、可用于理解概念，页面打 **非验证证据 / Unverified Playground** 标记；
> - **"证据"档**（锁版本 GCC/Clang + 工件 sha256 + PCK 证书）：只展示、可复算、可下载工件与命令，数字旁挂证书角标，点击展开 mutation 负测试结果。
>
> 混用两档是对项目"禁伪造"宪法的直接违反。

交互优先选 **Emscripten/browsercc 自建纯前端方案**（无服务器成本、无滥用面、GitHub Pages 可托管），仅在需要多编译器/汇编/sanitizer 的章节提供"在沙箱中复现"按钮（见 §2）。114MB 首次下载用 PCH 按需加载 + 长缓存缓解，教学场景可接受。

## 2. 服务端执行沙箱：三档路线，按真实用户量延迟建设

| 方案 | 隔离机制 | 关键数字 | 许可/成本 | 适合阶段 | 来源 |
|---|---|---|---|---|---|
| **Judge0** | Docker 隔离沙箱，60+ 语言，自托管或云，支持时限/内存上限/附加文件/webhook | 3.5k GitHub stars；云版 €27/月含 2000 提交/日 | 开源可自托管 | 有真实读者后（P2） | 【官方】[S40] |
| **Firecracker** | KVM microVM，专最小设备模型 + jailer 二道防线 | 启动 <125ms，单机 150 VM/s，每 VM <5MiB 开销；Lambda 月调用 15 万亿+ | Apache 2.0；**仅 Linux/KVM**，Windows 机做不了宿主 | 规模化（P3） | 【官方】[S41] |
| **E2B** | 自研 Firecracker microVM 运行时，快照启动 <200ms，24h 会话 | 商业云 + 可部署到自有 AWS/GCP；运行时 Apache-2.0 | 商业付费/自运维 | 不想自己运维时的商业选项 | 【官方】[S39] |

**建议**【推断】：

- **P1（现在～开源首发）：零服务端。** 静态站 + 浏览器 wasm 交互 + 证书静态校验（§4）。GitHub 已经在跑 Linux CI，真要"服务端复现"直接引导用户 fork + Actions，或本地 `uvx`（§5）。
- **P2（出现外部用户后）：一台便宜 Linux VPS + Judge0 自托管**，编译器镜像自己做（装 GCC 15/Clang 22，固化版本），每次执行入队限时限内存；编译器镜像本身也要 sha256 公示——沙箱输出要进证据链，前提是"编译器是谁"可证。
- **P3（多用户/对抗滥用出现）：Firecracker**。Docker 容器跑不可信用户代码的逃逸面在 2026 年不该再向公网暴露；microVM 是 E2B/Lambda 用规模验证过的答案。Windows 开发机无关紧要——宿主是 Linux 服务器。
- 预算红线：在日活 <100 阶段上任何常驻后端都是过度工程。阙疑的验证负载是**编译型重活**，比普通判题贵，更应推本地复算与浏览器执行，把服务端留给"多编译器对照"这一个浏览器做不了的卖点。

## 3. 文档站点：MkDocs Material 进入维护模式——这是本方向最重要的情报

### 3.1 事实

- **2025-11-05，squidfunk 宣布 Material for MkDocs 进入维护模式**；9.7.0（2025-11-11）是最后一个带新功能版本；之后只做关键 bug/安全修复，**支持到 2026-11**；团队转做下一代 SSG「Zensical」。作为补偿，原 Insiders 付费功能全部并入免费 MIT 版。【官方消息+发布说明实证】[S45]
- 2026 年文档框架版图（周下载量级）：Docusaurus ~3M（React，版本化/i18n 内置，生态最大）、VitePress ~2M（Vue+Vite，构建最快，100 页约 5s vs MkDocs 15s vs Docusaurus 45s）、Nextra ~800K（Next.js）、Astro Starlight ~200K（Islands 架构、Pagefind 离线搜索、i18n 内置）。【实测汇编】[S46][S47]

### 3.2 对阙疑的决策建议

**不要现在迁移书站，但新交互层不要建在 MkDocs 上。**【推断】理由：

1. 书的内容形态是纯 Markdown + mermaid，MkDocs Material 在冻结状态下依然是能打的站，2026-11 前无安全风险，迁移 150 页是纯支出零收益；Zensical 未成熟，等它出迁移路径。
2. 但阙疑要新增的东西（wasm playground、证书查看器、知识图谱、学习仪表盘）全是**重交互组件**，硬塞进 MkDocs 要靠脆弱的自定义主题/插件，恰好踩在 MkDocs 停止演进的方向上。
3. 推荐双轨：
   - **`book`（L4 出版视图）**：继续 MkDocs，冻结技术债，等 2027 年随 Zensical 或 Starlight 二选一一次性迁移；
   - **`quyi-lab`（应用层）**：新建独立小站，技术栈首选 **Astro + Starlight + 少量 Preact islands**（理由：内容页仍用 Markdown 写、交互按需水合、Pagefind 零后端搜索、与静态证书校验理念一致；Vue/React 团队则 VitePress/Docusaurus 亦可，三者差距远小于"是否迁移"本身）。它嵌入书站或反向链接都行，构建产物同为纯静态。
4. 迁移触发条件写死：①2026-11 安全窗口到期前 Zensical 无稳定版；②quyi-lab 需要与书站共享布局/导航——满足其一即评估 Starlight 全量迁移（Markdown 与 mermaid 均可平移，工作量主要在 admonition/宏插件替换）。

## 4. 证书查看器：零后端信任模型，最该先做的前端

PCK 证书（YAML）现在只服务于机审。开源后它是**最好的产品叙事**，而展示它不需要服务器【推断】：

- 静态托管每张证书的 YAML + 工件；页面用浏览器内置 **Web Crypto API（crypto.subtle.digest）现场重算 sha256**，与证书记录逐字节比对；
- mutation 负测试结果（blocked/n_a 列表）可折叠展示，读者可一键"喂入一个被篡改的读数"看 verifier 拒绝（wasm 化的 verifier 或 Pyodide 跑的 Python 验证器，见 §5）；
- 置信上界、claim_boundary（std/compiler/opt/platform 四档）用徽章渲染，不可点成"绝对真理"；
- provenance 区显示 commit、（新增的）模型/prompt/rubric 版本（对应 01 号报告 A9）。

这把 v29 的"第三方可揭穿篡改"从命令行爱好者扩展到**任何点开网页的读者**——信任根可在浏览器里自证，是比"我们有 CI"高一个段位的开源卖点。

知识图谱可视化同理为纯静态：现有 `knowledge_graph.json`/`learning_path.json` + **Cytoscape.js**（几百节点规模无压力，图分析生态成熟）渲染前置关系与跨卡论证网络，点击节点跳到书章/证书。无技术风险，一个页面的工作量。

## 5. queyi-core 的分发形态：让"复算"像装个包一样简单

【推断，基于实读：queyi-core 68 工具纯 stdlib】

- 以 `pyproject.toml` 打包发布 PyPI（或 GitHub Releases + uv tool），目标体验：
  - `uvx quyi verify pck.yaml`（验证单张证书）
  - `uvx quyi verify-site ./site`（整本站点的锚定/哈希巡检）
  - `uvx quyi lab`（起本地只读仪表盘）
- 纯标准库是巨大优势：**Pyodide（CPython 编译到 wasm）可以直接把规则验证器搬进浏览器**，读者在证书页现场跑 67 规则而无需信任任何服务器。规则层可 wasm 化，编译器层才需要 §1/§2 的执行方案——两层不要混。
- queyi-core 尽快开远端（公开 GitHub 仓库）+ 版本号 + CHANGELOG；目前"仓库外 166 commit、无远端、与 CPP-Bible 两份并列"是开源前必须了结的债（647 已如实登记），否则外部贡献者无法理解信任边界。
- 包分发后，PCK 证书 schema 要走 semver + 迁移期双解析（619-pck-v1 已在证书里标版本，继续保持）。

## 6. 学习者侧：FSRS、本地优先、零账号

### 6.1 间隔重复：从 SM-2 口径升级 FSRS

- Anki 自 **23.10 起内置 FSRS**（与经典 SM-2 并存）：基于"难度/稳定度/可提取率"三变量记忆模型，按个人复习历史拟合参数，可设目标留存率（推荐 90%；95% 复习量约翻倍）；同等留存下复习量比 SM-2 少约 **20–30%（对 99.6% 用户更优）**。open-spaced-repetition 开源，多语言实现。【官方+论文】[S49][S50]
- 阙疑已有 anki.csv 导出 + BKT solver + mastery 更新。**建议**【推断】：
  - anki.csv 继续作为最通用导出（Anki 里开 FSRS 即可享受算法，零开发）；
  - 站内学习仪表盘若做调度，直接用 FSRS 多语言实现而非自造；BKT（知识点掌握）与 FSRS（卡片记忆）是两个粒度，保留 BKT 做路径推荐、FSRS 做单卡复习排期；
  - 学习记录本地优先（LocalStorage/导出 JSON），v1 **不做账号体系**——账号带来的运营/隐私成本对单人开源项目是致命的，而导入导出 + 可选 GitHub Gist 同步足以覆盖早期用户。

### 6.2 社区与检索（全部零后端）

- 评论/反馈：**giscus**（GitHub Discussions 驱动，读者有 GitHub 账号即可，符合开源受众）；
- 站点搜索：继续内置客户端搜索，新站用 **Pagefind**（构建期索引、零服务、对中文需配分词但可用）；
- 贡献入口：每章"在 GitHub 编辑此页"直达 Markdown，配合 MIT 许可；
- 若未来真要多用户（做题记录云同步/班级），再评估 **Logto/Keycloak 自托管**，在此之前不装。

## 7. 桌面端：Tauri 2 值得记录，但不是这两年的事

- Tauri 2.0（2024-10 发布，2026 年在 2.11 线）：OS 自带 WebView（Win WebView2/mac WebKit/Linux WebKitGTK），安装包典型 **2–10MB**（实测同应用 Electron 85MB vs Tauri 2.5MB；另一组实测 Tauri2 约 27–29MB vs Electron 约 150MB）；Rust 后端；capability 权限白名单默认全关；**iOS/Android 同代码库**。【实测】[S42][S43][S44]
- 代价：三 WebView 渲染不一致（Figma 因此放弃）、深度原生能力要写 Rust、生态深度不及 Electron；Electron 仍是渲染一致性/自动更新签名成熟度选择。【实测】[S42][S44]

**对阙疑的判断**【推断】：**缓建桌面 App**。

- 目标用户（系统/嵌入式方向学生与工程师）的工作环境是浏览器 + 自己的工具链，桌面壳提供的增量主要是"离线 + 本地编译器接入"；
- 这两个增量用纯静态站 + PWA（离线缓存）+ `uvx quyi` CLI 已能拿到 80%，不需要引入 Rust 工具链；
- 若 2027 年后确有桌面需求（例如打包 GCC 工具链做一键离线实验箱），Tauri 2 是默认解，Python 侧以 sidecar（uv 管理的独立 Python）形态嵌入；那时再付 Rust 学习成本。

## 8. 落地顺序（前端路线图）

| 阶段 | 交付物 | 技术 | 依赖后端 | 与验证体系的接口 |
|---|---|---|---|---|
| P0（开源前） | queyi-core 公开仓库 + PyPI/uv 安装 + 证书查看器（现场 sha256）+ 证书角标嵌入书站 | 纯静态 + Web Crypto；Astro/Starlight 试点单页 | 无 | 只读 PCK/工件 |
| P1（首发） | 浏览器 wasm playground（先单线程章：语言/STL/模板）；"非验证证据"标记；Cytoscape 知识图谱页；giscus；Pagefind | browsercc/Emscripten + Preact island | 无 | playground 与证书严格分档 |
| P2 | 多编译器/汇编/sanitizer"沙箱复现"按钮；FSRS 复习模式（本地进度） | Judge0 自托管 Linux VPS + FSRS 库 | 一台 VPS | 沙箱输出默认不锚定；入证需走头部层正规流程 |
| P3 | 沙箱 microVM 化；书站向新框架迁移决策；（可选）学习者云同步/多用户 | Firecracker；Zensical/Starlight 评估；Logto 按需 | 多实例 | 编译器镜像哈希公示 |
| 缓建 | Tauri 桌面离线箱 | Tauri 2 + Python sidecar | — | — |

### 贯穿所有阶段的三条界面原则

1. **信任可见**：每个数字都能在 0–2 次点击内看到工件、命令、哈希、证书、负测试； unverified 的东西视觉上必须可区分。
2. **复算优先**：读者先被引导"自己跑/自己算"，再被引导"相信我们"；本地能做的（规则校验、哈希、wasm 运行）绝不放服务器。
3. **单人可维护**：无数据库、无账号（v1）、纯静态为主、新框架只加一个（Astro），Python 不离开核心团队舒适区。
