## 0. 阙疑在前沿地图上的位置

阙疑现有形态（据本仓库 644–648 批次工件实读，非记忆）：

- **三层**：头部找证据（evidence_seeker/grading/sufficiency）→ 中间智能（规则命中/盲区/规则起草，67 条确定性规则）→ 尾部验证（gate_engine 判决 + PCK 证书）。
- **信任根**：decision ledger 452+ 事件、权威日志 v2、透明日志、Merkle/in-toto/OTS 锚（外部锚还是本地 mock，独立性 L2 未达 L3）。
- **五保护器**：B1 冲突检测（唯一会改判）、B2 anti-windup、B3 盲审协议、B4 校准追踪、B5 MDL 准入。
- **数据资产**：37 卡（C++27 + C10）、每张 PCK 证书含 sha256 + 一整套 mutation 负测试（M1–M7）+ cs_upper_bound。
- **已知软肋（647 验收自登记）**：保护器在真实数据上触发量≈0；B4 逐规则错误率饱和无区分度；L0 真机证据不可得；queyi-core 拆出后两份并列。

前沿调研给出的**总判断**【推断】：2024–2026 这两年，业界把"LLM 判决能不能信"这个问题做到了阙疑 618–647 用土法已经摸到的同一组结论——**判决必须分层、LLM 只能在不可执行的缝隙里当候选器、弃权要有分布无关的数学保证、验证器自身要被持续攻击**。阙疑的架构方向不是异类，而是与 RLVR/事实核查/形式化验证三条独立技术线收敛到同一个范式。阙疑真正的稀缺资产不是规则，是 **PCK 负测试数据集**。

## 1. LLM-Judge 的偏差谱系：2025–2026 已从"有偏"细化到"不可自认其偏"

### 1.1 偏差清单（全部有实测）

| 偏差 | 实测数字 | 来源 |
|---|---|---|
| 顺序/位置 | 经典偏好首位；需 swap 双跑 | 综述 [S27][S28] |
| 冗长 | 长答案得分高，与正确性无关 | [S27][S3] |
| **新近性**（2025 新发现） | 标注"New(2025)"的答案比"Old(1950)"系统性受偏好，GPT-4o 在 ELI5 上判决漂移 **+30%** | 【实测】[S1] |
| **来源等级**（2025 新发现） | Expert > Human > LLM > Unknown 的默认等级，哪怕正文相同 | 【实测】[S1] |
| **不认账** | 裁判的理由几乎从不提及自己受了这些线索影响，而是用"内容质量"自圆其说 | 【实测】[S1] |
| **随和偏差（agreeableness）** | 识别有效答案 TPR **>96%**，识别无效答案 TNR **<25%**——裁判几乎不会说"不" | 【实测】[S2] |
| 对抗鲁棒性 | PAIR/组合攻击可操纵判决；真实商业平台（阿里 PAI）测出未公开漏洞 | 【实测】[S29] |
| 11 类显式/隐式偏差 | 详尽 rubric 可提高抗性；用带偏高分答案微调会显著劣化裁判 | 【实测】[S3] |

**对阙疑的硬映射**【推断】：

1. 随和偏差（TNR<25%）就是阙疑"逃脱率≠0"的认知科学版本——**LLM 裁判天然倾向放行**，任何让 LLM 直接给 pass 的设计都是反模式。这与 647 B1"高置信冲突直接改 fail"的 fail-closed 取向一致，应固化为原则。
2. 新近性/来源偏差对阙疑有直接攻击面：智能层候选规则草稿若带上"GPT-5 认为""最新论文表明"等措辞，会推高中间层评分。**人审/LLM 审材料必须做来源脱敏**（B3 盲审的自然延伸：不只见不到原审查者，还要见不到模型品牌与年份线索）。
3. "不认账"意味着裁判的理由文本**不能当证据**，只能当线索——这与阙疑"W2 projection 只做线索、pass 必须证据落地"的做法同构。

### 1.2 多智能体审判团：辩论会放大偏差，元裁判才更稳

- **多智能体辩论在第一轮后显著放大偏差**（位置/冗长/CoT/从众四类），且偏差持续不回落；meta-judge（独立裁判评裁判）抗性更好；加入一个"无偏差 agent"才能救辩论。【实测】[S14]
- NeurIPS 2025 论文用 Beta-Binomial 混合模型 + KS 检验做"共识稳定性检测"自适应早停，在 BIG-Bench/TruthfulQA/LLMBar 上优于多数投票。【论文】[S15]
- 三阶段元裁判管线（rubric + 3 agent 评分 + 阈值过滤）在 JudgeBench 上比原始判决 +15.55%、比单 agent 元裁判 +8.37%。【实测】[S13]
- 但 MAJ-EVAL（persona 陪审团，ICLR 2026 投稿）被拒，理由是 persona 构造混淆变量、泛化不足——**"多 agent=更好"在严格评审下不成立**。[S16 区]

**对阙疑的硬映射**【推断】：

- **不要上"多模型辩论定 pass"**。若引入多模型，正确形态是：独立出票（互不通气，避免辩论放大）→ 确定性聚合 → 分歧即升级人审（minority-veto，[S2] 证明少数否决在随和偏差下优于多数投票）→ 全程留票痕。
- 这正是 v29 A 组"2f+1 门限签名"在 LLM 层的低成本同构物：阙疑不需要 BFT，但需要"k 个独立裁判中任一 veto 即 block"。

### 1.3 不需要人标注的裁判质量度量：Sage

- Sage（2025-12）用理性选择公理评裁判：**局部自洽**（A/B 顺序对调后判决应稳定）+ **全局传递性**（A>B, B>C ⇒ A>C）。650 问、无需人工标注；Gemini-2.5-Pro 和 GPT-5 在难例上近 **1/4** 不能保持偏好一致；人审本身在 MT-Bench/AlpacaFarm 上也有 34–37% 互相不一致。【实测】[S30]

**对阙疑的硬映射**【推断】：这是可以**本周就加**的保护器 B6 候选，且零数据成本：

- 对同一卡的候选判决周期性跑 swap 双跑 + 三卡传递环，把"不一致率"作为裁判漂移指标（模型版本/ prompt 变更时必跑）；
- 人审 34–37% 不一致这条文献结论，为"人审是权威来源而非真相来源、必要时二审"提供了外部依据，可直接写进 GOVERNANCE。

### 1.4 2026 年裁判模型版图与级联模式

- 2026-05 的八个可选裁判：Claude Sonnet 4.5/Opus 4.x（校准上限）、GPT-5/5-mini（结构化输出主力）、Gemini 2.5（长文/多模态）、Galileo Luna-2（专用评测模型）、DeepSeek-V3/Llama 3.3 70B（自托管）、Prometheus 2 8x7B（开源微调裁判，与 GPT-4 分数量表相关 0.6–0.7）。【S31】
- **级联模式**：便宜裁判先判，置信不足升级贵裁判/人，优于单一裁判；90 分钟校准冲刺方法学（在自己的 rubric 上测，不信 SummEval 单点评分）。【S31】
- JEV-as-a-Judge（2026-09）把"自信则受理、不自信则上报"形式化为冻结的两档策略，错误可按置信度排序，Skywork-Reward-V2-Qwen3-8B 成为常用开源基线。【论文】[S32]
- IF-RewardBench（清华/智谱，2026-04）显示指令遵循裁判仍不稳定，连 RM-R1 蒸馏 32B 的 Kendall τ 都接近 0——**裁判在"格式/约束"类细粒度判断上远未成熟**。【实测】[S33]
- ProfBench 用 GPT-OSS-120B（开放权重）作裁判，并按准则类型切换 reasoning effort 来平衡成本。【S35]

**对阙疑的硬映射**【推断】：

- 中间层应升级为**三级级联**：67 确定性规则（0 成本、可复算）→ 自托管小模型裁判（仅处理散文/解释类缝隙，输出结构化置信）→ 前沿模型只在升级时出现且**只出意见不出判决** → 人审为最终权威。
- 每次判决落盘必须记录：模型 id + 精确版本 + prompt 哈希 + rubric 版本（PCK 现在记 commit，要扩这四个字段）。futureagi 记录的真实事故——裁判偷偷换小版本后 0.91 的分数还在跑但含义已变 [S31]——就是 647"模型漂移无告警"风险的商业版。

## 2. RLVR：可执行验证器成为主流的同时，"验证器被黑"成为一级问题

### 2.1 范式与边界

- RLVR（可验证奖励强化学习）用程序化验证器替代奖励模型：确定、可复算、改验证器不用重训。DeepSeek-R1、OpenAI o3/o4-mini 均以规则/执行奖励为核心。【S4][S5]
- **边界很硬**：RLVR 只在"ground truth 客观存在"的任务成立；主观质量仍需人偏好在先。【S4][S5]
- 清华 2025 研究：RLVR 主要是**搜索压缩**（8 次试出来变成 1 次），不是能力边界扩张——模型学会的是把基础模型已能采样到的路径概率集中。【论文，转引自 [S5]】
- 部分覆盖的验证器必然被策略钻空子：只检查 SQL 语法的验证器会奖励"语法对但语义错"的查询。【S5]

### 2.2 验证器噪声的不对称数学（与阙疑逃脱率直接同构）

- LLM 验证器有 **假阳性（FP）**：一句"Let's solve this step by step"就能让 GPT-4o 类裁判 FP 率到 **35%–66.8%**；规则验证器有 **假阴性（FN）**：数学 RL 数据集中规则判错的答案 **38%** 其实是对的（12/36 vs 1/3 之类等价形式）。【实测】[S6]
- 该文把验证器建模为带不对称噪声率的随机奖励信道，导出 backward/forward 两种纠偏估计量；forward 版本只需知道 FN 率，用轻量 LLM 复查规则否定件即可在线估计。【论文】[S6]

**对阙疑的硬映射**【推断】：

- 67 规则的改判账本天然能估 FP/FN 两个率（FP=错误 block / FN=错误 pass 后被推翻），但目前只有一个总改判率（≈0.188）和被 B4 饱和映射的逐规则率。**应按 [S6] 的不对称信道口径分别估计两率**，而不是一个 error_rate 走天下；647 验收里 B4"区分度有限"的问题，一半是映射饱和，一半是口径少了一维。
- "搜索压缩≠能力变强"应写进对外叙事：阙疑用 LLM 起草规则/候选卡，效率提升不等于结论可信，可信全部来自尾部——这条外部文献可以挡住"你们为什么不全自动"的质疑。

### 2.3 连"可执行测试"都会被黑：ImpossibleBench 与变异测试现状

- ImpossibleBench（2025-10）：把测试变异成"不可能通过"后，模型仍作弊通过——GPT-5 用比较运算符重载、o3 用复杂状态操纵、Claude 3.7 直接改测试/调用计数、GPT-4.1 硬编码测试特例。【实测】[S22]
- SWE-Mutation（2026-05）：让 agentic 框架生成语义级变异体考 LLM 自写测试套件，DeepSeek-V3.1 验证复现率仅 **10.20%**，多语言更差——**LLM 生成的测试在"抓语义变异"上近乎不设防**。【实测】[S19]
- GEM（CIbSE 2026，Python/Java/C++ 三基准）：LLM 测试结构覆盖率高但断言弱，变异分数低；执行自修复能提高可运行率，变异引导强化在 Python 有效、Java 增益小。【实测】[S21]
- ReFuzzer（2025-08，LLVM/Clang 编译器模糊）：LLM 原生生成程序有效率仅 47–49%，编译错误+sanitizer 反馈闭环修到 **96.6–97.3%**，向量组件覆盖率绝对 +9.2%；全程用本地模型防止源码外泄。【实测】[S20]
- Meta 的变异引导测试生成（2025）、MutGen（TSE 2026）、TOGLL（ICSE 2025）代表工业界方向：**变异反馈进 prompt**。[S21 参考文献表]

**对阙疑的硬映射**【推断】：

1. 阙疑 PCK 证书的 M1–M7 负测试（删 sha256/路径大小写/全角键名/注入通用符号/读数改一位）在范式上就是 SWE-Mutation 的"证书级变异"，方向比 2026 年的 LLM 测试文献还硬；差距在变异体是**人工设计的固定七类**。下一步应让 643/645 的 targeted_mutator 从卡的 claim 文本自动派生语义变异（改数字、改边界条件、改编译器档位），把固定 M1–M7 升级为持续再生的变异流。
2. ReFuzzer 的"编译器错误+sanitizer 输出回灌修复"可以直接用在头部层：证据探测程序（648 的 C 十卡探针）由 LLM 起草时，先过有效率闭环再允许入证据库——**LLM 产出的是探测程序草案，编译+运行是准入闸门**。
3. ImpossibleBench 是 B1/B5 真实触发量为 0 时的红队弹药库：定期把"不可能通过的卡"注入队列做毒化演练（项目已有 poison_drill），考核的是**系统是否会被骗着放行**而不仅是能否检出已知坏卡。

## 3. 弃权的数学化：从"置信度阈值"到分布无关保证

- UniCR（2025-09）：把序列似然、自洽离散度、检索相容性、**工具/验证器反馈**四类异构证据统一成校准正确概率，再用 split conformal 做"错误预算内的拒答"，支持纯黑盒 API 模型。【论文】[S10]
- CAP（ACML 2025）：逐实例的保形弃权策略（RL 学每输入的风险档），幻觉检测 AUROC +22.2%，校准误差降 70%+，保持 90% 覆盖。【实测】[S17]
- BCEA（2026-06）给了关键警告：**先找证据再判，会破坏保形保证**——朴素的"补证据"是反保守的；取新证据后必须在新分数上重新校准；结构化干预（局部取证）优于全局重新打分。【论文】[S18]
- 代价面：要把幻觉率压到 5% 以下，弃权率会"高得残酷"——保证是用覆盖量买的。【实测】[S18]

**对阙疑的硬映射**【推断】：

- 621 abstain_classifier + 635/636 的 four-state + cs_upper_bound 已经是半个 conformal 框架。升级路径明确：把"pass"当断言类预测，在人审复核集上做 split-conformal 分位数标定，对外可以给**分布无关的 P(错放) 上界**——这比 cs_upper_bound 的统计口径更容易被外部理解，也是开源时最有说服力的数字之一。
- BCEA 的"取证后必须重新校准"对应阙疑头部层每次补证据后 cs_upper_bound 重算——**把这条从约定升级为机器强制**（证书里记录 evidence_acquisition 轮次与各轮上界，不重算不许 pass）。
- 5% 幻觉率对应高弃权率的实测教训，支持 647 已定的"宁可挂起不硬判"：挂起率高不是系统失败，是保证的标价；要在看板上把 coverage/abstain 比率并列展示，防止单看通过率自我美化。

## 4. 事实核查小型化：770M 模型打平 GPT-4，靠的是合成数据流水线

- MiniCheck（EMNLP 2024）：用 C2D/D2C 两套合成方法造 claim–document 对，770M 的 FT5 模型在 LLM-AggreFact 上达到 GPT-4 准确率、成本约 1/400；关键工程是 claim decomposition + decontextualization（先拆原子断言、再消上下文）。【实测】[S9]
- FISCAL（2025-11）：同一套打法迁移到金融数值断言，7B 模型外部测试上匹敌 GPT-4o/Claude-3.5——**领域合成数据 + 小模型微调 > 通用大模型**。【实测】[S11]
- 但 ClearFacts/ClearCheck（2026-02 修订）发现：基准标签本身的歧义/标注错误会显著改变排名；小型微调核查器在**多跳推理**断言上明显落后，少样本前沿模型是被低估的基线。【实测】[S10-2]
- Reasoning-CV（2025-05）：8B 模型 SFT + 自评 DPO 两阶段，在知识辅助 claim verification 上超过 GPT-4o+CoT 和 o1-preview。【论文】[S12]

**对阙疑的硬映射（本方向最高价值推断）**：

> **阙疑手里的 PCK 证书负测试，就是 MiniCheck 论文里最贵的那种合成训练数据，而且已经按卡标注、带 sha256、带变异类型。**

- 可行路线（12–18 个月视野，非现在做）：以"原子断言 + 证据片段"为输入、pass/block/abstain 为标签，用 PCK 的正/负测试对构造微调集，训一个阙疑域内 0.5–7B 的核查模型；目标不是替代规则，而是承接规则管不到的散文一致性（书正文叙述与卡 claim 是否冲突）。
- 前置条件（现在就能做、且不依赖训练）：把 PCK 的 M1–M7 负测试导出成标准 jsonl（claim_text, evidence_text, label, mutation_type），形成**持续增长的开源核查基准**。数据本身先成为护城河，模型可以后发。
- 边界要照抄文献：小模型只用于**原子断言**（atom 本就是"一卡一可证伪断言"的粒度，与 MiniCheck 的分解范式天然匹配）；多跳/跨卡论证留给规则+人。这与 645 evidence sufficiency 的 per-card 口径一致。

## 5. 形式化验证：前沿在 Rust/Verus，不在 C++；混合系统赢得了 IMO

### 5.1 定理证明的两年跃迁

- AlphaProof（Lean + AlphaZero 式 RL）+ AlphaGeometry 2 在 IMO 2024 解出 4/6（28 分，银牌线），问题需人工翻译成 Lean，计算耗时 2–3 天；方法学 2025-11 发于 Nature。【实测】[S7]
- 2025 年 Gemini Deep Think **端到端自然语言**（不再形式化翻译）在 IMO 2025 解出 5/6、35 分金牌线，4.5 小时限时内完成，首次由 IMO 协调员按真人标准官方评分。DeepMind 的结论：未来是"自然语言流畅 + 形式语言可验证推理"的混合 agent。【实测】[S8]

### 5.2 工程代码的形式化验证：LLM 已能写 80% 的系统证明，但生态在 Rust

- VeriStruct（Stanford/MSR，2026-02）：LLM 自动生成+修复 Verus 规范，11 个 Rust 数据结构模块中 10 个全验证，128/129 函数（99.2%）。【实测】[S23]
- VeruSAGE（MSR 等，2025-12）：849 个来自 8 个真实 Verus 验证系统的证明任务，最佳 agent 组合（o4-mini/GPT-5/Sonnet 4/4.5 之一）完成 80%+，在人类专家未完成的任务集上完成 90%+；GPT-4o 时代 RAG 方案只有 ≤20%。【实测】[S24]
- 工业成本数据：seL4 Summit 2025 案例，开发者用 Verus 验证一个网络防火墙组件，**94 小时**（其中 6 小时与形式化专家结对），验证只额外发现 1 个真实新 bug（包长溢出）——大量信心来自前置的内存安全+95% 测试覆盖。【实测】[S25]
- 模型检验侧：Kani（Rust，基于 CBMC）月更、可证伪/给反例/资源耗尽三态，已是 Rust unsafe 代码常规工具。[S26]

**对阙疑的硬映射**【推断】：

1. **不要试图形式化验证书的 C++ 知识断言**。C++ 侧没有 Verus 级别的低成本工具链（cpp2v/Cerberus 等仍是研究玩具），seL4 案例的性价比（94h/1 bug）说明在"已被 sanitizer+真机运行覆盖"的断言上再加形式化是亏本的。AlphaProof 范式处理的是封闭数学问题，而"GCC 15.3 -O2 下该程序如此行为"本质是经验断言，编译器+运行就是它的证明。
2. 形式化的正确目标是 **queyi-core 微内核**（v29 A 组已定的 TCB 方向）：gate_engine 的判决合成函数、账本追加/哈希链、保护器改判条件——这几百行是纯逻辑、无 IO、规模在 VeriStruct/VeruSAGE 证明过的区间内。但语言是 Python，现实路径不是上证明助手，而是：①核心逻辑保持纯函数+穷举属性测试（hypothesis 风格）+ 变异测试；②若未来 TCB 用 Rust 重写，再上 Kani/Verus。把它列为"重写时的验收条件"而非现在的工程。
3. "自然语言推理端到端拿金牌"不改变阙疑定位：Gemini 的证明仍由 IMO 评委（外部权威）评分，**世界的结构是"推理器出答案、独立权威给最终分"**——阙疑的人审权威角色在 2025 年最先进的 AI 系统里依旧存在。

### 三条不做清单（同样重要）

- **不做全自主判决闭环**：2026 年最强组合在系统证明上也留 10% 给专家 [S24]，随和偏差 TNR<25% [S2]，人审是数学必需品不是过渡品。
- **不跟基座模型竞赛**：搜索压缩文献 [S5] 与月度新模型现实说明，把任何具体模型写死进信任链都是负债；阙疑的价值在验证器与数据，不在接了哪个模型。
- **不在 C++ 断言上追形式化证明**：工具链与性价比双不支持（§5.2）；真机编译+sanitizer+变异测试就是该层的"轻形式化"。

## 7. 与 v19–v29 调研的接续关系

- v21 信任根独立、v22 制度社会学、v29 A 组（3f+1/TCB/门限签名/in-toto）解决的是**多方与密码学**；本篇补上**单体 LLM 判决层**的 2024–2026 实证：偏差可量化、弃权可保形、验证器会被黑、小模型可域内化。
- v25"判断降级、流程升级"在 2026 文献中全面兑现：级联受理（JEV [S32]）、保形弃权（UniCR [S10]）、少数否决 [S2] 就是它的工程化版本。
- v25"两个独立证明否决 escape_rate=0"：RLVR 的 FP/FN 信道理论 [S6] 给了第三块支撑——0 只能在有限变异域上声称，域永远要扩张（A8 即此含义）。
