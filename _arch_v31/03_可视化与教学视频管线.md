## 0. 阙疑做视频的独特资产与独特约束

**资产**（实读仓库确认）：

- 37 张卡每张都是"一卡一可证伪断言 + claim_boundary + 证据 + 反例 + pedagogry"，模板里**已内置**教学三件套：`socratic`（提问）、`predict_first`（先预测）、`misconceptions`（引用全库统一误解库）。视频脚本结构在卡片 schema 里已经长好了。
- 57+ 真机汇编实证（objdump 真实产物，锁 GCC 15.3）、120 组 gcc/clang C 探针输出（648）、7515 个可编译代码块、511 个 mermaid 图、golden .out 逐字输出。
- 全书所有数字正处在"禁编造"宪法管辖下，配套有 data_sanity_audit/teaching_audit 抓编造轶事。

**约束**：

- 维护者单人 Python 栈；3b1b 本人 FAQ 给的判据是"写代码做视觉对你是抑制还是解放"——对本项目答案显然是解放（全项目 400+ Python 工具就是证据）[S58]。
- 视频必须延续书的信任体系：**画面里出现的每个数字都要有工件出处**，否则视频会成为第一个允许编造的介质，反噬全书公信力。

**总判断**【推断】：Manim 合适且够用；真正的工程重点不是选动画工具，而是设计一条"**证据驱动动画（evidence-driven animation）**"管线——画面数字从 golden 工件解析而来，而非人手敲进脚本。这是阙疑相对其他教 C++ 的 UP 主唯一可持续的差异化，也是最难被追平的：别人追动画质量，阙疑追的是"零编造可复算"。

## 1. 动画引擎选型：Manim 为主，Motion Canvas 观察，Remotion 只做数据批量活

### 1.1 Manim Community Edition（推荐主力）

- 版本实况：**0.20.1（2026-02-27 发布）**，月度发布，Python 3.11+，MIT；**0.19.0 起默认渲染器从 Cairo 换成 OpenGL（破坏性变更）**，老场景需 `manim -r cairo` 显式指定。【官方/PyPI 实测】[S56]
- 双版本格局：3b1b/manim 是 Grant 自用试验场（OpenGL/GLSL、实时交互）；ManimCommunity/manim 文档完善、多后端、社区大。**Grant 本人明确建议新人从 Community Edition 起步。**【官方】[S58]
- 依赖注意：ffmpeg 必装；任何 LaTeX 文本要本机 TeX 发行版（MiKTeX/TeX Live）[S56]；C++ 代码用内置 Code（Pygments 高亮）而非 LaTeX，可避开大量排版坑。
- 适配判断【推断】：与阙疑工具链同语言（Python）、同纪律（代码即产物、可 diff、可 CI 渲染）；数学排版能力对讲内存模型/复杂度/缓存曲线有用；代码高亮原生；Windows 是一等支持平台。**唯一需要固化的是版本与渲染器**（pin manim==0.20.x + 默认 cairo 写进项目配置，等 GL 后端稳定再评估），避免 0.19 式破坏。

### 1.2 Motion Canvas（观察备选，不建议现在 all-in）

- 形态：TypeScript 生成器函数即时间轴，Vite 实时预览（左代码右画面），音频旁白可事件锁帧（`waitUntil('event')`），内置 Code 组件（代码增删改动画是一等公民），MIT。【官方】[S59]
- 讲协议/算法/代码流的信息密度矢量动画，DX 明显优于盲渲染的 Manim；社区 19.1K stars。
- **风险信号**：截至 2026-07，**最后一个正式发布停在 2024-12-14（v3.17.2）**，之后只有提交无 release；151 个开放 issue、近 90 天仅合 1 个 PR。单人/小团队项目押注一个发布停滞的工具链不审慎。【实测】[S59]
- 另一个成本是 TypeScript——会让动画脚本脱离阙疑现有 Python 数据通路（工件解析、门禁、巡检全是 Python）。

**结论**：保持跟踪；等它恢复发布节奏后，在"纯代码演变、无数学曲线"的单集试点（如 ch117 拷贝消除规则演变）。Manim 仍是主线。

### 1.3 Remotion（特定场景，不用于主讲）

- React 代码驱动视频，参数化/批量渲染是核心卖点（同一模板批量出片、播放器可嵌入）。
- **许可（2026-09 条款，v5.0）**：个人与 ≤3 人组织含商用免费；4+ 人需 Company License；自动化调用渲染 API 按 $0.01/渲染、$100/月保底。阙疑单人公司当前在免费档，但"知识卡批量出视频"恰好命中 Automators 定义，**规模化自动管线一旦商用扩张要重新算账**。【官方】[S60]
- 用途定位【推断】：若将来做"每卡 30 秒数据卡片短视频"批量生成（图文 + 配音轨，非精致动画），Remotion 的参数化渲染合适；主线讲解视频不选它（React 生态对本项目是纯增量负担）。

### 1.4 生成式视频模型（Sora 2 / Veo 3）：技术内容禁用

- 2026 年最先进模型的**屏内文字仍是硬伤**：Sora 2 三十天 200+ 条实测，可正确读出的文字仅约 **5%**、部分可读 15%、约 80% 完全不可读；Veo 3 文字渲染 7/10，评测方明确建议"不要依赖它展示关键文字"。【实测】[S64][S63]
- 时长：Veo 3 标准 8 秒、Sora 2 约 20 秒，长片全靠拼接；优势是物理真实感与原生音轨。【实测】[S63][S65]
- 结论【推断】：代码、汇编、寄存器名、性能数字在生成模型里必然幻觉——与阙疑宪法根本冲突。**只允许做章节封面/转场 B-roll 等无事实信息画面**，且发布时标注 AI 生成（SynthID 等）。教学主体必须是代码驱动动画。

## 2. 旁白与音频：开源中文 TTS 已经过了可用线

| 方案 | 许可/出身 | 关键能力与数字 | 定位 | 来源 |
|---|---|---|---|---|
| **IndexTTS2** | Apache 2.0，bilibili | 零样本声音克隆（几秒参考音）；**字音混合建模纠正多音字**；情感与时长可独立控制；MOS 4.54（对比表：OpenAI TTS 4.2 / ElevenLabs 4.3 / Azure 4.3 / F5 4.19 / CosyVoice 4.12）；中英混读；arXiv 2506.21619 | **首选中文旁白** | 【官方+论文】[S61] |
| **CosyVoice2-0.5B** | 开源，FunAudioLLM/通义 | 流式 150ms 低延迟；方言/情感细粒度；比 v1 发音错误降 30–50% | 需要流式/方言时 | [S62] |
| **Kokoro-82M** | 开源轻量 | CPU 可跑、体积极小，已被 manim 生态包集成为后端 | 草稿配音/低成本批量 | [S67] |
| **VibeVoice-Realtime** | 微软，开源 | 提示音说话人包，实时 | 备选 | [S67] |
| ElevenLabs | 商业 | manim-voiceover 最早集成，英文质量标杆 | 英文频道预算允许时 | [S66] |

管线事实：

- **manim-voiceover**（Onur Solmaz）把旁白做成 Python 代码的一部分：AI 配音或真人录音均可，动画自动与语音对齐，支持翻译流水线（gettext + 机译）；作者的核心主张是"**全代码驱动视频**"——脚本、动画、音轨全部进 git，改版零手工重剪（告别 `Final.final.final.mp4`）。【官方】[S66]
- 成本预期校准：传统流程（写稿→录音→动画→剪辑，多轮返工）新手第一集几分钟视频可能要 **1 个月**；3b1b 早已是团队作业（写作/动画/插画/音乐/网页多人，见官方 about 名单）。【S66][S58]
- 生态信号：PyPI 包 `3brown1blue`（2026 年已到 1.2.1）能"主题/PPT→Manim 成片"，带观众分级、领域视觉模式、misconception engine（先演错误直觉再纠正，引用 Muller 研究效应量 0.8）、帧级审计脚本。**这说明"topic→视频"正在商品化**——动画生成本身不构成护城河，再次印证阙疑护城河只能是证据锁定。【官方包，质量未独立验证】[S67]

**对阙疑的用法建议**【推断】：

- 解说稿初稿可由 LLM 从卡的 pedagogry 字段生成（socratic/predict_first/misconceptions 就是分镜提示），但**人声定稿前必须过事实闸门**（§3）；
- 配音先用 IndexTTS2 克隆一个稳定的"阙读音色"（自建参考音，规避声音版权），所有视频同一声音 = 品牌识别；多音字/术语（`vector`、`-O2`、符号名）维护一份发音词典（IndexTTS2 支持拼音直注）；
- 双语字幕用 Whisper 系转写对齐生成草稿再人校，中文上 B 站、英文备 YouTube（manim-voiceover 的 i18n 路径已被趟过）。

## 3. 核心工程：证据驱动动画管线（本方向最重要的设计）

### 3.1 目标流水线

```
卡（ATOM/EV pck.yaml，锁 sha256）
  │  claim / claim_boundary / pedagogy / misconceptions / evidence 引用
  ▼
[1] 分幕规格 scene_spec.yaml（LLM 起草 + 人定稿）
  │  每幕含：旁白文本、画面元素、出现的全部数字 N_i、N_i 的工件引用
  ▼
[2] 数字绑定 numbers.lock（脚本生成，非手写）
  │  从 golden .out / .asm / .json 解析：
  │    例：77 章 vector 扩容三连的 call 次数、108 章 xchg 字节、
  │        648 十卡输出表的每个值（decay_sizeof_param=8 …）
  │  每条形如 {scene: 3, name: sizeof_param, value: "8",
  │           source: Examples/...out, sha256: …, extractor: regex/id}
  ▼
[3] Manim 场景（只允许引用 numbers.lock 的键，禁止裸字面量数字）
  │  代码高亮块同样从 Examples/ 真实源码片段抽取（带行号锚点）
  ▼
[4] manim-voiceover：IndexTTS2 配音 → 自动对轴
  ▼
[5] ffmpeg 合成 + Whisper 双语字幕草稿
  ▼
[6] 视频事实闸门 video_fact_gate.py（新门禁，照抄项目宪法）
     ① 画面 OCR（或渲染期直接收集绘制文本）抽取全部数字/标识符
     ② 每个必须在 numbers.lock 命中且值一致
     ③ 代码片段必须是 Examples/ 文件的精确子串
     ④ 本集引用的全部工件哈希在当前库可复算
     ⑤ 输出 provenance 片尾卡（编译器版本/命令/哈希/证书 id）
     任一不过 = 拒绝渲染发布
  ▼
[7] 发布：B 站/YouTube；描述区挂卡 id + 证书链接 + 工件下载
```

### 3.2 为什么必须这样设计（依据，不只是洁癖）

- 生成式视频文字 80% 不可读 [S64] 堵死了"AI 出画面"的路；Manim 画面里的数字是**人/模型敲进代码的字符串**——这正是书体系里 `[示意]` 病的视频版。项目花了半年把 353 处编造数字清到 7 处，没有理由在视频里开倒车。
- PCK 已有 `contains/contains_any` 符号锚定与 M7"读数篡改必 blocked"先例 [本仓库 EV-MEM-001.pck.yaml 实读]，把同一思想从证书扩到视频是自然延伸：**闸门不是新发明，是既有宪法换介质**。
- 渲染期收集文本比 OCR 可靠：Manim 的 Text/Code/DecimalNumber mobject 在场景树里都可遍历，直接 hook 收集"本帧实际绘制的字符串"，零识别误差。
- 数字绑定让"重新跑一遍编译器→数字变了→视频自动更新"成为可能（工件变更触发该卡相关集重渲染），与 golden 确定性复用、isolated worker 那一套缓存纪律同源，渲染成本可缓存摊薄。

### 3.3 视觉素材分层（哪些用什么画）

| 内容类型 | 工具 | 阙疑对应素材 |
|---|---|---|
| 内存布局/栈堆/指针/缓存行 | Manim 矩形+箭头（自定义 mobject 库一次建好复用） | ch35–41、ch77、false sharing |
| 汇编演变/指令高亮 | Manim Code 组件，源码取自 Examples/*.asm 真实行 | 57 个 ASM 实证 |
| 时间/性能数字（3.5ns/7.6ns 等） | 柱状/坐标图，数值走 numbers.lock | ch27/ch50/ch93 实测表 |
| 状态机/流程（生命周期五态、判决 FSM） | Manim 或直接用现有 511 个 mermaid 静态出图 | mermaid 块经 mmdc/kroki 渲染为透明 PNG 入片 |
| 终端实录（编译命令/报错/sanitizer） | **asciinema 录真终端 + agg 转 GIF/mp4**，不演假终端 | 所有门禁/探针均可真录 |
| 交互演示（排序、调度） | 先做成书站可玩的 D3/Preact 小部件，录屏入片（同时是网页资产） | learning 侧 widget |
| 概念封面/转场 | AI 生成视频或静态插画，仅限无事实信息画面 | — |

Compiler Explorer（godbolt）的分享短链可作辅助出处，但**画面以自家 Examples/ 工件为准**，避免外部链接漂移。

## 4. 冷启动计划： pilot 一集，模板化，再批量

【推断，按项目"串行小批量、禁一波流"的纪律】

1. **选题：ch77 vector_grow 扩容三连**（或 ch107 CAS 环）。理由：已有最完整的真机工件（operator new/memcpy/delete 三连逐字汇编 + golden）、误解普遍（"push_back 每次都分配"）、画面天然适合 Manim（栈/堆/指针移动/调用计数），是"证据驱动"样板间。
2. **时长 4–6 分钟，一卡一视频**；脚本严格按卡片 pedagogy：先 `predict_first`（停下来猜输出）→ 演错误直觉（misconceptions 引用）→ 真机揭示 → 工件定格 → 回到断言边界（GCC 15.3 -O2 x86-64，换档位可能不同）。
3. **同步建基础设施**：numbers.lock 格式、2–3 个可复用 mobject（内存块/缓存行/代码窗）、video_fact_gate 原型、配音发音词典初版。pilot 的验收物不是视频本身，是**第二集成本下降曲线**——若管线成立，第二集应只花第一集 1/3 的工时。
4. CI 渲染：Manim 帧渲染 CPU 可跑（Linux runner + ffmpeg + 免 LaTeX 方案或预装 TeX），加一个可选 video job（不阻塞主 CI，参考项目既有"慢测试分阶段"做法）；产物按集缓存。
5. **模板包随 pilot 发布到仓库**（scene_spec 模板 + numbers.lock schema + fact_gate），未来即使换人/换模型生产，质量下限由闸门保证而非制作者自觉。
6. 节奏目标：pilot 后月更 1–2 集，每集必须绑定一张已 machine-verified 的卡；**不允许视频先行于证据**（没有证书的卡不做视频）。

### 明确不做

- 不追 3b1b 的更新频率与制作规模（那是多人团队 [S58]）；单人项目的 1 个月/首集成本要靠模板和管线摊薄，不靠肝。
- 不让生成式视频碰任何带文字/代码的画面（§1.4）。
- 不做实时渲染交互课件（Manim GL 实时路线）——书站 wasm widget 才是交互载体，Manim 只出离线成片，两者分工。
- 不把动画脚本与证据解析耦死：解析器（Python，连现有工具链）产出中立 JSON，Manim 只消费 JSON，未来 Motion Canvas/Remotion 试点时同一套 numbers.lock 可复用。

## 5. 三方向交叉点（视频 ↔ 前端 ↔ 验证内核）

- 视频片尾/简介挂的证书链接落到方向二的**证书查看器**：观众→读者→自算哈希，视频本身成为阙疑验证体系的流量入口。
- 视频事实闸门是 queyi-core 的又一个 verifier（与 PCK 校验同构），随 `uvx quyi` 分发——**"阙疑验证过的视频"将来可以是一类独立产品**：任何创作者用其管线出的技术视频都可挂可机检的 provenance，这比再写一本书的杠杆更大（长期设想，非近期承诺）。
- 方向一的边界同样适用于视频脚本生产：LLM 可以写旁白初稿与分幕建议，但"这一版数字对不对"只由 fact_gate 判，LLM 不给放行——全部三条管线共用同一条判决层级原则。
