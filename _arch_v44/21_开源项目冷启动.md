## 一、repo→首批用户步骤

1. README 写「别人为何在乎」（一句研究问题+反直觉数字）2. 一行安装 3. 最小可复现 demo 4. 发 Show HN 5. 进 HF Evals/相关 Discord 6. 求前 10 真实用户反馈。

## 二、Show HN / Release Notes 模板

- Show HN 标题：「Show HN: QueYi – a C++ knowledge verifier with tamper-proof ledger (blind holdout 80%)」。正文：3 句价值+链接+最小示例+已知限制。
- Release Notes：一句话价值 + 安装一行 + 最小示例 + 限制链接 threats。

## 三、0→1k star 真实路径（范式）

- 范式：先 10 真实用户（同事/社区）→ 1 篇爆款 Show HN/Twitter → 进某大 V 收藏 → 自然增长。star 增长非线性，常靠一次外部曝光。【范式，盲区具名数据】

## 四、博客/演讲时机 & 失败因 & README & 传播

- 博客：匿名期前写「踩坑」不写身份；演讲：录用后。
- 失败因：README 写「我是做什么的」而非「你为何在乎」、无 demo、无持续更新。
- README fork：有「5 分钟跑通」+ 架构图 + 贡献指引才易被 fork。
- Twitter/HF：周更进度+代码片段，@相关领域人。

## 五、对阙疑的 3 条具体行动

1. **重写 README 为「别人为何在乎」结构**：首段放反直觉数字（盲 80%/账本 452），末尾放 5 分钟跑通。
2. **准备一篇 Show HN 文案**：按模板写好待匿名期后发，含最小 demo 链接。
3. **建「踩坑」dev blog**：每月 1 篇（如「我们怎么发现夹具 circular」），蓄存在感，匿名期前不曝作者。
