## 一、权威错误源清单（按可信度分层）

| 层级 | 源 | 用途 |
|---|---|---|
| 金标准 | WG21 标准草案（eel.is/c++draft, open-std.org） | 判定"什么是对"的最终依据 |
| 权威参考 | cppreference（含 compiler_support 表） | 特性/UB/编译器支持差异 |
| 社区实证 | Stack Overflow C++ 高频误区（如未定义行为、悬挂引用） | corpus 真实分布 |
| 规范 | C++ Core Guidelines（Stroustrup/Sutter） | "什么算好/错"的规范层 |
| 缺陷库 | GCC Bugzilla / LLVM Bugs / MSVC Developer Community | 真实编译器 bug 历史 |

## 二、跨编译器差异权威列表

- cppreference 的 `compiler_support` 页逐特性列 GCC/Clang/MSVC 支持状态，是跨编译器差异最常用表【官方，S35】。
- 真实差异长尾：模板/模块/coroutine 的代码生成与链接行为各家不同【官方，S35】。

## 三、真实 compiler bug 历史

- 各家 bug tracker 可查历史回归（如某优化导致 UB 误判）；做"外部 corpus 真实缺陷"时，应优先采**已被官方确认并修复**的 bug，而非未确认的抱怨【推断，S37】。

## 四、对阙疑 corpus 的校准

- 外部 corpus 20 条检出率仅 33%——若 corpus 来自 SO 误区而非标准草案，分布偏"人易错"而非"编译器相关"，需重定抽样框架【推断】。
- 建议 corpus 三源混合：标准草案反例 + cppreference UB 列表 + 已确认 compiler bug，提高权威性。
