# 05 · LLM 辅助攻击关系标注：可靠性边界

> 外部实证【一方称：源自 ACL 2024-2026 论证挖掘/LLM-judge 论文，本次未独立核验】。LLM 实验本次未跑（属 W 段、需外部依赖）。

## 5.1 方法

- **prompt engineering / few-shot / CoT**：给 LLM 卡面 `claim_structured` + MIS `refutations`，令其输出"攻击目标命题 id + 攻击强度(1-5)"。
- **fine-tuning**：若有标注样本，微调小模型专做攻击边抽取。

## 5.2 可靠性边界（核心风险）

| 风险 | 表现 | 对本仓的冲击 |
|---|---|---|
| **幻觉攻击** | 文本中不存在的攻击关系被编造 | 正确命题被标 OUT → **违反"零误伤"第一性** |
| 一致性差 | 同文本多次标注结果不一 | 不可复现、难溯源 |
| 强度误判 | 弱反驳标为强攻击 | 加权 AF 被噪声权重误导 |
| 张冠李戴 | 攻击边指向错误命题 | 辩护链错乱、人审困惑 |

## 5.3 与本仓"零误伤"的冲突与兜底

- 零误伤要求：**绝不允许正确命题因错误攻击边被标 OUT**。
- LLM 幻觉攻击直接威胁此底线。兜底机制：
  1. **LLM 只生成候选**，不自动入库（与 593 路线图一致）；
  2. **人审逐条确认**（维度 9）；
  3. **机器预筛**：用 embedding 相似度 + 模型级 consequence 检验（维度 10）标记"可疑边"优先人审；
  4. **溯源**：每条边记 LLM 模型/版本/prompt 哈希，便于误伤后回滚。

## 5.4 本仓落地评估（单用户阶段）

- 单用户阶段，人审就是"自己"——LLM 生成候选、人（同一人）确认，独立性问题比多人更突出（590：9 异族判官≈2 有效独立票；单用户≈1）。
- **可行路径**：LLM 生成 194+ 候选边 → 人在 Argdown/表格里逐条 accept/reject/改强度（预计工作量见维度 9）。
- **可靠性边界（待实证）**：本次未跑 LLM，无法给准确率数字；若未来实测，应以"零误伤率"为第一验收指标（而非整体 F1）。
