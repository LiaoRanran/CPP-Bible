# 03 · 下一代架构蓝图（阙疑 v8 · 可验证知识代谢系统）

> 主交付物。结论先行：**不是重构，是在现有机械验证骨架上做三件结构性升级 + 一个最小调度骨架，并给所有"等模型"的能力装上可计算的开关。**
> 开头一句话（任务要求）：**最该现在就做、做了会产生质变的一件事——把验证器从"外延通过"升级为"阴阳同构通过"（断言必须在机制被破坏的对照夹具上失败）。它不依赖任何模型变强、不增加人审、不改现有 56 卡的信任结论，却把六轮对抗中反复出现的"全绿但 claim 空转"整类逃逸一次性收口；这是用编译器当判官的性质判据，是当前所有投资里唯一一块"机制级而非补丁级"的收益。**

---

## 1. 目标架构总图（与 524 八层的关系：演进，不重构）

524 的八层是**活动视角**（感知→规划→调度→生产→验证→进化→知识→输出），活动齐但无法度量每层真假。v8 不推翻它，而是在同一组活动底下插一条**信任主轴**，每个组件必须在轴上有位置、有准入/退出指标：

```
                         信任主轴（所有组件的共同纵坐标）
  机验字节 → 机验活性(阴阳同构) → LLM筛查(可回滚) → 人抽审 → 人签inference/DAL A → 标准源
  ────────────────────────────────────────────────────────────────────────────────
  全自动区（当前苦力可做）          条件自动区（探针门控，未来）      人区（永不自动化）

  活动层（沿用 524 编号，组件按信任轴归位）：
  ┌─ 感知/知识：kg 文件图【已建】→ 概念图规范化【现在补，0连通】→ 空白/矛盾/陈旧选题【机械算子先行，排序等模型】
  ├─ 生产：Writer 三件套【已建】→ claim 三分类 obs/inf/syn【现在】→ 命题提议三元组【探针门控】
  ├─ 验证（核心投资区）：
  │    gate 静态层【已建 58 规则】
  │    replay 执行层【已建：rc/run_match/sha/P0-A】
  │    ★ v8 新增 V-iso 阴阳同构层【现在，性质判据替代符号黑名单】
  │    ★ v8 新增 V-honeypot 埋雷回归层【现在，双指标 hack-rate/hack-free】
  │    LLM 判官层【只埋接口+攒盲测集，探针门控后启用，llm-screened 可回滚】
  │    人审层【保留，职责收窄为 inference/DAL A + 抽审 + 标准源登记】
  ├─ 进化：逃逸归类→机械算子库 mutation_fuzz【现在，文件层可逆】→ 算子生成器【等模型，UCB 淘汰】
  ├─ 调度：task_queue SQLite 人工派发【530 T7 现在】→ Supervisor【8 周数据门】→ 多模型路由【3模型×5批数据门】
  ├─ 成本：CPVA fixture 字符数【已建】→ 全阶段实际成本【530 T6】→ 路由决策数据【攒】
  └─ 输出：闪卡/书【已建，但必须只吃 verified（修过滤）】→ 自适应【等模型】

  横切：golden/poison/pytest/observability 是信任主轴的仪表盘；warn 会计化（停止整体 accept）
```

**为什么是演进而不是重构**：六轮对抗验证过的资产（fail-closed 三分类、P0-A 独立重编译、principal 名册、毒样例 fail-closed 退出码、58 规则的形式层）全部保留并成为新层的地基；v8 不删任何现有组件，只在 replay 旁加同构层、在概念表上加约束、在信任轴上加开关。推倒重来的代价是丢掉这六轮买来的不变量。

## 3. 逐模块设计（现状→目标→过渡→机器验收）

### 3.1 验证器模块（v8 的核心投资区）

#### 3.1.1 V-iso：阴阳同构层（现在做，最高优先级）
- **现状**：replay 只做外延验证（stdout==.out、sha==卡值、符号文本 contains）。六轮逃逸本质全是"外延过但机制空"。
- **目标**：每条 observation 的关键断言必须同时提供**阴面**——一个"机制被破坏"的夹具变体，在该变体上断言必须失败。判据是性质（翻转性），不是符号枚举。
- **最小实现（苦力可照做）**：
  1. 证据卡 frontmatter 增可选 `negative_controls:` 列表，每项 `{fixture: 路径, expect: 关键读数变化描述, key: 哪个 run_match key 必须变化/缺失}`（v1 只支持读数翻转，不支持符号翻转；符号翻转 v2）。
  2. replay 对每个 negative_control：编译运行阴夹具，断言其指定 key 的值与阳夹具**不同**（或程序 rc≠0）；不满足 → `refute:negative_control_passed`（断言在坏夹具上也成立=无判别力）。
  3. 规则 `OBSERVATION-NEEDS-CONTROL`（先 warn 观察期，与 530 T4 活性判据合并实施，存量 0 block）。
  4. 阴夹具的 sha 不进卡（它是测试装置不是知识工件），但阴夹具路径必须存在、可重编译——复用 P0-A 的编译器提取。
- **为什么不被绕**：Writer 要让阴面通过，必须让"破坏机制"的夹具表现得和原夹具一样——那等于证明该机制对输出无贡献，claim 自相矛盾。这是 IPT 在编译器域的实例（02-A2）。
- **边界**：无法构造阴面的 observation（如纯存在性事实"该编译器支持 -O2"）自动归入 inference；这本身是有价值的分类信号。
- **机器验收**：①阳卡正常 confirm；②阴夹具与阳夹具同读数→replay refute（pytest 钉死）；③存量 56 卡 0 block（warn 观察）；④FENCE-001 补一个"删 fence 后循环被消除"的阴面作为样板（它天然有这个对照，EV-CONC 系列已有多夹具，成本极低）。

#### 3.1.2 V-honeypot：埋雷回归（现在做，便宜）
- **现状**：poison_drill 86 断言只验"已知坏载荷被拦"，不报告"正常卡通过率"。
- **目标**：双指标回归（02-A3）——`trap_block_rate`（历史逃逸雷被拦率，应 100%）与 `clean_pass_rate`（干净卡通过率，应 100%），两者都进 golden 指标，任一下降即红。把 6 轮对抗的代表性逃逸（缩进走私/编译后覆写/恒真符号/cat 证据/全角键）维护成**活雷**（在临时沙箱真跑，不只是文本检查）。
- **机器验收**：`poison_drill.py --honeypot` 输出两个百分率；CI 红线 trap=100% 且 clean=100%。

#### 3.1.3 断言判别力：符号黑名单→性质（530 T2 的正解升级）
- 530 T2 计划把 `.seh/.cfi/.p2align` 加入 UNIVERSAL_SYMBOLS——**会有效但仍是枚举**。v8 正解：V-iso 的翻转性是主判据；通用符号黑名单只保留为"快速 warn"辅助层（无阴面的全局 contains 断言遇到帧伪指令→advice 提示补阴面，而非永无止境扩黑名单）。
- **机器验收**：contains_any [".seh_endproc"] 无阴面→advice（不 block，避免误伤）；同断言配了阴面且翻转→放行。

#### 3.1.4 LLM 判官层（只埋接口，不启用）
- frontmatter 增 `proposed_verification: {by: model:<id>, at, anchor_refs: [...], eir_at_approval}` 可选字段；gate 识别但**不改变任何状态**；新增状态级 `llm-screened` 的枚举与 DAL 规则（该级永不能跳过 inference 人签）。
- 同时开始攒**人审盲测集**：把历次红队发现的真错误 + 正常命题做成版本化题库（`data/judge_calibration/v1.jsonl`），只攒不判。
- **机器验收**：字段存在不影响 56 卡；盲测集格式校验脚本存在；G-llm-screen OFF 时任何 llm-screened 状态被 gate block（防偷跑）。

### 3.2 claim 三分类模块（observation / inference / synthesis）
- **现状**：二分类，79 命题（50 obs/29 inf）；observation 仅查工件断言存在（可被自标绕过，批判 B.3）。
- **目标与过渡**：
  1. 530 T4 活性判据（warn）先落地；v8 把它与 V-iso 阴面绑定为 observation 的最终机器条件：**工件断言（存在）+ 活性三条件（量化对照/特有符号/非环境键）+ 阴面翻转**三者齐备才允许 observation 走机验全自动。三者任一缺失 → warn（观察期）→ 稳定后 block。
  2. 新增 `synthesis` claim_type 及规则 `SYNTH-TRACEABLE`（先 warn）：必须有 `synthesizes: [命题id/原子id…]`（全部存在且其证据 confirm）+ `considered_counterevidence: [id…]`；单卡/空列表不允许 synthesis。
  3. claim_type 误填的机器信号：observation 命题的 statement 若含标准法理措辞（"定义/保证/标准上/不要求"）仅 advice（不猜语义，只提示红队优先看）——故意不做成 block（语义正则必误伤）。
- **机器验收**：三分类枚举 gate 校验；synthesis 引用不存在 id→block；空反例列表→warn；存量 0 block。

### 3.3 知识图谱模块（从标签袋到可推理）
- **现状**：323/291 文件图真实可用；157 概念/79 命题边但跨原子连通=0；conflicts 19/19 噪声（contrasts 误并 + 句子 object）。
- **目标与过渡（现在做的纯机械部分）**：
  1. 530 T3 拆 CONTRASTS/CONTRADICTS 边（已在施工版，照做）。
  2. 受控概念槽：subject/object 的概念槽只能填规范集（kg concepts.subject 历史值 ∪ 别名表规范名），取值槽走白名单；先 warn。一次性从 157 短语聚类出规范候选（机械聚类脚本+人确认，约 2-3h 人工）。
  3. 新算子（纯 SQL，苦力可做）：
     - `kg coverage <概念>`：概念→verified 命题数/prerequisite 覆盖（选题空白信号）；
     - `kg suspect <原子id>`：命题被 refute/原子降级时，沿 prerequisite 与共享概念边列出下游 suspect（只列不改状态）；
     - `kg concept-islands`：单卡概念（回填/合并 backlog）。
  4. 概念层 KPI 改为：跨卡连通概念数（当前 0）、最大概念连通分量、人确认识别率；**删除"命题边条数"作为进度指标**。
- **等模型（只埋接口）**：跨表述对齐、开放矛盾发现。concept 表预留 `canonical_id`，命题预留 `alignment_status`。
- **机器验收**：连通指标可打印且当前诚实报 0；FENCE/LOCK/RACE 三卡归一到共享概念后 multi_atom≥1；contrasts 不再进 conflicts。

### 3.4 调度模块（L2 最小骨架，已在 530 T7 设计，蓝图确认边界）
- 照 530 T7 的 task_queue.py（SQLite/enqueue/claim/heartbeat/done/fail/blocked，BEGIN IMMEDIATE，deps，attempts>3 blocked）。v8 补充两点：
  - **能力标签**：task 行加 `requires: [mechanical,semantic,tool_change]` 标签 + `min_probe_score`（预留，人工派发阶段恒为 0），为 G-router 预埋，不实现路由。
  - **队列与任务类型对齐**：claim 生产/红队/replay 批是三类固定 type，payload_ref 只指向仓库文件（不塞长 prompt）。
- **明确不做**（现在）：Supervisor Loop、自动选模型、跨机分发——开关 G-supervisor/G-router 未到。
- **机器验收**：530 T7 的 6 个 pytest（幂等/并发 claim/deps/冒名/超时接管/重试上限）。

### 3.5 成本与可观测模块
- **现状**：CPVA 仅 fixture 阶段（STAGES 已扩 evidence_cards/redteam/gate_fix/human_review 但无数据）；observability 有 30 天轮转、阈值只 WARN。
- **目标**：
  1. 各角色在批次结束 record 真实阶段（窗口数/实际 token 估算/轮次/返工原因）；report 输出端到端每原子成本与分阶段占比——这是 G-router 的唯一决策依据。
  2. golden 指标增 V-honeypot 双率、概念连通率、warn 四桶计数；metrics_collector 采集。
  3. warn 会计化（530 T5）：accept 强制 --classify，四桶 real/false_positive/legacy/accepted。
- **机器验收**：record 一条 redteam 后 report 分阶段；无分类 accept 退出非 0。

### 3.6 输出模块（教学派生防污染）
- **现状**：flashcard_export 导出全部原子含 draft（批判 E16 实测 1/27 是 draft）。
- **目标**：所有教学派生（闪卡/书/测验）统一入口过滤 `status ∈ verified 集合`（machine-verified 是否放行由 G-iso 决定：G-iso ON 前 machine-verified 不进教学导出，保守）。
- **机器验收**：draft/machine-verified（G-iso 前）不进导出 CSV；verified 27（当前口径）正常导出；pytest 钉死。

## 4. 信任与放权矩阵（当前版 + 漂移方式）

| 主张类型 | 当前（2026，无模型探针数据） | G-iso ON 后 | G-llm-screen ON 后 | 永远 |
|---|---|---|---|---|
| observation（有活性+阴面） | 红队+人签 verified（现状多数靠卡级人签） | 机验可 machine-verified；教学导出放行 | LLM 一审 + 人抽审 20% | 终审保留回滚权 |
| observation 三条件不全 | 红队+人 | warn→改补或改 inference | 同左 | 不允许机验 |
| inference（标准/法理） | 命题级人签或登记标准源 | 不变 | LLM 可筛查错漏但不签发 | **人签 DAL A/B 永不自动化** |
| synthesis（新） | 不存在→补规则后：引用闭包机验+人签 | 同左 | LLM 核查引用闭包完整性 | 人签+反例清单 |
| judgment/设计权衡（不入卡） | 只能进正文/附录讨论，不得 claim 化 | 不变 | 不变 | 不进 verified 知识体 |
| 任何 LLM 自评/自评分 | 禁止入闸 | 禁止 | 禁止（判官是异体模型，不是产出者自己） | Oracle 铁律 |

**漂移方式**：矩阵的每一格变化必须由第 2 节开关触发，开关的 enter/exit 写机器指标；不允许提示词或会议改矩阵。矩阵版本化（`docs/kernel/trust_matrix_vN.md` 由 gate 配置引用），每次变化在 golden accepted 里留痕。
