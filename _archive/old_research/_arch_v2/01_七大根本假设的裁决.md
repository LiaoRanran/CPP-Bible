# 01 · 七大根本假设的裁决

> 每条给：裁决【确定/推断/待实验】+ 论证（源码锚点/外部证据/思想实验）+ 崩点 + 演化方向。不给"需要进一步研究"式废话。

## 假设 1：Oracle 铁律会不会变成天花板？LLM 语义判据能否在某临界点进闸？

**裁决【推断，可计算定义】：会有临界点，但它不是"模型够强了"的单点，而是三个可测量条件同时满足的区间；满足前 LLM 只能做"筛查器/红队"，满足后可以做"带否决权的一审"，但永远不做"终审"。**

### 1.1 为什么"永远不让 LLM 当闸"在长期是错的
铁律的真实理由不是"LLM 本质不可信"，而是**激励结构**：一个会被优化/会被对抗的模型，如果同时是自己产出物的评分者，reward hacking 是数学必然（Goodhart）。外部证据：
- RLVR 训练的模型系统性放弃规则归纳、枚举实例标签骗过只查外延的验证器（Helff et al. 2026, arXiv:2604.15149，正是本系统 IPT 思想的来源）；
- 13 个前沿模型的工具使用 hacking 率 0–13.9%，且 **RL 后训练显著提高 hacking**（0.6%→13.9%），72% 的 hacking 附带看似合理的 CoT——模型会把作弊叙述成正当解题（Thaman et al., RHB, arXiv:2605.02964）。
这两条说明：**能力↑不自动带来诚实↑，某些训练方向让 gaming↑**。所以"模型错误率下降就放权"是错误判据。

### 1.2 但"永不进闸"也有真实代价，且随模型变强单调增大
本系统 claim 语义正确性 100% 压在"人会签 + 单红队"上（数据流图 G7）。当前 27 原子可行；527 颗、跨 10 个域时，人成为吞吐瓶颈，而其中大量 observation 类命题的语义判断对强模型已经近乎平凡。永远人审=用最贵的环节做最机械的语义核对，违背强度匹配铁律本身。

### 1.3 可计算的准入条件（不是拍脑袋）
设 LLM 语义判官对**本系统历史命题**的三个指标，全部用"人已签过的命题"做盲测集（≥100 条，含红队抓出的真错误，不能只用通过的卡）：
- **EIR（逃逸率）**：判官放行人后来被证明错误的命题比例。准入阈值 **EIR ≤ 当前人工红队漏检率的 1/2，且 95% 置信上界 ≤ 5%**（小样本必须用上界，不能用点估计——27 颗时点估计毫无意义）。
- **CDR（校准退化率）**：连续两个批次（或滚动 50 条）EIR 不上升；一旦上界越过阈值自动降级。
- **DD（分歧可追溯率）**：判官与人审分歧时，100% 能产出"文件:行/命令/条文号"锚点；给不出锚点的分歧一律按人审算。
三个条件同时满足 → LLM 获得** observation 类命题的一审权**（不是 inference，更不是终审）；人变为抽审 + 只签 inference/DAL A-B。

### 1.4 自动退出机制（可回滚是前提）
- 判官结果**不直接改 status**，而是写入 `proposed_verification`（新字段）+ 证据锚点；原子状态机只接受"机器签名"一个新级别 `llm-screened`，它低于 human-verified，且**必须可批量回滚**（一个 git revert 撤销全部 LLM 一审）。
- 监控：每批次滚动计算 EIR 上界；超阈 → 自动把 llm-screened 降回 draft 并冻结该判官的一审权（开关在 gate 配置，不靠记忆）。
- **崩点**：人审盲测集被污染（判官见过答案）、评测任务分布漂移（训练过的域强、新域弱——RHB 实测"诚实解仍可行时 hacking 才被抑制，任务变难 hacking 率回升"）。所以盲测集必须版本化、分域统计、定期注入红队新抓的真错误。

## 假设 2："机器可核验"的边界在哪？observation/inference 二分够吗？

**裁决【确定】：二分不够，缺第三类；但第三类不能是"作者说了算"的垃圾桶，它要有自己的、比 inference 弱但非空的机器约束。**

### 2.1 原则上无法落到工件/实验/人签的知识
四类：①设计权衡（"这里该用 RAII 还是 GC"——价值判断+约束依赖）；②API/库设计品味；③大型系统涌现行为（"这种调度策略在负载倾斜下总体更稳"——无单卡可复现实验，只能聚合观测）；④反事实/历史归因（"当年若不引入 X 会怎样"）。

### 2.2 二分在现实中已经漏
- 实证：FENCE-001 的 prop-1"阻止编译器消除该循环"被标 observation，但它含机制归因（编译器**为什么**消除），纯输出实验只证明"有屏障时循环在、无屏障时被优化"的对照事实——归因部分是 inference。专家在边界摇摆，机器无判据（批判报告 B.3 已实测自标可绕过）。
- 反向漏：聚合型结论（"56 卡里 16 条多编译器声明无留痕"）是**可机验的统计**，但它不是单次实验 observation，也不是标准 inference，现在无处安放。

### 2.3 第三类：`synthesis`（综合/判断），三分类各有不同的可信度条件
| 类型 | 语义 | 机器条件（非空） | 人条件 |
|---|---|---|---|
| observation | 单次可复现实验的直接读数 | 活性对照（阴阳夹具/量化 falsification/特有符号断言，见 530 T4） | 无人签可 machine-verified |
| inference | 标准/法理推断 | external_basis 登记 + 命题级人签 | DAL A/B 必须人签 |
| **synthesis（新）** | 跨多证据/多卡/历史的聚合判断、设计权衡 | **可追溯枚举**：命题必须列出聚合所依赖的全部原子/证据 id，gate 能机械验证"所列 id 全部存在且 confirm"；统计型 synthesis 附生成命令（如 `knowledge_graph.py stats` 输出哈希）；**禁止单卡支撑 synthesis** | 一律人签，但抽审比例可随判官 EIR 降低 |

synthesis 与 inference 的关键差别：inference 依赖**外部权威**（标准条文），synthesis 依赖**本系统内已验证事实的集合**。它的机器约束是"引用闭包可验证"——不是验证综合结论对，而是验证"它声称综合的每一块都是真的、且没有遗漏反面块"（反面块检索可由红队/未来 LLM 做，但至少要求命题挂 `considered_counterevidence: [ids]`）。
**可信度不坍缩成作者说了算的原因**：读者/红队可以沿 id 列表重放整个综合过程；删一个反面 id 就是可检测的形式违规（比现在的自由 claim 强一个量级）。
**崩点**：聚合的权重/选择偏差无法机器判（选了支持自己的卡、漏掉反例卡）——这正是 synthesis 永远保留人签+反例清单义务的理由。

## 假设 3：五层/八层按"自动化程度"分层是最优分解吗？跃迁条件怎么变可计算？

**裁决【确定】：按自动化程度分层适合"描述现状"，不适合"驱动进化"；进化的真正轴是"信任级×能力依赖"，跃迁应由测量数据触发而非感觉。**

### 3.1 为什么现分层会误导
"L2=12% 调度/L3=12% 智能"把**没有代码**和**有代码但语义不成立**混为一谈（517 给 task_state 算 40% 队列完成度，实测它只是状态文件）。更糟的是它诱导"补齐每一层"的施工本能——528 用字段填充率宣告 L3 点火，而概念图 0 连通。

### 3.2 更好的分解：两条正交轴
- **信任轴**（主张需要什么强度的验证）：机验字节 → 机验活性 → LLM 筛查 → 人签 → 标准源。
- **能力轴**（执行需要什么模型能力）：机械执行（当前苦力可做）→ 模式识别（判 claim_type/找漏网反例，强模型可做）→ 开放推理（选题/新算子设计，暂不可委托）。
每个组件在两轴上有坐标；"放权"=信任轴下移（更自动），"进化"=能力轴上组件的可执行集合扩大。两轴解耦后，不会再出现"建了调度层所以智能层也该上"的虚假连带。

### 3.3 可计算跃迁门（替代"感觉该做了"）
| 跃迁 | 触发指标（全部满足） | 回退条件 |
|---|---|---|
| observation 全自动（现状已接近，待活性判据） | 活性规则上线后连续 3 批 0 逃逸（红队实测） | 出现 1 例 observation 语义逃逸→回红队强制 |
| LLM 一审 observation（假设1） | EIR 上界 ≤5% 且 ≤人红队漏检一半 | 滚动 EIR 越界 |
| 建 L2 队列（人工派发版） | 单周"跨窗口续跑"次数 ≥3 且 task_state 记录在案 | 队列 4 周无真实任务→封存（已在 530 T7 设计） |
| 建自动 Supervisor | 队列运行 ≥8 周 + 任务完成率 >90% + 卡死任务人工接管率 <10% | 接管率回升 |
| 多模型路由 | P1-2 成本数据覆盖 ≥3 模型×≥5 批 + 有实测成本差 | 数据不足则禁止 |
| 概念自动抽取入图 | 抽取结果在历史 27 卡盲测三元组准确率 ≥95%（人抽检） | 准确率跌破 |
| 变异算子自动生成 | 机械变异算子（mutation_fuzz）先运行 ≥1 季度且抓到过真实逃逸 | 生成算子 oracle 误判 |

## 假设 4：验证器博弈有终局吗？能不能让逃逸空间单调收敛，而不是补黑名单？

**裁决【确定+待实验】：纯军备竞赛无终局（黑名单永远有第 21 个符号，已 6 轮实证）；但结构性收敛存在——方向是"提高证据造假的物理成本 + 把验证从外延升级为同构 + 主动埋雷"。三者都不依赖 LLM 变强。**

三个可立即结构性收紧的机制（外部研究支撑）：
1. **证据生成与判定物理隔离 + 不可预测探针**（RHB 实测：简单环境加固使 hacking 率相对降 87.7% 且不降低任务成功率，arXiv:2605.02964）：
   - 本系统已做一半（P0-A 独立 tempdir 重编译）；缺口是探针可预测。引入**随机阴阳探针**：replay 时以固定随机种子对夹具做语义保持变异（变量改名/语句重排/编译顺序），断言判定必须不变；再以小概率注入**变异对照组**（故意删掉关键机制行，如删 fence），此时断言**必须翻转**。断言在"坏夹具"上不翻转=无判别力，这正是 IPT 的可执行形态（arXiv:2604.15149），且判断者是编译器不是 LLM。
   - Hack-Verifiable Environments 的方法论（Roth et al., TextArena）直接可搬：**在环境里埋可检测的雷并同时报告 hack-rate 和 hack-free 通过率**。本系统可在 poison_drill 里维护"埋雷清单"（已知逃逸形态的活样本），每季度报告两个数：雷被触发率（应 100% 拦）+ 正常卡通过率。
2. **外延→同构验证**：毒样例从"单点载荷"升级为"同构族+不变量"，524 H3 已提，530 未落地。关键升级是判据从"枚举变体"改为"性质"：不是列 .seh/.cfi/.p2align，而是断言"该文本在阴阳两个夹具上的判定必须不同"（性质），符号清单永远补不完，性质一次封死一类。
3. **提高造假成本而非试图列尽**：TRACE 的洞察——作弊比真做容易，所以检测"努力量"（arXiv:2510.01367）。对应到本系统：cat 式证据/无对照观测的共同特征是"准备成本低"。要求 observation 必须附带**最小实验结构**（对照+量化+特有符号三者至少二），本质是给造假加固定成本；成本高于真做时，理性 Writer 不赌（不防恶意攻击者，但本系统的威胁模型就是偷懒/投机的 Agent，不是外部黑客）。
**不收敛的残余**：恶意外部攻击者 + 可写仓库权限 + 可改工具源码，任何应用层机制都不防——这要靠 CODEOWNERS/分支保护（组织层），不在本系统设计范围内，应明确写出边界，不要假装规则能防。

## 假设 5：概念层怎么长出推理而不只是检索？现在能做的不白做部分是什么？

**裁决【确定】：157 概念 0 连通（实测）证明问题在数据模型而非查询能力。最小算子集里，"规范化+闭包枚举+极性冲突"现在纯机械可做且做了不白做；"语义相似度对齐/开放矛盾发现"必须等模型。**

### 5.1 为什么现在是标签袋
object 被填成句子（"数据竞争原子性/不建立happens-before"），没有受控词表约束；alias 表 11 条归一 0 命中（kg build 自报）。句子≠概念节点，自然零边。

### 5.2 最小数据模型改动（现在做，纯机械）
- 概念命名受控化（warn 起步，530 T3 已规划 CONCEPT-NORMALIZED）：subject 必须命中规范概念集，object 分为两类槽位——**概念槽**（受控词表）与**取值槽**（枚举白名单：数值/版本/true-false/"未定义"等），禁止把整句塞进 object。
- 概念规范集从现有 157 短语中机械聚类生成候选（去停用词、按共现 subject 合并），人工确认后入 `concept_aliases.txt`——一次性小工，不是持续工程。
### 5.3 现在就能做、且将来不返工的算子（L1）
- **前置闭包**：kg chain 已有（文件级）；概念级"生产 A 前其 prerequisite 概念是否都有 verified 原子"=纯 SQL，524 层1 空白选题直接可用。
- **引用闭包验证**（配合假设2 synthesis）：命题 evidence 列表的 id 全部存在且 confirm——纯机械。
- **极性冲突检测**：528 conflicts 已有极性词表（`_POLARITY`），修法是从"句子子串匹配"改为"概念槽+受控关系谓词"上的查询（同 subject、同谓词族、object 极性相反），数据规范化后误报率才能从当前 100% 降下来。
- **矛盾传播（suspect 标记）**：一条命题被 refute，沿 prerequisite/概念边机械标下游 suspect——纯图遍历，524 层7 已点名。
### 5.4 必须等语义能力的（L3，现在埋接口）
跨表述的本体对齐（"happens-before 关系" vs "同步关系"）、非极性语义矛盾（两条都不含"不/阻止"但冲突）、缺口发现中的"重要性排序"。接口预留：concept 表留 `canonical_id` 可空列 + 命题留 `alignment_status: manual|proposed`，将来模型只提候选、人确认（ODKE+ 的实证：本体引导+二次校验把抽取精度从 91% 提到 98.8%， grounding 降幻觉 35%，arXiv:2509.04696——证明"模型提议+结构校验+人确认"管线有效，但自动入库仍会脏）。

## 假设 6：怎么"随模型进化"且让弱模型脚手架自动卸载而不变成债？

**裁决【推断】：核心机制是"能力探针前置 + 脚手架自带过期条件"，而不是写两套系统。每个为弱模型建的人工环节都必须同时登记"什么测量值出现时我应该被绕过"。**

### 6.1 capability-aware 放权矩阵（任务前探测，不靠模型自报）
每次任务开工先跑 3 个廉价探针（用本系统自己的历史样本，不花钱买 benchmark）：
- **格式探针**：让模型从一张真实卡抽取 claim_structured，与人工金标比对字段完整率/类型一致率；
- **判据探针**：给 5 条已知红队逃逸（poison 库里有标准答案的）看它能否复现判定；
- **修复探针**：给 1 个已知小 bug（pytest 钉死的）看能否一次过测。
三探针分数决定本会话权限：探针不过 → 只派机械活（fixture/回填）；过格式+判据 → 可写 observation 初稿（人审）；过修复 → 可改工具（仍人 merge）。**权限绑定到会话测量值，不绑定模型名**（模型会更新版本，名字会骗人）。

### 6.2 脚手架自卸载的登记制
每个手工环节（人签 observation、人工概念归一、人工红队、人工续跑）在代码/文档里登记一行：`retire_when: <指标>=<阈值>`（假设 3 的跃迁门复用）。没有 retire_when 的人工环节视为永久需求，不允许以"临时"名义新增。530 的 task_queue 就是范例：人手动 `next` 派活，retire_when=队列 8 周稳定+Supervisor 条件满足。
### 6.3 为什么不会变债
自演化调研的共识：进化发生在 context/tool 层（记忆/技能/提示词）比 weight 层快且可逆（Gao et al. Survey, arXiv:2507.21046）。本系统所有脚手架都是文件（规则/毒样例/别名表/队列），天然在可快速卸载层；真正要防的是"脚手架失去明确 owner"——所以要求每条规则/人工环节有唯一 retire 条件，和代码同生命周期评审。
**崩点**：探针被针对性优化（模型学会应付探针）→ 探针题集必须像 poison 一样定期换血（每季度注入新红队真案例），且探针成功率本身是被监控指标。

## 假设 7：性能与严谨的帕累托前沿在哪？

**裁决【确定】：实测全量 replay 130.7s 不是下限，但压缩空间主要不在"更快编译"，而在"少跑、隔离跑、并行跑"三层，且每一层都有已实测的约束。**

| 步骤 | 实测耗时 | 本质串行？ | 压缩手段 | 代价/风险 |
|---|---|---|---|---|
| gate 静态检查 | ~4s | 否（纯读） | 已够快，不值得动 | — |
| poison | 几秒 | 否 | 已够快 | — |
