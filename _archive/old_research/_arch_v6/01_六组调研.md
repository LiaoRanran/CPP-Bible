## 组 1 · Oracle 自身 TCB 怎么收口

**它解决的人类老问题**：验证者本身会错——实证显示主流生产编译器普遍存在 miscompilation（Nullstone 12/20；Eide-Regehr 13 个编译器全在 volatile 上出错；Yang/Csmith 报告 325+ 真实编译器 bug，每个被测编译器都崩过也都静默错过）【事实，[CompCert 手册第 1 章](https://compcert.org/man/manual001.html)】。

**2025–2026 进展**：
- 【事实】CompCert 3.17（2026-02）仍是 C 编译器（"almost all of ISO C 2011"），**不是 C++ 编译器**；2026-03 首次以编译器使用取得 DO-178C/DO-333/DO-330 适航认证积分（ATR 42/72）；性能约 GCC -O1 的 90%（[compcert.org](https://compcert.org/index.html)）。**C++ 无对等已验证编译器**。
- 【事实】Translation validation 是替代路线：不证整个编译器，只在每次编译后验证"这一次翻译"保持语义；CakeML/Icing 用精化链验证快速数学优化，JIT 领域有 CoreJIT 验证投机与去优化（[Icing/CAV19](https://cakeml.org/cav19.pdf)、[CoreJIT POPL2021](https://cseweb.ucsd.edu/~dstefan/cse291-spring21/papers/barriere:jit.pdf)）。
- 【事实】差分/随机测试仍是抓编译器错误最有效手段（Csmith/EMI 谱系；形式化工具生态 2026 仍活跃，[fm-tools.sosy-lab.org](https://fm-tools.sosy-lab.org/)）。

**本仓可算/可做**：
- 【类比，本仓已有雏形】matrix 已含 GCC×clang×-std×-opt；它本质就是 translation validation 的廉价版（行为差分）。**现在能算的判据**：对每张卡的每个编译矩阵单元，定义"三方不一致率"=输出/结构分歧单元数/总单元数，进 metrics——编译器 TCB 从"盲信单一 g++"变成"有可观测分歧率的事实"。
- 【推断】换 CompCert 不可行（不支持 C++，夹具是 C++17/23）；自研 translation validation 无对象（不是自研编译器）；**现实最小一步 = 多编译器差分把"编译器出错"变成可检测事件 + 对关键结构断言（lock/原子指令）要求跨编译器一致**，不一致即该命题标 toolchain-dependent，不允许进 machine-verified。

## 组 2 · 错误率上界的定量数学（本轮核心，实算在 02）

**来源与公式**：
- 【事实】rule of three / 零失效可靠性：n 次独立试验 0 失效 ⇒ 失效率单侧 (1−α) 上界 = 1−α^(1/n)，95% 时近似 3/n（可靠性论证测试经典结果，[Microsoft TIA safe-fallback](https://learn.microsoft.com/ja-jp/previous-versions/azure/devops/pipelines/test/test-impact-analysis?view=tfs-2018) 与 demonstration testing 通用）。
- 【事实】Clopper-Pearson 精确二项区间（Beta 分布分位）是最保守的有限样本区间；Wilson 区间更窄但近似。
- 【事实】mutation testing 的外推假设（coupling effect/competent programmer）在 2025-26 仍受质疑：mutation score 能/不能预测真实缺陷检出没有定论，equivalent mutants 是公认噪声源（561 已部分覆盖，本轮只取样本量公式，不重复论战）。

**本仓现在就能吐的数字**（全部由 [probe_bounds.py](file:///C:/CodeLearnling/note/note/C++/CPP-Bible/_arch_v6/probe_bounds.py) 实算，明细见 02）：
- 56 卡 0 误伤 ⇒ 误伤率 95% 置信上界 **5.21%**（精确 C-P；rule3 近似 5.36%），90%=4.03%、99%=7.89%。
- mutation 拦截率 **61.4%（729/1188 全分母）C-P 95% 区间 [58.5%,64.1%]**；按可判分母 76.3%（729/956）区间 [73.4%,78.9%]；逃逸率（可判分母）[21.1%,26.6%]。
- 要宣称"逃逸率 ≤5% @95%"且 0 逃逸：**n≥59**（精确解）；按当前逃逸率 ±5% 半宽需 n≈279。
- 算子级：M4 200 可判 0 逃逸 ⇒ 上界 1.8%；M7 139 可判 0 逃逸 ⇒ 2.6%；**M2 207/207 全逃逸**（区间 [98.2%,100%]）——它不是"噪声"，是"该算子没有任何拦截"的硬事实。

## 组 3 · 论证与信念修正：给"哪些命题当前可接受"唯一机器答案

**它解决的老问题**：攻击/支持关系存在时，接受什么——Dung 1995 给出可计算的语义（grounded/preferred/stable 外延）。

**2025–2026 进展**：
- 【事实】Dung 框架有成熟实现（Haskell Dung 库 2026-02 仍维护、DIAMOND/ADF 用 ASP 求解，[Dung hackage](https://hackage.haskell.org/package/Dung)、[DIAMOND](https://arxiv.org/pdf/1312.6140v1.pdf)）；2026 年出现直接给 LLM agent 用的沙箱化 Dung MCP（dung_extensions 工具，[npm argdown-mcp](https://www.npmjs.com/package/@casualtheorics/argdown-mcp)）。
- 【事实】**关键复杂度结果（ARGUS, UAI 2026）**：grounded 语义下修复判定 **P**（多项式），preferred/stable 是 NP-完全，skeptical stable 是 Σ₂^p-完全；其最小改动修复算子满足改造后的 AGM 公设并有表示定理（[PMLR v337:7536](https://proceedings.mlr.press/v337/xiao26a.html)）。
- 【事实】论证系统修正的 AGM 翻译已有理论：以"论证状态最小改变"而非"攻击图最小改变"为标准（Coste-Marquis et al., TAFA-13）。

**本仓可算**：【类比】claim_structured 命题 + refute + suspect 级联 + impact 闭包 = 一个手写论证系统。最小落地：命题为节点、contradicts/contrast/refute 为攻击边、prerequisite/specializes 为支持边，**用 grounded 语义（P 类，可纯 Python 不动 ASP）**给"当前无争议可接受命题集"唯一答案；AGM 最小改变给级联划界。数据结构与算法在 03。

## 组 4 · 分权与多模型族治理

**它解决的老问题**：孟德斯鸠式分权——立法/行政/司法不能同一主体。

**2025–2026 实证（异族为什么比同质有效）**：
- 【事实】govllm 治理框架实测：裁判模型间一致率仅 51.5%–69.1%，**无单一模型在所有维度占优**；问题顺序变化使一致率波动达 25 个百分点（位置偏差）；专门化 panel 优于任何单一裁判（[arXiv:2605.24737, 2026-05](https://arxiv.org/html/2605.24737)）。
- 【事实】Cisco 的 constitution 标定工作明确："**同家族模型共享偏置，它们的一致不代表规范无歧义**，跨模型验证必须用不同厂商模型"；跨模型分歧把规范评审从穷举变成定向搜索，跨模型不一致最高降 57×（[arXiv:2605.24247, 2026-05](https://arxiv.org/html/2605.24247)）。
- 【事实】异构 Council Mode（不同厂商并行+综合）报告幻觉率下降（[arXiv:2604.02923v3, 2026-04](https://arxiv.org/html/2604.02923v3)）；但 Anthropic Constitutional Classifiers++ 也实证"集成+升级"仍有 reconstruction/obfuscation 两类未堵攻击（[2026-01](https://www.anthropic.com/research/next-generation-constitutional-classifiers)）——【推断】异族只减相关误差，不消除误差。

**本仓可算/可做**：把现状"苦力建设/trae 对抗/豆包验收/人 push"理论化为显式三权（03 详述）。现在能算的判据：**同族相关性审计**——任何"双模型一致"的结论必须记录两模型族 id，同族一致不计入独立佐证（可在 model_profiles 里加字段，<1 天）。

## 组 5 · 知识老化与复证周期

**它解决的老问题**：测试/知识会腐烂，而"还在通过"的测试最危险（stale，不是 fail）。

**2025–2026 实证**：
- 【事实】Google：84% 的 pass→fail 转变是 flaky 不是真回归；约 16% 测试有 flaky；Atlassian 2025 年 flaky 浪费 15 万开发者小时/年；Slack 把测试任务失败率从 57% 压到 <4%（[testdino 汇编 2026-03](https://testdino.com/blog/flaky-tests)，原始 Google/Slack/Atlassian 工程博客）。**反直觉算术**：单测试 0.05% flaky，1000 测试全套全绿率只有 61%——flaky 必须按套件级指标管。
- 【事实】TEBench（2026-05）：七个 agent 配置在项目级测试演化上 F1 收敛于 45.7–49.4% 的共同天花板，**Test-Stale（测试还过但已不验证新行为）最难，F1≈36%**，因为 agent 只会"执行-失败-修复"反应式循环，结构上处理不了 stale/missing（[arXiv:2605.06125v1](https://arxiv.org/html/2605.06125v1)）。

**本仓可算/可做**：【类比】命题绑定 g++ 15.3 字节，编译器升级即整体漂移——03 给"复证周期"机制。现在能算：按 `claim_boundary.opt/std/arch/artifact_compiler` 把命题分"工具链敏感/不敏感"两类（frontmatter 已有全部字段，一个脚本即可），后者在换编译器时豁免、前者强制 re-attestation。

## 组 6 · correct-by-construction：让生成端出生即带证明义务

**它解决的老问题**：事后测试贵且漏——把验证义务前移到规格/生成时刻。

**2025–2026 进展**：
- 【事实】"不要想象，去执行"：SolidCoder 用 property-based oracle 替代模型心算轨迹，GPT-4o 上 CodeContests +4.3p；消融显示"边缘情况前置意识"单项增益最大，执行落地抓到规格改进抓不到的另一类错误（[arXiv:2604.19825, 2026-04](https://arxiv.org/html/2604.19825)）。
- 【事实】Vibe coding 形式化立场文：最强模型在 318 题基准上只 28% 生成安全且正确代码；主张 side-car 式 autoformalize→验证→可执行反馈（[arXiv:2511.00202, LMPL 2025](https://arxiv.org/html/2511.00202v1)）。
- 【事实】VeriSpecGen：规格合成 86.6%（Claude Opus 4.5），关键机制是**原子需求分解 + 需求级测试 + 可追溯映射 + 局部修复**（[arXiv:2604.10392, 2026-04](https://arxiv.org/html/2604.10392)）；SPECA 从自然语言规格派生不变量/前置/后置/信任假设并跨实现复用（[arXiv:2604.26495v2, 2026-05](https://arxiv.org/html/2604.26495)）。
- 【事实】Red Gate 纪律：实现前测试必须先失败，否则测试可疑（VSDD，2026 社区方法）。

**本仓可算/可做**：【类比】这就是 V-iso 的方法论表亲——V-iso 已要求"写卡时同时写阴面可证伪条件"。可前移的出生字段：每条 claim 落卡时**强制**带"证伪探针"（什么编译器输出会使本命题 refute，V-iso 已起步）、"适用矩阵边界"（matrix 已有）、"Red Gate"（该 claim 的 replay 必须先能失败——即阴面必须实测翻转，533 已建机制）。本仓在这条线上**已领先行业口头实践**，缺的是把它从"建议"升为落卡硬字段。
