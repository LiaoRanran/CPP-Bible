## A. 论证子系统：claim_structured 的 grounded 语义

### A.1 现状为什么是 ad-hoc
【事实】现有机制：`claim_structured`（observation/inference/synthesis）、refute 三分类、suspect 级联（impact_analysis 多跳闭包）、kg 的 contradicts/contrasts 拆边。这些回答了局部问题（"这张卡被驳了影响谁"），但**没有任何一个函数回答全局问题："在当前所有攻击关系下，哪些命题仍然成立？"** 答案目前靠人读报告。

### A.2 数据结构（从现有 frontmatter 聚合，零新基础设施）
```
node  = {prop_id, atom_id, claim_type(observation/inference/synthesis),
         status(verified/refuted/draft...), evidence_strength(机验/人签)}
edge  :
  attack  : refute事件 / relations.contradicts / 机制对照被实测推翻
  support : relations.prerequisite/specializes/realizes（只影响"理由链"，不改变攻击语义）
```
输入全部已存在：命题在卡 frontmatter、关系在 atoms relations、refute 在 replay verdict 与 worklog（562-A1 提议的命题状态图是其物化层）。

### A.3 判定算法：只用 grounded 语义（多项式，纯 Python <150 行）
【事实依据】ARGUS（UAI 2026）证明 grounded 下修复判定在 P，preferred/stable 是 NP-完全、skeptical stable Σ₂^p——**本仓 79 命题规模也不碰 NP 语义，选 grounded 是复杂度上的硬决定不是偏好**。

Caminada 三值标注（in/out/undecided），不动点迭代：
```
IN    = 没有任何 IN 攻击者的命题
OUT   = 至少有一个 IN 攻击者的命题
UNDEC = 其余（互相攻击成环/攻击者自身未决）
```
迭代：反复传播直到不动点（grounded 唯一，与迭代顺序无关——这就是"唯一机器答案"的来源）。支持边不改变三值判定，只用于排序与解释。

苦力实现要点：
1. 构图：遍历 atoms（_as_list(frontmatter["claim_structured"])）+ relations + 当批复 replay 结果；
2. 初始：所有节点 UNDEC；
3. 反复：无 IN 攻击者的 UNDEC→IN；有 IN 攻击者的→OUT；直到无变化（79 节点 ≤79 轮）；
4. 输出：`{accepted:[...], rejected:[...], contested:[...], cascade_from_refute:{refuted_id:[受影响 IN→OUT 列表]}}`。

**机器验收（可钉 pytest）**：
- 空攻击集：全部命题 IN（健全性）；
- 自攻环（A 攻 A）：A=UNDEC 而非 IN（防自证，呼应 E12 自证断言）；
- 两条互攻：两个都 UNDEC（grounded 不轻信任何一方——正是"异族未决→人"的位置）；
- 一条 refute 事件：目标 OUT，其 prerequisite 下游按 impact 闭包进 cascade 列表（与 558 Part C 多跳闭包对齐）；
- 幂等：两次跑结果逐字一致；与人工对 3 个真实案例（FENCE prop-1、一个 inference 命题、一条历史 refute）标注一致。

### A.4 AGM 最小改变 → suspect 级联划界
【事实依据】论证系统修正的 AGM 翻译以"论证状态最小改变"为准（非攻击图最小改变）。落地规则：
- 一次新攻击只允许把最少必要的 IN 节点翻成 OUT/UNDEC——具体即**被攻击节点 + 其攻击闭包内没有其它独立 IN 支持者的节点**（独立支持=不经被驳节点也能到达该节点的 IN 链）；
- 有独立支持者的节点**保留 IN**（一个证据被驳不株连其它独立证据支持的命题）——这给当前"refute 一张卡该降级多少命题"提供了算法边界，替代 ad-hoc 全挂红。
- 实现：在 A.3 输出上对比"加入新攻击边前后"的三值标注，diff 即最小改变集；若有多个等小改变集，全部标 UNDEC 交人（grounded 不轻信）。

### A.5 与 knowledge_graph 四表怎么接
- 不新建图：论证视图是 kg 的一个**只读投影/视图**（节点=命题表行、攻击边=relations 中 contradicts + 运行期 refute 事件）；
- 530 T3 的 contrasts/contradicts 拆边正好是攻击边类型化的前置；
- 视图代码放 tools/（纯函数，gate 可 import），**不自动入库新命题**（529 冻结项不变：视图只消费已人签/已机验数据）。

## B. 分权子系统：把经验分工写成制度结构

### B.1 现状对应哪种制度模型
【类比】当前事实分工：
- **苦力**（执行模型）：写规则/工具/卡 → 行政（生产与执行）；
- **trae 异族（本会话角色）**：只读对抗/调研，不改正式文件 → 司法审查/反对党；
- **豆包/其它族**：验收 → 司法第二陪审；
- **人（liaoranran）**：push/accept/人签 inference → 制宪会议+最高法院+公民。
这是无意识的**三权分立 + 陪审团 + 制宪权归人**。问题是它靠投喂词口头维系，没有结构约束。

### B.2 2025-26 实证给出的三条设计约束
1. 【事实】同族模型共享偏置，其一致不是独立佐证（Cisco 2026-05）；
2. 【事实】无单一裁判模型全维度占优 + 裁判有高达 25p 的位置偏差（govllm 2026-05）；
3. 【事实】异族集成仍留 reconstruction/obfuscation 盲区（Anthropic 2026-01）⇒ 陪审团只减相关误差，否决权必须留给非 LLM（编译器/Oracle/人）。

### B.3 三权映射与最小落地（角色/必须异族否/否决权/留人）

| 权 | 角色（现状） | 准入 | 否决权 | 2026 可机器化的部分 |
|---|---|---|---|---|
| **立法**（规则/宪法） | 人定规则语义；建设模型可**起草**规则 | 起草者与审查者**必须异族**（不同厂商族） | 人独占（register_all 准入 = commit 权在人） | 规则注册表已有；补：规则元数据记 `drafted_by_model_family / reviewed_by_model_family`，同族→gate warn 拒绝生效 |
| **行政**（生产） | Writer/苦力产卡/产工具 | 单一模型即可 | 无自我验收权（现状：生成者不可 complete 自己产物，534 已建 verify_cmd） | task_queue 已强制 verify 通过才 done；补：行政产出进入司法队列前不具任何效力 |
| **司法**（验证/裁决） | 编译器 Oracle（机械）+ 异族评审（红队）+ 人（终审） | 机械 Oracle 不涉及模型族；**LLM 评审≥2 异族才计数**；inference 终审永远是人 | **Oracle/人有绝对否决；LLM 评审只有"建议 block/建议人审"权，无放行权** | 评审记录带 vendor family；同族一致标 correlated 不计独立票；N 异族分歧→自动升级人（不投票折中） |

**一票否决（veto）清单**（任一触发即停，不进入多数决）：
- 机械 Oracle（replay/gate block/poison trap）非 confirm；
- 任一异族给出带可复现锚点（文件:行/cmd 可重跑）的具体攻击——**一个带证据的攻击 > N 个无证据的赞成**（这与 V-iso"一个真翻转探针否决整条 claim"同构，也符合举证不靠人头的证据法直觉）；
- 人对 inference/synthesis 的拒签。

**现在缺第三方的两个环节（诚实点名）**：
1. **golden accept 单签**：四桶分类（real12/legacy108/accepted16）目前只一人签 → 至少应要求"分类规则由异族先独立跑一遍、分歧清单进人视野"（人仍拍板，但不能在没看过分歧的情况下签）；
2. **规则自写自测**：61 条规则由建设方起草又由建设方写 poison 测——548 的毒样例虽多但属"自查"；最低补强：每轮新规则必须有**异族只读写的攻击批次**（本会话/前几轮 _adv/_arch 调研正是此角色，应制度化进 task_queue 的 `redteam` 独立池，560-E2 案例库承接）。

### B.4 不做什么（红线）
- 不做 LLM 陪审团多数决放行（561 已否同质辩论；2026 证据显示异族也只去相关误差）；
- 不让司法模型获得"否决机械 Oracle"的权（层级铁序：Oracle > 异族建议 > 行政自报）；
- 不把人从立法/终审环节移除（无"AI 修宪"路径，等同 562 的 G-supervisor 边界）。

### B.5 与 02 数字的接口
- 异族陪审团的"独立票数"本身可用 02 的二项框架监控：把"异族评审漏报带锚攻击"当作坏事件，随红队批次累积，用同一脚本算其漏报率上界；
- 分权结构的健康判据：`rules_with_same_family_draft_and_review`（应为 0）、`single_signer_accepts`（应逐批下降到 0）、`llm_veto_over_oracle`（必须恒为 0，出现即结构事故）——三条进 metrics。
