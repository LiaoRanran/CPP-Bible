# 09 · 与现有系统集成方案

> 现有信任根组件（已读核实）：`tool_integrity.py`（5 核心+2 测试配置 sha，enforce fail-closed）、`governance_doc_guard.py`（manifest + 弱化扫描，manifest 自身不进校验）、`overturned_events.py`（推翻通道，git 作者绑定 fail-closed）。

## 9.1 与 tool_integrity 集成（互补不冲突）
| 维度 | tool_integrity（现状） | 新增 supply_chain + merkle |
|---|---|---|
| 范围 | 5 工具 + 2 测试配置（逐文件 sha） | 全范围集合根（含规则定义/原子/证据/基线）|
| 形式 | 基准文件 `.tool_checksums`（自签） | Merkle 根 + link 链 + OTS |
| 调用点 | 三判定入口 `enforce()` | gate 启动 `bootstrap_check()` |
| 缺口补 | 不校验规则定义内容 | 规则定义进 Merkle 根，启动校验 |

- **共存**：`tool_integrity` 继续钉"工具未被改"；`merkle_integrity` 钉"全部内容未被改"。两者正交。
- **`--update` 强化**：`tool_integrity --update` 增加 `--by/--reason`，写 `resign_log.jsonl`（封堵 585 攻击 1 重签无身份）。

## 9.2 与 gate_engine 集成（启动自校验）
`gate_engine.py` main 首行序列：
```python
tool_integrity.enforce("gate_engine")   # 现有：工具文件未改
supply_chain.bootstrap_check()           # 新增：全范围 Merkle 根与磁盘一致
```
→ 任何规则/策略定义文件被静默改 → 根变 → `bootstrap_check` 失败 → fail-closed 拒绝（封堵 585 攻击 1 文件级）。

## 9.3 与 poison_drill 集成（封堵攻击 2）
- poison 运行前调 `supply_chain.verify(step="poison_test")` + 豁免台账校验：
  - 每条 `exemptions` 台账项须有对应 `exemption-<id>.json` link（functionary=git HEAD，含 reason）。
  - 缺 link 或 reason 空 → 拒绝运行（fail-closed）。
- 行为级 covered（581）保留 + "每条 covered 规则须有真实触发它的毒样例测试日志"强校验。

## 9.4 与 overturned_events 集成（封堵攻击 3）
- 人审/推翻写入时，额外生成 `human_review` link（materials=上游 products，products=overturned_events.jsonl 哈希），进 Merkle 根。
- `overturned_events.append` 现有 git 作者绑定**保留并强化**：link 的 functionary 取同一 git author，使"记录篡改"可被 Merkle 检出。
- **诚实**：身份仍受 git 作者可自设限制（见 05.4），不可密码学证明。

## 9.5 与 governance_doc_guard 集成（补其已知缺口）
- `governance_doc_guard.py` 自承"manifest 自身不在校验范围"（line 14-16）——这正是 585 攻击同源敞口。
- 补法：把 `data/governance_docs_manifest.json` 纳入 Merkle 根 + 对其打 OpenTimestamps 戳。manifest 一旦被改 → 根变 → 检出。
- 弱化扫描（scan）结果进 `human_review` link 的 materials，使"绕过扫描"也被溯源。

## 9.6 数据流（端到端）
```
[write_cards] --atoms/misconceptions--> Merkle(atoms)根
     |                                      |
[gate_validate] --gate_engine.py+规则定义--> Merkle(tools+rule_defs)根 ──┐
     |                                      |                          │
[replay_verify] → [poison_test] → [mutation_test] → [metrics_collect] → [human_review]
     |                                                                  │
     └── 每步生成 link，materials=上一步 products（链路绑定）───────────┘
                                            ↓
                        Merkle(global)根 + 各 scope 根 → merkle_roots.json
                                            ↓
                        OpenTimestamps 戳（根 + .tool_checksums + governance manifest）
                                            ↓
                        data/supply_chain/{links,layout,merkle_roots,timestamps,resign_log}
```

## 9.7 集成风险
- **循环依赖**：`supply_chain` 自身文件须纳入 Merkle 根？否——其根由 `merkle_roots.json` 代表，该文件上链即可（递归无解，同 `.tool_checksums` 处理）。
- **启动性能**：`bootstrap_check` 重算根（108 文件 ~毫秒级，探针实测树高 5-7），可接受。
- **失败模式**：根不一致 → 拒绝运行（宁可停机不误判），符合 fail-closed 第一性。
