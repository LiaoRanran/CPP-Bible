# 05 · 方向 5：封堵 585 三个 meta 攻击的具体方案

> 攻击事实来源：【一方称】585 红队实锤（brief 复述）；本调研核实了相关防护现状（`tool_integrity.py`、`governance_doc_guard.py`、`overturned_events.py`）。

## 5.0 现状真实性核对（务请先读）
- **攻击 1（规则供给链）**：`tool_integrity.py` 仅钉 5 个**工具文件**（`gate_engine.py` 等，line 40-46），**规则/策略定义若游离于这 5 文件之外则不在校验内**；`--update` 无身份验证（line 11-13）；`gate` 启动确调 `enforce()`（line 177-207），但只校验"工具文件未变"，**不校验规则集内容**。→ 攻击面真实存在（文件级）。
- **攻击 2（毒样例自证）**：581 已改为"行为级 covered（真实 gate 命中规则 ID）"；但**豁免台账仍自写自验**（brief 确认）。→ 部分封堵，台账口仍开。
- **攻击 3（人签文本自证）**：`overturned_events.py`（592 落地）已做 **git 作者绑定**（`_validate_event` line 129-137：必须匹配该卡最后一次 git 提交作者，`human:任意名` 不再直接过）。→ **该攻击的表面形态已被 592 部分封堵**，但**单用户 git 作者可自设**仍是结构性上限（见 5.4）。

## 5.1 攻击 1：规则供给链攻击
**封堵机制（组合 04+01+03）**
1. **扩展完整性覆盖**：把"规则/策略定义文件"纳入 Merkle 根（不只在 `tool_integrity` 的 5 文件）。`gate` 启动除 `enforce()` 外，验 `merkle_roots.json` 中 `tools+rule_defs` scope 的根与磁盘一致。改任一规则文件 → 根变 → 启动拒绝（fail-closed）。
2. **in-toto link**：`gate_validate` step 的 products = `gate_engine.py` + 规则定义哈希；后续 step 的 materials 必须含此 products（链路绑定）。
3. **OpenTimestamps**：Merkle 根上链，证明"此规则集于 T 前存在"。
4. **重签防护**：`tool_integrity --update` 须带 `--by <git author> --reason <text>`，写入 `data/supply_chain/resign_log.jsonl`（人审留痕），不可无理由重钉。

**进程内运行时篡改（诚实说明）**：若攻击者在已加载模块的内存中把 rule.check 置空（文件未变），文件哈希/Merkle 根**检测不到**。缓解：gate 运行时算"**生效规则集指纹**"（加载后对所有 rule 对象算 sha）并与 Merkle 记录的 `rule_fingerprint` 比对（阶段 4 强化，留作 W 档运行时自检）。这是本攻击**唯一无法纯文件层封堵**的残余风险。

**优先级**：P0（文件级）+ 阶段 4 补运行时指纹。

## 5.2 攻击 2：毒样例自证攻击
**封堵机制**
1. **豁免台账人审绑定**：新增豁免须带 `human:<git author>` + `reason`，写入 `data/supply_chain/links/exemption-<id>.json`（functionary=git HEAD，模拟签名），台账校验每条豁免都有对应 link，否则 poison 运行拒绝。
2. **行为级强化**：581 的"真实 gate 命中规则 ID"保留；额外要求"**每条 covered 规则须有对应真实毒样例测试且测试真实触发该规则**"（测试运行日志为证），杜绝"0 真载荷 + 一行注释谎报"。
3. **Merkle 根**：`poison_drill.py` + 毒样例定义 + 豁免台账哈希进根。
4. **in-toto link**：`poison_test` step 的 materials 含豁免台账 products，绑定上游。

**优先级**：P1（台账人审）+ 行为级强化。

## 5.3 攻击 3：人签文本自证攻击
**现状**：592 已用 git 作者绑定封堵"任意名直过"。
**残余 + 封堵机制**
1. **人审记录 Merkle 树**：所有人审（overturned / human_review link）进 Merkle 根，篡改任一条 → 根变 → 检测。
2. **上链**：人审 link 的 Merkle 根 OpenTimestamps 钉时间，证明"该人审记录于 T 前存在"。
3. **身份组合**：`git 作者 + OpenTimestamps 时间戳 + 理由哈希` 作为"人审身份"证明，写入 link。

**结构性上限（必说）**：单用户阶段 git 作者可自设，OpenTimestamps 只证"存在时间"不证"身份"——**无法密码学证明"确实是某人审的"**。能防"事后篡改记录"，不能防"当时自签伪造"。这是单用户阶段的硬上限，需双人/密钥（W 档）才破。

**优先级**：P1（篡改检测）+ 接受身份上限。

## 5.4 封堵后剩余风险 + 单用户上限汇总
| 攻击 | 封堵后残余风险 | 单用户结构性上限 |
|---|---|---|
| 1 规则供给链 | 进程内运行时篡改仍漏（需运行时指纹，W档） | git 作者自设影响重签身份 |
| 2 毒样例 | 行为级测试可被精心构造绕过（需持续对抗） | 单用户无第二人复核台账 |
| 3 人签文本 | 记录篡改可检 | **身份无法密码学证明**（硬上限）|

W：运行时规则指纹（攻击 1 残余）、密钥体系（攻击 3 身份）。
