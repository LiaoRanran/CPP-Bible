# 01 · 第二锚独立性与信任根（Q1 + Q6）

> 任务疑问：T1「让每条规则挂一个可执行行为证据（毒样例 id / pytest 正反例），规则被写空 ⇒ 其证据必然失败，从而无需密码学也能发现 PoC-1」。在单用户、单机、无密钥、`.tool_checksums` 可 `--update` 无认证重签、git 历史可 rebase/amend 的前提下，**这第二锚和第一锚（checksum）是不是共享同一个可被一次性伪造的根？**

---

## 1. 现状锚点（代码实测，非转述）

- `tools/gate_engine.py`
  - `RULES: list[Rule] = []`（L176）—— 纯内存 list。
  - `register()`（L179–185）只校验「ID 不重复」+「教学/文学规则须有 basis」，**没有任何"行为证据"字段**。→ 说明 T1 的"规则挂证据"目前**根本没落地**，是待建提案。
  - `main()` 首行 `tool_integrity.enforce("gate_engine.py")`（L3571）—— 仅对 5 个 CORE_TOOLS 做 sha256 比对。
- `tools/tool_integrity.py`
  - `CORE_TOOLS`（L40–46）= gate_engine / atom_evidence_replay / poison_drill / toolchain / cppbible。
  - 文档自承：`.tool_checksums` **自身不纳入校验**（L20–24，递归无解，靠 git 历史留痕）。
  - `--update` **无任何身份认证**（L146–150）：谁跑谁重签，重签即"绿"。

**结论**：当前第一锚（checksum）的可信度最终落在"`.tool_checksums` + git 历史"上，而两者都写在同一个可写的本地仓库里。T1 提案的"行为证据"若也落在同一仓库（pytest 文件 / poison id 清单），则它的可信度同样落在"同一仓库 + 同一 git 历史"上。

---

## 2. 最小伪造链（PoC-1 升级版：规则被写空 + 所有证据仍绿）

目标：让某条规则 `R` 的函数被置空（不再报 finding），同时 `R` 名下的"行为证据"仍显示通过，全程在本地、无密钥、零痕。

涉及文件（同一仓库、同一 git）：
1. `tools/gate_engine.py` —— 把 `R.check` 置空 / 从 `RULES` 摘条目。
2. `R` 名下的证据载体 —— 若是 pytest：改对应测试让其 pass（或删测试）；若是 poison id：改该毒样例使其不触发 `R`；或直接删 `R` 对证据的引用。
3. `tools/.tool_checksums` —— `python tool_integrity.py --update` **无认证重签** ⇒ 第一锚绿。
4. git 历史 —— `git commit --amend` / `git rebase -i` 把"置空规则 + 重签基准"两笔提交改写合并，再 `git reflog expire --all && git gc --prune=now` 抹掉旧对象。

**留不留痕？** `--update` 本身是一次正常动作，会在 git 留一笔 commit。但单用户本地、无服务器强制、无第三方：rebase/amend + reflog 清理可**合法地**消除这笔痕迹。所以"留痕"在单用户无密钥下**可被合法操作抹掉**——这不是漏洞，是前提。

**两个锚共享同一个可一次性伪造的根吗？** 是。一次 `--update` 重签 checksum，一次改测试/证据重签"行为绿"，两次操作都只需"有写权限 + 会跑命令"，根就是"本地仓库写权限 + 自设 git 身份"。**没有异质根**。

---

## 3. 什么叫"真正异质"的第二锚

对照任务设问，真正异质需满足**至少一条**异质维度（异语言 / 异进程 / 异数据源 / 人持有的带外清单）：
- **异进程**：证据由另一个独立进程产出，且进程本身不被本次改动影响（但本仓 5 个 CORE_TOOLS 都进 checksum，改一个全红——这反而说明它们**同根**，不算异质）。
- **异数据源**：证据来自一个规则函数改不到的地方（例如人持有的脱机清单、另一个仓库、异模型独立重算）。
- **人持带外清单**："规则 R 必须有证据 E"这条约束本身由人离线保管，机器改动仓库无法改到它。

T1 提案的"规则挂 evidence id"**三样都不占**（同仓、同进程、同源 git）→ 与 checksum 同根，不是真异质。

## 4. 外部对标：谁在"单人本地无服务器无密钥"下可降级借用，谁必然退化

| 框架 | 核心机制 | 本仓约束下 | 退化后剩多少 |
|---|---|---|---|
| **Thompson trusting trust [ES1]** | 编译器可自我指涉注入，根不可信 | 完全适用：gate 规则被注入 = 同构攻击 | 无解，除非异质根。**诚实结论**：单用户无密钥下无法彻底防"判定核心被改"，只能 fail-loud + 留痕 + 人工复核 |
| **Wheeler DCC [ES2]** | 用异质编译器双编译比对检测 trusting trust | 需要"异质编译器"这一独立根 | 本仓无第二编译器（只有 g++15.3）→ **必然退化**；仅概念可借用（"双实现比对"思路见 Q2） |
| **in-toto / SLSA [ES3]** | 构建步骤 attestation + 供应链溯源 | 需要构建/签名基础设施 | 单用户离线 → 出处 attestation 无第三方签发方 → **退化**；但"可复算判决"部分覆盖（见 Q6 表） |
| **TUF [ES4]** | 密钥轮换、抗 key compromise | 需要密钥 | 无密钥 → **结构性无意义**；git 历史可部分替代"看谁改了" |
| **Sigstore / Rekor [ES5]** | 透明日志 + keyless 短期证书 | 需要第三方透明日志 | 单用户无第三方 → **真空白** |

**防住谁？（诚实分级）**
- 手滑误删：**N 档已防** —— `enforce()` fail-loud 拒绝运行 + 行为证据红。
- 弱模型苦力无意改坏：**N 档部分防** —— 若误删规则函数，`enforce` 红；若只"弱化"规则逻辑但没动签名，"行为证据"可能仍绿（这正是 T1 想补的，但 T1 同根，补得不彻底）。
- 外部恶意攻击者（有写权限）：**W 档** —— 一次 `--update` + 一次改证据 + 一次 rebase 即双锚同绿、痕迹可抹。无任何密码学/多主体时不可防。

## 5. Q6 · 轻量留痕 vs 正式供应链信任链：环 × 是否需要 × 本仓替代物

| 信任链环节 | in-toto/SLSA/TUF/Sigstore 角色 | 单用户无密钥是否需要 | 本仓替代物（已覆盖？） | 缺口/档 |
|---|---|---|---|---|
| 出处 attestation | 第三方/密钥签发"谁产的" | **否（W：结构无意义）** | 唯一资产 = **可复算判决**（gate/replay 可重跑，g++15.3 56/56 confirm） | 无第三方出处 → 接受"可复算即出处" |
| 构建 reproducibility | 可复现构建 | 已覆盖 | 真编译 Oracle（atom_evidence_replay） | 无 |
| 透明日志 Rekor | 不可篡改签名账本 | **否（W）** | 无（本地无第三方） | 真空白 |
| 密钥轮换 TUF | 抗 key compromise | **否（无密钥）** | 无 | 真空白 |
| 撤销 revocation | 失效旧密钥/证书 | 部分 | git 历史可看谁改了基准 | 弱 |
| 可信时间戳 | 第三方时间锚 | **否（W）** | git commit time（**B 级**，可被 rebase/amend 改，见 Q3） | 可被改 |
| 签名身份认证 | 验"是谁签的" | 否 | `principal_ok` 名册 + git 作者绑定（warn 级） | 自断言（见 Q4） |
| 完整性 checksum | 文件未改 | 已覆盖（**N**） | `tool_integrity` sha256 | `.tool_checksums` 自身不校验（已知缺口） |

**横向结论**：在"单人、本地、离线、无密钥、唯一资产是可复算判决"约束下，**只有"出处/可复算"和"完整性 checksum"两环被本仓以别的方式实质覆盖**；透明日志、密钥轮换、撤销、可信时间戳、签名身份认证这五环**结构性无意义或自断言**，列出来只是诚实标注"我们没假装做"，而不是硬凑。

## 6. 给建设方的最小加固建议（N 档，不引入密码学/服务器）

1. **把"证据绿"做成异数据源**：规则↔证据绑定清单放到**人持有的带外文件**（脱机 / 另一个不进 gate 校验的目录），机器改仓库改不到它；gate 启动时只读校验"每条规则都有带外清单里的证据 id"。这才能真正异质于 checksum。
2. **`.tool_checksums` 自身纳入一条"外壳"校验**：用 git -tracked 的 commit hash 间接约束（谁改基准、哪笔 commit 改的，必须能 `git log` 出来），并把"重签"做成**双人/异会话复核**事件而非单命令。
3. **显式标注不可防边界**：在 `enforce()` 文档与报告里写明"单用户无密钥下，本机制防手滑/弱模型，不防有写权限的蓄意伪造"——把诚实写进产品，而非藏起来。

> 否掉方向也算交付：T1 原提案（证据同仓同 git）**不应作为"信任根收口"落地**，它只是把 PoC-1 的伪造成本从"改一个函数"提高到"改一个函数+改一个测试+跑一次 --update"，而根没变。
