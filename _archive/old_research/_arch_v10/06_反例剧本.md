# 585 · 06 反例剧本（最小伪造链，单用户·无密钥）

> 性质：纯文本推演的攻击剧本，**未在本仓执行任何写盘/提交命令**（严守 585 只读纪律）。每条给出：前提、步骤、为何现有机制挡不住、该补哪道门。N/D/W 见 `00`/`07`。

## A. PoC-1 规则静默置空（已实证，见 `_arch_v7/03`）
- 前提：有 commit 权限；`.tool_checksums` 可 `--update`。
- 步骤：`gate_engine.py` 把某规则 `check` 改 `return []` → `poison_drill`/`gate` 该规则零命中发现，141→64 finding 静默消失；`tool_integrity --update` 重签。
- 为何挡不住：`run()` 对 `[]` 静默 `extend`（`gate_engine.py::run:3542-3547`）；`--update` 无认证（`tool_integrity.py::main:146-150`）。
- 该补：T1 行为证据（规则空了则名下 poison 载荷 `ok=False`）+ **异族只读眼睛翻 diff**。

## B. T1「第二锚」同根齐伪（最小伪造链，对应 `01 §1.3`）
- 前提：同 A，且目标规则在 581 `behavioral_covered` 集合。
- 步骤：① 编辑 `gate_engine.py` 空规则；② （可选）删/改对应 poison 载荷期望；③ `tool_integrity --update` 重签。
- 为何挡不住：T1 的"规则→证据绑定 manifest"与 `.tool_checksums` 是**同一组文件 + 同一次 `--update` + 同一个 git 根**；drill 不是提交门禁，本地不跑。
- 该补：真异质第二锚（见 `01 §1.4`：DDC 第二编译器 / 人持带外清单 / 未来第三方透明日志）。现状只能靠"异族只读 + git 不可抹除留痕"两道人工门。

## C. T3 人签伪造（对应 `04 §4.3`）
- 前提：单人、本地、git `user.name` 自配。
- 步骤：① 直接在 `data/human_sign_events.jsonl` 末追加一条 `{signee:"真人名", git_author:"真人名", ...}`；② `git config user.name 真人名` 后提交；③ 把后续事件的 `prev_hash` 顺手重算一遍，链自洽。
- 为何挡不住：`jsonl` 是普通文件可直改；`git_author` 自申报；本地 hash 链无外部锚点（见 `04 §4.4`）。
- 该补：明确 T3 是**审计痕迹非签名**；真保证来自"异族模型族代行签字 + 第三方时间戳（W）"。

## D. N5 等价放行（对应 `05 §5.3`）
- 前提：N5 落地且 canon 仅规范 frontmatter。
- 步骤：取一条"正文↔frontmatter 对拍"规则命中的卡 V1；造 V2：frontmatter 逐字节同 V1，仅改正文一句，使该对拍规则在 V2 不触发。按 N5 判据 `canon(P1)==canon(P2) ∧ op∉{M1,M7}` → `equivalent=True` → V2 被当等价体放行。
- 为何挡不住：canon 漏掉"非 frontmatter 的第三条读取路径"——这正是 PoC-2（空白符改动骗 gate）的翻版。
- 该补：canon 覆盖全读取路径 + fail-closed 向"不等价" + 金标准 fixture（见 `05 §5.5`）。

## E. git 时间轴改写（对应 `03 §3.2`）
- 前提：本地无远端/带外 head 副本。
- 步骤：`git commit --amend --date="..."`（倒填 author/committer date）；或 `git rebase -i` 重写；再 `git reflog expire --expire=now --all && git gc --prune=now` 抹掉旧 hash。
- 为何挡不住：date 自申报；reflog 可被同一个人清；无外部锚则"改写"本地不可侦测。
- 该补：发布快照时把 `head_hash` 钉到不可变介质；CI 比对 parent chain 连续性；真时间戳等第三方 notary（W）。

## F. 双实现对账共模（对应 `02 §2.3`）
- 前提：N3 落地的"与 `oracle_report()` 对账相等"。
- 步骤：（无需攻击）`oracle_rotation` 与 `oracle_report` 读同一 `oracle_registry.json`、套同一 stale 逻辑 → 两者"对账相等"但**一起错**（共模）。
- 为何挡不住：不是独立第二实现，是同一逻辑的两副本（循环印证）。
- 该补：N3 须走不同数据源/判定口径（如直接解析卡 frontmatter 的 `verified_by_oracle`），并放宽"必须对账相等"的约束。

## 总纲
所有 A–F 的共同根因：**本仓所有锚最终汇到同一 git 根 + 同一个会 `--update` 的人**。单用户无密钥下，机械 Oracle（编译器）+ meta 层（规则/毒样例/人签/台账）的诚实度，只能靠"**fail-closed 校验 + 异族只读眼睛 + git 不可抹除留痕**"三道独立门共同兜底——且后两道是人工/异步的。这正是 `_arch_v7/03` 与 `_arch_v9/08` 的结论，本预审细化并确认其仍成立。
