# 00 · 总览：开工前必须先解决的设计洞（红队预审一页纸）

> 角色：异族只读调研员。本文件是"挑刺清单"，不是背书。每条给 **N 档（现在单人本地就能做）** / **D 档（要攒证据/验证才敢下结论）** / **W 档（该等/该放弃）** + 一句话理由。
> 排序依据：**这条洞会不会让"整套诚实度量"建在可一次性伪造的地基上**。越靠前，越致命。

| # | 问题 | 档 | 一句话理由 |
|---|---|---|---|
| 1 | **Q1 · T1「规则注册表独立第二锚」真的独立吗** | **W（部分放弃）/ N（降级才成立）** | 第二锚与第一锚（checksum）同仓同进程同 git，`--update` 无认证即可同时重签两者 → 共享同一可一次性伪造的根；只有"人持带外清单 / 异进程 / 异数据源"才算真异质。 |
| 2 | **Q5 · N5 canon 等价只覆盖「只读 frontmatter 规则」** | **N（带 scope 词）/ D（验证 classify 覆盖）** | `equivalent=True` 的 scope 声明很窄（"只读 frontmatter 的规则"），但标志一旦被报告/看板误读为"无害"就会静默漏真逃逸；护栏 `selfcheck_equivalent` 的可靠性取决于 `classify` 是否把变体跑过**全规则集**——这是待验证的洞，不是假设。 |
| 3 | **Q4 · T3 人签 git 作者绑定在单用户下只是「自绑」** | **N（冷静期/异步复核）/ W（抗抵赖）** | `git user.name/email` 可任意 `git config` 自设，本地 jsonl 可直接改写，无第三方时间戳 → 防得住手滑/弱模型误签，防不住有写权限的蓄意伪造；真正四眼必须等多主体。 |
| 4 | **Q2 · N1/N2/N3 双实现是同谋不是独立** | **N（降格表述）/ D（找异数据源）** | 三者共享 `propositions.db`/git 时间源/同一字段语义假设 → common-mode（Knight & Leveson 1986 实锤高度相关失败）；N1 只算"同一视图查两遍"，N3 是"对自己对账"，都不构成独立第二实现。 |
| 5 | **Q3 · 582 把「重型时序引擎」和「时序语义」混为一谈** | **N（保留四轴，否掉引擎）** | git 本身就是 append-only Merkle 历史；四轴（断言时间/验证者版本/推翻事件/引用锚）可在单用户本地**低成本从 git 派生**，无需 XTDB/Datomic。该否的是"引入重型引擎"这一实现，不是"四轴时序语义"。 |
| 6 | **Q6 · 供应链信任链多数环在单用户无密钥下结构性无意义** | **W（多数环）/ N（出处/可复算已覆盖）** | 透明日志/密钥轮换/第三方时间戳/签名身份认证在单人离线无密钥下要么真空白、要么自断言；本仓已用"可复算判决（gate/replay 真编译）"覆盖最关键的"出处"语义。 |

---

## 给建设方的核心结论（一句话版）

> **不要假装单人本地能凑出"信任根"。** 诚实的收口上限是：fail-loud 防手滑 + 行为级证据防弱模型误改 + 留痕供人工复核 + 把"可伪造"这件事**显式标注**而不是藏起来。任何声称"这样就安全了"的断言，只要它依赖"攻击者不会改 git 历史 / 不会重签基准 / 不会改本地 jsonl"，就是在单人无密钥前提下**自欺**。真正独立的信任根（异质根、第三方、多主体）必须等——这就是 W 档存在的意义。
