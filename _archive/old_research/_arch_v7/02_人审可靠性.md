# 564-02 · 人审可靠性：人这个最终根怎么失效、怎么让它无法走过场

> 检索日期 2026-09-17/18。解剖基于本仓真实代码；外部数字带来源。

## B0 本仓逐环节失效点（今天结构上哪里允许 rubber-stamp）

### B0.1 `principal_ok` 人签 = 纯文本自证，无身份证明【已实现，PoC 已实证】
[gate_engine.py:128-144](file:///C:/CodeLearnling/note/note/C++/CPP-Bible/tools/gate_engine.py#L128-L144)：只验三件事——前缀 `human:`、名字非空、名字在 `HUMAN_PRINCIPALS=("liaoranran",)` 名册。
探针实测（2026-09-17）：
```
键入 human:liaoranran → principal_ok = True（无任何身份证明/密钥/二次确认）
键入 human:随便谁     → False（名册外被拦——拦的是名字拼写，不是身份）
```
⇒ 任何有文件写权限的主体（偷懒的 Writer、被注入的 agent、攻击者）直接键入在册人名即获得合法人签；gate 能区分"字符串对不对"，不能区分"是不是这个人签的"。**这不是假设漏洞，是设计边界**：单用户本地仓库没有密码学身份层；但必须诚实承认它——inference 级的人签强度目前等于"工作树写权限"。

### B0.2 136 条 warn 的人审：结构上允许闭眼清零
- warn 不阻断（设计正确），但**没有任何机制确认人"看过且判断过"**：warn 清单可以无限累积（当前 136，最大头 ATOM-CLAIM-CONCEPT-NORMALIZED 77 条），清债动作是"改文件让命中消失"或 `golden_lock --accept --classify ...`。
- 人可以在不读 Finding 正文的情况下批量 accept；`--classify` 要求逐条给 real/false_positive/legacy/accepted 四桶（530 T5 的改进，消灭了整体 accept），但**不要求给判别理由与证据锚点，也不复核分类正确性**——分类本身是人写的字符串。

### B0.3 `golden_lock --accept` 单签
[golden_lock.py:27-39](file:///C:/CodeLearnling/note/note/C++/CPP-Bible/tools/golden_lock.py#L27-L39)：必须带理由+逐规则分类（已优于"整体 accept"），但全程单人、无第二复核、无抽检回查；审计字段落快照，事后可追"谁在何时接受了什么"，但不能追"接受得对不对"。

### B0.4 inference 命题（29/79）全靠人签
50 条 observation 有机验；29 条 inference 的全部强度=一个会疲劳的单用户文本签名，且该签名按 B0.1 不可与 writer 区分。**这是全系统信任根最薄处**。

## 外部实证：人在什么情况下闭眼签（2025-26 数字）

- 【事实】**受过 20 小时 AI 素养训练的医生、自愿咨询、有完全自主权**的条件下，错误 LLM 建议仍使诊断准确率 84.9%→73.3%（−14.0pp，95%CI −18.9~−9.1，p<.0001），首选诊断 90.5%→76.1%（−18.3pp）（NEJM AI RCT，44 医生 264 例，2026-04-23，[DOI 10.1056/AIoa2501001](https://ai.nejm.org/doi/full/10.1056/AIoa2501001?query=featured_home)）。⇒ **培训和自愿都不能消除 automation bias**。
- 【事实】CDSS 系统综述："负向咨询率"（本来对的判断被错误建议改错）7–11%；病理专家网页实验 7% 的正确评估被错误 AI 建议推翻（[综述汇编 2025-08](https://gemini.google.com/share/65927edd0f4f)；[censinet 2026-07](https://www.censinet.com/perspectives/patient-safety-imperative-age-of-ai)引同一批研究）。
- 【事实】医生编辑 LLM 草稿时的原话机制："不是完全错的我就不改了"（"skipped correcting if they were not completely wrong"）——部分正确即放行（[arXiv:2511.19940, 2025-11](https://arxiv.org/html/2511.19940v1)）。
- 【事实】裁判/审阅场景：LLM 裁判一致率仅 51.5–69.1%、问题顺序使一致率波动达 25pp（563 组4 已引 govllm）——**人对 LLM 输出排序同样有顺序偏差**。
- 【类比】对本仓的映射不是"医生=监工"，而是同一条认知机制：**当机器/模型先给出一份流畅、大体正确的产物，人的复核会退化成"找显眼错误"而非"独立重算"**。136 warn 复核、inference 签署、golden accept 三个环节都暴露在该机制下。

## B1 ≥3 条现在就能加的"无法走过场"护栏（每条带机器判据）

### 护栏 1：人审队列埋活雷（canary-in-review），命中率是"审没审"的直接度量
- 做法：每批人审队列中由**异族只读会话**（trae）随机注入 k 条"已知必须驳回"的 Finding/卡（来自 poison 库改写、与真条目混排、人不知情哪条是雷）；人若放行活雷，该批复核作废重审。
- 机器判据：队列生成器输出含 `canary_id` 隐藏标记（只存在于生成器快照，不在人可见正文）；accept 动作必须对每个 canary 给出 reject，否则 accept 命令 exit 非 0。
- 错误率度量：用 563 二项框架——n 次埋雷中漏签 k 次，给"人审漏报率"C-P 上界；首批 k≥10（0 漏 → 上界≈25.9%，要承认单用户小样本上界很宽）；连续 30 次 0 漏 → 上界 9.5%；59 次 0 漏 → ≤5%@95%。
- 存量误伤检查：canary 是注入临时副本，不改 56 卡/136 warn 实体，零误伤。

### 护栏 2：签前必填"卡绑定判别项"（forced discriminative entry，禁止点确认）
- 做法：accept inference / 分类 warn 时，命令行强制回答一个**只有真读了该卡才能答对**的判别题，题目由卡内容机械生成且每卡不同：例如给出两个相邻符号/读数，问哪个是本卡断言目标；给出阴面翻转值，问删关键行会变几（533 iso_judge 已有这些数据）。
- 机器判据：题目答案从卡 frontmatter 的 anchor/remove/retain/artifact_assert 机械派生；答错即拒签；同一人同一卡重试必须换题（防背题）。
- 外部依据：VeriSpecGen 的需求级可追溯映射（563 组6）与医疗编辑研究中"只有强分歧才改"的失效模式——强制交互把"浏览"变成"计算"。
- 存量：只作用于 accept 新动作，不溯及既有人签（零误伤）。

### 护栏 3：强制对拍视图（redacted-diff review）
- 做法：人审界面/脚本对每条 inference 同时展示两个版本：原版 vs 把关键结论替换成"貌似合理的对立结论"的版本（异族生成、机械标注哪个是 A/B），人必须指出哪版与证据锚点一致才能签。
- 机器判据：记录人选择；选错→拒签+该条升级"需第二独立会话复核"；选择日志入 data/review_audit.jsonl。
- 依据：automation bias 在"对照呈现"下显著弱于"顺读呈现"（NEJM 研究里错误建议与正确资源并置仍被采纳，说明仅并置不够——故要求**主动指认**而非被动阅读）。

### （附加，便宜）护栏 4：人审自身抽检 + 563 上界
异族只读会话每季度从历史 human-verified 中随机抽 5–10 条重审（无替代权，只报分歧）；分歧 k/n 进 metrics；这条与 563-D6 golden 双签合并实现。

## 人审错误率怎么测（可操作方案）

| 方法 | 度量什么 | 公式/判据 | 局限 |
|---|---|---|---|
| 盲埋雷（护栏1） | 漏报率（该拒没拒） | k 漏/n 雷 → C-P 上界 | 雷与真条目分布难完全一致；雷会被熟悉后识破，需异族轮换造雷 |
| 复核一致性（护栏4） | 人与时隔己身/异族的一致率 | 分歧率 + Cohen's κ（与异族对同一批独立判） | κ 需要双方都有判断力；异族也会错 |
| 判别项错误率（护栏2） | "有没有真读"的过程指标 | 答错率，作为拒签触发不上报为内容错误率 | 证明读了不证明判得对，但能消灭纯 rubber-stamp |
| 事后翻转率 | 长期真值代理 | 562 overturned_by_stronger_verifier 事件 / 人签总数，随时间累积 | 滞后；很多错误可能永不被更强者碰到 |

## 单用户阶段的极限（诚实声明）

1. **无法排除自欺**：埋雷者=排雷者时 canary 失效；必须坚持雷由**异族只读会话**造（本会话即该角色），但异族生成质量本身有上界，且单用户仍可查看生成器快照作弊——护栏 1 防的是"无意闭眼"，不防"有意共谋"。
2. **上界天然宽**：单用户年人签量估计几十到几百条，563 框架下永远给不出窄上界（要 ≤5% 需 59 个独立埋雷且 0 漏，且事件要独立——同人同模式相关性强）。
3. **身份不可密码学化**：B0.1 的文本自签在引入第二主体之前无解；sigstore/rekor 在 561/562 已判"无多主体=纯负担"。
4. 因此 inference 级信任的正确表述不是"人签所以对"，而是：**"经过强制交互的人签 + 可事后翻转 + 漏报率有（宽）上界监控"**——它是有管理的残余风险，不是可信根。
