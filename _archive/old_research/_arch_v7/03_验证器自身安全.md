## C1 最小加固（分档）

### 现在能做（纯机械、存量零误伤、弱模型可执行）
1. **规则供给链双钥分离**（治 PoC-1A）：新增规则/修改规则 check 的 commit 与规则生效分离——规则注册表加 `sealed_at` 批次字段；新规则默认 `staging`（只 warn 不 block），满 1 个红队轮次且有异族只读批次确认"该规则确实在抓声称的东西"才升 registered。机器判据：gate 注册时过滤 staging 规则的 block 权；红队确认记录文件存在（无需密码学，git 留痕即可）。
2. **gate 自启动完整性前置**（治 PoC-1B 的触发缺口）：`gate_engine.main()` 开头对 5 个核心工具做一次 sha 校验（直接 import tool_integrity 的比对函数，不依赖外部命令编排）；不一致 → **fail-closed 拒绝运行**（不给"可能正确"的结果）。注意基准文件自身被改的情形仍需 git 兜底——在输出里打印"基准 git blob sha 与 HEAD 是否一致"，把重签动作强制暴露在 git diff 审查里。
3. **覆盖率载荷绑定**（治 PoC-2A）：covered 的判定从"源码文本出现 ID"改为"存在至少一个 poison 载荷，其期望 finding 含该规则 ID 且实跑确实产生该 finding"——即规则 ID 必须与 `who` 断言+实跑结果三方一致，纯注释/字符串不计。
4. **豁免台账二人锁**（治 PoC-2B）：豁免条目除 id/reason/date 外必须带 `redteam_seen: <异族会话标识+日期>`；单用户阶段异族只读会话名固定可识别；缺失 → 豁免无效（fail-closed 回退为欠账红）。台账改动必须出现在红队批次的 worklog 清单里（机器交叉检查 worklog 引用）。
5. **人签伪造可见化**（治 PoC-3，单用户阶段能做的极限）：gate 对所有 `human:*` 署名记录生成 `data/human_sign_events.jsonl`（文件:行:值:首次出现 commit）；新增人签出现在**没有对应 accept 命令记录**的文件中 → warn（"人签无审批留痕"）。不能防伪造，但让伪造必须同时伪造两处且留 diff。

### 等 L3/等多主体
- 规则/毒样例的**异族交叉**制度化（红队池必须不同模型族，563-03 三权表）；
- prompt injection 防护：结构化字段通道、指令外提、卡/引文内容禁含可执行指令（L3 上线前置条件）；
- 签名密码学化（sigstore/个人密钥）——触发条件见 05；
- 规则包供应链校验（in-toto/SLSA，561 已调研）——外部规则源出现时。

## 诚实结论
当前信任根的真实形状：**机械 Oracle（编译器）强，meta 层（规则/毒样例/人签/台账）全部是"文本自证 + git 留痕 + 单人"**。PoC-1/2/3 证明 meta 层没有任何自我证明能力——它的安全靠"改东西会在 git 里留下可见 diff 且有异族只读轮次翻 diff"。这与 562 的总判断一致：没有终极底座；加固方向不是"让根不可改"（做不到，--update 永远需要），而是**让任何对根的修改都必须同时穿过：fail-closed 校验、异族只读眼睛、git 不可抹除留痕**三道独立门。
