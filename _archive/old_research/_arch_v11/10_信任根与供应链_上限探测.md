## 二、模型上限态（真实判断）

1. **递归哈希/Merkle 锚——模型能设计，且比"无解"更进一步**：
   tool_integrity docstring 称签它自己递归无解——判断成立但**口径可换**：
   不要求 .tool_checksums 自洽，而把**它的内容哈希写进一个 git 跟踪的独立锚**
   （如 build 外的 committed meta 文件）。该锚自身仍靠 git 兜底，链条为：
   CORE 工具 → .tool_checksums → meta 锚 → git。攻击者需同时改三处并制造
   一致历史。不是密码学根，但把一次性 --update 自签（585 Q1）从"零额外
   痕迹"变成"多点联动"。工程 1 批。
2. **--update 认证——单用户无密钥下模型有两个真实可做的方案**：
   - ① 带外 code：--update 要求输入一个只存在于人侧（不入库）的 secret；
     secret 校验在本机进行——本质是"人必须在场按键"，防的是自动化脚本/
     被注入进程静默重签。不防持有者本人（当然不防，自己就是根）。
   - ② 顺序契约：--update 只在功能 commit 之后允许（当前 docstring 已写
     顺序纪律，但无机器强制），可加"基准与 HEAD 工作树状态一致性校验"。
   ⇒ 模型内能把 update 从"无认证命令"抬到"必须人在场+顺序可核"；做不到
     密码学身份认证（无 PKI）。
3. **git GPG 签名——技术可行但单用户下信任增益有限**：
   签名 commit 需要密钥（可本机生成），增益 = 区分"持 repo 内容者"与
   "持密钥者"——若攻击者拿到的是工作区而非密钥，签名有防伪装意义；但
   密钥和仓库在同一台机器，对本机入侵无增益。撤销/轮换链条不存在。
   ⇒ 可做，ROI 取决于威胁模型；模型能给配置规格，但不改变"根仍是自己"。
4. **可信时间戳——本轮对 585 Q6 结论的直接修正（附证据）**：
   585【一方称】"可信时间戳结构性无意义"。本轮检索【已查证一手项目】：
   **OpenTimestamps**（opentimestamps.org，检索 2026-09-19）：
   - 无需注册/密钥/API key，calendar server 免费（官网原文："free to use…
     don't require any registration or api key"）；
   - `ots stamp <file>` 把哈希经 Bitcoin 链锚定，`ots verify` 仅凭区块头
     独立验证；证明目标：字节存在不晚于某链上时刻；
   - IETF SCITT 草案 draft-fassbender-scitt-time-anchor-02（2026-05-28，
     【检索】）已将该机制标准化描述为"无第三方依赖、服务停运证明仍有效"。

   ⇒ 结论修正：**单用户下"公开链时间锚"是模型内可接入的、非自断言的
     外部时间证据**。585 的"结构性无意义"对"身份型时间戳（RFC3161 TSA）"
     成立（要信任 TSA 密钥），对"链锚时间戳"不成立。系统当前 0 接入
     纯属未做，不是结构不能。能解决的具体问题：基线/判决快照的"先于
     某时刻存在"——可钉死"事后补造基线"的时间窗口。
5. **透明日志（Rekor/sigstore 风格）——同样可修正**：
   sigstore 无需管理密钥（keyless，OIDC+Fulcio+Rekor【一方称厂商文档，
   本轮未读 sigstore 正文，降级标注】）。把基线哈希提交公开 Rekor 日志，
   得到"全世界可查的 inclusion proof + append-only"——防持有者自己
   悄悄换基线而不留**公开**痕迹。与 OTS 区别：OTS 证明时间，Rekor 证明
   公开纳入。单用户下二者都**有**意义，585 Q6 的"无意义"结论过宽。
6. **真正的结构性天花板（我同意 585 的部分）**：多主体、撤销基础设施、
   密钥托管、机构背书——单用户结构不存在；模型内近似（公开链/异族）只
   补"可公开验证性"，补不了"第二利益方"。

## 四、卡点与解冻信号

1. **递归根——理论边界：不存在自洽的单文件自证根**。信号：链条终点
   永远是外部根（git/公开链），这是数学结构不是工程债。
2. **--update 人在场——工程**。信号：secret 机制落地（secret 不入库）。
3. **链锚——工程，且需一次外部检索判断（链确认延迟/费用）**。信号：
   基线快照 stamp→verify 流程跑通并写入可复核证明文件（证明文件本身
   可放 _arch 或 data，政策决定）。
4. **多主体——结构不可解**。无信号；公开链替代的是"公开可验"，不替代
   分权。

## 五、本维度自由探索

1. **信任根分层应显式化（当前文档散落）**：建议（边界判断）把信任主张
   分成三类各自标根：① 判决正确性 ← 机械 Oracle；② 时间存在性 ← 公开
   链锚（未建）；③ 身份 ← 人（无替代）。当前所有信任主张笼统挂 git，
   git 同时被三类共用，单点性没有显形。
2. **依赖解释器自身（.venv/PyYAML 包）是未编号的供应链面**：585 Q6 覆盖
   概念但无清单——恶意 yaml 包可直接改解析结果。最小机制：冻结/记录
   site-packages 哈希（与 tool_integrity 同范式），纯工程。
