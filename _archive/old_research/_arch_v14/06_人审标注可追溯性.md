# 06 · 人审标注可追溯性

## 6.1 标注元数据 schema（提案）

每条人审记录（`data/human_annotations.jsonl`，每行一条 JSON）：
```json
{
  "edge_id": "MIS-CONC-003->PROP-CONC-RACE-001",
  "mis": "MIS-CONC-003", "prop": "PROP-CONC-RACE-001", "card": "ATOM-CONC-RACE-001",
  "decision": "confirm|reject|modify",
  "target_props": ["PROP-CONC-RACE-001"],   // modify 时指定
  "strength": 0.9,                            // 人审调整后的权重
  "reviewer": "git_author", "ts": "ISO8601",
  "reason_tags": ["target_ambiguous"], "reason_text": "...",
  "confidence": 4, "review_seconds": 28, "agree_with_machine": true,
  "generator_version": "594-v1"
}
```

## 6.2 与"机器可核验"第一性对接

- **机器复核人审**：用 W2 预测对比人审 decision，不一致触发复核（维度 2/3）。
- **理由机器解析**：结构化 `reason_tags` 可被机器聚合（如"target_ambiguous"高频 → 生成器需改进目标映射）；自由文本仅供人读。
- **历史审计**：谁/何时/改了什么判断全留痕；改判时旧记录保留（append-only），不覆盖。

## 6.3 版本控制：人审改判如何处理？

- **不覆盖**：append 新记录，旧记录留作审计。grounded 重算用最新有效记录。
- **触发重算**：确认/拒绝/修改任一条边 → 重跑 W2 → IN/OUT/UNDEC 分布变化（维度 9 反馈闭环）。
- **零误伤联动**：若人审确认一条边导致某已 confirmed 命题转 OUT，触发 golden_lock 复核（维度 10 集成）。

## 6.4 与本仓现有工具集成

- **overturned_events.jsonl**（573 设计）：人审"拒绝/改判"可视为一种 overturn 事件，写入此流（维度 10）。
- **governance_doc_guard.py**：人审标注的治理文档（如 annotation schema 本身）若变更需防护。
- **golden_lock.py**：人审 accept 动作可复用其锁机制，防并发/回滚。

## 6.5 外部实证【一方称：待核验】

- W3C PROV（数据溯源标准）：本 schema 的 `reviewer/ts/decision/reason` 即 PROV 的 agent-activity-entity 三元组简化版。
- 标注版本控制行业实践：append-only + 快照，与本提案一致。

## 6.6 本仓落地评估

- append-only jsonl 是零依赖、可 git 跟踪、可机器解析的最佳载体；比写卡面/写 propositions.db 更解耦（卡面只存结论，过程存 jsonl）。
- 验收：每条人审记录含 6 必备字段（edge_id/decision/reviewer/ts/reason/confidence）方可入库。
