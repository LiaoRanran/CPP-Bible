# 07 · 单用户独立性与多模型辅助

## 7.1 问题：单用户独立性天然弱

- 590 引【一方称】arXiv:2605.29800："9 异族判官 ≈ 2 有效独立票"——多人尚有损耗，单用户（自己生成+自己确认）≈ 0 独立性。
- 风险：自确认偏差、锚定（先看到自己生成的候选边，倾向于确认）。

## 7.2 替代/补充：本仓多异族模型

本仓已有多个异族模型：**Seed-Evolving / DS v4.1-flash / glm-4-flash**（brief 列出）。能否用"多模型预测一致性"作为人审替代或补充？

- **若 3 模型对某攻击边判断一致 → 自动确认？** 理论上可（ensemble 提升可靠性）。
- **若不一致 → 触发人审？** 是，把分歧留给人工。

## 7.3 common-mode failure（双实现同谋）风险【585 指出】

- 多模型一致**也可能全错**：若三模型共享训练数据/偏见，会"同谋"给出相同错误答案。
- 585 在双实现场景指出"双实现同谋"——多模型一致≠正确。故**多模型一致只能降低、不能消除人审必要性**。
- 本仓特别风险：Seed-Evolving 与 DS/glm 可能共享本仓卡语料做上下文，导致"同源偏见"。

## 7.4 本探针未跑模型（诚实声明）

- 本次**未调用任何异族 API**（只读/无网络）。多模型一致性的"自动确认"是**设计提案**，非实测。
- 若未来实测，验收指标应是"多模型一致组的零误伤率"，而非"一致率"。

## 7.5 单用户阶段质量方案（综合）

1. **自一致性**：同人隔时复标，一致性阈值触发复核。
2. **延迟复核**：标注后过段时间再看。
3. **机器辅助复核**：W2 预测 vs 人审，不一致触发复核（不依赖外部模型，可立即做）。
4. **多模型辅助（W 段）**：异族 API 集成后，三模型一致性作为"预确认"信号，但保留人审最终否决权 + common-mode 警惕。

## 7.6 本仓落地评估

- 当前（单用户 + 无 API）最务实的是 **W2 机器辅助复核**（维度 2/3/6），多模型辅助留 W 段。
- 即便上多模型，也必须保留"人审最终否决 + 陷阱题质检"，因 common-mode failure 无解于纯集成。
