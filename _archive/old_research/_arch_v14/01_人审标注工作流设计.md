# 01 · 人审标注工作流设计

## 1.1 完整流程（本仓定制）

```
自动生成候选边 (594: MIS related_atoms → 194 条)
   │
   ▼
按 MIS 群组聚合 (本探针: 42 组)
   │
   ▼
展示每组的: 误解 trigger_patterns + refutations 文本 + 关联卡的主张 + 候选目标命题列表 + W2 预测
   │
   ▼
人审判断 (三选项):
   确认 (攻击成立, 目标=全部候选命题)
   拒绝 (攻击不成立)
   修改 (成立, 但目标命题需调整 / 强度需改)
   │
   ▼
必填"理由"字段 (结构化标签 + 可选自由文本, 引用证据)
   │
   ▼
落库 (data/human_annotations.jsonl, 见维度 6) → 触发 W2 重算
```

## 1.2 194 条边如何分批/排序（本探针实证）

- **不要边级分批**：194 条边级判断 = 1.89h（本探针实测）。
- **按 MIS 群组聚合**：42 组，每组一次"目标映射"判断 = 24.5min（本探针实测）。
- **排序**：高可信度组（命题 cred≥0.8，占 191/194）优先批量确认；歧义度高组（多命题卡 / 多 MIS 同卡）优先精细审。主动学习式：歧义度降序，每条信息量最大。
- **每批大小**：建议 7 组/批（≈4min/批），批间强制休息防疲劳（维度 13 疲劳曲线）。

## 1.3 人审三选项 + 理由字段

- 确认/拒绝/修改三选项；"修改"必须指定目标命题子集与强度。
- 理由字段：**结构化标签为主**（如 `target_ambiguous` / `evidence_insufficient` / `direction_wrong` / `strength_overstated`），自由文本为辅。**必填**——理由质量是 automation bias 的检测信号（维度 3）。
