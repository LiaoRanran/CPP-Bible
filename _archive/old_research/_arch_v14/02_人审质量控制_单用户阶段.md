# 02 · 人审质量控制（单用户阶段）

## 2.1 质量控制方法谱系

| 方法 | 多人可行？ | 单用户替代 |
|---|---|---|
| 双盲标注 + 第三人裁决 | ❌ | 不可行（仅一人） |
| Cohen's kappa / Krippendorff's α | ❌（需≥2标注者） | 自一致性（同人隔时复标） |
| 抽检 | ✅ | ✅ 随机抽 10% 复核 |
| 金标准陷阱题 | ✅ | ✅ 插入已知答案题 |
| 标注者资格测试 | ✅ | 首轮校准（先标 5 组练手） |

## 2.2 单用户阶段的替代方案（本仓）

1. **自一致性**：同一批边隔 1–2 天复标，一致性 < 阈值触发全批复审。
2. **延迟复核**：标注后过段时间再看，避免首因效应。
3. **机器辅助复核**：W2 模型预测 vs 人审判断，不一致即标记（本探针 detect_signals 已实现逻辑）。
4. **理由质量评估**：理由为空/过短（<10 字）自动打回。

## 2.3 陷阱题设计（automation bias 防护的交叉）

- 在 42 组队列中混入若干"已知答案"组：例如一条明显成立的攻击（应确认）、一条明显不成立的（应拒绝）。
- 若人审对陷阱题判断错误，说明处于 rubber-stamp 状态，整批重审。
- 本探针模拟：rubber-stamp 对 10 个陷阱题 **0 捕获**，careful **10/10 捕获** → 陷阱题是单用户下最廉价的质检手段。

## 2.4 外部实证【一方称：待核验】

- NEJM AI 2026 RCT：受训医生遇错误 LLM 建议准确率 −14pp（automation bias 实证）。
- 标注质控行业标准（IAA / Cohen's kappa）定义在多人场景，单用户需转译为自一致性。

## 2.5 本仓落地评估

- 单用户阶段**唯一可机器执行的质检**是：自一致性 + 机器辅助复核（W2 对比）+ 理由质量 + 陷阱题。
- 工作量：42 组中插 3–5 个陷阱题（~2min），自一致性复标抽 5 组（~2min），总质控开销 < 10% 人审时间，可接受。
- 多用户（未来）再上双盲/kappa；当前架构需预留"标注者"字段以支持。
