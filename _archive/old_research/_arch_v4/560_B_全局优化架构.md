# 560-B · 全局优化架构设计（苦力可照做规格）

> 每层给：现状（文件:行锚）→ 目标 → 过渡方案 → 机器验收。铁律：**凡"必须真跑外部 Oracle 才信"的编译/运行，只允许隔离并行/减少重复，不允许用缓存结果替代判决**。所有优化默认 OFF/warn，存量零误伤，一批一 commit。

## B0. 优化分层与依赖顺序

```
B3 测试选择（日常收益最大、零 Oracle 风险）  ── 先做
B4 gate 索引化（小、独立）
B1 编译层：P0-A 降面 + 命令合并（动安全核心，需毒样例回归）
B2 replay/golden 并行隔离 + 结果复用（收益最大但风险最高，独立批）
B5 L2 依赖感知并行调度（吃 B2 的隔离原语，门控归人）
```

## B1. 编译层：P0-A 的 53.7s 怎么减，而不破坏重编译不变量

**现状**：每卡命令组正常产 asm/exe（run_commands 71.6s），随后 `_recompile_invariant`（[atom_evidence_replay.py:1345](file:///C:/CodeLearnling/note/note/C++/CPP-Bible/tools/atom_evidence_replay.py#L1345)）在 tempdir 用 `CCACHE_DISABLE=1` **把 artifact 编译行再独立编一遍**比 sha——470 P0-A 立此规矩是因为"后置段/helper 脚本可在正常编译后覆写工件，命中 ccache 会把两次编译变成恒真"。本轮实测它占全量 42.3%。

**禁止的"优化"**：给 P0-A 开 ccache（直接把不变量变恒真，否决）；用第一次编译产物代替独立重编（E01 原攻击：后置覆写正是打这个）。

**可做（按安全度排序）**：

1. **P0-A 只重编"被 sha 锚定的 artifact 行"，不重编整卡所有编译行。** 现状已用 `_artifact_compile_lines`（:1080）提取，实测 53.7s 说明大部分卡 artifact 行是重 TU 全量编译——这部分无可减。**可减的是 exe 行**：P0-A 的任务是证"磁盘 artifact 字节来自本次真编译"。对 `-S` 产 asm 的卡，asm artifact 行独立重编是必须；但同卡随后的"产 exe + 运行"不是 sha 锚定对象，当前不参与 P0-A（正确）。核查点：确保阴面/v-iso 新增的编译不被误纳入重复面。
   - 验收：56 卡 confirm 数不变；E01 毒样例（helper 后置覆写）仍 refute:artifact_tampered；P0-A 总耗时有下降即记录，无下降不硬凑。
2. **命令合并减少 CreateProcess（6.4s/319 次）**：同卡的 `-S` 与 exe 编译**不能合并**（不同输出/flags，且卡命令是契约）；可合并的是每卡重复的环境探测——`_compiler_id`/`_current_toolchain_id`（:518/:540，0.63s 且每卡重复 shell）在**单次 replay 进程生命周期内缓存**（functools.lru_cache 键=resolve_gpp 路径+mtime）。跨进程不缓存（工具链可能被换）。
   - 验收：56 卡 confirm 不变；故意换 PATH 中 g++ 后新进程仍能识别（新进程不继承缓存）。
3. **ccache 只允许服务"非判决编译"**：阴面探针、mutation 变体、worker 本地预演可以用 ccache；卡的主编译与 P0-A 保持现状。投喂词中"ccache 实测仅 1.22×"的根因有二：①P0-A 显式 disable；②本仓编译时间在 cc1plus 前端且头文件重，ccache 命中也要预处理一遍。**结论：不指望 ccache 提速门禁，只用于异步探索任务。**
4. **-O 分级：实测否决**（A §3：-O0/O1/O2 大 TU 差 <5%）。PCH/并行 make：夹具是单 TU 独立调用，无共同预编译头收益；引入 ninja 是造轮子（ledger §3 同口径冻结）。

**预期收益**：现实可拿 5–8s（环境探测 0.6s + 命令开销一部分）；53.7s 的 P0-A 主体是安全成本，明说**不压**。回退：全部为局部函数级改动，逐项可独立 revert。

## B2. replay/golden 层：卡间确定性并行 + 结果复用（最大收益，独立批）

**为什么 508/xdist 失败而本方案确定**：历史失败根因不是"并行"本身，是①共享 `build/.replay_lock` 进程锁；②共享 `build/` 瞬时产物（`_replay_*.exe`、同名中间文件）；③共享 Examples/atoms 工件的快照-还原（[_snapshot_artifact/_restore_artifact](file:///C:/CodeLearnling/note/note/C++/CPP-Bible/tools/atom_evidence_replay.py#L996-L1027)）；④poison 真编译与 replay 并发争同一批文件。xdist 是"把不隔离的测试撒出去"，当然假红。

**隔离原语（给苦力的确定方案，不是"加并行参数"）**：

1. **每 worker 独立工作根**：`build/workers/<wid>/{tmp,art_snapshots,asan}/`。Popen 的 cwd 与所有 `-o` 目标都在该目录下；环境变量（TMP/TEMP/ASAN_TMP）同样指过去（sanitizer 也有临时文件）。
2. **锁粒度从全局降到"卡工件"**：删除对全局 `build/.replay_lock` 的依赖；快照-还原只锁**本卡 artifact 路径**（锁文件 = `build/locks/<sha256(artifact_rel)>.lock`）。不同卡触不同 .asm/.out，天然不相交；同卡并发（同卡被两个任务选到）由 B5 调度层 touch/deps 保证不发生，锁是第二道防线。
3. **卡输入不可变前提**：并行期间工作树冻结——worker 池启动前记录 git index + 所有 fixture/artifact mtime 哈希，任一 worker 完成后若发现输入集变化，整批结果标记 invalid 重跑（防止"边验边改"，对应 559 touch 锁思想）。
4. **poison 与 replay 不混池**：poison 沙箱在 tempdir 自造卡（poison_drill 的 sandbox()），本就不该与正式工件同池；并行调度器把 poison 作为独立资源池（不同 worker 标签），或直接排在 replay 池之外。已知"poison 真编译与 replay 并发偶发假红"据此消除，而非靠重试。
5. **worker 数 = min(物理核-1, 重卡数)**，默认 4，必须可 `--jobs 1` 回退到当前完全串行路径（528 实测 -n auto 不稳的教训：不自适应当前核数之外的东西，不做负载猜测）。

**golden 不再重放**：golden_lock 的 `_status`（[golden_lock.py:166-195](file:///C:/CodeLearnling/note/note/C++/CPP-Bible/tools/golden_lock.py#L166-L195)）逐卡 in-process replay 是 131s 重复劳动。改为消费**本次/最近一次并行 replay 的结果清单**（每卡 verdict+verify 证据哈希，落 `build/replay_resultset.json`），清单指纹与当前工作树不符则整体失效回退串行（fail-closed，不吃陈旧绿灯）。slow 的 test_golden_lock_json 从"125s 重放"变成"读清单+抽验 3 卡真跑"。

**不可变工件目录（过渡态可选）**：把"删→重生成→比 sha→还原"（snapshot/restore 三件套）逐步替换为 content-addressed 只读目录 `build/artifacts/<sha256(源+命令)>/`（思想见 C2 Bazel CAS，但**只存本机判决产物、不作为信任源**）；卡锚定的 Examples/atoms/*.asm 仍是唯一 sha 真源，CA 目录只省去重复 I/O 与还原逻辑。该条【攒数据】，先做 1-4。

**预期收益【实测/推断分明】**：4 路并行下 127s→约 35–45s【推断，需落地实测，喂料门=加速比 ≥2.5× 且 56/56 verdict 逐卡与串行一致】；golden 131s→<5s（读清单）+抽验 ~8s。nightly 重放类工作 258s→~50s。
**回退**：`--jobs 1` 路径与今天逐字节等价；并行是新增代码路径，旧函数不删直到一个季度无回退事件。

## B3. 测试层：受影响测试选择 + 三层套（日常收益最大、零 Oracle 风险）

**现状**：fast 98s、全量 589s；slow 两例各自 replay 全量；548 已踩"diff 不许按卡裁剪"（跨卡规则会让"只跑改动卡"漏判）。

**选择规则（机械、可解释，不做 ML 排序）**：
1. 白名单（**任何** PR 都跑，~15s 封顶）：全部 gate 规则的纯 Python 单测、poison、replay 解析/分流单测、锁与增量 manifest 单测。
2. 按**变更面**选择：
   - 改 `tools/atom_evidence_replay.py|gate_engine.py|golden_lock.py|task_queue.py` → 全量（工具变，所有判决信任失效）；
   - 改 fixture `X.cpp` 或卡 `EV-X` → impact 闭包（impact_analysis 已有多跳传递闭包，558 Part C）选卡，**但始终外加"全卡 gate 扫描"**（gate 规则跨卡，548 教训）；
   - 只改 Book/正文 → doc_lint + frontmatter，不跑编译；
   - 改 tests/ → 仅该文件 + 白名单。
3. **安全兜底**：选择结果与"全量结果"每周比对一次（canary），出现一次"选择集绿/全量红"即当周回退全量并修选择规则；这是 Microsoft TIA 的 safe-fallback 同款设计（C1）。
4. pyproject `--basetemp=.pytest_tmp --tmp-path-retention=failed`（ledger 已定位的 safe-delete 卡顿）。

**三层套**：冒烟（白名单，每 commit，<20s）/ 增量（选择集，PR 合并前，目标 <30s）/ 全量（nightly，B2 并行后 <60s 门禁+异步 mutation）。不搞第四层。

**验收**：连续 2 周选择集与全量判决零分歧后才允许它进入 PR 必跑；分歧率永久进 metrics。

## B4. gate 层：索引化与缓存失效键

**现状**：子进程 3.4s（进程内缓存命中后 <0.5s）；61 规则多次全库扫描卡片。
- frontmatter 解析缓存（548 已做）补**失效键**：缓存键 = 文件路径+sha256(内容)，而不是 mtime（mtime 可被 checkout 改回）。
- 全库扫描收敛为一次遍历产出多份索引（id 索引、claimed_by/evidence 引用索引、relations 邻接表），规则查索引而非各 rglob；499 的 rglob 全文读取以"规则注册表声明需要的字段"白名单约束。
- 预期：子进程墙钟 3.4s→1.5–2s（解释器冷启动占大头，Python 侧已 <0.5s 不再有大肉）；规则数翻倍后扫描不线性膨胀。验收：141 命中逐字不变。

## B5. 调度层：task_queue 长出依赖感知并行（G-supervisor 仍 OFF）

**现状**：task_queue 已有可续跑/handoff/yield/touch 锁/租约/三级信任（534 已落地，1700 行），但 worker 是手工的、无并行派发。

**增量（人开 worker，系统不拉起）**：
- 任务行增 `resource_pool`（replay_build / poison / tool_change / doc）与 `shard_key`（卡 id）；`next/claim` 候选过滤增加"同 pool 在领任务数 < 容量（默认核-1）且 shard 不重叠"。touch_set 锁（534）已覆盖文件维度，pool 容量覆盖"核数"维度。
- 派给 worker 的命令模板直接调 B2 并行 replay：`atom_produce/replay_batch` 任务的 verify_cmd 改为 `replay --jobs 4 --cards <闭包子集>`，任务图按 impact 多跳闭包自动切 shard（每 shard 一组互不相关卡）。
- worker 池生命周期：**人**显式 `worker-start <pool> <n>`（等价 534 的"人开新会话"），队列只派发与记账；`doctor` 报 pool 占用/僵尸/租约；系统任何时候不自动 spawn（G-supervisor 边界不变）。
- 状态机只新增 `queued→claimed（带 pool 租约，容量受限于核数）`，其余复用 534。
- 验收：4 个手工 worker 并行跑全量 replay，结果与 `--jobs 1` 逐卡一致，加速比 ≥2.5×；无任务被两个 worker 领取（534 原子 claim 已保证）；pool 打满后第 5 个 next 正确排队。
