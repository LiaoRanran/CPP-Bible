## E1. 外置检索增强：双通道架构（物理隔离，不是同一个 RAG 加个提示词）

```
通道 A「线索通道」(productivity)                通道 B「证据通道」(verdict)
  人/Writer/红队主动检索                         只有本仓 Oracle 能写入
  cppreference / ISO / 编译器手册 /              g++ 真编译 · replay 三分类 · gate 规则
  worklog / _adv_* / 历史报告 / 网络             · poison 真载荷 · 人签（inference）
        │                                              │
        ▼                                              ▼
  claim 候选（未证实假设）                          verdict（verified/inference 三分类）
  必须带：引文(URL+检索日期+原文引句)               必须带：本仓文件:行/cmd 锚点
        │                                              │
        └──────────► 汇入同一张卡的不同字段 ◄───────────┘
              external_leads[]（可改、可弃、不进判决）
              绝不允许从 A 通道写 B 通道字段
```

**通道 A 的最小可行形态（现在做，纯流程+模板，不需要新基础设施）**：
1. 卡 frontmatter 已有 `external_basis`（ISO 条文/独立源）与 claim_structured 的三分类——新增字段 `external_leads:`（列表），每条 `{source_type, locator(URL/书:节/文档:行), retrieved_at, quote, claim_text, status: lead|rejected|verified_externally}`。**lead 状态永远不参与 gate 放行**。
2. Writer/红队工作流：检索到的任何断言，先以 lead 入卡；只有当它被下列之一处理后才改状态：①本仓 Oracle 复算（编译/replay/cmd 锚点）；②与人签的 inference 绑定（external_basis 现有路径）；③被证伪标 rejected 并留一句话理由（喂未来检索）。
3. **引文闭包机检（可复用 gate 模式）**：新规则 `EV-LEAD-CITATION`（先 advice 后 warn）：external_leads 缺 locator/retrieved_at/quote 即提示；含 external_leads 却无任何 Oracle 锚点又试图标 observation 的，直接 block（"检索到即当真"的机器封口）。
4. 检索粒度纪律（来自 VeriCite/CATS，C5）：逐 claim 挂证据（不整段引用）；来源冲突（如标准草案 vs 实现行为）→ status 留 lead + open_question，禁止择一入卡。
5. 本地权威库优先：cppreference 离线镜像/编译器内置手册可做本地语料；网络搜索只用于补缺，且 locator 必须可重放（记录查询式+日期）。

**通道 A 的质量指标（攒数据）**：lead→verified 转化率、lead 被 Oracle 驳回率（借 FCR/FFR 形态）、含 lead 卡的人均审稿时间变化。驳回率高的来源降权（人维护来源权重表，不做自动 embedding 排序）。

**明确不做**：向量 RAG 自动检索自动入卡、LLM 总结检索结果直接进正文、检索片段当作 verified_facts。

## E2. 可机器查询的长期记忆（JSONL 案例库 + 单一查询入口 + 批次累积纪律）

形态依据：Letta Context Repositories（记忆=带 frontmatter 的版本化文件、JIT 检索、git 管理，C4）。本仓用已有的"JSONL + Python 小工具"栈，零新依赖。

**新增四张结构化案例表（`data/memory/*.jsonl`，gitignore 同 data/tasks 口径，人审后可挑要入库的条目转 docs/kernel/）**：

1. `escape_patterns.jsonl`（逃逸模式库，最高价值）
   `{id, family(E01..E12/M1..M7/新编号), title, payload_shape(怎么造的), target_layer(replay/gate/poison/kg...), first_seen_batch, fixed_by(commit/rule_id), repro_cmd, status: open|closed|cannot_fix, lesson}`
   首批数据来源：六轮 _adv_* 报告的攻击表、poison_drill.py 的 107 载荷注释、mutation_fuzz 的 escaped 报告——**苦力一批批录入，每条必须有 repro 锚点（命令或载荷文件），没有锚点不收**。
2. `env_pitfalls.jsonl`（环境/工具链坑）
   `{id, area(windows/git/sqlite/python/compiler/test), symptom, root_cause, fix, first_seen, repro}`
   首批：双解释器(PATH 裸 g++)、WAL 需 busy_timeout 先于 journal_mode（534 实测 6/8 冷启动竞争）、SQLite ALTER 迁移中间态、%TEMP% safe-delete、.gitignore 行内注释失效、给 .asm 加注释破 sha、git objects 只读位、taskkill gbk 输出、wmic 缺失……
3. `false_reds.jsonl`（假红根因库）：`{id, symptom, root_cause_category(interpreter_split/concurrent_tempstate/flaky_env/data_drift), batch, fix}`。527 解释器分裂即首条。
4. `model_profiles.jsonl`（模型能力/成本档案）：`{model, batch, task_type, success_rate, avg_calls, tokens, rework_count, notes}`——喂 G-router/G-canary 的开门数据（现在只攒不用）。

**查询入口**：`tools/memory_query.py --family E01` / `--area sqlite` / `--status open`，纯 JSONL 过滤（几十到几百条，grep 级性能，不需要向量库）；投喂词/Writer 提示词把"开工前先查 escape_patterns 与 env_pitfalls"写成固定第 0 步。

**累积纪律（防变只读流水账）**：
- 每批收工由苦力把本批**新踩的坑/新逃逸**录入（一任务一 commit 的一部分，和毒样例同批）；
- 入库质量门：无 repro 锚点/无 fix 的条目只能进 `inbox.jsonl`，监工每周清；
- ledger §4 的基线数字改为由 metrics_collector 自动生成片段插入（人不再手抄数字，根除 9-16 漂移）；
- metrics.jsonl 恢复每批必采（CI 包装脚本保证，断流即 doctor 报黄）。

**与 534 handoff 的分工**：handoff 是**单任务**短期记忆（会话间续跑，任务 done 即归档）；案例库是**跨任务**长期记忆（可复用经验，按主题索引）。tried_and_failed 在任务 complete 时，自动把有复用价值的条目（含锚点）追加到 inbox.jsonl 的候选项，人决定是否转正。

## E3. knowledge_graph：从标签袋到真语义边（自动入库仍冻结）

**为什么 0/157 连通**：kg 边大多是"原子→标签词"（subject/object 袋）与卡引用边；概念节点之间无类型化关系，孤立是必然。

**真语义边的来源（只认三种，全部带来源 provenance）**：
1. **结构化源抽取**：claim_structured 的命题关系（A 依赖/矛盾/对比 B）经现有 `_claim_props` 已能取到——建边只允许来自命题正文，边带 `{src_atom, src_prop_id, edge_type, evidence_span, extracted_batch}`；无命题出处不建边。
2. **跨卡证据链**：falsification 字段的"位置/机制对照"（EV-CONC-001 已有 5 个对照函数）→ `mechanism_contrast` 边，这是现成的真实语义关系。
3. **人确认的共指归一**：528 概念归一（concept_aliases.txt）只借词汇不自动合并；产出的共指候选由人在批次 V 确认后才建 `same_as` 边（冻结项不解禁，只是把候选流做实）。

**边类型受控词表**（扩 kg 白名单）：`mechanism_contrast / contradicts / prerequisite / specializes / realizes / same_as(人签) / evidence_for`；contrasts 与 contradicts 已拆（530 T3）。每条边可机读溯源到命题 id 或卡段落——删除/改判一个命题时，kg 边能级联失效，不留鬼边。

**连通指标变真信号的门**：
- 现有 `kg concept-islands`/multi_atom 统计保留；新指标"语义边占比"（类型化边/总边）与"跨原子命题链长度"；
- 只报告不自动放行：指标进入 metrics.jsonl，连续 3 批改善才在 ledger 记趋势；
- 候选清单给红队：候选边的反例检索（kg suspect 同构思想）由人裁决。
- **否决**：embedding 相似度自动连边、LLM 从正文抽三元组直接入图（529 冻结原文："只 embedding 无闸门=自说自话"）。

## E4. 两条主线的交汇点（速度与知识的接口）

- B3 测试选择的依赖闭包与 E3 的机制边共用一份关系数据：`prerequisite/specializes` 边同时回答"改 A 要回归谁"（速度）和"A 与谁语义相关"（知识）——一次结构化建设，两个消费者。
- E2 的 env_pitfalls 直接降低 B 系列落地返工率（并行隔离方案的每一条都对应 env_pitfalls 一条：WAL、tmp、只读位、gbk）。
- replay_resultset（B2）与 metrics 一样进 data/ 时序资产：长期可查"哪张卡在哪个工具链/核数下多久"，喂 nightly 容量决策。
