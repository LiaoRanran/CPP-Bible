## 2.1 核心概念

**翻译验证（TV）** 的核心思想（与"验证编译器"相对）：**不证明编译器本身正确**（那是 CompCert 用 10 年+ 做的），而是**对每一次具体的编译，证明它的"输入源程序"与"输出目标程序"语义等价**。即验证的是**单个翻译步骤的 instance**，不是编译器这个 function【已查证：Necula & Rahul《Translation Validation for an Optimizing Compiler》PLDI 2000，people.eecs.berkeley.edu/~necula/Papers/tv_pldi00.pdf，检索 2026-09-19】。

- **TV vs 编译器验证（CompCert）**：TV = "每次编译都查"（成本低、只覆盖本次），编译器验证 = "一次性证明编译器正确"（成本高、覆盖所有编译）。TV 的代价是每次编译都要跑 validator；好处是不必信任编译器实现。
- **语义等价的形式化**：通常用**模拟关系（simulation relation）**——若目标程序每一步行为都能在源程序找到对应（源模拟目标），则目标没"做多余/错误的事"【已查证：Pnueli, Siegel, Singerman《Translation Validation》TACAS 1998 / ZPL01.pdf 2004，检索 2026-09-19】。

### 本项目的"源"与"目标"
- 源 = 夹具 `.cpp` + 卡的 `command`（编译命令，含 `-std`/`-O`/`-S` 等）。
- 目标 = 编译产物（`.asm` / 可执行 / 符号表）。本项目绝大多数是 `.asm`（反汇编对照） + 少量 `.out`（运行输出）。

### 语义等价的定义（本项目可行档）
对 C++ 做完整语义等价**不可行**（未定义行为、别名、并发），但可定义**可观察行为等价（observable equivalence）弱档**：
1. **逐字节一致（build reproducibility）**：同命令编译两次产物 sha 一致（最弱，但最强可证）。
2. **符号存在/不存在一致**：`nm`/`objdump` 导出的符号表逐条一致。
3. **关键段一致**：`.text`/`.data` 段内容一致（控制流/数据布局未变）。

## 2.3 本项目 replay 的翻译验证设计（三档）

### ★ 轻量档（纯标准库 + g++，已部分存在）
- **现状**：`_recompile_invariant`（代码行 1409）已做"独立重编译 + sha 比对"，等价于轻量 TV 的最弱档（逐字节一致）。它用 `CCACHE_DISABLE=1` 防缓存假真、临时目录隔离、原命令逐字执行只改 `-o` 目标（1420-1437）。
- **本项目可新增**：在轻量档基础上增加 **符号表一致性**（`nm` 导出后逐条比对）与 **关键段一致性**（`readelf -S` 取 `.text`/`.data` 段 sha）。纯标准库 + 系统 `nm`/`readelf`（Windows 下 MinGW 自带）即可。
- **能验证**：编译可复现、工件未被篡改、符号/段未变。
- **不能验证**：跨优化级别的语义等价、未定义行为差异。

### 中量档（需 g++ -fdump-tree-all，成本中-高）
- **做法**：用 `g++ -fdump-tree-all` 导出 GIMPLE IR，比对同一夹具**不同优化级别**（如 -O0 vs -O2）的 GIMPLE 差异，验证"优化未改变可观察行为"（符号存在性、控制流结构、关键函数调用）。
- **工具**：g++ 自带 `-fdump-tree-*`（无需新装），但**解析 GIMPLE 文本并做语义 diff 是纯标准库难事**（需自己写 AST 级比较器）；符号/控制流比对可用 `objdump -d` 反汇编后 diff。
- **能验证**：优化 pass 是否改变可观察行为（弱语义等价）。
- **不能验证**：跨编译器（MinGW vs Clang）的等价、完整语义。

### 重量档（需 SMT/Z3 + LLVM，结构性不可行）
- **做法**：Alive2/Souper 验证具体编译优化（如 -O2 某 pass）。
- **结构性上限**：**本项目用 g++/MinGW，不是 LLVM**；且纯标准库**无 Z3**。Alive2 明确不支持过程间变换且要 LLVM WITH RTTI【已查证：github.com/AliveToolkit/alive2，检索 2026-09-19】。→ **本项目重量档收益极低、成本极高，建议远期或不做**。

## 2.4 与现有 replay / in-toto / metrics 的集成

- **replay 判定增加"翻译验证"维度**：当前 verdict 只有"断言↔实际一致"（artifact_assert / run_match / sha）。轻量 TV（重编译不变量 + 符号表/段一致）作为**额外 inspection 点**；失败 → `infra_error`（编译环境问题，不是内容证伪，与 1458-1463 三分类一致）。
- **in-toto（601 供应链层）**：在 `replay_verify` step 的 inspection 里登记 TV 结果（参考 600 的 in-toto layout 设计）。
- **metrics 新增指标**："编译可复现率" = 可复现卡数 / 总卡数；不可复现卡列入待修复清单。

## 2.5 成本-收益（诚实）

| 档 | 实现成本 | 验证能力提升 | 性价比 |
|---|---|---|---|
| 轻量（符号表/段一致 + 升级 `_recompile_invariant`） | 小（纯标准库 + nm/readelf） | 高（把"已存在的最弱 TV"补成完整轻量 TV） | **高** |
| 中量（GIMPLE diff） | 大（要写 GIMPLE 解析/diff） | 中（弱语义等价） | 低 |
| 重量（Alive2/Souper） | 极高（LLVM+Z3，且不适用 g++） | 极低（本项目用不上） | 极低 |

## 2.6 反例（TV 哪些方法不适用本项目，说明原因）
1. **完整语义等价证明对 C++ 不可行**：C++ 有未定义行为、别名、模板实例化等，形式化语义本身是大开放问题；TV 只能做"可观察行为等价"弱档。
2. **Alive2/Souper 不直接适用**：验证对象是 LLVM IR，本项目产物是 g++ 的 GIMPLE/汇编/ELF，中间表示不同；且需 Z3（纯标准库无）。
3. **PCC（携带证明代码）过度**：要求编译器产出机器可检证明，需改造 g++ 工具链，成本远超收益。
4. **跨编译器字节一致本就不要求**：replay 已用 `artifact_compiler` 身份分流（1635-1682）——跨编译器降级为结构断言，TV 的"字节一致"只在同编译器下有意义，不要硬求跨编译器字节相等。
