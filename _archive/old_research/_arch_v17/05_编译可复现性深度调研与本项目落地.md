## 5.1 核心概念

**编译可复现性**：同一源代码 + 同一编译命令 + 同一编译器版本 ⇒ 产出二进制**逐字节一致（bit-for-bit identical）**【已查证：reproducible-builds.org，检索 2026-09-19】。它是**翻译验证的必要条件**——若编译不可复现，就无法稳定验证"输入输出对"（见 02 §2.4）。

### 编译不可复现的常见原因（来自 reproducible-builds.org）
1. 时间戳：`__DATE__`/`__TIME__`/`__TIMESTAMP__`
2. 随机数：编译器内部随机化（如变量布局）
3. 环境变量：`PATH`/`LC_ALL`/`TZ` 影响行为
4. 文件系统顺序：`readdir` 顺序不确定 → 链接顺序变
5. 并行编译：`make -j` 顺序不确定
6. 绝对路径：调试信息含绝对路径
7. 用户名/主机名：`__FILE__`、调试信息

### 可复现构建工具/标准
- **reproducible-builds.org**：标准定义与最佳实践【已查证：reproducible-builds.org，2026-09-19】
- **SOURCE_DATE_EPOCH**：用环境变量替代 `__DATE__/__TIME__` 的时间戳【已查证：rb.mapreri.org/site/docs/source-date-epoch/，2026-09-19】
- **diffoscope**：深入 ELF 段/调试信息/指令级比较差异【已查证：reproducible-builds.org/docs/，2026-09-19】
- **GCC `-frandom-seed`**：固定编译器内部随机种子
- **GCC `-ffile-prefix-map`**：绝对路径映射为相对路径
- **strip + objcopy**：去除不可复现的调试信息/符号表

## 5.2 本项目编译可复现性现状（实跑验证）

**本机实证（2026-09-19，g++ 15.3.0 MinGW-w64，临时目录，未碰 Examples 正式夹具）：**
```
g++ 版本: 15.3.0
A. 极小程序 两次编译可执行 sha 一致? True  (run1 d888784ee18f == run2)
B. _ch161_macro.cpp 两次汇编 sha 一致? True (fe3a13d96f29 == run2)
B. _ch161_loc.cpp  两次汇编 sha 一致? True (803ff04b8c6b == run2)
B. _ch161_full.cpp 两次汇编 sha 一致? True (45f77b69efde == run2)
```
- **结论**：在本机短窗口内，普通程序与 3 个含 `__DATE__/__TIME__/__FILE__/__TIMESTAMP__` 的夹具（`_ch161_macro/loc/full.cpp`，Examples/ 检索命中）**均编译出逐字节一致产物**。这与 replay 的 `_recompile_invariant` 对 56 张 confirm 卡通过的事实互相印证——**编译可复现在本项目已是事实，只是尚未被显式"声明为可证属性"**。

### ⚠️ 探针局限性（诚实标注，不算出的明说）
- 两次编译在**同一秒内**完成，`__TIME__`（秒级）无机会变化；跨天/跨秒漂移**未被本探针覆盖**。
- 仅用 `-O2 -S` 简易命令，未用**卡的真实 `command`**（含 `-std`/多 TU/链接）。真实命令更可能触发路径/顺序不确定性。
- 未用 `diffoscope` 做段级定位（仅比 sha）。
- → **严格结论**：本探针证明"短窗口内同命令同编译器确定"，**不能排除**跨时间边界或真实多 TU 命令下的非确定。完整审计需按 5.4 阶段 1 做"跨时间窗口 + 真实命令 + diffoscope"。

## 5.3 本项目夹具的不可复现风险点（需重点审计）
1. **3 个时间/文件宏夹具**：`_ch161_macro/loc/full.cpp`（已确认含宏）。建议：加 `SOURCE_DATE_EPOCH` + `-ffile-prefix-map` 后复测。
2. **多 TU 夹具**：`Examples/_ch12_tu_*.cpp`（25+ 个 TU）链接顺序依赖 `readdir` 顺序 → 潜在非确定。
3. **绝对路径**：卡的 `command` 若含绝对路径（如 `C:/.../x.cpp`），不同机器编译不可复现 → 应用 `-ffile-prefix-map` 或相对路径。
4. **调试信息**：若卡命令含 `-g`，调试段含路径/时间戳 → 不可复现；建议比对时 `strip` 或仅比 `.text` 段。

## 5.4 提升方案（三档，与 06 阶段 1 对齐）

| 档 | 做法 | 工具 | 能验证 | 不能验证 |
|---|---|---|---|---|
| 轻量 | 同命令编译两次比 sha/符号表/关键段 | 纯标准库 + g++/nm/readelf | 同输入同输出、工件未篡改 | 跨编译器/语义 |
| 中量 | diffoscope 定位两次差异，逐根修复 | diffoscope | 差异精确到段/指令 | 自动修复 |
| 重量 | 编译可复现作为 replay inspection（不可复现→infra_error） | 集成入 replay | 每次 replay 守门 | — |

**轻量档（推荐先做）**：把现有 `_recompile_invariant` 升级为——
- 比对 sha（已有）+ 比对 `nm` 符号表 + 比对 `.text`/`.data` 段 sha；
- 跨时间窗口：间隔 >1s 重编译，验证 `__TIME__` 不漂移；
- 跨编译器：保留现有 `artifact_compiler` 分流（1635-1682），其余编译器降级结构断言。

## 5.5 与翻译验证 / replay / metrics 的集成
- **编译可复现是 TV 的必要条件**（02 §2.4）：先证"同输入同输出"，才能谈"输入输出对语义等价"。
- **replay inspection 点**：不可复现 → `infra_error`（非 refute，属编译环境问题，对齐 ITP 三分类 1458-1463）。
- **metrics 新指标**："编译可复现率" = 可复现卡 / 总卡；不可复现卡入待修复清单。

---

## 5.6 成本-收益
- 轻量：成本小（纯标准库 + g++），收益高（把已存在的事实变"可证属性"）。
- 中量：成本中（diffoscope + 修复），收益中。
- 重量：成本中（集成 replay），收益高（守门）。

---

## 5.7 反例（哪些因素导致不可复现且难修复）
- **g++ 自身 bug 致非确定**：极少数编译器缺陷 → 只能等上游修或换版本，本项目无法在纯标准库内解决。
- **未定义行为（UB）导致的"合法非确定"**：同一源在不同优化下行为不同属语言层面，编译可复现性无法约束语义，需翻译验证（02）。
- **跨机器绝对路径**：除非全仓库改用相对路径或 `-ffile-prefix-map`，否则"在 A 机可复现、B 机不可"是结构性限制。
