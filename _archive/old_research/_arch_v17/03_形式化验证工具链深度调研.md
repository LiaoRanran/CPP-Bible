## 3.1 逐个工具

### CompCert —— 验证编译器
- **核心**：用 Coq 证明的优化 C 编译器，生成代码行为 == 源 C 语义【已查证：compcert.org】。
- **验证范围**：仅 **C**（ISO C99 大部分），**不支持 C++**；优化级别有限（手册称约 90% 算法已证，含所有优化与代码生成；elaboration/汇编/链接未完全验证）【已查证：compcert.org/man/manual001.html，检索 2026-09-19】。
- **对本项目价值**：本项目用 **g++ 编译 C++**，CompCert **直接不适用**；但其"每 pass 翻译验证"思路可借鉴（见 02）。
- **学习成本**：高（Coq + 编译器知识）。
- **反例**：不支持 C++ → 本项目夹具是 C++（Examples/ 全是 `.cpp`）→ 不能用 CompCert 替换 g++。

### seL4 —— 验证微内核
- **核心**：用 **Isabelle/HOL** 从抽象规格到 C 实现的精化证明（refinement），证明功能正确 + 安全【已查证：Klein et al. SOSP 2009，isabelle.in.tum.de/~kleing/papers/sosp09.pdf，检索 2026-09-19】。
- **验证范围**：微内核的功能正确性、安全性、可靠性。
- **对本项目价值**：其"抽象规格 → 具体实现 → 精化证明"的**方法论**可借鉴到"卡面断言 → 编译结果 → 精化证明"；但 seL4 本身是内核验证，与本项目无直接对接点。
- **学习成本**：高（Isabelle/HOL + OS 知识）。
- **反例**：内核验证，与"知识卡复算"无同构关系，直接套用无意义。

### Lean / Coq / Isabelle —— 交互式定理证明器（ITP）
- **Lean**：依赖类型，mathlib 数学库强，社区活跃【一方称】。
- **Coq**：软件验证传统强（CompCert 用 Coq），SSReflect/MathComp【一方称】。
- **Isabelle/HOL**：自动化高（`auto`/`sledgehammer` 调外部求解器），seL4 用【已查证：seL4 来源】。
- **对本项目价值**：本项目的"命题网络"（79 命题 / 274 边）可用 ITP 做形式化推理（证明蕴含/攻击后果）。但 **592 prop_closure 已用纯标准库 BFS 做可达性**，79 命题规模小，**ITP 是杀鸡用牛刀**（brief 方向 3 自己也这么判断）。
- **学习成本**：中-高（依赖类型/战术/自动化）。
- **反例**：79 节点图推理纯标准库 BFS 已够；ITP 的投入产出比差。

### Dafny / F* —— 验证式编程语言
- **Dafny**：微软，语法近 C#/Java，自带规约语言，自动生成验证条件调 SMT【一方称】。
- **F***：微软，依赖类型 + 效果类型，适合加密/安全协议，学习曲线陡【一方称】。
- **对本项目价值**：可用 Dafny 重写工具关键部分并自带规约。但 **Dafny/F* 不支持 Python**，本项目工具是 Python（replay/gate/poison 全是 .py）→ 无法直接采用，重写成 Dafny 成本极高且无收益。
- **反例**：不支持 Python 重写 → 与本项目技术栈不兼容。

## 3.2 工具对比表

| 工具 | 适用场景 | 学习成本 | 自动化 | 对 C++ | 对 Python | 本项目适配 |
|---|---|---|---|---|---|---|
| TLA+ | 并发/状态机 | 中 | 模型检查高/证明中 | 间接（建模状态） | 间接 | **适配（状态机）** |
| 翻译验证(轻) | 编译可复现 | 低 | 高（sha 比对） | 直接 | 直接 | **适配** |
| CompCert | C 编译器验证 | 高 | 低（需人工证） | 不支持 C++ | — | 不适用 |
| seL4 方法论 | 内核/精化 | 高 | 中 | — | — | 不适用（仅方法论借鉴） |
| Coq/Lean/Isabelle | 数学/程序证明 | 中-高 | 低-中 | 间接 | 间接 | 过度（79 命题） |
| Dafny/F* | 验证式编程 | 中/高 | 高 | — | **不支持** | 不适用 |

## 3.3 本项目工具链选择建议

- **最小可行（推荐）**：TLA+（状态机建模 + TLC 检查） + 纯标准库轻量翻译验证（编译可复现 + 符号表/段一致） + 现有 Python 工具。零新语言、零 SMT。
- **未来扩展（可选）**：若未来引入 clang/LLVM → 可上 Alive2（需 Z3，突破纯标准库约束，需用户裁决）；若命题网络规模暴涨 → 可评估 Lean（但仍可能过度）。
- **明确不适用**：CompCert（非 C++）、seL4（内核）、Dafny/F*（非 Python）、重量级 TV（LLVM/Z3 约束）。

---

## 3.4 成本-收益（每个工具）
- TLA+：成本中（1-2 天入门 + 规格编写），收益中-高（防状态机回归 + 活文档）。
- 轻量 TV：成本小，收益高（实打实的"编译可复现"可证）。
- 其余（CompCert/seL4/ITP/Dafny/F*/重量 TV）：成本中-极高，收益对本项目低-极低 → **不建议投入**。
