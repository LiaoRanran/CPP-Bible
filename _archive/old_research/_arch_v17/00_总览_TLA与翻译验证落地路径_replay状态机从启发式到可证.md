## 〇、两句话开头（按 brief 要求）

① **三个方向（TLA+ 模型检查 / 翻译验证 / 编译可复现性）中：**
- **性价比最高 = 编译可复现性（含把现有 `_recompile_invariant` 升级为"跨时间/跨编译器"审计）**：纯标准库 + g++、零新工具、分钟级可交付，且直接把"同输入同输出"这一 replay 已隐含依赖的假设变成机器可核验。
- **在本项目约束下（单用户 / 纯标准库 / Windows）有结构性上限 = 重量级翻译验证（Alive2/Souper + Z3/SMT）**：本项目用 **g++/MinGW 而非 LLVM**，Alive2 验证的是 LLVM IR；且纯标准库**无 Z3**。TLA+ 模型检查反而**没有硬上限**（单用户、56 卡固定集合、串行，状态空间可控）。
- **最意外的发现 = replay 早已内置轻量翻译验证**：`atom_evidence_replay.py` 的 `_recompile_invariant`（P0-A / 452 E01，代码行 1409）对每张卡独立重编译并比对 sha，因此 56 张 confirm 卡的"编译可复现"**已被现有管线实证**。原 brief 假设"replay 不验证编译可复现"是过时判断 —— 先读码纠正这一点，比引入任何新工具都值。

② **如果只允许先做一个阶段，选哪个、为什么、推进了多少：**
- 选 **阶段 1（编译可复现性审计 + 把 `_recompile_invariant` 从"同编译器"升级到"跨编译器结构断言 + 跨时间窗口"）**。原因：零新依赖、分钟级交付、直接闭环 replay 已依赖的隐含假设。
- 做完后，replay 从"编译结果 == 断言"的**启发式**，推进到"编译可复现（同输入 ⇒ 同输出）已机器核验"的**可证一层** —— 这是翻译验证最弱但最扎实的一档，且是现有管线的一部分，只需补审计与跨边界覆盖。

## 二、核心结论（6 条，逐条带证据）

1. **replay 已是"状态机"，只是隐式散落在 if/else 里**（代码行 1477-1741）：parse → 必填字段 → MSVC/编译器 → 取锁 → 快照 → 删旧工件 → 编译 → run_match → artifact_sha → 重编译不变量 → 多产物 → 阴性对照 → sanitizer → 还原 → 释放锁 → confirm。建模前必须先承认它有 20+ 个 return 点（1742 注释），不是线性流水线。
2. **三分类 verdict（confirm / refute:* / infra_error:*）是 fail-closed 的**（1456、2001）：infra_error 不计入内容恶化、但仍 exit 1，防"删夹具即放行"。这是已有不变量，TLA+ 只需把它形式化。
3. **轻量翻译验证已存在**：`_recompile_invariant`（1409）独立重编译 + `CCACHE_DISABLE=1` + 临时目录隔离 + 比对 sha，返回 tampered/ok/unavailable/infra。它等价于"翻译验证最弱档"。**纠正 brief 假设**：replay 不是"完全不验证编译可复现"，而是"已验证同编译器可复现"。
4. **并发隔离靠每卡锁，不是进程内并行**（1911-1917 注释、952-989）：工具刻意串行（无 `--jobs`），锁用 `O_CREAT|O_EXCL` + pid 存活检测 + 陈旧接管；Windows 上**不用 `os.kill(pid,0)`**（会 `TerminateProcess`，1019-1050）。这是可建模的不变量（锁最终释放、不会漏锁）。
5. **3 个夹具含时间/文件宏**（`_ch161_macro/loc/full.cpp`，检索 Examples/ 命中）：理论上 `__DATE__/__TIME__` 破坏可复现性，但**本机实证两次编译 sha 一致**（探针见 `probes/00_build_repro_probe.py` 输出）—— 因两次同秒、且 -O2 无 -g 不嵌路径。**不能据此排除跨天/跨秒漂移**，需补"跨时间窗口"审计（见方向 5）。
6. **编译器身份分流**（1635-1682）：同编译器强制 sha256；跨编译器降级为 `artifact_assert` 结构断言（不静默放行）。这是"判定一致性不变量"的现成实现，TLA+ 可把它提升为定理。
