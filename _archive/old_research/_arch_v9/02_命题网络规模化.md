**唱反调**：**ASP 的最大风险不是慢，而是"第二个语义"**。本仓今天所有判决都由 Python 函数（gate/replay）+ sqlite 视图给出，行为可用 pytest 逐条锁死；一旦引入 ASP，同一组事实就有了**两套语义**（Python 规则 vs 逻辑程序），二者不一致时"谁是真值"没有机器答案。⇒ ASP 只许承担**Python/sqlite 表达不了**的那类查询，且必须有**双实现对账**（Python 参考实现 vs ASP 结果）。

## 三、差距与风险

1. **缺口 1（最硬）**：没有**命题级依赖/冲突边**（`prop_depends_on` / `prop_contradicts` / `prop_refines`）。后果：改一条命题，机器**说不出**波及哪些命题；`impact_analysis` 只能给到**卡**级。
2. **缺口 2**：去重/同义**无机器判据**。79 命题里是否已有重复？—— **我算不出**（需要"同义"判据，而本仓冻结 LLM 裁判；只读统计只能给"规范化后字面相同"这种最弱判据，见 `07` C1）。
3. **缺口 3**：不一致检测只有 **1 条** `CONTRADICTS`（概念层、人手写）；命题层 0 条。"系统能发现自己的矛盾"目前**不可证伪**。
4. **风险 A（过度工程）**：命题 < 100 时上 ASP/图引擎，收益 ≈ 0，成本 = 引入第二语义 + 依赖治理（见上唱反调）。**触发门槛必须写成机器判据**（边/节点比、孤立率、闭包 P95）。
5. **风险 B（假继承）**：若依赖边由"散文引用"自动抽（正则），会造出**假边**（引用了某卡 ≠ 依赖其命题）⇒ 边必须带 `src_of_edge`（`human` / `machine:<rule>`），且机器抽的边**只能做提示**，不许进判决（沿用本仓"只写不读"纪律）。

## 四、判据表：什么时候 sqlite 不够、什么时候才轮到 ASP

**总判据（一句话）**：**要"枚举所有解并取最优/取最小"才用 ASP；要"从已知事实推闭包"用递归 CTE；要"读一条记录"用普通 SELECT。**

| 查询形态 | 例子（本仓语言） | sqlite 递归 CTE 够吗 | 需要 ASP 吗 | 判据（机器可判） |
|---|---|---|---|---|
| 1 跳读 | 某命题的证据锚 | 够 | 否 | — |
| 可达闭包（单调） | "改 EV-X 波及哪些命题" | **够**（WITH RECURSIVE + UNION） | 否 | 图中无否定/无"选择"算子 |
| 环检测 | 命题/卡依赖成环 | 够（递归 + 路径记录） | 否 | 闭包含自身即成环 |
| 分层/拓扑序 | 生成重验顺序（Lens 3） | 够（Kahn 或递归深度排序） | 否 | DAG |
| **一致性（可同时为真？）** | "这 N 条 observation 是否互相矛盾" | **不够**（默认否定的语义表达不了） | **是**（grounded/stable 语义） | 含**否定**或"至多/恰好 k"约束 |
| **最小冲突集（MUPS 类）** | "从 200 条命题里找最小的矛盾子集" | 不够 | 是（或用 hitting-set 专用算法，非 ASP） | 需要**最小化**（optimization） |
| 去重/同义 | 命题规范化后是否重复 | 够（`GROUP BY normalized_key`） | 否 | 规范化函数存在即可 |
| 概率/区间结论 | 逃逸率上界 | 够（`stat_bounds.py` 纯标准库） | 否 | — |

**随命题量分级的选型表（含触发条件，可机器判定）**

| 规模 | 触发条件（任一） | 存储 | 查询 | 是否需要 ASP | 是否需要外部引擎 |
|---|---|---|---|---|---|
| **<1k（现在）** | 命题 ≤ 200 | sqlite（现状） | Python 闭包 + 少量 CTE | **否** | **否** |
| **1k–10k** | 命题 > 200；或 `build` > 5s；或闭包查询 P95 > 200ms | sqlite + 索引 + 物化闭包缓存表 | 递归 CTE 为主；Python 只做编排 | **仅"一致性/最小冲突"类**，且必须与 Python 参考实现双跑对账 | 否 |
| **>10k** | 闭包/快照查询 P95 > 1s；或需要在线"任意历史时点" | 专用图/时序引擎（评估门槛见 `01` 的 W1） | 引擎原生 + 物化 | 是（非单调查询会成常态） | **才**评估 |

## 五、N / D / W

**N（现在借，1 件）——`tools/prop_closure.py`：命题级闭包的双实现对账 + 规模基线**

- 内容：把"命题 → 证据卡 → 卡 → 命题/证据"的**可达闭包**做两遍：① 纯 Python（照抄 `impact_analysis` 的闭包形状）；② sqlite `WITH RECURSIVE`。逐条对账，输出：每命题的 `up/down` 闭包大小、最大深度、孤立命题占比、以及**两实现差异集合**（必须为空）。
- 为什么这是 N：它是**选型表所需的实测数据**（阶段 1 的触发条件全靠它），且**零判决风险**（只读、新文件）。
- 机器验收：① 两实现对每条命题的输出**逐条相等**（不等 ⇒ exit 1）；② 两次跑一致；③ 只读（无写调用）；④ 命题总数 79 与 `prop_graph.stats()` 相等。
- 零误伤证据：新文件；`impact_analysis.py`/`prop_graph.py`/`knowledge_graph.py` **一行不改**；不跑 gate。
- **明确的"不做"**：本 N **不建** `prop_edges` 表、不自动抽边。抽边是 D 档（见下），因为机器抽边会造假边（风险 B）。

**D（攒数据，2 件）**

- D1：**人工登记命题级边**（先只登记两类最有价值的：`depends_on`、`contradicts`），带 `src_of_edge=human:<名>`。规模门槛：至少把 27 张原子卡内部的命题关系登记完（估计 ≤ 100 条边，**这是知识活**；机器只负责列"哪些命题还没有任何入/出边"）。
- D2：**每次登记后的图快照**落 `metrics.jsonl`（边数/孤立率/最大深度），供阶段 1/2 的触发条件判据使用 —— 这也是"N 档做完之后拿什么说'该上引擎了'"的唯一依据。

**W（等条件，3 件）**

- W1：**引入 clingo 做命题一致性检查**。解冻信号（全部满足）：① D1 已有 ≥1 条 `contradicts` 边且**真出现**过一次需要"最小冲突集"的实际问题；② 已写出 Python 参考实现并能双跑对账；③ 命题 ≥1k。**现在不装、不试装**（任务书也只允许在隔离副本试装）。
- W2：**引入图数据库**（Neo4j/其他）。解冻信号：闭包查询 P95 > 1s **且** 边数 > 5 万。现在 `291 边` 谈这个是**两个数量级之外**。
- W3：**MUPS/justification 类最小冲突算法**。解冻信号：命题进入"同一事实有两个相反结论且都需要保留"的常态（今天只有 1 条 CONTRADICTS，且是人手写的注释性边）。
