## 一句话回答伞主题

> **知识资产层的瓶颈不是"换数据库"，而是"四条轴没被记下来"。**

> 规模与换代在 **1k 命题以前都不需要外部引擎**：sqlite 派生视图 + git + jsonl 三件套足够，真正需要外部引擎的两类查询（**任意时刻快照**、**非单调一致性**）在本仓既非当前瓶颈、也还缺"先把轴攒出来"这一步。**先补齐四轴 + 只读对账，再谈 XTDB/clingo/in-toto。**

## 79 → 1 万命题的演进路线图（以"当前瓶颈"为分界，不按技术时髦排）

| 阶段 | 规模信号（可机器判定的触发条件） | 该阶段该做的事 | 何时才允许上外部引擎 |
|---|---|---|---|
| **0（现在）** | 命题 ≤ 200；`prop_graph stats` 秒级；`impact_analysis` 无环 | 补四轴（N1/N3/N4）+ 双实现对账（N2）+ 报告层等价变异体（N5）+ 批次数攒到 ≥6（N6 前置） | **不需要** |
| **1（100–1k）** | 命题数 > 200 **或** `build` 耗时 > 5s **或** 单卡 `claim_structured` 平均 > 5 条 | 命题级**依赖边**表（`prop_edges(src,dst,kind,src_of_edge)`）+ 递归 CTE 闭包 + 物化缓存；引用锚**字段化**（`source_span`）；oracle 字段补齐（先机器列缺清单，人填） | sqlite 仍够；**clingo 只用于一类查询**：非单调一致性（"这组命题能否同时为真"），因为这条 SQL 表达不了 |
| **2（1k–10k）** | 单批 mutation 变体 > 5k **或** 快照查询 P95 > 1s **或** 需要"任意历史时点"在线查询 | 派生视图与判定引擎**物理分离**（只读镜像 + 独立进程）；去重/同义/冲突的**机器三态**（精确重复 / 规范化同形 / 冲突边）；oracle attestation **谓词化**（对齐 in-toto/SLSA/AIBOM 的"谁在什么条件下产出了什么"） | 这时**才**值得评估 bitemporal 引擎（XTDB/Datomic 类）或图引擎；评估门槛见 01/02 |
| **3（>10k）** | 单机 sqlite 的闭包查询超秒级；或需要跨验证者的历史重验编排 | 增量物化 + 分区 + 跨版本重验调度（Lens 3 的算法草案） | 允许；但**判决仍必须留在本仓可复算的那一层**（LCF 式：内核简单、外层可换） |

**反例先行（本路线的失败条件）**：若命题网络长期**无依赖边**（大量"孤岛命题"），则阶段 1 的图投资无收益 —— 触发条件写成机器判据：`孤立命题占比 > 60%` ⇒ **不上图**，只做去重与引用锚。本仓现状可算：`knowledge_graph` 291 条边 / 325 节点 ≈ 0.9 边/节点，**谈不上稠密**（详见 `02`）。

## 我明确否掉的方向（否掉也是交付）

1. **现在引入 bitemporal 数据库（XTDB/Datomic/TerminusDB）** ⇒ 否。理由：本仓"时间"目前只服务**审计叙事**，真正被判决读取的只有"当前卡面文本 + 工件字节"。引入引擎会把**判决可复算性**外包给一个我们不控制其版本的外部系统（正是 Thompson/DDC 警告的信任面扩张，见 `03`），而收益（任意时刻快照）可以用 `git` + 只读派生视图买到。
2. **现在把 ASP/clingo 设为命题查询主引擎** ⇒ 否。理由：本仓 79 命题的查询是**单调**的（闭包/可达），SQL + Python 双实现已能对账；ASP 只在"非单调 + grounded 语义"才不可替代（详见 `02` 的判据表）。**先攒依赖边**，没有边就没有图查询需求。
3. **把 LLM 裁判引入知识资产层（RAGAS/AlignScore 类语义判据）** ⇒ 否（且是冻结项）。理由：这些指标**本身没有错误率上界**，而本仓的第一性要求是"错误率有上界、可审计"；引入即把上界变成未知。可用替代：词面/结构锚（`04` 的 N4）+ 引用可达性（本仓 `d5_source_integrity.py` 已有先例）。
