# 08 · 工具接口设计（CLI）

> 三个工具纯标准库（阶段 1-2 可落）；`timestamp.py` 薄壳调 ots CLI 或降级（阶段 3）。全部只读友好（`verify`/`prove`/`check-proof` 不写盘；`build`/`stamp` 仅写 `data/supply_chain/`）。

## 8.1 tools/merkle_integrity.py（阶段 1）
```
python tools/merkle_integrity.py build [--scope all|tools|atoms|evidence|examples|book|data_mutation]
    # 算指定 scope 的 Merkle 根，写 data/supply_chain/merkle_roots.json（保留 prev_root）
    # 退出 0=成功
python tools/merkle_integrity.py verify [--scope <s>] [--json]
    # 重算并与 merkle_roots.json 比对；exit 0=一致 / 1=不一致(列出差异文件) / 2=缺基准
python tools/merkle_integrity.py prove --leaf <path> [--scope <s>]
    # 生成包含证明 -> <path>.proof（JSON：{leaf_hash, index, total, path:[siblings]}）
python tools/merkle_integrity.py check-proof --leaf <path> --proof <f>
    # 验证包含证明（重算到根比对）；exit 0=在树中 / 1=不在
python tools/merkle_integrity.py consistency --old-root <r> --old-count <n> [--scope <s>]
    # N档：独立算前 n 叶 MTH 比对 old-root（前缀重算法）；exit 0=一致
```
- 文件枚举：scope 映射到 glob（如 `tools+rule_defs` = CORE_TOOLS + TEST_CONFIG + `rules/**/*.py` + `tools/governance_doc_guard.py` 引用的 manifest 源）。
- RFC6962 前缀哈希（`0x00` 叶 / `0x01` 节点），与 CT 兼容（见 04.1）。

## 8.2 tools/supply_chain.py（阶段 2）
```
python tools/supply_chain.py init
    # 生成 layout.json（基于 07.2 默认 7 步）；写 data/supply_chain/layout.json
python tools/supply_chain.py record --step <name> [--materials <glob>] [--products <glob>]
    # 读磁盘真实哈希，生成 link 写 data/supply_chain/links/<step>.json（模拟签名）
python tools/supply_chain.py verify [--json]
    # 1) 验 layout signed  2) 逐 link 验 sig  3) materials/products 比对磁盘
    # 4) 链路绑定（step N materials ⊇ step N-1 products） 5) 跑 inspections(tool_integrity --check)
    # exit 0=全过 / 1=失败(打印断裂点) / 2=缺 layout/link
python tools/supply_chain.py chain-status
    # 打印每步 functionary/ts/产品数/签名状态（人类可读）
python tools/supply_chain.py bootstrap-check
    # 仅校验"当前 Merkle 根与磁盘一致"（供 gate 启动调）；exit 0/1
```

## 8.3 tools/timestamp.py（阶段 3）
```
python tools/timestamp.py stamp --file <path> [--backend ots|local]
    # ots: 调 `ots stamp <path>`（需 opentimestamps-client）-> <path>.ots
    # local: 降级——把 hash 追加到 data/supply_chain/local_timestamp_log.jsonl（公开 append-only 日志）
python tools/timestamp.py verify --file <path> [--backend ots|local]
    # ots: 调 `ots verify <path>`（需联网+Bitcoin 锚点）
    # local: 在日志中查该 hash 的存在性
python tools/timestamp.py stamp-root
    # 对 data/supply_chain/merkle_roots.json + tools/.tool_checksums 打戳，更新 timestamp_index.json
```
- **诚实边界**：`ots` 后端完整 Bitcoin 验证需联网；`local` 后端仅证明"本仓日志中曾出现"，不具外部不可篡改性，仅作离线降级。

## 8.4 与 gate 启动集成（调用契约）
`gate_engine.main` 首行（现有 `tool_integrity.enforce()` 之后）追加：
```python
from supply_chain import bootstrap_check
bootstrap_check()   # 校验 Merkle 根与磁盘一致；失败 fail-closed 拒绝运行
```
`enforce()` 不变（仍钉 5 工具文件）；`bootstrap_check()` 补"规则/策略定义 + 全范围"的根校验（封堵 585 攻击 1 文件级）。

## 8.5 成本估算
| 工具 | 行数 | 复杂度 |
|---|---|---|
| merkle_integrity.py | ~200 | 低（纯哈希+树） |
| supply_chain.py | ~300 | 中（link/layout/验证链） |
| timestamp.py | ~120（ots 壳）/ +200（local 降级） | 中 |
| gate 启动改动 | ~5 | 低 |

## 8.6 反例（不适用设计）
- **重造完整 in-toto Python 库**：含完整密钥/RPC/网络，单用户用不到（见 01.10）。
- **自研 Bitcoin 解析器**：.ots 完整验证需区块数据，手搓不现实（见 03.8）。
