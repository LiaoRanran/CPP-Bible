# 06 · 方向 6：落地路线图与分阶段实施方案

> 阶段 0-4，依据本调研 01-05。N=现在做（纯库）/ D=攒数据 / W=等条件（密钥/托管/多人）。

## 阶段 0：基线与评估（无代码改动）
- 目标：量化信任根现状 + 攻击防护矩阵。
- 交付：`trust_root_assessment.md`（tool_integrity 覆盖清单、governance manifest 缺口、585 三攻击当前防护表）。
- 验收：表格列出"已封堵/部分/未封堵"三项。
- 风险：低。

## 阶段 1：Merkle 完整性层（纯库，最小落地）【= 00 ② 选定的最小阶段】
- 目标：集合完整性根 + 包含/一致性证明；覆盖规则定义文件。
- 工具：`tools/merkle_integrity.py`（build/verify/prove/check-proof/consistency）。
- 存储：`data/supply_chain/merkle_roots.json`。
- 集成：gate 启动自校验根。
- 验收：改任一被覆盖文件 → verify 失败；585 攻击 1 文件级回归通过；探针升级为正式工具。
- 工作量：小（597 探针已验，~150-200 行升级）。
- 依赖：无（纯标准库）。
- 风险：低。
- **完成后封堵**：585 攻击 1（文件级）+ 部分攻击 2（毒样例定义入根）。

## 阶段 2：in-toto 风格溯源链（纯库，最小子集）
- 目标：步骤 link + 链路绑定 + 模拟签名。
- 工具：`tools/supply_chain.py`（record/verify/chain-status）。
- 存储：`data/supply_chain/links/<step>.json` + `layout.json`。
- 集成：tool_integrity --check 作为 inspection；gate 启动调 supply_chain.verify_bootstrap()。
- 验收：断链路/改 link/签名不符 → verify 失败（探针已验机理）。
- 工作量：中（~200-300 行）。
- 依赖：阶段 1（Merkle 根为 link products）。
- 风险：中（需定义 7 步骤 + schema）。
- **完成后封堵**：攻击 1 步骤级溯源 + 攻击 3 人审记录入链。

## 阶段 3：OpenTimestamps 外部时间锚（需联网）
- 目标：关键根/基准上链，钉存在时间。
- 工具：`tools/timestamp.py`（stamp/verify，薄壳调 `ots` CLI 或降级方案）。
- 存储：`data/supply_chain/timestamps/<file>.ots` + `timestamp_index.json`。
- 集成：Merkle 根上链；tool_integrity 验 .ots。
- 验收：关键文件时间戳可验证；改文件后旧戳仍有效（戳证"旧存在"）。
- 工作量：中。
- 依赖：阶段 1（根就绪）；联网 + ots CLI 或降级。
- 风险：**环境风险（VPN 下 Bitcoin 验证可达性不确定）**；离线场景降级。
- **完成后封堵**：攻击 1/3 的"事后篡改"可被独立时间证明（不解决身份）。

## 阶段 4：SLSA L1 等价物 + 封堵 585 攻击（集成与强化）
- 目标：provenance 生成 + 三攻击封堵 + 重签人审 + 运行时规则指纹（W 档可选）。
- 工具：复用 01-03；新增 `tools/resign_log`、豁免台账 link 校验、poison 台账绑定。
- 验收：585 三攻击脚本**文件级/台账/身份**全部无法再静默成功（进程内运行时篡改预期仍可能，标注）。
- 工作量：大。
- 依赖：阶段 1-3。
- 风险：高（集成面宽）。
- **完成后**：信任根从"自签"变"可独立验证 + 可时间戳"，达 SLSA L1 等价物。

## 阶段依赖图
```
阶段0 → 阶段1 → 阶段2 → 阶段4
               ↘ 阶段3 ↗
```
阶段 1 独立可先做（00 ② 选定）；阶段 2/3 并行依赖 1；阶段 4 依赖 1-3。

## 关键决策点（需用户裁决）
1. **签名替代方案**：单用户用 git HEAD 模拟签名（本调研默认）vs 引入 Ed25519 自管密钥（W 档）。
2. **SLSA 目标**：定为"L1 等价物"（推荐，诚实可达）vs 强行 L2+（不可达，否决）。
3. **OpenTimestamps 联网策略**：调 ots CLI（需装依赖）vs 降级本地日志锚。

## 测试策略
- 每阶段：单元验证（改文件/断链/坏签 → 失败）。
- 回归：585 攻击脚本三则（阶段 4 全过，进程内篡改标注残余）。
- 探针：`probes/probe_supply_chain.py` 作为阶段 1-2 机理回归。

## 成本-收益汇总
- 阶段 1：成本最低、收益最高（见 00 ① 性价比最高）。
- 阶段 2：中成本、中高收益（步骤级溯源）。
- 阶段 3：中成本、中收益（时间锚，受联网/身份上限）。
- 阶段 4：高成本、最高收益（三攻击封堵）。
