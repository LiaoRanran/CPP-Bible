## 0. 判定口径（本报告的核心，先说清楚）

470 的多项修复落地为 **warn / advice / experimental（零输出）**。这些只让问题"可见"，
**不改变卡能否直推 confirm → verified**。本报告用两级口径：

- **严格拦截**＝卡无法直推 confirm/verified（block 或 refute）；
- **可见化**＝gate 有 warn/advice、卡**照样 confirm**（按 452 标准不算拦住）。

## 2. 新逃逸 / 新缺陷（本轮发现）

### N1（P0，最严重）僵尸锁导致 replay 全站拒绝服务
- **现象**：`build/.replay_lock` 残留（内容 pid 39120，锁龄 **2188s**），任何 `replay_card`
  取锁阻塞 **600s** 后返回 `infra_error:replay_busy`（实测取锁超时 600.22s）。
- **根因**：P0-G1 的锁只按 **mtime** 判陈旧（`stale_after=3600`），**不做 pid 存活检测**；
  持有进程被杀（崩溃/CI 超时/`kill`）后，锁在 **1 小时内拒绝所有人**。
- **放大因素**：P0-A 让单卡 replay 翻倍耗时（每卡二次编译）→ 进程被杀概率上升。
- **危害**：一次崩溃 = 整条 replay 门禁不可用 1 小时（CI 全红或超时）。这不是逃逸，是**可用性击穿**。
- **建议修法**：锁文件写入 pid；获取时 `os.kill(pid, 0)`（Windows 用 `OpenProcess`）判存活，
  进程不存在→立即接管；`stale_after` 缩到 300s；注册 `atexit`/`signal` 保证退出释放。

### N2 全局恒真断言不受约束（P0-C 盲区）
- **构造**：`artifact_compiler: Clang（≠本地）` + `artifact_assert: {contains_any: ['zzz_absent', '.file']}`。
- **实测**：`confirm`。`.file` 是任何 `gcc -S` 产物都有的样板 ⇒ 断言零信息，卡照样 confirm。
- **根因**：P0-C 的判别力统计**只在 `contains_in`（符号区间）内做**；全局 `contains`/`contains_any`
  的恒真性完全没约束。E03 探针被拦只是因为**恰好含 contains_in**。
- **建议修法**：把判别力统计扩展到全局断言——统计 text 在整个工件的出现频次与"跨 TU/跨函数覆盖度"；
  或要求全局断言必须带 `min`/`max` 计数（把存在性断言升级为量化断言）。

### N3 冲突同义词仍不完备（`refutes`）
- **实测**：`cancels` 归一后已拦；`refutes` 未归一 → 两颗矛盾原子静默共存。
- **根因**：仍是**枚举范式**（`CONFLICT_SYNONYMS` 四个词表外就漏）。
- **建议修法**：改为语义判据——未知关系类型一律 warn（"未知关系键不参与任何判定"），
  或把关系类型收敛为受控枚举（白名单外即 block）。

### N4（真实事故，非构造）工件被清空 = E13 实证
- `Examples/atoms/_atom_alloc_arena.asm`（EV-MEM-027 的 artifact）当前为**空文件**
  （`git diff` 显示 426 行全删；磁盘 sha `e3b0c442…` = 空串 sha256）。
- **成因**：replay「删旧工件 → 重生成 → finally 还原」模型在**进程被杀**时还原不执行 → 工件永久丢失。
  这正是 452 E13 的真实复现，且由本轮杀僵尸进程触发。
- **建议修法**：还原做成幂等（先写 `*.bak` 再原子替换）；或用"进程级事务目录"承载中间态。

## 3. 已验证有效（正面结论）

- **E07 覆盖扎实**：tab、tab+空格混合、引号值、注释值后走私，5/5 被 `indent-smuggle` 拦住。
- **E09 正常路径有效**：两进程并发同卡均 `confirm`，无假失败（串行化生效）。
- **E01 根因闭合**：借品 sha 与卡值一致也过不了重编译不变量。
- **E08 退出码正确**：未覆盖规则 / 有失败均 exit 1。
- **exp-scan 阴性对照通过**：纯计算夹具不命中（扫描特异），说明 E05 检测本身是对的——
  问题只在它停在 experimental。

## 4. 修复建议（按优先级）

1. **N1 僵尸锁**（P0，可用性）：pid 存活检测 + 缩短 stale + 退出钩子。
2. **N2 全局恒真断言**（P0，机器验证可信度）：判别力统计扩展到 `contains`/`contains_any`。
3. **E12 签收**（P0，链根）：`verified_by` 与 git author/CODEOWNERS 绑定（P0-G2 设计已在 470）。
4. **N4 工件事务化**（P0，数据完整性）：还原幂等，防异常退出丢工件。
5. **E10/E05 升格**（P1）：把 warn/experimental 升到 block——本轮证明它们拦不住卡直推 verified；
   升格前需先跑一轮 warn 面统计（本轮 E10a/b 均命中 warn，误伤面看起来小）。
6. **N3 未知关系键 warn**（P1）：结束同义词枚举范式。
7. **E16 闪卡过滤**（P1）：只导出 verified 及以上状态的原子。
