# 09 · 人审在攻击关系标注中的角色与质量控制

> 外部实证【一方称：NEJM AI 2026 RCT (automation bias)、IAA/Cohen's kappa 标注质控，待核验】。

## 9.1 工作流设计（候选）

```
MIS 关联自动生成候选攻击边 (N, 已做)
        │
        ▼
LLM 辅助标注攻击目标命题 id + 强度 (W, 可选)
        │
        ▼
人审确认 / 拒绝 / 改强度  ──► 可追溯记录(谁/何时/理由)
        │
        ▼
加权 AF 实测 (W2) → IN/OUT/UNDEC
        │
        ▼
mutation 反例验证 (D, 待数据)
```

## 9.2 单用户阶段的"独立性"问题

- 590 引【一方称】arXiv:2605.29800："9 异族判官 ≈ 2 有效独立票"——多人审尚有独立性损耗，单用户（自己生成+自己确认）**独立性≈0**。
- 缓解：用"时间隔离"（先生成、隔日再确认）、"机器预筛可疑边优先复核"、保留 LLM prompt 哈希以便他人后续审计。

## 9.3 质量控制指标

- **IAA / Cohen's kappa**：多人标注一致性——单用户阶段无法算，留作多用户时指标。
- **零误伤率**（本仓第一性）：正确命题被标 OUT 的比例，**必须 = 0** 才能上线。
- **攻击边密度 / 退化指数**（维度 13.5 提议）：发布门槛。

## 9.4 工作量估算（本仓）

- 候选边：MIS 单向 194 条（本探针，42 MIS 方向）；若并集 card→MIS 方向会更多（593 测 79 命题全被触及，估计候选边量级 200–400）。
- 人审需**逐条**确认每条候选边（accept/reject/改强度）。即便 200 条，按每条 10–30 秒，约 0.5–1.5 小时工作量——**单用户阶段可行**，是 D 段主要人时成本。
- 关键：用 Argdown/表格批量呈现（攻击边 + refutation 证据片段 + 默认建议强度），把人审降级为"勾选确认"，降低 rubber-stamp 风险（见维度 5/11）。

## 9.5 本仓落地评估

- 人审是 D 段**唯一不可自动化的瓶颈**，但工作量在单用户可承受范围（小时级）。
- 护栏：机器预筛 + 默认建议 + 溯源，把"标注"变成"确认"，对抗 automation bias。
