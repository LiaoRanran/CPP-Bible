## 一、精确表述

### B-1 Gettier 结构的精确分解与"运气正确"检测算法

**结构（四元组）**：Gettier 案例 = ⟨P 为真；S 相信 P；S 有理由 J 相信 P；**J 的成立与 P 为真的原因无关**⟩。第四元是全部要害——前三元为真而第四元失败时，信念"碰巧为真"，不构成知识。【已查证】https://plato.stanford.edu/archives/fall2025/entries/knowledge-analysis/ ；https://philosophystudent.org/analysis-of-and-responses-to-edmund-gettiers-is-justified-true-belief-knowledge/

**两个精确化的补救条件（阙疑可借用的检测原型）**：

- **安全条件（safety）**：S 知道 P，仅当 **S 不能轻易地错误相信 P**（could not easily have falsely believed P）。Williamson/Pritchard/Sosa 为其主要辩护人。【已查证】https://iep.utm.edu/safety-c/
- **追踪条件（Nozick tracking）**：S 知道 P 当且仅当 (1) P 真；(2) S 信 P；(3) **若 P 不为真，S 就不会相信 P**；(4) 若 P 为真，S 就会相信 P。条件 (3) 是反事实对齐检查的原型。【已查证】https://scholar.harvard.edu/files/sberker/files/phil169-meeting5.pdf
- Pritchard 2026 的反风险（anti-risk）重构：safety 与 sensitivity 的 anti-risk 公式化最终**等价**——"安全"是更稳健的选择。【已查证】https://pdfs.semanticscholar.org/2359/d1043905b6fe88803a03e811e2039650e847.pdf

**阙疑 Gettier 检测算法（两步，可执行）**：

**步骤 1：邻近世界扰动（safety 测试）**
对每条 `verified` 结论 C，构造扰动集 N(w)（邻近可能世界采样）：

| 扰动维度 | 具体操作 | 这是"邻近世界"的什么 |
|---|---|---|
| 源文档版本 | cppreference/标准文档 ±1 版本 | 若结论只因这一版文档才对，则不安全 |
| 编译器/平台 | 换 GCC/Clang、换标准版本 | 结论的真值依赖是否脆弱 |
| 表述变体 | 知识卡同义改写 | 结论是否绑定表述（F 方向接口） |
| 输入变体 | 同类别卡片中抽样换实例 | 是否过拟合单卡片 |

**安全分数**：`Safety(C) = 1 − |{w′ ∈ N(w) : verdict(w′) ≠ verdict(w)}| / |N(w)|`
`Safety < θ_safe`（建议初值 0.8，待实测回填）⇒ 该结论"轻易可错"，标记 `disputed`（不定罪，进复核队列）。

**步骤 2：承重证据检测（tracking 测试）**
定义：证据 e ∈ 理由链 R 是**承重的（load-bearing）**，若"e 为假 ⇒ 结论被推翻"。
- 逐条反事实测试：把 e 换成其否定，重跑验证；结论翻转 ⇒ e 承重。
- **判据**：`load_bearing_set(C) ≠ ∅` 是 `verified` 的必要条件；**空集 = 运气正确**（全部证据都与结论真值无关、只是碰巧全绿，即 Gettier 结构第四元的工程检出）。
- 每条结论必须登记 `minimal_load_bearing_set`（最小承重集，去冗余后）。

**机制对应（精确到公式）**：Nozick 条件 (3) "若 P 不为真则不信 P" ⟷ 阙疑的"存在承重证据 e：¬e ⇒ ¬verdict"——**追踪条件在工程上就是"最小承重集非空"**。

### B-2 击败器理论：两类击败与台账 schema

**精确分类（IEP）**【已查证】https://iep.utm.edu/defeaters-in-epistemology/ ：命题型击败器（propositional，认知者视角外）vs 心理状态型击败器（mental state，视角内）。**行为学分类**：

- **rebutting / overriding**（反对结论）：给出相信 ¬P 的理由——如"另一个人说 Liam 在别处"；
- **undercutting / undermining**（反对推理）：给出"r₁ 根本不再是 P 的理由"的理由——如"Emma 不可靠、常在旅行见闻上说谎"。关键差异（Easwaran 数学版）：rebutting 需要**比较强度**；undercutting **与强度比较无关**（源的可靠性直接归零）。【已查证】https://homeowmorphism.com/assets/2016/rebut-undercut.pdf
- 高阶证据（higher-order evidence）= undercutting 的现代形态：证据"你的信念不合理"应否影响信念本身。【已查证】https://www.alexworsnip.com/wp-content/uploads/2025/06/Higher-Order-Evidence-as-Undercutting-Defeat.pdf
- 与 v23"豁免四元组"接口：豁免 = 一种**预登记的计划性击败器**（"到期即复查"）；台账把它一般化。

**击败器台账 schema（设计对象）**：

```yaml
DefeaterLedger:
  target: <card_id | rule_id>
  entries:
    - id: str
      kind: rebutting | undercutting          # 反对结论 or 反对推理
      trigger:
        type: observation | source_revision | peer_disagreement | method_doubt
        condition: str                        # 人类可读；"若出现 X 则本知识应被推翻/降级"
        observable: bool                      # 该条件在实践中可否被观察？
      status: unobserved | observed | resolved
      registered_at / observed_at / resolved_at
      resolution: str                         # observed 后的处置（改判/降级/豁免/退役）
  defeat_state: intact | rebutted | undercut | disputed
```

**检测机制（三条扫描线）**：

1. **主动扫描（触发匹配）**：每次新证据入库，遍历全部台账条目匹配 trigger——如"cppreference 改版"→ 触发所有引用它的卡片的 undercutting 检查（源可靠性归零类，不需要强度比较，直接进 disputed）。
2. **被动登记（逃逸反哺）**：每次逃逸事件（实际被击中的错误）= 一次**观察到的 rebutting 击败器**；反向上溯登记到相关卡片——逃逸事件从此不只是一次失败统计，而是台账条目（与 v24"缺省负信号"合流）。
3. **可观察性自查（新增维度）**：台账中 `observable: false` 的条目是**装饰性击败器**（写了但永远无法触发）——需降级或重写。一条知识若全部击败器都不可观察，等价于"声称可错但实际不可错"，需要显式标注。

### B-3 拉卡托斯的可判决化：硬核/保护带分类与进步判据

**结构（精确版）**：研究纲领 RP = ⟨硬核 hard core；保护带 protective belt；负启发 negative heuristic（禁止攻击硬核）；正启发 positive heuristic（指导保护带调整以产生新预测）⟩。纲领的更新模式：P₁（问题情境）→ RP（纲领活动）→ P₂（更锐利的新问题）。【已查证】https://phfrohring.com/730b9fb3-95bf-4d91-a7b3-5d66d3dacf46/html ；https://plato.stanford.edu/archives/win2025/entries/lakatos/

**进步/退化的可判决标准（Lakatos 原始口径，非"感觉"）**：
- **进步（progressive）**：理论变动**预测了新颖事实（novel facts）**且其中若干被证实（corroborated）；
- **退化（degenerating）**：不预测新颖事实，或预测了但未被证实，**只能事后吸收**已知事实（post hoc accommodation）。【已查证】同上（UFRGS 摘要原文："prevê fatos novos e alguma dessas previsões é corroborada"；"não prevê fatos novos, ou, os prevendo, não são corroborados"）

**阙疑的可计算判据（v25 核心设计）**：把"理论变动"映射为"规则改动 ΔR"，新颖事实映射为"对**改动时尚未纳入**的样本的预测"：

- **预注册制度**：规则改动提交时必须先登记（pre-register）新预测 T：`T = "ΔR 将在集合 S_new 上产生分布 D_pred"`，S_new 为改动时未纳入的卡片/变异样本；
- **novelty_rate(R) = |{s ∈ S_new : ΔR 正确预测 s 且 R_old 未预测}| / |S_new|**；
- **accommodation_rate(R) = |{s ∈ S_old : ΔR 仅事后修正以吸收 s}| / |S_old|**；
- **判定**：novelty_rate > 0 且预注册的 T 被证实 ⇒ 进步；novelty_rate ≈ 0 而 accommodation_rate 上升 ⇒ 退化（显式告警：该规则改动是退化性的）。
- **关键机械化**：**事后解释不计进步**——没有预注册的"解释力"一律归入 accommodation（这正是把 Lakatos 从修辞变成审计点）。

**硬核/保护带分类判据（三条问题，输出 core | belt 标签）**：

1. **耦合问**：该规则被推翻时，是否必须同步改动 ≥3 条其他规则？（是 ⇒ 硬核候选——它是别的规则的地基）
2. **禁令问**：该规则是否已被声明"不得为修复逃逸而修改"？（是 ⇒ 硬核）
3. **吸收问**：该规则每次失败是否总被解释为"数据问题/流程问题/其它规则问题"？（是 ⇒ 硬核**运行中**，即使未声明）

**阙疑首版初判**（候选，待 632+ 批次审计）：硬核候选 = append-only 原则、DecisionEvent hash 链、独立双实现、UNKNOWN 六态、"不追求零误报"口径；保护带 = 67 规则的具体阈值与参数、证据权重、豁免期限。**硬核的代价声明**：硬核越多，纲领越刚性（改动触及面越大）——Lakatos 的机制正是"用保护带吸收反驳，保硬核不动"；阙疑必须显式写出负面启发（"以下规则不得为修复逃逸而改"），否则硬核是隐性的（隐性硬核 = 每次失败都在悄悄动地基）。

### B-4 知识生命周期状态机（可错论工程化）

**状态定义**（brief 指定五态 + 转移条件）：

| 转移 | 条件 | 机制 |
|---|---|---|
| draft → verified | 验证通过（A 方向 ProofObject 入链 + 边界 B 三元组） | gate + 证书 |
| verified → stale | 边界漂移（mutation_set_hash 变化/源文档改版/超过 TTL） | 扫描器 |
| stale → verified | 重查通过（在新边界下重新出证） | 重查队列 |
| stale → disputed | 重查失败 | 重查队列 |
| verified → disputed | 击败器 observed，或 safety 测试失败（B-1 步骤 1） | 台账扫描 / 安全测试 |
| disputed → verified | 击败器 resolved 且重查通过 | 人审 + 重查 |
| disputed → retired | 不可恢复，或替代知识上线（v24 主动退役） | 退役流程 |
| retired → draft | 新证据 + resurrection_condition 满足（Cromwell 边界：不得永久封存） | 复活流程 |
| 任意 → 任意（豁免激活） | 豁免四元组生效期间**状态不变，检查暂停** | 豁免是暂停器不是状态 |

**与 AGM 的对照（防止自造公设）**：【已查证】https://plato.stanford.edu/Entries/logic-belief-revision/ ；https://arxiv.org/pdf/2608.14567
- contraction（收缩）⟷ verified → stale（撤除承诺，保留数据）；
- revision（修订）⟷ stale → disputed → verified（吸收反例并保持一致性）；
- **阙疑只借 AGM 三条公设**：success（修订后新信息被接受）、consistency（保持一致）、minimal change（最小改动）；**明确放弃 recovery**（"先删再插应完全恢复"——belief base 模型下有争议的强公设，阙疑的台账是 belief base 而非 belief set，天然不满足 recovery，这不是缺陷）；**放弃 logical closure**（逻辑全知假设在工程上不可实现且不必需）。AGM 的已知短板（不能表示自身接受状态、不做重复修订）恰是阙疑用 append-only 台账补的。

**半衰期定量锚（Burton-Kebler 传统的工程借用）**：
- 事实：工程学位知识半衰期 1930 年代约 35 年 → 1960 年代约 10 年 → 今日软件工程 2.5–7 年（趋势向下限）；Gartner 预测 2030 年技术技能半衰期 2 年。【已查证】https://arpitbhayani.me/blogs/half-life/ ；https://artificialus.com/articles/the-two-year-cliff-how-manage-ai-knowledge-that-expires.md
- 方法：引文半衰期 H（引文年龄中位数）与 Price index P（近 5 年引文占比）存在经验关系 P(4)×H ≈ 2（力学期刊实证，1970 年前数据拟合佳、之后偏差增大）。【已查证】http://dianda.cqvip.com/Qikan/Article/Detail?id=23587497 ；https://www.lis.ac.cn/CN/article/downloadArticleFile.do?attachType=PDF&id=12296
- 阙疑借用：**卡片证据年龄中位数（EvidenceAge）**作为可计算复审触发器——`EvidenceAge(C) = median(now − evidence_i.date)`；超阈（按域设：语言核心语义慢、工具链快）⇒ 进复审队列。比固定 TTL 更有依据。

**生命周期元数据（每卡附加）**：

```yaml
Lifecycle:
  state: draft|verified|stale|disputed|retired
  state_history: [ {from, to, at, cause} ]     # append-only
  ttl_review_due: date
  evidence_age_median_days: int                # 半衰期代理指标
  domain_class: core_semantics|std_library|compiler|tooling   # 决定默认衰减率
  defeaters: <ledger ref>
  resurrection_condition: str                  # retired 的复活条件（Cromwell 边界）
```

## 二、阙疑重构草图

### 2.1 对象模型（新增四对象）

- **DefeaterLedger**（B-2 schema）：每卡的击败器台账；
- **Lifecycle**（B-4 schema）：五态状态机 + 证据年龄；
- **CoreBeltTag**：规则标签（core|belt）+ 负面启发清单 + 预注册预测记录；
- **GettierReport**：SafetyScore + minimal_load_bearing_set + 判定（secure|fragile|groundless）。

### 2.2 数据流

```
新卡 → draft
    → 验证（A 方向：ProofObject + 边界 B）→ verified
        ├─ 初始化：DefeaterLedger（≥1 条）+ Lifecycle（TTL + domain_class）
    → 周期扫描（三线并发）：
        ├─ 边界漂移扫描 → stale
        ├─ 击败器触发扫描（B-2 三条扫描线）→ disputed
        ├─ safety 测试（B-1 步骤 1，抽样）→ disputed（若 fragile）
        └─ 证据年龄扫描（半衰期）→ stale
    → 重查/人审 → verified | disputed → retired
    → retired 保留 resurrection_condition（禁永久封存）
```

### 2.3 关键不变量

- **INV-B1（实名可错）**：每张 verified 卡片必须携带非空 DefeaterLedger；写不出"什么会推翻它"⇒ 不允许进入 verified（"不可证伪 ⇒ 不受监"是拒绝理由）。
- **INV-B2（无预注册无进步）**：规则改动的"进步性"主张必须有改动前登记的预测；事后解释一律记 accommodation（B-3）。
- **INV-B3（复活路径）**：retired 必带 resurrection_condition（Cromwell 边界；与 A-1 的 π≠0 禁令同源）。
- **INV-B4（豁免即暂停）**：豁免四元组不改写 Lifecycle 状态，只挂起检查（可审计的暂停，不是静默的真值变化）。
- **INV-B5（承重非空）**：verified 结论的 minimal_load_bearing_set 非空；空集 ⇒ 强制进 disputed（Gettier 检出，B-1）。

## 四、迁移路径（从现有卡片/67 规则过渡）

- **阶段 0（零改码）**：为 629/630/631 已产出的基线卡片补两栏——"什么会推翻它"（哪怕一条）+ "证据年龄中位数"。只动报告，不动工具。
- **阶段 1（影子状态机）**：`lifecycle_fsm.py` 影子跟踪（从现有状态推导初始 state，只记录不判决）；跑一周对比"影子状态 vs 现有处置"差异。
- **阶段 2（抽样安全测试）**：`gettier_check.py` 对高价值卡片抽样跑 safety 测试（不动判决，只出 GettierReport 统计）；首版 θ_safe 从实测分布取分位点回填。
- **阶段 3（制度上线）**：规则改动走预注册（`core_belt_registry.preregister`）；硬核清单首版发布（负面启发显式化）；retired 卡片的复活条件回填。
- **不做**：不重写验证流程（状态机是包装层）；不做 AGM 全公设实现（只借三条）；不把 safety 测试当判决器（它是抽样告警器）。

## 五、死路复核（v24 之上新增）

- **新死路 V10：事后解释即进步**——退化纲领的定义本身；机制形态 = 规则改动后追加"解释为什么原样本失败"却没有预注册预测。
- **新死路 V11：装饰性击败器**——台账写满但全部 `observable: false`（声称可错实际不可错）；需可观察性自查。
- **新死路 V12：安全测试判决化**——把 safety 分数当判决依据（采样扰动≠穷举，会产生新的假阳性类别）；它是告警与分流信号，不是判决。
- **新死路 V13：五态机的僵尸删除**——把 retired 当删除（无复活条件）⟷ v24 V2 抹除工具的翻版；Cromwell 边界否决。
- 其余（可证伪性作划界、白鞋确认、元层全能）v24 结论不变。
