## 一、精确表述

### A-1 Rice 定理：证明 sketch（v24 补完）

**定义（语义属性）**：程序 P 的属性 Q 是语义的，若 Q 只依赖 P 计算的函数 φ_P（输入-输出行为），不依赖其编码（语法）。等价形式：L(M₁)=L(M₂) ⇒ M₁ 与 M₂ 同真同假于 Q。语法属性（"含几个 for 循环"）可判定；语义属性（"是否等价于某程序"）不可判定。【已查证】https://faculty.cc.gatech.edu/~ladha/toc/L16.pdf

**定理（Rice, 1953）**：设 P ⊆ 可计算偏函数集合，P 非平凡（P≠∅ 且 P≠全集），则 {⟨M⟩ | φ_M ∈ P} 不可判定。

**证明 sketch（4 步，归约 A_TM ≤ₘ P）**：

1. 非平凡 ⇒ 存在 f₁∈P；不妨设处处发散函数 ⊥ ∉ P（否则对补集 P̄ 重复同一论证——P 可判定 ⟺ P̄ 可判定）。
2. 反设存在判定器 H_P，对所有 ⟨M⟩ 正确回答 φ_M ∈ P 与否。
3. 构造归约函数：对任意 ⟨M,w⟩ 构造新机器 M′——**M′ 忽略自己的输入 x，先模拟 M 于 w；若 M 停止，则模拟 f₁ 于 x 并输出其结果；若 M 不停止则 M′ 发散**。
4. 于是 φ_{M′} = f₁ ⟺ M 在 w 上停机；即 ⟨M,w⟩∈A_TM ⟺ M′∈P。用 H_P 判 M′ 即得 A_TM 判定器，与 A_TM 不可判定矛盾。∎

**工程含义（精确化 v24 M1）**：

- **推论 R1（近似必然性）**：任何"内容语义正确性"检查器（gate 的 67 条规则、AI 判官、统计模型）都只能做近似判定。逃逸率 1/1406 非"规则不够多"，而是判定器在语义区的结构性行为。
- **推论 R2（未来的过去化）**：语义属性"依赖行为在未来的展开"；判定器只能在行为成为历史后确认。Georgia Tech 讲义原文：*"We may determine the future only when it becomes the past."* ⟹ 阙疑的逃逸事件（事后才发现）有其数学必然性；正确姿态是**事件驱动的知识更新**而非追求事前全知。
- **推论 R3（唯一逃逸窗）**：Rice 适用于图灵完备模型的语义属性。若把判定对象从"卡片描述的行为"降级为"卡片文本在受限判定语言中的性质"（QF 线性算术、位向量、正则约束等可判定理论），检查器可判定。**阙疑的 67 规则实质就是在做这个降级**——但它们尚未显式声明自己工作在哪个可判定片段内。

### A-2 三难的精确形式与 soundness/completeness 双义

**定义（decidable）**：存在算法，对任意输入在有限时间内终止并输出正确 yes/no。【已查证】https://kindatechnical.com/theory-of-computation/undecidability-in-practice-real-world-implications.html

**定理（三难）**：对任何非平凡语义属性，不存在同时满足 sound、complete、全域可判定的判定器。等价取二：sound ∧ terminating ⇒ incomplete；complete ∧ terminating ⇒ unsound。

**Soundness（抽象解释传统，精确版）**：抽象值必须**过近似**具体值：具体状态集合 ⊆ 抽象值所表示集合（α(⟦P⟧) ⊑ ⟦P⟧^♯）。直接后果【已查证】https://deepdiveembedded.com/articles/en/abstract_interpretation.html：分析器**可以**假警报（false positive，报"可能有问题"而实际没有），**必须不得**漏报（false negative，放走真问题）。可见 soundness 是**方向性承诺**，不是"更准"。

**Completeness 的双义（Monniaux 2024 明确指出，v25 新增精度）**【已查证】https://arxiv.org/pdf/2211.09572v3.pdf：

- (a) **证明系统完备**：凡语义为真的命题都可被证明；
- (b) **搜索过程完备**：搜索算法能找到证明系统内所有可证的命题。

二者独立：可以有完备证明系统 + 不完备搜索器（因效率取舍，如 widening 加速收敛）。**对阙疑的直接含义**：67 规则集（证明系统）与规则执行器（搜索过程）的完备性必须**分开声明**；当前系统混为一谈。

**BMC 的单向性（有界验证的性质）**："BMC 查找长度 1,2,… 的反例 ⟹ 它是 incomplete 的"（USTC 讲义原文）【已查证】http://staff.ustc.edu.cn/~huangwc/fm/ppt/5.2.3-4.s.pdf。方向性：
- BMC 报"找到反例" ⇒ **真反例**（对 k-步语义 sound，无假阳性）；
- BMC 报"k 步内无反例" ⇒ 只说明 k 步内无反例，**不是**正确性证明。

### A-3 有界验证框架（v25 新增，v24 未覆盖）

**定义（有界验证）**：给定系统 S、性质 φ、边界 B=(k, D, v)（步数 k / 输入域 D / 生成器版本 v），BMC(S, φ, B) 判定"在 B 内是否存在反例"。

**定理（有界可判定性）**：有限状态 S + 固定 k ⟹ 该判定可归约为 SAT/SMT 问题，可判定。【已查证】Kani 2026（arXiv:2607.01504）：bounded model checker "encodes default safety properties and checks them exhaustively up to a bound"，并把有界升级为无界的正规途径是**合约**（function contracts / loop contracts），把证明 harness 写成类单元测试。【预印本】

**k-induction（有界→无界的桥）**：若 (base) 前 k 步性质成立，且 (step) 假设连续 k 步成立可推出第 k+1 步成立，则性质在**所有**步成立。【已查证】https://arxiv.org/html/2207.01338v1 + ESBMC 综述 arXiv:2605.26169【预印本】

**阙疑映射（机制公式级，非泛泛类比）**：

| BMC 概念 | 阙疑对应 | 精确对应物 |
|---|---|---|
| 展开深度 k | 1593 条固定 mutation | k = \|mutation_set\|，且集合被冻结（hash 固定） |
| BMC 反例（SAT） | 变异击中（规则未拒绝） | 发现即真：**变异击中没有假阳性**，无需复核 |
| BMC 无 Recounterexample（UNSAT@k） | "mutation 全拒" | 只保证 \|M\| 内成立，**不保证规则正确** |
| k-induction 的 base | 现有 mutation 全绿 | 阙疑已有 |
| k-induction 的 step | "规则对任意新生成变异的结构性拒绝不变性" | **阙疑不存在**（无归纳证明）⟹ 一切结论永久带界 |
| 合约（contracts） | 卡片级作用域声明（豁免四元组的扩展） | 把"全局断言"降为"合同内断言"，使检查可分解 |

**形式化结论（边界三元组 B）**：任何验证结论必须写成 `verdict(φ) = f(φ, B)`，其中 B = (mutation_set_hash, mutation_count, generator_version)。缺失 B 的"通过"报告在数学上无内容（与未验证不可区分）。

### A-4 证明对象 schema（Curry-Howard ⟶ 工程格式）

**Curry-Howard（精确版）**：命题 ⟷ 类型，证明 ⟷ 程序（证据树）。证明不是说服性文字，而是**可构造、可检查的数据对象**。【已查证】https://softwarefoundations.cis.upenn.edu/lf-6.9.0/ProofObjects.html

**de Bruijn 判据**：证明助手必须产出可在系统之外独立检查的证明对象；检查器小到"一个多疑的用户能自己写出来"（Barendregt 命名）。其存在理由是把**证明检查器（简单、可信）**与**证明引擎（强大、不可信）**分离（Automath 1967 起，LCF 1970s 确立）。Chlipala 的判定：**Coq 满足 de Bruijn 判据，ACL2 不满足**（其决策过程没有证据痕迹 evidence trails）。【已查证】https://adam.chlipala.net/cpdt/html/Intro

**LCF 内核机制（工程上如何强制）**：定义不透明类型 `theorem`，其值**只能**由一小族已验证推理规则构造，系统任何其它代码无法凭空制造 theorem——**类型系统即访问控制**。【已查证】https://daicelabs.com/research/the-verification-gap-a-brief-history-of-formal-verification-from-hoare-1969-to-now

**SAT 域的格式教训（生成成本 vs 检查成本，v25 新增）**【已查证】https://m-fleury.github.io/ox-hugo/PolittFleuryBiere-SAT2023.pdf + GRAT 提案：

- **DRAT**：最易生成（SAT 竞赛标准格式），但**检查耗时常超过求解本身**——检查比求解还慢；
- **LRAT**：易于检查（带单元传播提示），但难以直接生成，无求解器原生支持；
- **FRAT**：混合过渡格式（生成接近 DRAT 成本，转换成本仍高）；
- **GRAT**：两段式——未验证的高效预处理器（gratgen）+ **经 Isabelle/HOL 形式化验证的检查器**（gratchk）；"first step only acts as certificate preprocessor, it is not part of the trusted code base"。
- **教训**：证明对象格式设计必须在"生成侧便宜"与"检查侧便宜"之间选边；把高效但不可信的预处理排除在信任库外、只让验证过的小内核进入信任库——这与 de Bruijn 判据同构。

**阙疑证明对象 schema（设计对象，非现状）**：

```yaml
ProofObject:
  claim:                      # 命题
    statement: str            # "规则 R7 对卡片 C 的 block 判定 sound"
    scope:                    # 边界三元组 B（A-3）
      mutation_set_hash: sha256
      mutation_count: int
      generator_version: str
  evidence_tree:              # 证据树（Curry-Howard 证据对象）
    nodes:
      - kind: experiment | reference | derivation | exemption
        payload: ...          # 原始记录（日志/引用/推导步/豁免四元组）
        source: str           # cppreference / 标准条款 / 实验编号
        precision: float      # 精度权重（C 方向接口）
    root_hash: sha256         # 全树哈希（挂入 append-only 台账）
  checker:
    kernel_id: str            # "pck_checker_v1"
    kernel_size_lines: int    # 可审性指标（de Bruijn：越小越可信）
    independent: bool         # 可系统外独立重查？
    checker_hash: sha256
  three_hard:                 # 三难声明（A-2）
    sacrificed: soundness | completeness | decidability
    external_oracle: str      # 人裁 / 更强元系统
  provenance:
    generator: str            # AI / 规则引擎 / 统计模型
    generated_at: ts
    trusted: false            # 生成器自陈永不入信任链（v24 M4 的强制字段化）
```

**检查算法（3 步，全部可独立重查）**：
1. **重算哈希**：evidence_tree 重算 root_hash 与声明一致；
2. **内核重放**：kernel 逐条复检 derivation 步骤，拒绝一切"跳跃"（不检查结论是否真，只检查每步是否合法——这正是 LCF 的 `theorem` 机制）；
3. **边界比对**：B 三元组与当前环境比对——mutation 集合哈希变了 ⇒ 该证书 `stale`（不是"失效"，是"需重查"）。

**可审性度量（Wiedijk de Bruijn factor 的阙疑版）**：DF = 形式证明大小 / 非形式说明大小（Wiedijk 用压缩后大小定义为 intrinsic DF）。【已查证】https://handwiki.org/wiki/De_Bruijn_Factor。阙疑应对每个内核报告 kernel_size_lines 与 DF；内核膨胀 = 信任塌缩失败。

## 二、阙疑重构草图

### 2.1 对象模型（新增三对象，不动现有对象）

- **ProofObject**（上文 schema）：证明对象，一等公民；现有 PCK 证书是其前身；
- **BoundAnnotation（B 三元组）**：边界标注，附着于一切验证结论；
- **KernelRegistry**：内核注册表（kernel_id / 行数 / 独立检查可用性 / 三难声明），组件注册表的数学分册。

### 2.2 数据流

```
候选知识 → gate 规则匹配（67 规则，近似判定）
        → 判决结果 + 证据集
        → ProofObject 生成（生成器=不可信）
        → kernel_checker 独立重查（图灵机意义上简单的检查器）
        → 三态结论：pass@B / block@B / unknown@B（B=边界三元组）
        → append-only 台账（root_hash 入链）
        → [边界漂移时] stale 标记 → 重查队列
```

与现状差异：**结论格式从三态（block/warn/pass）升级为带边界的四态（+unknown@B）**；证书从"生成即入链"改为"生成→重查→入链"。

### 2.3 关键不变量

- **INV-A1（边界附着）**：任何 pass/block 结论必带 B；无 B 的结论按 unknown 处理（A-3）。
- **INV-A2（检查器最小化）**：终审只发生在 kernel；生成器输出永远是"候选证书"（A-4/de Bruijn）。
- **INV-A3（三难声明必填）**：组件注册必须提交三难声明；缺失即拒绝注册（A-5 表）。
- **INV-A4（非同源互证）**：互查的两个实现不得共享代码路径（双实现 68.4%→100% 的教训：同源修复的是分歧不是真值）。
- **INV-A5（无自证）**：任何"元验证"不得复用同一套规则（v24 V1 的机制化：kernel 与 gate 的规则集必须不相交）。
