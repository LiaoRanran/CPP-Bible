## 一、精确表述

### C-1 ACC 冲突监测 → 独立冲突检测器

**精确模型（Botvinick 传统）**：ACC 监测的不是"对错"，而是**同时激活的互斥反应之间的冲突量**——冲突是各反应单元激活度的函数（互斥对的激活乘积之和），冲突信号本身不决定反应，只触发控制层提高投入（compensatory adjustments in cognitive control）。ERN（错误相关负波）与 FRN（反馈相关负波）是同一监测系统在"已做出反应"与"外部反馈"两条路径上的表达。【已查证】https://webapps.pni.princeton.edu/ncc/publications/2004/BotvinickTICS2004.pdf ；https://pmc.ncbi.nlm.nih.gov/articles/PMC2965315/pdf/nihms215243.pdf（Potts 2011：ERN 为单一中央成分）
**2026 证据（TD 学习的时间反向传播）**：reward positivity 被证实追踪**正向** RPE，且沿线索→反馈方向反向传播——监测系统对"比预期好"与"比预期差"双向敏感。【已查证】https://onlinelibrary.wiley.com/doi/10.1111/psyp.70308

**阙疑冲突检测器设计（输入/输出规格）**：

```
输入：evidence[]（每条：verdict_i ∈ {pass, block, neutral}, support s_i ∈ [0,1], precision w_i）
      rule_matches[]（每条：rule_id, verdict, scope）
输出：ConflictReport { type, strength C, pairs[], recommended_action }

计算（对互斥对的乘积和，归一化）：
  pairs = {(i,j) : verdict_i ⊥ verdict_j}          # ⊥ = 互斥（pass vs block）
  conflict_raw = Σ_{(i,j)∈pairs} (w_i·s_i)·(w_j·s_j)   # 互斥强度乘积和
  total = Σ_i (w_i·s_i)                                # 总证据强度
  agreement = 1 − 2·conflict_raw / total²              # 归一化一致性
  C = conflict_raw × (1 − agreement)                   # 冲突强度（brief 指定形式）
  C > θ_conflict（建议初值 0.3，待实测）⇒ 触发补偿性调整（升级复核/提高检查强度）
```

**冲突四型分类与处置（v25 新增）**：

| 类型 | 定义 | 处置（只分流，不改判） |
|---|---|---|
| R-R | 两条规则对同卡互斥判决 | 升级人审（疑似规则冲突，登记 R-R 事件） |
| E-R | 证据支持与规则判决相反 | 检查规则适用范围（可能规则越界或证据有误） |
| E-E | 两条证据互相矛盾 | 证据溯源比对 + precision 仲裁（C-3） |
| 欠定 | 无互斥但 total < θ_under | 直接 unknown（无冲突≠有把握） |

**关键边界（v24 C1/V6 的机制化）**：冲突检测器**不得 import 判决代码**（模块独立）；冲突信号不直接改判，只触发"提高检查强度"——ACC 亦如此（冲突不选反应，只加控制）。这一条写成不变量 INV-C1。

### C-2 元认知校准度：可计算定义 + 在线更新 + 降级

**精确度量（三个层级）**：

- **Brier 分数**：`BS = (1/N) Σ_i (p_i − y_i)²`，proper scoring rule（诚实报概率最优）。
- **Murphy 分解**：`BS = Reliability − Resolution + Uncertainty`
  - `Reliability = (1/N) Σ_k n_k (p_k − ō_k)²`（校准项：说的和做的差多少；越低越好）
  - `Resolution = (1/N) Σ_k n_k (ō_k − ō)²`（分辨项：能不能区分高风险/低风险；越高越好）
  - `Uncertainty = ō(1−ō)`（底率项，与预测质量无关）
  【已查证】https://scispace.com/pdf/simplifying-and-generalising-murphy-s-brier-score-3ykaymue3m.pdf ；https://stormrisk.github.io/2008/stephenson-brier.pdf
- **ECE**：分箱后 `ECE = Σ_k (n_k/N)·|acc_k − conf_k|`（LLM 评估常用）。【已查证】https://arxiv.org/html/2605.23909
- **校准 vs 分辨的区分（不可混淆）**：resolution 问"能否把会的和不会的分开"，calibration 问"整体把握感是否匹配整体表现"；可以分辨好而校准差。【已查证】https://datafield.dev/metacognition/part-03/chapter-15/key-takeaways.html

**阙疑校准追踪器（每验证器一份）**：

```
CalibrationTracker(verifier_id):
  数据：滑动窗口 W（最近 N=200 条判决，每条：(confidence p_i, truth y_i)）
  指标：ECE(W)、Reliability(W)、Brier(W)；N 足够时报告 Mratio 类指标
       （meta-d′/d′：元认知敏感度相对一阶敏感度——验证器"知道自己何时可能错"的程度）
  在线更新：每来一条真值（复核/逃逸回填）即入窗；分箱用贝叶斯平滑（先验 = 历史箱均值）
  三级降级：
    L1  ECE > θ1（0.10）：**重校准**——置信度按历史正确率重映射（isotonic/分箱映射）
    L2  Reliability 持续高企或样本不足：**禁言**——该验证器停止输出置信度（只报 pass/block），
        因"假置信"比"无置信"更有害
    L3  多次重校准失败：**降级**——退出自动判决，全部转人审队列
```

**两个统计陷阱（必须防）**：
1. **D-K 效应的回归均值人工物**：Dunning–Kruger 曲线可由边界约束+回归均值完全解释（Magnus & Peresetsky 2022："does not require any psychological explanation"）；Jansen 等大规模复制+建模（Mazor & Fleming 2021 评述）亦指向统计机理。⟹ 校准分析**必须控制回归均值**（否则会把噪声误读为系统性过度自信）。【已查证】https://public-pages-files-2025.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2022.840180/pdf ；https://static1.squarespace.com/static/5616b377e4b0670f148ff742/t/608288806174bf495dd843b2/1619167367512/MazorFleming2021_NHB.pdf
2. **hard-easy 效应**：难任务系统性过度估计、易任务不足估——校准度**必须分域（难度层）报告**，聚合值会互相抵消出假"良好"。【已查证】https://www.cogn-iq.org/learn/theory/overconfidence-bias/

**额外警告（extreme-confidence 启发式）**：仅凭"极端置信度"就能在部分数据集上构造出高于随机的元认知判别——**校准度不能只看置信度分布形态**。【已查证】https://pmc.ncbi.nlm.nih.gov/articles/PMC11110933/

### C-3 预测编码精度加权 → 证据精度 schema

**精确表述**：precision = 逆方差（1/σ²）。层级预测编码中，precision 决定各层预测误差的**增益（gain）**——高精度误差更新多，低精度误差更新少；attention 即对特定误差源的精度优化。【已查证】https://scipedia.bohrium.com/en/sciencepedia/feynman/keyword/predictive_coding ；https://pmc.ncbi.nlm.nih.gov/articles/PMC4387510/

**阙疑证据精度 schema**：

```yaml
EvidencePrecision:
  source_class: standard_text | cppreference | compiler_behavior | experiment | ai_generated | human_expert
  variance_estimate: float      # 该类源实测误差方差（在线估计，禁止手填）
  precision: 1 / variance_estimate
  modifiers:
    recency: decay_factor       # 越旧越低（半衰期，B 方向接口）
    independence: factor        # 与其它证据同源 ⇒ 降权（防重复计票，v21"他验独立"同源）
    directness: factor          # 直接观察 > 二手转述
```

**加权更新规则（精度加权平均 = 逆方差加权）**：

`belief_new = (π_prior·belief_prior + Σ_i p_i·value_i) / (π_prior + Σ_i p_i)`，其中 `p_i = precision_i`（含 modifiers）。

**两条关键限定（防万能论）**：
1. **校准与精度独立**（反直觉的一手证据）：多感官实验中，校准（长期修正）被发现**独立于线索可靠性**——precision 加权适用于**即时融合**，不适用于**慢速校准**；系统性偏差需要独立的校准机制，不能指望降权自动修复。【已查证】https://pmc.ncbi.nlm.nih.gov/articles/mid/NIHMS328320/（Zaidel 2011："Multisensory calibration is independent of cue reliability"）
2. **precision 本身会漂移**（源退化/环境变化）⟹ 需要自适应估计：Kalman 式自适应增益 + divergence 检测（预测误差持续超预期 ⇒ 提高过程噪声 ⇒ 等效降低自身精度）。工程对应场景已被明确列出：sensor degradation、model mismatch、multi-sensor fusion。【已查证】https://pytcl.readthedocs.io/en/latest/adaptive_filtering.html

**阙疑规则**：每源每季度重估 variance；单源连续 N 次（建议 5）判决被事后推翻 ⇒ 自动降 precision 并进审计（"源退化"的 divergence 检测）。

### C-4 记忆再巩固 → 重建式 replay

**精确表述**：检索不是被动读取——被检索的记忆会**去稳定化（destabilize）**，随后需要**重新稳定化（restabilize）**；再巩固有边界条件（不是所有记忆、所有条件下都发生）。【已查证】https://pmc.ncbi.nlm.nih.gov/articles/PMC7167366/（Kida 2020 原文："Memory retrieval is not a passive process"）；https://pmc.ncbi.nlm.nih.gov/articles/PMC10017482/（Ferrara 2023 boundary conditions）；https://www.frontiersin.org/journals/human-neuroscience/articles/10.3389/fnhum.2021.643106/full（Kim 2021 对"普遍属性"的挑战）
**CLS 理论（双系统，工程选型的依据）**：慢系统（新皮层：慢学、分布式、提取统计结构）+ 快系统（海马：单次经历、稀疏、模式分离）；replay 允许**按目标加权经验统计**。【已查证】https://www.psychologie.uzh.ch/dam/jcr:83bd242c-50a5-45df-919e-3c134ff6979e/Kumaran.TiCS.2016.pdf

**阙疑 replay 两版对比**：

| | 存档式（现状） | 重建式（v25 建议） |
|---|---|---|
| 操作 | 读存档证书，验证哈希一致 | 从原始证据**重新构建**证书 + **重新验证** |
| 证明什么 | 存储完整性（"文件没坏"） | 知识在**当前环境**下仍成立 |
| 漂移检出 | 无（环境变了存档不变） | 有（重建结果 vs 存档结果比对） |
| 成本 | 低 | 高 ⟹ 只对高风险子集（boundary conditions 教训） |

```
replay_v2(card):
  1. 加载原始证据（**不加载旧结论**）
  2. 重新执行验证（重跑规则、重算哈希、重新检索源）
  3. 生成 ProofObject'
  4. 比对 (ProofObject'.claim, ProofObject'.bound) 与存档
  5. 一致 → verified（刷新时间戳）；不一致 → disputed（附差异报告：哪一步变了）
```

**关键不变量（防确认偏误的机器版）**：replay 不得先读存档结论再"验证"——先看答案再验证 = 确认偏误。写为 INV-C4。

## 二、阙疑重构草图

### 2.1 对象模型（新增四对象）

- **ConflictReport**：冲突类型（R-R/E-R/E-E/欠定）+ 强度 C + 涉及对 + 建议动作；
- **CalibrationTracker**：每验证器的 ECE/Reliability/窗口/降级级别；
- **EvidencePrecision**：源精度记录（方差在线估计 + modifiers）；
- **ReplayEngine v2**：重建式重放器（步骤 1-5 状态机）。

### 2.2 数据流

```
证据 + 规则匹配 → [冲突检测层]  ← 独立模块，不 import 判决代码
    ├─ C > θ → 补偿性调整（升级复核 / 提高检查强度）
    └─ C ≤ θ → 判决层（gate/replay/人审，现状不变）
                  → 判决输出（含置信度 p）
                  → [校准追踪器]（真值回填后更新 ECE/Reliability）
                  → [证据精度]（源 divergence 检测更新 variance）
→ 周期：[重建式 replay]（高风险子集）→ 一致/不一致 → verified/disputed
```

### 2.3 关键不变量

- **INV-C1（冲突不判决）**：冲突信号只触发分流与强度提升，不改判（Botvinick 结构同构）。
- **INV-C2（禁言优于假置信）**：校准不达标的验证器停止输出置信度，不得"带病报率"。
- **INV-C3（精度实测）**：precision 必须来自实测方差与 divergence 检测，禁止人工指定"权威源高权重"。
- **INV-C4（重建防偷看）**：replay 从原始证据重建，禁止先读存档结论（防机器版确认偏误）。
- **INV-C5（分域报告）**：校准度按难度层/域报告，禁止单一聚合值（hard-easy 效应防线）。

## 三、最小原型规格（4 文件）

| 文件 | 职责 | 接口 |
|---|---|---|
| `conflict_detector.py` | 独立冲突检测（不依赖判决模块） | `detect(evidence[], rule_matches[]) -> ConflictReport`；四型分类 + 强度 C |
| `calibration_tracker.py` | 在线校准（ECE/Brier-reliability）+ 三级降级 | `update(verdict_id, p, truth)`；`level(verifier_id) -> L0|L1|L2|L3`；`report(verifier_id, domain)` |
| `evidence_precision.py` | 源精度在线估计 + divergence 降权 | `precision(source) -> float`；`observe(source, error)`；`divergence_check(source) -> flag` |
| `replay_rebuild.py` | 重建式 replay（vs 存档式） | `rebuild(card) -> ProofObject'`；`compare_with_archive(card, po') -> {consistent|drifted, diff}` |

关键测试：INV-C1（`conflict_detector` 的 import 图不含判决模块）、INV-C4（replay 函数在其调用图中不得读取 archive 结论字段）、INV-C2（L2 后 `confidence` 字段必须为空）。

## 四、迁移路径（从现有验证流水线过渡）

- **阶段 0（数据先行）**：为现有判决产物补"置信度字段"（初值可全为空）+ 真值回填通道（复核/逃逸结果挂回判决 id）。此阶段只加数据，不改逻辑。
- **阶段 1（影子冲突检测）**：`conflict_detector.py` 对历史判决离线重跑，统计冲突率与四型分布；据此回填 θ_conflict。
- **阶段 2（校准只报不降级）**：`calibration_tracker.py` 上线报告模式；θ1 从实测 ECE 分布取分位点。
- **阶段 3（重建式 replay 试点）**：对高风险子集（曾 disputed/stale 的卡片）先跑 `replay_rebuild.py`，与存档式并行比对成本与检出率。
- **不做**：全库重建式 replay（成本）；校准与精度混用（Zaidel 独立性）；用 D-K 曲线解释验证器表现（统计人工物）。

## 五、死路复核（v24 之上新增）

- **新死路 V14：冲突信号判决化**——把 C 直接当判决依据（ACC 结构否决：冲突不选反应；v24 C1/V6 的强化版）。
- **新死路 V15：精度加权万能论**——用 precision 加权承担慢速校准职责（Zaidel 2011 独立性发现否决；校准需要独立机制）。
- **新死路 V16：校准聚合幻觉**——把难易任务合并算一个 ECE（hard-easy 效应会互相抵消出假良好；必须分域）。
- **新死路 V17：偷看式 replay**——先读存档结论再验证（存档式 replay 的隐性确认偏误；重建式 replay 的动机之一）。
- 其余（更强痛感告警、主动遗忘工具、ACC 万能论、无限 replay）v24 结论不变。

## 六、置信度与诚实声明

- **高置信**：冲突监测模型与 ERN/FRN 结构（Botvinick 2004、Potts 2011）；reward positivity 追踪正 RPE（2026 Psychophysiology）；Brier/Murphy 分解（多来源一致）；校准 vs 分辨区分、hard-easy 效应、D-K 统计人工物（Magnus 2022、Mazor & Fleming 2021）；再巩固"检索非被动"与 boundary conditions（Kida 2020、Ferrara 2023、Kim 2021）；CLS 双系统与 replay 目标加权（Kumaran 2016）；逆方差加权与"校准独立于可靠性"（Fetsch 2011、Zaidel 2011）。
- **中置信**：冲突四型分类、C 公式的 θ 初值、三级降级阈值为【类比推断】（工程化首版，未经阙疑实测）；Mratio 类指标在"验证器"语境的适用性待验证。
- **待验证**：`θ_conflict=0.3`、`θ1=0.10`、divergence 连续 N=5 等参数全部需实测回填；extreme-confidence 启发式的干扰程度未在验证器场景测量。
- **边界**：本文件给机制设计与迁移阶段；再巩固/CLS 与阙疑 replay 的对应是类比（生物机制证据充分，但工程映射未验证）。
