## ① 哪 3 个外部理论对本项目价值最大、哪 3 个看似相关但实际不适用、最意外的发现

**价值最大（现在就能用、直接补缺口）：**
1. **供应链溯源证明（in-toto + SLSA + OpenTimestamps）** —— 直接封堵 585 红队实锤的 3 个 meta 层攻击（自签 checksum / manifest 不进校验 / conftest 钩子可改）。纯标准库可落地、无需硬件/LLM，是把"我相信这个 checksum"升级为"任何人可验证这条溯源链"的最短路径，也是"可换验证者"的硬前提。
2. **TLA+ / 模型检测 / 翻译验证（translation validation）** —— 把 replay(编译+sha)、队列、闸门的状态机用数学规约，使"防呆"从启发式变可证。与现有 replay 同构，可轻量引入（不需立刻上 Coq）。
3. **统计学习理论（PAC / VC 维 / Rademacher / Clopper-Pearson 本是其实例）** —— 把第一性原则"错误率有上界"从经验上界收紧为理论可证上界，定量回答"攒多少变体/样本才能宣称某错误率上界"。

**看似相关但不适用：**
1. **范畴论（抽象）** —— 对 YAML 命题图是"理论价值≫实用价值"，无具体可落地的验证收益，纯装饰性。
2. **知识图谱嵌入（TransE/ComplEx/RotatE）** —— 需训练/近似向量，与"LLM 冻结""可机核验"原则冲突；命题关系稀疏、不可训练，预测不可证。
3. **概率论证（Probabilistic AF）** —— 给论证赋概率会破坏"IN/OUT 决断"所需的零误伤决断性；概率本身不可机验（common-mode failure），与"错误率有上界"目标相悖。

**最意外的发现：**
- 项目的第一性原则"错误率有上界"**其实已经是无意识地实现了一个 PAC 式保证**（Clopper-Pearson 上界 @95% 即 PAC 风格的经验界），但缺少 VC 维/复杂度论证 → 当前上界是"统计经验"而非"理论可证"，可被更严谨的统计学习理论收紧（方向 5）。
- 而项目**最大的缺口不是缺理论，而是缺"证明/溯源层"**：585 红队能攻破的，恰恰是"没有被签名证明的溯源"。换句话说，外部理论里离项目最近的不是高深数学，而是**供应链溯源证明**这种工程框架——它直击已被攻破的信任根。

## ② 如果只允许再引入 1 个外部理论就能让阙疑从"可用"变"令人信服"，选哪个、为什么

**选：供应链溯源证明（in-toto + SLSA + OpenTimestamps）。**

- 项目最弱、且已被 585 实锤攻破的正是**信任根/溯源层**（自签 `.tool_checksums`、manifest 不在校验范围、conftest 钩子可被改）。
- in-toto 用**签名 attestation** 记录每个流水线段（build / replay / mutation / poison）的 inputs→outputs；SLSA 给成熟度等级；OpenTimestamps 给不可篡改时间戳。三者**纯标准库可落地、无需硬件/LLM、且是"可换验证者"的硬前提**。
- 它把"我相信这个 checksum"变成"**任何人都能独立验证这条溯源链**"——这才是让怀疑者信服的关键（"令人信服"= 可独立验证，而非再堆一层测试）。
- 备选的"形式上论证/证明助手"(Coq/Lean) 是理论上限，但受单用户/无 CI/Windows 约束，非单点最优；溯源证明是**现在就能交付、且直接封堵已证漏洞**的唯一杠杆。
