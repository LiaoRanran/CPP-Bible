# 02 · 方向 2：形式化验证与证明助手

> 来源：【已查证】CompCert=Leroy POPL 2006 / CACM 2009；seL4=Klein et al. SOSP 2009 / CACM 2010；TLA+=Lamport TLA 1994(ACM)、lamport.azurewebsites.net；Coq/Lean【已查证】见 web 检索。

## 2.1 方法论与工具能力边界

| 工具/方法 | 核心思想 | 能力边界 | 对本项目价值 | 成本 |
|---|---|---|---|---|
| CompCert | 编译器语义保持的机器证明 | 需 Coq + 巨大证明工程 | replay(编译+sha)可借鉴"语义保持"思路 | 极高 |
| seL4 | 微内核 fully verified | 8700 行 C 全证明 | 信任根/闸门的可验证性参照 | 极高 |
| Lean/Coq/Isabelle | 交互式证明助手,依赖类型 | 表达力强但学习曲线陡 | 命题 IN/OUT 定理化 | 高 |
| 翻译验证 TV | 只证"源→目标"结果等价,不证全过程 | 比全证明轻 | **直接对接 replay** | 中 |
| 模型检测 | 穷举状态空间验性质 | 状态爆炸 | 队列/闸门状态机 | 中(需 SPIN/TLA+) |
| 契约式设计 DbC | 前置/后置条件断言 | 易落地 | 卡面 artifact_assert | 低 |

## 2.2 本项目的 replay 与翻译验证对比
- **相同点**：都验证"转换前后语义一致"。replay = 编译卡面示例 + sha 比对；TV = 证明源与目标语义等价。
- **不同点**：replay 是**确定性抽样比对**（跑一遍看 sha），不是数学证明；TV 给出**证明对象**。
- **可借鉴**：把 replay 升级为"翻译验证"——不只比 sha，而是证明"编译产物满足卡面声明的 run_match_keys 契约"。这比上 Coq 轻得多（可在 Python 层用契约式断言实现）。

## 2.3 轻量 vs 架构级
- **轻量（现在做）**：用 TLA+ 规约 replay/队列/闸门状态机（纯文本规约，可模型检测），用 DbC 风格断言加固卡面。
- **架构级（W 档）**：用 Coq/Lean 证明 verdict 函数的正确性——成本极高，单用户阶段不值。

## 2.4 成本-收益
- 引入 TLA+/DbC：**成本=数天规约+学习；收益=把"防呆启发式"变"可证不变量"**，高性价比。
- 引入 Coq 全证明：**成本=数月；收益=数学级保证但单用户无复核者**，性价比低（与"可换验证者"目标也部分冲突——证明本身需专家）。

## 2.5 看似相关但不适用（反例）
1. **全证明助手(Coq/Lean)对 verdict 函数**：单用户、无 CI、Windows 环境，维护证明比维护测试更难，且证明正确性仍依赖"可信内核"——只是把信任根上移，未消除。
2. **模型检测全状态穷举**：命题网络 274 边状态空间爆炸，直接穷举不可行；需抽象/符号化，属研究级。

## 2.6 本项目现状
replay=编译+sha 确定性验证,无形式化证明；卡面 YAML 手工写,无自动断言验证。缺口：replay 无"语义保持"证明、卡面断言无自动校验。
