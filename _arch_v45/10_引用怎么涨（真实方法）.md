# 方向 10：引用怎么涨（真实方法）

## 核心结论
1. 对 0 影响力单人作者，引用的真实增长引擎只有三个：**(a) 你的工具被人当默认评测用（基准被复用）、(b) 一个能跑的一行安装 demo 降低采用门槛、(c) 一次在正确社区的传播**。玄学涨引用于事无补。
2. QueYi 是"验证基准"——这类工作的引用增长最快路径是**成为别人论文的 evaluation harness**（别人用你的 48 卡/452 账本测他们的模型），而非靠你发推文。所以优先级是"让别人好用"，不是"让自己有名"。
3. 诚实预期：单人首作顶会基准，第一年引用常 <20；但一旦进某 workshop 的 baseline 列表或被一篇大组论文引用，会滚雪球。把目标设为"进 3 个相关工作的 related work"，而非绝对数字。

## 精确数字与案例
- **机制证据**：LiveCodeBench、HumanEval 等基准的引用爆发，源于"被各大模型论文列为评测项"，而非作者营销。基准类论文的引用中位数远高于同质量方法论文。
- **可复用性阈值**：GitHub repo 的"一键跑通率"决定采用。QueYi 当前 813 行内核 + 9 保护器，若能提供 `pip install queyi && queyi eval --model X` 式接口，采用门槛骤降。
- **传播杠杆（按性价比排序）**：
  1. Papers with Code / Hugging Face 挂 benchmark（机器可发现）；
  2. 在 3 个对口社区发"怎么用 QueYi 测你的 C++ 模型"短文（Reddit r/MachineLearning、知乎、小红书）；
  3. workshop 演讲（见方向 06）；
  4. 找 1 位有 follower 的研究者合作转发（见方向 31–33）。
- **反模式**：买引用、互引圈、水会议——会触发方向 54/58 的诚信风险，对双非作者致命。

## 对阙疑的 3 条具体行动
1. **做"零配置评测入口"**：把 QueYi 包成 `queyi benchmark --model <path> --out report.json`，配 Colab/在线 demo；让任何人 5 分钟跑出"你的模型在 QueYi 上的 80% 检出 vs 33% 外部"对比图——这是被引的命门。
2. **主动进 baseline 列表**：投稿时联系 3 个做"C++ 代码模型/程序修复"的组，请他们把 QueYi 加进评测；在他们的 arXiv 里被引 1 次 > 你发 10 条推文。
3. **建 citation README**：在 repo 写"如果你用 QueYi 评测，请引我们的 NeurIPS E&D 2027 / arXiv:XXXX"，并给 BibTeX 一键复制——降低别人引用你的心理成本。

## 盲区（诚实标注）
- 引用增长的具体数字（第一年 <20）为行业经验值，无 QueYi 实测；需发 arXiv 后跟踪。
- "被大组引用滚雪球"依赖运气 + 主动 outreach，不可控；应把 KPI 设为"进 N 个 related work"而非绝对数。
- 中文社区（小红书/知乎）对英文顶会引用贡献弱，主要价值是国内人脉/合作（方向 41）。
