# 方向 20：变异测试算子设计（具体算子列表）

## 核心结论
1. 变异测试是 QueYi "变异测试 core 97.3% / all 81.5%" 的方法论基础；**算子设计决定 mutation score 的意义**——算子太弱（只改常量）则高分会虚高，算子强（删语句/换逻辑）才硬。
2. C++ 变异算子应覆盖：算术、关系、逻辑、位运算、赋值、常量、控制流、函数调用、指针/引用、类型转换十大类；QueYi 的 97.3% 应明确"基于哪套算子"（建议对标 muCPP / 通用算子集）。
3. 对审稿人：公开算子清单 + 每类生成的变异数 + 被 killed 比例，是 benchmark 严谨性的硬证据；模糊说"做了变异测试"会被质疑（方向 05 同类问题）。

## 精确数字与案例（具体算子列表）
**A. 算术算子**：`+↔-`、`*↔/`、`%↔*`、`++↔--`、`x+=1↔x-=1`、`x*2↔x/2`
**B. 关系算子**：`>↔<`、`>=↔<=`、`==↔!=`、`a>b↔a>=b`
**C. 逻辑算子**：`&&↔||`、`!expr` 删除、`true↔false` 常量
**D. 位运算**：`&↔|`、`^↔&`、`<<↔>>`、`~x` 删除、`x&1↔x|1`
**E. 赋值算子**：`=`↔`+=`、`x=y↔x=0`、`a=b↔a=a`
**F. 常量算子**：`0↔1`、`1↔2`、`0.0↔1.0`、`NULL↔非NULL`、`index↔index+1`（边界）
**G. 控制流算子**：`if(c)` 删条件体、`break↔continue`、`return e↔return 0`、循环边界 `i<N↔i<=N`、死代码插入
**H. 函数调用算子**：`f(x)↔f(y)`（参数替换）、`f()↔0`（返回值替换）、`f()↔g()`（同类函数替换）、删调用
**I. 指针/引用算子**：`->↔.`、`*p↔p`、`&x↔x`、指针偏移 `+1↔-1`
**J. 类型/转换算子**：`(int)↔(float)`、`static_cast↔reinterpret_cast`、`const` 去/加、`signed↔unsigned`

- **算子强弱分级**：弱（常量 0↔1、关系 >↔<）易被测；强（语句删除、逻辑 &&↔||、控制流）才是真压力。QueYi 应报告"强算子子集的 mutation score"以证严。
- **等价变异（equivalent mutants）**：部分变异在语义上与原程序等价（无法被任何测试 kill），需人工审查或工具判等；这会影响"all 81.5%"的解释——建议报告"等价变异数"以透明。
- **案例**：已有 C++ 变异框架 muCPP、Mull、Cream；它们的算子集可作 QueYi 的对标基线。

## 对阙疑的 3 条具体行动
1. **公开算子表 + 计数**：在附录列上述 10 类算子，每类生成变异数 N_i 与被 killed 数 K_i，computed mutation score = ΣK/ΣN；让 97.3% 可追溯。
2. **报告强算子子集分**：单独给出"控制流+逻辑+语句删除"子集的 score，证明不是靠弱算子刷分。
3. **处理等价变异**：人工审查或标记等价变异数 M_eq，最终 score 分母剔除 M_eq 并说明，避免 reviewer 质疑"81.5% 是否含无法 kill 的等价变异"。

## 盲区（诚实标注）
- "97.3%/81.5%"来自 brief 锚点，未核实是基于哪套算子；写稿前必须对应到具体算子表（盲点，行动 1）。
- 等价变异的判定在 QueYi 中若未做，会削弱 score 可信度；需补或透明声明。
- 现有 C++ mutator（Mull/muCPP）的算子覆盖可能与我列的不完全一致，应核对后采用业界命名。
