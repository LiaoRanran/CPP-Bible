# 方向 56：单人开源项目收入来源

## 核心结论
1. 单人开源项目**几乎不可能靠"开源本身"养活自己**（除极少数爆款）；现实收入是**"开源做名片 + 服务/就业/赞助变现"**的组合。对 QueYi：最大变现不是卖软件，而是**用它拿到更好的工作/读研/合作机会**（方向 42/44）。
2. 可选通道（按单人可行性排序）：**① 就业/实习（最高回报）② 企业赞助/合同 ③ GitHub Sponsors/Open Collective ④ 咨询/定制 ⑤ 内容（课程/书）⑥ grant（方向 55，已收紧）**。
3. 对 QueYi 的独特点：它的"可审计验证"对企业合规有真实价值 → **企业赞助/合同**（如存储厂商验证固件）比个人赞助更实在。

## 精确数字与案例
- **赞助现实**：GitHub Sponsors 对非爆款项目月入常 <$100；Open Collective 透明账本（呼应 QueYi 可审计理念）适合接企业赞助。
- **就业回报**：一个能跑的开源系统（QueYi）对求职/读研的溢价远高于赞助收入——**这是主赛道**。
- **Tidelift**：为开源维护者按"企业依赖的包"付费；QueYi 若被企业依赖可申报。
- **咨询/合同**：把 QueYi 的验证能力包装成"AI 生成代码审计"服务，按项目收费。
- **案例**：多数单人 FOSS 作者收入 = 主职 + 少量赞助；纯靠开源者极少（多为爆款如 curl）。
- **反模式**：为钱做"开源"，偏离研究目标 → 两头空。

## 对阙疑的 3 条具体行动
1. **明确主KPI是机会而非现金**：把 QueYi 当"求职/读研/合作"的杠杆（方向 42/44/31），赞助当 bonus。
2. **开 Open Collective**：透明账本接小额赞助 + 展示可审计治理，与项目理念一致。
3. **试企业合同**：向本地存储/芯片厂商提"付费的 AI 代码审计小项目"，用 QueYi 交付——比 grant 快、比赞助实。

## 盲区（诚实标注）
- 具体赞助/合同金额无 QueYi 实测；均为行业经验值。
- 企业是否愿为"单人开源验证工具"付费未知；需实际谈。
- 国内开源变现（如 Gitee 赞助、企业开源计划）生态弱于国际，需另探。
