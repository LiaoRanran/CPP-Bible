# 方向 52：12–18 个月后会被追上吗

## 核心结论
1. **"宽泛的代码验证"会被追上（已成红海）**；**"C++ 知识 + 可审计哈希链"的组合 12–18 个月内被完全追上的概率中等偏低**——因为它是"冷门领域 + 非热点机制"，大组不稀罕做，大厂不聚焦。
2. 最可能的"追兵"是：① 你方向 49 里的 TC-Bench/Code2Bench 团队扩到 C++；② 某个 SE 组把"可审计"加进他们的 benchmark；③ 大厂开源一个"code verification benchmark"。三者都在 12–18 个月内可能发生。
3. 对策不是"跑更快"（单人跑不过组），而是**绑定生态 + 抢时间戳**：arXiv 早发（方向 09）+ 让 QueYi 被引用（方向 10）+ 用"可审计"制造不可比性。

## 精确数字与案例
- **追兵概率（我的判断，低置信）**：
  - TC-Bench/Code2Bench 扩 C++：**中**（它们做通用代码评测，扩语言自然）；
  - SE 组加"可审计"：**中低**（append-only 哈希链在 SE benchmark 罕见）；
  - 大厂出 code verification benchmark：**中**（如 Meta 自评开源化，方向 50）；
  - 直接复刻 QueYi 组合：**低**（冷门 + 无热点激励）。
- **时间窗**：NeurIPS 2027 投稿（约 2027-05）前，最可能的追兵（TC-Bench 系）可能已扩 C++——**所以你应在 related work 提前对比，把"可审计 + 知识语义"钉死为差异**。
- **案例**：LiveCodeBench 被广泛采用后，"抗污染代码基准"迅速变挤；QueYi 应吸取教训，靠"可审计"而非"抗污染"（后者已被占）立身。
- **护身符**：时间戳（arXiv）+ 生态（被引）+ 不可比性（哈希链）。

## 对阙疑的 3 条具体行动
1. **12 个月内抢发**：2026-10 发 arXiv v0.1（方向 09），建立时间优先，防被抢。
2. **季度竞品扫描**：每季度搜"code verification benchmark"新论文，更新 related work；发现追兵立即在稿里对比。
3. **绑定不可比维度**：把"可审计/第三方可校验"写成核心差异化，使"被追上准确率"不等于"被取代"。

## 盲区（诚实标注）
- "概率中等/中低"是我的主观判断，无数据支撑；不应作为唯一依据。
- 我无法预测 2026-2028 是否有大组突然转向此方向；冷门不等于无人。
- 若 TC-Bench 系已在做 C++（未确认），本判断需立即修正。
