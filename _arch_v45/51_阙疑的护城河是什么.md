# 方向 51：阙疑的护城河是什么

## 核心结论
1. QueYi 的护城河**不是"验证算法"**（会被复制），而是四样叠加：**(a) append-only 哈希链 + Merkle checkpoint 的可审计性、(b) C++ 知识语义的领域深度、(c) 累积的 corpus（48 卡 + 452 账本）、(d) 三编译器差异的独特数据**。单点都可被抄，组合 + 时间积累难抄。
2. 最硬的护城河是 **(a) 可审计性**：它不是"更准"，而是"别人凭什么信"——这是结构性差异（监管/科研刚需），不是性能差异（可被超越）。
3. 第二硬的是 **(c) corpus 的时间积累**：每多一卡/一夹具都是沉没成本堆高的壁垒；对手要从零复刻需同等时间。

## 精确数字与案例
- **可审计性**：append-only 哈希链 + Merkle checkpoint ⇒ 任意历史点可第三方校验（类比证书透明度 CT 日志）。对手很难在"同样便宜"下提供等价保证。
- **领域深度**：C++ UB（方向 16）+ 编译器差异（方向 17）+ 真实 bug（方向 18）三类数据叠加，是"懂 C++"的壁垒，非通用代码评测可比。
- **corpus 积累**：48 卡（26 verified + 3 red-team + 19 draft）+ 15 夹具 + 20 外部；每卡都是独立工作的沉淀。
- **案例类比**：LiveCodeBench 的护城河是"持续更新 + 被引用生态"，类似地 QueYi 的护城河是"可审计 + 领域积累"。
- **反例**：若护城河只是"四态判决"这个概念，3 个月可被复刻——所以必须把"哈希链 + corpus"作为核心叙事。

## 对阙疑的 3 条具体行动
1. **把可审计性放第一卖点**：intro/abstract 首句即"auditable"，并给 `verify-chain` 演示（别人抄不走"证据链"叙事）。
2. **持续堆 corpus**：每月加 ≥2 卡/1 夹具，公开 build log（方向 33），把时间积累显性化。
3. **固化三编译器数据**：把 GCC/Clang/MSVC 差异固化为专有数据集，标注为"collected by us"——独特资产。

## 盲区（诚实标注）
- "组合护城河"是否真能挡住有资源的大组，无实证；大组若投 10 人也能快速积累 corpus。
- 可审计性若被标准化（如行业推签名推理日志），优势削弱（方向 47/50）。
- corpus 的"独特性"需确认没有公开等价集（如某些 C++ bug 数据库）——需检索核对。
