# 方向 33：怎么在学术界建立存在感

## 核心结论
1. 0 影响力作者的"存在感"不能靠刷脸，只能靠**可被发现的工作**：arXiv 预印本 + GitHub 可跑系统 + 在正确社区被引用（方向 10）。存在感 = "别人搜 C++ verification 时第一个看到你"。
2. 低成本高杠杆动作：**(a) 在 3 个对口 workshop 讲 poster（方向 06）、(b) 在 arXiv/朋辈社区持续更新、(c) 主动给相关论文写公开 review/评论、(d) 成为某 benchmark 的默认评测（方向 10）**。
3. 对双非单人，存在感的正循环是：**QueYi 被 1 个大组用作 baseline → 他们引你 → 你出现在更多 related work → 导师/合作者主动找你**。起点是让系统"极易被采用"（方向 10 的零配置接口）。

## 精确数字与案例
- **可发现性杠杆（按性价比）**：
  1. Papers with Code 挂 benchmark（机器检索）；
  2. arXiv 作者页（Google Scholar 自动建）；
  3. GitHub Topics 标签（`cpp-verification` 等）；
  4. 中文社区（知乎/小红书）做"科普 + 链接"，引国内合作（方向 41）。
- **案例**：LiveCodeBench 作者靠持续更新 + 被大模型论文引用，2 年内成代码评测默认基准；起点只是 arXiv + GitHub。
- **主动曝光**：在 Twitter/X 发"QueYi v0.2 更新：盲 holdout 80%→X%"，@ 相关研究者；但单人无 follower 时效果有限，需找有 follower 的合作者转发（方向 31/32）。
- **反模式**：水会议蹭作者、买引用、标题党——一次翻车毁所有（方向 58 诚信）。

## 对阙疑的 3 条具体行动
1. **占 3 个发现入口**：arXiv + Papers with Code + GitHub Topics 全部挂 QueYi，确保"搜得到"。
2. **做 1 个 workshop poster**：2027 相关 workshop 投短文 + 现场讲，面对面建 5 个有用联系（比线上发 100 封冷邮件转化高）。
3. **公开 build log**：在 repo 写"每月进展"笔记（含失败），展示持续工作——reviewer 爱看"活的"项目而非一次性稿。

## 盲区（诚实标注）
- "被大组引用"是外部不可控，需把 KPI 设为"进 N 个 related work"而非绝对名气。
- 中文社区对英文引用贡献弱，主要价值是国内人脉（方向 41/43）。
- X/Twitter 在国内访问受限，需权衡精力分配。
