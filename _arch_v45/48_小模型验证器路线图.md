# 方向 48：小模型验证器路线图

## 核心结论
1. 用"大模型自己验证"成本高、且不可审计；**小模型验证器**（专门训练/微调的 code verifier）是更便宜、更快、可部署的方向——QueYi 可作为"小验证器"的**评测基准与裁判**，而非自己做验证器。
2. 路线图分三步：**(1) 用 QueYi 的 48 卡 + 452 账本做训练/评测数据；(2) 训练/微调小型 verifier 判定四态；(3) 用 QueYi 的哈希链记录其判决，保证可审计**。这样 QueYi 从"验证系统"扩展为"验证器生态的基准"。
3. 对审稿人：提出"小验证器 + 可审计基准"的组合，比单纯"大模型自检"更工程化、更可信，也呼应 E&D 的"数据集/基准"定位。

## 精确数字与案例
- **小验证器动机**：大模型自检每次调用昂贵且慢（vs QueYi 0.59ms/卡本地判决）；小 verifier（1–7B）可本地部署、低延迟。
- **数据来源**：QueYi 的 48 卡（26 verified + 3 red-team + 19 draft）+ 15 真实缺陷夹具 + 外部 20 条 = 可作 verifier 的**监督数据**，标签是四态判决（金标准）。
- **案例**：已有工作训练"reward model for code"（如 CodeRL、过程奖励模型）用编译器/测试作监督；QueYi 的四态 + 哈希链可作更强监督信号（含审计）。
- **评测**：用盲 holdout（20 样本）作小 verifier 的测试集，比照 QueYi 自身 80% 检出，看小模型能否接近——这是自然的实验。
- **风险**：48 卡太少训练不足；需扩到数百卡或用 LLM 蒸馏（但注意污染，方向 02）。

## 对阙疑的 3 条具体行动
1. **把 QueYi 定位成"小验证器的基准"**：稿件加一节"QueYi as a benchmark for compact verifiers"，展示如何用四态标签监督小模型。
2. **跑一个 baseline**：微调一个 1–7B 模型（或 prompt 一个开源小模型）在 QueYi 卡上判四态，报准确率，作为"系统 vs 小模型"对比。
3. **扩 corpus 到 ≥100 卡**：小验证器需要更多数据；把扩 corpus 列为 2027 核心工作（也提升盲 holdout 统计力，方向 03）。

## 盲区（诚实标注）
- 微调小模型需要算力（GPU）；单人资源有限，可能只能 prompt 评测而非训练——需评估。
- 48 卡做训练严重不足，本路线图依赖扩 corpus（未完成）。
- "小 verifier 能否接近大模型"是开放问题，无先验答案。
