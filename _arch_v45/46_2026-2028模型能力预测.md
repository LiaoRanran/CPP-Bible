# 方向 46：2026–2028 模型能力预测

## 核心结论
1. 2026–2028 的确定性趋势：**推理时计算（test-time compute）持续加码、代码能力继续逼近"能写对"、agent 化落地**；但**"能写对"与"能被信任"之间仍有鸿沟**——这正是 QueYi 的窗口：越强的模型越需要独立验证，而非自证。
2. 对 QueYi 的启示：**不要押注"模型变弱"**（不会），要押"模型越强、验证越刚需"——因为高价值场景（存储固件、航天、医疗）对 AI 生成代码的**可审计信任**要求只增不减。
3. 风险：若模型内置"自我验证"足够强（方向 47），外部验证被边缘化；QueYi 的对策是转向"**独立第三方可审计**"（哈希链 + 基准），而非"我比模型更聪明"。

## 精确数字与案例
- **推理模型**：2024–2026 从 o1 到各家"thinking"模型，test-time compute 成标配；代码任务上"生成 + 自检"闭环渐强。
- **代码基准进展**：HumanEval 早已饱和（>90%），基准转向更难、更抗污染（LiveCodeBench、TC-Bench、Code2Bench，方向 49）。
- **agent 化**：2026 年 agent 执行真实任务（写代码/改仓库）爆发，但**可靠性/审计**成瓶颈——QueYi 的"可审计判决"正对痛点。
- **案例**：即使 2026 最强模型，C++ UB 类知识错误仍高频（方向 16/18）；模型"自信地说错"（arXiv 2512.07404 "Do LLMs Trust the Code They Write?"）是新问题。
- **预测（低置信）**：2028 前模型在"单文件代码正确率"或达 90%+，但在"跨编译器 UB/知识边界"仍低于人类专家——QueYi 护城河。

## 对阙疑的 3 条具体行动
1. **framing 转向"可审计"**：稿件不主张"我们比模型强"，而主张"我们提供独立、防篡改的信任层"——模型越强越需要（抗趋势淘汰）。
2. **持续 benchmark 化**：把预测写进 intro motivation，说明 2026–2028 验证需求上升，引方向 49/50 的工作做证据。
3. **跟踪前沿**：每季度读 1 篇"LLM code verification"新论文（方向 49），更新 related work，防被说服力更强的叙事盖过。

## 盲区（诚实标注）
- 能力预测本质是高不确定性，本文件为趋势判断非精确预言；不应作为唯一决策依据。
- 我未做实证模型在 C++ UB 上的逐年错误率曲线（缺数据）；若有需补实验。
- 若 2027 出现"内置强验证"突破（方向 47），本方向结论需重估。
