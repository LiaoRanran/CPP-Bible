## 一、架构思想层

### 1.1 红队提示词 v1.0（鉴别诊断+对照实验+错误预测）

**文件位置**：`prompts/redteam_v1.0.md`（新建 `prompts/` 目录）

**提示词正文**：

```
# 红队审查员 v1.0

你是独立红队审查员。你的任务是找出原子草稿中的错误，不是证明它正确。
你与 Writer 使用不同模型/不同方法——你不读 Writer 的草稿全文（P1-1），只读夹具源码、工件（.asm/.out）、证据卡 actual。

## 铁律
1. 先列假设，再验证。不先下结论（防 premature closure）。
2. 每个关键发现必须有「对照实验」或「工件证据」，不接受「我觉得」。
3. 修复循环 ≤2 轮，超限升级人审。
4. 报告最后必须含「下一批错误预测」≥3 条。

## 第一步：鉴别诊断（Differential Diagnosis）
列出 3–5 个最可能的错误假设，按「概率+严重性」排序：
- [高概率/高严重] 假设1：____
- [中概率/高严重] 假设2：____（can't-miss，即使概率低也必须排除）
- ...

can't-miss 错误清单（每批必须排除）：
- [ ] 自证断言（夹具自定义函数使断言恒真，P4）
- [ ] 恒真观测（actual 只有存在性判断，无判别力，P6）
- [ ] 口径不统一（不同策略用不同口径算同一指标，ALLOC-002 教训）
- [ ] 消除与失败不可区分（dtor=0 是泄漏还是被编译器消除？LEAK-001 教训）
- [ ] 对照被污染（对照实验有多个变量同时变化，SHARED-002 教训）
- [ ] claim 规格本身错误（格式对但内容错，False Axioms）

## 第二步：逐个验证
对每个假设，设计「测试」（夹具检查/工件检查/对照实验）并执行：
- 假设1 → 测试：____ → 结果：排除/确认/待查
- ...

## 第三步：严重度分级
- 🔴 阻断（block）：claim 错误/证据不可复核/卡与工件不符
- 🟠 高（high）：论证有漏洞/对照不严谨/缺活性对照
- 🟡 建议（suggestion）：可改进但不影响正确性

## 第四步：下一批错误预测
基于本批发现的错误模式，预测下一批可能出现的同类错误 ≥3 条：
1. 预测：____（依据：本批 XX 错误的同类扩展）
2. ...

## 输出格式
### 鉴别诊断清单
（3-5 个假设，含 can't-miss 检查结果）

### 验证记录
（每个假设的测试方法+结果+证据）

### 缺陷清单
（🔴/🟠/🟡 分级，每条含：位置/问题/证据/修法建议）

### 下一批错误预测
（≥3 条）
```

**验收标准**：
- [ ] 文件存在 `prompts/redteam_v1.0.md`
- [ ] 含鉴别诊断步骤（先列假设再验证）
- [ ] 含 can't-miss 清单（≥6 条）
- [ ] 含对照实验要求
- [ ] 含错误预测（≥3 条）
- [ ] 含严重度三级分级

**优化位置（v1.0 → v1.1）**：
- [OPT-1] can't-miss 清单需要根据每批实际命中情况动态更新（当前是第五批教训的静态清单）
- [OPT-2] 错误预测的命中率追踪机制未实现（需配合 docs/failure_mode_predictions.md）
- [OPT-3] 对照实验的「单变量」检查目前是人工判断，未来可加 gate 规则自动检查夹具是否有多个变量同变

```markdown
## claim 契约（v0.1 试点）

### 一句话 claim
<单句可证伪>

### precondition（前提条件）
在什么条件下此 claim 成立：
- 条件1：____
- 条件2：____
（如：编译器版本 ≥ C++17、对象非 const、单线程环境）

### postcondition（后置断言）
claim 成立时，什么必须为真：

（如：sizeof(unique_ptr<int, EmptyDel>) == 8、输出包含 "hello"）

### invariant（不变量）
在整个过程中始终保持真的性质：
- 不变量1：____
（如：引用计数 ≥ 1、资源指针非空）

### 规格独立性检查
此 claim 的关键数字是否有独立于 Writer 夹具的验证？
- [ ] 是：验证方法 ____（如：标准条文交叉验证/另一种实现重算/红队对照实验）
- [ ] 否：⚠️ 高风险，False Axioms 可能（ALLOC-002 教训）

### 可证伪性
什么观测会推翻此 claim：____
```

### 2.1 T3 混合检索 v0.1（knowledge_search.py）

**文件位置**：`tools/knowledge_search.py`（新建）

**功能规格**：
- 输入：查询关键词（支持多词 AND）
- 输出：相关原子 + 证据卡 + 误解 + 夹具，按相关度排序
- 三路并行：
  1. **frontmatter 精确过滤**：在 atoms/evidence/misconceptions 的 frontmatter 中搜关键词（id/type/serves/tags）
  2. **正文关键词搜索**：在正文 markdown 中搜关键词（grep 式，带行号）
  3. **图遍历**：从匹配的原子出发，沿 prerequisite/contrasts/extends 边遍历 1 跳，返回关联原子

**实现要求**：
- 纯 Python 标准库（re/os/json/argparse），不依赖外部包
- 索引在运行时构建（不预建索引文件，v0.1 简化）
- 输出格式：`[相关度] 类型:ID — 标题 — 路径:行号`
- 支持 `--limit N`（默认 20）
- 支持 `--type atom|evidence|misconception|all`（默认 all）

**验收标准**：
- [ ] 文件存在 `tools/knowledge_search.py`
- [ ] `python tools/knowledge_search.py "移动语义"` 返回 ≥5 条结果（含 MOVE-002/RVREF-001 等）
- [ ] `python tools/knowledge_search.py "RAII" --type atom` 只返回原子
- [ ] `python tools/knowledge_search.py "不存在的关键词xyz123"` 返回空（不报错）
- [ ] `python -m py_compile tools/knowledge_search.py` 通过
- [ ] 前端无外部依赖（import 仅限标准库）

**优化位置（v0.1 → v1.0）**：
- [OPT-13] 无语义检索（当前只有关键词），v1.0 加 embedding 语义检索（需评估依赖）
- [OPT-14] 无预建索引（每次运行时扫描），原子 >100 时会慢，v1.0 加索引缓存
- [OPT-15] 相关度排序目前是「命中数」，v1.0 加 TF-IDF 或字段权重（frontmatter 命中 > 正文命中）
- [OPT-16] 图遍历目前 1 跳，v1.0 加可配置跳数和环路检测

### 2.2 T4 分层记忆 v0.1（memory_manager.py）

**文件位置**：`tools/memory_manager.py`（新建）

**功能规格**：
- 三层记忆：
  - **core**（`Memory/core.md`）：当前批次状态，由系统维护，Agent 只读+追加
  - **recall**（`Memory/recall.md`）：最近 N 批的归档，append-only，自动追加
  - **archive**（`Memory/archive/`）：更老的归档，按日期分文件
- 三个命令：
  - `python tools/memory_manager.py recall <keyword>`：在 core+recall+archive 中搜关键词
  - `python tools/memory_manager.py archive "<内容>"`：把内容追加到 recall（append-only，不替换）
  - `python tools/memory_manager.py rotate`：把 recall 中超过 30 天的条目移到 archive/YYYY-MM.md
- **安全约束**：
  - core.md 只有系统（脚本）能写，Agent 不能直接修改
  - 所有写入都是 append-only，不替换/不删除
  - 不可信内容（用户输入）不能直接写入 core，只能写入 recall 并标注 `[untrusted]`

**实现要求**：
- 纯 Python 标准库
- core.md 格式：`## YYYY-MM-DD\n- <条目>`（每条一行）
- recall.md 格式同上，按日期倒序
- archive/YYYY-MM.md 格式同上
- rotate 命令：读取 recall.md，把超过 30 天的条目移到对应 archive 文件，recall 保留最近 30 天

**验收标准**：
- [ ] 文件存在 `tools/memory_manager.py`
- [ ] `python tools/memory_manager.py archive "测试条目"` 后，recall.md 末尾含「测试条目」
- [ ] 再次 archive 不覆盖已有内容（append-only 验证）
- [ ] `python tools/memory_manager.py recall "测试"` 返回含「测试条目」的结果
- [ ] `python tools/memory_manager.py rotate` 不报错（即使没有超 30 天条目）
- [ ] core.md 不存在时，recall 命令仍能工作（只搜 recall+archive）
- [ ] `python -m py_compile tools/memory_manager.py` 通过

**优化位置（v0.1 → v1.0）**：
- [OPT-17] 无「记忆完整性检查」（每批开始时验证 core 包含必要状态），v1.0 加 `memory_manager.py check` 命令
- [OPT-18] 无自动归档触发（当前需手动 rotate），v1.0 可集成到 pre-push hook 或 CI
- [OPT-19] recall 搜索目前是关键词匹配，v1.0 加日期范围过滤和标签过滤
- [OPT-20] 无「记忆失明」检测（编排失败是静默的，MemGPT 教训），v1.0 加定期校验：core 中的关键 ID 是否仍能在 recall/archive 中找到
