# 445 对"系统极限"的再批判：前沿研究能否突破 444 定义的四道墙？

> 日期：2026-09-13。444 定义了四道"做不到"的墙：100% 语义正确、零成本、完全自治、零误报。本轮调研前沿研究，逐条检验这些墙是"真极限"还是"当前认知的极限"。

---

## 一、第一道墙：100% 语义正确——真的做不到吗？

### 444 的说法

语义理解本身是开放问题，红队也会漏，100% 语义正确做不到。

### 前沿研究：形式化验证 + LLM 的混合架构

**LeanTutor（arXiv 2601.17473）**：数学证明辅导系统，LLM 用自然语言与学生交互，Lean 定理证明器在后端检查证明正确性。每一步自动形式化，每一步编译检查。

**PALM（Purdue）**：分析 520 个 GPT-3.5 证明错误，发现 LLM 经常识别正确的高层结构，但低层细节出错。提出 generate-then-repair：LLM 生成初始证明，符号方法迭代修复低层问题。

**Seed-Prover 1.5**：用 agentic RL 训练的形式化定理证明模型，通过与 Lean 大规模交互学习。

**关键洞察**：LLM 擅长高层结构，不擅长低层细节；形式化验证器提供 100% 正确的 ground truth。两者结合 = "LLM 生成 + 验证器检查"的混合架构。

### 对阙疑的冲击

C++ 的语义可以分为两类：

| 类别 | 可形式化？ | 验证器 | 阙疑现状 |
|---|---|---|---|
| 类型系统 | 是 | 编译器（-fpermissive 检查） | 已有（编译失败=refute） |
| 内存模型 | 部分 | sanitizer（ASan/TSan/UBSan） | 已有（sanitizer 检查） |
| UB | 部分 | UBSan + 静态分析 | 部分（UBSan 检查） |
| 性能 | 否 | 无（性能是经验的） | 实测（但不形式化） |
| 教学正确性 | 否 | 无（学生理解是主观的） | 人审 |

**结论**：100% 语义正确不是"全有或全无"——可形式化的部分（类型/内存/UB）可以做到 100%，不可形式化的部分（性能/教学）做不到。

**阙疑已经在做可形式化部分的 100% 验证**（编译+sanitizer），但可以更系统：
- 用 Clang Static Analyzer 做更深入的静态检查（当前只用了编译+sanitizer）
- 用 C++ 标准的形式化模型（如 cppreference 的规则）做 claim 的"可证伪性检查"
- 把"claim 是否与标准矛盾"变成机器可查的（用标准条文作为 ground truth）

**修正后的极限**：可形式化语义 100% 正确，不可形式化语义高概率正确。不是"100% 做不到"，是"部分做得到"。

## 二、第二道墙：零成本——真的做不到吗？

### 444 的说法

红队/人审需要 token，这是"质量税"，零成本做不到。

### 前沿研究：自我改进系统的成本曲线

**Self Rewarding Self Improving（arXiv 2505.08827）**：模型可以通过 self-judging 自我改进，不需要 reference solutions。核心洞察：**生成和验证之间存在不对称性——验证比生成容易**。如果系统能验证自己的输出，就可以用验证信号做奖励，不需要人工标注。

**ARISE-RL（arXiv 2609.01058）**：rubric-mediated co-evolution，Generator 生成任务和评分标准，Solver 解决任务，两者共同进化。

**关键洞察**：自我改进系统的成本曲线是**递减的**——初期需要大量人工（红队/人审），但随着规则积累，越来越多的检查变成零成本的机器检查。长期来看，边际成本趋近于零。

### 对阙疑的冲击

阙疑的成本结构：

| 阶段 | 成本来源 | 成本趋势 |
|---|---|---|
| v6.0（当前） | 红队+人审+双平台 replay | 高（每颗 6 窗口） |
| v7.0 | Writer 自检拦住形式错误，红队只看语义 | 中（每颗 2-3 窗口） |
| v8.0 | claim 契约化+活性对照自动化，红队只看深层语义 | 低（每颗 1-2 窗口） |
| v9.0 | 自动毒样例生成+持续对抗，人审只做 DAL A | 极低（每颗 <1 窗口） |

**关键机制**：红队发现的问题→变成规则→规则零成本运行→红队不需要再查这类问题→红队可以往更深的地方挖→发现新问题→变成新规则。这是一个**正反馈循环**，成本随时间下降。

**修正后的极限**：零边际成本做得到（当所有已知问题都变成规则后），但零总成本做不到（因为新问题永远需要红队去发现）。不是"零成本做不到"，是"零边际成本做得到，零总成本做不到"。

## 三、第三道墙：完全自治——真的做不到吗？

### 444 的说法

校准需要外部 ground truth，完全自治=无法校准。

### 前沿研究：自校准 Agentic AI

**自校准 Agentic AI 框架（arXiv 2607.22400）**：用 ARIMA 预测器动态近似 ground truth，不需要持续人工监督。核心：系统自己预测"正常应该是什么样"，然后用预测值作为 ground truth。

**Self-Correcting DRL Agent（SAI 2024）**：用 Digital Twin 作为漂移无关的参考，Agent 学会区分"不可靠的传感器"和"可靠的 DT 预测"，实现实时自动校准。

**RefGRPO（arXiv 2606.14211）**：free calibration bonus——反思与结果一致时给奖励，训练模型的校准能力。

**关键洞察**：ground truth 不一定是"人工标注"，可以是"可验证的外部信号"（编译器输出、测试结果、形式化验证）。如果系统的输出可以被外部验证器检查，就不需要人工 ground truth。

### 对阙疑的冲击

阙疑的校准信号：

| 校准信号 | 来源 | 是否需要人 |
|---|---|---|
| 编译成功/失败 | 编译器 | 否 |
| sanitizer 报告 | ASan/TSan/UBSan | 否 |
| replay confirm/refute | 机器比对 | 否 |
| 红队评分 | LLM | 否（但 LLM 本身需要校准） |
| 人审签署 | 人 | 是 |
| 学生学习效果 | 学生反馈 | 是（长期） |

**阙疑已经有大量不需要人的校准信号**（编译/sanitizer/replay）。人审只做 DAL A/B（高风险），DAL C/D/E 机器自动 verified。

**完全自治的条件**：如果系统的所有输出都可以被外部验证器检查（编译+测试+形式化验证），就可以完全自治。阙疑的"教学正确性"无法被外部验证器检查，所以需要人审。

**修正后的极限**：可验证部分完全自治做得到（编译+sanitizer+replay 都是自动的），不可验证部分（教学效果）做不到。不是"完全自治做不到"，是"可验证部分自治做得到，教学效果自治做不到"。

## 四、第四道墙：零误报——真的做不到吗？

### 444 的说法

规则越严误报越多，信噪比是永恒的权衡，零误报做不到。

### 前沿研究：自适应规则 + LLM 分类器

**AutoSpec（arXiv 2606.24245）**：用归纳逻辑编程自动进化安全规则。核心：counterexample mining——误报和漏报作为反馈信号，自动精炼规则。

**Argos（arXiv 2501.14170）**：LLM 自动生成异常检测规则，F1=0.936。FN Rules Only 提高召回率，FP Rules Only 提高精确率。

**LLM-Driven 静态分析误报缓解（arXiv 2511.04023）**：用 LLM embedding + 学习分类器区分真漏洞和误报。误报率从 42% 降到 17%。

**自适应阈值**：静态阈值误报 20-40%，自适应基线降到 5-15%。

**关键洞察**：误报率不是固定的——可以通过自适应规则和 LLM 分类器持续降低。但零误报意味着零召回（不检查就没有误报），这是 No Free Lunch 定理。

### 对阙疑的冲击

阙疑的误报治理：

| 方法 | 误报率 | 现状 |
|---|---|---|
| 静态规则（当前） | ~53%（32 条 warn 中 17 条 MATRIX 误报） | 已有 |
| 规则质量评估（拦截率） | 可降低 | 437 设计，待落地 |
| 自适应阈值（根据历史数据调整） | 5-15% | 未做 |
| LLM 分类器（区分真问题和误报） | 可降到 17% | 未做 |
| 规则自动进化（counterexample mining） | 持续下降 | 未做 |

**阙疑可以做的**：
1. 每条规则记录"历史误报率"（这条规则在多少张合法卡上误报了）
2. 误报率高的规则自动降级（从 block 降为 warn，从 warn 降为 advice）
3. 用 LLM 做"误报二次筛选"（gate 报 warn 后，LLM 判断是不是真问题）
4. 规则自动进化（误报作为反馈，自动调整规则条件）

**修正后的极限**：零误报做不到（No Free Lunch），但误报率可以从 53% 降到 5-15%。不是"零误报做不到"，是"低误报做得到，零误报做不到"。

## 五、综合结论：四道墙的真实高度

| 墙 | 444 的说法 | 前沿研究修正后 |
|---|---|---|
| 100% 语义正确 | 做不到 | 可形式化部分做得到（类型/内存/UB），不可形式化部分（性能/教学）做不到 |
| 零成本 | 做不到 | 零边际成本做得到（规则积累后），零总成本做不到（新问题永远需要红队） |
| 完全自治 | 做不到 | 可验证部分自治做得到（编译/sanitizer/replay），教学效果自治做不到 |
| 零误报 | 做不到 | 低误报做得到（5-15%），零误报做不到（No Free Lunch） |

**核心修正**：444 的"做不到"是"全有或全无"的极端表述。真实情况是"部分做得到，部分做不到"——可形式化/可验证/可积累的部分做得到，不可形式化/不可验证/不可积累的部分做不到。

### 对阙疑的架构启示

1. **语义分层**：把 claim 分成"可形式化断言"和"不可形式化断言"。可形式化的用编译器/静态分析器 100% 验证，不可形式化的用红队+人审。
2. **成本曲线管理**：明确记录"红队发现的问题→变成规则"的转化率。转化率越高，边际成本下降越快。
3. **自治边界**：明确哪些检查可以完全自治（编译/sanitizer/replay），哪些需要人（DAL A/B 人审）。不要追求"完全自治"，追求"可验证部分完全自治"。
4. **误报治理**：每条规则记录历史误报率，高误报率规则自动降级。目标是误报率从 53% 降到 15% 以下。

## 六、这轮调研的元发现

444 说"做不到"，445 说"部分做得到"——这个反复本身就是元认知的实践：**对"极限"的判断也需要校准**。

444 的"做不到"是基于"当前认知"的判断，445 的"部分做得到"是基于"前沿研究"的修正。这说明：
- "极限"不是静态的，是随技术进步而移动的
- 对"极限"的判断本身也需要持续怀疑和修正
- 这就是「阙疑」的核心哲学：多闻阙疑——对"做不到"也要保持怀疑
