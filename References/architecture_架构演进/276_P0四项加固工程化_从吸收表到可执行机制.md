# P0 四项加固工程化：从吸收表到可执行机制

> 2026-09-12。第九轮。275 回答「学什么」，276 回答「怎么落地」。P0 四项（爆炸半径 / error budget / 先决边 / 环节减法）全部给出 **schema、机械判据、落点、验收**——不写「应该」，只写「机器怎么拦」。

> 总原则延续：**模型是提议器，系统是判定者。** 这四项的共同特征是——它们都不依赖模型自觉，全部由机械门禁强制。

## P0-1 爆炸半径声明（Blast Radius Manifest）

### 机制
每个 GAUNTLET 剧本、每次 FORGE 候选实验，**启动前**必须前置一份 blast radius 声明（三要素）：

```yaml
blast_radius:
  scope:                    # 影响白名单：只允许动这些
    paths: ["goldens/mem/", "evidence/mem/EV-MEM-04*.md"]
    atoms: []               # verified 原子默认不可碰
    shared_state: false     # 是否动 golden_lock / 门禁基线
  abort:                    # 自动中止条件（命中任一即停）
    - gate_block_gt: 0
    - replay_refute_gt: 0
    - timeout_min: 30
    - writes_outside_scope: true
  rollback:                 # 回滚路径（必须先验证可用）
    mode: git_stash | checkpoint_dir | worktree_branch
    verified: true          # 回滚路径已实测可用，不是写着好看
```

### 机械判据
- 三要素任一缺失/为空 → **实验不允许启动**（运行器前置 BLOCK，不靠模型自觉）。
- `writes_outside_scope: true` 一旦触发 → 立即中止 + 自动回滚 + 记一次逃逸。
- `rollback.verified: false` → 声明无效（防止「写了回滚但从没试过」）。

### 落点
- GAUNTLET 运行器（273 协议的执行壳）前置检查；
- FORGE 候选仓 frontmatter 强制字段。

### 与 L6 的分工
L6 检查点解决「**能**回滚」；blast radius 解决「**事先声明**回滚边界、且越界即停」。前者是能力，后者是纪律。

## P0-2 Error Budget（错误预算）

### 机制
把「逃逸率 ≤20%」从报告指标升级为**可透支、可耗尽、强制停线**的预算：

```yaml
error_budget:
  unit: per_domain_per_batch        # 每域每批独立预算
  max_escapes: 2                    # 每批允许逃逸数（对应 ~20%）
  state:
    remaining: 2
    consumed_by:                    # 消耗必须来自独立判定（见下）
      - {id: T3, judge: redteam_independent}
  freeze_rule: remaining == 0 → 锁库
  recharge: 修复 + GAUNTLET 复测全绿才充值
```

### 预算状态机
`budget_remaining (2)` → 每发生一次「逃逸/红队阻断/门禁 block 漏网」消耗 1 → `0` 时**自动锁库**：禁止新原子/新章节生产，只允许修复动作，直至复测全绿充值。

### 机械判据（防预算被操纵）
- 新增 gate 规则 **EV-BUDGET-EXHAUSTED**：预算为 0 时，任何新建 goldens/atoms 草稿的提交 = BLOCK。
- **消耗判定权与生产权分离**：预算只能被「独立红队（P1-1）或机器门禁」消耗，**生产方不能自判无逃逸**——否则预算形同虚设（这一条与 P1-1 红队隔离联动，是 error budget 成立的前提）。
- 与 golden_lock 分工：golden_lock 锁「指标不恶化」（存量质量）；error budget 锁「流程质量不透支」（增量节奏）。

### 落点
gate_engine 新增规则 + 每批 budget 台账文件（机器维护，模型只读）。

## P0-3 先决边（Surmise Relation）—— L4 的数学地基

### 机制
relations 从自由文本标签升级为**类型化三元组**：

```yaml
relations:
  - {type: prereq,       target: ATOM-MEM-MOVE-002, rationale: "移动语义是右值引用的前置概念", evidence: human_or_empirical}
  - {type: evolved_to,   target: ATOM-HIST-AUTOPTR-001, rationale: "auto_ptr 演化到 unique_ptr"}
  - {type: contrasts,    target: ATOM-UB-GRAY-001, rationale: "灰区分界对照"}
```

边类型枚举：`prereq`（先决）/ `evolved_to`（演化）/ `contrasts`（对照）/ `mechanism_of`（机制归属）。

### 关键约束（KST 的 surmise relation 必须经验证，不能模型乱标）
- **prereq 边也需要证据**：`evidence` 字段只接受 `human`（人审确认学习先后）或 `empirical`（有学习路径实证）；模型自标的 prereq 默认 `unverified`，不参与 outer fringe 计算。
- **悬空分级**（升级现有 ATOM-REL-TARGET）：
  - verified 原子的 prereq 指向不存在目标 → **BLOCK**（知识结构断裂比 warn 严重）；
  - draft 原子的悬空 → warn（允许暂时欠债）。

### outer fringe（教学推荐引擎的核心，可机械计算）
对任意「已掌握集合 S」：
```
outer_fringe(S) = { A ∉ S | A 的所有 prereq 都 ∈ S }
```
= 所有前置已满足、自身未掌握的原子 → 这就是「下一步该学什么」的确定性答案（KST 的 outer fringe）。配套写一个小工具 `fringe.py`，输入已掌握原子列表，输出推荐序列。

### 机械判据
1. 边类型枚举校验（非枚举值 = BLOCK）；
2. verified 原子 prereq 悬空 = BLOCK；
3. `fringe.py` 能对当前全库机械输出 outer fringe（跑得出结果才算落地）；
4. prereq 无 evidence = 不进 fringe 计算。

### 落点
atoms frontmatter schema + gate_engine 规则升级 + 一次全库 relations 迁移 + tools/fringe.py。

## P0-4 环节做减法（Pipeline Slimming）—— 对抗 Lusser 衰减

### 现状问题
Lusser's law：95% 可靠的环节，链 5 个只剩 77%。现有流水线环节重叠：Writer 自评（Step1）与机器门禁重叠；红队 P4–P7 检查与 gate 规则重叠。**重叠不是双保险，是复合衰减 + 上下文成本。**

### 减法原则
1. **机器能判的，不设模型环节**：Step1 自评只保留机器判不了的——教学叙事质量、类比恰当性、概念转变有效性；格式/断言/毒样全部归机器。
2. **红队只查机器规则盲区**：红队不再重复跑 P1–P7 已机械化的检查，改为携带「**盲区清单**」入场（如 PERF-003 上 P4–P7 四条全零命中的登记），专查规则覆盖不到的语义问题。
3. **环节数硬上限 ≤ 8，其中模型环节 ≤ 3。**

### 重设计后的 8 环节流水线
| # | 环节 | 性质 | 职责 |
|---|---|---|---|
| 1 | 任务分级路由 | 机械+模型 | META 路由（已知/未知/争议/创造）|
| 2 | 取证 | 机械 | 夹具 + 真机 + 工件 sha |
| 3 | 落卡 | **模型** | Writer，只写机器判不了的叙事 |
| 4 | 机器门禁 | 机械 | gate/replay/poison/lock |
| 5 | 红队（独立上下文）| **模型+独立源** | 只查盲区清单（P1-1：不给草稿全文）|
| 6 | 修复循环 | **模型** | 限定 ≤2 轮，超限升级人审 |
| 7 | 人审 | 人 | 只复核边界 + 授予 5 分/verified |
| 8 | 原子化 + 锁同步 | 机械 | git mv + frontmatter + golden_lock |

模型环节 3 个（3/5/6），机械环节 5 个——**可靠性由机械环节兜底，模型环节被夹在客观锚之间**。

### 关键：减法不减制衡
砍掉的是**重叠**，不是制衡。红队独立性反而加强（独立上下文 + 盲区清单）；人审仍然是唯一 verified 来源。

### 机械判据
- 流水线定义文件中环节数 ≤ 8、模型环节 ≤ 3（可机械计数）；
- GAUNTLET 复测：减法后逃逸率**不高于**减法前（用 T1–T10 基线对比），否则回滚减法。

## 四项联动：一个新的横切纪律层

| 机制 | 管什么 | 时间尺度 |
|---|---|---|
| Blast radius（P0-1）| 单次实验的破坏边界 | 单次 |
| Error budget（P0-2）| 每批/每域的质量透支 | 批次 |
| Prereq 边（P0-3）| 知识结构的形式化与教学推荐 | 永久 |
| 环节减法（P0-4）| 可靠性的复合衰减 | 流程 |

四者互不替代，合起来构成 272 六层护栏之外的**横切纪律层**：护栏防「单点错」，这四项防「系统级失控」（爆炸、透支、结构断裂、衰减）。

## 落地顺序（依赖关系决定）

1. **P0-3 先决边**（schema 改动最小、收益最直接、不依赖 GAUNTLET 数据）→ gate 规则 + 全库 relations 迁移 + fringe.py。
2. **P0-1 爆炸半径**（GAUNTLET 尚未正式跑，先补协议成本最低）。
3. **P0-2 error budget**（依赖 GAUNTLET 跑起来产生消耗数据；且依赖 P1-1 红队隔离保证消耗判定独立）。
4. **P0-4 环节减法**（需要 GAUNTLET 基线做减法前后对比，放最后，避免无基线盲改）。

每步验收都走「机械判据 + GAUNTLET 复测」，不接受「感觉更顺了」。
