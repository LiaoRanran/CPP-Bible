## 一、Game Hopping 对照实验方法论（294 P2-8）

### 来源

密码学可证明安全中的 **Game Hopping**：通过一系列「不可区分」的游戏转换，从真实攻击游戏逐步转换到一个明显安全的游戏。每一步转换必须证明「攻击者无法区分」。

### 对应到夹具设计

我们的对照实验常犯的错误：**一次改变多个变量**（PERF-003 红队抓的「对照组三变量同变：驱动+平台+stdlib」）。

Game Hopping 方法论要求：**每次只改变一个变量，每步证明「不可区分」（即除了目标变量外，其他都相同）**。

### 夹具设计的 Game Hopping 模板

```
Game 0（基准）：全局 new，10000 次分配，MinGW 15.3 -O2
  ↓ 改变变量：分配器（全局 new → monotonic_buffer_resource）
Game 1：monotonic，10000 次分配，MinGW 15.3 -O2
  ↓ 改变变量：分配器（monotonic → pool）
Game 2：pool，10000 次分配，MinGW 15.3 -O2
  ↓ 改变变量：平台（MinGW → WSL g++-14）
Game 3：pool，10000 次分配，WSL g++-14
```

每一步的「不可区分」验证：
- Game 0 → Game 1：除了分配器，其他都相同（编译器、优化档、分配次数、对象大小）
- Game 1 → Game 2：除了分配器类型，其他都相同
- Game 2 → Game 3：除了平台，其他都相同

### 与现有对照实验的对比

| 现有做法 | Game Hopping 做法 |
|---|---|
| 实验组 vs 对照组（一次变多个） | 逐步转换（每次变一个） |
| 「唯一变量」靠人保证 | 每步显式列出「改变了什么、什么没变」 |
| 基数不一致（PERF-003 教训） | 每步用同一基数（同一轮排序后的中位数） |
| 结论是「A 比 B 快」 | 结论是「从 Game 0 到 Game N，每步的变化量是 X」 |

### 落地方式

- 文档级：写入夹具设计方法论（prompts/ 或 templates/）
- 非强制：现有夹具不需要改，新夹具建议采用
- 红队检查项：红队 must-check 加「对照实验是否一次只变一个变量」

## 二、High-Impact/Low-Probability 分析（294 P2-10）

### 来源

军事红队方法论中的 **High-Impact/Low-Probability Analysis**：分析概率低但影响大的情景——不是「最可能发生什么」，而是「如果发生了，后果是什么」。

### 对应到人审问题模板

每个人审问题必须考虑：**如果这个 claim 错了，最坏后果是什么？**

### 人审问题模板（v0.2 新增）

```
### 人审问题（High-Impact 分析）

1. claim 失效的最坏后果是什么？
   - 如果 claim 被证伪，哪些已 verified 原子会受影响？
   - 教材中哪些章节引用了这个 claim？
   - 读者会被误导到什么程度？

2. claim 失效的概率有多大？
   - 证据强度：____（1-5 分）
   - 平台依赖：____（高/中/低）
   - 编译器版本依赖：____（高/中/低）

3. 如果 claim 失效，有没有「安全网」？
   - 是否有其他证据卡独立支撑？
   - 是否有标准条文作为兜底？
   - 是否可以快速回退（claim 收窄而非删除）？

4. 决策矩阵：
   - 高影响 × 高概率 → 必须修，不能送审
   - 高影响 × 低概率 → 可以送审，但必须在 limitations 中声明
   - 低影响 × 高概率 → 建议修，但不阻断
   - 低影响 × 低概率 → 记录在案，后续处理
```

### 与失效后果分级的关系

- 296 的「失效后果分级」（DAL A–E）是**静态分级**（claim 本身的重要性）
- 本文档的 High-Impact 分析是**动态评估**（结合证据强度和失效概率）
- 两者结合：A 级 claim + 高失效概率 = 必须修；A 级 claim + 低失效概率 = 可以送审但声明局限

## 三、证据最小化规则（294 P2-9，待工具升级）

### 来源

Curry-Howard 对应中的 **证明化简（Proof normalization）**：证明可以被化简到最小形式，去掉冗余步骤。

### 对应到证据卡

证据卡的 `actual` 字段中，可能有可被其他行推导的冗余行。例如：
- 如果 actual 中有 `a=1` 和 `b=2` 和 `a+b=3`，则 `a+b=3` 是冗余的（可由前两行推导）
- 如果 actual 中有 `total=100` 和 `used=80` 和 `free=20`，则 `free=20` 是冗余的

### gate 规则设计（待实现）

```
规则 ID: EV-EVIDENCE-MINIMAL
级别: warn
检查: actual 中的每一行，是否可以由其他行通过简单算术/逻辑推导得出？
实现: 
  - 解析 actual 中的 key=value 对
  - 检查是否存在 a+b=c、a-b=c、a*b=c 等简单关系
  - 如果存在，warn：「actual 第 N 行可由第 M 行和第 K 行推导，建议移除」
豁免:
  - 如果该行是活性对照（证明变量确实在变化），不视为冗余
  - 如果该行是 claim 直接引用的关键值，不视为冗余
```

### 为什么是 P2 不是 P0

- 实现复杂度高（需要解析 actual 格式、做简单代数推导）
- 误报风险高（什么是「可推导」需要仔细定义）
- 收益有限（现有卡的冗余不多）
- 建议：先在 2-3 张卡上手动试点，确认有价值再实现

## 四、双向可追溯（294 P2-11，待工具升级）

### 来源

DO-178C 的**双向可追溯性**：系统需求 ↔ 高层需求 ↔ 低层需求 ↔ 源码，四个层级双向 trace。

### 对应到我们的系统

现有追溯是**单向**的：
- 原子 → 证据卡（atom 的 evidence 字段）
- 证据卡 → 原子（card 的 serves 字段）
- 证据卡 → 夹具（card 的 fixture 字段）

缺少**反向追溯**：
- 夹具 → 证据卡（哪些卡引用了这个夹具？）
- 证据卡 → 原子（哪些原子引用了这张卡？）—— 这个有（serves 字段）
- 原子 → 章节（Book/ 中哪些章节引用了这个原子？）
