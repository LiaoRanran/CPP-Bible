## 一、运筹学：原子生产的自动调度

### 1.1 核心理论

**MILP（混合整数线性规划）**：
- 二元变量 x[i,j] ∈ {0,1}：任务 i 是否分配给机器 j
- 约束：每个任务恰好分配一个机器、同一机器任务不重叠、优先关系
- 目标：最小化 makespan（总完成时间）或最大化吞吐量
- NP-hard，MILP 保证最优但可扩展性差，启发式用于大规模

**LLM + 优化**：
- 学习模型改进 MILP 求解（分支定界的启发式）
- 多 Agent 任务分配与调度的联合优化

### 1.2 对「阙疑」的映射

**当前是"手动调度"**：
- 用户决定做哪批、做哪几颗
- 没有考虑依赖关系（prereq）和资源约束（WSL/Windows 不能并行）

**MILP 调度模型**：

```
变量：x[atom, agent] ∈ {0,1}  # 原子分配给哪个 Agent
      t[atom] ≥ 0              # 原子开始时间
      d[atom] > 0              # 原子预计耗时

约束：
  ∑_agent x[atom,agent] = 1          # 每颗原子恰好一个 Agent
  t[j] ≥ t[i] + d[i]  if i prereq j  # 依赖关系
  同 Agent 原子不重叠                 # 资源约束
  WSL/Windows 任务不能并行            # 环境约束

目标：min max(t[atom] + d[atom])     # 最小化 makespan
```

**落地**：`tools/scheduler.py`
- 输入：原子列表（含依赖关系、预计耗时、资源需求）
- 输出：批次计划（哪些原子一批、顺序如何）
- 用 PuLP 或 OR-Tools 求解
- 试点：第六批 CONC 域的 3 颗原子调度

## 二、统计学：从二值判决到效应量+置信区间

### 2.1 核心理论

**p 值二分法的危机**：
- 82.6% 的研究批评孤立使用 p 值
- 复制危机：只有 50% 的显著 claim 能被复制
- p-hacking：测试多个假设但只报告显著的

**现代标准**：
- 效应量（effect size）：不只是"显著/不显著"，而是"效应有多大"
- 置信区间（CI）：效应的精度范围
- 精确 p 值：不是 p<0.05，而是 p=0.032
- Type I（假阳性）vs Type II（假阴性）

### 2.2 对「阙疑」的映射

**当前 replay 是"二值判决"**（confirm/refute），类似于 p<0.05 的二分法。

**升级为"效应量 + 置信区间"**：

| 维度 | 当前 | 升级 |
|---|---|---|
| 判决 | confirm/refute（二值） | 吻合度（0-1）+ 置信区间 |
| 证据强度 | 双平台 confirm = 通过 | 双平台 = 高置信，单平台 = 低置信 |
| 复制 | Windows + WSL | + gcc-13/14/MinGW 跨版本 |
| 断言覆盖 | 只锚常量+活性对照 | 断言必须覆盖 claim 全部范围 |

**复制危机的教训**：
- 我们的"双平台 confirm"就是复制（Windows + WSL）
- 但还需要"跨版本复制"（gcc-13 + gcc-14 + MinGW 15.3）
- PERF-003 的"同机跨运行波动 2x+"就是"复制失败"的例子——锚方向不锚倍数是正确的

**p-hacking 的对应**：
- "断言锚过窄" = 只测试容易通过的情况
- 防御：红队必须检查"断言是否覆盖了 claim 的全部范围"
- 这是 can't-miss 清单的新条目

**Type I/II 错误的权衡**：
- Type I（假阳性）：错误的 claim 被 confirm（gate 漏拦）
- Type II（假阴性）：正确的 claim 被 refute（门禁误报）
- 当前系统偏向降低 Type I（严格门禁），但可能增加 Type II
- 应该监控两者的比率，动态调整门禁严格度

## 三、机器学习：规则的自动生成与异常检测

### 3.1 核心理论

**LLM 辅助逻辑规则学习**（arXiv 2601.19255）：
- 将人类专业知识转化为可解释的逻辑规则
- 多规则生成与选择：生成多个候选，用留出测试集选择
- 防止过拟合：held-out test 评估

**CommBank 案例**（2026）：
- 欺诈检测 Agent 自动生成规则
- 生产/更新了 3/4 的卡欺诈规则
- 欺诈损失下降 20%

**异常检测**：
- Isolation Forest、DBSCAN、贝叶斯变点检测
- 自适应阈值：根据数据演化自动校准

### 3.2 对「阙疑」的映射

**规则自动生成**（323 进化算法的具体实现）：
- 从红队发现的问题模式中自动学习新规则
- 生成多个候选规则，用历史数据（已知的问题/非问题）评估
- 选择真阳性率高、假阳性率低的规则
- CommBank 的"Agent 写自己的检测规则"= 我们的"系统红队自动生成门禁规则"

**异常检测的三个应用**：

| 检测目标 | 方法 | 价值 |
|---|---|---|
| 异常原子 | 与其他原子差异大的可能有问题 | 发现"格式不对"的原子 |
| 异常门禁输出 | warn 数突然增加 | 发现系统问题（不是内容问题） |
| 异常红队行为 | 红队突然抓不出问题 | 发现"走过场"的红队 |

**落地**：
- `tools/rule_miner.py`：从红队报告中挖掘规则模式
- `tools/anomaly_detector.py`：监控原子/门禁/红队的异常
- 先从"异常红队行为"开始（最简单，数据已有）

## 四、密码学：可验证计算的启示（有限适用）

### 4.1 核心理论

**ZKP（零知识证明）**：
- 证明陈述为真而不透露任何其他信息
- 三个性质：完备性、可靠性、零知识性
- zkML：证明 AI 模型执行正确，不暴露权重或输入

**TEE + ZKP**：
- 硬件可验（TEE 远程证明）+ 密码学可证（ZKP）
- "Start with TEE, end with ZK"

### 4.2 对「阙疑」的映射

**直接价值有限**：
- 我们不需要密码学级别的验证（replay 已经足够）
- ZKP 的"证明而不透露"与我们的"完整原始输出留痕"原则冲突
- 记录为"不适用"，不浪费资源

**间接价值**：
- "可验证计算"的概念：replay 的本质是可验证计算
- 可以升级为"可验证的证据链"：每个证据卡都有可验证的来源链（command + sha + 编译器版本）
- 这已经在做了（artifact_sha256 + command），不需要密码学

## 五、人机交互：提示词作为代码

### 5.1 核心理论

**2026 趋势**：
- Prompt 是代码，不是自然语言（应该版本控制、评审、差异化）
- 程序化优化取代手工调参（DSPy）
- 提示词变成"规格与评估"问题

**"Prompt Design at Scale"**（arXiv 2607.19257）：
- 三个几乎没有受控证据的设计决策：
  1. 如何格式化指令（markdown/纯文本/散文/表格）
  2. 系统提示词能承载多少指令而不降低遵从度
  3. 模型能持有多少上下文而不降低回忆和诚实度

**Reflexive Prompt Engineering**：
- 五组件：提示设计/系统选择/评估/监控/治理

### 5.2 对「阙疑」的映射

**提示词作为代码**：
- 我们的提示词（312/313/314/320）已经在版本控制（References/ 下）
- 但缺少"PR 评审"（当前是用户审查，应该更系统化）
- 缺少"测试用例"（已知会失败的输入）

**三个关键问题需要 A/B 测试**：
1. 我们的提示词用 markdown 格式——是否最优？
2. 我们的提示词 32KB——是否超过了"指令承载上限"？
3. 我们的上下文包含大量历史——是否影响回忆？

**提示词的"规格与评估"**：
- 当前提示词有"验收标准"，但缺少"对抗性测试"
- 应该为每个提示词建立"测试用例"：
  - 正常输入（应该成功）
  - 边界输入（应该优雅处理）
  - 恶意输入（应该被拦截）

**DSPy 的思路**：
- 自动优化提示词，而不是手工调参
- 可以用历史数据（成功/失败的提示词）训练优化器
- 落地：先收集提示词的成功率数据，再考虑自动优化

## 六、生态学：系统鲁棒性的生物机制

### 6.1 核心理论

**功能冗余**（Functional redundancy）：
- 多个物种执行相似功能，一个消失后其他可以补偿
- 保险假说：生物多样性作为对冲干扰的保险

**抵抗性 vs 恢复力**：
- 抵抗性（Resistance）：维持原状的能力
- 恢复力（Resilience）：扰动后恢复的速度
- 东京大学 2026：长期稳定性主要依赖短期抵抗性

**投资组合效应**（Portfolio effect）：
- 物种对环境的差异响应创造总体稳定性
- 基本权衡：恢复力、抵抗性、效率、冗余之间的权衡

### 6.2 对「阙疑」的映射

| 生态学概念 | 「阙疑」对应 |
|---|---|
| 功能冗余 | 多证据卡验证（同一 claim 有多张卡） |
| 保险假说 | 多平台验证（Windows + WSL + CI） |
| 抵抗性 | gate 拦截错误的能力 |
| 恢复力 | 修复错误的速度（发现→修复时间） |
| 投资组合效应 | 多模型协作（不同模型的差异响应） |
| 模块化 | 域划分（MEM/CONC/UB 隔离） |

**基本权衡的量化**：
- 效率 vs 冗余：证据卡越多越可靠，但维护成本越高
  - 当前：每颗原子 2 张卡（判据+对照），是否最优？
- 抵抗性 vs 恢复力：严格门禁（高抵抗性）可能降低吞吐量（低恢复力）
  - 当前：gate block=0 但 warn 持续上升，是否过于严格？

**生态系统的"健康指标"**：
- 生物多样性 = 原子类型多样性（mechanism/pitfall/contrast 的比例）
- 功能冗余度 = 每颗原子的平均证据卡数
- 连通性 = 原子关系网络的平均度
- 这些可以作为系统健康的监控指标

## 九、一句话总结

325 把「阙疑」的理论支撑从十八学科扩展到**二十四学科**。最关键的三个新洞察：

1. **运筹学的自动调度**——当前是手动调度（用户决定做哪批），可以用 MILP 自动优化：考虑依赖关系（prereq）、资源约束（WSL/Windows 不能并行）、目标最小化 makespan

2. **统计学的效应量升级**——当前 replay 是二值判决（confirm/refute），类似于 p<0.05 的二分法。应该升级为"效应量+置信区间"：双平台=高置信，单平台=低置信；同时监控 Type I/II 错误率，动态调整门禁严格度

3. **生态学的功能冗余与保险假说**——多证据卡=功能冗余，多平台验证=保险机制，多模型协作=投资组合效应。系统健康可以用"生物多样性（原子类型比例）+ 功能冗余度（平均证据卡数）+ 连通性（网络平均度）"量化监控
