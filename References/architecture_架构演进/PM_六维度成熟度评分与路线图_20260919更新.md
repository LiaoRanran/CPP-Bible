### 6. 人审层（4/10）

**已建成**：
- overturned 通道人审接口（573/592：human 须过 git 作者绑定，冒名/缺字段/卡解析不到拒写，fail-closed）
- 人审 CLI 基础（596：list/show/approve/reject/modify，MIS 群组级）
- MIS 群组级人审方案（595 实证：42 次 vs 194 次，降 4.6 倍，24.5 分钟 vs 1.89 小时）
- automation bias 可机器检测（595 实证：agree_rate==1.0 + 理由过短 → 触发复核，rubber-stamp 0/10 捕获 vs careful 10/10）
- 人审质量控制方案（595：自一致性 + W2 机器辅助复核 + 理由质量评估）
- 主动学习式排序（595：按歧义度降序）

**关键发现（596 后）**：
- MIS 卡面 0 张有 verified_by/machine_verified → 全 low
- 人审 approve 升到 medium 仍不改变判决（命题全 medium，误解 medium 无法反压）
- 只有 modify --confidence high 才会让误解反压命题——W2 语义特性，非 bug
- **产品含义**：人审的主要动作不是 approve/reject（不改变判决），而是 modify --confidence（给特别强的误解升 high）

**剩余缺口**：
- 人审效率工具正式落地（598：群组级队列 + 详情页 + 辩护链 + 机器预测）——提示词已写好，待投喂
- 人审反馈闭环（人审拒绝→反馈生成器与 W2 权重，下一轮候选边质量上升）
- 人审数据可视化（人审进度/通过率/拒绝原因分布）
- 多人协作（单用户阶段，git 作者=自设，automation bias 风险高）
- 人审工作量估算与监控（当前只有 595 的一次性估算，没有持续监控）

**为什么是 4/10 不是 5/10**：从"只有 CLI 接口"（3/10）到"有明确的效率优化方案且已实证降 4.6 倍"（4/10）。598 落地后（群组级队列 + automation bias 护栏 + 反馈闭环）到 5/10。
