> 目标：把"科学发现"从Agent的偶然行为变成可执行、可检查、可复现的流程

## 一、两种生产模式的区分

「阙疑」有两类原子生产，必须明确区分：

| 维度 | 计划型生产（v1.x） | 发现型生产（v2.0） |
|---|---|---|
| 起点 | 人指定选题（如"做RAII-002"） | 系统发现异常/问题 |
| claim状态 | 选题时基本已知 | 未知，需从竞争假设中裁决 |
| 核心风险 | 生产质量（证据不严谨） | 认知偏差（选错假设/实验不判别） |
| 流程 | 8步生产流程 | 认知循环（本文档） |
| 产出 | 验证已知命题 | 发现新知识 |
| 占比目标 | 初期80%，成熟期40% | 初期20%，成熟期60% |

**关键原则（科学哲学的context区分）**：
- 发现的语境（context of discovery）：允许狂野、类比、直觉、多个互相矛盾的假设
- 辩护的语境（context of justification）：必须严谨、受控、可复现、经红队攻击
- **认知层管前者，v1.x的质量层管后者，两者不可混用标准**——不能用"不够严谨"扼杀假设生成，也不能让狂野的假设未经严谨验证就进入verified。

## 二、科学发现状态机

### 2.1 状态定义

```
S0 现象采集（Phenomenon）
    │  输入：实验输出/文档/矛盾/跨域类比/教学疑问
    ▼
S1 异常识别（Anomaly Detection）
    │  判定：观测与现有预期/原子/文档是否冲突？
    │  ├─ 不冲突 → 归档为常规观测，结束
    │  └─ 冲突 → 进入S2
    ▼
S2 溯因建模（Abduction）
    │  产出：≥2个竞争假设 H1, H2, ...（每个含机制解释）
    ▼
S3 假设评审（Hypothesis Review）
    │  检查：假设是否可证伪？是否彼此互斥？机制是否自洽？
    │  ├─ 不合格 → 回S2
    │  └─ 合格 → 进入S4
    ▼
S4 判别实验设计（Discriminating Experiment）
    │  产出：对每个假设推出预言P1,P2,...；设计能区分它们的实验
    ▼
S5 实验执行（Execution）
    │  产出：夹具+工件+读数（走v1.x的双平台/sha/活性对照规范）
    ▼
S6 假设裁决（Adjudication）
    │  判定：哪个假设的预言被观测支持？哪些被否证？
    │  ├─ 全部被否证 → 回S2（说明需要新假设，这是好事）
    │  ├─ 无法区分 → 回S4（实验不判别，重新设计）
    │  └─ 有假设存活 → 进入S7
    ▼
S7 替代解释排查（Alternative Explanation Sweep）
    │  红队角色：还有什么没排除的解释？（混杂变量/巧合/工具假象）
    │  ├─ 发现新解释 → 加入竞争假设，回S4
    │  └─ 穷尽 → 进入S8
    ▼
S8 知识固化（Crystallization）
       存活假设 → claim → 走v1.x的8步生产流程（辩护语境）
       同时：cognition_record归档 + 知识进化层更新
```

### 2.2 状态机的强制门禁

每个状态转换有机器可检查的条件（gate新增COGNITION-*规则）：

| 转换 | 门禁条件 | 防什么 |
|---|---|---|
| S1→S2 | 异常必须有具体观测证据（不是"我觉得奇怪"） | 防空穴问题 |
| S2→S3 | 竞争假设≥2个，每个含机制解释 | 防"先有结论再找证据" |
| S3→S4 | 假设两两可证伪、预言不同 | 防"伪竞争"（两个假设预言相同） |
| S4→S5 | 判别实验的唯一变量明确、活性对照存在 | 防不判别实验 |
| S6→S7 | 裁决引用具体读数，不是主观判断 | 防确认偏误 |
| S7→S8 | 替代解释清单≥3条且全部排除或纳入 | 防过早收敛 |

## 三、溯因推理（Abduction）模板

### 3.1 溯因与演绎/归纳的区别（Agent最易混淆）

- **演绎**：H（假设）+ 规则 → 必然结论。"如果屏障阻止消除（H），那么加屏障的循环应该保留（结论）"
- **归纳**：多次观测 → 概括规则。"测了gcc/clang/riscv都这样→规则成立"
- **溯因**：观测到异常事实F → 找能解释F的最佳假设H。"LSan没报但析构计数是0（F）→ 什么H能解释？"

溯因的逻辑形式：
```
观察到事实 F（令人惊讶的/与预期冲突的）
如果 H 为真，F 是理所当然的
因此，有理由认为 H 为真（溯因是或然的，不是证明）
```

### 3.2 溯因推理的强制模板

```yaml
abduction:
  surprising_fact: |
    令人惊讶的事实（必须具体到读数/工件行号）
    例：同一泄漏夹具，加一个volatile计数器后，LSan从零报告变为报64B/2 allocs
  default_expectation: |
    原本预期什么，为什么F令人惊讶
    例：加计数器与泄漏无关，预期LSan结论不变
  candidate_hypotheses:
    - id: H1
      statement: "假设陈述"
      mechanism: "H为什么能导致F（因果链，不能是相关性）"
      explains: [F的哪些方面]
      fails_to_explain: [F的哪些方面解释不了]
    - id: H2
      ...
    - id: H3
      ...
  best_explanation_criteria:      # 最佳解释推理（IBE）的选择标准
    - 解释广度（解释的事实数量）
    - 解释深度（机制是否触及根本原因 vs 表面描述）
    - 简洁性（奥卡姆剃刀，辅助假设更少）
    - 可检验性（能推出新的可证伪预言）
    - 与已verified知识的一致性
  selected: "Hx + 选择理由"
```

### 3.3 溯因推理的常见谬误（红队检查项）

| 谬误 | 描述 | 红队判别方法 |
|---|---|---|
| 单假设陷阱 | 只生成1个假设就去验证 | 检查candidate_hypotheses≥2 |
| 事后合理化（ad hoc） | 为保护心爱假设不断加特设条件 | 检查辅助假设数量，>2个则警惕 |
| 肯定后件 | "如果H则F；观测F；所以H"（逻辑无效） | 检查是否排除了其他也能推出F的H |
| 把相关当因果 | A和B同时变化就说A导致B | 检查mechanism是否有因果链+控制变量 |
| 工具假象误当现象 | 异常其实是工具bug（如MinGW无LSan） | 跨平台/跨工具复现异常 |
| 基线错误 | 没有正确的对照组就声称异常 | 检查"正常情况"是否真的测过 |

## 四、判别实验设计准则

### 4.1 什么是"判别实验"（Crucial Experiment）

判别实验不是"验证H1的实验"，而是**"实验结果在H1和H2下必然不同"的实验**。

形式化：
- 设计实验E，使得：H1为真→观测O1；H2为真→观测O2；且O1≠O2
- 执行E：观测到O1→H2被否证（暂时）；观测到O2→H1被否证
- **关键：实验前必须先写死O1/O2，不能看了结果再解释**（防事后合理化）

### 4.2 判别实验的设计检查清单

```yaml
discriminating_experiment:
  hypotheses_distinguished: [H1, H2]     # 这个实验区分哪些假设
  prediction_matrix:                      # 预言矩阵（实验前写死）
    - if: "H1为真"
      then_observe: "O1（具体读数）"
    - if: "H2为真"
      then_observe: "O2（与O1不同的具体读数）"
  single_variable: "唯一变量是什么"
  controls:                               # 对照（v1.x教训）
    active_control: "活性对照（证明实验装置有效）"
    negative_control: "阴性对照（已知不应该触发的条件）"
    counterexample_control: "反例对照（已知应该触发的条件）"
  bounded: "循环有界/资源有限/不会replay超时"
  cross_platform: "Windows/WSL/跨架构的预期是否一致，不一致处如何处理"
  falsifiable_outcome: "什么结果会让你放弃自己最心爱的假设"
```

### 4.3 判别力分级

- **强判别**：实验结果能唯一确定一个假设，其他全部被否证
- **弱判别**：实验结果改变假设的相对可信度，但不唯一确定
- **不判别（必须重做）**：所有假设下结果相同，或结果可以被事后解释成支持任何假设

红队有权判定实验"不判别"并打回S4——这是CONC-001/LEAK系列多次踩的坑（实验看起来在验证，其实结果可以被多种解释兼容）。

### 4.4 从已发生案例提炼的判别实验范式

| 范式 | 做法 | 案例 |
|---|---|---|
| 干预-观测 | 只改变一个因素，观测结论是否翻转 | LEAK-002加volatile计数器 |
| 跨平台三角验证 | 同一假设在不同编译器/架构下的预言 | CONC-001三平台+riscv |
| 符号级定位 | 不停留在输出，定位到具体汇编指令 | FENCE的lock/fence指令 |
| 剂量-响应 | 改变变量量级，观测是否单调响应 | ALLOC-002规模n=1000→8000 |
| 边界探测 | 在前提条件的边界处测试 | SSO阈值15/16字符 |
| 主动证伪 | 专门设计让心爱假设失败的实验 | 红队的核心动作 |

## 五、确认偏误的系统性防御

科学发现最大的敌人是确认偏误（confirmation bias）——Agent倾向于设计"证明自己对"的实验。

### 5.1 结构性防御（不靠Agent自觉）

1. **假设-预言前置冻结**：S4的prediction_matrix在执行实验前写入文件并"冻结"（git add），实验后不得修改预言，只能记录实际结果
2. **证伪任务强制化**：每个发现型生产必须包含至少1个"试图证伪首选假设"的实验
3. **魔鬼代言人角色**：批评家被强制要求为"最不被看好的假设"做最强辩护
4. **结果盲分析**：分析师拿到的工件用中性标签（A/B/C），不知道哪个对应哪个假设（盲法）
5. **预注册（pre-registration）**：实验前登记"什么结果支持/反对哪个假设"，事后不得改判据

### 5.2 贝叶斯式假设更新（轻量级，不做严格数学）

每个假设维护可信度变化记录：
```yaml
hypothesis_tracking:
  H1:
    prior: "初始可信度及理由"
    updates:
      - evidence: "观测O1"
        likelihood_if_H1: "H1下O1多可能"
        likelihood_if_H2: "H2下O1多可能"
        posterior_shift: "H1可信度↑/↓及理由"
    final: "存活/被否证/存疑"
```
这迫使Agent显式记录"证据如何改变信念"，而不是看完结果直接下结论。

## 六、认知层与v1.x质量层的接口

认知层产出的"存活假设"进入v1.x流程时：

| 认知层产物 | 映射到v1.x |
|---|---|
| 存活假设H | 原子的claim（仍需≤50字+强度检查） |
| 判别实验夹具 | Examples/_atom_*.cpp（走sha/双平台规范） |
| 预言矩阵的O1/O2 | 证据卡的actual/artifact_assert |
| 被否证的假设 | 写入误解库（"以为X，实际Y"是最好的误解素材） |
| 替代解释清单 | 证据卡的limitations字段 |
| cognition_record | 原子frontmatter新增cognition_ref字段指向记录 |

**铁律**：无论发现过程多么精彩，最终claim进入verified仍必须通过v1.x的全部质量门禁（replay/gate/红队/人审）。认知层不提供任何"质量免检"。

## 七、认知层的失败模式

| 失败模式 | 描述 | 防御 |
|---|---|---|
| 溯因枯竭 | Agent生成不出≥2个假设 | 提供溯因启发法（类比/逆向/极端化/尺度变换）；或标记为"需人类介入" |
| 假设爆炸 | 生成太多假设无法逐一实验 | 用IBE标准排序，先测区分度最高的 |
| 实验不判别 | 结果兼容所有假设 | S6门禁打回S4，强制重设计 |
| 过早收敛 | 第一个假设"看起来对"就停止 | S7替代解释≥3条+魔鬼代言人 |
| 过晚收敛 | 无限增加假设，无法决策 | 设定假设数量上限（≤5）和实验轮数上限（≤3轮），超出则人审 |
| 发现与辩护混淆 | 用狂野的发现标准写verified claim | 两层分离，verified必须走严谨流程 |
| 溯因记录造假 | 事后补写"我当时假设了H" | 预注册冻结（git时间戳证明） |

## 八、落地优先级

认知层不需要一次建成：

1. **第一步（最小可用）**：cognition_record模板 + S2（竞争假设≥2）+ S4（预言矩阵前置）两条门禁——这两条成本最低、收益最大，直接消灭"单假设陷阱"和"事后合理化"
2. **第二步**：S7替代解释排查 + 盲分析
3. **第三步**：假设可信度追踪 + 预注册冻结的工具化
4. **第四步**：问题驱动机制（358第3.4节）的自动化——系统主动从异常生成研究backlog

## 核心结论

认知层把「阙疑」最有价值但当前靠运气发生的行为——CONC-001的假设被推翻、LEAK-002的观测反转、ALLOC-002的方向反转——变成**可重复的标准认知流程**：

> 异常不是失败，而是科学发现的原料。v1.x把异常当bug修掉，v2.0让系统先问"这个异常在告诉我们什么"，用竞争假设和判别实验榨取它的全部认知价值，然后才进入严谨的固化流程。
