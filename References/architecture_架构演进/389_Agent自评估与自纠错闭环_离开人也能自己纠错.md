# 389 Agent 自评估与自纠错闭环：离开人也能自己纠错

> 日期：2026-09-13。监工完成。聚焦**自纠错**——用户目标是"离开了人也能自己纠错，人在只是更直观"。
> 核心命题：**纯内在自纠错（模型自己判断自己）是脆弱的；基于外部信号的接地自纠错（执行结果、结构化批评、过程奖励模型）才有效。自纠错循环必须稳定（EIR≈0）才能部署，否则变成"抛光退化机"。**

## 一、核心发现

**关键结论**（Zylos AI，2026）：到 2025 年，领域已收敛——**内在自纠错（模型判断自己）是脆弱的，接地自纠错（锚定在执行结果、结构化批评、过程奖励模型）才是真正的收益所在**。

**自纠错循环**（AI/TLDR）：Generate（草稿）→ Evaluate（批评/运行验证器）→ Regenerate（带批评反馈）→ 直到通过或达到上限。

**代表工作**：
- **Reflexion**：语言自我批评存储在情景记忆中，GPT-4 编码基准 80%→91%
- **Agent-R**：MCTS 构建从错误轨迹恢复正确轨迹的训练样本，迭代自训练
- **SPOC**：自发自纠错，单次推理中交错生成和验证，双角色（提议者+验证者）
- **Once-More**（ICLR 2026）：生成过程中持续监控，中间步骤检测到错误立即干预（不等完整输出）

**关键指标**：
- **EIR（Error Introduction Rate）**：自纠错把正确答案改错的比率。必须近零，否则循环不稳定
- **"Ctrl+Z 不是策略"**：只有在测量循环稳定后才部署自纠错，否则反复精炼可能变成"抛光退化机"（polished degradation machine）

## 二、和我们系统的映射

| 外部概念 | 我们的现状 | 差距 |
|---|---|---|
| Generate | Writer 生产原子 | ✅ |
| Evaluate | 红队+门禁 | ✅ 但红队是独立子 Agent，不是自评估 |
| Regenerate | 红队后修复 | ✅ 但需要人审裁决 |
| 接地自纠错 | 门禁是确定性验证器（接地） | ✅ gate/replay 是外部信号 |
| 内在自纠错 | Agent 的"自检"（不可靠） | ⚠️ 我们有 self_check 但红队抓过"自证断言" |
| EIR 测量 | 从未测量自纠错是否引入新错误 | ❌ |
| 循环上限 | 红队修复上限 2 轮（371） | ✅ 有上限 |

## 三、挖掘（核心洞察）

**1. 我们的系统已经是"接地自纠错"的雏形，但缺 EIR 测量**：
- Writer 生产 → 红队批评 → 修复 → 门禁验证——这就是 Generate→Evaluate→Regenerate→Verify
- 门禁（gate/replay）是确定性验证器，不是模型自己判断自己——这是"接地"的
- **但我们从没测量"修复是否引入了新错误"**——ALLOC-002 修了口径，结果 bitmap reset 不一致（新错误）；LEAK-002 修了 H2，结果观测反转（新发现）
- **EIR 不为零，且我们没有追踪**

**2. 红队是"结构化批评"，比模型自评估可靠**：
- 373 对抗证明：红队（独立子 Agent）能抓出 Writer 自己看不到的问题（口径不统一、恒真断言）
- 这验证了"内在自纠错脆弱，接地/外部批评有效"的结论
- **红队是我们自纠错闭环的核心——不是可选的，是必要的**

**3. "修复上限 2 轮"是正确的设计**：
- 371 设定红队修复上限 2 轮，超出部分升级人审
- 这防止了"无限自纠错循环"（抛光退化机）
- **和 Once-More 的"中间步骤干预"思路一致——不等完整输出，在关键点就干预**

**4. 自纠错的终极目标：离开人也能纠错**：
- 当前：红队发现→修复→人审裁决→人审签署
- 目标：红队发现→修复→门禁验证→自动签署（DAL C/D/E 放权）
- **369 的"放权"就是自纠错闭环的自动化——DAL C/D/E 可以机器自动签署，不需要人**
- **但放权的前提是 EIR≈0——如果自纠错会引入新错误，放权就是危险的**

**5. 过程奖励模型（PRM）是未来方向**：
- 当前我们的验证是"结果级"（最终卡是否过门禁）
- PRM 是"步骤级"（每一步是否正确）——可以更早发现错误
- **映射到我们：红队的"阻断/高级/建议"分级就是粗粒度的 PRM——阻断=步骤错误，高级=步骤可疑，建议=步骤可优化**

## 四、应用（分阶段）

### 立即落地（零成本）

**应用 1：EIR 追踪**
- 每批红队修复后，记录"修复是否引入新错误"（新的阻断/高级/门禁失败）
- 存到质检报告的"修复质量"段
- 如果 EIR > 20%，说明自纠错循环不稳定，需要人审更严格

**应用 2：修复后的"回归验证"强制化**
- 红队修复后，必须跑全量门禁（replay+gate+poison），确认没有回归
- 当前已经在做，但没有显式标注"这是回归验证"
- 显式标注后，EIR 就可以自动计算

### 中期落地

**应用 3：DAL C/D/E 的自动签署**（和 369 放权配合）
- 如果 EIR < 5% 且门禁全绿，DAL C/D/E 可以自动签署
- 人审只处理 DAL A/B 和 EIR 超标的批次
- 这是"离开人也能纠错"的具体实现

**应用 4：步骤级验证（粗粒度 PRM）**
- 红队报告的"阻断/高级/建议"分级，自动映射到"步骤错误/步骤可疑/步骤可优化"
- 累积数据后，可以训练"哪些步骤最容易出错"的模型
- 这是 385 数据飞轮的输入

## 五、局限

- 完整 PRM 需要训练模型，我们不具备
- EIR 测量需要人工判断"修复是否引入新错误"，不能完全自动化
- 自纠错循环的稳定性依赖红队质量——如果红队漏了，自纠错就无效
- 本调研未覆盖"多轮自纠错的最优轮次"——2 轮是经验值，没有数据支撑
- 放权（DAL C/D/E 自动签署）的风险需要更多数据支撑，当前 EIR 数据不足
