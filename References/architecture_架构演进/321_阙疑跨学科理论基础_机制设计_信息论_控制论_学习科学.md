## 一、机制设计：三权分立的激励对齐

### 1.1 核心理论

**委托-代理问题**（Principal-Agent）：委托人（监工/用户）对代理人（Writer/红队）的**偏好**和**能力**都缺乏先验知识——"双重未知性"。

**AI Alignment via Incentives**（arXiv 2605.01643）的关键发现：
> 在 solver-auditor 系统中，惩罚不对齐可以阻止坏输出，但也会降低 auditor 监督的激励。鲁棒对齐需要**动态奖励机制**，同时保持 solver 的威慑和 auditor 的监督。

**哨兵审计**（Sentinel Auditing, arXiv 2603.27049）：
- 故意构造 1-2 个**已知答案的探针任务**混入正常批次
- 用代理人在探针上的表现评估其可靠性
- 解决"激励崩溃悖论"——当审计率太低时，代理人会作弊

### 1.2 对「阙疑」的映射

| 机制设计概念 | 「阙疑」现状 | 升级方向 |
|---|---|---|
| 委托人 | 监工/用户 | ✅ 已有 |
| 代理人 | Writer/红队/Gatekeeper | ✅ 已有 |
| 显式激励 | ❌ 只有隐式提示词要求 | 引入"哨兵探针" |
| 动态奖励 | ❌ 静态提示词 | 基于表现的提示词调整 |
| 可验证行动 | ✅ 门禁/红队报告 | 强化 |

**落地：哨兵探针**

每批混入 1 个**已知答案的探针原子**（如"移动语义是否真的零拷贝"——答案已知，有历史证据卡）：
- Writer 不知道哪个是探针
- 红队也不知道哪个是探针
- 如果 Writer 在探针上犯了已知错误 → Writer 可靠性下降 → 提示词需要加强
- 如果红队在探针上漏检 → 红队可靠性下降 → can't-miss 清单需要补充
- 探针结果不计入正常批次产出，只用于评估

**红队激励平衡**：
- 红队太严 → Writer 保守（claim 不敢冒险）→ 教学价值下降
- 红队太松 → 质量下降
- **动态调节**：如果连续 2 批红队零阻断，说明红队可能太松或 Writer 太强 → 提高红队严格度；如果连续 2 批阻断 >5，说明 Writer 提示词有问题 → 先修 Writer

## 二、信息论：压缩的理论极限

### 2.1 核心理论

**熵率**（Entropy Rate）：一段文本的理论最小体积 = H(X) × N / 8 字节，其中 H(X) 是每 token 的熵。
- 技术英语的熵率 c ≈ 0.8 bits/token
- 保真度 0.85 时最小 28 token，0.95 时 256 token（Entropy Gate, arXiv 2606.03739）

**LLMLingua 系列**：
- 用小模型困惑度信号做 token 级压缩，GSM8K 上 **20x 压缩仅掉 1.52 点**
- LongLLMLingua：长上下文 4x 压缩**反而提升 21.4%**（因为减少了噪声干扰）
- 激进方法 480x 压缩保留 62-73% 能力；保守方法 10-20x 保留 90%+

### 2.2 对「阙疑」的映射

**提示词瘦身的理论基础**（317 P1-1）：
- 312 提示词 32KB，按技术英语熵率 0.8 计算，理论最小约 3.2KB
- 目标 <10KB 是合理的（约 3x 压缩，保真度 >95%）
- 方法：基于困惑度删除低信息 token（重复的铁律、格式规范），保留高信息 token（本批特定指令）

**证据卡三层分离的理论基础**（302）：
- actual（断言锚）= 高信息、低体积（<1KB）
- .out（完整输出）= 低信息密度、高体积（10-50KB）
- 分离本质上是"有损压缩"——把高频细节外置，只保留低频摘要
- LongLLMLingua 的发现支持这一点：**减少噪声反而提升性能**

**上下文压缩的升级**（317 P1-2）：
- 当前：手动写对话摘要（自由文本，信息损失不可控）
- 升级：用"基于困惑度的 token 选择"——保留高困惑度（高信息）的事实，删除低困惑度（冗余）的推理
- 结构化摘要（YAML）比自由文本熵率更低（更可压缩）

## 三、控制论：外环的稳定性分析

### 3.1 核心理论

**PID 控制器**（90%+ 工业控制回路使用）：
- **P（比例）**：响应当前误差，快但有稳态误差，增益太高会振荡
- **I（积分）**：积累历史误差，消除稳态误差，但可能超调和积分饱和（windup）
- **D（微分）**：响应误差变化率，提供阻尼减少超调，但放大噪声

**负反馈稳定性**（Nyquist 判据）：
- 相移达到 180° 且环路增益 >1 时，反馈变成正反馈，系统振荡
- 增益裕度和相位裕度量化系统离不稳定有多远

### 3.2 对「阙疑」外环的映射

我们的外环（315 §三）目前只有 **P 控制**：
```
测量（红队报告/门禁结果）→ 比较（与目标对比）→ 调整（规则改进/提示词修订）
```

**缺少 I 控制**：
- 问题：同一个问题反复出现但每次只修表面（如"断言未在 Linux 工件实测"出现了两次）
- 修法：积累近 3 批的错误模式，如果同类问题出现 ≥2 次 → 升级为规则/毒样例（不只是修当前卡）

**缺少 D 控制**：
- 问题：矫枉过正（规则加太多导致 warn 爆炸，如 4→8→10→15）
- 修法：监控 warn 数变化率，如果 1 批内 warn 增长 >5 → 暂停加新规则，先消化存量

**振荡风险**：
- 如果外环调整太激进（P 增益太高），系统会在"太松"和"太严"之间振荡
- 具体表现：一批加 5 条规则 → 下一批 warn 爆炸 → 下一批删 3 条规则 → 循环
- **防振荡**：每批新增规则 ≤2 条，且必须有回归验证（全库 replay 不恶化）

**PID 外环的具体实现**：
```yaml
outer_loop:
  P_current_batch:
    - 红队阻断级问题 → 立即修当前卡
  I_historical:
    - 近 3 批同类问题 ≥2 次 → 升级为规则/毒样例
    - 近 3 批 warn 持续 >10 → 提示词结构需要修订
  D_trend:
    - warn 增长率 >5/批 → 暂停加新规则
    - 红队阻断数下降趋势 → 可以提高红队严格度
  stability_guard:
    - 每批新增规则 ≤2
    - 规则变更必须全库回归验证
    - 连续 2 批方向相反 → 锁定当前状态，人审介入
```

## 四、学习科学：教学转化的深化

### 4.1 核心理论

**间隔重复**（Spaced Repetition）：
- 复习间隔：1天 → 3天 → 1周 → 2周 → 1月
- 每次复习重置遗忘曲线
- 5 次复习可以保持记忆数年

**主动回忆**（Active Recall / Testing Effect）：
- 主动提取比被动复习好 **150%**
- "测试"本身就是学习，不只是评估

**其他有效技术**：
- 精细加工（Elaboration）：新知识与已有知识联系
- 交错练习（Interleaving）：混合不同主题比集中练习好
- 生成效应（Generation Effect）：自己生成答案比看答案记忆好

### 4.2 对「阙疑」教学转化的映射

**原子复习调度**（间隔重复）：
- 当前：原子写一次就 verified，不再复习
- 升级：建立"原子健康度"调度
  - 新原子 1 天后：自动 replay（确认仍可复现）
  - 3 天后：检查 claim 是否与新证据矛盾
  - 1 周后：检查 Book 引用是否同步
  - 2 周后：全量门禁复跑
- 原子健康度下降（replay 失败/claim 被新证据推翻）→ 自动降级为 draft，触发重新审查

**Book 的主动回忆设计**：
- 当前：<atom> 标签只是引用
- 升级：每个 <atom> 标签附带一个"回忆提示"（如"移动语义的代价是什么？先想再看答案"）
- 读者先回忆，再展开看原子卡的 claim 和证据

**交错练习**：
- 当前：Book 按域分章（part04_memory 全是内存）
- 升级：在章末/篇末增加"跨域综合题"（如"RAII + 移动语义 + 异常安全的交互"）
- 混合不同域的原子，提升迁移能力

**生成效应**：
- 证据卡的 falsification 字段本质上是"让读者自己生成反例"
- 可以扩展：每颗原子附带 1 个"生成题"（如"构造一个让 unique_ptr 泄漏的场景"），读者先写，再看误解库的答案

- 机制设计保证各角色的激励对齐（不偷懒、不作弊）

- 信息论保证压缩有效率（不丢关键信息）
- 学习科学保证输出有教学效果（不只是生产知识，而是生产可学习的知识）
