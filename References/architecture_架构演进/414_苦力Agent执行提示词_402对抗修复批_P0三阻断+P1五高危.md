## P0-1：F08 poison_drill exit 逻辑错（最优先，CI 硬门禁失效）

### 问题
`tools/poison_drill.py:801`：
```python
raise SystemExit(0 if passed == total_d else 1 or (1 if uncovered else 0))
```
`1 or x` 恒为 1；且 `passed == total_d` 时忽略 uncovered 返回 0。**未覆盖规则时 CI 不红**。

### 修复
```python
all_passed = (passed == total_d)
no_uncovered = (len(uncovered) == 0)
raise SystemExit(0 if (all_passed and no_uncovered) else 1)
```

### 验证
- 注入一个未覆盖规则（临时加一条规则到 gate_engine，不配毒样例）→ poison exit 应为 1
- 恢复后 → exit 应为 0
- 毒样例：P21（模拟 uncovered 非空时 exit 非零）
- pytest：test_poison_exit_code（3 例：全过无未覆盖=0 / 全过有未覆盖=1 / 有失败=1）

## P0-2：F01 cl 卡永久免检链

### 问题
`atom_evidence_replay.py:831-833`：含 `cl` 的卡直接 `return infra_error:msvc_unavailable`，跳过所有校验。gate S2 只认卡面 `verdict:confirm`。**含 cl 的卡永不复算，一次 accept 永久挂账**。

### 修复
两层防御：
1. **replay 层**：`infra_error:msvc_unavailable` 时，仍然校验卡面 `verdict`——如果卡面写 `confirm` 但 replay 无法复算，应标记 `verdict_mismatch`（卡面说 confirm 但实际没跑），而不是静默通过
2. **gate 层**：新增规则 `EV-MSCV-NO-VERIFY`——如果卡的 command 含 cl/cl.exe/clang-cl 且卡面 `verdict:confirm`，block（因为无法复算的卡不能标 confirm）。允许 `verdict:infra_error` 或 `verdict:unverified`

### 验证
- 造一张含 cl 命令、verdict:confirm 的卡 → gate block
- 造一张含 cl 命令、verdict:unverified 的卡 → gate 通过
- replay 含 cl 卡 → 返回 infra_error 但不跳过 verdict 校验
- 毒样例：P22（cl 卡标 confirm 被拦）
- pytest：test_msvc_no_verify（3 例）

## P0-3：F02 编译后覆写（声明-实现绑定根本缺陷）

### 问题
`gate_engine.py:1112-1180` 的 `EV-ARTIFACT-PRODUCER` 只检查 producer 段逐字在 command + -o 绑定，**不检查编译后是否有覆写**。cp/mv 黑名单永远列不全（python/powershell/cmd/cat 都能覆写）。

### 修复（不用黑名单，用时序约束）
在 `check_evidence_artifact_producer()` 中新增检查：
- 解析 command 的每一行（按 `&&`/`;`/换行分割）
- 找到 artifact_producer 段所在的行
- 检查该行之后是否有任何行包含 artifact 路径（即编译后有人碰了这个文件）
- 如果有 → block（"编译后存在对 artifact 的后续操作，无法证明工件未被覆写"）

这是**时序约束**不是黑名单——不管用什么工具覆写，只要在编译行之后碰了 artifact 路径就拦。

### 验证
- `g++ -S x.cpp -o x.asm && python -c "open('x.asm','w').write('bad')"` → block
- `g++ -S x.cpp -o x.asm`（单行，无后续操作）→ 通过
- `cp other.asm x.asm && g++ -S x.cpp -o x.asm`（覆写在编译前）→ 通过（编译覆盖了覆写）
- 毒样例：P23（编译后 python 覆写被拦）
- pytest：test_artifact_producer_post_write（4 例）

## P1-4：F03 contains_in/absent_in 的 text 字段不受通用符号表约束

### 问题
`EV-ASSERT-SYMBOL-MAPPED` 只检查 `symbol` 字段，不检查 `contains_in`/`absent_in` 的 `text` 字段。`mov`/`ret`（任何函数恒有）与纯中文句（asm 恒 0 次）在跨编译器路径全部 confirm。

### 修复
在 `EV-ASSERT-SYMBOL-MAPPED` 的检查中，对 `contains_in`/`absent_in` 的 `text` 字段也应用通用符号表约束：
- `mov`/`ret`/`call`/`jmp`/`push`/`pop` 等通用助记符 → block（无判别力）
- 纯中文/非 ASCII 文本 → block（asm 中不可能出现）
- 空字符串 → block

### 验证
- 毒样例：P24（contains_in text=mov 被拦）
- pytest：test_contains_in_generic_symbol（3 例）

## P1-5：F09 单文件重复 YAML 键 after-wins 遮蔽 S2

### 问题
YAML 规范允许重复键，后写的覆盖先写的。如果卡的 frontmatter 有两个 `verdict:` 键，第一个是 `refute` 第二个是 `confirm`，解析后只有 `confirm`——gate S2 被遮蔽。

### 修复
在 frontmatter 解析后，检查是否有重复键。Python 的 yaml.safe_load 默认静默覆盖，需要自定义：
- 用 `yaml.SafeLoader` 子类，在 `construct_mapping` 中检测重复键
- 发现重复键 → gate block（`EV-FRONTMATTER-DUPLICATE-KEY`）

### 验证
- 毒样例：P25（重复 verdict 键被拦）
- pytest：test_duplicate_yaml_key（3 例）

## P1-6：F04 中文/全角 .out 键漏网

### 问题
`EV-OUT-UNDECLARED-KEY` 只检查 ASCII 键，中文/全角键（如 `ｎｐｒｏｃ=`、`硬件并发数=`）漏网。

### 修复
在 `EV-OUT-UNDECLARED-KEY` 的键提取中，用 Unicode 正则 `[\w\u4e00-\u9fff\uff00-\uffef]+=...` 替代纯 ASCII `\w+=...`。

### 验证
- 毒样例：P26（全角键被拦）
- pytest：test_out_key_unicode（2 例）

## P1-7：F06 虚构 .out 留痕

### 问题
卡的 `.out` 文件可以是手写的（不是 command 真实产出），replay 只比对 .out 内容与卡内 actual，不验证 .out 是否由 command 真实产出。

### 修复（轻量，不做完整重编译）
在 `EV-ARTIFACT-GEN-TRACE`（已有规则）中新增检查：
- `.out` 文件的 mtime 必须晚于 `.cpp` 文件的 mtime（.out 比源码新）
- 如果 .out 比 .cpp 旧 → warn（"可能不是当前源码的产出"）

这是启发式检查，不是完美防御（可以 touch .out），但能拦住低级伪造。完美防御需要重编译，成本太高。

### 验证
- 毒样例：P27（.out 比 .cpp 旧触发 warn）
- pytest：test_out_mtime（2 例）

## P1-8：F07 relations 第四种隐形写法

### 问题
relations 字段支持纯标量项（如 `relations: [PERF-001]`），这种写法不经过 DAG mapping 校验，静默丢弃。400 断言"不存在第四种写法"被推翻。

### 修复
在 `ATOM-REL-TARGET` 检查中，检测 relations 中的纯标量项：
- 如果 relations 是 list 且元素是字符串（不是 dict）→ warn（"纯标量 relations 不经过 DAG 校验，建议改为 {id, type} 结构"）
- 不 block（存量可能有这种写法），但 warn 提醒

### 验证
- 毒样例：P28（纯标量 relations 触发 warn）
- pytest：test_relations_scalar（2 例）
