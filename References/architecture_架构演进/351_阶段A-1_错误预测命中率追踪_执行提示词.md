> 2026-09-12 · 阶段A第1项（小工作量）· 投喂Agent执行

---

## 一、目标

把红队从"感觉严格"变成"数据严格"——追踪红队每条错误预测的命中率，量化红队效能，识别低质量提示词。

**核心指标**：
- 错误预测命中率 = 被验证为真的阻断数 / 总阻断数（目标≥70%）
- 强证伪比例 = 改变claim方向的阻断数 / 总阻断数（目标≥20%）
- 阻断可复现率 = 有具体验证动作的阻断数 / 总阻断数（目标100%）

---

## 二、数据结构设计

### 2.1 红队报告新增字段

在红队报告（docs/G5_MEM_batch*_quality_inspection.md 或独立红队报告）中，每条阻断必须包含：

```yaml
- id: BL-001              # 阻断编号
  severity: block          # block/high/advice
  prediction: "夹具的meta()口径不统一，pool漏算free-list堆数组"  # 红队的预测/假设
  verification_action: "读夹具源码，检查Pool::meta()是否包含free_list数组的大小"  # 具体验证动作
  verification_result: confirmed  # confirmed(预测为真) / refuted(预测为假) / partial(部分为真)
  impact: direction_change  # direction_change(改变claim方向) / detail_fix(修细节) / no_impact(无需修改)
  evidence: "Pool::meta()只算sizeof(free_list)+8，漏掉1024×8=8192B堆数组"  # 验证证据
```

### 2.2 存储位置

- **原始数据**：每批红队报告中（docs/G5_MEM_batch*_quality_inspection.md 的红队章节）
- **汇总统计**：新建 `docs/redteam_metrics.md`，按批次汇总
- **机器可读**：新建 `tools/redteam_metrics.py`，从红队报告中解析统计

### 2.3 汇总表格式（docs/redteam_metrics.md）

```markdown
# 红队效能追踪

## 总览
| 批次 | 总阻断 | confirmed | refuted | partial | 命中率 | 强证伪 | 强证伪率 | 可复现率 |
|---|---|---|---|---|---|---|---|---|
| 第三批 | 3 | 3 | 0 | 0 | 100% | 1 | 33% | 100% |
| 第四批 | 2 | 2 | 0 | 0 | 100% | 1 | 50% | 100% |
| 第五批 | 5 | 5 | 0 | 0 | 100% | 2 | 40% | 100% |
| CONC-001 | 0 | 0 | 0 | 0 | N/A | 0 | 0% | N/A |
| CONC-002 | 0 | 0 | 0 | 0 | N/A | 0 | 0% | N/A |

## 按类型统计
| 错误类型 | 出现次数 | 命中率 | 首次出现批次 |
|---|---|---|---|
| 自证断言 | 1 | 100% | 第三批 |
| 口径不统一 | 1 | 100% | 第五批 |
| 观测可被无关改动翻转 | 1 | 100% | 第五批 |
| ... | ... | ... | ... |

## 低命中率预警
（命中率<70%的红队提示词/检查项，标记为"需修订"）
```

## 三、实现步骤

### Step 1：回溯填充历史数据

从已有的红队报告中提取数据，填充第三批到CONC-002的历史记录。

**历史红队报告位置**：
- 第三批：docs/G5_MEM_batch3_quality_inspection.md（如存在）
- 第四批：docs/G5_MEM_batch4_acceptance_report.md
- 第五批：docs/G5_MEM_batch5_quality_inspection.md（待写，但红队数据在2026-09-12.md记忆中）
- CONC-001：红队0阻断/高级1/建议3
- CONC-002：红队0阻断/高级2/建议3

**注意**：历史红队报告可能没有prediction/verification_action字段，需要根据报告内容"回溯推断"。如果无法推断，标注为"unknown"，不计入命中率统计。

### Step 2：新建tools/redteam_metrics.py

功能：
1. 解析红队报告中的阻断条目（匹配prediction/verification_action/verification_result字段）
2. 计算命中率/强证伪比例/可复现率
3. 按错误类型聚类（用关键词匹配：自证/口径/恒真/内联/消除/...）
4. 输出汇总表（Markdown格式）
5. 低命中率预警（<70%的检查项列出）

**命令行接口**：
```bash
python tools/redteam_metrics.py --report docs/G5_MEM_batch5_quality_inspection.md  # 解析单批
python tools/redteam_metrics.py --all  # 解析所有批次，输出汇总
python tools/redteam_metrics.py --update  # 更新docs/redteam_metrics.md
```

### Step 3：更新红队提示词模板

在红队提示词（312 v3.1 / 后续提示词）中增加要求：
- 每条阻断必须包含prediction/verification_action/verification_result/impact/evidence五字段
- 红队在报告开头给出"错误预测≥3"（在审查前先预测会发现什么错误）
- 审查结束后，逐条验证预测是否为真

### Step 4：集成到门禁

在ci_local_precheck.py或gate_engine中增加：
- 红队报告格式检查（每条阻断是否有五字段）——缺字段报warn
- 命中率趋势监控（连续2批命中率<70%→报warn，提示修订红队提示词）

### Step 5：验证

```bash
# 1. 解析历史数据
python tools/redteam_metrics.py --all

# 2. 检查汇总表生成
cat docs/redteam_metrics.md

# 3. 格式检查（用一个缺字段的红队报告测试，应报warn）
# 4. 单元测试（如有tests/目录，加test_redteam_metrics.py）
```

## 四、关键约束

1. **不修改已有红队报告的内容**——回溯填充只在docs/redteam_metrics.md中做，不修改原始报告
2. **不修改replay/gate的核心逻辑**——命中率追踪是"观测层"，不影响"判决层"
3. **命中率<70%只报warn不报block**——避免红队为了命中率而"少抓错"（Goodhart定律）
4. **历史数据标注为"回溯推断"**——与未来的"实时记录"区分
5. **错误类型聚类用关键词匹配**——不做复杂NLP，保持简单可维护
