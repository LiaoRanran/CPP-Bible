# 489 教学效果衡量与反馈闭环详细方案
## 从"知识生产"到"学习效果验证"

> 生成时间：2026-09-14
> 前置实测：pedagogy 字段覆盖率 28/28 = 100%（已从 29% 补齐）；learning_path.py 132 行；teaching_audit.py 106 行；flashcard_export.py 164 行；闪卡 107 张；误解 80 条（54% 被引用）
> 核心问题：系统有"知识生产"和"内容质量"，但没有"教学效果"——生产了知识，不知道学生学得怎么样

---

## 一、问题：生产了知识 ≠ 教会了学生

### 现状

- 28 颗 verified 原子，每颗都有 pedagogy 字段（audience/cognitive_load/prerequisites_readable）
- 107 张闪卡（Anki CSV + Markdown）
- 80 条误解（54% 被原子引用）
- learning_path.py 生成学习路径
- teaching_audit.py 检查教学字段完整性

### 缺失

1. **没有学习效果反馈**：学生学了之后懂了吗？误解纠正了吗？没有数据
2. **学习路径是静态的**：不能根据学生水平和错误动态调整
3. **误解库是专家写的**：不是从学生真实错误中挖掘的，可能遗漏学生真正会犯的错
4. **闪卡只有导出没有追踪**：导出了 107 张，但学生复习了吗？记住了吗？
5. **教学价值只有估算**：484 的 ROI 是"误解数×卡数×断言数"的估算，不是实际学习效果
6. **没有前置/后置测试**：学之前懂多少？学之后懂多少？没有对比

## 二、教学效果衡量体系

### 2.1 三层衡量

```
L1: 内容质量（已有）
  └─ 断言可验证、口径统一、证据完整
  └─ 51 规则 + replay + 红队

L2: 教学设计（部分有）
  └─ pedagogy 字段（audience/cognitive_load/prerequisites）
  └─ 误解关联、闪卡、学习路径
  └─ 但没有验证设计是否有效

L3: 学习效果（完全缺失）
  └─ 学生实际学了之后的效果
  └─ 前置测试 vs 后置测试的提升
  └─ 误解纠正率
  └─ 长期 retention（一周后还记得吗？）
```

### 2.2 效果指标

| 指标 | 定义 | 数据来源 |
|---|---|---|
| 前置-后置提升 | 后置测试得分 - 前置测试得分 | 测试数据 |
| 误解纠正率 | 学之前犯的错，学之后不犯了的比例 | 测试数据 |
| 闪卡 retention | 闪卡复习后的记忆保持率 | Anki 数据（如果有） |
| 学习路径完成率 | 学生按路径学完的比例 | 学习记录 |
| 单原子学习时间 | 学完一颗原子平均花多久 | 学习记录 |
| 求助率 | 学习过程中需要额外查资料的频率 | 学习记录 |
| 迁移能力 | 学了原子后，能否解决新的相关问题 | 迁移测试 |

## 三、前置/后置测试体系

### 3.1 每颗原子配测试题

每颗 verified 原子必须配：
- **前置测试**（3-5 题）：学之前测，检测已有认知（包括误解）
- **后置测试**（3-5 题）：学之后测，检测是否掌握
- **迁移测试**（1-2 题）：检测能否迁移到新场景

### 3.2 测试题格式

```yaml
# atoms/mem/ATOM-MEM-RAII-001.md 末尾
assessment:
  pre:
    - question: "下面代码会泄漏资源吗？为什么？"
      code: |
        void f() {
          int* p = new int[10];
          if (rand() % 2) throw "error";
          delete[] p;
        }
      options:
        - "不会泄漏，因为有 delete"
        - "会泄漏，异常路径跳过 delete"
        - "不会泄漏，编译器自动回收"
      correct: 1
      targets_misconception: MIS-MEM-001  # 这题检测哪个误解
  post:
    - question: "用 RAII 改写上面的代码"
      type: open  # 开放题，需要人评或 LLM 评
  transfer:
    - question: "lock_guard 是 RAII 吗？它管理什么资源？"
      type: open
```

### 3.3 测试题生成

- Writer 生产原子时同时生成测试题
- 红队审核测试题（是否真的能检测理解，而不是记忆）
- gate 规则：verified 原子必须有 assessment 字段（至少 pre + post 各 3 题）

### 3.4 测试运行

`tools/assessment_runner.py`（约 100 行）：
- 运行前置测试 → 记录得分和错误
- 学习原子内容
- 运行后置测试 → 记录得分
- 计算提升量
- 输出学习效果报告

## 四、误解挖掘（从学生错误中学习）

### 4.1 问题

当前 80 条误解是专家写的，不是从学生真实错误中挖掘的。可能：
- 遗漏了学生真正会犯的错
- 有些误解学生根本不会犯（专家想多了）
- 误解的严重度估计不准

### 4.2 改法：学生错误数据驱动

1. **收集学生错误**：前置测试中，学生选错的选项就是真实误解
2. **错误聚类**：把相似的错误聚类，形成新的误解候选
3. **误解有效性验证**：
   - 每条误解有"出现频率"（多少学生犯这个错）
   - 出现频率 <5% 的误解 → 降级（不是常见误解）
   - 出现频率 >30% 的误解 → 升级（核心误解）
4. **误解库更新**：根据学生数据持续更新误解库

### 4.3 工具：misconception_miner.py（约 120 行）

```python
def mine_from_test_results(test_results):
    """从测试结果中挖掘误解"""
    wrong_answers = collect_wrong_answers(test_results)
    clusters = cluster_similar_errors(wrong_answers)
    for cluster in clusters:
        if cluster.frequency > 0.05:  # 超过 5% 的学生犯这个错
            candidate = {
                'misconception': generate_description(cluster),
                'frequency': cluster.frequency,
                'severity': estimate_severity(cluster),
                'examples': cluster.examples,
                'source': 'student_data',
            }
            yield candidate
```

## 五、自适应学习路径

### 5.1 问题

当前 learning_path.py 生成的是静态路径（按 prerequisite 排序），不考虑：
- 学生的已有水平
- 学生的学习速度
- 学生的薄弱环节

### 5.2 改法：自适应路径

```
学生 → 前置测试（诊断水平）
     → 识别薄弱误解
     → 生成个性化路径（优先学能纠正薄弱误解的原子）
     → 每学完一颗 → 快速检测
        → 通过 → 继续下一颗
        → 没通过 → 推荐前置原子或补充材料
     → 后置测试（验证整体效果）
```

### 5.3 工具：adaptive_path.py（约 150 行）

```python
def generate_adaptive_path(student_level, weak_misconceptions):
    """生成个性化学习路径"""
    # 1. 根据学生水平过滤原子（beginner 只推荐 beginner 原子）
    # 2. 优先推荐能纠正薄弱误解的原子
    # 3. 按 prerequisite 排序
    # 4. 每颗原子配检测点
    path = []
    for atom in candidate_atoms:
        path.append({
            'atom': atom.id,
            'reason': f'纠正 {atom.targets_misconceptions}',
            'prerequisites': atom.prerequisites,
            'checkpoint': atom.assessment.post,
        })
    return path
```

## 六、闪卡效果追踪

### 6.1 问题

flashcard_export.py 导出了 107 张闪卡，但：
- 不知道学生有没有复习
- 不知道记住了没有
- 闪卡质量好不好（有没有用）

### 6.2 改法

1. **闪卡质量评分**：每张闪卡有"有效性"评分（基于学生反馈）
2. **Anki 集成**：如果学生用 Anki，可以导入复习数据（retention 率）
3. **闪卡 A/B 测试**：同一概念的不同闪卡表述，对比哪个效果好
4. **低质量闪卡标记**：retention 率低的闪卡 → 建议重写

### 6.3 工具：flashcard_analytics.py（约 80 行）

- 导入 Anki 的复习数据（apkg 或 csv）
- 计算每张闪卡的 retention 率
- 标记低质量闪卡
- 生成闪卡效果报告

## 七、教学价值量化（升级 484 的 ROI）

### 7.1 当前 ROI（484）

```
ROI = 教学价值 / token 消耗
教学价值 = 误解数×2 + 卡数×1 + 断言数×0.5
```

这是**估算**，不是实际效果。

### 7.2 升级：实际效果驱动

```
教学价值 = 实际学习提升 × 覆盖学生数
实际学习提升 = 后置得分 - 前置得分（平均）
覆盖学生数 = 学过这颗原子的学生数
```

没有学生数据时，用估算值；有学生数据后，用实际值替换。

### 7.3 教学效率

```
教学效率 = 学习提升 / 学习时间
```

- 高效率：短时间大提升
- 低效率：花了很多时间但提升小 → 教学设计有问题

## 八、实施计划

### 第一阶段（零/低成本，立即做）

1. **assessment 字段**：每颗原子加前置/后置测试题（先从 5 颗核心原子开始试点）
2. **gate 规则**：ATOM-ASSESSMENT-REQUIRED（verified 原子必须有 assessment）
3. **assessment_runner.py**：运行前置/后置测试，计算提升量（约 100 行）
4. **闪卡质量标记**：flashcard_export 加"有效性"字段（先人工标记）

### 第二阶段（中等成本，下一批做）

5. **误解挖掘**：misconception_miner.py，从测试错误中挖掘新误解
6. **自适应路径**：adaptive_path.py，根据学生水平生成个性化路径
7. **教学效果报告**：每批次生成教学效果报告（平均提升、误解纠正率）

### 第三阶段（高成本，需要学生数据）

8. **闪卡 analytics**：导入 Anki 数据，计算 retention
9. **A/B 测试**：不同教学设计的效果对比
10. **持续优化**：根据学生数据持续优化原子、误解、闪卡

## 十一、风险与缓解

| 风险 | 缓解 |
|---|---|
| 没有学生数据 | 先用专家估算，有学生数据后替换；可以自己当学生测试 |
| 测试题质量差 | 红队审核测试题；测试题本身也要过门禁 |
| 自适应路径复杂度高 | 先做简单版（按水平过滤+优先薄弱误解），不做完整推荐算法 |
| 闪卡数据难获取 | Anki 导入是可选的，没有数据就用人工评分 |
| 增加 Writer 负担 | 测试题模板化，Writer 只填内容；先试点 5 颗再推广 |
| 教学效果衡量周期长 | 短期看前置-后置提升，长期看 retention 和迁移 |

---

## 十二、关键认知

**系统的终极目标不是"生产了多少颗原子"，而是"教会了多少学生"。**

当前系统在 L1（内容质量）和 L2（教学设计）已经很强，但 L3（学习效果）是空白。没有 L3，L1 和 L2 的优化就是"自嗨"——内容再严谨、设计再精巧，如果学生学了没效果，一切归零。

教学效果衡量是系统从"知识生产工具"进化为"教学系统"的关键一步。
