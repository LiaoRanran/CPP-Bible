## 1. 背景：这是什么系统

CPP-Bible「阙疑」是一个机器可核验的 C++ 知识生产系统。知识以"原子（atom）+ 证据卡（evidence card）+ 误解（misconception）"为单位，每条 claim 必须由可重编译的夹具（fixture）、汇编/运行工件（artifact）、机器断言（artifact_assert / run_match）支撑。三权分立：Writer（生产）→ 独立红队（盲读质疑）→ Gatekeeper（门禁）→ 人审。

## 2. 真实工具接口（开工前自己 --help 复核一次）

```powershell
python tools/gate_engine.py --list        # 规则全集（条数以此为准，勿写死）
python tools/gate_engine.py --check       # 任一 block 即 exit 1
python tools/gate_engine.py --run         # 打印工单
python tools/atom_evidence_replay.py --card <卡路径> [--no-sanitizer] [--keep-tmp] [--no-restore]
python tools/atom_evidence_replay.py --check   # 全量，任一 refute 即 exit 1；三分类 confirm/refute/infra_error
python tools/golden_lock.py show          # 仅看；禁止 sync
python tools/poison_drill.py              # 现有 P1-P10 + 阴性，观察其沙箱写法
python tools/cppbible.py check --stage quality
```
- gate 扫描根在 `gate_engine.py` 是模块级变量 `ATOMS`/`EVIDENCE`（默认 `ROOT/atoms`、`ROOT/evidence`）——**可被 monkeypatch 重定向**，这是合法沙箱攻击点。
- replay 每次用 `tempfile.mkdtemp(prefix="replay_")` 构建，默认结束还原仓库工件（只读角色）。
- 判定分流：同编译器走 `artifact_sha256` 强校验（不查断言）；跨编译器走 `artifact_assert`（断言才真正被执行）。**这条不对称是重点攻击面。**

## 3. 攻击任务分两路

### 路 A · 认知层对抗（占工作量约 30%）
攻击 372 v5 的**论证本身**，每条必须引用文档具体小节 + 给出反例（优先用仓库真实历史案例，其次构造反例）：
- A1 五原则（左移/增量/分层/聚焦/流动）是否完备、是否正交？能否构造一个真实问题落在五原则缝隙里？
- A2 "双成本动态转化漏斗"切分是否成立？有没有第三种成本被漏掉（例如：协调成本、上下文切换成本、对抗者本身的成本）？
- A3 T0 博弈防御的五条逃逸路径是否可被**新的**投机方式绕过？T0 自身会不会提高门槛到逼退合法生产（误杀）？
- A4 T-ep 三字段（applicability/evidence_strength/inductive_leap）在真实写卡时是否可操作，还是会沦为形式填空？给一个"填得漂亮但 claim 仍错"的样例。
- A5 规模门控阈值（200/1000 文档）有无依据？回流优先（T6）会不会拖慢本该快速推进的生产？
- A6 文档状态机（proposed→adopted→implemented）会不会自己流于形式？谁有权判 superseded？
- A7 找 v5 的**自指矛盾**：它主张的某条原则是否被它自己的写法/任务表违反（例如它一边说修剪库存一边增加任务）。

### 路 B · 实操渗透（占工作量约 70%，这是本次重点）
对每个靶位（第 5 节），在沙箱里构造**最小陷阱**（一个坏原子或坏证据卡 + 必要夹具），跑真实 gate/replay，裁决它被拦还是逃逸。**必须真的造文件、真的编译、真的跑门禁。**

### 3.5 两阶段协议（强制顺序，兼顾独立性与预算效率）

建设者手里已有一份"自述已知洞清单"（W1/W2/W3/A3/nproc 等，在 `docs/kernel/371*` 报告里）。为避免你"按答案册复核"浪费增量价值，攻击分两阶段：

- **阶段一·盲测（独立发现）**：只读本提示词 §1 列出的文件，**禁止读 `docs/kernel/371*`、`docs/kernel/369_*` 等建设者压力测试/验收报告**（那是答案册）。仅凭第 5 节的"攻击类别"（不含建设者的具体定位与定级）独立构造、独立定位、独立定级。第 5 节给类别是测试计划，不代表洞已被证实——你要自己把它打成 ESCAPED 或证明它其实 BLOCKED。
- **阶段二·开卷（校准 + 新攻击）**：阶段一封板后，再读建设者自述清单，做三件事：① 对盲测**没打出来**的已知洞独立复现，判断建设者自述是否成立、危害定级是否准确（建设者可能夸大或缩小）；② 对盲测已打出的，比对双方定级差异；③ 把主要预算投入第 6 节清单外新攻击与已知洞的**新变种**。

报告中每条攻击必须标注来源：`【盲测独立发现】` 或 `【开卷验证】` 或 `【开卷新变种】`。最终统计"盲测独立命中率"（建设者已知洞中你盲测独立复现的比例）与"新增发现数"（建设者清单外的逃逸）。**这两个数分别度量你的独立性和增量价值。**

## 4. 沙箱攻击范式（照此写攻击脚本，确保零污染）

### 4.1 gate 层攻击（frontmatter / claim / 断言形式 / 状态签收）
复用 `poison_drill.py` 的成熟范式，新建 `_adversarial/adv_gate_<靶位>.py`：
```python
import sys, tempfile, shutil
from pathlib import Path
sys.path.insert(0, str(Path("tools").resolve()))
import gate_engine as ge

def sandbox():
    tmp = Path(tempfile.mkdtemp(prefix="adv_"))
    (tmp/"atoms").mkdir(); (tmp/"evidence").mkdir()
    orig_a, orig_e = ge.ATOMS, ge.EVIDENCE
    ge.ATOMS, ge.EVIDENCE = tmp/"atoms", tmp/"evidence"
    try:
        yield tmp
    finally:
        ge.ATOMS, ge.EVIDENCE = orig_a, orig_e
        shutil.rmtree(tmp, ignore_errors=True)

with sandbox() as tmp:
    # 在 tmp/"atoms"/<domain>/ 写你的陷阱原子、tmp/"evidence"/<domain>/ 写陷阱卡
    # 然后直接调用 gate 的检查函数（读 gate_engine.py 找到规则入口），
    # 打印：该陷阱触发了什么 block/warn，或者——它 ESCAPED 了（无 block）
    ...
```
要点：每个陷阱独立沙箱；**同时跑一个"干净对照"**确认沙箱本身不会无中生有报 block（排除 FALSE_POSITIVE 来自脚手架）。

### 4.2 replay 层攻击（工件 / sha / 断言实际编译 / 留痕）
- 陷阱夹具放 `_adversarial/fixtures/`，陷阱卡放 `_adversarial/cards/`，卡内 `fixture/artifact/command` 指向这些隔离路径；
- 用 `python tools/atom_evidence_replay.py --card _adversarial/cards/<卡>.md --no-sanitizer` 单卡复算（需要 sanitizer 的靶位再去掉该开关）；
- replay 在自己的 tmp 构建、默认还原，不应污染 `Examples/atoms/`；若发现它改写了仓库工件且没还原，这本身是一条 ESCAPED（只读契约被破坏）；
- 结束删除 `_adversarial/` 下所有生成物。

### 4.3 每条攻击的记录模板
```
### B<n> · <攻击名>
- 假设（我想骗过哪条规则/哪个机制）：
- 最小复现：<文件路径> + <确切命令>
- 真实输出（关键行原文）：
- 裁决：BLOCKED / ESCAPED / FALSE_POSITIVE
- 若是 ESCAPED，危害：坏东西能走到哪一步（draft? machine-verified? verified?）
- 修复候选：新增规则名+判定逻辑 / 新毒样例（必须给"坏例被拦 + 干净例放行"一对）
- 归类：这违反了工具的哪条"隐性假设"（进假设台账）
```

## 5. 攻击靶位（历史已暴露的类别，逐个独立复现并尝试变种）

> 这些是"已知可能有洞"的方向。你的更高价值目标是**发明这个清单之外的新攻击**（第 6 节）。

- **B1 不可证伪 claim**：构造一个 claim 含模糊措辞（"可能/通常/影响性能"）、不指向任何可观测读数的原子，看 gate 是否放行（v5 T0 预判目前无规则拦）。
- **B2 无判别力断言的新变种**：已知 P4 拦"夹具自定义函数满足断言"、P6 拦三种 null 拼写。尝试新形态：`contains_in` 断言一个在任何程序里都必然出现的符号（如 `main`、`call`、`ret`）；用跨编译器会漂移的 `call_count`；断言格式串模板而非取值。目标：让断言恒真但 replay 仍 confirm。
- **B3 .out 留痕造假**：在 `.out` 里写与真实运行不符的漂亮数字，而卡用 `run_match_file/run_match_keys`。验证 v5 预判：P7 留痕锚是否对 run_match_file 形态恒命中、S3/恒真观测规则是否不扫描 .out 取值域——即**留痕层数字能否凭空编造**。
- **B4 self_check / hash 伪造**：卡上填一个 `self_check: confirm` 但不附可复算 hash，或附一个与当前卡内容不符的 hash，看是否有任何环节复算它（v5 T0 预判：目前没有）。
- **B5 环境依赖值进断言**：把 `hardware_concurrency()`、文件绝对路径、用户名、hostname、时区、`%TEMP%`、编译器版本字符串等环境相关值写进 `run_match`/断言，本机绿、换环境必红。系统刚被 nproc 真实击穿一次（CI 核数不同）——找出还有多少同类值能混进断言。
- **B6 负向断言无 -Werror**：写 claim "零诊断/无警告"，command 不加 `-Werror`（甚至故意留一个 warning），验证 rc=0 是否被当成"零诊断"证据（v5 W3 预判的全库体裁洞）。
- **B7 多 TU 单 artifact 锚定**：构造一个多翻译单元夹具（产多个 .asm/.o），证据卡只有单 `artifact`/`artifact_sha256` 字段。验证：能否只锚一个无关产物就让整卡 confirm，而真正承载 claim 的那个 TU 无人校验（v5 W1）。
- **B8 稻草人 falsification**：给一个数值上"看起来量化"但对照双方不满足单变量、或对照必然成立的 falsification，绕过只查"有无量化值"的 P5。
- **B9 状态/签收越权**：尝试无 `human:` 签收把 status 推到 verified；用错误的 status_history 键名、错误的 `by` 前缀（无 `machine:/redteam:/human:` 冒号）、DAL 与 human_review 不匹配，找出 gate 的边界；也试"机器自检自签"能否闭环。
- **B10 盲读欺骗**：构造一张**形式 100% 完美（字段齐全、断言 confirm、留痕漂亮）但 claim 方向错误**的卡。模拟红队两段式盲读：只看夹具/工件时能否识破？如果形式信号齐全会显著增加识破难度，记录这是流程弱点。

- 明确给出一句话结论：**当前系统在无人盯防（放权）时，最坏能被污染到哪一步。**

## 10. 同族对抗模式（当攻击者与建设者同模型族时，本节覆盖 §3.5）

**本批启用条件：攻击者 = DeepSeek v4.1 flash 新会话（无记忆），建设者也是 DeepSeek v4.1 flash。** 同族共享训练直觉与思维盲区，"发现全新攻击类别"的能力天然偏弱，故重排 KPI，不复用 §3.5 的"盲测发现已知洞"（已知洞在投喂前已由建设者修复）。

### 10.1 前置（建设者已完成，攻击者开卷即知）
建设者已修复其自述工具债 W1/W2/W3/A1/A3，每项配毒样例 + pytest 并单独提交。攻击者会拿到一份**修复清单**（commit hash、新规则名、新增毒样例编号、修复了什么）。同族模式不忌讳看修复清单——洞已修，目标是找"修复是否完备、能否绕过"。

### 10.2 攻击 KPI（按优先级）
1. **【主】修复绕过（变异测试）**：对每一项已修复的洞，构造**新变种**尝试绕过新规则/新检查。例如：W3 加了"零诊断必须 -Werror"，尝试用 `-w`、`#pragma GCC diagnostic`、`system()` 抑制、把警告移到不被编译的 TU、用 `-isystem` 把夹具伪装成系统头……每个变种裁决仍 BLOCKED 还是被绕过 ESCAPED。要求同时验证**干净例不被误伤**（FALSE_POSITIVE）。
2. **【主】端到端逃逸链**：不只打单点。在沙箱里构造一个 **claim 方向错误**的原子，尝试把它从 draft 一路推到能同时通过 gate + replay（沙箱内模拟 machine-verified/verified 所需条件），找出最弱环节如何**串联**。单点都被拦不等于链跑不通；要给出"最接近成功的一条链卡在哪一步"。
3. **【主】攻击面机械穷举**（同族擅长、不依赖创造性）：frontmatter 字段缺失/错类型/错键名、路径分隔符（`\` vs `/`）、大小写、CRLF/LF、Unicode 同形字、相对/绝对路径、符号链接、空文件、超长行、YAML 折叠块 `>-`/`|`、重复键、矩阵字段与实际不符、status_history 键名/`by` 前缀边界、DAL 与 human_review 组合枚举。逐项给 BLOCKED/ESCAPED/FALSE_POSITIVE。
4. **【次】清单外新攻击**：尽力而为。同族在此项预期产出低，**有 1 个实测的清单外 ESCAPED 即超额完成**；找不到不扣分，严禁为凑数把推测包装成实测。

### 10.3 两阶段（灰盒→白盒，替代 §3.5）
- **阶段一·黑盒**：不读修复提交的工具源码，只对修复后的系统从外部攻击（写陷阱、跑门禁），记录行为。
- **阶段二·白盒**：再读修复 diff 与工具源码，针对实现细节找逻辑缝隙（如规则只匹配某种写法、豁免条件可被关键词骗过、正则漏 case）。
- 每条标注【黑盒】/【白盒】与对应修复项编号。

### 10.4 权重声明（必须写进报告开头）
本报告为**同族对抗**产物：能强力证伪"修复是否完备"、能系统发现执行层/配置层漏洞；**不能排除只有异模型才能想到的新攻击类别**。报告结尾须明确列出"同族未能覆盖、建议未来用异模型（如 Seed-Evolving）复攻的方向"。这不是谦虚，是如实标注证据边界。
