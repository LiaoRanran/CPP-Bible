# 400 阙疑 v6.0 逻辑自洽性审查：10 个结构性问题与修复

> 日期：2026-09-13。对 399 v6.0 做**内卷式自洽性审查**——不是外部对抗，而是内部找逻辑矛盾、循环依赖、未定义接口、闭环缺口。每个问题给出修复方案。
> 原则：**一份能自洽运行的架构，比一份看起来完整的架构更重要。**

## 问题 1：可观测性的"观测成本 vs 观测收益"矛盾

**矛盾**：399 说可观测性是所有优化的前提（L7），但可观测性本身消耗 token（记录数据）、工具输出是上下文污染源（L5）。观测越细，污染越大。

**修复**：分层观测——
- **默认层（零成本）**：只记录确定性数据（门禁结果、原子数、耗时、sha），写进文件不进上下文
- **诊断层（按需开启）**：per-step token/延迟，只在"本批出现异常"时开启
- **审计层（事后）**：完整 trace，只在对抗/事故调查时回放
- 观测数据**写文件不进上下文**，Agent 只读汇总指标（≤10 行），不读原始 trace

## 问题 2：多模型路由与 EIR 的鸡生蛋问题

**矛盾**：路由决策（L5）需要便宜模型的 EIR 数据（L7），但 EIR 数据需要先用便宜模型生产才能积累。没有 EIR 就不能安全路由，不路由就没有 EIR。

**修复**：三阶段冷启动——
1. **阶段 A（当前）**：全部用当前模型生产，同时用便宜模型做**影子运行**（shadow run）——便宜模型的产出不入库，只和贵模型对比，积累 EIR
2. **阶段 B**：便宜模型 EIR 连续 3 批 <5% 后，开放"低风险任务"（如证据卡格式检查、门禁结果解读）
3. **阶段 C**：EIR 连续 10 批 <1% 后，开放"中风险任务"（如证据卡初稿），高风险（claim 撰写、红队）永远用贵模型
- **明确**：便宜模型的产出必须经过 gate+replay 验证（确定性验证器），不依赖 LLM 评分

## 问题 3："谁来审红队"的无限递归

**矛盾**：红队误判（373 IFNDR 条款）需要仲裁，建设者有利益冲突，人审是最终仲裁但用户说"先机器审查"。机器仲裁机器会无限递归。

**修复**：仲裁分层，终止于可验证事实——
1. **红队发现** → 建设者可"接受"或"申诉"
2. **申诉**必须引用**可机器验证的证据**：标准条文原文（eel.is 链接+条款号）、工件反汇编行号、复现命令输出
3. 仲裁器（可以是另一个 Agent）**只验证证据是否成立**，不做主观判断
4. 如果证据是"主观判断"（如"claim 不够精确"），默认红队胜（建设者必须改）
5. 如果证据是"可验证事实"（如"IFNDR 不是 16.2 子条"），机器查原文即可终止递归
- **关键**：递归终止于"外部权威"（标准条文/工件/复现输出），不终止于"另一个模型的判断"

## 问题 4：声明-实现绑定的技术方案缺失

**矛盾**：399 铁律 5 说"声明-实现必须绑定"，但 command 是自由文本，静态分析可被 shell 转义绕过，沙箱监控当前没有。

**修复**：不做 command 文本分析，做**产物溯源**——
1. replay 重编译时，**实际执行 command**（已经在做），捕获实际调用的编译器路径和版本（`g++ --version` 的输出）
2. 比对实际编译器版本 vs 卡内 `artifact_compiler` 字段，不匹配→`infra_error:compiler_mismatch`
3. 比对重编译产物 sha vs 卡内 `artifact_sha256`，不匹配→`refute:artifact_stale`
4. command 里写 `cp other.asm x.asm` 这种借工件，重编译会覆盖 x.asm，sha 必然不匹配→自动暴露
5. **不需要沙箱监控**——重编译+sha 比对已经能抓住"声明-实现脱钩"，因为产物无法伪造（sha 是确定性的）
- **残余风险**：command 里写 `g++ ... && cp other.asm x.asm`（编译后覆盖）——需要检查 command 是否含 `cp`/`copy`/`mv`，发现即 block（简单文本检查，不是完整 shell 解析）

## 问题 5：正例集本身可能有盲区

**矛盾**：56 张合法卡是正例集，但"合法"是当前 gate 判定的。如果 gate 有盲区，正例集里可能有漏网坏卡，用有盲区的正例集回归会固化盲区。

**修复**：正例集定期独立审查——
1. 每次独立对抗（如 373）后，用新发现的攻击手法**回测全部 56 卡**（不只是毒样例）
2. 回测发现的"漏网坏卡"标记为 `legacy_debt`，不 block 但计入 warn
3. 正例集版本化：每次 gate 规则大改后，正例集快照（`tests/fixtures/legit_cards_v{N}/`）
4. **正例集不是"真理"，是"当前已知合法"**——它本身也在进化

## 问题 6：上下文压缩可能丢失关键事实

**矛盾**：383 说 70% 阈值触发压缩，但压缩可能丢失"这个 claim 被红队改过""这个 sha 是旧版"等关键事实。

**修复**：关键事实**必须持久化到文件，不依赖上下文**——
1. 定义"不可压缩事实清单"：
   - 工件 sha256、编译器版本、门禁结果
   - 红队裁决（采纳/驳回+理由）
   - claim 修订历史（方向性反转必须留痕）
   - 当前批次的待办清单和阻断项
2. 这些事实**必须写进卡内 frontmatter 或质检报告**，不能只存在于对话上下文
3. 上下文压缩时，Agent 从文件重新加载这些事实（不靠记忆）
4. **原则**：对话上下文是易失的，文件是持久的。任何"丢了会导致错误决策"的信息必须在文件里

## 问题 7：知识图谱冷启动的假阳性

**矛盾**：relations schema 落地后，存量 27 颗逐步迁移期间图谱不完整，缺口检测会产生大量假阳性（"这颗原子没有 prereq"可能只是没回填）。

**修复**：图谱迁移状态标记——
1. 每颗原子加 `graph_migrated: true/false`
2. 缺口检测只扫 `graph_migrated: true` 的原子
3. 存量迁移按域推进（mem→conc→lang→...），每完成一个域做一次完整性检查
4. 全部迁移完后删除 `graph_migrated` 字段

## 问题 8：Fuzzing 过度依赖 Clang

**矛盾**：399 说 Fuzzing 需 Clang（P3），但毒样例自动化不一定需要覆盖率引导。

**修复**：分两条路——
1. **LLM 变异（不需要 Clang，P2）**：Mut4All 思路——从 14 逃逸+13 绕过中提取攻击模式，让 LLM 生成变异毒样例（文本级变异：改 frontmatter、改 relations 写法、改 actual 格式）
2. **覆盖率引导 Fuzzing（需 Clang，P3）**：libFuzzer 对 gate_engine.py 的 Python 代码做覆盖率引导（需要 atheris，Python 的 libFuzzer 绑定）
3. **大部分逃逸是文本级的**（frontmatter 伪造、字段缺失、格式变异），LLM 变异就能覆盖；覆盖率引导主要用于发现 Python 代码的解析盲区

## 问题 9：MCP 化是"为未来设计"

**矛盾**：工具都是仓库内 Python 脚本，只在这个项目用，MCP 化的"其他 Agent 可调用"收益当前不存在。

**修复**：MCP 化降级，先做 JSON 输出——
1. **P2 只做 JSON 输出**（`--json` 标志）：这是 MCP 化的前置，且独立有用（Agent 解析 JSON 比解析文本可靠）
2. **MCP 化推迟到 P3**：当出现"需要在 Cursor/Claude Code 中直接调用 gate"的真实需求时再做
3. **不过度工程化**——YAGNI 原则

## 问题 10：数据飞轮 Distill 的可靠性

**矛盾**：Distill（失败模式自动聚类）用 LLM 聚类，聚类结果可能错误或遗漏，错误的聚类会导致错误的规则进化。

**修复**：Distill 人机协同，不做全自动——
1. LLM 负责**候选聚类**（从一批红队发现中提取模式，给出分类建议）
2. 人（或监工 Agent）负责**审核聚类**：合并/拆分/驳回
3. 只有审核通过的聚类才进入 Improve（规则进化）
4. 每次聚类保留"未分类"桶——LLM 不确定的不强行归类
5. **类比**：LLM 是住院医（提诊断），人是主治医（签字确认）

## 修复后的架构调整汇总

| 层 | v6.0（399） | v6.1（400 修复） |
|---|---|---|
| L7 可观测性 | 全量 per-step | 三层（默认/诊断/审计），数据写文件不进上下文 |
| L5 路由 | 直接级联 | 三阶段冷启动（影子运行→低风险→中风险） |
| L6 红队仲裁 | 未定义递归终止 | 终止于外部权威（标准条文/工件/复现输出） |
| L3 声明-实现绑定 | 只有原则 | 产物溯源（重编译 sha+编译器版本+cp/mv 检查） |
| L6 正例回归 | 56 卡固定 | 版本化+对抗后回测+legacy_debt 标记 |
| L5 上下文压缩 | 70% 阈值 | +不可压缩事实清单（必须持久化到文件） |
| L1 知识图谱 | 直接落地 | graph_migrated 标记+按域迁移 |
| L6 Fuzzing | 需 Clang P3 | 拆为 LLM 变异（P2）+覆盖率引导（P3） |
| L3 MCP 化 | P2 | 降级为 JSON 输出（P2），MCP 推迟 P3 |
| L7 Distill | 自动聚类 | 人机协同（LLM 候选+人审核） |

## 元结论

v6.0 的 10 个问题中，最关键的 3 个：
1. **红队仲裁的递归终止**（问题 3）——不解决，"机器审查更严"就是空话
2. **声明-实现绑定的技术方案**（问题 4）——不解决，373 的 14 个逃逸还会复发
3. **关键事实持久化**（问题 6）——不解决，上下文压缩/窗口切换会反复丢信息

这 3 个是"不做就会出错"的，其余 7 个是"做了更好"的。
