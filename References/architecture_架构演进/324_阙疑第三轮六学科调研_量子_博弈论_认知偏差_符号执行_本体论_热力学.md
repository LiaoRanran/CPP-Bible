## 一、量子信息：claim 的叠加态与测量坍缩

### 1.1 核心隐喻

**叠加态 → 测量坍缩**：
- claim 在被验证前处于"叠加态"（可能对也可能错，置信度在 0-1 之间）
- replay 验证 = "测量"，导致 claim 坍缩为 confirm（对）或 refute（错）
- 未验证的 claim 是"潜在的"，验证后的 claim 是"确定的"

**纠缠**：
- 同一夹具的多张证据卡共享工件 = "纠缠态"
- 一张卡的 sha 变化会影响所有关联卡（非局域性）
- 量子纠错：多个冗余证据卡可以纠正单个卡的错误

### 1.2 对「阙疑」的映射

| 量子概念 | 「阙疑」对应 |
|---|---|
| 叠加态 | 未验证的 claim（draft 状态） |
| 测量 | replay 验证 |
| 坍缩 | confirm/refute 二值结果 |
| 纠缠 | 共享工件的多张证据卡 |
| 量子纠错 | 多证据卡冗余验证 |
| 退相干 | 证据卡随时间失效（编译器升级后断言失效） |

**实用价值**：这个隐喻解释了为什么"未验证的 claim 不能当作知识"——它处于叠加态，只有测量（验证）后才有确定值。也解释了为什么证据卡需要冗余（量子纠错）。

## 二、博弈论：Writer/红队/Gatekeeper 的三方博弈

### 2.1 核心理论

**纳什均衡**：没有 agent 能通过单方面改变策略来提高收益。

**演化博弈**：
- Replicator Dynamics：高收益策略在群体中扩散
- ESS（演化稳定策略）：即使有变异也不会被入侵的策略
- Ev-Trust：将信任度转化为生存优势，抑制短视行为

**机制设计**：
- 从"内部对齐"转向"外部交互规则"
- 设计激励让安全行为成为理性选择
- CoopEval 评估四种合作机制：重复博弈/声誉系统/第三方调解/契约

### 2.2 对「阙疑」的映射

**三方博弈分析**：

| 角色 | 策略空间 | 收益函数 |
|---|---|---|
| Writer | 严谨写 / 敷衍写 | 通过红队的概率 - 写作成本 |
| 红队 | 严格审 / 走过场 | 抓出真问题的声誉 - 审查成本 |
| Gatekeeper | 严格拦 / 宽松放 | 拦截错误的声誉 - 误报成本 |

**当前均衡分析**：
- 当前均衡：Writer 严谨写 + 红队严格审 + Gatekeeper 严格拦
- 这是高成本均衡，但也是高质量均衡
- 风险：如果红队"走过场"的收益 > "严格审"（因为抓不出问题也不会被惩罚），均衡会漂移

**演化稳定策略（ESS）识别**：
- 哪些规则是 ESS？（即使有 Agent 试图"作弊"也不会被入侵）
- 三权分立是 ESS：Writer 不能自己审查自己（否则确认偏误）
- replay 是 ESS：不能跳过验证（否则 claim 处于叠加态）
- 人审是 ESS：高 DAL 原子不能跳过（否则错误传播）

**信任/声誉机制**（Ev-Trust 的映射）：
- 红队的"抓出真问题率" = 声誉
- 高声誉红队的意见权重高（贝叶斯可靠性，322）
- 低声誉红队自动降级（演化选择）

**机制设计的落地**：
- 红队抓出真问题 → 记录到声誉系统
- Writer 一次过红队 → 记录到声誉系统
- 声誉影响后续任务分配（高声誉 Writer 可以做高 DAL 原子）

## 三、认知偏差：红队和人审的心理学基础

### 3.1 核心理论

**确认偏误**（Confirmation Bias）：
- 最普遍的认知偏差
- 倾向于寻找、解释、记忆支持已有信念的信息
- 三种形式：选择性搜索、选择性解释、选择性记忆

**锚定效应**（Anchoring）：
- 第一个信息影响后续判断
- "anchor-first"协议可降低 40% 锚定效应

**动机性推理**（Motivated Reasoning）：
- 推理本身被想要的结论塑造
- 比确认偏误更深层：不只是选择性搜索，而是推理过程被污染

**制度化红队**：
- AI 实验室不只是要求模型"更诚实"，而是分配红队角色
- 红队的正式工作是"打破东西、暴露失败模式"
- 不是建议，而是强制

### 3.2 对「阙疑」的映射

**各角色的认知偏差与防御**：

| 角色 | 主要偏差 | 防御机制 |
|---|---|---|
| Writer | 确认偏误（找支持证据） | 两段式盲读（红队先不读卡） |
| Writer | 锚定效应（第一个 claim 影响后续） | claim 必须先经过"反面论证" |
| 红队 | 确认偏误（倾向于"抓问题"） | 红队必须同时给出支持和反对证据 |
| 红队 | 动机性推理（想要证明 Writer 错） | 红队结论必须配可验证的证据 |
| 人审 | 确认偏误（倾向于"通过"） | 人审必须先读红队报告再决定 |
| 人审 | 锚定效应（第一个原子的质量影响后续） | 人审按随机顺序审查 |

**红队提示词的"认知偏差检查清单"**（新增 can't-miss 条目）：
1. 我是否只找了支持 claim 的证据？（确认偏误）
2. 我是否被 claim 的第一个表述锚定了？（锚定效应）
3. 我是否想要证明 Writer 错？（动机性推理）
4. 我是否忽略了矛盾的证据？（选择性记忆）
5. 我是否把"没有发现问题"等同于"没有问题"？（无知论证）

**"AI 太同意你了"的警示**：
- Psychology Today 2026-08：AI 和团队都有确认偏误，需要制度化的反对角色
- 「阙疑」的三权分立就是制度化的反对角色
- 但要警惕：红队也可能变成"同意机器"（如果红队和 Writer 用同一个模型）
- 防御：红队用不同模型（多模型协作，308）

## 四、符号执行：夹具的全路径验证

### 4.1 核心理论

**KLEE 符号执行引擎**：
- 不用具体值（x=5），用符号值（x=symbolic）
- 跟踪路径约束（path condition）
- 自动生成高覆盖率测试，探索所有可能执行路径
- 发现传统测试找不到的 bug（断言违反、空指针、缓冲区溢出）

**Concolic testing**：
- 混合具体执行和符号推理
- 提高可扩展性和路径探索效率

**LLM + 符号执行**（2026）：
- 4-agent 架构检测 Rust 内存漏洞
- Oracle/Validator 做战略规划，Safety Agent 做安全分析

### 4.2 对「阙疑」的映射

**当前 replay 的局限**：
- 只跑一次具体输入（确定性输出）
- 只能验证"这一次运行"的行为，不能验证"所有可能运行"
- 对于 CONC 域（数据竞争、内存序），一次运行可能看不到竞争

**符号执行的升级**：
- 用 KLEE 对夹具做符号执行，探索所有输入路径
- 验证 claim 的不变量是否在**所有路径**上成立
- 例如："unique_ptr 转移后源为空"——符号执行可以验证所有输入下源都为空

**CONC 域特别适合**：
- 数据竞争检测：符号执行可以穷举线程交错
- 内存序验证：符号执行可以探索所有重排可能
- 无锁算法验证：符号执行可以检测 ABA 问题

**落地路径**：
- 我们的原子夹具通常 <100 行，适合符号执行（路径爆炸问题不严重）
- 为高 DAL 原子（A/B 级）加 KLEE 符号执行验证
- 作为 L3 验证层（322 的形式化验证分层）的具体实现
- 工具：KLEE（C/C++）或 CBMC（有界模型检查）

**与 replay 的关系**：
- replay = 具体执行（一次运行）
- KLEE = 符号执行（所有路径）
- 两者互补：replay 验证具体输出，KLEE 验证全路径不变量

## 五、本体论：从分类法到逻辑推理

### 5.1 核心理论

**OWL（Web Ontology Language）**：
- W3C 标准，用于表达丰富的本体
- 类（Class）、属性（Property）、个体（Individual）
- 基于描述逻辑（Description Logic），可判定的一阶逻辑子集

**推理机（Reasoner）**：
- 从显式知识推导隐式知识
- 例：Manager ⊑ Employee ⊑ Person ⇒ 推理出 Manager 是 Person
- 检测不一致性（矛盾）

**从分类法到本体**：
| 层级 | 能力 | 缺失 |
|---|---|---|
| Schema | 结构 | 语义、推理 |
| Taxonomy | 层级 | 逻辑、公理 |
| Ontology (OWL) | 概念、关系、公理、推理 | — |

### 5.2 对「阙疑」的映射

**当前原子体系是"分类法"**：
- 按域（MEM/CONC/UB）和类型（mechanism/pitfall/contrast）分类
- 只有层级，没有逻辑约束和推理

**升级为"本体"**：

```owl
# 类定义
ATOM-MEM-RAII a owl:Class ;
    rdfs:subClassOf ATOM-MEM .

# 属性定义
prereq a owl:ObjectProperty ;
    rdfs:domain ATOM ;
    rdfs:range ATOM .

# 约束
ATOM-MEM-RAII prereq ATOM-MEM-VALUE-001 .  # RAII 依赖值类别

# 基数约束
ATOM a owl:Class ;
    rdfs:subClassOf [
        a owl:Restriction ;
        owl:onProperty hasEvidence ;
        owl:minCardinality "1"^^xsd:integer
    ] .
```

**推理机可以自动检测**：
- 循环依赖（A prereq B, B prereq A）
- 孤立原子（没有任何关系的原子）
- 不一致的类型声明（原子声明为 mechanism 但内容是 pitfall）
- 缺失证据（hasEvidence 基数 < 1）

**与 gate 的关系**：
- gate 是模式匹配（正则/关键字）
- 本体推理是逻辑推理（子类关系/基数约束/不一致检测）
- 两者互补：gate 做快速检查，本体做深度推理

**落地路径**：
- 先用 RDFS（轻量级）建立原子的类层级和属性
- 再用 OWL 添加逻辑约束（基数、不相交、等价）
- 用 Python 的 OWLAPI（owlapy）或 rdflib 实现
- 工具：`tools/ontology_check.py`，作为 gate 的补充

## 六、热力学：「阙疑」作为局部熵减系统

### 6.1 核心理论

**熵 = 无序度/不确定性**：
- 热力学熵：系统的微观状态数
- 信息熵（Shannon）：不确定性的度量
- 热力学第二定律：封闭系统熵增

**生命 = 局部熵减**：
- Schrödinger（1944）：生命以负熵为食
- 开放系统可以局部熵减（同时增加全局熵）
- 自组织：远离平衡的开放系统自发形成有序结构

**自由能原理与熵的统一**（323 的深化）：
- 自由能最小化 = 熵抵抗 = 预测误差最小化
- 三层统一：热力学层（Schrödinger）→ 信息论层（Friston）→ 神经科学层（Seth）

**进化的热力学理论**（2025）：
- 进化不只是随机变异+选择
- 还有第二驱动力：信息熵减少
- 熵减生成复杂性，选择精炼和稳定

### 6.2 对「阙疑」的映射

**「阙疑」是局部熵减系统**：
- 投入能量（计算/人工）→ 将无序的知识变成有序的原子体系
- 知识熵 = 原子体系的不确定性（未验证的原子、矛盾的 claim、缺失的证据）
- 每批生产原子 = 降低知识熵（从不确定到确定）

**熵增的风险**：
- 如果不维护，系统会"熵增"：
  - 原子过时（编译器升级后证据失效）
  - 证据失效（断言不再匹配）
  - 关系断裂（原子被删除后引用悬空）
  - 规则膨胀（只增不减，warn 持续上升）

**熵减的机制**：
- replay 复跑 = 对抗"证据失效"的熵增
- golden_lock sync = 对抗"关系断裂"的熵增
- 规则适应度计算 = 对抗"规则膨胀"的熵增（323 进化算法）
- 原子激活值调度 = 对抗"原子过时"的熵增（323 复杂网络）

**自组织的目标**：
- 系统应该能自发形成有序结构，不需要人工干预
- 规则的自动进化（323）= 自组织的规则层
- hub 的自动识别（323）= 自组织的网络层
- 置信度的自动更新（322 贝叶斯）= 自组织的决策层

**与自由能原理的统一**：
- 「阙疑」的自由能 = claim 与证据的差距（预测误差）
- 最小化自由能 = 最小化知识熵 = 提高系统的有序度
- 主动推理 = 主动设计实验来降低不确定性（探索高不确定性领域）
