## 背景（最小必要上下文）
阙疑元系统：机器可核验、错误率有上界、可审计、可随模型升级换验证者。当前 C++ 试车场有 27 张原子卡 / 79 条 claim_structured 命题（observation 50 / inference 29）。mutation 七算子持续对证据卡做变异测闸门。最新 v3 基线总逃逸 38/997=3.81%；刚挖出最大活雷 **M5：29/29 inference 命题被改成 observation 后，OBSERVATION-LIVENESS 活性闸全放行**。
- 根因：活性判据是**卡级**的（命题引用的证据卡上有夹具符号/量化取值/非环境 run 键即放行），不是**命题级**的（不校验那个对照能否证伪这条具体命题）；inference 命题蹭了同卡别的 observation 命题的工件证据。
- 建设侧 575 拟的收口：observation 命题必须在命题项内显式带 `liveness` 锚（主形态 `kind: fixture_symbol, symbol: X`，机检 X 真实出现在引用卡 artifact_assert 中且非通用符号；另有 quantified / run_key 两形态），缺锚或锚假 ⇒ warn；inference 命题靠 external_basis 不要求锚。新规则 warn 起步。

## Part A：评审「命题级活性锚」是不是对的收口（最重要，先做）
1. **这个设计会不会只是把缺口上移一层？** writer 仍可给 observation 命题随手填一个「引用卡里真实存在、非通用、但并不证伪这条命题」的符号——纯结构机检只能验「锚存在且非通用」，验不了「锚针对性」。请严格论证：在不引入 LLM 语义判别的前提下，命题级锚把攻击成本提高了多少、还剩什么不可消除的缺口，这个残余是否只能靠人签/未来更强验证者。
2. **找更优或更差的替代结构**，至少评估：① 要求 observation 命题的锚符号在卡上**只被这一条命题引用**（排他锚，机器可查符号→命题引用计数）；② 阴面翻转与命题锚绑定（V-iso 阴面删机制时，必须翻转的正是该命题声明的锚符号——把活性锚和阴阳同构焊死）；③ 命题级 witness/certificate（每命题一个可独立重放的最小证伪脚本）。给出每种的机检可行性、误伤面、苦力成本。
3. **异族先例调研**（真实来源+链接+日期）：需求可追溯性矩阵（requirements traceability，每条需求↔测试的双向追溯，与命题↔工件锚是否同构、能否借其「孤儿测试/孤儿需求」检测）；argument interchange format / AIF、Dung 论证框架在 claim-evidence 针对性上的机器判据；scientific claim verification / evidence attribution per claim（2024–2026）；形式化 witness/编译器 certificate（为什么一个 witness 能证一条具体性质而不只是「程序跑过」）；KG/文献库里三元组「出处到命题」的 grounding 做法（PROV-O、W3C PROV）。每条挂「阙疑现在能借什么、哪部分必须等模型」。
4. 给一句裁决：575 的命题级锚方向**做 / 改后做 / 不做**，若改，给出最小修改。
