## 三、核心概念 20 个（每个含不可替代性论证）

### A. 宪法层（4 个，Lakatos hard core）

**1. 五公理**
- 来源：277 宪法
- 内容：证据先于断言 / 验证必须独立 / 可证伪性 / verified 唯人签 / 修宪程序
- 不可替代性：整个体系的价值基础。去掉任何一条，体系的判定权就会混乱（如去掉「verified 唯人签」，机器就能自封 verified，三权分立崩塌）。Lakatos hard core——放弃=放弃整个纲领。

**2. 六态状态机**
- 来源：270 阙疑 → 271 收敛 → 277 宪法
- 内容：idea → candidate → draft → verified → deprecated → retracted（含阙疑悬置判断）
- 不可替代性：原子生命周期的唯一状态定义。没有它，「什么算完成」「什么可以进教材」就没有客观标准。阙疑（EPOCHE）已融入此概念，不再独立存在。

**3. 三权分立（Writer / RedTeamer / Gatekeeper）**
- 来源：277 宪法判定权矩阵
- 内容：生成权 / 批判权 / 判定权分离，verified 唯人签
- 不可替代性：防止「自己写自己审」的确认偏误。注意：285 反例 1 要求升级为「方法独立」（不仅跨模型，更要跨方法），但三权分立的组织设计本身不可替代。

**4. 修宪程序**
- 来源：277 宪法第九节
- 内容：提案 → 红队批判 → 人审批准 → 生效，旧版降级为只读演进档案
- 不可替代性：架构变更的治理机制。没有它，架构会变成「谁都能改」的混乱状态，或「永远不改」的僵化状态。

### B. 执行层（5 个）

**5. 8 环节执行流水线**
- 来源：277 宪法第八节（吸收 272 SCAFFOLD）
- 内容：选题 → 夹具 → 证据卡 → 原子草稿 → 红队 → 门禁 → 人审 → 原子化
- 不可替代性：从选题到 verified 的标准流程。没有它，每批原子生产的质量不可控。SCAFFOLD（272）的失败模式/护栏/杠杆已融入此概念的各环节，不再独立。

**6. gate_engine（机械判定）**
- 来源：267 门禁硬化 → 269 证据约束网 → 工程实现
- 内容：33 条规则，机械复算 claim/actual/frontmatter/relations，block=0 才能过
- 不可替代性：「模型是提议器，系统是判定者」的核心实现。没有它，所有判定都依赖模型推理（不可靠）。注意：规则需要元规则压缩（P4–P7 可合并为「断言可证伪」元规则），但 gate_engine 本身不可替代。

**7. 毒样例（poison_drill）**
- 来源：273 GAUNTLET → 工程实现 P1–P11
- 内容：已知错误模式的最小样本，验证 gate 能拦住（P1 硬编码 / P4 自证断言 / P6 恒真观测 等）
- 不可替代性：gate 的制衡——防止 gate 规则自身有漏洞。没有毒样例，gate 可能「看起来在工作但实际拦不住真错误」。GAUNTLET（273）的压力测试协议降级为「毒样例的扩展协议」，待工程验证后升级。

**8. golden_lock**
- 来源：工程实现
- 内容：跨文件一致性锁——原子/证据卡/误解/夹具的引用关系必须同步，恶化=0 才能过
- 不可替代性：多文件系统的一致性守护者。没有它，改了原子忘了改证据卡，引用关系就会断裂（第五批 EV-SERVES-EXIST 债就是例子）。

**9. error budget / debt_ledger**
- 来源：276 P0 四项 → 工程实现
- 内容：带息债务 / owner 必须 human / 到期 ≤90 天 / 负债率 >15% 停线
- 不可替代性：技术债的量化管理。没有它，warn 会无限累积（当前 24% 已超管控线），体系会被自己的债务拖垮。

**10. 红队方法论**
- 来源：277 宪法 + 285 C1 鉴别诊断 + 285 错误预测
- 内容：独立上下文（P1-1 不给草稿全文）+ 鉴别诊断（先列 3-5 错误假设再验证）+ 对照实验优先 + 错误预测（下一批 ≥3 条）
- 不可替代性：三权分立中「批判权」的实现。没有它，红队就是「走过场」（第五批证明：压缩红队会放过方向性错误）。此概念吸收了 P1-1、鉴别诊断、错误预测，不再各自独立。

### C. 证据层（3 个）

**11. 真机取证 + 客观锚（sha256）**
- 来源：277 宪法公理 1 → 工程实现
- 内容：夹具必须真机编译运行，输出锚定 sha256，跨编译器用 contains_any
- 不可替代性：「证据先于断言」的实现。没有它，claim 就是空谈（ALLOC-002 初版就是没有独立取证导致方向反转）。

**12. 断言锚纪律**
- 来源：PERF-003 教训 → 固化
- 内容：actual 只锚常量+活性对照，时序数据/性能倍数放 .out 留痕层，不入断言
- 不可替代性：防止「断言被环境波动打碎」（PERF-003 的倍数从 18.86× 变 8.78× 证明：锚倍数=自找麻烦）。这是从失败中提炼的元纪律，不可替代。

**13. 证据卡标准（chain of custody）**
- 来源：285 C2 法律证据链 → 升级
- 内容：五问（谁编译/何时/在哪/怎么保存/什么记录确认）+ 可移植性边界（哪些断言跨编译器稳定）
- 不可替代性：证据的可审计性。没有它，证据卡只有 sha（回答「完整性」），没有「谁/何时/在哪」（回答「来源」），复现性不足。

### D. 知识管理层（4 个）

**14. prerequisite DAG / learning_path**
- 来源：276 P0 三项 → 工程实现（learning_path.py / atom_coverage_map.py）
- 内容：原子间的前置依赖边，拓扑排序生成学习路径，覆盖率门禁
- 不可替代性：知识体系的结构骨架。没有它，原子就是孤立的知识点，不是「贯通的系统教材」。fringe.py（修正案 4）是此概念的扩展（最薄弱优先），不再独立。

**15. claim 契约化**
- 来源：282 修正案 1 + 280 形式化方法
- 内容：claim 含 precondition / postcondition / invariant 三段式，gate 机械检查
- 不可替代性：规格优先（Spec Review），治 ALLOC-002 式的「规格错了但格式对」。**待工程验证**——需在一批原子生产中实施后确认有效。

**16. 分层记忆（core / recall / archive）**
- 来源：283 T4 + 285 反例 6 修正
- 内容：规则驱动自动归档 + append-only + Agent 只读+追加，core 由系统维护
- 不可替代性：上下文管理——解决 MEMORY.md 膨胀和上下文耗尽后需人重新喂摘要的问题。**待工程验证**——MemGPT 式的自主管理对弱模型危险（静默失败），修正为规则驱动后需验证。

**17. 混合检索（T3）**
- 来源：283 T3
- 内容：文档语义 + 代码精确 + 图遍历三路并行，一次查询返回原子+证据+夹具
- 不可替代性：知识获取效率——当前 Agent 找东西靠 grep+手动，90 工具零检索。**待工程验证**——最小可用版（关键词+frontmatter 过滤）可先做。

### E. 元治理层（4 个）

**18. 概念治理规则**
- 来源：282 修正案 5 + 284 元批判 + 285
- 内容：概念零增长（新增必须退役等价）+ 不吸收标注 + 最小可用版 + 不可替代性论证
- 不可替代性：防止概念膨胀（266→286 从 1 个概念膨胀到 53 个就是因为没有这个规则）。本文档即此规则的第一次执行。

**19. 架构成熟度模型（极致 5 标准）**

- 内容：预测性 / 概念收敛 / 架构-工程闭环 / 方法独立 / 停止条件，5 条可操作标准
- 不可替代性：判断「架构是否足够好可以开工」的度量。没有它，「还不够极致」永远成立（Xeno 悖论）。

**20. 调研质量标准（三关）**
- 来源：284 元批判
- 内容：原文精读关 + 反例关 + 落地关，不过三关的调研不算「证据级」
- 不可替代性：防止摘要级调研（275–283 全是摘要级，285 才过三关）。没有它，调研会无限累积但不吸收（调研通货膨胀）。

## 七、审计结论

### 收敛结果
- 审计前：53 个概念（21 份文档）
- 审计后：核心 20 + 待验证 5 + 退役 22 + 档案 6
- **概念数量减少 62%**（53→25 个活跃概念）

### 关键发现
1. **266–272 的早期概念几乎全部被吸收**——SVKC/门禁/自审/证据约束网/阙疑/SCAFFOLD 都已融入宪法和工程实现，继续作为独立概念存在是冗余。
2. **273–274 的创造力/压力测试机制未实施**——GAUNTLET/FORGE 停在提案级，降级为待验证扩展。
3. **283 的 5 个工具只有 2 个值得做核心**（T3 混合检索、T4 分层记忆），T1 合并入 claim 契约化，T2/T5 降级为工程优化。
4. **284–286 的元层面概念（三关/成熟度/概念治理）是元规则**——它们不直接生产原子，但保证体系不退化，必须保留为核心。

### 与 271 概念上限的对齐
271 规定「状态/机制各 ≤6」。当前：
- 状态概念：六态机（1 个，含 6 个状态值）✓
- 机制概念：核心 20 个中，纯机制约 12 个（gate/毒样例/golden_lock/debt/红队/取证/断言锚/证据卡/DAG/契约化/记忆/检索）——**超过 6**。
- 修正：271 的「机制 ≤6」是早期约束，当前体系复杂度已超出。建议将「机制 ≤6」修正为「机制分层 ≤4 层，每层 ≤6 个」（L2 执行层 6 个 / L3 证据层 3 个 / L4 知识层 4 个 / L5 元治理 3 个）。这是对 271 的合理修正，需走修宪程序。
