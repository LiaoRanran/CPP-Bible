# 380 知识网络化：从原子集合到可计算知识图谱

> 日期：2026-09-13（夜）。监工完成。覆盖 374-379 均未深挖的一层：**如何把 27 颗平铺的原子升级为可计算、可推理的知识网络**。
> 这是"超强项目"的关键一跃：从"质量受控的知识条目库"到"能自主发现知识缺口、生成学习路径、检测跨概念矛盾的知识系统"。
> 流程：搜集 → 整理 → 挖掘 → 联系 → 批判 → 结合 → 应用。

## 一、搜集（搜了什么）

两路并行检索：
1. GraphRAG / 知识图谱构建 / 关系抽取 / 图谱推理（LLM 结合）
2. 教育领域知识图谱 / 知识点前置关系 / 自动构建

核心来源（12 份）：
- **GraphRAG 原始范式**：实体/关系抽取 → Leiden 社区检测 + LLM 摘要 → 全局（社区摘要）/局部（实体子图）检索
- **Towards Practical GraphRAG**（arXiv 2507.03226）：依赖解析构建达 LLM 性能 94%，成本大降；RRF 混合检索
- **Graph-R1**（arXiv 2507.21892）：超图构建 + 端到端强化学习，n 元关系事实抽取
- **CrossAug**（arXiv 2605.28004）：GNN 识别结构不完整子图，LLM 补全——**图缺口检测**
- **UniAI-GraphRAG**（arXiv 2603.25152）：**本体引导抽取**（预定义 Schema 引导 LLM 识别领域实体/关系）
- **Auto-HKG**（arXiv 2602.00020）：从题库自动构建层级教育知识图谱
- **K2-18 教育图谱转换器**：教材→概念+依赖+难度+评估点
- **AI 编程导师图谱**（CSDN）：循环→排序算法的前置关系
- **On Building a Knowledge Graph of Open Courses**：**PrerequisiteTo / EquivalentTo 关系**（学习顺序 + 可替代性）
- **概念依赖图**：需要先学什么 / 已知 A B C 下一步学什么 / 最短学习路径
- **知识图谱个性化学习路径**（技术栈）：前驱/后继/包含/相关关系 + 图推理
- **知识图谱增强 LLM 推荐**（编程技能体系）：图谱节点权重 + 个性化内容生成

## 三、挖掘（核心洞察）

**A. 图谱构建的"本体引导"是质量关键**：不是让 LLM 自由抽取实体关系（会抽出一堆无关边），而是**用预定义 Schema 引导**——告诉模型"本领域只有这几类实体、这几类关系"。UniAI-GraphRAG 证明本体引导显著提高抽取准确率。映射到我们：relations 字段（prereq/contrasts/serves）就是本体，但没显式化成 schema 约束。

**B. 高效构建**：依赖解析（规则）可达 LLM 性能 94%，成本大幅降低。映射：**关系抽取不一定需要大模型**——可以用确定性规则（比如同域原子自动检查是否有 prereq/contrasts）做初筛，LLM 只做复核。这符合 376 的任务分级。

**C. 教育图谱的关系类型比我们丰富**：我们有 prereq（前置）/ contrasts（对比）/ serves（服务），教育图谱还有 **EquivalentTo（等价/可替代）**——两个知识条目讲同一件事。这个关系对应：
- 375 的跨原子重复检测（N2 说两个原子重复）
- Book 章节去重
- 选题评估（"这个新原子是不是已有原子的等价物"）
我们的 relations 缺这个类型。

**D. 图补全 = 自动发现知识缺口**：CrossAug 用 GNN 识别"结构上不完整的子图"（该有边但没有），再让 LLM 补全。映射到我们：**relations 缺口检测**——哪些原子同域且主题相关但没有任何 relations 边？这大概率是遗漏的边。这比 375 的"证据缺口扫描"更具体、可机器判定。

**E. 图推理 = 学习路径 + 下一步选题**：概念依赖图能回答三个问题：①学 X 前需要什么？②已知 A B C，下一步学什么？③从 A 到 Z 的最短路径？第三个问题直接对应 Book 的教学顺序优化，第二个问题直接对应 377 的选题（链的末端 = 下一个自然问题）。

**F. 社区检测 = 知识地图**：Leiden 把图分成社区，每个社区有 LLM 摘要。映射：atoms/mem/、atoms/conc/、atoms/ub/ 就是现成的域社区，但域内没有更细的子社区。社区摘要可以作为 Book 章节大纲，也可以做覆盖率分析（哪些子主题没原子）。

**G. 混合检索**：向量+图+关键词融合。映射到平台化（378）：Phase 2 Web 应用的知识检索层，可以同时支持"按概念找原子"（图遍历）和"按语义找原子"（向量）。

## 四、联系（和我们系统的映射）

| 外部发现 | 我们的现状 | 差距 |
|---|---|---|
| B. 本体引导抽取 | relations 字段存在但散落 | 没有显式 relations schema（类型+约束+方向语义） |
| C. EquivalentTo 关系 | 只有 prereq/contrasts/serves | 缺"等价/重复"关系，跨原子重复检测无图支持 |
| D. 图补全 | 375 提出证据缺口扫描 | 可升级为"relations 缺口检测"（机器可判） |
| E. 图推理 | 377 提出想法链 | 可形式化为"概念依赖图上的学习路径生成" |
| F. 社区检测 | 域分目录（mem/conc/ub/lang） | 域内无子社区、无社区摘要、无覆盖率分析 |
| A. 高效构建 | 关系靠红队/建设者手工补 | 可用规则初筛+LLM 复核的半自动关系抽取 |

**已有雏形**：relations DAG（prereq/contrasts/serves）+ atoms/evidence/misconceptions 三目录结构 = 知识图谱的骨架。缺的是：显式 schema、等价关系、图补全、图推理工具。

## 五、批判（哪些不适用/有局限）

1. **完整 GraphRAG 对我们过度**：我们不需要实体抽取（原子是人工设计的知识单元，不是从文本挖的），不需要向量嵌入（原子规模小，几十个），不需要社区检测算法（域目录已经是社区）。**我们要的是"图的数据结构+图工具"，不是"图谱构建流水线"**。
2. **LLM 关系抽取对我们可能引入噪声**：我们原子数量少（27），人工维护 relations 是可行的；自动抽取反而可能抽错关系引入误导。半自动（规则初筛+人审）比全自动可靠。
3. **图数据库（Neo4j）过度**：27 颗原子用 JSON/脚本就够，不需要图数据库。只有到数百颗原子+需要复杂图查询时再考虑。
4. **EquivalentTo 需要谨慎定义**：两个原子"讲同一件事"和"讲相关的事"边界模糊。需要明确判据（比如：claim 能否互相蕴含？证据是否同源？）。
5. **图谱推理的结论需要回到证据卡验证**：图推理（"A 是 B 的前置"）产生的任何结论，都必须能追溯到 relations 字段和证据卡，不能是推理器"脑补"的。

## 六、结合（和已有架构的结合点）

**和 relations 归一（N1）**：N1 刚把 relations 双写法归一（2026-09-13），这是图谱化的前置——归一后才能可靠地解析和遍历。图谱化是 N1 的自然延伸。

**和 375 跨原子矛盾**：EquivalentTo 关系直接服务跨原子重复检测；图补全直接服务"矛盾/重复/缺口"三类问题的机器化。

**和 377 想法链**：想法链 = 概念依赖图上的路径。图建好后，"下一个自然问题"可以从链末端自动发现。

**和 378 平台化**：Phase 2 Web 应用的知识检索层 = 图遍历+向量融合。图谱是平台化的数据基础。

**和 Book 回流**：Book 章节 ↔ 原子引用的关系，本身就是图的一部分（chapter_serves_atom）。图谱化后可以检查"Book 引用了哪些原子、哪些原子没被 Book 引用"（知识回流缺口）。

**和 gate 规则**：可以加规则：`relations 引用的目标原子必须存在`（已部分有：ATOM-PREREQ-READABLE）→ 升级为"relations 类型必须在 schema 内"（格式层）+ "同域相关原子无 relations 边 → warn"（缺口层）。

## 七、最终应用（分阶段落地）

### 立即落地（零成本，流程改进）

**应用 1：relations schema 显式化**
- 定义 schema：`{prereq, contrasts, serves, equivalent}`（新增 equivalent）+ 每个类型的语义（方向、含义、允许的域组合）
- 写成 docs/kernel/relations_schema.md，gate 校验 relations 类型合法
- 这是图谱化的地基，N1 归一后就能做

**应用 2：relations 缺口检查（手工版）**
- 每批原子生产时，检查"本批原子与同域原子是否有应有而未有的 relations 边"
- 红队盲读时增加一项：看 relations 是否遗漏（比如新原子和某个既有原子明显对比关系但没写 contrasts）
- 不需要工具，改红队检查清单即可

### 中期落地（需少量工程）

**应用 3：relations 缺口检测工具**
- 脚本扫描：同域、主题关键词重叠（用 frontmatter 的 topic/type 字段）、但无 relations 边的原子对 → warn
- 对应 D 类图补全的最小实现（规则版，不用 GNN）
- 产出候选边清单，人审后补进 relations

**应用 4：equivalent 关系落地**
- 新增 relations 类型，先手工补已知等价/重复对（从 375 跨原子矛盾检测的结果开始）
- gate 校验 equivalent 边的两端 claim 是否确实可互相蕴含（warn 级）

### 长期落地

**应用 5：图推理工具**
- 基于 relations DAG：①学 X 的前置链 ②已知集合的下一步候选 ③最短路径（教学顺序）
- 输出给 Book 教学逻辑和选题评估
- 需要原子数量 ≥100 才有价值，早了是玩具

**应用 6：社区摘要与覆盖率分析**
- 每域生成子社区摘要（主题聚类）
- 覆盖率分析：Book 章节 ↔ 原子映射的空白区 = 选题候选
- 这是"认知智能"（377）的机器化支撑

## 九、局限与后续

- 本调研聚焦"知识网络化"，未覆盖"图的可视化呈现"（那是 378 平台化的事，TUI/Web 阶段再做）。
- 关系抽取的半自动化（规则初筛+LLM复核）需要先做一轮"人工标注 vs 自动抽取"的对照验证，确认自动抽取的准确率≥90% 才值得引入。
- EquivalentTo 的判据需要和红队一起定义清楚，否则会变成"随意标等价"的逃逸面。
- 图谱化的前提是 relations 字段质量足够（N1 归一 + 每批检查），在此之前图工具是"垃圾进垃圾出"。
- 本调研未覆盖"时序关系"（版本演进：一个原子如何取代另一个）——目前误解库的 MIS-* 编号有暗含时序，但未显式建模，留待未来。
