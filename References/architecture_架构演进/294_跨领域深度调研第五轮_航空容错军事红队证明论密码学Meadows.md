## 一、方向一：DO-178C 航空航天软件认证

### 核心内容

DO-178C 是民用航空机载软件的认证标准，定义五级 **DAL（Design Assurance Level）**：

| DAL | 失效后果 | 目标数 | 典型系统 |
|---|---|---|---|
| A | 灾难性（可能机毁人亡） | 71 | 飞行控制律、FADEC |
| B | 危险 | 较大 | 自动驾驶 |
| C | 较大 | 中等 | 显示系统 |
| D | 较小 | 低 | 乘客娱乐 |
| E | 无安全影响 | 0 | 非关键 |

**DAL A 级的核心要求**：
1. **双向可追溯性**：系统需求 ↔ 高层需求 ↔ 低层需求 ↔ 源码，四个层级双向 trace（每条需求能追到代码，每行代码能追到需求）
2. **DO-333 形式化方法补充**：专门指导形式化验证在航空软件中的应用
3. **工具资格等级 TQL 1–5**：工具本身也要认证——如果工具有 bug 会影响认证结果，工具必须达到对应 TQL
4. **四个 SOI 评审阶段**：SOI#1 Planning → SOI#2 Development → SOI#3 Verification → SOI#4 Certification
5. **seL4 案例**：用形式化证明（数学证明强度）满足 DO-178C，是微内核认证的里程碑

### 最强点

- **DAL 分级**：不是「所有软件一样严」，而是按失效后果分级——A 级 71 个目标，E 级 0 个。这是「按风险分配验证资源」的典范。
- **工具资格 TQL**：验证工具本身也要被验证——这正是我们的毒样例在做的事（验证 gate_engine 不会漏报），但 DO-178C 把它制度化了。
- **双向可追溯性**：不是单向的「需求→代码」，而是「代码→需求」也要能追——防止写了没人要的代码。

### 批判

- DO-178C 是文档驱动的，大量精力花在文档上而非实际验证上——形式化方法（DO-333）是补充但非强制。
- 认证成本极高，DAL A 级软件的开发成本是普通软件的 10 倍以上——不适合我们的「快速迭代」模式。
- 双向可追溯性在实践中常流于形式（traceability matrix 填表），不保证真正的理解。

### 吸收动作

| 动作 | 落点 | 优先级 |
|---|---|---|
| 原子按「失效后果」分级（不是按 type） | gate_engine 加 ATOM-DAL 规则：pitfall/contrast 类原子需要更强证据 | P1 |
| 工具资格制度化：每个 gate 规则必须有毒样例覆盖 | poison_drill 加 RULE-COVERAGE 检查：未被毒样例覆盖的规则 warn | P0 |
| 双向可追溯：证据卡→夹具→原子 claim 双向 trace | golden_lock 已有单向，加反向检查（夹具被哪些卡引用） | P2 |
| SOI 四阶段评审映射到 8 环节流水线 | 文档级，不做代码 | P3 |

## 二、方向二：军事红队方法论

### 核心内容

红队起源于冷战时期美军模拟苏联策略。以色列在情报失败后建立「魔鬼代言人」办公室。CIA《Tradecraft Primer》定义了结构化分析技术：

**核心技术**：
1. **ACH（Analysis of Competing Hypotheses）**：列出多个竞争假设，用证据矩阵逐个评估——不是找支持首选假设的证据，而是找「哪个假设被证据排除」
2. **Devil's Advocacy（魔鬼代言人）**：专门指派个人/团队论证主流结论是错的
3. **Team A/Team B**：两队分别论证不同假设，然后辩论
4. **High-Impact/Low-Probability Analysis**：分析概率低但影响大的情景
5. **"What If?" Analysis**：假设某事件发生，倒推其信号

**关键原则**（来自美军 ATP 2-33.4 和 CIA Tradecraft Primer）：
- 红队「不是为了对，而是为了测试共识能否存活挑战」
- 红队为指挥官工作，不为规划人员工作——**制度性独立**
- 只攻击不提出替代假设 = 只做了一半工作
- 只找漏洞不提出加固建议 = 「损坏报告没有修复建议」

### 最强点

- **ACH 的证据矩阵**：不是「找支持的证据」，而是「找排除假设的证据」——这是证伪主义在情报分析中的落地。
- **制度性独立**：红队直接向最高指挥官汇报，不被规划部门管辖——我们的红队独立子 agent 是技术独立，但缺少「组织独立」的制度保障。
- **「只攻击不替代」是半工作**：红队必须产出替代假设 + 加固建议。

### 批判

- 军事红队在实践中常沦为「仪式」——如果红队总是被忽视，它就变成了合规表演。
- ACH 的证据矩阵在证据模糊时容易变成「各打五十大板」，无法真正区分假设。
- 红队成员的「对手思维」需要专业训练，不是随便找个人唱反调就行。

### 吸收动作

| 动作 | 落点 | 优先级 |
|---|---|---|
| 红队必须产出「替代假设」（不只是找错） | 红队提示词加：每条阻断必须配「替代解释」 | P0 |
| ACH 证据矩阵用于 claim 验证：列出 claim 的 3 个竞争解释，用证据排除 | claim 契约化 v0.2 加「竞争假设」字段 | P1 |
| 红队「制度性独立」：红队上下文不包含 Writer 的自述（已在 P1-1 两段式中部分实现） | 红队提示词强化：第一段盲读夹具/工件，不读卡 | P0（已在 288 决策点 3） |
| High-Impact/Low-Probability 分析：每个原子必须考虑「如果 claim 错了，后果是什么」 | 人审问题模板加「claim 失效的最坏后果」 | P2 |

## 三、方向三：Curry-Howard 对应（命题即类型，证明即程序）

### 核心内容

Curry-Howard 对应是逻辑与程序语言之间的**精确数学等价**（不是隐喻）：

| 逻辑 | 程序语言 |
|---|---|
| 命题 φ | 类型 τ |
| 证明 p | 表达式 M |
| 「p 是 φ 的证明」 | 「M 是类型 τ 的表达式」 |
| 蕴含 A ⇒ B | 函数类型 A → B |
| 合取 A ∧ B | 乘积类型 A × B |
| 析取 A ∨ B | 和类型 A + B |
| 真 True | unit 类型 |
| 假 False | 空类型 |
| 证明化简 | 程序求值（β 归约） |
| 证明规范化 | 程序求值到值 |

**深层含义**：
- 写一个类型正确的程序 = 构造一个证明
- 类型检查器 = 证明验证器
- 程序求值 = 证明化简

### 最强点

- 给我们的「证据=证明」一个**数学根基**：claim 是命题，证据卡+夹具是证明，gate_engine 是类型检查器。
- 「证明化简=程序求值」意味着：证据可以被「化简」到最小形式——这正是我们的「断言锚只锚常量+活性对照」（去掉冗余证据）。
- 「空类型=假」意味着：如果能构造出空类型的表达式，就证明了矛盾——这是「反证法」的程序语言对应。

### 批判

- Curry-Howard 对应在直觉主义逻辑中成立，但经典逻辑（排中律）需要额外的控制算子（call/cc）——不是所有逻辑都能直接对应。
- C++ 的类型系统远非「证明系统」——它有 UB、有类型擦除、有未定义行为。Curry-Howard 是理想，C++ 是现实。
- 「证明即程序」在实践中只对纯函数式语言成立，有副作用的程序不对应任何有意义的证明。

### 吸收动作

| 动作 | 落点 | 优先级 |
|---|---|---|
| claim 契约化的数学根基：claim=命题，证据=证明，gate=类型检查器 | 写进 claim 契约化 v0.2 的「理论基础」节 | P1 |
| 「证明化简」= 证据最小化：证据卡应只保留不可约简的断言 | gate_engine 加 EVIDENCE-MINIMAL 规则：actual 中可被其他行推导的行 warn | P2 |
| 「空类型=假」= 反证法夹具：如果能构造出 claim 的反例，claim 被证伪 | 红队提示词加：尝试构造 claim 的反例（空类型表达式） | P1 |

## 四、方向四：密码学可证明安全

### 核心内容

密码学的「可证明安全」方法论：

1. **归约证明（Reduction）**：如果攻击者能攻破协议 X，就能构造另一个攻击者 B 攻破已知困难问题 Y（如大数分解、离散对数）。因为 Y 被认为是困难的，所以 X 是安全的。
   - 形式：Adv_X(A) ≤ f(q) · Adv_Y(B)，其中 q 是攻击者查询次数
2. **随机预言机模型（ROM）**：假设哈希函数是真随机函数（已知为假——真随机预言机不可计算），但几乎所有互联网协议都在 ROM 下证明安全。
   - 关键：ROM 是「已知为假但实用」的假设——与我们的「断言锚不完美但可复算」同构
3. **Game Hopping**：通过一系列「不可区分」的游戏转换，从真实攻击游戏逐步转换到一个明显安全的游戏。每一步转换必须证明「攻击者无法区分」。
4. **安全边界量化**：Adv(A) ≤ q_h · Adv_MLWE + (q_h + q_s)²/2^n——攻击者优势被量化为困难问题优势的函数。
5. **紧致性（Tightness）**：安全边界越紧致（f(q) 越小），证明越强。

### 最强点

- **归约证明的链式结构**：「如果 X 被攻破，则 Y 被攻破」——这正是我们的证据链应该有的结构：「如果证据卡 refute，则夹具输出与 actual 不符，则 claim 被证伪」。
- **ROM 的「已知为假但实用」**：承认模型不完美，但量化不完美的影响——这比「假装完美」诚实得多。
- **Game Hopping 的逐步不可区分**：每一步转换都必须证明「攻击者无法区分」——这是对照实验的严格形式。

### 批判

- ROM 下安全的方案在实际哈希函数下可能不安全（已知有反例）——「已知为假」的假设最终会咬人。
- 归约证明的安全边界常常不紧致（f(q) 很大），实际安全参数需要留大量余量。
- 可证明安全只证明「在模型下安全」，不证明「在现实中安全」——侧信道攻击、实现 bug 都不在证明范围内。

### 吸收动作

| 动作 | 落点 | 优先级 |
|---|---|---|
| 证据链归约化：每张证据卡必须声明「如果这张卡 refute，哪个 claim 被证伪」 | 证据卡模板加 `refutes: [ATOM-XXX]` 字段 | P1 |
| 「已知为假但实用」原则：断言锚的局限性必须显式声明（如「倍数不锚，只锚方向」） | 证据卡模板加 `limitations` 字段 | P0（已在 PERF-003/004 中实践） |
| Game Hopping 对照实验：逐步改变一个变量，每步证明「不可区分」 | 夹具设计方法论：对照实验必须逐步改变，不能一次变多个 | P1 |
| 安全边界量化：错误预测命中率应量化为「红队假设的验证动作产出新证据的比例」 | 288 OPT-2 已修正，本方向提供理论支撑 | P2 |

### 原文确认的关键洞察

- Meadows 原话：「人们通常知道杠杆点在哪，但几乎总是**推错方向**」——我们在参数层（12）花了大量精力，但真正的杠杆在范式层（2）。

## 六、交叉发现：五个方向的共同结构

五个看似无关的领域，共享同一个深层结构：

| 共同结构 | 航空 DO-178C | 军事红队 | Curry-Howard | 密码学 | Meadows |
|---|---|---|---|---|---|
| **分级/分层** | DAL A–E | 假设概率/影响 | 逻辑层级 | 安全边界紧致度 | 12 杠杆点 |
| **可追溯性** | 需求↔代码双向 | 证据↔假设矩阵 | 证明↔程序 | 归约链 | 信息流 |
| **验证验证者** | TQL 工具资格 | 红队的红队 | 类型检查器正确性 | ROM 已知为假 | 超越范式 |
| **替代/竞争** | 多目标 | ACH 多假设 | 经典vs直觉 | Game Hopping | 多范式 |
| **显式声明局限** | 认证范围 | 红队不是为了对 | 副作用不对应 | ROM 不完美 | 模型是部分的 |

**核心洞察**：这五个领域都在解决同一个问题——**在不确定中建立可验证的信任**。航空用认证、军事情报用红队、数学用证明、密码学用归约、系统思维用杠杆点。我们的「极致自律超级系统」也是在解决同一个问题。
