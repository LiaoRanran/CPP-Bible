## 〇、放权前提：系统假设了 Agent 善意（v5 最高优先级 P0）

v1-v4 都在优化"善意 Agent 如何更快更严"。但用户要放权、人不在场，**机制设计必须假设 Agent 会在约束内投机**——不是不信任，是不能把正确性建立在信任上。Agent 可"合法"骗过现有门禁的路径：

| 投机方式 | 为什么现有门禁抓不到 |
|---|---|
| self_check 跑旧版本，再改卡提交 | 字段存在且当时为真，最终卡与自检结果不符，无人复算 |
| claim 写模糊/不可证伪（"可能影响性能"） | replay 只验工件，判不了 claim 的可证伪性 |
| 断言锚选"必然出现但无判别力"的符号 | 恒真变体无穷，P4 毒样例只堵了"自定义函数满足"一种 |
| falsification 写稻草人对照 | P5 只查"有无量化值"，查不了"对照是否真有判别力" |
| 选最简单原子、避开难域 | 完成数量指标，覆盖率恶化（见 §4 恶性回路） |

**机制设计原则：让"骗过门禁"比"真做对"成本更高，而非依赖诚实。**

| 原则 | 落地 |
|---|---|
| 自检证据可独立复算 | self_check 必须带卡内容+夹具的 hash；gate/红队重算比对，hash 不符即"自检失效"阻断 |
| claim 可证伪性本身受检 | 新规则：claim 必须含至少一个"可观测、可失败"的预测（指向 evidence 的具体读数）；纯形容/无读数的 claim 直接 warn→block |
| 断言判别力检查 | artifact_assert 必须配"反例夹具下该断言失败"的证据（阴阳配对），否则视为无判别力 |
| 选题不能自由挑简单的 | 选题受覆盖率配额约束（§4），不由 Writer 自选 |

**这是放权的地基：T0（博弈防御）必须在大规模放权前完成，否则放权等于放大投机。**

## 一、认识论约束：归纳跳跃必须显式（P0）

证据卡实际证明的是：**在环境 E（编译器 X / 版本 Y / 档位 Z / 平台 P）下，工件呈现观测 O**。
但 claim 写的是普遍陈述：**机制 M 成立**。

从 O 到 M 是**归纳跳跃**，而系统没有字段标注这个跳跃的边界。真实打脸已多次发生：
- PERF-003：claim 隐含"某资源更快"，实测 MinGW 与 Linux 排序**完全相反**
- LEAK-002：LSan 报告与否随一个无关 volatile 计数器**翻转**
- CONC-001："屏障拦不住消除"被三平台实测推翻后改写

这些不是操作失误，是**有限观测被写成了普遍结论**。当前 matrix 字段记录了环境，但没有把"证据仅在 matrix 范围内成立"变成 claim 的硬约束。

新增三个 frontmatter 字段（证据卡/原子）：
```yaml
applicability:        # 适用域：实测覆盖的环境边界
  tested: [MinGW GCC15.3 -O2, WSL g++14 -O1, riscv64 g++13 -O2]
  not_tested: [MSVC, clang, -O3]
evidence_strength:     # 证据强度（分级）
  # single-platform-observation < multi-platform-consistent
  # < cross-arch-consistent < standard-text-grounded
inductive_leap:        # 跳跃声明：从观测到 claim 越了什么，什么观测会推翻
  claim_holds_beyond_tested: false
  falsifier: "若在任一未测平台/档位观测到相反方向，claim 收窄或降级"
```

**这把 falsification 从"卡内对照实验"升级为"claim 的适用边界管理"**，与 T10 知识保鲜联动：环境变化时，所有 `not_tested` 覆盖到新环境的原子自动进入复验队列。

## 二、三层断裂 + 知识漏斗（v4 核心，保留）

| 断裂 | 实测 |
|---|---|
| 一·确定性成本过高 | replay 202s、跑两次、20 检查串行 |
| 二·探索发现遗传率低 | 第五批 3 个方向发现仅 1 个沉淀且为文档 |
| 三·知识回流断裂 | Book 147 章节引用原子 id = 0；book_atom_sync.py 写了未入库 |

知识演化闭环（漏斗是动态的，非静态分类）：
```
探索发现 →T9固化→ 确定性检查 →(环境变化)→ 新探索
                ↓
        原子 →T6回流→ Book/图谱（消费端）  ← 当前断裂
```
**T9（发现固化）是进化引擎，T6（回流）是闭环最后一环。**

五原则（时间-左移 / 计算-增量 / 风险-分层 / 人力-聚焦 / 价值-流动）。完备性不做数学声称，待外部对抗找第六维度。

## 三、架构文档的自我治理（P0，自我指涉一致性）

**系统批判"原子造库存"，但架构文档自己就在造库存**：References/architecture 已 105 份且只增不减，Agent 上下文无法承载，新旧规范冲突时无所适从（312 v1/v2/v3 并存就导致过 Writer 照错版本生产）。

文档和原子必须遵守同一生命周期纪律：

1. **架构文档状态机**（头部强制字段）：
   `proposed → adopted → implemented`；旁路 `rejected` / `superseded by <编号>`
2. **架构保鲜**（与 T10 同机制）：implemented 的归档；rejected/superseded 移 `archive/`；只有 `adopted/active` 文档进入 Agent 上下文
3. **一份当前事实源**：维护 `docs/kernel/CURRENT_ARCHITECTURE.md`，只列"当前生效的原则/规则/流程"，所有 3xx 文档是它的历史论证，不是并列规范
4. **索引即清单**：README_INDEX 增"状态列"，105 份逐一标状态（这本身是第一个可交给差模型的杂活）

元原则（并入"流动"）：**任何知识产物——原子、证据卡、架构文档——都必须有消费路径和生命周期，否则就是库存。**

## 四、系统级恶性回路（超越指标级古德哈特）

v4 的古德哈特防御是"单个效率指标配对冲指标"。v5 指出还有**回路级**风险：

```
规则/检查增多 → 单原子成本上升 → Agent 生产变慢
        → Agent 倾向选简单原子（容易过审）→ 难域零开采、简单域过度重复
        → 覆盖率结构恶化（P0 章节无原子，边角知识点成堆）
```

防御（选题侧配额，不靠 Agent 自觉）：
- 选题由 G1 knowledge_map 的覆盖率缺口驱动，**P0/P1 章节有开采配额**，配额未完成时不允许在已饱和域继续生产
- 监控"规则数/卡"和"平均原子 DAL"，规则复杂度增长设预算
- 覆盖率健康度进度量（难域原子占比不应持续下降）

## 五、规模门控：防止优化本身过度工程（P1）

用户是有限额度、个人单机环境，不是无限云资源。部分 v4 任务在当前规模是**负收益**：

| 设施 | 当前规模 | 门控阈值 | 结论 |
|---|---|---|---|
| grep + frontmatter 索引 | 54 卡 / 105 文档 | <200 文档足够 | **现在做**，零依赖 |
| 关键词检索 + 标签 | — | 200-1000 文档 | 到时再做 |
| 向量库/embedding（T13） | — | >1000 文档或跨库 | **现在不做**，embedding token + 基础设施在小库是净亏损 |
| ccache / 增量 replay（T1/T2） | 编译是真实 202s | 任何规模 | **确定收益，做** |
| 多 Worker 并行（第三层） | 单人额度 | 有稳定多模型额度后 | 暂缓 |

原则：**先用零依赖手段（grep/索引/缓存），规模越线才引入重设施。** 每条优化标注触发规模，不到阈值不做。

## 六、人的接口预算（P1，人是唯一瓶颈）

v4 说"人每天 ≤30 分钟"，但又把回流审阅、异常处理、DAL 签署、选题都给人——人会成为新瓶颈，且随时被打断。

- **决策聚合**：人的所有决策（选题/DAL/回流写入/异常）聚合成**一个批量审批队列**，固定时段一次处理，不随时打断
- **分级**：能自动决策（有明确规则）的绝不打扰；人只看"需要价值判断且机器置信度低"的
- **硬约束度量**："人均每日决策耗时"和"积压队列长度"进度量；持续 >30min 说明放权不彻底，要继续把决策规则化，而不是给人加活

## 七、从鲁棒到反脆弱（P1）

当前系统是**鲁棒**的（抵御已知错误：规则+毒样例），不是**反脆弱**的（从波动中自动变强）。poison_drill 是离线固定的 11 个样例。

**主动故障演练（chaos drill）**：定期随机注入故障——删夹具、改 sha、破坏 claim、伪造 self_check hash、写稻草人 falsification——验证系统是否发现；**凡成功逃逸的故障，自动转为新毒样例/新规则候选**。
这把 T9 固化通道从"红队人工触发"升级为"演练自动触发"，系统从每次逃逸中自动变强。常态频率：每批次前跑一次随机注入。

## 八、技术依赖的故障放大（P1）

- **T3 复用缓存的风险**：golden_lock 若复用增量 replay 结果，缓存 bug 会同时污染两个本应独立的检查（失去"第二双眼睛"）。防御：golden_lock 每周一次**绕过缓存独立全跑**做交叉验证；复用只用于日常提速。
- **T4 并行化前提**：并行前必须审计所有质量工具的**写路径**（哪些写 Examples/、哪些写 build/），写同一目录的串行，只读的并行。已知 replay 写 Examples/atoms/，其余待审计。
- **特性开关**：每个优化独立 flag，灰度期"观测+拦截并行"（不能只观测不拦截导致坏产物入库），出问题一键回退全量。

### 第三层：大厦（1 月+，给路径）

## 十、度量（三组 + 新增）

- **效率**：replay（分场景）、quality、轮次、token、卡行数、**人均决策耗时/队列长度**
- **质量对冲**：红队方向发现数≠0、遗传率 100%、误报率<10%、**长期存活率（终极滞后指标）**、演练逃逸率（反脆弱）
- **价值/结构**：回流率（基线 0%）、映射覆盖、**难域 P0 覆盖率（防选题退化）**、证据强度分布、架构文档 active 比例

效率+对冲+价值三组同时达标才算健康。

## 十一、自我对抗轨迹与开放问题

v3→v4：双成本动态化、回流断裂、分层失效（实测）。
v4→v5（本轮六视角）：
- 博弈论 → T0 放权地基（P0）
- 认识论 → 归纳跳跃三字段（P0）
- 自我指涉 → 架构文档生命周期（P0）
- 系统论 → 恶性回路与选题配额
- 经济学 → 规模门控（向量库当前不做）
- 人因 → 决策接口预算
- 反脆弱 → 主动故障演练
- 技术依赖 → 缓存复用的独立性、并行写路径审计

**仍开放（不伪装）**：
- claim 可证伪性"自动检查"本身可能被措辞绕过（需要红队语义判断兜底，规则只能拦明显的）
- evidence_strength 分级靠人标，存在主观性，先给粗粒度四级
- 长期存活率/演练逃逸率需时间积累，先建采集
- 五原则完备性、第六维度是否存在，待外部模型对抗
- T0 博弈防御可能提高生产门槛，与"降本"张力，需试点量化

## 十二、停止规则

1. 达到各层完成定义即停；收益<成本 10× 不做
2. 规模未越阈值不引入重设施（§5）
3. 效率指标必须连同对冲+价值指标达标
4. **放权地基（T0+T-ep）未完成前，不扩大自动化比例**
5. **回流（T6）和文档治理（T-doc）未完成前，不扩大原子/文档产能**
6. 接受外部对抗，重点攻：博弈防御是否可被新投机方式绕过、归纳字段是否可操作、文档状态机会不会流于形式、规模门控阈值是否合理

> v5 本质：v4 解决"知识怎么高效可靠地产出和回流"，v5 补上"凭什么敢放权（博弈前提）、产出的普遍结论边界在哪（认识论）、系统会不会自我膨胀（文档治理/恶性回路/反脆弱）"。一个能在人不在场时自我纠错、且不自我膨胀的系统，才配叫自律。
