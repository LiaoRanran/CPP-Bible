# 426 架构设计：时序约束通用框架（不变量约束优于存在性检查）

> 日期：2026-09-13。来源：422 反面教训系统化的原则一。402 F02（编译后覆写）的根因是 EV-ARTIFACT-PRODUCER 只做"存在性检查"（编译行在 command 中），被"真编译+python 覆写"绕过。本文设计通用的时序约束框架，让所有新规则按不变量约束设计，而不是存在性检查。

---

## 一、问题：存在性检查的根本缺陷

### 1.1 什么是存在性检查

```python
# 反模式：只检查 X 存在
def check_artifact_producer(card):
    if card.artifact_producer in card.command:
        return pass  # 编译行在 command 中 → 通过
    return block
```

这个检查的缺陷：**只验证"编译行存在"，不验证"编译行之后 artifact 没有被修改"**。

攻击者可以：
```bash
g++ -S -o artifact.asm fixture.cpp && python -c "import shutil; shutil.copy('other.asm', 'artifact.asm')"
```
编译行存在（通过检查），但编译后 artifact 被覆写了。

### 1.2 存在性检查的通用缺陷

| 存在性检查 | 绕过方式 |
|---|---|
| command 中含编译行 | 编译后覆写 artifact |
| artifact_sha256 字段存在 | sha 填借品的真值 |
| actual 中有断言标签 | 标签在夹具注释中（不在工件中） |
| relations 中有 prerequisite | 目标原子已 deprecated |
| .out 中有读数 | 读数是旧版本生成的 |

**共同特征**：只验证"X 存在"，不验证"X 的状态/时序/代际正确"。

---

## 二、解决方案：不变量约束

### 2.1 什么是不变量约束

```python
# 正模式：验证不变量
def check_artifact_producer(card):
    # 不变量：编译行之后，没有对 artifact 路径的写操作
    compile_line = find_compile_line(card.command, card.artifact)
    if not compile_line:
        return block("无编译行")
    after_compile = command_after(card.command, compile_line)
    if contains_write_to_path(after_compile, card.artifact):
        return block("编译后覆写 artifact")
    return pass
```

**不变量约束 = 验证"X 之后无 Y"、"X 与 Y 同代"、"X 非注释"等状态/时序/代际属性。**

### 2.2 三类不变量

| 类型 | 说明 | 例子 |
|---|---|---|
| 时序不变量 | X 之后无 Y | 编译行之后无 artifact 写操作 |
| 代际不变量 | X 与 Y 同代 | artifact_sha256 == 重生成工件的 sha |
| 空间不变量 | X 在正确的空间 | 断言标签在工件中（非夹具注释） |

## 三、通用框架设计

### 3.1 check_invariant() 辅助函数

在 `gate_engine.py` 中新增：

```python
class InvariantChecker:
    """
    不变量约束检查器：支持时序、代际、空间三类不变量。
    所有新 gate 规则应使用此框架，而非手写存在性检查。
    """

    def __init__(self, command=None, artifact_path=None, artifact_content=None, fixture_source=None):
        self.command = command
        self.artifact_path = artifact_path
        self.artifact_content = artifact_content
        self.fixture_source = fixture_source

    # === 时序不变量 ===

    def after_line_no_write(self, marker_line, target_path):
        """
        时序不变量：marker_line 之后，没有对 target_path 的写操作。
        支持 cp/mv/python/powershell/cmd/重定向等多种写操作。
        """
        after = self._command_after(marker_line)
        write_ops = self._detect_write_ops(after, target_path)
        if write_ops:
            return InvariantResult(
                passed=False,
                reason=f"marker_line 之后有 {len(write_ops)} 个写操作: {write_ops[0]}",
                evidence=write_ops
            )
        return InvariantResult(passed=True)

    def after_line_no_command(self, marker_line, command_pattern):
        """时序不变量：marker_line 之后，没有匹配 command_pattern 的命令。"""
        ...

    # === 代际不变量 ===

    def same_generation(self, claimed_sha, regenerate_func):
        """
        代际不变量：claimed_sha == 重新生成的 sha。
        regenerate_func 是重编译函数，返回新工件的 sha256。
        """
        actual_sha = regenerate_func()
        if claimed_sha != actual_sha:
            return InvariantResult(
                passed=False,
                reason=f"sha 不一致: claimed={claimed_sha[:8]} actual={actual_sha[:8]}",
                evidence={"claimed": claimed_sha, "actual": actual_sha}
            )
        return InvariantResult(passed=True)

    def same_command_as_out(self, card_command, out_command):
        """代际不变量：.out 的生成命令与卡的 command 一致（或子集）。"""
        ...

    # === 空间不变量 ===

    def symbol_in_artifact_not_comment(self, symbol, artifact_content):
        """
        空间不变量：symbol 在 artifact_content 中存在，且不在注释中。
        剥离 //、/* */、asm ; 注释后再匹配。
        """
        stripped = self._strip_comments(artifact_content)
        if symbol not in stripped:
            return InvariantResult(
                passed=False,
                reason=f"symbol {symbol} 不在工件中（或仅在注释中）",
                evidence=None
            )
        return InvariantResult(passed=True)

    def symbol_in_function(self, symbol, function_name, artifact_content):
        """空间不变量：symbol 在指定函数体内存在。"""
        ...

    # === 内部工具 ===

    def _command_after(self, marker_line):
        """提取 marker_line 之后的命令文本。"""
        ...

    def _detect_write_ops(self, command_text, target_path):
        """检测 command_text 中对 target_path 的写操作。"""
        # 支持：cp/mv/python -c "shutil.copy"/powershell Copy-Item/
        #       cmd copy/> 重定向/>> 追加/任何含 target_path 的写命令
        ...

    def _strip_comments(self, content):
        """剥离 C/C++/asm 注释。"""
        ...
```

### 3.2 InvariantResult 数据结构

```python
@dataclass
class InvariantResult:
    passed: bool
    reason: str = ""       # 失败原因
    evidence: any = None   # 证据（写操作列表、sha 对比等）
```

### 3.3 写操作检测（_detect_write_ops）

这是时序不变量的核心。需要检测的写操作：

| 类型 | 模式 | 例子 |
|---|---|---|
| cp | `cp <src> <target>` | `cp other.asm artifact.asm` |
| mv | `mv <src> <target>` | `mv other.asm artifact.asm` |
| python | `python -c "import shutil; shutil.copy(...)"` | F02 实际攻击 |
| powershell | `Copy-Item <src> <target>` | |
| cmd | `copy <src> <target>` | |
| 重定向 | `command > <target>` | `echo x > artifact.asm` |
| 追加 | `command >> <target>` | |
| 任意含 target 的写命令 | 命令行含 target 路径且有写语义 | |

**关键**：不是黑名单（列不全），是"target 路径出现在写位置"的语义检测。如果无法确定语义，给 warn（保守）。

## 四、应用：重构现有规则

### 4.1 EV-ARTIFACT-PRODUCER 重构

```python
# 旧（存在性检查，被 F02 绕过）
def check_artifact_producer(card):
    if card.artifact_producer not in card.command:
        return block("producer 不在 command 中")
    if not has_output_binding(card.command, card.artifact):
        return block("-o 目标 != artifact")
    return pass

# 新（不变量约束）
def check_artifact_producer(card):
    checker = InvariantChecker(command=card.command, artifact_path=card.artifact)
    
    # 1. 编译行存在（存在性检查，基础）
    compile_line = checker.find_compile_line(card.artifact_producer)
    if not compile_line:
        return block("producer 不在 command 中")
    
    # 2. -o 目标 == artifact（存在性检查）
    if not checker.has_output_binding(compile_line, card.artifact):
        return block("-o 目标 != artifact")
    
    # 3. 时序不变量：编译行之后无 artifact 写操作（新增，防 F02）
    result = checker.after_line_no_write(compile_line, card.artifact)
    if not result.passed:
        return block(f"编译后覆写 artifact: {result.reason}")
    
    return pass
```

### 4.2 EV-ASSERT-SYMBOL-MAPPED 重构

```python
# 旧（存在性检查，被注释伪造绕过）
def check_assert_symbol_mapped(card):
    for assert in card.artifact_assert:
        if assert.symbol not in card.fixture_source:
            return block("符号不在夹具源码中")
    return pass

# 新（空间不变量）
def check_assert_symbol_mapped(card):
    checker = InvariantChecker(fixture_source=card.fixture_source)
    for assert in card.artifact_assert:
        # 空间不变量：符号在夹具源码中，且非注释
        result = checker.symbol_in_artifact_not_comment(assert.symbol, card.fixture_source)
        if not result.passed:
            return block(f"符号 {assert.symbol} 不在夹具源码中（或仅在注释中）")
    return pass
```

### 4.3 工件同代检查（Writer 自检 WC-01）

def check_artifact_same_generation(card):

## 七、元结论

**存在性检查是"检查清单"，不变量约束是"状态机"。**

- 存在性检查：X 在不在？（一维，易绕过）
- 不变量约束：X 在不在 + X 之后有没有 Y + X 和 Z 同不同代 + X 在不在正确空间？（多维，难绕过）

402 的元结论"修复按字符串/单点生效，攻击按数据流/时序穿链"——这个框架就是答案：**让修复也按数据流/时序生效，而不是按字符串/单点。**

**这是架构级的改进**，不是修一个规则——它改变了所有未来规则的设计范式。
