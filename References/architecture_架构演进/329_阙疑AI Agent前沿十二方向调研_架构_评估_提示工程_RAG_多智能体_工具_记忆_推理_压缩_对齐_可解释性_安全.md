## 一、Agent 架构：从 ReAct 到多智能体

### 1.1 核心技术谱系

| 架构 | 核心思想 | 适用场景 | 局限 |
|---|---|---|---|
| **ReAct** | 推理+行动交替循环 | 简单工具使用 | 一旦走错计划无法恢复 |
| **Reflexion** | Actor + Evaluator + Critic 自我批评 | 需要纠错的任务 | 反思质量受限于模型自评估能力 |
| **Tree of Thoughts** | 树状推理，可回溯 | 规划/搜索问题 | 计算成本 5-15x |
| **LATS** | 蒙特卡洛树搜索 + 语言模型 | 复杂决策 | 实现复杂 |
| **Plan-and-Execute** | 先规划后执行 | 长程任务 | 规划可能过时 |

### 1.2 对「阙疑」的映射

**三权分立 = Reflexion 的工业级实现**：
- Writer = Actor（执行生产）
- 红队 = Evaluator + Critic（评估+批评）
- Gatekeeper = 自动化检查（机器级 Evaluator）
- 人审 = 最终裁决

**可引入的升级**：
- **ToT 式 claim 生成**：Writer 生成 3 个候选 claim，评估后选最优（而非一次成型）
- **LATS 式状态评估**：每个原子生产步骤有"状态价值"评估，低价值路径自动回溯
- **Plan-and-Execute**：批次开始前先做完整计划（已在做，提示词=计划）

## 二、LLM 评估：从单一基准到整体评估

### 2.1 核心技术

- **HELM**（斯坦福）：16 场景 × 多指标，整体评估
- **MMLU-Pro**：10 选项（降低猜测概率），12k 题
- **GPQA**：研究生级 QA，448 题，高难度
- **结构化提示评估**：更稳健、可复现

### 2.2 对「阙疑」的映射

**门禁系统 = HELM 的微缩版**：
- 多个"场景"：replay / gate / poison / pytest / golden_lock
- 多个"指标"：confirm 率 / block 数 / warn 数 / 覆盖率
- 整体评估，而非单一指标

**可引入的升级**：
- **原子评估基准**：标准化的原子质量测试集（如"100 个典型 claim，评估通过率"）
- **红队问题多选项**：不是简单的"对/错"，而是 5 级严重度（阻断/高/中/低/建议）
- **跨批次一致性评估**：同一主题在不同批次的原子质量是否一致

## 四、RAG：从向量检索到知识图谱

### 4.1 核心技术

- **混合搜索** = 新基线（向量 + BM25，解决专有名词检索失败）
- **Reranking** = 高级阶段（提升 Top-K 准确率）
- **GraphRAG** = 关系型/多跳推理（准确率 54.2% vs 纯向量 16.7%，3.3 倍）
- **Agentic RAG** = 迭代检索/多工具

### 4.2 对「阙疑」的映射

**知识检索工具升级**：
- 当前 `tools/knowledge_search.py` = 纯文本搜索
- 升级为**混合搜索**：frontmatter 关键词（BM25）+ 正文语义（向量）
- 原子关系（prereq/contrasts）= **知识图谱**，可以用 GraphRAG 检索
- **先例检查**（法学 328）= 检索最相似的已验证原子

**GraphRAG 的适用场景**：
- "解释 A 和 B 的关系" → 遍历原子关系图
- "这个主题的完整知识体系" → 子图检索
- 简单事实查找 → 纯向量即可

## 五、多智能体系统：角色分解与协作

### 5.1 核心框架

|---|---|---|

### 5.2 对「阙疑」的映射

- 人审 = 产品经理（最终验收）

**可引入的升级**：

- **共识机制**：多个红队 Agent 审查同一原子，取共识（降低单个红队的偏差）

## 六、工具使用：从 Toolformer 到 Function Calling

### 6.1 核心技术

- **Toolformer**（Meta, 2023.2）：自监督工具学习，从无标注文本挖掘"文本-API调用"对应
- **Gorilla**（Berkeley, 2023.5）：API 调用微调，1645 个 API，解决 API 幻觉
- **Function Calling**（OpenAI, 2023.6）：标准化工具调用，JSON 参数
- **工具幻觉** = 主要问题：生成不存在的 API 或错误参数

### 6.2 对「阙疑」的映射

**工具调用体系**：
- replay/gate/poison/golden_lock = Function Calling
- 工具清单显式列出 + 参数验证 = 防工具幻觉

**可引入的升级**：
- **Toolformer 思想**：让 Agent 自动学习何时调用工具（而非硬编码流程）
- **工具使用审计**：记录每个工具的调用频率/成功率/失败原因，优化工具设计
- **动态工具加载**：根据任务类型加载相关工具（减少上下文占用）

## 七、长上下文处理：MemGPT 与分层记忆

### 7.1 核心技术

- **MemGPT**（2023.10）：OS 风格虚拟内存，主上下文=RAM，外部存储=磁盘
- **分层记忆**：核心记忆（当前）+ 召回存储（历史）+ 归档存储（旧）
- **上下文窗口 = L1 缓存**（不是完整内存系统）
- **21.8% 结构浪费**（4.45B token 测量：模型重复处理陈旧内容）

### 7.2 对「阙疑」的映射

**记忆系统升级**：
- 当前 `.codebuddy/memory/` = 扁平存储
- 升级为**三层记忆**：
  - L1（核心记忆）：当前批次的关键数据（夹具/sha/读数）
  - L2（召回存储）：历史教训库 + 已验证原子索引
  - L3（归档存储）：旧批次报告 + 架构调研文档
- **自动换页**：上下文接近上限时，旧消息自动摘要 + 移入 L2

**MemGPT 的中断机制**：
- Agent 可以主动调用"记忆管理"函数（保存/检索/归档）
- 类比：我们的 Agent 应该主动管理上下文（"这个数据重要，保存到记忆"）

## 八、推理优化：投机解码与 KV Cache

### 8.1 核心技术

- **投机解码**：小模型草稿 + 大模型验证（2-3x 加速）
- **KV Cache** = 主要瓶颈（长上下文+大 batch 时超过模型参数内存）
- **PD 分离**：预填充/解码分离（蚂蚁 1120 tokens/s，复杂任务 10min→2min）
- **基数树缓存**（SGLang）：上下文极致复用，2.7x 吞吐
- **KV Cache 压缩**：8x（4x eviction × 2x quantization）

### 8.2 对「阙疑」的映射

**编译缓存 = 推理优化的类比**：
- ccache（线 C）= 编译层面的投机解码（缓存编译结果）
- 证据卡的 .asm 工件 = "KV Cache"（避免重复编译）
- WSL /tmp 构建目录 = 更快的"内存"（避免 /mnt/c 慢 15-20x）

**可引入的升级**：
- **夹具编译缓存**：相同源码+编译器的编译结果缓存（ccache 已在做）
- **replay 结果缓存**：相同卡+相同工件的 replay 结果缓存
- **增量门禁**：只重跑变更的卡，而非全量 48 张

## 九、模型压缩：量化、剪枝、蒸馏

### 9.1 核心技术

- **量化**：INT8/INT4（GPTQ/AWQ），4-bit 推理
- **剪枝**：SparseGPT/Wanda，50% 参数移除
- **蒸馏**：大模型→小模型
- **KV Cache 压缩**：8x（eviction + quantization）

### 9.2 对「阙疑」的映射

**证据卡瘦身 = 模型压缩的类比**：
- 量化 = 保留关键信息，降低精度（如完整原始输出→摘要）
- 剪枝 = 移除不服务于教学的内容（颗粒度失控的解决方案）
- 蒸馏 = 从长卡中提取"核心卡"（教学要点卡）

**可引入的升级**：
- **三层证据卡**（315 已设计）：
  - 核心卡（断言+结论，~50 行）
  - 留痕卡（完整原始输出，~200 行）
  - 修订史卡（变更记录）
- **自动剪枝**：工具检测证据卡中不服务于 claim 的内容，建议删除

## 十、对齐研究：从 RLHF 到 Constitutional AI

### 10.1 三代演进

| 代际 | 技术 | 核心机制 | 特点 |
|---|---|---|---|
| 第一代 | RLHF | 人类反馈 + 奖励模型 + PPO | 成熟但复杂昂贵 |
| 第二代 | DPO/KTO/ORPO | 直接偏好优化，无奖励模型 | 简单稳定，成本低 |
| 第三代 | Constitutional AI | 宪法驱动自对齐 + AI 反馈 | 可扩展，可解释 |

### 10.2 对「阙疑」的映射

**红队审查 = Constitutional AI 的"宪法"**：
- can't-miss 清单 = 宪法原则（10 条不可违反的规则）
- 红队按宪法审查 = 模型按宪法自我批评
- 宪法可更新 = 规则可迭代（P4-P7 就是宪法修正案）

**可引入的升级**：
- **原子宪法**：明确的质量原则文档（docs/kernel/原子宪法.md），红队按此审查
- **DPO 思想**：直接从"好原子/坏原子"偏好对中学习，不需要显式"质量评分模型"
- **AI 反馈**：用高能力模型做红队（替代人类审查的部分工作）

## 十一、可解释性：Mechanistic Interpretability 与 SAE

### 11.1 核心技术

- **Mechanistic Interpretability**：理解模型内部电路（神经元/注意力头/回路）
- **SAE（稀疏自编码器）**：提取可解释特征（Anthropic Claude 3 Sonnet 3400 万特征）
- **Activation Engineering**：操纵激活引导行为（"人格开关"，OCEAN 特质调节）
- **消融**：定位关键组件（移除某组件看行为变化）

### 11.2 对「阙疑」的映射

**工件分析 = Mechanistic Interpretability 的类比**：
- 看 .asm = 看模型的"内部电路"（编译器如何翻译代码）
- 符号区间断言 = 定位关键"组件"（函数体中的特定指令）
- 消融 = 移除夹具中的某部分看 claim 是否仍成立

**可引入的升级**：
- **SAE 思想**：从大量证据卡中提取"可解释特征"（教学要点的自动提取）
- **Activation Engineering**：通过操纵提示词中的"激活"（关键词/结构）来引导 Agent 行为
- **回路发现**：自动发现"哪些证据卡共同支撑某个 claim"（证据回路）

## 十二、AI 安全：红队与攻防不对称

### 12.1 核心技术

- **红队**：攻击方找漏洞（人类红队 100% 成功率，个体最高 75%）
- **越狱**：绕过安全对齐（提示注入/多模态/角色劫持）
- **Constitutional Classifiers**（Anthropic）：防御通用越狱，95%+ 拦截，1% 开销
- **攻防不对称**：攻击永远领先防御（攻击者移动第二）

### 12.2 对「阙疑」的映射

**红队 = AI 安全红队的类比**：
- 找原子的"漏洞"（claim 缺陷/证据不足/口径不统一）
- 攻防不对称 = 红队永远能找到新问题（这是好事，推动改进）
- 人类红队 > 自动红队（创造力是关键）

**可引入的升级**：
- **原子质量分类器**：训练自动分类器拦截低质量原子（Constitutional Classifiers 的类比）
- **红队自动化**：用 LLM 自动生成"攻击提示词"（测试原子的鲁棒性）
- **防御纵深**：多层检查（gate + 红队 + 人审），单层失效不导致整体失败

## 十四、一句话总结

329 把「阙疑」的理论支撑从三十六学科扩展到**四十八个方向**（新增 12 个 AI Agent 前沿技术）。最关键的三个新洞察：

1. **RAG 的 GraphRAG 可以直接应用于原子关系检索**——原子之间的 prereq/contrasts 关系天然是知识图谱，GraphRAG 在"解释 A 和 B 的关系"类查询上准确率是纯向量的 3.3 倍（54.2% vs 16.7%）。我们的先例检查工具应该升级为混合搜索 + 图谱遍历。

2. **对齐研究的 Constitutional AI 是红队审查的理论基础**——can't-miss 清单就是"原子宪法"，红队按宪法审查 = 模型按宪法自我批评。宪法可更新（P4-P7 就是宪法修正案），这解释了为什么我们的规则体系能持续进化。可以正式文档化为 docs/kernel/原子宪法.md。

3. **MemGPT 的分层记忆直接解决上下文耗尽问题**——我们反复遇到"单窗口上下文耗尽导致半成品"，MemGPT 的 OS 风格虚拟内存（主上下文=RAM，外部存储=磁盘，自动换页）是成熟方案。三层记忆（L1 当前批次/L2 历史教训/L3 归档）+ 自动换页可以将上下文浪费降低 50%（行业测量 21.8% 结构浪费）。
