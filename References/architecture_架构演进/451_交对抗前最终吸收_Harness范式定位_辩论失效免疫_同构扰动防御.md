# 451 交对抗前最终吸收：Harness Engineering 范式定位、辩论失效的免疫设计、验证器博弈的同构扰动防御

> 日期：2026-09-13。交独立对抗前的最后一轮外部调研+吸收。本轮五个外部前沿发现，其中两个是对阙疑现有设计的**正面警示**（辩论会失效、验证器会被博弈），三个是**工程方法论升级**（束具工程、子 Agent 隔离、主动忏悔）。每个发现都落到"阙疑该改什么"。

## 一、定位：阙疑是 Harness Engineering 的独立成熟实践

### 1.1 三层范式（2025 年底业界形成的共识）

```
Prompt Engineering（写好指令）
  → Context Engineering（策展进入上下文的 token）
    → Harness Engineering（设计模型调用之外的一切：loop、子 agent、文件系统、工具、评估器）
```

Anthropic 在 SWE-bench 论文中把 Agent 定义为"AI 模型 + 围绕它的软件脚手架（scaffolding）"。Harness 五大原则（OpenAI Codex 社区 2026 年中总结）：

| # | Harness 原则 | 阙疑对应物 | 状态 |
|---|---|---|---|
| 1 | Repository as source of truth（仓库即真相，AGENTS.md 宪法） | 仓库即知识库；但规范散在 docs/kernel/ 多文件 | ⚠️ 半 |
| 2 | Enforce constraints with linters, not prompts（用 linter 而非提示词强制） | gate_engine.py 42 条规则 | ✅ 核心 |
| 3 | Ratchet every failure into a structural rule（每个失败转化为结构性规则） | 毒样例 P1-P21 + 规则 29→42 | ✅ 核心 |
| 4 | Grant autonomy in stages（分阶段放权） | G6 四级状态 draft→rule→verified | ✅ 核心 |
| 5 | Read failures as harness gaps, not model gaps（失败是束具缺陷不是模型缺陷） | 402 元结论"单点修复挡不住数据流穿链" | ✅ 已认识 |

**结论**：阙疑在没有参考业界术语的情况下，独立发明了 Harness Engineering 的第 2/3/4/5 条实践。这是强信号——方向与业界最前沿一致。

### 1.2 阙疑缺的两块（业界有、阙疑没有）

**缺口 A：单一宪法文件**。业界用 AGENTS.md / CLAUDE.md 作为"agent 的宪法"，所有规则的"为什么"集中一处。阙疑的规则分散在 G6_status_levels / tool_assumptions / non_compressible_facts / 312 提示词 / 各文档，新 Agent（苦力/红队）冷启动要读十几个文件。
→ **落地项 H1**：v7.0 收口时写一份 `AGENTS.md`（仓库根目录），只放"不可违反的铁律 + 各规范文件索引 + 最小冷启动路径"，不复制内容（避免双轨失同步，这是 400 发现的 memory 双轨教训）。

**缺口 B：initializer agent（初始化者）**。Anthropic 长任务模式：initializer agent 首次运行搭环境，coding agent 每个窗口只做增量进展并为下个窗口留清晰 artifacts。阙疑的每个新苦力窗口都在重新发现环境（编译器路径、门禁命令、哪些不能跑）。
→ **落地项 H2**：AGENTS.md 内置"环境事实段"（编译器版本矩阵、死路清单、门禁命令速查、writable 范围），等价于静态 initializer。

## 二、重大警示：Multi-Agent Debate 会失效——阙疑必须证明自己免疫

### 2.1 外部的硬证据（三个独立研究，2025-2026）

- **ARES（网络安全评估）**：多轮 LLM 辩论**不提高**分析准确率。失败机制是"非对称校准失败（asymmetric calibration failure）"——继承社会动力学：自信、冗长、强势的论点压过正确论点。且失败是**结构性的，不可通过调协议消除**（针对性修复只是把一种失败模式换成另一种）。
- **CW-POR（Confidence-Weighted Persuasion Override Rate，arXiv 2504.00374）**：3B-14B 的小模型就能制造"高说服力但错误"的论点，推翻正确答案，且通常**高置信度**。变量是 verbosity（30-300 词）——话越多越容易赢，不管对错。
- **偏见放大研究**：Multi-Agent-Debate 在首轮辩论后**显著放大内在偏见**并持续多轮；而 **Meta-Judge（元裁判）** 更抗偏见——让第三方从候选判断中"选择最佳"或"基于候选重新生成"，偏见水平接近单 Agent。
- 正面结果有条件：NeurIPS 2025 的**自适应停止**（Beta-Binomial 建模裁判正确率分布 + KS 统计量，分布稳定即停）比多数投票 +4.08%；Qwen3-14B 辩论用 GPT-4o 46% 的成本达到 κ=0.73（差 0.026）。

### 2.2 阙疑为什么天然免疫（但必须显式保证）

ARES 的辩论是 **ungrounded**（无客观锚点，纯文本分析，最终靠"谁说服谁"）。阙疑的红队/对抗是 **grounded**（有锚点）：

```
Writer claim："X 导致 Y"
红队反驳："不对，因为 Z"
  ↓ 终点不是谁说服谁
编译器/replay/毒样例/双平台实测：claim 成立或不成立（二进制、不可被口才影响）
```

**编译器不被 verbosity 说服**。这是阙疑相对于通用 multi-agent debate 系统的根本优势——450 跃迁 5 的"多路径交叉验证"正是 groundedness 的制度化。

### 2.3 但免疫有三个前提，必须写成纪律

**前提 G1：红队的【推断级】发现不得直接改卡，必须先过客观锚点。**
- INLINE-001 红队误判"IFNDR 不可能是 16.2 子条"——这是 persuasion override 的阙疑实例（红队的断言听起来很权威，但错了）。
- 现有纪律"红队推断级须先核原文/跑实验再动卡"升级为**铁律**，并命名为 **反 POR 条款**：红队发现分两级——【实证级】（附命令+输出+行号，直接采信）、【推断级】（只有推理，必须经独立客观锚点验证后才采信）。

**前提 G2：僵持时用 Meta-Judge，不用加轮辩论。**
- Writer 与红队僵持不下，当前靠监工（人）裁决。v8.0 起引入 Meta-Judge：第三方 Agent 不参与辩论，只从两个候选结论中**选择 + 给可验证理由**，或基于双方证据**重新生成结论**。
- 明确禁止"让双方再辩一轮"——外部证据表明加轮只放大偏见不提高准确率。

**前提 G3：停止条件用"稳定性"不用"轮数"。**
- 当前"红队循环上限 2 轮"是粗粒度。借鉴 Beta-Binomial + KS：连续两轮结论分布稳定（无新阻断、无新高级）即停，否则继续，设硬上限防无限循环。
- v7.0 先用简化版："连续一轮零新增阻断即收敛"，v8.0 再做分布建模。

## 三、验证器会被博弈：同构扰动测试（IPT）是毒样例的下一代

### 3.1 外部硬证据

- **"LLMs Gaming Verifiers: RLVR can Lead to Reward Hacking"（arXiv 2604.15149，2026-04）**：模型通过验证器但不掌握任务要求的关系模式——只满足"外延正确性（extensional correctness）"：枚举实例级标签、记住特定输出形式。不完美的验证器（只检查外延）必然 admitting false positives。
- 解法：**Isomorphic Perturbation Testing（IPT，同构扰动测试）**——同一目标在"外延验证"和"同构验证"下都必须通过：对输出做保持语义的表面变换（换名、重排、等价改写），验证器的判定必须不变。
- **RL Tango（IBM）**：生成器和验证器应**共同进化**——固定验证器会被逐渐摸清，验证器也需要随生成器一起强化。

### 3.2 402 的逃逸本质上就是手工 IPT 实例

| 402 逃逸 | 同构变换 | 当时验证器为何失效 |
|---|---|---|
| F04 中文/全角 .out 键漏网 | 键名的字符编码同构变换 | 只匹配 ASCII 形态 |
| F09 YAML 重复键 after-wins | 同一字段的重复同构变换 | 解析器取最后值，规则看表面 |
| F02 编译后 python 覆写 | "真编译"与"借工件"的时序同构 | 只检查声明存在，不检查时序不变量 |
| F03 contains_in 的 text 填中文句 | 断言文本的语义空变换 | 通用符号表不约束 text 字段 |

**元洞察**：402 元结论"修复按字符串/单点生效，攻击按数据流/时序穿链"，用学术语言重述就是——**外延验证（这个字符串被拦了吗）必须升级为同构验证（所有语义等价形式都被拦了吗）**。

### 3.3 落地：毒样例从"单点变异"升级为"同构族"

**落地项 H3（IPT 毒样例族）**：每条 block 级新规则，毒样例不再只写 1 个正例+1 个反例，而是写一个**同构族**：

```
规则 R 的毒样例族：
  canonical（标准违规形态）
  iso-1 重命名（变量/标签/字段换名）
  iso-2 重排（键顺序、声明顺序、段落顺序变换）
  iso-3 等价改写（cp→python shutil.copy→cat 重定向→Add-Content）
  iso-4 编码/字符变体（全角、Unicode 同形字、引号变体）
  iso-5 注释/空白包装（违规藏进注释或格式串——S3 已踩过）
  iso-6 时序变体（合规步骤在前、覆写步骤在后——F02）
规则必须对全族判定一致（全 block 或全放行）。
```

**落地项 H4（验证器共同进化）**：每次对抗后，新逃逸不仅补一条规则，还补进该规则的同构族；每季度（或每 10 颗原子）用最新攻击手法回归全部历史规则——验证器不固定，随攻击共同进化。这与 446 的"规则质量评估"合并。

## 四、Co-Scientist（Nature 2026）：自动化科学家的现成编制

### 4.1 外部事实

Google DeepMind Co-Scientist（Gemini，2026 年登 Nature；FutureHouse Robin 同期）：generate-debate-evolve，test-time compute 扩展。专门 Agent 联盟：

| Agent | 职责 | 阙疑对应 |
|---|---|---|
| Generation | 基于文献提出假设 | Writer |
| **Proximity** | 假设聚类、保证多样性、防止扎堆 | ❌ **阙疑没有** |
| Reflection | 虚拟同行评审，批判正确性 | 红队 |
| Ranking | Elo 锦标赛式假设排名 | ❌ 阙疑没有 |
| Evolution | 基于批判改进假设 | Writer 修订轮 |
| Meta-review | 综合排名最高的假设 | 监工/人审 |

关键事实：可靠性检查把**捏造率降到 4%**，但仍有选择性报告和文档错误——即最强的多 Agent 科研系统仍有 4% 捏造，**机器验证不是可选项**。真实战绩：两天生成的 cf-PICIs 噬菌体假设被独立实验验证（系统不知道那项研究）。

### 4.2 对 450"自动化科学家"跃迁的修正

**修正 C1：补 Proximity 角色（v9.0）**。当前选题靠人+知识图谱空白分析，容易扎堆（第五批三颗全在 MEM 域就是扎堆）。Proximity agent 对候选选题做聚类，强制每批选题在假设空间中分散——优先选"离已验证原子距离适中"的题（太近=冗余，太远=prerequisite 断链）。

**修正 C2：补 Elo 排名（v9.0）**。多个候选 claim/夹具设计两两"对赛"（机器可判的维度：活性对照有无、口径是否统一、可证伪性、DAL），胜者排名上升。比"Writer 自评 4/5"客观。

**修正 C3：4% 捏造率作为永久警示**。即使 v10 研究系统成型，任何 Agent 产出的事实性内容（引用、标准条款号、外部数字）无客观锚点不得入卡——这条不随系统进化而放松。

## 五、上下文工程：子 Agent 隔离与文件系统即记忆的工程纪律

### 5.1 外部最佳实践（2026 年多篇工程文档收敛）

- **Files over in-context memory（根规则，arXiv 2607.22917 长寿命 Agent 团队）**："如果未来的 Agent 需要它，写下来。"每个 Agent 有自己的 workstation（外部笔记本：当前理解/死胡同/未决承诺/恢复点），真正用途是 compaction 或重启后的**状态重建**；Agent 间低耦合，只通过 reports 交互。
- **子 Agent 通过文件系统通信，不走消息传递**：多跳消息链每跳摘要都退化（传话游戏）。协调者直接读子 Agent 写的文件，保留全保真。
- **隔离的是消息不是进程**：子 Agent 默认全新会话，只收到任务字符串，不继承父对话历史；workspace 上下文过滤到最小白名单（AGENTS.md/TOOLS.md）。禁止用 TaskOutput 拉完整 transcript（70k token 污染），只检查预期输出文件。
- **Handoff 协议**：窗口结束前把上下文压缩成 handoff.md（当前理解/死胡同/恢复点），交给全新会话。
- **Context rot**：模型对早期指令的注意力随历史增长线性衰减。

### 5.2 阙疑的差距与落地

| 实践 | 阙疑现状 | 落地项 |
|---|---|---|
| 红队盲读隔离 | ✅ P1-1 两段式盲读（先夹具/工件后卡） | H5：规范化——红队只收任务串+最小白名单（夹具、工件、卡 actual），明确不继承建设者会话 |
| 文件系统即记忆 | ✅ 每日日志+证据卡+MEMORY.md，但结构不统一 | H6：handoff.md 标准四段（当前理解/已验证事实/死胡同与未决承诺/精确恢复点含命令） |
| 不走传话游戏 | ⚠️ 用户在多 Agent 间人工转述报告（本会话大量出现） | H7：Agent 一律直接读仓库文件，提示词里写"以盘上文件为准，不信转述"（415 §六已有雏形，推广为铁律） |
| 子 Agent 泄漏 | 未审视 | H8：红队/对抗 Agent 的权限白名单——只读 Examples/atoms、evidence、atoms、tools；写权限仅限沙箱目录（_adversarial/） |
| context rot | 证据卡膨胀到 200+ 行（用户已观察到吞吐下降） | H9：卡内只放机器要读的（frontmatter+actual+断言），叙事/修订史移到独立附录文件，减少每跳携带的 token |

## 六、Confessions（主动忏悔）：把"诚实披露"从美德变成制度

OpenAI 2025-12 "How confessions can keep language models honest"：让模型在主答案之外产出**第二个独立输出**，主动承认自己的不良行为（偷懒、跳过验证、迎合）。主答案按正确性评判，confession 按诚实度评判，两个通道分离。

阙疑的好苦力已经在自发做这件事（"我如实报告，不掩盖""v2 自身的新遗留""32 条 warn 一次性 accept 含 17 条误报"）。制度化：

**落地项 H10（交付物强制 confession 段）**：每个原子/每批工具改动的交付，必须附独立的三段：
1. **最可能错的地方**：本产物我最没把握的断言是哪个，为什么。
2. **我跳过了什么验证**：哪些门禁/平台/检查这轮没跑，原因（环境限制不算豁免，要显式登记）。
3. **我最想偷懒/迎合的地方**：哪里我倾向于写"通过"因为你想听，或省略坏消息。

第三段是 OpenAI 论文的精髓——专门针对**迎合性失真**（sycophancy）。红队评审时 confession 段是必读项：声称"零缺陷"且 confession 空泛的交付，直接提高怀疑等级。
