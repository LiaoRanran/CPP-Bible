## T0（最高优先，先做）· 修 E1 touch 路径归一化逃逸

### 问题（已实证，不是假设）
`tools/task_queue.py` 两处只做 `str(p).replace("\\","/")`：
- `enqueue` 入库处（约 666 行）：`touch_set = sorted({str(t).replace("\\","/") ...})`
- `_conflicts` 比较处（约 377 行）：`want = {str(t).replace("\\","/") ...}`

后果（实测 4/4 逃逸）：wA 领任务 touch=`tools/task_queue.py` 在飞，wB 用 `TOOLS/TASK_QUEUE.PY` / `Tools/Task_Queue.py` / `./tools/task_queue.py` / `tools/./task_queue.py` 声明**同一物理文件**，集合比较全部不等 → wB 照样领到 → 两 worker 并发改同一文件。Windows 文件系统大小写不敏感。可复跑探针 `_adv_v90/probe_touch_case.py`（逃逸 4/4）。

### 修法（照做，别另起炉灶）
1. 新增一个归一化辅助函数（放 `_conflicts` 附近）：
   ```python
   from pathlib import PurePath
   import os
   def _norm_touch(p) -> str:
       # PurePath 解析掉 ./ 和中段 /./；os.path.normcase 平台相关：
       # Windows 自动小写化（大小写不敏感），Linux 原样（保持大小写敏感语义）。
       return os.path.normcase(PurePath(str(p).strip()).as_posix())
   ```
2. `enqueue` 入库处（约 666 行）改为用 `_norm_touch`：
   `touch_set = sorted({_norm_touch(t) for t in (touch or []) if str(t).strip()})`
3. `_conflicts` 的 `want`（约 377 行）改为 `{_norm_touch(t) for t in touch}`；`claimed_touch`（约 371 行）从库读回时也用 `_norm_touch` 再过一遍（双保险，因为历史库里可能已存未归一化值）。
4. **跨平台注意**：不要写死 `.lower()`——Linux 大小写敏感，必须靠 `os.path.normcase` 的平台行为。注释里写清这条。
