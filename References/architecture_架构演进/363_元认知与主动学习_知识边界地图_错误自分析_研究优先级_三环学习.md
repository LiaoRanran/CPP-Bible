## 一、为什么元认知是"超强智能"的最后一层

一个系统可以有正确的知识（v1.x）、能做科学发现（认知层）、能综合理论（进化层）、能验证理解（理解层），但如果它**不知道自己的边界**，仍然会：
- 在无知的地方自信地输出（Dunning-Kruger效应）
- 重复犯同类错误（不会从错误模式中学习）
- 把精力花在低价值问题上（不会选择研究方向）
- 在错误的认知框架里越走越远（不会反思自己的思维方式）

元认知（metacognition）= "对认知的认知"：监控、评估、调节自己的认知过程。这是把"聪明"变成"智慧"的一层。

元认知监督角色（361角色8）是这一层的执行者，本文档定义它操作的对象和算法。

## 二、知识边界地图（Epistemic Boundary Map）

### 2.1 四类知识状态（拉姆斯菲尔德框架的工程化）

```
                    已知（Known）              未知（Unknown）
              ┌─────────────────────┬─────────────────────┐
  意识到的     │ ① 已知已知          │ ② 已知未知          │
  (Aware)     │ verified原子+理解度  │ 已识别的backlog     │
              ├─────────────────────┼─────────────────────┤
  没意识到的   │ ③ 未知已知          │ ④ 未知未知          │
  (Unaware)   │ 隐性知识待显化      │ 真正的盲区（最危险）│
              └─────────────────────┴─────────────────────┘
```

| 象限 | 含义 | 「阙疑」中的对应 | 处理策略 |
|---|---|---|---|
| ①已知已知 | 已验证且知道自己掌握 | verified原子+L级别 | 维护、间隔重复、教学 |
| ②已知未知 | 知道自己还没搞懂 | 研究backlog/未完成批次 | 按优先级研究 |
| ③未知已知 | 系统隐含知道但没显式化 | 工件里有但没提炼的规律 | 综合者提炼/观察员挖掘 |
| ④未知未知 | 不知道自己不知道 | 真正的盲区 | 主动探测（最关键） |

### 2.2 边界地图的数据结构

```yaml
boundary_map:
  known_known:
    - domain: mem
      atoms: 20
      understanding_levels: {L0:20, L1:16, L2:6, L3:2, L4:5}
  known_unknown:
    - id: GAP-...
      topic: "CONC-003 数据竞争UB的TSan检测"
      why_known_unknown: "已规划但未生产"
      prerequisites_ready: true
  unknown_known:
    - candidate: "工件中反复出现但未提炼的规律"
      source: "观察员对工件的模式挖掘"
      status: 待综合者确认
  unknown_unknown_probes:        # 主动探测记录
    - probe: "在边界条件X下测试原理P"
      result: "发现了预期外行为"
      new_gap_opened: GAP-...
```

### 2.3 主动探测"未知未知"（核心能力）

系统不能只被动等待异常，要主动设计"探测性实验"探索边界：

探测策略：
1. **边界探测**：在已verified原理的适用范围边缘测试（SSO在15/16字符、屏障在循环外/分支内）
2. **组合探测**：把多个已验证机制组合，看是否出现预期外交互
3. **跨平台探测**：把只在单平台验证的claim放到新编译器/架构（riscv已证明有价值）
4. **否定探测**：故意违反每个前提条件，观察claim何时失效（刻画适用边界）
5. **极端值探测**：规模/竞争度/优化档推到极端（0、1、极大值）
6. **随机扰动探测**：对夹具做随机小改动，观察结论稳定性（变异测试思想）

每次探测要么确认边界（提升信心），要么打开新的未知未知（发现金矿）——**后者价值更大**。

## 三、错误自分析系统

### 3.1 错误的分类学（持续进化）

系统维护统一的错误分类法（taxonomy），每个红队阻断/CI失败/人审打回都归类：

```yaml
error_taxonomy:
  epistemic:                    # 认知类错误
    - confirmation_bias         # 确认偏误
    - single_hypothesis         # 单假设陷阱
    - confounding_variable      # 混杂变量
    - correlation_as_causation  # 相关当因果
    - overgeneralization        # 过度概括
    - vacuous_claim             # 空证明/claim弱化
  measurement:                  # 测量类错误
    - self_satisfied_assert     # 自证断言
    - trivial_observation       # 恒真观测
    - derived_redundant_metric  # 派生重复读数
    - compile_time_constant     # 编译期常量冒充活性观测
    - cross_compiler_unverified # 跨编译器断言未实测
    - baseline_mismatch         # 对照基数不一致
  methodological:               # 方法类错误
    - non_discriminating_exp    # 实验不判别
    - single_variable_violation # 唯一变量被污染
    - storage_covariate         # 存储位置等同变
    - platform_overclaim        # 平台结论过度外推
  process:                      # 流程类错误
    - handoff_skipped           # 交接验证跳过
    - redteam_compressed        # 红队被压缩走过场
    - premature_atomization     # 未完成就原子化
  tooling:                      # 工具类错误
    - rule_bypass               # 规则被绕过（规范博弈）
    - false_negative            # 工具漏报
    - false_positive           # 工具误报
```

### 3.2 错误聚类与模式发现

定期（每批次后）自动分析：
- **频率聚类**：哪类错误最常发生？→ 针对性加强规则/提示词
- **域分布**：哪个域错误率高？→ 该域需要更严审查
- **新型错误检测**：出现分类法里没有的错误→新增错误类型+新增PAT+可能新增gate规则
- **复发检测**：同一错误类型在修复后再次出现→说明修复（规则/提示词）无效，需要双环学习
- **逃逸分析**：错误穿透了几层防御才被发现？（理想情况下错误应在最早的层被拦住）

### 3.3 错误的"防御层穿透"分析

```yaml
defense_layers: [writer自检, gate, replay, poison, 红队, 人审]
error_escape:
  error: "ALLOC-002口径不统一"
  caught_by: "红队"
  penetrated: [writer自检, gate, replay]   # 穿透了3层
  root_cause: "这些层都不检查测量口径一致性"
  fix:
    single_loop: "修这颗原子"
    double_loop: "新增口径一致性检查规则"
    triple_loop: "测量类认知方式需要'口径声明'前置步骤"
```

穿透层数越多的错误，越说明系统有结构性盲区，越值得高阶学习。

### 3.4 错误预测的命中率追踪（修正Goodhart后）

v1.1批判了"命中率Goodhart"。v2.0的正确追踪方式：
- 不只看命中率，看**错误预测的认知价值**：
  - 该预测的验证动作是否产出了新证据/新实验？（LEAK-002的H2就是高价值预测）
  - 该预测是否指向一类新错误模式（而不只是这一颗原子的错）？
- 强证伪比例（改变claim方向的阻断占比）
- 预测的具体性（在哪里/是什么/怎么验证，三要素齐全率）
- 红队独立性评分（独立发现率，见361）

## 四、研究优先级算法（主动学习）

### 4.1 系统自己决定"下一个研究什么"

不再纯靠人指定选题，系统对known_unknown和探测发现的gap计算优先级。

### 4.2 评分模型

每个候选问题计算四个维度（0-10分）：

| 维度 | 含义 | 评估方法 |
|---|---|---|
| 信息量（Information Gain） | 答案能区分多少竞争假设/消除多少不确定性 | 关联的竞争假设数、对理论的检验强度 |
| 影响面（Impact） | 关联多少已有原子/理论/教学内容 | 图谱中受影响节点数、是否触及理论硬核 |
| 可行性（Feasibility） | 现有工具/平台能否验证 | 夹具可建性、平台支持、预计轮数 |
| 新颖性（Novelty） | 是填补空白还是验证已知 | 空白区域高分，重复验证低分 |

**优先级 = 信息量×权重 + 影响面×权重 + 可行性×权重 + 新颖性×权重**
（权重可配置；探索期提高新颖性权重，巩固期提高影响面权重）

### 4.3 特殊加分项

- **理论预言的问题**：理论综合产生的predicted_atoms（检验理论=高价值）
- **预测失败暴露的问题**：理解验证中预测错了（直接的理解漏洞，最高优先）
- **范式危机信号**：ad_hoc补丁率高的理论相关问题
- **跨域迁移验证**：能同时检验两个域的问题
- **错误高发区**：历史错误聚类指向的薄弱域

### 4.4 探索-利用平衡（Exploration vs Exploitation）

借鉴强化学习：
- **利用（exploitation）**：在已建立的理论框架内填补原子（稳，收益可预测）
- **探索（exploration）**：探测未知未知、检验理论边界、跨域尝试（风险高，但可能有大发现）
- 系统维护探索/利用比例（建议成熟期30%探索/70%利用，初期可更高探索）
- 长期只利用→知识停滞；只探索→不成体系。元认知监督监控这个平衡。

## 五、三环学习（Triple-Loop Learning）

### 5.1 三个学习环

```
单环学习（Single-loop）：纠正错误
  "这颗原子错了" → 改对
  问：我们做对了吗？（Are we doing things right?）
        │
双环学习（Triple-loop的第二层）：改规则/假设
  "这类错误反复出现" → 改gate规则/红队提示词/流程
  问：我们在做对的事吗？（Are we doing the right things?）
        │
三环学习（Triple-loop）：改认知方式本身
  "我们选择问题的方式/形成假设的方式/判断证据的方式有系统性偏差"
  → 改研究策略/思维框架/角色配置/探索利用平衡
  问：我们如何决定什么是"对"？（How do we decide what is right?）
```

### 5.2 三环学习的触发条件

| 环 | 触发 | 动作 | 例子 |
|---|---|---|---|
| 单环 | 单个错误 | 修产物 | 改claim/夹具 |
| 双环 | 同类错误≥2次，或规则漏报 | 改规则/提示词/模板 | 新增P4-P7规则 |
| 三环 | 跨多类错误的共同认知偏差，或范式级问题 | 改方法论/研究纲领/角色网络 | 认识到"只做计划型生产导致没有发现"，引入认知层 |

### 5.3 三环学习的具体产物

- 定期的"方法论复盘"：最近N批的错误是否指向某种共同的思维习惯？
  - 例：发现系统反复"低估平台差异"→不是个别错误，是认知方式过度依赖单一平台→三环修正：跨平台验证前置为认知层强制步骤
- 研究策略调整：探索/利用比例、域的优先级、角色模型配置的调整
- 认知框架更新：当某个深层假设反复导致错误，质疑它（接近范式革命在方法论层面的对应物）

### 5.4 防止"过度反思"

三环学习不能频繁触发（否则系统陷入自我怀疑、不产出）：
- 单环：随时
- 双环：有明确复发证据时
- 三环：一个里程碑（如每10批/每个域收尾时）专门复盘，或出现范式级信号时
- 反思的结论本身要经批评家审查（防止"为改而改"）

## 六、元认知层的可观测指标

| 指标 | 含义 | 健康信号 |
|---|---|---|
| 边界地图覆盖率 | 已测绘主题/总主题 | 随研究推进增长 |
| 未知未知发现率 | 探测打开的新gap数 | >0（完全没有=探测不够努力） |
| 错误复发率 | 同类错误重复出现比例 | 双环学习后应下降 |
| 防御层穿透深度 | 错误平均穿透几层 | 随规则完善而变浅 |
| 新型错误占比 | 分类法外的错误 | 早期高（在学习），成熟期低但不为0 |
| 预测失败率 | L2预测题实测错误比例 | 适中（太高=理解差，太低=题太简单） |
| 探索/利用比 | 探索型生产占比 | 符合设定比例 |
| 理论预言成功率 | predicted_atoms被证实比例 | 高=理论强，持续低=理论有问题 |
| 三环学习有效性 | 方法论调整后错误率是否真的下降 | 下降（否则反思无效） |

## 七、元认知层的失败模式

| 失败模式 | 描述 | 防御 |
|---|---|---|
| 元认知盲区 | 监督角色自己也有盲区 | 元认知报告被独立抽检；人审元认知结论 |
| 过度自信 | 边界地图低估未知未知 | 保持主动探测；未知未知发现率=0是警报 |
| 过度反思 | 频繁三环学习导致不产出 | 三环触发门槛+反思结论经审查 |
| 指标Goodhart | 优化元认知指标本身 | 指标只作诊断不作目标；多指标交叉 |
| 错误分类僵化 | 新型错误硬塞进旧分类 | 分类法可进化，保留"新型错误"通道 |
| 探索瘫痪 | 探索太多不成体系 | 探索/利用比例约束 |
| 利用僵化 | 只在熟悉域利用 | 新颖性维度+探索配额 |
| 反思不闭环 | 提了方法论问题但不改 | 三环结论必须落到提示词/规则/配置变更 |

## 八、落地优先级

1. **第一步**：错误分类法落地（把已发生的错误——自证断言/口径不统一/观测反转/跨编译器未实测等——归类入库）+ 每批次错误聚类（元认知监督/监工承担）
2. **第二步**：known_known/known_unknown边界地图（从golden_lock+backlog+未完成批次聚合，工具脚本）
3. **第三步**：研究优先级评分（对backlog打分，辅助人决策，不替代人）
4. **第四步**：主动探测机制（否定探测/边界探测作为发现型生产的固定动作）
5. **第五步**：三环学习复盘节奏化（每域收尾/每10批一次方法论复盘）
6. **第六步**：unknown_known挖掘（观察员从工件提炼隐性规律）+ 探索/利用平衡监控

## 核心结论

前八层让系统能正确地认知和生产，元认知层让系统**审视自己的认知和生产**：

> 知道自己知道什么（边界地图①②）、挖掘自己隐含知道什么（③）、主动探索自己不知道自己不知道什么（④）；记住自己怎么犯错、为什么没更早发现（错误自分析）；自己选择最该研究什么（主动学习）；并在错误中区分"改对一件事""改一条规则""改一种思维方式"三个层次（三环学习）。
>
> 一个能画出自己无知边界、能从错误模式中进化认知方式、能自主选择学习方向的系统，才具备"离开人也能自我纠错和成长"的基础——这正是你要求的"人在只是更直观"的工程化答案。
