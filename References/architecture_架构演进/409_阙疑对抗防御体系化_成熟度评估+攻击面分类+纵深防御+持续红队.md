# 409 阙疑对抗防御体系化：成熟度评估 + 攻击面分类 + 纵深防御 + 持续红队

> 日期：2026-09-13。外部调研：红队成熟度模型（L1-L4）、防御纵深四层、OWASP LLM Top 10、提示注入分类（直接/间接/认知）、持续红队循环（Discover→Harden→Re-test）、GPT-Red 自动红队（reward 对应真实后果+策略多样性）、PrompTrend（心理攻击 > 技术攻击）、Anthropic 红队 2 周发现 14 个 Firefox 高危漏洞。
> 核心问题：**373 对抗后我们修了 5 条规则、加了 16 个毒样例，但这是"补漏洞"不是"建防御"。对抗结果回来后，需要系统性框架来分类、消化、转化每一个发现。**

## 一、阙疑红队成熟度评估

### 行业四级模型

| 级别 | 特征 | 阙疑现状 |
|---|---|---|
| L1 Ad hoc | 无正式程序，零星手动测试 | ❌ 已过 |
| **L2 Developing** | 自动扫描+手动注入，有毒样例但无体系 | ✅ **当前在此** |
| L3 Defined | 结构化程序，攻击面全覆盖，指标驱动，CI 集成 | 🎯 目标 |
| L4 Managed | 持续红队，紫队演练，指标驱动改进 | 长期 |

### 阙疑在 L2 的具体表现
- ✅ 有手动红队（独立子 agent 两段式盲读）
- ✅ 有毒样例（36 个，poison_drill 100% 拦截）
- ✅ 有自动扫描（gate_engine 42 条规则）
- ❌ 毒样例没有版本化、没有按攻击面分类
- ❌ 红队不是持续的（每批一次，不是 CI 定期）
- ❌ 没有攻击面覆盖率指标（404 说"规则覆盖率 24%"但没追踪趋势）
- ❌ 没有从对抗发现到毒样例的自动化转化管道

### 升级到 L3 的三个标志
1. **攻击面分类全覆盖**：每个已知攻击面都有对应的毒样例+规则
2. **CI 集成**：每次提交跑毒样例回归，每周跑一次全量红队
3. **指标驱动**：攻击面覆盖率、逃逸数、修复时间、复发率可追踪

## 二、阙疑攻击面分类学（10 类，不是通用 OWASP）

OWASP LLM Top 10 是通用的，阙疑有自己特有的攻击面。按"已发生/已修复/未覆盖"分类：

| # | 攻击面 | 状态 | 对应规则/毒样例 |
|---|---|---|---|
| A1 | 声明-实现脱钩（漂亮声明+假工件） | ✅ 已修 | EV-ARTIFACT-PRODUCER + P15/P16 |
| A2 | 断言恒真（写死的字面量/自比） | ✅ 已修 | EV-ASSERT-DISCRIMINATOR + P4/P6 |
| A3 | 工件借用/覆盖（cp/mv 其他工件） | ⏳ 核实中 | P1a 任务 0 |
| A4 | 注释伪造（夹具注释里写符号名） | ✅ 已修 | _strip_comments + P15 |
| A5 | 通用符号滥用（main/call/ret 哪都命中） | ✅ 已修 | EV-ASSERT-SYMBOL-MAPPED + P15 |
| A6 | 未声明键（.out 有断言没声明的键） | ⚠️ warn 级 | EV-OUT-UNDECLARED-KEY + P14 |
| A7 | 符号映射缺失（断言符号不在工件里） | ⚠️ 部分可判 | EV-ASSERT-SYMBOL-MAPPED |
| A8 | **间接注入**（知识库内容被污染，影响后续生产） | 🔴 未覆盖 | 无 |
| A9 | 规则逃逸（找到规则边界条件） | 🔴 持续风险 | 373 的 13/17 绕过 |
| A10 | 门禁假阳性（sha 路径覆盖不到 artifact_assert） | ✅ 已修 | 跨编译器断言必须实测 |

### 最危险的未覆盖项：A8 间接注入

这是阙疑特有的风险，OWASP 里叫"间接提示注入"：
- 我们的证据卡/原子/误解库会被后续生产消费（RAG 式检索）
- 如果一张卡的 claim 是错的（但过了门禁），后续生产会引用它作为"已知事实"
- ALLOC-002 的"pool 32B 最省"就是一次间接注入——它被写进卡后，后续生产可能引用这个错误结论
- 防御：claim 可证伪性 + 红队 + 版本管理（406 的 MAJOR 版本保留旧 claim）

## 三、防御纵深五层（阙疑版）

行业是四层，阙疑需要五层（因为我们的"产品"是知识，不是对话）：

### L1 输入过滤：gate_engine 规则（42 条）
- 第一道防线，机械检查
- 覆盖 A1-A7（形式问题）
- 不覆盖 A8（语义问题）、A9（规则逃逸）

### L2 过程控制：MCC 六步 + 红队两段式盲读
- 生产过程中的防御
- 预言冻结（实验前写死）+ 两段式盲读（不读卡自述）
- 覆盖 A9（红队找规则逃逸）

### L3 输出验证：replay 三分类 + artifact_assert
- 产物级验证
- confirm/refute/infra_error 三分类
- 跨编译器才执行 artifact_assert（Windows sha 路径覆盖不到）
- 覆盖 A10（门禁假阳性）

### L4 系统控制：golden_lock + 健康度 + 版本管理
- 系统级防御
- golden_lock 防恶化（warn 升 block）
- 404 健康度仪表盘（攻击面覆盖率、逃逸数趋势）
- 406 版本管理（claim 反转保留旧版，防间接注入扩散）

### L5 持续对抗：定期红队 + 毒样例回归
- 主动防御（不是等问题出现）
- 每周一次全量红队（CI 定时）
- 每次对抗发现→毒样例→规则→回归（404 的 Test-Fix-Prove）

### 纵深原则
- **任何单层被突破不导致系统失败**：A8 间接注入如果过了 L1，L2 红队应该抓到；如果红队也没抓到，L4 版本管理限制扩散
- **每层有明确的覆盖范围和盲区**：不假设某层"应该能拦住"，而是显式记录盲区

## 四、持续红队管道（阙疑版）

行业四组件：探针库 + 测试运行器 + 结果存储 + 告警路由。

### 阙疑映射

| 组件 | 行业 | 阙疑 | 状态 |
|---|---|---|---|
| 探针库 | 版本化攻击样本 | 毒样例库（36 个） | ⚠️ 未版本化、未分类 |
| 测试运行器 | 自动执行 | poison_drill.py | ✅ 已有 |
| 结果存储 | 漏洞数据库 | golden_state.json + 373 档案 | ⚠️ 分散 |
| 告警路由 | 通知/阻断 | gate block + warn | ✅ 已有 |

### 闭环（Check Point 的持续红队循环）

```
Discover（发现新攻击面）
  → Threat model（威胁建模：这个攻击面影响哪些卡）
  → Red team（红队实测：能不能真的绕过）
  → Prioritize（定级：block/warn/advice）
  → Harden（修规则+加毒样例）
  → Protect（golden_lock 基线更新）
  → Monitor（健康度追踪）
  → Re-test（回归：毒样例全跑+存量 0 误伤）
```

### 关键设计（来自 GPT-Red 的教训）
1. **reward 对应真实后果**：不是"攻击文字出现"，而是"门禁真的被绕过"——毒样例必须能真的触发 block/pass
2. **攻击成功与策略多样性同时优化**：只追求拦截率会坍缩成少数套路，要追踪 tactic coverage（攻击面覆盖了几类）
3. **心理攻击 > 技术攻击**（PrompTrend 数据）：两段式盲读就是利用建设者的心理盲区，比技术攻击更有效

## 五、对抗结果回来后的标准处理流程

等 402 对抗结果回来，按这个流程处理（不是"看报告→修规则"）：

### Step 1：分类（每个发现归入 A1-A10）
- 是已知攻击面的新变种？还是全新攻击面？
- 如果是全新攻击面，更新分类学（A11...）

### Step 2：定级（block/warn/advice）
- 能让假卡过门禁 = block
- 能让质量下降但不造假 = warn
- 改进建议 = advice

### Step 3：复现（独立验证，不轻信报告）
- 像 373 那样：读源码验证报告说的是不是真的
- 写最小复现卡（放 `_diag/`），确认能触发

### Step 4：转化（Test-Fix-Prove）
- Test：写毒样例（必须能真的触发）
- Fix：修规则（窄化，不误伤合法卡）
- Prove：毒样例拦截 + 存量 0 误伤 + pytest

### Step 5：回归（全量门禁）
- gate + poison + pytest + replay 全绿
- golden_lock accept（如果 warn 数变了）

### Step 6：留痕（健康度更新）
- 攻击面覆盖率更新（A1-A10 各有几个毒样例）
- 逃逸数、修复时间记录
- 373 档案式记录

## 七、元结论

373 对抗的价值不是"修了 5 条规则"，而是**暴露了我们的防御是单层的**——全靠 gate_engine 规则。规则能拦形式问题，拦不住语义问题（A8 间接注入）和规则逃逸（A9）。

防御纵深的核心是：**不假设任何一层完美，每层都有明确的盲区，下一层补上一层的盲区**。

阙疑的红队成熟度从 L2 升到 L3，不需要更多规则，需要：
1. 攻击面分类（知道自己有哪些盲区）
2. 覆盖率追踪（知道盲区有没有缩小）
3. 持续循环（不是"跑一次对抗"，是"发现→修复→回归→再发现"）

**先做 P0**：给 36 个毒样例加 A1-A10 标签，计算当前攻击面覆盖率。这是零风险的基础设施，对抗结果回来后直接能用。
