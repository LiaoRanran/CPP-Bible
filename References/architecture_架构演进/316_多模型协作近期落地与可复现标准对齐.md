## 一、多模型协作：不接多模型也能做的事

### 1.1 现状约束

当前是单模型环境（豆包/CodeBuddy），无法真正调用多个不同模型。但 308 调研的核心洞察——**"角色分化"**——不需要多模型也能落地。

### 1.2 角色提示词分化（立即可做）

同一个模型，但用不同的系统提示词扮演不同角色，强制"思维模式切换"：

| 角色 | 当前提示词 | 分化方向 | 预期效果 |
|---|---|---|---|
| Writer | 通用生产提示词 | 强化"创意+教学直觉"，弱化"自我审查"（审查交给红队） | claim 更大胆，不自我阉割 |
| RedTeamer | 通用审查提示词 | 强化"怀疑+反例构造"，强制"先盲读夹具不读卡" | 独立性更强 |
| Gatekeeper | 门禁执行 | 纯机械，零创意，只执行规则 | 不越界做内容判断 |

**关键**：Writer 提示词里**不要**写"请确保断言正确"——这是红队的活。Writer 越敢写，红队越有东西可抓。当前 Writer 提示词里混了太多"自我审查"要求，导致 claim 过于保守。

### 1.3 交叉验证（单模型模拟）

对高 DAL（A/B）原子，用**同一模型的两次独立调用**做红队：
- 第一次：红队提示词 v1（侧重形式问题）
- 第二次：红队提示词 v2（侧重语义问题）
- 对比两次结果，交集 = 高置信问题，差集 = 需要人审

这比单次红队贵 2x，但对 DAL A/B 原子（错用即 UB）值得。

### 1.4 质量反馈调度（数据积累后）

记录每个"角色"在每类任务上的表现：
- Writer 某类 claim 被红队打回率 >50% → 该类提示词需要修订
- 红队某类问题漏检率 >30% → 该类 can't-miss 清单需要补充
- 这是外环（315 §三）的输入

## 二、可复现研究标准对齐

### 2.1 FSCRS-1 基线要求

美国联邦科学计算可复现标准（FSCRS-1）的强制基线：
1. 所有计算工作流必须用**科学 notebook 格式**（人类可读、可执行、版本控制）
2. 从 raw data 到 final output **全流程可重跑**
3. 关键指标/图表带**参数与环境信息**
4. **版本控制**（git）
5. 依赖锁定（lockfile）

### 2.2 我们的证据卡 vs FSCRS-1

| FSCRS-1 要求 | 我们的现状 | 差距 |
|---|---|---|
| 人类可读 | ✅ 证据卡是 Markdown | 无 |
| 可执行 | ✅ command 字段可重跑 | 无 |
| 版本控制 | ✅ git | 无 |
| 全流程可重跑 | ⚠️ fixture+command 可重跑，但**环境信息不完整** | 缺 CPU 型号/内存/OS 版本 |
| 关键指标带参数 | ⚠️ matrix 有编译器/优化档，但**缺运行时参数**（线程数/迭代数写在 actual 里但不结构化） | 缺结构化 env 字段 |
| 依赖锁定 | ❌ 无 requirements.lock（工具依赖） | 缺 |

### 2.3 补全方案

**证据卡新增 `environment` 字段**（可选，不强制）：
```yaml
environment:
  os: "Windows 11 23H2 / WSL Ubuntu 24.04"
  cpu: "AMD Ryzen 7 5800H (8C/16T)"
  ram: "32GB DDR4"
  compiler: "GCC 15.3.0 (MinGW-w64) / GCC 14.2.0 (WSL)"
  stdlib: "libstdc++ 15.3 / 14.2"
  run_params: "threads=4, iters=1e7, rounds=7"
```

**工具依赖锁定**：
- `requirements.lock.txt`（当前已有 requirements.txt，但无 lock）
- CI 用 lock 文件安装，避免依赖漂移

**可复现性抽查**（对应 CI 加速）：
- 不需要每次全量 replay 48 张卡
- 每次 CI 随机抽查 5 张卡 + 全量跑新卡
- 全量 replay 每周一次（cron）

## 三、FAIR 原则对证据卡的质量度量

### 3.1 FAIR 四原则

| 原则 | 含义 | 对证据卡的应用 |
|---|---|---|
| **Findable**（可发现） | 有唯一标识、可搜索 | id: EV-MEM-045 ✅；但全文搜索效率低 |
| **Accessible**（可访问） | 开放获取、标准协议 | Markdown 文件 ✅ |
| **Interoperable**（可互操作） | 用标准格式、可被机器解析 | frontmatter YAML ✅；但字段名不统一 |
| **Reusable**（可复用） | 有清晰的使用条件、元数据 | matrix/controlled_vars ✅；但缺 limitations 字段 |

### 3.2 落地改进

1. **Interoperable**：统一证据卡字段名（当前 actual 有 run_final_O2 / run_perf_O2 / run_match_file 三种形态，replay 已兼容但不统一）
2. **Reusable**：每张卡必须有 `limitations` 字段（什么条件下结论不成立），当前只有部分卡有
3. **Findable**：`tools/atom_graph.py`（306 方案）建立索引，支持按域/类型/关系搜索

## 五、与 315 的整合

315 聚焦**制衡升级**（突变测试/模型检查/双环），316 聚焦**角色分化+可复现标准**。两者互补：

- 315 的"外环"需要 316 的"质量反馈调度"作为输入
- 315 的"突变测试"需要 316 的"environment 字段"来判断变异是否因环境差异而 false positive
- 316 的"角色分化"是 315"双环"中内环的优化

**共同指向**：「阙疑」架构的下一个里程碑是**从"单环三权分立"进化到"双环持续改进 + 角色分化 + 可复现标准"**——内环更锋利（角色分化），外环更系统（错误模式台账+突变评分），底座更扎实（可复现标准）。
