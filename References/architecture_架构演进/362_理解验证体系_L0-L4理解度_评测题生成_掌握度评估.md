# 362_理解验证体系_L0-L4理解度_评测题生成_掌握度评估

> 2026-09-12 · v2.0展开文档4/6 · 对应358第⑥节（教学层增强）
> 目标：从"验证claim正确"升级为"验证系统（和学习者）真正理解"

---

## 一、正确性 ≠ 理解

v1.x的verified只回答一个问题："这个命题是真的吗？"但一个命题为真，不代表：
- 系统能用它解释新现象
- 系统能预测没测过的场景
- 系统能把它迁移到新领域
- 系统能基于它提出新问题

**这正是"知识库"和"理解"的鸿沟**。一个通过了全部考试但不会做题的学生，和一个verified了20颗原子却无法预测第21种情况的系统，问题相同：只有被验证的点，没有可迁移的理解。

理解验证体系用L0-L4五级，把"理解"变成可测量、可生产、可检验的产物。

## 二、L0-L4理解度模型

### 2.1 五级定义（改造自SOLO分类法）

| 级别 | 名称 | 标志 | 核心问题 | 产物 |
|---|---|---|---|---|
| L0 | 正确（Correct） | claim经证据验证为真 | "是真的吗？" | verified原子 |
| L1 | 解释（Explain） | 能用机制和直觉讲清"为什么" | "为什么？" | 直觉段+类比+机制链 |
| L2 | 预测（Predict） | 能预测没见过的场景的结果 | "如果…会怎样？" | 预测题+可验证答案 |
| L3 | 迁移（Transfer） | 能把原理用到新域/新结构 | "换个地方还成立吗？" | 跨域连接+迁移题 |
| L4 | 创造（Create） | 能提出新问题/新假设/新实验 | "接下来该研究什么？" | 衍生问题/新原子种子 |

### 2.2 各级的通过标准

**L0 → L1（解释）**：
- 机制链完整：从原因到结果的每一步因果都显式（不跳步）
- 有一个初学者可理解的类比，且类比的结构与真实机制对应（不是误导性类比）
- 能回答"为什么不是相反的情况"
- 检验：把直觉段给一个不懂该主题的人看，他能复述机制（人审/教师角色评）

**L1 → L2（预测）**：
- 至少3道预测题，覆盖：典型场景/边界场景/反直觉场景
- 题目是"学习者没见过的具体代码/场景"，不是原子内容的复述
- 每道题有：可验证的答案（编译器实测/标准条文）+ 推理路径
- 检验：预测题的答案必须实际编译验证过（不能是"应该是这样"）

**L2 → L3（迁移）**：
- 至少1个跨域连接：原理在另一个域的对应现象（如MEM的"自证断言"→CONC的"自定义原子计数"）
- 迁移题：给出新域场景，要求识别同一原理并正确应用
- 明确迁移的边界：什么条件下迁移成立，什么条件下失效
- 检验：跨域连接的对应现象必须在新域有实证（不能是想象的类比）

**L3 → L4（创造）**：
- 该原子启发了至少1个新的、值得研究的问题（进入研究backlog）
- 新问题满足：非平凡（不是原子内容的复述）、可研究（有验证路径）、有信息量（答案能区分假设）
- 检验：新问题被观察员/溯因者评估为"值得研究"，且最好真的产出了新原子

### 2.3 理解度的Schema

```yaml
understanding:
  level: 0-4
  L1:
    mechanism_chain: ["因果步骤1", "因果步骤2", ...]
    analogy: "类比描述"
    analogy_mapping: "类比结构↔真实机制的对应关系"
    why_not_opposite: "为什么不是相反情况"
  L2:
    prediction_problems:
      - id: PP-...
        scenario: "没见过的具体场景/代码"
        type: typical | boundary | counterintuitive
        predicted_outcome: "预测结果"
        verified_by: "实际编译验证的证据/工件"
        reasoning_path: "从原理到预测的推理"
  L3:
    transfer_links:
      - target_domain: "目标域"
        corresponding_phenomenon: "对应现象"
        evidence_in_target: "新域实证"
        transfer_boundary: "迁移成立/失效条件"
  L4:
    generated_questions:
      - question: "衍生的新问题"
        novelty: non_trivial | ...
        research_path: "验证路径"
        produced_atom: "若已产出，关联原子"
```

## 三、预测题的生成与验证（L2是核心）

### 3.1 为什么L2是理解的分水岭

- L1可以靠"复述"通过（把claim换个说法）
- L2无法靠复述——必须在**没见过的场景**里推出结果
- 能预测 = 内部心智模型能运行（不只是存储了结论）

### 3.2 预测题的类型学

| 类型 | 设计方法 | 例子（基于FENCE-001） |
|---|---|---|
| 典型场景 | 原理的直接应用 | "循环里只放atomic_signal_fence，循环会被消除吗？" |
| 边界场景 | 在前提条件的边界 | "屏障在循环体里但在if(false)分支里呢？" |
| 反直觉场景 | 直觉答案与正确答案相反 | "零指令的signal_fence也能阻止消除吗？" |
| 干扰场景 | 加入看似相关实则无关的因素 | "把屏障换成一个空函数调用会怎样？" |
| 组合场景 | 多个原理同时作用 | "屏障+volatile+原子类型同时存在，哪个在起作用？" |
| 反向题 | 给结果反推条件 | "循环没被消除，代码里一定有什么？" |

### 3.3 预测题的质量检查（批评家职责）

- **非复述检查**：题目答案不能直接出现在原子正文（否则是记忆题不是预测题）
- **可验证检查**：答案必须能实际编译/查标准验证，不能是开放性论述
- **判别检查**：真理解和假理解会给出不同答案（题目要有区分度）
- **覆盖检查**：典型/边界/反直觉三类至少各1道
- **答案实测检查**：所有预测题答案必须有实测工件，禁止"想当然"

### 3.4 预测题作为系统自检工具

预测题不只是考学习者，更是**系统自我检验**：
- 系统生成预测题时，如果设计不出边界/反直觉题→说明系统自己只理解到L1
- 预测题实测结果如果与系统预期不符→发现了理解漏洞（这是最好的认知层输入，直接进观察员的异常报告）
- **"预测失败"是高价值事件**：它暴露了理论/心智模型的缺陷，应触发溯因流程

## 四、迁移的机制（L3）

### 4.1 迁移不是类比

- 类比："A像B"（修辞，帮助理解，不需要同构）
- 迁移："A和B共享同一个深层原理P，因此A的结论在满足边界条件时适用于B"（需要结构同构+实证）

### 4.2 迁移的验证要求

迁移主张必须满足：
1. 抽象出共同原理P（不是表面相似）
2. 在目标域找到P的对应现象
3. 目标域现象有独立实证（不是从A推演出来的，而是实测的）
4. 明确迁移边界（P在目标域成立的条件）

### 4.3 迁移与模式库（PAT）、理论的关系

```
单次跨域迁移成立（L3产物）
    │ 同一原理在第2、3个域复现
    ▼
升级为跨域模式 PAT（360第6节）
    │ 模式有了统一机制解释 + 跨域预测成功
    ▼
升级为跨域原理（理论的一部分）
```
理解验证体系是知识进化层的"进料口"——L3迁移是模式和理论的经验来源。

## 五、L4创造：理解产生新问题

### 5.1 为什么"能提出好问题"是最高理解

- 提出非平凡的新问题，需要知道现有知识的边界在哪
- 这直接连接认知层的问题驱动机制（358第3.4节）
- 一个理论/原子的"生育力"（fecundity，科学哲学评价理论的标准之一）就是它能催生多少新研究

### 5.2 好问题的标准（继承研究优先级）

- 非平凡：答案不是原子内容的直接推论
- 可研究：有可行的验证路径（夹具/标准/实验）
- 有信息量：答案能区分竞争假设
- 有连接：能填补知识图谱空白或检验理论预言

### 5.3 L4的闭环

L4产生的新问题 → 观察员的gap/anomaly报告 → 溯因者生成假设 → 新的认知循环 → 产出新原子。**理解体系与认知体系在此闭环：理解的终点是产生新的认知。**

## 六、掌握度评估（对学习者和对系统）

### 6.1 双对象

- **对学习者（人）**：用L0-L4题评估人对每个主题的掌握，驱动自适应学习路径
- **对系统（AI）**：用L0-L4评估系统自身的理解深度，驱动知识补强

### 6.2 系统理解度仪表盘

```yaml
domain_understanding:
  mem:
    L0_atoms: 20          # verified命题数
    L1_coverage: 80%       # 多少原子有合格直觉/类比
    L2_coverage: 30%       # 多少有验证过的预测题
    L3_transfers: 2        # 跨域迁移数
    L4_questions: 5        # 催生的新问题数
    weak_spots: ["预测题缺失的原子列表", "预测失败暴露的理解漏洞"]
```

### 6.3 理解度驱动的生产优先级

- L1覆盖率低→优先补直觉/类比（教师角色）
- L2覆盖率低→优先补预测题（这是理解的主要缺口）
- 预测失败→最高优先级（理解漏洞，走认知层）
- L3少→优先做跨域连接（综合者）
- 这把"下一颗原子做什么"从拍脑袋变成理解度驱动

### 6.4 对人的自适应学习（教学应用）

- 学习者在某主题L0通过但L2失败→说明"记住了但不会用"→推送预测题专项
- L2通过但L3失败→"会做题但不会迁移"→推送跨域变式
- 间隔重复（v1.x已规划）按理解度调整间隔：L0的知识点复习间隔短，L3的间隔长
- 这让CPP-Bible不只是教材，而是自适应理解训练系统

## 七、理解验证的失败模式

| 失败模式 | 描述 | 防御 |
|---|---|---|
| 假预测题 | 题目是原子内容的复述 | 非复述检查+批评家审 |
| 答案想当然 | 预测答案没实测 | 答案实测检查（强制工件） |
| 误导性类比 | 类比结构与机制不符 | analogy_mapping显式对应+红队审 |
| 牵强迁移 | 表面相似就迁移 | 共同原理+目标域实证+迁移边界 |
| 级别注水 | 自评L4实际只有L1 | 每级有独立通过标准+批评家评 |
| 题海战术 | 大量低质量预测题 | 题目判别力检查，重质不重量 |
| 理解度形式化 | 仪表盘好看但不反映真实理解 | 定期用"隐藏场景"盲测系统自身 |

## 八、落地优先级

1. **第一步**：原子frontmatter增加understanding扩展（可选字段，不破坏现有契约）；为现有20颗verified原子补L1（直觉/类比，部分已有）
2. **第二步**：L2预测题试点——选3-5颗核心原子（FENCE-001/RAII-001等），每颗3道实测预测题，跑通"预测题答案必须编译验证"流程
3. **第三步**：理解度仪表盘（从frontmatter聚合，工具脚本）
4. **第四步**：L3跨域迁移（MEM→CONC，配合模式库）
5. **第五步**：L4问题闭环（接入认知层backlog）；对人的自适应学习路径

## 核心结论

v1.x保证系统说的是**真话**（claim正确），理解验证体系保证系统真的**懂自己说的话**（能解释、能预测、能迁移、能创造）。

> 验证claim是"对知识的体检"，验证理解是"对认知能力的路考"。L2预测是分水岭：能在没见过的场景里推出正确结果，才算从"记住结论"进入"拥有模型"。而L4把理解的终点接回认知的起点——最深的理解表现为能提出下一个好问题。这让「阙疑」从生产正确知识的系统，变成能证明自己理解、并因理解而持续生长的系统。
