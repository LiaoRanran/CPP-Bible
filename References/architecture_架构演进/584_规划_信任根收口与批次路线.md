## 四、584 的两个候选（请拍板）

### 候选 A（推荐）：584 建设 —— 信任根收口包（无密码学版）
三件，全是确定性、弱模型可执行、无 LLM、无密码学：

- **T1（PoC-1a + 1b）规则注册表独立第二锚**：让"静默置空规则函数 / 从注册表摘掉规则"无法在不留痕下通过。
  - 规则 id + 数量 + 每条规则的"行为证据指针"（毒样例 id 或 pytest 正反例函数名）固化成一份**独立于 `.tool_checksums` 的规则清单**（进 tests 或一份带测试锁的 manifest）；新增规则必须同时带行为证据 + 红队 seen，删除/置空规则若无显式二人留痕 ⇒ fail-closed。
  - 思路：`.tool_checksums` 不能自校验自己（谁改基准都能重签），那就让"**规则必须有可执行行为证据**"成为独立不变量——把规则函数写空，必然导致它名下的毒样例/正反例失败。这与 581 的行为级 covered 是同一套哲学。
  - 边界：不做密码学签名、不做 `--update` 身份认证（单用户冻结）；只做"第二锚 + 留痕 + fail-closed"。
- **T2（581 豁免债清偿）**：对 25 条 legacy 独占逐条核实——8 条 weak-test 在对应测试文件补该 rule_id 的断言、12 条 missing-test 补测试或转真毒样例；确实不经济的保留 legacy 但必须落到一条**可执行**证据。目标：把行为覆盖从 38/63 往上抬、消灭"20 条背书对不上"，诚实覆盖率向表观收敛（且收敛方式是补证据不是改口径）。
- **T3（PoC-3）人签事件流**：新增只追加 `data/human_sign_events.jsonl`（schema 仿 overturned：`{ts,target,card,prop?,signee,git_author,commit,reason}`）；`principal_ok` 从"文本匹配 `human:名`"升级为"文本匹配 + git 作者一致 + 事件流可对账"，缺事件/冒名/git 不可用 fail-closed；复用 573 `log_overturned` 已验证的 git 作者绑定模式。机器**只追加校验过的事件，不替人签**。

每件一 commit、正反例、收工总验收同 583（gate/poison/replay/fast/slow/受控目录/ruff/退出码）。

### 候选 B：584 异族只读大轮（换新会话、换模型）
让异族带"583 产物 + 564 三 PoC + 581 实现"做只读范式批判，重点：① T1 的"独立第二锚"在单用户无密码学下是否真独立，还是自我指涉的幻觉；② 双实现对账（N1/N3/N2）会不会因共享同一套底层假设而同谋（564 已警告"同族一致不算独立佐证"）；③ 四轴快照把 git 时间当 asserted 轴，rebase/amend 下如何不撒谎；④ 对照外部（in-toto/SLSA、LCF、DDC、Sigstore）指出我们"轻量留痕"相对正式供应链信任链到底缺了哪几环、哪些在单用户阶段可合法省略。
产物落新 `_arch_v10/`，全程只读（硬隔离沿用 582：禁 pytest/poison/mutation/--update/git 写，实跑须 `git worktree add` 副本）。

> 监工注：A 与 B **不冲突但有先后**——建议先 A 建设（趁 567/581 范式热乎收口），再用 B 异族批判 A 的产物（让异族打一个已经落地的具体实现，比打空气更有信息量，也符合"建设→异族对抗→豆包验收"的既定循环）。若你更想先听外部声音再动手，也可先 B 后把 A 改名 585。
