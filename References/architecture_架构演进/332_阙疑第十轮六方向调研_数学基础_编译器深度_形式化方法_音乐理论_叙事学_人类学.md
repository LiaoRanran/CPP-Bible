## 一、数学基础：证明论与类型论

### 1.1 核心理论

**证明论（Gentzen）**：
- 证明本身成为研究对象（相继式演算、切消除、规范化）
- 分析证明的形式来理解系统的强度
- 切消除定理：任何证明都可以转化为无切证明（更直接、更清晰）

**模型论（Tarski）**：
- 逻辑有效性 = "在所有模型中为真"
- 关注语句在其中为真/假的结构
- 可靠性定理（⊢→⊨）和完备性定理（⊨→⊢）

**递归论**：
- 什么是可计算的（图灵机、递归函数）
- 不可判定性（停机问题、哥德尔不完备定理）
- 计算复杂度的层级

**类型论（Russell, Martin-Löf）**：
- 用类型代替集合作为数学基础（避免罗素悖论）
- 依赖类型理论（DTT）：类型可以依赖于值
- Curry-Howard同构：证明=程序，命题=类型

**AlphaProof（DeepMind, 2024）**：
- LLM（Gemini）+ AlphaZero式RL + Lean证明助手
- IMO银牌（2024），Nature 2025
- 过程：自然语言问题→生成Lean tactic→Lean检查→RL反馈

### 1.2 对「阙疑」的映射

**Curry-Howard同构 = 「阙疑」的核心对应**：
- 命题（Proposition）= claim
- 证明（Proof）= 证据卡
- 程序（Program）= 夹具
- 类型检查（Type checking）= gate_engine检查
- 这解释了为什么「阙疑」的三要素（claim/证据卡/夹具）是天然统一的

**证明论 = 红队的"证明"**：
- 红队的阻断必须有证明链（从夹具/工件到结论的推理链）
- 切消除 = 红队的"简化"（去掉不必要的中间步骤，直接指向核心问题）
- ALLOC-002的方向反转就是一次"切消除"：去掉了"pool最省"的中间假设，直接指向"口径不统一"

**模型论 = 证据卡的"模型"**：
- 夹具/工件是claim的"模型"（在其中claim为真的结构）
- 可靠性 = claim在所有模型中为真（跨平台验证）
- 完备性 = 如果claim为真，一定存在模型（证据卡）

**递归论 = 任务的可判定性**：
- 哪些问题可以机械解决（gate规则）= 可判定问题
- 哪些问题需要人审（claim的教学价值）= 不可判定问题
- 这解释了为什么人审不能完全取消：有些问题是不可判定的

**AlphaProof = 「阙疑」的终极形态**：
- LLM + 形式化验证 + RL反馈
- 「阙疑」目前是：LLM（Writer）+ 机器验证（gate/replay）+ 人审反馈
- 未来可以加入RL：根据红队/门禁的反馈自动优化提示词

## 二、编译器深度：IR与优化

### 2.1 核心理论

**IR（中间表示）**：
- 源代码与机器码之间的桥梁
- LLVM IR：静态单赋值（SSA）形式
- MLIR：多层级IR，支持自定义dialect
- 作用：解耦前端与后端，支持多语言多目标

**优化Pass**：
- 常量传播（Constant Propagation）
- 死代码消除（DCE）
- 内联（Inlining）
- 向量化（Vectorization）
- 稀疏条件常量传播（SCCP）：全程序分析

**JIT（即时编译）**：
- 运行时编译，基于profile的优化
- CoSSJIT：静态分析+推测执行的结合
- 部分求值（weval, PLDI 2025）：在IR级别展开解释器循环

**MLIR Transform Dialect**（CGO 2025）：
- 显式调度的转换（tiling, vectorization, distribution）
- 确定性优化，不依赖启发式pass
- 输入=计算IR + 转换脚本

**AI辅助编译**：
- VecTrans（2025）：LLM辅助代码向量化
- 基于深度学习的优化决策预测

### 2.2 对「阙疑」的映射

**IR = 提示词的"中间表示"**：
- 用户需求（源代码）→ 提示词（IR）→ Agent执行（机器码）
- 提示词的"SSA形式"：每个变量只赋值一次（每个概念只定义一次）
- 多层级IR：用户需求→架构文档→提示词→执行步骤

**优化Pass = 提示词的优化**：
- 常量传播 = 把常用值直接写入（如"33条规则"直接写进提示词）
- 死代码消除 = 删除提示词中的冗余部分
- 内联 = 把常用模式直接展开（如红队的can't-miss清单）
- 向量化 = 批量处理（一次处理多个原子）

**JIT = 运行时调整**：
- 根据Agent的反馈动态调整提示词
- profile-guided optimization = 根据历史批次的反馈优化下一批提示词
- 推测执行 = 假设Agent会按预期执行，如果失败则回退

**MLIR Transform Dialect = 显式的转换脚本**：
- 提示词的"编译管道"：从用户需求到执行步骤的显式转换
- 确定性优化：不依赖"启发式"（Agent的自由发挥），而是显式的步骤
- 这是「阙疑」从"提示词工程"到"提示词编译"的进化方向

**部分求值 = 针对特定任务特化**：
- 通用提示词（解释器）→ 针对特定原子的特化提示词（编译后）
- 例如：CONC域的提示词是MEM域提示词的"部分求值"版本

## 三、形式化方法：定理证明与程序验证

### 3.1 核心理论

**交互式定理证明器**：
- Lean：基于依赖类型理论，mathlib 210,000+定理（2025）
- Coq/Rocq：基于归纳构造演算
- Isabelle：基于高阶逻辑，自动化强
- Agda：基于依赖类型，编程语言风格

**模型检验**：
- 穷尽检查所有状态（SPIN, NuSMV）
- 适合有限状态系统
- 状态爆炸问题

**程序验证**：
- Hoare逻辑：{P} S {Q}（前置条件/程序/后置条件）
- Verus：Rust的形式化验证，requires/ensures
- 三证明系统交叉验证：Verus(SMT)+Rocq(定理证明)+Lean

**AI+形式化**：
- AlphaProof：IMO银牌（2024）
- DeepSeek-Prover-V2：MiniF2F 88.9%
- Goedel-Prover-V2：MiniF2F 90.4%
- Axle：Lean 4的云基础设施，支持百万级请求

### 3.2 对「阙疑」的映射

**定理证明器 = 「阙疑」的形式化验证**：
- gate_engine就是一个"证明器"：检查原子是否满足规则
- replay是"执行验证"：运行夹具验证claim
- 红队是"反例搜索"：寻找claim的反例

**Lean mathlib = 原子库的目标**：
- mathlib 210,000+定理 vs 「阙疑」20原子
- 差距是10000倍，但方向一致：可验证的知识单元
- 「阙疑」的原子就是"教学版的定理"

**模型检验 = 毒样例的穷尽检查**：
- P1-P7毒样例就是"模型检验"：穷尽检查gate是否能拦截
- 状态爆炸 = 毒样例的组合爆炸（需要智能选择毒样例）

**Hoare逻辑 = claim的pre/post条件**：
- claim契约化（pre/post/invariant）就是Hoare逻辑的应用
- requires = 前提条件（读者需要知道什么）
- ensures = 后置条件（读者学完后能做什么）

**三证明系统交叉验证 = 三权分立的形式化版本**：
- Writer（构造证明）+ 红队（寻找反例）+ Gatekeeper（检查证明）

- 「阙疑」目前缺少RL：可以加入"根据红队/门禁反馈自动优化提示词"的闭环

## 四、音乐理论：和声与对位

### 4.1 核心理论

**和声（Harmony）**：
- 垂直方向：同时发声的音符组成和弦
- 三和弦：根音+三度+五度（大/小/减/增）
- 和弦进行：I-IV-V-I（最基本的进行）
- 协和与不协和：张力与解决

**对位（Counterpoint）**：
- 水平方向：多个独立旋律线的组合
- 要求：每条线独立，但组合起来和谐
- 技术：模仿、卡农、赋格
- 赋格：主题在多个声部中重复与发展

**节奏（Rhythm）**：
- 时间结构：重复与变化
- 节拍：强拍与弱拍的模式
- 切分音：强调弱拍，制造张力

**即兴（Improvisation）**：
- 在规则内的自由创造（爵士即兴）
- 和弦音阶理论：每个和弦对应一个音阶
- 后波普爵士的复杂和声需要新的分析方法

### 4.2 对「阙疑」的映射

**和声 = 原子的"垂直"关系**：
- prereq/contrasts：同时存在的关系（原子之间的静态关系）
- 和弦进行 = 原子的"进行"（学习路径中的原子序列）
- 协和与不协和 = claim与证据的张力与解决（不协和=问题，协和=解决）

**对位 = 原子的"水平"关系**：
- 学习路径：顺序的关系（先学A再学B）
- 每条线独立 = 每颗原子独立可验证
- 组合起来和谐 = 原子体系整体一致

**赋格 = 主题在多个原子中重复与发展**：
- 一个核心概念（如"内存安全"）在多个原子中展开
- RAII-001（主题呈示）→ UNIQUE-001（答题）→ SHARED-001（发展）
- 这解释了为什么原子之间需要"主题一致性"

**即兴 = Agent在规则内的创造**：
- 提示词给规则（和弦进行），Agent自由发挥（即兴旋律）
- 好的Agent能在规则内创造出好的"旋律"（高质量的原子）
- 差的Agent只会"弹音阶"（机械执行，没有创造）

**节奏 = 生产的节奏**：
- 批次的频率与间隔（节拍）
- 强拍 = 大批次（4颗原子），弱拍 = 小批次（1颗原子）
- 切分音 = 意外的突破（如ALLOC-002的方向反转）

## 五、叙事学：英雄之旅与情感弧

### 5.1 核心理论

**英雄之旅（Campbell, 1949）**：
- 12-17阶段的循环结构
- 三个阶段：出发（Departure）→ 启蒙（Initiation）→ 回归（Return）
- 原型：英雄、导师、门槛守卫、阴影、变形者、骗子

**三幕结构**：
- 第一幕：铺垫（Setup）
- 第二幕：对抗（Confrontation）
- 第三幕：解决（Resolution）

**情感弧**：
- Rise（上升）：从低到高的情感曲线
- Fall（下降）：从高到低的情感曲线
- "所有故事都是一个故事"（all stories are one story）

**叙事弧**：
- 平衡→打破平衡→恢复平衡
- 激励事件（Inciting Incident）：打破平衡的事件
- 中点（Midpoint）：故事的转折点
- 高潮（Climax）：最大的冲突
- 结局（Resolution）：新的平衡

### 5.2 对「阙疑」的映射

**英雄之旅 = 原子的"学习之旅"**：
- 读者（英雄）从无知（平凡世界）出发
- 遇到claim（激励事件）
- 经过证据卡（考验/盟友/敌人）
- 达到理解（高潮）
- 回归（应用知识）

**三幕结构 = 原子的三部分**：
- 第一幕：前提（prerequisite，读者需要知道什么）
- 第二幕：核心（claim+证据，主要内容）
- 第三幕：结论（应用/扩展，读者学完后能做什么）

**情感弧 = 学习的情感曲线**：
- Fall：困惑（"这怎么可能？"）→ 洞察（"原来如此！"）
- Rise：好奇（"还有什么？"）→ 掌握（"我懂了！"）
- 好的原子应该有情感弧，而不是平铺直叙

**叙事弧 = claim的论证弧**：
- 平衡（常见误解）→ 打破平衡（反例/实测）→ 恢复平衡（正确理解）
- 激励事件 = 红队的阻断（打破Writer的平衡）
- 高潮 = 实测反转（如ALLOC-002的方向反转）
- 结局 = 修正后的claim

**原型 = 原子的角色**：
- mechanism = 英雄（提供核心知识）
- pitfall = 阴影（揭示常见错误）
- contrast = 变形者（展示不同角度）
- tool = 导师（提供工具/方法）

## 六、人类学：文化演化与双重继承

### 6.1 核心理论

**双重继承理论（Boyd & Richerson, 1985）**：
- 人类通过两个继承系统适应：基因 + 文化
- 基因-文化协同进化：文化改变基因的选择压力
- 文化传播：垂直（父母→子女）、水平（同伴）、斜向（非父母长辈）

**模因学（Meme）**：
- 文化传播的单位（道金斯, 1976）
- 模因的变异、选择、传播
- 模因学的失败：过于简化，忽略了基因-文化的交互

**文化演化的机制**：
- 变异：文化特质的随机变化
- 选择：适应环境的特质被保留
- 传播：通过社会学习传播
- 偏向传播：成功偏向、声望偏向、相似性偏向

**生态位构建（Niche Construction）**：
- 有机体主动改变环境
- 环境反过来影响进化
- 人类的文化就是最大的生态位构建

### 6.2 对「阙疑」的映射

**双重继承 = 「阙疑」的双重继承**：
- 基因 = 代码（gate_engine/replay等工具，稳定但变化慢）
- 文化 = 文档/提示词（300-332，变化快但需要维护）
- 基因-文化协同进化 = 工具与方法论的协同进化
  - gate规则（基因）改变提示词（文化）的写法
  - 提示词（文化）的需求改变gate规则（基因）的设计

**模因 = 原子/误解**：
- 原子是"教学模因"：通过学习传播
- 误解是"错误模因"：通过错误传播
- 红队的作用是"模因选择"：淘汰错误的模因

**文化演化 = 架构的演化**：
- 300-332的演化过程就是文化演化
- 变异：每轮调研引入新的方向
- 选择：用户选择哪些方向有用
- 传播：有用的方向被写入提示词/工具

**生态位构建 = 「阙疑」主动构建环境**：
- 创建工具（gate/replay/poison）= 构建环境
- 环境反过来约束「阙疑」（必须通过门禁才能提交）
- 这是正反馈循环：工具越好，约束越强，质量越高

**偏向传播 = 知识的传播偏向**：
- 成功偏向：已验证的原子更容易被引用
- 声望偏向：人审签署的原子更有权威性
- 相似性偏向：同域的原子更容易被关联
