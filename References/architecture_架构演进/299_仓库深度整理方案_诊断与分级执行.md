## 二、分级整理方案

### P0：立即清理（低风险，纯 git 操作）

**动作 1：从 git 移除 _asm_demo/ 和 _emp_bench/**
```bash
git rm -r --cached _asm_demo/ _emp_bench/
```
（`--cached` 保留本地文件，只从 git 索引移除）

**动作 2：.gitignore 加两条**
```
_asm_demo/
_emp_bench/
```

**动作 3：提交**
```
git commit -m "chore: 移除误入库的临时目录 _asm_demo/_emp_bench（保留本地文件）"
```

**效果**：git 跟踪文件从 ~2300 减到 ~2109，减少 191 个临时文件。

---

### P1：References/ 子目录化（中风险，需更新引用）

按 289 的分类体系，将扁平的 96 个文件移入子目录：

```
References/
├── 00_导航/
│   └── 00_调研总档案_导航与核心发现.md
├── 01-10_指令与流程/
│   ├── 01_*.md ... 10_*.md（10 份）
├── research_资料研究/
│   ├── 11_*.md ... 79_*.md（53 份，缺 37-49）
└── architecture_架构演进/
    ├── 271_*.md ... 298_*.md（28 份）
```

**需要同步更新的引用**：
- `00_调研总档案_导航与核心发现.md` 中的所有链接
- Book/ 中引用 References/ 的地方（需 grep）
- tools/ 中硬编码 References/ 路径的脚本（需 grep）
- CI 配置（ci.yml）中引用 References/ 的地方

**风险**：移动 96 个文件，如果有遗漏的引用会导致链接断裂。需要 `grep -r "References/"` 全仓扫描。

**缓解**：先做全仓引用扫描，生成引用清单，移动后逐一更新，最后跑 CI 验证。
