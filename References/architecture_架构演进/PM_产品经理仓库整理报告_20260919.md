## 一、产品定位与核心价值

### 一句话定位
**阙疑是一个"机器可核验、错误率有上界、可换验证者"的 C++ 严格知识生产元系统。**

不是 C++ 教程库，不是代码片段集合，而是一套**知识生产的质量基础设施**——C++ 内容是试车场，真正的资产是元系统本身。

### 核心价值三角
| 维度 | 当前状态 | 上限 |
|---|---|---|
| 机器可核验 | ✅ 63 规则 / 191 命中 / 124 毒样例 | 规则全覆盖 + 行为级覆盖 |
| 错误率有上界 | ✅ 逃逸率 1/1406 ≈ 0.071%（C-P95 上界 ~0.40%） | 真实缺陷检出率（原理不可知分母） |
| 可换验证者 | 🟡 oracle_registry 3 oracle 全 OFF，0 卡填 verified_by_oracle | 多判官独立投票 + 换代影响面 |

### 与普通知识库的本质区别
普通知识库 = "人写了什么"；阙疑 = "机器能验证什么、验证不到什么、为什么验证不到"。每一条知识都附带**可复现的判决证据**（真编译、变异测试、毒样例、活性锚），而不是"作者声称"。

## 八、总结

**阙疑已经完成了从"0 到 1"的机械判决层闭环**（逃逸率 0.071%、度量诚实、信任根加固），正站在"1 到 N"的门槛上。下一个大版本的核心突破点在**论证层**——但 593 调研已经明确指出：论证层的瓶颈不是算法（grounded 求解 <0.5ms），而是**缺可信加权攻击边这一数据地基**。

因此，**594 调研（攻击关系自动生成）是整个 v2.0 的关键前置**。如果 594 能找到可行的攻击边生成路径，596 就能开工建设数据地基，v2.0 就能在 2-3 个批次内落地。如果 594 发现攻击边生成不可行（LLM 幻觉率太高、纯规则覆盖太差），则需要重新考虑 v2.0 的路径——可能转向"人审标注为主、机器辅助为辅"的渐进式方案。

**仓库卫生是产品化前的必要整理**——309 个未跟踪文件、2.5GB 缓存、136 个临时件，这些不影响功能但影响可维护性和产品形象。建议 595 批次专门做卫生 + 归档。

**人审层是持续的瓶颈**——12+ 项交人项全部积压，单用户阶段处理速度有限。grounded 层落地后可以自动确定 in/out，只留 undecided 给人审，这是缓解人审压力的关键路径。
