## 一、模糊测试（Fuzzing）

### 核心思想

覆盖率引导的模糊测试：给程序喂大量变异输入，保留能覆盖新代码路径的输入，重复数百万次。与 sanitizer（ASan/UBSan）配合，发现内存错误和 UB。

**关键机制**：
1. 变异输入（随机翻转、插入、删除）
2. 运行目标程序，记录覆盖率（边覆盖）
3. 如果输入覆盖了新边，保留到语料库
4. 否则丢弃
5. 重复

### 代表工具

| 工具 | 风格 | 覆盖率来源 | 特点 |
|---|---|---|---|
| libFuzzer | 进程内、变异式 | LLVM SanitizerCoverage | 快、单元测试风格、与 sanitizer 紧密集成 |
| AFL++ | 多进程、覆盖率引导 | 编译时插桩 | 多核、多样化变异、最广泛使用 |

### AI 引导的模糊测试

LLM 生成种子（覆盖 RFC 边界情况），AFL++ 扩展语料库。案例：QUIC 协议模糊测试，LLM 生成 45 个种子 → AFL++ 扩展到 12,000 个输入 → 68% 行覆盖率 → 发现 3 个崩溃。

### 与阙疑的关系

**模糊测试 = 自动毒样例生成的方法论。**

- 阙疑的毒样例是人工设计的（P1-P33）
- 模糊测试可以自动生成"变异的卡/夹具/工件"
- 覆盖率 = gate 规则的覆盖（哪些规则被触发了）
- 保留能触发新规则的变异体 = 新毒样例候选

### 对阙疑的启示

1. **自动毒样例生成（v8.0）**：用 LLM 生成变异的卡，跑 gate，拦不住的就是新毒样例
2. **覆盖率指标**：不只是"规则数"，还要看"规则被触发的频率"——从未被触发的规则可能是死规则
3. **与 sanitizer 配合**：夹具编译时用 ASan/UBSan，自动发现内存错误和 UB
4. **AI 引导**：LLM 生成种子（边界情况的卡），模糊测试扩展

## 二、差分测试（Differential Testing）

### 核心思想

多个功能等价的程序在相同输入下的输出应该一致，不一致就是 bug。由 McKeeman 1998 年在编译器测试中开创。

**编译器差分测试的经典方法**：
- YARPGen 生成随机程序（含 checksum）
- 用不同编译器（GCC/Clang/MSVC）和优化档编译
- 运行并比较 checksum
- 任何 checksum 变化 = 编译器 bug

### 跨版本差分测试

新版本编译器可能引入 bug（如移除了安全检查）。方法：
1. 定位两个版本的疑似差异
2. 只在新版本报告的问题 = 编译器引入的漏洞

### 与阙疑的关系

**阙疑的双平台 replay 就是差分测试。**

- Windows MinGW 和 WSL g++ 是两个"功能等价的实现"
- 相同的卡/夹具/command，输出应该一致
- 不一致 = 跨编译器问题（如 EV-MEM-017 的 _Znwm vs _Znwy）

但阙疑当前的差分测试是"手动的"——人看两个平台的输出是否一致。可以自动化。

### 对阙疑的启示

1. **跨平台一致性自动检查**：gate 规则可以自动比较 Windows 和 WSL 的 .out 输出
2. **跨编译器版本差分测试**：编译器升级后，自动重跑所有卡，发现引入的 bug
3. **差分测试作为 oracle**：当没有单一正确答案时（如性能数据），用"两个平台应该方向一致"作为 oracle
4. **MSVC 永久边界**：MSVC 不可用，所以差分测试只在 MinGW/g++ 之间做

## 三、技术债务管理

### 核心指标

| 指标 | 公式 | 健康阈值 |
|---|---|---|
| 技术债务比率（TDR） | 修复成本 / 开发成本 | <5% 健康，5-10% 可接受，>20% 危险 |
| 技术债务指数（TDI） | 0-1 归一化 | 0-0.3 绿色，0.3-0.6 黄色，0.6-1.0 红色 |
| 圈复杂度 | 线性独立路径数 | <10/函数 |
| 代码重复率 | 重复行数 / 总行数 | <5% |

### 债务分类

| 类型 | 说明 | 阙疑对应 |
|---|---|---|
| 代码债务 | 重复、复杂、坏味道 | 工具代码的重复 |
| 测试债务 | 覆盖率低、测试脆弱 | 毒样例覆盖盲区（A4/A8/A10=0） |
| 文档债务 | 过时、缺失 | 32 条 warn 中的存量债 |
| 基础设施债务 | CI 慢、工具旧 | replay 不支持多 TU、无 ccache |
| 知识债务 | 未记录的决策 | 437 个 Examples 行尾漂移 |

### 与阙疑的关系

**阙疑的 32 条 warn 就是技术债务。**

当前问题：
- warn 信噪比未知——多少是真问题，多少是误报？
- 没有量化——32 条 warn 对应的 TDR 是多少？
- 没有清理计划——哪些 warn 应该修，哪些可以接受？

### 对阙疑的启示

1. **warn 分类**：每条 warn 标记为"真问题/误报/存量债/可接受"
2. **TDR 计算**：估计修复 32 条 warn 的成本 / 总开发成本
3. **债务台账**：debt_ledger.py 已有，应该扩展为完整的技术债务管理
4. **信噪比治理**：误报率 >50% 的规则应该降级或改进
5. **golden_lock 的 warn 基线**：8→32 的一次性 accept 是"债务积累"，应该有计划地清理

## 四、学习科学

### 四大有效学习方法

| 方法 | 效果 | 机制 | 阙疑对应 |
|---|---|---|---|
| 主动回忆（Active Recall） | 比被动复习有效 23 倍 | 提取信息强化神经通路 | 闪卡、MCQ |
| 间隔重复（Spaced Repetition） | 317 项研究元分析证实 | 延迟提取=理想难度 | Anki 导出 |
| 交错练习（Interleaving） | 提升识别能力 | 混合主题训练分类 | 学习路径 DAG |
| 精细化（Elaboration） | 加深理解 | 新知识与已有知识连接 | relations、误解库 |

### 基于误解的学习（Misconception-Based Learning）

直接针对学生的错误概念进行教学，比"先讲正确概念"更有效。因为：
- 学生的错误概念是"直觉的"，不直接面对就不会消失
- 错误概念→反例→正确概念的路径，比直接讲正确概念更深刻
- 阙疑的 misconceptions/ 库（80 条）就是基于误解的学习的素材

### 流畅性错觉（Fluency Illusion）

"看懂了"≠"学会了"。被动复习（重读、高亮）产生熟悉感，让人以为学会了，但提取能力没有提升。主动回忆虽然不舒服，但正是这种"不舒服"在强化记忆。

### 与阙疑的关系

**阙疑的教学转化体系应该基于学习科学。**

- 闪卡（423）= 主动回忆 + 间隔重复
- 诊断 MCQ（v8.0 M5）= 主动回忆
- 学习路径 DAG（v8.0 M5）= 交错练习
- 误解库（80 条）= 基于误解的学习 + 精细化
- 错误示例库（v8.0）= 反例教学

### 对阙疑的启示

1. **闪卡应该支持间隔重复**：不只是导出 Anki CSV，还要有内置的复习调度（SM-2 算法）
2. **MCQ 应该有"误解选项"**：每个错误选项对应一个常见误解（misconception），学生选错了就推送对应的误解卡
3. **学习路径应该交错**：不是"学完 A 再学 B"，而是"A-B-A-C-B-A"的交错
4. **避免流畅性错觉**：每颗原子应该有"自测题"，让学生主动回忆，而不是只读卡

### 最紧急的发现

**技术债务管理是当前最被忽视的领域。**

阙疑有 32 条 warn，但：
- 不知道信噪比（多少真问题，多少误报）
- 没有量化（TDR 是多少）
- 没有清理计划（哪些该修，哪些可接受）
- golden_lock 一次性 accept 了 24 条 warn，这是"债务积累"

在送去对抗之前，至少应该对 warn 做分类和量化——否则对抗模型会问"你的 32 条 warn 都是什么？多少是真问题？"

### 最有价值的框架

**差分测试 = 双平台 replay 的理论基础和自动化方向。**

阙疑一直在做双平台 replay，但没有形式化。差分测试给出了：
- 理论基础（独立实现应该一致）
- 自动化方法（自动比较输出）
- 扩展方向（跨版本、跨优化档）
