### 二、P4-P7 收紧方案

#### 2.1 P4 EV-SELF-SATISFIED-ASSERT：前提判定修正 + 同构风险扩展

**当前代码**（gate_engine.py L653）：
```python
if not _re.search(r"operator\s+(new|delete)", code):
    continue  # 夹具未自定义分配/释放 ⇒ 无自证风险
```

**问题**：`operator\s+(new|delete)` 同时匹配"定义"和"调用"。`::operator new(...)` 是调用，不是定义。

**改进**：
1. 只匹配**定义**形态：`void\s*\*\s*operator\s+new\s*\(` 或 `void\s+operator\s+delete\s*\(` 出现在函数定义位置（行首或缩进后，不是 `::` 前缀）
2. 扩展到"夹具自写格式串"的同构风险：如果断言候选是 printf 格式串（`%s`、`%d` 等），且该格式串在夹具中定义，则同样零判别力（命中定义处即通过）
3. 豁免条件收紧：卡内注明"调用点 N 处"不够，必须给出具体的调用点计数或 grep 结果

**伪代码**：
```python
# 只匹配定义（不是调用）
has_defined_operator = _re.search(r'^\s*(void\s*\*\s*operator\s+new|void\s+operator\s+delete)\s*\(', code, _re.M)
# 扩展：夹具自写格式串
has_defined_format = _re.search(r'printf\s*\(\s*"[^"]*%[sdx][^"]*"', code)  # 格式串在夹具中
```

#### 2.2 P5 EV-FALSIFICATION-QUANT：从"有无数字"升级为"成对取值"

**当前代码**（L678）：
```python
if f and not _re.search(r"\d", f):
    out.append(Finding(...))
```

**问题**：只要有数字就通过，不区分"单个数字"和"成对对照"。

**改进**：要求 falsification 中出现**成对取值**——两个不同的数值，且语义上是"预期 vs 实测"或"对照 A vs 对照 B"。

**判定模式**：
- `\d+\s*(vs|/|→|->)\s*\d+`（显式对照，如 "3 vs 0"、"8056/32"）
- `应为?\s*\d+.*实测\s*\d+`（预期 vs 实测）
- `对照\w*[:：]\s*\d+.*实验\w*[:：]\s*\d+`（对照 vs 实验）

**豁免**：如果 falsification 是纯定性描述（如"若 X 则 Y"），且卡内有单独的 `falsification_quant` 字段提供量化值，则通过。

#### 2.3 P6 EV-TRIVIAL-OBSERVATION：从拼写白名单改为结构判据

**当前**：`_TRIVIAL_OBS_PATTERNS` 只认三种 null 拼写。

**改进**：识别"恒真型结构"——由夹具自身定义直接推出的布尔读数。

**结构模式**：
- `X_nonzero=1` / `X_is_nonzero=1`（存在性判断）
- `X_beats_Y=1` / `X_slower=1`（方向判断，无具体数值）
- `X_plusN=1`（阈值判断，无具体数值）
- `same_line=1` / `is_same=1`（同型自比）

**同时要求**：每张卡至少一条"对关键变量有响应"的对照读数——即改变输入时该读数会变。

**实现难点**：结构判据容易误报（`sharing_is_slower=1` 是有判别力的，因为它对照了两种布局）。需要区分"恒真"和"有判别力的布尔"。

**折中方案**：
- 保留拼写白名单（高置信度）
- 新增"结构模式"为低置信度（advice 级，不是 warn）
- 要求卡内至少一条读数是"数值型"（不是布尔型）——如果 actual 全是布尔读数，报 warn

#### 2.4 P7 EV-MATRIX-UNBACKED：豁免必须带可核对锚

**当前代码**（L720）：
```python
if len(comps) > 1 and not any(k in raw for k in ("外部", "留痕", "待 CI", "CI 回填")):
```

**问题**：关键词自证——写一句"外部留痕"就豁免。

**改进**：豁免必须伴随可核对内容。对于 matrix.compiler 中每个**没有仓内工件**的编译器，卡内必须出现至少一个可核对锚：
- `.out` 文件路径（如 `Examples/atoms/_atom_xxx_linux.out`）
- CI run 号（如 `CI run #566`）
- `::notice::` 注解（GitHub Actions 日志注解）
- 完整复跑命令行（如 `g++-14 -std=c++23 -O2 ...`）

**判定**：
```python
# 对每个额外编译器，检查是否有可核对锚
extra_comps = comps[1:]  # 第一个默认有仓内工件
for comp in extra_comps:
    has_anchor = any([
        _re.search(r'\.out', raw),           # .out 文件
        _re.search(r'CI\s*run\s*#\d+', raw), # CI run 号
        '::notice::' in raw,                 # GitHub 注解
        _re.search(r'g\+\+-\d+\s+-std=', raw), # 命令行
    ])
    if not has_anchor:
        out.append(Finding(...))
```

**副作用**：现有多编译器卡需补齐锚，预计新增若干 warn（接受为真实债）。

## 第二部分：证据卡迁移脚本（302 落地工具）

### 五、迁移目标

把 48 张证据卡从旧形态（actual.run_final_O2 超长字符串）迁移到新形态（actual.run_match_file + run_match_keys），配合 302 的三层分离。

### 六、迁移脚本设计

#### 6.1 输入输出

**输入**：
- 证据卡文件（evidence/**/EV-*.md）
- 对应的 .out 文件（Examples/atoms/_atom_*.out，如果存在）

**输出**：
- 修改后的证据卡（actual 字段改为 run_match_file + run_match_keys）
- 生成的 .out 文件（如果卡内有 actual.run_final_O2 但没有 .out 文件）

#### 6.2 迁移逻辑

```
for each evidence card:
    1. 解析 frontmatter
    2. 如果 actual.run_final_O2 存在：
       a. 提取 run_final_O2 的值（超长字符串）
       b. 解析 key=value 对（用 | 分隔）
       c. 确定 run_match_keys：
          - 从 hypothesis 中提取提到的数值指标
          - 从 expected.run 中提取提到的指标
          - 取交集 + 必要的活性对照
       d. 如果 .out 文件不存在，创建它（写入 run_final_O2 的值）
       e. 替换 actual 字段：
          actual:
            run_match_file: Examples/atoms/_atom_xxx.out
            run_match_keys: [key1, key2, ...]
       f. 删除卡内的"修订记录"节（如果有）
       g. 保留 revision_note 一句话（指向 commit hash）
    3. 如果 actual.run_match_file 已存在：跳过（已迁移）
```

#### 6.3 run_match_keys 的自动提取

**策略**：
1. 从 hypothesis 中提取所有数值（正则 `\d+\s*B`、`\d+\s*ns`、`\d+\s*×` 等）
2. 从 expected.run 中提取所有 key（正则 `(\w+)=`）
3. 取两者的交集作为 run_match_keys
4. 如果交集为空，取 expected.run 中的前 5 个 key
5. 始终包含活性对照 key（如果卡内有标注）

**人工审核**：自动提取后，Writer/红队需要审核 run_match_keys 是否覆盖了 claim 的核心断言。

#### 6.4 安全措施

1. **dry-run 模式**：先预览改动，不实际写入
2. **备份**：迁移前自动 git commit（确保可回退）
3. **验证**：迁移后重跑 replay，确认 48/48 confirm
4. **分批迁移**：先迁 3 张试点，验证后再全量

#### 6.5 脚本接口

```bash
# 预览（不写入）
python tools/migrate_evidence_cards.py --dry-run

# 迁移指定卡
python tools/migrate_evidence_cards.py --card evidence/mem/EV-MEM-040.md

# 全量迁移
python tools/migrate_evidence_cards.py --all

# 迁移后验证
python tools/migrate_evidence_cards.py --verify
```

### 七、迁移风险与缓解

| 风险 | 缓解 |
|---|---|
| run_match_keys 遗漏关键指标 | 自动提取 + 人工审核；gate 规则检查覆盖度 |
| .out 文件与卡不同步 | replay 工具检查 .out 存在性和 sha |
| 旧卡的 actual 格式不统一（不是 key=value\|） | 脚本检测格式，不统一的跳过并标记 |
| 迁移后 replay 失败 | 分批迁移，每批后重跑 replay；失败则回退 |
