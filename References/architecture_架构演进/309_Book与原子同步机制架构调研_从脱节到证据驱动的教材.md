# 309_Book与原子同步机制架构调研_从脱节到证据驱动的教材

> 2026-09-12 · 当前 Book 151 个文件、23 颗原子，但 Book 引用原子 0 处、原子引用 Book 仅 2 处——完全脱节。
> 本文调研如何建立双向同步机制，让原子证据驱动教材正文。
> 关联：Book/（16 部分 151 文件）· atoms/（23 颗）· M1_ontology

---

## 一、现状诊断

### 1.1 脱节程度

| 指标 | 数值 | 说明 |
|---|---|---|
| Book 文件数 | 151 | 16 个部分，覆盖 C++ 全体系 |
| 原子数 | 23 | MEM 21 + UB 1 + HIST 1 |
| Book 引用原子 | 0 | 教材正文没有任何 `ATOM-XXX` 引用 |
| 原子引用 Book | 2 | 原子的 sources 字段偶尔提到 Book 章节 |
| MEM 原子数 | 21 | part04_memory 只有 10 章 |

**问题本质**：原子是"证据库"，Book 是"教材正文"，但两者是独立发展的——原子生产不看 Book，Book 写作不看原子。

### 1.2 脱节的后果

1. **教材没有证据支撑**：Book 的论述是"作者说"，不是"证据说"——读者无法验证
2. **原子没有教学出口**：原子的 claim 和证据卡是"为自己存在"，没有转化为教材章节
3. **重复劳动**：Book 里已经写了 RAII/智能指针，原子又重新写一遍，但两者没有链接
4. **不一致风险**：Book 的说法和原子的实测结论可能矛盾（如 ch41:1704 写"ASan 可检测循环引用泄漏"，但 LEAK-001/002 实测证明"没报≠没泄漏"）
5. **无法追溯**：读者看到 Book 的一个结论，无法找到对应的实验证据

### 1.3 已有的局部修正

- LEAK-001 入库时修正了 Book/part04_memory/ch41_smart_pointers.md L1704（"ASan 可检测"→分层表述）
- 但这是"原子生产时顺手改 Book"，不是系统性的同步机制

## 二、同步机制设计

### 2.1 双向引用规范

**原子 → Book**：每颗原子的 `sources` 字段必须列出对应的 Book 章节（如果存在）。

```yaml
sources:
  - "Book/part04_memory/ch41_smart_pointers.md#L1700-L1750"
  - "C++ Standard [util.smartptr]"
```

**Book → 原子**：Book 正文中，每个有实验证据的论断必须标注对应的原子。

```markdown
## 41.3 shared_ptr 的线程安全

shared_ptr 的控制块使用原子操作维护引用计数，因此多个线程各自持有副本时是安全的。
但被指向的对象本身不受保护，需要额外同步。<atom>SHARED-002</atom>
```

**渲染**：`<atom>SHARED-002</atom>` 在构建时渲染为可点击链接，指向原子的完整证据。

### 2.2 一致性检查工具

写 `tools/book_atom_sync.py`，检查：

1. **原子无 Book 引用**：原子的 sources 没有 Book 路径 → warn
2. **Book 论断无原子支撑**：Book 中出现"实验证明""实测""性能数据"等关键词，但没有 `<atom>` 标注 → warn
3. **矛盾检测**：Book 的说法与原子的 claim 矛盾（需要语义分析，初期人工审核）
4. **原子过时**：Book 已更新但原子未更新（或反之）→ 通过 git log 检测

**用法**：
```bash
python tools/book_atom_sync.py --check          # 检查同步状态
python tools/book_atom_sync.py --report         # 生成同步报告
python tools/book_atom_sync.py --atom SHARED-002 # 检查某颗原子的同步状态
```

### 2.3 原子驱动的 Book 写作流程

**新流程**：
1. 先生产原子（claim + 证据卡 + 实测）
2. 原子 verified 后，Writer 基于原子写 Book 章节
3. Book 章节中引用原子（`<atom>XXX</atom>`）
4. 一致性检查工具验证双向引用

**旧流程**（当前）：
1. 先写 Book 章节（基于作者知识）
2. 再生产原子（独立于 Book）
3. 两者没有链接

**关键转变**：从"Book 是主、原子是辅"变为"原子是证据、Book 是叙事"——原子先于 Book，Book 引用原子。

### 2.4 渐进式同步

不需要一次性改 151 个 Book 文件。按优先级：

| 优先级 | 范围 | 理由 |
|---|---|---|
| P0 | part04_memory（10 章） | MEM 域 21 颗原子，对应最紧密 |
| P1 | part03_language（值类别/移动） | VALUE-001/002、MOVE-002 对应 |
| P2 | part09_concurrency | CONC 域首批原子后 |
| P3 | 其余部分 | 逐步推进 |

**P0 实施**：为 part04_memory 的 10 章逐一标注 `<atom>` 引用，预计 1-2 轮完成。

## 三、原子到教材的转化模板

每颗原子可以转化为 Book 的以下内容：

| 原子内容 | Book 转化 |
|---|---|
| claim | 章节的核心论断 |
| hypothesis | 章节的"为什么" |
| 证据卡 actual | 章节的"实验结果"（表格/代码块） |
| 夹具 | 章节的"示例代码" |
| 误解 | 章节的"常见误区"框 |
| 红队阻断 | 章节的"注意"框（"这里容易错"） |
| 修订记录 | 章节的"历史注记"（可选） |
| relations | 章节的"延伸阅读" |

**模板**：
```markdown
## 章节标题

<核心论断，来自原子 claim>

### 直觉解释
<教学类比，来自原子 pedagogy>

### 实验证据
<来自证据卡的 actual 数据，表格或代码块>

```cpp
<来自夹具的核心代码>
```

### 常见误区
<来自误解库>

> 注意：<来自红队阻断的关键提醒>

### 延伸阅读
- <atom>RELATED-ATOM</atom>
- [外部资料](...)
```

## 四、与其他系统的关系

### 4.1 与知识图谱（306）的关系

- 原子图谱中的 `example_of` 关系可以对应 Book 的章节
- 知识空白发现可以指导 Book 的待写章节
- 重复检测可以发现 Book 与原子的内容重叠

### 4.2 与 G6 四级状态的关系

- 只有 human-verified 或 red-team-verified 的原子才能被 Book 引用
- draft 状态的原子不能出现在 Book 中（防止未验证的结论进入教材）
- 一致性检查工具验证 `<atom>` 引用的原子状态

### 4.3 与 CI 的关系

- book_atom_sync.py --check 加入 CI quality job
- 如果 Book 引用了不存在的原子或 draft 原子 → CI 失败
- 如果原子无 Book 引用 → warn（不阻断）
