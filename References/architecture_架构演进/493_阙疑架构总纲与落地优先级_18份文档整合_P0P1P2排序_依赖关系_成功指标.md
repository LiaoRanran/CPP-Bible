## 八、与 479 实测结果的对照

479 批次验证了几个关键判断：

1. **ccache 不是性能瓶颈**（1.22×）→ P0-1 增量 replay 才是正解，已排最高优先级
2. **E12 git 绑定存量命中 0** → 确认 git author 只是第一层，P2-14 GPG 签名是远期真解
3. **doc_lint 发现 19 处存量失真** → P0-7 文档 frontmatter + P0-4 编号修复是前置
4. **分类学错位留待裁决** → 建议方案 B（改文档标注被取代），不影响 P0 推进
5. **TDD 反转已落地** → 478 的零成本项已完成，P0 中不再重复

## 九、使用方式

苦力 Agent 按此优先级推进：
1. 每次开工前 Read 本文档，确认当前批次和项
2. 每项完成后跑全量门禁，对比基线数字
3. 每项一个独立 commit + 毒样例 + pytest
4. 完成后更新本文档的状态列（P0-1 ✅ 等）
5. 遇到依赖未满足的项，跳过做下一个

人（监工）只需要：
- 裁决 P1/P2 的范围调整
- 签署 verified 原子
- push
- 季度回溯（491）
