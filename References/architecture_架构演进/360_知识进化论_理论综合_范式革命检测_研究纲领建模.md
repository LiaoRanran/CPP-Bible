## 一、为什么"原子积累"不等于"知识增长"

当前20颗verified原子是20个正确的命题，但它们是**点状的**：
- 学生学完20个点，遇到第21个没见过的情况，仍然不会判断
- 命题之间的深层推导关系没有被显式表达（只有prereq/contrasts这种浅层关系）
- 没有"统一解释"——例如消除、重排、屏障、volatile、原子类型，本质是同一个"可观测性契约"问题的不同侧面，但这个统一理论不存在

**知识的增长有两种模式**：
1. **常规积累**：在现有框架内增加命题（v1.x做的事）
2. **进化压缩**：把多个命题压缩为更少、更一般、能预测新情况的原理（v2.0要做的事）

真正的智能标志是压缩——能从少量原理推出大量结论，而不是记住大量结论。

## 二、知识的四级表示模型

### 2.1 层级定义

```
范式 Paradigm（看待整个领域的框架/世界观）
  │  例："C++程序的语义由抽象机的可观测行为定义，不是源码的字面执行"
  │
  ├── 理论 Theory（一组命题+推导规则构成的解释体系）
  │    │  例：编译器转换理论（消除/重排/提升的统一模型）
  │    │
  │    ├── 原理 Principle（高度概括的命题，跨多个具体场景）
  │    │    │  例："未被可观测的计算可能被编译器消除"
  │    │    │
  │    │    └── 命题/原子 Atom（具体可证伪陈述）
  │    │         例：FENCE-001"屏障在循环体内阻止消除"
  │    │
  │    └── 概念 Concept（术语指称）
  │         例：可观测行为、副作用、内存序
```

### 2.2 各级的Schema

**原理（Principle）**：
```yaml
id: PRIN-{DOMAIN}-{NNN}
statement: "原理陈述（跨场景的一般命题）"
scope: "适用范围与边界"
derived_atoms: [ATOM-...]        # 这个原理能推出哪些原子
derivation_rules: "从原理推出原子的推理规则"
exceptions: [已知例外]
compression_ratio: "原理数:它解释的原子数（应<1）"
evidence_strength: "支持原理的独立证据线数量"
status: draft / established / challenged / superseded
```

**理论（Theory）**：
```yaml
id: THEORY-{DOMAIN}-{NNN}
name: "理论名称"
hard_core: [硬核假设列表]          # 拉卡托斯：不轻易放弃的核心
protective_belt: [保护带假设]      # 遇异常时优先调整的辅助假设
positive_heuristic: "正面启发法：该做什么研究/实验"
negative_heuristic: "反面启发法：不要质疑什么"
principles: [PRIN-...]
predicted_atoms: [理论预言但尚未生产的原子]
anomalies: [当前解释不了的异常]
explains_atoms: [已解释的原子]
status: progressive / degenerating / crisis / replaced
```

**范式（Paradigm）**：
```yaml
id: PARA-{DOMAIN}
worldview: "框架的核心世界观陈述"
theories: [THEORY-...]
exemplar_problems: [范式的典范问题及其标准解法]
methods: "范式认可的研究方法"
values: "范式重视的价值（如可复现性/形式化/工程实用）"
```

## 三、理论综合（Theory Synthesis）流程

### 3.1 触发条件

- 一个域verified原子≥10颗（MEM已达20，满足）
- 或：出现≥3颗原子共享同一深层机制（人工/系统识别）
- 或：教学中发现"多个点其实是一回事"

### 3.2 综合流程

```
T1 聚类（Clustering）
   按"共享机制"而非"共享主题"分组原子
   例：消除/重排/volatile/原子类型 → "可观测性"簇
        （而不是按"都是并发"这种表面主题）
   ▼
T2 机制提取（Mechanism Extraction）
   对每个簇，问：这些原子共同体现的更一般原理是什么？
   产出：候选原理（必须能从原理推出簇内所有原子）
   ▼
T3 公理化（Axiomatization）
   区分：哪些是公理（不证自明/约定），哪些是定理（可推导）
   建立推导关系：原理 + 规则 → 原子
   ▼
T4 压缩检验（Compression Test）
   - 覆盖：原理能推出簇内全部verified原子吗？有反例吗？
   - 压缩：原理数 < 原子数吗？（否则没压缩）
   - 预测：原理能预言"还没生产的原子"吗？（最强检验）
   - 简洁：有没有更简单的等价原理集？
   ▼
T5 红队攻击（Theory Red Team）
   - 找原理的反例（什么情况下原理不成立）
   - 找过度概括（原理的适用范围是否被夸大）
   - 找循环论证（原理是不是只是原子的重述）
   ▼
T6 固化（Crystallization）
   原理/理论入库，原子frontmatter增加derived_from字段
   理论的predicted_atoms进入研究backlog（主动学习输入）
```

### 3.3 防止"错误压缩"的四条判据（红队强制）

1. **覆盖反例检查**：簇内只要有1颗原子无法从原理推出→原理不成立或需限定scope
2. **非同义反复检查**：原理不能只是原子的合取/重述（"RAII/屏障/volatile都很重要"不是原理）
3. **预测新颖性检查**：原理必须能推出至少1个"簇内没有的新预言"，且新预言可验证
4. **独立证据检查**：原理最好有≥2条独立证据线（不同夹具/不同现象），防止单一路径过拟合

### 3.4 压缩的产物示例（MEM域可能的理论）

> **理论候选："可观测性契约理论"**
> - 硬核：编译器可以任意转换程序，只要不改变抽象机定义的可观测行为
> - 原理1：计算若不产生任何可观测效果，可能被消除（解释消除类原子）
> - 原理2：重排的自由度取决于内存模型赋予的顺序保证（解释屏障/内存序类原子）
> - 原理3：让计算"可观测"的手段（volatile/原子IO/屏障位置）决定它能否存活
> - 预测：任何"加了同步却仍失效"的bug，本质都是同步手段没有作用在正确的可观测点上
> - 这个理论能统一FENCE-001、未来的CACHE/volatile/内存序多颗原子

（这是示例，实际理论必须经T1-T6流程和红队攻击，不能直接采纳）

## 四、范式革命检测（库恩模型的工程化）

### 4.1 范式健康度监控

系统为每个理论维护"研究纲领"状态（拉卡托斯）：

| 状态 | 判据 | 含义 |
|---|---|---|
| progressive（进步的） | 理论不仅能解释新异常，还能预言新事实并被证实 | 健康，继续在框架内积累 |
| degenerating（退化的） | 理论只能被动地为每个异常打补丁（ad hoc），不再预言新事实 | 警惕，开始积累 |
| crisis（危机） | 退化持续 + 出现竞争性理论能更好解释 | 准备范式转换 |
| replaced（被取代） | 新理论解释旧理论全部成功 + 解释旧理论的异常 | 范式转换完成 |

### 4.2 危机检测指标（机器可追踪）

```yaml
paradigm_health:
  anomaly_rate: "近期异常数 / 近期原子数（上升=危机信号）"
  ad_hoc_patch_rate: "保护带补丁数 / 理论预言成功数（>1=退化）"
  novel_prediction_rate: "理论预言被证实的数量（下降=退化）"
  competitor_explanatory_power: "竞争理论的覆盖率（接近/超过旧理论=危机）"
  crisis_threshold: "ad_hoc率连续3批>1 且 新预言连续3批=0 → crisis"
```

### 4.3 范式转换的规则

- 新范式必须满足：
  1. 解释旧范式下所有verified原子（不能丢知识）
  2. 解释导致危机的全部异常
  3. 至少有1个旧范式给不出的新预言被证实
- 旧范式不删除，标记superseded并保留（科学史价值+教学对比）
- 范式转换是**人审A级事件**（最高决策影响，不可机器自治）
- 转换后全库受影响原子重新审视（但verified状态不自动撤销，逐个复核）

### 4.4 已发生的微型范式转换（案例库）

| 旧框架 | 异常 | 新框架 | 案例 |
|---|---|---|---|
| "ASan能检测循环引用泄漏" | 多形态下LSan零报告 | "检测信号分层，报告与否依赖代码形态" | LEAK-001/002 |
| "屏障阻止编译器重排" | 屏障拦不住循环消除 | "屏障约束顺序但不制造可观测性" | FENCE-001 |
| "pool元数据最小" | 统一口径后pool=8056B | "元数据开销与单块释放能力绑定" | ALLOC-002 |
| "小对象池总是更快" | Linux平台排序翻转 | "性能结论平台相关，可移植的是因果链" | PERF-003 |

这些都是"旧claim被新证据推翻"的微观革命。v2.0让这个过程被显式追踪，而不是改完就忘。

## 五、研究纲领的启发法（指导研究方向）

每个理论建立后，它本身指导未来研究：

**正面启发法（该做什么）**：
- "可观测性契约理论"→ 系统地测试每种语言构造的可观测性边界（volatile/原子/IO/屏障组合）
- 理论的predicted_atoms自动成为研究backlog

**反面启发法（不要做什么）**：
- 不要轻易修改硬核（如遇到反例先怀疑夹具/测量，而不是直接推翻"可观测行为契约"）
- 但反面启发法不是教条——当保护带补丁率超过阈值，硬核也要接受审查

**保护带的有序调整**：
异常出现时，按顺序调整：①测量工具→②夹具→③辅助假设→④原理scope→⑤硬核
越靠前越先怀疑，防止"一有反例就推翻理论"或"死守错误理论"。

## 六、跨域知识迁移（模式库的进化机制）

### 6.1 模式（PAT）的生命周期

```
错误/发现首次出现（某域）
    ▼
抽象为模式PAT（剥离领域细节，保留结构）
    ▼
模式入库 + 标注first_observed域
    ▼
新域开工 → 自动检查"该模式在本域可能的形态"
    ▼
在新域发现同模式 → domain_instances增加，模式可信度↑
    ▼
模式在多域复现 → 可能升级为"原理"（跨域原理）
    ▼
模式被反例限制 → 增加scope边界
```

### 6.2 模式升级为原理的条件

- 在≥3个不同域复现（domain_instances≥3）
- 有统一的机制解释（不只是"看起来像"）
- 能预言新域中的情况

例：自证断言（MEM的operator new、可能在CONC的原子计数器、UB域的自定sanitizer）若在3域复现，可升级为原理：**"验证路径必须独立于被验证对象，否则验证退化为恒真"**——这是一条跨域的认识论原理。

### 6.3 迁移检查的自动化

新域/新原子开工时，系统输出：
```
跨域模式检查报告：
- PAT-SELF-SATISFIED（自证断言）：本域风险点=自定义原子操作计数，建议检查
- PAT-TRIVIAL-OBS（恒真观测）：本域风险点=use_count/线程join后的固定值
- PAT-COMPILER-ELISION（编译器消除）：本域风险点=无副作用的同步代码
...（按本域相关性排序）
```

## 七、知识进化层的失败模式

| 失败模式 | 描述 | 防御 |
|---|---|---|
| 过早综合 | 原子太少就建理论，基础不牢 | 触发阈值≥10颗 + 覆盖率检验 |
| 过度概括 | 原理scope过大，反例频发 | 四条压缩判据 + 红队找反例 |
| 理论增生 | 太多互相重叠的理论 | 理论也做去重/合并，理论数受控 |
| 范式保守 | 死守退化理论，拒绝转换 | crisis阈值机器监控 + 竞争理论机制 |
| 范式激进 | 稍有异常就革命 | 保护带有序调整 + 转换的高门槛 |
| 伪压缩 | 原理只是原子重述，无预测力 | 预测新颖性检查（必须有新预言） |
| 迁移牵强 | 表面相似就跨域套用 | 迁移需统一机制解释+新域实证 |
| 知识丢失 | 范式转换丢掉旧知识 | 新范式必须覆盖旧范式全部verified原子 |

## 八、落地优先级

1. **第一步**：原子frontmatter增加derived_from/related_principles字段；开始维护模式库PAT（把已有的自证断言/恒真观测/口径不统一/编译器消除等抽象入库）——成本低，立即支撑跨域迁移
2. **第二步**：MEM域首次理论综合试点（20颗原子已满足阈值），走T1-T6，产出第一个理论（很可能是"可观测性契约理论"）
3. **第三步**：理论Schema+研究纲领状态追踪（progressive/degenerating）
4. **第四步**：范式健康度监控+危机检测指标自动化
5. **第五步**：范式转换流程（人审A级）首次实战

## 核心结论

v1.x让「阙疑」能积累**正确的点**；知识进化层让它能把点连成线、织成网、长成能预测新情况的理论体系。

> 智能的本质不是记住更多事实，而是用更少的原理解释更多的现象。理论综合是压缩，范式革命是压缩算法的升级，跨域迁移是压缩成果的复用。当系统能自己完成"积累→压缩→预言→危机→再压缩"的循环，它就从知识库变成了会成长的认知体。
