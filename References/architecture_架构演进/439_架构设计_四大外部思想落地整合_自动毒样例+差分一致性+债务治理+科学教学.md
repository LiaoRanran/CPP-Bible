## 一、P1：技术债务治理（warn 分类+量化+清理）

### 1.1 问题

阙疑有 32 条 warn，但：
- 不知道信噪比（多少真问题，多少误报）
- 没有量化（TDR 是多少）
- 没有清理计划
- golden_lock 一次性 accept 了 24 条 warn

**对抗模型一定会问**："你的 32 条 warn 都是什么？多少是真问题？多少是误报？"

### 1.2 warn 分类标准

每条 warn 必须标记为：

| 分类 | 说明 | 处理方式 |
|---|---|---|
| real_issue | 真问题，应该修 | 排入修复计划 |
| false_positive | 规则误报，应该改进规则 | 改进规则或降级为 advice |
| legacy_debt | 存量债，暂时接受 | 登记到 debt_ledger，定期清理 |
| accepted | 可接受的设计选择 | 登记理由，不再告警 |

### 1.3 技术债务指数（TDI）

```
TDI = (real_issue + 0.5 * legacy_debt) / total_warn
```

| TDI 区间 | 等级 | 动作 |
|---|---|---|
| 0-0.3 | 绿色（健康） | 持续监控 |
| 0.3-0.6 | 黄色（预警） | 纳入下个迭代修复 |
| 0.6-1.0 | 红色（高危） | 阻断送对抗，专项治理 |

### 1.4 debt_ledger.py 扩展

当前 debt_ledger.py 只记录"到期债务"，扩展为完整的技术债务台账：

```yaml
# data/debt_ledger.yaml
- id: DEBT-001
  type: warn
  rule: EV-MATRIX-*
  count: 17
  classification: false_positive
  description: "MATRIX 规则对已真实跨平台卡的误报"
  estimated_fix_cost: 4  # 小时
  risk: medium
  status: accepted  # open/accepted/fixed
  accepted_by: human:liaoranran
  accepted_at: "2026-09-12"
```

### 1.5 gate 规则：WARN-CLASSIFIED（warn）

存量 warn 必须有分类标记，否则给"未分类 warn"的 advice。

## 二、P1：差分测试自动化（跨平台一致性检查）

### 2.1 问题

阙疑的双平台 replay 是"手动的"——人看两个平台的 .out 输出是否一致。没有自动比较。

### 2.2 差分测试规则：EV-CROSS-PLATFORM-CONSISTENCY（warn）

对每张卡，自动比较 Windows 和 WSL 的 .out 输出：
- 确定性输出（如 dtor_count=1）必须逐字一致
- 性能输出（如运行时间）只比较方向（A>B 还是 A<B），不比较数值
- 不一致 → warn（可能是跨编译器问题，如 EV-MEM-017）

### 2.3 跨版本差分测试（v8.0）

编译器升级后，自动重跑所有卡：
- 比较新版本和旧版本的 .out 输出
- 确定性输出变化 = 编译器引入的 bug 或行为变化
- 自动生成"编译器升级影响报告"

### 2.4 差分测试作为 oracle

当没有单一正确答案时（如性能数据），用"两个平台应该方向一致"作为 oracle：
- 如果 Windows 说 A>B，WSL 说 A<B → 数据不可信，warn
- 如果两个平台方向一致 → 数据可信

## 三、P2：自动毒样例生成（模糊测试方法论）

### 3.1 核心流程

```
1. LLM 生成种子：变异的卡/夹具/工件（边界情况、奇怪格式）
2. 跑 gate，记录哪些规则被触发
3. 拦不住的变异体 → 新毒样例候选
4. 拦住的变异体 → 已有规则覆盖，不需要新毒样例
5. 重复，直到覆盖率不再提升
```

### 3.2 覆盖率指标

不只是"规则数"，还要看"规则被触发的频率"：
- 从未被触发的规则 = 死规则（可能是规则太严，或没有对应的毒样例）
- 被频繁触发的规则 = 高价值规则
- 覆盖率 = 被触发过的规则数 / 总规则数

### 3.3 与 sanitizer 配合

夹具编译时用 ASan/UBSan：
- 自动发现内存错误和 UB
- 发现的问题自动转化为新原子（如"这个夹具在 ASan 下报错"）

### 3.4 落地路径

- v8.0：LLM 生成种子 + 人工筛选新毒样例
- v9.0：全自动模糊测试管道（持续运行，自动发现新毒样例）

## 四、P2：教学转化体系深化（学习科学）

### 4.1 闪卡 v2.0（主动回忆 + 间隔重复）

当前 423 只做了静态导出（Anki CSV）。v2.0 应该：
- 内置 SM-2 间隔重复算法
- 每张卡有"难度"字段（easy/medium/hard）
- 复习调度：1天→3天→7天→14天→30天
- 导出时包含调度信息

### 4.2 诊断 MCQ（主动回忆 + 误解驱动）

每颗原子配 3-5 道 MCQ：
- 每个错误选项对应一个常见误解（misconception）
- 学生选错了 → 推送对应的误解卡
- 学生选对了 → 强化正确概念
- 这是"基于误解的学习"的直接应用

### 4.3 学习路径 DAG（交错练习）

不是"学完 A 再学 B"，而是交错：
- A-B-A-C-B-A（间隔重复 + 交错练习）
- 根据 relations 生成学习路径
- 每步有自测题（主动回忆）

### 4.4 错误示例库（反例教学）

把 misconceptions 变成"错误代码 + 为什么错 + 怎么改"的活示例：
- 错误代码：学生常写的错误版本
- 为什么错：引用对应的原子卡
- 怎么改：正确版本 + 解释
- 这是"反例教学"的直接应用

### 4.5 避免流畅性错觉

每颗原子必须有"自测题"：
- 学生读完卡后，必须回答 2-3 个问题
- 答不上来 → 标记为"未掌握"，安排复习
- 答对了 → 标记为"已掌握"，进入间隔重复
