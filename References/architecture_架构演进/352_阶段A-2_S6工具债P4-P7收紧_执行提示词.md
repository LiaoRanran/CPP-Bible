## 一、目标

收紧S6阶段（毒样例演练）的P4-P7四条规则，解决PERF-003实测中暴露的"4/4零命中"问题——规则写了但抓不到真实错误。

**四条规则的当前问题**（来自docs/S6_tool_debt.md）：

| 规则 | 当前问题 | 收紧方向 |
|---|---|---|
| P4 EV-SELF-SATISFIED-ASSERT | 前提误判：只检查"夹具自定义operator new/delete"，但自证断言可以是任何自定义函数 | 扩展到"任何夹具自定义函数+断言只做存在性匹配" |
| P5 EV-FALSIFICATION-QUANT | 只查"有无数字"，不查数字是否可复算 | 增加"数字必须有对应的actual行或.out留痕" |
| P6 EV-TRIVIAL-OBSERVATION | 只认三种null拼写（!= nullptr/== nullptr/!= NULL），模式太窄 | 扩展到"纯存在性判断"（!= 0/== 1/非空检查等），但保留跨类型比对的豁免 |
| P7 EV-MATRIX-UNBACKED | "留痕"关键词自证豁免过宽——只要写了"留痕"就豁免 | 豁免必须带可核对锚（.out路径/CI run号/::notice::注解/复跑命令行） |

## 二、实现步骤

### Step 1：P4收紧——自证断言扩展

**当前实现**（gate_engine.py中的EV-SELF-SATISFIED-ASSERT）：
- 检查夹具是否自定义operator new/delete
- 如果是，且断言只做contains存在性匹配→命中

**收紧后**：
- 检查夹具中是否有**任何自定义函数**（不只是operator new/delete）
- 如果断言的contains目标是该自定义函数的**符号名**，且断言只做存在性匹配（不含调用点/参数/返回值检查）→命中
- 豁免：卡内已注明"调用点N处"或"该函数被调用N次"的卡（有量化调用点，不是纯存在性）

**新增毒样例P4b**：
- 夹具自定义一个普通函数（如`int my_counter() { return 0; }`）
- 证据卡断言`contains: "my_counter"`（只检查函数存在，不检查调用）
- 预期：P4命中

### Step 2：P5收紧——falsification数字可复算

**当前实现**：
- 检查falsification字段是否有数字（正则匹配\d+）
- 无数字→命中

**收紧后**：
- 检查falsification中的每个数字是否在卡的actual字段或.out留痕中出现
- 数字不在actual/.out中→命中（数字不可复算）
- 豁免：数字是"阈值"（如">10x"中的10）且卡内注明是"阈值非实测值"

**新增毒样例P5b**：
- falsification写"如果性能倍数<5则证伪"，但actual中没有5这个数字，.out中也没有
- 预期：P5命中

### Step 3：P6收紧——恒真观测模式扩展

**当前实现**：
- 检查actual中是否有`!= nullptr`/`== nullptr`/`!= NULL`三种模式
- 有→命中

**收紧后**：
- 扩展模式表：`!= 0`/`== 1`/`!= NULL`/`== true`/`!= false`/`is_not_null`/`exists=1`等纯存在性判断
- 保留豁免：跨类型比对（如sizes equal=1，是对"删除器是否被擦除"有判别力的）
- 豁免条件：actual行中包含比较对象的明确标识（如`size_a=8 size_b=16 equal=0`，equal是比较结果不是纯存在性）

**新增毒样例P6b**：
- actual写`allocation_succeeded=1`（纯存在性，1只表示"成功了"，没有量化）
- 预期：P6命中

### Step 4：P7收紧——矩阵留痕必须带可核对锚

**当前实现**：
- 检查matrix.compiler字段是否有"外部留痕"说明
- 有"留痕"关键词→豁免

**收紧后**：
- 豁免必须满足以下**至少一个**条件：
  1. 卡内有`.out`文件路径（如`留痕见Examples/_atom_xxx.out`）
  2. 卡内有CI run号（如`CI run #566 ::notice::`）
  3. 卡内有完整复跑命令行（如`setarch -R g++ -fsanitize=thread ...`）
  4. 卡内有工件sha256（跨编译器的工件锚）
- 只有"留痕"二字但无以上任何锚→命中

**新增毒样例P7b**：
- matrix写`compiler: {gcc-14: "现场复跑，有留痕"}`，但卡内没有.out路径/CI run号/命令行/sha
- 预期：P7命中

## 三、关键约束

1. **收紧不导致已有原子被block**——全库回归必须block=0，warn增加可以接受
2. **毒样例必须是"最小可复现"**——每个毒样例只触发一条规则，不触发其他规则
3. **豁免条件必须可机器检查**——不能是"卡内说明了"这种模糊条件
4. **规则改动必须有修订记录**——在gate_engine.py的规则注释中记录"v1→v2的变更原因"
5. **不修改replay/golden_lock的核心逻辑**——只改gate_engine.py的规则实现
