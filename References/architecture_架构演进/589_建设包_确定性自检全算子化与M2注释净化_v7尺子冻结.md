## 3. 任务 1 · 确定性自检覆盖全算子（固定小卡集，与主跑规模解耦）

**问题**：`selfcheck_determinism()`（约 1201 行）用 `sub_ops = [o for o in ops if o in _SELFCHECK_OPS]`（约 1208 行）只留 M1/M6/M7，却对**全量 cards/limit** 重跑；`jobs>1` 时还用 `jobs=1` 串行再跑一遍（约 1212-1213）。若简单把 _SELFCHECK_OPS 扩成 7 算子，串行对账会退化成全量串行（约 667s），不可接受。

**改法（改 `tools/mutation_fuzz.py`，不碰 CORE）**：

1. 新增**固定自检卡集**（确定性、可 review、提交进仓库）：建议落 `data/mutation/selfcheck_cards.json`（卡相对路径列表，按算子分组或扁平去重均可），内容取自任务 0.3 实跑确认的候选；总卡数控制在 **12–18 张**，保证每个算子 M1–M7 在该集上**至少产生 1 条 blocked 变体**（M6 另含 1 条 equivalent）。
2. 改 `selfcheck_determinism`：重跑对象从"3 算子 × 全卡"改为"**全 7 算子 × 自检小卡集**"；`jobs>1` 的 `jobs=1` 串行对账也用同一小卡集。该小卡集**固定、不随命令行 `--limit`/`--cards` 变化**（保证自检结果跨运行稳定可比）。`--limit` 仅约束主跑，不再约束自检。
3. **覆盖有效性 fail-loud**：自检启动前先断言小卡集对每个算子都产出了 ≥1 条 blocked；某算子 0 blocked（选卡无效=该算子自检空转、绿得没有判别力）→ 直接报错退出（exit2）并指明是哪个算子选卡失败，不许静默通过。
4. 控制串行对账成本：`jobs=1` 全算子 × 小卡集的墙钟目标 **< 90s**（实跑填进 worklog；超标就缩减每算子卡数，但不得破坏"每算子 ≥1 blocked"）。

**测试（新增到 tests，沿用 579 既有 selfcheck 测试的风格，至少 4 条）**：
- (a) 干净态：全算子小卡集 `jobs=4` 与 `jobs=1` 逐变体一致，`selfcheck_determinism` 返回 `(True, [])`，CLI `--selfcheck-determinism` exit0；
- (b) **可证伪反例**：用 monkeypatch/替身让"第二次跑"在某一条变体上判决偏斜，断言返回 `(False, 非空 diffs)` 且 CLI **exit2**、抖动清单含该变体（这是"绿必须能被打成红"的锁）；
- (c) 覆盖断言：小卡集对 M1–M7 **每个**算子 ≥1 blocked，否则自检报错（构造一个缺卡的假清单断言 fail-loud）；
- (d) 断言自检算子覆盖 == 全 7 算子（防止以后有人改回子集却无测试拦）。

**边界**：只改自检的"算子集与卡集"选择，**不许改 `_variant_index` 的比对字段、不许改任何判决路径**。任务 1 完成后，全量 v6 数字必须**逐字不变**（本任务不产新基线，基线在任务 3 统一重冻结）。

## 4. 任务 2 · M2 攻击集净化：字段块内的注释路径不再造伪变异

**问题根因（已定位，先读码确认）**：`mut_m2`（约 203 行）已用 `_gate_read_spans()`（约 173 行）把范围限定在门禁读取字段的**字符区间**内；但 spans 按"顶格键→下一顶格键"划区间，**字段块内部缩进的注释行（`   # ...路径...`）也落在区间内**，于是 `_PATHP.finditer`（约 211 行）扫到注释里的示意路径也造了变形。这 27 条改的是注释，YAML 解析后丢弃，故 P1/P2 canon 相同、被等价判据正确剔除——但它们根本不该被造出来。

**改法（改 `tools/mutation_fuzz.py`，不碰 CORE）**：

1. 新增纯函数，例如 `_is_within_yaml_comment(text: str, idx: int) -> bool`：判断字符偏移 `idx` 是否位于其所在行的 YAML 注释段——即该行在 `idx` 之前出现了"行首 `#`"或"前面是空白/TAB 的 `#`"（YAML 规定 `#` 只有在行首或前面是空白时才开始注释）。**保守**：无法可靠判断引号内 `#` 时，只认"`#` 前是空白或行首"（真实路径里的 `#` 前通常紧跟非空白字符，不会误判）。M6 的 `_mut_matrix_values` 已有 `ln.split("#",1)[0]` 剥注释先例（约 450 行起），口径与其保持一致；**本包不重构 M6**（M6 的 8 条 flow 等价变体是合法等价样本，保留）。
2. 在 `mut_m2` 的遍历里，对每个路径匹配除现有 `_gate_read_spans` 判断外，**再加 `and not _is_within_yaml_comment(text, m.start())`**。注意控制流：遇到"在 span 内但落在注释里"的路径要 **`continue` 继续找下一个匹配**，而不是 return；只有找到"span 内、非注释、含 `/`、非 `./` 开头"的真实路径才产出三种变形并 return；遍历完没有则维持现在的 out_of_scope 单例（`vtext=None`）语义不变。
3. 单元测试 `_is_within_yaml_comment`：整行注释、行内注释（`key: val   # 见 Examples/x.cpp`）、真实值行（`run_match_file: Examples/x.out` 必须判 False）、`#` 紧贴非空白（保守判非注释）等边界。

**正反例回归锁（关键，防止"净化"误伤真实变异 = 攻击集盲区）**：
- **反例（27 条消失）**：EV-CONC-001 / EV-CONC-002 / EV-MEM-038 等字段块内注释示意路径不再产生"转大写/加./、反斜杠"变体；任务 0.4 的 27 条清单在修后**逐条消失**。
- **正例（真实变异一条不少）**：修后 M2 的 **blocked 变体集合与 v6 完全相同（141 条，按卡 + 变形类型对账）**；特别构造一张合成卡：frontmatter 注释里写一条路径、`actual.run_match_file`（或 command/artifact_assert）里也写一条真实路径，断言**只变异真实路径、不碰注释路径**。
- 修后单跑 M2（`--operators M2 --cards all --limit 999`）应为：**blocked=141、equivalent=0、n_a=27，总 168**（v6 是 195=141+27eq+27n_a；27 条注释伪变异消失）。任何 blocked 变少都说明误删了真实变异，**立即回退、报偏差**。
