# 399 阙疑 v6.0 完整架构蓝图：整合 25 份调研的终极形态

> 日期：2026-09-13。本份是 374-398 共 25 份架构调研的**整合产物**——不是再调研，而是把所有精华压缩成一份可执行、可对抗、可落地的架构蓝图。
> 定位：**v6.0**（372 是 v5，本份在 v5 基础上吸收 25 份调研后升级）。
> 用途：①送去独立对抗模型攻击；②晚上集中搭建的依据；③后续所有进化的基线。

## 〇、设计哲学（5 条铁律）

### 铁律 1：T0 博弈防御（继承 v5）
假设 Agent 会在约束内投机——每条规则都要问"如果 Agent 想绕过，它会怎么做？"。373 对抗实证：14 个逃逸中 11 个是"在规则字面内投机"（空名签收、.out 编造、借工件），不是"违反规则"。

### 铁律 2：数据驱动决策（新增）
所有架构决策必须有数据支撑。"文献说有效"≠"我们系统上有效"。每个优化上线前必须 A/B 测试或基准验证。**可观测性是所有优化的前提**（387）。

### 铁律 3：最小可行优先（新增）
不做过度设计。先做"最小可行版本"，用数据验证后再扩展。398 的内卷结论：7 项 P0 精简到 3 项核心。**内卷的价值是做更少但更准。**

### 铁律 4：接地自纠错（389）
纯内在自纠错（模型判断自己）是脆弱的。自纠错必须接地——执行结果、结构化批评、PRM 评分。EIR（错误引入率）必须近零才能放权，且 EIR 必须区分"红队采纳"和"红队驳回"（397）。

### 铁律 5：声明-实现必须绑定（373 绕过测试核心发现）
任何"工具只查声明文本"的规则都可被"写漂亮声明、干另一件事"绕过。规则必须检查**实现**而非**声明**——artifact_producer 必须和 command 实际执行绑定，不能只看字段写了什么。

## 一、七层架构

```
┌─────────────────────────────────────────────────────┐
│ L7 自治层：自纠错 / 数据飞轮 / 自我进化 / 可观测性    │
├─────────────────────────────────────────────────────┤
│ L6 验证层：门禁 / 红队 / 形式化 / Fuzzing / 正例回归  │
├─────────────────────────────────────────────────────┤
│ L5 运行时：上下文工程 / 多模型路由 / 鲁棒性 / 沙箱    │
├─────────────────────────────────────────────────────┤
│ L4 接口层：提示词(压缩) / Agent Skills / 查询分解     │
├─────────────────────────────────────────────────────┤
│ L3 工具层：gate/replay/poison/golden_lock + MCP化    │
├─────────────────────────────────────────────────────┤
│ L2 存储层：扁平文件(当前) → 向量+图混合(长期)         │
├─────────────────────────────────────────────────────┤
│ L1 数据层：原子/证据卡/误解/架构文档 + 知识图谱schema │
└─────────────────────────────────────────────────────┘
```

### L1 数据层

**实体**：
- 原子（atoms/）：27 颗，10 类 type，四级 status（draft/rule/verified/deprecated）
- 证据卡（evidence/）：56 张，verdict=confirm/refute，双平台 artifact
- 误解（misconceptions/）：~80 条，3 反例
- 架构文档（References/architecture_架构演进/）：25 份（374-398）+ 历史

**知识图谱 schema（380）**：
- relations 字段：prereq（前置）/ contrasts（对比）/ serves（服务）/ equivalent（等价，新增）
- 跨域引用：ATOM-MEM-* ↔ ATOM-CONC-* ↔ ATOM-LANG-*
- 缺口检测：哪些原子没有前置？哪些域没有覆盖？哪些关系缺失？

**可攻击点**：relations 有三种写法（list/mapping/string），归一规则只拦两种（373 绕过测试发现 mapping-form 被静默丢弃）。

### L2 存储层

**当前**：扁平 Markdown 文件 + grep/Glob 检索（~183 文件，检索 1-3 秒）

**中期**：Chroma（向量语义检索）+ NetworkX（图多跳推理）——都是 Python 库，零基础设施

**长期**（原子>100 时）：pgvector + Neo4j 混合存储

**可攻击点**：扁平文件在 500+ 原子时检索性能会成为瓶颈；向量检索的 embedding 模型选择会影响召回质量。

### L3 工具层

**核心工具（5 个）**：
| 工具 | 功能 | 当前状态 |
|---|---|---|
| gate_engine.py | 42 条规则，block/warn/advice | 运行中 |
| atom_evidence_replay.py | 三分类（confirm/refute/infra_error） | 运行中 |
| poison_drill.py | 30 毒样例，RULE-COVERAGE 10/37 | 运行中 |
| golden_lock.py | 基线同步+恶化检测 | 运行中 |
| cppbible.py | 质量检查总入口 | 运行中 |

**升级方向**：
- MCP 化（394）：包装成标准接口，任何 MCP 兼容 Agent 可调用
- 输出 JSON 化：为 MCP 包装做准备
- 静态分析集成（392）：clang-tidy/Clang Static Analyzer 作为第二层验证（需 Clang 环境）

**可攻击点**：工具调用无审计（388 OWASP 第 2 大风险）；工具输出是上下文最大污染源（383，70% 阈值触发清理）。

### L4 接口层

**提示词体系**：
- 生产提示词（312 系列）：28KB，目标压缩 ≥30%（386）
- 红队提示词（373 系列）：两段式盲读 + can't-miss 清单
- 搜索提示词：加查询分解+信息缺口检测（393）

**优化手段**：
- 负面指令改正面（减 10-15% token，386）
- 删除重复内容
- 背景知识移附录
- 精准 few-shot（省 40-60%，386）

**Agent Skills（394）**：可复用技能包（npx skills add），当前是"提示词复制粘贴"，未来标准化

**可攻击点**：提示词压缩可能丢失关键约束（需要 A/B 测试验证）；查询分解可能增加搜索次数反而浪费 token。

### L5 运行时

**上下文工程（383）**：
- 70% 阈值触发压缩
- 工具输出清理（最大污染源）
- 会话压缩+长期持久三层记忆（393）

**多模型路由（384）**：
- 级联路由：先便宜模型→验证→不通过升级
- 50-70% 任务可用最便宜层（文献结论，需验证）
- 我们的优势：有确定性验证器（gate/replay），比 FrugalGPT 的 LLM 评分更可靠

**鲁棒性（376）**：
- checkpoint-resume（预测性暂停+冷恢复）
- 优雅降级五级
- Windows/WSL 双环境一致性

**沙箱（388）**：
- 纵深防御（输入过滤/权限隔离/输出校验）
- 工具调用边界审计（ClawGuard 思路）

**可攻击点**：多模型路由的"便宜模型 EIR 更高"与"放权要求 EIR≈0"矛盾（397 批判 2）；上下文压缩可能丢失关键信息。

### L6 验证层

**门禁体系**：
- gate：42 条规则，block/warn/advice 三级
- replay：三分类（confirm/refute/infra_error），双平台
- poison：30 毒样例，RULE-COVERAGE 10/37
- golden_lock：基线同步+恶化检测

**红队（382）**：
- 两段式盲读（先夹具/工件，后卡）
- 每条阻断配替代解释≥1+验证动作
- can't-miss 清单（13 条）
- 迭代轮次：当前 1 轮，目标 2-3 轮（需验证新增发现率）

**形式化（391）**：
- claim 反事实条件字段（什么观测会推翻 claim）
- 反事实扰动测试（PERF-003 已实证价值）
- 完整 Lean 证明（P4 不做，成本过高）

**Fuzzing（395）**：
- 毒样例自动化（从红队逃逸中学习攻击模式）
- 覆盖率引导（发现规则盲区）
- 需 Clang 环境（当前无，P3 长期）

**正例回归（398）**：
- 新规则上线必须报"存量命中数（真债/误伤）"
- 56 张合法卡=天然正例集
- 373 修复批实测：新规则误伤 6 张，降为 warn

**可攻击点**：红队本身的质量保证（谁来审红队？）；毒样例只有负例没有正例；Fuzzing 需 Clang 环境。

### L7 自治层

**自纠错（389）**：
- 接地自纠错（执行结果/结构化批评/PRM）
- EIR 追踪（错误引入率，区分红队采纳/驳回）
- EIR≈0 才能放权

**数据飞轮（385）**：
- Execute（生产）→ Coach（红队+门禁）→ Distill（失败模式聚类）→ Improve（规则+提示词进化）
- 当前：Execute+Coach 成熟，Distill+Improve 缺失
- 373 的 14 逃逸+13 绕过是 Distill 的原材料

**自我进化（379）**：
- 经验→启发式（ERL/EvolveR）
- 双反馈（RetroAgent）
- 元认知反思（MARS）
- 技能演进（Memento-Skills）

**可观测性（387）**：
- 四支柱：Traces+Metrics+Logs+Evaluations
- per-step token/延迟/模型/工具参数
- 当前：手动记录（质检报告加头部），长期自动化脚本

**可攻击点**：数据飞轮的 Distill 阶段缺失（失败模式靠人聚类）；可观测性数据来源有限（豆包不暴露 API token）；自我进化可能"抛光退化"（EIR>0 时越修越差）。

## 二、三大核心流程

### 流程 1：原子生产（MCC 六步）

```
预言冻结（实验前写死，git 时间戳为证）
  → 夹具设计（单变量对照+活性对照+反例对照）
  → 双平台实测（Windows+WSL，确定性读数）
  → 证据卡（actual 逐字+sha 锚+falsification 可证伪）
  → 红队（两段式盲读，阻断必须修）
  → 门禁全跑（replay/gate/poison/pytest/golden_lock/WSL 预检）
  → 原子化（move+签署+gate block=0+golden_lock sync）
```

**关键纪律**：
- 时序数据不入断言锚（PERF-003 教训）
- 工件与断言同代（ALLOC-002 教训）
- 夹具不重载 operator new/delete（避 P4 自证断言）
- 性能卡 command 不含性能打印（-DBENCH_FULL 宏门控）
- 自旋夹具必须有界（无限循环致 replay 超时）

### 流程 2：对抗进化（红队→毒样例→规则→回归）

```
红队发现逃逸
  → 分类（声明-实现脱钩 / 恒真断言 / .out 编造 / ...）
  → 生成毒样例（阴阳配对）
  → 加规则（窄化设计，实测误伤≤存量真债）
  → 正例回归（存量 56 卡命中数）
  → 回归测试（pytest + poison 全量）
```

**373 实证**：14 逃逸→4 新规则（窄化后）→30 毒样例→pytest 135→正例回归误伤 6→降为 warn

### 流程 3：数据飞轮（Execute→Coach→Distill→Improve）

```
Execute：生产原子/证据卡
  ↓
Coach：红队+门禁+人审
  ↓
Distill：失败模式自动聚类（当前缺失，P2）
  ↓
Improve：规则进化+提示词版本管理+回归测试（当前部分缺失）
```

## 三、质量保障体系

### 四级状态（G6）
- draft → rule → verified → deprecated
- status_history 三点（创建/机器验证/人签）
- principal_ok 单点化（前缀+实名非空+人级在册）

### DAL 分级
- A/B：强制人审
- C/D/E：红队通过即可，但豁免须人签 dal_reviewed_by

### 三分类 replay
- confirm（内容通过）
- refute（内容证伪）
- infra_error（环境故障，fail-closed，不计入内容恶化）

### EIR 追踪
- 每批记录：修复操作数 / 红队采纳数 / 红队驳回数
- EIR = 采纳数 / 修复操作数
- EIR≈0 才能放权

### 正例回归
- 新规则上线必须报存量命中数
- 误伤必须收窄或降 warn

## 八、可攻击点清单（给对抗模型的靶子）

对抗模型请重点攻击以下断言：

1. **"可观测性是所有优化的前提"**——是否有"边做边观测"的路径？手动记录是否足够？
2. **"312 压缩 ≥30% 且质量不降级"**——压缩的边界在哪？哪些约束不能删？
3. **"正例回归靠流程纪律"**——人会忘，是否必须工具化？
4. **"多模型路由 50-70% 可用最便宜层"**——在我们的任务分布上是否成立？便宜模型的 EIR 多少？
5. **"EIR≈0 才能放权"**——EIR 怎么精确测量？红队驳回的怎么算？
6. **"声明-实现绑定"**——技术上怎么实现？command 是自由文本，怎么验证它真的执行了声明的编译器？
7. **"数据飞轮 Distill 自动聚类"**——失败模式的分类标准是什么？LLM 聚类的可靠性？
8. **"知识图谱 schema 落地"**——relations 三种写法的归一是否完备？有没有第四种？
9. **"Fuzzing 需 Clang"**——GCC 有没有等价的 fuzzing 工具？是否必须等 Clang？
10. **"扁平文件在 500+ 原子时成为瓶颈"**——具体瓶颈是什么？检索速度？一致性？并发？
11. **"红队 2-3 轮迭代"**——多轮红队的边际收益递减点在哪？
12. **"MCP 化提升互操作性"**——我们的工具都是 Python 脚本，MCP 包装的真实收益是什么？
13. **"负面改正面减 10-15% token"**——这个数字来自文献，在我们的提示词上实测是多少？
14. **"工具输出是最大污染源"**——我们的工具输出占上下文比例实测是多少？
15. **"三级 block/warn/advice"**——warn 级的"半通过"是否会导致信噪比恶化（373 绕过测试发现）？

## 九、元结论

阙疑 v6.0 的核心进化（从 v5 到 v6）：

| 维度 | v5（372） | v6（399） |
|---|---|---|
| 架构层 | 轻内核+演化 | 七层完整架构 |
| 验证 | 门禁+红队 | 门禁+红队+形式化+Fuzzing+正例回归 |
| 成本 | 无体系 | 提示词压缩+路由+工具清理+可观测性 |
| 自治 | 自纠错+数据飞轮（概念） | 自纠错+数据飞轮+EIR+可观测性（可执行） |
| 安全 | 签收防伪 | 签收+工具审计+声明-实现绑定+沙箱 |
| 落地 | 无路线图 | 三阶段+P0 三项核心 |
| 对抗 | 一次性 | 持续进化引擎 |

**v6 的核心信念**：架构的价值不在"层数多"，而在"每层都有可验证的主张、可攻击的细节、可落地的路径"。本份列出的 15 个可攻击点，就是 v6 接受检验的入口。

**调研的尽头是架构，架构的尽头是落地，落地的尽头是对抗中进化。**
