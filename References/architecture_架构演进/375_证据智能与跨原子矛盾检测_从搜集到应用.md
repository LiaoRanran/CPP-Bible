# 375 证据智能与跨原子矛盾检测：从搜集到应用

> 日期：2026-09-13。监工完成，是 374（语义自律）的上一层延伸。
> 流程：搜集 → 整理 → 挖掘 → 联系 → 批判 → 结合 → 应用。

## 一、搜集（搜了什么）

三路并行检索，覆盖 2025-2026 年前沿：
1. 主动实验设计 / 证据缺口检测 / 闭环科学发现
2. 知识图谱矛盾检测 / 跨文档不一致 / 多源融合
3. AI Scientist 自动化科研 / 假设-实验-证伪闭环

核心来源（12 份高相关）：
- LLM-AutoSciLab（arXiv 2605.24043）：假设条件化主动实验设计
- Hypothesis-Driven Deep Research（arXiv 2605.10224）：结构化 gap 识别
- The Little Scientist（arXiv 2608.16951）：科学方法五步法+局部最优逃逸
- PRISM（RSC 2026）：模拟作为强制前置门
- Personal Knowledge Agent（GitHub）：持久信念图+直接矛盾检测
- NotebookLM 三重一致性校验（语义/引用/时序）
- AutoVerifier（arXiv 2604.02617）：跨源矛盾根因分析
- Kontrast（arXiv 2607.25959）：跨模态不一致分类法
- AI Scientist v2（Sakana AI）：Best-First Tree Search 并行探索
- DeepScientist（arXiv 2509.26603）：贝叶斯优化+Findings Memory+分层验证
- NovelSeek（arXiv 2505.16938）：自进化想法生成+多轮实验
- POPPER（awesome-ai-for-science）：agentic 连续证伪

## 二、整理（分类）

| 类别 | 核心问题 | 代表工作 |
|---|---|---|
| A. 证据缺口检测 | 系统自动知道"还缺什么证据" | Hypothesis-Driven Deep Research |
| B. 主动实验设计 | 选哪个实验最能区分竞争假设 | LLM-AutoSciLab、PRISM |
| C. 科学方法闭环 | hypothesis→prediction→code→test→reconciliation | The Little Scientist、POPPER |
| D. 直接矛盾检测 | 同一实体互斥属性/跨源冲突 | Personal Knowledge Agent、ClinicalTruth |
| E. 引用/时序断裂 | 引用不存在、时序倒置 | NotebookLM 三重校验 |
| F. 矛盾根因分析 | 矛盾不只是对错，要分析为什么 | AutoVerifier、Kontrast |
| G. 探索策略 | 线性 vs 树搜索 vs 贝叶斯优化 | AI Scientist v2、DeepScientist |

## 三、挖掘（每个类别的核心洞察）

**A. 证据缺口检测**：gap identification 产出结构化描述——name / type（logical 或 informational）/ importance / rationale / suggested search。不是"感觉缺证据"，是"这个断言的哪个前提没有被验证、缺什么类型的证据、建议怎么补"。

**B. 主动实验设计**：从已有观测构建机制假设集 → 识别"候选假设预测不一致的观测点" → 用主动学习选择最能区分机制的实验。核心不是"做更多实验"，是"做最有信息增益的实验"。PERF-003 的双平台翻转，如果先列竞争假设（池更快/全局new更快/取决于平台），就会主动设计双平台对照，而不是做完才发现。

**C. 科学方法闭环**：hypothesis → prediction（实验前写死）→ code → test → reconciliation（预测vs实测的差异分析）。卡在局部最优时第二个 agent 介入。我们的 371 预言冻结就是 prediction 环节——外部验证了这个设计是对的。

**D. 直接矛盾检测**：新 claim 批量嵌入，和已有信念图比对，检测直接矛盾。但关键局限：**只检测直接矛盾，不检测传递性矛盾**（A矛盾B，B蕴含C，所以A矛盾C）。传递矛盾需要推理，纯嵌入做不到。

**E. 引用/时序断裂**：三类——语义层冲突（同一实体互斥属性）、引用层断裂（"见X"但X不存在）、时序层倒置（A的结论依赖B但B在A之后）。这三类可以直接映射到原子间关系检查。

**F. 矛盾根因分析**：跨源矛盾时不只标记分歧，还做根因分析——谁在claim、源是否独立、为什么分歧。典型根因：不兼容的运行时定义、基线依赖、口径不同。我们 ALLOC-002 的"元数据口径不统一"就是典型的口径矛盾。

**G. 探索策略**：线性 pipeline（v1）→ Best-First Tree Search 并行探索（v2）→ 贝叶斯优化平衡探索/利用（DeepScientist）。核心：不是按计划机械走，是"有希望的方向深挖 + 新方向探索"动态平衡。

## 四、联系（和我们系统的映射）

| 外部发现 | 我们已有的对应 | 差距 |
|---|---|---|
| A. 证据缺口检测 | 建设者凭经验判断 | 没有工具自动扫描断言-证据绑定 |
| B. 主动实验设计 | 夹具凭直觉设计 | 没有"竞争假设→区分点"的强制模板 |
| C. 科学方法闭环 | 371 预言冻结（prediction） | prediction 有，reconciliation 不系统 |
| D. 直接矛盾检测 | 无（27颗原子是孤岛） | 完全空白 |
| E. 引用/时序断裂 | relations DAG（部分） | 没有跨原子引用检查 |
| F. 矛盾根因分析 | 红队人工做 | 没有结构化根因模板 |
| G. 树搜索探索 | 线性批次（一批3颗） | 没有动态优先级 |

**已被外部验证的设计**：371 预言冻结 = The Little Scientist 的 prediction 环节；三权分立 = 科学方法的独立验证；对抗驱动 = POPPER 的连续证伪。

## 五、批判（哪些不适用、哪些有局限）

1. **AI Scientist v2 的三篇全AI论文后来被评审指出方法缺陷**——全自动化科研质量仍需人审，支持我们"人审最后一关"的设计，不支持"完全无人"。
2. **DeepScientist 消耗 200万+ token**——我们额度限制做不到，需要更高效的闭环，不能照搬"大规模探索"。
3. **传递性矛盾需要推理，纯工具做不到**——跨原子矛盾检测首批只能做直接矛盾+引用断裂，传递矛盾留中期，且需要 LLM 辅助会有误报。
4. **主动实验设计的上限取决于假设集质量**——如果建设者列的竞争假设本身就漏了关键假设，再聪明的实验设计也区分不出来。假设生成是瓶颈，不是实验选择。
5. **树搜索需要评估函数**——"哪个方向更有价值"的评估本身是主观的，我们目前靠人审判断，自动化评估需要先定义价值指标（教学价值/证据强度/未覆盖度）。
6. **PRISM 的模拟前置门在我们域不适用**——C++ 夹具的"模拟"就是编译+运行，已经在做了，不需要额外模拟层。

## 六、结合（和已有架构的结合点）

**和 374 语义自律的结合**：
- 374 应用1（断言-证据绑定）是基础——只有绑定关系结构化了，证据缺口检测才能自动扫描。
- 374 应用3（正反论证强制）是主动实验设计的输入——竞争假设列出来了，才能选区分点。

**和 371 预言冻结的结合**：
- 预言冻结 = prediction，主动实验设计 = "选哪个 prediction 最有区分度"
- reconciliation（预测vs实测差异）可以标准化为卡内必填节，而不是现在散落在修订记录里

**和 G6 状态体系的结合**：
- 跨原子矛盾检测可以作为 verified 级的前置检查——原子入库前检查和已有原子是否直接矛盾/引用断裂
- machine-verified 级可以加"证据缺口扫描通过"作为条件

**和 relations DAG 的结合**：
- 跨原子矛盾检测需要 relations 字段先结构化（N1 双写法归一就是前置条件，hy4p 正在修）
- 引用断裂检查 = relations 引用的 target id 是否存在 + 是否是 verified 级

**和批次策略的结合**：
- 从"线性批次"升级为"每批结束后评估价值→下一批动态选方向"
- 价值指标候选：教学覆盖度（这个知识点在 Book 里有没有对应章节）、证据强度（实测vs外部锚点）、未覆盖度（域内空白比例）

## 七、最终应用（分阶段落地）

### 首批（语义自律落地后即可做，轻量）

**应用 1：证据缺口扫描工具**
- 扫描所有原子的 claim 断言（374 落地后有结构化断言），检查绑定的 evidence id
- 产出 gap 报告：哪些断言没有绑定证据、哪些 evidence 是 verdict=refute、哪些引用了不存在的 id
- 不自动修，只报告——建设者决定补什么
- 这是 A 类的最小落地，不需要 LLM，纯工具扫描

**应用 2：夹具设计模板升级**
- 建设者写夹具前必须填：竞争假设≥2（支持/反对各≥1）、本夹具的哪个观测点能区分这些假设
- 没有"区分点"的夹具设计→warn
- 这是 B 类的流程化，不需要新工具，改提示词模板即可

**应用 3：跨原子直接矛盾+引用断裂检查**
- 同域原子的 claim 断言是否互斥（关键词级初筛，LLM 复核）
- relations 引用的 target id 是否存在、是否 verified
- 作为 verified 入库前置检查
- 这是 D+E 类的最小落地，传递矛盾留中期

### 中期（需要更多基础设施）

**应用 4：矛盾根因分析模板**
- 红队/监工发现跨原子矛盾时，必须填根因分类：口径不同 / 前提不同 / 平台不同 / 真矛盾 / 时序更新
- 这是 F 类的结构化

**应用 5：reconciliation 标准化**
- 每张卡必填"预言 vs 实测差异"节（371 已有预言冻结，补 reconciliation 环节）
- 差异>0 必须解释原因

### 长期（需要价值评估体系）

**应用 6：批次树搜索**
- 每批结束后自动评估各方向价值（教学覆盖/证据强度/未覆盖度）
- 下一批优先深挖高价值方向，同时保留探索新域的预算
- 这是 G 类的落地，但需要先定义可计算的价值指标

## 八、本调研和 374 的关系

374 解决"claim 有没有证据支撑"（语义自律，验证层）
375 解决"系统知不知道缺什么证据、原子之间有没有矛盾"（证据智能+知识图谱层，建构层）

两者是递进关系：374 落地后 375 才有结构化输入（断言-证据绑定、竞争假设）。不能跳过 374 直接做 375。

## 九、局限与后续

- 本调研聚焦"证据智能+跨原子矛盾"，未覆盖"认知智能"（跨原子发现新概念、生成新假设）——那是更上一层，留待 375 落地后再调研。
- 跨原子矛盾检测的误报率需要实测校准——首批上线后要用已知矛盾（如 LEAK-001 vs LEAK-002 的互补关系）做阴阳例测试。
- 主动实验设计的"区分点"判断目前只能靠建设者自填，未来可以用夹具的观测点 vs 竞争假设的预测做自动匹配，但这需要断言结构化到更细粒度。
