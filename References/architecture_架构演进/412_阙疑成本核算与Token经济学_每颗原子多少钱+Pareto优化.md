# 412 阙疑成本核算与 Token 经济学：每颗原子多少钱 + 如何 Pareto 优化

> 日期：2026-09-13。外部调研：任务级成本（Cost Per Task）、Token Efficiency Ratio (TER)、成本归因六维度、模型路由 Pareto 优化（删被支配模型）、连续批处理 2-3x 吞吐、投机解码 2-3 token/验证、Shopify Gisting 6000→1500 token、自动前缀缓存。
> 研究问题（411 SOP）：阙疑每颗原子的生产成本是多少？哪些环节最费 token？如何在不损失质量的前提下做 Pareto 优化？

---

## 一、阙疑的成本结构：每颗原子多少钱

### 成本分解（MCC 六步的 token 消耗）

| 环节 | 模型 | 上下文特征 | 成本占比（估） |
|---|---|---|---|
| 1. 夹具设计+实测 | Writer（强模型） | 系统提示词+历史+证据卡 | ~30% |
| 2. 证据卡撰写 | Writer（强模型） | 系统提示词+夹具输出+读数 | ~25% |
| 3. 红队两段式盲读 | 红队（强模型，独立子 agent） | 重新加载系统提示词+夹具/工件 | ~25% |
| 4. 修订 | Writer（强模型） | 系统提示词+红队报告+卡 | ~15% |
| 5. 门禁全跑 | 机器（零 token） | 纯脚本 | 0% |
| 6. 原子化+签署 | 机器/人 | 零或极少 | ~5% |

### 关键发现
1. **输入 token 是大头**：系统提示词（312 等）+ 历史上下文 + 证据卡内容，输入:输出比可达 100:1（agent 场景的典型值）
2. **红队是成本热点**：独立子 agent 重新加载系统提示词，上下文不共享 = 重复消耗
3. **门禁零成本**：gate/replay/poison 都是纯脚本，这是阙疑的成本优势——质量保证不花 token
4. **修订轮数是成本放大器**：红队发现的阻断越多，修订轮数越多，成本越高（但质量也越高）

### 行业基准
- 输出 token 通常比输入贵 2-5x（每个输出 token 需要完整前向传播，输入可以并行 prefill）
- 但输入 token 总量通常远大于输出（agent 场景 100:1），所以**输入才是成本驱动**
- 无界对话历史是最大的成本泄漏——滑动窗口修复可降 40-70%

## 二、成本核算方法

### 核心指标：Cost Per Verified Atom（CPVA）

不是"每颗草稿原子"，是"每颗 verified 原子"——因为草稿可能被红队打回、可能最终不签署。

```
CPVA = (Writer tokens + Redteam tokens + Revision tokens) × 模型单价 / verified_atoms
```

### Token Efficiency Ratio (TER)

```
TER = 有效产出 token / 总消耗 token
```
- 有效产出 = 最终入库的原子+卡+误解的字符数（转 token）
- 总消耗 = 所有 LLM 调用的 input+output token
- 阙疑当前 TER 估计很低（<5%），因为大量 token 花在系统提示词重复加载和红队的探索性调用上

### 成本归因六维度（行业标准）
1. **per task**：每颗原子的成本（核心指标）
2. **per step**：MCC 每步的成本（夹具/卡/红队/修订）
3. **per model**：每个模型的总消耗（Writer 模型 vs 红队模型 vs 苦力模型）
4. **per batch**：每批的总成本（第五批 6 窗口 vs 第四批 3 窗口）
5. **per revision**：每次修订的成本（红队发现的问题数 × 修订成本）
6. **per domain**：每个域的成本（MEM vs CONC vs UB）

## 三、五个优化杠杆（按 ROI 排序）

### 杠杆 1：模型路由（最高杠杆，可降 60-75%）

**阙疑已经在做**：苦力用差模型、对抗用强模型。但可以更精细：

| 任务 | 当前模型 | 建议模型 | 理由 |
|---|---|---|---|
| 夹具设计+实测 | 强模型 | 强模型 | 需要创造力和严谨，不能降 |
| 证据卡格式化 | 强模型 | **中端模型** | 数据已就绪，只是格式化 |
| 红队盲读 | 强模型 | 强模型 | 找漏洞需要能力 |
| 红队报告撰写 | 强模型 | **中端模型** | 发现已记录，只是整理 |
| 修订（格式类） | 强模型 | **中端模型** | 改措辞/加字段不需要强推理 |
| 修订（claim 反转） | 强模型 | 强模型 | 需要重新推理 |
| 苦力（批量/机械） | 差模型 | 差模型 | 已经最优 |
| 门禁 | 机器 | 机器 | 零 token |

**Pareto 原则**：如果模型 B 在质量≥、成本≤、延迟≤三维都优于 A，A 就是被支配的，删掉。当前需要实测：中端模型做"证据卡格式化"的质量是否与强模型相当。

### 杠杆 2：前缀缓存（高杠杆，可降 30-50% 输入成本）

- 系统提示词（312/401/402）是稳定前缀，放最前面 = 缓存命中
- 312 压缩后从 ~6000→~4000 token（403 B1 已做），缓存效率更高
- 红队独立子 agent 重复加载系统提示词 = 如果平台支持前缀缓存，这部分是 0.1x 费率
- **Shopify Gisting**：系统提示词从 6000→1500 token（4x 压缩），质量不降——这是 407 L1 的极端形态

### 杠杆 3：上下文管理（高杠杆，可降 40-70%）

- **不可压缩事实清单**（A3，13 项）= 滑动窗口的核心——只保留必须的，其他递归摘要
- **递归摘要**（407 L4）= 控制历史上下文增长——每几步用便宜模型总结
- **动态工具呈现**（407 L3）= 只给相关工具，不把所有工具 schema 塞进上下文
- **证据卡按需加载** = 不把全库 56 张卡塞进上下文，用 grep/glob 只取相关的

### 杠杆 4：批处理（中杠杆，基础设施级）

- 连续批处理（vLLM/TensorRT-LLM）：GPU 利用率 60-85%，吞吐量 2-3x
- 但这是推理基础设施优化，阙疑用 API 不直接控制
- **可落地的批处理**：多颗原子的门禁可以并行跑（机器成本，不是 token 成本）
- **不可批处理**：红队必须单颗（独立性要求）

### 杠杆 5：投机解码（低杠杆，API 级不可控）

- 小模型草拟 token，大模型并行验证，2-3 token 换 1 次验证
- 这是推理引擎优化，API 用户不直接控制
- 但选择支持投机解码的模型/平台可以间接受益

## 五、质量-成本 Pareto 前沿

不是"越便宜越好"，是"在给定质量下成本最低"：

```
质量 ↑
  │     ● 强模型全流程（当前）
  │    ╱
  │   ●  路由优化（中端模型做格式化）
  │  ╱
  │ ●   前缀缓存+上下文管理
  │╱
  └──────────→ 成本 ↓
```

- 当前位置：强模型全流程，质量高但成本也高
- 第一步优化：模型路由（格式化/报告用中端模型）——质量不降，成本降 30-40%
- 第二步优化：前缀缓存+上下文管理——质量不降，成本再降 20-30%
- 第三步优化：成本追踪找到真正的热点——数据驱动，不猜

**红线**：红队和夹具设计不能降模型——这两个环节的质量直接决定系统的可信度。

| 优先级 | 项 | 预计成本降低 | 风险 |
|---|---|---|---|
| **P0** | 成本追踪工具（cost_tracker.py） | 0%（先测量） | 零 |

## 七、元结论

阙疑的成本优势是**门禁零 token**——质量保证靠机器不靠模型，这是与纯 LLM 工作流的根本区别。

但成本盲区是**没有追踪**——不知道每颗原子花了多少 token，不知道哪些环节最费，不知道优化有没有效果。

P0 不是"立刻降成本"，是"先测量"——cost_tracker.py 跑一批数据后，才能知道模型路由和上下文管理的真实 ROI。

**最反直觉的发现**：红队是成本热点（独立子 agent 重复加载上下文），但红队也是质量保证——不能砍红队，只能优化红队的上下文效率（前缀缓存+递归摘要）。
