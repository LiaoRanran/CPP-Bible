## 一、内卷式自我批判（先批判自己，再提修正案）

### 批判 1：Meadows 杠杆点诊断——我们的进化层级偏低

266–278 的架构动作按 Meadows 12 杠杆点分层：

| 杠杆点层级 | 动作 | 数量 |
|---|---|---|
| 12 数字/参数 | 调阈值、加豁免、改 warn 数 | 多 |
| 10–8 结构/反馈 | 加 gate 规则、加毒样例、debt 负债率 | 多 |
| 6 信息流 | prereq 边、knowledge_graph | 少 |
| 5 规则 | 三权分立、8 环节、修宪程序 | 中 |
| 4 自组织 | FORGE 候选仓（未落地）、sleep 阶段（未做） | 极少 |
| 2 范式 | 宪法 v1.0（五公理）、阙疑认识论 | 极少 |

**诊断**：大部分动作在 5–12 层（规则/参数），只有 277 宪法和 274 FORGE 触及 2–4 层。Meadows 的教训是「人们倾向于动最容易的（数字），而不是最有效的（范式/自组织）」——我们也在犯这个错。

**推论**：本轮修正案必须至少有两个动作在 2–4 层，否则又是「加规则」的低杠杆循环。

### 批判 2：系统原型预警——宪法自身有三个原型风险

- **目标侵蚀**：为过门禁而降低 claim 质量。证据：第五批 ALLOC-002 初版 claim「pool 元数据 32B 最省」与实测 8056B 方向相反，但初版过了 gate（gate 只查格式不查语义）。→ 修正案 1（claim 契约化）直接治。
- **转移负担**：用豁免代替修复。证据：61 条 compile 豁免，debt_ledger 有到期机制但「豁免即债」的意识不够强。→ 修正案 3 加「豁免即债，利息率>0」。
- **公地悲剧**：Examples/ 目录多 Agent 并发写。证据：Windows replay 与 WSL 预检并发写 .asm 出假 refute（40/40→16/24）。当前用「禁止并行」临时解决，根本解法是**每 Agent 独立 worktree**。→ 修正案 5 加工作区隔离纪律。

### 批判 3：概念膨胀审计——宪法自身在突破自己的上限

- 271 规定「双价值轴」，但 277 第七节写了**四条**（自律/性能/创造力/睿智）——内部不一致。
- 概念总数：五公理 + 5 个架构组件（阙疑/护栏/杠杆/锻炉/前额叶）+ 六态 + 8 环节 + 4 价值轴 + 4 横切纪律 = 32 个核心概念。
- 271 的「概念上限状态/机制各 ≤6」是为了防膨胀，但宪法自身可能在突破。
- **反身性问题**：我们在设计「防概念膨胀的系统」，但系统自身的概念在膨胀。
- → 修正案 5：价值轴收敛为两轴（自律=下限，性能=上限+效率），创造力/睿智降为性能轴的子维度；宪法加「概念审计」元规则。

## 二、宪法 v1.1 修订提案（5 个修正案）

### 修正案 1：claim 契约化（范式级，杠杆点 2）

**机制**：claim 从「写给人看的自然语言单句」变为「机器可解析的契约 + 自然语言解释」。每个原子 frontmatter 加：
- `claim_pre:` 前置条件（夹具前提，如「对象非 const」「n=1000」）
- `claim_post:` 后置条件（断言锚，如「dtor_count=1」「pool_meta=8056」）
- `claim_invariant:` 不变式（跨状态成立，如「引用计数≥0」）
- `claim:` 保留自然语言单句（供人读，是契约的解释而非替代）

**机械判据**：gate 加规则 `CLAIM-CONTRACT`——postcondition 中的每个断言必须在 evidence 卡的 actual 中有对应行；precondition 必须在夹具中有对应设置；invariant 必须在 ≥2 个状态点成立。**claim 与 actual 不一致 = BLOCK**（直接治 ALLOC-002 方向反转）。

**落点**：宪法第二节 L2「客观锚」升级为「L2 契约化客观锚」；第五节环节 3「落卡」加契约字段要求；20 颗已 verified 原子分批迁移（不强制一次完成，新原子必须用，旧原子在下次修订时补）。

**退役了谁**：无退役（是增强，不是替换）。但「claim 单句即全部」的隐含假设被退役。

**杠杆点**：2（范式）——改变了「什么是一个 claim」的根本理解。

### 修正案 2：candidates/ 仓 + 两阶段检验闸（自组织级，杠杆点 4）

**机制**：
- 阶段一（进仓，发散零门槛）：任何想法写 `candidates/<domain>/<id>.md`，frontmatter 含 `kill_criteria:`（预设什么条件下该杀）+ `press_release:`（学完后学生能做什么，写不出来不进仓）。
- 阶段二（过闸，收敛有判据）：从 candidates/ 到 draft 的检验闸用**负向判定**——默认 kill，除非 kill_criteria 全部不触发 + press_release 成立 + 有最小夹具草图。
- 候选永不冒充证据（T14 零容忍，宪法已有）。

**机械判据**：candidates/ 文件缺 kill_criteria 或 press_release = 不进仓（lint 级）；过闸时 kill_criteria 逐条核对，触发任一 = kill 并留痕（为什么杀）。

**落点**：宪法第二节「锻炉 FORGE」检验闸升级；第四节候选仓物理分仓加 frontmatter 约定；新建 `candidates/` 目录（278 确认是唯一纯缺口）。

**退役了谁**：无退役。但「检验闸通过才进 draft」的正向判定被「默认 kill」的负向判定替代。

**杠杆点**：4（自组织）——让系统能自己产生、筛选、淘汰想法，不依赖人逐个评审。

### 修正案 3：毒样例 P1–P11 + 失败模式频率追踪 + 修复模式库（规则级，杠杆点 5）

**机制**：
- 毒样例从 P1–P7 扩展到 **P1–P11**，新增 P8–P11（第五批真实案例）：
  - P8 编译期常量冒充活性观测（PERF-004 三元两支都是 0）
  - P9 一 bit 两计（LEAK-002 cycle_is_leak 与 dtor_count 同源）
  - P10 口径不统一致方向反转（ALLOC-002 pool 32B vs 8056B）
  - P11 消除与失败不可区分（LEAK-002 构造被编译器消除 vs 真泄漏）
- **失败模式频率追踪**：每批红队拦截记录类别，累计后看哪类高频，优先机械化。频率表进 `docs/failure_mode_taxonomy.md`。
- **修复模式库** `tools/repair_patterns/`：从红队历史中提炼「识别特征→修复模板→验证方法」，Writer 写完后自动扫描，命中则提示修复（Getafix 思想）。
- **修复后必须红队复审**（不是只跑 gate）——防 plausible but incorrect。

**机械判据**：P8–P11 各配最小触发夹具 + 预期 gate 拦截；修复模式库扫描结果进红队输入。

**落点**：宪法第二节 L4「毒样」扩展；第五节环节 6「修复循环」加「修复后红队复审」。

**退役了谁**：无退役。但「修复后跑 gate 即过」的隐含假设被退役。

**杠杆点**：5（规则）。

### 修正案 4：fringe.py + prerequisite 边构建 + sleep 阶段（信息流级，杠杆点 6）

**机制**：
- **prerequisite 边构建**：用 LLM 当领域专家跑 QUERY 算法（Vanderbilt 方法）——对每对原子问「掌握 B 是否必须先掌握 A」，多轮采样取一致边，人工抽检。不手工编 relations。
- **fringe.py**：复用 `learning_path.py` DAG + `prereq_topo_check.py` 拓扑校验，计算 outer fringe = verified 原子中 prereq 全满足但自身未 verified 的 = 下一步该锻造。
- **sleep 阶段**（DreamCoder 思想）：每批原子生产后，从已 verified 原子中提炼夹具骨架（结构聚类：分配计数型/析构观测型/地址判定型），更新 `templates/` 库。**当前只有 wake（生产）没有 sleep（提炼），这是「越写不快」的根因。**

**机械判据**：fringe 输出必须与 `atom_coverage_map.py` 的最薄弱域一致；sleep 阶段每批至少提炼 1 个骨架或显式声明「无新模式」。

**落点**：横切纪律「prereq 先决边」加实现路径；新建 `tools/fringe.py` + `templates/` 目录。

**退役了谁**：无退役。knowledge_graph.json 限期一个迭代激活（接 fringe）或退役。

**杠杆点**：6（信息流结构）。

### 修正案 5：概念审计 + 价值轴收敛 + 工作区隔离（元规则级，杠杆点 2）

**机制**：
- **价值轴收敛**：四轴→两轴。自律轴（下限：GAUNTLET 逃逸率/error budget/检查点续作）+ 性能轴（上限+效率：候选质量差/环节数/上下文消耗）。创造力（检验闸通过率/创新增量）和睿智（路由正确率/信息增益）降为性能轴的子维度。
- **概念审计元规则**：宪法每次修宪必须做「概念审计」——每个新概念问「不可替代吗？能合并吗？能退役吗？」，概念总数只减不增（除非退役一个再加一个）。
- **工作区隔离**：每个 Agent 独立 worktree（`git worktree`），禁止共享 Examples/ 目录并发写。Windows replay 与 WSL 预检的「禁止并行」升级为「物理隔离」。

**机械判据**：修宪提案必须含「概念审计」节（本修正案即首例）；价值轴在宪法第七节收敛为两条；worktree 隔离进 pre-push 检查。

**落点**：宪法第七节价值轴收敛；第九节修宪程序加「概念审计」步骤；第十节执行 Agent 提示词加 worktree 纪律。

**退役了谁**：「创造力轴」「睿智轴」作为独立轴退役（降为子维度）；「禁止并行」的临时纪律退役（升级为 worktree 隔离）。

**杠杆点**：2（范式）——改变了「架构自身如何演进」的元规则。

## 三、实施顺序与依赖

```
修正案 1（claim 契约化）────┐
                              ├─→ 修正案 3（毒样例 P8–P11，依赖契约化检测）
修正案 2（candidates/ 仓）───┘  （独立，可并行）
                              
修正案 4（fringe + sleep）──── 独立，依赖 prerequisite 边构建（LLM 采样，可并行）

修正案 5（概念审计+价值轴）─── 元规则，最先做（为后续修订提供纪律）
```

**建议顺序**：
1. **修正案 5 先做**（元规则，为后续修订提供概念审计纪律，且价值轴收敛是纯文本改动零风险）
2. **修正案 1 + 2 并行**（claim 契约化是基础结构变更，candidates/ 仓独立）
3. **修正案 3**（在契约化基础上，毒样例检测更强）
4. **修正案 4**（prerequisite 边构建需要时间，可后台进行）

**还债并行**：当前债务率 24%（warn 8/规则 33），在实施修正案的同时，按利息率/RICE 还债——优先还 ATOM-REL-TARGET（利息>0，每批新原子都受影响），EV-SERVES-EXIST（利息=0，原子化时自动清）。

## 四、GAUNTLET 复测要求（修宪程序第五步）

每个修正案生效后必须：
- GAUNTLET 逃逸率不升高（≤20%）
- 全监督档逃逸 =0
- 新增毒样例 P8–P11 必须能拦截第五批的真实错误（回归测试）
- claim 契约化后，第五批 ALLOC-002 的旧 claim（方向反转版）必须被 CLAIM-CONTRACT 规则 BLOCK（验证治了病）
- candidates/ 仓的「默认 kill」必须能杀掉一个「press_release 写不出来」的候选（验证负向判定生效）

## 五、给用户的话

这轮内卷式思考最有价值的不是 5 个修正案，而是三个自我批判：

1. **我们的进化杠杆层级偏低**——大部分在「加规则」，本轮刻意把 claim 契约化做成范式级（点 2）、candidates/ 做成自组织级（点 4），而不是又加几条 gate 规则。
2. **宪法自身在突破自己的概念上限**——四价值轴 vs 双价值轴的不一致，是「设计防膨胀系统但自身膨胀」的反身性问题。修正案 5 是元规则级修复。
3. **当前只有 wake 没有 sleep**——每批原子从零写，没有从已 verified 原子提炼可复用模式。DreamCoder 的 wake-sleep 告诉我们「库自己写自己」才是越写越快的关键。

**下一步**：本文是修宪提案（第二步）。按宪法第九节，需要独立红队批判（第三步）才能生效。你可以：
- **A. 直接拍板**：5 个修正案全部通过，我开始实施（先修正案 5，再 1+2 并行）。
- **B. 先红队批判**：我模拟独立红队过一遍 5 个修正案（含「这是不是又在加概念」），出批判报告后你再定。
- **C. 调整修正案**：哪个修正案你觉得不对/不够/多余，指出来我改。

我倾向 **B**——宪法是最高事实源，修宪必须过红队，而且 5 个修正案里肯定有「看起来好但实际有坑」的（比如 claim 契约化会不会增加 Writer 负担到弱模型干不动？candidates/ 的 press_release 会不会变成新的形式主义？）。红队过一遍更稳。你定。
