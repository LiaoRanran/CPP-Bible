# 358_「阙疑」架构v2.0_从质量管理系统到认知-生产-进化系统

> 2026-09-12 · 架构v2.0 · v1.1的根本性升级（不是修补，是增加缺失的认知维度）
> 核心认知：v1.x解决"怎么保证知识是对的"，v2.0解决"怎么发现新知识/理解知识/进化知识"

---

## 一、v1.x的根本局限：它是"工厂"不是"科学家"

v1.x的隐喻是**工厂**：原料（选题）→流水线（8步生产）→质检（红队/gate）→出厂（verified）。

工厂能保证"不出错"，但不能：
- 发现没人问过的新问题
- 从矛盾数据中产生新假设
- 从1000个知识点中蒸馏出10条原理
- 知道自己"不知道什么"
- 把MEM域的教训自动迁移到CONC域
- 在范式层面发生革命

真正的超强智能系统的隐喻是**科学家共同体**：
- 有人观察异常（现象层）
- 有人提出假设（溯因推理）
- 有人设计实验（判别性实验）
- 有人分析数据（统计/因果）
- 有人综合理论（知识压缩）
- 有人批评证伪（红队）
- 有人教学传播（教学转化）
- 有人审视"我们是不是在用错误的框架"（范式反思/元认知）

v2.0要建的是这个**科学家共同体的认知架构**，工厂（v1.x的质量保证）降级为其中的"实验验证"子系统。

## 三、新增层⑧：认知层——科学发现的形式化

### 3.1 为什么需要认知层

v1.x的生产流程是"给定选题→生产原子"，但**选题本身是怎么来的？**当前靠人（监工）指定。真正的智能系统应该能自己发现"下一个最有价值的问题"。

### 3.2 科学认知循环（OODA的科学方法版）

```
        ┌─────────────────────────────────────────┐
        ▼                                         │
  ① 观察现象                              ⑥ 证伪/确证
  （实验数据/异常/矛盾/                              │
    跨域类比/教学疑问）                      ⑤ 推演推论
        │                                  （从假设推出可观测预言）
        ▼                                         │
  ② 溯因推理（Abduction）                          │
  （什么假设能解释这个异常？）              ④ 设计判别实验
        │                                  （能区分竞争假设的实验）
        ▼                                         │
  ③ 生成竞争假设（≥2个）                           │
  （假设A vs 假设B vs 假设C）──────────────────────┘
        │
        ▼
  （实验结果）→ 假设存活/死亡 → 进入⑦知识进化层
```

**关键：溯因推理（Abduction）是v1.x完全缺失的**
- 演绎（Deduction）：规则→结果（"所有屏障阻止重排，X是屏障，所以X阻止重排"）
- 归纳（Induction）：样本→规则（"测了10次都这样，所以规则是这样"）
- **溯因（Abduction）：异常→最可能的解释**（"LSan没报泄漏，但析构计数是0——什么假设能同时解释这两点？"）

CONC-001的"屏障拦不住消除"被推翻、LEAK-002的"加volatile计数器让LSan从零报告变报告"——这些最有价值的发现都是溯因推理，但当前是Agent偶然做出来的，不是流程强制的。

### 3.3 认知层的强制产出物

每次"发现型"生产（区别于"计划型"生产），必须记录：

```yaml
cognition_record:
  anomaly: "观察到的异常/矛盾是什么"           # 现象
  competing_hypotheses:                        # ≥2个竞争假设
    - h1: "假设A（含机制解释）"
    - h2: "假设B（含机制解释）"
  discriminating_experiment: "什么实验能区分A和B"  # 判别实验
  prediction_h1: "如果A对，应该观测到什么"
  prediction_h2: "如果B对，应该观测到什么"
  result: "实际观测到什么，哪个假设存活"
  alternative_explanations: "还有什么没排除的解释"  # 红队重点
```

这比v1.x的"claim+证据"多了**假设竞争**和**判别实验设计**——科学发现的核心不是"证明我是对的"，而是"我的假设在竞争中存活下来"。

### 3.4 问题驱动机制（异常从哪来）

系统主动产生研究问题的6个来源：

| 来源 | 机制 | 示例（已发生的） |
|---|---|---|
| 实验异常 | 实测结果与预期/文档不符 | gcc-14升版致6卡refute |
| 原子矛盾 | 两颗verified原子的claim表面冲突 | PERF-003双平台排序相反 |
| 知识边界 | 图谱中的孤立区域/缺失关系 | CONC域零开采 |
| 教学疑问 | 初学者常见困惑（误解库高频触发词） | "delete放函数尾就够" |
| 跨域类比 | 其他域的模式可能在本域重现 | MEM的自证断言→CONC也可能有 |
| 工具反例 | 工具漏报/误报暴露的认知盲区 | LSan可达性假阴性 |

**研究优先级排序**（主动学习）：
- 信息量：这个问题的答案能区分多少个竞争假设？
- 影响面：这个问题关联多少颗已有原子？
- 可行性：现有工具能否验证？
- 新颖性：是填补空白还是验证已知？

## 四、新增层⑦：知识进化层——从原子到范式

### 4.1 知识的四个层级（当前只有第2级）

| 层级 | 定义 | 当前状态 | 例子 |
|---|---|---|---|
| 概念（Concept） | 术语及其指称 | M1_ontology有 | RAII、内存序、缓存行 |
| 命题（Proposition） | 可证伪的陈述 | ✅ 原子=命题 | "屏障在循环体内阻止消除" |
| 理论（Theory） | 一组命题构成的解释体系 | ❌ 缺失 | "编译器消除模型"（消除/重排/提升的统一解释） |
| 范式（Paradigm） | 看待整个领域的框架 | ❌ 缺失 | "C++内存模型的形式化视角"vs"工程经验视角" |

**当前20颗原子是20个孤立的命题**——它们没有被综合成理论。学生学到的是20个"知识点"，不是"一个能预测新情况的心智模型"。

### 4.2 理论综合（知识压缩/蒸馏）

**机制**：当一个域的原子数达到阈值（如≥10颗），触发"理论综合"：
1. 聚类：哪些原子共同解释同一现象？（如消除/重排/屏障/原子类型→"编译器与硬件的重排模型"）
2. 抽象：从具体命题中提取更一般的原理
3. 公理化：原理之间的推导关系（哪些是公理，哪些是定理）
4. 压缩检验：理论能否预测出"还没生产的原子应该说什么"？

**压缩的判据**（防止"错误压缩"）：
- 覆盖：理论能解释该域所有verified原子（不能有反例）
- 预测：理论能预测未验证的情况（预测被后续实验确认）
- 简洁：理论的公理数 < 命题数（否则没有压缩）
- 独立可证伪：理论本身有可被推翻的预言

### 4.3 范式革命（库恩模型）

```
常规科学（在范式内生产原子）
    │
    ▼
异常积累（发现范式解释不了的原子）──v1.x没有这个检测
    │
    ▼
危机（异常数量/重要性超过阈值）
    │
    ▼
范式竞争（旧范式 vs 新范式，用判别实验裁决）
    │
    ▼
范式转换（新范式解释旧范式的所有成功 + 解释异常）
```

**对「阙疑」的意义**：当一组verified原子与当前教学框架（Book的表述）持续冲突时，不是"修原子"，而是"Book的范式需要更新"。LEAK系列对"ASan能检测循环引用泄漏"的修正，就是一次微型范式革命。

### 4.4 跨域迁移机制

**结构化迁移**（不再靠"红队提示词里写教训"）：

每个"教训"抽象为**模式（Pattern）**：
```yaml
pattern:
  id: PAT-SELF-SATISFIED
  name: 自证断言
  abstract: "验证工具使用了被测对象自身提供的定义/函数，使断言恒真"
  first_observed: {domain: mem, atom: UNIQUE-002}
  domain_instances: [mem, conc]        # 在哪些域出现过
  detection_rule: "断言目标是夹具自定义符号，且只做存在性匹配"
  generalized_lesson: "验证路径必须独立于被验证对象"
  cross_domain_checklist: "在新域生产时，检查该域是否存在同类自证结构"
```

新域开工时，自动运行"跨域模式检查"：其他域的PAT在本域是否可能重现？

### 4.5 拉卡托斯"科学研究纲领"的应用

每个理论有：
- **硬核（hard core）**：理论的核心假设，不轻易放弃（如"编译器优化保持可观测行为等价"）
- **保护带（protective belt）**：辅助假设，异常出现时先修改保护带（如"ASan没报≠没泄漏"是保护带假设）
- **启发法（heuristic）**：正面启发法（该做什么实验）/反面启发法（不要质疑什么）

这防止"一遇到反例就推翻理论"或"永远不承认理论错误"两种极端。

## 五、机制层升级：多认知角色网络

### 5.1 v1.x的三角色不够

Writer（生产）/红队（证伪）/Gatekeeper（规则）覆盖了"建设-批判-裁判"，但科学认知需要更细的分工：

| 认知角色 | 思维方式 | 职责 | 对应科学哲学 |
|---|---|---|---|
| 观察员（Observer） | 现象敏感 | 发现异常/矛盾/模式 | 经验主义 |
| 溯因者（Abducer） | 发散/类比 | 为异常生成≥2个竞争假设 | 皮尔斯溯因 |
| 实验师（Experimenter） | 严谨/控制变量 | 设计判别实验+夹具 | 实验科学 |
| 分析师（Analyst） | 统计/因果 | 评估证据强度/排除混淆 | 统计推断 |
| 综合者（Synthesizer） | 抽象/压缩 | 命题→理论→范式 | 理论构建 |
| 批评家（Critic/红队） | 对抗/证伪 | 找替代解释/攻击claim | 波普尔证伪 |
| 教师（Teacher） | 具象/共情 | 理论→直觉/误解/层级 | 教育学 |
| 元认知监督（Meta） | 反思/全局 | 监控认知过程/知识边界/范式健康 | 元认知 |

### 5.2 角色协作流（认知流水线）

```
观察员 → 溯因者 → [假设A/B/C]
                      │
                      ▼
              实验师设计判别实验
                      │
                      ▼
              分析师评估（哪个假设存活）
                      │
              ┌───────┴───────┐
              ▼               ▼
          综合者建理论    批评家攻击（全程并行）
              │               │
              └───────┬───────┘
                      ▼
              教师转化为教学原子
                      │
                      ▼
              元认知监督（全程）：
              认知过程有没有跳过步骤？
              竞争假设是否真的被判别？
              知识边界地图更新了吗？
```

### 5.3 角色与模型的匹配（异质性）

不同认知角色适合不同模型特性：
- 溯因者/综合者：强推理、强类比能力的模型
- 批评家：与生产角色**不同模型**（独立性，v1.1已识别）
- 实验师/分析师：强代码/强数值能力
- 教师：强表达/共情能力
- 元认知：最强模型（需要全局视角）

## 六、教学层增强：理解验证（不只是"claim对不对"）

### 6.1 "verified"只验证了正确性，没验证"理解"

理解的四个层次（SOLO分类法的改造）：

| 层次 | 标志 | 验证方式 |
|---|---|---|
| 能解释（Explain） | 用自己的话讲清机制 | 直觉段/类比段质量评审 |
| 能预测（Predict） | 给出没见过的场景，预测结果 | 预测题：新代码片段→预测编译器行为 |
| 能迁移（Transfer） | 把原理用到新域/新问题 | 跨域迁移题（MEM原理→CONC场景） |
| 能创造（Create） | 提出新问题/新假设/新实验 | 开放题：基于该原子提出一个值得研究的问题 |

### 6.2 每颗原子的"理解度"分级

- L0：verified（命题正确）
- L1：+能解释（有高质量直觉/类比）
- L2：+能预测（有预测题且答案可验证）
- L3：+能迁移（有跨域连接/迁移题）
- L4：+能创造（该原子启发了新问题/新原子）

当前大部分原子在L0-L1，极少数到L2。这给"教学层建设"提供了明确的升级路径。

## 七、元认知层：系统对自己认知的认知

### 7.1 知识边界地图（Epistemic Boundary Map）

系统持续维护：
- **已知已证**：verified原子覆盖的区域
- **已知未知**：已识别但未生产的问题（backlog，按3.4优先级排序）
- **未知未知**：通过"探测性实验"发现的盲区（故意测试边界条件）
- **错误高发区**：哪些域/哪类claim历史上最容易出错

### 7.2 错误模式自分析

定期（每N批）自动分析：
- 红队阻断的聚类：最近的错误属于哪些PAT？
- 新型错误：有没有出现现有PAT都不覆盖的错误？→ 生成新PAT
- 规则有效性：哪些规则从没触发过（过窄/过时）？哪些频繁误报？
- 认知过程审计：有没有"跳过竞争假设""判别实验不判别"的情况？

### 7.3 学习策略的自我进化（三层学习）

- 单环：修对这颗原子（v1.x已有）
- 双环：修规则/流程（v1.x已有）
- **三环（v2.0新增）：修"认知方式"本身**——我们选择研究问题的策略对不对？我们的假设生成是不是太保守？我们的理论综合是不是太早/太晚？

## 八、DIKW的补全：从知识到智慧

```
Data    ：夹具的原始输出（.out/.asm的字节）
Information：actual里的结构化读数（size=16, dtor=0）
Knowledge ：原子的claim（"删除器是unique_ptr类型的一部分"）  ← v1.x在这里
Understanding：理论（"类型系统承载编译期信息，类型擦除把信息移到运行时控制块"）  ← v2.0
Wisdom    ：范式/判断力（"什么时候该用类型安全，什么时候该用类型擦除"）  ← v2.0
```

v1.x止步于Knowledge，v2.0要走到Understanding和Wisdom——这正是"超强智能"和"知识库"的区别。

## 九、v2.0的实施哲学：反脆弱而非只是严谨

v1.x追求"不出错"（robust，坚固）。v2.0追求**反脆弱（antifragile）**：
- 坚固：错误不发生（不可能，且会扼杀探索）
- 反脆弱：**错误必然发生，但每次错误都让系统变强**（错误→PAT→规则→毒样例→跨域迁移→理论修正）

v1.x已经有反脆弱的种子（红队→规则沉淀），v2.0把它系统化：
- 每个错误不只是"修掉"，而是"榨取最大认知价值"（它暴露了什么认知盲区？什么理论需要修正？什么域可能有同类问题？）
- 保留"探索的自由"：认知层允许产生"后来被证伪的假设"（科学本来如此），但用v1.x的质量层保证**进入verified的结论是可靠的**
- 两层分离：**发现的语境（context of discovery）可以狂野，辩护的语境（context of justification）必须严谨**——这是科学哲学的核心区分，v1.x只有后者。

## 十、v2.0与v1.x的关系

- v1.x的六层架构**全部保留**，成为v2.0九层架构的下层（①-⑥）
- v1.x的工厂流水线成为"实验验证子系统"，服务于认知层的"判别实验"环节
- v1.x的对抗性设计（v1.1）成为批评家角色的方法论
- v2.0新增的⑦认知层⑧知识进化层⑨元认知层，是"科学家"的大脑
- **不是推倒重来，是给工厂装上科学家的大脑**

## 核心结论

v1.x是一个优秀的**知识质量保证系统**（它的严谨性/对抗性/可追溯性已经超过大多数同类项目）。

但"超强智能系统"需要的不只是"不出错的知识生产"，而是：
1. **能发现**（认知层：异常→溯因→竞争假设→判别实验）
2. **能理解**（知识进化层：命题→理论→范式，L0-L4理解度）
3. **能进化**（范式革命+跨域迁移+反脆弱）
4. **能自省**（元认知：知识边界+错误自分析+三环学习）

v2.0的本质：**让系统从"按规范生产正确命题的工厂"，进化为"能做科学发现、能构建理论、能知道自己无知的科学家共同体"——而工厂（v1.x）成为这个共同体的实验室。**
