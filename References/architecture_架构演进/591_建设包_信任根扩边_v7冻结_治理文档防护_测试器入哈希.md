### 2.2 实现：governance_doc_guard.py
创建 `tools/governance_doc_guard.py`（纯标准库，不引入新依赖），包含：

**(a) manifest 机制**
- `MANIFEST_PATH = Path("data/governance_docs_manifest.json")`
- manifest 结构：`{ "generated_at": "<iso时间>", "git_commit": "<short sha>", "files": [ { "path": "References/.../590_....md", "sha256": "<64位>", "size": <int> } ] }`
- `generate_manifest()`：扫描 `References/architecture_架构演进/` 下所有 `.md`（含子目录），计算 sha256，按路径排序输出。
- `verify_manifest()`：重新扫描计算，与 manifest 逐条比对；不一致的文件列出（新增/删除/内容变更）；全部一致返回 (True, [])，不一致返回 (False, diff_list)。
- `update_manifest()`：重新生成并写入；打印变更清单（哪些文件变了）；需 `--force` 显式标志才执行（防误调用覆盖）。

**(b) 弱化指令扫描器**
- `scan_weakening_instructions()`：对 manifest 中的每个 .md 文件，扫描是否包含以下模式（正则，大小写不敏感）：
  - "降为 warn" / "降级为 warn" / "block 改 warn" / "warn 起步"（注意："warn 起步"是本仓纪律用语，需区分上下文——只在"将某规则/某卡降为 warn"语境报警，单独出现不报警）
  - "豁免" + "毒样例" / "豁免" + "规则" / "跳过" + "门禁" / "跳过" + "判决测试"
  - "删除" + "闸" / "移除" + "校验" / "不再校验" / "关闭" + "自检"
  - "降低阈值" / "放宽" + "条件" / "扩大" + "豁免"
- 对每个命中，输出：文件路径 / 行号 / 命中文本 / 风险等级（high=直接指令弱化判决 / medium=描述性提及可能弱化 / low=纪律用语上下文）。
- 产出 `data/governance_weakening_scan.json`：`{ "scan_time": "...", "findings": [ ... ], "summary": { "high": N, "medium": N, "low": N } }`。
- **边界诚实**：这是模式匹配，不是语义理解；会有误报（如本投喂词本身就在讨论"降为 warn"这个词）。扫描结果是"人审清单"，不是自动判决。所有命中都标 `needs_human_review: true`。

**(c) CLI 入口**
- `python tools/governance_doc_guard.py verify`：校验 manifest，exit 0=一致，exit 1=不一致（打印 diff）。
- `python tools/governance_doc_guard.py update --force`：更新 manifest，exit 0。
- `python tools/governance_doc_guard.py scan`：扫描弱化指令，输出 JSON，exit 0。
- `python tools/governance_doc_guard.py preflight`：verify + scan 组合，verify 不一致 exit 1，scan 有 high 级命中 exit 2（打印清单），全部干净 exit 0。

## 任务 3：测试器配置入哈希面（A2 防御）

### 3.1 问题
590 发现：tests/conftest.py 在 pytest 收集前执行，可通过 `pytest_runtest_makereport` 钩子把 failed 改判 passed，但 conftest 不在 CORE_TOOLS 中，无完整性校验。篡改 conftest 可让"pytest 全绿"而判决被全面抽空。

### 3.2 实现（保守方案，不改变判决逻辑）
- 在 `tools/tool_integrity.py` 中新增 `TEST_CONFIG_TOOLS` 清单（与 CORE_TOOLS 并列，不合并）：
  - `tests/conftest.py`
  - `pyproject.toml`（判决配置部分：pytest markers / addopts / ruff select）
  - （如果有其他 pytest 配置文件如 setup.cfg / tox.ini，也列入，但本仓确认只有 pyproject.toml）
- 新增 `verify_test_config()` 函数：对 TEST_CONFIG_TOOLS 计算 sha256，与 `.tool_checksums` 中的 test_config 节比对。
- 新增 `--check-test-config` CLI 标志：只校验测试配置，exit 0=一致，exit 1=不一致。
- 在 `enforce()` 中**不**自动调用 test_config 校验（因为 enforce() 是 gate/replay/poison 三入口的首句闸，而这三个入口不跑 pytest，conftest 篡改不影响它们）。test_config 校验只在 pytest 启动时触发。
- 在 `tests/conftest.py` 顶部新增 pytest 启动自检钩子：
  ```python
  def pytest_configure(config):
      # 591: 测试器配置完整性自检
      import subprocess, sys
      r = subprocess.run(
          [sys.executable, "tools/tool_integrity.py", "--check-test-config"],
          capture_output=True, text=True, cwd=str(Path(__file__).parent.parent)
      )
      if r.returncode != 0:
          pytest.exit(f"测试器配置完整性校验失败（conftest/pyproject 被篡改）:\n{r.stderr}", returncode=2)
  ```
  - **注意**：这个钩子本身在 conftest.py 里，如果 conftest 被篡改，攻击者可以删掉这个钩子。所以这是"纵深防御"而非"根治"——它能防住"只改钩子内容不改文件哈希"的攻击，但防不住"改钩子+重签"的攻击。根治需要 conftest 入 CORE_TOOLS 且 enforce() 在 pytest 之外独立校验，但那会改变架构。如实登记这个限制。
- 更可靠的方案（备选，如果上面的钩子被认为太弱）：在 `pyproject.toml` 的 `[tool.pytest.ini_options]` 里加 `addopts = --confcutdir=.` 并配合一个独立的 `.pytest_guard.py` 启动脚本——但这会改变 pytest 启动方式，风险较大。**优先采用上面的 conftest 钩子方案**，如果苦力评估后认为不够，停在任务边界报告，不擅自改架构。
