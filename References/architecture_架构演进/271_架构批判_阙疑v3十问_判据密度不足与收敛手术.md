# 架构批判：阙疑 v3 的十问 —— 粗糙不在概念少，在判据密度不足

> 2026-09-12。第四轮架构迭代，但这一轮**不是升级，是审判**：怀疑的靶子是自己上一轮的 v3「阙疑/EPOCHE」。用户判定「还是过于粗糙」。我认同，并要用 v3 自己的标准来审 v3——它宣称要「判据密度」「可废止」「反脆弱」，那么它自己做到了吗？
>
> 总判先给：**v3 的粗糙不是缺概念，恰恰是概念过剩、判据稀缺。** 它引入了一堆漂亮的算子名（溯因、判别实验、融贯、硬核/保护带、contending），却几乎没有给任何一个配「可计算的判据」。概念密度远高于算法密度，机制多停在隐喻层。这一轮的产出是：十问 → 六大致命 → 收敛手术 → v3.1 骨架。

---

## 〇、方法论：用 v3 自己的尺子量 v3

v3 立了三条元规则：①每个新算子必须由 ≥1 次真实事故证明增量（否则不建）；②没测的显式留白，不假装测过；③一切结论可被新证据废止。

那么对 v3 本身问三句：
- 它的六大机制，每一个都达到了「可计算判据」的最低标准吗？（没有）
- 它声称「不推翻 v1/v2」，那么与 v1/v2 的接口是整合的还是叠床架屋的？（叠床架屋）
- 它批判 v2「观察负载理论」，
- 自己有没有偷偷依赖它批判过的东西？（有——oracle 回来了）

以下十问，按杀伤力排序。

---

## 一、六大致命批判

### 致命一：oracle 问题回魂（v3 最大的自相矛盾）

**批判对象**：机制 3「判别实验合成引擎」里的 property-based testing（QuickCheck/Hypothesis）。

v2 之所以能声称「无人自纠错」，靠的是 mutation testing 绕开了 oracle：变异体是**已知错误**，判据是「是否有客观源与它冲突」——这是机械可判的关系。

v3 为了治 Ashby 必要多样性，引入 QuickCheck 式生成性探索：「声明性质，自动枚举维度找反例」。但 QuickCheck 的 oracle 是**性质断言本身**。在软件层，性质是程序员写的、判定是机械的（测试红/绿）；在知识层：
- 「性质」由 LLM 起草（如「任何普适结论必须在版本×编译器×优化级上有边界」）；
- 「找到的这个反例是否真的反驳性质」也由 LLM 判定。

**oracle 回来了，而且比 v2 批判过的 AFL fuzzing 更隐蔽——它披着「生成性探索」的外衣，实际是让 LLM 当裁判的旧病复发。** v2 在 268 里刚把「LLM 当裁判」钉在耻辱柱上，v3 在机制 3 里又把它请回来了，还没承认。

**项目实证**：PERF-004 的断言锚三次收敛（v1 时序数据入断言 → run_mismatch；v2 对比结论入断言 → 基数不一致；v3 只锚常量+活性对照）。这个教训正是「语义层的『反例』无法被机器独立判定」——最后是**人**判断哪个才是真反例。

**收敛手术**：
1. 明确废除「性质探索覆盖未知的未知」的说法——这是做不到的，且与阙疑自己矛盾（未知就是未知，别假装能自动探索）。
2. 机制 3 降级为「已知算子库的枚举」：判别实验 = 在**预先登记的夹具变换算子**（noinline/拆 TU/换平台/换 sanitizer/活性对照…）上做有限组合，结果一律由客观源（编译器/运行/sanitizer/标准原文）判定，LLM 只负责「提议假设与算子」、不负责「判定结果」。
3. 「未知的未知」诚实划回未知地图，由阙疑承担——这才是这个名词该站的位置。

### 致命二：迪昂-蒯因滑坡——信任基线未定义

**批判对象**：机制 1「证据背景假设显式化」与整体论立场。

v3 正确指出「观察负载理论、客观源会骗人」（LSan 假阴性、-O2 内联、MinGW DLL）。但把「工具可能错」升格为「每张证据卡必须声明背景假设」后，出现了两个工程问题：

1. **无限回归**：证据依赖假设，假设也是 claim，也依赖假设……回归链在哪停？v3 没说。如果每层都问「这个假设可信吗」，系统将瘫痪在怀疑里——这正是迪昂-蒯因整体论著名的实践难题：**彻底整体论 = 无可行动**。
2. **信任基线缺失**：项目实证是——客观源（编译器实测、标准原文）**绝大多数时候是对的**，LSan 假阴性是例外不是常态。工程上需要的不是「怀疑一切」，而是**一张已知盲区表 + 显式怀疑触发条件**：什么情况才值得怀疑工具？（工具版本变更、与另一独立工具冲突、命中已知盲区、结果违反强先验。）

**收敛手术**：
1. 定义**信任基线协议**：默认可信源清单（gcc/clang 实测、标准原文、sanitizer 于已校准场景），外加「怀疑触发条件」四条（见上），触发后降级为 instrument-suspect，但**不瘫痪主线**。
2. **假设链只保留一层**：证据卡只声明「直接依赖的背景假设」，不再递归追问假设的假设。递归是认识论的自嗨，不是工程。
3. 阙疑的对象修正：**阙的是「未验证的主张」，不是「一切」**。对默认可信基线，阙疑必须付出明确的怀疑成本（写触发记录），否则系统会变成什么都信不起来的空转机器。

### 致命三：概念债务与接口未整合（工程上最实际的粗糙）

**批判对象**：v3 整体结构。

三轮下来概念清单：v1 七层 + v2 的 L1.5 证成层、anchored/cross-checked/disputed、mutation score、golden_lock + v3 的探究网络、contending、硬核/保护带、minority report、判别实验、混沌演练。**每一轮都在加概念，没有一轮宣布旧概念退役。**

于是出现无法回答的接口问题：
- v2 的 `disputed` 与 v3 的 `open-inquiry` 是替换还是并存？冲突到底先走哪个？
- v2 的 `anchored/cross-checked` 在 v3 的状态机里怎么映射？`contending` 是第四种状态还是 `disputed` 的改名？
- v2 的 `mutation score` 在 v3 的「解释融贯度」面前还有位置吗？两者什么关系？
- 黄金锁、typestate CLI（v1 落地）与探究网络怎么联动？

**v3 文档没有回答任何一个。** 这是「层叠而不整合」——架构每升一版，概念债务增加一截，最终文档变成哲学名词展览馆，执行 Agent 不知道该按哪套跑。

**收敛手术**：立**架构收敛契约**（v3.1 起强制执行）：
1. 每轮升级必须附一张「概念保留/合并/退役表」：新概念进来时，显式声明它替代了哪个旧概念、旧概念是退役还是降级为字段。
2. 状态机**只有一个**：v2 的信任分级 + v3 的探究态**合并**（见第四节 v3.1 状态机），不允许两套并存。
3. 概念总数设上限（比如状态 ≤ 6、机制 ≤ 6），超了必须先退役再新增——用 Ashby 的反面约束自己：**概念也要受必要多样性约束，但不是越多越好。**

### 致命四：「共同体」是假独立——同构演员

**批判对象**：v3 的「人工科学共同体」隐喻。

真实科学共同体的独立性来自**利益、方法、仪器的异质性**：不同实验室用不同的设备、不同的理论倾向、不同的动机去检验同一主张。

v3 的 Writer/RedTeam/Gatekeeper 呢？**它们是同一个底层模型家族的三个角色**，共享同一套 LLM 盲区；「异构 LLM 盲审」我在 269 已经承认相关性不为零，v3 没有解决，只是把它藏进「共同体」这个有光环的词里了。让同一个大脑扮演三个角色再让他们互相审，不是三角验证，是独角戏。

**收敛手术**：
1. **独立性的定义改成工具链级**：真正的「独立检验者」是编译器（gcc vs clang）、标准库（libstdc++ vs libc++）、sanitizer、标准原文、不同优化级——它们才是不同「仪器」。LLM 角色一律定位为「定位/提议」，永不当「裁决」（与致命一修法同构）。
2. 删除「异构 LLM 共识」作为证据等级的说法，改为「异构 LLM 定位交叉」——只提高引文/实验的定位召回，不参与真值判断。
3. 文档诚实声明：**本系统是「多源证据网」，不是「多个头脑」**。共同体是修辞，证据网是机制，别用修辞掩盖机制缺失。

### 致命五：认知转化后端的工程落差（愿景最大、准备最少）

**批判对象**：机制 6「误解驱动的认知转化」+ Feynman 门。

这是 v3 里最动人的部分，也是最空的部分：
1. **无输入管道**：CPP-Bible 目前没有学习者数据。误解库只有「专家预设的误解」（MIS-MEM-013..029），没有一条来自真实读者的错误答案。「诊断朴素心智模型」诊断谁？数据从哪来？v3 没说。
2. **教学法有争议**：「制造认知冲突」对一部分学习者有效，对另一部分产生挫败与习得性无助（认知负荷过载）；「更优解释」的判断标准是什么？「Feynman 门」谁能当 Feynman？判据是什么？都没有。
3. 用「预测卡点」定义品味，是把教学洞察降维成数据匹配——真正的好教材品味是「**什么值得教**」的价值判断，不是「读者会卡在哪」的预测问题。v3 优化了「怎么教」，没碰「教什么」。

**收敛手术**：
1. Phase F **从工程承诺降级为研究议程**，明确标注「需要真实学习者小样本实证（n≥20）后才可宣称有效」，禁止用「系统自认为讲清楚了」自嗨（v3 自己立的规则，v3 没执行）。
2. Feynman 门改为**可操作版本**：「目标读者（按已知误解分布采样）能否独立重述并应用」——留待真实数据，不虚构判据。
3. 认知冲突四步只用于**已有真实误解证据**的主题；专家预设误解一律标「候选」，未经学习者验证不得驱动教学路径。

### 致命六：哲学自洽——客观锚的地位含糊

**批判对象**：v3 的「融贯度选择」+「客观锚不可被架空」。

v3 一边说「真理在竞争假设与证据的融贯中涌现」（IBE），一边说「客观锚节点拥有不可被假设互证架空的特殊地位」。这两个立场打架：
- 如果融贯是真理标准，客观锚的优先权从何而来？「不可被架空」难道不是一种预先钦定的中立观察——正是 v3 批判 v2 的「中立观察教条」？
- 如果客观锚有优先权，那融贯计算还有什么用？遇到冲突时听谁的，判据是什么？

v3 没有回答，这是哲学层的自相矛盾，会直接污染实现层的冲突处理规则。

**收敛手术**：明确声明——**客观锚是「实用基线」而非「认识论特权」**：它可信不是因为哲学上被证明（没有证明），而是因为工程上我们**协议约定**优先信它，并且它的失效模式可以被审计（已知盲区表 + 版本追踪 + 与另一独立源交叉时自动降权）。融贯用于「客观锚沉默时」的假设排序，不用于否决客观锚。这样两个立场就分层了：**客观锚定真值下限，融贯管解释排序**，互不越权。

## 二、两个次级批判（同样真，但可低成本修）

### 次级一：contending 状态语义不清，悬置可能沦为懒惰的借口

「判别实验无法区分 → 保持 contending」——但「无法区分」由谁判定？没有客观触发条件，contending 就会变成「写不出来就悬置」的遮羞布，恰好背叛阙疑的本意（阙疑是诚实的纪律，不是懒惰的豁免）。

**修法**：contending 必须有**客观触发**：存在 ≥2 个活假设 且 已提议/已执行的判别实验无法在它们之间产生决定性结果（结果 X 与 ¬X 都未出现，或两个假设对结果的预测相同）。并带**退出条件**：有新判别实验提案 → 执行 → 收敛；否则定期复审。悬置必须是「有实验日程的悬置」，不是「无限期的悬置」。

### 次级二：重演验收的判据仍是人判——黑盒又回来了

v3 用「系统重演 LEAK/B/gcc-14 事故」做验收，但「重演成功」谁说了算？如果还是人看结果，那这个验收就不可复现。

**修法**：重演判据**半自动化**——机器计算「系统输出假设排序」与「事实结论」的匹配度（如覆盖度/秩相关），人只复核边界案例。这样验收可以从「监工看一眼」变成「每轮自动跑、数字说话」。

## 三、收敛手术：v3.1 骨架（阙疑收敛版）

不是新版本号自嗨，而是把十问的修法**全部落成一张可执行的收敛表**。

### 3.1 概念保留/合并/退役表（架构收敛契约，v3.1 强制）

| 概念 | 处置 | 理由 |
|---|---|---|
| 七层管线（v1） | 保留 | 骨架仍成立 |
| 形式 Pass 六组（v1） | 保留 | 拦形式错误，职责清晰 |
| typestate 状态机（v1） | **合并进 v3.1 单一状态机** | 不再单独存在 |
| L1.5 证成层（v2） | **降级为「探究网络的一个算子集」** | 不单独成层 |
| anchored / cross-checked（v2） | 保留为**信任度字段** | 不再是状态 |
| disputed（v2） | **合并进 v3.1 的 open-inquiry** | 冲突一律先进溯因，不再直接否决 |
| mutation score（v2） | 保留，并入「证据网强度」指标 | 仍是唯一可计算的语义质量量 |
| 探究网络（v3） | 保留为**唯一内核** | 所有活动=图上算子 |
| contending（v3） | 保留，但需客观触发+退出条件 | 见次级批判一 |
| property-based 性质探索（v3） | **退役** | oracle 回魂，见致命一 |
| 硬核/保护带（v3） | 保留为**字段** | 冲突修正优先级 |
| minority report（v3） | 保留为**档案** | 教学与历史价值 |
| 混沌演练（v3） | 保留，但注入源需 held-out | 见 268 Goodhart 批评 |
| 认知转化四步（v3） | 降级为**研究议程** | 见致命五 |

### 3.2 v3.1 单一状态机（把 v1 typestate + v2 信任 + v3 探究合并）

```
draft ──▶ anchored（挂了客观指针；信任度=low）
   └──▶ open-inquiry（客观源冲突/证据不足 → 溯因诊断，不再直接否决）
           ├─ 客观源沉默且 LLM 分歧 → contending（有实验日程，见退出条件）
           ├─ 判别实验收敛 → 修正保护带 / 翻案硬核 / 证 instrument-suspect
           └─ 收敛后重走证成
anchored ──▶ cross-checked（客观源一致 + 矩阵完备 + mutation score 达标；信任度=high）
   └──▶ published（可废止）
cross-checked ──▶（人在，可选）human-signed（背书标记，非状态）
任何 published ──▶ nightly/工具链/标准变更 → 自动重验 → open-inquiry 或保持
```

**关键改动**：状态 ≤ 6（draft/anchored/open-inquiry/contending/cross-checked/published），信任度是字段不是状态；冲突不再「否决」，一律先进 open-inquiry——但 open-inquiry 必须产出实验计划，不许空转。

### 3.3 判据清单（每个机制一个可计算判据，缺判据 = 不算机制，算隐喻）

| 机制 | 可计算判据 | 来源/实现 |
|---|---|---|
| 证据卡完备性 | 每子断言有指针、引文可达、摘录字符串命中 | v2 Phase1 已定义，照做 |
| 版本矩阵 | 空格数 = 0 | schema 校验 |
| mutation score | 被客观源杀死的变异体比例（硬性：结论反转必死） | v2 已定义 |
| 多源一致 | 冲突数 = 0 或已处置记录 | 客观源冲突检测 |
| 溯因诊断树 | 覆盖率：列出的竞争假设 ⊇ 已知 H1..H5 模板的命中 | 模板 + 红队 checklist |
| 判别实验有效性 | 结果可归因（X/¬X 出现其一）、由客观源判定、区分了哪些假设显式声明 | 算子库 + 判定归属 |
| contending 合法性 | 客观触发条件成立、有实验日程、复审期 ≤ N 天 | 状态机规则 |
| 信任基线怀疑 | 命中 4 条触发条件之一才允许降级 instrument-suspect | 规则表 |
| 混沌演练 | MTTD/逃逸率/错误检出率，注入集 held-out | 仪表盘 |

### 3.4 与 v1/v2 的接口映射（一句话版）

- 七层骨架不变，L1.5 证成层并入探究网络算子集；
- 状态机只有一个（3.2）；
- mutation score 继续当语义质量的唯一硬指标，融贯度只在客观源沉默时管排序；
- 黄金锁/typestate CLI/CI 照旧，只是状态名与冲突入口按 v3.1 改。

## 四、落地优先级重排（先补判据，再补概念）

1. **P0（下一轮就做）**：信任基线协议 + 假设一层截断（致命二）；contending 客观触发与退出条件（次级一）。两个都是纯规则，立即见效。
2. **P0**：概念收敛契约落表（3.1），把现有文档/代码里的 disputed/typestate 并入单一状态机（致命三）。

## 五、价值轴：性能与自律（用户目标的架构化，本轮新增）

用户目标：「榨干每一丝性能」+「极致的自律超级系统」。这不是口号，是 v3.1 的**两条横切价值轴**——所有机制、状态、判据都必须过这两道审计。缺判据 = 算隐喻；缺价值审计 = 算自嗨。

### 5.1 性能轴（efficiency）：每一丝消耗都要有产出

性能的定义不是「快」，是**「每单位消耗的知识产出」**——token 是钱、上下文窗口是稀缺资源（本项目上下文耗尽反复发生）、CI 时间是成本、多平台低价模型轮班是现实约束。

**性能审计判据（v3.1 起每轮必报）**：

| 判据 | 度量 | 现状 |
|---|---|---|
| 信息冗余率 | 同一事实在卡/图/夹具/asm/误解里重复存储的份数 | 高（每原子 2 卡+夹具+asm+误解，卡与关系图内容重叠） |
| 重跑率 | 未变更对象被重新编译/重跑的比例 | 高（门禁全量跑；goldens/ 不被扫描还漏检） |
| 上下文效率 | 每产出 1 颗 verified 原子消耗的上下文/轮次 | 低（红队独立子 agent 重读全文件） |
| 吞吐率 | 每 token 产出的 verified 原子数 | 未度量 |
| 模型-任务匹配度 | 确定性活是否由最便宜的模型完成 | 未路由、无量化策略 |

**收敛动作**：
1. **DRY 证据层**：探究图是唯一事实源，证据卡/夹具/误解全部改为「图的投影视图」，不平行存储（3.1 概念合并表的性能动机）。
2. **增量门禁**：按影响面（changed files → 相关原子/卡/规则）跑子集，全量只留 nightly 与 pre-push；**goldens/ 必须纳入扫描**（性能-正确性交叉点）。
3. **检查点+缓存标准化**：夹具编译产物/实测输出按 sha 缓存，未变不重跑；红队上下文注入「增量 diff」而非全文件。
4. **模型路由量化**：任务分档（确定性校验→最便宜档；判别实验执行→中档；溯因/洞察→最强档），每档有 token/产出预算，超预算自动降档或分片——接住「多平台低价模型轮班」的现实。

### 5.2 自律轴（self-discipline）：不需要外部看守的自律

自律 ≠ 被门禁管住。极致自律 = **每个动作自带目标函数，越界/欺骗/偷懒在没有外部监督时也会被自身机制发现**。门禁是外部拐杖，自律是内化。

**自律审计判据（v3.1 起每轮必报）**：

| 判据 | 度量 | 现状 |
|---|---|---|
| 自我欺骗检出率 | 注入已知缺陷（held-out）被系统自身发现的比例 | 有混沌演练雏形，但注入源与系统同构（Goodhart） |
| 范围越界数 | 未授权动作（混提交/擅自 push/扩任务）发生次数 | 有记录（References 混入、探针残留） |
| 诚实标注率 | 「未采集/未测/未知」被如实标注而非脑补的比例 | 高（铁律 7 执行好，这是底子） |
| 规则自反性 | 规则是否约束规则自身（审计者被审计） | 弱（gate 扫不到 goldens/ 的教训） |
| 惰性检出 | 红队走过场/rubber-stamp 的检测 | 只有 meta-redteam 雏形 |

**收敛动作**：
1. **自律 = 目标函数内化**：给每个角色（Writer/RedTeam/Gatekeeper）写行为准则目标函数（Writer：最小化未锚定断言；RedTeam：最大化证伪尝试数），门禁从「规则列表」升级为「目标函数 + 反例检测」，让自律可被度量而非被命令。
2. **自我欺骗检测器**：held-out 注入源改为**外部事故集**（非本系统 LLM 生成），每轮混沌演练强制跑，逃逸率归零才允许 release；Goodhart 防御 = 注入集与优化目标分离。
3. **自律的自觉性**：每颗原子产出附带「自律声明」：我改了哪些范围、我未测什么、我凭什么认为自己没错——让阙疑（诚实）成为每个动作的默认输出，而不是被问才答。
4. **规则自反**：把「规则本身是否被遵守、规则本身是否有盲区」设为最高级审计项（元审计），goldens/ 不被扫描这类漏洞应由元审计自动发现。

### 5.3 两条轴的交叉制衡（「极致自律超级系统」的裁决规则）

- 追求性能可能鼓励偷懒（跳过红队、压缩流程）→ 自律轴压住；
- 追求自律可能空转（每轮全量审计、怀疑一切）→ 性能轴压住。
- **裁决规则**：性能优化不得绕过自律判据（所有提速必须在检出率不降的前提下）；自律判据不得无限膨胀（每条新规则必须先证明 ≥1 次真实事故增量，且总概念数受 3.1 上限约束）。两轴互相制衡——既快又不自欺，才是「极致」。

## 六、可证伪条件（v3.1 承诺什么、失败长什么样）

- **承诺**：在 held-out 事故集上，系统（自动或半自动）能重演 ≥ 80% 的判别实验决策；冲突一律先溯因而非直接否决；任何 contending 都有可查的实验日程。
- **失败形态**：① 系统重演 LEAK-001 时仍把 H3（测量盲区）漏出假设清单——溯因诊断树不合格；② 客观源冲突直接进 disputed 而非 open-inquiry——状态机没接上；③ mutation score 被废弃、融贯度开始否决客观锚——哲学错误复辟；④ contending 数量增长且无实验日程——悬置沦为懒惰。

## 七、给用户的话

你说得对，v3 粗糙。粗在它像一个哲学系学生写的论文——名词漂亮、概念成串、每个都值得玩味，但**没有一个能落地成「下一步跑什么命令、什么数字算通过」**。v3.1 的收敛手术把每一处都补上了判据或退役决定：oracle 回魂被掐死、信任基线有了协议、概念有了退役表、悬置有了日程、重演有了自动判据。**粗糙感的来源不是缺想法，是缺「能算的东西」——这轮补的就是这个。**

再加你刚锚定的两条价值轴：「榨干每一丝性能」与「极致自律」。它们不是风格偏好，是 v3.1 的**验收标准**——性能轴问「每一分 token/上下文/算力有没有产出可度量的知识」，自律轴问「没有人在场时，系统会不会自己发现自己的欺骗、越界、偷懒和盲区」。前者治浪费，后者治自欺；两者互相制衡，不允许用性能当偷懒的借口，也不允许用自律当空转的理由。这轮之后，v3.1 的每一轮进展都带两张审计表（性能 5 项、自律 5 项），数字说话。
