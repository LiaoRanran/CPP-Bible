# 411 元调研：阙疑调研方法论的自我批判与升级

> 日期：2026-09-13。外部调研：系统性文献综述（PRISMA、PICO、双重独立筛选、叙事综合）、技术雷达（ThoughtWorks 四象限、TRL 1-9、ENISA 力量公式）、个人知识管理（Zettelkasten 原子化、Tiago Forte 渐进式总结五层、CODE 框架）。
> 核心问题：**37 份调研了（374-410），但调研本身没有方法论——没有明确研究问题、没有质量分级、没有优先级排序、没有 ROI 追踪、没有停止条件。** 这是"榨干每一丝性能"的盲区。

---

## 一、阙疑调研的现状评估（37 份的五个问题）

### 问题 1：没有明确的研究问题（PICO 缺失）
- 当前："调研 XX 方向"——范围模糊
- 应该："阙疑在 XX 方面的具体问题是 Y，外部有什么解决方案？哪些适用于阙疑？如何验证？"
- 后果：搜索结果发散，每份调研都"什么都聊一点"，落地项密度低

### 问题 2：没有质量分级
- 当前：搜索结果混用一手（论文/官方）、二手（技术博客）、三手（聚合/转载）
- 应该：优先引用一手，三手只作线索不作证据
- 后果：有些结论来自低质量来源，可信度存疑

### 问题 3：没有优先级排序
- 当前：37 份调研的落地优先级是临时拍的
- 应该：每份调研的结论按 Adopt/Trial/Assess/Hold 分类（技术雷达）
- 后果：不知道哪些该立刻做、哪些该观望、哪些不适用

### 问题 4：没有 Layer 4 涌现
- 渐进式总结五层：
  - Layer 0：搜索结果原文 ✅
  - Layer 1：每份调研文档（374-410）✅
  - Layer 2：元调研批判（396）✅
  - Layer 3：架构蓝图整合（399）✅
  - **Layer 4：混合成原创的可执行落地计划 ❌**
- 398（P0 落地）是部分尝试，但不够系统——没有把所有调研变成一个有优先级、有验收、有依赖关系的落地路线图

### 问题 5：没有 ROI 追踪和停止条件
- 当前：用户说停才停
- 应该：连续 2 份调研没有新的可落地项 = 该方向已饱和；技术雷达全部分类完成 = 调研阶段完成
- 后果：可能在边际递减后还继续调研，浪费 token

## 二、升级版调研流程（SOP）

### Step 0：调研前——明确研究问题（PICO 适配）

每个调研方向开始前，必须写清：
```
【问题】阙疑在 {方面} 的具体问题是 {具体问题}
【现状】当前怎么做的，有什么痛点
【目标】调研后要回答什么问题（3-5 个具体问题）
【验收】调研产出必须包含：{n} 个可落地项 + {m} 个"不适用"判断
```

例（不好）："调研提示词压缩"
例（好）："阙疑的 312 提示词需要压缩 30% 且不损失约束。外部有哪些压缩方法？哪些不损失约束？压缩后如何验证质量？压缩与前缀缓存的冲突如何处理？"

### Step 1：调研中——质量分级

搜索结果分三级，引用时标注：
- **一手**（🔵）：论文、官方文档、标准、源码
- **二手**（🟡）：技术博客、教程、会议演讲（作者有实操经验）
- **三手**（🔴）：聚合、转载、营销文（只作线索，不作证据）

关键结论必须有一手来源支撑。如果只有三手来源，标注"待核实"。

### Step 2：调研后——技术雷达式优先级

每份调研的结论按四象限分类：

| 象限 | 定义 | 阙疑示例 |
|---|---|---|
| **Adopt** | 成熟、已验证、立刻落地 | 406 version 字段、409 毒样例分类 |
| **Trial** | 有潜力、需小范围试点 | 405 闪卡工具、407 L2 即时加载 |
| **Assess** | 持续关注、尚未成熟 | LLMLingua 动态压缩、Shopify Gisting |
| **Hold** | 不适用、太风险、时机未到 | Qt 平台化（引擎未稳定） |

每个象限的判断标准：
- Adopt：有一手来源 + 有阙疑实测验证 + 零风险
- Trial：有一手来源 + 风险可控 + 需要试点
- Assess：概念有趣但缺乏落地条件
- Hold：与当前阶段目标冲突或依赖未就绪的基础设施

### Step 3：Layer 4 涌现——从调研到落地计划

每积累 5-10 份调研，做一次 Layer 4 综合：
- 不是再写一份调研，而是写一份**可执行落地计划**
- 包含：所有 Adopt/Trial 项的优先级排序、依赖关系、验收标准、预计工作量
- 399（架构蓝图）是 Layer 3，411 之后应该有 Layer 4 的"阙疑落地路线图 v1.0"

### Step 4：ROI 追踪

每份调研后记录：
```
调研编号：374
可落地项：{n} 个
已落地：{m} 个
落地后效果：{实测数据或"待验证"}
价值评级：高/中/低
```

每 10 份做一次 ROI 回顾：哪些方向价值最高？哪些方向在灌水？调整后续调研方向。

### Step 5：停止条件

满足任一条件即停止该方向调研：
1. 连续 2 份调研没有新的可落地项（边际递减）
2. 技术雷达上该方向的所有子领域都有了 Adopt/Trial/Assess/Hold 分类
3. 可落地项已超过当前执行能力 2 倍（先消化再调研）

## 四、调研质量的可验证指标

从"感觉调研有用"到"数据证明调研有用"：

| 指标 | 定义 | 当前值 | 目标 |
|---|---|---|---|
| 可落地项密度 | 每份调研的 Adopt+Trial 项数 | 待算 | ≥2/份 |
| 落地率 | 已落地 / 可落地项 | 待算 | ≥50% |
| 一手来源占比 | 引用中一手来源比例 | 待算 | ≥60% |
| 调研→落地延迟 | 调研完成到落地的平均窗口数 | 待算 | ≤3 窗口 |
| 重复率 | 与已有调研内容重复的比例 | 待算 | ≤10% |

这些指标可以放进 404 的健康度仪表盘（"调研健康"维度）。

## 五、元结论

37 份调研的价值是真实的——产生了 v6.0 架构、401/402/403 提示词、404-409 的具体方案。但调研方法论本身是"直觉驱动"的，不是"系统驱动"的。

升级的核心不是"更多调研"，而是**更好的调研**：
1. 调研前有明确问题（不是"调研 XX"）
2. 调研中有质量分级（不是什么都引用）
3. 调研后有优先级排序（不是临时拍落地顺序）
4. 定期有 Layer 4 涌现（不是调研完就完了）
5. 有 ROI 追踪和停止条件（不是用户说停才停）

**最有价值的立即行动**：对 37 份已有调研做回溯分类（上面第三节），然后写一份 Layer 4 的"阙疑落地路线图 v1.0"——把所有 Adopt/Trial 项按依赖关系和优先级排好。这是从"调研积累"到"系统执行"的关键一步。

累计 37 份（374-411）。
