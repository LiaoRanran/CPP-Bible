# 468 · 阙疑架构大一统：知识生命周期 × 验证金字塔 × 能力梯度

> 日期：2026-09-13。这是 195 份调研（271-467）的最终统一。不再开新方向，不再加新术语，把所有有效概念压缩到一个三维模型里：**知识生命周期（X 轴：知识怎么流动）× 验证金字塔（Y 轴：确定性怎么保证）× 能力梯度（Z 轴：自治程度怎么演进）**。
> 本文同时做内卷批判和极限优化：统一之后再攻击统一架构自身。

---

## 一、为什么需要大一统

195 份文档产生了这些并行框架：
- 399 的七层架构（L1 数据→L7 自治）
- 427 的工具依赖 DAG
- 447 的 v7-v9 版本路线
- 449 的八大范式跃迁
- 450 的智能层次八跃迁
- 460 的 7 层 40 落地项
- 466 的六个结构性矛盾
- 467 的渐进激活矩阵

它们都对，但**没有一个回答"一个原子从选题到教会学习者，中间到底发生了什么"**。大一统从这个问题出发。

## 二、X 轴：知识生命周期（十个阶段的闭环）

```
①选题 → ②假设 → ③实验 → ④观测 → ⑤证据 → ⑥对抗 → ⑦裁决 → ⑧知识 → ⑨教学 → ⑩反馈
 ↑                                                                                    │
 └────────────────────────────────────────────────────────────────────────────────────┘
                                      （反馈驱动新选题）
```

| 阶段 | 产出物 | 当前工具 | 确定性程度 |
|---|---|---|---|
| ①选题 | 选题论证（知识缺口/误解频率/教学价值） | 人工 + 知识图谱缺口检测（未来） | 低（判断） |
| ②假设 | claim 契约（pre/post/invariant + 竞争假设 + DAL） | claim 契约化 v2.0（待落地） | 中（结构化） |
| ③实验 | 夹具（.cpp）+ 实验设计（活性对照/反例对照/单变量） | 夹具方法论 v2.0（待落地） | 中（模式约束） |
| ④观测 | 工件（.asm/.out）+ 双平台实测 | g++/clang + replay 编译 | **高（编译器裁决）** |
| ⑤证据 | 证据卡（actual/expected/falsification/sha） | replay + gate | **高（可复现）** |
| ⑥对抗 | 红队报告（阻断/高级/建议 + 错误预测） | 独立子 agent 两段式盲读 | 中（模型判断） |
| ⑦裁决 | verdict（confirm/refute/infra_error）+ 门禁 | gate 42 规则 + poison + pytest | **高（规则裁决）** |
| ⑧知识 | 原子卡（verified）+ 误解卡 + relations | golden_lock + 人审 | 高（签署） |
| ⑨教学 | 闪卡/MCQ/学习路径/错误示例 | atom_to_flashcard（待建） | 中（内容生成） |
| ⑩反馈 | 学习效果（正确率/遗忘率/元认知校准） | FSRS 调度 + 教学代理（未来） | 低（数据积累） |

### 关键洞察 1：当前系统只做到 ⑧，⑨⑩ 完全空白

27 颗 verified 原子是"生产出来的知识"，不是"被学会的知识"。闭环在 ⑧ 断了，反馈回路（⑩→①）不存在——所以选题靠人工直觉，没有数据驱动。

### 关键洞察 2：②假设 是最薄弱的环节

第五批三个方向性错误（ALLOC 口径反转/LEAK 观测翻转/PERF 恒真读数）全部源于 ②——假设没有写清楚"我要观测什么、什么结果算证伪、活性对照是什么"。红队在 ⑥ 才抓到，成本是 ② 阶段写清楚的 50-100 倍（红队 53 次工具调用 vs claim 契约多写 10 行）。

## 三、Y 轴：验证金字塔（六层，从廉价到昂贵）

```
                    ┌─────────┐
                    │ L6 教学验证 │  学习者是否真的学会（最终质量）
                   ┌┴─────────┴┐
                   │ L5 人审裁决 │  DAL A/B、异常升级、签署
                  ┌┴───────────┴┐
                  │ L4 语义对抗  │  红队盲读、口径统一、活性对照、突变杀灭
                 ┌┴─────────────┴┐
                 │ L3 证据复现    │  replay（sha/断言/sanitizer/双平台）
                ┌┴───────────────┴┐
                │ L2 规则检查      │  gate（字段/格式/ID/relations/DAG）
               ┌┴─────────────────┴┐
               │ L1 写作时自检      │  Writer 自检（零 token，提交前拦截）
              ┌┴───────────────────┴┐
              │ L0 编译通过          │  编译器是最硬的裁决者（-Wall -Werror）
              └─────────────────────┘
```

### 每层的成本与拦截目标

| 层 | 执行者 | 单次成本 | 拦截什么 | 当前状态 |
|---|---|---|---|---|
| L0 | 编译器 | ~2s 机器时间 | 语法错误、类型错误、部分 UB（警告） | ✅ 完备 |
| L1 | Writer 自检脚本 | ~1s 机器时间，0 token | 字段缺失、sha 不同代、断言候选不存在 | 🔨 苦力在建 |
| L2 | gate_engine | ~3s 机器时间，0 token | 42 类机械违规 | ✅ 运行中 |
| L3 | replay | ~2min 机器时间（ccache 后 ~10s），0 token | 证据不可复现、断言失败、sanitizer 报错 | ✅ 运行中 |
| L4 | 红队子 agent | **~15000-30000 token** | 口径错误、恒真读数、组合逃逸、语义矛盾 | ⚠️ 频率降级中 |
| L5 | 人（用户） | 用户注意力（最稀缺资源） | DAL A/B 的语义正确性、教学价值 | ⚠️ 瓶颈 |
| L6 | 学习者 | 时间 | 知识是否可学会、是否纠正了误解 | ❌ 空白 |

### 关键洞察 3：成本金字塔是指数级的，"左移"是最大的成本优化

- L1 拦截一个字段错误：0 token
- L2 拦截：0 token
- L3 拦截：0 token（机器）
- L4 红队拦截一个口径错误：~20000 token
- L5 人审拦截：消耗用户最稀缺的注意力
- L6 学习者发现"教错了"：信任崩塌，不可挽回

**第五批的三个方向性错误全部在 L4 才被抓到。如果 claim 契约化（L1.5）和夹具方法论（L1.5）落地，它们在写作时就会被拦截，红队预算可以砍 60%。**

这就是"左移"：把 L4 的检查尽可能下沉到 L1/L2。下沉一项，红队就少一项负担。

### 关键洞察 4：L3 是系统的信任锚，但有明确天花板

L3（replay+gate+poison）是零 token、可无限重跑的机器验证，是系统最大的成本优势。但 402 对抗证明它的天花板是"单点合规"——组合攻击（F02 编译后覆写）、时序攻击（producer 后覆写）、环境依赖（nproc 进断言）都穿过去了。

**L3 的强化方向不是加规则，而是从"存在性检查"升级到"不变量检查"（426）**：
- 存在性检查："字段 X 存在吗？" → 可被"写了但不对应实现"绕过
- 不变量检查："整个数据流中，artifact 的每个字节都能追溯到唯一的编译命令吗？" → 组合攻击无法绕过

## 四、Z 轴：能力梯度（自治程度的四阶段演进）

| 阶段 | L0-L3 机器层 | L4 语义层 | L5 裁决层 | L6 教学层 | 人的角色 |
|---|---|---|---|---|---|
| **当前 v6.x** | 自动 | 红队（模型，每 3 颗 1 次） | 人审 DAL A/B | 空白 | 监工+审查者 |
| **v7.0（近期）** | 自动 + L1 自检 | claim 契约+夹具方法论+红队（好模型，每颗） | 人只审异常（DAL A） | 闪卡试点 | 异常处理者 |
| **v8.0（中期）** | + 突变杀灭+差分测试 | LLM 二次筛选 warn、规则质量评分 | DAL C/D/E 全机器豁免 | 闪卡+MCQ+路径 DAG | 目标设定者 |
| **v9.0（远期）** | + 持续进化循环 | counterexample mining 自动生成规则候选 | 全自治，人审抽检 | 教学效果代理验证 | 旁观者/教练 |

### 关键洞察 5：自治的前提是校准，不是规则数量

448 的核心结论：放权的前提是"机器判断与人类判断的一致率"可量化。当前没有这个数据——红队阻断了多少、人审推翻了多少、机器放行后人审发现错了多少（假阴性），全部没有记录。

**所以 v7.0 最该建的不是更多规则，而是校准数据采集（465 任务 D 成本 trace + 红队裁决留痕）。没有校准数据，放权是赌博。**

## 六、内卷：攻击这个统一架构

统一之后必须自我攻击，否则又是一份"看起来很美"的文档。

### 攻击 1：三维模型是描述，不是机制

X/Y/Z 三轴准确描述了系统，但**没有给出任何新的强制约束**。399 的七层、460 的 40 项也是描述。描述性架构的风险是：苦力读完知道"系统长什么样"，但不知道"下一步具体改哪个文件的哪一行"。

**修正**：本文第八节给出按依赖排序的具体落地序列，每项挂文件/工具/验收命令。架构文档必须能直接转成提示词，否则就是知识化石（466 矛盾 1）。

### 攻击 2："错误左移"可能被滥用为砍红队的借口

我说"L1/L2 下沉能让红队预算砍 60%"，但这是**假设，不是数据**（453 协议）。claim 契约化能不能真的拦住 ALLOC 口径反转？不一定——口径错误是语义的，L1 自检只能检查"有没有写竞争假设"，不能检查"竞争假设对不对"。

**修正**：左移的拦截率必须用历史数据验证——把第五批三个错误回放给 claim 契约 v2.0，看它能不能在 L1 拦住。拦不住的部分，红队预算不能砍。这是 467"接口先行+数据积累"的具体应用。

### 攻击 3：教学闭环（⑨⑩）可能是过度设计

用户当前阶段的核心痛点是"原子生产慢、门禁有逃逸"，不是"学不会"。在 27 颗原子、生产链还没完全自动化时投入教学转化，可能是在错误的环节优化。

**反方论证**：但 467 已论证教学试点 ROI 高（不需要重流程、1 小时出活、直通终极目标）。且教学转化会**反向暴露原子卡的问题**——如果一颗原子转不成一张清晰的闪卡，说明它的 claim 本身就不清晰。教学是生产质量的另一面镜子。

**修正**：教学试点定位为"质量探针"而非"产品功能"——用 1 颗原子验证"原子卡是否清晰到能直接教学"，这是 L6 对 L4 的反向校验。

### 攻击 4：能力梯度（Z 轴）假设模型会越来越强，但没设计"模型变弱/不稳定"的回退

白嫖模型可能限流、降级、换版本（用户已经历 ds v4.1 flash 额度耗尽、换 Qwen、换 Trae）。架构假设"晚上好模型加入→激活更多"，但如果好模型不稳定呢？

**修正**：每个激活项必须有"降级模式"——好模型不在时，红队从"每颗"降回"每 3 颗"，但 L0-L3 机器层不受影响。这正是"机器层做地基、模型层做增强"的架构价值：**模型是可插拔的增强，不是单点依赖**。467 的可插拔原则要显式包含"模型缺席"场景。

### 攻击 5：进化引擎闭环可能引入"规则通胀"正反馈

"对抗发现→自动生成规则→入库"如果全自动，会导致规则数量爆炸（444 预警的新规则→新误报正反馈）。每颗原子都为它遇到的攻击加一条规则，100 颗后规则可能有 200 条，大部分是过拟合的特例。

**修正**：规则入库必须过"泛化测试"——一条新规则必须能拦住 ≥2 个不同形态的攻击用例才能升 stable（464-T2 渐进发布 + 突变族 IPT）。只拦一个特例的规则进 experimental，3 批后无新命中则 deprecated。规则数量要做减法（466 中期调整 1）。

### 攻击 6：⑩反馈→选题的数据回路在单人场景下样本量不足

FSRS/学习效果数据需要大量学习者样本才有统计意义。用户一个人学，数据点稀疏，"数据驱动选题"在 v9.0 之前都是空话。

**修正**：⑩ 在 v7/v8 只做数据采集不做自动决策；选题仍由人+知识图谱缺口（覆盖率）驱动，学习效果数据作为辅助。诚实标注这条回路的激活前提（样本量）。

## 七、极限优化：五个最高杠杆点

经过统一和自我攻击，真正高杠杆的优化收敛到五个（按 ROI 排序）：

### 杠杆 1：L1 写作时自检（最高 ROI，零 token 拦截）

- **做什么**：writer_selfcheck.py（苦力在建）+ claim 契约 v2.0 + 夹具方法论 v2.0
- **为什么**：把 L4 红队的机械性检查（sha 同代、字段完整、断言候选存在、活性对照有无）下沉到 L1
- **验收**：回放第五批三个错误，记录 L1 能拦住几个（预期 1.5-2 个，口径语义错误拦不住）
- **成本**：苦力 2-3 窗口；**收益**：红队 token -30~50%，每颗原子窗口 6→≤3

### 杠杆 2：对抗逃逸清零 + 进化引擎闭环

- **做什么**：先修完 402 的 13 个逃逸（402→414→465 任务 E），再跑 452；建立"对抗→规则候选→毒样例→泛化测试→入库"流水线
- **为什么**：已知逃逸未修就跑新对抗是浪费（466 矛盾 3）；闭环不通，对抗就只是一次性审计
- **验收**：402+452 逃逸全部有处置（修复/驳回+理由），新规则过泛化测试
- **成本**：好模型 2-3 窗口（语义修复）；**收益**：拦截率 35%→≥60%

### 杠杆 3：L3 从存在性检查升级到不变量检查

- **做什么**：426 InvariantChecker 最小版——artifact 全链路溯源（每个字节追溯到唯一编译命令）+ 多写操作时序检测
- **为什么**：这是堵住组合攻击（F02 类）的根本解，比逐条加 cp/mv 黑名单（永远列不全）强
- **验收**：402 F02 攻击用例在不变量检查下无法逃逸；存量 56 卡零误伤
- **成本**：好模型 1-2 窗口（晚上做）；**收益**：堵住整类时序攻击

### 杠杆 4：校准数据采集（放权的前提）

- **做什么**：465 任务 D 成本 trace + 红队裁决留痕（采纳/驳回/误判）+ 机器放行后人审发现率
- **为什么**：没有校准数据，"放权自动化"是赌博；有了数据才能量化红队频率、规则质量、自治边界
- **验收**：10 颗原子后输出第一份校准报告（每颗 token、红队采纳率、L1 拦截率、假阴性）
- **成本**：苦力 1 窗口建工具，之后自动采集；**收益**：所有后续放权决策的数据基础

### 杠杆 5：教学闪卡作为"质量探针"试点

- **做什么**：1 颗原子（RAII-001）→ 3-5 张 FSRS 格式闪卡 + atom_to_flashcard.py
- **为什么**：直通终极目标 + 反向检验原子卡清晰度 + 零重流程
- **验收**：闪卡能独立教会一个概念（用户自评）；转卡过程暴露的原子卡问题记录在案
- **成本**：苦力 1 小时；**收益**：打通 ⑨ 的最小闭环，验证教学转化可行性

### 明确不做的（防止精力分散）
