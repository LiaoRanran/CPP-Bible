## 二、加密度方案：三轨并行

### 轨道 A：建设苦力（CodeBuddy 白天 + Cline 夜间）
**原则：不同时改同一文件域，用分支或文件域隔离避免冲突。**

| 苦力 | 时间 | 负责域 | 批次规模 |
|------|------|--------|---------|
| CodeBuddy (glm-4-flash) | 白天（免费额度） | tools/ 新工具 + tests/ | 中批（3-4 任务，20-30 min） |
| Cline (glm-4-flash) | 夜间（免费额度刷新） | data/ 台账 + 审计报告 + 文档 | 小批（2-3 任务，15-20 min） |

**文件域隔离规则**：
- CodeBuddy 只改 tools/*.py 和 tests/test_*.py
- Cline 只改 data/*.md 和 References/ 下的文档
- 两者都不改 CORE_TOOLS（gate_engine / atom_evidence_replay / poison_drill / toolchain / cppbible）——CORE 修改由 MainAgent 单批慢做
- 如果必须改 CORE，提前在提示词里声明，且该批只改一个 CORE 文件

### 轨道 B：调研苦力（Trae / Seed-Evolving，异族）
- 与建设完全隔离（只读，产出 _arch_v*）
- 每 2-3 天一轮，主题从建设中遇到的理论缺口选
- 调研产出必须含"可转化 N 项"，否则不算完成

### 轨道 C：人审（用户本人，每天 25 分钟）
- 用 604 的 `attack_edge_review.py review-group` 工具
- 每天审 5 个 MIS 群组（~25 分钟，604 实测 42 组共 24.5 分钟）
- 9 天清完 388 条边
- 同时顺手填 golden accept（1 次操作治 slow 红）

## 三、严谨性保障（不丢质量的硬门）

### 每批必须通过的门禁（写进提示词，苦力不跑=不验收）
```
1. pytest -m "not slow" -n auto → exit 0（完整 fast，不是单文件）
2. python tools/tool_integrity.py --check → exit 0
3. python tools/gate_engine.py --check → exit 0，数字与基线一致
4. python tools/poison_drill.py → exit 0，数字与基线一致
5. python tools/atom_evidence_replay.py --check → exit 0（confirm=56）
6. ruff check（改动文件）→ All passed
7. git diff --quiet -- atoms evidence Examples Book → exit 0
```

**605/606 的教训**：只跑单文件测试 = 质量债。以后提示词里把"完整 fast"写成第一条验收标准，苦力跳过=该批不算完成。

### 多苦力冲突预防
- 每批开工前：`git pull --rebase`（如果有远程）或 `git log -1` 确认 HEAD
- 每批只改自己负责的文件域
- 如果发现别人改了自己要改的文件，停手报告，不强行 merge
- MainAgent 每天做一次集成：把各苦力的 commit 线性整理，跑完整门禁

### 质量债偿还计划
- 608 批（MainAgent 单批慢做）：补 605/606 的质量债——跑完整 fast 回归、补不变量边界测试、验证 metrics with_heavy=True
- 以后每 4 批插入一批"质量债偿还"批，不做新功能，只补测试和验证
