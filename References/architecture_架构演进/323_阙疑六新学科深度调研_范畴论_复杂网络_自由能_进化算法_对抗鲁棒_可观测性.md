## 一、范畴论：原子体系的数学结构

### 1.1 核心理论

**Curry-Howard-Lambek 对应**：
- 命题 = 类型 = 对象
- 证明 = 程序 = 态射
- 直觉主义逻辑 = 类型化 λ 演算 = 笛卡尔闭范畴——三者是同一事物的三个视角

**范畴论的核心**：
- 关注对象之间的**关系**（态射），而非对象内部结构
- 组合性：复杂系统由简单组件通过态射组合而成
- 函子（Functor）：范畴之间的结构保持映射
- 自然变换（Natural Transformation）：函子之间的映射

**"Categorical Foundations of General Intelligence"**（2026）：
- 范畴论为通用智能提供数学基础——优先考虑实体间的交互，而非内部构成
- 集合论基于"成员关系和层次"，范畴论基于"对象和态射"

### 1.2 对「阙疑」的映射

**原子体系是一个范畴**：
| 范畴论概念 | 「阙疑」对应 |
|---|---|
| 对象（Object） | 原子（ATOM-MEM-*） |
| 态射（Morphism） | 关系（prereq/contrasts/serves） |
| 组合（Composition） | 原子的组合（复杂概念由简单原子构成） |
| 函子（Functor） | 域间映射（MEM 的 RAII → CONC 的锁安全） |
| 自然变换 | 跨域的结构保持变换 |

**Curry-Howard 对应为三层体系提供数学基础**：
- claim = 命题（需要被证明/证伪）
- 证据卡 = 证明（支持/反驳命题）
- 夹具 = 程序（可执行的证明过程）
- replay = 类型检查（验证证明是否有效）

**组合性指导原子设计**：
- 新原子应该尽量由已有原子通过关系组合而成，而非从零创建
- 如果一个概念需要 5 个新原子才能表达，可能是"组合方式"有问题
- 函子映射：MEM 域的成熟模式（如 RAII 的"获取即初始化"）可以映射到 CONC 域（如"加锁即初始化"）

## 二、复杂网络：原子关系图的拓扑分析

### 2.1 核心理论

**无标度网络**（Scale-Free Network）：
- 度分布服从幂律 P(k) ~ k^(-γ)，γ 通常 2-3
- 少数 hub 节点拥有大量连接，大多数节点低度
- **优先连接**：新节点倾向于连接已有高度节点
- 对随机故障鲁棒，对定向攻击脆弱

**小世界属性**：
- 短平均路径长度（任意两节点距离短）
- 高聚类系数（朋友的朋友也是朋友）

**模块化**：
- 密集连接的节点群形成功能模块
- 模块内密集连接，模块间稀疏连接

### 2.2 对「阙疑」的映射

**原子关系网络的拓扑分析**（306 的深化）：
- 计算每个原子的**度**（被引用次数），识别 hub 原子
- 预期：RAII、移动语义、unique_ptr 等是 hub（被大量引用）
- hub 原子需要更高维护优先级（出错影响面大）

**鲁棒性分析**：
- 随机删除一个原子：影响小（大多数原子低度）
- 删除 hub 原子（如 RAII）：影响大（大量引用断裂）
- 落地：hub 原子的 DAL 自动提升一级（更严格审查）

**模块化验证**：
- 按域（MEM/CONC/UB）划分模块
- 计算模块内密度 vs 模块间密度
- 如果模块间连接太少，说明域之间缺乏交叉引用（教学上的孤岛问题）

**优先连接的利用**：
- 新原子应该优先连接到 hub 原子（通过 prereq/contrasts）
- 这加速新原子的"融入"（被已有知识网络吸收）
- 落地：新原子生产时，gate 检查是否至少引用 1 个 hub 原子

## 三、自由能原理：「阙疑」作为预测机器

### 3.1 核心理论

**Friston 自由能原理**（FEP）：
- 所有生命系统通过最小化**自由能**（=惊讶的上界）来维持存在
- 大脑是**预测机器**：生成世界模型→预测感官输入→用实际输入更新模型
- 预测误差不是"垃圾"，而是学习信号

**主动推理**（Active Inference）：
- 统一感知和行动：
  - **感知方向**：更新信念匹配现实（修改内部模型）
  - **行动方向**：改变世界匹配预测（实验/干预）
- 天然驱动探索：寻求解决不确定性（信息增益最大的地方）

**精度加权**（Precision Weighting）：
- 平衡内部期望和感官数据的权重
- 高可靠感官数据权重高，低可靠数据权重低

### 3.2 对「阙疑」的映射

**「阙疑」的自由能 = claim 与证据的差距**：
- claim = 内部模型（对世界的预测）
- 实测结果 = 感官输入（实际遇到的）
- 最小化自由能 = 最小化 claim 与证据的差距

**主动推理的两个方向**：
| 方向 | 「阙疑」对应 | 例子 |
|---|---|---|
| 感知（更新信念） | 红队发现问题后修 claim | CONC-001"屏障拦不住消除"被实测推翻→修 claim |
| 行动（改变世界） | 设计新实验验证 claim | 加 volatile 计数器证明分配真发生 |

**精度加权 = 证据可靠性**（322 贝叶斯的深化）：
- 双平台 confirm 的证据 = 高精度感官数据
- 单平台、无活性对照的证据 = 低精度
- 高 DAL 原子需要高精度证据（精度阈值高）

**探索驱动**：
- 「阙疑」应该主动寻求"高不确定性"的领域（如 CONC 域零开采时）
- 信息增益最大的地方 = 最值得探索的地方
- 这解释了为什么转 CONC 域是正确决策（MEM 域边际递减，CONC 域信息增益大）

## 四、进化算法：规则的自动进化

### 4.1 核心理论

**LLM 驱动的进化**：
- LLM 作为**变异算子**，产生语义有意义的变异（而非随机突变）
- EoT（进化思维链）：让"盲目随机突变"变成"有语义的定向探索"
- LLM 引导的进化比纯随机 GA 收敛快 **5-20 倍**

**代表系统**：
- LEAR：LLM-Driven Evolution of Agent-Based Rules
- CodeEvolve：islands-based 遗传算法 + LLM 编排
- REvolve：进化发现强化学习算法（排除标准机制，促进非标准规则涌现）

**协同进化**（Co-Evolution）：
- 策略和对手一起进化
- LLM 在进化中发明了种子策略中不存在的新战术机制

### 4.2 对「阙疑」的映射

**规则进化的自动化**（315 外环的升级）：
- 当前：红队发现问题 → 人审 → 手动加规则（人工选择）
- 升级：LLM 自动生成规则候选 → 门禁验证（适应度函数）→ 保留高适应度规则

**适应度函数**：
- 真阳性率：规则抓到真问题的比例
- 假阳性率：规则误报的比例
- 覆盖度：规则覆盖的历史问题比例
- 适应度 = 真阳性率 - α × 假阳性率 + β × 覆盖度

**选择与淘汰**：
- 每批结束时，对所有规则计算适应度
- 低适应度规则（假阳性率 >30%）→ 降级为 warn 或删除
- 高适应度规则 → 保留并可能升级为 block

**协同进化**：
- Writer 变强（claim 更严谨）→ 红队必须变强（才能发现问题）
- 红队变强 → Writer 必须变强（才能通过审查）
- 这是正反馈循环，防止系统"停滞"

**与双环的关系**：
- 内环（315）：单原子闭环（生产→红队→修复）
- 外环（315）：批次诊断→规则改进→回归验证
- 进化算法（323）：外环的具体实现机制（变异→选择→遗传）

## 五、对抗鲁棒性：从内容红队到系统红队

### 5.1 核心理论

**所有防御都可能被自适应攻击者绕过**（arXiv 2604.23887）：
- 模型依赖的防御（安全指令、分隔符、指令层次）全部失败
- 输入清洗也失败：恶意输入空间太大
- 自适应攻击者从每轮防御者响应中学习并进化策略

**GPT-Red**（OpenAI, 2026-07）：
- 自动化红队模型，规模化发现漏洞
- 用 GPT-Red 对抗训练 GPT-5.6，显著提升鲁棒性

**二阶提示注入**（Confused-Deputy）：
- 低权限代理被诱导请求高权限代理解除操作
- 跨代理的权限提升

**6 阶段红队方法论**：
侦察→提示注入测试→越狱测试→数据提取测试→过度代理测试→报告

### 5.2 对「阙疑」的映射

**当前只有"内容红队"，缺少"系统红队"**：
- 内容红队：审查 claim/证据是否正确（我们已做）
- 系统红队：审查门禁/工具的**绕过路径**（未做）

**系统红队的目标**：找到"如何让一个错误的原子通过门禁"
- 能否通过操纵 frontmatter 字段绕过 gate？
- 能否通过构造特殊夹具让 replay 恒真？（P4 自证断言就是例子）
- 能否通过证据卡的 actual 格式让断言静默通过？（EV-MEM-038 的 heap_at_len 教训）
- 能否通过 golden_lock 的计数逻辑隐藏恶化？

**二阶注入风险**：
- Writer 写的证据卡会被红队读取
- Writer 能否通过证据卡的内容"引导"红队的判断？（如在卡内写"这个断言已经验证过"）
- 两段式盲读（312）就是防御：红队先不读卡，只读夹具/工件

**系统红队的落地**：
- 每批混入 1 个"恶意原子"（已知有缺陷但伪装成正确的）
- 测试门禁和红队能否发现
- 这与 321 的"哨兵探针"互补：哨兵探针测可靠性，系统红队测安全性

## 六、可观测性：Agent 行为的完整追踪

### 6.1 核心理论

**AgentTrace**（arXiv 2602.10133）：
- 结构化日志框架，三个层面：
  - **操作层**：工具调用、文件读写、命令执行
  - **认知层**：决策、推理、假设
  - **上下文层**：参考资料、历史原子、环境信息
- 不只是调试，而是安全、问责、实时监控的基础层

**OpenTelemetry GenAI 语义约定**（1.29 稳定版，2026）：
- `gen_ai.*` 命名空间标准化 LLM 调用属性
- `gen_ai.system`（提供商）、`gen_ai.request.model`、`gen_ai.usage.tokens`

**Traces = AI 系统的"调用栈"**：
- 每个 LLM 调用、工具调用、检索步骤、中间决策都被捕获
- 显示"发生了什么"以及"如何和为什么"

**四大支柱**：监控、追踪、评估、治理

### 6.2 对「阙疑」的映射

**当前可观测性的缺口**：
- 只有门禁输出（replay/gate/poison 的结果）
- 缺少"认知层"追踪：为什么选这个 claim？为什么改这个断言？为什么跳过红队？
- 缺少"操作层"追踪：每次编译/运行/grep 的详细日志

**AgentTrace 式三层日志的落地**：

```
traces/
  batch5/
    ATOM-MEM-PERF-004/
      operational/    # 工具调用日志（编译/运行/grep）
      cognitive/      # 决策日志（claim 选择/断言修改/红队处置）
      contextual/     # 上下文日志（参考资料/历史原子/环境）
```

**对"离开人也能自己纠错"的关键意义**：
- 没有追踪，就无法诊断为什么出错
- 有了追踪，可以回放失败的决策路径，找到根因
- 可以用追踪数据训练"错误预测模型"（315 的错误预测命中率）

**与元认知监控的关系**（320）：
- 元认知监控（工具调用数/修订轮次/warn 趋势）是追踪数据的**聚合**
- 追踪是原始数据，元认知是分析结果
- 先有追踪，才能有元认知

## 九、一句话总结

322 把「阙疑」的理论支撑从四学科扩展到六学科，323 再扩展到**十二学科**。最关键的三个新洞察：

1. **复杂网络的 hub 识别**——RAII/移动语义等核心原子应该自动提升 DAL 等级，因为它们出错影响面最大
2. **进化算法的规则自动进化**——LLM 作为变异算子 + 适应度函数（真阳性/假阳性率）= 规则的自动生成和淘汰，不再依赖人工
3. **系统红队**——我们只做了"内容红队"（审查 claim），还需要"系统红队"（审查门禁的绕过路径），这是"离开人也能自己纠错"的关键缺失环节
