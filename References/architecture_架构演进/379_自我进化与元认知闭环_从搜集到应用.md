# 379 自我进化与元认知闭环：从搜集到应用

> 日期：2026-09-13（夜）。监工完成，覆盖 374-378 均未触及的一层：**系统如何从运行中自动学习、自我进化**——从"静态规则集"走向"自适应系统"。
> 流程：搜集 → 整理 → 挖掘 → 联系 → 批判 → 结合 → 应用。

## 一、搜集（搜了什么）

两路并行检索：
1. Agent 自我改进 / 自反射 / 经验学习 / 记忆整合
2. 元认知 / 自我监控 / 从失败中自动发现规则 / 技能重写

核心来源（12 份）：
- **Experiential Reflective Learning (ERL)**（arXiv 2603.24639）：反思轨迹产出启发式，测试时检索注入
- **EvolveR**（arXiv 2510.16079）：离线自蒸馏 + 在线交互检索原则，完整经验生命周期
- **Self-Consolidation**（arXiv 2602.01966）：对比反思 + 文本经验蒸馏为可学习参数
- **RetroAgent**（arXiv 2603.08561）：事后自省的双重内在反馈（数值进度 + 语言洞察）
- **MARS**（arXiv 2601.11974）：元认知反思（原则性反思 + 程序性反思）
- **Meta 组织第二大脑**（engineering.fb.com 2026-09）：专家修正四阶段编译闭环，回归套件强化
- **Memento-Skills**（alphaXiv 2603.18743）：技能重写 + 技能发现（让 Agent 设计 Agent）
- **CowAgent 五层自进化**（CSDN）：记忆维护→总结→复盘→梦境整理→源码自更新
- **三层记忆**（patterns/decisions/errors）：代码约定/架构决策/重复错误与修复
- **Agentic Self-Improvement 框架**：Reflexion 模式（生成→批判→修订循环）
- **STAR-XAI**（arXiv 2509.17978）：二阶代理（agent 反思自己计划质量并主动纠正）
- **Self-Correction Patterns**（2026）：监控→识别失败→调整计划→优雅恢复

## 二、整理（分类）

| 类别 | 核心问题 | 代表工作 |
|---|---|---|
| A. 经验→启发式 | 从轨迹里提炼可复用的教训 | ERL、EvolveR |
| B. 双反馈 | 数值+语言双通道评估进步 | RetroAgent |
| C. 元认知反思 | 原则性+程序性两类反思 | MARS、STAR-XAI |
| D. 修正编译闭环 | 专家修正→诊断→编译→验证→回归 | Meta Second Brain |
| E. 技能演进 | 重写失败技能/发现新技能 | Memento-Skills |
| F. 记忆分层 | patterns/decisions/errors 三类 | 三层记忆、CowAgent |
| G. 渐进进化层级 | 静态→训练→自改进→递归自改进 | Improvement Stack |

## 三、挖掘（核心洞察）

**A. 经验→启发式（最关键）**：不是把轨迹原样丢进记忆库（那叫"写了日记"），而是**反思轨迹产出抽象、可跨任务复用的启发式规则**，下次任务时检索注入。判断是否进入"自我进化"的三点：①做完有没有主动复盘？②复盘结论是否抽象成可复用洞察（而非流水账）？③这些洞察下次/下个会话有没有真的被读出来、改写决策？三点都满足才算，只满足第一点叫"写了日记"。

**B. 双反馈**：数值反馈衡量增量进步（不是全有全无的成败），语言反馈蒸馏策略洞察。数值防止"过早收敛"，语言捕获"为什么有效"。

**C. 元认知反思**：原则性反思（抽象出规范规则避免错误，如"永远先证伪内联假设"）+ 程序性反思（推导逐步成功策略）。二阶代理（STAR-XAI）更进一步：agent 能质疑自己已批准的计划并主动纠正——这是"监控自己的监控"。

**D. 修正编译闭环（和我们最像）**：每个专家修正走四阶段——①诊断反馈为可行动问题（含根因）②编译为最小可验证修改 ③验证修复无回归 ④领域专家审阅。**闭环完成后，回归测试套件被该问题强化**——未来更新必须保持此行为。这就是"每次红队发现都变成毒样例"的完整形式化。

**E. 技能演进**：技能持续失败或新任务超出库范围 → 触发技能重写/技能发现（重组现有技能或合成全新技能填补空白）。这是"让 Agent 设计 Agent"的入口。

**F. 记忆分层**：三层——patterns（代码约定/项目结构）、decisions（架构选择及其理由）、errors（反复出现的错误及其修复）。每类触发时机和检索方式不同，混在一起会互相污染。

## 四、联系（和我们系统的映射）

| 外部发现 | 我们的现状 | 差距 |
|---|---|---|
| A. 经验→启发式 | 红队教训→写进规则（半自动） | 靠人/红队手动发现+监工写规则，无自动提炼 |
| D. 修正编译闭环 | 红队发现→修复→毒样例（已接近！） | 已是最接近的：373 每条规则都配毒样例+阴阳例，但"回归套件强化"是手动的 |
| F. 记忆分层 | 2026-09-12.md 是流水账式 | 没有按 patterns/decisions/errors 分层 |
| E. 技能演进 | 规则新增靠监工裁决 | 无自动"技能重写/发现" |
| C. 元认知 | 红队是外部监督，非自我监控 | 建设者没有"监控自己的监控" |
| G. 进化层级 | 处于 Level 3（自改进）边缘 | 离递归自改进还有距离 |

**最扎心的对照**：Meta Second Brain 的闭环（诊断→编译→验证→人审→回归强化）几乎就是我们 373 批的流程，但它是**自动化的、每次修正都编译进回归套件**；我们是**手动的、靠监工和红队逐条驱动**。

## 五、批判（哪些不适用）

1. **自蒸馏到参数（Self-Consolidation）**：需要微调/训练基础设施，我们只有 API 调用，不适用。我们的"参数"就是规则代码+毒样例。
2. **梦境记忆（CowAgent 第4层）**：重放记忆强化，对文本型知识生产价值有限，跳过。
3. **自动技能发现（Memento-Skills）**：需要大规模运行数据（数千次任务）才能可靠触发。我们目前几十次任务，过早自动化会发现大量假技能。适合长期。
4. **数值反馈（RetroAgent）**：我们的任务成败是门禁的离散判定（block=0/1），不是连续进度。但可以引入"进展量化"（如红队发现的严重度分级）作为弱数值信号。
5. **递归自改进**：理论上终极形态，但我们的工具链还远未稳定到"自动改自己"的程度。**在语义自律（374）落地前，自动改规则是危险的**——规则本身的质量还没被机器判据保证。

## 六、结合（和已有架构的结合点）

**和 G6 状态体系**：状态转换（draft→machine-verified→human-verified）本身就是天然的"经验检查点"——每次转换时可以附加"本轮教训"字段，自动汇入错误记忆层。

**和毒样例体系**：毒样例已经是"回归套件强化"的雏形（每条规则配阴阳例）。缺的是**自动回填**——红队发现新逃逸后，系统应提示"此逃逸应成为哪条规则的毒样例"，而不是靠人记得。

**和记忆文件（376）**：376 提出了标准化记忆格式（已完成/未完成/关键数据/下一步），379 升级为**分层记忆**：patterns（跨批次的稳定教训）/ decisions（架构选择及理由）/ errors（本批错误及修复）。376 是"可恢复"，379 是"可学习"。

**和三权分立**：红队=外部批判，元认知=内部批判。两者互补：外部抓"我不知道的错"，内部抓"我应该知道的错"。建设者应被要求在提交前自问"我的 claim 有没有可能是错的？错的证据长什么样？"——这对应 374 的正反论证强制，379 让它成为习惯。

**和 371 预言冻结**：预言冻结（实验前写死预测）本身就是元认知的实证形式——它让 agent 事后能看出自己预测对了没有。这是"自我监控"的最小落地。

## 七、最终应用（分阶段落地）

### 立即落地（零成本，流程改进）

**应用 1：错误记忆分层**
- 2026-09-12.md 从流水账改为三段：patterns（本批沉淀的可复用教训，如"断言候选必须在 Linux 工件实测""夹具注释勿写带引号取值串"）/ decisions（本批架构选择及理由，如"窄化按 id 枚举豁免"）/ errors（本批错误及修复，如"EV-MEM-017 断言 _Znwm 实际 _Znwy"）
- 每批结束由监工整理，新 Agent 启动时读 patterns 层（比读全部记忆快）

**应用 2：回归强化提示**
- 红队发现新逃逸时，报告模板强制包含"此逃逸应成为哪条规则的毒样例"字段
- 建设者修复时自动检查毒样例是否已回填，缺则提示

**应用 3：建设者提交前自检三问**
- ①我的 claim 可能错在哪？②错的证据长什么样（我该怎么验证）？③如果红队攻击我的卡，最可能打哪？
- 这是"元认知最小落地"，和 374 正反论证强制合并

### 中期落地（需少量工程）

**应用 4：经验→启发式自动提炼**
- 每批门禁结果（哪些卡 refute、哪些毒样例失败、哪些红队发现）结构化汇总
- 一个"提炼 Agent"（小模型即可）从失败记录中提取候选规则，监工裁决后进 gate
- 对应 D 类"修正编译闭环"的自动化第一步

**应用 5：规则→毒样例覆盖率自动检查**
- 每条规则绑定 ≥1 个毒样例（现在是手动的）
- gate 检查规则是否有毒样例覆盖，缺则 warn（这其实已部分实现：RULE-COVERAGE 26% 登记）

### 长期落地

**应用 6：技能自动演进**
- 数据量足够后（≥数百次任务），按 Memento-Skills 模式：持续失败的技能 → 触发重写；新任务超出库范围 → 触发发现
- 这是"让 Agent 设计 Agent"的入口，也是递归自改进的前置

## 九、局限与后续

- 自动提炼规则（应用 4）必须小步验证：先只提炼"warn 级候选"，人审后才升 block。否则机器会自己引入坏规则。
- 三层记忆（应用 1）需要和现有 2026-09-12.md 兼容，不另起炉灶——建议从下一批开始，用新格式维护，旧内容不迁移。
- 递归自改进是终极目标，但**先决条件是工具链本身稳定**（语义自律落地+规则数稳定+绕过测试通过）。在此之前，自动改规则是危险的。
- 本调研未覆盖"多 Agent 协作中的学习共享"（一个 Agent 学到的教训如何被其他 Agent 继承）——那是分布式记忆问题，当前单机多会话场景通过记忆文件共享，已够用。
