# 306_原子知识图谱与关系网络架构调研_从扁平列表到可导航知识体系

> 2026-09-12 · 当前 23 颗原子是扁平列表，关系只有 prerequisites/contrasts 两类。
> 本文调研如何构建原子知识图谱，发现知识空白、检测重复、支持导航。
> 关联：atoms/（23 颗）· gate_engine ATOM-REL-TARGET/ATOM-REL-DAG 规则 · M1_ontology

## 一、现状诊断

### 1.1 原子分布

| 域 | 原子数 | 编号 |
|---|---|---|
| MEM（内存） | 18 | MOVE-002, RVREF-001, VALUE-001/002, PERF-001/002/003/004, RAII-001/002, NEW-001, UNIQUE-001/002, SHARED-001/002, WEAK-001, ALLOC-002, LEAK-001/002 |
| UB（未定义行为） | 1 | UB-GRAY-001 |
| HIST（历史） | 1 | HIST-AUTOPTR-001 |
| CONC（并发） | 0 | — |
| COMP（编译器） | 0 | — |
| NET（网络） | 0 | — |

**问题**：MEM 域 18 颗（78%），其他域几乎空白。知识结构严重不均衡。

### 1.2 关系类型统计

| 关系类型 | 使用原子数 | 占比 |
|---|---|---|
| prerequisites | 24 | 100%（每颗都有） |
| contrasts | 24 | 100%（每颗都有） |
| related | 0 | 0% |
| builds_on | 0 | 0% |
| depends_on | 0 | 0% |

**问题**：关系类型单一，只有"前置"和"对比"。缺少：
- `builds_on`：在某原子基础上扩展（如 PERF-004 builds_on PERF-001 的性能方法论）
- `related`：相关但非前置/对比（如 LEAK-001 related LEAK-002）
- `refutes`：反驳某原子的结论（如 UB-GRAY-001 refutes 某常见误解）
- `supersedes`：替代某原子（如新版原子替代旧版）
- `example_of`：某概念的具体实例（如 UNIQUE-001 是 RAII-001 的 example_of）

### 1.3 关系质量问题

1. **ATOM-REL-TARGET 预存债 4 条**：原子 relations 指向不存在的原子（如 MOVE-002 指向 VALUE-001/PERF-001，在它们锻造之前）
2. **无环检测**：ATOM-REL-DAG 规则检查是否有环，但当前关系简单，没有触发过
3. **关系不可导航**：读者无法从一颗原子跳转到相关原子，因为 relations 只是 frontmatter 字段，没有渲染为链接
4. **知识空白不可见**：无法从图谱中看出"哪个域还没有原子""哪个概念没有覆盖"

## 二、知识图谱设计

### 2.1 扩展关系类型

| 关系类型 | 语义 | 示例 | 方向 |
|---|---|---|---|
| `prerequisites` | 理解本原子需要先理解的原子 | PERF-004 prerequisites [PERF-001] | 有向 |
| `contrasts` | 与本原子形成对比的原子 | UNIQUE-002 contrasts [SHARED-002] | 无向 |
| `builds_on` | 在某原子基础上扩展/深化 | PERF-004 builds_on [PERF-001] | 有向 |
| `related` | 相关但非前置/对比 | LEAK-001 related [LEAK-002] | 无向 |
| `example_of` | 本原子是某概念的具体实例 | UNIQUE-001 example_of [RAII-001] | 有向 |
| `refutes` | 本原子的结论反驳某原子/误解 | UB-GRAY-001 refutes [MIS-UB-001] | 有向 |
| `supersedes` | 本原子替代某旧原子 | (暂无) | 有向 |

**约束**：
- `prerequisites` 和 `builds_on` 必须形成 DAG（无环）
- `contrasts` 和 `related` 是无向的（A contrasts B ⟺ B contrasts A）
- `example_of` 是多对一的（多个原子可以是同一个概念的实例）

### 2.2 关系自动推断

部分关系可以从原子内容自动推断：

| 关系 | 推断规则 | 置信度 |
|---|---|---|
| `related` | 两颗原子的 serves 指向同一夹具，或 hypothesis 有共同关键词 | 中 |
| `contrasts` | 两颗原子的 claim 是对立的（如"A 比 B 快" vs "B 比 A 快"） | 中 |
| `example_of` | 原子的 type 是 mechanism/pitfall，且引用了某 concept 原子 | 低 |
| `builds_on` | 原子的 hypothesis 引用了另一原子的结论（如"在 PERF-001 的基础上"） | 高 |

**实现**：写一个 `tools/atom_graph.py` 工具，扫描所有原子的 frontmatter 和正文，自动建议关系，Writer/红队审核后确认。

### 2.3 知识空白发现

基于图谱，可以自动发现知识空白：

1. **域空白**：某个域（如 CONC/COMP/NET）原子数为 0
2. **概念空白**：某个高频概念（如"内存序""锁""无锁"）没有对应原子
3. **关系空白**：某颗原子只有 prerequisites，没有 contrasts/related（孤立节点）
4. **深度空白**：某条知识链只有 1-2 层（如 RAII-001 → UNIQUE-001，但没有更深的扩展）
5. **对比空白**：某颗原子没有 contrasts（缺少对照视角）

**输出**：`docs/knowledge_gaps.md`，定期更新，列出当前知识空白和建议的下一批原子。

### 2.4 重复检测

基于图谱，可以检测潜在重复：

1. **claim 相似**：两颗原子的 claim 语义高度重叠（用关键词重叠度或 embedding 相似度）
2. **夹具相同**：两颗原子使用同一夹具（可能是不同角度，也可能是重复）
3. **证据卡相同**：两颗原子引用同一证据卡（可能是合理共享，也可能是重复）
4. **误解相同**：两颗原子关联同一误解（可能是合理共享，也可能是重复）

**输出**：`docs/duplicate_candidates.md`，列出潜在重复的原子对，供红队审核。

## 三、图谱可视化与导航

### 3.1 静态图谱（HTML/SVG）

生成一个 `docs/atom_graph.html`，展示所有原子的关系网络：
- 节点 = 原子，颜色按域区分（MEM=蓝，UB=红，HIST=绿，CONC=橙）
- 边 = 关系，不同线型区分（prerequisites=实线，contrasts=虚线，builds_on=箭头）
- 节点大小 = 证据卡数量（越多越大）
- 点击节点显示原子摘要

**技术**：纯 HTML/SVG + 少量 JS（力导向布局或分层布局）。

### 3.2 原子内导航

在每颗原子的正文中，把 relations 渲染为可点击链接：
```markdown
## 关系
- 前置：[PERF-001](ATOM-MEM-PERF-001.md) — 性能方法论
- 对比：[UNIQUE-002](ATOM-MEM-UNIQUE-002.md) — 删除器类型系统
- 扩展：[PERF-003](ATOM-MEM-PERF-003.md) — 小对象分配器
```

当前 frontmatter 的 relations 是机器可读的，但正文没有渲染。可以在原子模板中增加"关系"节，自动从 frontmatter 生成。

### 3.3 域导航页

为每个域生成一个 `atoms/<domain>/README.md`，列出该域的所有原子，按主题分组，标注关系：

```markdown
# MEM 域原子（18 颗）

## 值类别与移动（4 颗）
- VALUE-001 值类别五分类
- VALUE-002 引用折叠与完美转发（builds_on VALUE-001）
- MOVE-002 移动语义机制
- PERF-001 移动性能量化（contrasts MOVE-002）

## RAII 与智能指针（6 颗）
- RAII-001 RAII 与异常安全
- UNIQUE-001 unique_ptr 转移（example_of RAII-001）
- ...
```

## 四、工具设计

### 4.1 tools/atom_graph.py

**功能**：
1. 扫描所有原子的 frontmatter，提取 relations
2. 验证关系完整性（ATOM-REL-TARGET 检查）
3. 验证无环（ATOM-REL-DAG 检查）
4. 自动建议关系（基于关键词/夹具/证据卡重叠）
5. 发现知识空白（域/概念/关系/深度/对比）
6. 检测潜在重复
7. 生成图谱 HTML

**用法**：
```bash
python tools/atom_graph.py --check          # 验证关系完整性
python tools/atom_graph.py --suggest        # 自动建议关系
python tools/atom_graph.py --gaps           # 发现知识空白
python tools/atom_graph.py --duplicates     # 检测潜在重复
python tools/atom_graph.py --render         # 生成图谱 HTML
```

### 4.2 与 gate_engine 的关系

当前 gate_engine 已有：
- ATOM-REL-TARGET：关系目标必须存在
- ATOM-REL-DAG：关系必须无环
- ATOM-PREREQ-READABLE：前置原子必须可读

atom_graph.py 可以扩展这些检查，并增加：
- ATOM-REL-TYPE：关系类型必须在允许的枚举中
- ATOM-REL-SYMMETRIC：contrasts/related 必须双向声明（A contrasts B ⟹ B contrasts A）
- ATOM-ISOLATED：原子不能没有任何关系（孤立节点）

## 五、实施路径

### 5.1 第一阶段（关系扩展 + 验证工具）

1. 扩展关系类型枚举（增加 builds_on/related/example_of/refutes/supersedes）
2. 更新原子模板，增加"关系"节
3. 写 tools/atom_graph.py --check（验证关系完整性）
4. 为现有 23 颗原子补全关系（当前只有 prerequisites/contrasts）

### 5.2 第二阶段（知识空白 + 重复检测）

1. atom_graph.py --gaps（发现知识空白）
2. atom_graph.py --duplicates（检测潜在重复）
3. 生成 docs/knowledge_gaps.md
4. 用知识空白指导第六批选题（如 CONC 域空白）

### 5.3 第三阶段（可视化 + 导航）

1. atom_graph.py --render（生成图谱 HTML）
2. 为每个域生成 README.md
3. 原子正文增加"关系"节
4. 自动建议关系（atom_graph.py --suggest）

## 七、与其他系统的关系

### 7.1 与 Writer 预防机制（303）的关系

- Writer 在写新原子前，先查 atom_graph.py --gaps，了解知识空白
- Writer 在写 relations 时，atom_graph.py --suggest 可以自动建议相关原子
- 减少 ATOM-REL-TARGET 预存债（关系指向不存在的原子）

### 7.2 与红队（305）的关系

- 红队在审查时，用 atom_graph.py --duplicates 检查是否与已有原子重复
- 红队用 atom_graph.py --gaps 检查新原子是否填补了知识空白
- 红队的"与既有证据实质重复"检查（can't-miss 第 10 条）可以工具化

### 7.3 与 Book 教材的关系

- 原子图谱可以指导 Book 的章节结构
- 知识空白 = Book 的待写章节
- 原子关系 = Book 的交叉引用

---

*核心结论：23 颗原子当前是"扁平列表 + 两类关系"，知识结构不可见、空白不可发现、重复不可检测。扩展关系类型（7 类）+ atom_graph.py 工具（验证/建议/空白/重复/可视化）可以把原子库从"文件集合"升级为"可导航知识体系"。这不仅是组织工具，更是选题指导——知识空白直接告诉我们下一批该做什么。*
