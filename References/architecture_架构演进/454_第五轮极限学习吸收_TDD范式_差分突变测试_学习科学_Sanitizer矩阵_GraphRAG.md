# 454 第五轮极限学习吸收：TDD范式、差分/突变测试、学习科学、Sanitizer矩阵、GraphRAG

> 日期：2026-09-13。对抗模型正在跑 452，本轮并行调研五个未深挖方向。严格执行 453 的证据标准：每条标注证据等级（一手实验/元分析/社区实践/营销站），落地项按"立即可做/待验证假设/驳回"三级分类，不拿业界背书代替论证。

## 一、TDD + LLM：阙疑已经在做，但顺序反了

### 1.1 外部发现（证据等级：一手论文 + 社区实践）

- **Test-Oriented Programming (TOP)**（ACM 2026-09，一手）：GenAI 时代的新范式——开发者只检查测试代码，生产代码完全交给 LLM。核心洞察：LLM 生成的生产代码不可信，但 LLM 生成的测试代码如果人审过，就可以作为可执行规格驱动生成。
- **T_ENET**（arXiv 2509.24148，2026-08 更新，一手）：仓库级 TDD 框架三要素——①specification enhancement（从大测试集中找代表性子集）②retrieval augmentation（用测试引导上下文检索）③test-driven refinement（解释测试失败信号迭代改进）。
- **Tests as Prompt**（arXiv 2505.09027，一手）：WebApp1K 基准，测试用例同时作为 prompt 和验证，1000 题 20 域。
- **Property-Based Testing (PBT)**（ACM 3696630，一手）：用 Hypothesis 生成属性测试，比手写单元测试更系统——测试的是"属性"（如"对任意输入 x，f(x) == f(f(x))"）而非"具体输入输出对"。
- **社区实践**（CSDN 2026-06，二手）：测试用例成为 LLM 唯一输入指令源，金融/医疗/IoT 场景回归失败率从 18% 压到 0.7%。证据等级低（无对照实验），但方向与论文一致。

### 1.2 对阙疑的意义

**阙疑的夹具设计本质上就是 TDD**——断言（artifact_assert/run_match）是测试，夹具是实现。但当前顺序是**先写夹具再写断言**，这是反的。

**落地项 T1（立即可做，零成本）**：夹具生产流程改为"断言先行"——
1. 先写 claim 和 falsification（要证什么、怎么证伪）
2. 再写 artifact_assert/run_match（断言长什么样）
3. 最后写夹具让断言通过
这和 TDD 的"红→绿→重构"同构：先写会失败的断言（红），再写夹具让它通过（绿），最后优化夹具（重构）。

**落地项 T2（待验证假设）**：Property-Based Testing 升级夹具的 metamorphic relation。443 提过夹具的 metamorphic_relation 字段，但目前是自然语言描述。PBT 的思路是把属性写成可执行的——比如"对任意 n，arena 元数据不随 n 变"（ALLOC-002 的活性对照就是这个属性的手工实例）。v8.0 试点：选 1 颗原子，把 metamorphic relation 写成可执行的 QuickCheck 式属性。

**落地项 T3（待验证假设）**：TOP 范式的"人审测试不审实现"——阙疑的人审目前审的是原子卡（claim+证据），不是夹具。如果断言先行且人审断言，夹具可以完全交给 Agent 生成——这可能大幅提升吞吐。但需要验证：人审断言的成本是否低于人审夹具+断言？

## 二、差分测试 + 突变测试：断言判别力的量化方法

### 2.1 外部发现（证据等级：一手论文，硬数据）

- **TyMut**（SPLASH 2025 OOPSLA，一手）：类型驱动突变 fuzz C++ 编译器，发现 102 个 bug（56 个新确认，50%+ 是 miscompilation，7 个隐藏 20+ 年，22 个隐藏 10+ 年）。核心方法：must analysis 为 80% 生成程序提供确定测试 oracle。
- **Mut4All**（arXiv 2507.19275，一手）：LLM 从 bug report 学习合成突变器，GCC/Clang 34 bug（17 新），Rust 62 bug（41 新）。
- **跨编译器数值不一致**（arXiv 2509.00256，一手）：LLM 生成程序，对比 GCC/Clang 不同优化档的浮点输出，发现位级不一致。
- **单编译器差分测试**（arXiv 2501.00655，一手）：同一编译器不同版本对比，发现代码大小优化回归。

### 2.2 对阙疑的意义

这是本轮最有价值的发现——**直接解决 402 的核心问题**。

402 F03："contains_in/absent_in 的 text 字段不受通用符号约束，mov/ret 任何函数恒有，中文句 asm 恒 0 次"——本质是**断言判别力不足**：断言通过不代表 claim 成立，因为断言太弱了。

**突变测试是量化断言判别力的标准方法**：对夹具做受控突变（改一个语义关键点），如果断言仍然通过，说明断言判别力不足（杀不死突变体）；如果断言失败，说明断言能区分正确与错误实现。

**落地项 D1（立即可做，高价值）**：对每颗新原子的断言，做"突变体杀灭测试"——
1. 取夹具的 .cpp，手动改 1-2 个关键语义点（如把 `==` 改成 `!=`、把 `1` 改成 `0`、删掉活性对照）
2. 重编译、重跑 replay
3. 如果断言仍 confirm → 断言判别力不足，标 weak，必须加强
4. 如果断言 refute → 断言有判别力
这不是新工具，是手工流程，可以立即用在 CONC-003 等新原子上。

**落地项 D2（待验证假设）**：多编译器差分测试升级双平台验证。阙疑目前是 Windows MinGW + WSL GCC 双平台 confirm。可以加第三列：同一夹具在 GCC -O0 vs -O2 的输出对比——如果输出不同，说明有 UB 或实现定义行为（这本身就是教学点）。但需要 Clang 才能做真正的多编译器差分（当前无 Clang），所以先做 GCC 内多档位差分。

**落地项 D3（待验证假设）**：把突变测试自动化。v8.0 写一个 mutation_tester.py：对夹具的 .cpp 做 AST 级突变（==→!=、+→-、1→0 等），批量重编译重跑，输出"突变体杀灭率"。杀灭率 < 80% 的断言自动标 weak。这是对 446"规则质量评估"的具体化。

## 三、学习科学：教学转化的硬证据

### 3.1 外部发现（证据等级：元分析 + 大样本随机试验，最强）

- **间隔重复 meta-analysis**（2026-01，14 研究 21415 学习者，一手元分析）：SMD=0.78，大效应。Dunlosky 2013 经典综述在十种学习技术中只给间隔重复和主动回忆评"高效用"。
- **主动回忆**（Roediger & Karpicke 2006，经典实验）：一周后保留率 80%（自测组）vs 34%（重读组），相同学习时间。Adesope 2017 元分析：Hedges' g=0.61。
- **测试效应/forward testing effect**（Assadipour 2025，一手）：测试不仅是评估，还加速后续编码——"先测再学"比"先学再测"效果好。
- **LLM 增强间隔重复**（ASEE 2025，33 学生试点，一手但样本小）：平均分高 18.2%，中位数高 33.2%。
- **Price et al. 2025**（26258 医生随机试验，一手大样本）：之前答错的题后来 58% 正确 vs 43% 对照（d=0.62）。
- **desirable difficulty**（Bjork 经典理论）：学习时感觉越难，长期保留越好——错误示例、交错练习、间隔都是"合意困难"。

### 3.2 对阙疑的意义

阙疑的教学转化（405 四层：闪卡/MCQ/学习路径DAG/错误示例）有了硬证据支持，但需要修正设计：

**落地项 L1（立即可做）**：闪卡必须是主动回忆设计——正面是问题（"什么是 false sharing？"），背面是答案+证据卡链接。**不能**是"正面概念+背面解释"的被动阅读卡（那是重读，效果 34%）。
- 证据：Roediger 2006，80% vs 34%。

**落地项 L2（立即可做）**：错误示例（misconceptions）是"desirable difficulty"的最佳载体——先让学生判断"这段代码有什么问题"，再给正确解释。比直接给正确答案更有效。阙疑已有 80 条 MIS，但闪卡导出时应该把 MIS 做成"找错"题型而非"陈述"题型。
- 证据：Bjork desirable difficulty + Price 2025（答错后再纠正的保留率更高）。

**落地项 L3（待验证假设）**：间隔重复算法内置。闪卡工具（408 已做？状态待核实）应该支持 SM-2 算法（Anki 同款）：答对的卡间隔拉长，答错的卡缩短。但这需要用户数据（答题记录），当前阙疑没有用户系统——v9.0 考虑。

**落地项 L4（待验证假设）**：交错练习。学习路径 DAG 不应是"学完 A 再学 B"的线性路径，应该支持交错（A1→B1→A2→B2）。证据：交错练习比集中练习长期保留好，但短期感觉更差。需要 v8.0 学习路径工具支持。

## 四、Sanitizer 矩阵：从"用到了"到"系统化"

### 4.1 外部发现（证据等级：官方文档 + 社区手册，事实级）

- **UBSan**：有符号溢出、空指针解引用、错位指针、越界数组（静态可判定时）、无效移位、浮点转换溢出。`-fno-sanitize-recover=all` 让 UB 直接崩溃而非打印继续。
- **ASan**：影子内存，堆/栈/全局越界、use-after-free、use-after-return、内存泄漏（LSan 内置）。
- **TSan**：数据竞争，需 `setarch -R`（阙疑已知）。
- **MSan**：未初始化内存读取，**仅 Clang**（阙疑当前无 Clang，永久边界）。
- **组合限制**：ASan 和 TSan 不能组合；ASan+UBSan 可以；TSan+UBSan 可以。
- **Clang Static Analyzer**：编译期静态分析，与运行期 sanitizer 互补。

### 4.2 对阙疑的意义

阙疑已经在用 ASan/UBSan/LSan/TSan，但用法是"需要时加"，不是系统化。

**落地项 S1（立即可做）**：Sanitizer 矩阵写入夹具方法论 v2.0（443）——按原子类型规定必须跑的 sanitizer：
| 原子类型 | 必须跑 | 原因 |
|---|---|---|
| UB 类（ATOM-UB-*） | UBSan `-fno-sanitize-recover=all` | UB 必须可观测 |
| 内存类（ATOM-MEM-*） | ASan + LSan | 内存错误+泄漏 |
| 并发类（ATOM-CONC-*） | TSan（WSL setarch -R）+ UBSan | 数据竞争+UB |
| 性能类（ATOM-MEM-PERF-*） | 无（sanitizer 影响性能） | 但需声明 |
- 证据：官方文档，事实级。

**落地项 S2（立即可做）**：UBSan 加 `-fno-sanitize-recover=all`。当前 UB 类原子可能用了默认的"打印后继续"，这会让 UB 看起来"正常运行"。加这个 flag 后 UB 直接 abort，replay 会拿到非零退出码——更强的"UB 可观测"。
- 注意：这会改变现有 UB 类原子的 .out，需要重生成。先试点 1 颗。

**落地项 S3（待验证假设）**：Clang Static Analyzer 集成。当前无 Clang，永久边界。但可以在 CI 中加 Clang CSA 步骤（如果 CI 环境有 Clang）。待核实 CI 环境。

## 五、GraphRAG + 语义检索：v10+ 的事，但现在可以打底

### 5.1 外部发现（证据等级：一手论文 + 行业标准）

- **GraphRAG**（微软 2024，2026 持续演进）：知识图谱 + 向量检索混合，用 RRF（Reciprocal Rank Fusion）融合两路排名。
- **RAGAS**（2026 事实标准）：四指标——faithfulness（答案基于检索上下文）、answer relevancy、context precision、context recall。目标值：faithfulness >0.9、relevancy >0.85、precision >0.80、recall >0.85。
- **GLM-RAG**（arXiv 2607.28397，2026-08，一手）：图语言模型做图检索。
- **混合检索**：向量 + 图谱 + 关键词三路，RRF 融合（k=60 标准超参）。

### 5.2 对阙疑的意义

阙疑的知识检索目前是 grep/文件系统，这在 27 颗原子时够用，但到 100+ 颗时会不够。

**落地项 R1（待验证假设，v9.0）**：原子卡的 relations DAG 已经是知识图谱雏形——prerequisite/specializes/realizes/evolved_from/contradicts（417 已加）。可以做 GraphRAG：用户问"什么是 false sharing"，不仅返回 PERF-004，还返回它的 prerequisite（PERF-001）、contrasts（PERF-003）、相关 MIS。这比 grep 强。
- 但需要 embedding 模型（算力），零预算约束下是 v10+。

**落地项 R2（立即可做，零成本）**：RAGAS 的 faithfulness 指标可以直接用于阙疑的教学产物——闪卡/MCQ 的答案必须能在证据卡中找到出处。这是"无锚不入"（铁律 10）在教学侧的延伸。

## 六、本轮元批判（按 453 标准）

### 真增量（改变做法）

1. **断言先行（T1）**：当前夹具生产顺序反了，改成"先断言后夹具"是 TDD 的核心，零成本且可能减少"断言写死常量"类问题（ALLOC-002 H4 的根因就是先写夹具后补断言，断言抄了夹具的编译期常量）。
2. **突变体杀灭测试（D1）**：直接解决 402 F03（断言判别力不足），这是目前最痛的工具债之一。手工流程立即可用。
3. **Sanitizer 矩阵（S1）+ UBSan abort（S2）**：从"用到了"到"按类型强制"，S2 让 UB 真正可观测。
4. **闪卡主动回忆设计（L1）+ 错误示例找错题型（L2）**：教学转化从"有产物"到"有证据支持的设计"。

### 换术语（已有实践获得学名）

- TDD/TOP → 阙疑早已在做（断言+夹具），只是顺序反了
- PBT → 443 的 metamorphic_relation 是自然语言版，PBT 是可执行版
- GraphRAG → relations DAG 是图谱雏形，缺向量检索

### 明确不采纳/推迟

- MSan（无 Clang，永久边界）
- 间隔重复算法（需用户系统，v9.0）
- 向量检索/embedding（需算力，v10+）
- 多编译器差分（无 Clang，先做 GCC 内多档位差分）

### 证据越界警示

- "回归失败率 18%→0.7%"来自 CSDN 博客，无对照实验，**不引用为证据**，只作方向参考。
- "LLM 增强间隔重复 18.2%/33.2%"来自 33 人试点，样本小，**只作假设不作规格**。
- RAGAS 目标值（>0.9/>0.85）是行业惯例，不是阙疑场景验证过的，**只作参考**。
