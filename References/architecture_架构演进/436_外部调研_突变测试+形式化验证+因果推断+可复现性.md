# 436 外部调研：突变测试 + 形式化验证 + 因果推断 + 可复现性

> 日期：2026-09-13。继续上压力，从四个方向做外部调研。这四个方向都与阙疑的核心问题直接相关：gate 规则质量、claim 可验证性、夹具设计理论、双平台 replay。

## 一、突变测试（Mutation Testing）

### 核心思想

给代码引入人工 bug（变异体），看测试能不能发现。如果测试发现了（杀死了变异体），说明测试有效；如果没发现（变异体存活），说明测试有盲区。

**变异得分** = 杀死的变异体 / (总变异体 - 等价变异体)

| 得分范围 | 含义 |
|---|---|
| 0-30% | 严重缺口，测试几乎没测任何东西 |
| 30-60% | 弱测试，只覆盖 happy path |
| 60-80% | 不错，大部分逻辑被测了 |
| 80%+ | 非常健壮的测试套件 |

### 等价变异体问题

有些变异体产生与原代码相同的行为（如 `a + 0` → `a`），这些是"等价变异体"，不算测试盲区。需要人工或工具识别。

### 与阙疑的关系

**阙疑的毒样例 = 变异体，gate 规则 = 测试，拦截率 = 变异得分。**

- 毒样例 P1-P33 就是人工构造的"变异体"（违规的卡/夹具/工件）
- gate 规则就是"测试"，看能不能拦住这些变异体
- 拦截率就是"变异得分"——402 对抗的 35% 拦截率，相当于突变测试的 35% 变异得分
- 419 攻击用例库就是"真实变异体库"——从三次对抗中收集的真实攻击用例

### 对阙疑的启示

1. **gate 规则的质量应该用突变测试来评估**——不只是"规则数"，而是"拦截率"
2. **等价变异体问题在阙疑中存在**——有些"违规"的卡其实是合法的（如 EV-MEM-035 的 absent lock），需要识别
3. **突变测试可以自动生成毒样例**——用 LLM 自动生成变异体，然后看 gate 能不能拦住，拦不住的就是新毒样例
4. **402 的 35% 拦截率相当于突变测试的 35% 得分**——这是"弱测试"水平，目标应该是 60%+

## 二、形式化验证（Formal Verification）

### 核心思想

用数学推理证明或反驳程序的正确性。与测试不同，形式化验证穷举所有可能的输入和状态，给出"数学证明"或"具体反例"。

### 主要方法

| 方法 | 核心做法 | 结论含义 |
|---|---|---|
| BMC（有界模型检查） | 把转移关系展开 k 步，问"第 k 步能否违反属性？" | SAT→找到 bug；UNSAT→只证明前 k 步安全 |
| K-Induction | 假设前 k 步满足，再要求下一步也满足 | UNSAT→证明永远安全 |
| SMT solver | 把约束编码为 SMT-LIB2，用 Z3/CVC5 求解 | SAT→反例；UNSAT→证明 |
| 契约编程 | requires/ensures/invariant 标注，自动验证 | 每个函数的契约独立验证 |

### 与阙疑的关系

**阙疑的 claim 契约化（precondition/assertion/invariant/falsification）就是形式化验证的轻量版。**

- precondition = requires（前置条件）
- assertion = ensures（后置条件）
- invariant = invariant（不变量）
- falsification = 反例条件

但阙疑当前只做了"结构检查"（有没有这四段），没有做"逻辑验证"（这四段在逻辑上是否一致、是否可满足）。

### 对阙疑的启示

1. **claim 的逻辑一致性可以用 SMT solver 验证**——precondition 和 invariant 是否矛盾？assertion 是否可满足？
2. **契约编程可以应用于夹具设计**——夹具的函数可以标注 requires/ensures，自动验证
3. **形式化验证是 v8.0 L4 语义验证的方向**——当前 L1-L3 是结构/内容/逻辑验证，L4 语义验证需要形式化方法
4. **但形式化验证的成本很高**——阙疑应该从"轻量形式化"开始（claim 契约化），逐步深化

## 三、因果推断（Causal Inference）

### 核心思想

潜在结果框架（Rubin Causal Model）：对于每个个体 i，有两个潜在结果：
- Y(1)：接受处理后的结果
- Y(0)：未接受处理的结果

个体处理效应（ITE）= Y(1) - Y(0)
平均处理效应（ATE）= E[Y(1) - Y(0)]

**关键问题**：我们只能观察到 Y(1) 或 Y(0) 中的一个，不能同时观察到两者——这就是"因果推断的基本问题"。

解决方法：随机化（处理分配独立于潜在结果）、控制混杂、匹配、倾向得分。

### 与阙疑的关系

**阙疑的"单变量对照"夹具本质上是因果推断实验。**

- 处理（Treatment）= 改变一个变量（如布局从 tight 改为 padded）
- 结果（Outcome）= 性能变化（如运行时间）
- 处理效应（ATE）= Y(tight) - Y(padded) = 18.86×
- 控制变量（Controls）= 其他所有变量保持不变（线程数、迭代数、编译器、优化档）

阙疑的"唯一变量"原则就是因果推断的"可识别性"条件——只有处理变量变化，其他变量不变，才能把结果变化归因于处理。

### 对阙疑的启示

1. **夹具设计应该遵循因果推断的原则**——随机化执行顺序（消除顺序效应）、控制混杂变量、明确处理和对照
2. **性能数据应该报告 ATE + 置信区间**——不只是"中位数比值"，而是"平均处理效应 + 95% CI"
3. **"唯一变量"原则需要机器验证**——gate 规则可以检查夹具是否真的只有一个变量变化（通过 diff 两个版本的源码）
4. **反事实（Counterfactual）思维**——claim 应该明确"如果不做这个处理，结果会怎样"，这就是 falsification 段

## 四、可复现性（Reproducibility）

### 核心要求

| 维度 | 要求 | 阙疑当前 |
|---|---|---|
| 环境锁定 | Docker、OS 版本、库版本固定 | 只有编译器版本，无 OS/库锁定 |
| 随机种子 | 所有 PRNG 设种子，记录在输出中 | 性能夹具无种子（但 C++ 程序本身确定性） |
| 数据版本化 | 数据集 checksum、DVC | 工件 sha256 ✅ |
| 配置即代码 | 所有参数在版本控制的配置文件中 | command 字段 ✅ |
| 构建确定性 | 相同输入产生相同输出 | 工件 sha 可复现 ✅ |
| 环境记录 | CPU 型号、核心数、内存、OS | 部分（nproc 有，CPU 型号无） |

### Hermetic Build（密封构建）

Docker 不等于密封构建。密封构建要求：
- 基础镜像用 digest pinning（不是 floating tag）
- 依赖预先下载并校验 checksum
- 构建工具版本精确指定
- 时间戳固定或移除
- 只允许确定性操作
- 内容寻址存储

### 与阙疑的关系

**阙疑的双平台 replay 就是可复现性的实践，但还不够严格。**

- Windows MinGW 和 WSL g++ 两个平台各跑一次 ✅
- 工件 sha256 记录在卡中 ✅
- command 字段记录构建命令 ✅
- 但没有记录 CPU 型号、OS 版本、库版本 ❌
- 性能数据没有环境控制（CPU 负载、电源模式）❌

### 对阙疑的启示

1. **性能卡必须记录完整环境信息**——CPU 型号、核心数、OS 版本、编译器版本、优化档、电源模式
2. **构建环境可以用 Docker 锁定**——但阙疑当前是本机构建，Docker 化是 v8.0 的事
3. **工件 sha256 已经是很好的实践**——继续保持
4. **可复现性检查可以自动化**——gate 规则检查卡中是否有环境信息字段

## 五、四大方向对阙疑的综合影响

| 方向 | 对阙疑的核心贡献 | 落地优先级 |
|---|---|---|
| 突变测试 | gate 规则质量用拦截率评估，毒样例=变异体 | P1（419 已在建） |
| 形式化验证 | claim 契约化深化，SMT 验证逻辑一致性 | P2（v8.0 L4） |
| 因果推断 | 夹具设计的理论基础，ATE+CI 报告 | P0（性能卡统计升级） |
| 可复现性 | 环境信息完整记录，构建确定性 | P1（性能卡环境字段） |

### 最紧急的发现

**因果推断 + 可复现性 = 性能卡统计严谨性的理论基础。**

PERF-004 的问题本质上是：
1. 没有遵循因果推断的原则（没有随机化、没有报告 ATE+CI）
2. 没有遵循可复现性的要求（没有记录完整环境信息）

这两个方向的结合，给出了性能卡 v2.0 规范的完整理论基础。

### 最有价值的框架

**突变测试 = gate 规则质量评估的方法论。**

阙疑一直在数"规则数"（42 条）和"毒样例数"（47 条），但真正的质量指标是"拦截率"——突变测试给出了这个指标的计算方法和评估标准（35%=弱，60%+=不错，80%+=健壮）。

402 对抗的 35% 拦截率，用突变测试的标准看，就是"弱测试"水平——这明确了阙疑的改进目标。
