# 415 阙疑知识图谱推理与跨域迁移：从静态 relations 到可推理的知识系统

> 日期：2026-09-13。外部调研：CCCE 双向影响分析（知识图谱遍历+自适应决策门控）、CASCADEKG 级联更新（γ^k 多跳加权）、GraphOracle 关系依赖图（RDG）、传递闭包（A→B+B→C⇒A→C）、跨域 ICL 示例吸收阈值、ANALOGYKB 百万级类比库、IsoSci 同构跨域基准（91.3% 推理增益是知识依赖的）、Echo 五维分解（结构/属性/过程/功能/交互）、DOCER 过时引用检测、文档腐烂三类型（引用漂移/概念陈旧/结构衰变）。
> 研究问题（411 SOP）：阙疑 27 颗原子之间的静态 relations 能否升级为可推理的知识图谱？哪些推理可以零 LLM 实现？跨域知识迁移如何避免"纯结构类比"的陷阱？

---

## 一、阙疑知识图谱现状

当前 27 颗原子，每颗声明 relations（prereq/contrasts/contradicts/serves），但：

| 能力 | 现状 | 缺口 |
|---|---|---|
| 关系声明 | ✅ 每颗有 relations | 静态，无推理 |
| 悬空引用检测 | ⚠️ 部分（ATOM-REL-TARGET） | 只检查目标存在，不检查矛盾/循环 |
| 影响分析 | ❌ 无 | 改了 A，不知道哪些受影响 |
| 传递闭包 | ❌ 无 | A→B+B→C 不推导 A→C |
| 矛盾检测 | ❌ 无 | A.prereq=B 且 B.contradicts=A 不报警 |
| 跨域迁移 | ❌ 无 | MEM 教训不自动应用到 CONC |
| 文档腐烂 | ⚠️ 部分（sha 校验） | 不检查引用的夹具/卡是否还存在 |

**核心问题**：relations 是"装饰"不是"基础设施"——写了但不用。

## 二、L1 结构检查（零 LLM，可立即转苦力实现）

### 5 种检测，全部纯图遍历

| 检测 | 判据 | 级别 | 现有规则 |
|---|---|---|---|
| **悬空引用** | relations 中的 ID 在 atoms/ 中不存在 | block | ATOM-REL-TARGET（已有） |
| **serves 悬空** | serves 的概念在 misconceptions/ 中不存在 | warn | EV-SERVES-EXIST（已有，但只 warn） |
| **矛盾关系** | A.prereq 含 B 且 B.contradicts 含 A | block | ❌ 新增 |
| **循环依赖** | A.prereq 含 B 且 B.prereq 含 A（任意长度环） | block | ❌ 新增 |
| **自引用** | A.prereq/contrasts/contradicts 含 A 自身 | block | ❌ 新增 |

### 实现方式
- 解析所有原子的 frontmatter.relations，构建内存图（dict+set，27 颗零开销）
- 深度优先遍历检测环和矛盾
- 新增 gate 规则：`ATOM-REL-CONTRADICTION`、`ATOM-REL-CYCLE`、`ATOM-REL-SELF`
- 这是 404 知识健康维的 L1 层，也是 402 对抗 F07（relations 纯标量静默丢弃）的补全

## 三、L2 影响分析（零 LLM，图遍历）

### 场景：修改/推翻一颗原子，哪些受影响？

CCCE 的双向影响分析算法映射：

```
修改原子 A
  ↓
上游遍历（谁依赖 A）：找所有 prereq/contrasts 链中含 A 的原子
  ↓
下游遍历（A 依赖谁）：找 A 的 prereq/contrasts 链中的所有原子
  ↓
输出：受影响原子列表 + 影响路径 + 优先级
```

### 优先级排序（CASCADEKG 的 γ^k 加权）
- 直接关联（k=1）：最高优先级
- 2 跳关联（k=2）：γ × 优先级
- 3 跳以上（k≥3）：γ² × 优先级，仅提示不阻断
- γ 建议 0.5（每跳衰减一半）

### 工具：tools/impact_analysis.py
```
输入：原子 ID 或 git diff（检测哪些原子被改了）
输出：
{
  "changed": ["ATOM-MEM-PERF-004"],
  "upstream": [
    {"id": "ATOM-CONC-FENCE-001", "path": "PERF-004 → FENCE-001", "hops": 1, "priority": "high"},
    {"id": "ATOM-MEM-RAII-001", "path": "PERF-004 → FENCE-001 → RAII-001", "hops": 2, "priority": "medium"}
  ],
  "downstream": [...],
  "action": "建议复跑受影响原子的 replay + 红队"
}
```

### 集成点
- 修改原子后自动跑（pre-commit hook 或 CI step）
- 人审签署时显示"这颗原子的变更影响 X 颗其他原子"
- 这是 400 问题 4（关键事实持久化）的延伸——不仅记录事实，还推理事实的影响

## 四、L3 传递闭包（零 LLM）

### 隐式依赖推导
- A.prereq=B 且 B.prereq=C ⇒ A 的隐式 prereq 含 C
- 用于学习路径推荐：学 A 之前需要学什么？（完整前置链）
- 用于完备性检查：A 的 claim 依赖 C 的结论，但 A 没声明 C 为 prereq → warn

### 教学转化（405 的 L3 学习路径 DAG）
- 基于传递闭包自动生成学习路径
- 例如：学 CONC-FENCE-001 之前，需要学 MEM-PERF-004（缓存行）→ MEM-ALLOC-002（内存布局）
- 这是 405 教学转化体系的核心数据结构

## 五、L4 跨域迁移（需 LLM，但有结构支撑）

### 关键警告（IsoSci 实证）
**91.3% 的推理模式增益是知识依赖的，不是结构不变的**——纯结构类比（"MEM 有口径问题，所以 CONC 也有"）不够，需要域知识支撑。

### Echo 五维分解（跨域类比的正确方式）
将可复用知识分解为五个维度，逐维匹配：

| 维度 | MEM 实例 | CONC 对应 |
|---|---|---|
| **结构** | 元数据口径不统一 | 内存序定义不统一（acquire/release 在不同编译器的实现） |
| **属性** | pool 元数据 32B vs 8056B | mutex 30ns vs 300ns（不同竞争度） |
| **过程** | 红队发现方向反转 | 红队发现 claim 被工件推翻 |
| **功能** | "元数据换灵活性"的教学结论 | "屏障换顺序性"的教学结论 |
| **交互** | 三策略对比实验 | 三同步原语对比实验 |

### 跨域迁移的正确流程
1. 源域（MEM）提取教训的**五维表示**
2. 在目标域（CONC）找**结构同构**的位置
3. 用目标域的**实测数据**验证（不是直接套用结论）
4. 如果验证通过 → 生成目标域的新原子/误解
5. 如果验证不通过 → 记录"类比失败"（也是有价值的知识）

### 红队的跨域类比攻击
- 用 MEM 的漏洞模式（口径不统一、断言恒真、工件不同代）扫描 CONC 原子
- 这是 409 对抗防御的 A8（间接注入）的反向应用——用已知漏洞模式找未知漏洞

## 六、L5 文档腐烂检测（零 LLM）

### DOCER 映射：阙疑的引用腐烂三类型

| 类型 | 阙疑实例 | 检测方法 |
|---|---|---|
| **引用漂移** | 原子引用的夹具名改了（_atom_conc_fence → _atom_fence_vs_atomic） | 解析原子中的 fixture 字段，检查文件是否存在 |
| **概念陈旧** | 原子 claim 引用的规则号改了（MIS-ID-FORMAT → MIS-LIBRARY） | 解析原子中的规则引用，检查规则是否存在 |
| **结构衰变** | 原子的 relations 指向已废弃的原子 | L1 悬空引用检测 |

### 实现
- 扩展 `EV-MATRIX-UNBACKED`：不仅检查 .out 路径，还检查 fixture/evidence/misconception 引用
- 新增 `ATOM-REF-DEAD`：原子中引用的任何文件/ID 不存在 → warn
- 这是 406 增量知识更新的配套——原子会老，引用会断

## 八、元结论

阙疑的 relations 目前是"写了但不用"——27 颗原子之间的关系只用于展示，不用于推理。这是最大的浪费。

**零 LLM 就能做的**（L1/L2/L3/L5）：结构检查、影响分析、传递闭包、引用腐烂——这些是图遍历，不需要模型，27 颗原子用内存 dict 就够了。

**需要 LLM 但有结构支撑的**（L4）：跨域迁移——但必须用五维分解+实测验证，不能纯结构类比（IsoSci 证明 91.3% 是知识依赖的）。

**最有价值的立即行动**：L1 结构检查（P0）——3 条新 gate 规则，零 LLM，零风险，直接把 relations 从"装饰"变成"基础设施"。这也是 402 对抗 F07（relations 纯标量静默丢弃）的根本修复——不仅检查格式，还检查语义。

**架构意义**：知识图谱推理是阙疑从"原子库"（27 个独立文件）升级到"知识系统"（27 个节点的可推理图）的关键一步。没有这一步，原子越多越乱；有了这一步，原子越多越强（网络效应）。
