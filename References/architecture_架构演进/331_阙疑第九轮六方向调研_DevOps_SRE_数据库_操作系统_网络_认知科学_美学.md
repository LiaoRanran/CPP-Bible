## 一、DevOps/SRE：持续交付与混沌工程

### 1.1 核心理论

**DORA 四指标**（精英团队基准）：
- 部署频率：多次/天
- 变更前置时间：< 1 小时
- 变更失败率：0-15%
- 恢复时间：< 1 小时

**可观测性三支柱**：
- 日志（Logs）：结构化日志 + correlation ID
- 指标（Metrics）：时间序列数据（Prometheus）
- 追踪（Traces）：分布式追踪（OpenTelemetry/Jaeger）

**混沌工程**：
1. 建立稳态假设（什么是"正常"）
2. 模拟真实故障（不是staging，是production）
3. 观察系统响应
4. 验证弹性（系统是否自愈）

**部署策略**：
- 蓝绿部署：两套环境，切换流量
- 金丝雀发布：逐步放量（1%→10%→100%）
- 特性开关：代码部署与功能发布解耦

### 1.2 对「阙疑」的映射

**DORA 指标 = 「阙疑」的交付指标**：
- 部署频率 = 原子生产速度（每批几颗）
- 变更前置时间 = 从claim到verified的时间
- 变更失败率 = 红队阻断率/CI红率
- 恢复时间 = 从发现问题到修复的时间

**可观测性三支柱 = 门禁三支柱**：
- 日志 = replay 的详细输出（每个卡的confirm/refute原因）
- 指标 = golden_lock 的统计数据（atoms/evidence/replay_confirm）
- 追踪 = 原子的 status_history（从draft到verified的完整轨迹）

**混沌工程 = 毒样例演练（P1-P7）**：
- 稳态假设 = 门禁全绿（block=0）
- 模拟故障 = 注入毒样例（自证断言/恒真观测/伪证伪）
- 观察系统响应 = gate是否拦截
- 验证弹性 = 毒样例被拦截，正常卡不被误伤

**金丝雀发布 = 原子的渐进式验证**：
- 1% = 草稿（goldens/，不被gate扫描）
- 10% = 红队审查（独立子agent）
- 100% = 原子化（atoms/，被gate全量扫描）

## 二、数据库理论：CAP与ACID

### 2.1 核心理论

**CAP 定理**（Brewer, 2000; Gilbert & Lynch, 2002 证明）：
- 一致性（C）：每次读返回最新写入或错误
- 可用性（A）：每个请求收到非错误响应
- 分区容忍（P）：网络分区时系统继续运行
- 三选二（实际中P必须选，所以是C vs A）

**ACID**：
- 原子性（Atomicity）：全部完成或全部不完成
- 一致性（Consistency）：从一个一致状态到另一个一致状态
- 隔离性（Isolation）：并发事务互不干扰
- 持久性（Durability）：提交后永久保存

**隔离级别**（从低到高）：
- Read Uncommitted：脏读
- Read Committed：不可重复读
- Repeatable Read：幻读
- Serializable：完全隔离

**BASE**（ACID的对立面）：
- 基本可用（Basically Available）
- 软状态（Soft state）
- 最终一致性（Eventual consistency）

### 2.2 对「阙疑」的映射

**CAP = 「阙疑」的三难**：
- 一致性（C）= 质量（claim与证据一致）
- 可用性（A）= 速度（快速生产原子）
- 分区容忍（P）= 覆盖（多域/多主题）
- 三选二：要质量+速度就牺牲覆盖（只做几颗精品）；要速度+覆盖就牺牲质量（批量生产但可能有问题）

**ACID = 原子的四个属性**：
- 原子性：一颗原子一个claim（不混多个主题）
- 一致性：与Book/其他原子一致（consistency检查）
- 隔离性：独立可验证（不依赖其他原子的运行时状态）
- 持久性：verified后不变（status_history记录变更）

**隔离级别 = 红队的"隔离级别"**：
- Read Uncommitted = 看卡自述（最低隔离，最容易被误导）
- Read Committed = 看卡+夹具（中等隔离）
- Repeatable Read = 盲读夹具/工件后再对照卡（高隔离）
- Serializable = 完全独立，不看任何Writer产出（最高隔离，红队两段式盲读）

**最终一致性 = 架构调研的收敛**：
- 多轮调研（300-331）最终收敛为统一的架构理论
- 临时不一致是允许的（不同文档可能有不同观点）
- 最终必须收敛（整合时统一）

## 三、操作系统：虚拟内存与并发原语

### 3.1 核心理论

**虚拟内存**：
- 地址空间：每个进程有独立的虚拟地址空间
- 页表：虚拟地址→物理地址的映射
- TLB：页表缓存（加速地址翻译）
- 缺页中断：访问未映射页面时触发

**调度算法**：
- FCFS（先来先服务）
- SJF（最短作业优先）
- RR（时间片轮转）
- 多级反馈队列（MLFQ）

**并发原语**：
- Mutex：互斥锁（只有一个线程持有）
- Semaphore：计数信号量（N个槽位）
- Condition Variable：等待+信号
- RWLock：多读者/单写者
- Monitor：Mutex+CondVar的封装

**无锁数据结构**：
- CAS（Compare-And-Swap）：原子的读-改-写
- RCU（Read-Copy-Update）：读无锁，写复制
- Hazard Pointer：安全的无锁内存回收

### 3.2 对「阙疑」的映射

**虚拟内存 = Agent的上下文管理**：
- 地址空间 = Agent的上下文窗口（有限但虚拟为无限）
- 页表 = 记忆索引（L1/L2/L3的映射）
- TLB = 最近使用的记忆（快速访问）
- 缺页中断 = 上下文耗尽时触发"换页"（从L2/L3加载）

**调度 = 任务优先级调度**：
- FCFS = 按顺序处理任务
- SJF = 优先处理小任务（快速交付）
- RR = 时间片轮转（避免大任务阻塞）
- MLFQ = 多级反馈队列（P0/P1/P2优先级）

**并发原语 = 多Agent协作的同步**：
- Mutex = 人审（全局锁，只有一个人能签）
- Semaphore = 并行任务数限制（同时最多N个红队）
- Condition Variable = 等待条件（等CI绿后再push）
- RWLock = 读多写少（多个Agent可以同时读，只有一个能写）

**无锁 = 放权后的无锁协作**：
- CAS = 乐观并发（先做，冲突时重试）
- RCU = 读无锁（红队可以自由读，Writer写时复制）
- 目标：减少人审这个"全局锁"的使用

## 四、计算机网络：拥塞控制与共识算法

### 4.1 核心理论

**TCP拥塞控制**：
- CUBIC：基于丢包的拥塞控制（丢包→减速）
- BBR：基于模型的拥塞控制（估计瓶颈带宽+RTT，不依赖丢包）
- BBR在浅缓冲区/无线网络上优于CUBIC，在有损Wi-Fi上可能更差

**共识算法**：
- Paxos：基础共识算法（proposer/acceptor/learner）
- Raft：可理解的共识算法（Leader选举/日志复制/安全性）
- 多数派重叠：任何两个多数派至少共享一个成员（安全性的基础）

**Raft三状态**：
- Follower：被动接收Leader的日志
- Candidate：选举超时后变为Candidate，发起选举
- Leader：处理所有客户端请求，复制日志到Followers

### 4.2 对「阙疑」的映射

**BBR vs CUBIC = 两种方法论**：
- BBR（基于模型）= 先建模型再行动（红队先分析夹具/工件再攻击）
- CUBIC（基于反馈）= 基于失败调整（门禁失败后修改卡）
- 「阙疑」应该是BBR式：先理解（模型），再行动（生产），而不是CUBIC式：失败了再调

**Raft = 「阙疑」的共识机制**：
- Leader = 人审（最终决策者）
- Followers = 红队/门禁（提供信息，但不决策）
- 日志复制 = 决策记录（status_history记录每一步）
- 安全性 = 决策不会被推翻（verified后不变）

**多数派重叠 = 集体智慧的聚合**：
- Writer/红队/Gatekeeper/人审 = 四个"节点"
- 任何三个的"多数派"至少共享一个视角
- 这保证了决策的安全性（不会出现矛盾的结论）

**拥塞控制 = Agent的任务拥塞控制**：
- 上下文耗尽 = 网络拥塞
- 减速 = 降低任务复杂度（从一批4颗降到1颗）
- BBR式 = 估计上下文容量，主动调整任务量

## 五、认知科学深度：工作记忆与元认知

### 5.1 核心理论

**工作记忆**：
- 容量有限：从7±2（Miller, 1956）修正为4±1（Cowan, 2001）
- 主动维护+处理：不只是存储，还包括操作
- 与注意力紧密相关：工作记忆容量的预测力可能反映注意力控制

**执行功能**（Miyake et al., 2000）：
- 抑制控制：抑制不相关的反应
- 工作记忆：维护和处理信息
- 认知灵活性：在不同任务/规则间切换

**元认知**：
- 对认知的认知：监控/评估/调节自己的思维
- 元认知监控：知道自己知道什么/不知道什么
- 元认知调节：根据监控结果调整策略

**元认知怠惰**（2024-2025新问题）：
- 生成AI普及后，人们过度依赖AI，不主动思考
- 即使AI给出错误答案，也不质疑

### 5.2 对「阙疑」的映射

**工作记忆 = Agent的上下文窗口**：
- 容量有限（4±1个"块" = 上下文窗口的token限制）
- 主动维护+处理 = 不只是存储历史，还包括推理
- 上下文耗尽 = 工作记忆溢出，需要换页（MemGPT）

**执行功能 = 「阙疑」的三权分立**：
- 抑制控制 = 红队（抑制Writer的过度自信）
- 工作记忆 = Writer（维护和处理claim/证据）
- 认知灵活性 = Gatekeeper（在不同检查规则间切换）

**元认知 = 「阙疑」的自我批判**：
- 元认知监控 = 知道系统的弱点（如P4-P7的盲区）
- 元认知调节 = 根据弱点调整（如新增P8-P10规则）
- 「阙疑」的多轮自我批判就是元认知的实践

**元认知怠惰 = 警惕Agent的怠惰**：
- Agent过度依赖提示词，不主动思考
- 即使提示词有错误，也不质疑（如312的v2错误）
- 红队的价值就是对抗元认知怠惰（强制质疑）

## 六、美学：康德与黑格尔

### 6.1 核心理论

**康德的审美判断四契机**（《判断力批判》, 1790）：
1. **质**：无利害的愉悦（不涉及欲望/道德）
2. **量**：无概念的普遍性（每个人都应该同意，但不是基于概念）
3. **关系**：无目的的合目的性（形式看起来有目的，但没有实际目的）
4. **模态**：无概念的必然性（必然让人愉悦，但不是逻辑必然）

**黑格尔的美学**：
- 美是理念的感性显现（the sensuous manifestation of the Idea）
- 艺术是绝对精神的一种形式（与宗教、哲学并列）
- 艺术的三种类型：象征型→古典型→浪漫型
- "艺术的终结"：艺术被哲学超越

**尼采**：
- 阿波罗（梦幻/形式）vs 狄奥尼索斯（醉狂/解构）
- 艺术是生命的必要幻觉（让生活变得可承受）

### 6.2 对「阙疑」的映射

**康德的"无目的的合目的性" = 好的原子设计**：
- 好的原子看起来自然，没有刻意的"教学感"
- 形式看起来有目的（结构清晰），但没有实际的"说教目的"
- 读者在学习时感到愉悦（无利害的愉悦）

**黑格尔的"美是理念的感性显现" = claim与证据的关系**：
- claim = 理念（抽象的真理）
- 证据卡 = 感性显现（具体的实证）
- 美 = claim与证据的完美统一（不是claim悬空，也不是证据堆砌）

**形式与内容的统一 = 原子的设计原则**：
- 形式（结构/frontmatter/章节）必须服务于内容（claim/证据/教学）
- 不能为了形式而形式（如过度复杂的frontmatter）
- 也不能只有内容没有形式（如无结构的长文）

**美学维度 = 「阙疑」目前缺少的维度**：
- 目前只有正确性（replay/gate）和严谨性（红队）
- 缺少"美"（优雅/简洁/可读性）
- 好的系统应该不仅正确，而且优雅
- 可以增加"美学审查"：原子是否简洁？是否有冗余？是否易读？

### 7.1 第九轮最有价值的三个洞察

1. **混沌工程 = 毒样例演练的理论基础**——P1-P7 毒样例就是「阙疑」的混沌工程：建立稳态假设（门禁全绿）→ 模拟故障（注入毒样例）→ 观察系统响应（gate是否拦截）→ 验证弹性（毒样例被拦截，正常卡不被误伤）。这解释了为什么毒样例如此重要：它是主动验证系统弹性，而不是被动等待故障。

3. **美学是「阙疑」目前缺少的维度**——目前只有正确性（replay/gate）和严谨性（红队），缺少"美"（优雅/简洁/可读性）。康德的"无目的的合目的性"和黑格尔的"美是理念的感性显现"可以指导原子设计：好的原子不仅正确，而且优雅。可以增加"美学审查"作为新的检查维度。
