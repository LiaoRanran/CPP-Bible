## T2 · 断言通用集收口到"帧/伪指令"层

**问题**：`.seh_endproc/.cfi_startproc/.p2align` 等 ABI 帧伪指令在任何 gcc -S 产物里恒出现，contains/contains_any 拿它们做断言=恒真（521 漏洞7 只修一半，批判 B.4）。

**⚠️ 隐藏陷阱（最容易白改）**：`gate_engine.py:1463` 的 token 提取正则是 `_IDENT_RE = re.compile(r"[A-Za-z_][A-Za-z0-9_]{2,}")`——**它不匹配以 `.` 开头的串**。所以只把 `.seh_endproc` 加进 `UNIVERSAL_SYMBOLS`（:1459 frozenset）**完全不生效**，因为这些伪指令在更早的分词阶段就没被提取成 token。必须两处都改：
1. 在断言目标分词处，额外识别"以 `.` 或 `%` 开头的汇编伪指令/寄存器名"（单独正则，如 `[.%][A-Za-z0-9_]+`），把它们并入"无判别力通用符号"判定。
2. `UNIVERSAL_SYMBOLS`（:1459）扩入：`.file .section .p2align .seh_proc .seh_endproc .seh_endprologue .seh_stackalloc .cfi_startproc .cfi_endproc .cfi_def_cfa .cfi_def_cfa_offset .cfi_offset`（按实际汇编里出现的补全，先 grep `Examples/atoms/*.asm` 统计真实出现的 `.` 伪指令再定集合，别凭空列）。

**口径**：
- 全局 `contains`/`contains_any`/`absent*` 命中这些 → 无判别力，按现有 UNIVERSAL_SYMBOLS 的 block 路径处理（参考 :1578-1608 既有分支，保持一致）。
- 区间断言 `contains_in` 的 text：沿用现有口径（纯中文/空 block，普通助记符 advice），**不要**因为是 `.` 伪指令就改变 contains_in 既有行为。
- 同一伪指令作为**夹具特有函数体内**的合理区间证据（配真 symbol）→ 放行。

**验收**：先 grep 全库 .asm 确认真实伪指令词表；毒样例：`.seh_endproc` 全局 contains → block（反例），同符号在特有函数体区间配真符号 → 放行（正例）；存量 56 卡 block=0；pytest 成对。独立 commit。

## T7 · task_queue.py · L2 调度最小骨架（独立新文件，不做 Supervisor）

**新文件** `tools/task_queue.py` + 数据目录 `data/tasks/queue.db`（把 `data/tasks/` 加进 `.gitignore`，不入库）。**零新依赖**（标准库 sqlite3），并发安全用 `BEGIN IMMEDIATE` 原子事务。

表结构：
```sql
CREATE TABLE tasks(
  id TEXT PRIMARY KEY,            -- 幂等键：同 type+payload_hash 只入队一次
  type TEXT NOT NULL,             -- atom_produce/redteam/replay_batch/...
  payload_ref TEXT NOT NULL,      -- 指向仓库内任务文件，不把长 prompt 塞库
  status TEXT NOT NULL,           -- queued/claimed/done/failed/blocked
  priority INTEGER NOT NULL DEFAULT 100,
  deps TEXT NOT NULL DEFAULT '[]',-- 前置任务 id JSON 数组，未全 done 不可 claim
  claimed_by TEXT, claimed_at TEXT, heartbeat_at TEXT,
  attempts INTEGER NOT NULL DEFAULT 0, result_ref TEXT, error TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
```
子命令：
- `enqueue --type --payload-ref [--priority] [--deps id,...] [--id]`：同 id/dedup 已存在→打印已存在并 exit 0（幂等）。
- `claim --worker <名> [--types t,...]`：原子领走一个 deps 全 done 的最高优先级 queued 任务，输出 JSON，status→claimed、attempts+1、写 heartbeat。
- `heartbeat <id> --worker`、`done <id> --result-ref`、`fail <id> --error`、`blocked <id> --reason`：**worker 必须与 claim 者一致才能改**，否则拒绝。
- `list [--status] [--json]`、`next`（claim 的只读预览，不改状态）。
- **stale 接管**：claimed 且 heartbeat 超 600s → 下次 claim 可被重新接管回 queued，attempts 保留；attempts>3 自动 blocked（防无限重试）。
- 与 `task_state.py` 关系：task_state 仍是"长任务进度笔记本"，task_queue 只管"谁该干什么/干完没"；v1 由人执行 `task_queue next` 手动派活，**不写自动 Supervisor Loop**。

**验收（pytest ≥6 例）**：①enqueue 幂等（同键两次只一条）②两连接争抢同一行只一个 claim 成功 ③deps 未完成不可 claim ④非 claim 者 done 被拒 ⑤heartbeat 超时可接管 ⑥attempts>3 进 blocked。空队列 `list` 不崩。独立 commit。
