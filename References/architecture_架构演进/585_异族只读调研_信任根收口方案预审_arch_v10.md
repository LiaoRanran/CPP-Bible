## 二、必须回答的红队问题（每组给"最小攻击/伪造路径 + 现在能做的 N 档 / 要攒证据的 D 档 / 该等或该放弃的 W 档"）

### Q1 · T1"规则注册表独立第二锚"真的独立吗？（最高优先）
建设方设想：让每条规则必须挂一个**可执行行为证据**（毒样例 id 或 pytest 正反例），规则函数被写空/被摘注册表 ⇒ 其名下证据必然失败，从而无需密码学也能发现 PoC-1。
- 在**单用户、单机、无密钥、`.tool_checksums` 可被 `--update` 无认证重签、git 历史可被 rebase/amend 改写**的前提下，攻击者（或被注入的恶意苦力/被误导的弱模型）要让"规则被写空 + 所有证据仍绿"，**最少需要同步改动哪几个文件、留不留痕、痕迹能否被合法操作抹掉**？给出具体到文件的伪造链。
- "第二锚"和第一锚（checksum）是否共享同一个可被一次性伪造的根（比如一次 `--update` + 一次改测试就能同时重签两者）？怎样的结构才是**真正异质**的第二锚（异语言？异进程？异数据源？人持有的带外清单？）？
- 对照：Thompson《Reflections on Trusting Trust》、reproducible/bootstrappable builds、Diverse Double-Compiling（Wheeler DCC）、in-toto/SLSA、TUF。**哪些在"单人本地无服务器无密钥"下可降级借用，哪些必然退化、退化后还剩多少保证？** 诚实区分：这套机制分别能防住「手滑误删」「弱模型苦力无意改坏」「外部恶意攻击者」到什么程度。

### Q2 · "双实现对账一致"会不会是同谋的假独立？
583 的 N1（prop_asof）、N3（与 metrics_collector 对账）、未来 N2（Python 闭包 vs SQLite 递归 CTE）都用"两个实现结果一致"当正确性证据。
- 当两个实现共享同一解析器、同一 git 时间源、同一套字段语义假设时，对账一致提供的是独立性还是只是"同一错误犯两遍"？
- 调研 N-version programming / multi-version 的 **common-mode failure** 实证（含 Knight & Levenhagen 经典实验的现代视角与批评），给出"两个实现要在哪些维度上真正不同才算独立第二实现"的判据清单；据此判定 N1/N2/N3 各自算不算、差在哪。

### Q3 · git 提交时间当"断言时间轴"可不可信？我们否 bitemporal 否对了吗？
N1 把卡的 `git log -1` 时间降级为 `asserted_at_approx`（B 级证据）。
- rebase / amend / squash / cherry-pick / 浅克隆 / 跨机时钟偏差 / 文件移动保留历史 等操作下，这个时间分别会怎么撒谎？有没有只读办法检测"时间轴被改写过"（reflog？commit-graph？parent 链？）？
- 关键反问：**git 本身就是一个 append-only 的 Merkle 历史**，582"现在否掉 bitemporal 引擎（XTDB/Datomic）"是否把"重型时序数据库"和"时序语义"混为一谈？在单用户本地 git 下，四轴快照（断言时间/验证者版本/推翻事件/引用锚）是否其实可以低成本从 git 派生而无需新引擎？给出"该否的是什么、不该否的是什么"。

### Q4 · T3 人签事件流在无密码学下到底防住了谁？
拟新增只追加 `data/human_sign_events.jsonl`，`principal_ok` 升级为"文本 + git 作者一致 + 事件可对账"，复用 git 作者绑定 fail-closed。
- `git user.name/user.email` 可任意配置、本地 jsonl 可直接改写、无第三方时间戳——逐条拆解：这相对 PoC-3（键入字符串即过）**净增了哪些真实保证**，哪些只是"多了个文件让人以为签过"？
- 调研：单人场景如何模拟四眼原则（异步自我复核、强制冷静期、带外确认）、approval fatigue / rubber-stamp automation、人对自动化建议过度依赖的 2024–2026 实证（NEJM AI 2026 RCT 已知，再找不同领域的）；给"单用户阶段人签机制的诚实威胁模型边界"。
- 本地 hash-chaining（每条事件含前一条哈希）在无第三方时防什么、不防什么？

### Q5 · N5"双解析器 canon 相等 ⇒ 等价变异体"是完备判据吗？
判据：变体与原文经 safe_load 与硬化解析器两路规范化后都相等、且算子∉{M1,M7}，则标 equivalent（判决不可见面未变）。
- 是否存在"两路 frontmatter canon 相等、但**第三条读取路径**（replay 直接读工件/命令、某条规则用正则扫原文而非解析结果、run_match 读外部文件）产生不同 finding"的形态？尽力构造具体反例（可纯文本推演，不必跑编译）。
- 调研等价性判定的学术武器：**Equivalence Modulo Inputs（Le et al.）**、metamorphic testing、differential testing、compiler/reducer 的 TCE、test-equivalence 的不可判定性边界。据此判定：我们的 canon 等价是 sound 还是 complete、偏向哪一侧、误判（把真逃逸洗成等价 / 把无效变异当真洞）各自的代价该如何不对称地防（应偏向哪侧 fail）？

### Q6 · 轻量留痕 vs 正式供应链信任链，我们到底缺哪几环、哪几环可合法省略？
横向对照 in-toto attestations、SLSA provenance levels、Sigstore/Rekor 透明日志、TUF、Sigstore keyless、reproducible builds：列出它们的每一环（出处、构建、透明日志、密钥轮换、撤销……）在"单人、本地、离线、无密钥、唯一资产是可复算判决"约束下——**哪环提供的保证我们已经用别的方式覆盖、哪环是真空白、哪环在单人场景结构性无意义**。产出一张"环 × 是否需要 × 本仓替代物"对照表，不要泛泛而谈。
