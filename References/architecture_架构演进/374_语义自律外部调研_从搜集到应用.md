# 374 语义自律外部调研：从搜集到应用

> 日期：2026-09-13。监工完成，为下一批"形式自律→语义自律"跃迁提供外部理论支撑。
> 流程：搜集 → 整理 → 挖掘 → 联系 → 批判 → 结合 → 应用。

## 一、搜集（搜了什么）

三路并行检索，覆盖 2024-2026 年学术与开源实践：
1. 论证质量自动评估 / claim verification / 可证伪性形式化
2. LLM 事实核查 / 证据链验证架构 / RAG+Verification
3. 多 Agent 辩论 / 对抗形式化 / truth-seeking

核心来源（10 份高相关）：
- AutoVerifier（arXiv 2604.02617）：断言三元组+知识图谱+六层验证
- RECV（arXiv 2402.10735）：claim+evidence 原子推理类型分解
- MArgE（arXiv 2508.02584）：论证树替代自由辩论
- Arbiter（GitHub vishk23/arbiter）：claim 提取+Z3 形式化验证+多 Agent 辩论
- ReviewScore（arXiv 2509.21679）：评审本身 15-26% misinformed
- ReasonGraph（GitHub Delphictunic）：架构约束强制验证，非提示词约束
- MARCH（arXiv 2603.24579）：信息不对称三 Agent（Solver/Proposer/Checker）
- DebateCV（arXiv 2507.19090）：正反方+Moderator 多轮辩论
- ColMAD（arXiv 2510.20963）：MAD 协议设计比 Agent 数量重要
- ProductionOS debate-tribunal（GitHub）：第一轮强制分歧协议

## 二、整理（分类）

| 类别 | 核心问题 | 代表工作 |
|---|---|---|
| A. 断言结构化 | claim 如何变成机器可判 | AutoVerifier、RECV |
| B. 论证结构化 | 红队/辩论如何可审计 | MArgE、Arbiter |
| C. 验证者独立性 | 如何避免验证者被带偏 | MARCH、ReasonGraph、RAG+RAV |
| D. 评审可靠性 | 红队/评审本身出错率 | ReviewScore |
| E. 辩论协议 | 多 Agent 如何不变成多数投票 | ColMAD、DebateCV、debate-tribunal |
| F. 架构强制 | 验证靠工具还是靠提示词 | ReasonGraph、Arbiter |

## 三、挖掘（每个类别的核心洞察）

**A. 断言结构化**：整句 claim 不可机器判，必须拆成原子断言（SPO 三元组或演绎/溯因类型），每个原子断言绑定证据。未绑定的断言 = 不可验证 = 不应进入 verified。

**B. 论证结构化**：自由文本辩论"不可忠实证明"（not faithfully justifiable），必须用论证树（claim→warrant→evidence→backing→rebuttal）。红队反馈不是"说了什么"，而是"攻击了哪个断言、反证是什么、替代解释是什么"。

**C. 验证者独立性**：Checker 不能看 Solver 的原始答案，只能看 Proposer 分解的原子命题——信息不对称防止被措辞带偏。验证必须通过架构约束（工具强制），不能靠提示词"请诚实"。

**D. 评审可靠性**：15.2% weakness、26.4% question 是 misinformed（评审自己理解错了）。红队的 block 级发现必须有可复现锚（命令/行号/输出），无锚者降级为观察。

**E. 辩论协议**：同构 Agent 辩论不能可靠超越多数投票；异模型+强制分歧（第一轮正反方必须各给最强论证）比"加更多 Agent"有效。协议设计是关键变量。

**F. 架构强制**："每个 claim 追溯到精确证据块"应由工具强制，而不是提示词要求。验证失败是架构级阻断，不是建议级提醒。

## 四、联系（和我们系统的映射）

| 外部发现 | 我们已有的对应 | 差距 |
|---|---|---|
| A. 断言-证据绑定 | claim 契约化（372 v5 设计了未落地） | 没有工具检查绑定关系 |
| B. 论证树 | 红队自由文本反馈 | 没有结构化模板 |
| C. 信息不对称 Checker | 两段式盲读（373 §3.5） | 已做，但红队仍看卡全文 |
| D. 评审可靠性 | 监工源码核实（人工环节） | 没有"无锚阻断自动降级"规则 |
| E. 异模型+强制分歧 | ds+hy4p 异模型、竞争假设≥2 | 竞争假设只要求"有"，不要求正反方 |
| F. 架构强制 | replay/gate 工具强制 | 语义层全靠提示词/红队 |

**已被外部验证的方向**：两段式盲读=MARCH 信息不对称；三权分立=RAG+RAV；对抗驱动=ColMAD 协议优先；机器可核验=Arbiter 形式化验证。

## 五、批判（哪些不适用、哪些有局限）

1. **AutoVerifier 的 SPO 三元组对 C++ 技术断言不完全适用**——C++ claim 常是"在 X 条件下，Y 比 Z 快 N 倍"，不是简单主-谓-宾。需要扩展为"前提-断言-测量"三元组，而不是照搬 SPO。
2. **Arbiter 的 Z3 形式化验证只适用于数学/形式化 claim**，C++ 性能/内存模型 claim 无法 Z3 验证，只能靠实测夹具。我们的 replay 机制比 Z3 更适合这个域。
3. **MArgE 的论证树增加了红队写作成本**——在上下文有限的环境里，结构化模板可能压缩红队的发散空间。需要平衡"可审计"和"创造力"。
4. **ReviewScore 的 misinformed 率是学术评审场景**，我们的红队有夹具/工件可核，misinformed 率应该更低，但"红队误解工具行为"（如 contains_in 恒真那次）仍是真实风险。
5. **异模型辩论的有效性依赖模型能力差异**——如果两个模型能力差距过大，弱模型的反对意见可能被强模型无视。hy4p 和 ds 能力接近，是合适的配对。

## 六、结合（和已有架构的结合点）

**和 372 v5 的结合**：
- T-ep 认识论三字段（applicability/evidence_strength/inductive_leap）+ A 类断言-证据绑定 = 语义自律的双支柱
- claim 契约化（≤50字+pre/post/invariant）+ 原子断言分解 = claim 层的完整结构化
- T0 博弈防御 + E 类强制分歧 = 建设者必须同时给正反论证

**和 373 对抗结果的结合**：
- B1（claim 模糊词）→ A 类：断言必须可拆、可绑定
- B8（稻草人 falsification）→ B 类：红队必须填"被攻击的断言"三栏
- B10（空洞 claim 方向）→ A+E：没有反方论证的 claim 不进 verified
- 红队 IFNDR 误判 → D 类：无锚阻断自动降级

**和 G6 状态体系的结合**：
- 语义自律规则落地后，machine-verified 级可以从"格式+证据卡 replay 通过"升级为"格式+断言-证据绑定通过"
- human-verified 级保留给"语义层机器判不了的方向判断"

## 七、最终应用（下一批具体落地什么）

等 hy4p 窄化修复+P1+绕过测试完成后，下一批（语义自律首批）落地三条：

### 应用 1：断言-证据绑定检查（对应 A 类，替换 B1 软规则）
- claim 必须能拆成 ≥1 个原子断言，每个原子断言显式声明 `binds_evidence: [EV-XXX]`
- gate 规则 `ATOM-CLAIM-EVIDENCE-BIND`：未绑定的断言→warn（存量迁移期）→block（新卡）
- 毒样例：阳（claim 有断言无绑定）→拦；阴（每个断言绑定真实存在的 evidence id）→放行
- 这是语义自律的第一条机器规则，直接打 B1/B10

### 应用 2：红队阻断结构化模板（对应 B+D 类）
- 红队每条 block 级发现必须填三栏：`attacked_assertion`（被攻击的原子断言）/`counter_evidence`（反证，含复现命令）/`alternative_explanation`（替代解释≥1）
- 三栏缺任一→自动降级为"高级"而非"阻断"
- 这把红队质量从"看字数"变成"看结构"，直接打 B8，也防止红队 misinformed

### 应用 3：正反论证强制（对应 E 类，升级竞争假设）
- 建设者必须在原子卡内显式给 `supporting_arguments`（≥2）和 `counter_arguments`（≥2）
- 缺反方论证→warn→block
- 这把"单方面论证"变成"正反论证"，机器可判，直接打 B10

### 应用 4（中期，不在首批）：语义层独立 Checker
- 参考 MARCH，建一个只看原子断言+证据卡、不看 claim 原文的语义验证 Agent
- 这是红队两段式盲读的进一步深化，需要等应用 1 落地（有了原子断言结构才能做）

## 八、本调研的局限与后续

- 本调研聚焦"语义自律的外部理论"，未覆盖"证据智能"（自动设计实验）和"认知智能"（跨原子发现矛盾）——那是更上一层，留待语义自律落地后再调研。
- 所有外部工作都是通用域（事实核查/科研评审），C++ 技术知识域的特殊性（实测夹具、内存模型、平台相关）需要在落地时适配，不能照搬。
- 下一批落地后，需要用对抗测试验证这三条语义规则是否会被绕过（同义词、结构变形、空绑定等），形成"语义层对抗→语义层规则"的新闭环。
