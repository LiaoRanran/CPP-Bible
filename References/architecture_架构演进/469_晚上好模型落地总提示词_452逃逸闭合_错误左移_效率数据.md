## 二、P0 安全地基：闭合 452 第四轮对抗的确认逃逸

第四轮对抗（`_adv_v70/`，独立模型盲读产出）经 replay 实弹确认的逃逸，按严重度排序。**每条修复必须：配毒样例（poison）+ pytest 正反例 + 存量零误伤（gate block=0 不新增）+ 独立 commit。**

### P0-1【最高，运行时覆写 H1】F02 的 gate 文本检测被 helper 脚本绕过

- **实测**：`EV-ADV70-H1.md` 用 `python build_step.py` 编译，脚本**内部硬编码 artifact 路径**做覆写，命令行文本里既无工件名也无写动词 → gate `_post_compile_writes` 零命中 → replay **confirm 逃逸**（sha=借品真值）。
- **根因**：gate 只做命令文本分析；replay 无"运行时最后写入者"校验。黑名单（cp/mv/python…）永远列不全，426 已论断必须升级到不变量。
- **修复方向（二选一或组合，先读 `tools/gate_engine.py:1296-1333` 与 `tools/atom_evidence_replay.py` 的 run_commands）**：
  1. **最小（gate 侧，warn/block）**：command 中出现脚本解释器（python/python3/bash/pwsh/sh）调用且该脚本文件在仓库内时，解析脚本内容；脚本内出现对 artifact 路径（含 basename）的写操作（open(w)/shutil.copy/重定向）→ block。脚本不在仓库（无法静态读）→ warn"产物经不可审计脚本产出"。
  2. **根本（replay 侧，426 不变量）**：replay 跑完 command 后，校验 artifact 的 mtime 晚于最后一个编译动作、且 command 全序列中对该路径的最后一次"写"来自编译器 argv[0]；不是则 refute/infrastructure 分流。
- **建议**：本晚先做方向 1（gate 静态，零运行时风险）+ 毒样例；方向 2 登记为 P1 留给下一窗口（涉及 replay 运行时，回归面大）。
- **验收**：`EV-ADV70-H1.md` 探针 gate 判 block/warn；新建干净卡（脚本只读不写 artifact）不误伤；poison + pytest 绿。

### P0-2【高，假证据 H6】读文件式夹具（cat 式证据）

- **实测**：`EV-ADV70-H6.md` 夹具 open 随库提交的 `expected_data.txt` 并打印，run_match 逐字一致、sha 一致 → **confirm**。但输出只证明"程序打印了文件内容"，不证明任何计算/机制。
- **修复方向**：新增 gate 规则 `EV-FIXTURE-NO-ECHO-DATA`（先 warn 观察 1 批，再升 block）：扫描 fixture 源码，若存在"打开仓库内数据文件（ifstream/fopen/open with r）且其内容经 cout/printf 流向 stdout 的 run 标签"→ warn，提示"读数回显不构成机制证据，活性读数必须由计算产生"。
- **边界**：合法夹具也可能读文件（如演示文件格式），故先 warn；判据聚焦"读入值未经任何运算直接成为 run_match 标签值"。
- **验收**：H6 探针 warn；存量 56 卡若有同类，列出来交人裁决（可能是真问题，如 EV-MEM-017 族）。

### P0-3【高，环境依赖 H7】环境量进 run_match_keys（d8ff94d 只改卡未立规则）

- **实测**：`EV-ADV70-H7.md` 把 nproc/环境量放进 keys，本机 confirm、CI 核数不同必红。历史 commit d8ff94d 修了存量卡但**没立规则**，会复发。
- **修复方向**：gate 规则 `EV-OUT-NO-ENV-KEY`（block 新卡，存量 warn）：run_match_keys / actual run 标签的值若来自 `std::thread::hardware_concurrency`、`std::filesystem::file_size`（非确定性文件）、`__DATE__/__TIME__/__FILE__`、`getenv`、`%USERNAME%/%TIME%/%DATE%`、`nproc`、`uname`、PID、时间戳（chrono now/clock/time）→ block。
- **注意**：`hardware_concurrency` 走 sysconf 不受 taskset 影响（d8ff94d 已实证），不能用"CI 钉核数"绕过，必须禁止进确定性 keys（允许打印但要标记为非确定性、不进 run_match）。
- **验收**：H7 探针 block；CONC-002 的 nproc 兜底（insufficient_cores）是**合法范式**（打印核数用于守卫，不作为逐字 key），不得误伤——用它做反例毒样例。

### P0-4【中高，H2】producer 后写动词黑名单外延不完备

- **实测**：install / ln -sf / xcopy / robocopy / tar 落在黑名单外：xcopy/robocopy/type 完全 BLOCK=0，install/ln/tar 仅 warn。
- **修复方向**：不要再补黑名单。反转判据为 **"producer 段之后，任何触碰 artifact 路径的命令段默认 block；只有读白名单（type/cat/head/tail/grep/od/objdump/nm/file/sha256sum）放行"**（白名单比黑名单安全：读工具数量有限且可枚举，写工具/脚本无限）。读 `_post_compile_writes` 现有 `_POST_READ_PROGS`，把它从"语义不明保守 warn"升级为"不在读白名单即 block"。
- **验收**：H2 全部写动词探针 block；读白名单工具（objdump 验证 .asm 是常见合法后置段）放行；存量卡 command 若有后置触碰 artifact 的非读段，列出来。
