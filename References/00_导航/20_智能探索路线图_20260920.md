# 阙疑智能探索路线图（2026-09-20）

> 产品经理视角的智能方向规划。基于人审全量完成（388/388）和 W2 分层判决（IN114/OUT7），六维度平均 7.7 已超"智能调研启动线 7.5"。
> **核心原则**：智能是"基于已验证数据的推理"，不是"生成新内容"。所有智能功能必须建立在已验证的证据之上，不打开 delegation，不 LLM-as-judge 终审。

## 一、为什么现在可以开始智能探索

### 1.1 三个启动条件

| 条件 | 状态 | 说明 |
|---|---|---|
| ① 论证层 ≥ 7.0 | 🔄 6.0（609 后预计 7.0） | 人审全量完成，分层判决已实现，辩护链可计算 |
| ② 人审反馈闭环跑通 | ✅ 已达成 | 388 条全量，两次判决翻转（IN79/OUT42→全IN→IN114/OUT7） |
| ③ 推翻通道有真实事件 | ⏳ 0 条（待触发） | 首次真实推翻需人触发，系统绝不自动产生 |

**结论**：3 个条件中 2 个已达成，1 个待触发。不需要等全部 3 个，可以先做"不依赖推翻事件"的智能功能（如辩护链生成、因果推理）。

## 二、智能探索的四个方向

### 方向 1：辩护链推理（最优先，纯确定性，零 Oracle 风险）

**目标**：基于 W2 判决和人审数据，自动计算每个节点的辩护链（攻击者+辩护者+可信度+击败关系），并支持因果推理（"如果 X 被推翻，哪些节点会受影响"）。

**为什么最优先**：
1. 纯确定性计算（不需要 LLM，不需要 Oracle）
2. 数据已就位（388 条人审 + W2 判决）
3. 是其他智能功能的基础（因果推理、漏洞检测都依赖辩护链）
4. 零 Oracle 风险（不生成新内容，只计算已有数据的关系）

**具体功能**：
- 辩护链生成：输入节点 ID，输出完整辩护链（攻击者+辩护者+可信度+击败关系）
- 因果推理：输入"如果 X 被推翻/改判"，输出受影响的节点列表和判决变化
- 辩护链可视化：生成辩护链的图表（节点+边+可信度+击败关系）
- 最小攻击集：计算"要让 X 变成 OUT，最少需要推翻哪些节点"

**NDW 分类**：
- N（现在可以做）：辩护链生成、因果推理（纯确定性，数据已就位）
- D（需要数据/工具）：辩护链可视化（需要 Web 界面或 HTML 生成）
- W（有风险，不做）：自动生成新的攻击边（需要 Oracle，可能生成无效边）

### 方向 2：论证漏洞检测（高优先，基于统计，零幻觉）

**目标**：基于人审数据和 W2 判决，自动检测论证层的漏洞（如"某个命题没有攻击者"、"某个 MIS 没有辩护者"、"某个子图完全孤立"）。

**为什么高优先**：
1. 基于统计和图论，零幻觉（不生成新内容，只检测已有结构的异常）
2. 可以指导后续建设（如"哪些命题需要补攻击者"、"哪些 MIS 需要复核"）
3. 是"验证已生成内容"的延伸（从验证单条内容到验证整个论证结构）

**具体功能**：
- 无攻击者命题检测：列出所有没有任何 MIS 攻击的命题（可能是论证盲区）
- 无辩护者 MIS 检测：列出所有 OUT 且无辩护者的 MIS（当前 7 个全部如此）
- 孤立子图检测：列出与其他节点完全不连通的子图
- 可信度分布异常检测：如"某个主题的 MIS 全部是 low，没有 medium"
- 人审质量检测：如"某个 MIS 的所有边都是 modify，没有 approve"（可能是歧义度高）

**NDW 分类**：
- N（现在可以做）：无攻击者命题检测、无辩护者 MIS 检测、孤立子图检测
- D（需要数据）：人审质量检测（需要 review_seconds/reason_len 等质量指标，609 A2 已加）
- W（有风险，不做）：自动修复漏洞（需要 Oracle，可能修复错误）

### 方向 3：人审效率优化（中优先，基于主动学习，降低 backlog 成本）

**目标**：基于人审数据和 W2 判决，优化人审流程（如"哪些边最值得人审"、"哪些边可以批量通过"、"哪些边需要重点复核"）。

**为什么中优先**：
1. 人审全量已完成（388/388），当前没有 backlog
2. 但未来会有新的候选攻击边（如基于人审反馈生成的新边），需要优化人审效率
3. 是"降低人的工作量"的关键（用户希望"真正完全脱手"）

**具体功能**：
- 歧义度排序：按歧义度（modify 比例、evidence 冲突、主题争议度）对候选边排序
- 批量通过建议：基于历史人审数据，建议哪些边可以批量通过（如"同主题、同 evidence 质量、同 MIS 组"的边）
- 重点复核建议：基于 W2 判决，建议哪些边需要重点复核（如"OUT 的 MIS 对应的边"、"modify 比例高的 MIS"）
- 人审工作量预估：基于候选边数量和歧义度分布，预估人审总时间

**NDW 分类**：
- N（现在可以做）：歧义度排序、重点复核建议（基于已有数据）
- D（需要数据）：批量通过建议（需要更多人审数据训练模型）
- W（有风险，不做）：自动通过（违反第一原则，人审是人的权力）

### 方向 4：推翻通道自我纠错（低优先，需要真实推翻事件，结构性瓶颈）

**目标**：基于推翻事件（overturned_events.jsonl），自动更新论证层（如"某个命题被推翻后，自动更新 W2 判决和辩护链"）。

**为什么低优先**：
1. 推翻通道当前 0 条事件（首次真实推翻需人触发）
2. 是结构性瓶颈（单用户阶段，推翻事件很少）
3. 需要真实推翻事件才能验证效果

**具体功能**：
- 推翻事件自动联动：新推翻事件写入后，自动重算 W2 判决和辩护链
- 推翻影响分析：输入推翻事件，输出受影响的节点列表和判决变化
- 推翻回滚：如果推翻事件被撤销（append-only 可追加反向记录），自动回滚判决

**NDW 分类**：
- N（现在可以做）：推翻事件自动联动（工具已就位，overturned_events.py 592 已建）
- D（需要数据）：推翻影响分析（需要真实推翻事件才能验证）
- W（有风险，不做）：自动产生推翻事件（系统绝不自动，需人触发）

## 五、风险与边界

### 5.1 第一原则不变

- **生成者不能兼任判断者**：所有智能功能只能"推理已验证数据"，不能"生成新内容并自行判断"
- **人审是人的权力**：智能功能可以建议，但最终决定必须由人做出（或由人授权的确定性规则做出）
- **系统从不自动接受 Oracle 判决**：所有智能功能的输出都是"建议"或"计算结果"，不是"判决"

### 5.2 智能的定义

**本项目的"智能"= 基于已验证数据的确定性推理**，不是：
- ❌ 生成新内容（如自动写新命题、新 MIS）
- ❌ LLM 判断（如用 LLM 判断某个命题是否正确）
- ❌ 机器学习模型（如训练一个分类器预测攻击边是否有效）
- ✅ 图论推理（如辩护链、因果推理、最小攻击集）
- ✅ 统计分析（如漏洞检测、歧义度排序、人审质量分析）
- ✅ 规则引擎（如基于确定性规则的建议生成）

### 5.3 结构性上限

1. **单用户阶段**：人审数据只有一个来源（用户本人），智能功能的训练/验证数据有限
2. **推翻事件稀缺**：首次真实推翻需人触发，推翻通道自我纠错功能难以验证
3. **可信度体系简单**：当前只有 high/medium/low 三级，且最高是 medium（没有 high 可信度节点）
4. **论证规模小**：当前只有 79 命题 + 42 MIS + 388 边，智能功能的效果可能不明显

## 七、总结

**阙疑的"智能"不是生成新内容，而是基于已验证数据的确定性推理。**

人审全量完成（388/388）和 W2 分层判决（IN114/OUT7）是智能探索的"燃料"——没有这些数据，智能无从谈起。

第一个智能原型（辩护链推理工具）是纯确定性的，零 Oracle 风险，数据已就位，预计 610-611 可以完成。

**最关键的一件事**：609 完成后（预计平均 8.1，论证层 7.0），立即启动辩护链推理工具——这是从"验证已生成内容"到"推理已验证数据之间的关系"的质变，也是阙疑从"严格知识生产系统"到"智能论证系统"的第一步。
