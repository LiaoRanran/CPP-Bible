## 一、一句话定位

**阙疑 = "生成者不能兼任判断者"第一原则下的 C++ 学习内容可验证性系统**——它不是一本 C++ 书，而是一套"如何让 AI 生成的知识不撒谎"的验证方法论，C++ 只是它的第一个、也是最复杂的实验场。

### 2.3 平台期的本质

_arch_v18 调研的核心发现：**平台期不是"做不动了"，而是"目标替代"**——51 批次把工件验证做到 9.2，但仓内无一条用户掌握度记录。系统在"验证已生成的内容"上越来越强，但在"人是否真的学会了"这个终极目标上，还是零。

**这不是坏事**——这说明基建已经足够扎实，可以开始向更高层目标（学习者镜像→自进化→领域扩展）进军了。

## 三、核心竞争力（护城河）

### 3.1 第一原则：生成者不能兼任判断者

这是阙疑的灵魂。所有设计都围绕这条原则：
- 苦力不跑验收（角色分离）
- 人审是人的权力（系统从不自动接受 oracle 判决）
- delegation 默认关闭（永不自动）
- golden accept 永不自动（人审权力）

**这条原则让阙疑和"AI 自己写自己审"的系统有本质区别**——后者把可能出错的地方从内容层挪到了验证层，套了一层更难被发现的壳。阙疑拒绝这条路。

### 3.2 验证方法论（可迁移）

阙疑的核心资产不是 27 张原子卡或 56 张证据卡，而是**这套验证方法论本身**：
- 变异测试 + 等价变异体判别
- 毒样例 + 阴性对照
- 行为级覆盖（封死覆盖率伪造）
- Merkle + in-toto + OpenTimestamps 供应链溯源
- W2 加权论证框架
- BKT 学习者镜像
- Clopper-Pearson 统计上界

**这套方法论可以迁移到任何知识生产场景**——电子、金融、法律、医学。C++ 只是第一个实验场，而且是已知最复杂的知识生产场景之一。

### 3.3 诚实度量（反 AI 味）

阙疑的度量哲学是"只给统计上界，不给虚假宣称"：
- 逃逸率 1/1406，C-P95 上界 [0.0018%, 0.3956%]——不说"零逃逸"，说"上界 0.4%"
- 表观覆盖率 100% vs 诚实覆盖率 95.2%——主动暴露虚高
- v1→v5 标为"口径修正"而非"单调收敛"——不伪造进步
- 六维度评分明确标注"系统自评估，非客观质量分"

**这种诚实本身就是竞争力**——在 AI 生成内容普遍夸大的时代，"主动说自己哪里不行"比"说自己都行"更可信。

## 四、风险与挑战

### 4.1 结构性风险（无法通过工程解决）

| 风险 | 说明 | 缓解 |
|------|------|------|
| **单用户信任根无法闭环** | git 作者可自设、无第三方时间戳、无密钥签名 | OpenTimestamps 链锚可部分缓解（免密钥），但身份上限仍在 |
| **单人评审风险** | 388 条人审全由 1 人完成，automation bias 风险 | NEJM AI 2026 实证：automation bias 使准确率降 14pp；陷阱题+理由长度可检测 |
| **外部认可度** | GitHub 上搜不到 LiaoRanran/CPP-Bible（小仓库收录不全） | push 后可解；但"可信参考"需要外部独立验证者 |

### 4.2 工程风险（可解决但需投入）

| 风险 | 说明 | 优先级 |
|------|------|--------|
| **modify 口径冲突** | keep-low（IN114/OUT7）vs upgrade-medium（IN121/OUT0），7 节点翻转 | P0 |
| **governance high=55** | 55 条历史文档描述性内容被标 high，需人审语义判定 | P0 |
| **活性锚缺 50 条** | gate 持续报 OBSERVATION-LIVENESS warn | P1 |
| **oracle 0/83 卡** | 换代时全体强制重验 | P1 |
| **M6 等价变异** | 8 条等价变异稀释拦截率（379/716=52.9%） | P1 |
| **M1 TCE 逃逸** | 1 条真实逃逸（冻结，需工件比对） | P2 |

### 4.3 战略风险（方向选择）

| 风险 | 说明 |
|------|------|
| **"自用工具书" vs "对外可信参考"** | 前者目标已近（内核搓熟），后者需要外部独立验证者（结构性难题） |
| **包装层时机** | 内核还"远远没有产生类智能"，过早做包装层会分散精力 |
| **领域扩展顺序** | C++→电子→金融，每一步验证方法论的可迁移性递减，难度递增 |
| **自进化系统的伦理边界** | 系统自己发现→提案→验证→合并，在哪一步必须停？第一原则是否允许？ |

## 七、对用户的建议

### 7.1 现在最该做的事

1. **用起来**——学习者镜像（612）完成后，用户自己作为第一个"学习者"用起来。没有真实用户数据，BKT 就是空中楼阁。
2. **裁决 modify 口径**——这个决策不做，论证层的所有结论都是"双轨制"，对外无法讲清楚。
3. **push**——9 个 commit 待推，CI 持续红，影响外部可见性。

### 7.2 不要做的事

1. **不要现在做包装层**——内核还"远远没有产生类智能"，包装层是锦上添花，不是雪中送炭。
2. **不要打开 delegation**——第一原则，永不自动。
3. **不要攻坚 M1 TCE**——1 条逃逸，工作量大，收益小，继续冻结。
4. **不要声称"零逃逸"**——1/1406 不是零，C-P95 上界 0.4% 才是诚实表述。

### 7.3 最值得投入的方向

**学习者镜像**——这是唯一能让系统从"验证已生成的内容"跃迁到"帮助人真正学会"的方向。_arch_v18 调研已经证明这是下一个跃迁点，612 正在做第一个原型。如果这个原型能跑通（用户用起来，掌握度数据真实增长，推荐真的有用），那阙疑就从"验证工具"变成了"学习系统"——这是质的飞跃。

**阙疑的基建已经足够扎实（平均 8.1），现在是从"验证内容"向"帮助人学会"跃迁的拐点。学习者镜像是这个跃迁的钥匙。用起来，比什么都重要。**
