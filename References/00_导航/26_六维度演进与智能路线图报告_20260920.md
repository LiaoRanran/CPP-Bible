## 三、结构性上限声明

### 3.1 信任根层上限（8.5）

**原因**：单用户阶段身份无法闭环。
- git 作者可自设（人签自证）
- OpenTimestamps 只证"存在时间"不证"身份"
- SLSA L2+ 不可达（单用户）
- 无密钥/签名身份认证

**解冻信号**：引入异族独立验证者（oracle 验证 0/83 → 83/83），或引入外部可信时间戳+签名身份。

### 3.2 机械判决层上限（9.5）

**原因**：单用户阶段规则集有限，无法覆盖所有边界情况。
- M1 TCE 逃逸（escaped=1，冻结）
- 变异算子覆盖有限（7 算子）
- 规则集 63 条（可能有未覆盖场景）

**解冻信号**：引入更多变异算子（R8），或引入外部独立验证者交叉验证判决。

### 3.3 人审层上限（9.0）

**原因**：单用户人审质量受限于个人判断力和时间。
- automation bias（单人易橡皮图章）
- 人审一致性无法验证（无第二人交叉）
- 人审耗时有限（388 条已全量，但后续新增需持续）

**解冻信号**：引入第二人审（四眼原则），或引入异族独立验证者交叉验证人审结果。

**状态**：610 进行中（B1 核心引擎/B2 CLI/B3 HTML 可视化）。

### 4.3 智能原型 2：论证漏洞检测工具（610 C1-C3）

**核心能力**：

- 高级漏洞（6 类）：modify 比例/rubber-stamp/主题不平衡/命题过载/MIS 过载/循环论证
- 漏洞报告生成（完整报告+优先级+修复建议）

**基础**：
- 609 论证层可视化

- W2 分层判决（IN114/OUT7）

**状态**：610 已完成（C1/C2/C3 三个 commit）。

### 4.4 智能原型 3：论证推理引擎（611-615，规划中）

**目标**：从"检测漏洞"到"自动推理论证"。

**核心能力**（规划中）：
- 给定命题，自动推导支持/攻击链
- 给定 MIS，自动推导被驳斥的命题

**基础**：

- W2 分层判决（IN114/OUT7）

**状态**：规划中，待 610 完成后启动。

### 4.5 智能原型 4：自我纠错系统（616-620，规划中）

**目标**：从"人工触发推翻"到"自动检测并建议推翻"。

**核心能力**（规划中）：
- 自动检测判决不一致（同一命题不同路径判决不同）
- 自动检测人审错误（人审结果与 W2 判决矛盾）
- 自动生成推翻建议（附证据链）
- 推翻通道集成（overturned_events.py）
- 自我纠错闭环（推翻→重算→验证）

**基础**：
- 610-615 智能原型 1-3
- 推翻通道（overturned_events.py，592 已建）
- 人审全量数据（388/388）

**状态**：规划中，待智能原型 1-3 完成后启动。

**第一原则约束**：自我纠错系统只"建议"推翻，不"自动"推翻。最终推翻必须由人触发（human 须过 git 作者绑定，fail-closed）。系统绝不自动产生推翻。
