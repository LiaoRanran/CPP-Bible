## 三、测试质量评估

### 3.1 测试架构优点

| 优点 | 说明 | 证据 |
|---|---|---|
| **分层测试** | fast/slow 分离，fast 72s/slow ~6min | pyproject.toml markers |
| **快照测试** | syrupy 快照锁输出 | 5 snapshots passed |
| **回归锁** | 每批新增测试锁行为 | 609 新增 125 用例 |
| **确定性保障** | replay_serial/SERIAL_EXTRA 防并发假红 | conftest.py |
| **行为级覆盖** | poison 行为级覆盖（非文本 grep） | 38/63 RULE-COVERAGE |
| **等价变异自证** | --selfcheck-equivalent 保守性自证 | 凡标等价者 new_block/warn 必空 |

### 3.2 测试架构不足

| 不足 | 影响 | 建议 |
|---|---|---|
| **slow 测试时间长** | ~6 分钟，开发者反馈慢 | 609 B1 已优化 72.6s→20.0s，H9 连接复用待做 |
| **并发假红历史** | -n auto 下 replay 锁竞争 | replay_serial/SERIAL_EXTRA 已缓解 |
| **golden 预期红** | test_golden_lock_json 持续红 | 人审权力，永不自动 accept |
| **测试覆盖率未量化** | 无 coverage.py 报告 | 建议加 coverage 报告（中优先级） |
| **mutation 测试超时** | test_mutation_fuzz.py 全量超时 | 609 B2 如实标 TIMEOUT |

### 3.3 测试纪律

| 纪律 | 状态 | 说明 |
|---|---|---|
| 一任务一 commit | ✅ | 每批 5-20 commit |
| 新功能必加测试 | ✅ | 609 新增 125 用例 |
| 回归锁必加 | ✅ | 每批收工门禁 |
| CORE 修改必 --update | ✅ | tool_integrity --update |
| 不修改受控目录 | ✅ | atoms/evidence/Examples/Book |

## 六、结论

阙疑项目测试体系已达 **135 个测试文件/~1250 用例**，分为 **16 类**，fast/slow 分离（72s/~6min），快照测试 5 个，唯一预期红 1 个（golden 待 accept）。

**测试体系的三大特点**：
1. **分层测试架构成熟**——fast/slow 分离，回归锁+快照+确定性保障
2. **行为级覆盖**——poison 行为级覆盖（38/63），非文本 grep
3. **测试纪律严格**——一任务一 commit/新功能必加测试/CORE 修改必 --update

**测试体系的三大不足**：
1. **slow 测试时间长**——~6 分钟，609 B1 已优化但仍有空间
2. **测试覆盖率未量化**——无 coverage.py 报告，建议加
3. **并发假红历史**——replay_serial/SERIAL_EXTRA 已缓解但未根除
