## 一、核心资料（S 级）

### 1. Michael-Scott Queue（PODC 1996）

- **类型**：学术论文（奠基性）
- **来源**：University of Rochester（cs.rochester.edu）
- **链接**：https://www.cs.rochester.edu/u/scott/papers/1996_PODC_queues.pdf
- **作者**：Maged M. Michael、Michael L. Scott
- **核心内容**：提出了至今仍是标准的无锁 FIFO 队列算法——单链表 + dummy node + Head/Tail 指针 + CAS 循环 + modification counter 防 ABA。同时提出两锁队列（Head lock + Tail lock）作为对比。
- **解决的问题**：在多生产者多消费者场景下，如何实现不阻塞、不死锁的并发队列
- **为什么重要**：**这是使用最广泛的无锁队列算法**，Java `ConcurrentLinkedQueue`、Boost.Lockfree、folly 等都基于此。论文含完整伪代码、正确性证明（5 条不变量归纳）、线性化证明、非阻塞性证明、12 核 SGI 性能实验。
- **技术亮点**：
  - **dummy node 技巧**：Head 始终指向 dummy node，使 enqueue 不碰 Head、dequeue 不碰 Tail，避免死锁
  - **Tail 可以滞后**：Tail 指向最后或倒数第二个节点，dequeue 时帮忙推进 Tail（"帮忙"模式是无锁算法的常见技巧）
  - **modification counter 防 ABA**：CAS 的不是裸指针而是 `<ptr, count>` 对
  - **一致性检查（E7/D5）**：每次 CAS 前重新读取并检查 Tail/Head 是否变化，防止使用过期值
  - **先读值再 CAS（D12）**：dequeue 必须在 CAS 前读出 value，否则另一个 dequeue 可能已经 free 了节点
- **与 C++ 的关系**：C++ 实现只需 `std::atomic<Node*>` + `compare_exchange_weak`；论文的伪代码可直接翻译
- **与 CPP-Bible 的关系**：CONC 域"无锁队列"核心原子；可以做成从两锁队列→无锁队列的渐进式教学案例
- **可以放入哪个章节**：part09_concurrency（lock-free 数据结构）
- **适合讲什么**：CAS 循环模式、dummy node 技巧、ABA 问题与防御、线性化点
- **可以提取什么源码**：论文 Figure 1 的完整伪代码（~40 行），可直接翻译为 C++
- **可以设计什么实验**：单锁队列 vs 两锁队列 vs MS 无锁队列的性能对比（不同线程数、不同工作负载）
- **可以设计什么案例**：MS queue 的"帮忙推进 Tail"模式——这是无锁算法中"其他线程帮你完成未竟工作"的经典案例
- **历史背景**：1996 年 PODC 会议；之前的无锁队列算法（Valois、Prakash）都有缺陷或不完整；Michael-Scott 是第一个简单、正确、实用的
- **工程背景**：12 核 SGI Challenge 上的实验表明，无锁队列在多道程序系统上显著优于阻塞算法（因为不会被调度延迟拖死）
- **相关论文**：Treiber 1986（stack）、Herlihy 1991（共识数）、Michael 2004（Hazard Pointer）
- **相关项目**：Java ConcurrentLinkedQueue、Boost.Lockfree、folly MPMCQueue（不同思路）
- **相关作者**：Maged Michael（也是 Hazard Pointer 发明者）、Michael Scott
- **可信度**：S
- **教材价值**：S

### 2. preshing "An Introduction to Lock-Free Programming"

- **类型**：技术博客（经典入门）
- **来源**：preshing.com
- **链接**：https://preshing.com/20120612/an-introduction-to-lock-free-programming/
- **作者**：Jeff Preshing
- **核心内容**：lock-free 的学术定义（Herlihy："在无限执行中，无限次有某个方法调用完成"）、CAS 循环模式、ABA 问题、顺序一致性 vs 弱内存模型、x86 TSO vs ARM/PowerPC 弱模型
- **解决的问题**：如何从"不用锁"的模糊概念过渡到"非阻塞性"的精确定义
- **为什么重要**：**lock-free 最好的入门文章之一**。澄清了"lock-free ≠ 不用 mutex"——lock-free 是一种活性保证（系统不可能死锁），不是实现方式
- **技术亮点**：
  - **lock-free 的精确定义**：不是"不用锁"，而是"只要有线程在调用操作，就一定有操作在有限步内完成"——一个线程被调度延迟不会拖死其他线程
  - **CAS 循环的标准模式**：读共享变量到局部 → 做投机工作 → CAS 发布 → 失败重试
  - **ABA 问题的直觉解释**：线程读 A，其他线程改成 B 再改回 A，CAS 误以为没变
  - **x86 TSO 的关键事实**：x86 上每个 load 自带 acquire、每个 store 自带 release——所以很多 x86 上能跑的无锁代码在 ARM 上会崩
- **与 C++ 的关系**：直接用 `std::atomic` 和 `compare_exchange_weak` 演示；C++11 atomic 默认 seq_cst 但可降级
- **与 CPP-Bible 的关系**：CONC 域"无锁编程入门"的最佳参考写法；与上一轮内存模型调研形成闭环
- **可以放入哪个章节**：part09_concurrency
- **适合讲什么**：lock-free 定义、CAS 循环、ABA、内存序与平台差异
- **可以设计什么实验**：在 x86 上跑通的无锁代码，用 QEMU ARM 模拟验证是否在弱模型上失败
- **历史背景**：2012 年发表，C++11 刚标准化 atomic；至今仍是最受推荐的 lock-free 入门
- **可信度**：A+（一手实践，代码可复现）
- **教材价值**：S

## 二、工业实现（A+ 级）

### 3. folly MPMCQueue（序列号同步模式）

- **类型**：开源库（工业实现）
- **来源**：Facebook folly（GitHub）
- **链接**：https://github.com/facebook/folly/blob/master/folly/MPMCQueue.h
- **核心内容**：有界多生产者多消费者队列，用**每个槽位的 turn 序列号**实现同步，不需要 CAS 重试循环
- **解决的问题**：MS queue 的 CAS 循环在高竞争下会大量重试（cache line 乒乓）；MPMCQueue 用序列号把重试变成"等轮到我"
- **为什么重要**：**这是与 MS queue 完全不同的设计思路**——MS queue 是链表+CAS，MPMCQueue 是环形数组+序列号。序列号模式更高效、更简单，但需要有界
- **技术亮点**：
  - **序列号同步**：每个槽位有 `turn`，生产者等 `turn == ticket` 然后写数据并 `turn += 1`；消费者等 `turn == ticket+1` 然后读数据并 `turn += 1`
  - **无 CAS 循环**：用 `atomic::wait`（C++20）或自旋等序列号，不需要 compare_exchange
  - **内存序最优**：生产者写数据用 release、消费者读数据用 acquire；序列号本身用 seq_cst（或 acquire/release 配对）
  - **动态扩容**：支持多段数组（closed arrays），ticket offset 追踪当前段
- **与 C++ 的关系**：纯 C++ 模板，用 `std::atomic`；是学习 C++20 `atomic::wait`/`notify` 的绝佳案例
- **与 CPP-Bible 的关系**：CONC/PERF 交叉原子——"两种无锁队列设计对比"；序列号模式是 MS queue 之外的重要路线
- **可以放入哪个章节**：part09_concurrency、part14_perf
- **适合讲什么**：序列号同步模式、有界 vs 无界队列、CAS 循环 vs 序列号等待
- **可以提取什么源码**：核心 enqueue/dequeue（~30 行）
- **可以设计什么实验**：MS queue vs MPMCQueue 在不同线程数/队列长度下的吞吐对比
- **历史背景**：序列号模式源于 Dmitry Vyukov 的 bounded MPMC queue；folly 在此基础上增加了动态扩容
- **相关项目**：Vyukov 的 MPMC queue、Boost.Lockfree queue
- **可信度**：A+（Facebook 生产环境验证）
- **教材价值**：A+

### 4. folly ConcurrentHashMap（Hazptr 内存回收）

- **类型**：开源库（工业实现）
- **来源**：Facebook folly（GitHub）
- **链接**：https://github.com/facebook/folly/blob/master/folly/concurrency/ConcurrentHashMap.h
- **核心内容**：分段锁 + 无锁读取的并发哈希表，用 **Hazard Pointer** 做节点内存回收
- **解决的问题**：并发哈希表的读路径无锁、写路径分段锁，节点删除后安全回收
- **为什么重要**：**这是 Hazard Pointer 在工业代码中的真实使用案例**——与上一轮 RCU 调研形成直接对比。文件头注释明确说"多线程性能只输给 lock-free atomic maps（AtomicUnorderedMap/AtomicHashMap），但前提是你能完美预估大小"
- **技术亮点**：
  - **分段锁**：写操作只锁一个 segment，不锁全表
  - **Hazptr 保护读路径**：读节点时用 hazptr_holder 保护，删除节点后等 grace period 再回收
  - **与 AtomicHashMap 的对比**：AtomicHashMap 是纯无锁但需要预分配固定大小；ConcurrentHashMap 更灵活
- **与 C++ 的关系**：用 folly Hazptr（上一轮调研的 folly hazptr 实现）
- **与 CPP-Bible 的关系**：CONC 域"无锁哈希表"案例；展示 HP 在真实代码中的用法
- **可以放入哪个章节**：part09_concurrency
- **适合讲什么**：分段锁设计、Hazptr 实际用法、无锁读+有锁写的混合设计
- **历史背景**：folly 是 Facebook 的基础库，ConcurrentHashMap 用于 Facebook 后端
- **可信度**：A+
- **教材价值**：A

## 四、无锁数据结构的"渐进式"教学路径（CPP-Bible 可直接用）

这是本轮调研最有教学价值的发现——无锁数据结构可以做成一条**渐进式学习路径**，每一步都有明确的"为什么需要下一步"：

| 步骤 | 数据结构 | 同步机制 | 解决的问题 | 新引入的概念 |
|---|---|---|---|---|
| 1 | 单锁队列 | mutex | 基础线程安全 | 临界区 |
| 2 | 两锁队列 | Head lock + Tail lock | 读写并发 | 锁粒度 |
| 3 | MS 无锁队列 | CAS 循环 | 消除锁、避免调度延迟拖死 | CAS、ABA、线性化 |
| 4 | MPMCQueue | 序列号 | 消除 CAS 重试（高竞争优化） | 序列号同步、有界队列 |
| 5 | 无锁哈希表 | 分段锁 + Hazptr | 从队列到更复杂结构 | 内存回收、分段 |

每一步都可以做性能对比实验，让学生看到"为什么需要更复杂的机制"。
