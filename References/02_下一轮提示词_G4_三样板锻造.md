| 样板 | 主题 | 域 | 取材 |

### 每样板必须走四步（**一轮内走完四步，但每步独立留痕、不得合并成一段**）

> 澄清（2026-09-10 监工确认）："一轮内走完"= 一次来回里把四步全做完（减少往返轮次），
> **不是**"把红队与升级合并成一步"。红队报告与升级说明是两份材料：前者只负责挑错，
> 后者逐条回应"补了什么"，混写成"我改了"就无法验证是否真被挑出问题。

1. **写"3 分平庸版"** —— 正确但平庸：只有结论 + 一段解释，像普通教程那样。
   保存为 `goldens/{A,B,C}_*.md` 的 `## 平庸版` 节（或独立 `*_v3.md`）。
2. **红队攻击** —— 拿 S1–S6 逐条找漏洞，输出攻击报告：
   - S1：签收是不是人？`verified_by: human:*` 有了吗？
   - S2：断言有没有可独立复算的证据？`evidence[]` 指向的卡 `verdict` 是 confirm 吗？
   - S3：反例真会失败吗？期望值有没有硬编码进夹具？矩阵够不够（compiler/std/opt）？
   - S4：入库会不会让黄金锁恶化？（先 `python tools/golden_lock.py check` 看基线）
   - S5：有没有需要开的豁免票？若开票，`owner` 必须 `human:*`。
   - S6：把这份样板当"毒样例"攻击制衡层——现有规则抓不抓得住它的问题？
3. **升级到 5 分候选** —— 逐条写明"补了什么"：补了哪个证据（卡 ID + 哈希）/ 钻到哪一层
   （`depth.layer` + `drill_note`）/ 补了哪些误解（分层）/ 加了什么教学桥（预测-揭示、对照）。
4. **人审** —— 交用户审。**未获认可不得作为模板、不得进 `atoms/`、不得进 G5。**

### 五件套硬性要求（每样板都要满足）

1. **祈使句标题**（"用 `move` 表达所有权转移" 而非 "移动语义介绍"）；
2. **四段式叙事**（问题 → 机制 → 证据 → 反例与边界）；
3. **误解分层**（`pedagogy.misconception[]` ≥3 条，**每项标 `level: surface|deep`**；
   **deep 类必须配 ≥2 个独立反例**指向证据卡——surface 一次纠正即可，deep 是结构性误解，
   反例不够纠不过来。依据见 `G1_layout.md` §3，门禁规则 `ATOM-MISCONCEPTION-LEVELS` 会拦）；
4. **三问题主线**（是什么 / 为什么需要 / 什么时候**不该**用）；
5. **ASM 行号注释**（纵深证据指向具体汇编行，如 `call malloc @line 109`，不是泛泛"我看了汇编"）。

## 注意事项（血泪清单，别重蹈）

1. **工件与断言必须同代**：改 `.cpp` 或改卡里计数 → 必须重生成 artifact 并换 `artifact_sha256`；
   核验要比"**新工件 vs 卡**"，不是"旧工件 vs 旧记录"。
2. **卡 `command` 契约**：路径正斜杠 · 编译产物必须写 `build/`（根级 exe 会被 pre-push 拦）·
   `&&` 串联 · 不支持管道/重定向。
3. **编译验证不带 PATH 前缀**：裸 `g++` 在本机 PATH 里解析到 **mingw1310（缺 cc1plus）**，
   工具已钉 `toolchain.resolve_gpp()`；但**人工验证也别前置 PATH**，否则是假阳性。
4. **新建议的两条**：S3 的"硬编码期望"检测会拦"打印常量冒充观测"——夹具里不要出现
   与 `actual` 完全相同的字符串字面量。
5. **查同名必须 rglob**：新增 `tools/*.py` 前递归查（`tools/legacy/` 下已有同名踩过坑）。
6. **中文提交走 `-F` + UTF-8 文件**；`i18n.commitEncoding/logOutputEncoding` 已设 utf-8。
