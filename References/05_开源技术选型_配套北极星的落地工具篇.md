### 1.1 可放心引入（宽松 / 弱传染）



| 许可证                                    | 含义                                   | 本项目可用方式                   |
| -------------------------------------- | ------------------------------------ | ------------------------- |
| MIT / BSD-2 / BSD-3 / Apache-2.0 / ISC | 保留版权声明即可，可闭源衍生                       | 直接依赖、可打包进产物               |
| MPL-2.0                                | 弱传染：**修改它本身的文件**才需开源，你写的内容 / 调用方不受影响 | mdBook 这类构建工具可放心用，不改它源码即可 |
| CC BY-SA / CC BY                       | 内容许可，署名 + 相同方式共享                     | 仅用于 "内容参考"，不拷代码           |

### 1.2 必须隔离（强传染）



| 许可证                                             | 风险                | 本项目对策                                                    |
| ----------------------------------------------- | ----------------- | -------------------------------------------------------- |

## 5. 引入依赖的五条不变量



1. **许可证先行**：进依赖前读 LICENSE 全文、存 `docs/third_party/`、登来源台账；MIT/BSD/Apache/ISC/MPL (不改源码) 放行，GPL/AGPL 一律进程隔离或不用。

2. **G5 零运行时依赖**：当前阶段只预留数据字段，不提前装 G6+ 的工具，防止工具绑架内容生产节奏。

3. **能抄架构就不引依赖**：open-mastery/PyEdmine/NexStep/pyKT 读设计即可，核心质量链（gate/replay）保持自研一致性。

4. **服务化隔离强传染**：Judge0 类只走 HTTP，仓库内只存客户端调用代码和部署文档，不 vendoring 其源码。

5. **工具服从内容，不反向**：任何工具要求改变原子 schema / 证据卡契约 / 阶段门的，先改工具适配，不动已人审的内容标准。
