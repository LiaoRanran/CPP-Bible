## 一、核心资料（S/A+ 级）

### 1. CDSChecker：C/C++11 内存模型的穷举模型检查器

- **类型**：学术工具（OOPSLA 2013 + TOPLAS 2016 期刊扩展版）
- **来源**：UC Irvine（Brian Norris & Brian Demsky）
- **链接**：http://demsky.eecs.uci.edu/cdschecker/ · 论文 https://dl.acm.org/doi/pdf/10.1145/2806886
- **核心内容**：穷举探索并发代码在 C/C++11 内存模型下的**所有合法行为**，用偏序归约（partial order reduction）消除冗余执行、缩小状态空间。以动态库形式实现 thread/atomic，不需要特殊编译器。
- **解决的问题**：人脑无法穷举弱内存模型下的所有交织和重排——"看起来对"的并发代码可能在某些合法执行下出错
- **为什么重要**：**它发现了已发表、经同行评审的 work-stealing queue（Chase-Lev deque）和 SPSC queue 中的 bug**。这证明了两件事：① 并发算法的正确性极难靠人脑保证；② 模型检查能找到 code review 和测试找不到的 bug。
- **技术亮点**：
  - 直接实现 C++11 内存模型（不是 SC 近似），relaxed/acquire/release/seq_cst 都精确建模
  - 偏序归约 + 多种新技术最小化执行数
  - CDSSPEC 扩展：用规格注解自动检查线性一致性（linearizability）
- **局限**：有状态模型检查面临状态空间爆炸；不适合大规模程序，适合单元级数据结构
- **与 CPP-Bible 的关系**：CONC 域"怎么验证无锁代码正确"的核心工具；与第五轮 herd7（litmus 级）互补——herd7 验证小片段，CDSChecker 验证完整数据结构
- **可以设计什么实验**：用 CDSChecker 跑一个故意写错内存序的无锁栈（release 写成 relaxed），展示它能穷举出错误执行
- **可信度**：S（OOPSLA + TOPLAS，被后续工具广泛引用）
- **教材价值**：S

### 2. GenMC：模块化多内存模型的无状态模型检查器

- **类型**：学术工具（CAV 2021）
- **来源**：ETH Zurich / MPI-SWS（Michalis Kokologiannakis、Viktor Vafeiadis 等）
- **链接**：https://people.inf.ethz.ch/mkokologiann/papers/cav2021-genmc.pdf · GitHub 开源
- **核心内容**：基于 LLVM 的无状态模型检查器，用执行图（execution graph）表示程序行为。模块化架构支持 RC11（修复后的 C++11 模型）、IMM（中间内存模型，可映射到 x86/ARM/Power）、LKMM（Linux 内核模型）。
- **为什么重要**：**一个工具可以切换不同内存模型验证同一份代码**——这正好对应 CPP-Bible 第七轮"x86 能跑 ARM 失败"的教学需求：同一份代码在 IMM-x86 下无 bug，切到 IMM-ARM 就可能出错。
- **技术亮点**：
  - 无状态（stateless）：不存全局状态，用 DPOR（动态偏序归约）避免重复探索
  - 已扩展到 Rust（RustMC，2025）、持久内存（PerSeVerE/Px86）
  - **Nidhugg（姊妹工具）用它复现了 Linux Tree RCU 的生产环境安全和活性 bug**——几秒钟内复现
  - 支持自定义同步原语
- **与 CDSChecker 对比**：CDSChecker 只支持 C++11 模型；GenMC 模块化支持多模型，且基于 LLVM 更工程化
- **可信度**：S（CAV，形式化验证顶会）
- **教材价值**：A+

### 3. Relacy Race Detector：开发者友好的单线程模拟器

- **类型**：开源工具库
- **来源**：Dmitry Vyukov（Google，MPMCQueue/SPSC queue/工作窃取算法作者）
- **链接**：https://github.com/dvyukov/relacy
- **核心内容**：用协程在**单线程内模拟多线程调度**——把 `std::atomic` 替换为 `rl::atomic`、`std::thread` 替换为 `rl::thread`，Relacy 穷举所有线程交织和 C++11 内存模型允许的重排。
- **为什么重要**：**这是开发者最容易上手的并发验证工具**——不需要特殊编译器、不需要多线程环境、确定性复现（每次跑同样的调度序列）。
- **技术亮点**：
  - 检测数据竞争、死锁、活锁、丢失唤醒
  - 精确模拟 C++11 内存模型（包括 relaxed）
  - 单线程确定性执行——bug 可 100% 复现（不像真多线程偶现）
  - **moodycamel::ConcurrentQueue（工业级无锁队列）内置 Relacy 测试支持**（`MCDBGQ_USE_RELACY` 宏）
  - 支持标准同步原语（mutex/rwlock/condvar/semaphore）
- **局限**：模拟的是 C++ 内存模型，不是真实硬件；状态空间大时也会爆炸
- **与 CPP-Bible 的关系**：CONC 域"写一个无锁数据结构后怎么自测"的首选工具；教学上比 CDSChecker 更易演示
- **可信度**：A+（工业界广泛使用，作者是无锁编程权威）
- **教材价值**：S（教学友好度最高）

### 4. ThreadSanitizer（TSan）vs KCSAN：动态检测的两条路线

- **类型**：生产级动态检测工具
- **来源**：Google（TSan）/ Linux Kernel（KCSAN）
- **链接**：https://releases.llvm.org/9.0.0/tools/clang/docs/ThreadSanitizer.html · https://docs.kernel.org/dev-tools/kcsan.html
- **核心对比**：

| 维度 | TSan（用户态） | KCSAN（内核态） |
|---|---|---|
| 检测方式 | 编译器插桩，追踪所有内存访问 | watchpoint + 采样，概率性检测 |
| 算法 | 混合 lockset + happens-before | 采样观察窗口内的冲突访问 |
| 开销 | 5-15x 减速、5-10x 内存 | 较低（采样可调） |
| 覆盖率 | 高（检查所有访问） | 概率性（采样可能漏报） |
| 弱内存模拟 | **不模拟重排**（近似 SC） | **CONFIG_KCSAN_WEAK_MEMORY=y 可模拟重排** |
| 适用 | 用户态 C/C++ 程序 | Linux 内核 |

- **关键洞察**：**TSan 不模拟弱内存重排**——它检测的是 SC 下的数据竞争。这意味着在 x86（接近 SC）上 TSan 漏报的 bug，在 ARM 上可能爆发。KCSAN 的弱内存模拟是独特能力：它主动模拟内存访问重排来暴露缺失屏障的 bug。
- **KCSAN vs KTSAN**：KTSAN 是基于纯 happens-before 的方案，需要了解 LKMM 全部排序规则（复杂）；KCSAN 用采样绕开了建模全部规则的负担，但代价是概率漏报。
- **可信度**：S（Google/Linux 官方工具，工业级）
- **教材价值**：S

## 二、并发正确性验证的四个层次

```
层次 1：动态检测（运行时观察）
  TSan（用户态，全覆盖高开销，不模拟弱内存）
  KCSAN（内核态，采样低开销，可模拟弱内存重排）
  → 问题：只覆盖实际跑到的执行，偶现 bug 可能漏

层次 2：模拟调度（单线程穷举交织）
  Relacy（协程模拟，确定性复现，开发者友好）
  → 问题：模拟 C++ 模型而非真实硬件，状态空间大时爆炸

层次 3：模型检查（穷举所有合法执行）
  CDSChecker（C++11 模型，发现过 Chase-Lev deque bug）
  GenMC（多模型模块化：RC11/IMM/LKMM，可切 x86/ARM）
  Nidhugg（LLVM-based，复现过 Linux RCU bug）
  → 问题：状态空间爆炸，只适合单元级数据结构

层次 4：形式化证明（数学证明正确性）
  herd7（litmus test 级，cat 模型穷举）
  TLA+（设计/算法级，AWS 用来找 DynamoDB bug）
  交互式定理证明（Coq/Isabelle，最强但最贵）
  → 问题：成本极高，需要形式化方法专业知识
```

**教学主线**：层次 1 是日常工具（每次写并发代码都跑 TSan）→ 层次 2 是无锁数据结构自测（Relacy）→ 层次 3 是关键数据结构发布前验证（CDSChecker/GenMC）→ 层次 4 是标准/内核级正确性保证。

## 三、其他高价值资料（A 级）

### 5. Correct and Efficient Work-Stealing for Weak Memory Models（PPoPP 2013）

- **类型**：学术论文
- **来源**：INRIA / Cambridge（Nhat Minh Lê、Antoniu Pop、Francesco Zappa Nardelli、Alastair Reid）
- **链接**：https://fzn.fr/readings/ppopp13.pdf
- **核心内容**：Chase-Lev work-stealing deque 在弱内存模型下的正确实现——逐操作分析 take/push/steal 的内存序需求。正是 CDSChecker 发现旧实现 bug 后，社区给出的弱内存修正版。
- **教学价值**：**"一个经典无锁算法在弱内存下需要哪些屏障"的完整推导**，是 CONC 域高阶原子的绝佳案例。

### 6. RelaSharp：C# 版 Relacy 思路

- **类型**：开源工具
- **链接**：https://github.com/nicknash/RelaSharp
- **核心内容**：生成 C++11/C# 内存模型允许的执行、竞争检测、死锁/活锁检测、随机调度。Relacy 思路的跨语言验证。
- **教学价值**：说明"单线程模拟多线程"是通用验证范式。

### 7. CODEX/CB-DPOR：Boost lock-free queue bug

- **类型**：学术研究
- **核心内容**：用上下文有界 DPOR 模型检查，在 Boost lock-free queue（Michael-Scott queue 实现）的开发版本中复现了一个需要 5 线程交织才触发的 bug。
- **教学价值**：又一个"知名库也有并发 bug"的真实案例。

### 8. moodycamel::ConcurrentQueue 的 Relacy 集成

- **类型**：工业源码
- **核心内容**：工业级无锁队列通过 `MCDBGQ_USE_RELACY` 宏内置 Relacy 测试——这是"工业项目用模拟调度验证无锁代码"的范例。
- **教学价值**：展示验证工具如何融入真实项目的构建系统。

## 四、工具选型决策表

| 场景 | 首选工具 | 理由 |
|---|---|---|
| 日常并发代码自测 | TSan | 编译器开关即用，覆盖率高 |
| 写了一个无锁数据结构 | Relacy | 确定性复现，穷举交织，上手简单 |
| 关键无锁结构发布前验证 | GenMC | 多内存模型，可切 x86/ARM 对比 |
| 验证 C++ 内存序选择是否正确 | CDSChecker | 精确实现 C++11 模型 |
| Linux 内核并发 bug | KCSAN | 内核态 + 弱内存模拟 |
| litmus test 级别的硬件行为 | herd7 | cat 形式化模型 |
| 算法/协议设计级正确性 | TLA+ | 抽象级别高，AWS 验证 DynamoDB |
| ARM 上才出现的 bug | GenMC(IMM-ARM) 或 KCSAN weak | TSan 在 x86 上模拟不了 ARM 重排 |

## 九、对 CPP-Bible 的工程升级建议

1. **CONC 域新增"并发验证工具链"章节**——四层次 + 选型决策表，这是现有教材普遍缺失的
2. **每个无锁数据结构原子配三层验证**：TSan（动态）+ Relacy（模拟）+ 模型检查（穷举），形成验证阶梯
3. **"TSan 不模拟弱内存"必须写成显式警告**——这是最容易被误解的点（x86 上 TSan 绿 ≠ ARM 上正确）
4. **把 CDSChecker 发现 Chase-Lev bug 做成教学案例**——"为什么人脑不可靠、必须用工具"的最强论据
5. **CPP-Bible 自己的 gate_engine 可借鉴 DPOR 思路**——当前 poison_drill 是固定毒样例，未来可探索随机交织注入

## 十、发现的知识空白

1. **并发验证工具链完全空白**——全书只教怎么写并发，不教怎么证明写对了
2. **TSan 的弱内存盲区无警示**——读者会以为 TSan 绿就等于正确
3. **模型检查器无介绍**——CDSChecker/GenMC 在中文教材中几乎不出现
4. **"已发表算法也有 bug"无案例**——缺少对权威保持审慎的工程态度教育
5. **确定性复现概念缺失**——Relacy 的单线程确定性模拟是调试偶现 bug 的利器
