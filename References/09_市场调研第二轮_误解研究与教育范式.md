# 市场调研简报（第二轮）：误解研究 / 测试驱动学习 / 多Agent质量 / 可复现范式 / 间隔重复

> 2026-09-11，监工主动调研。聚焦 CPP-Bible 核心机制的学术同源和扩展方向。

## 一、编程误解研究——误解库的学术基础

**关键发现**：
- **McMining**（arXiv 2510.08827）：自动从学生代码中挖掘误解的任务，配套基准数据集+大量标注代码样本。核心思路是"误解可以从错误模式中自动发现"，不需要人工逐条编。
- **C++ Gotcha Guide**（cpplang.vercel.app）：社区维护的 C++ 常见陷阱清单，按主题分类。
- **CppCon 2024 "Irksome C++"**：系统梳理 C++ 核心语言和标准库中的命名/行为不一致性——这些不一致正是误解的温床。
- **波兰学习者调查**：39% 认为语法复杂、28% 认为内存管理难、17% 认为材料过时。内存管理和过时材料是两大痛点，与 CPP-Bible 的 P0 域（MEM/PERF/CONC）高度重合。

**对 CPP-Bible 的意义**：
- 误解库（MIS-MEM-005 等）是核心差异化，但目前靠人工编写。McMining 的思路可以借鉴：**从全书 7572 个 cpp 块的编译错误/运行失败中自动挖掘误解模式**，把"人工编误解"变成"从真实错误中归纳"。
- gray_zone_scan 已经在做句子级初筛，可以扩展成"误解模式挖掘器"——扫描常见错误模式（如 `std::move(const T&)`、`return std::move(x)`、`delete this` 后访问等），自动生成误解候选。

**行动项**：G5 后做 `tools/misconception_miner.py`，从编译错误日志和 CI 失败记录中自动归纳误解模式，人工审核后入库。

## 二、测试驱动学习——证据卡可以扩展成 Koans

**关键发现**：
- **Koans 模式**（Ruby/Python/Common Lisp/Elixir 各语言都有）：通过修复失败的测试来学习语言特性。"禅宗"式教学，每个测试教一个知识点。
- **Exercism**：测试驱动 + 可选人工导师，强调惯用法（idiomatic）而非"能跑就行"。
- **Cyber Dojo**：TDD 练习平台，可视化 red-green-refactor 循环，追踪测试运行频率。
- **Cal Poly TDL 研究**："Teach by example, present examples with automated tests, start with tests"——测试比散文示例更精确地表达行为。

**对 CPP-Bible 的意义**：
- 证据卡本质上就是"可执行测试"——`//@` 契约 + run_expected 断言 + 证伪对照。但目前是"作者写测试验证自己的论断"，学习者是旁观者。
- **可以扩展成 Koans 模式**：把每个原子的夹具改造成"学习者需要填空/修复的失败测试"，学习者通过让测试通过来理解知识点。这是从"阅读型教材"到"交互型教材"的关键一步。
- 例如 ATOM-MEM-RVREF-001 的夹具可以变成：给出 `void f(X&& x) { /* 学习者填空：让 x 被移动 */ }`，测试验证移动构造被调用。

**行动项**：G6 前端链做 Koans 导出器——从原子的证据卡自动生成"填空式失败测试"，学习者在浏览器或本地跑测试通过。

## 三、多Agent协作质量——三权分立的学术依据和优化方向

**关键发现**：
- **MARS**（arXiv 2509.20502）：Multi-Agent Review System，author 生成 → 多个 reviewer 独立评审 → meta-reviewer 整合反馈。避免 reviewer 间通信开销，比多Agent辩论（MAD）更高效。
- **LLM Review**（OpenReview）：盲同行评审提升创意写作质量。关键发现：**小模型用该框架胜过大模型单agent**；"creativity requires divergence"——收敛对有ground truth的任务有效，创意任务需要发散。
- **Multi-Agent Reflexion**：失败轨迹发给多个 persona-guided critics，沿不同轴（证据利用/探索/规格严格度）disagree，judge 综合。
- **MAD conformity 问题**（arXiv 2509.11035）：多Agent辩论中 agent 会跟随多数意见即使错误，导致错误传播。需要 anti-conformity 机制。
- **A-HMAD**：异构多Agent辩论，不同角色/模型类型，比同构更有效。

**对 CPP-Bible 的意义**：
- CPP-Bible 的 Writer-RedTeamer-监工三权分立，本质上就是 MARS 架构（author=Writer, reviewer=RedTeamer, meta-reviewer=监工+人审）。学术上有依据。
- **跨平台异源策略（traeWork Writer / CodeBuddy RedTeamer）正好对应 A-HMAD 的异构思想**——不同平台不同模型实例，减少 conformity。
- LLM Review 的发现很重要：**小模型+评审框架可以胜过大模型单agent**——这直接支持"垃圾大模型也能干活"的思路，前提是评审框架足够强。
- MAD conformity 问题提醒：RedTeamer 不能只看 Writer 的自证，必须独立复跑（CPP-Bible 已经在做）。

**行动项**：把 MARS/LLM Review 的论文引用写进 docs/kernel/，作为三权分立架构的学术依据。论文支线的 related work 必引。

## 四、可复现研究范式——原子+证据卡的理论同源

**关键发现**：
- **Quarto / Jupyter / R Markdown**：literate programming，代码与文本交织在同一文档，一键重跑，结果内嵌。支持多格式输出（HTML/PDF/ePub/Word）。
- 核心原则：**文档中的所有数字/结果都必须可复算**，不允许"手写的结果"。
- 已广泛用于科研和教学（大学课程用 Quarto 写讲义）。

**对 CPP-Bible 的意义**：
- CPP-Bible 的"原子 + 证据卡"机制就是 literate programming 的变种——文本（原子正文）和可执行代码（证据卡夹具）分离但关联，通过 atom_evidence_replay 一键复算。
- Quarto 的"单一源文档多格式输出"可以借鉴：原子是单一源，导出为 HTML 网站 / PDF / ePub / Anki 卡片 / Koans 测试。
- 可复现研究的核心原则"所有结果可复算"正是 CPP-Bible 的 M2 实证方法的理论基础。

**行动项**：论文中把 CPP-Bible 定位为"面向编程教育的可复现知识表示系统"，与 Quarto/Jupyter 同属 literate programming 谱系，但针对 C++ 编译型语言做了专门设计（证据卡+汇编锚定+版本矩阵）。

## 五、间隔重复 / 知识卡片——原子的天然导出形态

（注：本方向搜索受限，基于领域知识整理）

- **Anki / SuperMemo / SRS**：间隔重复算法，知识卡片+定时复习，在医学/语言学习中验证有效。
- 编程教育中已有应用：Anki 编程卡片、LeetCode 间隔复习等。
- **CPP-Bible 的原子天然适合导出为 SRS 卡片**：每个原子有 claim（正面）、misconceptions（反面）、socratic 提问（主动回忆）、evidence（实证支撑）——这就是一张高质量卡片的全部要素。
- genanki（MIT，已在 References/05 选型）可以从原子 YAML 自动生成 Anki 牌组。

**行动项**：G6 做 `tools/atom_to_anki.py`，从原子自动导出 Anki 卡片（正面=claim+socratic提问，反面=解释+证据摘要+误解反例）。这是零成本的学习者价值增量。

## 七、核心洞察

这轮调研最大的收获是**确认了 CPP-Bible 的几个核心机制都有学术同源**：
- 证据卡 = 可复现研究（literate programming）+ 测试驱动学习（TDL）
- 误解库 = 编程误解研究（McMining）
- 三权分立 = 多Agent评审（MARS）
- 原子导出 = 间隔重复（SRS）+ Koans

这意味着项目不是"拍脑袋的工程"，而是**把多个已验证的教育/研究范式整合到 C++ 编程教育场景**。论文叙事可以从这个角度切入：不是"又一个 C++ 教程"，而是"可复现知识表示 + 多Agent质量保证 + 自适应学习路径"在编程教育中的系统整合。
