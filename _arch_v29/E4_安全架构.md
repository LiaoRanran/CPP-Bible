# 方向 E4：安全架构

> 核心问题：**阙疑这整套系统本身该如何架构，才能"自身安全、可治理、失败安全"？** 对应阙疑"通用验证内核 + 元治理 + 优雅降级"。
> 检索：15 次（零信任实现 PEP/PDP、微隔离、安全设计框架、SBOM、安全飞地 vs TEE、策略即代码 OPA、职责分离、最小权限 RBAC/ABAC、安全默认/失败安全、TCB 最小化、机密计算、安全架构模式、ZTNA、供应链安全、优雅降级、API 安全网关）。
> 边界：A1 已提密码学协议、A4 已提 TCB/TEE，本轮**落到整体安全架构模式**；与 A4 不重复（更偏架构编排）。

## 一、核心概念清单（≥10 条）

- **零信任架构实现（NIST 800-207）**：把架构拆成 PDP（策略决策点）+ PEP（策略执行点）+ PAP（策略管理点）；每次访问动态评估，消灭隐式信任。分布式 PEP 下沉到本地代理可成"最后一道防线"。
- **微隔离（Micro-segmentation）**：把东西向（east-west）流量按工作负载精细隔离，限制横向移动——零信任的网络层落地。
- **安全设计框架（OWASP/CISA Secure-by-Design）**：安全须内建而非外挂；CISA 要求设计阶段即落实安全属性（呼应 E1 SDL）。
- **SBOM（软件物料清单）**：机器可读地列出全部组件/依赖，是供应链透明与漏洞追踪的"成分表"（SPDX/CycloneDX）。
- **安全飞地 vs TEE**：Secure Enclave 把信任边界缩到最小硬件块；TEE（SGX/TrustZone）提供运行隔离。但信任根仍在厂商（呼应 A4 死路）。
- **策略即代码（OPA/Rego）**：把访问/决策策略从应用逻辑解耦，集中声明式管理；Netflix 等用于内部 API 访问控制。
- **职责分离（SoD）**：任一用户不应拥有独立完成危险操作的全部权限——需多人控制；对应"攻击/验证不可由同一主体完成"（v21）。
- **最小权限（RBAC/ABAC/PBAC）**：从角色到属性到策略的演进；零信任 AI Agent 场景已演进到 PBAC。
- **安全默认与失败安全（Fail-safe Defaults）**：默认即"无访问/不开火"；fail-open（失败放行）是反模式。SoK (2412.17329) 系统化了该范式。
- **TCB 最小化（架构层）**：现代 OS 努力缩小 TCB 以便彻底审计/形式化（呼应 A4）——架构上"只信最小集"。
- **机密计算（Confidential Computing / CoCo）**：在 TEE 内加密保护"使用中数据"，容器级机密计算（Confidential Containers）把机密性延伸到 pod。
- **安全架构模式库（Open Security Architecture）**：可复用的安全模式与控制映射（NIST 800-53），供架构师组合使用。
- **ZTNA（零信任网络访问 / SDP）**：软件定义边界，按精细策略把授权用户连到具体应用，无需传统 VPN。
- **供应链安全架构（SLSA + OWASP）**：从源码→依赖→构建→制品→发布全链路防篡改；SLSA 提供分级 checklist。
- **优雅降级（Graceful Degradation, CMU 2025）**：受攻击时系统仍维持关键功能、自动权衡降级，而非整体崩溃——架构韧性核心。
- **API 安全网关**：认证/授权/最小权限/可审计集中到网关层，是微服务的统一安全入口。

## 二、对阙疑的映射（全标【类比推断】）

- **零信任 PEP/PDP → 阙疑每次开火的动态裁决【类比推断】**：v21"不隐式信任任何单一验证器"对应零信任。阙疑应把"开火决策"拆成 PDP（综合多验证者+人审信号决策）与 PEP（执行判决处），任何单次验证都不直接触发开火，须 PDP 复核——消灭 v21 单点隐式信任。
- **微隔离 → 验证器/攻击生成器的网络隔离【类比推断】**：v21 攻击生成器是危险组件，应按微隔离思路与验证器、被测代码网段隔离，限制东西向横向移动——攻击生成器即便被攻破也难横向扩散。
- **安全设计 → 阙疑自身走 Secure-by-Design【类比推断】**：E1 SDL 应施加于阙疑工具自身；安全不是外挂防火墙而是内核设计属性（呼应 A4 TCB 最小化）。
- **SBOM → 规则/依赖的物料清单【类比推断】**：v25 规则集应维护"规则 SBOM"——每条规则依赖哪些定义、哪些工具、哪些版本，便于漏洞追踪与一键回滚（呼应 A1 provenance）。
- **策略即代码 → 阙疑决策策略外置【类比推断】**：开火/人审/降级的阈值策略用 OPA 式声明式策略管理，与验证逻辑解耦，便于审计与动态调参（呼应 C3 决策准则外置化），避免策略硬编码散落。
- **职责分离 → 攻击与验证必须分离【类比推断】**：v21 铁律"攻击生成器≠验证器"。SoD 提供架构依据——生成攻击的主体不可同时拥有"判定该攻击有效"的权限，否则共谋（呼应 A4 信息流隔离）。
- **最小权限 → 验证器权限按角色收敛【类比推断】**：v23 人审账号、v21 工具权限应按 RBAC/ABAC 最小化；验证器默认无写被测代码权限，攻击生成器默认不可访问 Ledger（呼应 A4 能力安全）。
- **失败安全 → 验证失败默认不开火【类比推断】**：E1 已提"失败安全默认"，本轮落到架构——阙疑任何组件故障时必须 fail-safe（默认不开火/转人审），绝不能 fail-open（放行）。这是系统级硬准则。
- **TCB 最小化 → 阙疑可信内核 shrunk【类比推断】**：A4 已论证 TCB 可缩到可验证规模；E4 在架构层落实——把"规则匹配/判决/账本"作为唯一可信集，其余外移且默认无信任（呼应 A2/A4）。
- **机密计算 → 私有代码处理的可选隔离【类比推断】**：阙疑处理私有源码时，Confidential Containers 可在 TEE 内加密处理"使用中数据"；但须牢记 A4——信任根仍在厂商，不可作为唯一信任源，须配合零信任。
- **优雅降级 → 受攻击时维持关键验证【类比推断】**：CMU 2025 优雅降级给阙疑韧性范式——部分验证器被攻破/过载时，系统自动降级（如关闭 AI 验证、退回静态+人审），而非整体停摆，维持"至少不漏放高危"的最低保障（呼应 A3 CAP 取舍）。
- **API 安全网关 → 工具调用的统一入口【类比推断】**：v21 Agent 外骨骼的工具调用应经统一网关做认证/授权/审计/最小权限，避免工具直连造成的权限散落（呼应 A4 沙箱）。
- **供应链安全 → 阙疑自身的 SLSA 化【类比推断】**：v21 工具链/规则更新应走 SLSA 分级——构建生成 provenance、签名防篡改、发布可控（呼应 A1 SLSA/in-toto），防"规则更新被投毒"。
- **安全架构模式库 → 阙疑架构的组合蓝本【类比推断】**：Open Security Architecture 的可复用模式（控制映射、能力模型）可作阙疑安全架构的"积木库"，避免从零设计。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **开火决策应拆 PDP/PEP，消灭单点隐式信任**：把零信任的 PDP/PEP 模式直接映射到阙疑判决流，任何验证结果须经独立策略点复核。
2. **策略即代码让决策准则可审计可回滚**：阈值/降级策略外置为声明式（OPA），避免硬编码散落、便于治理（呼应 v26 元治理）。
3. **优雅降级是韧性的架构级答案**：受攻击/故障时自动降级到"最低可保障验证"，而非全崩——给 v21"持续可用"以架构支撑。
4. **规则 SBOM 让规则依赖可追踪可回滚**：每条规则维护依赖清单，投毒/错误时可一键定位与回滚（呼应 E2 投毒防护）。

## 四、设计原则（1-2 条，可操作）

- **D-E4-1：阙疑整体按零信任 + 失败安全架构**：PDP/PEP 拆分判决，任何组件失败默认不开火转人审；攻击生成器与验证器微隔离、职责分离。
- **D-E4-2：决策策略外置为策略即代码 + 规则 SBOM**：开火/降级阈值用 OPA 式声明式管理；规则集维护 SBOM 式依赖清单支持回滚。

## 五、失败教训与死路（≥5 条）

- **fail-open 是致命反模式**：任何"验证失败就放行"的默认都会让整套防护归零；必须 fail-safe（呼应 E1 失败安全）。
- **TEE/机密计算信任根在厂商（A4 死路复用）**：Confidential Containers 仍依赖云厂商 TEE，不能作为唯一信任源。
- **隐式信任单点（v21 死路复用）**：若某验证器/人审直接触发开火而无 PDP 复核，即背叛零信任。
- **策略硬编码散落难治理**：阈值写死在各组件，调参/审计成本高且易不一致；须策略即代码外置。
- **微隔离若配置错误=形同虚设**：东西向隔离策略错配会放行横向移动；须持续验证隔离有效性（呼应 E1 安全控制验证）。
- **供应链无 provenance 易被投毒**：规则/工具更新若无 SLSA 签名，更新通道可成投毒入口（呼应 E2 投毒）。
