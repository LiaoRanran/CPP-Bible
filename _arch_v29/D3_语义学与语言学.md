# 方向 D3：语义学与语言学

> 核心问题：**阙疑要判定的"命题/误解/真实语义"到底是什么意义上的"意义"？如何避免语义歧义与语境陷阱？** 对应阙疑"W2 命题-误解图 + 真实语义审查"。
> 检索：15 次（组合性/弗雷格原则、蒙太古语法、语义vs语用/Grice、词汇语义/WSD、分布语义、框架语义 Fillmore、形式语义/λ演算、类型论语义、组合语义 NLP、语义解析、认知语义 Lakoff、真值条件语义、指称语义、歧义消解、上下文嵌入 BERT）。
> 边界：v21 已提"真实语义误解"，本轮**补语义学的意义理论**；与 D1 表示、B3 类型论不重复。

## 一、核心概念清单（≥10 条）

- **组合性原则（Frege 原则）**：复杂表达式的意义由其部分意义+组合规则决定。是形式语义的基石，也是"程序语义可分解验证"的理论依据。
- **蒙太古语法（Montague, 1970-71）**：用形式逻辑（λ 演算、可能世界）给自然语言建模型论语义，主张"自然语言与逻辑语言同等形式化"。验证了"意义可机械组合"。
- **语义 vs 语用（Grice 合作原则）**：字面意义（语义）与语境推断（语用、implicature）分离。Grice 四准则（量/质/关系/方式）解释"弦外之音"。
- **词汇语义与词义消歧（WSD）**：多义词在上下文中定义；WordNet 提供同义词集层级。是"代码命名/注释歧义"的对应问题。
- **分布语义（Distributional Hypothesis, Firth 1957）**："词义由其上下文定义"，用向量空间（Word2Vec/BERT）表示；与 B2 分布语义、D1 KGE 同源。
- **框架语义（Fillmore, 1982）**：词的意义依赖其 evoked 的"框架"（场景/图式）；FrameNet 据此标注。适合表示"场景化语义"——与 D1 框架表示直接呼应。
- **形式语义与 λ 演算**：意义用 λ 项表达，β-归约组合；是组合语义的计算引擎（呼应 A2/B3）。
- **类型论语义**：意义按类型（实体、真值、函数）组织，控制组合合法性；是 Montague 风格的现代形态（呼应 B3 类型论）。
- **真值条件语义**：句子意义=其真值条件；源自弗雷格/罗素/戴维森，用逻辑词刻画推理角色。
- **指称语义（Scott-Strachey）**：程序语言的数学语义——把程序映射到数学对象（域），保证"程序意义可严格定义"。是 v21 验证器语义的近亲。
- **歧义消解**：句法-语义接口的歧义（如 PP 挂靠）；人靠语境消解，机器需消歧模型——对应"代码审查中的歧义误判"。
- **上下文嵌入（BERT 等）**：词向量随上下文动态变化，捕捉多义；相比静态词向量更贴近"语义依赖语境"。
- **认知语义（Lakoff）**：意义根植于身体经验与隐喻；概念隐喻理论——提示"语义"不只是符号，还有认知图式。
- **语义解析（Semantic Parsing）**：自然语言→形式意义表示（如 SQL/DRT），机器可据此行动——对应阙疑"规则 DSL 解析"。

## 二、对阙疑的映射（全标【类比推断】）

- **组合性 → "程序语义可分解判定"【类比推断】**：v21 真实语义审查可借组合性——表达式意义由子表达式组合，故可分层验证（先验证子表达式语义，再组合）。这把"整体误判"拆成"局部语义验证"，正合 v25 Rule 的递归匹配。
- **蒙太古语法 → 规则 DSL 的形式语义基础【类比推断】**：阙疑规则若用类 Montague 的 λ 演算表达语义，则可机械组合与判定，避免"规则意图模糊"。规则引擎应具备形式语义而非自然语言描述（呼应 D1 双表示）。
- **语义 vs 语用 → "会话语用"是误判高发区【类比推断】**：v21 真实语义误解常发生在"调用约定/隐式前置"等语用层（如对象语义的隐含不变量）。阙疑须区分"字面语义"与"语境约定"，否则把语用违规当语义违规（或反之）。
- **词汇语义/WSD → 代码命名与注释的歧义【类比推断】**：代码标识符多义（如 `size` 指字节还是元素数）、注释歧义，对应自然语言 WSD。阙疑验证器需做"代码语义消歧"，不能仅按字面名匹配（呼应 v20 真实语义）。
- **分布语义 → "相似代码/相似误解"的向量度量【类比推断】**：用分布语义（如 code embedding）度量两段代码/两条误解的语义相似，辅助 v25 冲突检测与去重（呼应 B2 NCD、D1 嵌入）。
- **框架语义 → "场景化误解"的结构【类比推断】**：Fillmore 框架=场景化意义，恰好对应 v21 真实语义中"某 C++ 构造在特定用法场景才误解"。FrameNet 式标注可把误解图组织成"框架-触发-角色"，比扁平列表更贴合。
- **指称语义 → 验证器的"程序意义"定义【类比推断】**：v21 验证器要判定程序"做了什么"，本质是给它建指称语义（Scott-Strachey）。形式化语义是"验证器正确验证"的前提——没有语义定义，验证无意义（呼应 A2 形式化）。
- **真值条件语义 → "命题卡片"的真值定义【类比推断】**：W2 命题是"真/假"陈述，真值条件语义给"何时命题成立"以精确定义，使误报/漏报可基于真值判定而非直觉。
- **歧义消解 → 审查中的歧义误报源【类比推断】**：人类审查者常因句法/语义歧义误判（如 PP 挂靠歧义类比"作用域歧义"）。阙疑应内置消歧步骤，避免把歧义当确定性错误。
- **认知语义 → "约定俗成"的语义层【类比推断】**：Lakoff 提示语义含认知图式；C++ 的对象模型语义很多是"社区约定"而非纯逻辑，阙疑须把约定层显式建模，而非当客观真理。
- **语义解析 → 规则自然语言的机器可读化【类比推断】**：v25 规则若以自然语言写，应经语义解析转成形式 DSL（如 DRT/SQL 式），才能机检——避免"规则意图≠机器执行"。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **"真实语义"应明确区分语义层与语用层**：v21 的"真实语义误解"大多实为语用/约定违规，混为一谈导致误报。阙疑须建两层判定。
2. **指称语义是验证器合法性的前提**：没有给程序建形式指称语义，验证器本身"验证什么"就不清；这是 v21 验证器自证的关键一环。
3. **框架语义为"场景化误解"提供现成结构**：FrameNet 式组织比扁平列表更贴合 v21 真实语义，可直接借鉴。
4. **组合性使"分层语义验证"成立**：子表达式语义可独立验证再组合，是大规模代码审查可扩展性的理论依据。

## 四、设计原则（1-2 条，可操作）

- **D-D3-1：规则用带形式语义的 DSL（类 Montague/λ）书写**：规则先定义指称语义（程序意义），再以组合方式表达；机器按语义而非字面匹配，减少歧义误判。
- **D-D3-2：真实语义审查分语义/语用两层**：先判字面真值条件，再判语境约定；任一层命中才计为误解，避免把语用违规当语义错误。

## 五、失败教训与死路（≥5 条）

- **自然语言规则无形式语义必歧义**：v25 规则若仅自然语言描述，意图≠执行，必产生系统性误判；必须 DSL 化。
- **混淆语义与语用致误报**：把"约定违规"当"语义错误"会淹没真问题；须分层。
- **静态词向量难处理多义**：BERT 前静态嵌入对多义代码名乏力；阙疑语义度量须用上下文嵌入。
- **组合性假设失效于非组合结构**：成语/宏/模板元编程等非组合构造，组合性原则不适用，需特殊处理（呼应 v20 语义层）。
- **认知语义的"约定"难形式化**：C++ 社区约定并非逻辑可推，形式化成本高，须接受部分不可形式化（呼应 B1 不可判定）。
- **语义解析错误传导**：自然语言→DSL 解析错会污染整条规则；须人审校验解析结果。
