# 方向 E3：自动化漏洞挖掘

> 核心问题：**有哪些已验证有效的自动化手段，能替阙疑"找 bug、证漏洞、自动生成攻击输入"？** 对应阙疑"攻击生成器 + 覆盖证明"的工程武器库。
> 检索：15 次（覆盖引导模糊测试 AFL/libFuzzer、符号执行 KLEE/angr、concolic、静态/污点分析、DL 漏洞检测、差分测试、Sanitizer、SMT/Z3、信息流/污点、自动利用生成 AEG、CWE/CVE、程序切片、定向模糊、模糊综述）。
> 边界：v21 已提"攻击生成器"，本轮**落到具体挖掘技术**；与 E1 威胁建模、v28 攻防不重复。

## 一、核心概念清单（≥10 条）

- **覆盖引导模糊测试（Coverage-guided Fuzzing, CGF）**：AFL/libFuzzer 以插桩覆盖率反馈指导变异，进化出触发新路径的输入；是现代漏洞挖掘主力（AFL 由 lcamtuf 开发）。
- **符号执行（Symbolic Execution）**：KLEE、angr 用符号值代替具体值，沿路径积累约束，用 SMT 求解器生成触发路径的输入；可系统性探索分支。
- **Concolic 测试（动态符号执行）**：具体执行+符号执行混合，兼顾真实性与探索性；对大型程序更可扩展（模块化测试缓解路径爆炸）。
- **静态分析 / 数据流 / 污点分析（Taint Analysis）**：从 source（不可信输入）到 sink（危险操作）追踪数据流；SonarQube 等借此查注入类漏洞；是"不运行即可查"的手段。
- **基于深度学习的漏洞检测**：VulDeePecker、SynergyBug 等用图神经网络/LLM 从代码学漏洞模式；但误报率高、可解释差（呼应 E2 机制可解释）。
- **差分测试（Differential Testing）**：用多个相似实现相互对拍，发现"语义不一致"的隐性 bug（如编译器、文件系统、DL 系统测试）。
- **Sanitizer（ASan/UBSan/MSan）**：运行时插桩检测越界、未初始化、UB；与 fuzzing 协同（AFL++ 配 ASan）是标准组合。
- **SMT 求解器（Z3）**：符号/约束求解引擎，是符号执行、concolic、演绎验证的共同底座（呼应 A2）。
- **信息流/污点（Implicit Flow）**：不仅显式数据依赖，还含隐式流（分支导致信息泄露）；DIFC（A4）与污点分析同源。
- **自动利用生成（AEG, Avgerinos et al. NDSS 2011）**：给定可能含 bug 的程序，自动生成能稳定利用的 PoC；证明漏洞"确属可利用"而非纸面。
- **CWE/CVE/CVSS 体系**：CWE 是弱点根源分类（800+）、CVE 是具体实例、CVSS 评风险；为漏洞提供统一词汇与优先级——对应阙疑的漏洞分类标尺。
- **程序切片（Program Slicing）**：提取影响某变量/点的语句子集（前向/后向），定位根因、缩小审查范围——对应 v25 错误归因（ErrorFlow）。
- **定向模糊（Directed Fuzzing, AFLGo/WindRanger）**：把算力和时间集中导向指定目标点（如补丁函数、疑似漏洞点），用于崩溃复现与补丁验证。
- **模糊测试综述（2024）**：LLM 增强模糊测试成为新方向——用 LLM 生成种子/变异策略，提升覆盖率（与 v21 LLM 辅助同源）。

## 二、对阙疑的映射（全标【类比推断】）

- **覆盖引导模糊 → 攻击生成器的核心引擎【类比推断】**：v21 攻击生成器（mutation 等）应以 AFL 式覆盖引导为底座——每条生成的攻击按"是否触发新语义路径"反馈变异，而非盲目随机；这把 v28 的"攻击生成"变成有覆盖率指标的工程循环。
- **符号执行 → "证明存在触发某误解的输入"【类比推断】**：v20 真实语义误解可建模为"是否存在输入使对象语义被违反"。符号执行 + Z3 能**生成**这样一个反例输入（若存在），把"疑似误解"变成"可复现的反例"——这正是 v21"验证需呈现证据"的自动化形态。
- **Concolic → 大程序的实用探索【类比推断】**：纯符号执行路径爆炸，concolic 的模块化/动态混合更适合阙疑审查大代码库；对应"先具体跑通再符号深挖"的两阶段策略。
- **污点分析 → "不可信输入到危险 sink"的静态防线【类比推断】**：v20 验证中"外部输入→危险操作"的链路可用污点分析静态标出，无需运行即发现潜在安全误解（如未校验的指针来源）；补充动态验证。
- **DL 漏洞检测 → 语义层误报的双刃剑【类比推断】**：用 DL/LLM 检测 C++ 语义漏洞速度快，但误报高、不可解释（呼应 E2）。阙疑若用，须把它当"候选生成器"而非"判定器"，最终由人审/形式化确认。
- **差分测试 → 多验证器交叉对拍【类比推断】**：v22 多验证者可借差分测试思想——用多个独立验证器对同一代码对拍，语义不一致处即可疑（呼应 A3 多验证者）；这是 E1 红蓝对抗的自动化版。
- **Sanitizer → 验证器的动态探针【类比推断】**：阙疑运行时给被测程序插 ASan/UBSan，配合 fuzzing 自动捕获未定义行为；把 v20 的"内存安全语义"变成运行时可检测项。
- **AEG → "验证器证漏洞可利用"的收口【类比推断】**：v25 发现疑似漏洞后，AEG 自动产出 PoC 证明"确可利用"，避免误报为"理论漏洞"；对应 v21"硬开火需确证"的最后一道闸。
- **CWE/CVE → 漏洞分类标尺【类比推断】**：阙疑的"误解类型"应映射到 CWE（如 CWE-416 释放后使用），用其统一词汇做覆盖率与优先级度量（呼应 E1 MITRE ATT&CK 标尺）。
- **程序切片 → 错误归因的自动化【类比推断】**：v27 ErrorFlow/错误归因可用程序切片自动提取"导致该误报/漏报的语句集"，缩小人审范围，提升根因定位效率（呼应 v23 人审减负）。
- **定向模糊 → "补丁/新规则"的精准验证【类比推断】**：v25 新规则上线后，用定向模糊把算力集中到规则覆盖的目标点，验证其是否真能触发预期误报，做规则回归。
- **LLM 增强模糊 → 攻击生成的智能种子【类比推断】**：v21 用 LLM 辅助验证，可让 LLM 生成高质量初始种子/变异策略喂给 fuzzer，提升覆盖效率——但须防 LLM 偏见导致覆盖盲区（呼应 C2 偏置）。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **符号执行 + Z3 可"生成反例"而非仅"判定"**：把 v20 的"疑似语义误解"变成可复现的反例输入，是 v21"呈现证据"的自动化武器。
2. **定向模糊让规则/补丁验证可精准回归**：新规则上线用 AFLGo 式定向模糊验证其触发行为，避免规则"写了但验不出"。
3. **AEG 是硬开火前的"可利用性确证"**：杜绝"理论漏洞"误报，只有能自动生成 PoC 才升级为硬开火。
4. **差分测试是红蓝对抗的自动化形态**：多验证器交叉对拍发现语义不一致，与 A3 多验证者、E1 红蓝同源。

## 四、设计原则（1-2 条，可操作）

- **D-E3-1：攻击生成器以覆盖引导模糊 + 符号执行为双引擎**：fuzzing 广覆盖 + 符号执行深探索，反例由 Z3 生成；覆盖度用 CWE/ATT&CK 标尺度量。
- **D-E3-2：硬开火需 AEG 可利用性确证 + 切片归因**：疑似漏洞经 AEG 产出 PoC 才升级硬开火；误报/漏报用程序切片自动定位根因。

## 五、失败教训与死路（≥5 条）

- **符号执行路径爆炸**：大程序纯符号执行不可行，须 concolic/模块化（呼应 B1 状态爆炸）；阙疑审查大库须混合策略。
- **DL 漏洞检测误报高且不可解释**：直接当判定器会淹没人审；只能做候选生成（呼应 E2）。
- **fuzzing 覆盖不全**：覆盖率指标本身可被绕过，未覆盖路径仍有漏洞；须结合静态（污点）补盲区（呼应 C1 coverage）。
- **AEG 对复杂利用失败**：现实漏洞利用链长，AEG 难自动生成；阙疑不能只依赖 AEG 确证，复杂处仍要人审。
- **CWE 分类主观**：弱点归类有争议，阙疑映射 CWE 须标注主观性，避免错配优先级。
- **LLM 模糊种子的覆盖盲区**：LLM 偏见致生成种子偏向训练分布，遗漏长尾攻击（呼应 C2 偏置错配）。
