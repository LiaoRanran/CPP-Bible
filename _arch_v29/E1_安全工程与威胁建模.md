# 方向 E1：安全工程与威胁建模

> 核心问题：**如何用成熟的安全工程方法，把"攻击-验证"变成一套可重复、可治理的工程实践？** 对应阙疑"攻击生成 + 人审 + 闭环"的工程化。
> 检索：15 次（STRIDE、攻击树/图、安全设计原则 Saltzer-Schroeder、纵深防御、零信任 NIST 800-207、MITRE ATT&CK、PASTA、安全混沌工程/GameDay、红蓝对抗、攻击面管理、DREAD、安全开发生命周期 SDL、abuse/misuse cases、对抗仿真、安全控制验证）。
> 边界：v28 已提攻防理论，本轮**落到工程方法论**；与 A3 共识、A4 TCB、A1 密码学不重复。

## 一、核心概念清单（≥10 条）

- **STRIDE 威胁建模**：微软方法，按六类威胁枚举——Spoofing（仿冒）、Tampering（篡改）、Repudiation（抵赖）、Information Disclosure（信息泄露）、Denial of Service（拒绝服务）、Elevation of Privilege（提权）。基于数据流图识别入口点。
- **攻击树/攻击图（Attack Trees/Graphs）**：以树（AND/OR）或图建模攻击者达成目标的路径；是攻击生成的结构化表示（与 v28 攻击生成同源）。
- **安全设计原则（Saltzer & Schroeder 1975）**：最小权限、失败安全默认、机制经济性、开放设计（不靠隐蔽性）、完整中介、最小公共机制、心理可接受——v21 信任根独立与此同源。
- **纵深防御（Defense in Depth）**：多层异构防护，任一层失效不致命；与 v21"多验证者/多防线"同构。
- **零信任架构（NIST SP 800-207）**：永不隐式信任，每次访问由策略执行点（PEP）+ 策略决策点（PDP）基于身份/上下文动态授权；消灭"内网即可信"。
- **MITRE ATT&CK**：基于真实对抗的战术/技术/程序（TTP）知识库；是攻击建模的共享词汇与覆盖度量基准。
- **PASTA（攻击模拟与威胁分析流程）**：七阶段、以风险为中心的威胁建模；把威胁与业务风险、攻击模拟闭环。
- **安全混沌工程 / GameDay（Gremlin）**：主动注入故障/攻击，验证防御韧性；"假设-实验-学习"的对抗性演练。
- **红蓝对抗（Red/Blue Team）**：红队专司突破、蓝队专司防御检测；演练后蓝队据弱点改进——是"攻击-验证"的人工原型。
- **攻击面管理（ASM）**：持续发现/枚举暴露面（资产、配置、漏洞），优先修复高风险暴露；对应阙疑"规则覆盖的攻击面"。
- **DREAD 风险评分**：Damage/Reproducibility/Exploitability/Affected users/Discoverability 五维定性评分，优先排序——与 v23 软警报率/风险排序同源。
- **安全开发生命周期（Microsoft SDL）**：需求→设计→实现→验证→发布五核心阶段 + 培训/响应两支撑；强制安全与隐私检查点。
- **Abuse/Misuse Cases（滥用/误用用例）**：在需求阶段显式写出"系统如何被恶意/错误使用"，逆向推导防护——对应阙疑"先想攻击再想验证"。
- **对抗仿真 / 安全控制持续验证（Continuous Security Validation, AttackIQ/Picus）**：持续用真实攻击手法测试控制是否真有效，给出"防御确实管用"的证明（assurance），而非纸面合规。

## 二、对阙疑的映射（全标【类比推断】）

- **STRIDE → 攻击生成的六维枚举【类比推断】**：v21 攻击生成器（mutation 等）应借 STRIDE 做结构化枚举——每条生成的攻击显式归属到"仿冒/篡改/抵赖/泄露/DoS/提权"之一，覆盖度可量化。这把 v28 的"攻击生成"从随机变异升级为系统化建模。
- **攻击树 → 误解图/攻击路径的结构化表示【类比推断】**：v25 W2 的命题-误解图可用攻击树表达——"某安全属性被违反"为根，各子攻击路径为分支；自动生成与穷举攻击路径，对应 v24 的"覆盖证明"与 v28 攻击生成的树状展开。
- **安全设计原则 → 阙疑自身的安全设计基调【类比推断】**：Saltzer-Schroeder 的"开放设计、最小权限、失败安全默认"正是 v21 信任根独立 + v23 人审队列的设计准则——阙疑的内核应"失败安全"（验证失败时默认不开火而非默认放行）。
- **纵深防御 → 多防线冗余【类比推断】**：v21 的多验证者/多层规则即纵深防御——静态分析、动态、语义、人审各为一层，单层失灵不致命，比单点验证稳健（呼应 A3 3f+1）。
- **零信任 → "任何验证结果都需再授权"【类比推断】**：v21 不隐式信任任何单一验证器/人审。零信任的 PEP/PDP 范式可映射到阙疑"每次开火需策略决策点复核 + 多方签名"，消灭"某验证器说中就算"的隐式信任（呼应 A1 信任根独立）。
- **MITRE ATT&CK → 攻击覆盖的共享基准【类比推断】**：阙疑可把"已能验证的攻击类"映射到 ATT&CK 战术/技术，用其作为覆盖度度量标尺，明确"还有哪些 TTP 未覆盖"（呼应 v23 coverage）。
- **PASTA → 风险驱动的威胁建模闭环【类比推断】**：阙疑的自我进化应是"风险中心"的——先识别高风险攻击场景，再生成针对性验证，而非无差别全扫；PASTA 七阶段提供流程骨架。
- **安全混沌工程/GameDay → 对抗性演练常态化【类比推断】**：v21 AISI 的"验证器 vs 攻击器共同进化"正是安全混沌工程的精神——定期主动注入新型攻击（GameDay），验证阙疑是否真能识别，发现盲点即补规则（呼应 v28 红蓝对抗）。
- **红蓝对抗 → "攻击器=红队、验证器=蓝队"的原型【类比推断】**：v21 的攻击生成器即红队，验证器即蓝队，二者对抗演练后蓝队（验证器/规则）据弱点进化——这是阙疑闭环的人类学原型，应制度化。
- **DREAD → 误报/风险排序的量化【类比推断】**：v23 软警报率与 v25 判决优先级可用 DREAD 五维评分定量排序，"哪个误报最危险、哪个漏洞漏报代价最高"可排序处置（呼应 C3 损失不对称）。
- **SDL → 阙疑自身开发的 SDL【类比推断】**：阙疑系统（Agent 外骨骼）自己的开发应走 SDL——需求阶段写 abuse cases、设计阶段威胁建模、验证阶段持续验证，避免 v21 自证困境在工具自身重演。
- **Abuse/Misuse Cases → "先想攻击后想验证"的需求范式【类比推断】**：v20 验证应默认从"这段代码会被如何误用"出发，而非"这段代码对不对"；abuse case 把攻击前置到需求，对应 v21"理解被验证对象需要理解其敌手"。
- **持续安全验证 → 控制有效性证明（assurance）【类比推断】**：v21 Assurance 2.0 不应是纸面声明，而应用 AttackIQ/Picus 式"持续用真实攻击验证防御是否真有效"，给 v25 Ledger 一个"验证器确实有效"的动态证明。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **攻击生成应升级为 STRIDE 结构化枚举 + 攻击树**：从随机 mutation 升级为有分类、可度量的攻击路径生成，覆盖度可量化（呼应 MITRE ATT&CK 标尺）。
2. **"失败安全默认"是阙疑内核的硬准则**：验证失败必须默认不开火而非放行——把 Saltzer-Schroeder 第五原则落成系统行为。
3. **持续安全验证给 assurance 以动态证明**：v21 的 assurance 不应静态声明，而应像 AttackIQ 那样持续用真实攻击验证验证器本身有效。
4. **SDL 应施加于阙疑工具自身**：避免"验证器自己没被安全开发"的元层漏洞。

## 四、设计原则（1-2 条，可操作）

- **D-E1-1：攻击生成器按 STRIDE+ATT&CK 结构化枚举**：每条攻击归属威胁类与 TTP，覆盖度用 ATT&CK 标尺度量，盲区即进化目标。
- **D-E1-2：阙疑内核失败安全 + 持续验证自身**：验证失败默认不开火；定期用真实攻击样本回测验证器有效性，无效即告警。

## 五、失败教训与死路（≥5 条）

- **安全靠隐蔽性必败（开放设计原则）**：任何把"攻击者不知道内部"当防御的方案必崩；阙疑不可依赖规则保密（呼应 v28 公开透明）。
- **单点验证 = 纵深防御缺失**：只靠一层验证器，单层失效即全局失效；须多层冗余（A3 3f+1）。
- **纸面合规≠真安全**：SDL/合规清单不等于防御有效，须持续验证（AttackIQ）——阙疑的 assurance 必须动态。
- **威胁建模脱离了攻击面会空转**：STRIDE 若不绑定真实攻击面（ASM），枚举出的威胁无优先级；阙疑须先有攻击面清单。
- **红蓝对抗若没复盘=演戏**：演练后蓝队不改进则无意义；阙疑每次对抗须产出规则补丁并登记 Ledger。
- **DREAD 主观评分易失真**：五维定性分受评分者偏差，阙疑风险排序须辅以客观数据（损失不对称 + 历史误报率）。
