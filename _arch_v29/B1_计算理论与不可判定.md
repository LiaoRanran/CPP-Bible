# 方向 B1：计算理论与不可判定

> 核心问题：**验证的数学极限在哪里？什么能被机械验证、什么不能？** 对应阙疑"通用内容验证器不存在"的精确表述。
> 检索：15 次（图灵机/丘奇论题、停机问题、Rice 定理、P/NP/PSPACE、预言机相对化、超计算、Gold 极限学习、λ 演算、Cook-Levin、Entscheidungsproblem、Rice 证明结构、Blum 公理、乔姆斯基层次、递归函数、Kolmogorov 不可判定）。
> 边界：v24 已提 Rice/哥德尔/Trakhtenbrot，本轮**深挖证明结构与推论**；与 v28 复杂系统不重复。

## 一、核心概念清单（≥10 条）

- **图灵机与丘奇-图灵论题**：Turing (1936) 提出通用计算模型；丘奇论题（不可证明，属经验性）主张"直觉上可计算 = 图灵机可计算"。
- **停机问题不可判定**：Turing 用对角化证明"不存在判定任意程序是否停机的总算法"。这是不可判定性的母题。
- **Rice 定理**：任意非平凡的程序**语义**性质都是不可判定的。即"程序做什么"的描述性性质无法被通用算法判定——只有语法性质（如"源代码含某关键字"）可判定。
- **P / NP / PSPACE**：P=多项式时间可解，NP=多项式时间可验证，PSPACE=多项式空间。P≠NP 未解；已知 NP⊆PSPACE，PH⊆PSPACE。
- **Cook-Levin 定理 (1971)**：SAT 是首个被证明 NP-完全的；所有 NP 问题都可多项式归约到 SAT。若 P=NP 则所有 NP 问题多项式可解。
- **预言机机器与相对化障碍**：带 oracle 的图灵机。Baker-Gill-Solovay (1975) 证明存在 oracle A 使 P^A=NP^A、又存在 B 使 P^B≠NP^B——说明任何**相对化**的证明都无法解决 P vs NP（还有自然证明、代数化两道障碍）。
- **超计算（Hypercomputation）争议**：加速图灵机、无限时间图灵机等试图超越丘奇-图灵界；主流观点认为物理上不可实现（Copeland, Davis 反对），逻辑不可计算性无法被"加速"绕过。
- **Gold 极限识别 (1967)**：归纳推理的奠基结果——从正例流中"在极限下"识别语言。证明某些语言类（如递归可枚举但非递归）**无法在极限下识别**；这是"归纳不可完全"的严格形式。
- **λ 演算**：Church 的计算模型，与图灵机等价；是函数式语言与类型论的基础（呼应 A2）。
- **Entscheidungsproblem**：希尔伯特的"判定问题"——一阶逻辑是否可判定。Church 与 Turing (1936) 独立证明**不可判定**。
- **Blum 公理与加速定理 (1967)**：刻画复杂性测度的两条公理；加速定理表明存在函数，对其任何算法都能找到"几乎处处更快"的另一算法——复杂度无"最优"算法。
- **乔姆斯基层次**：0 型（递归可枚举）~ 图灵机；1 型（上下文相关）~ 线性有界自动机；2 型（上下文无关）~ 下推自动机；3 型（正则）~ 有限自动机。0 型即不可判定疆域。
- **递归函数论**：Kleene 部分递归函数，刻画"部分可计算"；停机问题即"部分递归函数在某输入无定义"。
- **Kolmogorov 复杂度的不可判定**：K(x)（最短描述长度）本身不可计算（否则可解停机问题）；算法随机性（Martin-Löf）也基于此。

## 二、对阙疑的映射（全标【类比推断】）

- **Rice 定理 → "通用内容验证器不存在"的精确数学表述【类比推断】**：v24 已提 Rice，本轮升级——阙疑想建"通用验证器判断任意卡片/规则是否正确"，这恰是 Rice 定理的靶：判断任意程序的语义性质不可判定。因此阙疑必须**声明牺牲哪一角**（只验证受限规则族、接受不可判定残留），而非追求通用判定。v24 三难声明在此获数学支撑。
- **停机问题 → "验证器自身是否会停/陷入"不可判【类比推断】**：阙疑的攻击-验证共同进化环若要求"判定任意验证过程是否收敛"，即撞停机问题。须接受部分验证过程可能不终止，用超时/资源上限兜底（呼应 A3 的 FLP）。
- **预言机 → "人审作为 Oracle"的形式化【类比推断】**：v21/v23 的人审实质是一个不可计算的 oracle——机器把"此卡片是否成立"问人。预言机理论说明：引入 oracle 可越过某些不可判定性，但 oracle 本身的能力边界须显式声明（人审也会错、会累、会被骗）。
- **Gold 极限识别 → 规则集在极限下的收敛【类比推断】**：阙疑自我进化"在经验流中逐步识别正确规则"。Gold 定理警告：某些目标类无法在极限下学全——提示阙疑的规则学习须限定可识别类，且不可声称"最终必然学全"。
- **Cook-Levin → "验证本身可能是 NP 难"【类比推断】**：若阙疑某类验证任务可归约为 SAT 类 NP 完全问题，则无多项式验证算法；须要么近似、要么限制规则表达力到 P 内（呼应 A2 抽象解释把难问题变近似）。
- **超计算争议 → 不指望物理超机救场【类比推断】**：阙疑不可寄望"更强的物理计算"突破不可判定壁垒，应在可计算边界内设计（接受 Rice 死线）。
- **Blum 加速定理 → 无"最优验证算法"【类比推断】**：阙疑的验证器永远可被加速，不必追求"最优"验证器，只需"足够好 + 可进化"（呼应 v21 渐进验证）。
- **Kolmogorov 不可判定 → 最小规则集不可算【类比推断】**：阙疑若想自动求"规则集的最短描述/最简规则"，K(x) 不可计算，只能用 MDL 近似（见 B2）。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **Rice 定理给出"通用验证器"不可存在的严格证明**，而不只是 v24 的直觉性三难——这是阙疑设计上"必须声明牺牲"的最硬数学约束。
2. **预言机理论把"人审"正式建模为 oracle**：明确人审是"不可计算但可查询"的部件，其能力边界（错误率、疲劳、被欺骗）须作为 oracle 参数进入系统分析。
3. **Gold 极限识别把"自我进化能否学全"形式化**：阙疑不可声称规则学习最终完备，必须限定可识别类。
4. **P vs NP 的三道障碍（相对化/自然证明/代数化）** 提示：任何"巧妙绕过不可判定"的尝试都会撞结构化壁垒，阙疑应避免在错误方向上消耗。

## 四、设计原则（1-2 条，可操作）

- **D-B1-1：阙疑必须显式声明"牺牲角"**——基于 Rice/停机，写明"不追求通用判定；只验证受限规则族；不可判定残留交人审 oracle + 超时兜底"。
- **D-B1-2：把验证目标限制在可计算/多项式类**——规则表达力约束到可机械验证的子类（避免归约到 NP 完全），对难判部分用近似（抽象解释）而非硬解。

## 五、失败教训与死路（≥5 条）

- **追求"完全验证"在数学上不可能（v24 三难声明深化）**：Rice + 停机问题证明通用语义判定不存在；阙疑若设"通用验证器"目标必死。
- **P vs NP 未被攻克，且三道障碍挡路**：任何声称"找到多项式通用验证"的方案都需先过相对化/自然证明/代数化，几乎不可能。
- **超计算物理不可实现**：指望超机突破不可判定是死路，阙疑应在可计算界内设计。
- **Gold 定理：某些类无法在极限下学全**：阙疑自我进化若不限类，会陷入"永远学不全"的尴尬，须限定可识别类。
- **Blum 加速：无最优算法**：追求"最优验证器"无意义，应转向"可进化 + 足够好"。
- **Kolmogorov 不可计算**：自动求最简规则/最短证明不可能，只能近似（MDL），不能作为精确优化目标。
