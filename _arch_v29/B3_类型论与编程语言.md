# 方向 B3：类型论与编程语言

> 核心问题：**能否把"规则的前置条件、证据的不可重用、副作用的边界"写进类型，让编译器替我们拦错？** 对应阙疑"规则前置 + 凭证一次性 + 副作用追踪"。
> 检索：15 次（依赖类型、线性类型/Rust 所有权、效应系统/代数效应、仿射/相关类型、DSL、渐进类型、Rust 限制、类型系统进展、线性逻辑、代数效应 handlers、精化类型、类型驱动开发、量化类型论、会话类型、能力+线性类型）。
> 边界：A2 已提依赖类型，本轮**深化工程化与更多类型族**；与 A2 不重复（更偏语言设计）。

## 一、核心概念清单（≥10 条）

- **依赖类型**：类型可依赖值（如 `Vec A n` 长度 n 进类型）。Agda、Idris、F*、Coq 支持；可在类型层强制不变量（见 A2）。
- **线性类型 / Rust 所有权**：线性逻辑（Girard）的 Curry-Howard 对应——资源必须恰好使用一次（不可复制/丢弃）。Rust 的所有权+借用检查器在编译期保证内存安全与数据竞争自由，零运行时开销（NLL 算法精确化生命周期）。
- **效应系统（Effect Systems）**：在类型中标注"此函数会做什么副作用"（读文件、抛异常、用随机）。OCaml 5 效应、Koka 的代数效应处理器（effect handlers）把异常/async/状态做成用户态可组合库。
- **仿射/相关/子结构类型**：线性逻辑去掉"收缩/弱化"规则得到资源敏感类型——仿射（可丢弃不可复制）、相关（可复制不可丢弃）、有序（不可复制不可丢弃）。C++ 的 `unique_ptr`/move 语义是其片段。
- **精化类型（Refinement Types）**：基础类型 + 逻辑谓词（如 `x:Int{x>0}`）。LiquidHaskell 用 SMT 自动验证谓词，把"正数金额""长度上限"等不变量纳入类型。
- **DSL 设计原则**：为特定领域定制语言（如 SQL、正则）。嵌入式 DSL（eDSL）借宿主语言复用；关键在"领域抽象 + 组合子 + 最小认知负荷"。
- **渐进类型（Gradual Typing）**：静态/动态混合（TypeScript），可在 JS 上加可选类型标注。但"collapsible contracts"病理可使性能下降达 120×；类型迁移成本高。
- **代数效应处理器（Algebraic Effects + Handlers）**：Plotkin & Pretnar 提出；计算与效应解耦，handler 拦截并解释效应，比异常更通用、可组合。
- **会话类型（Session Types, Honda 1993）**：为并发/分布式通信协议建模——在编译期验证消息的顺序、方向、类型，防止协议错配。
- **类型驱动开发（Type-Driven Development, Idris）**：以类型作为程序"计划"，编译器/类型检查器当助手引导到满足规格的实现；前置条件即类型。
- **量化类型论（QTT）**：Idris 2 核心，给类型变量加"使用次数"标注（0/1/多），统一依赖类型与线性类型——表达"运行时擦除的数据"与"必须使用的资源"。
- **类型系统可靠性（Soundness）**：Pierce《Types and Programming Languages》——类型系统是强制抽象层级的句法方法；每个类型系统的安全需相对自身错误集证明。

## 二、对阙疑的映射（全标【类比推断】）

- **线性类型 → "证据/凭证的一次性使用"防重放【类比推断】**：阙疑的 VerificationRun 凭证、签名、票据应"用过即废"以防重放攻击。线性类型在编译期强制"每个凭证恰好消耗一次"，比运行时检查更可靠——可把凭证建模为线性资源，非法复用直接类型错误。
- **效应系统 → "哪些工具会写数据"的编译期追踪【类比推断】**：v21 关注"验证器副作用"。效应系统给每个工具标 `effect{writes:Ledger, reads:Source}`，编译器可证明某规则绝不写 Ledger，或某攻击生成器只读不写——从类型层阻断越权，呼应 A4 能力安全。
- **依赖类型 → "规则前置条件在类型中声明"【类比推断】**：v25 Rule 的适用域（如"只在 L≥3 层匹配 object 语义"）可写成依赖类型 `Rule(reqLayer:Level | reqLayer>=3)`，非法调用编译期被拒，把运行时 ConflictDetector 前移。
- **精化类型 → "断言须满足的可判定谓词"【类比推断】**：每张卡片断言可标 `Assertion{x : Proposition | wellFormed(x)}`，LiquidHaskell 式 SMT 自动验证"断言格式合法、引用存在"，减少 v25 W2 命题图的格式错误。
- **会话类型 → "验证者-攻击者协议顺序"【类比推断】**：阙疑的攻击-验证共同进化是多方协议。会话类型可在编译期保证"先发 mutation 再收 verification 再记 ledger"的顺序正确，防协议错配导致的竞态。
- **DSL → 规则/卡片的领域专用语言【类比推断】**：v25 规则与卡片若用通用语言写易出错；应为"规则 DSL"定制（如声明式匹配 + 前置条件 + 动作），降低认知负荷并便于形式化（呼应 A2）。
- **量化类型论 → "可擦除 vs 必需"的资源区分【类比推断】**：阙疑运行时哪些验证数据可丢弃、哪些必须保留（如 Ledger 写入），用 QTT 的用量标注区分，优化存储与证明成本。
- **渐进类型 → "逐步给规则加类型"的迁移路径【类比推断】**：阙疑现有规则可能无类型，可像 TypeScript 一样渐进加类型（先宽松后收紧），但须警惕"collapsible contracts"式性能/正确性陷阱。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **线性类型为"凭证一次性"提供编译期保证**：比 v21 的运行时防重放更强，把重放漏洞在类型层消灭。
2. **效应系统把"副作用边界"形式化**：阙疑可精确声明每个工具读/写哪些资源，从类型层防共谋越权（补 A4 能力安全的类型化实现）。
3. **会话类型给"共同进化协议"顺序安全**：阙疑攻击-验证多轮交互可类型化为会话，编译期防错配。
4. **精化类型让 SMT 自动查不变量**：把"断言格式/引用合法"这类检查从人工/运行时前移到编译期。

## 四、设计原则（1-2 条，可操作）

- **D-B3-1：规则 DSL 内建线性/依赖/精化类型**——凭证为线性资源、前置条件为依赖类型、断言格式为精化类型，使越权/重放/格式错误在编译期被拒。
- **D-B3-2：工具副作用用效应系统声明**——每个工具标注读/写资源集合，验证器匹配阶段可静态证明"无未授权写入"，无需运行时监控全部。

## 五、失败教训与死路（≥5 条）

- **依赖类型学习曲线极陡（A2 已提）**：Idris/Agda 门槛高，团队难普及；阙疑若全面依赖类型化需配套培训与 LLM 辅助。
- **Rust 所有权在 GC 语言难移植**：借用检查器的好处建立在无 GC 上，在 Python/JS 生态无法直接复用；阙疑若核心非 Rust 写，需另寻效应/线性实现。
- **渐进类型有 120× 性能陷阱**：collapsible contracts 病理让"渐进"代价高昂；阙疑若用渐进类型须控制契约边界。
- **效应系统标注负担**：每个函数标效应累赘，且组合效应易爆炸；阙疑工具若全标效应维护成本高。
- **会话类型对动态协议不友好**：严格会话类型难表达动态分支/版本演化；阙疑协议若频繁变，会话类型需频繁重设计。
- **精化类型依赖 SMT 能力**：复杂谓词 SMT 可能超时/不解，阙疑精化断言须保持谓词在 SMT 可解范围内。
