# 大组 A 综合：信任与密码学

> 大组 A 覆盖 A1 密码学信任协议 / A2 形式化方法与程序验证 / A3 分布式共识与容错 / A4 操作系统安全与可信计算基。
> 共 60 次检索。核心命题：**没有可信第三方时，如何建立可验证、可独立、最小化的信任？** 直接服务阙疑"信任根独立 + 通用验证内核 + 自我进化"。

## 一、四方向横向对比

| 方向 | 核心机制 | 对阙疑最硬的映射 | 最大死路 |
|---|---|---|---|
| A1 密码学协议 | ZK / MPC / 门限签名 / TUF / SLSA / 透明日志 | 验证与证据暴露解耦、多验证者阈值 t-of-n、provenance | zkML/TEE 封棺；可信设置中心化 |
| A2 形式化 | CompCert/seL4 精化证明、抽象解释、分离逻辑 | 验证器自身可验证、coverage 的 sound 上界、规则隔离 | 全量形式化不可行、spec gap |
| A3 共识 | 3f+1 BFT、CRDT、FLP、CAP、故障检测器 | 多验证者节点数下限、账本无冲突合并、不可靠活性 | 单用户无真 BFT、2PC 阻塞、FLP |
| A4 OS 安全 | TCB 最小化、能力安全、安全启动、TEE 死路 | 最小可信内核、规则权限 capability 化、信任链 | TEE 信任根在厂商、侧信道 |

## 二、跨方向收敛的核心洞察（≥5 条）

1. **"信任根独立"可以量化且工程化**：A1 的 1-of-N 诚实 + A3 的 3f+1 + A4 的 TCB 三路合流——阙疑的信任根应是"N 方中至少 k 方独立 + 最小可验证内核 + 阈值签名"的组合，而非抽象口号。
2. **"最小可验证内核"现实可达**：A2 的 seL4/CompCert + A4 的微内核 TCB 证明"几千行核心可被全程形式化"。阙疑不必全系统形式化，只需把核心（规则匹配/判决/账本）缩到可证规模。
3. **多验证者聚合的统一数学**：A1 门限签名 + A3 的 3f+1/2f+1 = 阙疑"硬开火需 ≥2f+1 方签名"的密码学+共识双重支撑。v22 的 BFT 推论在此被夯实。
4. **账本同步应甩掉共识开销**：A3 的 CRDT（无冲突合并）+ A1 的 Merkle 透明日志 = 阙疑 Ledger 的理想形态：各处本地 append，合并无冲突，第三方可出具一致性证明揭穿篡改。
5. **证明/验证链必须可机器校验且带 provenance**：A1 的 in-toto/SLSA + A2 的精化证明 + A4 的 Measured Boot 信任链，共同指向——阙疑每条 VerificationRun 应记录"谁、用何工具、在何版本、产出何证明"，形成不可篡改且可第三方核验的 attestation。
6. **"隔离"必须多层次**：A4 能力安全 + 沙箱 + 信息流控制，提示单层权限（RBAC）不够，阙疑需权限隔离 + 信息流隔离 + 沙箱三层防共谋。

## 三、对阙疑 642+ 的设计建议（排序）

1. **把核心重构为微内核式 TCB（A4+A2）**：规则匹配/判决/账本为唯一可信内核，目标形式化验证；其余外移。
2. **多验证者按 3f+1 部署 + 门限签名（A3+A1）**：硬判决需 2f+1 方签名，单点失效/被攻陷不致误判。
3. **Ledger 用 CRDT + Merkle 透明日志（A3+A1）**：无冲突合并 + 第三方可审计。
4. **VerificationRun 全程 provenance（A1+A4）**：in-toto 式 attestation 记录过程，Measured Boot 式信任链防篡改。
5. **规则/工具 capability 化并默认沙箱（A4）**：seccomp/Landlock 式约束，攻击生成器强制沙箱。

## 四、死路总表（去重）

- zkML / TEE 封棺：信任根交厂商 + 侧信道无解（A1/A4）。
- 全量形式化不可行：成本/维护压倒性（A2）。
- 单用户无真 BFT（f=0 退化）（A3）。
- 2PC 协调者阻塞、FLP 异步死锁（A3）。
- spec gap：证明错误的规格（A2）。
- 微内核性能代价、能力撤销复杂（A4）。

## 五、与 v21-v28 的更新

- **加强**：v21 信任根独立从"原则"升级为"3f+1 + TCB + 阈值签名"的可操作三角；v22 BFT 3f+1 获 A3 数学夯实；v26 审计阈值与 A1 门限签名同源。
- **修正/细化**：v21 的"TEE 可用"被彻底否定为死路（A4 给出具体死因）；v23 coverage 获 A2 抽象解释的 sound 上界数学底座。
- **新增武器**：in-toto provenance、CRDT 账本、能力安全、信息流控制——v21-v28 未系统化覆盖。
