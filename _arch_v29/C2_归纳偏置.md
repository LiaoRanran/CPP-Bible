# 方向 C2：归纳偏置

> 核心问题：**任何学习都预设了"世界有什么结构"？阙疑的自我进化到底押注了哪些结构假设？** 对应阙疑"先验/规则偏置的设计与对齐"。
> 检索：15 次（归纳偏置定义 Mitchell、NFL 必要性、奥卡姆/MDL、架构偏置 vs 偏好偏置、核方法、Transformer 偏置、DL 偏置综述、元学习学偏置、课程学习、正则即偏置、贝叶斯先验、偏置对齐、GNN 置换不变、CNN 局部性、偏置错配负迁移）。
> 边界：v23/v25 已涉及置信/规则，本轮**系统化偏置理论**；与 B2 奥卡姆、C1 NFL 不重复。

## 一、核心概念清单（≥10 条）

- **归纳偏置（Inductive Bias, Mitchell 1980）**：学习器把无限假设空间压到有限可搜索范围所依赖的假设集。没有偏置，"从有限样本学无限函数"不可能（与 NFL 同源）。
- **没有免费午餐（NFL）再证偏置必要性**：Wolpert 证明对所有可能函数平均，任何算法等价；算法优劣完全取决于**其偏置与真实结构的匹配度**——偏置不是可选项，而是学习的前提。
- **奥卡姆剃刀 / MDL 作为偏置**："最短描述"是一种偏好偏置，偏好更简单的假设（见 B2）。
- **架构偏置 vs 偏好偏置（Architectural vs Preference Bias）**：架构偏置内建于模型结构（CNN 的局部连接、RNN 的时序）；偏好偏置是学习算法对假设排序（正则、目标函数）。两者分工决定"什么容易学"。
- **CNN 的归纳偏置**：局部性（locality）+ 平移等变性（translation equivariance）——对图像这类结构极有效，样本高效。
- **Transformer 的归纳偏置**：注意力机制弱内建偏置、长程直连，靠数据量弥补；故有"lost-in-the-middle""attention sink"等位置偏置涌现。
- **核方法的偏置**：核函数编码"相似性/平滑性"先验（如 RBF 的光滑偏好），决定函数空间（RKHS）。
- **元学习学偏置（Meta-learning Inductive Bias）**：Dorrell-Latham 等让网络"元学习出自己的归纳偏置"——从多任务中习得"什么结构该假设"，而非手工设定。
- **课程学习（Curriculum Learning, Bengio）**：从易到难安排样本，是一种**训练序**偏置——模拟人类学习，常加速收敛与泛化。
- **正则化即归纳偏置**：weight decay/L2/dropout 都是把"偏好小权重/稀疏/鲁棒"编码进学习，是偏好偏置的实现。
- **贝叶斯先验即偏置**：先验分布 p(θ) 显式编码"参数什么样更可能"，是偏置的贝叶斯表达（呼应 B2 Solomonoff）。
- **偏置对齐（Alignment）/错配**：偏置须与真实数据结构匹配；错配导致**负迁移（negative transfer）**——错误先验比无先验更糟。

## 二、对阙疑的映射（全标【类比推断】）

- **归纳偏置是自我进化的"隐形骨架"【类比推断】**：v21-v25 反复说"从经验进化规则"，但没点明——进化必押注某种世界结构假设（如"攻击有可归纳模式""相似代码相似误解"）。这些假设就是阙疑的归纳偏置，应被**显式写出来并监控**，而非藏在内核里。
- **NFL → 阙疑不能没有领域先验【类比推断】**：C1 的 NFL 证明无偏置则无最优。阙疑若声称"对所有代码/所有攻击最优验证"，必撞 NFL。必须绑定 C++ 语义、对象模型等具体先验（v20 的 65 条 object 即一种架构偏置）。
- **架构偏置 vs 偏好偏置 → 阙疑的两类规则偏置【类比推断】**：阙疑规则引擎的"架构偏置"= 规则 DSL 的表达力限制（B3）；"偏好偏置"= 规则采纳/淘汰的排序（B2 MDL、v25 CalibrationTracker）。两者须分开设计、分别可审计。
- **CNN 局部性 → "邻近语义更相关"作为规则偏置【类比推断】**：阙疑"同文件/同函数内的对象更可能共享误解"是一种局部性等变偏置，类似 CNN——可据此做样本高效的检查（只看局部邻域）。
- **Transformer 弱偏置 → 阙疑大模型验证器需显式喂偏置【类比推断】**：若阙疑用 LLM 做语义验证，其弱归纳偏置意味着必须靠 v20 的领域先验、v25 的语义审查框架**显式注入**，而非指望模型自己学出 C++ 结构。
- **元学习偏置 → "让规则集自己学出偏置"【类比推断】**：阙疑自我进化可借鉴元学习——从多类攻击任务中**习得**"应假设什么结构"，把手工偏置升级为可进化的元偏置，但须防元偏置过拟合（见失败教训）。
- **课程学习 → 验证难的递进训练【类比推断】**：v21 AISI 的渐进学习可形式化为课程学习——先学易判定规则、再攻难例（如模板注入、对象语义陷阱），对应"先简单后复杂"的训练序偏置。
- **正则即偏置 → 规则集的防膨胀正则【类比推断】**：B2 的 MDL 可视为对规则集的"正则化"——惩罚规则数量/长度，是一种偏好偏置，防过拟合噪声（呼应 B2 MDL 采纳准则）。
- **贝叶斯先验 → 攻击先验的显式表达【类比推断】**：v21/v23 的攻击分布可表达为贝叶斯先验 p(attack)，与 B2 Solomonoff 通用先验衔接——偏置从"隐式"变"可算"。
- **偏置错配 → "错误先验比无先验更糟"的红线【类比推断】**：阙疑若押注错误结构（如"所有 bug 都局部"），会比无偏置更糟（负迁移）。须有机制检测偏置失配（如 C1 分布偏移监控）并回退。

## 三、净新增（v21-v28 没有的洞察，≥3 条）

1. **阙疑的归纳偏置必须被显式化**：之前把"从经验学"当黑箱；本轮明确"学"必依赖隐藏偏置，应把 v20 的 65 条 object、v25 的语义框架列为**显式架构偏置清单**并持续审计。
2. **偏置分两类（架构/偏好）需分别治理**：规则 DSL 的架构偏置与采纳排序的偏好偏置要独立可审计、可回滚。
3. **元学习偏置是可进化的下一步**：手工偏置可升级为"从多攻击任务元学习偏置"，但须防过拟合。
4. **偏置错配负迁移是比"无偏置"更危险的死路**：明确红线——错误先验比无先验更糟，须有失配检测。

## 四、设计原则（1-2 条，可操作）

- **D-C2-1：建立显式归纳偏置清单并持续审计**——把 v20 object 语义、v25 框架、v23 攻击先验列为可审查偏置表，定期用 C1 分布偏移检测其是否仍匹配。
- **D-C2-2：偏置失配即回退至更弱偏置**——监测到偏置与数据错配（负迁移迹象）时，自动降级到更通用偏置（如去掉"局部性"假设），而非坚持错误先验。

## 五、失败教训与死路（≥5 条）

- **无偏置则无学习（NFL）**：阙疑不可能"零假设"进化，必须接受并显式管理偏置。
- **偏置错配导致负迁移**：错误先验比无先验更糟；阙疑若押错结构假设会系统性漏报。
- **Transformer 弱偏置需海量数据**：若阙疑靠 LLM 验证又无领域数据注入，弱偏置致泛化差；须显式注入 v20 先验。
- **元学习偏置易过拟合元任务**：从有限攻击任务学出的偏置可能只适配所见，迁移失效；须多样元任务。
- **课程学习排序难设计**："由易到难"的难度定义本身需偏置，排错反而拖慢；阙疑须有客观难度度量。
- **正则不足致规则过拟合噪声**：偏好偏置太弱，规则集会拟合历史偶然（呼应 B2 sophistication 噪声问题）。
